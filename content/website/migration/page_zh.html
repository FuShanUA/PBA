遗留代码库合理化：ERP 平台选择与迁移

一家领先的技术服务公司需要对其 ERP 进行现代化改造。他们尚未确定要迁移到哪个平台，而且如果不先了解现有系统实际包含哪些信息，就无法负责任地做出这一决策。挑战在于：数百万行代码、与数百万个活跃订单纠缠在一起的自定义逻辑，以及承载着多年未清技术债务的数据负载。

Palantir 进行了一次快速的 AI 驱动评估，带来了立竿见影的清晰认知。在盘点出的数百万行代码中，约一半的规则被标记为待废弃，数千条独立规则被精简到仅数百条，在做出平台决策之前就消除了数百万行技术债务。AIP 驱动的工作流将所有自定义逻辑映射到活跃订单，实现了零业务中断的干净废弃。与此同时，并行的数据评估将迁移量削减了 60% 以上，大幅降低了总体 GB 数。经过合理化的范围随后直接输入到场景建模中。通过预测仅迁移剩余内容在各候选平台上的成本，Palantir AIP 使客户能够做出明智、理性的平台选择，而不是盲目地押注某个目标系统。

客户自己的一小支工程师团队全程参与，验证各项发现并直接负责高风险领域。最终，客户带着更清晰的系统规划、对真实迁移成本更深入的理解，以及无论最终选择哪个平台都能继续推进工作的内部能力，顺利完成了项目。

多市场 SAP ECC → S/4HANA 迁移

一家全球食品制造商面临一项艰巨的高管指令：在24个月内将其全球业务中20多个市场迁移到 SAP S/4HANA。传统的迁移方案——每个市场都要经历长达数月的僵化线性流程——使这一时间表在结构上不可能实现。数十年的分散化运营导致每个国家都有自己的数据标准、付款条款和业务规则，没有全球统一模板，并且由于员工流动而造成机构知识的流失。

Palantir 与其技术和业务团队共同召开了一次为期24小时的密集工作会议。在数小时内，Palantir 的 AI FDE 代理就摄取了原始 ECC 数据，自动生成了 S/4HANA 就绪的数据集，并直接从历史交易数据中推断出现有的业务规则，完全跳过了原本需要数周甚至数月的需求收集研讨会。一个验证引擎将数千个带有未映射付款条款的销售订单与全球目录进行交叉比对，创建了一个 SME 工作流应用，能够对任务分配、审批、升级和审计追踪进行优先级排序，将人工注意力仅集中在异常情况上。

其结果重塑了迁移模式：数据不再是瓶颈。跨市场的并行工作流取代了逐国顺序部署，一个全面的全球统一模板取代了针对每个国家的定制构建。在这次快速演示之后，预计的完成时间、总预算和人员时间估算都大幅缩减。

首次完全由 AI 执行的 SAP 迁移：旧版 SAP → S/4HANA

在两周内，Palantir 完成了从旧版 SAP 到 S/4HANA 的 20,000 多条位置记录的迁移。这是首个完全通过 AI 劳动力运行完整迁移生命周期的项目。

Palantir AIP 摄取了庞杂的 SAP PDF 和电子表格，自动构建了数据模型，并端到端地构建了转换管道。每个逻辑流程（包括在移除空组织节点后重新映射资产层级）都在一个带有评论区的连接前端中呈现，以收集人工输入。SME 的反馈直接回传到管道中，促使 AI FDE 在几分钟（而非数周）内执行针对性修复和评估。清晰的加载表数据就绪百分比让团队有了一个可衡量的改进目标，使整个系统具备自我纠错能力。

关键洞察：动态生成的 SME 视图支持对任务的持续评估。给别人看电子表格，就会得到电子表格质量的反馈；给他们看交互式层级结构，就会得到精准、可操作的反馈，代理可以立即据此采取行动。

大规模 SQL 迁移：SQL Server → PySpark

一家大型零售商拥有数百个相互依赖、冗长且复杂的 SQL Server 查询，支撑着其报告基础设施。这种复杂性和相互依赖性带来了一个几乎无法克服的挑战，且已持续了十多年，但这一切都必须迁移。

Palantir 构建了一个管道，对 SQL 执行静态分析以生成完整的依赖关系图，然后分派并行的 AI FDE 任务，每个任务都在自己的自动化浏览器实例中运行，自主地解释、重编码、构建和验证每个数据集。结果：他们 250 多个数据集全部以 100% 的准确率完成迁移和验证。数万行 SQL 被转换为透明的 PySpark。凭借不到 4 千美元的 AI token 成本投入，客户从两周完成 5 次迁移提升到每天完成数百次迁移。

这数十个代理组成的集群针对结构化任务图并行执行，并在编排上进行了精心投入。计划/执行模式、动态提示模板、多模型协调和内存管理协同工作，以找到可扩展的、可重复的构建路径。
