编写优质代码

编写高质量代码的能力是……

  • 01

    高效

    代码以最佳性能运行，并且可以扩展。

  • 02

    有效

    代码应该没有 bug，并且易于测试。

  • 03

    易于阅读、维护和升级.

    代码的各个元素应该结构合理、定义清晰，从简单的变量命名到多个文件、类和框架的结构。

为什么我们重视编写高质量的代码？

Palantir 是一家由许多小团队组成的大公司。在产品和业务拓展部门，4-8 名工程师组成的团队为我们的核心平台做出贡献，并通过自定义代码扩展这些平台。要让这种去中心化的模式运转良好，代码必须高质量。

我们的业务发展很快。为了最大限度地发挥工程师的创造力和提升开发速度，我们给予工程师很大的自由来架构他们的代码，而不施加严格的风格规范。无论你是从事长期平台项目的软件工程师，还是需要在下周截止日期前完成原型扩展的前线部署软件工程师，你都需要理解什么样的代码才是高质量的代码。

02 /

如何准备

我们不会问你某些特定编程语言中晦涩难懂的特性。

我们关注的是你作为程序员的技能，而不是你记忆 Java 编译器细节的能力。

准备展示编码技能的最佳方式就是多写代码！练习时请记住以下几点：

—— 1

一场好的编码面试的核心要素之一，是将概念性的算法解决方案转化为实际实现该方案的代码的能力。

这种转化往往并不显而易见，需要提前进行一些规划和思考。

—— 2

思考边界情况以及代码可能出错的方式。

思考如何测试它。

—— 3

一旦找到以最优理论复杂度（例如 O(n)）运行的算法，就要继续思考可扩展性以及在效率方面什么是重要的。

有时一个 O(n) 的算法可以用执行 n 次或 2*n 次迭代的循环来实现。有时添加一个空间复杂度为 O(n) 的数据结构是不必要的。

—— 4

思考代码的结构、命名和整体整洁度。

—— 5

注意 API 调用。

使用简单的工具调用（如数组和字符串操作或数据结构）是可以的，但对于你进行的每一次 API 调用，请确保你理解它的功能及其复杂度。

03 /

关于面试本身

只要是你使用的命令式编程语言，我们在面试中通常都可以接受。

避免使用过于小众或过时的语言。例如，我们显然接受业界常用的语言，如 Java、Python、C/C++、C#、JavaScript 等（包括 Rust、Go、Groovy、TypeScript 等变体）。

我们也接受稍微老一些的语言，只要它们仍然是命令式的，比如 Visual Basic、Pascal/Delphi、Perl 等。但我们不接受非命令式语言（Prolog、Lisp、Erlang），也不接受过于小众、过时和/或与现代业界实践差异过大的语言（Cobol、Fortran）。

来现场面试时，请做好在白板上写代码的准备。（如有需要，我们可以提供纸笔或电脑。）
