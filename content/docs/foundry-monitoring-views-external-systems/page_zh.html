将警报发送到外部系统

当监控器触发或恢复时，警报既可以发送给 Foundry 内的订阅用户，也可以发送给 Foundry 外部的服务。监控视图目前支持将警报发送到 PagerDuty、 Slack和 webhook。

所有集成均针对给定的严重级别进行配置。只有与该严重级别匹配的警报才会触发集成。例如，如果 PagerDuty 集成配置为 MEDIUM 严重级别，则当监控器以 LOW 或 HIGH 严重级别触发时，不会触发该集成。

PagerDuty

此集成使用 PagerDuty V2 Events API ↗ ，通常不需要服务用户、电子邮件，也不需要自定义允许列表或出口配置。单个集成会将监控视图内给定严重级别的所有警报映射到 PagerDuty 服务中定义的 Events V2 API 集成。请注意，在监控视图中定义的多个集成可以映射到同一个 PagerDuty 集成密钥。

为您的 PagerDuty 服务创建 Events V2 API 集成

为 PagerDuty 服务配置您所需的升级策略、紧急度设置和支持时间。在 集成 选项卡上，为该服务添加新集成。选择 Events API V2 作为集成类型并添加该集成； Events API V2 通常可以在 最受欢迎的集成 部分。添加集成后，选择齿轮图标将显示其详细信息，包括 集成密钥 ，用于 为您的监控视图创建新的 PagerDuty 集成。

为您的监控视图创建新的 PagerDuty 集成

导航至 管理订阅 标签页（用于您的监控视图）。从 PagerDuty 通知 部分中，选择加号（+）以创建新的 PagerDuty 集成。您需要指定集成的名称、创建 Events V2 API 集成时获得的集成密钥以及严重性级别。根据需要为每个所需的严重性级别重复此操作。

为健康检查启用 PagerDuty

默认情况下，监控视图将为监控规则警报以及属于已升级/关联到该监控视图的检查组的旧版健康检查生成 PagerDuty 通知。但是，在 v1.860.0 版本（2024 年 2 月）发布之前创建的监控视图默认不会生成 PagerDuty 警报，必须手动启用。

要启用此功能，请选择 为健康检查启用 PagerDuty 复选框。将使用以下严重性映射：

  • 信息/低严重性健康检查将使用 LOW 严重性集成。
  • 中等/中等严重性健康检查将使用 MEDIUM 严重性集成。
  • 严重/高严重性健康检查将使用 HIGH 严重性集成。

Slack

此集成可以在一组已配置的频道中触发 Slack 消息。

创建 Slack 源

此集成需要在 Data Connection 中创建 Slack 源。此源需要配置持有者令牌（bearer token）。该持有者令牌应具有以下作用域：

  • channels:join：Foundry 将使应用自动加入所请求的频道。
  • channels:read：用于列出可用频道。
  • chat:write：用于向已配置的频道发送消息。
  • （可选） groups:read：向私密频道发送消息时必需。

在 Slack 中生成此类令牌的一种示例方法如下：

  1. 在您的工作区中创建一个新的 Slack 应用。
  2. 转到 OAuth & Permissions。
  3. 将上述作用域添加为 机器人令牌权限范围。
  4. 在您的工作区中安装 Slack 应用。
  5. 复制 机器人用户 OAuth 令牌。

请参阅 Slack API 文档 ↗ 以了解更多详情。

为您的监控视图创建 Slack 集成

导航至 管理订阅 标签页（适用于您的监控视图）；在 Slack 部分，使用加号（+）以创建新的 Slack 集成。选择一个已配置的 Slack 源。 Slack Channels 字段随后将填充可用频道列表，您可以将警报发送至这些频道。

要配置与私有频道的集成，请将 Slack 应用邀请至私有频道，并确保 groups:read 该 scope 已被授予。

配置严重性级别，并根据需要为每个其他所需的严重性级别重复此操作。

为资源名称可见性配置可导出标记

来自监控视图的 Slack 通知可以显示人类可读的资源名称（例如“生产销售数据集”），而不是资源标识符（RID，如 ri.main.dataset.xyz789）。这使得警报更易于理解，并帮助您快速评估紧急程度。资源名称仅在安全控制允许时才会显示；具体而言，当资源上的所有 标记 都包含在 Slack 源的可导出标记配置中时。

更新后的通知格式

Slack 通知格式已更改，现在会在安全控制允许的情况下包含资源名称。如果您有机器人或自动化解析器在处理来自 Slack 的监控视图通知，则可能需要对其进行更新，以处理新的消息格式。

资源名称可见性的工作原理

当监控器触发并向 Slack 发送警报时，Foundry 会检查资源名称是否可以安全共享：

  • 资源名称已显示： 资源上的所有标记和组织均已包含在 Slack 源的可导出标记列表中。
  • 改为显示 RID： 资源上的一个或多个标记或组织不在可导出标记列表中。

例如，如果名为 "Customer Revenue Data" 的数据集具有 Confidential 标记，且该标记属于 Sales 组织：

  • 如果 Confidential 和 Sales 被配置为可导出，Slack 会显示“Customer Revenue Data”。
  • 如果可导出标记中缺少其中任何一个，Slack 会显示 ri.foundry.main.dataset.abc123。

为您的 Slack 源配置可导出标记

要在 Slack 通知中启用资源名称，具有 Information Security Officer 角色的用户必须配置可导出标记：

  1. 导航至 Data Connection 应用程序。
  2. 选择用于监控视图通知的 Slack 源。
  3. 选择 连接设置 并导航至 导出配置 选项卡。
  4. 开启 启用导出到此源。
  5. 添加 标记 以及可能出现在 Slack 消息中的组织。
    • 您必须同时添加安全标记 和 组织标记。
    • 您必须对添加的每个标记或组织拥有取消标记权限。
  6. 选择 保存 以应用配置。

要添加哪些标记

考虑为以下内容添加可导出标记：

  • 您的监控视图所监控的数据集和数据流上的标记
  • 与您正在监控的项目相关联的组织标记
  • 您希望在 Slack 中查看其友好名称的资源上出现的任何标记

您可以从限制性较低的标记开始，并根据需要添加限制性较高的标记。请记住，如果资源上的任何标记不在可导出列表中，则会显示 RID 而非名称。

Information Security Officer 是 Foundry 中的默认角色。用户可以在 控制面板 中的 注册权限下被授予此角色。有关可导出标记如何与 Data Connection 配合使用的更多详细信息，请查阅 导出文档。

Webhook

此集成可以触发 Webhook （在数据连接中配置）。请参阅 Webhook 文档以了解如何设置 Webhook。要使用 Webhook 集成，该 Webhook 必须具有一个字符串输入参数，名为 Message 参数。其中将填充通知的内容。目前尚无法自定义内容。

为您的监控视图创建新的 Webhook 集成

导航至 管理订阅 标签页（针对您的监控视图）；在 Webhooks 部分中，使用加号（+) 以创建新的 webhook 集成。您需要先选择一个 webhook，然后才能选择该 webhook 上的 Message 参数和严重性级别。根据需要为每个所需的严重性级别重复此操作。
