开始使用

构建新的用例

在本教程中，我们将使用 Use Cases 应用程序创建一个包含各种应用程序和本体论资源的新用例。然后，我们可以直接从用例概览页面导航到 Workshop 和 Ontology Manager 等应用程序，还可以添加其他应用程序。

第 1 部分：创建用例

首先，我们需要访问 Use Cases 应用程序。

登录 Foundry 后，在左侧导航栏的 Platform Apps下访问 Use Cases 应用。如果该应用程序不可见，请选择 “查看全部” 并找到 用例 图表工具 运营应用程序 已应用标签 平台应用 在出现的搜索窗口中。

现在您将进入 Use Cases 应用的主页。如果您尚未创建任何用例，此页面将为空。

在 所有用例 部分的右侧，点击 + 新建。这将打开 创建用例 弹窗。添加用例名称和描述。在我们的示例中，用例名称为“航班警报用例”，描述为“用于管理航班警报和更新时刻表的用例。"

在本教程中，我们将在文件系统中创建一个新的支撑 Project。点击 + 新建 在右下角，以打开 新建项目 弹窗，该弹窗允许您向 Foundry 文件系统添加新的 Project。添加名称、可选描述以及 空间 为您的 Project。

您的空间将决定组织中用户的默认 Organization 和角色。在我们的示例中，我们的 Project 名为“Flight Alert Project”，描述为“航班警报用例的支撑 Project”。我们的空间是 Palantir，我们的 Organization 是 Palantir，默认角色是 Viewer.

选择 创建 以创建新的 Project 并返回到 创建用例 弹窗。再次选择 创建 以创建您的用例并进入 用例概览 页面预览同步的数据。

了解更多关于 组织, 角色（role），以及其他 平台安全 概念。

第 2 部分：编辑元数据

创建用例和支撑 Project 后，您可以修改有助于定义用例的元数据。这些元数据包括用例名称、描述、所有者和状态。

此时，您的用例概览应如下所示：

默认情况下，您将是用例的技术所有者。在我们的示例中，我们使用的是 test 用户。

名称

如果您想更改用例的名称，可以在用例概览页面上进行。点击页面顶部的用例名称，并在文本字段中进行编辑。

描述

您可以通过点击描述并在文本字段中进行编辑，轻松更改用例的描述。

所有者

您可以为用例分配两种类型的所有者： 技术 和 业务.

  • 技术所有者： 技术所有者通常是应用程序构建者，负责使用 Foundry 资源为用例创建应用程序输出。
    • 您是用例的默认技术所有者。
  • 业务所有者： 业务所有者通常是跟踪用例工作流进度和财务细节的用户。
    • 您的用例没有默认分配的业务所有者。

要更改用例的所有者，请将鼠标悬停在名称或空白字段上，然后点击铅笔图标。这将打开一个搜索下拉列表，您可以在其中滚动浏览或搜索可用用户。由于我们的用例目前还没有业务所有者，我们现在将分配一个。

我们添加了用户 test2 作为我们用例的业务所有者。

状态

您可以为用例分配与其运营状态相关的状态：

  • 活跃： 已在您的 Foundry 实例中发布并运行。
  • 实验性： 正在进行中，尚未正式发布。
  • 已弃用： 不再运行。

在以下位置更改您的用例状态： Experimental to Active。点击状态下拉菜单，选择 Active，然后点击 更改状态.

第 3 部分：添加资源

现在我们已经创建了一个带有支撑 Project 的新用例，可以开始添加应用资源了。首先创建一个新的 Workshop 模块。

在您的用例概览页面中，找到 应用程序 部分（位于页面中间），然后点击 + 添加新应用。选择 Workshop 选项，然后点击 创建.

新的 Workshop 模块将被创建并打开。在这里，您可以为模块命名，并从各种小组件中进行选择以进行配置和使用。了解更多关于 创建交互式模块 这一全新界面让用户无需再编写复杂且容易出错的 Mapbox JSON 样式，即可将栅格图像添加到图层。取而代之的是，配置栅格图层只需指向地图瓦片服务器的 URL——请注意，管理员可能需要为该服务器地址范围配置网络

您可以 返回 到用例的信息，请点击 Workshop 模块名称左上角的标题。
