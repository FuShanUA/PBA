FAQ

如何知道某个对象类型何时已被索引到 OSv2？

Ontology Manager 应用程序有一个专用的管道图，显示 Funnel 管道中各个作业的状态。图中 Object Storage v2 节点上的绿色对勾表示索引已完成，该对象类型已准备好可以从 OSv2 进行查询。

为什么某个索引作业之前已成功注册到 Object Storage v1（Phonograph），却仍然可能失败？

OSv1 和 OSv2 的数据验证略有不同。

OSv1 的行为通常取决于底层数据存储的行为，因为它与底层分布式文档存储和搜索引擎紧密耦合。OSv2 具有更严格的验证，以确保进入本体论的数据质量，并提供比 OSv1 更确定的行为和更高的系统可读性。

因此，某些索引管道在使用 OSv2 时可能会遇到之前 OSv1 接受的验证错误。有关此类破坏性变更的详细列表，请参阅以下文档： OSv1 与 OSv2 之间的本体论破坏性变更.

某个作业失败了，但如果我重试可能会成功。如何触发重新构建？

OSv2 管理作业的各个方面，包括作业重试。如果作业由于暂时性错误而失败，且重新构建该作业可能会解决该错误，OSv2 将在大约五分钟后自动重试该作业。如果 OSv2 检测到该作业以终止性方式失败（例如由于数据格式无效），则只会在有新数据可用时才自动重试。对于由受限视图数据源支撑的对象类型，当数据或策略发生变化时会触发作业。

可以索引的数据大小是否有限制？

索引大小主要受限于给定对象类型被索引到的对象数据库的存储空间。例如，在 OSv2 数据存储中，这将是搜索节点的磁盘空间。

如果磁盘空间不足，索引作业将无法成功，并会在 Ontology Manager 应用程序的管道图中报告底层问题。如果遇到磁盘空间错误，请联系您的 Palantir 代表。

是否可以为以下对象类型大规模回填历史数据： 使用流式数据源的对象类型?

同步由流式数据源支撑的对象类型分为两个阶段：内部流创建和索引。流式索引作业的索引延迟与以下方式相当： Funnel 批处理管道，使用 Spark 对历史流式数据的初始处理进行高度并行化。此索引延迟与以下方式相当： 对实时本体论数据的用户编辑。内部流创建通常是限制因素；它利用我们的流式基础设施以逐条记录的方式处理数据源。

流式传输到本体论的预期延迟是多少？

以下操作中最耗时的部分是 Funnel 流式管道 中的 Flink 检查点操作，用于实现“恰好一次”的流式一致性。默认检查点频率为每秒一次，因此这是数据到达输入流与被索引到本体论之间的主要延迟。我们会持续进行实验，通过降低频率甚至完全移除检查点来评估成本/性能/延迟之间的权衡。

如有必要，请联系 Palantir Support 配置相关行为。

流式传输到本体论的预期吞吐量是多少？

每个对象类型索引到以下位置的吞吐量限制为 2 MB/s： Object Storage v2 对象数据库。如果您需要更高的索引吞吐量，请联系 Palantir Support。

在本体论中使用流式数据源时，是否可以指定用于对象去重的时间戳？

不， Funnel 流式管道 在索引时保留输入流的顺序。数据应按顺序写入流中。这可以在上游流式管道中通过按事件时间戳对数据进行窗口化并指定主键（使数据按哈希分区）来实现。

本体论流式处理是否支持变更数据捕获（CDC）工作流？

Funnel 流式管道 支持创建、更新和删除工作流。您可以在以下文档中找到有关如何设置删除元数据的更多信息 （CDC）同步。Db2 CDC 同步是通过 文档。

使用流数据源时，我可以向本体论写入部分行吗？我可以每次只更新部分属性，而不必提供整个对象吗？

目前不可以。解析整个对象应在上游管道中完成。如果 有状态流式处理 由于规模问题无法为您解决此问题，请联系 Palantir Support。

我可以将本体论流式处理用于 多对多关联类型?

是的，支持此功能。了解有关如何使用流数据源配置本体论类型的更多信息 请参阅我们的文档.

是否支持以下数据源的流式处理： 对象数据库 以外的 对象存储 v2 (物化 or 发布后，我们建议在，例如）？

本体论流式处理目前仅由 Object Storage v2 对象数据库支持。如果您需要在其他对象数据库中使用此功能，请联系 Palantir Support。

是否支持 物化 对于使用流数据源的对象类型？

不支持；由于使用流数据源的对象类型不支持用户编辑，物化数据集与流中的归档数据集没有区别。在当前架构下，无法提供数据集中的去重视图。

My Funnel 流式管道 始终在运行。我该如何取消它？

用户无法取消 Funnel 流式管道。Funnel 始终保持流的活跃状态，因为生产对象类型需要高可用性。这种设置在原型设计阶段可能会产生不必要的成本。如果这对您的用例造成重大阻碍，请联系 Palantir Support。或者，您可以在原型设计阶段尝试将对象类型切换为批处理类型。

如何在不停机的情况下将我的流数据源从一个流切换到另一个流？

Funnel 流式管道 有一种启发式方法，用于在切换到新流之前确定其管道是否已与替换流“保持同步”。您可以通过以下步骤将数据源更改为指向其他流或流的分支：

  1. 在单独的流（或另一个分支）上运行您的新逻辑。
  2. 等待新流完成回放，例如在所有历史记录处理完毕之后。
  3. 将您的对象类型输入数据源更改为新流。
  4. Funnel 流式管道将保持原始流上的实时管道运行，直到新流上的替换管道完成索引。
  5. Funnel 完成切换后，您就可以关闭原始流。

有哪些常见错误可能导致意外后果？

  1. 如果您的数据与预期不符，请确保输入流的顺序符合您的预期。
  2. Funnel 流式管道 执行与以下相同的验证： Funnel 批处理管道。但是，对于流式管道，由于流处理无法暂停，没有机制在用户转换中抛出错误，因此无效记录会被丢弃。

本体论流式处理的成本是多少？

Funnel 流式管道 计算资源的计算方式与普通流式资源相同。请查看我们的 流式计算用量 文档，以了解有关流式资源成本的更多信息。

保留窗口是如何工作的？

保留窗口最初是在测试版发布期间作为限制数据大小的机制而开发的。因此，它仅以尽力而为的方式实现。这意味着保留窗口内的对象将可查询，而窗口外的对象最终将被删除。例如，如果保留窗口设置为两周，而流数据源的某个对象最后一次由输入流更新是在三周前，则该对象可能会从该对象类型中删除。但是，该对象也可能在本体论中保留更多天，并且不保证在任何特定时间范围内被删除。

当前从本体论中"清理"旧数据的机制是通过 管道替换 来实现的，默认情况下每两周运行一次。替换时，Funnel 流式管道会从保留窗口的开头重新播放流，从而从本体论中删除较旧的对象。如果您需要更频繁地删除旧对象，请联系 Palantir Support。

如果未设置保留窗口，则输入流源中的所有数据都将被摄取到本体论中。

为什么我的流源以批处理方式建立索引，或者因重复错误而失败？

In 本体论管理器，您必须始终将输入数据源显式指定为流；这适用于具有流式数据源的对象类型以及 受限视图 由流支撑的对象类型。否则，您的数据源将回退为以标准 Funnel 批处理管道的方式建立索引。请查阅我们关于 配置流式对象类型 以了解更多详情。

我可以通过 本体论函数?

查询具有流式数据源的对象类型吗？是的， 查询本体论 对流式对象类型和批处理对象类型的工作方式相同。
