模型函数开发者指南

模型函数是自动生成的函数，可封装实时模型部署，使模型能够在 Workshop、 Vertex和其他最终用户应用程序中进行实时推理。模型函数具有与底层模型相同的输入和输出 API，可以通过 TypeScript、Python 调用，也可以直接在应用程序中使用。

本开发者指南介绍了模型函数的行为，包括版本更新、API 变更和配置选项。适用于通过以下两种部署发布的函数： 直接模型部署 和 Modeling Objective 实时部署。

有关如何在代码中导入和调用模型函数的说明，请参阅 模型上的函数。

先决条件

在发布模型函数之前，请确保您的模型满足 函数发布要求。

发布模型函数

模型函数可以通过以下两种类型的部署发布：

  • 直接模型部署： 在模型页面中，选择侧边栏中的 + 图标（需先 创建直接部署）。
    • 每个分支只能有一个函数来封装相应的部署。
  • Modeling Objective 实时部署： 在部署详情页面中，使用 Publish Function 卡片（需先 创建实时部署 ）将其封装为函数。

从建模目标发布时，系统将引导您完成为函数设置参数的过程。

两种方法都会生成功能等效的模型函数。它们是简单的包装器，将所有逻辑延迟到底层的实时部署，但会将模型 API 转换为函数可识别的输入和输出类型。

要了解如何在代码中导入并调用模型函数，请参阅 模型上的函数。

函数版本升级

本节介绍函数升级的行为，以及如何管理调用该函数的资源，尤其是在模型 API 发生变更的情况下。

直接模型部署：为每个版本自动发布函数版本

当在已发布函数的分支上发布模型的新版本时，也会自动创建关联函数的新版本。无需将调用该函数的资源更新到新的函数版本，除非模型 API 发生了变更， 如下所述。

虽然在给定仓库或应用程序中通常只能导入一个函数版本，但出于变更管理目的而希望将多个模型版本导入项目中的用户，可以通过在不同分支上发布多个函数来实现这一点，因为模型的每个分支上可以有一个部署和一个函数。

Modeling Objectives：如果 API 发生变化，则在发布后创建新版本

您不应忽略此警告。将正在运行的部署更新为具有不同模型 API 的新模型时，需要手动操作来修复下游使用。该对话框将引导您完成为受此发布影响的所有部署发布新函数版本的过程。

如果您选择不发布新的函数版本，当前函数版本的使用将会中断。要解决此问题，请返回该部署的 详情 页面并发布新的函数版本。

模型 API 变更

当模型 API 在不同版本之间发生变更时，必须更新消费者才能继续正常工作。这包括 TypeScript v1 函数和 Workshop 应用程序。模型函数使用函数支持的类型来镜像模型的 API。API 发生变更后：

  • 先前的模型函数版本将暴露不再与当前模型匹配的过时 API。
  • 函数和底层的实时部署都会根据当前 API 验证输入/输出。
  • 先前的模型函数版本将无法通过验证并停止工作，因为实时部署仅接受与新模型 API 版本匹配的输入/输出。

每次模型 API 发生变更后，您都应更新模型函数和应用程序。

逐行发布

对于具有单个表格输入和单个表格输出的模型，逐行发布会扁平化其函数 API，使每次函数调用仅处理单行数据而非数组。

对于单个表格输入到单个表格输出的模型，逐行函数发布默认处于启用状态。这意味着模型 API 恰好声明一个输入和一个输出，且两者均为表格类型。声明任何额外输入或输出的模型 API（例如一个表格输入外加一个 Parameter 输入）不符合逐行发布的条件，且已发布的函数将改为接受并返回数组。

逐行发布允许针对每次推理调用对模型 API 进行扁平化处理，使执行函数时以单行表格数据作为输入并输出单行表格数据。或者，可以考虑 在模型 API 中直接使用对象或 ObjectSet 以便在函数中更方便地将您的模型与对象结合使用。
