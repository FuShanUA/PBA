阶段 1：角色与职责

以下角色与职责是基于为各种规模和范围的使用案例和组织开发 Program 团队的经验而提出的建议。这些建议旨在概述在建立和扩展 Foundry Program 时经常面临的组织需求；根据您的需求和使用案例，这并不一定意味着您的组织必须始终设置每个角色。

项目负责人

职责

Foundry Program 成功的主要负责人和推动者，在整个组织内设定并传达 Foundry Program 的愿景。

  • 与高级利益相关者和相关高管密切合作，在 Foundry Program 与其他领导层之间保持反馈闭环。这包括汇报项目状态、吸收全组织战略，以及协作寻找通过 Foundry 在各组织间实现数字化转型的新机会。
  • 与平台和数据治理团队就使用案例治理进行协作，制定并执行相关流程，确保使用案例从启动和范围界定到发布和维护的整个过程中符合治理要求。
  • 通过与 计划经理 合作，设定项目流程和扩展需求的高层方向，并利用这一愿景指导各团队以及跨职能协作工作中的流程、治理和最佳实践。
  • 与领域负责人协作，根据项目的整体愿景和组织当时的战略，评估、确定优先级并批准或拒绝新的使用案例请求。

画像与所需技能

  • 通常直接向高级/高管发起人汇报
  • 经过验证的领导力和管理能力
  • 对全组织的愿景和战略有深刻理解
  • 具有战略背景及软件平台的有效开发经验
  • 出色的沟通者和激励者

计划经理

职责

  • 在各使用案例中标准化并推行 Foundry 开发最佳实践，与数据治理团队、平台团队和使用案例负责人密切合作，制定符合组织标准作业程序（SOP）和团队结构的实践。
  • 与 Program 负责人合作，负责跨职能沟通，并在其他组织纵向领域和项目领域负责人中推广 Foundry Program。这一层级的沟通通常比高级领导层和高管低一级。
  • 与跨职能利益相关者就变更、风险和资源管理框架进行协作。在阶段 1，这些框架可能是高层次的，主要由在这些业务领域（风险团队、人员配置团队、信息官）具有经验的外部利益相关者推动，但项目经理负责为项目创建并推广这些基本工件。随着项目的发展，这些工件的所有权可以移交给合适的负责人，例如 平台负责人 或 数据治理负责人.
  • 创建用于评估各使用案例内部及之间以及各团队绩效的框架。这包括设定和管理 OKR 与 KPI，并创建汇总报告，以记录项目不同部分的进展和改进机会。
  • 负责端到端的使用案例范围界定和开发，以推动价值提升和整体数字化转型。
  • 与工程师和应用开发人员密切协作，通过编写任务、绘制图表、工作流程和线框图、测试新功能和工作流程，以及在开发过程中与利益相关者沟通联络，交付并迭代需求。
  • 与领域负责人合作，确保技术和运营目标的一致性；就使用案例的目标和期望成果进行协作，并就一套商定的指标和报告达成一致，以监控进展和成功情况。

画像与所需技能

  • 具有管理跨职能项目的经验
  • 具有管理技术和组织项目并向高级/高管利益相关者汇报的经验
  • 出色的书面和口头沟通能力
  • 熟悉组织结构及其运作方式
  • 出色的领导力和组织能力

数据治理负责人

职责

  • 与合规、法务和数据保护（或类似团队）合作，确保法律法规和要求在 Foundry 中的数据处理方式中得到体现，包括敏感数据的处理方式
  • 专注于让数据可用，并符合内部和外部的数据质量标准及 SLA。
  • 负责数据治理要求的文档编制和维护，并在各工作流中传达这些要求。
  • 围绕数据治理流程构建监控和指标体系，并负责这些系统的持续报告和调整。
  • 与权限管理员和数据负责人合作，在项目权限中实施组和角色。针对常见项目类型创建文档和可复用的工作流，并建立工作流以支持针对各项目类型的数据治理要求的自助服务。
  • 在 Foundry 计划的所有工作流中实施数据治理审查流程。与团队负责人合作，了解其工作流需求和流程，并实施数据治理检查、要求和流程，以确保整个计划都符合数据治理标准。
  • 如有需要，与 Palantir 团队对接以获取支持服务交付；利用 Palantir 的资源（包括文档、顾问团队和支持服务），实施符合贵组织需求的数据治理计划，并配备充分的供应商支持体系。

在设立此角色时，使用 Foundry 中的隐私和公民自由 来阐明治理为何要从工作流的目的及其可能影响的人员开始。 实践指南 将有关最小化、访问、监督、问责和保留的规划问题映射到 Foundry 的功能。

在第一阶段，数据治理负责人这一角色通常可以由 数据负责人 或 本体论负责人兼任。但是，鉴于数据管理的规模以及工作流和用例的复杂性，我们建议最迟在第三阶段将其设为具有专门资源的独立角色。

画像与所需技能

  • 熟悉数据治理最佳实践和标准
  • 熟悉组织范围内的数据访问权限、法规和身份验证系统（例如 Okta 或 Active Directory）
  • 具备领导技术团队的经验
  • 编程技能（SQL、Python、PySpark/Spark）
  • 熟悉数据质量和版本控制的最佳实践
  • 熟悉代理/虚拟机
  • 出色的技术沟通者
  • 了解系统架构

  • 调度指标

数据负责人

职责

  • 负责 Foundry 与源系统之间的数据连接，确保所有连接干净、可靠且合规。
  • 创建并维护整个计划中数据摄取举措的优先级待办列表和路线图。与计划管理层合作，确保待办列表和路线图与整个计划的目标、战略和实施路线图保持一致。
  • 管理数据摄取和管道健康状况，包括制定计划范围内的数据摄取标准，以及确定并执行管道健康指标。
  • 监控数据质量和健康状况，包括元数据管理。在所有管道中设计和实施监控系统，并负责这些系统的报告和补救。
  • 专注于向用户提供数据，并符合内部和外部的数据质量标准及 SLA；这需要与用例团队以及 Foundry 计划内外的合规、安全、权限和数据治理团队密切合作。
  • 与数据保护官和合规团队（或类似团队）合作，确保法律法规和要求在 Foundry 中数据的处理和使用方式中得到体现，包括敏感数据的处理方式。
  • 与用例团队合作，寻找新数据获取的机会，并设计这些管道将如何实施以及如何集成到现有架构和结构中。
  • 建立并执行数据管道构建和数据集成设计的最佳实践。创建一套可传达给实施团队并大规模使用的指南和最佳实践。
  • 在管道设计中与权限管理员合作，在项目权限中实施组和角色，既包括新项目的设计，也包括现有项目的持续增长和维护。

画像与所需技能

  • 数据工程师技能（SQL、Python、PySpark/Spark）
  • 了解数据清洗和数据质量的最佳实践
  • 了解版本控制的最佳实践
  • 熟悉代理/虚拟机/系统连接
  • 能够在技术与非技术利益相关者之间进行沟通
  • 具备领导技术团队的经验

本体论负责人

职责

  • 管理本体论的开发和权限，包括定义本体论标准；在本体论中创建反映组织优先事项和结构的数据模型，并与实际运营和需求深度关联
  • 结合 Foundry 项目路线图制定并维护本体论路线图；负责本体论作为支撑所有用例和项目计划的 foundational 结构的长期演进愿景
  • 负责本体论的维护，并深入理解相关数据源，包括确保管道满足数据摄取和转换到本体论的标准，了解如何丰富管道内容以避免其过时和失效，并根据新用例、管道和数据源或用户提出的需求更新本体论
  • 与 数据治理管理员 and 数据负责人 密切合作，确保本体论开发计划的可行性和安全性。这包括在数据摄取和管理的设计与架构方面开展协作，将其作为本体论的数据填充来源，并确保在组织需求、这些需求如何且应当如何在本体论中表示，以及两者如何通过合规且功能完善的管道相互连接之间形成闭环。
  • 与领域负责人和用例团队合作，将概念映射到本体论；深度参与用例的规划和开发，确保用例范围内包含的所有与本体论相关的概念和想法都能按照本体论结构实施

画像与所需技能

  • 数据管道开发和管理技能
  • 出色的组织和文档编写能力
  • 具备数据库专业知识
  • 能够在技术与非技术利益相关者之间进行沟通
  • 具备领导技术团队的经验
