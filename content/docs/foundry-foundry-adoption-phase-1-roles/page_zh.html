阶段 1:角色与职责

以下角色和职责是基于为各类规模和范围的用例与组织组建项目团队的经验而提出的建议。这些建议旨在概述在建立和扩展 Foundry 项目时经常面临的组织需求;具体取决于您的需求和用例,这并不一定意味着您的组织必须始终为每个角色配备人员。

项目负责人

职责

Foundry 项目成功的主要负责人和推动者,在整个组织范围内制定并传达 Foundry 项目的愿景。

  • 与高级利益相关者和相关高管密切合作,在 Foundry 项目与领导层其他成员之间保持反馈循环。这包括汇报项目状态、吸纳组织整体战略,以及协作寻找通过 Foundry 在整个组织范围内实现数字化转型的新机遇。
  • 在用例治理方面与平台团队和数据治理团队开展协作,通过制定并执行相关流程,确保用例从初始构思和范围界定到发布和维护的全过程均符合治理要求。
  • 通过与相关方合作,为项目流程和扩展需求设定总体方向 项目经理 利用这一愿景来指导各团队内部及跨职能协作中的流程、治理和最佳实践。
  • 与领域负责人协作，根据项目的整体愿景和组织当时的战略，对新的用例请求进行评估、确定优先级，并予以批准或拒绝。

职位概况与所需技能

  • 通常直接向高级/高管发起人汇报
  • 经过验证的领导力和管理技能
  • 对组织整体愿景和战略的深刻理解
  • 在战略及软件平台有效开发方面的背景
  • 出色的沟通者和激励者

项目经理

职责

  • 在各用例中标准化并推行 Foundry 开发最佳实践，与数据治理团队、平台团队及用例负责人密切合作，制定符合组织标准操作流程（SOP）和团队结构的实践规范。
  • 与项目负责人协作，负责跨职能沟通，并向组织其他业务条线及项目领域负责人宣传推广 Foundry 项目。这一沟通层级通常比高级领导层和高管低一级。
  • 与跨职能利益相关者就变更、风险和资源管理框架展开协作。在第一阶段，这些框架可能较为宏观，且主要由在这些业务领域具有经验的外部利益相关者（风险团队、人员配置团队、信息官）推动，但项目经理负责为该项目创建并推广这些基本产物。随着项目的不断发展，这些产物的所有权可以移交给适当的所有者，例如 平台负责人 或 数据治理负责人。
  • 创建用于评估各用例内部及跨用例、各团队内部及跨团队绩效的框架。这包括设定和管理 OKR 与 KPI，并创建汇总报告，以记录项目不同组成部分的进展情况和改进机会。
  • 负责端到端的用例范围界定和开发，以推动价值提升和整体数字化转型。
  • 与工程师和应用程序开发人员密切协作，通过撰写任务、绘制图表、工作流程和线框图、测试新功能和工作流程，以及在整个开发过程中与利益相关者保持沟通，来交付需求并不断迭代。
  • 与领域负责人协作，确保技术和运营目标保持一致；共同确定用例的目标和预期成果，并商定一套指标和报告，以监控进展和成效。

简介与所需技能

  • 具备管理跨职能项目的经验
  • 具备管理技术和组织项目并向高级/高管级利益相关者汇报的经验
  • 出色的书面和口头沟通能力
  • 熟悉组织架构及其运作方式
  • 卓越的领导力和组织能力

数据治理负责人

职责

  • 与合规、法务和数据保护部门（或类似团队）协作，确保法律法规和相关要求在 Foundry 中的数据处理方式中得到体现，包括敏感数据的处理方式
  • 专注于确保数据可用，并符合内部和外部数据质量标准及 SLA。
  • 负责数据治理要求的文档编制和维护，并在各工作流中进行传达。
  • 围绕数据治理流程建立监控和指标体系，并负责这些系统的持续报告与调整。
  • 与权限管理者和数据负责人合作，在项目权限中实施组和角色。针对常见项目类型创建文档和可重复的工作流程，并制定相应工作流程，使用户能够自助满足适用于每种项目类型的数据治理要求。
  • 在 Foundry 计划的所有工作流中实施数据治理审查流程。与团队负责人合作，了解其工作流需求和流程，并实施数据治理检查、要求和流程，以确保整个计划符合数据治理标准。
  • 如有需要，可与 Palantir 团队对接以交付支持服务；利用 Palantir 资源（包括文档、咨询团队和支持服务），结合贵组织的需求实施数据治理计划，并确保建立起充分的供应商支持体系。

在第 1 阶段，数据治理主管这一角色通常可由 数据负责人 或 本体论负责人担任。但是，鉴于数据管理的规模以及工作流程和用例的复杂性，我们建议最迟在第 3 阶段将其设为配有专门资源的独立角色。

概况与所需技能

  • 具备数据治理最佳实践和标准方面的知识
  • 熟悉组织范围内的数据访问权限、法规和身份验证系统（例如 Okta 或 Active Directory）
  • 具备领导技术团队的经验
  • 编程技能（SQL、Python、PySpark/Spark）
  • 了解数据质量和版本控制的最佳实践
  • 熟悉代理 / 虚拟机
  • 出色的技术沟通能力
  • 了解系统架构

数据负责人

职责

  • 负责 Foundry 与源系统之间的数据连接，确保所有连接干净、可靠且合规。
  • 创建并维护涵盖整个项目的数据摄取举措的优先级待办事项列表和路线图。与项目领导层协作，确保待办事项列表和路线图与更广泛的项目目标、战略和实施路线图保持一致。
  • 管理数据摄取和管道健康状况，包括设定整个项目范围的数据摄取标准，以及确定和执行管道健康指标。
  • 监控数据质量和健康状况，包括元数据管理。设计并实施覆盖所有管道的监控系统，并负责这些系统的报告和补救工作。
  • 专注于让数据可供用户使用，并确保符合内部和外部的数据质量标准与 SLA;这涉及与用例团队以及合规、安全、权限和数据治理团队(包括 Foundry 计划内部和外部的团队)的密切合作。
  • 与数据保护官和合规团队(或类似团队)合作，确保相关法律和要求体现在 Foundry 中数据处理和使用的方式上，包括处理敏感数据的方法。
  • 与用例团队合作，识别获取新数据的机会，并设计这些管道的实施方式以及如何将其集成到现有架构和结构中。
  • 建立并推行数据管道构建和数据集成设计方面的最佳实践。创建一套指南和最佳实践，以便大规模地传达给实施团队并供其使用。
  • 在管道设计方面与权限管理员合作，在项目权限中实施组和角色，涵盖新项目的设计以及现有项目的持续发展和维护。

个人简介和所需技能

  • 数据工程师技能(SQL、Python、PySpark/Spark)
  • 熟悉数据清洗和质量方面的最佳实践
  • 熟悉版本控制方面的最佳实践
  • 熟悉代理 / 虚拟机 / 连接系统
  • 在技术和非技术利益相关者之间进行沟通的能力
  • 领导技术团队的经验

本体论负责人

职责

  • 管理本体论的开发和权限，包括定义本体论标准；在本体论中创建数据模型，使其反映组织的优先事项和结构，并与实际运营情况和需求深度关联
  • 结合 Foundry 项目路线图制定并维护本体论路线图；负责本体论作为支撑所有用例和项目举措的基础结构不断演进的长期愿景
  • 负责本体论的维护并深入了解相关数据源，包括确保管道满足向本体论摄取和转换数据的标准、了解如何丰富管道以避免其变得陈旧过时，以及根据新的用例、管道和数据源或用户主导的请求更新本体论
  • 密切配合 数据治理管理员 和 数据负责人 以确保本体论开发举措的可行性和安全性。这涉及就数据摄取和管理的设计与架构开展协作，将其作为本体论的水合源，并确保在组织需求、这些需求能够且应当如何在本体论中表示，以及两者如何通过合规且能正常运行的管道相互连接这三者之间形成闭环。
  • 与领域负责人和用例团队合作，将概念映射到本体论；深入参与用例的范围界定和开发，以确保用例范围内包含的所有与本体论相关的概念和想法都能按照本体论结构加以实现

个人简介和所需技能

  • 领导技术团队的经验
