对象表格

直方图 对象表格 小部件用于以表格形式显示对象数据。配置对象表格小部件的模块构建者可以使用以下功能：

  • 在一个或多个对象类型上显示数据。
  • 选择要显示的列，包括使用时间序列属性的时间序列列，以及通过函数即时生成的派生列。
  • 按一个或多个列进行排序。
  • 设置列宽和行高。
  • 显示在 Ontology Manager 中配置的条件格式和数字格式选项。
  • 允许在表格中进行单选或多选。
  • 行内编辑，支持在表格内进行单元格级别的回写。
  • 在表格中选择行时触发 Workshop 事件。
  • 在右键菜单中添加自定义行操作。

配置选项

对于对象表格小部件，核心配置选项如下：

  • 输入数据

    • 导入对象集： 这是对象表格小部件的输入变量，用于确定将在对象表格中显示的数据。这允许模块构建者定义新的对象集变量，或复用在此 Workshop 模块其他位置创建的现有对象集变量。

  • 列配置

    • 使分区垂直拆分，从而在模块中有效地创建一个新列。 此部分确定将在对象表格中显示的列。一旦对象集填充完毕，此配置选项会展开显示初始对象集中的属性类型。此外，特殊列类型允许模块构建者显示关联对象、参数化 URL 链接、时间序列数据以及通过函数即时生成的派生列。处于 要在标记和发布函数的过程中查看进度，请选择 模式的用户也可以选择配置显示给他们的列。通过选择 配置列 （位于列标题旁边的箭头菜单中），查看者可以选择要在对象表格中显示的列及其显示顺序。请查看 时间序列属性 部分以了解有关时间序列数据的更多信息，以及 函数支撑列 部分以了解如何配置派生列。

      显示的列名是一个文本字段，默认为添加时对象类型的属性名称。 如果对象类型的属性名称稍后在 Ontology 中被更新，对象表格中显示的列名不会自动更改。

    • 派生属性： 派生属性 在模块级别配置的属性可以作为列显示在对象表格中。这些属性在运行时基于关联对象值或聚合计算得出。请参阅 派生属性文档 以了解配置详情和支持的小部件。

    • 不支持的属性类型： 某些大型属性（例如 Geoshape 和 Vector）默认不加载，以保持性能。在查看模式下，用户可以选择单元格上的 "..." 溢出菜单以按需加载不支持的属性值。在小部件编辑器中，不支持的属性会带有警告图标和工具提示，以指示潜在的性能影响。

    • 启用行内编辑： 启用后，此开关允许在对象表格中配置单元格级别的编辑。请参阅 行内编辑（单元格级别回写） 部分以了解有关如何配置此高级功能的更多信息。

    • 默认排序： 此设置允许对表格应用一个或多个默认排序。模块构建者可以对表格中显示的可见属性类型或未显示的隐藏属性类型进行排序。如果未应用排序，则数据不会排序。我们建议在必要时指定排序。

    • 变量支撑的可见性和顺序： 启用后，允许使用包含可见列 API 名称的字符串数组变量来控制哪些列可见。此数组变量还控制列的显示顺序。如果字符串数组为空，则表格中将显示所有已配置的列。

    • 隐藏列配置： 启用后，隐藏 配置列 选项（该选项存在于视图模式下的表格标题菜单中）。

  • 右键菜单

    • 启用导出为 CSV： 启用后，此开关允许用户通过行的右键菜单将对象表格数据导出为 CSV 格式。此功能支持导出函数支撑的列和关联对象属性，并且一次最多可导出 10,000 行。
    • 启用导出为 Excel： 启用后，此开关允许用户通过行的右键菜单将对象表格数据导出为 Excel 格式。此功能一次最多可导出 200,000 行。
      • 在导出中使用自定义列名： 启用后，导出的 Excel 文件将使用用户定义的列名，与所配置的对象表格中显示的列名一致。禁用后，导出的文件将使用底层属性 API 名称作为列标题。
    • 自定义右键菜单： 此选项允许模块构建者通过自定义操作配置行的右键菜单。请参阅 自定义右键菜单 部分，以了解有关如何配置此功能的更多信息。

  • 点击

    • 活动对象： 这是对象表格中两个输出变量中的第一个，输出当前活动/高亮对象的对象集。此对象集随后可用于当前模块中的下游小部件。
    • 禁用活动对象自动选择： 默认情况下，表格中的第一行会在加载时被自动设置为活动对象。禁用此设置可阻止该行为，使加载时活动对象为空。自动选择通常在小部件变为可见时发生；例如，如果对象表格位于折叠的部分中，则在该部分展开之前不会发生自动选择。如果小部件使用 Eagerly mount or Never unmount 显示优化，则自动选择可能会在小部件隐藏时发生。
    • 启用多选： 启用后，此开关允许在表格中勾选/选择多个对象，并通过 此选项输出当前所选对象的对象集。随后可以在当前模块内的下游小组件中使用此对象集。 对象集变量输出。
    • 选定对象： 这是对象表格中两个输出变量中的第二个，输出当前勾选/选择的对象的对象集。此对象集随后可用于当前模块中的下游小部件。注意：仅当 启用多选 开关设置为 true 时，才会使用并填充此输出变量。
    • 活动对象选择时： 此选项允许模块构建者配置 Workshop 事件，以便在表格中选中某一行时触发（例如，使带有更详细对象视图的抽屉面板出现）。

  • 显示与格式设置

    如果您的对象具有存储图像 URL 的属性，您可以添加类型类 hubble:icon 以显示该图像，而不是在设置对象类型时选择的图标。此功能允许您在数据旁边显示图形符号或图像。

    • 每行显示的行数： 此数字控制每个表格行的高度。
    • 启用值换行： 启用后，允许文本内容在单元格内换行。此选项支持结构体属性以及结构体属性数组的换行。当内容过长而无法完整显示时，结构体值将显示省略号截断，并在悬停工具提示中显示完整值。
    • 冻结列数： 此数字决定固定在表格左侧的冻结列数，当用户向右滚动时这些列将保持可见。
    • 空状态消息： 配置当支撑小部件的对象集为空时小部件显示的内容。默认情况下 默认值，小部件将显示通用表格图标以及“未找到对象”消息。要自定义显示的图标和消息，请选择 您可以使用顶部导航栏中的时间范围选择器来配置指标显示的时间段。可用的预设选项包括一天、两天、七天、14 天和 30 天。您还可以选择 option.
    • 自定义“无值”显示： 启用后，当单元格没有值时，将覆盖表格中显示的内容。默认情况下，将显示“无值”。
    • 合并多个对象类型： 此设置仅影响显示多个对象类型的表格。禁用时，每个对象类型将显示在各自的选项卡中。启用时，所有对象类型将显示在单个表格中，并且在跨对象类型的情况下，显示名称和 ID 均相同的属性类型将合并为单个列。此选项在 启用行内编辑 设置为 true 时不可用。
    • 水平适应列宽： 启用后，列将自动调整大小以填满表格的当前宽度。
    • 启用窄表头： 启用后，表格表头将从 50 像素缩小到 30 像素。
    • 条件格式化为整个单元格着色： 启用后，条件格式化将为整个单元格着色。注意：条件格式化在 Ontology Manager 中为普通属性类型进行配置，而对于函数支撑的属性，则在对象表格（Object Table）小部件配置面板中进行配置。
    • 显示安全标记： 启用后， 属性安全标记 将以浓缩的灰色胶囊形式呈现，选中时会展开窗口视图。
    • 无障碍标签： 提供一个非空标签（使用静态文本或字符串变量），以便向屏幕阅读器标识该表格。这还会将底层表格实现切换为专为增强无障碍功能而设计的实现。

  • 场景

    • 从中加载数据的情景： 选择要为对象表格（Object Table）加载数据的情景。此输入还会影响对象表格中显示的对象及其各自的顺序。
    • 与情景进行比较： 启用此开关以选择要比较数据的情景数组变量。这会将表格中的数据与数组中各情景的值进行比较，在有修改的列中并排显示这些值。
    • 有关构建自定义主题的示例，请参阅 分类轴 的文档以获取更多信息。

保存用户列配置

要保存用户的列配置，请按照以下步骤使用带有状态保存的字符串数组变量：

  1. 确保 状态保存已启用.
  2. 在控制面板中启用 变量支撑的可见性和顺序 并使用一个新的静态字符串数组变量（该数组变量可以为空）。这将存储哪些列可见以及它们的顺序。
  3. 在 设置 面板中为字符串数组变量添加外部 ID，并确保启用它以用于状态保存。

函数支撑的列

本节中的教程引用了 Flight Alert 对象类型，该对象类型在您的 Foundry 环境中可能不可用。请将其作为指南，然后使用您 Foundry 实例中类似的对象类型进行操作。要了解有关函数的更多信息，请参阅专门的 函数文档.

摘要

要创建返回一个或多个函数支撑列的函数，您需要满足以下规范：

  1. 函数的输入参数必须包含一个 ObjectSet<ObjectType> 参数（并且可以选择包含其他输入参数）。此 ObjectSet<ObjectType> 参数将使表格中显示的对象能够传入函数，从而生成所需的派生列。一个 ObjectType[] 参数在这里也适用，但并不推荐这种性能较低的选项。

  2. 函数的返回类型必须是从对象类型到值或自定义类型的映射，使函数能够返回对象到值或自定义类型的映射，该映射可以包含一个或多个字段：

    • In TypeScript v2中名字为 'John' 的所有人的年龄求和，请使用 FunctionsMap<ObjectType, CustomType>.
    • In Python中名字为 'John' 的所有人的年龄求和，请使用 Record<ObjectSpecifier<ObjectType>, CustomType>.
    • In 或中名字为 'John' 的所有人的年龄求和，请使用 dict[ObjectType, CustomType].

    了解有关自定义类型的更多信息。

一旦满足上述条件的函数配置并发布，您就可以在对象表格（Object Table）配置中成功配置函数支撑的属性列。请参阅 有关如何思考问题类别并识别它们的更多细节 以获取更详细的教程。

函数支撑属性的功能

对象表格（Object Table）小部件支持显示通过函数实时计算的函数支撑属性。这为模块构建者提供了极大的灵活性，可以显示例如以下列：

  • 计算两个或多个其他属性之间的和、差或其他数学运算。
  • 展示根据 Workshop 模块中其他位置的数据输入而更新的统计模型输出。
  • 显示来自关联对象的属性
  • 根据 Workshop 模块中其他位置的用户输入更改显示内容。

    public flightAlertCalculateUrgency(flightAlerts: ObjectSet<FlightAlertWorkshopTutorial>):

        flightAlerts.all().forEach(flightAlert => {
            var hoursDelayed = flightAlert.timeOfDelayHours
            if (hoursDelayed! > 4) {

            }
            else if (hoursDelayed! > 2) {
                map.set(flightAlert, "Medium")
            }
            else {
                map.set(flightAlert, "Low")
            }
        });
        return map;
    }
}

import { ObjectSet, ObjectSpecifier } from "@osdk/client";
import { FlightAlertWorkshopTutorial } from "@ontology/sdk";

async function flightAlertCalculateUrgency(
    flightAlerts: ObjectSet<FlightAlertWorkshopTutorial>
): Promise<Record<ObjectSpecifier<FlightAlertWorkshopTutorial>, string>> {
    const map: Record<ObjectSpecifier<FlightAlertWorkshopTutorial>, string> = {};
    for await(const flightAlert of flightAlerts.asyncIter({"$select": ["timeOfDelayHours"]})) {
        const hoursDelayed = flightAlert.timeOfDelayHours;
        if (hoursDelayed! > 4) {
            map[flightAlert.$objectSpecifier] = "High";
        } else if (hoursDelayed! > 2) {
            map[flightAlert.$objectSpecifier] = "Medium";
        } else {
            map[flightAlert.$objectSpecifier] = "Low";
        }
    }
    return map;
}

export default flightAlertCalculateUrgency;

@function
def flight_alert_calculate_urgency(
    flight_alerts: FlightAlertWorkshopTutorialObjectSet,
) -> dict[FlightAlertWorkshopTutorial, str]:
    result = {}
    for flight_alert in flight_alerts.iterate():
        hours_delayed = flight_alert.time_of_delay_hours
        if hours_delayed is not None and hours_delayed > 4:

import { Function, FunctionsMap } from "@foundry/functions-api";
import { AirportObject, FlightAlertWorkshopTutorial, ObjectSet } from "@foundry/ontology-api";

export class MyFunctions {
    @Function()
    public getColumnsFromLinkedDepartureAirport(flightAlerts: ObjectSet<FlightAlertWorkshopTutorial>):
    FunctionsMap<FlightAlertWorkshopTutorial, LinkedDepartureAirportProperties> {
        // Fetch all linked airports and store in dictionary, keyed by iata
        const iataToAirport: { [iata: string]: AirportObject } = {};
        flightAlerts.searchAroundDepartureAirport().all().forEach(airport => {
            iataToAirport[airport.iata!] = airport;
        });

        const map = new FunctionsMap<FlightAlertWorkshopTutorial, LinkedDepartureAirportProperties>();
        flightAlerts.all().forEach(alert => {
            // Get airport for this alert
            const airport = iataToAirport[alert.departureAirportCode!];
            // Skip if airport not found
            if (!airport) {
                return;
            }

            map.set(alert, {
                airport: airport.airport!,
                city: airport.city!,
                country: airport.country!,
            });
        });

        return map;
    }
}

import { ObjectSet, ObjectSpecifier, Osdk } from "@osdk/client";
import { AirportObject, FlightAlertWorkshopTutorial } from "@ontology/sdk";

async function getColumnsFromLinkedDepartureAirport(
    flightAlerts: ObjectSet<FlightAlertWorkshopTutorial>
): Promise<Record<ObjectSpecifier<FlightAlertWorkshopTutorial>, LinkedDepartureAirportProperties>> {
    // Fetch all linked airports and store in dictionary, keyed by iata
    const iataToAirport: { [iata: string]: Osdk.Instance<AirportObject, never, "iata" | "airport" | "city" | "country"> } = {};
    for await(const airport of flightAlerts.pivotTo("departureAirport").asyncIter({"$select": ["iata", "airport", "city", "country"]})) {
        iataToAirport[airport.iata!] = airport;
    }

    const map: Record<ObjectSpecifier<FlightAlertWorkshopTutorial>, LinkedDepartureAirportProperties> = {};
    for await(const alert of flightAlerts.asyncIter({"$select": ["departureAirportCode"]})) {
        // Get airport for this alert
        const airport = iataToAirport[alert.departureAirportCode!];
        // Skip if airport not found
        if (!airport) {
            continue;
        }

        map[alert.$objectSpecifier] = {
            airport: airport.airport!,
            city: airport.city!,
            country: airport.country!,
        };
    }

    return map;
}

export default getColumnsFromLinkedDepartureAirport;

from functions.api import function
from ontology_sdk.ontology.objects import AirportObject, FlightAlertWorkshopTutorial
from ontology_sdk.ontology.object_sets import FlightAlertWorkshopTutorialObjectSet

@function
def get_columns_from_linked_departure_airport(
    flight_alerts: FlightAlertWorkshopTutorialObjectSet,
) -> dict[FlightAlertWorkshopTutorial, LinkedDepartureAirportProperties]:
    # Fetch all linked airports and store in dictionary, keyed by iata
    iata_to_airport: dict[str, AirportObject] = {}
    for airport in flight_alerts.search_around_departure_airport().iterate():
        iata_to_airport[airport.iata] = airport

    result: dict[FlightAlertWorkshopTutorial, LinkedDepartureAirportProperties] = {}
    for alert in flight_alerts.iterate():
        # Get airport for this alert
        airport = iata_to_airport.get(alert.departure_airport_code)
        # Skip if airport not found
        if airport is None:
            continue

        result[alert] = LinkedDepartureAirportProperties(
            airport=airport.airport,
            city=airport.city,
            country=airport.country,
        )

    return result

内联编辑（单元格级写回）

摘要

启用内联编辑后，模块用户可以修改对象表中显示的单元格级数据，然后将这些编辑保存到对象数据中。编辑选项通过在 操作 本体论中配置的 操作内联编辑文档 进行定义；有关内联编辑的更多注意事项，请参见该文档。要与内联编辑兼容，操作必须满足以下条件：

  • 该操作应使用单个“修改对象”规则，或由函数支撑。
  • 操作中所有被修改的属性必须定义为“来自参数”（而非“作为静态值”或“来自对象参数的属性”）。
  • 属性参数必须是单一的基本类型（例如，布尔值、整数或字符串，而不是对象引用或数组）。
  • 参数的可见性选项不应设置为“隐藏”（因为每个参数都将关联到表中的一个可见列）。

其他注意事项：

  • 如果某个参数定义了用户可从中选择的枚举值，则在用户修改该参数时，这些选项将被保留并显示在单元格内的下拉列表中。
  • 如果某个参数或操作具有验证条件（例如，某个数字参数必须介于 1 和 10 之间），则将强制执行这些验证条件。
  • 在内联编辑期间，参数的显示选项将不会被保留（例如文本输入与文本区域）。
  • 为了获得更简便的配置体验，操作参数 ID 应与表中显示的属性 ID 相匹配。这样可以自动将操作参数映射到表列。
  • 为了保持显示一致，应使用本体论中的 Multipass 值格式将 Multipass 用户参数映射到列/属性类型。有关值格式的更多信息，请参见 本体论文档.
