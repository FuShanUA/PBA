宣布推出支持 Webhook 的 REST API 源

发布日期:2023-05-26

REST API Webhook 现已正式发布。您现在可以使用直接云连接以及专用于构建请求的用户界面来创建 Webhook。此外,REST API 源还支持代理(Agent),另外,如果您希望构建按顺序连续执行的链式 Webhook 请求,还可以指定多个域名。新源在“源创建”页面上显示为“REST API”,并且平台内教程介绍了如何将 Webhook 与此源类型结合使用。该 Webhook 教程 已更新,同时还提供了一个 消歧义页面 ,其中涵盖了 REST 连接的所有选项。

请注意,REST API 源的直接连接需要 网络出口管理 且需通过控制面板在您的环境中启用。如有关于您环境出口管理的任何疑问,请联系您的管理员。

使用 REST API Webhook

要使用 REST API webhook，请先在 Data Connection 中创建“REST API”源。然后，提供基本 URL 和身份验证机制，以及出口或代理配置。 除了利用新增的云运行时和直接连接支持外，您还可以考虑使用代理，或在必要时指定多个域，以构建连续执行的链式 webhook 请求。

创建源后，您可以使用新的请求构建器构建 webhook，然后将其接入 Actions 或 Workshop。请求构建器支持：

  • 对相对 URL 路径、标头、查询参数和请求体进行参数化。
  • 请求体以表单输入、表单 URL 编码、原始 JSON 或二进制附件的形式提供。
  • 从 Data Connection UI 测试连接。
  • 链式请求，包括从某个请求的响应中提取值，以供后续请求使用。
  • 使用出站应用进行 OAuth2 授权。请联系您的 Palantir 代表启用此功能。

涉及 REST API 的同步、导出和其他功能

目前，REST API 源类型仅支持 webhook。如果您正在使用 webhook，则应使用新的 REST API 源。

  • 若要对可通过互联网访问的源执行同步或导出，您应使用 外部转换。
  • 否则，对于同步或导出到本地部署源的情况，请继续使用 magritte-rest-v2。

代码工作区：Foundry 的强大功能，现可通过第三方 IDE 使用

发布日期：2023-05-26

借助代码工作区，数据科学家、分析师、统计学家和机器学习工程师可以使用 JupyterLab® 和 RStudio® Workbench IDE，同时享受 Palantir Foundry 平台的优势。代码工作区将 Foundry 本体论 的强大功能以及 Palantir 一流的安全性、分支和资源管理能力带入数据科学和机器学习工作流。

兼具熟悉的第三方 IDE 与 Foundry 安全性

代码工作区为用户打造了熟悉的体验，同时保持了 Foundry 强大的 安全功能。无需将数据下载到本地 notebook，也无需手动构建从数据湖到 HPC 或 SaaS ML 平台的连接器，您现在可以直接在 Foundry 中处理数据，并降低数据传输的复杂性和数据泄露的风险。Foundry 支持的第三方 IDE 与 Foundry 安全性的核心组件相绑定：在 Foundry 中限制对数据集的访问权限，也会限制代码工作区 IDE 的访问权限，从而确保各工具之间的权限一致。

Foundry 用户现在可以使用 JupyterLab® 或 RStudio® Workbench 对 Foundry 中的数据进行读取和写入、安装软件包并利用版本控制。此集成支持 数据血缘 以及仪表板的分支功能，同时配备专为企业级隐私和安全而构建的功能。现在，生产和开发工作流可以在同一平台上以相互隔离的方式执行，从而加速运营化：例如，您可以在一个分支上使用该分支的数据构建仪表板，待仪表板通过适当验证后再将其合并到主分支。

借助 Foundry 的强大功能开展数据科学

Foundry 用户可以使用代码工作区进行协作、迭代和快速构建，从而实现工作流运营化。代码工作区还支持与 Python 和 R 相关的仪表板和工作流构建。

通过将所有内容托管在 Foundry 中，随时可能在同一个代码库上协同工作的团队也能获得顺畅的协作体验。与 Git 工作流类似，不同技术背景的用户可以根据权限在分支上提出更改。所有用户都可以受益于仪表板的数据血缘视图以及完善的编辑并发体验。此外，数据科学家还可以受益于统一的代码工作区界面中直观的软件包和资源配置文件管理。

我应该在什么时候使用代码工作区？

代码工作区为平台管理员提供了一种易于部署、完全托管、安全且生产就绪的方式，用于向用户提供 JupyterLab® 和 RStudio® Workbench，同时内置了 Foundry 的数据治理以及对 FedRAMP、GxP 和其他标准的合规支持。借助代码工作区，用户可以安全地连接到现有内部系统，并在 Foundry 的访问控制和数据权限管理下，基于数据构建分析、模型、仪表板或完整的工作流。

随着代码工作区的推出，运营化仅一步之遥。现在，您可以使用熟悉的 IDE 调用模型并将其发布到本体论，还可以构建在分支上开发、符合治理规范的仪表板，这些仪表板会在有新数据可用时自动刷新。

要开始构建，请查阅 代码工作区文档。

对象存储 v2 现已正式发布

发布日期：2023-05-26

Palantir 很高兴地宣布，Foundry 新一代本体论架构现已正式发布。 对象存储 v2（OSv2） 是对支撑 Foundry 本体论的后端基础设施的全面重构。OSv2 旨在取代 对象存储 v1（Phonograph） 长期架构，并提供了以多种数据存储类型并行支撑对象存储的灵活性，从而随着 Foundry 的发展，满足查询模式、性能或规模方面的需求。

OSv2 为 Foundry 带来了许多新功能，并在规模和性能方面实现了显著改进，同时提供了支持 Foundry 本体论持续增长和投入的架构。

规模、性能和延迟方面的改进

对象存储 v2 为 Foundry 带来了多项规模、性能和延迟方面的改进：

  • 通过默认为所有对象类型启用增量对象索引，显著提升了本体论数据索引的性能。
  • 索引规模提升，单个对象类型可支持数百亿量级的对象实例。
  • 提升了用户编辑吞吐量，支持在单个操作中编辑多达 10,000 个对象。如果需要启用更高的限制，请联系 Palantir 支持团队，为您的注册创建变更请求。
  • 降低了用户编辑延迟，在前端应用中可以更快地观察到用户编辑，并且用户编辑会近乎实时地自动传播到 物化对象数据集。

新能力

OSv2 的新能力包括：

  • 能够 迁移现有用户编辑 在对象类型定义发生破坏性架构变更后。

  • 更细粒度的对象权限，依托 多数据源对象类型，支持列/属性级别的权限。

其他新功能包括：

  • 当显式配置的对象类型接收到新数据或用户编辑时，Workshop 支持自动刷新模块。
  • 无限分页端点使本体论消费者能够加载超过 10K 个对象，对于通过 API 与 Foundry 本体论交互的应用程序开发者而言尤其有价值。

迁移到 OSv2

Foundry 提供了强大的 自助迁移工具 ，该工具位于本体论管理器中，可在不造成任何停机的情况下选择性地将对象类型从对象存储 v1（Phonograph）迁移到 OSv2。对象存储 v1（Phonograph）并未被弃用或移除，但鉴于 OSv2 拥有更强大的功能集和长期产品路线图，建议所有新对象类型均使用 OSv2。

详情请参阅 对象存储 v2 文档。

Foundry 访问的仅消费者模式

发布日期：2023-05-26

通过 Foundry 全新的仅消费者模式，为单一应用程序用户配置简化的体验。Foundry 现在支持强大的配置功能，可将特定用户组的体验限制为仅其被授予权限的自定义应用程序。在此受限视图中，导航侧边栏不会显示，因为这些用户本就不应离开这些特定的应用程序。

在控制面板的 Foundry 套件 配置中，现在有一项配置可以 限制平台访问。默认情况下，此配置设置为"此组织中的所有人"，从而保持当前行为。

或者，现在可以仅向特定群组授予平台访问权限，而其他用户将只能访问其被明确授予访问权限的、使用 Slate 或 Workshop 构建的面向消费者的应用程序。在没有平台访问权限的情况下，这些用户将不再看到 Foundry 侧边栏，也无法导航至 Foundry 的其他部分。

通过此配置，可以为无需访问整个 Foundry 的用户提供真正独立的自定义应用程序体验。有关配置此类受限访问的更多信息和指南，请查阅控制面板 工作区 文档。

Quicksearch 简介：快速搜索与导航

发布日期：2023-05-11

Quicksearch 是一款用于搜索、导航和发现的新工具，旨在让在 Foundry 中查找资源和导航变得快速而愉悦。Quicksearch 交互有以下两种新模式：

  1. 跳转模式 根据近期历史记录提供简短的个性化结果列表，帮助您直接在 Foundry 中导航，并在平台应用程序、自定义应用程序、对象、数据集和其他资源之间切换。
  2. 完整结果模式 帮助您查找内容并探索 Foundry 中已有的资源。使用高级筛选器、丰富的元数据和改进的结果排名搜索 Foundry 应用程序、对象、数据集和其他资源，突出显示最相关的结果。

跳转模式

使用 Quicksearch 键盘快捷键和跳转模式，无需伸手去拿鼠标，即可在 Foundry 中飞速导航：

  • 易于访问： 如需打开 Quicksearch，请选择 搜索... （位于 Foundry 侧边栏中）或使用键盘快捷键 *Ctrl+J (Windows) 或 Cmd + J (macOS)。
  • 易于访问： 如需打开 Quicksearch，请选择 搜索... （位于 Foundry 侧边栏中），或使用 Ctrl + J （在 Windows 上）或 ⌘ + J （在 macOS 上）。
  • 以导航为核心： 初始对话框和下拉菜单以导航为导向。开始键入即可获得建议。使用键盘可在数秒内跳转到任何 Foundry 页面。
  • 仅在标题中搜索： 跳转模式仅搜索应用程序、资源和对象的标题。如需搜索其他字段和元数据，请使用完整结果模式。
  • 一键直达完整结果： 在对话框和下拉菜单中，按下 Enter/Return ，或按以下类型筛选： 应用程序、 对象、 数据集或 文件 以切换到高级搜索模式。
  • 个性化结果： Quicksearch 中的结果会根据您最近访问或收藏的资源等信息进行个性化。

完整结果视图

探索 Foundry 数据、应用程序和资源，以发现相关的工作成果：

  • 以发现为核心： 专为搜索和发现而设计，用户可以比较多个搜索结果，找到对自己最有用的资源。
  • 在多种字段中进行搜索： 可搜索描述、列名、文件路径等。此外，还可以按创建者、标签、项目、文件夹等进行筛选。
  • 标签页： 该界面包含一个最佳结果标签页和四个可按以下类型筛选的标签页： 应用， 对象， 数据集，或 文件
  • 元数据： 用户可以查看每个结果的信息，以评估该资源是否与自己相关。可查看的信息包括搜索关键词高亮、文件路径、查看次数、最近更新时间、关键安全元数据等。
  • 排名： 结果会根据包含文本匹配和其他权重提升参数的算法进行排名。
  • 筛选器： 高级搜索中提供了筛选器。此外，通过在初始搜索下拉菜单中选择筛选器标签页，用户可以执行复杂的筛选搜索（例如，“项目 X 下由我创建的所有报告”）。
  • 权限： Quicksearch 遵循 Foundry 中的所有现有权限。具有 Discover 权限的内容将打开一个 Request access 消息。用户将看不到其无权访问的内容。

应用程序门户简介

发布日期：2023-05-11

应用程序门户 是一款用于发现和快速访问 Foundry 中所有应用程序的新工具，包括 Foundry 核心平台应用程序以及由平台管理员推广至门户的受信任自定义应用程序。

应用程序门户从 Foundry 侧边栏启动，打开后会显示所有应用程序的视图，并提供其他类别用于浏览平台应用程序和已推广的自定义应用程序。通过 ⭐ 收藏某个应用程序后，该应用程序将固定到侧边栏，以便快速访问。

策划应用程序门户

应用程序门户有两种使用模式：

  • 基础（开箱即用）： 一款用于发现和了解所有 Foundry 平台应用程序的工具。无需任何管理工作。即使没有任何已推广的自定义应用程序，应用程序门户也是左侧边栏中不可或缺的工具。
  • 高级（基于策划）： 管理员、Palantir 代表或客户治理团队会将所有受信任的自定义应用程序推广到应用程序门户。

有关推广应用程序的权限和工作流的更多详细信息，请查阅 应用程序门户 文档。

审批简介：平台变更管理

发布日期：2023-05-04

审批为 Foundry 引入了全新的合规、治理和同行评审工作流

使用 Approvals 应用程序管理请求、审批和平台变更。Approvals 以加快价值实现速度为重点，让您能够设置审查流程，同时提供易于访问的审计历史记录，从而为您的组织提供合规、治理和同行评审工作流。

在一个收件箱中管理权限变更请求

Approvals 应用程序允许管理员通过一个通用收件箱，在 Foundry 中设置由一个或多个任务（单个操作）组成的用户请求，交由相应的审批人进行审查。用户可以从任务列表中进行选择，由相应的审查人员予以批准。此外，建议用户在提交 Project 访问请求时选择加入现有群组，从而优化管理员通过平台设置下的群组设置集中组织权限管理的能力。

一旦请求下的所有任务均获批准，Foundry 将自动完成该请求，省去了管理员为执行该决策而进行手动调整的步骤，也免除了验证正确设置是否已完成所需的工作。

Approvals 不仅解决了收集和管理 Project 访问请求这一特定问题，还为进一步集中管理目前分散在 Foundry 各处、用于访问和变更管理流程的其他审批工作流奠定了基础。

基于丰富 UI 的情境化决策

通过使用 Approvals，组织可以更深入地洞察数据访问决策的血缘关系，以便进行审计。此外，可以将审阅者（例如管理员和项目所有者）分配到与其监督和职责范围相关的特定任务。

当用户提交请求时，系统会自动向负责的审阅者发送平台内通知和电子邮件。请求可直接在 Approvals 用户界面中进行处理，必要时，审阅者可以发表评论或就特定任务向用户寻求澄清。请求获得批准后，Foundry 将自动执行变更，无需额外的手动操作。

我应该在什么时候使用 Approvals？

Approvals 专为需要清晰流程的组织而设计，用户可通过该流程获得访问资源的批准，并在管理员或所有者审阅后自动获得相应权限。其他 Approvals 请求类型（例如本体论提案和引用添加）计划在未来的版本中推出。

默认情况下，Approvals 应用程序已在所有堆栈上启用。如果存在自定义工作流，我们强烈建议将其调整为使用 Approvals 应用程序，以充分利用其改进的工作流实现。

查看 有关设置 Approvals 的文档 以开始使用。
