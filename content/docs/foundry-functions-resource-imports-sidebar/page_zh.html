将资源导入代码仓库

以下文档特定于 TypeScript v1 函数。如需更 强大的功能，包括对 Ontology SDK 和可配置的资源请求的支持，我们建议 迁移到 TypeScript v2。

代码仓库中的 资源导入 侧边栏提供了一个集中式界面，用于在您的 TypeScript 函数仓库中管理导入的 Foundry 资源。该侧边栏允许您导入、移除和查看各种资源的详细信息，包括本体论类型、LMS 语言模型、线上部署以及 REST API 等外部系统。

选择本体论

导入对象类型和关联类型需要本体论。要选择本体论：

  1. 选择 添加 以打开资源选择器菜单，然后选择 本体论 以开始导入本体论类型。如果尚未选择本体论，此操作将自动打开本体论选择器对话框。

如果您已经导入了至少一个本体论类型，系统会自动选中该类型所属的本体论。要更改本体论，请选择所选本体论名称旁边的 编辑 按钮以打开本体论选择器对话框。

您仓库中的所有已导入资源必须与同一个本体论相关联。请注意，更改本体论后再导入资源，将会覆盖来自其他本体论的现有导入。

导入资源

较新版本的 TypeScript v1 模板会将代码仓库导入的当前状态保存在 resources.json 检入到你的代码仓库的文件中。

如果你在侧边栏中遇到关于无法解析的文件的警告，请参阅 基于文件的本体论导入 章节，以了解预期的文件格式以及解决该问题的故障排除步骤。

要使用侧边栏导入资源：

  1. 使用侧边栏右上角的 添加 按钮，然后选择所需的资源类型。这将打开该资源的选择器对话框。
  2. 使用搜索栏和筛选器来查找你想要导入的资源。
  3. 选择某个资源，以显示包含详细信息的预览面板。
  4. 使用 选择 按钮将资源添加到你的选择中。
  5. 展开购物车面板以查看你的选择，然后点击 确认选择。

确认选择后，Code Assist 将重新启动，以重新运行必要的代码生成任务来应用你的更改。随后，每个导入的资源都会作为一个生成的包提供，因此你需要从生成的包路径（而不是相对于你自己文件的路径）导入它。例如，本体论类型是从 @foundry/ontology-api导入的；具体路径取决于资源类型。

了解有关导入特定类型资源的更多信息：

  • 本体论类型
  • 语言模型
  • 在线部署
  • 外部源

管理已导入的资源

资源在侧边栏中按类型进行分类：

  • 本体论：对象、接口和关联类型
  • 模型：LMS 模型和在线部署
  • 源：诸如 REST API 之类的外部系统

在侧边栏顶部选择相应的资源图标以按类型筛选，或使用文本输入框按名称搜索。要移除某个资源，请将鼠标悬停在资源图标上并选择 移除 按钮。要同时添加或移除多个资源，请使用选择器对话框。要查看更多详细信息，请选择一个已导入的资源以打开其预览面板。

某些资源类型可能与其他资源之间存在依赖关系。例如，关联类型归类在各自的对象类型之下。如果已导入的资源存在依赖项，资源标题旁将显示类似"(1 个关联类型)"的消息。要查看资源的依赖项，请将鼠标悬停在资源图标上并选择出现的尖角符号。

导入不含 API 名称的资源

资源必须具有 API 名称,才能在 TypeScript 函数仓库中的代码内被引用。如果资源缺少 API 名称,则会显示警告。将鼠标悬停在警告标志上可了解更多信息,或通过选择 添加 API 名称来轻松配置 API 名称。 或者,选择 了解更多 以查看针对特定资源类型定制的有关添加 API 名称的文档。

导入具有值类型依赖项的资源

某些资源依赖于 值类型 来定义用于与这些资源交互的数据类型,例如函数接口。对于这些资源,其值类型依赖项会自动导入到仓库中,以便可以随资源一起使用。

在某些情况下,导入此类资源的组合可能会导致值类型依赖项冲突。当不同资源依赖的同一值类型版本不同时,就会发生这种情况。无法同时导入同一值类型的两个版本,这会导致编译错误。此错误伴随侧边栏中的警告出现,便于您查看存在依赖项冲突的资源。

基于文件的仓库导入

较新版本的 TypeScript v1 模板使用已检入到您的仓库中的 resources.json 文件来维护仓库导入的当前状态。这为您提供了完整的 Git 语义，允许您审查、创建分支和还原对导入的更改。资源导入侧边栏会通过自动将条目插入到 resources.json 文件中来帮助您更新此文件。

如果 resources.json 文件处于无效状态，侧边栏中将出现一条警告，告知您该文件无法处理。如果遇到此错误，请确保您的文件包含一个具有以下数据的 JSON 对象：

字段类型
objectTypes数组 { rid: string }
linkTypes数组 { rid: string }
sources数组 { rid: string }
functions数组 { rid: string, version: string }
valueTypes数组 { rid: string, version: string }
functionInterfaces数组 { rid: string, version: string }
_comment字符串
version[1]整数

[1] version 字段用于表示 resources.json 文件的版本和格式。目前只有 version: 1 是受支持的。 version: 0 用于指示您的仓库必须从先前的仓库范围导入工作流进行迁移。当您创建包含 version: 0 的提交时，将自动处理此迁移，并将补丁应用到您的仓库。

请注意，由于 resources.json 文件已检入到您的仓库中，因此您可以查看提交历史记录，并利用该历史记录将文件还原到可用状态。
