第 3 阶段：角色与职责

以下是 Foundry 项目团队第 3 阶段新增的角色与职责，是对 第 1 阶段 和 第 2 阶段中所建立角色的补充。

卓越中心

职责

  • 卓越中心（CoE）是一种轮岗机制，而非专职团队；我们建议在中央项目组内设立一组可随时调用的人员，用于填补 Foundry 各项举措在知识、技能或资源带宽方面的缺口。
  • 这些资源会深度融入其所参与的用例，但在大多数情况下，不应构成特定项目执行工作的主体。
  • 关键在于，必须由长期参与用例所服务领域的人员负责；CoE 资源是为推动某项举措而临时部署的资源，无法承担长期负责的职责。

实施示例

  • 为正在开展特定工作流的团队嵌入一名数据科学家，为其开发和部署模型。
  • 嵌入一名管道专家，帮助构建初始数据管道或难度特别大的集成。
  • 提供一名项目经理来建立可持续的运营流程和项目治理体系，同时配备一名用例所有者，由其维护特定用例的所有权或投资。

角色

  • 项目经理
  • 数据工程师
  • 前端开发人员
  • 数据工程师/科学家

代理管理员

职责

  • 代理管理员负责创建和配置 Data Connection 代理，并与相关数据源所有者共享这些代理。
  • 作为一个团队，代理管理员应集中掌控代理的安装和配置，从而在 Foundry 计划中实现更强的安全性与管控能力。
  • 代理管理员通常被分配到特定的组织域或地理区域，但合理的职责划分会因组织结构和合规要求而有所不同。我们建议确保代理管理员是其特定区域内数据摄取所需数据源套件方面的领域专家。
  • 代理管理员应与 Palantir 团队密切合作，以识别上游问题，并在承担更多职责之前积累业务和 Foundry 背景知识。
  • 代理管理员与数据所有者密切合作，数据所有者是导入 Foundry 以供使用的各个源系统的主要联系人。在配置新数据连接的过程中，数据所有者将与代理管理员密切合作，而数据源所有者将根据商定的 SLA 和条款对上游问题承担责任。

简介与所需技能

  • 熟悉代理 / 虚拟机 / 系统连接
  • 具备有关组织数据源、IT 基础设施和内部访问流程的具体技术知识
  • 数据工程技能（SQL、Python、PySpark/Spark）

平台负责人

职责

  • 平台负责人主要负责数据安全和权限管理，以及 Foundry 治理、合规、性能和计算/存储成本分配。
  • 平台负责人应当是整个组织 IT 领域的领导者，能够为 Foundry 计划构建 IT 基础设施，并将其适当地整合到整体 IT 结构和流程中。
  • 构建数据安全体系，包括有关最佳实践和合规协议的文档与培训。该角色将与权限管理员密切合作，推动制定 Foundry 内权限管理和数据访问控制方面的需求与长期愿景。
  • 随着时间推移，与内部 IT 团队以及权限管理员、数据治理负责人和与 Foundry 计划相关的其他 IT 团队合作，界定并在 Foundry 上实施所需的组织定制，以满足业务需求。这包括与现有组织技术构建集成点以简化数据流、在平台上自定义资源配置文件，以及监控和管理 Foundry 的集群成本。
  • 为平台团队制定全面的成功指标和路线图，以支持 Foundry 计划的战略和增长路线图。推动对平台 KPI 的报告和监控，并与计划负责人合作，宣传成功经验并开展定期汇报。

岗位简介与必备技能

  • 拥有领导 IT 和平台团队的经验
  • 拥有与更广泛的 IT 组织建立并维护关系的经验
  • 书面和口头沟通能力
  • 以工作流负责人身份与高级管理层协作的经验
  • 熟悉数据安全和权限管理最佳实践，且与组织政策及更广泛的监管政策保持一致
  • 出色的组织和项目管理能力

IT 服务负责人

职责

  • IT 服务负责人负责平台架构和跨平台软件集成，这包括 Foundry 如何连接其他系统，以及 Foundry 在企业 IT 生态系统中的定位。
  • IT 服务负责人应与技术负责人共同创建和管理自定义配置，确保这些配置符合公司的期望或规程。这些配置可能包括 Spark 配置文件、YARN 配置以及对 Foundry 应用的更改。
  • 与平台负责人合作，根据项目的战略和目标建立 IT 政策和系统。
  • 与项目内的其他团队协作，确定他们的 IT 需求。
  • 监控、审查并执行整个平台上的任何升级或配置变更，并在各工作流之间传达所需的变更。
  • 与平台负责人合作，建立成本监控和报告机制，确保 Foundry 成本透明并得到妥善管理。

  • 对 Foundry 架构有深入的理解
  • 具备监控和控制 IT 服务预算的经验
  • 跨职能协作技能
  • 与 Foundry 计划以外的组织 IT 团队建立牢固关系的能力

权限管理员

职责

  • 权限管理员负责管理 Foundry 中群组的整体组织，该组织决定了如何为不同类型的用户开通 Foundry 访问权限。这可能涉及与组织特有的身份管理系统集成，或进行 SAML 集成。
  • 需要与数据治理主管定期协作；该角色应充当平台实施与数据治理协议、流程和控制措施交汇处的执行层。
  • 权限管理员应当是数据治理要求方面的主题专家，并熟悉实施层面的要求和数据结构，以便在各项目和工作流中以最佳方式执行权限管理。
  • 全面负责 Foundry 中群组的整体组织，这些群组决定了如何为不同类型的用户开通 Foundry 访问权限。
  • 随着平台日趋成熟、用例和用户群体不断扩展，需与技术合规经理紧密协作，负责受限视图和权限的实施。

简介和所需技能

  • 在技术和非技术利益相关者之间进行沟通的能力
  • 熟悉组织范围内的数据访问权限、法规和身份验证系统（例如 Okta 和 Active Directory）
  • 编程技能（SQL、Python、PySpark/Spark）
  • 了解数据治理最佳实践
  • 出色的技术沟通者
  • 具备系统架构知识

技术合规经理

职责

  • 技术合规经理负责在开发开始之前审批项目。该角色负责向请求新项目的人员提供有关平台的信息。审批时应考虑需要利用的源数据、项目的目的，以及需要访问数据和配置权限的用户构成情况。
  • 技术合规经理角色应与组织的数据保护政策以及平台和特定项目所处的更广泛的监管体系保持一致。
  • 此外，该角色还确保受限视图的实施，并针对每种项目类型定义标准结构。
  • 技术合规经理将与权限经理密切合作;在规模化运营时,该角色可能存在于组织级域中。

简介与所需技能

  • 熟悉组织范围内的数据访问权限、法规以及身份验证系统(例如 Okta 和 Active Directory)
  • 对 Foundry 权限架构有深刻理解
  • 在数据合规、数据监管和数据隐私方面具有实施和/或政策制定的经验背景
  • 具备编程实践知识(SQL、Python、PySpark/Spark)
  • 了解数据治理最佳实践以及数据保护政策与法规
  • 出色的技术沟通能力
  • 了解系统架构

支持服务

职责

  • 支持服务是负责处理 Foundry 相关问题和用户提交问题的支持团队,这些问题涉及 IT 直接负责的项目,此外还包括一般性 Foundry 支持和用户开发支持。
  • 该团队的结构具有灵活性;可以决定哪些支持工作应在内部(由组织内部的团队)开展,哪些应由 Palantir 提供,并制定标准操作流程,以在客户和 Palantir 双方之间端到端地管理用户支持问题的解决。
  • 该团队的最终目标是实现自主性；内部团队由一支深入理解组织业务、结构、工作流程以及 Foundry 架构的内部支持团队赋能。支持服务团队的最终目标是使组织的 Foundry 使用能够扩展至超越用例团队的带宽和支持能力，并通过减少对 Palantir 支持服务的依赖来提升速度。
  • 支持服务团队需要深入理解 Spark 并能识别编程反模式的技术人员。

人员画像与所需技能

  • 对业务工作流程以及 Foundry 中的技术结构和概念的理解
  • 强烈的好奇心和出色的调查分析能力
  • 具备为支持服务构建和使用报告与监控系统的经验
  • 出色的书面沟通能力；应承担为支持工作流程编写文档的职责，并在问题需要上报时与开发团队或 Palantir 支持团队进行沟通
