阶段 3：角色与职责

以下是 Foundry 项目团队在阶段 3 中新增的角色与职责，此外还包括在 第 1 阶段 和 第二阶段.

卓越中心

职责

  • 卓越中心（CoE）是一个轮岗机制而非专职团队；我们建议从中央项目团队中组建一组可用人员，用于填补 Foundry 计划在知识、技能或资源带宽方面的缺口。
  • 这些资源会深度嵌入到他们所参与的使用案例中，但在大多数情况下，他们不应成为特定项目执行带宽的主要部分。
  • 至关重要的是，使用案例所贡献的领域必须由一名长期参与者负责；CoE 资源旨在作为临时资源部署以推动计划进展，不能承担长期所有权的责任。

实施示例

  • 嵌入一名数据科学家，为正在处理特定工作流的团队开发和部署模型。
  • 嵌入一名管道专家，帮助构建初始数据管道或特别困难的集成。
  • 提供一名项目经理，与将维持特定使用案例的所有权或投入的使用案例负责人一起，建立可持续的运营流程和项目治理体系。

角色

  • 项目经理
  • 数据工程师
  • 前端开发人员
  • 数据工程师/科学家

Agent 管理员

职责

  • 代理管理员负责创建和配置数据连接代理，并与相关数据源所有者共享这些代理。
  • 作为一个团队，代理管理员应负责代理安装和配置的集中控制，从而在 Foundry 项目中增强安全性和管控能力。
  • 代理管理员通常被分配到特定组织的领域或地理区域，但职责的合理划分会因组织结构和合规要求而异。我们建议确保代理管理员是其所在区域数据摄取所需数据源套件方面的主题专家。
  • 代理管理员应与 Palantir 团队密切合作，识别上游问题，并在承担更多所有权之前建立业务和 Foundry 背景知识。
  • 代理管理员与数据所有者密切合作，后者是为 Foundry 摄取的各个源系统的主要联系人。在配置新数据连接期间，数据所有者将与代理管理员密切合作，而数据源所有者将根据商定的 SLA 和条款承担上游问题的责任。

画像与所需技能

  • 熟悉代理/虚拟机/系统连接
  • 对组织的数据源、IT 基础设施和内部访问流程具备具体的技术知识
  • 数据工程技能（SQL、Python、PySpark/Spark）

平台负责人

职责

  • 平台负责人主要负责数据安全和权限管理，以及 Foundry 的治理、合规、性能以及计算/存储成本分摊。
  • 平台负责人应是更广泛组织 IT 领域中的领导者，能够为 Foundry 项目构建 IT 基础设施，并将其适当地与整体 IT 结构和流程集成。
  • 构建数据安全体系，包括关于最佳实践和合规协议的文档和培训。该角色将与权限管理员密切合作，围绕 Foundry 内的权限管理和数据访问控制推动需求制定和长期愿景。
  • 随着时间推移，与内部 IT 团队以及权限经理、数据治理负责人和与 Foundry 项目相关的 IT 团队合作，在 Foundry 上界定并实施所需的组织定制，以满足业务需求。这包括与现有组织技术构建集成点以简化数据流、在平台上自定义资源配置文件，以及监控和管理 Foundry 的集群成本。
  • 为平台团队制定全面的成功指标和路线图，以支持 Foundry 项目战略和增长路线图。推动平台 KPI 的报告和监控，并与项目负责人合作，宣传成果并进行定期汇报。

画像与所需技能

  • 具备领导 IT 和平台团队的经验
  • 具备与更广泛的 IT 组织建立并维护关系的经验
  • 具备书面和口头沟通能力
  • 具备作为工作流负责人与高级领导层合作的经验
  • 了解数据安全和权限管理最佳实践，并符合组织及更广泛的监管政策
  • 具备强大的组织和项目管理能力

IT 服务负责人

职责

  • IT 服务负责人负责平台架构和跨平台软件集成，包括 Foundry 如何连接到其他系统，以及 Foundry 在企业 IT 生态系统中的定位。
  • IT 服务负责人应与技术负责人共同创建和管理自定义配置，确保其符合公司期望或协议。这些配置可能包括 Spark 配置文件、YARN 配置以及对 Foundry 应用程序的更改。
  • 与平台负责人合作，根据项目战略和目标制定 IT 政策和系统。
  • 与项目内的其他团队协作，确定其 IT 需求。
  • 监控、审查并执行整个平台的任何升级或配置变更，并就各工作流所需的变更进行沟通。
  • 与平台负责人合作，建立成本监控和报告机制，确保 Foundry 成本透明并得到管理。

画像与所需技能

  • 具有 IT 背景的强大个人贡献者
  • 对 Foundry 架构有深入理解
  • 具备监控和控制 IT 服务预算的经验
  • 具备跨职能协作能力
  • 能够与 Foundry 项目之外的组织 IT 团队建立牢固关系

权限经理

职责

  • 权限经理负责 Foundry 内群组的整体组织工作，这决定了如何向不同类型的用户配置 Foundry 访问权限。这可能需要与组织特定的身份管理系统集成，或进行 SAML 集成。
  • 需要与数据治理负责人定期协作；该角色应作为平台实施与数据治理协议、流程和控制措施交汇处的执行层。
  • 权限经理应是数据治理要求方面的主题专家，并熟悉实施层面的要求和数据结构，以便在各项目和工作流中最佳地执行权限管理。
  • 负责 Foundry 内群组的整体组织工作，这决定了如何向不同类型的用户配置 Foundry 访问权限。
  • 随着平台日趋成熟以及使用场景和用户群的持续扩大，与技术合规经理紧密合作，负责受限视图和权限的实施。

画像与所需技能

  • 能够在技术和非技术利益相关者之间进行沟通
  • 熟悉组织范围的数据访问权限、法规和身份验证系统（例如 Okta 和 Active Directory）
  • 编程技能（SQL、Python、PySpark/Spark）
  • 了解数据治理最佳实践
  • 出色的技术沟通者
  • 了解系统架构

技术合规经理

职责

  • 技术合规经理负责在开发开始之前批准项目。该角色负责向请求新项目的人员提供有关平台的信息。审批时应考虑需要利用的源数据、项目的目的，以及需要访问数据和配置权限的用户的构成情况。
  • 技术合规经理角色应与组织的数据保护政策以及平台和特定项目所处的更广泛的监管体系保持一致。
  • 此外，该角色还负责确保受限视图（Restricted Views）的实施，并定义每种项目类型的标准结构。
  • 技术合规经理将与权限经理密切合作；在规模化运营时，该角色可能存在于组织级别的域中。

画像与所需技能

  • 熟悉组织范围的数据访问权限、法规和身份验证系统（例如 Okta 和 Active Directory）
  • 对 Foundry 权限架构有深入的理解
  • 在数据合规、数据法规和数据隐私方面具有实施和/或政策制定的经验
  • 了解编程实践（SQL、Python、PySpark/Spark）
  • 了解数据治理最佳实践以及数据保护政策和法规
  • 出色的技术沟通者
  • 了解系统架构

支持服务

职责

  • 支持服务是处理 Foundry 问题以及用户提交的与 IT 直接负责的项目相关的问题的支持团队，同时也负责一般的 Foundry 支持和用户开发支持。
  • 该团队的结构得益于灵活性；可以决定哪些支持应在内部（在组织的团队内）开发，哪些应由 Palantir 提供，以及管理跨客户和 Palantir 的用户支持问题端到端解决的标准操作程序。
  • 该团队的最终目标是建立自主性；内部支持团队深入了解组织的业务、结构、工作流程和 Foundry 架构，从而为内部团队赋能。支持服务团队的最终目标是使组织的 Foundry 使用规模超越用例团队的带宽和支持能力，并通过减少对 Palantir 支持服务的依赖来提升速度。
  • 支持服务团队需要深入理解 Spark 并能识别编程反模式的技术人员。

画像与所需技能

  • 既了解业务工作流程，又了解 Foundry 中的技术结构和概念
  • 好奇心强，具备出色的调查能力
  • 具有构建和使用支持服务的报告和监控系统的经验
  • 出色的书面沟通能力；应负责为支持工作流程编写文档，并在问题需要升级时与开发团队或 Palantir 支持团队进行沟通
