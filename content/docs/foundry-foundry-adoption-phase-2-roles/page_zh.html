第二阶段：角色与职责

以下是 Foundry 项目团队第二阶段新增的角色与职责，是对 第一阶段中所确立角色的补充。

教育与培训专家

职责

  • 协调符合业务和用例优先级的培训活动；与用例负责人和领域负责人合作，确保培训与用例上线、功能上线以及新一批用户加入特定工作流程保持同步。
  • 与用例团队合作，制定针对具体用例和工作流程的培训文档，目标是确保用户和开发人员都能理解不同的用例和工作流程，并确保围绕这些用例开展的培训和编写的文档符合项目标准。
  • 对接公司特有的内部人力资源（HR）流程，将 Foundry 纳入公司的教育项目、认证和执行环节；教育与培训专家应与 HR 合作，将 Foundry 培训与教育整合到所有组织纵向领域的入职培训和继续教育项目中。这样可以避免 Foundry 项目陷入孤岛状态、无法与组织的其他部门整合。
  • 通过教育推广 Foundry；负责可用培训和现有用例的沟通与宣传工作。具体形式多种多样，取决于组织结构，可以包括与您所在组织的学习与发展团队合作，将 Foundry 培训纳入发展和技能提升机会，或者与内部沟通或活动团队合作，发布新的培训和认证机会，并宣传 Foundry 教育的益处。
  • 开展技能差距分析和审计，以持续改进培训和教育资源；根据业务成果和投资回报率（ROI）的提升情况，制定评估不同培训和教育材料成效的方法。
  • 创建 Foundry 培训计划，为不同角色和用例设定里程碑和成功标准；这些培训可以是 Workshop、在线培训、自助式培训、Palantir 提供的学习资源、现场培训、测验和文档，以及在 Foundry 中设计培训项目。
  • 如果组织内设有“培训师培训”（Train-the-Trainer）计划，该角色应协调并促成该计划的实施；这使 Foundry 教育能够突破仅依靠专职教育和培训资源的限制，得以扩展。

角色简介与所需技能

  • 具备教学设计最佳实践和培训方法方面的知识，包括辅导、Workshop 和在线学习方法
  • 出色的沟通与协作能力
  • 较强的组织能力，并具备项目管理经验
  • 具备一定的技术领域知识
  • 了解业务结构和团队，能够跨团队沟通协调并深入理解各团队的目标

数据治理管理员

职责

  • 专注于让用户能够使用数据，同时符合内部和外部的数据质量标准及 SLA。
  • 负责该计划中数据治理要求的文档编制与维护，并在各工作流之间传达这些要求。
  • 围绕数据治理流程建立监控和指标体系，并负责这些系统的持续报告与调整。
  • 与权限管理员和数据负责人合作，在项目权限中实施群组和角色。针对常见的项目类型和工作流程创建文档和可复用的流程，使用户能够自助满足适用于各项目类型的数据治理要求。
  • 在 Foundry 计划的所有工作流中实施数据治理审查流程。与团队负责人合作，了解其工作流的需求和流程，并实施数据治理检查、要求和流程，以确保整个计划符合数据治理标准。
  • 如有需要，可与 Palantir 团队对接以交付支持服务；利用 Palantir 的资源（包括文档、咨询团队和支持服务），在符合组织需求且具备充足供应商支持体系的前提下实施数据治理计划。

在第一阶段，数据治理管理员这一角色通常可由 数据负责人 或 本体论负责人担任。但是，鉴于数据管理的规模以及工作流程和用例的复杂性，我们建议最迟在第三阶段将其设为独立角色并配备专门的资源。

画像与所需技能

  • 熟悉整个组织范围的数据访问权限、法规和身份验证系统（例如 Okta 和 Active Directory）
  • 编程技能（SQL、Python、PySpark/Spark）
  • 了解数据质量和版本控制的最佳实践
  • 熟悉代理 / 虚拟机
  • 具备出色的技术沟通能力
  • 了解系统架构

数据源开发人员

职责

  • 数据源开发人员是从数据负责人处承接个人贡献者任务的工程师，负责 Foundry 计划中所用全部相关数据源的获取和清理流程。
  • 我们建议将该角色分配给一个集中的数据源开发人员团队，而不是将所有权分散到各个用例团队，以保持符合所有管道的合规、治理和安全要求。这样做还可以确保数据结构和管道架构的标准化。
  • 每个数据源开发人员都负责一组数据源的数据连接配置和技术连接，以及 Foundry 数据源项目，摄取的数据在其中以原始格式提供。
  • 作为一个团队，数据源开发人员应负责创建共享库及其他文档，用于数据清理、清理自动化以及必要时的数据混淆。
  • 与组织中的数据所有者合作，收集有关数据源的技术细节，并设计实现数据摄取的管道，以最大程度地支持组织目标以及最终状态工作流的策略和要求。
  • 负责数据摄取、管道健康状况和数据质量的日常管理。确保管道设计、构建、更新和监控工作得到妥善安排，与项目目标以及用例和工作流需求保持一致。
  • 管理和处理数据源中的故障或问题。这包括与相关 IT 团队和项目经理合作制定升级处理标准作业程序（SOP），建立用于对故障作出响应的监控和告警系统，推动围绕故障的沟通，在故障发生时实施补救措施，并创建复盘流程以推动从故障中总结经验教训。
  • 专注于在符合内部和外部数据质量标准及 SLA 的前提下向用户提供数据。与合规团队和数据治理负责人密切合作，为数据管道制定指南、最佳实践以及审查和监控流程。

岗位画像与所需技能

  • 数据工程技能（SQL、Python、PySpark/Spark）
  • 具备数据清洗和数据质量最佳实践方面的知识
  • 具备版本控制最佳实践方面的知识
  • 熟悉代理 / 虚拟机 / 系统连接

本体论管理器

职责

  • 负责基于现有模型和生产管道开发本体论，该本体论随后将作为所有工作流项目的消费点。
  • 管理本体论待办事项，确定变更请求的优先级，并在需要时分流至其他团队。以清晰的视角评估所有新对象请求及对本体论的其他变更，充分了解其对更广泛的组织级本体论的影响，以及本体论的长期演进和路线图。
  • 与用例负责人和数据源开发者合作，处理需摄取到 Foundry 的新数据源请求；在所有新用例架构和数据获取讨论中发挥核心作用，确保与现有本体论以及整个项目范围的本体论增长与演进战略保持一致。
  • 负责本体论的维护，并对每个用例的相关数据源建立深入理解。与数据源开发者协作以理解各数据源，成为领域专家以规划数据源与本体论的集成，并与用例团队合作以了解本体论设计和决策的影响。
  • 与数据治理和合规团队合作，确保对本体论和数据源的访问按照内部治理程序实施。为本体论开发和维护中的治理检查制定可扩展的流程。
  • 与本体论负责人和数据负责人密切合作，确保本体论与数据摄取和维护流程保持一致。根据整个项目的路线图和长期战略开发本体论。

本体论经理这一角色通常是集中设置的，但对于成熟的平台（第 3 阶段和第 4 阶段），该角色可以按各个领域进行细分。在第 4 阶段，该角色将向管道开发人员和对象视图开发人员提供指导并提出功能请求，以确保本体论和数据资产能够为临时性使用和用例开发提供最佳支持。

角色画像与所需技能

  • 数据管道开发与管理技能
  • 数据库知识
  • 组织领域知识
  • 在技术和非技术利益相关者之间进行沟通的能力
