本体论 SDK 现已支持 Java 开发 [Beta]

发布日期：2024-07-25

Java 支持现已在 本体论 SDK 和 开发者控制台中推出。Java 开发者现在可以生成 Java 库，以便轻松地与本体论对象、关联、操作和函数进行交互。

本体论软件开发工具包（OSDK）让您能够直接在您的开发环境中访问本体论的全部强大功能。您可以通过开发者控制台生成本体论 SDK，该控制台是一个通过 Palantir API 创建和管理应用程序的门户。凭借对 Java SDK 的全新支持，您可以构建基于 Java 的程序，例如与本体论交互的后端服务。这些服务将使用机密客户端向 Palantir 平台进行身份验证，并根据授予用户的权限提供数据。

本体论 SDK 生成的 Java 库代码示例。

开始使用 Java 软件包

Java 支持已作为附加语言添加到 Developer Console 中，Developer Console 还支持 Typescript 和 Python 开发。想要使用 Java SDK 的开发者可以按照文档中说明的步骤 来创建 Developer Console 应用程序 并生成新版本。 Application SDK 页面现在包含一个 maven 选项卡，其中列出了所有生成的 Java 软件包。

在生成 Java OSDK 之前，您必须先在 Application SDK > Settings下设置 Maven 组 ID。生成后，请按照 API documentation > Getting started 中的说明，将您的本体论 SDK 导入到 Java 环境中。

Developer Console 中的 Application SDK 页面，您可以在其中设置 Maven 组 ID 并生成新的 SDK 版本。

需要支持？

Developer Console 包含为本体论 SDK 支持的所有语言动态生成的 API 文档。使用语言下拉菜单可切换到针对 Java 的文档。

我们始终乐于通过我们的 Palantir 社区论坛 ↗与您交流。请提交与 Ontology SDK 或 Developer Console 相关的反馈和任何问题，并使用 #ontology-sdk 标签。

Notepad 文档现在可用于 AIP Assist 自定义文档

发布日期：2024-07-25

自 8 月 5 日当周起，AIP Assist 可以为您的用户提供源自 Notepad 的内容，补充其对自定义文档的现有支持。为 AIP Assist 集成额外的文档源可增强其为用户提供个性化资源的能力，契合您的运营需求，并在需要时有效呈现相关信息。

Notepad 对自定义文档的支持让您能够充分利用 Notepad 文档易于访问且创建简便的优势，从而加快工作流程和新用户引导、提供有针对性的指导内容，并实现支持流程的自动化。请确保先按用户和组配置 Notepad 文档的可见性设置，因为 AIP Assist 会遵循现有权限。然后，导航至 控制面板 > AIP Assist 以配置 Notepad 自定义文档的可见性，可选择在整个平台上任意位置授予访问权限，或仅在选定资源上授予访问权限。

AIP Assist 中的自定义文档是 Palantir 的 AIP 产品的一部分，并且 需要您的 enrollment 已在控制面板中启用 AIP。如果您已启用 AIP 和 Assist 功能，但在 Notepad 中未看到将 Notepad 文档添加到 AIP Assist 的选项，则可能需要联系 Palantir 代表，以确认您的注册是否有资格使用此功能。

释放 Notepad 文档的潜能

在 AIP Assist 中添加自定义文档现在比以往更加轻松；您只需极少配置且无需编写代码，即可将 Notepad 文档添加到您的自定义文档中。

Notepad 操作下拉菜单中的“添加到 AIP Assist”选项。

如上所示，只需点击几下，您即可将 Notepad 中的信息内容添加到 AIP Assist。利用这项新功能，您可以轻松地使用来自您组织的直接信息来增强 AIP Assist 的回复，并帮助用户充分利用您的平台。

AIP Logic Evaluations 简介：用于增强 Logic 函数测试的全新工具

发布日期：2024-07-18

LLM（大语言模型）本质上是非确定性的，这可能会让人担心您的 AI 工作流是否能持续生成生产环境所需的高质量结果。意识到这一点，我们开发了 AIP Logic Evaluations，这是一套全新功能，可帮助您严格评估 AIP Logic 函数的性能。这套功能自本周起已在所有租户中推出。

AIP Logic 函数中显示测试用例结果的评估侧边栏。

使用开箱即用和自定义评估函数进行测试

评估使您能够为 Logic 函数编写详细的测试，从而让您能够：

  • 使用多种开箱即用评估函数之一，例如字符串匹配、对象匹配和时间范围。
  • 在 AIP Logic 中使用 LLM 编写自定义评估函数来评估函数输出。
  • 利用将对象集用作测试用例的能力，扩展测试规模。
  • 在评估指标仪表板中查看汇总结果和单个测试用例。

何时使用 AIP Logic 评估

从函数迭代到监控生产环境中的函数性能，评估旨在为开发周期的每个阶段提供支持。

  • 在整个开发生命周期中调试和改进 Logic 函数与提示词。
  • 在开发过程中比较和评估不同模型（GPT-4 对比 Llama 3），并将其作为模型迁移的工具。
  • 在工作流投入生产环境后监控其长期性能。

推出简化的应用程序访问管理

发布日期：2024-07-18

Palantir 平台应用程序遵循 开发生命周期，应用程序访问权限是在 Control Panel > Application access中为当前生命周期阶段进行配置的。当应用程序从一个生命周期阶段过渡到下一个阶段时，同一组用户会保持访问权限。现在，即使应用程序在未经管理员审查的情况下经历多个生命周期阶段，情况也是如此。

只有两种情况会导致应用程序的有效访问权限自动发生变化：

  • 当应用程序进入 正式发布阶段时，所有用户都会自动获得访问权限—— 除非 该应用程序在实验或 Beta 阶段已被明确禁用。在进入正式发布阶段时会自动启用的应用程序，现在在 Application access 中显示为 Not yet enabled 而非 Disabled ，以指示此状态。

  • 当应用程序被 弃用时，所有用户都将失去对该应用程序的访问权限。

有了这些改进，之前的 Needs review 页面顶部的提示框将被替换为针对重大应用程序生命周期更新的更具针对性的提示框：

  • 已正式发布但先前被禁用的应用程序： 在实验阶段或 Beta 阶段被明确禁用或仅限特定用户组使用的应用程序，在这些应用程序进入正式发布阶段后仍将保持受限状态。此处提供快速操作，可用于保留该限制，或在应用程序进入新的生命周期阶段后为其所有用户启用该应用程序。

  • 近期已进入下线阶段且仍处于启用状态的应用程序： 当应用程序进入下线阶段后，之前拥有访问权限的用户将继续保持访问权限。此时，我们建议您与现有用户协作，逐步减少该应用程序的使用，并在用户迁移完毕后将其禁用。

  • 已弃用但仍处于启用状态的应用程序： 在应用程序处于下线阶段期间，预计所有用户均已迁移至其他工作流，因此已弃用的应用程序可能随时从您的 Palantir 平台部署中消失，不应再继续使用。

有了这些更改，应用程序访问页面可让您专注于那些经历了重大生命周期变更的应用程序，并快速重新审视哪些用户应有权访问它们。当应用程序进入下一个生命周期阶段时，您不再需要每次都重新确认上一个生命周期阶段的访问设置。

请参阅 我们关于这些改进的文档更新。

Pipeline Builder 中的新增管道管理功能

发布日期：2024-07-02

管道构建器用户现在可以通过显示和隐藏选定的节点及颜色分组，来更高效地管理大型管道。自定义显示的节点可让您快速轻松地识别管道片段，并获得更佳的导航和编辑体验。

新的管道管理功能包括：

  • 显示和隐藏选定的节点： 选择一组节点并右键单击以将其隐藏，或隐藏所有其他节点。
  • 显示和隐藏颜色分组： 从图例中选择并隐藏某个颜色分组，或隐藏所有其他颜色分组。
  • 隐藏的输入和节点计数： 选择节点左侧的连接圆圈可查看隐藏的节点输入，或查看隐藏节点的总数。
  • 轻松显示隐藏的节点： 跟踪隐藏的节点，并一键将其全部显示。
  • 跨视图兼容性： 显示和隐藏功能可在不同视图中使用，包括主图、差异视图和冲突解决页面。
