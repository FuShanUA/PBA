JupyterLab®

Code Workspaces 使您能够在 Foundry 中使用 JupyterLab® ↗ 。Code Workspaces 中的 JupyterLab® 支持：

  • 读取和写入表格数据集、 Iceberg 表日 虚拟表.
  • 从非结构化数据集下载或上传文件。
  • 从 conda 或 PyPI 导入 Python 库。
  • 预览 Dash、Streamlit 或 TensorBoard™ 应用，以便于迭代。
  • 发布 Dash 或 Streamlit 应用。
  • 与本体论交互。
  • 在 Code Workspaces 中使用 LLM 辅助编码与 AIP agent.

代码工作区目前支持 Dash ↗ 和 或 用于 Python 应用程序。用户可以在代码工作区中直接创建应用程序，并使用 Foundry 的 版本控制, 分支日 数据治理 内置功能。

代码工作区应用程序支持分支功能。如果您 创建新的工作区分支，发布新应用程序或同步更改将在该分支上发布应用程序的新版本，使您可以在向用户公开之前预览应用程序。要在 master 分支上发布，请将您的分支合并到 master。

Dash 和 Streamlit 应用程序可以使用 受限视图 作为输入。启用 受限输出模式 ，然后在使用 受限视图作为应用程序输入之前。当您从包含受限视图的工作区发布时，每个用户只能看到其权限允许的数据。

JupyterLab® 设置

使用直方图中的 设置 标签页配置 JupyterLab® 工作区首选项。您的首选项将在所有 Jupyter® 工作区中保留。

持续提示

持续提示会在您输入时建议代码补全，默认在所有 Jupyter® 工作区中启用。可在 设置 标签页。

应用程序面板

使用直方图中的 应用程序 标签页（位于 JupyterLab® 工作区左侧边栏）预览 Dash、Streamlit 和 TensorBoard™ 应用程序，并发布 Dash 和 Streamlit 应用程序。TensorBoard™ 仅支持预览。该面板一次显示一种应用程序类型。在按照以下任何发布或预览说明操作之前，请先选择您要使用的应用程序类型。

选择应用程序类型

要选择面板显示的应用程序类型：

  1. 打开 应用程序 标签页（位于 JupyterLab® 工作区左侧边栏）。
  2. 在监听器设置向导的 应用程序类型 行，选择下拉菜单，其中显示当前选定的类型。
  3. 选择您要使用的应用程序类型。Jupyter® 工作区支持 Dash、Streamlit 和 TensorBoard™。

面板随后将显示已发布的应用程序以及所选类型的可用操作。面板会记住您在此工作区中的选择。

如果您的工作区使用 托管的 conda/PyPI 环境，则在发布 Dash 或 Streamlit 应用程序之前，您必须安装应用程序类型所需的库。例如， streamlit 库是发布 Streamlit 应用程序所必需的。当缺少该库时， 发布应用程序 将被禁用，并且面板会指示需要安装哪个库。请从 ”面板中找到。 例如，要使用 面板安装，或在终端中运行 maestro env conda install <library_name> 。请使用 conda 安装该库；PyPI 安装不满足此要求。面板也会为 TensorBoard™ 报告缺少库的情况，TensorBoard™ 没有发布流程；在这种情况下，该消息仅供参考，预览仍然可用。

Dash 应用程序

已发布的 Dash 应用程序受 30 秒超时限制，这意味着 Dash 服务器必须在执行您的 Dash 应用程序 Python 文件后的 30 秒内启动。否则，您的 Dash 应用程序将无法启动。

要创建 Dash ↗ 应用程序，请按照以下说明操作：

  1. 选择 Dash 作为应用程序类型 菜单中选择 应用程序 panel.
  2. 选择 发布应用程序，选择一个位置，位于您的 文件和项目 用于您的新应用程序，并提供模块名称和变量名称。系统将自动在与所提供模块名称对应的路径下创建文件。

Dash 应用程序的模块名称应以点分路径的形式输入，该路径相对于仓库根目录（例如 app，或者如果您的模块位于某个文件夹内，folder.app）。变量名是模块文件中为 Dash 应用服务器声明的 Python 变量，通常称为 server.

  1. 可选： 配置高级设置。默认情况下，应用程序设置将与 Jupyter® 工作区的设置保持一致。
  2. 选择 发布并同步 以注册您的新 Dash 应用程序并将代码同步到支撑代码仓库。CI 检查和发布完成后，您可以选择“应用程序”面板中的链接来查看已发布的应用程序。

要在本地针对现有的 Dash 应用程序进行开发：

  1. 打开终端窗口并执行您新创建的文件，例如， python app.py.
  2. 打开 应用程序 选项卡，然后选择 选择 Dash 作为应用程序类型.
  3. 选择 打开预览 （位于应用程序面板中）。

您可以确保 JupyterLab® 工作区中的 conda/PyPI 环境在已发布的 Dash 应用程序中自动恢复，方法是使用 Jupyter® Notebooks 中的托管 conda/PyPI 环境.

Streamlit 应用程序

已发布的 Streamlit 应用程序受 30 秒超时限制，这意味着 Streamlit 服务器必须在执行 Streamlit 应用程序 Python 文件后的 30 秒内启动。否则，您发布的 Streamlit 应用程序将无法启动。

要创建 或 应用程序，请按照以下说明操作：

  1. 打开 应用程序 标签页（位于 JupyterLab® 工作区中），然后 选择 Streamlit 作为应用程序类型.
  2. 选择 发布应用程序，选择一个位置，位于您的 文件和项目 中为新的应用程序选择一个位置，并输入相对于仓库根目录的 Python 文件名，例如 app.py.
  3. 可选： 配置高级设置。默认情况下，应用程序设置将与 JupyterLab® 工作区的设置一致。
  4. 选择 发布并同步 以注册您的新 Streamlit 应用程序，并将代码同步到支撑代码仓库。CI 检查和发布完成后，您可以在 Applications 面板中选择链接以查看已发布的应用程序。

要针对现有 Streamlit 应用程序进行本地开发：

  1. 打开终端窗口，然后使用 Streamlit 通过以下命令运行代码 streamlit run app-name.py.
  2. 打开 应用程序 标签页（位于 JupyterLab® 工作区中），然后 选择 Streamlit 作为应用程序类型.
  3. 选择 打开预览 以预览您在本地开发的应用程序。

您可以确保 JupyterLab® 工作区中的 conda/PyPI 环境在已发布的 Streamlit 应用程序中自动还原，方法是使用 Jupyter® Notebooks 中的托管 conda/PyPI 环境.

TensorBoard™

您可以直接在代码工作区中预览 TensorBoard™ ↗ 直接从 Code Workspaces：

  1. 运行 tensorboard --logdir=<$PATH_TO_LOGS_DIRECTORY> 在终端中运行，并填入包含 TensorFlow 日志的目录路径。
  2. 打开 应用程序 标签页（位于 Jupyter® 工作区中），然后 选择 TensorBoard™ 作为应用程序类型.
  3. 选择 打开预览 以预览 TensorBoard™。

AIP agent

JupyterLab® Code Workspaces 在工作区侧边栏中提供 AIP agent。该 agent 使用 支持的 AIP 大语言模型 (LLM) 帮助您在 Foundry 中开发和部署代码。此 实验性 功能适用于所有启用了 AIP 的 Foundry 注册.

在您的工作区中，选择 </> 图标（位于左侧边栏底部），然后在 提问... 文本框中输入提示。该 agent 会提供编码指导，或根据其可用工具生成文件。

配置 agent

选择扳手图标以查看可用的 工具，然后禁用 agent 不需要的工具。这些工具使 agent 能够编写文件、编写和运行代码片段、搜索和安装库以及执行终端命令。

使用 agent 的 设置 菜单重命名对话线程并查看系统提示。关闭或重启工作区后，聊天历史记录不会保留。请在结束会话之前同步您想要保存的任何代码或模型输出。

要更改代理的 LLM，请在提示词文本框底部选择当前模型名称。不同提供商的模型行为各不相同。 了解有关提示词工程最佳实践的更多信息.

常见的 AIP 代理用例

您可以使用 AIP 代理来：

  • 获取有关您的数据的编码技巧和说明
  • 自动执行重复性任务，例如安装库和清理数据
  • 构建可发布的 Dash 和 Streamlit 应用程序

使用由 Maestro 提供支持的托管环境功能，可以在 Jupyter® 工作区、应用程序、转换和模型输出之间一致地还原 Jupyter® conda/PyPI 环境。Maestro 是一款 Foundry 库管理工具，可让您为 Jupyter 工作区安装和管理库。它与 conda 和 pip 集成，让库安装更加轻松，并有助于保持环境一致。要将命令转换为 Maestro，请参阅下方适用于以下任一项的说明：

conda 或 or PyPI.

托管环境在代码工作区工作流之间保持一致，从而无需重新运行相同的 mamba 和 pip 命令，每次重启工作区、启动应用程序或运行 Jupyter® Notebook 转换时都需要重新执行。借助托管环境，您工作环境中已安装的库会通过您的 /home/user/repo 文件夹中的文件进行跟踪，从而使环境能够在不同工作流之间恢复到原始状态。

以下两个文件用于跟踪您的托管环境：

  1. /home/user/repo/.envs/maestro/meta.yaml：被称为环境 清单，其中包含一组 请求的 适用于您环境的库和版本。 详细了解 meta.yaml 文件.
  2. /home/user/repo/.envs/maestro/hawk.lock - 称为环境 "锁定文件"，其中包含一组 "已解析" 适用于您环境的库和版本，根据清单中指定的约束解析而来。该 hawk.lock 文件取代 conda.lock，该文件已被弃用。 了解有关 hawk.lock 文件.

我们不建议修改 hawk.lock 锁定文件。相反，请依靠安装命令为您更新这些文件。除非出现 git 冲突，否则您也无需修改 meta.yaml 文件；在以交互方式安装库时，该文件将自动更新。

您的托管环境安装在您的 /home/user/envs/default 文件夹中。此环境会在以下阶段之前还原：

  • 启动您的 Jupyter® 工作区
  • 启动从您的工作区生成的应用程序
  • 运行从您的工作区生成的 Jupyter® Notebook 转换
  • 运行模型

2. 更新您的托管环境

按照以下步骤更新您的托管环境并管理库。

使用 Maestro 管理 conda 库

    Copied!

  • 使用终端卸载： 要卸载库，请在终端中运行以下命令：

    Copied!

  • 使用“库”面板进行安装： 搜索库名称（例如， numpy）并进行安装。

  • 使用终端安装： 要安装库的最新版本，请在终端中运行以下命令：

4. 在 JupyterLab® 界面中查看环境文件

在 Data Connection 中导航至 要在标记和发布函数的过程中查看进度，请选择 工作区中的下拉菜单并选择 显示隐藏文件.

5. 使您的受管环境与 hawk.lock 文件

检出新分支或拉取新的 git 更改后，您的 hawk.lock 文件的内容可能会发生变化。

要同步您的受管环境，请在工作区终端中执行以下命令：

Copied!
1
maestro env install

maestro 是用于更新受管环境的命令行界面。上述命令会从清单中重新解析锁定文件，并将环境安装到 /home/user/envs/default 文件夹。

6. 解决环境文件中的 git 冲突

要解决托管环境中的 git 冲突，请先删除 hawk.lock 文件。请导航至 meta.yaml 文件以解决所有冲突，然后合并您的分支。

合并后，在终端中运行 maestro env install 命令以重新生成 hawk.lock 文件并重新安装托管环境。

7. 升级您的托管环境

要更新您的托管环境，请先移除 hawk.lock 文件。然后，删除您的 /home/user/envs/default 文件夹（rm -rf /home/user/envs/default）。最后，在您的终端中运行 maestro env install 命令以重新生成您的 hawk.lock 文件。您的环境将使用升级后的库版本重新安装。
