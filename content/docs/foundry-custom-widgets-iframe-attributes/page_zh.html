启用其他 iframe 属性

某些浏览器权限（例如摄像头和麦克风访问权限）始终要求应用程序用户通过浏览器提示向 Foundry 授予权限。启用 iframe 属性后，应用程序即可请求访问权限，但用户仍必须明确授予权限。请参阅 Permissions Policy 文档 ↗ 以了解更多信息。

自定义小部件运行时会使用一个 <iframe> ↗ 元素，其限制性属性默认会禁用某些浏览器功能（例如弹出窗口和摄像头访问权限）。不过，小部件开发者可以为自定义小部件启用其中一部分属性值。随后，应用程序构建者必须手动为所请求的属性值授予权限，这些属性值才能生效。通常，小部件开发者与应用程序构建者是同一个人。

可用的 iframe 属性

小部件开发者可以请求启用以下 iframe 属性：

allow ↗ 属性值：

  • camera
  • microphone
  • autoplay

sandbox ↗ 属性值：

  • allow-downloads
  • allow-forms
  • allow-popups

声明请求的 iframe 属性

小部件开发者可以在其自定义小部件配置的 permissions 字段中声明请求的 iframe 属性：

允许宿主应用程序中所请求的 iframe 属性

选择启用某些 iframe 属性可能需要应用程序构建者确认一个 检查点。

在 Workshop 中，应用程序构建者可以在配置自定义小部件时，为所请求的 iframe 属性授予权限。 权限 部分，位于 参数 和 事件 部分，会显示这些设置。

在开发过程中，小部件开发人员可以临时允许所请求的 iframe 属性以进行测试；随后可以使用 自定义小部件演练场 环境或 VS Code 工作区 而无需明确授予权限。

下载小部件中包含的静态资源

下面介绍了两种下载自定义小部件中包含的静态资源的方法。请查阅 Vite Static Asset Handling ↗ 文档以获取更多信息。

直接使用 href

在自定义小部件开发模式下,开发服务器从与自定义小部件运行时不同的源(例如, localhost)提供资源。此行为可能导致浏览器打开新标签页,而非触发下载。但在生产环境中使用自定义小部件时,资源将正确触发下载。

当使用 Vite 方法 将静态资源导入为 URL ↗时,资源 URL 可直接用于 <a> 元素的 href 属性中,并结合 download 属性:
