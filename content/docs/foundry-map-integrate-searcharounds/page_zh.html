地图周边搜索

周边搜索是基于关联或函数的搜索，允许用户探索相关对象。您可以 在控制面板中配置周边搜索限制。

基于关联的周边搜索

用户可以从任何地理空间对象向与其关联的任何地理空间对象执行周边搜索。请参阅 创建关联类型 以了解更多信息。

基于合并关联的周边搜索

地图应用程序可以运行两步周边搜索，即一个地理空间对象通过一个中间对象（可以是非地理空间对象）与另一个地理空间对象相关联。

  • 中间对象可能表示两个对象之间的关系。例如，一个 Factory 对象和一个 Supplier 对象可能通过一个 Supply Contract 对象相关联；当运行周边搜索时，地图将显示一条从工厂到供应商的弧线，该弧线代表供应合同。
  • 中间对象也可能是两个对象都参与的事件。例如，一个 Customer 对象可能关联到一个 Distribution Center 对象，通过一个 Delivery 事件 - 在这种情况下，投递事件将显示为沿弧线移动的圆圈。圆圈的位置将根据事件的开始时间和结束时间以及当前选定的时间戳，沿弧线通过插值计算得出。

有两种方法可以配置在关联合并 Search Around 中使用的对象：

  • 将中间对象指定为关联合并对象，这意味着该对象类型本身永远不会出现在 Search Around 列表中，但其传递关联会出现在其中。
  • 指定要合并的特定关联遍历。如果只需对中间对象的部分关系进行关联合并，请使用此方法。

将中间对象类型设置为始终关联合并

要将中间对象类型指定为始终关联合并，请开启 始终关联合并 ，该选项位于 Search Around 部分中，该部分位于中间对象类型的 Capabilities 标签页中。这意味着该对象类型本身永远不会出现在 Search Around 列表中，但其传递关联会出现在其中。

例如，如果中间对象类型为 Delivery，且两侧的对象类型分别为 Distribution Center 和 Customer，那么当选中某个 Distribution Center 进行 Search Around 时， Delivery 不会显示在列表中，但 Customer (via Delivery) 会显示。请参见以下示例：

将特定关联遍历设置为关联合并

要将特定关联遍历指定为关联合并，请同时指定 要合并的传入关联 和 要合并的传出关联 ，这两项设置位于中间对象类型的 Search Around 部分（ 功能 选项卡）。

例如，如果您希望能够从 Supplier 对象类型到 Distribution Center 对象类型（经由 Delivery 对象类型）执行 Search Around，则需要将 Delivery 对象类型配置为中间对象，方法是选择 Delivery <-> Supplier 关联作为 要合并的传入关联 ，并将 Delivery <-> Distribution Center 关联作为 要合并的传出关联。 Supplier 被选中进行 Search Around 时， Distribution Centers (via Delivery) 将作为选项显示在列表中。

如果您希望两个关联遍历方向都显示在 Search Around 列表中（例如，既让 Suppliers 拥有 Distribution Centers (via Delivery) ，也让 Distribution Centers 拥有 Suppliers (via Delivery)），则需要将这些关联同时配置为 要合并的传入关联 和 要合并的传出关联。

Search Around 函数

您可以创建功能强大的 Map Search Around （用于地图），方法是编写 Map Search Around 函数。这允许您编写 TypeScript 函数，该函数接收选定的对象并遍历本体论，以取回与正在进行的特定分析相关或有用的所有对象。

Map Search Around 函数返回一个数据结构，其中可以包含：

  • objectRids：对象，将被添加到地图上。
  • edges：边，包括源对象、目标对象以及可选的中间对象。源对象和目标对象将被添加到地图上，并在它们之间绘制一条弧线；当选中该弧线时，将列出中间对象。
  • measures：时间序列度量，将被添加到 时间线。

提示与故障排除

  • 为了获得最佳性能，所有代码都应尽可能保持异步。在函数代码中，请始终使用 allAsync() 和 getAsync() 而不是 all() 和 get() 来加载对象，并尽可能少地使用 await 语句。
  • Map 应用程序将使用函数的最新发布版本。要发布您的函数，您需要为所需的分支/提交打上符合 semver 规范的版本标签，例如：1.0.0。
  • 您的仓库需要访问您想在函数中使用的所有本体论对象和关联。此配置可在 本体论 部分（位于仓库的 设置中）进行。
  • 如果对象类型及其支撑数据集定义在与仓库不同的项目中，则包含该仓库的项目需要引用这些支撑数据集及相应的对象类型。

此示例代码包含三个基于开源示例数据的 Search Around 函数：

  • airportsRelatedObjects：返回与一组机场相关的各种对象。可在地图模板中用于机场分析。

  • routesBetweenAirports：给定一组机场，返回仅在这些机场之间的所有航线。

import { Distance, Function, Integer, Filters } from "@foundry/functions-api";
import { ObjectSet, Objects, ExampleDataAirport } from "@foundry/ontology-api";

export interface IMapSearchAroundResults {
    objectRids?: string[];
    edges?: IMapSearchAroundEdge[];
    measures?: IMapSearchAroundMeasure[];
}

export interface IMapSearchAroundEdge {
    sourceObjectRid: string;
    targetObjectRid: string;
    intermediaryObjectRids?: string[];
}

export interface IMapSearchAroundMeasure {
    objectRids: string[];
    measureId: string;
}

export class MapSearchAroundFunctions {

    /**
     * Return relevant objects for airports: runways, routes
     */
    @Function()
    public async airportsRelatedObjects(airportSet: ObjectSet<ExampleDataAirport>): Promise<IMapSearchAroundResults> {
        const relatedObjects = (await Promise.all([
            airportSet.searchAroundExampleDataRunway().allAsync(),
            airportSet.searchAroundRoutes().allAsync(),
        ])).flat();

        const objectRids = relatedObjects.map(o => o.rid!);

        return {
            objectRids,
        };
    }


    /**
     * Return all airports within the specific number of kilometres of the selected airport (defaulting to 50)
     */
    @Function()
    public async nearbyAirports(airport: ExampleDataAirport, distanceKm?: Integer): Promise<IMapSearchAroundResults> {
        const point = airport.airportLocation;
        const distance = Distance.ofKilometers(distanceKm ?? 50);

        if (point === undefined) {
            return {};
        }

        const nearbyAirports = await Objects.search()
            .exampleDataAirport()
            .filter(airportFilter => airportFilter.airportLocation.withinDistanceOf(point, distance))
            .allAsync();

        const objectRids = nearbyAirports.map(o => o.rid!);

        return {
            objectRids,
        };
    }


    /**
     * Return only routes that depart from and arrive in the selected airports
     */
    @Function()
    public async routesBetweenAirports(airportSet: ObjectSet<ExampleDataAirport>): Promise<IMapSearchAroundResults> {
        const airports = await airportSet.allAsync();
        const airportCodes = airports.map(airport => airport.airport);
        const airportsByCodes = new Map(Array.from(airports, a => [a.airport, a]));

        const routes = await Objects.search()
            .exampleDataRoute()
            .filter(route => Filters.and(
                route.origin.exactMatch(...airportCodes),
                route.dest.exactMatch(...airportCodes),
            ))
            .allAsync();

        const edges = routes.map(route => ({
            sourceObjectRid: airportsByCodes.get(route.origin!)!.rid!,
            targetObjectRid: airportsByCodes.get(route.dest!)!.rid!,
            intermediaryObjectRids: [route.rid!],
        }));

        return {
            edges
        };
    }

}
