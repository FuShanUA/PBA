探索其他操作类型

该 快速入门 教程构建了一种操作类型：修改单个对象上某个属性的规则。操作类型可以表达的内容远不止属性编辑。同一配置界面还允许您创建和删除对象、管理对象之间的关联、在函数中运行自定义逻辑、调用外部系统、通知用户、触发构建以及合并场景编辑。

本页将介绍其中的每项功能，说明其使用时机，并提供指向参考文档的链接。示例将继续使用 Demo Ticket 对象类型（来自 快速入门 教程），以便您可以在同一个本体论中跟随示例进行操作。

前提条件

  • 请完成 快速入门 教程。其中涵盖了创建向导、参数和提交条件，本页其余部分假设您已了解这些内容。
  • 请确认您计划更改的对象类型已 配置为可编辑。

在何处配置规则

以下功能均通过规则进行配置，规则可以在两个位置添加。

创建向导会为新操作类型配置第一条规则。在 操作类型 步骤中，打开 对象 标签页，选择对象类型，然后选择操作所做的更改，具体选项位于 “对象操作”下。选择要包含在 映射 步骤中的属性。 入门 教程将逐步讲解此流程。

对于已存在的操作类型，请在 Ontology Manager中将其打开，选择 规则 选项卡，然后选择 添加新规则 以选取所需的规则。本页所述的每个规则都可以在此添加。

单个操作类型可以组合多个规则。 函数规则 是个例外：它不能与其他本体论规则组合使用。

创建和删除对象

入门教程会修改用户选择的对象。若要改为创建新工单，请添加一条 创建对象 规则并选择 Demo Ticket 对象类型。该对象类型的主键在本示例中为 Ticket ID ，是一个必须填写的属性。请添加新对象所需的其他属性，例如 Title、 Status和 Priority，方法是选择 添加属性。

您添加的每个属性都会自动创建一个同名参数，并将该属性映射到该参数。您也可以改为将属性映射到对象引用参数的某个属性、用户无法更改的静态值，或者映射到当前用户或提交时间。请查看 值和参数 以了解所有映射选项。

另外两条相关规则涵盖了其余情况：

  • 创建或修改对象： 修改对象引用参数中提供的对象。当未提供对象时，将使用自动生成的唯一 ID 或用户提交的主键创建一个新对象。
  • 删除对象： 删除对象引用参数中提供的对象。此规则不能引用由同一操作创建的对象。

当操作类型包含多个规则时，Foundry 会将它们编译为针对每个对象的单次编辑，因此规则的顺序会影响结果，且某些组合不受支持。请先查看 无效组合 ，然后再将创建、修改和删除规则组合到单个操作类型中。

管理对象之间的关联

操作可以维护对象之间的关系及其属性。需要使用哪种规则取决于 关联类型的基数。

对于多对多关联类型，请添加“ 创建关联 ”规则来关联通过对象引用参数提供的两个对象，或添加“ 删除关联 ”规则来移除它们之间的关系。

对于一对一或一对多关联类型，关系存储在对象的外键属性中。请使用“ 修改对象 ”规则来设置或清除该属性，而不是使用关联规则。

您还可以在单个操作中创建对象及其多对多关联。配置一个 创建对象 规则，所用对象类型具有多对多关联类型，然后选择 添加关联 （位于 添加属性 下方），以选择关联类型并配置关联。

使用函数运行自定义逻辑

规则将编辑描述为声明式映射，这并不总是足够的。当您想要修改与用户所选对象相关联的所有对象、根据读取多个对象的业务逻辑计算属性值，或者创建多种类型的对象并将它们关联在一起时，请考虑使用 本体论编辑函数 来支撑该操作。

添加单个 运行函数 规则，然后选择已发布的函数以及要使用的版本。函数的每个输入都会在操作类型上创建为参数，随后您可以像约束任何其他参数一样对其进行约束。 运行函数 规则无法与其他 本体论规则组合，因为仅凭函数代码就能表达它们所能表达的一切。

请按照 函数支撑的操作教程 了解完整的操作流程，包括如何 更改函数版本 （即该操作所引用的版本）。默认情况下，操作会保持在您所选的版本上。启用 自动升级 改为在运行时解析版本范围，并在执行此操作之前，请先查看其中所述的权限与破坏性变更之间的权衡。

使用 webhook 调用外部系统

当 Foundry 之外的系统是流程中某一部分的事实来源时，webhook 规则会作为应用操作的一部分向该系统发送请求。操作参数可以作为输入传递给 webhook。

有两种独立的规则均可发送该请求，你添加的规则将决定其运行时机：

  • Webhook: 该请求在应用对象编辑后发送。请从 Side Effects 分组中添加此规则。一个操作类型可以包含多个此类规则，且失败情况不会显示给最终用户，而该用户可能已经看到了成功消息。
  • Writeback Webhook: 该请求会在评估任何其他规则之前发送。请从 External Request 分组中添加此规则。如果请求失败，则不会应用任何编辑，最终用户将看到失败信息。一个操作类型只能包含一个此类规则，且其 输出参数 可供后续规则使用。

该 webhook 必须已存在于 Data Connection 中，然后才能在规则中选择它。请按照 设置 webhook ，了解配置步骤，并查看 webhooks ，了解输入参数、输出参数和身份验证选项。

在应用操作时通知用户

一个 通知 规则会告知用户该操作已应用。收件人可以是固定的一组用户，也可以从对象参数的某个属性派生，而内容可以是引用操作参数的模板。每位收件人都会根据各自的通知偏好收到平台内推送通知、电子邮件或同时收到两者。

通知会在应用操作的所有编辑后发送，但其内容是根据这些编辑应用之前的本体论状态生成的。请参阅 设置通知 ，了解具体示例，并查看 通知 ，了解所有收件人和内容选项。

触发构建

一个 计划 规则会在应用操作时触发 计划 的构建。可从 高级 组中添加此规则。这样，本体论中的最终用户工作流就能作为操作的一部分重新计算数据集。该计划必须处于 项目范围模式。

带有计划规则的操作类型会在构建开始后应用其对本体论的编辑，而不是等待构建完成。请参阅 触发计划构建 以了解如何向参数化计划传递值，以及如何将生成的计划运行 RID 记录到对象上。

合并场景中的编辑

在 场景 中所做的编辑仅存在于该场景的沙箱中，不会影响主本体论。合并操作会将所有已暂存的编辑作为单个事务进行提交。合并操作需要一个 场景 参数，该参数包含场景的 RID，该值通常从 Workshop 变量或本体论 SDK 应用程序传入。

创建合并操作有两种途径：

  • 创建新的操作类型，并在创建向导中选择 场景 选项卡，然后通过添加相关的 对象类型 和 关联类型来定义合并范围。
  • 向现有的操作类型添加 应用场景 规则，可在其 规则 选项卡中完成。

在这两种情况下，请使用该操作类型的 安全与提交条件 选项卡来定义哪些用户有权运行合并。请查阅 合并场景 以了解完整配置。

本体论场景目前处于 Beta 阶段，在您的注册中可能无法使用。请联系 Palantir 支持团队以申请获取场景的访问权限。

对接口执行操作

接口针对每种本体论编辑操作都设有专门的规则：

  • 创建接口对象
  • 修改接口对象
  • 删除接口对象
  • 在接口对象上创建关联
  • 在接口对象上删除关联

每条规则都针对实现该接口的任意对象类型，而非某个特定的对象类型。修改规则和删除规则接受接口引用参数，以替代对象引用参数。查看 接口上的操作。

在规则中映射结构体属性

结构体属性 的值取自一个结构体参数，该参数的嵌套字段与属性的各个字段一一对应。在规则中映射该属性，并确保每个字段都已映射。查看 结构体上的操作。
