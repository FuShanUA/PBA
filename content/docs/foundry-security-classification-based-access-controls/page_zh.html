基于分类的访问控制

基于分类的访问控制默认情况下在 Foundry 上未启用。分类标记可能因机构而异，因此在不同的 Palantir 环境中可以进行不同的配置。分类标记的配置需要 Palantir 参与。

基于分类的访问控制（CBAC）是用于保护敏感政府信息的强制性控制。CBAC 标记（也称为分类标记）通过要求用户拥有特定的分类标记才能访问信息来限制访问。

分类标记的访问权限可能与在 Palantir 平台之外进行的安全许可流程相关联。与一般的强制性控制一样，分类标记可以与其他访问要求结合使用，例如 自主角色 和 强制标记 可以应用于某个资源。

分类标记的关键特征

分类标记特有的三个显著特征如下：

  • 层级性： 分类标记的一个常见用例是限制对敏感信息的访问，其中信息的敏感性是以层级方式定义的。例如，您可能有一组用户仅有资格访问标记为“机密”或以下的敏感数据。另一组用户可以有资格访问标记为“绝密”或以下的敏感信息，其中可以包括“机密”数据。
  • 分类标记中的析取元素： 非分类标记以合取方式工作——用户需要拥有应用于资源的所有标记才能访问。分类标记可以包含析取组件，属于分类标记析取组件中某一组的用户即可满足 CBAC 访问条件。这通常用于定义可发布性，例如在不同组织或国家之间共享。例如，来自以下任一组织的用户 country A OR country B 可以满足分类标记中的析取元素（参见 有关如何思考问题类别并识别它们的更多细节).
  • 分类标记的普遍性： 使用 CBAC 强制控制的环境要求所有项目都设置 项目分类 。此外，所有数据集都必须具有数据分类，这意味着原始数据集（即没有输入的数据集）必须具有 文件分类.

关键概念

分类标记

分类标记按类别进行配置。例如，一个类别可能定义数据的类型，另一个类别可能描述该数据应如何传播（即共享）。

一个分类可以包含多个分类标记。一个分类可以由来自不同类别的分类标记组成。关于哪些分类标记组合是有效组合的规则可以由 Palantir 配置并在平台中强制执行。

合取和析取的分类标记类别

分类标记类别的一个定义性特征是它们可以支持析取（OR）行为。当类别为合取（AND）时，用户必须拥有该类别中使用的所有分类标记的访问权限才能访问分类数据。当类别为析取时，用户只要拥有该类别中的任一标记即可被授权访问带有标记的分类数据。

整个分类的各组件以合取方式组合。这意味着，如果一个分类包含来自多个类别的分类标记，用户必须满足每个分类标记类别中的所有组件才能访问该数据。

文件和数据分类

文件分类是用户必须满足才能发现该文件的分类。此限制是在其他要求（例如项目的分类以及项目或文件的强制标记）之外的附加要求。

数据分类适用于某些类型的文件，例如数据集。数据分类是指用户必须满足才能查看文件中数据的分类。用户必须满足数据分类才能查看文件中的数据，但这并不影响他们发现该数据集的存在以及查看其元数据（例如名称、描述和 schema）的能力。数据分类无法直接编辑；相反，数据分类由以下内容组合而成：

  • 资源的文件分类（如果已设置）。
  • 所有上游 数据依赖项.

的数据分类。

这意味着数据分类始终至少与文件分类以及所有上游数据依赖项的数据分类一样严格。

项目分类

项目分类控制谁能够发现项目并访问其中的资源。要访问某个资源，用户必须满足该资源的项目分类以及该资源的文件和数据分类。在使用分类标记的环境中，所有项目都必须具有项目分类。创建项目时必须选择一个分类，之后可以更新但不能移除。

项目分类不会影响项目中数据集的数据分类，因此项目分类不会沿数据依赖项继承。如果其他项目中存在派生的下游数据集，则只有 数据 分类会被继承。这与项目标记的行为不同，项目标记会被下游数据集继承。

项目最高分类

项目最高分类指定项目中所有资源的最高分类。项目最高分类也称为“允许标记上限”。数据或文件分类更高的资源无法创建到最高分类较低的项目中，也无法移入其中。分类低于或等于项目最高分类的资源可以存在于该项目中，但这些资源仅对满足整个项目分类的用户可见。

在创建项目时，项目最高分类默认等于项目分类，但可以独立于项目分类进行编辑或移除。

将对象类型或关联类型添加到项目时，可能需要移除项目的最高分类。但请注意，如果项目中的对象类型或关联类型缺少文件分类，则将无法实例化。

如果在其他项目中的上游数据集上添加了更高密级作为文件分类，并被该项目内的数据集继承为数据标记，则该数据标记将违反项目最高密级。如果发生这种情况，数据仍将受到更高密级的保护，但会显示警告，并且在违规解决之前，无法在该项目中构建该数据集或任何下游资源。可以通过修复上游数据集上的分类并移除该上游数据集作为输入并重新构建数据集，或通过更新项目的最高密级来解决此违规。这与以下行为相同： 项目约束违规.
