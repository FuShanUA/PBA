合并分支

合并 允许您在决定复制更改之前，先暂存将引入父分支的更改。如果您的分支与父分支之间存在逻辑冲突，您可以在合并过程中解决冲突，并重新运行您的转换以检查结果是否正确。

在本文档的其余部分中，我们将您尝试合并的分支称为 源分支，将您尝试合并到的分支称为 目标分支.

预览合并

在编辑分支的任何时候，您都可以点击工具栏中的 预览合并 按钮进入合并状态，并查看源分支与目标分支之间的更改。Code Workbook 仅允许将分支合并到其直接父分支。进入合并后，源分支与目标分支之间的差异将在每个转换上高亮显示。请在内容面板中查找 已修改 和 冲突 标签以查看更改。在下面的截图中，源分支（右侧）与目标分支（左侧）之间的代码更改以绿色高亮显示。

在合并期间运行转换时，Code Workbook 会自动在输出数据集上创建一个 合并分支 。这使合并与目标分支和源分支相互隔离。这些合并分支将以以下形式显示在您的数据集上 vector-merge-{source}-{target}-{uuid}.

解决合并冲突

如果同一个转换在源分支和目标分支中都被修改，则可能出现合并冲突。本节将描述在此场景下会发生什么。

点击 预览合并时，系统会提示您需要先解决冲突才能继续合并。

点击发生冲突的转换将显示合并冲突视图。对于代码，内联冲突标记允许您选择要采用哪种逻辑。

解决合并冲突后， 合并分支 按钮将变为可用。

管理合并

在分支合并期间，您可以使用工具栏左上角的后退按钮返回目标分支。要在开始合并之前返回源分支，请点击 退出合并。退出时，您在合并中所做的任何更改都将被移除。

准备和退出合并是完全安全的，不会影响您在分支上所做的更改——您可以自由地预览和退出合并，以查看将引入目标分支的更改。如果在您开始合并后目标分支上引入了更改，工具栏中将出现一个 更新合并 按钮。您可以使用此按钮以目标分支中的最新逻辑更新您的合并。

完成合并

解决冲突并且所有其他分支特定的检查都成功后，点击 合并分支 将更改引入您的目标分支。您将看到一个包含两个开关的对话框：

第一个开关允许您选择是否将事务从源分支复制到目标分支。假设在创建分支后，master 分支上进行了额外的工作，并且在派生数据集的 master 分支上提交了新的事务。如果此开关设置为 True，则自 updated-branch 分支创建以来在 master 上创建的事务在合并后将不再显示在数据集上。

第二个开关允许您选择是否从数据集中删除源分支。请注意，这与删除工作簿分支本身不同，后者总是在合并时完成且不可配置。如果第二个开关为 True，源分支将从工作簿中创建的派生数据集中删除。

完成合并可能需要一些时间。合并完成后，您刚刚合并的分支将被自动删除，除非它仍有子分支。
