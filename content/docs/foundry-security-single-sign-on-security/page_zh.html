保护身份

身份安全最佳实践

使用单点登录身份提供程序 (IdP) 访问 Palantir Foundry 时,您应当遵守相关的安全最佳实践。

使用强多因素身份验证 (MFA)

Palantir 强烈主张采用超越传统用户名 + 密码方式的身份证明。我们的软件产品强制要求使用多因素身份验证。如果您在身份提供程序中使用自己实现的多因素身份验证,则应要求采用强形式的身份验证。

强形式身份验证的示例(大致按优先顺序排列):

  • 已连接的硬件令牌,例如兼容 FIDO2 的 USB 安全令牌(如 YubiKey、Google Titan)或 CAC 智能卡
  • 未连接的硬件令牌,例如一次性密码 (OTP) 令牌生成器(如 RSA SecurID、Thales SafeNet)
  • 软件令牌，例如移动设备身份验证器应用程序（如 Microsoft Authenticator、Google Authenticator）
    • 相比移动设备上的推送通知，更推荐使用 OTP 生成器
  • 生物识别技术，例如指纹或面部识别（如 Apple Touch ID 和 Face ID、Windows Hello）

其他形式的多因素身份验证（MFA），例如基于短信的 OTP（文本消息）、电子邮件 OTP 和两步验证（点击链接）或安全问题，不属于强身份验证方式，应予以弃用并改用其他方法。

如果您的身份提供商未强制实施多因素身份验证，我们的产品原生支持多因素身份验证。

要求定期重新进行身份验证

Palantir Foundry 有意强制规定相对较短的最大会话生命周期，以强制定期向身份提供程序重新进行身份验证。由于会话令牌可能被攻击者窃取并可能在其有效期内被滥用，对所有用户会话强制实施相对较短的生命周期可以在一定程度上确保任何滥用行为都受到时间限制。

出于同样的原因，您应确保身份提供商生成的会话令牌的生命周期不过于宽松。

实施零信任安全原则

如果您使用现代身份提供商，应启用并使用零信任技术和策略。此类技术可能包括条件访问、设备健康或状态评估、强多因素身份验证声明及相关控制措施。请参阅您的身份提供商文档，了解可用的功能以及如何实施这些功能。

零信任安全模型的最佳实践包括：

  • 不要基于薄弱的安全指标来信任设备或用户。这包括基于软件的机器证书、单因素身份验证或网络位置。
  • 不要让用户或设备免于强制安全控制。
  • 访问敏感资源时，要求进行近期的强多因素身份验证。
  • 要求以设备安全或健康证明或评估作为访问条件。
  • 要求在出现异常登录或活动时进行重新身份验证。

严格管理服务账户

服务账户通常对敏感数据拥有宽泛的访问权限，且与标准用户账户相比往往安全性较差。这使它们成为攻击者的诱人目标。

服务账户管理的常见陷阱包括：

  • 服务账户可能被多人访问。
  • 服务账户可能未启用多因素身份验证。
  • 在人员离开您的组织后，服务账户的凭据可能未被轮换。
  • 服务账户的凭据或令牌可能被硬编码在脚本或应用程序中。

如果您在 Palantir Foundry 中使用服务账户，务必妥善保护它们以保障您的数据安全。

服务账户管理的最佳实践包括：

  • 确保每个服务账户都有文档记录、有指定的所有者，并定期审查其适用性。
  • 配置您的身份提供程序，仅允许您的服务账户从特定 IP 地址进行身份验证。
  • 在可能的情况下，要求服务账户使用多因素身份验证。
  • 将服务账户凭据材料存储在特权访问管理（PAM）解决方案中。
  • 要求通过多方身份验证才能访问服务账户凭据材料。
  • 根据团队变动或人员离职情况，按需轮换服务账户凭据材料。
  • 严格监控服务账户行为、登录和凭据材料。

中央身份验证

中央身份验证 是由 Palantir 管理的 Microsoft Entra ID（Azure AD）身份提供程序。Central Auth 由 Palantir 信息安全团队管理，旨在为没有自己的身份提供程序或尚未将身份提供程序与 Foundry 集成的客户提供安全优先的身份验证解决方案。

如果您的 Foundry 安装没有身份提供程序，我们或许能够通过 Central Auth 为您提供访问权限。如需了解更多信息，请联系您的 Palantir 代表。

Central Auth 安全

Central Auth 可作为 SAML Multipass 领域与您的 Foundry 安装集成。集成后，用户账户的预配和取消预配由 Palantir 管理。用户组、标记和其他 Platform 安全功能仍由您管理。

所有 Central Auth 账户都必须满足严格的安全控制要求：

  • 需要使用高强度密码和强多因素身份验证。
  • Central Auth 用户可能需要根据可疑登录或可疑行为重新进行身份验证。
  • 超过 30 天未使用的账户可能会被禁用，恕不另行通知。
