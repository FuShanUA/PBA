Ontology SDK TypeScript 1.1 正式发布

发布日期：2024-04-24

在为主要版本升级（TypeScript 2.0）做准备之际，我们发布了次要版本 1.1。将您的代码迁移到新版本将帮助您为 TypeScript 2.0 做好准备。

我们为什么要开发 TypeScript 2.0？

为了从新的本体论原语（如本体论接口和实时订阅）中受益，并以更高效的方式处理数据，我们重构了 OSDK TypeScript 语义。此更改将标记为主要版本 v2.0，将于 2024 年底之前发布。

在发布 2.0 版本之前，我们旨在先提供 1.1 和 1.2 版本作为通往即将到来的升级的桥梁，从而最大程度地减少对客户的影响。

为了明确起见，接下来即将发布的两个版本详情如下：

  • 版本 1.1： 此版本保持了当前的语言语法，但会弃用一些不再受支持的方法和属性。

  • 版本 1.2： 1.2 版本将于今年晚些时候发布，将主要提供与 1.x 版本相同的功能，但会引入新的语言语法。

Python 代码仓库中的原生加速 Spark

发布日期：2024-04-11

我们很高兴地推出 Pipeline Builder 中的原生加速 Spark 和 Python 代码仓库，这是一项旨在提升性能并降低批处理作业成本的功能。借助该功能，您可以利用底层硬件优化来提高数据管道的效率。

使用原生加速可获得以下优势：

  • 更快的性能： 原生加速优化了通用 SQL 函数，例如 select、 filter和 partition，可显著提升批处理作业的速度。
  • 成本降低： 通过提升性能，原生加速还有助于降低与批处理作业执行相关的成本，对于有大数据需求或高吞吐量要求的用户来说是理想之选。
  • 详细实现： 我们提供相关指南，帮助您设置此功能并将其集成到您的工作流中。

用法与限制

您可以在管道构建器和 Python 转换中启用原生加速。请注意，使用用户自定义函数（UDF）和弹性分布式数据集（RDD）操作的仓库也可能从此功能中略微受益。

原生加速对于拥有大数据工作流或对延迟敏感的工作流的数据科学家尤其有益。如果您频繁运行构建（每 5 分钟一次）或在成本敏感的环境中运营，原生加速可提供强大的解决方案。

要测试原生加速的成效，只需在启用该功能的情况下将管道运行一次。如果发现性能有所提升，请为该管道保持启用此功能。

项目约束正式发布 | 项目约束的引入支持对数据使用方式实施高级治理护栏。通过项目约束，所有者可以配置允许或禁止将哪些标记应用于项目内的文件。项目约束能够在技术上有效落实目的限制等数据保护原则。

这通常用于防止用户意外联接不应联接的数据，适用于用户可能需要访问多种标记、但不应允许特定标记数据组合的情形。例如，出于合规原因，银行可能要求敏感的投资数据绝不能与研究数据联接。然而，合规人员可能需要分别访问投资数据和研究数据才能开展工作。

如需更多信息，请参阅 项目约束文档 以及有关 如何配置的详细信息。
