HyperAuto V2 现已正式发布 [GA]

发布日期：2024-04-30

HyperAuto 是 Palantir Foundry 用于集成 ERP 和 CRM 系统的自动化套件，提供点击式工作流，可从源系统的原始数据动态生成有价值、可用的输出（数据集或本体论）。该功能自本周起已在所有租户中正式可用。

这一新的主要版本带来了显著更新的用户体验，并为自动化 SAP 相关的数据摄取和数据转换工作流提升了性能和稳定性。

要创建您的第一个 HyperAuto 管道，请参阅 入门指南.

实时 HyperAuto 管道概览。

SAP 数据的动态集成与管理

继之前的 测试版公告之后，以下功能现已正式发布：

  • 配置简便： HyperAuto 提供用户友好的点击式向导、便于快速设置的默认配置，以及面向高级用户的可自定义设置，可自动执行数据重命名、清洗、反规范化和去重等任务。
  • Pipeline Builder 集成： HyperAuto 可动态生成 Pipeline Builder 管道，提供透明的 UI，并包含用于更新和部署管道配置变更的变更管理工作流。
  • 实时 SAP 数据处理： HyperAuto 支持从 SAP 源系统进行实时数据流传输（需要 SLT Replication Server），使数据能够在几秒钟内从源系统流入本体论。
  • 支持 SAP 数据的静态切分： 在此新版本中，HyperAuto 支持在已上传的数据集之上进行操作，适用于无法与 SAP 源系统建立实时连接的情况。

开发者控制台中的静态应用网站托管现已正式发布（GA）

发布日期：2024-04-30

开发者控制台（Developer Console）现在提供托管静态网站的功能。这一新增功能使开发人员能够使用 Foundry 来托管和提供其网站服务，而无需外部网站托管基础设施。静态网站由一组固定的文件（HTML、CSS、JavaScript）组成，这些文件会下载到用户的浏览器中并在客户端进行展示。众多 Web 应用开发框架（例如 React）均可用于创建静态网站。

静态网站支持适用于由 Palantir 管理的域名上的部署（例如：enrollment.palantirfoundry.com 或对应的地理区域域名）。针对客户管理域名上的部署的功能支持目前正在积极开发中。

网站托管菜单。

Ontology SDK TypeScript 1.1 发布公告

发布日期：2024-04-24

为准备进行重大版本升级（TypeScript 2.0），我们发布了次要版本 1.1。将您的代码迁移到此新版本将帮助您为 TypeScript 2.0 做好准备。

我们为什么要开发 TypeScript 2.0？

为了受益于新的本体论原语（如本体论接口、实时订阅），以及以更高效的方式处理数据，我们重构了 OSDK TypeScript 语义。此变更将作为主版本 v2.0 发布，计划于 2024 年底之前推出。

在 2.0 版本发布之前，我们希望通过先提供 1.1 和 1.2 版本作为即将到来的升级的过渡，来最大程度地减少对客户的影响。

为便于说明，接下来的两个版本详情如下：

  • 版本 1.1： 此版本保持当前的语言语法，但将弃用一些不再受支持的方法和属性。

  • 版本 1.2： 版本 1.2 将于今年晚些时候发布，主要提供与 1.x 版本相同的功能，但会引入新的语言语法。

Python 代码仓库中的原生加速 Spark

发布日期：2024-04-11

我们很高兴地介绍 Pipeline Builder 中的原生加速 Spark 和 Python 代码仓库，这是一项旨在提升性能并降低批处理作业成本的功能。该功能允许您利用底层硬件优化来提高数据管道的效率。

使用原生加速可获得以下优势：

  • 更快的性能： 原生加速可优化通用 SQL 函数，例如 select, filter日 partition，从而显著提升批处理作业的速度。
  • 降低成本： 通过提升性能，原生加速还有助于降低批处理作业执行相关的成本，使其成为满足大数据需求或高吞吐量要求的理想选择。
  • 详细的实施说明： 我们提供相关指导，帮助您设置此功能并将其集成到您的工作流中。

使用情况和限制

您可以在 Pipeline Builder 和 Python 转换中启用原生加速。请注意，使用用户自定义函数（UDF）和弹性分布式数据集（RDD）操作的仓库也可以从此功能中略微受益。

原生加速对于拥有大数据或延迟敏感型工作流的数据科学家尤其有益。如果您频繁运行构建（每 5 分钟一次）或在成本敏感的环境中运行，原生加速可提供强大的解决方案。
