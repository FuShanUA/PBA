本体论架构

Foundry 本体论是组织的运营层。本体论位于集成到 Foundry 中的数字资产（数据集和模型）之上，并将这些资产与其现实世界中的对应事物相连接，范围涵盖工厂、设备和产品等物理资产，以及客户订单或金融交易等概念。本体论充当组织的数字孪生，包含实现各种类型用例所需的语义元素（对象、属性、关联）和动态元素（操作、函数、动态安全）。要了解有关 Foundry 本体论及其如何帮助实现更好决策的更多信息，请参阅 本体论文档.

Foundry 本体论由多项服务支撑，这些服务协同工作，对本体论中的对象进行索引、存储、查询和操作。本页提供了本体论后端架构的高层次概览。

功能组件与架构

Foundry 平台采用微服务架构,由多个服务共同组成本体论后端。本体论后端负责以下三个主要功能:

  • 数据源管理 用于向本体论提供数据,并管理本体论中的架构定义。
  • 查询、搜索和聚合对象 来自本体论,并支持特定的筛选和权限控制。
  • 向本体论写入数据的编排,包括对数据源建立索引,以及根据在 Foundry 中做出的决策或采取的操作对本体论对象进行编辑。

这些功能由构成本体论后端的各项服务共同处理,相关服务概述如下:

  • 本体论元数据服务 (OMS)
  • 对象数据库
  • 对象集服务 (OSS)
  • 操作
  • 对象数据漏斗
  • 小部件允许您使用

本体论元数据服务 (OMS)

本体论元数据服务 (OMS) 是一项总体性服务，用于定义现有的本体论实体集合。该定义包括对象类型的元数据、描述对象类型之间各种关系的关联类型、能够以结构化和受控的方式修改对象数据的操作类型，等等。

如需详细了解 Foundry 本体论的核心概念，请参阅 本体论元数据文档.

对象数据库

对象数据库是负责存储本体论中已索引对象数据的服务，旨在为用户应用提供快速的数据查询和查询计算。除存储已索引数据外，对象数据库还负责对用户编辑进行索引、查询和编排。

对象存储 v1（Phonograph） 是 Foundry 旧版的本体论后端组件。 对象存储 v2 是用于支撑本体论的下一代规范数据存储。有关这些服务的更多信息，请参见 有关如何思考问题类别并识别它们的更多细节.

对象集服务 (OSS)

对象集服务（OSS）是负责从本体论提供读取服务的服务；OSS 允许其他 Foundry 服务和应用程序从本体论查询对象数据，从而实现对对象的搜索、筛选、聚合和加载。

对象集

对象集是现实世界实体的列表，保存后可供日后参考，并可在支持对象的各类 Foundry 应用程序中使用。对象集会作为资源保存，便于与合作者共享。

对象集可以通过其定义（静态或动态）以及其在对象后端中的当前状态（临时或永久）来描述：

  • 静态对象集： 静态对象集保存为主键列表，无论输入数据发生任何变化，它都将保持不变。

  • 动态对象集： 动态对象集保存为用于创建该对象集的筛选器的表示形式。当新数据与筛选器匹配时，对象集将随之更新。

  • 临时对象集： 临时对象集主要用于在平台中将对象集从一个应用程序或服务传递到另一个应用程序或服务，并且只能由创建它的用户访问。临时对象集的示例 RID 如下 ri.object-set.main.temporary-object-set.37d7e171-2d11-4fcd-b031-9a0863f6f744 并在 24 小时内过期。

  • 永久对象集： 永久对象集存储在对象后端中，以供将来在整个平台中参考和使用。

操作

操作服务负责将用户编辑应用于对象数据库。操作提供了一种结构化的方式来修改对象的属性值，并为用户编辑启用复杂的权限和条件。此外，操作还可用于创建历史操作日志，以分析用户决策。

对象数据漏斗

对象数据漏斗（"Funnel"）是对象存储 v2 架构中的一个微服务，负责协调向本体论写入数据。Funnel 从 Foundry 数据源（如数据集、受限视图和流式数据源）以及用户编辑（来自操作）读取数据，并将这些数据索引到对象数据库中。Funnel 还确保在底层数据源更新时，已索引的数据保持最新状态。

本体论后端的演进

本节介绍对象存储 v1（Phonograph）的旧架构以及对象存储 v2 的更新架构。

对象存储 v1（Phonograph）架构 [计划弃用]

计划弃用

对象存储 v1 (Phonograph) 目前处于 计划弃用 阶段，并将于 2026 年 6 月 30 日之后不可用。 迁移您的对象类型和关联类型 到对象存储 v2。请参阅 Migrate object types and many-to-many link types from Object Storage v1 to v2 干预 升级助手 以了解更多信息。 如果您对工作流中从 OSv1 到 OSv2 的迁移有任何疑问，请联系 Palantir 支持。

对象存储 v1（Phonograph）是 Foundry 最初的对象数据库，旨在索引和管理来自各种潜在数据模型的信息，同时在本体论中的对象数据上保持 Foundry 的安全模型。除了索引和存储数据之外，对象存储 v1（Phonograph）还跟踪用户生成编辑的应用情况，通过搜索和聚合来处理复杂的用户查询，并协调数据回写。

对象存储 v2 架构

随着 Foundry 获得更多功能并不断发展以满足 Palantir 客户复杂的运营需求和日益增长的规模，对象存储 v2 从第一性原理出发构建，以支持下一代由本体论驱动的用例和工作流。

具体而言，新架构将原本集中在对象存储 v1（Phonograph）中的关注维度分离，并在系统设计中解耦各项职责；通过分离负责数据索引和查询的子系统，对象存储 v2 能够更轻松地水平扩展以满足未来的需求。

对象存储 v2 还集成了其他服务，例如 操作 ，通过 对象数据漏斗.

对象存储 v2 带来的新功能和能力包括：

  • 通过为所有对象类型启用增量对象索引（默认启用），显著提升了本体论数据索引的性能。
  • 单个对象类型的索引吞吐量提升至可索引数百亿量级的对象。
  • 借助多数据源对象类型实现更细粒度的对象权限，包括列/属性级别的权限。
  • 提升了用户编辑吞吐量，支持在单个操作中编辑多达 10,000 个对象。如果需要启用更高的限制，请联系 Palantir 支持团队，为您的注册创建变更请求。
  • 降低了用户编辑延迟，并可更快地观察到用户编辑结果。
  • 在对象类型发生破坏性架构变更后，能够迁移现有的用户编辑。
  • 通过支持流式数据源，实现对本体论的低延迟数据索引。
  • 每种对象类型最多支持 2000 个属性。
  • 通过基于 Spark 的查询执行层，实现更大规模的 Search Around 和更精确的聚合。
    • 默认情况下，Search Around 的限制为 100,000 个对象。如果您的用例需要超过 100,000 个对象的更大规模 Search Around，请联系 Palantir 支持团队了解如何启用此功能。
