管理标记

标记在 Foundry 设置的标记部分中进行管理。然后，标记会被应用于整个平台上的资源。

创建标记类别

类别删除

标记类别一旦创建，便无法删除。

管理用户可以创建标记和标记类别，并控制其元数据、可见性和成员资格。访问平台设置的标记部分需要特殊的平台权限。

如果您是拥有必要权限的管理用户，可以在平台设置的标记部分中点击 新建标记类别 按钮。

创建标记类别时，您可以设置 类别可见性 并分配类别权限。默认情况下，类别创建者将成为管理员。类别创建者可以选择将自己从创建者位置上移除，并添加另一位管理员。

类别可见性

标记可见性是按类别分配的，但组织类别除外。每个组织各自拥有自己的可见性设置。

在大多数情况下，标记和类别的名称及描述并非敏感信息，即使是没有标记访问权限的用户也应能看到。此行为由类别可见性决定，即 Visible 。

如果类别可见性设置为 Visible，组织中的所有用户都可以在标记界面中看到该类别及其标记的存在。如果用户不满足标记权限要求，他们将无法看到该标记或类别的存在。

如果标记类别的可见性为 Hidden，则该类别及其标记的存在被视为敏感信息。该 Hidden 类别可以对所有未被明确授予 Category Viewer 权限的用户隐藏。

标记类别确保以下可见性规则：

  • 可见性是针对一个类别及其所有标记统一定义的；不能按单个标记进行分配。
  • 所有有权访问某个标记的用户都可以查看该类别及该类别内所有其他标记的存在。这些用户不会作为“类别查看者”出现在 API 结果中，但应被视为隐含拥有该权限。
  • 所有在某个标记上拥有角色（管理员、移除者）的用户都可以查看该类别及该类别内所有标记的存在。这些用户不会作为“类别查看者”出现在 API 结果中，但应被视为隐含拥有该权限。
  • 所有在某个类别上拥有角色（管理员、查看者）的用户都可以查看该类别及该类别内所有标记的存在。

类别权限

用户可以拥有指定其如何与标记类别交互的权限：

  • 类别管理员： 可以更改类别的描述和权限，并在该类别中创建标记的用户。
  • 类别查看者： 可以查看该类别及其内所有标记的存在的用户。

按组织限制类别

可以将标记类别限制为单个组织，以确保该组织以外的用户永远无法看到它。

创建标记

标记删除

标记一旦创建，便无法删除或移动到其他类别。

如果您是拥有必要权限的管理用户，可以在平台设置的标记部分中点击 新建标记 按钮来创建新标记。然后，您可以分配标记管理员和标记移除者。

在 Foundry 中创建标记时，系统会自动授予您“管理权限”访问权限。我们建议将新标记的这些权限分配给不同的团队成员。这样，您可以避免仅依赖单一管理员来管理所有标记权限。

标记权限

以下权限适用于资源级标记。组织拥有单独的权限模型及其自身的 应用组织 和 扩展访问 权限。有关组织级权限的详细信息，请参阅 组织权限.

创建新标记时，您可以添加具有不同访问级别和权限的用户和组：

  • 管理权限： 可以授予权限以管理此标记、其成员及其元数据的用户。
  • 应用标记： 可以将此标记应用于项目和资源的用户。此权限仅授予应用标记的能力，不授予标记的成员资格。
  • 移除标记： 可以从项目和资源中移除此标记的用户。要移除标记，用户还必须能够应用该标记。
  • 成员： 可以查看受此标记保护的资源和项目的用户。

上述所有权限都是独立的，不会自动为用户提供成员资格权限。例如，用户可以对某个标记拥有“应用标记”和“管理权限”访问权限，但不是该标记的成员。在这种情况下，用户可以将该标记应用于平台上的文件、文件夹和项目，并管理该标记，但他们无法查看带有该标记的数据。

向用户授予标记

标记是全局授予用户的。当用户被授予某个标记时，该用户即获得全局权限来查看受该标记限制的内容类型。但是，拥有某个标记的访问权限并不意味着用户可以查看带有该标记的所有内容；用户仍必须通过其角色拥有相应权限。除非用户对该标记拥有额外的管理权限，否则无法将该标记的访问权限授予其他用户。

如果标记权限被授予某个组，则该组的新用户将继承这些权限。

应用标记

如果满足以下两个要求，您可以在资源、文件夹或项目上应用标记：

  1. 您拥有该标记的“应用标记”权限。
  2. 您拥有“更新资源上的标记”权限，该权限默认包含在所有者角色中。

应用标记是一项敏感操作，可能会限制下游用户。在将标记应用于现有管道之前，我们建议采取以下步骤：

  1. 确认标记是否存在： 确保您要应用的标记已创建，或者 创建标记.
  2. 为您的管道创建分支： 创建一个新分支以继续执行这些步骤。将标记应用于现有管道时，您可能需要在管道中的某个位置停止标记的传播（例如，以便最终用户可以打开已清除 PII 的数据集）。 stop_propagating 语法仅在受保护分支上生效。在您的新分支合并到受保护分支之前，您无法 stop_propagating 继承的标记。
  3. 查看数据血缘： 确认您的数据血缘图上包含完整的节点集合，并确认您了解潜在更改的下游影响。
  4. 查看管道中的事务类型： 标记在事务级别沿数据依赖关系传播。增量构建的数据集（APPEND 或 UPDATE 类型）需要特殊处理。具体而言，使用 APPEND 事务构建的数据集的最新视图将包含来自旧上游事务的依赖关系；相比之下，使用 SNAPSHOT 事务（Foundry 默认）构建的数据集的最新视图仅依赖于上游数据集的最新事务。如果您只处理 SNAPSHOT 事务，则可以继续执行这些步骤。否则，请参阅相关文档： APPEND 和 UPDATE 事务 以及 标记如何传播.
  5. 确定何时停止继承标记： 探索管道数据血缘中的节点，并查看列和数据预览，以确定应停止继承要应用的标记的位置。例如，一旦管道中删除了 DOB（出生日期）列，您可能希望停止传播 PII 标记。您可以在此步骤中激活模拟模式，以查看标记将在何处以及如何传播。
  6. 预先进行必要的转换更改： 在您的分支中，添加 stop_propagating 语法到您标识的转换中。将您的分支合并到受保护分支，以便 stop_propagating 语法处于活动状态。
  7. 构建您的生产管道： 构建所有下游转换，包括您标识为 stop_propagating的节点。您需要重新构建具有 stop_propagating 语法的数据集以及 stop_propagating 转换下游的所有数据集。如果您有下游 APPEND or UPDATE 数据集，请查看 本指南.
  8. 查看模拟的更改： 查看管道的最终模拟数据血缘。确认 stop_propagating 转换下游的数据集不受新标记应用的影响。确保敏感列不会出现在不会接收传播标记的数据集中。
  9. 应用标记： 上述步骤应确认应用标记将保护包含敏感数据的数据集，并且标记不会传播超出必要范围。此时，您可以应用标记。

如果您在应用标记后发现错误（例如，大量用户无法看到他们应该能够看到的数据），您可以移除标记，它将立即停止传播。然后，您应再次查看模拟更改以确定问题的原因。

移除标记

您可以移除标记以向更多用户授予访问权限、重新分类转换后的数据，或将派生资源与继承的标记分离。

例如，假设数据集 A 包含 PII，并且某个标记保护从数据集 A 派生的数据集。如果数据集 B 从数据集 A 派生，但已经过转换以移除 PII，您可能希望从数据集 B 中移除该标记，以允许更广泛地使用该数据。

要移除标记，您必须同时拥有应用和移除特定标记的权限。您还需要通过允许更改资源标记的角色访问相关资源。如果您使用的是默认角色，此访问权限可通过 Owner 组织概览

移除直接应用的标记

直接从文件、文件夹或项目中移除标记将立即从继承该标记的任何依赖项中移除该标记。直接移除标记后，您无需重新构建下游数据集，因为标记将立即在下游被移除。以下概念性示例显示了直接应用的 PII 标记。

移除继承的标记

您只能从受限视图和数据集中移除继承的标记。如果在派生依赖文件时移除或混淆了受限内容，您可以从派生文件中移除该标记。当继承的标记被移除后，下游数据集将不再受该标记保护，更多用户可能可以访问该数据集。用户仍需要拥有该标记的访问权限才能查看上游数据。

要从受限视图中移除继承的标记，请编辑受限视图并点击 停止传播 （位于相应标记旁边）。

要从数据集中移除继承的标记，请使用 stop_propagating 转换代码中的语法。要安全地移除继承的标记，请按照以下步骤操作：

  1. 确定在何处移除敏感数据： 检查您的完整管道，并决定要在何处移除敏感数据。
  2. 创建一个分支： 直方图 stop_propagating 语法仅在既受保护又启用了该设置的分支上才会生效 Require security approvals before merging 在您的分支合并到受保护分支之前，您将无法 stop_propagating 继承的标记。
  3. 进行必要的转换更改： 在您选择的数据集中，移除敏感数据并添加 stop_propagating 语法到转换中。
  4. 构建您的分支： 构建您的分支，并确认敏感数据已在输出数据集中被移除。 stop_propagating 语法此时不会阻止标记被继承，因为您当前在非受保护分支上。
  5. 合并您的分支： 确认敏感数据已被移除后，您可以安全地将您的转换更改合并到主分支。合并您的分支将应用 stop_propagating syntax.
  6. 构建您的主分支及下游依赖项： 直方图 stop-propagating 更改必须沿着管道中的最新事务传播，这要求您重新构建具有 stop_propagating 语法的数据集以及 stop_propagating 转换的数据集。所有数据集构建完成后，确认继承的标记已被移除。如果存在下游的 APPEND 或 UPDATE 事务，请查阅 其他文档。

调查标记继承

标记会 继承 沿着文件层级和数据依赖关系进行。这意味着文件本身可以受到标记的保护，并且/或者数据本身受到标记的保护。有时您需要调查标记的来源，而从概念上理解标记被继承的不同方式非常重要。

您可以通过选择文件以打开右侧详情面板，并在 Access requirements > Markings 区域的字段中添加命令。

调查文件层级

要查看文件的标记，请选择该文件并打开资源面板。在 访问权限 区域的字段中添加命令。

调查数据依赖关系

要确定标记源自哪个数据依赖项，您可以使用 Data Lineage 应用程序，或在打开数据集文件后使用 Compare 标签页。

由于标记是在 文件级别 应用的，但会沿着 事务传播，因此可能很难确定标记是何时为某个数据集引入的。我们建议先检查 Data Lineage 应用程序，以查看标记的来源。

使用 Data Lineage 应用程序，点击 Legend > Permissions type: Data access in datasets。然后展开数据血缘的所有上游节点，并遍历数据血缘以查看标记的来源。沿数据依赖关系继承的标记由数据血缘边车图标指示。
