数据集投影

数据集投影 可以提升一大类查询的性能。如果你有一个数据集，希望针对多种查询模式进行优化（例如，在两个不同的列上进行筛选），你应该考虑为该数据集添加投影。具体的 用例 示例如下所列。

每个投影通常支持单一查询模式，专注于改进对一组列的筛选或对一组列的连接。可以向一个数据集添加多个投影，并且投影支持所有列类型。此外，投影可以添加到快照数据集或增量构建的数据集中。 Noho 服务用于管理投影，并在 设置投影.

投影存在一些限制：

  • 投影只能添加到仅追加（append-only）的数据集上。在仅追加的数据集中，只能向数据集添加（即追加）行；无法从仅追加的数据集中手动删除文件或事务。具体而言，对仅追加数据集唯一可执行的 事务 是向数据集添加行的事务。 APPEND, SNAPSHOT日 UPDATE 投影系统会自动识别违反此要求的数据集并禁用其上的投影，但作为用户，你仍应避免这种情况。
  • 投影不支持 schema 演进，即使是像添加列这样增量一致的操作也不支持。

查看下面的示例用例，了解投影是否适合你的用例。首先学习如何 设置投影.

用例

许多类型的查询都能从投影中受益。以下示例将演示：

  • 在多个预先指定的维度上筛选大型数据集
  • 在预先指定的一组列上连接大型数据集
  • 在预先指定的一组列上聚合大型数据集
  • 读取频繁写入的增量数据集或流式数据集
  • 查询直接上传的数据

在一组列上进行筛选

给定一个有序的列列表，优化对列表任意 前缀 的筛选。投影只会加速将列与常量值进行比较的筛选。并且对字符串列的任何筛选必须 区分大小写.

例如，假设有一个投影针对有序列列表上的筛选进行了优化 ["x", "y", "z"]。 它将加速以下类型的查询：

  • SELECT * FROM dataset WHERE x = 5 AND y = 10 AND z = '15'
  • SELECT * FROM dataset WHERE x = 5 AND y = 10
  • SELECT * FROM dataset WHERE x = 5 AND q = 3
    • 如果对不在配置列表中的其他列还有额外的筛选条件，例如本例中的 q = 3，Spark 会自动尝试拆解它可以“下推”到数据源（在本例中为 x = 5）的筛选条件，并在之后应用其余条件。

但以下类型的查询不会被优化：

  • SELECT * FROM dataset WHERE abs(x) == 10
    • abs(x) == 10 没有将列与常量值进行比较。
  • SELECT * FROM dataset WHERE x % 100 == 10
    • x % 100 == 10 没有将列与常量值进行比较。
  • SELECT * FROM dataset WHERE y = 10
    • ["y"] 不是 ["x", "y", "z"].
  • SELECT * FROM dataset WHERE z = '15'
    • ["z"] 不是 ["x", "y", "z"].
  • SELECT * FROM dataset WHERE x = 5 OR q = 3
    • 的前缀，Spark 将无法把 x = 5 筛选条件下推到数据源，因为那样会遗漏 x = 5 为 false 但 q = 3 为 true 的行。

范围查询

投影可以选择性地加速筛选列上的范围查询，例如：

  • SELECT * FROM dataset WHERE x > 5 AND x < 10
  • SELECT * FROM dataset WHERE s LIKE 'SOME_PREFIX%'

局限性

  • 无法创建一个既包含非原始类型（例如数组）列、又支持筛选列上范围查询的投影。

在一组列上进行连接

给定一个无序的列集合和分桶数量，仅针对该精确集合和分桶数量优化连接。

例如，一个针对 {"x", "y"} 上的连接进行优化的投影将优化以下类型的查询：

  • SELECT * FROM dataset1 INNER JOIN dataset2 ON dataset1.x = dataset2.x AND dataset1.y = dataset2.y

但以下查询不会被优化：

  • SELECT * FROM dataset1 INNER JOIN dataset2 ON dataset1.x = dataset2.x

连接已投影和未投影的数据集

在 Foundry 中，大型数据集的连接通常执行排序合并连接（sort-merge join）。这包括根据连接键对每个数据集进行分区、按该键对每个分区排序，然后合并具有相同键的（已排序的）分区。

  • 在一般情况下，这涉及对两个数据集进行 shuffle 和排序。
  • 如果其中一个数据集具有针对在连接列上进行连接而优化的投影，则该数据集不会被 shuffle 或排序，但另一个数据集会被 shuffle 或排序。
  • 如果两个数据集都具有针对在连接列上进行连接而优化的投影， 并且使用相同数量的桶，那么两个数据集都不会被 shuffle 或排序。这可以带来显著的性能提升。将具有连接优化投影的数据集与显式分桶的数据集（无投影）进行连接时也是如此，不过同样地，桶的数量和连接列必须匹配 完全一致.

Foundry 中的大多数投影消费者在执行 sort-merge 连接时，默认情况下不会利用投影已经排序这一事实，因此你可能仍会在 Spark 查询计划中看到排序操作。在 transform 中，你可以使用 Spark 配置文件 BUCKET_SORTED_SCAN_ENABLED 来基于投影已排序这一事实修改 Spark 的行为，但这并不总能提升性能，实际上还可能使性能变差。

在预先指定的一组列上进行聚合

在 Foundry 中，聚合通常涉及根据聚合键对数据集执行 shuffle exchange（即对数据集进行分区）。当从经过哈希分桶的投影读取数据时（所有连接优化的投影都属于这种情况，但筛选优化的投影可能不属于这种情况），消费者可以避免这种 shuffle，从而在聚合过程中带来显著的性能提升。 主键期望检查 对于以仅追加方式增量更新的数据集，投影（基于主键列）尤其有益，一方面是因为投影执行的压缩操作，另一方面是因为可以利用投影的哈希分桶来执行用于计算期望的聚合。

从增量管道读取数据

增量管道可能产生非常高的文件数量，并相应地导致读取性能下降。例如，一个每五分钟写入十个分区的管道每年将写入超过一百万个文件。由于多种原因，这些文件难以读取，其中包括仅仅生成输入分区列表这样的操作。

投影提供了一种透明地压缩此类增量管道的方法。只需设置一个针对筛选或连接优化的投影，读取操作就会使用该投影。 了解有关在增量管道中使用投影的更多信息。

即使投影未与规范数据集完全保持最新，消费者仍然可以利用投影的筛选或连接优化，前提是在投影最后一次构建时的最新事务与规范数据集上的当前最新事务之间，规范数据集上没有 SNAPSHOT 或 DELETE 事务（或修改现有文件的 UPDATE 事务）。

查询上传的数据

CSV 是一种低效的数据查询文件格式，但上传到 Foundry 的数据（通过 Data Connection 从文件系统源上传、手动上传等）最初通常为 CSV 格式。创建 transform 作业是将这些 CSV 转换为更高效格式（如 Parquet）的一种方法。或者，你可以添加一个投影；读取操作将使用优化后的投影以获得更好的性能，而数据集仍包含原始的 CSV 文件。
