导出任务（旧版）

我们通常不建议使用导出任务将数据写回外部源。但是，根据您的 Foundry 订阅情况，某些源类型可能仍可使用并支持导出任务。

以下导出任务文档适用于尚未迁移到我们的 推荐导出工作流.

概述

导出任务允许您将数据从 Foundry 导出到各种外部数据源。导出任务的配置由两部分组成：

  • 源： 定义代理如何连接到数据源。其配置方式应与数据集同步相同。
  • 任务配置： 定义导出类型、输入数据集以及导出参数。

当在任务输出数据集上启动作业时，导出任务将被触发。

已知的导出任务限制

  • 导出任务未与标记和导出控制集成。通过导出任务导出的数据不需要对导出的数据集或流拥有取消标记权限。
  • 导出任务未针对性能进行优化。导出大量数据可能导致长时间运行的作业或无法完成的作业。
  • 导出任务没有用于配置的用户界面，而必须使用 YAML 进行配置以提供所需的配置选项。并非所有导出任务选项都有自助使用的文档说明；在某些情况下，导出任务只能通过 Palantir 的支持进行配置。
  • 导出任务仅适用于 agent-worker 源.

开始使用

配置导出任务的步骤：

  1. 在 Data Connection 中配置一个源，以连接到您要导出到的目标系统。
  2. 在 Foundry 文件系统中，导航到包含该源的文件夹。右键单击该资源并选择 Create Data Connection Task.
  3. 在任务编辑器 UI 中：
    • 保持源命名为 inputSource
    • 添加一个名为以下名称的输入数据集 inputDataset
    • 创建或选择一个名为以下名称的输出数据集 outputDataset
    • 针对您的具体导出类型配置 YAML

输入源 必须 必须命名为 inputSource 且输出数据集 必须 必须命名为 outputDataset。不使用这些特定名称可能导致任务错误。

支持的导出类型

Data Connection 导出任务支持写入各种常见的企业系统：

  • Amazon S3
  • OneLake 和 Azure Blob 文件系统 (ABFS)
  • HDFS
  • 兼容 JDBC 的系统配置效果的执行方式，包括：
    • 关系型数据库
      • PostgreSQL
      • 进行表批量同步的配置
      • MySQL
    • 数据仓库
      • Teradata
      • Snowflake
      • Vertica
  • 文件系统，包括网络文件系统 挂载在中间代理上
  • SFTP

常见配置选项

增量导出

所有导出类型都支持 incrementalType 参数，该参数控制数据随时间导出的方式。对于 JDBC 导出，此参数是按数据集指定的，而不是全局指定的。

当设置为 snapshot （默认值）时，导出任务会导出输入数据集当前视图中可见的所有文件。这意味着每次导出都将包含完整的数据集，无论之前导出过什么内容。

当设置为 增量式时，导出行为会改变以优化效率。首次导出的行为类似于快照，导出所有可用数据。在后续导出中，只要初始导出的事务仍存在于数据集中，就只会包含自上次导出以来新增的事务。如果初始事务不再可用（例如，由于数据集重建），系统将自动回退到完整快照导出。

基于文件的导出示例：

Copied!
1
incrementalType: incremental

路径重写

基于文件的导出支持 rewritePaths 配置选项，用于在导出过程中自定义文件名和路径。此字段接受一个由正则表达式和替换模板组成的映射：

Copied!
1
2
rewritePaths:
  "^spark/(.*)": "$1"  # Removes the spark/ prefix

替换模板支持多种动态替换模式：

  • 正则表达式捕获组，例如 $1, $2等，用于引用原始路径中匹配的部分。
  • 时间戳模式，例如 ${dt:yyyy-MM-dd}，使用 Java 的 DateTimeFormatter 语法插入当前日期和时间。
  • 使用以下方式引用 Foundry 事务 ID ${transaction}
  • 使用以下方式引用 Foundry 数据集 ID ${dataset}
