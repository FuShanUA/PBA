设置

  1. 打开 Data Connection 应用程序并选择 + 新建源 在屏幕右上角。
  2. 选择 AVEVA PI 从可用的连接器类型中选择。
  3. 请按照后续的配置提示进行操作，并使用以下各部分中的信息，继续完成连接器的设置。

了解有关 设置连接器 在 Foundry 中。

身份验证

您可以通过以下方式向 PI System 进行身份验证：

  1. 用户名和密码： 提供用户名和密码。我们建议使用服务凭据，而非个人用户凭据。
  2. Kerberos： 提供 Kerberos 配置。（仅在通过 中间代理连接时可用）

网络连接

连接器（例如，通过代理进行连接时的代理）需要能够访问 PI 服务器的 Web API。这通常是通过 HTTPS（默认端口 443）连接到所提供的 URL。

数据模型

PI System 连接器通过 Web API ↗ 工作，并遵循 流和值 ↗的概念，统一来自 属性 ↗ 具有数据引用和 PI 点 ↗。目标数据集中的每一行都将是带有来自关联流的元数据（名称、路径、webID 等）的值。

此外，PI System 连接器使用 Web API，这意味着由静态输入（而非标记数据）支撑的属性值无法通过流式传输或具有时态值目标的批量检索进行检索，但可以通过最新值批量同步进行检索。

您可以从四种不同的目标位置类型中进行选择，以指定应同步哪个流：

  • 属性筛选器： 一个动态筛选器，它会遍历 Asset Framework ↗ 层次结构（基于提供的路径，并按附加模式进行过滤）。
  • 标记名称过滤器： 一个动态过滤器，作用于 PI Point ↗ 名称（位于特定 Data Server ↗上）。
  • 标签名称列表： 静态列表，包含 PI Point ↗ ，通过其在特定 Data Server ↗上的名称进行标识。
  • WebIDs 列表： 静态列表，包含 WebIDs ↗ 可以引用 属性 ↗ 或 PI Points ↗。

批处理功能

增量行为

在通过绝对或相对时间窗口检索值时，可以使用增量配置。启用后，系统会在每次运行后保存每个唯一 WebID 的最新时间戳。在后续运行中，系统会将此保存的时间戳用作起始点。时间戳介于已保存时间戳与当前运行开始时间之间的数据被视为重叠数据，将被排除在处理之外。

文件分区

在通过绝对或相对时间窗口检索值时，您可以设置分区配置。当 设置分区配置 启用后，PI System 会检索配置窗口内的数据，并按顺序将数据写入磁盘，以避免超出运行时内存。

Web ID 缓存

如 数据模型 如上所述，第一步是解析 WebIDs ↗。如果 PI 服务器端没有任何更改，此操作可能会非常耗时且重复。为了加快重复同步的速度，用户可以启用 WebID 缓存来存储已解析的 WebID，并可在下次运行时重用该缓存。

有两种机制可以保持缓存处于最新状态：

  • 在任何同步配置上使缓存失效。
  • 可选的过期延迟时间，超过该时间后缓存应被视为已过期。

流式传输功能

流式同步使用 通道 ↗ 以便从服务器及时获取更新。

存活检查

为了确认与服务器的连接仍处于活动状态，连接器会定期执行存活检查，以验证最近是否收到了服务器发送的实际消息或空消息（即“心跳”）。这样便可重启流；否则，如果先前的连接已被静默关闭，则必须建立新的连接。

Web ID 缓存与目标重新评估

初次启动时，连接器会解析 WebID 并将其存储在缓存中。重启时将使用此缓存，以便快速恢复与服务器的连接。此缓存还会定期重新评估，以获取最新的 WebID 列表。用户可以禁用此定期重新评估，或更改其频率。

积压配置

流可能因多种原因停止并重启，例如代理重启、连接丢失以及手动取消。在这些情况下，重新建立连接之前可能会有一小段时间。为避免数据缺口，用户可以启用积压数据来捕获此间隔期间错过的任何数据。

PI 连接器与 REST API 连接器的对比

虽然 REST API 连接器在某些情况下可能提供更大的灵活性，但以下是使用 PI 连接器的一些优势。

  • 用户友好的界面： PI 连接器提供点击式界面，只需了解 PI 概念即可使用。相比之下，REST API 连接器需要了解 Web API、不同的端点和查询格式，才能为外部转换或定期同步检索数据。

  • 即用型数据： PI 连接器同步输出的表格数据已经过解析，可直接使用。而 REST API 输出的是 JSON 对象，需要先进行解析才能在下游转换中使用。这就要求对响应格式有额外的了解。

  • 流式同步： PI 连接器允许用户设置流式同步，而 REST API 无法实现这一点。

  • “智能”开箱即用功能： 如 批处理功能 部分所述，PI 连接器包含的功能允许用户执行原本需要复杂编排才能完成的操作。 PI 连接器隐式提供了多种功能，可帮助用户避免常见的陷阱，支持多个层级的分页和分桶，从而高效、动态地检索数据。这对于在不触及 API 速率限制的情况下检索大量数据非常有价值，尤其是考虑到 REST API 的批处理端点很可能会触及速率限制并静默失败。
