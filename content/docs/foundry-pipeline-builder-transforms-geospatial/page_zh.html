创建地理空间转换

借助 Pipeline Builder，您可以加载、转换并运用地理空间数据。如果 Pipeline Builder 的当前功能尚不支持您的地理空间工作流，请查阅 Foundry 的 旧版地理空间文档 以在 Code Repositories 中转换您的数据。

地理空间数据建模

逻辑类型

Pipeline Builder 在内部使用逻辑类型的概念对地理空间数据进行建模，逻辑类型是在基础类型（字符串、整数、布尔值、数组、结构体）之上对所表示的数据施加额外约束。例如， 几何 类型被定义为必须是有效 GeoJSON 的字符串，而 GeoPoint 必须是经度介于 -180 和 180 与纬度介于 -90 和 90之间的结构体，两者均包含边界值。支持的类型完整列表可在 有关如何思考问题类别并识别它们的更多细节.

Pipeline Builder 中的所有逻辑类型都是其基础类型的继承者；例如，几何类型可以用作期望输入类型为字符串的表达式的输入，但反之则不行。要将基础类型转换为扩展该基础类型的特定逻辑类型，您可以使用“逻辑类型转换”表达式，该表达式会将与该逻辑类型关联的约束应用于数据，并将未通过此验证的值置为空值。表达式能够将逻辑类型指定为输入和输出，这确保了当特定于地理空间的表达式期望 GeoJSON 字符串时，接收到的将是 GeoJSON 字符串。

支持的地理空间类型

Pipeline Builder 目前支持以下地理空间类型：

  • GeoPoint： 一个由 longitude and latitude，其中 longitude 组成的结构体，其中每个值为介于 -180 and 180日 latitude 组成的结构体，其中每个值为介于 -90 and 90之间的双精度浮点数，两者均包含边界值。GeoPoint 必须是根据 WGS:84 或 EPSG:4326 坐标参考系 (CRS) 的有效 (x, y) 坐标。
  • Geometry： 符合 GeoJSON 规范的字符串化 JSON 数据块。单个坐标应采用 WGS:84/EPSG:4326 格式，与 GeoPoint 类型相同。
  • H3Index： 表示有效 H3 六边形索引的字符串。
  • LatLonBoundingBox： 边界框，由 minLat, minLon, maxLat, maxLon组成的结构体表示，其中每个条目都是有效的 GeoPoint，且 maxLat > minLat and maxLon > minLon.
  • Ontology GeoPoint： 与 Ontology 的 GeoPoint 属性类型兼容的字符串，需满足格式 {lat},{lon}，其中 -90 <= lat <= 90 and -180 <= lon <= 180.
  • MGRS： 表示有效 MGRS（军事网格参考系）坐标的字符串。

加载地理空间数据

Pipeline Builder 支持多种用于地理空间数据的转换和表达式。

  • GeoPoint：
    • 构建 GeoPoint 列： 接受一个 lat,lon 对，验证上述边界范围，并将其转换为 GeoPoint 表示形式。
    • 从坐标系 (CRS) 创建 GeoPoint： 接受一个 x,y 对和一个坐标参考系，将该 (x,y) 投影到 WGS:84，然后构建 GeoPoint 表示形式。支持从 EPSG 数据库中的大多数坐标系进行转换，包括所有 UTM 分区。
  • Geometry：
    • 解析熟知文本 (WKT)： 将熟知文本 (WKT) 字符串转换为几何逻辑类型。可选择提供源坐标系标识符，以便在 WKT 尚未采用 WGS:84 时将源 CRS 转换为 WGS:84。
    • 规范化几何： 给定 WGS:84 格式的 GeoJSON 字符串，规范化以下属性：正确顺序（右手规则）、闭合环、去除重复项以及点的恒定维度。
    • 从 Shapefile 提取行： 给定原始 shapefile 的数据集，将每个 shapefile 解析为包含每个条目的几何和属性的行。输出数据集将包含一个几何列，以及用户列出的每个属性对应的列。可以为非 WGS:84 数据集指定坐标参考系。
    • 从 GeoJSON 提取行： 给定原始 GeoJSON 文件的数据集，将每个文件解析为包含每个条目的几何和属性的行。输出数据集将包含一个几何列，以及用户列出的每个属性对应的列。可以为非 WGS:84 数据集指定坐标参考系。

还存在其他表达式，可用于在上述两种类型之间进行转换，以及将它们转换为 H3 索引、MGRS、边界框和 Ontology GeoPoint 格式。

在有关坐标参考系统和投影的文档中详细了解地理空间数据格式。

转换地理空间数据

填充 Pipeline Builder 的地理空间类型列后，您就可以利用专门针对地理空间数据运行的转换。大多数转换在流式和批处理工作流中均受支持。下面列出了一些亮点。

几何比较

  • 交集
  • 差值
  • 对称差
  • 并集（按列和聚合）

球面几何

  • 两点之间的 Haversine/大圆距离
  • 反向 Haversine 距离（给定起点、距离和方位角，计算终点）
  • 几何图形的面积/质心/长度

H3

  • 获取某个分辨率下 H3 六边形的邻居
  • 用某个分辨率的 H3 六边形覆盖多边形

复杂形状近似

  • 椭圆/圆
  • 扇形区域（环形扇区）
  • 给定几何图形的凸包

地理空间连接

Pipeline Builder 支持以下地理空间连接：

  • 几何交集连接
  • 几何交集反连接
  • 几何距离连接
  • 几何最近邻连接
  • 近似最近邻（ANN）连接

几何交集连接

Pipeline Builder 的几何交集连接需要两个数据集，每个数据集都必须有一个几何类型的列。几何交集连接不接受 Ontology GeoPoint 或 GeoPoint 作为输入类型。在应用连接之前，我们建议对几何列进行规范化，并显式过滤掉 null 输出中不需要的值。如果管道中存在非确定性或另一个连接，我们建议在地理连接之前添加一个检查点。

Pipeline Builder 可以连接中等大小几何图形（最多约 34 个点）的数据集，两侧各最多 100 万行，并假设输出行数增加两倍。对于倾斜数据，该连接可以支持一侧最多 2.5 亿行与另一侧 1600 行的连接。随着几何图形大小的增加，稳定性可能会下降。该连接可以稳定支持将一个包含超大几何图形（约 4 万个点）的数据集与最多 50 万行的数据集进行连接。任何更大的规模可能会间歇性成功，但不受官方支持。

输出行数与交叉连接相当的几何交集连接可能会导致连接的稳定性下降。

作为几何交集连接的替代方案，配置了“几何图形有交集”过滤器的交叉连接可能提供更稳定的内存使用。但是，这种方法可能会导致构建时间急剧增加。

几何交集反连接

Pipeline Builder 的几何交集反连接返回左侧数据集中几何图形与右侧数据集中任何几何图形均不相交的行。此连接在批处理和流式管道中均受支持。

几何交集反连接需要两个数据集，每个数据集都必须有一个几何类型的列。与交集连接类似，我们建议对几何列进行规范化，并显式过滤掉 null 输出中不需要的值。

几何距离连接

Pipeline Builder 的几何距离连接需要两个数据集，每个数据集都必须有一个几何类型的列、一个大于零的距离值，以及一个用于确定所提供距离单位的坐标参考系统字符串。例如，如果坐标参考系统提供的是 "epsg:4326"，则距离将被假定为以度为单位。与交集连接类似，我们建议对几何列进行规范化，并显式过滤掉 null 输出中不需要的值。如果管道中存在另一个连接或非确定性，请在连接之前添加一个检查点。

Pipeline Builder 可以连接小型几何图形（每个大约最多 8 个点）的数据集，两侧各最多 100 万行，并假设连接后行数增加 2 倍。当输出的行数与交叉连接的行数相当时，稳定性可能会下降。

作为几何距离连接的替代方案，配置了几何缓冲区和 "Geometries have intersection" 过滤器的交叉连接在行数大幅增加时可能提供更稳定的内存使用。但是，这种方法在大多数情况下可能会显著增加构建时间。

几何 k 近邻 (KNN) 连接

Pipeline Builder 的几何最近邻连接需要两个数据集：一个 base 几何图形数据集和一个 neighbors 点数据集。 k 整数参数配置为每个基础几何图形查找的最近邻数量。需要坐标系来确定基础几何图形与邻居点之间的距离如何计算和比较。结果将是合并行的集合，每行包含一个 GeoPoint，它是 k 距离基础几何图形最近的点之一。平局任意打破，结果不按特定顺序返回。

数据集中的所有 GeoPoint neighbors 必须能够放入 executor 和 driver 内存中。这是目前的硬性要求，限制了连接的可扩展性。Foundry 目前仅接受 neighbors 数据集中的 GeoPoint 逻辑类型，以限制内存消耗。如果您的用例需要分布 neighbors 数据集，或者连接的 neighbors 一侧需要非点几何图形，请联系您的 Palantir 代表。

在实践中，Pipeline Builder 支持较小的 k 值（< 5），邻居数据集最多几十万行，基础数据集 100 万个几何图形。当两个数据集都有几十万行时，Pipeline Builder 可以支持更大的 k值。在这种情况下，查找多达几百个最近邻应该可以快速完成。超过此规模增加输入可能会间歇性成功，但目前一般不受支持。

近似最近邻（ANN）连接

Pipeline Builder 的近似最近邻 (ANN) 连接提供了 KNN 连接的替代方案，它优先考虑处理速度而非精确度。与为每行查找精确的 K 个最近邻的 KNN 连接不同，ANN 连接使用估计的近似匹配，在精度仅略有降低的情况下大幅提升处理速度。

当处理速度比精确度更重要时，或者在使用精确 KNN 连接会太慢的大型数据集时，请考虑使用 ANN 连接。对于需要精确最近邻结果的用例，请使用 几何 KNN 连接 来替代。

故障排除

如果您的连接遇到稳定性问题，请使用以下步骤进行修复：

  1. 在连接之前删除不必要的列。
  2. 简化输入几何图形（例如，可以对大型几何图形使用更粗的粒度吗？）
  3. 垂直扩展；手动为 driver 和 executor 选择具有更多内存的计算配置文件。
  4. 将最大的输入数据集拆分为每组约 2500 万行的集合，然后在单独的构建中将结果合并在一起。
  5. 减少输出中的行数（即左右几何图形之间的交点数量）。

预览转换结果

在 Pipeline Builder 中完成数据转换后，您可以在地图上直观地验证这些转换的结果。在常规预览窗格中，选择您想在地图上预览的单元格（这些单元格必须来自上述地理空间类型之一的列）。右键单击并选择 Open Geo Preview.

将出现一个新的预览标签页，显示所选单元格在地图上的绘制结果。

在 Ontology 中使用地理空间数据

Pipeline Builder 的地理空间功能旨在与平台下游数据无缝集成。

  • 本体论
    • Builder 的几何列类型与本体论的 geoshape 类型兼容，但在 Builder 中将列映射到对象之前，请务必应用“Normalize geometry”表达式。这可确保 geoshape 数据在将数据索引到本体论时能够通过验证。
    • 虽然当前的 GeoPoint 逻辑类型无法直接在 Ontology 中使用，但可以在索引之前将点轻松转换为“Ontology GeoPoint”类型（格式为“{lat},{lon}”的字符串）。
  • 数据集
    • 地理空间类型数据会持久保存在 Builder 管道的输出数据集中，因此如果您从该数据集创建下游 Builder 管道，您的数据仍将保留其正确的逻辑/地理空间类型。
  • 地理时间序列同步
    • 您可以将 GeoPoint 和几何列映射到地理时间序列同步输出，以便在下游应用程序（例如 Map 应用程序）中渲染点和几何图形。所有地理时间序列同步输出都必须包含一个 GeoPoint 列，用于指示与每行对应的观测位置。请查阅 地理时间序列输出文档 以了解有关如何在集成中配置地理空间属性的更多详细信息。
