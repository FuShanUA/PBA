读取和写入授权

测试版

读取和写入授权位于 测试版 开发阶段，在您的注册环境中可能无法使用。功能特性和平台支持在积极开发期间可能会发生变化。

读取和写入授权为操作类型添加安全边界。 读取授权 限制操作在被其他逻辑调用时可以直接读取或作为输入接收的标记数据。 写入授权 为操作创建或修改的数据设定最低安全要求。这些授权是对用户现有权限和操作类型的 提交标准的补充。它们不会授予访问权限，也不会取代现有权限或提交条件。

读取授权

读取授权为操作在执行期间可以读取或作为输入接收的数据提供了额外的上限。读取授权在 Foundry 将值加载到参数中时适用，包括当其他逻辑调用该操作时，以及由函数支撑的操作执行读取时。如果数据超出了配置的读取授权，即使用户本来可以访问该数据，操作也无法加载该数据。

应用操作的用户仍必须具有访问该数据的权限。如果没有为读取授权配置任何标记，则除了用户现有的访问权限之外，操作没有额外的读取边界。

写入授权

写入授权定义了操作创建或修改的数据必须满足的最低安全要求。Foundry 会验证结果数据的安全性，如果结果低于配置的最低要求，则会阻止该操作。

写入授权不会授予用户对标记的访问权限、自动添加任何已配置的标记，也不会使原本无效的编辑变为有效。用户必须具有所需的权限，在适用的情况下提供有效的标记值，并通过操作类型的提交条件。如果没有为写入授权配置任何标记，则此功能不会强制执行额外的最低输出安全要求。

对于由平台管理的写入（包括 操作日志 和 编辑历史 对象），配置的写入授权不会被强制执行。这意味着应用于操作日志和编辑历史的安全性可能低于写入授权。

强制标记保证

强制标记 旨在沿数据依赖关系传播，以便派生数据保留其输入数据的保护。对于操作，操作的逻辑会设定应用于输出数据的安全性。因此，操作产生的输出的安全性可能与其接收或读取的数据相同、更高或更低。读取和写入授权设定了操作可以执行的操作的上下限。两者共同保证了操作输入和输出之间允许的安全差异。

将写入授权配置得比读取授权宽松，会使操作能够写入低于其可读取数据安全边界的数据。这会故意切断强制标记的传播，并可能导致数据降级。当读取和写入设置不一致时，操作类型编辑器会显示警告。

当读取和写入授权不一致时，Foundry 会检查保存或发布操作类型的用户的权限。用户必须具有对读取和写入边界之间被切断的每个强制标记进行降级的权限。如果检查通过，操作类型可以执行已批准的降级；Foundry 不会在运行时重复此权限检查。

读取和写入授权目前是可选的。如果未配置读取授权，Foundry 在保存或发布操作类型时不会执行降级权限检查。因此，操作可以读取高于其写入边界的数据并写入限制较少的数据，这可能导致数据泄露。只要操作可能读取标记数据，就应配置读取授权。

配置读取和写入授权

在操作类型编辑器中，启用 访问约束 以配置授权。启用访问约束会将两个授权初始化为无标记。禁用访问约束会清除两个授权。

使用直方图中的 写入安全 和 读取安全 选项卡以分别配置每个授权。当设置不一致时，编辑器会显示警告。如果某个授权包含您无法查看的值，这些值将显示为已脱敏且无法编辑。

在提交操作之前，操作表单可以显示 最低所需安全 （基于写入授权）。状态可能为：

  • 安全通过： 目标安全预期满足配置的最低要求。
  • 安全未通过： 目标安全低于配置的最低要求。
  • 无法确定： Foundry 无法在提交前确定目标安全。
  • 未设置： 未配置写入授权标记。
  • 已脱敏： 用户无法查看已配置的授权。

表单状态提供早期反馈。Foundry 在提交操作时执行权威验证，如果生成的数据不满足写入授权，则操作将失败。
