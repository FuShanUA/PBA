BigQuery

身份验证

使用 BigQuery 连接器需要以下 Identity and Access Management (IAM) 角色：

读取 BigQuery 数据：

  • BigQuery Read Session User：在 BigQuery Project 上授予
  • BigQuery Data Viewer：在 BigQuery 数据上授予，用于读取数据和元数据
  • BigQuery Job User （可选）：授予后可摄取视图并运行自定义查询

将数据从 Foundry 导出到 BigQuery：

  • BigQuery Data Editor：在 BigQuery 数据集或 Project 上授予
  • BigQuery Job User：在 BigQuery Project 上授予
  • Storage Object Admin：如果数据通过 Google Cloud Storage 导出，则在存储桶上授予

使用临时表：

  • BigQuery Data Editor：如果数据集由连接器自动创建，则在 BigQuery Project 上授予
  • BigQuery Data Editor：在提供的数据集上授予，作为存储临时表的位置

在以下内容中了解有关所需角色的更多信息 Google Cloud 访问控制文档 ↗.

从以下可用的身份验证方法中选择一种：

  • GCP 实例账号： 请参阅 Google Cloud 文档 ↗ 了解如何设置基于实例的身份验证。

    • GCP 实例身份验证仅适用于通过在 GCP 中经过适当配置的实例上运行的代理进行操作的连接器。
    • GCP 实例身份验证凭据不支持 虚拟表.

  • 服务账号密钥文件： 请参阅 Google Cloud 文档 ↗ 了解如何设置服务账号密钥文件身份验证。密钥文件可以以 JSON 或 PKCS8 凭据的形式提供。

  • Workload Identity Federation (OIDC)： 按照显示的源系统配置说明来设置 OIDC。请参阅 Google Cloud 文档 ↗ 了解 Workload Identity Federation 的详细信息，以及 我们的文档 了解 OIDC 如何与 Foundry 配合使用的详细信息。

网络

BigQuery 连接器需要通过 443 端口访问以下域名：

  • bigquery.googleapis.com
  • bigquerystorage.googleapis.com
  • storage.googleapis.com
  • www.googleapis.com

可能还需要访问以下其他域名：

  • oauth2.googleapis.com
  • accounts.google.com

如果您正在建立 直接连接 在 Google Cloud Platform (GCP) 上的 Foundry 与 GCP 上的 BigQuery 之间建立直接连接时，您还必须通过相关的 VPC 服务控制启用该连接。如果您的设置需要此连接，请联系 Palantir Support 获取更多指导。

从 BigQuery 同步数据

BigQuery 连接器支持针对大型数据同步和自定义查询的高级同步配置。对于更复杂的场景，请使用 虚拟表 or 代码级替代方案.

要设置 BigQuery 同步，请选择 源探索 在数据源右上角 概述 屏幕。接下来，选择要同步到 Foundry 中的表。准备同步时，请选择 为 x 个数据集创建同步.

了解更多关于 探索并创建同步 （在 Foundry 中）的更多信息。

在浏览可用的同步并将其添加到连接器后，导航至 编辑同步。在 同步 左侧面板中，找到要配置的同步并选择 > 右侧的。

数据模型

来自 BigQuery 的表导入 Foundry 时，数据以 Avro 格式保存。类型为 BIGNUMERIC 和 TIME 的列在导入时不受支持。

从 Foundry 向 BigQuery 导出数据时，除 MAPS, STRUCTS 和 ARRAYS 之外的所有列类型均受支持。

自定义 SQL

可以运行任意查询，结果将保存在 Foundry 中。查询输出必须小于 20GB（BigQuery 表的最大大小），或者必须启用临时表。查询必须以关键字开头 select or with构造一个本体论编辑容器。例如： SELECT * from table_name limit 100;.

增量同步

通常，同步会导入目标表中所有匹配的行，无论同步之间数据是否发生变化。相比之下，增量同步会维护最近一次同步的状态，并且仅从目标中摄取新的匹配行。

从 BigQuery 摄取大型表时可以使用增量同步。要使用增量同步，表必须包含一个严格单调递增的列。此外，被读取的表或查询必须包含具有以下数据类型之一的列：

  • INT64
  • FLOAT64
  • NUMERIC
  • BIGNUMERIC
  • STRING
  • TIMESTAMP
  • DATE
  • TIME
  • DATETIME

示例： 一个 5 TB 的表包含数十亿行我们想要同步到 BigQuery 的数据。该表有一个 单调递增列 中的一个顶层键下定义，该键名为 id。可以将同步配置为每次摄取 5000 万行，使用 id 列作为 增量列，初始值为 -1，配置的限制为 5000 万行。

首次运行同步时，前 5000 万行（基于 id升序排列）中包含 id 值大于 -1 的行将被摄取到 Foundry 中。例如，如果此同步运行了多次，且上次运行期间摄取的最大 id 为 19384004822，则下一次同步将摄取接下来的 5000 万行，从第一个 id 大于 19384004822的行开始，依此类推。

增量同步需要以下配置：

选项是否必填？描述
列是选择将用于增量摄取的列。如果表不包含任何受支持的列类型，下拉列表将为空。
Initial value是开始同步数据的起始值。
LimitNo单次同步中要下载的记录数。

自定义查询的增量同步

要为自定义查询同步启用增量查询，必须将查询更新为符合以下格式：

SELECT * from table_name where incremental_column_name > @value order by incremental_column_name asc limit @limit

临时表

从非标准 BigQuery 表同步超过 20GB 的数据时，必须启用临时表。临时表允许 BigQuery 导入大型查询输出的结果、从视图和其他非标准表导入数据，并支持大型增量导入和摄取。

单次同步最多可以导入磁盘可用大小的数据。对于 在 Foundry worker 上运行的同步，这通常限制为 600 GB。请使用增量同步来导入更大的表。

要使用临时表，请启用 临时表设置 （位于连接器配置中），并根据需要配置以下设置：

  • 自动创建数据集： 选择此选项以创建一个 Palantir_temporary_tables 数据集来存储临时表。此选项要求 BigQuery 账号在项目中具有 BigQuery Data Editor 角色。
  • 提供要使用的数据集： 选择此选项以手动添加 项目 ID and 数据集名称 （即您要用于存储临时表的数据集）。此选项要求 BigQuery 账号在所提供的数据集上具有 BigQuery Data Editor 角色。

使用临时表时必须启用 BigQuery 视图 ↗ ，使用 虚拟表.

将数据导出到 BigQuery

导出到 BigQuery 是通过 导出任务完成的。对于更复杂的场景，请使用 代码级替代方案.

连接器可以通过两种方式导出到 BigQuery：

  • 通过 Google Cloud Storage 作为中间存储（推荐）。请参阅下面关于 通过 Cloud Storage 导出 的文档以获取更多信息。
  • 通过 BigQuery API see 从本地文件读取数据 ↗ 以了解所用 API 的详细信息

通过 API 写入适用于数百万行的数据规模。此模式的预期性能是大约两分钟导出一百万行。如果您的数据规模达到数十亿行，请改用 Google Cloud Storage。

任务配置

要开始导出数据，您必须配置一个导出任务。导航到包含您要导出到的连接器的 Project 文件夹。右键单击连接器名称，然后选择 Create Data Connection Task.

在 Data Connection 视图的左侧面板中，验证 Source 名称与您要使用的连接器匹配。然后，将输入数据集添加到 Input 字段。输入数据集必须命名为 inputDataset，它是要导出的 Foundry 数据集。导出任务还需要配置一个 Output 。输出数据集必须命名为 outputDataset 并指向一个 Foundry 数据集。输出数据集用于运行、调度和监控任务。

在 Data Connection 视图的左侧面板中：

  1. 验证 Source 名称与您要使用的连接器匹配。
  2. 添加一个 Input named inputDataset。该 输入数据集 是要导出的 Foundry 数据集。
  3. 添加一个 Output named outputDataset。该 输出数据集 用于运行、调度和监控任务。
  4. 最后，在文本字段中添加一个 YAML 块来定义任务配置。

左侧面板中显示的连接器和输入数据集的标签并不反映 YAML 中定义的名称。

向输出表追加行

如果您需要向目标表追加行，可以使用 REQUIRE_INCREMENTAL 而不是替换数据集。

增量同步要求仅向输入数据集追加行，并且 BigQuery 中的目标表与 Foundry 中输入数据集的架构相匹配。

通过 Cloud Storage 导出（推荐）

要通过 Cloud Storage 导出，必须在连接器中配置 Cloud Storage 存储桶 配置设置。此外，该 Cloud Storage 存储桶必须仅用于连接器的临时表，以便尽可能少的用户可以访问临时写入该存储桶的任何数据。

我们建议通过 Cloud Storage 而非 BigQuery API 导出到 BigQuery；Cloud Storage 在大规模场景下运行更好，并且不会在 BigQuery 中创建临时表。

通过 BigQuery API 导出

导出作业会在目标表旁边创建一个临时表；该临时表不会应用额外的访问限制。此外， SNAPSHOT 导出会删除并重新创建表，这意味着额外的访问限制也会被删除。

在通过 BigQuery API 导出期间，数据会导出到临时表 datasetName.tableName_temp_$timestamp。导出完成后，行会自动从临时表传输到目标表。

通过 BigQuery API 导出不支持 Hive 表分区。对于使用 Hive 表分区的数据集，请改用通过 Cloud Storage 导出。

如果导出以 REQUIRE_INCREMENTAL 模式运行，则可以共享目标表。以 SNAPSHOT 模式运行会在每次运行时重新创建表，因此需要重新应用共享。

要通过 BigQuery API 成功导出，请勿对导出的表应用 BigQuery 行级或列级权限。

from pandas import DataFrame
from transforms.api import lightweight, Output, Input, transform_pandas
from transforms.external.systems import ResolvedSource, external_systems, Source
from google.cloud import bigquery
import json

@lightweight
@external_systems(
    bigquery_source=Source("<source_rid>")
)
@transform_pandas(
    Output("<dataset_rid>"),
    carriers_df=Input("<dataset_rid>") # dataframe with schema [carrier_name: String, carrier_details: String]
)
def read(bigquery_source: ResolvedSource, carriers_df: DataFrame) -> DataFrame:
    # Authenticate BigQuery client
    account_info = json.loads(bigquery_source.get_secret("jsonCredentials"))
    client = bigquery.Client.from_service_account_info(account_info)

    # Table reference
    bigquery_project = "<bigquery_project_id>"
    bigquery_dataset = "<bigquery_dataset_id>"
    bigquery_table = "<bigquery_table_id>"
    table_ref = f"{bigquery_project}.{bigquery_dataset}.{bigquery_table}"

    # Filter parameters
    carrier_list = carriers_df['carrier_name'].drop_duplicates().tolist()
    min_weight = 10

    job_config = bigquery.QueryJobConfig(
        query_parameters=[
            bigquery.ArrayQueryParameter("carrier_list", "STRING", carrier_list),
            bigquery.ScalarQueryParameter("min_weight", "FLOAT64", min_weight)
        ]
    )

    query = f"""
        SELECT shipment_id, carrier, weight, tracking_number
        FROM `{table_ref}`
        WHERE carrier IN UNNEST(@carrier_list) AND weight >= @min_weight
    """

    query_job = client.query(query, job_config=job_config)
    return query_job.to_dataframe()

from pandas import DataFrame
from transforms.api import lightweight, Output, Input, transform_pandas
from transforms.external.systems import ResolvedSource, external_systems, Source
from google.cloud import bigquery
import json

@lightweight
@external_systems(
    bigquery_source=Source("<source_rid>")
)
@transform_pandas(
    Output("<dataset_rid>"),
    shipments_df=Input("<dataset_rid>"), # DataFrame with schema [shipment_id: Long, tracking_number: String]
)
def update_tracking_numbers(bigquery_source: ResolvedSource, shipments_df: DataFrame) -> DataFrame:
    # Authenticate BigQuery client
    account_info = json.loads(bigquery_source.get_secret("jsonCredentials"))
    client = bigquery.Client.from_service_account_info(account_info)

    # Table reference
    bigquery_project = "<bigquery_project_id>"
    bigquery_dataset = "<bigquery_dataset_id>"
    bigquery_table = "<bigquery_table_id>"
    table_ref = f"{bigquery_project}.{bigquery_dataset}.{bigquery_table}"

    # 1. Clear temporary table if it exists
    temp_table_id = f"{bigquery_project}.{bigquery_dataset}.temp_update_tracking"
    client.delete_table(temp_table_id, not_found_ok=True)


    # 2. Upload shipments_df to a temporary table
    load_job_config = bigquery.LoadJobConfig(
        schema=[
            bigquery.SchemaField("shipment_id", "INT64"),
            bigquery.SchemaField("tracking_number", "STRING"),
        ]
    )
    job = client.load_table_from_dataframe(shipments_df, temp_table_id, job_config=load_job_config)
    job.result()  # Wait for load to finish

    # 3. MERGE to update tracking_number in main table
    merge_query = f"""
    MERGE `{table_ref}` T
    USING `{temp_table_id}` S
    ON T.shipment_id = S.shipment_id
    WHEN MATCHED THEN
      UPDATE SET tracking_number = S.tracking_number
    """

    client.query(merge_query).result()

    # 3. (Optional) Clean up temporary table
    client.delete_table(temp_table_id, not_found_ok=True)

    # Optionally, return the updated rows as a DataFrame for confirmation
    updated_ids = shipments_df["shipment_id"].tolist()
    query = f"""
        SELECT shipment_id, tracking_number
        FROM `{table_ref}`
        WHERE shipment_id IN UNNEST(@updated_ids)
    """
    job_config = bigquery.QueryJobConfig(
        query_parameters=[
            bigquery.ArrayQueryParameter("updated_ids", "INT64", [int(x) for x in updated_ids])
        ]
    )
    updated_rows = client.query(query, job_config=job_config).to_dataframe()
    return updated_rows

  • 临时表 必须启用才能进行注册 BigQuery 视图 ↗，并且必须将相关角色添加到 身份验证凭据.
  • 组织 Spark 设置 以在使用 BIGNUMERIC Spark 中的列。

有关构建自定义主题的示例，请参阅 连接详情 和 临时表 部分以了解更多详情。

计算下推

Foundry 支持在使用虚拟表时将计算下推到 BigQuery。虚拟表输入利用 BigQuery Spark 连接器 ↗ 该连接器内置了对谓词下推的支持。

当使用注册到同一数据源的 BigQuery 虚拟表作为管道的输入和输出时，可以将计算完全联合到 BigQuery。此功能目前可在 Python 转换中使用。请参阅 Python 文档 以了解如何将计算下推到 BigQuery 的详细信息。

故障排除

未找到：数据集 <dataset> 未在以下位置找到 <location>

BigQuery 会根据查询中使用的输入或查询结果的存储位置来确定给定查询的运行位置。使用临时表时，输出会设置为临时表数据集中的临时表；该数据集的位置将决定查询的运行位置。请确保同步的所有输入和临时表数据集位于同一区域。如果 自动创建数据集。 设置已启用，请使用 Google Cloud 控制台或 Google 的 SDK/API 来确定名为以下名称的数据集的位置 Palantir_temporary_tables.

gRPC 消息超出最大大小

如果同步包含大型内容（如 JSON 列）的数据，传输可能会失败并出现上述错误。请调整 BigQuery 的 Maximum inbound message size in gRPC 设置 以增加单次 API 调用中的数据传输量。请注意，单次调用会获取多行数据，因此将其设置为最大行大小可能还不够。

您可以通过导航到以下位置找到此配置选项 Connection Settings > Connection Details，然后滚动到 更多选项 并选择 gRPC 设置.

基于 BigQuery 视图的数据集或虚拟表的预览无法加载

如果您的预览无法加载且目标 BigQuery 表是视图，这可能是架构不匹配的结果。视图的架构由创建时定义的 SQL 查询结果确定。对底层表结构的后续更改 不 会自动应用到视图的架构，并且在尝试使用该视图时（例如通过 Palantir 平台中的同步/虚拟表）可能导致意外行为。

您可以通过在 BigQuery 控制台中比较视图和底层表的架构来验证这一点，检查是否存在任何差异。这可能包括：

  • 视图中存在但底层表中不存在的列（反之亦然）
  • 同一列具有两种不同的数据类型

如果发现任何差异，您可以使用以下方法重新创建或刷新视图来解决 CREATE OR REPLACE VIEW or ALTER VIEW。有关更多信息，请参阅此 Google Cloud 社区帖子 ↗ 其中更详细地描述了预期行为，并提供了关于最佳实践的额外指导。
