Audit Explorer [Beta]

测试版

Audit Explorer 处于 测试版 开发阶段，可能无法在您的注册租户中使用。功能在积极开发过程中可能会发生变化。

Audit Explorer 是一款 数据治理 应用程序，用于搜索和查看 audit.3 Foundry 中的审计日志。您可以按用户、事件、资源和时间筛选审计日志，并通过图表查看随时间变化的活动情况。Audit Explorer 支持安全调查、合规审查，以及对 Foundry 中数据使用情况的监督。

隐私最佳实践是仅在明确的监督或合规目的下搜索审计日志，并将访问权限限制在为此目的需要使用它的人员。审计日志可能包含个人身份信息，例如姓名和电子邮件地址，因此请确保每次搜索都与您需要回答的问题相称。Audit Explorer 会记录每次搜索，这使审查者对其使用审计数据的方式负责。请查看 实践中的隐私与公民自由 以获取有关 目的限制, 访问治理日 问责的指导。所有对 Audit Explorer 的使用都必须遵守 Palantir 的 可接受使用政策 ↗.

Audit Explorer 的工作原理

Audit Explorer 从审计表中读取日志：审计表是一种 Iceberg 表 由 audit.3 审计导出 写入的。要创建导出，您需要具有为组织创建审计导出的权限。 组织管理员 角色默认授予此权限。了解更多关于如何 创建审计表.

使用 Audit Explorer 时请注意以下几点：

  • 支持的表： Audit Explorer 仅打开具有 audit.3 模式.
  • 您自己的权限： Audit Explorer 使用您自己的权限运行查询，不会授予额外的访问权限。您需要 读取该表的权限 ，并且必须满足其 标记。如果您没有读取表的权限，Audit Explorer 会显示与架构错误的表相同的错误。要确定错误是由权限还是架构引起的，请阅读 错误详情.
  • 仅限审计表中的日志： Audit Explorer 仅显示已到达审计表的日志，因此最近的活动可能尚未显示。近期时间段的结果为空并不一定表示没有发生任何活动。了解更多关于如何 检查数据新鲜度.

主要功能

  • 搜索和筛选： 在侧边栏中构建搜索。按时间、用户、事件类型、类别、资源或本体论资源进行筛选，并添加自由文本词。从精选的推荐事件列表中选择事件类型。了解更多关于如何 搜索和筛选审计日志.
  • 图表： 查看匹配事件的发生时间以及哪些事件类型最频繁。了解更多关于 图表.
  • 日志表： 显示或隐藏列，右键单击大多数值可以仅包含该值、排除该值或切换到新搜索。右键单击 时间 值可以在该日志周围缩放时间范围。了解更多关于 该 日志 table.
  • 日志详情： 查看谁在何时何地做了什么，并为事件（例如本体论操作和函数执行）提供可读的摘要。了解更多关于如何 查看审计日志详情.
  • 会话： 列出会话以跟踪用户活动的顺序，并查看 检查点 理由。了解更多关于如何 探索用户会话.

访问 Audit Explorer

从 应用程序门户 在 Workshop 导航侧边栏中打开 Audit Explorer。按名称搜索，或在以下位置找到它 安全与治理.

如果您没有看到 Audit Explorer，请联系您的平台管理员以 修改应用程序访问权限 在 Control Panel 中。平台管理员还可以使用应用程序访问权限将 Audit Explorer 限制为需要使用它的组。应用程序访问权限仅控制谁可以打开 Audit Explorer。在其他应用程序中，审计表自身的权限和标记控制对它的访问。

首次打开 Audit Explorer 时，您必须 确认使用指南.

搜索会被记录

Audit Explorer 每次运行搜索时都会写入一条审计日志，因此您对审计数据的使用本身也是 可审计的。每条日志使用 dataSearch 分组依据 并记录以下内容：

  • 您搜索的审计表
  • 您的过滤器和自由文本搜索词
  • 您选择的时间范围以及 Audit Explorer 记录该搜索时所覆盖的时间窗口

日志不会记录 SQL 查询、结果、您查看或打开的日志，也不会记录搜索是否完成。每条日志的结果为 SUCCESS，这表示该搜索已被记录，而不表示它返回了结果。

当您执行以下任一操作时，Audit Explorer 会记录一次搜索：

  • 打开一个表
  • 打开或切换到一个标签页
  • 应用过滤器更改
  • 重置过滤器
  • 应用最近的搜索
  • 更改时间范围
  • 选择 刷新

在您编辑过滤器时，Audit Explorer 不会记录任何内容，直到您选择 保存您的更改。。例外情况是 自由文本搜索 菜单中选择 添加新过滤器 菜单，它会在您选择后立即运行并记录该搜索。Audit Explorer 不会将滚动、排序、更改列、加载过滤器值建议、浏览 选择事件类型 对话框、重新排序过滤器或打开日志详情记录为单独的搜索。

审阅者可以通过选择 提交 Audit Explorer 查询 位于 访问与管理 菜单中选择 选择事件类型 对话框来找到这些日志，该对话框会按事件名称 AUDIT_EXPLORER.QUERY_SUBMIT进行过滤。仅按 dataSearch 类别过滤还会匹配其他应用中的搜索。要审阅对单个审计表的搜索，还需添加一个 “资源” 过滤器并填入该表的资源标识符（RID）。了解更多关于 审计日志搜索.

搜索日志会像其他 audit.3 日志一样进入您组织的审计导出。在导出的日志中，过滤器是 requestFields.dataSearchContext 条目中的一个 JSON 值，其描述为 auditExplorerQueryFilters，而被搜索的表位于 resultFields.dataSearchResults。该 JSON 值的格式可能会发生变化。

最佳实践与限制

搜索会消耗 Foundry 计算，并且某些结果需要仔细解读。

保持搜索范围狭窄

为限制计算资源的使用，请遵循以下做法：

  • 使用能够回答您问题的最短时间范围。
  • 在大型表上，避免使用空时间范围，它显示为 全部时间。Audit Explorer 仅按时间范围限定过滤器值建议的范围，而不考虑您的其他过滤器。当时间范围为 全部时间时，打开诸如 Service 之类的过滤器的值建议会读取整个表中的该列。选择 所有事件类型 菜单中选择 选择事件类型 对话框也会执行相同操作。 日志频率 图表同样不显示任何条形，结果计数仅显示目前已加载的行。
  • 保持默认排序，即最新的 时间 排在最前。其他排序方式会读取时间范围内与您的过滤器匹配的每一行。
  • 完成后请关闭 Audit Explorer。当搜索标签页处于打开状态时，Audit Explorer 每 60 秒以及您每次返回浏览器窗口时都会检查表中的最新日志。即使您没有在搜索，它也会这样做。

时区

Audit Explorer 没有时区设置。它按以下方式处理时间：

  • 直方图 日志 表、日志详情面板、图表和时间范围控件以您浏览器的本地时区显示格式化时间，不带时区缩写。您输入时间也使用本地时间。如果您选择 显示原始值 ，该选项位于 时间 列，它会显示以协调世界时（UTC）存储的值。
  • 日志频率 条形以 UTC 边界为起点，例如 UTC 午夜。如果您浏览器的时区不是 UTC，条形标签可能显示的不是午夜的本地时间，而是前一天或后一天的日期。
  • 复制时间戳 菜单中选择 时间 单元格菜单会以 UTC 复制时间，例如 2026-10-12T14:03:00.000Z.

计数包含重复行

审计日志传送到 Foundry 时可能会产生重复行，计数中包含这些重复行。因此结果计数、图表和会话 事件 计数可能会略高于唯一事件的数量。具有相同 日志条目 ID 的行是重复行。要获得精确计数，请按以下字段去重 logEntryId.
