什么是数据管道？

Foundry 中数据集成的总体目标是提供组织内客观现实的数字化视图。实现这一目标通常需要从多个源系统同步数据、施加统一的模式（schema）、将数据集组合在一起，并使团队能够基于共同的数据基础构建用例。

在此背景下，“数据管道”一词被广泛用于指代数据从源系统经过中间数据集，最终产出高质量、经过治理的数据集的流动过程，这些数据集可以被结构化为 本体论 或作为以下内容的基础： 机器学习 和 分析 工作流。

尽管 Foundry 中任何通过转换逻辑连接在一起的两个数据集都可以被视为管道，但在实践中，我们所称的“数据管道”的定义更为严格。通常，管道具有 所有权的概念——即由一个人或一组人来监督管道，确保数据定期、可靠地流经管道，以支持业务流程。

除了所有权的概念之外，高质量的、可用于生产环境的数据管道还具有其他一些特征。我们将在本文档的其余部分探讨这些理念，并提供指向更多资源的链接以供深入学习：

除了所有管道共有的功能之外，还应根据数据规模、延迟要求和维护复杂度等因素，考虑为您的数据基础创建哪种类型的管道。Foundry 中有三种主要类型的管道：批处理、增量和流式。 了解更多关于管道类型的信息。

管道设置

Foundry 的 Pipeline Builder 使用户能够通过简化的点击式界面快速、轻松地设置管道。借助 Pipeline Builder，用户可以获得 Git 风格的变更管理、数据健康检查、多模态安全以及细粒度数据审计等优势。

技术用户可以比以往更快速地构建和维护管道，专注于对端到端管道和期望输出的声明式描述。此外，Pipeline Builder 的点击式、基于表单的界面使技术水平较低的用户也能通过简化的方式创建管道。

构建调度

简而言之，一系列数据转换必须定期运行才能被视为数据管道。在 Foundry 中定义构建 调度 是构建管道的基本步骤，因为下游数据消费者期望数据定期更新。数据流经管道的频率取决于组织需求：有些管道可能仅每周或每天运行一次，而另一些管道则每小时甚至更频繁地运行。

数据质量

在定义管道的初始阶段，我们建议在每一步都频繁检查输入和输出的质量。从源系统同步的数据通常包含未定义的值以及格式不良或不一致的数据。清洗和规范化数据是管道构建过程的核心部分。

Foundry 中提供了用于检查数据集假设的工具：

  • 数据集预览 支持对数据集的任意列计算统计信息，以及筛选行的子集以快速检查预期结果。
  • Code Repositories 对 转换调试 的支持可用于在编写转换逻辑时检查输入数据集的结构是否符合预期。
  • Foundry 分析套件中的应用，尤其是 Contour，可以通过点击式的方式非常有助于验证对数据集的假设。

在您的管道建立之后， 健康检查 是验证数据随时间推移保持高质量的推荐方式。以下是一些健康检查的入门资源：
