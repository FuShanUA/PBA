直接数据源 [Beta]

Beta

直接数据源处于 beta 开发阶段，在您的注册中可能无法使用。功能在开发过程中可能会发生变化。

直接数据源支持以低延迟向本体论写入数据，包括 编辑 由基于流的数据支撑的对象类型。它们允许数据应用程序直接写入本体论。目前，仅 Pipeline Builder 是受支持的写入器应用程序。

直接数据源以牺牲吞吐量为代价，换取更稳健的本体论写入能力，包括流上的用户编辑以及基于时间的排序。它们最适用于对数据和编辑均要求低延迟的低吞吐量工作流，例如对流式对象类型的编辑，或具有小型、频繁增量构建的批处理对象类型——在这类场景中，从源事务到对象出现在本体论中的端到端索引延迟是不可接受的。

配置直接数据源

直接数据源目前只能在管道构建器中进行配置。请参阅 管道构建器文档 中的指南，以了解更多信息。

部署后，该对象类型将显示在 本体论管理器中，并且其对象可在 Insight 和 Object Explorer。

调试

在直接数据源写入器及其对象类型之间导航

您可以在以下位置查看将直接数据源的编辑内容写入本体论的 Pipeline Builder 管道： 数据源 选项卡（位于 Ontology Manager 中）。选择该管道即可在 Pipeline Builder 中导航至该管道。

目前，仅 Pipeline Builder 是受支持的写入器应用程序。

活跃度

数据活跃度显示在 数据源 选项卡中（位于 Object Storage V2下）。活跃度可帮助您确定当前对象视图的新鲜度：

  • 数据： 最近一次写入本体论的直接写入。
  • 架构 当前架构是否为最新。
  • 最新编辑： 最近一次写入本体论的编辑。如果尚未为该对象类型写入任何编辑，则不会显示此字段。

流指标

您可以在以下位置查看由管道构建器编排的写入作业或当前正在运行的作业的流指标： 本体论管理器。导航到 对象存储 V2 的 数据源 选项卡（位于对象类型中），然后在实时管道中选择直接数据源节点。

  • 选择 查看指标 横幅，以查看 Flink 流式作业的日志、作业历史记录和其他指标。
  • 要查看当前正在运行的作业的信息，请选择 最新作业上的省略号，然后选择 查看作业详情。

日志记录

在调试缺失对象或无效写入时，查看直接写入的日志尤其有用。如果检测到无效的直接写入，横幅将出现在 数据源 选项卡。这些无效写入将被丢弃,不会出现在本体论中。

调试无效写入:

  1. 导航至 数据源 选项卡并找到警告横幅。
  2. 选择 查看日志 在横幅上查看哪些主键被丢弃，以及原因。

写入通常因数据验证失败而被拒绝。请在管道上游更正数据结构，然后重放管道。视图重置且写入再次有效后，横幅即会清除。如果无法确定写入被拒绝的原因，请联系 Palantir 支持。

重放管道会重置对象视图，从而移除所有现有对象。请在重放前考虑这一点。

常见问题

部署管道后，流式作业始终在启动之前失败。这是预期行为吗？

是的。首次部署时，作业可能会在提交之前失败，或者在使用重置输出重放管道时失败，因为 Funnel 设置过程可能导致超时。如果作业超出重试次数限制，请重新构建失败的作业。重放时，您无需再次使用重放进行部署；触发另一次重放会启动 Funnel 的另一轮设置，这可能再次导致超时。

我重放了我的流式管道，现在我所有的对象都丢失了。为什么会发生这种情况？

这是直接数据源目前存在的限制。现有对象视图会被完全清除，以便立即提供新视图。由于切换是即时完成的，新视图尚未完全填充，因此对象视图可能不完整或为空。用于解决此限制的后台重放功能正在开发中。

我缺少一些预期应存在于本体论中的对象。我该如何调试这个问题？

首先，请检查 数据活跃度。如果 数据 活跃度已过时（例如为 30 分钟前的数据），则源数据流很可能已停止。请检查 流指标 或当前作业。

如果 数据 是最新的，则无效写入很可能已被 Funnel 拒绝。Ontology Manager 的 数据源 标签页中也会显示一个横幅，以指示被拒绝的写入。请参阅 日志记录 以了解补救步骤。

在某些情况下， 数据 可能已过期 并且 由于无效写入而缺失，这意味着某个时间点之后的所有写入均被拒绝。
