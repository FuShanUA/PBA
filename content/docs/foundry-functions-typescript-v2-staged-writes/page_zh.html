暂存写入 [Beta]

Beta

暂存写入功能处于 beta 开发阶段，您的注册环境中可能尚未提供。在开发过程中，功能可能会发生变化。请联系 Palantir 支持团队以请求访问权限。

实时预览和已发布函数预览仅在代码仓库中受支持，本地开发或 VS Code 工作区环境中不受支持。

本页介绍 TypeScript v2 函数中的暂存写入。有关 Python 的信息，请参阅 Python 函数中的暂存写入。

暂存写入为编辑本体论中对象的函数提供了一种额外的执行模型。与通过常规 本体论编辑函数进行的编辑不同，暂存写入函数：

  • 为函数中应用的本体论编辑提供写后读（read-after-write）保证。在函数中应用的所有编辑均会被暂存，并会在函数后续的本体论查询和聚合中反映出来。
  • 允许嵌套调用其他进行本体论编辑的暂存写入函数。

本页介绍如何编写暂存写入函数，并记录其独特属性。有关编辑函数工作原理的更多详细信息，请参阅 概述页面。

与常规本体论编辑函数的主要区别

暂存写入函数在多个重要方面与常规编辑函数不同。

写后读保证

在暂存写入函数中，读取的任何本体论数据都会反映该函数中先前所做的所有编辑（以及在同一操作执行中调用该函数的暂存写入函数所做的所有编辑）。此类编辑仅处于暂存状态，其他用户所做的查询或执行上下文之外的函数均无法看到。这使您可以在函数内部使用搜索请求和聚合来查询本体论，并且所有暂存的编辑都会反映在查询结果中。

无需在函数结束时返回编辑

常规的 Python 和 TypeScript V2 本体论编辑函数需要将一批本体论编辑作为函数的返回值返回，这些编辑才能被应用。而在暂存写入函数中，本体论编辑会被自动暂存，并会在函数执行结束、操作完成时应用于本体论。这样，函数的返回值便可用于向调用方返回其他信息。

例如，您可以应用一个操作来执行 TypeScript V2 暂存写入函数，该函数随后会进行一些编辑，并进一步调用 AIP Logic 函数。AIP Logic 函数执行的查询将返回 TypeScript V2 函数中所做的本体论更改；AIP Logic 函数所做的任何额外编辑都将加入相同的暂存编辑，无需将其作为 Logic 函数的一部分返回。操作完成后，所有暂存的编辑都将自动应用。

原子执行

暂存写入函数中的所有操作（包括查询、函数调用和 AIP Logic 执行）会将它们的编辑暂存在一起。这些暂存的编辑将在函数成功完成后提交（即应用到本体论）。如果函数抛出错误，本体论将保持不变，并且在操作重试该函数之前，所有暂存的编辑都会被丢弃。

WriteableClient

暂存写入函数使用 WriteableClient 而不是标准的 Client。该 WriteableClient 提供了直接创建、更新和删除对象的方法，而无需构建编辑批次。

定义暂存写入函数

暂存写入函数必须显式声明将要编辑的实体，并使用 Edits 类型，该类型从 @osdk/functions 包导出。第一个参数必须是 WriteableClient<T> 其中 T 是该函数将执行的所有编辑类型的联合类型。返回值不再局限于编辑数组，因此您可以返回任意值。以下示例声明了一个函数，该函数将编辑 Employee 对象类型：

import { Employee } from "@ontology/sdk";
import { Edits } from "@osdk/functions";
import { WriteableClient } from "@osdk/functions/experimental";

type OntologyEdit = Edits.Object<Employee>;

async function createEmployee(
    client: WriteableClient<OntologyEdit>,
    employeeId: string,
    firstName: string,
    lastName: string
): Promise<Integer> {
    await client.create(Employee, {
        employeeId: employeeId,
        firstName: firstName,
        lastName: lastName
    });

    return employeeId;
}

export default createEmployee;

import { Employee, Ticket } from "@ontology/sdk";
import { Edits, Integer } from "@osdk/functions";
import { WriteableClient } from "@osdk/functions/experimental";
import { randomUUID } from "crypto";

type OntologyEdit = Edits.Object<Ticket> | Edits.Link<Employee, "assignedTickets">;

async function assignTicketAndCheckWorkload(
    client: WriteableClient<OntologyEdit>,
    employeeId: Integer,
    title: string
): Promise<{ ticketId: string, totalAssignedTickets: number }> {
    const ticketId = randomUUID();

    // Create the ticket
    await client.create(Ticket, {
        ticketId: ticketId,
        title: title,
        status: "open"
    });

    // Assign the ticket to the employee
    await client.link(
        { $apiName: "Employee", $primaryKey: employeeId },
        "assignedTickets",
        { $apiName: "Ticket", $primaryKey: ticketId }
    );

    // Query the employee's total workload including the newly assigned ticket.
    // This works because of the read-after-write guarantee.
    const result = await client(Ticket).aggregate((tickets) =>
        tickets
            .where(ticket => ticket.assignedTo.employeeId.exactMatch(employeeId))
            .where(ticket => ticket.status.exactMatch("open"))
            .count()
    );

    return {
        ticketId: ticketId,
        totalAssignedTickets: result
    };
}

export default assignTicketAndCheckWorkload;

从暂存写入函数调用其他函数

当您在暂存写入函数中调用另一个函数或查询时，这些操作会参与到相同的暂存编辑中。任何读取都会反映执行中先前暂存的编辑，而被调用函数所做的任何编辑也会添加到相同的暂存编辑中。这适用于：

  • 其他 TypeScript 暂存写入函数
  • AIP Logic 函数
  • 本体论查询

如果顶层函数成功完成，则跨嵌套调用暂存的所有编辑将一起提交。如果任何调用抛出异常，则整个批次都会回滚。

在下面的示例中， assignTicket 是从同一仓库发布的独立暂存写入函数。 bulkAssignTickets 通过 OSDK 生成的 $Queries import 调用它；每次调用都会将其编辑添加到相同的暂存编辑中。

import { Employee, Ticket, $Queries } from "@ontology/sdk";
import { Edits, Integer } from "@osdk/functions";
import { WriteableClient } from "@osdk/functions/experimental";

type OntologyEdit = Edits.Object<Ticket> | Edits.Link<Employee, "assignedTickets">;

async function bulkAssignTickets(
    client: WriteableClient<OntologyEdit>,
    employeeId: Integer,
    ticketIds: string[]
): Promise<Integer> {
    let assignedCount = 0;

    for (const ticketId of ticketIds) {
        // Each call to `assignTicket` stages its edits alongside those of
        // the calling function.
        await client($Queries.assignTicket).executeFunction({
            employeeId: employeeId,
            ticketId: ticketId,
        });

        assignedCount++;
    }

    // All staged edits across the nested calls will be committed together
    // when the top-level function completes.
    return assignedCount;
}

export default bulkAssignTickets;

执行生命周期

了解暂存编辑何时提交对于构建可靠的函数非常重要：

  1. 函数执行： 所有操作(创建、更新、删除、读取、嵌套函数调用)都会暂存到本体论中。这些操作对函数本身以及所有嵌套函数可见,但在提交之前不会出现在当前执行范围之外。
  2. 提交: 如果函数成功完成,所有暂存的编辑将在操作结束之前被提交。
  3. 出错时回滚: 如果函数抛出错误,本体论将保持不变,所有暂存的编辑将被丢弃。随后,操作将重试该函数。

import { Employee } from "@ontology/sdk";
import { Edits, Integer } from "@osdk/functions";
import { WriteableClient } from "@osdk/functions/experimental";

async function updateEmployeeWithValidation(
    client: WriteableClient<Edits.Object<Employee>>,
    employeeId: Integer,
    newSalary: number
): Promise<Integer> {
    // Validate input
    if (newSalary < 0) {
        // Staged edits will be discarded
        throw new Error("Salary cannot be negative");
    }

    // Update the employee
    await client.update(
        { $apiName: "Employee", $primaryKey: employeeId },
        { salary: newSalary }
    );

    // If we reach here, all staged edits will be committed atomically
}

export default updateEmployeeWithValidation;
