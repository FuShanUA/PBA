Salesforce

Foundry 的 Salesforce 连接器允许您在 Salesforce 与 Foundry 数据集之间同步数据。

本文档针对的是最新版本的 Salesforce 连接器。如果您正在编辑现有的 Salesforce 连接器，它可能是旧版本。请查看 迁移 章节以了解更多信息。

性能与限制

该连接器默认使用 Salesforce Bulk API ↗ 对于任何包含超过 2000 行的数据操作，建议使用该 API。阅读更多关于 Bulk API 限制 ↗.

该连接器也可以选择使用 Salesforce SOAP API ↗ 通过设置 JDBC 属性 UseBulkAPI to false。SOAP API 同样受 Salesforce SOAP API 调用限制 ↗.

身份验证

选择一种凭据方法来验证您的 Salesforce 连接：JWT 令牌或用户名-密码。

自 Spring '26 版本起，Salesforce 限制了新连接应用的创建。现有连接应用仍可继续使用，Salesforce 建议新集成使用 外部客户端应用 ↗ 。以下章节介绍如何配置外部客户端应用。请查阅 Salesforce 授权文档 ↗ 的文档以获取更多信息。

JWT 令牌

您可以使用 OAuth 2.0 JSON Web Token (JWT) bearer 流程 ↗ 来授权 Foundry 访问数据，而无需在每次请求时进行交互式登录。

要启用 JWT 身份验证，您必须生成证书，在创建外部客户端应用时上传该证书，然后授权集成用户。

第 1 部分：生成证书

首先，创建一个 Salesforce 用户，并确认其具有 API 以及您希望修改的任何 Salesforce 对象的访问权限。请确保您能够以该集成用户身份登录，因为在后续步骤中您需要以该用户身份进行授权。

现在，创建一个 JWT 证书。Salesforce JWT bearer 流程 ↗ 需要一个 X.509 证书及关联的私钥。要生成私钥，请使用 openssl 在命令行中运行以下命令：

  1. 生成 x.509 公钥和私钥对：

    Copied!
    1
2
openssl genrsa 1024 | openssl pkcs8 -topk8 -inform PEM -out key.pem -nocrypt
openssl req -new -x509 -key key.pem -out cert.pem -days 3650

  2. 将证书导出到 PFX 存储，转换为 Base64，并复制到剪贴板：

    Copied!
    1
openssl pkcs12 -export -in cert.pem -inkey key.pem | openssl base64 | pbcopy

请务必将证书值保存在安全的位置。稍后在 配置.

第 2 部分：创建外部客户端应用

如果您的 Salesforce 组织已拥有可用于此连接器的正常工作的连接应用，您可以继续使用它。Salesforce 限制了新连接应用的创建，但并未禁用现有的连接应用。对于现有的连接应用，请查阅 Salesforce 关于管理 OAuth 访问的指南 ↗.

在开始之前，请确认您的 Salesforce 组织已启用外部客户端应用（原连接应用）。您的 Salesforce 用户还必须具有创建外部客户端应用和编辑其策略的权限。

按照 Salesforce 文档创建应用 创建外部客户端应用 ↗，或参考 Trailhead 单元 为 API 创建并配置外部客户端应用 ↗。只有下面列出的设置会影响此连接器；创建表单中的其余部分请保持默认值。

完成后，该应用必须具备：

  • 已启用 OAuth： 连接器通过 OAuth 进行身份验证，因此未启用 OAuth 的应用无法使用。
  • 回调 URL 为 https://localhost:12345: Salesforce 要求提供回调 URL，但连接器从不发送该 URL。请使用此值，以使其与 第 3 部分.
  • 中的浏览器授权选项相匹配。来自 第 1 部分 的 X.509 证书已上传： 上传 cert.pem 文件。上传证书是启用 JWT bearer 流程的关键，没有单独的设置来开启该流程。
  • OAuth 作用域： 授予 api。同时授予 offline_access and refresh_token ，但仅当您打算使用 第 3 部分.

检索应用的消费者密钥并将其存储在安全的地方。您将在下方连接器配置中将其输入为 Consumer key 。该密钥在您显示之前处于隐藏状态，并且 Salesforce 可能会要求您确认发送到您电子邮件地址的验证码后才会显示。连接器将消费者密钥包含在已签名的 JWT 中发送，因此您不需要 Salesforce 随其一起颁发的消费者密钥。

请勿将 JWT bearer 流程与 为指定用户颁发基于 JSON Web Token (JWT) 的访问令牌 设置混淆。该设置会更改 Salesforce 颁发的访问令牌的格式，而此连接器并不需要它。

新建的外部客户端应用可能无法立即使用。如果在创建应用后不久身份验证失败，请等待最多 30 分钟后重试，然后再更改配置。

第 3 部分：授权用户

在连接器可以使用外部客户端应用之前，必须先为集成用户授权。预授权是推荐选项，因为连接器使用已签名的 JWT 进行身份验证，从不交换浏览器流程产生的授权码。

  • 预授权用户： 在应用的 OAuth 策略中，将 允许的用户 to 管理员批准的用户已预授权。然后，通过分配给该用户的配置文件（Profile）或包含该用户的权限集（Permission Set）授予集成用户访问权限。仅靠该策略本身无法授权用户，必须进行此授予。请查阅 Salesforce 外部客户端应用文档 ↗ 以了解可用的策略值。
  • 执行一次性授权： 以集成用户身份在浏览器中完成一次 Salesforce 登录流程。此选项要求应用还具备 offline_access and refresh_token scopes:
    1. 导航到以下 Salesforce URL： https://<salesforce-url>/services/oauth2/authorize?client_id=<CONSUMER_KEY>&redirect_uri=<CALLBACK_URL>&scope=api%20offline_access%20refresh_token&response_type=code&response_mode=query&nonce=bebmwgu22zh
      • 替换 <CONSUMER_KEY> 填入您的消费者密钥，并将 <CALLBACK_URL> 填入应用上配置的回调 URL。
      • 替换 <salesforce-url> 填入您的 Salesforce 实例 URL（<site>.my.salesforce.com).
    2. 完成登录流程并批准所请求的作用域。确认显示的用户名是集成用户，而不是您的个人账户。授权错误的用户会导致连接器看似正常工作，随后因错误用户的权限而失败。
    3. 浏览器预计会在 https://localhost:12345处以“Not Found”错误结束。回调 URL 并非真实的端点，因此该错误表示流程已完成。

用户名-密码

要使用以下方式连接到 Salesforce 用户名-密码 ↗ 身份验证方法，您必须在 Salesforce 中创建一个服务用户账户和一个外部客户端应用。然后，将服务用户凭据添加到 Salesforce 连接器中。

按照以下步骤启用用户名-密码身份验证流程。

  1. 创建一个 Salesforce 用户，并确认其具有 API 以及您希望修改的任何 Salesforce 对象的访问权限。记下该用户的用户名和密码以备后用。

  2. 创建一个外部客户端应用，请遵循 第 2 部分 但需注意以下差异：

    • 无需证书。
    • 授予 完全访问权限 (full) OAuth 范围，而不是 api，以便该应用可以访问当前用户可用的所有数据。
    • 在应用的 OAuth 策略中，将 允许的用户 to 所有用户均可自行授权.
    • 无需消费者密钥。此身份验证方法仅使用您在下方配置的用户名和密码。

用户名-密码身份验证方法支持以下配置选项：

Username是应用所模拟的账户的用户名。

如果您在尝试从 Foundry 连接时遇到授权问题，并查看 Failed: API security token required 菜单中选择 Salesforce 登录历史 （属于该用户），则必须将该用户的安全令牌添加到密码末尾。

安全令牌是一个自动生成的密钥，从不受信任的网络登录 Salesforce 时必须将其添加到密码中。Salesforce 不允许用户在应用程序内查看安全令牌；相反，您必须以 集成用户 的身份登录 Salesforce，并导航到右上角的 我的设置 。然后，导航到 Personal > Reset My Security Token.

网络

如果您的 Salesforce 连接器使用直接连接运行，则必须添加 网络出口策略 以将连接加入白名单。

选择添加现有策略，或创建新策略。

要将 Salesforce 的直接连接加入白名单，请添加以下策略：

  • 登录 URL：需要 DNS，端口 443 （HTTPS），以及以下之一：

    • login.salesforce.com (production) OR
    • test.salesforce.com (sandbox)

  • 实例 URL：需要 DNS 为 <site>.my.salesforce.com，端口 443 （HTTPS）。

证书和私钥

SSL 连接会验证服务器证书。通常，SSL 验证通过证书链完成；默认情况下，代理和 Foundry 工作进程信任大多数行业标准证书链。如果您要连接的服务器使用自签名证书，或者在验证过程中存在 TLS 拦截，则连接器必须信任该证书。了解更多关于 在数据连接中使用证书.

从 Salesforce 同步数据

使用直方图中的 使用 以同步表。编辑同步时可使用其他配置选项。

增量

在使用 Salesforce 连接器进行增量同步期间，如果增量列的值 大于或等于 之前观察到的最大值，则会同步新数据。此行为虽然是同步数据精确性和正确性所必需的，但会导致输出数据集中出现重复行。增量管道应始终包含去重步骤。

选中直方图中的行后，您可以使用

您可以向同步配置添加行筛选器，以排除不符合一组条件的数据。 使用条件树来定义您的筛选器：

  • 逻辑运算符：
    • ALL：要求其下嵌套的所有节点均为真。
    • ANY：要求至少一个嵌套节点为真。
  • Conditions：
    • 从可用列的列表中进行选择。
    • 根据列类型，选择合适的运算符。
    • 设置一个用于与所选列进行比较的值。

请务必 保存 您的配置，以将其应用到同步。

迁移

如果您已经拥有 Salesforce 连接器，您可能正在运行旧版本。要确定您的连接器版本，请迁移到 Connection settings > Connection details。如果源配置显示一个 自定义 YAML 部分，其中包含一个 type: salesforce 字段，则您正在使用旧版 Salesforce 连接器。您必须迁移到最新版本，才能在错误修复之外获得 Palantir 支持。

迁移连接器

  1. 打开 数据连接 应用程序，然后选择 源 （位于屏幕右上角）。
    1. 选择 Salesforce （从可用的连接器类型中选择）。
    2. 按照后续的配置提示，使用以下各章节中的信息继续完成连接器的设置。
  2. 配置身份验证以与旧版源相匹配。在旧版源配置中，找到 auth-method or authentication-method 自定义 YAML 中的块。
    • If type: oauth2-jwt，使用以下内容配置新源 JWT 身份验证:
      • claim-sub 从自定义 YAML 中变为 Username （在新连接器配置中）。
      • x509-cert 被导出为 PFX，然后进行 Base64 编码并变为 Certificate。在上方 JWT 身份验证 部分中了解有关证书的更多信息。
    • 如果 PFX 受密码保护，请开启 The certificate is password protected 并输入 Certificate password.
      • claim-iss 从自定义 YAML 中变为 Consumer key （在新连接器配置中）。
    • If type: oauth2-username-password，使用以下内容配置新源 用户名-密码身份验证:
      • username 从自定义 YAML 中变为 Username （在新连接器配置中）。
      • password 从自定义 YAML 中变为 Password （在新连接器配置中）。
      • client-id and client-secret 旧版源上的属性为 不 新连接器所必需。
  3. 配置其他属性：
    • auth-url 从自定义 YAML 中变为 Login URL （在新连接器配置中）。
    • If auth-url 在自定义 YAML 中的值为 test.salesforce.com ，请开启 Is Salesforce sandbox account （在新连接器配置中）。

迁移同步

配置新的 Salesforce 连接器后，为之前由旧版连接器同步的对象创建同步。使用 使用 可批量同步多个对象并创建新数据集。

如果使用相同的 API 版本，旧版和新的 Salesforce 连接器将使用相同的 schema；在重新映射输入后，所有下游应用程序应能继续正常运行。

您必须迁移下游管道以使用新的同步数据集。确认没有其他消费者需要旧版数据集后，您可以删除这些数据集、相关联的同步和连接。使用 调度指标 来查找旧版数据集在您的环境中的使用位置。
