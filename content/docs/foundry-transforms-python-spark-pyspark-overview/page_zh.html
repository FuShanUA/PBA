PySpark 转换

有关基础概念（包括转换的输入和输出以及轻量级转换与 PySpark 转换之间的区别），请参阅 转换。

PySpark 是一种包装器语言，允许您与 Apache Spark 后端交互，从而快速处理数据。Spark 可以跨分布式服务器网络对超大型数据集进行操作，如果使用得当，可带来显著的性能和可靠性优势。但是，它也存在一些局限性，尤其是当您更习惯于使用 SQL 等关系型数据库系统时。例如，Spark 无法确切知道某一行存在于哪台服务器上，因此无法直接选择特定行来进行更新或删除。如果您习惯于以这种方式思考数据库，则需要调整您的概念模型，将数据集视为一个整体，并基于列（而非行）来处理数据。

如果您熟悉循环、列表和变量等过程式 Python 结构，请参阅 从 Python 过渡 ，以了解如何使用 PySpark DataFrame 对象。

  • DataFrame： 是一组行，并带有 命名列
    • 结构上类似于 SQL 数据库，但为非关系型
    • 不可变： 无法对 DataFrame 进行 更改 （在其创建后），但它可以被 转换 成新的 DataFrame（从而产生两个 DataFrame：原始 DataFrame 和转换后的 DataFrame）。数据集可以被覆盖，但 Foundry 会跟踪版本历史记录，因此您可以随时探索并回退到较早的构建版本。
    • 惰性求值： 一系列转换任务会作为一个（合并后的）操作进行求值，然后在构建被触发时才执行。
  • 弹性分布式数据集： （RDD）是底层 数据结构 ，构成了 DataFrame 的基础。通过将 DataFrame 分区为多个互不相交的子集，转换可以在计算机集群（网络）中的多台计算机（节点）上并行求值。这一切都在后台自动完成，但在使用 PySpark 编写代码时，牢记这一点非常重要。
  • 共享变量： 默认情况下，Spark 会将单独管理的 副本 （即转换任务中使用的每个变量的副本）发送到每台并行计算机（节点）——这是出于效率考虑。如果必须在多个任务之间共享某个变量，Spark 支持两种类型的共享变量：
    1. 广播变量： 在内存（RAM）中缓存（保存）一个值，该值会被广播到集群中的所有计算机（节点）
    2. 累加器： 可相加或聚合的变量，包括（但不限于）计数器和求和。此概念与 GroupedData 相关，对统计计算非常有用。
  • 为什么要使用 DataFrame？： Spark DataFrame 专为处理大规模（PB 级以上）结构化数据集合而设计和优化。
  • 为什么我应该编写 PySpark 代码？： 借助 PySpark，您可以在代码仓库和 Code Workbook 中自定义转换数据集的方式，比单独使用 Contour 或 Blacksmith 更加复杂、灵活。
  • PySpark 不适合用于什么？： PySpark 旨在用于转换数据集，而非访问单个值。您可以计算总和与平均值，但不能也不应该直接引用数据。

在 SQL 中，查询会生成“视图”（虚拟表结果集）；而使用 PySpark 处理数据集则会生成全新的数据集。这不仅使您能够基于派生数据集构建新数据集，组织中的其他成员也可以重用中间数据集来完成各自的数据处理任务。在 Palantir Foundry（一个数据操作系统）中，数据集之间会通过父子（或源-结果）有向树关系自动建立关联。这使得任何人都能轻松追溯 Spark 转换的数据血缘。换句话说，您可以探索数据集的依赖项是如何构建的，以及这些数据集来自何处。您还可以发现组织中的其他成员是如何使用某个数据集的，这样您就可以从示例中学习，或有效减少重复工作。

理解 PySpark 代码

初始代码基础

在 Code Workbook 中，您的函数可能类似于以下形式：

def new_frame(old_frame):
  df = old_frame
  # df = transformations on df
  return df
  • old_frame：引用一个 DataFrame ，它表示一个 数据集 ，存储在 Foundry 中。 old_frame 是 不可变的 ，这意味着它无法在此处被修改 new_frame 函数。从某种意义上说，转换的每个中间步骤都会产生一个新的、不可变的 DataFrame，我们可能需要再次对其进行转换，或将其按原样返回。这种说法并不完全准确，但作为一种认知模型，它将帮助您更好地组织代码。
  • new_frame：您可以在此函数中定义一系列转换，并希望将它们应用于 old_frame。您的 return 语句应返回一个 DataFrame （在本示例中我们将其称为 df ）。在底层，您对该 DataFrame 应用的每一个转换都会被合并并 优化，然后才会应用于输入数据集。当您使用代码触发构建后，结果将保存到 Foundry 中的一个新数据集文件中，构建完成后您即可对其进行探索。

一个 DataFrame 中的数据无法被直接引用，因为它既不是 Array 也不是 Dictionary。实际上，由于底层一直在进行各种分区和混洗操作，无论如何都无法确定数据在任意给定时刻的具体位置。除非您要对数据集进行筛选或聚合，否则您编写的代码应当相对 不可知 数据集的内容。排序通常开销高昂且速度缓慢,因此经验法则是:假设每一行都是随机排序的,将您的工具集限制为列、筛选、聚合,以及您自己的创造性问题解决能力。

警告

跟踪传入列的架构非常重要,因为 PySpark 不是类型安全的,它会尝试对所有转换操作进行求值,并在运行时任何操作失败时中断。

不要对字符串或日期执行数学函数,不要对数字执行字符串操作,也不要对整数执行日期操作,因为类型冲突时的行为难以预测。

在对值进行操作之前,请务必先将其转换为正确的类型。

命名列

DataFrame 中的每一列都有名称(并且可以重命名)。列名是唯一的,且区分大小写。请遵循以下 Foundry 数据集准则:

  • 始终使用小写字母或数字。
  • 分隔单词请使用 _ (下划线)而不是空格(因为不允许使用空格)。
  • 避免 camelCasedColumnNames 是惯例。
  • 切勿使用特殊字符,例如 (, ),或 &.
  • 聚合函数有时会自动生成包含特殊字符的列名。您需要在转换中返回 dataframe 之前,为该列提供别名或对其进行重命名。

转换的链式调用

当你接触现有代码时，你会注意到，对于引用 DataFrame 的变量应该如何命名，并没有硬性规定。在本速查表中，DataFrame 将被称为 df，但在其他示例中，它也可能是 raw， out， input， table， something_specific。怎么命名都可以，只要能完成任务。

return df.select("firstName", "age") \

       .filter(df.age > 21) \
       .withColumnRenamed("firstName", "first_name")

如果你不熟悉编程： df 位于左侧的 = 中存储的是将转换 应用 于 df （位于右侧）后得到的结果，随后才会继续执行下一行代码。在本例中，我们将结果存入了一个同名的变量，实际上覆盖了 df 在每一步之后所包含的内容。你可以使用不同的名称来存放 DataFrame 转换的结果，但在大多数情况下，直接覆盖变量名并继续下去是没有问题的。在每个转换函数的末尾，我们都必须返回新的 DataFrame：要么将其作为变量返回（如第一个示例中那样），要么将其作为最后一次转换的结果返回（如第二个示例中那样）。

这两个示例完成的是同一件事：

  1. 仅选择 df 中我们想要包含在转换后数据集中的 2 列
  2. 将 age 列进行类型转换，以确保它是整数而不是字符串。
  3. 筛选我们数据集中的行，使其仅包含 age > 21
  4. 将列 firstName 重命名为 first_name

生成的数据集将只包含两列 first_name， age 并且 21 岁及以下的人员被排除在外。这就是 df 最后所包含的内容，你可以 return 它，或对其应用更多转换。以下各节将更详细地探讨这些转换。

窗口函数

窗口函数会追加聚合值和其他计算值，而不会丢弃 DataFrame 对象的原始行或列。可将它们用于累计总和、排名和滚动平均值。详情请参阅 窗口函数。
