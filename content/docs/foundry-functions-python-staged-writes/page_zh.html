Python 中的暂存写入 [Beta]

Beta

暂存写入目前处于 beta 开发阶段。功能在积极开发过程中可能会发生变化。

实时预览和已发布函数预览仅在代码仓库中受支持，而在本地开发或 VS Code 工作区环境中不受支持。

暂存写入为编辑本体论中对象的 Python 函数提供了一种额外的执行模型。与常规 Python 本体论编辑函数不同，暂存写入函数：

  • 为函数中应用的本体论编辑提供写后读保证。函数中应用的所有编辑均会被暂存，并在函数后续的本体论查询和聚合中得到反映。
  • 允许嵌套调用其他进行本体论编辑的暂存写入函数。

本页介绍如何使用 Python 编写暂存写入函数，并记录其独特属性。有关 TypeScript v2，请参阅 TypeScript v2 函数中的暂存写入。有关编辑函数工作原理的更多详细信息，请参阅 本体论编辑概览。

与常规本体论编辑函数的主要区别

暂存写入函数在多个重要方面与常规编辑函数不同。

写后读保证

在暂存写入函数中，读取的任何本体论数据都会反映此前在函数内所做的所有编辑，以及同一操作执行中调用该函数的暂存写入函数所做的所有编辑。这些编辑仅处于暂存状态，对执行上下文之外的其他用户或函数不可见。您可以在函数内使用搜索请求和聚合来查询本体论，结果将反映之前暂存的所有编辑。

无需返回编辑

常规的 Python 本体论编辑函数必须返回一批本体论编辑，这些编辑才会被应用。暂存写入函数会自动暂存其编辑，并在操作完成时将其应用到本体论。该函数可以返回任何受支持的函数类型，而无需返回编辑。

原子执行

暂存写入函数中的所有操作（包括查询、函数调用和 AIP Logic 执行）都会将其编辑一起暂存。函数成功完成后，这些编辑才会提交到本体论。如果函数抛出错误，本体论将保持不变，并且在操作重试该函数之前会丢弃所有暂存的编辑。

WriteableClient

Python 暂存写入函数使用生成的 WriteableClient 而不是标准的 FoundryClient。请使用 WriteableClient 来构造一个暂存写入容器。该容器提供与常规 Python 编辑容器相同的对象和关联编辑 API,但您无需从函数中返回其编辑内容。

定义暂存写入函数

要定义 Python 暂存写入函数:

  • 将 beta=True 设置在 @function 装饰器中。
  • 使用装饰器的 edits 参数来声明函数可编辑的每个对象类型和关联类型,包括通过嵌套函数调用编辑的类型。要声明关联编辑,请使用 OntologyLinkType(SourceObjectType, "linkApiName")。
  • 使用生成的 WriteableClient 类型为第一个参数添加注解。函数运行时会为操作执行注入带有事务上下文的客户端,因此请勿在函数中构造该客户端。
  • 返回任何受支持的函数类型。

from functions.api import Integer, function
from ontology_sdk import WriteableClient
from ontology_sdk.ontology.objects import Employee

@function(beta=True, edits=[Employee])
def update_employee_last_name(
    client: WriteableClient,
    employee_id: Integer,
    new_last_name: str,
) -> Integer:
    staged_writes = client.ontology.staged_writes()
    editable_employee = staged_writes.objects.Employee.edit(employee_id)
    editable_employee.last_name = new_last_name
    return employee_id

将暂存写入函数配置为 函数支持的操作 ,以应用其编辑。

from functions.api import function
from ontology_sdk import WriteableClient
from ontology_sdk.ontology.objects import Employee

@function(beta=True, edits=[Employee])
def create_employee(
    client: WriteableClient,
    employee_id: str,
    first_name: str,
    last_name: str,
) -> str:
    staged_writes = client.ontology.staged_writes()
    staged_writes.objects.Employee.create(
        employee_id=employee_id,
        first_name=first_name,
        last_name=last_name,
    )
    return employee_id

from uuid import uuid4

from functions.api import function
from ontology_sdk import WriteableClient
from ontology_sdk.ontology.objects import Ticket

@function(beta=True, edits=[Ticket])
def create_ticket(client: WriteableClient, title: str) -> str:
    ticket_id = str(uuid4())
    staged_writes = client.ontology.staged_writes()
    staged_writes.objects.Ticket.create(
        ticket_id=ticket_id,
        title=title,
        status="open",
    )
    return ticket_id

暂存写入函数中的写后读

from functions.api import Integer, function
from ontology_sdk import WriteableClient
from ontology_sdk.ontology.objects import Ticket

@function(beta=True, edits=[Ticket])
def create_ticket_and_count_open(
    client: WriteableClient,
    ticket_id: str,
    title: str,
) -> Integer:
    staged_writes = client.ontology.staged_writes()
    staged_writes.objects.Ticket.create(
        ticket_id=ticket_id,
        title=title,
        status="open",
    )
    return (
        client.ontology.objects.Ticket.where(
            Ticket.object_type.status == "open"
        )
        .count()
        .compute()
    )

从暂存写入函数调用其他函数

当您通过 WriteableClient调用另一个函数或查询时，这些操作将参与同一批暂存编辑。被调用函数中的读取会反映执行中先前暂存的编辑，而被调用函数所做的编辑也会加入同一批暂存编辑。这适用于：

  • 其他 Python 或 TypeScript v2 暂存写入函数
  • AIP Logic 函数
  • 本体论查询

如果顶级函数成功完成，嵌套调用中暂存的所有编辑将一起提交。如果任何调用引发错误，则整组编辑将被丢弃。

在以下示例中， assign_ticket 是从同一仓库发布的独立暂存写入函数。 bulk_assign_tickets 通过 OSDK 生成的查询 API 调用它，每次调用都会将其编辑添加到同一批暂存编辑中：

from functions.api import Integer, OntologyLinkType, function
from ontology_sdk import WriteableClient
from ontology_sdk.ontology.objects import Employee, Ticket

@function(
    beta=True,
    edits=[Ticket, OntologyLinkType(Employee, "assignedTickets")],
)
def bulk_assign_tickets(
    client: WriteableClient,
    employee_id: Integer,
    ticket_ids: list[str],
) -> Integer:
    for ticket_id in ticket_ids:
        client.ontology.queries.assign_ticket(
            employee_id=employee_id,
            ticket_id=ticket_id,
        )
    return len(ticket_ids)

执行生命周期

暂存写入函数使用以下执行生命周期：

  1. 函数执行： 创建、更新、删除、读取和嵌套函数调用都在同一个暂存事务中进行。这些编辑对函数和嵌套函数可见，但在提交之前不会显示在执行范围之外。
  2. 提交： 如果函数成功完成，所有暂存编辑将在操作完成之前提交。
  3. 出错时回滚： 如果函数引发错误，本体论将保持不变，所有暂存编辑将被丢弃。然后，操作可以重试该函数。

from functions.api import Integer, function
from ontology_sdk import WriteableClient
from ontology_sdk.ontology.objects import Employee

@function(beta=True, edits=[Employee])
def update_employee_with_validation(
    client: WriteableClient,
    employee_id: Integer,
    new_salary: float,
) -> Integer:
    if new_salary < 0:
        raise ValueError("Salary cannot be negative")
    staged_writes = client.ontology.staged_writes()
    editable_employee = staged_writes.objects.Employee.edit(employee_id)
    editable_employee.salary = new_salary
    return employee_id
