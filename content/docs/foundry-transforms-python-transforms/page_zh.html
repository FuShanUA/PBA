转换

Foundry Transforms 是数据处理管道的核心构建模块。它们定义了数据如何从输入流向输出，将计算逻辑和资源需求封装在单个声明式单元中。

转换注册在 Pipelines 中，它可以由多个转换定义组成。

定义转换

每个转换由三个关键组件组成：

  1. 装饰器： 定义输入、输出和配置
  2. 函数签名： 与装饰器中声明的输入和输出相匹配
  3. 计算逻辑： 实际的数据处理代码

以下是用于定义转换的基本模式：

def filter_hair_color(hair_eye_color, processed):  # function signature matches input/output
    ... # compute logic

Python 转换可以配置为使用单节点（轻量级）或多节点（Spark） 计算引擎。默认情况下，转换在单节点上运行，您可以将数据加载为 Polars ↗ 或 pandas ↗ DataFrame。Polars 是一个用于转换表格数据的 DataFrame 库，以其性能、稳定性和易用性而著称。Pandas 是一个广泛使用且易于上手的数据分析工具。

import polars as pl
from transforms.api import transform, Input, Output


@transform.using(
    hair_eye_color=Input('/examples/students_hair_eye_color'),
    processed=Output('/examples/hair_eye_color_processed')
)
def filter_hair_color(hair_eye_color, processed):
    # Load data as Polars DataFrame
    df = hair_eye_color.polars()

    # Apply filtering logic
    filtered = df.filter(pl.col('hair') == 'Brown')

    # Write the result
    processed.write_table(filtered)

轻量级语法选项

您可以使用以下任一语法选项来定义单节点（轻量级）转换：

  • @transform.using(...)：推荐的 API
  • @transform.lightweight(...)：一个显式别名，引用轻量级
  • @lightweight 装饰器，与 @transform(...)：旧版 API

版本要求

该 @transform.using API 需要 transforms 3.68.0 或更高版本。要使其在代码仓库中可用，请升级您的仓库，具体步骤请参阅 仓库升级指南。请确保 transformsLangPythonPluginVersion 等于 1.978.0 或更高版本。

Spark API @transform.spark.using 需要 transforms 3.95.0 或更高版本。请确保 transformsLangPythonPluginVersion 等于 1.1003.0 或更高版本。

要了解有关 transforms 版本的更多信息，请参阅 transforms 版本概述。

排查 @transform.using 的版本错误

如果您收到类似以下的错误消息，则您可能正在使用旧版本的 transforms 库，而该版本不支持更新后的语法：

  • Usage of transform.using() on outdated repository
  • A function object does not have an attribute using

要解决此问题，请执行以下操作：

  • 将您的仓库升级到最新版本的 transforms 库和仓库模板，具体步骤请参阅 仓库升级指南。
  • 或者，也可以切换到旧版语法，使用 @lightweight 搭配 @transform(...)。

@transform.using(output=Output('/Project/folder/output'), dataset=Input('/Project/folder/input'))
def compute(ctx, output, dataset):
    polars_df = dataset.polars()         # polars_df is a polars.DataFrame object
    lazy_df = dataset.polars(lazy=True)  # Activate streaming mode, lazy_df is a polars.LazyFrame
    pandas_df = dataset.pandas()         # pandas_df is a pandas.DataFrame
    arrow_table = dataset.arrow()        # arrow_table is a pyarrow.Table

    # DuckDB connection with pre-registered input datasets
    conn = ctx.duckdb().conn
    df_from_duckdb = conn.sql("SELECT * FROM dataset").fetchdf()  # dataset is automatically registered

    output.write_table(lazy_df)          # Any of the formats above can be passed to write_table

请注意，调用 dataset.pandas() 需要在您的环境中安装 pandas。同样， dataset.polars(...) 需要 Polars 可用。

from transforms.api import transform, Input, Output


@transform.using(
    large_dataset=Input('/datasets/large_file'),
    processed=Output('/datasets/processed')
).with_resources(
    cpu_cores=8,          # Use 8 CPU cores
    memory_gb=16,         # Allocate 16GB memory
    gpu_type="NVIDIA_T4"
)
def process_large_dataset(large_dataset, processed):
    ...
  • cpu_cores： CPU 核心数。该值可以是小数，例如 0.5，默认值为 2。
  • memory_mb 或 memory_gb： 内存分配；只能使用其中一个，不能同时使用两者。
  • gpu_type： 要为转换分配的 GPU 类型，以字符串形式提供。

只能配置 memory_gb 和 memory_mb 中的其中一个。

默认情况下，允许的最大值为 8 个核心和 64 GB 内存。如需提高这些上限，请联系 Palantir Support。

有关可用 GPU 类型和 GPU 预配要求的详细信息，请参阅 资源配置 文档。

转换上下文

在某些情况下，数据转换可能依赖于其输入数据集之外的其他内容。例如，转换可能需要访问当前 Spark 会话或与外部服务通信。在这种情况下，您可以将 TransformContext 对象注入到转换中。

要注入 TransformContext 对象，您的计算函数必须接受一个名为 ctx的参数。请注意，这也意味着任何输入或输出都不能命名为 ctx。请参阅 API 参考 ↗ 以了解 TransformContext 的全部功能。

Pyspark 转换

默认情况下，转换在单个计算节点上运行，并利用 pandas 或 Polars 等数据处理库。对于大数据计算工作流， PySpark ↗ 可在 Python 转换中使用。

PySpark 是一种封装语言，允许您与 Apache Spark 后端交互，从而快速处理数据。Spark 可以跨分布式服务器网络操作超大规模数据集，在正确使用的情况下可提供可扩展性和可靠性方面的优势。但是，它也伴随着更高的开销和资源占用，因此并不适合中小规模数据。

虽然此处提供了 PySpark 转换 API 的高层次概览，但请参阅 Python 转换（Spark） 文档以了解更多详情。

配置 PySpark 转换

在 PySpark 转换中，资源通过 Spark 配置文件进行配置。这些配置文件允许对大规模计算使用进行严格的访问控制。

Iceberg 表

在 Python 转换中，您可以通过 transforms.tables 库使用 Foundry Iceberg 表作为输入和输出。此处同样适用三段式转换结构。装饰器使用 TableInput 和 TableOutput定义输入和输出。函数签名会接收运行时句柄，例如 IcebergInput 和 IcebergOutput。计算逻辑使用标准的 DataFrame 代码来读取和写入数据。

有关在转换中使用 Iceberg 表的详细信息，请参阅 使用 Iceberg 的转换。

转换逻辑级版本控制

警告

为了使 TLLV 正常运行，您的代码必须在模块级别声明所有导入，并且不应尝试修补或以其他方式修改其他模块中的对象。如果您的项目并非如此， 则必须禁用 TLLV。请参阅下面的代码示例以了解更多信息。

默认情况下会启用 TLLV。 要禁用 TLLV，请将 transformsPython 配置中的 tllv 设置为 false。此配置位于您的 Python 转换子项目中的 build.gradle 文件中。 

transformsPython {
    tllv false
}

转换的版本是一个字符串，用于在考虑逻辑过时时比较转换的两个版本。如果转换的输入未发生更改且转换的版本未发生更改，则转换的输出为最新。如果版本发生变化，转换的输出将失效并被重新计算。

默认情况下，转换的版本包括以下内容：

  • 定义转换的模块
  • 转换所依赖的所有模块
  • 任何项目依赖项

如果其中任何一项发生更改，版本字符串将随之更改。 如果您希望在所列部分未涵盖的文件发生更改时使输出失效，请设置 tllvFiles 于 transformsPython 配置中。一个示例用例是：您正在读取某个文件的配置，并希望在配置发生更改时使输出失效。

事务性

转换在事务上下文中执行，该事务在输出上打开，并在作业成功时提交。如果未在输出上定义任何逻辑，或者在写入期间的错误被捕获并忽略，则成功的转换将在此类输出上产生空快照。
