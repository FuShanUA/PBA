App Pairing

App Pairing 为跨应用程序工作流提供支持，让您能够连接受支持的 Palantir 平台应用程序并同步多个视图，确保在一个应用程序中所做的数据或对象更改会自动更新到另一个应用程序，反之亦然。您可以在 AIP Chatbots （您创建的）中利用 App Pairing 的功能来 执行命令、 Workshop 模块 中通过 App Pairing 小组件使用该功能，或 Notepad 文档 中配置 内联命令。

例如，您或其他用户可以在 Graph 应用程序中更改数据，配对的 Workshop 模块中的相应数据将随之更新。要建立此连接， 请将 App Pairing 小组件添加 到与 Graph 应用程序配对的 Workshop 模块。此连接使您能够在 Graph 中选择对象，该对象将在配对的 Workshop 模块的对象列表中高亮显示。

设置 App Pairing 小组件

将 App Pairing 小组件添加到 Workshop 模块

要将 App Pairing 小组件添加到 Workshop 模块，请导航至 Workshop 并选择 + New Module。类似于其他 Workshop 小组件，您将可以选择在 Workshop 的某个部分或模块标头中添加小部件。此功能仅在小部件可见时才生效，因此您应将其添加到 Workshop 应用程序的标头中，以确保其始终保持可见。

将小部件添加到 Workshop 应用程序的标头后，请为其命名。每个小部件 必须 具有面向用户的名称，以便其他应用程序对其进行识别和发现。额外配置为可选项，您可以参阅下方的 高级配置 部分以了解更多详情。

创建与其他应用程序共享状态的变量

将 App Pairing 小部件添加到 Workshop 模块后，请转到右侧面板更新其配置，使其使用以下两种内置共享状态类型之一： 选择 或 打开数据。共享状态类型定义了 App Pairing 将在应用程序之间共享哪些变量。

  • 选择： 允许在 Workshop 与所连接的应用程序之间共享所选数据。当您在应用程序中选择对象时，Workshop 中也会随之选中相同的对象及其元数据。
  • 打开数据： 允许将受支持应用程序中的可见数据与 Workshop 共享。例如，如果用户打开一个包含 10 个对象的图，并将 Graph 应用程序与其 Workshop 模块配对，那么在配对时，该图上的全部 10 个对象都将填充到 Workshop 模块中。

通过 开放数据 状态类型进行的应用配对仅在 Graph 中受支持。

默认情况下，将会有一个预配置的选中对象变量，因为这是最常用的变量类型。当小部件与 Gaia 地图或 Graph 分析配对时，默认值将记录 Gaia 或 Graph 中当前选中的对象。

您可以选择 添加变量 来添加多个 选择 或 开放数据 变量，以满足模块所需的数据类型；您可以在下方 高级配置部分中了解更多信息。

配置完成后，来自配对应用程序的任何更新都将更新 Workshop 变量。使用 选择 变量时，用户在其 Workshop 模块中对变量所做的任何更新都会发送到配对的应用程序。

配对小部件

您必须将小组件与应用配对，共享状态变量才会更新。要配对小组件，请打开您想要与 Workshop 模块配对的应用。打开后，该应用会以 Discovered 状态显示在 App Pairing 菜单中，该菜单与 App Pairing 小组件一同添加到了 Workshop 中。

请选择 Pair （位于您想要与 Workshop 模块配对的应用旁边）。所选应用将显示在配对菜单的 Paired 部分中。

如果未发现任何受支持的应用，App Pairing 小组件将显示以下消息：

如果您使用 Iframe 小组件在 Workshop 中嵌入外部应用或另一个 Palantir 应用（例如 Gaia 地图），那么您的应用将自动发现并与嵌入的应用配对。要取消嵌入的应用与 Workshop 的配对，请转到 App Pairing 小组件图标，选择要渲染的 Paired 应用，然后选择 Unpair。

要详细了解复杂的配对逻辑，请参阅 下方的高级配置部分。

配置 App Pairing 小组件的外观

该 Appearance 部分位于 Widget setup 面板中，该面板位于 App Pairing 小组件的配置菜单内，使您能够自定义小组件在 Workshop 应用中的渲染行为。

显示名称： 设置小组件的名称，以便在配对时供其他应用发现。默认显示 Workshop 应用的名称。 自动打开模式： Disabled 默认处于关闭状态，因此应用配对菜单仅在选中时才会打开。您可以启用 自动打开模式 ，以便应用配对菜单自动打开并提示用户选择要配对的应用。其他配置选项包括：

  • Enabled：菜单在初始时以及应用配对发生更改时都会打开。
  • Only initially：菜单仅在应用加载时打开。
  • Only on pairing change：每次当前配对的应用发生更改时，菜单都会打开。

启用 Toast 通知： 默认处于禁用状态。您可以启用 Toast 通知，以便在另一个应用与当前应用配对时通知您应用的用户。

提供错误识别和故障排除说明的 Toast 通知将始终显示，即使您关闭 启用 Toast 通知。

启用暂停更新的开关： 默认处于禁用状态。您可以启用该开关来暂停和恢复小组件中状态更新的发送与接收。暂停后恢复更新时，小组件将同步到最新状态。

在变量更新时触发命令

使用 变量更新时触发命令 部分，该部分位于 小组件设置 面板，该面板位于 App Pairing 微件的配置菜单 以便当您的应用程序中的变量更新时，触发向其他应用程序发出的命令。

应用高级配置

您可以通过微件配置面板中的以下高级配置来自定义 App Pairing 体验，从而让您能够控制其原本自动执行的功能。如果现有的内置变量不适合您的用例，您还可以创建自定义变量，使用 scope 变量手动管理哪些应用程序相互配对，或者禁用 Workshop 与您配对的 Gaia 地图或 Graph 分析之间的数据富化。

在 共享状态变量 部分（位于 微件设置 面板中），您可以创建 自定义 变量，用于您的应用程序中传递的、不符合微件默认变量类型的数据。

在 媒体类型字符串 文本框中，通过输入媒体类型字符串或其他变量数据类型来描述自定义数据类型。

Workshop 支持以下变量数据类型：

  • 布尔值
  • 日期
  • 数值
  • 数值数组
  • 字符串
  • 字符串数组

此外，自定义状态变量配置使 App Pairing 微件能够支持未来的应用程序集成，而无需 Palantir 对其现有预设进行更新。

在 高级 部分（位于 微件设置 面板中），您可以 禁用数据富化 如果您确定配对的应用程序与 Workshop 之间会相互传递兼容的状态有效负载。Gaia 和 Graph 都 需要 enrichment 才能与 Object Synonym RIDs set Workshop 同步变量类型。

此外，您可以配置一个 Scope Id ，以便手动协调哪些应用程序相互配对。请使用 Scope Id 变量（由 Workshop 自动生成）来确保所有应用程序都属于同一作用域，从而启用配对功能。您可以使用 Scope Id 变量将 Workshop 小组件添加到作用域，并将非 Workshop 应用程序关联到作用域，方法是添加 &appPairingScopeId=[scope-id] 到其 URL 中。手动配对或取消配对应用程序会更改作用域。
