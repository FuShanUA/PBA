保护敏感数据

正如你在 保障数据基础安全中所看到的，各个项目中的数据访问可以由项目所有者管理。这就是所谓的 自主访问控制 ↗。然而，对于敏感数据，需要一种更强大、更集中化的访问控制模型。

在我们的示例中，我们有一个包含乘客出生日期（DOB）的概念性数据集，这些数据属于个人身份信息（PII）。我们可能希望严格控制此类 PII，确保只有接受过 PII 培训的人员才能访问这些数据。我们可以使用标记（Markings）来解决这个问题。

标记是 Foundry 对 强制访问控制 ↗的实现。标记代表一种数据类型（如 PII），指定的用户或组列表可以访问该类型的数据。当标记应用于数据集时，无权访问该标记的用户将绝对无法访问该数据，即使项目所有者尝试与其共享也是如此。重要的是，此限制会传播到平台中任何由该数据集 派生 而来的数据。

此功能对数据治理非常强大，使数据保护官能够集中管理和审计究竟谁可以访问某一类别的数据。

在向最终用户介绍我们的应用程序之前，我们要确保保护敏感数据。同样，在我们的示例中，我们有乘客出生日期（DOB），我们希望在数据管道中对其进行锁定。

创建标记

我们需要创建一个标记类别，即一组标记的名称。在本例中，创建一个名为“Information”的标记类别，因为将来可能还需要其他与信息相关的标记（例如个人健康信息，即 PHI）。创建类别后，你可以创建 PII 标记。然后，你可以将有权限查看 PII 数据的人员添加为标记的成员，并将管理团队添加为标记的管理者。

模拟我们的标记更改

标记具有沿数据血缘传播的强大特性。因此，将新标记应用于现有管道可能会导致下游用户意外被锁定，因此最佳实践是始终先模拟将标记应用到管道，以查看其传播范围。为此，请打开管道的数据血缘并开启模拟模式。你可以在 raw/passengers 数据集上编辑标记，并应用你创建的 PII 标记。然后，你将看到应用 PII 标记后所有将受影响的下游数据集。

我们不希望所有数据使用者都必须拥有 PII 访问权限，因此我们希望在管道中的某个环节移除敏感的 DOB 列。为此，我们应该点击浏览整个管道，审查我们认为最适合移除 PII 标记的位置。通常，这是通过在选择数据集时打开底部的预览视图来完成的，这样我们就可以查看数据和列。

在我们的概念性示例中，我们可以看到 PII 标记一直传播到本体论数据集，这将锁定所有无权访问 PII 的最终用户。因此，我们决定最好尽可能长时间地将敏感数据保留在管道中，但在乘客数据的本体论版本（即 /Sky Industries/Customer Metrics [Ontology]/passengers).

移除即将继承的标记

在数据血缘视图中，点击 Customer Metrics [Ontology]/passengers 数据集，点击 Code，然后点击 View in repository。这将打开用于创建此概念数据集的代码仓库。在代码仓库中，您需要：1) 创建一个分支，2) 删除敏感列（即删除 dob 列），3) 从输入数据集中移除即将被继承的 PII 标记，然后 4) 创建拉取请求。我们建议查阅有关如何 移除继承的标记和组织.

在同事批准停止传播 PII 标记的拉取请求后，我们需要构建此数据集及其下游的所有内容，以便最新的数据集事务全部“停止传播”即将添加的标记。此外，APPEND 或 UPDATE 事务类型有一些需要特别注意的事项。但在我们的示例中，所有内容都是作为 SNAPSHOT 构建的，这是 Foundry 中的默认事务类型。

应用标记

在应用标记之前，我们要再次确认它只会传播到我们期望的数据集，而不会传播到其他数据集。为此，请再次打开管道的数据血缘视图，开启模拟模式，在 raw/passenger 数据集上应用标记，并确认 ontology/passenger 数据集不受影响。这表明上一节中的 stop_propagating 逻辑已正确应用。

现在您可以应用标记了，如下面的概念数据截图所示。为此，请转到 raw/passenger 数据集，打开安全助手，并应用标记。单击保存后，PII 标记将立即应用并立即向下游传播。您可以通过查看数据血缘并观察现在带有标记的数据集上的标记徽章来确认这一点。您已成功保护了敏感的 PII 数据。
