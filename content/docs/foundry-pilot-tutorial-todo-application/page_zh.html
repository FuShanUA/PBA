构建一个待办事项应用程序

在本教程中，我们将使用 Pilot 构建一个发布检查清单应用程序。它将允许你组织任务列表并跟踪其完成情况。

Pilot 将帮助你构建发布检查清单、检查其提议的本体论，并测试生成的应用程序。本教程会创建新的对象类型和操作，因此请使用一个可以创建资源的项目和本体论。

生成的待办事项应用程序允许你添加任务、将其标记为已完成或未完成、筛选列表以及删除任务。请先按照应用程序演练进行操作，或前往 复用现有任务模型 or 以小组件形式构建检查清单 （如果你想直接跳转到特定章节）。

生成的布局和名称可能有所不同。请在操作过程中将控件和结果与截图进行比较。橙色轮廓标识了相邻步骤中使用的控件或状态指示器。

检查提议的数据模型

在工作区中，选择 本体论 （位于应用程序预览上方）。本示例需要：

  • A Release Checklist Task 对象类型，带有 ID, Title日 Completed properties
  • 用于添加任务的操作
  • 用于设置任务完成状态的操作
  • 用于删除任务的操作

检查这些实体是否被标记为 由 Pilot 提议。在应用程序能够将其用于生产数据之前，仍需在 Foundry 中实现这些实体。

选择任务对象类型以打开其数据预览。确认三个请求的示例任务是否存在。如果 Pilot 复用了现有实体或生成了不同的模型，请在聊天中描述差异，并在部署前再次检查结果。

使用种子数据进行测试

选择 预览 并确认 概念数据 已被选中。截图显示了数据源控件、任务输入和筛选器的位置。

测试生成的控件：

  1. 输入 Verify the published checklist 并选择 添加任务。确认任务已出现，且剩余计数增加了一。
  2. 将任务标记为已完成。确认其复选框已被选中，且剩余计数减少了一。
  3. 选择 已完成。确认已完成的任务已出现。
  4. 选择 活跃。确认已完成的任务未显示。
  5. 返回到 所有 并重新加载预览。确认任务及其完成状态仍然保留。
  6. 将任务标记为未完成。确认剩余计数增加了。
  7. 删除此测试任务。确认它已消失，且原始示例任务仍然保留。

如果某个控件失败，请向 Pilot 描述实际行为和预期结果，然后在修复后重复检查。这些检查验证的是本地预览行为；生产权限和提议的本体论定义仍需验证。

在分支上实现本体论

选择 部署 （位于 Pilot 右上角）。这将在预览左侧打开部署检查清单。下面的示例显示了一个已配置的应用程序；你的检查清单将反映你的进度。

自动预览行为 实现本体论实体，新定义可能显示为 未找到 on 点击单个编辑项，可并排查看。为它们创建一个部署分支：

  1. 选择 在分支菜单中输入新分支的名称，随后点击。Pilot 可能会在你首次进入时打开 创建部署分支 对话框，当你首次进入 部署.
  2. 输入分支名称，例如 Release checklist tutorial.
  3. 检查响应的 位置 and 应用程序实体。本示例提出了一个对象类型和三个操作类型。
  4. 表单准备就绪后，选择 在分支菜单中输入新分支的名称，随后点击.

等待实施和对象索引完成。在索引进行期间，操作可能失败，数据可能缺失。如果无法创建分支，请查看说明；必须启用全局分支（Global Branching）。

实施完成后，检查所选的 分支 在左侧以及 分支上的生产数据 在预览上方。

分支预览使用所选 Foundry 分支上的记录。本地种子任务是独立的，因此新的任务对象类型最初可能没有记录。

要验证应用程序，请添加一个发布任务，例如 Validate the deployment branch，重复完成、筛选、重新加载和删除检查，完成后删除测试任务。然后选择 查看分支 以打开全局分支（Global Branching）。

审查并合并本体论提案

在全局分支（Global Branching）中：

  1. 确认该分支包含任务对象类型和三个操作。
  2. 选择 创建提案 来运行评估套件。
  3. 为你的专业代码智能体输入 提案名称 and 提案描述，然后选择 创建.

等待任务对象类型完成索引，然后在合并前审查提案：

  1. 打开 更改 ，并确认该提案创建了预期的任务对象类型和操作，且未修改无关的定义。
  2. 返回到 概述 以检查资源检查和所需的审批。下面的示例显示了四个资源，其检查已通过且审批为自动；您的策略可能有所不同。
  3. 选择 合并提案，审查确认信息，然后确认 合并提案。等待提案显示为 已合并.

返回 Pilot 并选择 切换到 Main。确认 实现本体论实体 报告 所有实体在 Main 上均为最新.

在共享应用程序之前，请审查生成的操作的提交条件。默认条件仅允许使用 Pilot 创建该操作的用户提交它。请在 Ontology Manager 中配置预期的访问权限。

配置应用程序并运行检查

在部署清单中，打开 配置应用程序和子域名 并选择 配置应用程序.

  1. 为你的专业代码智能体输入 Developer Console 应用程序名称的源（例如 Release checklist tutorial.
  2. 选择 配置。该 子域名 字段在此选择后显示。
  3. 输入一个可用的子域名。等待可用性检查完成，然后选择 “创建应用程序”.

确认应用程序卡片出现并报告 应用程序范围已是最新。如果显示 域名等待审批，请联系您的注册管理员批准该请求，然后再托管网站。参见 批准子域名请求.

接下来，打开 通过所有 CI 检查.

  1. 选择 生成部署文件以启用检查 在出现提示时，或 更新文件 如果部署文件已过时。
  2. 等待 SUCCEEDED 在您打算发布的提交上。
  3. 如果检查失败，请打开其构建输出，让 Pilot 修复报告的问题，并等待更新后的提交通过检查。

发布并验证托管的应用程序

检查成功后，选择 标记并发布 在部署清单底部：

  1. 审查所选的分支或提交以及最新发布的标签。
  2. 选择 补丁（Patch）, 次要（Minor）, 主要（Major），或 您可以使用顶部导航栏中的时间范围选择器来配置指标显示的时间段。可用的预设选项包括一天、两天、七天、14 天和 30 天。您还可以选择.
  3. 检查 正在发布 在对话框底部，然后确认 标记并发布。本示例选择了补丁版本 0.0.2；您的版本号可能有所不同。

等待发布构建成功。创建标签并不会批准域名，也不会确认网站可用。

完成域名审批并按照 应用发布步骤操作。部署成功后打开托管应用，并针对一个合成测试任务重复七项任务检查。在对真实记录执行操作之前，请先验证数据源和您的权限。

复用现有任务模型

若要基于现有定义进行构建，请打开 Pilot 欢迎屏幕：

  1. 在您的终端会话中将 类型 to OSDK 应用 并选择您的主题、保存位置和本体论。
  2. 选择 Add context > Add object types，搜索您的任务对象类型并打开其详情。选择 选择，然后选择 确认选择.
  3. 选择 Add context > Add action types。按受影响的任务对象类型进行筛选，选择其添加、完成和删除操作，然后选择 确认选择.
  4. In 修改本体论权限，保持禁止创建和修改。
  5. 描述清单交互，并明确要求 Pilot 仅使用选定的现有定义。

在选择 “创建应用程序”之前，请检查提示下方的四个附件标签以及消息 Pilot 无法对本体论进行更改.

生成后，检查 本体论。此示例应显示 现有 4 和 建议 0，其中 不允许修改 位于对象类型和全部三个操作上。

重复种子数据检查。然后选择 生产数据，等待预览重新加载，并使用合成任务测试已部署的操作。重新加载后验证完成情况、筛选和持久性，然后删除测试任务。生产列表与种子记录是分开的。

选择 部署。如果现有定义未更改，请确认 所有实体在 Main 上均为最新。如果 创建部署分支 在这些定义已是最新时仍会打开，请选择 取消.
