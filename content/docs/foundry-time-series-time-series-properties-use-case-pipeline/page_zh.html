使用 Pipeline Builder 创建时间序列数据

您将使用本指南创建的管道将生成 时间序列数据 ，作为以下对象的支撑数据 时间序列同步 以关联 时间序列属性 ，该选项位于 Carrier, Route日 Airport 对象类型来创建新的 时间序列对象。此管道的设置比从时间序列数据集到时间序列属性的标准映射更为复杂，因为我们将对非时间序列数据进行计算以生成时间序列数据。请查阅我们的 Pipeline Builder 文档 以了解通用管道指南信息。

我们正在使用的航班数据集包含以下列，我们将使用这些列来创建时间序列属性：

  • flight_id: string | 用于标识航班以及数据集中每一行的唯一字符串。
  • date: date | 航班飞行的日期。
  • destination_airport_id: string | 用于标识目的地机场的字符串。
  • airline_id: string | 航空承运人的 ID。
  • origin_airport_id: string | 出发地机场的 ID。
  • dep_delay: integer | 出发延误的分钟数。
  • arr_delay: integer | 到达延误的分钟数。
  • route_id: string| 用于标识航线的唯一字符串。

第一部分：生成时间序列数据

使用与支撑以下对象相同的航班数据集 Flights 对象类型，我们可以执行一些聚合转换，并基于航班指标生成时间序列数据。如果您的时间序列数据来自历史记录系统或边缘传感器并已进入 Foundry，则此步骤不是必需的。您可以直接进入 生成时间序列同步.

1. 对以下对象应用转换 Carrier 和 Route 对象类型（object types）

从航班数据集中，使用以下步骤应用转换。您需要对以下两个 Carrier 和 Route 对象类型分别执行此操作。

聚合数据

使用聚合转换按日期和对象的 ID 进行分组（在本例中，使用 route_id 选项卡中为 Route 对象类型；您还需要单独使用 airline_id 选项卡中为 Carrier 对象类型执行相同操作），并计算平均到达延误、平均出发延误以及每日航班数量。

聚合后，数据集的预览应显示以下 schema：

转换为新的数据类型

要将这些新数据用作时间序列，我们必须创建一个时间戳类型的列。为此，请使用 cast 转换将 date 列转换为时间戳类型的列。我们还将很快应用 unpivot 转换来合并 daily_avg_dep_delay, daily_avg_arr_delay日 daily_count_of_flights 值到同一列中。由于此函数要求所有值具有相同的数据类型，我们还必须将每日航班数量指标转换为 double 类型（与平均延误指标相同的数据类型）。

Univot 以合并时间序列值

由于此数据集在不同列中包含时间序列数据，我们必须使用 unpivot 转换将其合并到一个值列中，以便数据能够符合时间序列同步所需的 schema，如下所示：

  • series ID: string | TSP 所引用的一组时间戳和值对的序列 ID，必须与 TSP 的序列 ID 匹配。
  • timestamp: timestamp or long | 度量该数量的时间。
  • value: integer, float, double, string | 在度量时该数量的值。字符串类型表示分类时间序列；每个分类时间序列最多可以有 10,000 个唯一变体。

第二部分：创建时间序列同步

1. 移除空值

在生成的数据集上应用筛选转换以移除任何 null 值。

2. 配置时间序列同步

现在，创建一个 时间序列同步 通过选择 将 从屏幕右侧的管道输出部分。然后，选择 时间序列同步。填写新时间序列同步的必要数据，并考虑以下事项：

  • 标题“[示例] 时间序列同步 | 事件”将对应于您 Palantir 文件系统文件夹中生成的资源。
  • 选择 series_id 列，用于 序列 ID field.
  • 添加已创建的 date 时间戳列到 时间 field.
  • 将 series_value 导出到 标题可将排序方式切换为 field.

现在， 保存并构建 管道。输出将在与管道相同的文件夹中创建。

3. 使用时间序列同步向对象类型添加属性

现在您已创建了一个包含时间序列同步的管道，可以使用该同步向 Route, Carrier 和 Airport 对象类型添加时间序列属性。请继续阅读我们的文档，了解 向对象类型添加时间序列属性 以获取更多指导。
