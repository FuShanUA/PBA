PostgreSQL

身份验证

Foundry PostgreSQL 连接器需要使用 用户名和密码 进行身份验证。我们建议使用服务凭证而非个人用户凭证。

用户名和密码身份验证可以与客户端和/或服务器证书以及需要验证这些证书的 SSL 模式结合使用。

您必须确保所提供的用户在目标数据库上拥有必要的权限，以及读取或写入目标表的权限。对于 （CDC）同步。Db2 CDC 同步是通过，用户可能还需要 CREATE 和 REPLICATION 对目标数据库的权限。

网络

PostgreSQL 连接器需要访问您希望连接的数据库实例的网络权限。PostgreSQL 连接通常使用主机名或 IP 在端口 5432 上进行连接。

如果您在运行到 PostgreSQL 的连接 在 Foundry 中，在 出站策略覆盖 中设置源时，必须添加相应的 Data Connection 应用程序.

对于可通过互联网访问的云端托管 PostgreSQL 实例（例如 Amazon Relational Database Service (RDS) 中的 PostgreSQL），如果您未使用主机名，则必须为数据库的主机名或 IP 地址添加出口策略。请查看您的托管云端 PostgreSQL 实例提供商的官方文档，以了解所需网络配置的更多详细信息。

您需要确保已允许来自 Foundry 的入站流量访问您的 PostgreSQL 实例。您可以在 选项卡,该选项卡位于 Control Panel 的 页面（位于 Control Panel 中）查看 Foundry 流量的出口 IP。请查看您的托管服务提供商的文档，了解如何允许来自这些 IP 的流量访问您的数据库实例。

Amazon RDS 中的 PostgreSQL

如果您连接的是 Amazon RDS 中托管的 PostgreSQL 托管实例，可以使用 直接连接 并配置必要的出口策略。

  • 要查找您在 Amazon RDS 中托管的 PostgreSQL 实例的主机名，请在 AWS 控制台中导航到您的实例。RDS PostgreSQL 的基于主机名的出口策略示例如下 <your-database-name>.<unique-identifier>.<region>.rds.amazonaws.com (port 5432)

连接到 RDS PostgreSQL 实例时，您可能需要在源配置面板中将 RDS 根证书颁发机构 (CA) 添加为服务器证书。请下载 rds-ca-2019-root.pem 来自 Amazon S3 站点 ↗，然后将证书详细信息复制到 Foundry 中，以信任与 Amazon RDS 的连接。有关使用 SSL/TLS 连接到 RDS 数据库实例的更多信息，请查看官方 AWS 文档 ↗.

连接详情

选项是否必填？描述
Host type是指定 Foundry 应如何连接到您的 PostgreSQL 数据库。

选项 1：主机名
提供主机名。这是所有 PostgreSQL 连接的推荐选项，并且在连接到云端托管的 PostgreSQL 实例时应始终使用。例如，托管在 Amazon RDS ↗.

选项 2：IPv4
提供 IPv4 地址。如果您通常使用 IPv4 地址进行连接（无论是在企业网络内还是通过互联网），都可以使用此选项。

选项 3：IPv6
提供 IPv6 地址。如果您通常使用 IPv6 地址进行连接，请使用此选项。
Port是指定连接时要使用的端口。大多数 PostgreSQL 实例的默认端口为 5432。有关端口的更多信息，请参阅 官方文档 ↗ 以及您的数据库实例的配置。
Database name是您在 PostgreSQL 实例中要连接的数据库的名称。
Authentication是使用以下内容进行配置 身份验证 上方显示的指南。
Network Connectivity是您必须提供出口策略以允许连接到您的 PostgreSQL 实例。请参阅 网络 参数
SSL Mode是默认为 verify-full。有关更多详细信息，请查阅 官方文档 ↗ 选项卡中为 ssl-mode PostgreSQL JDBC 驱动程序上的连接参数。

变更数据捕获 [Beta]

测试版

PostgreSQL 的变更数据捕获同步目前处于 测试版 开发阶段，在您的注册环境中可能无法使用。功能在积极开发过程中可能会发生变化。请联系 Palantir 支持团队以请求访问此功能。

PostgreSQL 数据源支持 （CDC）同步。Db2 CDC 同步是通过 （CDC）同步。

由于 PostgreSQL 支持逻辑复制，变更数据捕获可以近乎实时地将变更流式传输到已配置的表。根据 PostgreSQL 文档 ↗:

逻辑复制是一种基于复制标识（通常是主键）来复制数据对象及其变更的方法。

Foundry 从 PostgreSQL 进行的变更数据捕获同步通过使用现有的复制槽或在目标数据库上创建新的复制槽和发布来运作。每个数据连接源只能配置一个复制槽和发布，但可以通过单个连接将任意数量的表流式传输到 Foundry。如果您希望使用多个复制槽或发布，可以创建多个连接到您的数据库的数据连接源。

在设置变更数据捕获同步之前，请首先确保您有一个可用的 PostgreSQL 源连接和一个可用的探索运行时。如果运行时仍在初始化，您可能需要等待几秒钟并刷新页面。然后，导航到 CDC 同步 选项卡，并提供变更数据捕获所需的额外配置。

选项是否必填？描述
复制槽名称是用于 CDC 的复制槽的名称。如果该槽不存在，将会创建它。有关更多信息，请参阅官方 PostgreSQL 文档 ↗.
发布名称是用于 CDC 的发布的名称。有关更多信息，请参阅官方 PostgreSQL 文档 ↗.
自动创建发布是如果启用，将为所有选定的表自动创建发布。这要求用户具有以下权限： CREATE and REPLICATION 在数据库上，以及 SELECT 在表上。

配置好变更数据捕获所需的设置后，您可以导航到 概述 页面，或停留在 CDC 同步 页面并选择 + 创建 CDC 同步 以创建新的变更数据捕获同步。

有关在 PostgreSQL 中使用 CDC 的更多信息，请查阅 官方文档 ↗ 有关所使用 PostgreSQL 版本的逻辑复制的内容。

from transforms.api import transform_pandas, Output
from transforms.external.systems import external_systems, Source
import psycopg2
import pandas as pd


@external_systems(
    postgres_source=Source("<source_rid>")
)

@transform_pandas(Output("<output_dataset_rid>"))
def compute(postgres_source):

    conn = psycopg2.connect(
        host="host",            # Database host address
        port="5432",            # Database port
        database="postgres",    # Database name
        user="user",            # Database username
        password=postgres_source.get_secret("PASSWORD") # Database password
    )

    query = "SELECT * FROM plants;"

    return pd.read_sql_query(query, conn)

import logging
from transforms.api import lightweight, Output, transform_pandas, Input
from transforms.external.systems import external_systems, Source
import psycopg2
import pandas as pd

logger = logging.getLogger(__name__)

# Maps Foundry column names to PostgreSQL column names
COLUMN_MAPPING = {
    "plant_name": "name",
    "plant_height": "height_cm",
    "plant_color": "color",
}

CREATE_TABLE_SQL = """
    CREATE TABLE IF NOT EXISTS plants (
        name TEXT PRIMARY KEY,
        height_cm DOUBLE PRECISION,
        color TEXT
    )
"""


@lightweight
@external_systems(
    postgres_source=Source("<source_rid>")
)
@transform_pandas(
    Output("<output_dataset_rid>"),
    plants_df=Input("<input_dataset_rid>")
)
def compute(postgres_source, plants_df):
    conn = psycopg2.connect(
        host="<your_host>",
        port="5432",
        database="<your_database>",
        user="<your_user>",
        password=postgres_source.get_secret("PASSWORD"),
    )

    pg_columns = [COLUMN_MAPPING[c] for c in plants_df.columns]
    placeholders = ", ".join(["%s"] * len(pg_columns))
    columns_str = ", ".join(pg_columns)
    insert_sql = f"INSERT INTO plants ({columns_str}) VALUES ({placeholders})"

    try:
        with conn:
            with conn.cursor() as cursor:
                cursor.execute(CREATE_TABLE_SQL)
                for _, row in plants_df.iterrows():
                    cursor.execute(insert_sql, tuple(row))
    except Exception as e:
        logger.error(f"Error writing to PostgreSQL plants table: {e}")
        raise RuntimeError(f"Failed to write data to PostgreSQL: {e}") from e
    finally:
        conn.close()

    return pd.DataFrame({"rows_written": [len(plants_df)]})
