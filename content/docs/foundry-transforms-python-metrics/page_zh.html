指标

使用 指标 遥测标签页来调试和监控您的构建。

访问指标

按照以下步骤查看指标详情。请注意， 指标 标签页仅在作业已输出指标时才会显示。

  1. 查看构建报告：
    • 从 数据集预览 或 数据血缘中，选择 历史记录 标签页，从列表中选择一个构建，然后选择 查看构建报告。
    • 从 所有构建列表中选择一个构建。
  2. 选择一个作业： 构建由一个或多个作业组成，这些作业显示在甘特图下方的列表中。从列表中选择一个作业，选择 遥测 选项，然后选择 指标 标签页，即可查看构建容器输出的指标在时间序列图表上的绘制情况。

内存利用率

该 内存利用率 图显示了构建的内存使用情况。红色虚线表示构建所请求的内存限制。任何超过此限制的构建都会导致容器抛出内存不足（OOM）错误。

以下示例显示了一个已抛出 OOM 错误的构建，这意味着该构建受内存限制。内存使用量持续上升，最终导致 OOM。如果遇到 OOM 错误， 提高容器的内存限制 ，方法是将容器内存设置为 32 GB 或其他合适的值。

下面的示例展示了一个未充分利用所请求内存的构建。该构建远未达到内存限制，因此 将内存请求 设置为 32 GB 可减少此特定构建的资源消耗。

CPU 利用率

该 CPU 利用率 图表显示构建的 CPU 使用情况。橙色虚线表示构建所请求的 CPU。 默认请求两个核心。构建调度器将等待，直到能够在具有足够可用核心来满足您请求的主机上分配您的作业。主机上任何额外的未使用核心都将被自动调配，以帮助运行构建。

在上面的示例中，请求了两个 CPU，但实际使用了 22 个来帮助加快构建速度。请注意，无法保证主机在构建期间始终有额外的 CPU 可供分配。

请求结果
1 CPU core由于调度器能够更容易地找到空闲主机，构建将更快启动。构建时间可能会不一致，因为可用的 CPU 资源可能有所变化。
8 CPU cores构建启动平均耗时会更长，因为调度器可能难以找到有空闲核心的主机。由于构建期间将保证 8 核可用性，构建时间可能会更加一致。
