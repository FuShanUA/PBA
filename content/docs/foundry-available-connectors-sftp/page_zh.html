SFTP

将 Foundry 连接到 SFTP 服务器，以在文件夹和 Foundry 数据集之间同步数据。

受支持的功能

功能状态
探索🟢 正式可用
批量导入🟢 正式可用
增量🟢 正式可用
导出任务🟡 已弃用（仅限旧版 SFTP 源）
文件导出🟢 正式可用

数据模型

该连接器可以将任何类型的文件传输到 Foundry 数据集中。文件格式会被保留，在传输期间或之后不会应用任何 schema。请对输出数据集应用任何必要的 schema，或编写一个 下游转换 来访问数据。

性能与限制

可传输的文件大小没有限制。但是，网络问题可能导致大规模传输失败。特别是，运行时间超过两天的 Foundry 同步将被中断。为避免网络问题，我们建议使用较小的文件大小，并限制每次同步执行中摄取的文件数量。同步可以 被安排 频繁运行。

身份验证

可以使用密码或 SSL 私钥建立与 SFTP 服务器的连接。如果在连接服务器时遇到任何问题，请通过 Foundry 之外的 SFTP 客户端尝试连接，以验证身份验证详细信息是否正确。此连接的用户必须有权访问根目录，并具有读取和列出根目录内所有文件和目录的权限。

网络

如果您的 SFTP 连接 在 Foundry 中运行，则您必须添加 网络出口策略 以将该连接加入白名单。

应为 SFTP 服务器主机名（如果通过域名连接）以及该 SFTP 服务器主机名解析到的 IP 创建出站策略。正确配置出站策略后，非标准连接端口 (22) 仍可能因 主机名验证而无法使用。如果发生这种情况，请向 Palantir 支持团队报告问题，并附上应用于此连接的策略列表。

如果服务器域名解析到多个域名和/或服务器，则需要将所有相关域名及其关联的 IP 加入白名单。要验证服务器是否解析到多个域名和/或服务器，请运行命令 dig <domain> 在您的终端中针对要连接的服务器运行该命令，并查看应答部分。

在 UNIX 机器上，通过运行以下命令找到您的服务器域名解析到的 IP 地址：

此密钥必须在 主机密钥 部分（位于 连接详情 页面中进行配置。如果无法获取此密钥，或密钥频繁更改，可以使用 接受任何主机密钥 开关来禁用密钥验证，但禁用密钥验证是不安全的，不建议这样做。

主机名验证

Foundry 会对所有出站路由尝试主机名验证。端口 22 以外的网络流量有时不会被验证，导致连接挂起和/或超时错误。如果在正确配置出站策略后仍持续出现错误，请向 Palantir 支持团队报告问题，并附上您希望禁用主机名验证的策略列表。

故障排除

借用连接执行 ls 失败

如果构建失败并出现错误 Borrowing connection for ls failed，且错误中包含 SocketException: Connection reset，请检查构建日志以查看是否已建立与 SFTP 服务器的网络连接。如果日志中不包含以下行 Connection established 和 Remote version string，则可能是防火墙阻止了来自连接运行时的出站流量，或者目标 SFTP 服务器不允许传入连接。请检查出站策略和防火墙规则，并联系 SFTP 服务器管理员以解决网络连接问题。以下是成功连接日志的示例：

jschLogMessage: Connecting to <HOSTNAME> port 2232
jschLogMessage: Connection established
jschLogMessage: Remote version string: <value identifying the type of server>

连接挂起

如果连接挂起且没有任何进展或明显的失败，请将超时设置为一个较小的值（1000，例如）以帮助识别是哪个调用被挂起。例如，列出某个特定目录可能耗时较长，或者文件的某些部分读取时间过长。

连接挂起可能由于 主机名验证导致，设置较小的超时将允许生成失败日志，帮助支持团队识别连接问题的根本原因。

from transforms.api import Output, Input, TransformOutput, TransformInput, transform
from transforms.external.systems import external_systems, Source, ResolvedSource
import pandas as pd
import paramiko
import io

@external_systems(
    sftp_source=Source("<source_rid>")
)
@transform(
    output_file=Output(
        "<output_dataset_rid>"
    ),
    xlsx_files=Input("<input_dataset_rid>"),
)
def compute(
    sftp_source: ResolvedSource,
    output_file: TransformOutput,
    xlsx_files: TransformInput, # input dataset containing a list of xlsx files
) -> None:

    # 1. SFTP connection setup
    hostname = "<hostname>"
    port = <port> # (usually 22)
    username = "<username>"
    private_key_string = sftp_source.get_secret("privateKeyString")

    # 2. Transform private key string to proper input parameter of paramiko
    # Use StringIO to treat the string as a file-like object
    private_key_stream = io.StringIO(private_key_string)
    private_key = paramiko.Ed25519Key.from_private_key(private_key_stream)

    # 3. Define the SFTP client
    transport = paramiko.Transport((hostname, port))
    transport.connect(username=username, pkey=private_key)
    sftp = paramiko.SFTPClient.from_transport(transport)

    # 4. Iterate over input files and upload each to SFTP
    remote_paths = []
    fs = xlsx_files.filesystem()
    input_files = fs.ls()
    for f in input_files:
        with fs.open(f.path, "rb") as fileobj:  # Open in binary mode
            remote_path = get_remote_path(f.path)
            with sftp.file(remote_path, "wb") as remote_file:
                remote_file.write(fileobj.read())  # Write bytes directly
            remote_paths.append({"file_name": f.path, "remote_path": remote_path}) # record mapping of file name to uploaded path

    # 5. Return dataset of remote paths
    output_file.write_pandas(pd.DataFrame.from_records(remote_paths))


def get_remote_path(file_path):
    """
    Define the remote path where the file will be uploaded.
    """
    remote_target_folder = "<example_target_folder>"
    clean_file_path = file_path.replace(" ", "_")
    return f"{remote_target_folder}/{clean_file_path}"

旧版 SFTP 连接器

以下章节介绍旧版 SFTP 连接器，仅在维护该连接器的现有使用时应参考这些内容。任何新建 SFTP 源的操作都应遵循上述章节中描述的步骤。

迁移到新的 SFTP 连接器

从旧版 SFTP 连接器迁移到新连接器不是自动完成的，必须手动进行。新连接器支持几乎相同的配置选项，并且应创建新的源来替换旧源。

创建新源时，以下差异适用：

  • 无法从旧源中检索密码，如果您不再拥有密码的访问权限，必须向服务器管理员索取。
  • privateKeyFile and privateKeyPassphrase 不再受支持，如果使用私钥认证，应直接在源设置中输入私钥的内容。
  • knownHostsFile 不再受支持，并且 base64HostKey 必须在源设置中正确配置。

设置旧版 SFTP 连接器

要设置旧版 SFTP 连接器，请导航到 Data Connection 应用程序，然后选择 + New source。在源选择界面上，向下滚动到 高级，然后选择 自定义源。按照配置界面中的提示继续设置您的 SFTP 连接器。

使用旧版 SFTP 连接器导出

我们通常不建议使用 导出任务 将数据写回外部源，以下文档仅用于支持现有的旧版导出任务。任何新的导出必须使用更新后的、一等公民的 SFTP 连接器.

要导出数据，您必须配置一个 导出任务。导航到包含您要导出到的连接器的项目文件夹。右键单击连接器名称，然后选择 创建数据连接任务.

在数据连接视图的左侧面板中：

  1. 验证 Source 名称与您要使用的连接器相匹配。
  2. 添加一个 Input named inputDataset。该 输入数据集 是被导出的 Foundry 数据集。
  3. 添加一个 Output named outputDataset。该 输出数据集 用于运行、调度和监控任务。
  4. 最后，在文本字段中添加一个 YAML 块来定义任务配置。

左侧面板中显示的连接器和输入数据集的标签不会反映 YAML 中定义的名称。

创建导出任务 YAML 时使用以下选项：

选项是否必填？描述
directoryPath是文件将写入的目录。路径必须以尾部 /.
excludePathsNo正则表达式列表；名称与这些表达式匹配的文件将不会被导出。
rewritePathsNo请参阅 章节 的文档以获取更多信息。
uploadConfirmationNo当值为 exportedFiles时，输出数据集将包含已导出文件的列表。
createTransactionFoldersNo启用后，数据将写入指定 directoryPath内的子文件夹中。每个子文件夹对于 Foundry 中的每个导出事务都有一个唯一名称，并基于该事务在 Foundry 中提交的时间。
incrementalTypeNo对于增量构建的数据集，设置为 incremental 以仅导出自上次导出以来发生的事务。

rewritePaths

如果第一个键与文件名匹配，键中的捕获组将被替换为该值。该值本身可以包含额外的部分，用于向文件名添加元数据。

如果值包含：

  • ${dt:javaDateExpression}：值的这部分将被替换为导出文件时的时间戳。 javaDateExpression 遵循 DateTimeFormatter ↗ pattern.
  • ${transaction}：值的这部分将被替换为包含此文件的事务的 Foundry 事务 ID。
  • ${dataset}：值的这部分将被替换为包含此文件的数据集的 Foundry 数据集 ID。

示例：

考虑 Foundry 数据集中名为 "spark/file_name" 的文件，其所在事务的 ID 为 transaction_id 以及数据集 ID dataset_id。如果您使用表达式 fi.*ame 作为键，并将 file_${dt:DD-MM-YYYY}-${transaction}-${dataset}_end 作为值，则当该文件写入 SFTP 时，它将被存储为 spark/file_79-03-2023-transaction_id-dataset_id_end.

标志文件

当给定构建的所有数据复制完成后，连接器可以向 SFTP 服务器写入一个空的标志文件。该空文件表示内容已准备好供使用，并且不会再被修改。标志文件将被写入 directoryPath。但是，如果启用了 createTransactionFolders ，则会为写入内容的每个文件夹创建一个标志文件。如果启用了标志文件，且标志文件名为 confirmation.txt，则所有标志文件将在构建中正在导出的文件写入完成后一次性写入。标志文件在构建结束时写入，而不是在子文件夹导出完成时写入。

如果 SFTP 服务器中的文件比标志文件更新，这通常表示上一次导出未成功，或者该文件夹的导出正在进行中。

扩展协商

SFTP 协议允许客户端在客户端和服务器均支持的情况下使用该协议的高级功能。对于大多数行业标准 SFTP 实现，我们建议保持启用扩展。但是，如果存在兼容性问题，扩展可能会导致连接失败。Foundry SFTP 连接器允许根据需要禁用扩展。一般来说，最佳实践是仅禁用必要的扩展，而不是禁用所有扩展。
