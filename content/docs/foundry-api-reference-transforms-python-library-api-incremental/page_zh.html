transforms.api.incremental

transforms.api.incremental(require_incremental=False, semantic_version=1, snapshot_inputs=None, allow_retention=False, allow_user_deletes=False, strict_append=False, v2_semantics=False)

一个装饰器，用于将输入和输出转换为其 transforms.api.incremental 对应物。

该 incremental 装饰器必须用于包装 Transform 或 ContainerTransform：

>>> @incremental()
... @transform.using(...)
... def my_compute_function(...):
...     pass

如果使用 Spark：

>>> @incremental()
... @transform(...)
... def my_compute_function(...):
...     pass

该装饰器会从输出数据集读取构建历史，以确定上次构建时输入的状态。此信息用于将 TransformInput、 TransformOutput和 TransformContext 对象转换为其增量对应物： IncrementalTransformInput、 IncrementalTransformOutput和 IncrementalTransformContext。

此装饰器还可用于包装 transform_df() 和 transform_pandas() 装饰器。这些装饰器会对输入调用 dataframe() 和 pandas() （不带任何参数），以提取 PySpark 和 pandas DataFrame 对象。这意味着所使用的读取模式将始终为 added ，而写入模式将由 incremental 装饰器确定。如需读取或写入任何非默认模式，必须使用 transform() 装饰器。

如果您的转换执行涉及连接、聚合、去重等操作的复杂逻辑，则建议您先阅读 增量文档 ↗ ，然后再使用此装饰器。

如果您的 PySpark 或 pandas 转换中新增的输出行仅取决于新增的输入行，如以下 append ↗ 示例所示，则默认模式将生成正确的增量转换。

如果您的转换接收的输入数据集具有 SNAPSHOT 事务，但不会改变增量运行转换的能力（例如参考表），请查看 snapshot_inputs 参数。此参数有助于避免需要将转换作为完整快照运行 SNAPSHOT。

  • 参数：

    • require_incremental (bool ↗ , 可选) – 如果 True，则转换将拒绝以非增量方式运行，除非该转换从未运行过。这是根据所有输出数据集均没有已提交的事务来确定的。

    • semantic_version (int ↗ , 可选) – 默认值为 1。此数字表示转换的语义性质。每当转换逻辑的更改会使现有输出失效时，都应更改此数字。更改此数字将导致转换的后续运行以非增量方式执行。

    • snapshot_inputs (list ↗ of str ↗ , 可选) – 需要为其创建快照的输入 SNAPSHOT 事务不会使转换的当前输出失效。例如，更新查找表并不意味着先前计算的输出不正确。当除这些输入以外的所有输入只有新增数据或没有新数据时，转换将以增量方式运行。读取快照输入时， transforms.api.IncrementalTransformInput 将仅公开输入数据集的当前视图。

    • allow_retention (bool ↗ , optional) – 如果 True，foundry-retention 所做的删除将不会破坏增量性。

    • allow_user_deletes (bool ↗ , optional) – 如果 True，非 foundry-retention 所做的删除将不会破坏增量性。此参数需要 v2_semantics=True ，且在轻量级转换中不受支持。

    • strict_append (bool ↗ , optional) – 如果 True 且转换以增量方式运行，则底层的 Foundry 事务类型将为 APPEND。如果 True 且转换未以增量方式运行，则需要将 require_incremental 设为 True 以强制执行增量 APPEND 事务。请注意，写入操作不得覆盖任何文件，即使是辅助文件（例如 Parquet 摘要元数据或 Hadoop SUCCESS 文件）也不例外。所有 Foundry 格式的增量写入都应支持此模式。

    • v2_semantics (bool ↗) – 默认为 False。如果 True，将使用 v2 增量语义。v2 与 v1 增量语义在行为上应无差异，我们建议所有用户将其设置为 True。非 Catalog 增量输入和输出，包括 媒体集，仅在使用 v2 语义时才受支持。

当 v2_semantics 设置为 True时，您可以为增量输入配置事务限制，以限制每个作业中读取的数据量。这在处理具有大量累积事务的输入时非常有用。详情请参阅 限制增量输入的批量大小 以了解配置 transaction_limit 参数的详细信息，该参数适用于 Input()。

  • 抛出：
    • TransformTypeError – 如果被包装的对象不是 Transform 对象。
    • TransformKeyError – 如果快照输入在 Transform 对象上不存在。
