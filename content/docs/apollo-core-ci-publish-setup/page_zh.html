从您的 CI 管道将产品发布到 Apollo

获得 Apollo Hub 的访问权限后，下一步是开始将您的服务发布为 产品 ，随后由 Apollo 进行部署。

将产品发布到 Apollo 旨在通过一条简单的命令来完成，您可以将该命令添加到您的持续集成（CI）解决方案中。

本指南将逐步讲解如何从 CI 管道向 Apollo 发布，以便每次向您的服务提交新更改时，都将新的产品发布添加到 产品目录 中。

先决条件

访问令牌

您需要 Bearer Token 或客户端 ID 和客户端密钥，才能在 CI 管道中运行 Apollo CLI 命令。

如果您使用的是 Bearer Token，则应将该令牌作为名为 APOLLO_TOKEN 的密钥添加到您的 CI 管道中，以便在 CI 脚本中可以使用该值。

了解有关为 Apollo CLI 配置身份验证的更多信息。

使 apollo-cli 在您的 CI 管道中可访问

因为您将使用 apollo-cli发布到 Apollo，所以您需要确保在用于发布产品的 CI 步骤中已安装 CLI。CLI 是一款通用工具，可用于列出产品版本、创建构建产物以及将产品发布到 Apollo。

您可以通过以下四种方式确保在运行 CI 作业时 CLI 已下载且可访问：

  • [推荐] 在 CI 作业期间使用以下命令直接从您的 Hub 下载 CLI。如果您使用服务用户而不是 Bearer Token 进行身份验证，则需要执行一个额外的步骤。
使用服务用户时的额外步骤 使用服务用户进行身份验证时，您必须运行以下命令来获取 Bearer Token。请在 client_id 和 client_secret 字段中输入您的服务用户凭据。此命令会将 Bearer Token 保存到变量中，变量名为 APOLLO_TOKEN 以便在运行后续命令下载 Apollo CLI 时对其进行引用。 
Copied!
1APOLLO_TOKEN=$(
2    curl -v -s "https://<Hub>.palantircloud.com/multipass/api/oauth2/token" \
3    -H 'content-type: application/x-www-form-urlencoded' \
4    --data-urlencode "grant_type=client_credentials" \
5    --data-urlencode "client_id=$CLIENT_ID" \
6    --data-urlencode "client_secret=$CLIENT_SECRET" \
7    | grep -o '"access_token":\s*"[^"]*"' \
8    | sed -E 's/"access_token":\s*"([^"]*)"/\1/' \
9)
Copied!
1curl -o apollo-cli -H "authorization: Bearer $APOLLO_TOKEN" "https://<Hub>.palantircloud.com/assets/dyn/apollo-cli/bin/<os_distribution>/apollo-cli"
  • 下载 apollo-cli 二进制文件(来自您的 Hub),并将其托管在 CI 虚拟机可访问的位置。
  • 将 CLI 二进制文件直接提交到您的代码仓库。
  • 构建包含 CLI 的 Docker 镜像,以便在 CI 步骤中使用。

发布时使用 apollo-cli

使用 apollo-cli product-release create 命令从 CI 管道发布到 Apollo。发布任何产品类型时,必须提供以下标志:

  • --apollo-url: 您的 Apollo Hub 实例的 URL。
  • --apollo-token: 您在上一步中创建的必备 Bearer Token。如果您使用的是服务账户，请勿包含此参数。
  • --apollo-client-id: 服务账户的客户端 ID。如果您使用的是 Bearer Token，请勿包含此参数。
  • --apollo-client-secret: 服务账户的客户端服务。如果您使用的是 Bearer Token，请勿包含此参数。
  • --maven-coordinate: 指代产品特定版本的唯一标识符。Maven 坐标的格式为 groupID:artifactID:version。

发布 Helm chart 时，您必须使用 --helm-repository-url 标志指定托管您的 chart 的制品仓库。该仓库可以是您 Hub 中的制品存储，也可以是单独的外部存储，例如现有的 Artifactory 或 Harbor 实例。您还需要设置 -—maven-coordinate，即您要发布的 Release 的唯一标识符。请参阅 Product Releases 文档 以了解标识符格式的更多信息。

下面是一个示例 apollo-cli 命令，该命令使用已推送到您 Hub 制品仓库的 Bearer Token 来发布 Helm chart 的新 Release：

Copied!
1./apollo-cli product-release helm-chart init --apollo-url https://<Hub>.palantircloud.com --apollo-token $APOLLO_TOKEN --maven-coordinate "com.palantir:apollo-demo-app:${RELEASE_VERSION}" --name oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --version ${RELEASE_VERSION} --repository-url oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --username $HUB_ARTIFACT_STORE_USER --password $HUB_ARTIFACT_STORE_PASS --output-dir "./chart"
2
3./apollo-cli product-release create --manifest "./chart/manifest.yml"

下面是一个示例 apollo-cli 命令，该命令使用已推送到您 Hub 制品仓库的服务账户来发布 Helm chart 的新 Release：

Copied!
1./apollo-cli product-release helm-chart init --apollo-url https://<Hub>.palantircloud.com --apollo-client-id $CLIENT_ID --apollo-client-secret $CLIENT_SECRET --maven-coordinate "com.palantir:apollo-demo-app:${RELEASE_VERSION}" --name oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --version ${RELEASE_VERSION} --repository-url=oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --username $HUB_ARTIFACT_STORE_USER --password $HUB_ARTIFACT_STORE_PASS --output-dir "./chart"
2
3./apollo-cli product-release create --manifest "./chart/manifest.yml"

针对现有 CI 管道的示例发布步骤

以下是一个 GitLab CI 阶段的最小示例，该阶段将发布托管在您 Hub 的制品存储库中的 Helm chart。在此 CI 文件中查看上述命令。下面的完整示例展示了如何将 Helm chart 推送到 Hub 的制品存储库。

Copied!
1publish_helm_chart_apollo:
2  stage: publish_helm_chart_apollo
3  image: alpine/helm:3.10.2
4  dependencies:
5    - build_and_push_helm_chart
6  before_script:
7    - apt-get update -qq && apt-get install curl git unzip -y
8    - 'curl -o apollo-cli -H "authorization: Bearer $APOLLO_TOKEN" "https://<Hub>.palantircloud.com/assets/dyn/apollo-cli/bin/linux-amd64/apollo-cli"'
9    - chmod 700 apollo-cli
10    - export RELEASE_VERSION=$(git describe --tags)
11  script:
12    - ./apollo-cli product-release helm-chart init --apollo-url https://<Hub>.palantircloud.com --apollo-token $APOLLO_TOKEN --maven-coordinate "com.palantir:apollo-demo-app:${RELEASE_VERSION}" --name oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --version=${RELEASE_VERSION} --repository-url oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --username=$HUB_ARTIFACT_STORE_USER --password=$HUB_ARTIFACT_STORE_PASS --output-dir "./chart"
13    - ./apollo-cli product-release create --manifest "./chart/manifest.yml"
14  only:
15    - tags
16  except:
17    - branches

dependencies 代码块允许您复用在 build_and_push_helm_chart 阶段中打包的 Helm chart。

在此示例中，已发布的 Apollo Release 版本将为 RELEASE_VERSION，该版本将匹配 refs/tag 中为当前提交找到的标签。如果为该提交创建了 SemVer 格式的 git 标签(例如 2.0.0),那么 RELEASE_VERSION 将为该版本号。

该 only 和 except 键在本示例中将该阶段配置为仅在与新 git 标签对应的构建上运行。您可以移除这些键，以便在配置了 CI 管道运行的 git 分支上，每次提交时都运行发布步骤。

在 CI 管道中运行上述步骤后，您将能够在相应产品的主页上查看您的发布版本。您可以通过选择 产品 （位于 Apollo 的左侧菜单面板中）导航到产品目录来找到相应产品。

用于产品发布的完整 GitLab CI 脚本

Copied!
1# .gitlab-ci.yml
2stages:
3  - build_and_push_container
4  - build_and_push_helm_chart
5  - publish_helm_chart_apollo
6
7build_and_push_container:
8  stage: build_and_push_container
9  image: docker:22.06.0-beta.0-git
10  variables:
11    DOCKER_HOST: tcp://docker:2376
12    DOCKER_TLS_CERTDIR: "/certs"
13    DOCKER_TLS_VERIFY: 1
14    DOCKER_CERT_PATH: "$DOCKER_TLS_CERTDIR/client"
15  services:
16    - docker:22.06.0-beta.0-dind
17  before_script:
18    - sleep 5
19    - docker login -u $HUB_ARTIFACT_STORE_USER -p $HUB_ARTIFACT_STORE_PASS containers-<Hub>.palantircloud.com
20    - export RELEASE_VERSION=$(git describe --tags)
21  script:
22     - docker build -t apollo-demo-app:$RELEASE_VERSION .
23     - docker tag apollo-demo-app:$RELEASE_VERSION containers-<Hub>.palantircloud.com/apollo-demo-app:$RELEASE_VERSION
24     - docker push containers-<Hub>.palantircloud.com/apollo-demo-app:$RELEASE_VERSION
25  only:
26    - tags
27  except:
28    - branches
29
30build_and_push_helm_chart:
31  stage: build_and_push_helm_chart
32  image: alpine/helm:3.10.2
33  artifacts:
34    untracked: true
35  before_script:
36    - export RELEASE_VERSION=$(git describe --tags)
37  script:
38    - cd helm-chart
39    - 'sed -i "s/version:.*/version: \"${RELEASE_VERSION}\"/g" Chart.yaml'
40    - 'sed -i "s/appVersion:.*/appVersion: \"${RELEASE_VERSION}\"/g" Chart.yaml'
41    - 'sed -i "s/imageVersion:.*/imageVersion: \"${RELEASE_VERSION}\"/g" values.yaml'
42    - helm package .
43    - helm registry login -u $HUB_ARTIFACT_STORE_USER -p $HUB_ARTIFACT_STORE_PASS containers-<Hub>.palantircloud.com
44    - helm push apollo-demo-chart-${RELEASE_VERSION}.tgz oci://containers-<Hub>.palantircloud.com/
45  only:
46    - tags
47  except:
48    - branches
49
50publish_helm_chart_apollo:
51  stage: publish_helm_chart_apollo
52  image: alpine/helm:3.10.2
53  dependencies:
54    - build_and_push_helm_chart
55  before_script:
56    - apt-get update -qq && apt-get install curl git unzip -y
57    - 'curl -o apollo-cli -H "authorization: Bearer $APOLLO_TOKEN" "https://<Hub>.palantircloud.com/assets/dyn/apollo-cli/bin/linux-amd64/apollo-cli"'
58    - chmod 700 apollo-cli
59    - export RELEASE_VERSION=$(git describe --tags)
60  script:
61    - ./apollo-cli product-release helm-chart init --apollo-url https://<Hub>.palantircloud.com --apollo-token $APOLLO_TOKEN --maven-coordinate "com.palantir:apollo-demo-app:${RELEASE_VERSION}" --name oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --version=${RELEASE_VERSION} --repository-url oci://containers-<Hub>.palantircloud.com/apollo-demo-chart --username=$HUB_ARTIFACT_STORE_USER --password=$HUB_ARTIFACT_STORE_PASS --output-dir "./chart"
62    - ./apollo-cli product-release create --manifest "./chart/manifest.yml"
63  only:
64    - tags
65  except:
66    - branches
