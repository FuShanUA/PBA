存活性和就绪性 [Beta]

本规范的这一扩展定义了服务副本的存活性和就绪性，以及服务应如何传达这两者。

存活性

存活性是服务副本进程状态的指标。 它用于指示进程是否已进入无响应状态并需要重启。 产品必须包含符合以下要求的存活性 HTTPS 端点：

  • 暴露一个无需身份验证的 HTTPS GET 端点。
  • 可通过相对于服务配置的 sls-status 端点的路径 /status/liveness 进行访问
  • [200, 399] 之间的任何响应代码均表示该副本处于存活状态，无需重启。 按照惯例，应使用 200 OK。
  • 响应代码 < 200 和 >= 400 表示应重启该副本。
  • 该端点可每 5 秒被调用一次，而不会影响性能。 预期产品会缓存资源密集型的存活性检查，以避免对性能产生负面影响。
  • 响应正文必须为空。

就绪

就绪状态是服务副本响应网络请求能力的指标，会影响该副本是否应接受发往其服务的流量。 产品必须包含符合以下要求的就绪 HTTPS 端点：

  • 公开一个无需身份验证的 HTTPS GET 端点。
  • 该端点应可通过相对于服务所配置的 sls-status 端点的 /status/readiness 路径进行访问。
  • 任何介于 [200, 399] 之间的响应代码都表示节点已准备好接收请求。 按照惯例，应使用 200 OK。
  • 响应代码 < 200 或 >= 400 表示副本不应接收请求。
  • 传输错误表示节点不应接收请求。
  • 该端点可以每 5 秒调用一次，而不会影响性能。 资源密集型的就绪检查应由产品进行缓存，以避免对性能产生负面影响。
  • 产品的就绪状态是服务副本的本地关注点，不应受其依赖服务的就绪或存活检查的影响。
  • 响应体必须为空。

如果副本指示其尚未就绪，则不会有任何网络流量路由到它。若要接收网络流量，可以：

  1. 节点必须在能够响应请求时立即指示其已就绪，即使结果主要是 4xx 和 5xx 响应。这样可以确保错误页面能够被访问，并且可以检索其他调试信息。或者
  2. 服务必须在其清单中声明 allow-traffic-when-not-ready 扩展（参见以下示例）。在这种情况下，Kubernetes 流量路由将忽略就绪状态，即使 pod 不可用，节点端点也将可路由。
