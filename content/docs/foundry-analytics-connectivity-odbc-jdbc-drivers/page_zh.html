适用于 Foundry 数据集的 ODBC 和 JDBC 驱动程序

适用于 Foundry 数据集的 ODBC 和 JDBC 驱动程序提供了一个基于 SQL 的只读接口，用于从客户端应用程序（如 BI 工具和 ETL 工具）访问数据集。用户可以在 Foundry 中浏览项目和数据集，并执行 SQL 查询以访问表格数据。这些驱动程序利用 此处描述的角色属于 在服务器端处理和执行 SQL 查询。

选择 JDBC 还是 ODBC？

在客户端应用程序同时支持两种协议的情况下，我们建议使用 JDBC 而非 ODBC。JDBC 驱动程序更易于安装和配置，并且数据加载性能更佳。

此处描述的角色属于

这些驱动程序依赖 Foundry SQL Server 来处理和执行针对 Foundry 数据集的 SQL 查询。请查阅 Foundry SQL Server 架构 文档，以了解更多关于架构以及如何提升查询性能的信息。

第 2 部分：配置数据源名称（DSN）配置

要在客户端应用程序中使用该驱动程序，请先为您的 Foundry 环境配置数据源名称（DSN）配置：

  1. 在 开始时间 菜单中，搜索 ODBC 并打开 ODBC 数据源 工具。请选择 64 位版本。
  2. 在 用户 DSN or 系统 DSN 选项卡上，点击 添加... .
  3. 选择 FoundrySqlDriver 从驱动程序列表中选择。
  4. 输入以下必需参数：
    1. 数据源名称： 您机器上该数据源的名称。

使用指南

使用 SQL 查询 Foundry 数据集

可以在 SQL 查询中通过路径或 RID 引用数据集。SQL 语法取决于为连接设置的方言（参见 配置参数).

SPARK 方言

-- Basic SELECT
SELECT * FROM `/Path/To/Dataset`

-- Filtering with a WHERE clause
SELECT * FROM `/Path/To/Dataset`
WHERE years < 13 AND category = 'Z';

-- Using JOIN
SELECT *
FROM `/Path/To/Dataset_A` a
JOIN `/Path/To/Dataset_B` b
    ON a.id = b.fk_id;

ODBC 和 ANSI 方言

-- Basic SELECT
SELECT * FROM "/Path/To/Dataset";

-- Filtering with a WHERE clause
SELECT * FROM "/Path/To/Dataset"
WHERE years < 13 AND category = 'Z';

-- Using JOIN
SELECT *
FROM "/Path/To/Dataset_A" a
JOIN "/Path/To/Dataset_B" b
    ON a.id = b.fk_id;

请参阅 指南：识别数据集的 RID 或文件路径 以获取有关使用数据集标识符的更多说明。

使用 OAuth 进行身份验证

无需手动生成绑定到单个 Foundry 账户的身份验证令牌，ODBC 和 JDBC 驱动程序支持 OAuth 2.0 流程以提供更多身份验证选项：

  • 个人用户: 驱动程序会在您的浏览器中打开登录提示，供您向 Foundry 进行身份验证。
  • 服务用户：驱动程序以在 Foundry 中注册的第三方应用程序所附加的服务用户身份连接到 Foundry。
  • 外部应用程序（面向开发者）：第三方应用程序与 Foundry 的 OAuth 系统集成，代表其用户获取令牌。

在可能的情况下，我们建议使用这些基于 OAuth 的选项而非令牌生成，因为它们更安全，并且允许共享使用嵌入式连接字符串，而无需共享单个用户的令牌。

个人用户（仅限 Windows 上的 ODBC）

ODBC 驱动程序在 Windows 上运行时支持自动 OAuth 登录和授权流程。此流程仅支持安装在您计算机上的桌面应用程序，不支持通过网页浏览器访问的应用程序。

按照以下步骤设置此流程：

  1. （由 Foundry 管理员完成） 注册一个 第三方应用程序 在 Foundry 中，指定以下配置选项：
    1. 客户端类型： 公共客户端 在大多数情况下是推荐的； 机密客户端 如果您的用例需要，也受支持。
    2. 授权授予类型： 启用 授权码模式 并将重定向 URL 设置为 http://127.0.0.1/foundrydriver/oauthredirect.
    3. 确保应用程序已 注册 and 已启用.
    4. 复制应用程序的 客户端 ID （从应用程序详情页面），并与任何在其计算机上设置 ODBC 连接的用户共享。
  2. 收到 客户端 ID 后，从您的 Foundry 管理员处设置以下 ODBC 连接参数：
    1. AuthMethod = OauthFlow
    2. OauthClientId = <YOUR_CLIENT_ID>
      或者， 客户端 ID 可以设置在应用程序的用户名字段中，而不是 OauthClientId，以便在应用程序内配置凭据。 AuthMethod 仍必须设置。
  3. （可选）如果您在 Windows ODBC 管理器应用程序中配置这些设置，可以选择 测试 选项来触发登录提示并验证登录是否正常工作。

下次您在客户端应用程序中使用该驱动程序时，系统会提示您在浏览器中登录 Foundry。此后，您无需在每次使用驱动程序时都登录，但偶尔可能会再次提示您登录。

服务用户

对于不与单个用户关联的工作流（例如按计划刷新仪表板的数据），我们建议使用基于 OAuth 的服务用户，并利用 第三方应用程序 以及 OAuth 客户端凭据（Client Credentials）授权类型。驱动程序使用长期有效的客户端 ID/密钥对向 Foundry 进行身份验证，这比使用生成令牌的手动创建服务账户更易于管理。

请按照以下步骤为服务用户设置 OAuth：

  1. （由 Foundry 管理员完成。） 注册一个 第三方应用程序 在 Foundry 中：
    1. 客户端类型： 选择 机密客户端.
    2. 授权授予类型： 启用 客户端凭据授权（Client credentials grant）， 并务必将 客户端 ID and 客户端密钥（Client Secret） 对存储在安全的位置。
    3. 确保应用程序已 注册 and 已启用.
    4. 确保生成的服务用户已被授予对将通过 ODBC 或 JDBC 驱动程序访问的所有数据集的访问权限。为应用程序生成的服务用户列在 客户端凭据授权（Client credentials grant） 详细信息面板中。
  2. 配置驱动程序时，请设置以下配置参数：
    1. AuthMethod = ClientCredentials
    2. OauthClientId = <YOUR_CLIENT_ID>
    3. OauthClientSecret = <YOUR_CLIENT_SECRET>
      或者， 客户端 ID and 客户端密钥（Client Secret） 可以设置在应用程序的用户名和密码字段中，而不是 OauthClientId and OauthClientSecret，以便在应用程序内配置凭据。 AuthMethod 仍必须设置。

驱动程序现在将以 OAuth 应用程序的服务用户身份连接到 Foundry。

外部应用程序（面向开发者）

应用程序开发人员可以将 ODBC 和 JDBC 驱动程序集成到运行其自身 OAuth 客户端的应用程序中，以管理与第三方应用程序的 OAuth 登录流程。此选项允许完全控制登录流程，包括将用户重定向到 Foundry 进行身份验证，以及在用户完成身份验证和授权后处理授权响应。请参阅 为 Foundry 编写 OAuth2 客户端 文档，以代表 Foundry 用户获取访问令牌。

一旦您的应用程序代表用户获取了访问令牌，即可通过标准的密码属性将其传递给驱动程序：

  • ODBC Pwd / JDBC Password = <ACCESS_TOKEN_OBTAINED_FROM_TOKEN_ENDPOINT>

在 ODBC 驱动程序中启用日志记录

如果您需要启用驱动程序日志记录来排查问题，请按照以下步骤操作，这些步骤可能需要管理员权限。

  1. 创建一个用于保存日志的文件夹，例如 My Documents\Foundry Driver logs.
  2. 打开 Windows ODBC 数据源 工具。您可以在 Windows 搜索栏中搜索“ODBC”找到它。请选择 64 位版本。
  3. 打开 系统 DSN 选项卡。选择 FoundrySql 数据源，然后选择 组织。选择哪个 Foundry 数据源并不重要，因为日志记录设置将应用于所有使用 Foundry 驱动程序的数据源。
  4. 选择 日志记录选项（Logging Options） 在配置窗口中。
  5. 将日志级别设置为 DEBUG。将日志路径设置为您之前创建的文件夹。
  6. 选择 OK 以保存设置。

重新启动客户端应用程序并执行您要排查的操作。日志应显示在您选择的文件夹中。如果您需要 Palantir 或其他支持团队的支持，可以将此文件夹压缩为 zip 文件以进行共享。

排查完成后，返回 ODBC 数据源 工具，并通过将日志级别设置为 OFF来禁用日志记录。建议执行此步骤以提高性能。

在 JDBC 驱动程序中启用日志记录

JDBC 驱动程序会发现您的 Java 应用程序在类路径上提供的任何 SLF4J 日志记录器。具体而言，您的应用程序应提供以下类的实现 org.slf4j.impl.StaticLoggerBinder 和 org.slf4j.impl.StaticMDCBinder。您可以通过添加 slf4j-simple （1.X 版本）作为项目依赖项来使用默认实现。

如果您尚未配置 SLF4J 日志记录器，则在首次加载驱动程序时会看到以下消息：

SLF4J: Failed to load class "org.slf4j.impl.StaticLoggerBinder".
SLF4J: Defaulting to no-operation (NOP) logger implementation
SLF4J: See http://www.slf4j.org/codes.html#StaticLoggerBinder for further details.
SLF4J: Failed to load class "org.slf4j.impl.StaticMDCBinder".
SLF4J: Defaulting to no-operation MDCAdapter implementation.
SLF4J: See http://www.slf4j.org/codes.html#no_static_mdc_binder for further details.

使用配置文件配置 JDBC 驱动程序 foundry.ini 配置文件

除了使用连接字符串之外，还可以通过配置文件来配置 JDBC 驱动程序。为此，请创建一个名为 foundry.ini 的文件，放在与 JDBC .jar 文件相同的目录中。

.ini 文件分为两个部分： low-priority 和 high-priority。在 low-priority 部分中指定的属性优先级低于连接字符串属性。这意味着，如果在 low-priority 部分和连接字符串中指定了相同的属性，则将使用连接字符串中的值。相反，在 high-priority 部分中指定的属性将优先于连接属性。这在报表从开发机器发布到服务器，且服务器属性需要优先于开发属性的情况下非常有用。

示例 foundry.ini 文件：

[high-priority]
proxyHost=myproxy.abc
proxyPort=1234

[low-priority]
branch=production-branch

在 Java 16 及以上版本中使用 JDBC 驱动程序

默认情况下，JDBC 驱动程序支持的最高 Java 版本为 Java 15。要在 Java 16 及以上版本中使用该驱动程序，请将 --add-opens Java 运行时选项设置为 java.base/java.nio=org.apache.arrow.memory.core,ALL-UNNAMED.
