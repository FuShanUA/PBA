API：对象集

本页面介绍 TypeScript v1 (TSv1)。TypeScript v2 (TSv2) 和 Python 通过 Ontology SDK 查询本体论（Ontology）：请参阅 TypeScript 和 或 OSDK 参考文档。 迁移指南 将每个 TSv1 操作符映射到其对应的 TSv2 形式。

An 对象集 表示单一类型对象的无序集合。您可以使用函数 API 来筛选对象集、基于已定义的关联类型对其他对象类型执行 Search Around，以及计算聚合值或检索具体对象。除了将单个对象作为输入传递给函数之外，您还可以随时使用对象搜索 API 来搜索对象集。

在 TypeScript v1 中，筛选、排序和聚合仅适用于启用了 Searchable 渲染提示（render hint） 的属性，因为这些属性已建立搜索索引。您可以在 Ontology Manager 中启用此渲染提示。

作为函数输入，对象集比对象数组更高效，因为它们会延迟加载直到需要时才加载。请查看 优化性能 以了解高效使用对象集的最佳实践。

对象搜索

直方图 Objects.search() 接口允许您对导入到项目中的任何对象类型发起搜索。在此示例中，函数使用给定的 airportCode 来查找从该机场出发的所有航班。然后，它会查找这些航班的所有不同目的地并将其返回。

import { Function } from "@foundry/functions-api";
import { Objects } from "@foundry/ontology-api";

export class FlightFunctions {
    @Function()
    public currentFlightDestinations(airportCode: string): Set<string> {
        const flightsFromAirport = Objects.search()
            .flights()
            .filter(flight => flight.departureAirportCode.exactMatch(airportCode))
            .all();

        const destinations = flightsFromAirport.map(flight => flight.arrivalAirportCode!);

        return new Set(destinations);
    }
}

还可以通过将对象列表、对象资源标识符列表或对象集资源标识符作为参数传递给被搜索的对象类型，来创建对象集。例如： Objects.search().flights([flight]).

一旦您拥有了给定类型的对象集，就可以对该集合执行下文所述的各种操作。

在 TypeScript v1 中， .filter() 对象集上的方法允许您根据对象的可搜索属性来筛选对象集。筛选方法接受一个筛选定义，该定义基于您要筛选的属性类型。有关 TypeScript v2 的等效方法，请参阅迁移指南中的 筛选操作符映射 表。TypeScript v1 的筛选方法如下：

  • 所有属性类型都支持 .exactMatch() 筛选，即筛选出该属性值完全匹配的对象。这对于筛选字符串的精确匹配（如上例所示）或筛选对象的主键（例如，.filter(object => object.primaryKey.exactMatch(PrimaryKey))).
    • 要检查某个属性是否 null or undefined，请使用 hasProperty() method.
    • 要传递多个值，请使用展开运算符 .exactMatch(...listVariable)。如果传入空数组，则筛选将被忽略。
  • 字符串属性支持多种关键字筛选。完整详情请参阅 Code Assist 中每个方法的文档。
    • .phrase() 将搜索查询拆分为多个词元（token），这些词元通常是单个单词。它会筛选出按顺序包含所有词元且词元之间没有其他词元的值。下划线和句点不会将属性值拆分为单独的词元。例如，搜索 banana 不会返回 banana_pudding or banana.pudding.
    • .phrasePrefix() 与 phrase()几乎完全相同，但最后一个词元还会匹配以该词元开头的词元。例如， .phrasePrefix() 搜索 fresh banana 将匹配属性值 fresh banana_pudding，但不匹配属性值 banana_pudding fresh。一个 .phrasePrefix() 搜索 pudding 将不匹配属性值 banana_pudding.
    • .prefixOnLastToken() 将搜索查询拆分为多个词元，然后根据值是否包含所有给定词元进行筛选，其中最后一个词元还会匹配以该词元开头的词元。例如， big app 将匹配 big apples 以及 apples from the big tree，但不会匹配 apples from the biggest tree.
    • .matchAnyToken(), .fuzzyMatchAnyToken() 将搜索查询拆分为多个词元，然后根据值是否包含任意给定词元进行筛选。 fuzzy 版本允许近似值匹配。
    • .matchAllTokens(), .fuzzyMatchAllTokens() 将搜索查询拆分为多个词元，然后根据值是否包含所有给定的词元进行过滤。 fuzzy 版本允许近似值匹配。
      • 模糊过滤器可以接受一个可选的 Fuzziness 参数，该参数从以下导入 @foundry/functions-api.
      • 可用选项的说明 Fuzziness 可以在以下文档中找到 ElasticSearch 文档 ↗。更多信息也可以在下方找到。
  • 数字、日期和时间戳属性支持 .range() filters.
    • 范围过滤器提供一组 .lt(), .lte(), .gt() and gte() 方法，用于执行小于 / 小于等于 / 大于 / 大于等于（分别对应）的比较。
  • 布尔属性支持 .isTrue() and .isFalse() filters.
  • 地理点属性支持 .withinDistanceOf(), .withinPolygon()日 .withinBoundingBox() filters.
  • 地理形状属性支持 .withinBoundingBox(), .intersectsBoundingBox(), .doesNotIntersectBoundingBox(), .withinPolygon(), .intersectsPolygon()日 doesNotIntersectPolygon() filters.
  • 关联过滤器可用于过滤具有或不具有特定类型关联对象的对象，使用 .isPresent() method.
  • 数组属性支持 .contains() 过滤器，该过滤器筛选出数组属性值包含 任意 给定值的对象。

组合过滤器

在 TypeScript v1 中，你可以使用 Filters 从以下导出的 API @foundry/functions-api来组合过滤器。可用的方法有：

  • and() 将对象集过滤为通过所有给定过滤器的对象
  • or() 将对象集过滤为通过任一给定过滤器的对象
  • not() 对给定的过滤器取反

对于 TSv2，请参阅 Not, And日 Or 过滤器。

在下面的示例中，我们可以使用以下方法按航班目的地过滤航班对象集 and():

import { Filters } from "@foundry/functions-api";

Objects.search()
    .flights()
    .filter(flight => Filters.or(
        Filters.and(flight.destination.exactMatch("SFO"), flight.passengerCount.gt(100)),
        Filters.and(flight.destination.exactMatch("LAX"), flight.passengerCount.gt(300)),
    ))

上面的代码将过滤出抵达 SFO 且乘客超过 100 人，或抵达 LAX 且乘客超过 300 人的航班。

使用 Filters 方法组合过滤器，而不是逻辑运算符

在 TypeScript v1 中， .filter() 对象集上的方法不使用运算符 && or ||。要应用多个过滤器，你必须使用 Filters 上列出的方法之一（或多次调用 .filter() 多次以实现 and 条件）。

使用模糊搜索过滤字符串属性

指定可选的 fuzziness 参数可以对模糊匹配行为进行更精细的控制。如果你不指定模糊度，则会根据你搜索的词元长度允许自动编辑距离。你需要导入 Fuzziness （来自 @foundry/functions-api 来指定编辑距离。

Fuzziness 是一个 TypeScript v1 概念，在 TypeScript v2 中没有对应项；详情请参阅 没有 TypeScript v2 等价项的功能 迁移指南中的相关内容。

模糊匹配任意词元

1
Objects.search().employee().filter(employee => employee.firstName.fuzzyMatchAnyToken("Michael", { fuzziness: Fuzziness.LEVENSHTEIN_TWO })).all();

上面的代码返回名字与提供的搜索词在两次编辑以内（Levenshtein 距离为二）的所有员工。在这个示例中，这将包括 Michael, Micheal, Mikhael, Michel, Mikhail, Mihail （但不包括 Miguel 等）。如果你对搜索词的准确性更有把握，可以使用更小的编辑距离（不同的 Levenshtein 距离）进行搜索，从而进一步精炼搜索结果。

模糊匹配字符串数组属性

基于数组的属性上的所有过滤器都可以使用其底层类型可用的方法。例如，字符串数组属性可以基于字符串属性可用的任何方法进行过滤，尽管方法的命名可能略有不同。过滤数组属性时，只要数组元素中有单个匹配项，该对象就会被返回。

周边搜索

TypeScript v1 中的搜索周边限制

以下限制适用于 TypeScript v1 Objects API。加载到内存中的对象集 .all() or .allAsync() 允许具有 最多 3 次 Search Around。如果使用了超过 3 次 Search Around，将抛出错误。在 Object Storage v2 中，从对象集 A 对对象集 B 执行 Search Around 时，生成的对象集 B 不能包含超过 1000 万个对象实例，否则将抛出错误。对于 Object Storage v1，该限制为 100,000 个对象实例。

根据对象集的对象类型， 周边搜索 会生成相应的方法以支持遍历 链接 ，具体取决于对象集的对象类型。在下面的示例中，我们根据出发代码筛选出一个航班对象集，然后 Search Around 到这些航班上的乘客。这将生成一个乘客对象集，可以进一步对其进行筛选或 Search Around。

TypeScript v1 会为每种链接类型生成一个 Search Around 方法，并以该链接命名。TSv2 将其替换为单个 pivotTo() 方法；参见 关联.

K 近邻 (KNN)

KNN 限制

KNN 仅在索引到 OSv2的对象类型上受支持。在 TypeScript v1 中，k 值限制在 0 < K <= 100 的范围内。此外，搜索向量必须与索引时使用的向量大小相同，并且有 2048 维的限制。如果超出任何这些限制，将抛出错误。

具有嵌入属性的对象类型可用于 KNN 搜索。这些搜索将返回 k 个对象，这些对象的嵌入属性与提供的嵌入参数最接近。以下示例返回与提供的电影剧本最相似的电影。嵌入可以在转换工具中生成，例如 如果希望用户在每次运行预览前手动确认，请开启；或者在函数查询时 使用 Palantir 提供的嵌入模型 or 在函数中使用您自己的模型.

请确保您的函数仓库的 functions.json 配置文件已将 enableVectorProperties 条目设置为 true.

两个版本都调用 nearestNeighbors()，但签名有所不同：TypeScript v1 传递一个回调，指定向量属性和搜索向量，而 TSv2 将查询、邻居数量和属性作为位置参数，并且最多接受 500 个邻居而不是 100 个。参见 最近邻.

集合操作

在 TypeScript v1 中，相同对象类型的对象集可以通过集合操作以多种方式进行组合：

  • .union() 创建一个由任意给定对象集中存在的对象组成的新对象集。
  • .intersect() 创建一个由所有给定对象集中都存在的对象组成的新对象集。
  • .subtract() 移除给定对象集中存在的任何对象。

TSv2 以相同的名称公开相同的三个方法；参见 集合操作.

检索所有对象

在 TypeScript v1 中， .all() 和 .allAsync() 方法会检索对象集中的所有对象，但如果您尝试一次加载过多对象，函数将无法执行。在 TypeScript v1 中，您可以加载的最大对象数量为 100,000。但是，加载超过 10,000 个对象也可能导致函数执行超时。 了解有关函数中时间和空间限制的更多信息。

你可以利用代码库升级拉取请求中的 .allAsync() 方法来检索一个 Promise，该 Promise 会解析为对象集中的所有对象。 .allAsync() 加载与以下内容相同的数据： .all() 并避免阻塞。它适用于并行加载多个独立的对象集：启动每个 .allAsync() 调用，然后使用以下方法一起等待它们 Promise.all()，而不是依次加载一个又一个对象集。

这两种方法都会将每个对象完整地加载到内存中，因此请仅对已知较小的对象集使用它们。在调用 .all() or .allAsync()之前，请考虑您是否需要：

  • 计算计数、求和或分组： 用途 后端聚合 例如 .count() or .groupBy() 来代替，这些方式不会加载对象。
  • 返回有界结果、样本或用于显示的列表： 用途 .orderBy(...).take(n) instead.
  • 处理已经有界的输入： .all() 适用于输入已知较小的情况，例如 Workshop 传递给 函数支撑列.
  • 的可见行。覆盖每个匹配的对象： 保留 .all()。不要用以下方式替换必须完整的遍历 .take(n)，因为它会静默截断结果。

分页一致性与快照

.all() 和 .allAsync() 使用以下方法对结果进行分页 对象集服务 (OSS) 端点可检索对象集中的所有对象。这些端点从一致的快照中读取连续的页面。对于流式数据源，不保证快照的一致性。这些端点的分页一致性检查无法禁用。如果服务检测到页面之间的不一致，遍历可能会因 PagingInconsistencyDetected 而失败。长时间运行的遍历也可能因其快照过期而失败。有界 .take(n) 读取不要求跨页面的一致性，但 n 最多可以为 10,000。如果函数运行本身具有快照，例如当操作在 快照隔离 模式下运行时，运行中的每次读取都会固定到该快照，包括 .take(n).

如果完整遍历因快照错误而失败，请考虑以下选项：

  • 改用后端聚合来计算结果。
  • 使用有界 .take(n) 读取（最多 10,000 个对象），前提是部分结果能够满足函数的需求。
  • 筛选到数据的稳定子集。
  • 保持输入较小，以便遍历快速完成。
  • 如果函数可以安全地重复执行，请从头开始重试以启动新的遍历。
  • 快照的生命周期有限。如果长时间运行的函数因其快照过期而失败，请重新评估工作流是否需要跨读取的一致视图。如果不需要，您可以在 函数配置中禁用快照。使用快照隔离的函数支撑操作要求保持启用快照。此设置并不能完全防止分页不一致错误，因为 .all() and .allAsync() 方法会强制执行分页一致性，而不受函数配置的影响。

有关 TSv2 的等效实现，请参阅 将对象加载到内存中.

排序和限制

您可以不检索所有对象，而是通过对对象集应用排序子句来加载有限数量的对象，然后指定要加载的具体对象数量。在 TypeScript v1 中，您可以使用以下方法：

  • .orderBy() 指定要用于排序的可搜索属性，并允许您指定排序方向。只有类型可排序的属性（数字、日期和字符串）才能在此方法中选择。您可以调用 .orderBy() 多次以按多个属性进行排序。
  • .orderByRelevance() 指定对象应按其与所提供筛选条件的匹配程度排序，最相关的排在最前面。查询词与给定对象上属性值的相关性是一个复杂的判定过程，会考虑该词在属性值中出现的频率、该词在所有对象中出现的频率等因素。如果仅执行 .exactMatch() 筛选或对非字符串属性进行筛选，则相关性排序不太适用。在单次搜索中只能使用其中一个 .orderBy() and .orderByRelevance() 。
  • .take() and .takeAsync() 使您能够从集合中检索指定数量的对象。这些方法仅在您指定了排序之后才可用。

.orderBy(...).take(n) 最多返回 n 对象并静默丢弃其余对象；它不是对对象集进行分页的方法。请仅在部分结果正确时使用它。如果您的函数只需要摘要，请使用 后端聚合。要分批处理稳定的对象集，请在支持范围筛选的唯一非空属性上按升序排序。排序键必须唯一，这样在越过某个批次中的最后一个值时才不会跳过具有该值的其他对象。对于每个后续批次，使用 .range().gt(lastValue) 来筛选出大于上一批次中最后一个值的值。此模式假设匹配的对象及其排序键值在各次查询之间保持不变。在 TypeScript v1 中，字符串属性不支持范围筛选，因此字符串主键不能用于此模式。

对于 TSv2，请参阅 加载有序结果; 排序和加载 列出了没有 TSv2 形式的 TSv1 功能。

例如，以下代码将检索入职日期最早的十名员工：

Objects.search()
    .employees()
    .orderBy(e => e.startDate.asc())

计算聚合

TypeScript v1 中的聚合限制

从 TypeScript v1 Objects API 返回的聚合限制为 总共 10,000 个桶。如果超出此限制，将抛出错误。

使用以下方式进行分桶时 .topValues()，如果数据具有超过 1,000 个不同的值，结果将是近似的。在这种情况下，前几个值的列表可能不准确。

按属性对对象进行分组

在许多情况下，无需加载对象集中的所有对象。相反，您只需加载值的分桶聚合即可进行进一步分析。

要开始计算聚合，请调用对象集上的 .groupBy() 方法。这允许您对对象集中对象类型的其中一个可搜索属性指定分桶。

对于 TSv2，请参阅 分组类型.

例如，以下代码按入职日期对员工进行分组：

Copied!
1
2
3
Objects.search()
    .employees()
    .groupBy(e => e.startDate.byDays())

在指定要用于分桶的属性时，您需要根据属性类型提供有关如何进行分桶的额外信息。对于 TSv2，请参阅 分组策略映射。TypeScript v1 的分桶方法如下：

  • 对于 boolean 属性，唯一的选择是 .topValues()。这会返回两个桶，一个用于 true ，另一个用于 false.
  • 对于字符串属性，有两种选择：
    • .topValues()：适用于快速响应时间和基数较小的属性。它按字符串属性的前 1,000 个值进行分桶。此限制是为了确保返回的聚合结果不会过大。
    • .exactValues()：适用于更精确的聚合，并且可以为高基数属性考虑最多 10,000 个桶。可以考虑的桶数量可以通过 .exactValues({"maxBuckets": numBuckets}) where numBuckets 指定，必须是介于 0 和 10,000 之间的整数值。此方法的响应时间可能较长，因为需要考虑更多的结果。
  • 对于数值属性（例如， Integer, Long, Float, Double），两种分桶选项是：
    • .byRanges() 允许你指定应使用的确切范围。例如，你可以使用 .byRanges({ min: 0, max: 50 }, { min: 50, max: 100 }) 将对象分桶到你在此处指定的 [0, 50] 和 [50, 100] 两个范围中。范围的 min 是包含的（闭区间），而 max 是排除的（开区间）。你可以省略其中任意一个 min or max 来表示一个包含从 -∞ 到 max or min 到 ∞ 的值的桶。
    • .byFixedWidth() 指定每个桶的宽度。例如，你可以使用 .byFixedWidth(50) 将对象分桶到宽度各为 50 的范围中。
  • 对于 LocalDate 属性，提供了多种便捷方法以便于分桶：
    • .byYear()
    • .byQuarter()
    • .byMonth()
    • .byWeek()
    • .byDays() 按天对值进行分桶。你可以传入一个天数用作桶宽度。
  • 对于 Timestamp 属性，适用的分桶选项与 LocalDate相同，此外还有以下新增选项：
    • .byHours() 按小时对值进行分桶。你可以传入一个小时数用作桶宽度。
    • .byMinutes() 按分钟对值进行分桶。你可以传入一个分钟数用作桶宽度。
    • .bySeconds() 按秒对值进行分桶。你可以传入一个秒数用作桶宽度。
  • 对于 Array 属性，分桶选项由数组中元素的类型决定。具体来说，你会获得与 Array<PropertyType> 相同的分桶方法，就像 PropertyType （例如， Array<boolean> 获得与 boolean).
    • 例如，如果你有一个名为 employeeSet 的对象集，由 Alice 和 Bob 组成，他们的 Array<string> property pastCountries holds ["US", "UK"] and ["US"] 分别为，那么 employeeSet.groupBy(e => e.pastCountries.exactValues()).count() 将返回 { "US": 2, "UK": 1 }.

按一个属性分组后，你可以选择调用 .segmentBy() 方法来执行进一步的分桶。这允许你计算由两个可搜索属性分桶的三维聚合。TypeScript v2 通过同一个 $groupBy 对象中的第二个键来按第二个属性分桶，这会返回不同的结果形状；参见 没有 TypeScript v2 等价项的功能 迁移指南中的相关内容。

选择聚合指标

对对象集进行分组后，你可以调用各种聚合方法来计算每个桶上的聚合指标。在 TypeScript v1 中，需要属性的方法仅接受标记为可搜索的属性。有关 TypeScript v2 的等效方法，请参见 聚合指标映射 迁移指南中的表格。可能的 TypeScript v1 聚合方法包括：

  • .count() 仅返回每个桶中的对象数量
  • .average() 返回给定数值、时间戳、日期属性的平均值
  • .max() 返回给定数值、时间戳、日期属性的最大值
  • .min() 返回给定数值、时间戳、日期属性的最小值
  • .sum() 返回给定数值属性值的总和
  • .cardinality() 返回给定属性不同值数量的近似值

在 TypeScript v1 中，调用这些方法之一会返回一个 TwoDimensionalAggregation or ThreeDimensionalAggregation。一个 ThreeDimensionalAggregation 如果你在调用最终聚合方法之前调用了 .segmentBy() 则会返回。

了解更多关于这些聚合类型结构的信息，包括 有效的分桶类型.

生成的聚合结果被包装在一个 Promise中，因为计算聚合需要从远程服务加载数据。你可以使用 async/await ↗ 语法来解包 Promise 结果。

import { Double, Function, ThreeDimensionalAggregation } from "@foundry/functions-api";
import { Objects } from "@foundry/ontology-api";

export class AggregationFunctions {
    @Function()
    public async employeesByRoleAndOffice(): Promise<ThreeDimensionalAggregation<string, string, Double>> {
        return Objects.search()
            .employee()
            .groupBy(e => e.title.topValues())
            .segmentBy(e => e.office.topValues())
            .count();
    }
}

在 TypeScript v1 中，分组聚合已经具有以下形状： ThreeDimensionalAggregation，因此函数可以直接返回它，如上所示。在 TSv2 中， .aggregate() 返回一个扁平的行数组，因此函数必须自行组装聚合类型。参见 聚合类型 和 分组.

你也可以在不使用以下内容的情况下执行其他聚合： groupBy 只需替换上面 TypeScript v1 代码示例中的相应行，例如：

  • 所有员工的数量： Objects.search().employee().count(); （如上例所示）
  • 员工的平均任职年限： Objects.search().employee().average(e => e.tenure);
  • 员工的最大任职年限： Objects.search().employee().max(e => e.tenure);
  • 员工的最小任职年限： Objects.search().employee().min(e => e.tenure);
  • 所有员工薪资的总和： Objects.search().employee().sum(e => e.salary);
  • 办公室的数量： Objects.search().employee().cardinality(e => e.office);
