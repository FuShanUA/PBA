API：对象集

一个 对象集 表示单一类型对象的无序集合。您可以使用函数 API 来筛选对象集、基于已定义的关联类型对其他对象类型执行 Search Around，以及计算聚合值或检索具体对象。除了将单个对象作为输入传递给函数之外，您还可以随时使用对象搜索 API 搜索对象集。

筛选、排序和聚合仅适用于启用了 Searchable 渲染提示 的属性，因为这些属性已为搜索建立了索引。您可以在本体论管理器中启用此渲染提示。

作为函数输入，对象集比对象数组更高效，因为它们会推迟到需要时才加载。请参阅 优化性能 以了解高效使用对象集的最佳实践。

对象搜索

该 Objects.search() 接口允许您对导入到项目中的任何对象类型发起搜索。在本示例中，该函数使用给定的 airportCode 来查找从该机场出发的所有航班。然后，它会找出这些航班的所有不同目的地并将其返回。

import { Function } from "@foundry/functions-api";
import { Objects } from "@foundry/ontology-api";

export class FlightFunctions {
    @Function()
    public currentFlightDestinations(airportCode: string): Set<string> {
        const flightsFromAirport = Objects.search()
            .flights()
            .filter(flight => flight.departureAirportCode.exactMatch(airportCode))
            .all();

        const destinations = flightsFromAirport.map(flight => flight.arrivalAirportCode!);

        return new Set(destinations);
    }
}

对象集也可以通过将对象列表、对象资源标识符列表或对象集资源标识符作为参数传递给所搜索的对象类型来创建。例如： Objects.search().flights([flight])。

获得给定类型的对象集后，您就可以对该集合执行各种操作，如下文所述。

过滤

对象集上的 .filter() 方法允许您根据对象的可搜索属性对对象集进行过滤。过滤方法接受一个过滤定义，该定义基于您所过滤属性的类型。

  • 所有属性类型都支持 .exactMatch() 过滤器，该过滤器会筛选出与该属性值完全匹配的对象。这对于筛选字符串的完全匹配（如上例所示），或筛选对象的主键（例如.filter(object => object.primaryKey.exactMatch(PrimaryKey))）。
    • 要检查某个属性是否为 null 或 undefined，请使用 hasProperty() 方法。
    • 要传递多个值，请使用展开运算符 .exactMatch(...listVariable)。如果传入空数组，则该过滤器将被忽略。
  • 字符串属性支持多种关键字过滤器。有关完整详情，请参阅 Code Assist 中每个方法的文档。
    • .phrase() 将搜索查询拆分为词元（通常是单个单词），然后根据值是否按顺序包含所有给定的词元且中间没有其他词元来进行过滤。请注意，以下划线或句点分隔的字符串值将被视为一个词元。例如，搜索 "banana" 时，属性值为 "banana_pudding" 或 "banana.pudding" 的对象将不会被返回。
    • .phrasePrefix() 几乎与 phrase()相同，但最后一个词元也会匹配以该词元开头的词元。例如，使用 .phrasePrefix() 搜索 fresh banana 会匹配属性值 fresh banana_pudding，但不匹配属性值 banana_pudding fresh。使用 .phrasePrefix() 搜索 pudding 不会匹配属性值 banana_pudding。
    • .prefixOnLastToken() 将搜索查询拆分为词元，然后根据值是否包含所有给定的词元来进行过滤，其中最后一个词元也会匹配以该词元开头的词元。例如， big app 会匹配 big apples 以及 apples from the big tree，但不会匹配 apples from the biggest tree。
    • .matchAnyToken()， .fuzzyMatchAnyToken() 将搜索查询拆分为词元，然后根据值是否包含给定词元中的任意一个来进行过滤。其中 fuzzy 版本允许匹配近似值。
    • .matchAllTokens()， .fuzzyMatchAllTokens() 将搜索查询拆分为多个词元，然后根据值是否包含所有给定词元来进行筛选。该 fuzzy 版本允许近似值进行匹配。
      • 模糊筛选器可以接受一个可选的 Fuzziness 参数，该参数从 @foundry/functions-api导入。
      • 有关可用 Fuzziness 选项的说明，请参阅 ElasticSearch 文档 ↗。更多信息也可在下方找到。
  • 数字、日期和时间戳属性支持 .range() 筛选器。
    • 范围筛选器提供一组 .lt()、 .lte()、 .gt() 和 gte() 方法，分别用于执行小于 / 小于或等于 / 大于 / 大于或等于比较。
  • 布尔属性支持 .isTrue() 和 .isFalse() 筛选器。
  • 地理点属性支持 .withinDistanceOf()、 .withinPolygon()和 .withinBoundingBox() 筛选器。
  • 地理形状属性支持 .withinBoundingBox()、 .intersectsBoundingBox()、 .doesNotIntersectBoundingBox()、 .withinPolygon()、 .intersectsPolygon()和 doesNotIntersectPolygon() 筛选器。
  • 关联筛选器可使用 .isPresent() 方法来筛选具有或不具有特定类型关联对象的对象。
  • 数组属性支持 .contains() 筛选器，该筛选器会筛选出数组属性值包含给定值中 任意一个 的对象。

组合筛选器

您可以使用 Filters API 来组合筛选器，该 API 从 @foundry/functions-api导出。可用的方法包括：

  • and() 将对象集筛选为通过所有给定筛选器的对象
  • or() 将对象集筛选为满足任一给定筛选条件的对象
  • not() 对给定的筛选条件取反

在下面的示例中，我们可以按航班目的地筛选航班对象集，使用 and()：

import { Filters } from "@foundry/functions-api";


Objects.search()
    .flights()
    .filter(flight => Filters.or(
        Filters.and(flight.destination.exactMatch("SFO"), flight.passengerCount.gt(100)),
        Filters.and(flight.destination.exactMatch("LAX"), flight.passengerCount.gt(300)),
    ))

上述代码将筛选出抵达 SFO 且搭载超过 100 名乘客，或抵达 LAX 且搭载超过 300 名乘客的航班。

警告

该 .filter() 方法在对象集上不会使用运算符 && 或 ||。要应用多个筛选条件，您必须使用 Filters 中上面列出的方法之一（或调用 .filter() 多次以实现 and 条件）。

使用模糊搜索对字符串属性进行筛选

指定可选的 fuzziness 参数可以对模糊匹配行为进行更精细的控制。如果不指定模糊度，允许的编辑距离将根据您所搜索词元的长度自动确定。您需要导入 Fuzziness （来自 @foundry/functions-api ）才能指定编辑距离。

模糊匹配任意词元

Objects.search().employee().filter(employee => employee.firstName.fuzzyMatchAnyToken("Michael", { fuzziness: Fuzziness.LEVENSHTEIN_TWO })).all();

上面的代码会返回名字与所提供的搜索词相差不超过两次编辑（Levenshtein 距离为 2）的所有员工。在此示例中，这将包括 Michael， Micheal， Mikhael， Michel， Mikhail， Mihail （但不包括 Miguel 例如）。如果您对搜索词的准确性更有把握，可以采用较小的编辑距离（即不同的 Levenshtein 距离）进行搜索，从而进一步细化搜索结果。

对所有词元进行模糊匹配

Objects.search().employee().filter(employee => employee.fullName.fuzzyMatchAllTokens("Michael Smith", { fuzziness: Fuzziness.LEVENSHTEIN_ONE })).all();

您还可以对包含多个词元的短语使用模糊过滤器。上述代码将匹配全名中 同时包含 Michael 和 Smith 且每个词元最多允许一处编辑的员工——例如， Mikhael Smitt （即每个词元的 Levenshtein 距离均为 1）。使用 fuzzyMatchAllTokens 或 fuzzyMatchesAllTokens 过滤器时，不会考虑词元的顺序。

对字符串数组属性进行模糊匹配

所有针对基于数组的属性的过滤器都可以使用其底层类型可用的方法。例如，可以根据字符串属性可用的任何方法对字符串数组属性进行过滤，不过这些方法的命名可能略有不同。对数组属性进行过滤时，只需数组元素中有任意一个匹配，该对象即会被返回。

周边搜索

周边搜索限制

加载到内存中的对象集 .all() 或 .allAsync() 最多允许 进行 3 次周边搜索。如果使用了超过 3 次 Search Around,将抛出错误。在 Object Storage v2 中,当从对象集 A 对对象集 B 执行 Search Around 时,生成的对象集 B 不能包含超过 1000 万个对象实例,否则将抛出错误。对于 Object Storage v1,该限制为 100,000 个对象实例。

根据对象集的对象类型, Search Around 方法会被生成,以支持遍历 关联 。这一遍历同样基于对象集的对象类型。在下面的示例中,我们先根据出发代码筛选出一个 Flights 对象集,然后 Search Around 到这些航班上的乘客。最终得到一个 Passengers 对象集,该对象集可以进一步筛选或继续 Search Around。

const passengersDepartingFromAirport = Objects.search()
    .flights()
    .filter(flight => flight.departureAirportCode.exactMatch(airportCode))
    .searchAroundPassengers();

请注意，出于性能原因，单次搜索中可执行的 Search Around 操作数量目前限制为 3。如果您尝试运行 Search Around 深度超过三层的搜索，该搜索将在运行时失败。

K 近邻 (KNN)

KNN 限制

KNN 仅在索引到 OSv2中的对象类型上受支持。k 值限制在 0 < K <= 100 的范围内。此外，搜索向量必须与索引时使用的向量大小相同，且有 2048 维的限制。如果超出这些限制中的任何一项，将抛出错误。

具有嵌入属性的对象类型将可用于 KNN 搜索。这些搜索将返回嵌入属性与所提供的嵌入参数最接近的 k 个对象。以下示例返回与所提供的电影剧本最相似的电影。嵌入可以在诸如 管道构建器之类的转换工具中生成；也可以在函数查询时 使用 Palantir 提供的嵌入模型 或 在函数中使用您自己的模型生成。

请确保您的函数仓库的 functions.json 配置文件中的 enableVectorProperties 条目已设置为 true。

集合运算

可以使用集合运算以多种方式组合同一对象类型的对象集：

  • .union() 会创建一个新对象集，其中包含存在于任一给定对象集中的对象。
  • .intersect() 会创建一个新对象集，其中包含存在于所有给定对象集中的对象。
  • .subtract() 会移除存在于给定对象集中的任何对象。

检索所有对象

该 .all() 和 .allAsync() 方法会检索对象集中的所有对象。请注意，如果您尝试一次加载过多对象，您的函数将无法执行。目前，您最多可以加载 100,000 个对象。但是，加载超过 10,000 个对象也可能导致函数执行超时。 了解有关函数中时间和空间限制的更多信息。

您可以使用 .allAsync() 方法来获取一个 Promise，该 Promise 会解析为对象集中的所有对象。这对于并行加载来自多个对象集的数据非常有用。

排序和限制

您无需检索所有对象，而是可以对对象集应用排序子句，然后指定要加载的具体对象数量，从而加载有限数量的对象。为此，您可以使用以下方法：

  • .orderBy() 指定用于排序的可搜索属性，并允许您指定排序方向。只有类型可排序的属性（数字、日期和字符串）才可在此方法中选择。您可以调用 .orderBy() 多次，以按多个属性进行排序。
  • .orderByRelevance() 指定应按对象与所提供筛选条件的匹配程度返回对象，最相关的排在最前面。查询词与给定对象的属性值之间的相关性是一个复杂的判定过程，需要考虑该词在属性值中出现的频率、该词在所有对象中出现的频率等因素。在仅执行 .exactMatch() 筛选或对非字符串属性进行筛选时，相关性不太适用。请注意，只有 .orderBy() 和 .orderByRelevance() 中的一个可以在单次搜索中使用。
  • .take() 和 .takeAsync() 使您能够从集合中检索指定数量的对象。只有在指定了排序之后，才能使用这些方法。

例如，以下代码将检索入职日期最早的十名员工：

Objects.search()
    .employees()
    .orderBy(e => e.startDate.asc())
    .take(10)

再举一个例子，假设有一个对象类型 claims 其中包含某保险公司的事故理赔文本。假设您想查找一起涉及红色汽车和鹿的特定理赔。如果不使用 .orderByRelevance() 行，任何包含以下任意词语的结果 red、 car、 collision、 with或 deer 都可能出现在前 10 个结果中。而使用 .orderByRelevance() 行时，前 10 个结果将是包含搜索词最多的理赔，从而使最相关的理赔排在最前面。

计算聚合

聚合限制

从 Objects API 返回的聚合结果限制为 总共 10,000 个桶。如果超出此限制，将抛出错误。

使用 .topValues()进行分桶时，如果数据包含超过 1,000 个不同的值，结果将是近似值。在这种情况下，最常出现的值列表可能不准确。

按属性对对象进行分组

在许多情况下，无需加载对象集中的所有对象。相反，您只需加载按值分桶的聚合结果即可进行进一步分析。

要开始计算聚合，请调用 .groupBy() 对象集上的方法。这允许您指定按对象集中对象类型的某个可搜索属性进行分桶。例如，此代码按入职日期对员工进行分组：

Copied!
1
2
3
Objects.search()
    .employees()
    .groupBy(e => e.startDate.byDays())

在指定按哪个属性进行分桶时，您需要根据属性类型提供有关如何执行分桶的额外信息：

  • 对于 boolean 属性，唯一选项是 .topValues()。这将返回两个桶，一个用于 true ，另一个用于 false。
  • 对于字符串属性，有两种选项：
    • .topValues()：用于获得快速响应时间，适用于基数较小的属性。它按字符串属性的前 1,000 个值进行分桶。此限制是为了确保返回的聚合结果不会过大。
    • .exactValues()：用于获得更精确的聚合结果，并可为高基数属性考虑最多 10,000 个桶。所考虑的桶数量可通过 .exactValues({"maxBuckets": numBuckets}) 来指定，其中 numBuckets 必须是介于 0 和 10,000 之间的整数值。此方法的响应时间可能较长，因为需要考虑更多结果。
  • 对于数值属性（例如 Integer、 Long、 Float、 Double），两种分桶选项为：
    • .byRanges() 允许您指定应使用的确切范围。例如，您可以使用 .byRanges({ min: 0, max: 50 }, { min: 50, max: 100 }) 将对象分桶到您在此处指定的 [0, 50] 和 [50, 100] 两个范围中。该范围的 min 是包含的，而 max 是不包含的。您可以省略 min 或 max 来分别表示包含从 -∞ 到 max 或从 min 到 ∞ 的值的桶。
    • .byFixedWidth() 指定每个桶的宽度。例如，您可以使用 .byFixedWidth(50) 将对象分桶到宽度均为 50 的各个范围中。
  • 对于 LocalDate 属性，提供了多种便捷方法以便轻松分桶：
    • .byYear()
    • .byQuarter()
    • .byMonth()
    • .byWeek()
    • .byDays() 将值按天进行分桶。您可以传入天数用作桶宽度。
  • 对于 Timestamp 属性，适用与 LocalDate相同的分桶选项，同时还提供以下附加选项：
    • .byHours() 将值按小时进行分桶。您可以传入小时数用作桶宽度。
    • .byMinutes() 将值按分钟进行分桶。您可以传入分钟数用作桶宽度。
    • .bySeconds() 将值按秒进行分桶。您可以传入秒数用作桶宽度。
  • 对于 Array 属性进行分组时，分桶选项由数组中元素的类型决定。具体而言，您为 Array<PropertyType> 获得的分桶方法与您为 PropertyType 获得的相同（例如， Array<boolean> 获得的分桶方法与 boolean的相同）。
    • 例如，如果您有一个名为 employeeSet 的对象集，其中包含 Alice 和 Bob，他们的 Array<string> 属性 pastCountries 的值分别为 ["US", "UK"] 和 ["US"] ，那么 employeeSet.groupBy(e => e.pastCountries.exactValues()).count() 将返回 { "US": 2, "UK": 1 }。

按一个属性分组后，您可以选择调用 .segmentBy() 方法来执行进一步分桶。这使您能够计算按两个可搜索属性分桶的三维聚合。例如，您可以按入职日期和角色对员工进行分组，如下所示：

    .employees()

选择聚合指标

对对象集进行分组后，您可以调用各种聚合方法来计算每个桶的聚合指标。需要属性的方法仅接受标记为可搜索的属性。可能的聚合方法包括：

  • .count() 仅返回每个桶中的对象数量
  • .average() 返回给定数值、时间戳或日期属性的平均值
  • .max() 返回给定数值、时间戳或日期属性的最大值
  • .min() 返回给定数值、时间戳或日期属性的最小值
  • .sum() 返回给定数值属性值的总和
  • .cardinality() 返回给定属性中不同值的大致数量

调用这些方法之一会返回一个 TwoDimensionalAggregation 或 ThreeDimensionalAggregation。一个 ThreeDimensionalAggregation 会被返回，如果你先调用了 .segmentBy() ，之后才调用最终聚合方法之一。

详细了解这些聚合类型的结构，包括 有效的分桶类型。

请注意，生成的聚合结果会被包装在一个 Promise中，因为计算聚合需要从远程服务加载数据。你可以使用 async/await ↗ 语法来解包 Promise 结果。

import { Function, ThreeDimensionalAggregation } from "@foundry/functions-api";
import { Objects } from "@foundry/ontology-api";

export class AggregationFunctions {
    @Function()
    public async employeesByRoleAndOffice(): Promise<ThreeDimensionalAggregation<string, string>> {
        return Objects.search()
            .employee()
            .groupBy(e => e.title.topValues())
            .segmentBy(e => e.office.topValues())
            .count();
    }
}

你还可以通过替换上方代码示例中的相应行，来执行其他不使用 groupBy 的聚合，例如：

  • 所有员工的数量： Objects.search().employee().count(); （如上例所示）
  • 员工的平均在职时长： Objects.search().employee().average(e => e.tenure);
  • 员工的最长在职时长： Objects.search().employee().max(e => e.tenure);
  • 员工的最短在职时长： Objects.search().employee().min(e => e.tenure);
  • 所有员工薪资的总和： Objects.search().employee().sum(e => e.salary);
  • 办公室的数量： Objects.search().employee().cardinality(e => e.office);
