平台概览

Palantir AIP 在全球最关键的商业和政府场景中支持实时、AI 驱动的决策。从 公共卫生 ↗ to 电池生产 ↗，各类组织都依赖 Palantir 在其企业中安全、可靠且高效地利用 AI——并 取得运营成果 ↗.

简而言之，Palantir AIP 将生成式 AI 与运营相连接。AIP 与 Foundry（Palantir 的数据运营平台）以及 Apollo（Palantir 用于自主软件部署的任务控制平台）一起，构成了 AI Mesh 的一部分，能够交付全方位的 AI 驱动产品，从基于 LLM 的 Web 应用程序，到使用视觉-语言模型的移动应用程序，再到嵌入本地化 AI 的边缘应用程序。我们将这一整套能力、功能和工具称为 Palantir 平台.

虽然许多因素都有助于通过 Palantir 平台实现并扩大运营影响——包括 AIP 训练营 ↗（客户在训练营中亲自动手，在数小时内即可用 AI 取得成果）——但关键的差异化因素是一种围绕 Palantir 本体论.

本体论

本体论旨在表示 决策 ，而不仅仅是数据。世界上每个组织都面临着一个挑战：如何在内部和外部条件不断变化的情况下，往往还需要实时地做出最佳决策。

这些决策过程的复杂性在本体论中得到了体现，本体论促进了与现有企业系统的深度双向互操作性。本体论将相关的数据、逻辑和操作组件自动集成到一个现代化的、AI 可访问的计算环境中。除了传统的商业智能和分析工作流之外，这还解锁了具有 AI 协作能力的运营应用程序的快速开发。

决策组件

每个决策都可以分解为 数据, 逻辑日 操作.

  • 数据： 关于世界和我们的运营，有哪些相关的事实或真相构成了此决策的背景？
  • 逻辑： 哪些组织或业务规则为该决策提供了护栏？在不同假设下某些结果的概率是多少？在以往类似的情况下我们做了什么，结果如何？我们的预测和优化模型提供了哪些输入？
  • 操作： 该决策的“动力学”或影响是什么——也就是说，决策如何在世界上体现？我们如何减少或压缩从在 AIP 中做出决策到在生产环境中产生影响之间的步骤？

在 Palantir 平台中，所有这些组件都旨在促进 AI 协作模式，以充分释放您的操作人员、分析师和领域专家的潜力。

同步至数据集

本体论将数据集成为 对象和关联（objects and links） ，从而使运营的现实世界复杂性对人类和 AI 都易于理解。这解锁了构建 人 + AI 协作 工作流。

本体论原生支持多种数据类型以及若干扩展基元，例如 语义搜索 用于解锁非结构化数据， 媒体引用 用于处理图像和视频，以及 值类型 用于将额外的约束和上下文嵌入到数据中。这些是 AI 工作流开发的数据构建模块，将在下文的 逻辑 和 操作 章节中进一步介绍。

该数据模型为开箱即用的应用程序提供支持，可用于探索结构化、非结构化、地理空间、时间、模拟及其他数据模态。这些基线工具通过情境感知的 AIP Assist 得到增强，从而大幅缩短在平台中探索和分析数据的见效时间。

除了应用程序构建和分析之外，在本体论中对数据建模还会自动创建强大的 API 网关和本体论软件开发工具包（OSDK），作为整个企业范围内连接的“操作总线”。

逻辑

如果数据为我们的决策定义了情境，那么逻辑则封装了丰富这一情境的推理与分析，使人机协同（Human+AI）团队能够做出更好的决策。这可以以模型输出和可视化的形式在操作应用程序中作为附加上下文提供，也可以直接融入操作的机制之中。

鉴于这一定义十分宽泛，定义和执行逻辑的能力贯穿整个平台；例如，让我们考虑 模型, 业务逻辑日 模板化分析与报告.

链接进行访问。

生成式 AI、LLM、预测、优化器等。

LLM 或预测等模型接受参数并提供输出，作为当前决策的上下文。在数据科学家所熟悉的循环中，这些模型往往要经历训练和优化的迭代过程；然而，将这些模型作为生产环境中的操作工作流使用可能是一项挑战。Palantir 的建模能力可以促进模型的操作化部署。

在 Palantir 平台中，模型的完整生命周期被捕获为 建模目标 ，而模型本身的逻辑则通过 模型适配器进行抽象。这种方式意味着，无论您是 在平台中训练, 自带容器，或 上传预训练模型，各种类型的模型都可以通过 函数 绑定到本体论，以便在操作应用中进行实时交互，或配置为 批量部署 并安排在数据管道中执行。

专门针对生成式 AI，Palantir 的 语言模型服务 为多模态交互提供了统一接口，同时抽象了具体的模型和提供商实现细节，使跨商用 LLM 的开发变得简单。为了进一步改善结果，Palantir 的 评估 工具使您能够随时间推移并在不同模型之间对 LLM 性能进行基准测试，以监控漂移并自信地做出变更。

业务逻辑

业务规则、流程映射、语义搜索

在建模方法采用“自下而上”的方式对数据进行训练的同时，业务逻辑通常基于支配运营领域的显式或隐式规则，以“自上而下”的方式构建。这些规则可能存在于外部系统中，Palantir 可以通过 外部函数 和 Webhook 直接与之连接，以在运营工作流中进行实时交互，或通过 外部转换 实现管道连接。业务逻辑也可以直接在 Palantir 平台中使用 规则 和 Pipeline Builder 在数据管道中编写逻辑，并使用 Automate 和 Functions 编写将实时执行的逻辑。

模板化分析与报告

对象视图、分析模板、生成的报告

逻辑不仅存在于数据科学模型或硬编码的业务规则中；分析师通常会在一次性调查、分析或报告中捕获和积累高价值的逻辑。在 Palantir 平台中，您可以使用点选式分析工具（如 Contour 和 的流可在）以及笔记本（如 代码工作区）来构建分析和仪表板。本体论数据模型的语义使这些分析产品易于模板化并重复使用，无论是嵌入在 对象视图 or Workshop 应用程序中，还是作为独立的 仪表板呈现。这些对象视图、模板化分析和仪表板可以插入运营应用中，提供一目了然的洞察以指导决策，同时为进一步的临时探索提供途径。

综合来看，逻辑的这三个方面——模型、业务逻辑以及模板化分析与报告——提供了一个工具箱或调色板，用户可以从中自由组合，为决策者在关键时刻提供所需的全部背景信息。

操作

任何决策要产生影响，都必须传播到现实世界中。这正是操作定义企业“动词”的地方——即所执行的事情——并控制人工操作员或 AI 代理如何确保其决策得以持久化，无论是在本体论数据模型中，还是通过与 外部系统的交互来实现。此外，在本体论中捕获决策结果使用户能够将特定决策与未来数据中对结果的观察相关联。这使得反馈循环能够将未来的决策置于过去选择的背景之下，并可用于重新训练或微调模型，或者仅仅为操作员提供对过去更清晰的图景。

在本体论中表示这些“动力学”的原子单元是 操作，它为更改或创建数据以及协调外部系统中的更改提供了具体、细粒度的控制。基本操作可以通过点选式表单配置界面轻松定义。任意复杂度的操作可以使用 函数支撑的操作 和 本体论编辑 Typescript API来指定。操作还可以打包到 本体论软件开发工具包 （OSDK）以及 平台 API 中，以便自定义应用开发和现有的第三方工具能够轻松且安全地回写到本体论。

权限 为每个操作确定哪个用户或代理在什么条件下能够执行该操作，从而在最底层为安全、可审计和透明的控制奠定基础。

在复杂且紧密耦合的环境中，例如供应链或制造车间，微小的变化可能引发连锁反应，导致意外或非预期的结果。 加载对象数据。 原语允许用户通过对本体论的一个分支进行更改来预测这些后果，从而有效地创建一个沙盒世界，可以在其中（以及在其下游）针对潜在更改进行预测、业务流程模型和其他分析。 和 应用专精于此类流程可视化和场景测试； 来运行该专业代码代理。你还可以通过 应用构建器原生支持场景，用于开发包含“如果……”工作流的运营应用。

这些基元为在生产工作流中运行的人机协作（Human+AI）团队创建了一个安全的开发环境。Actions 提供的细粒度权限和访问控制构成了一个"控制平面"，在其中代理（agent）被沙箱化，对其可使用的数据和工具施加特定限制。在大多数模式中，AI 代理不会直接进行更改，而是创建提案，可以通过与 AIP 逻辑 集成到 Workshop 中的函数进行同步集成，或通过 发布后，我们建议在 或 使用 LLM Pipeline Builder 中的节点异步完成。生成的提案随后可呈现给操作员，以进行细化、反馈和最终决策。这种基于提案的模式不仅强化了"人在回路"（human in the loop）范式，还会生成有价值的元数据，从而形成一个正向循环，使代理能够通过持续反馈不断学习和演进。
