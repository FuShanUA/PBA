派生序列

派生序列允许用户保存和复制应用于本体论中时间序列的计算和转换。通过将这些数据保存为 Palantir 资源，派生序列可以共享并作为时间序列属性保存回本体论。一旦进入本体论，派生序列的行为与任何其他时间序列属性一样，但都是实时计算的，从而无需管理或存储派生数据，也无需在整个平台中重复这些计算。

在以下位置浏览、创建和管理派生序列： 派生序列 Ontology Manager 时间序列目录.

派生序列类型

派生序列可以是 模板化的 or 单个.

模板化派生序列

模板化派生序列是针对根对象类型进行模板化的，因此必须作用于单个根对象。模板化派生序列的强大之处在于，它们允许您在给定类型的所有对象之间快速复制逻辑。例如，如果许多假设的 Machine 对象具有温度传感器，模板化派生序列将使您能够快速在 Machines.

单一派生序列

单一派生序列不用于模板化，可以作用于多个对象。单一派生序列允许您创建不受限于所有输入都来自同一对象的逻辑。

要求

以下各节说明了创建派生序列时必须遵循的要求。

时间序列对象类型

时间序列本体论是创建派生序列的前提条件。派生序列是针对 时间序列对象类型创建并存储在其上，或者 根对象类型上的时间序列属性 or 传感器对象。请查阅 时间序列本体论文档 的文档以获取更多信息。

逻辑要求

派生序列逻辑管理由 Quiver 提供支持。大多数 Quiver 时间序列操作在派生序列中都受支持；请查看完整列表 受支持操作列表 以了解派生序列逻辑。

模板化派生序列的逻辑

模板化派生序列的逻辑必须包含 单个根对象。根对象上的时间序列属性以及与根对象关联的传感器对象都可以在逻辑中使用。了解更多信息 时间序列对象类型 以明确区分根对象类型和传感器对象类型。

单一派生序列

单一派生序列的逻辑可以包含任意数量的传感器对象或根对象，只要它们都位于同一个本体论中。

权限要求

要保存派生序列， 对象类型编辑权限 需要在绑定的对象类型上具有。

自动保存要求

绑定到传感器对象类型的派生序列可以 自动 保存 到本体论，使用操作类型。派生序列自动保存会安排本体论操作编辑，以根据本体论中请求的内容管理关联的传感器对象。派生序列也可以 手动 保存到本体论.

自动保存到本体论的传感器对象类型要求

  1. 用于自动保存到本体论的传感器对象类型的主键必须为以下类型 String.
  2. 传感器对象类型必须使用以下方式存储 对象存储 v2；这是操作写入时间序列属性所必需的。
  3. 传感器对象类型必须启用编辑功能。
  4. 对于模板化派生序列，必须存在单个 一对多基数关联 位于根对象类型和传感器对象类型之间，且根对象类型位于“一”的一方。

自动保存到本体论的操作类型要求

如果不满足以下任何要求，您将无法选择用于自动写入本体论的操作类型：

  1. 每个操作类型必须只有一条规则。
  2. Action 类型的参数不得使用限制可提供值的约束。同样，Action 类型的参数不得使用会导致值约束的覆盖。
  3. Action 类型不应有未使用的参数。如果某个参数未被使用，则不能将其配置为必填。
  4. 未提供值的属性被视为未映射。未映射的传感器对象属性的参数必须配置为“非必填”。对于模板化派生序列，传感器对象类型上不属于根对象类型的外键属性始终是未映射的。
  5. Action 类型的提交条件不得使用基于参数的条件。

您必须创建三个独立的 Action 类型：创建、修改和删除。这些 Action 类型的规则如下所列。

Create object 操作类型

规则： 每个属性类型使用相同类型的参数，并编辑对象类型的所有属性。如果您使用 Ontology Manager 配置 Action 类型，则必须从 表单 左侧的选项卡中手动为主键创建一个字符串参数。

Modify object 操作类型

规则： 与 Create object Action 类型类似， Modify object Action 类型应使用与关联属性类型相同类型的参数，并应编辑除主键之外的所有属性。

Delete object 操作类型

规则： 配置 Delete object Action 类型来删除传感器对象类型。无需进一步的属性或参数配置。

了解更多关于 创建派生序列 的更多信息，请参见下一节。

权限要求

要使用自动本体论保存，您必须满足 提交标准 Action 类型的相关要求。

此外，您必须能够查看根对象类型和传感器对象类型的对象。在由受限视图支撑的对象类型上使用自动保存时请务必谨慎，因为派生序列的本体论状态是根据用户可查看的对象计算的。对于模板化派生序列，用户应有权访问整个根对象范围及其关联的传感器对象。同样，单个派生序列只能由可查看关联单个传感器对象的用户进行更新。
