代理权限

要创建代理，您必须同时具备以下条件：

  • 包含以下工作流的组织角色： 创建数据连接代理 工作流。 Organization administrator and Data flows administrator 角色默认包含此工作流，您也可以将其添加到 自定义角色。组织角色在 组织权限 页面中访问这些指标，该页面位于 控制面板.
  • 直方图 Editor or Owner 角色，才能在您要保存代理的 Project 中进行操作。

2023 年 5 月 27 日之前开通的部署可能不需要 创建数据连接代理 工作流即可创建代理。拥有 更改代理创建身份验证方法 工作流的用户（该工作流默认包含在 Organization administrator 角色中）可以在 Control Panel 中强制执行此要求。有关这些部署的问题，请联系 Palantir Support。

代理创建后，您在包含该代理的 Project 上的角色决定了您可以对其执行的操作。下表列出了每个角色的默认权限，如果您的组织使用 自定义角色。该 Editor 角色包含所有 Viewer 权限，而 Owner 角色包含所有 Editor 权限的用户隐藏。

角色代理上的权限
Viewer查看代理的状态、健康状况、指标、配置、事件历史记录和升级窗口。
Editor将代理分配给数据源、添加或移除插件和驱动程序、编辑代理的配置和升级窗口、重启或停止代理，以及删除代理。
Owner添加或移除证书、为代理生成下载链接或新令牌，以及部署 安全隧道发起程序 到代理上。

如果您在 Project 上仅拥有 Editor 角色，您可以在该处创建代理，但无法生成用于安装的下载链接。

拥有 Editor 角色的用户可以将代理分配给新的数据源并更改其配置。请仅将 Editor 和 Owner 角色授予您信任来管理该代理的用户。

证书

代理与 Foundry 和您的内部网络进行通信。这意味着代理需要在其信任库中拥有正确的证书才能建立这些连接。

有两种情况可能需要在代理上配置额外的证书：

  • 允许代理与 Foundry 通信的证书
  • 允许代理与您的系统通信的证书（仅限代理 worker）

在这两种情况下，都可以在 Data Connection 应用程序的代理管理页面中添加证书。

允许代理与 Foundry 通信的证书

用于连接到您的 Foundry 实例的证书已包含在默认的代理安装包中。通常，这意味着您的代理主机与 Foundry 通信不需要额外的证书。

如果从代理到 Foundry 的流量经由显式或透明代理中转，则可能需要在初始设置过程中将代理的证书添加到代理中。由于在此场景下缺少证书将导致代理无法由 Foundry 管理，因此必须在下载初始安装包之前将这些证书添加到代理中。

如果代理启动时出现与证书相关的错误，导致代理无法与 Foundry 通信，这些错误将显示在名为以下文件的日志文件中 <bootvisor_directory>/var/service.log.

如果您在首次尝试设置代理时遇到错误，或事先知道需要额外的证书，您应该：

  1. 跳过代理设置页面，不要尝试在代理主机上下载和安装。
  2. 按照以下说明，从代理管理页面添加必要的证书 上述章节，然后下载并按照标准安装说明进行操作。

如果您的额外证书用于显式代理， 则可能需要进行额外的配置.

请确保您为与 Foundry 的连接所管理的所有证书（包括代理证书）在过期或轮换之前保持有效。使用 证书过期监控 来提前收到通知。

如果证书更改导致 Agent Manager 无法连接到 Foundry，仅更新 Data Connection 中的证书无法恢复连接，因为 Agent Manager 将无法检索该更新。请按照 证书恢复流程 更新本地信任库或重新安装代理。

TLS 检查环境中的代理

如果您在安装代理的主机上对流量执行 TLS 检查，则需要先手动将根 CA 导入 Agent Manager 的信任库，Agent Manager 才能首次连接到 Foundry。

为此，请按照以下说明操作：

  1. 获取用于对受检查流量重新签名的根 CA 的公共证书。您的网络团队应该能够提供该证书。或者，您可以在代理主机上使用 OpenSSL 检查证书链并找到根证书： openssl s_client -showcerts -connect FOUNDRY_URL:443.
  2. 使用 SSH 访问代理主机，并将证书放置在运行 Agent Manager 的用户可以访问的位置。其中一个此类位置可能是 <agent-manager-install-directory>/var/security.
  3. 导航到 Agent Manager 的 Java 安装目录： cd <agent-manager-install-directory>/jdk/amazon-corretto*.
  4. 将证书导入 Agent Manager 的信任库： ./bin/keytool -import -alias <CERT_NAME> -file /path/to/certificate.pem -keystore ../../var/security/truststore.jks （提示时，密码为 truststore).
  5. 启动 Agent Manager。您应该会看到 Connected to Agent Manager, but no connection from agent 在 Data Connection 的代理详情页面上，确认 Agent Manager 已成功连接到 Foundry。
  6. 要允许代理连接到 Foundry，请按照 上述说明 将相同的证书添加到代理中。

代理指标和健康监控

  • 操作系统物理内存
  • 磁盘空间
  • 可用磁盘空间
  • 相对于核心数标准化的操作系统负载
  • CPU 利用率
  • 代理密钥库中距下次过期的时间
  • 代理信任库中距下次过期的时间
  • 代理堆内存
  • 已用堆内存百分比
  • 代理运行时间
  • 代理线程数
  • 自上次代理重启以来上传的同步/任务数
  • 正在运行的同步/任务数
  • 已排队的代理同步/任务数
  • 同步/任务持续时间
  • 代理上次心跳时间
  • 代理管理器版本过期时间
  • 代理版本过期时间

将鼠标悬停在指标卡片上可查看带时间戳的详细信息，选择卡片右上角可展开详细视图。

"距离下次过期的时间"指标

直方图 代理密钥库中距下次过期的时间 和 代理信任库中距下次过期的时间 指标分别指代理密钥库和信任库中距最早证书过期的时间。例如，如果代理的密钥库中有两个证书，一个在一周后过期，另一个在一个月后过期，则该数值为 1w 因为那是最近的过期日期。

代理密钥库和信任库包含用户添加的证书以及代理管理器自动添加的证书。代理管理器证书会自动升级。

如果证书已过期，指标将显示 000ms。如果代理没有存储任何证书，图表将为空。

“版本过期时间”指标

直方图 代理管理器版本过期时间 和 代理版本过期时间 指标指代理和代理管理器相对于您环境中可用版本的过时程度。

版本过时指标的计算方式为代理或代理管理器上次更新日期与最新可用版本发布日期之间的天数。以下示例说明了这些指标及相关监控器的预期行为：

。点击示例图像即可将其展开。最新发布版本代理/代理管理器当前版本版本过期时间指标值备注
0v1.0v1.00代理更新到当前最新版本。
1v1.0v1.00
2v0.1 -> v2.0v1.00 -> 2当 Palantir 发布新版本时，指标跳升至 2 当 Palantir 发布新版本时。
3v2.0v1.03
4v2.0v1.0 -> v2.04 -> 0指标恢复为 0 在 维护窗口期间成功更新后。

在此示例中，前两天的代理版本过期时间指标为 0。当新版本可用时，该指标随后会跳升至 2 ，并将持续增加直到下一个代理维护窗口，最终在维护窗口期间成功完成更新后回落至 0 。

如果监控器被设置为在软件版本过旧时发送警报，而 Palantir 的新版本发布间隔超过了允许的天数，那么即使某个代理一直没有机会进行更新，该监控器也会在新版本可用时立即开始发出警报。这些警报将在下一个维护窗口期间成功完成更新后自动解除。

在上面的示例中，如果监控器被设置为在过期时间达到 >2天时发出警报，那么即使代理没有机会升级到最新版本，第 3 天也会发出警报。该警报将在第 4 天成功完成更新后自动解除。

健康监控

健康监控器允许您在满足特定条件或阈值时，为任何指标配置不同严重程度（高、中或低）的警报。

您可以通过以下方式监控代理的健康状况： 创建监控视图 菜单中选择 数据健康 应用程序。监控视图是一组监控规则的集合，这些规则对已订阅的用户群体具有特别的意义。

您可以通过选择 监控视图 标签页。

来查看现有的监控视图。选择特定监控视图后，您可以通过选择 管理监控来配置代理的健康监控器。在此页面上，您可以创建新的监控规则。

在监听器设置向导的 创建监控规则 页面上，您可以配置具体的规则以及不同严重程度的警报。

了解更多关于 使用监控器跟踪数据健康状况 和 将监控器与 PagerDuty 集成.

自动升级窗口

Data Connection 代理服务会定期更新，以提供安全性、稳定性和性能方面的改进。确保代理及时获得这些重要改进的最佳方式是为每个正在使用的代理配置升级窗口。以下部分介绍了升级窗口期间发生的情况，并提供了最佳实践指南。

升级窗口

代理升级窗口是一组时间间隔，在此期间代理暂时离线被认为是安全的。这些时间间隔每周重复出现，可以在 维护窗口 页面的 代理设置 选项卡中为 Data Connection 应用程序中的指定代理进行定义。

Data Connection 协调器会监控代理及其各自的升级窗口；当有新版本可用时，它将在这些升级窗口期间自动升级代理。

作为升级的一部分，代理将被重启。这将终止任何正在运行的作业，并短暂阻止新作业在该代理上运行。

代理升级窗口应至少为 60 分钟。不过，实际升级过程应相对较短；所需时间应与代理重启大致相同。

错开升级

为了确保对数据管道的影响降到最低，我们建议为所有 Data Connection 数据源分配至少两个代理，并为在这些代理上运行的任意一组数据源错开升级窗口。例如，一个代理的升级窗口可以定义在周日，而另一个代理的升级窗口可以安排在周三。这样可以确保在任一代理的升级窗口期间，被中断的作业可以在伙伴代理上重试，新作业也可以继续排队并运行，直到正在升级的代理完全恢复在线。

安排数据集同步

当无法使用错开的升级窗口时，重要的是将升级窗口安排在活动较少（理想情况下为零）的时段。在这种情况下，数据集同步的调度应确保其在升级窗口开始之前完成，或在窗口结束后几分钟才开始（以考虑到窗口临近结束时发生的重启）。

备份和缓存

代理在安装、版本升级、版本降级和日常使用过程中可能会备份或缓存文件。这包括代理软件和连接器插件的早期版本。安全性和稳定性修复会在 最新版本中提供。代理升级后，被替换的版本仍会保留在主机上，但不再被加载或运行。通常，备份和缓存文件可以安全地忽略，并将在 30 天后自动删除。如果它们在代理主机上占用了超出预期的磁盘空间，可以安全地将其删除。请在 维护窗口.

之外执行删除操作。备份和缓存文件位于代理安装目录中的以下子目录中：

子目录用法
/backups用于在执行升级时存储代理配置的备份。
/var/data/cache用于在代理正常运行期间缓存数据。
/var/data/maven代理在安装和升级过程中下载的连接器插件和构件版本的本地缓存，按版本存储。仅加载当前分配给代理的版本；被取代的版本仍保留在缓存中但不会运行，可以将其删除。
/var/data/processes为每个代理进程保存一个工作目录，包括该进程使用的连接器插件。只有当前正在运行的进程在使用中。为了仅保留最近的非活动目录（默认保留最近 10 个），非活动目录在超过保留期（默认 30 天）后或主机磁盘空间不足时会被自动删除。也可以手动删除。
/var/data/processes/<bootstrapper>/var/conf/agent/managed-plugins由 Foundry 提供的连接器插件，每个连接器对应一个 .jar 。存在的最高版本即为正在使用的版本；被取代的版本会被移动到相邻的 archive 目录中，可以将其删除。

要识别 /var/data/processes下当前正在运行的进程目录，请在每个目录中运行 service/bin/init.sh status 。报告为正在运行的目录即为正在使用的目录；其他目录处于非活动状态，可以将其删除。

配置主机覆盖

可以为代理配置自定义的主机名到 IP 地址映射，以覆盖标准 DNS 解析，类似于 Unix 系统中 /etc/hosts 中的条目。这些主机覆盖允许代理将特定主机名解析为与标准 DNS 查询不同的 IP 地址。

如何为代理配置主机覆盖

按照以下步骤直接从 Data Connection 应用程序中为代理添加主机覆盖：

  1. 在 Data Connection 中导航至 代理 页面，并选择您要配置的代理。
  2. 在 Data Connection 中导航至 代理设置 页面，添加具有所需主机名和 IP 地址映射的主机覆盖。
  3. 保存更改并重启代理，以使配置生效。

例如，如果您的数据源只能通过以下地址访问： 10.0.0.1 （位于您的私有网络内）：

  1. 配置一个主机覆盖（host override），将一个临时域名（例如 my-private-internal-database.local）映射到 10.0.0.1。所选的域名可以是任意名称，但我们建议使用能够描述该 IP 上所托管系统的名称。
  2. 使用此临时域名，而不是 10.0.0.1 （在您的源和出口策略配置中）。

来自 Foundry 内部的网络连接会使用该域名发起请求，而代理会在网络边缘将其解析为正确的私有 IP 地址。

主机覆盖配置会影响代理级别的 DNS 解析，并适用于该代理发起的所有连接。这些映射的优先级高于标准 DNS 查询。

何时使用主机覆盖

您应在以下场景中配置主机覆盖：

  1. 私有网络中只能通过 IP 地址引用的源系统： 从 Foundry 内部发起的网络请求必须使用非私有 IP 地址，以避免基础设施冲突。因此，当使用 代理出口策略 连接到只能通过私有 IP 地址访问且没有可解析域名的源时，请使用主机覆盖将占位域名解析为私有网络内的正确私有 IP。

  2. 本地测试： 在开发过程中测试与 localhost 或其他本地服务的连接时。

主机覆盖需要代理版本 9.2446.0 或更高版本。您可以在 Data Connection 的代理 概述 页面中验证您的代理版本。
