对象监控：自动化工作流

发布日期：2023-01-26

针对业务数据变更触发自动化工作流

对象监控应用旨在让用户随时掌握信息，并基于数据更新中显现的组织事件实现自动化工作流或告警。

Palantir Foundry 用户现在可以使用对象监控应用，在 Foundry 本体论中出现已定义的对象数据变更时设置自动通知或触发操作。对象监控器可为用户跟踪已保存的搜索和对象，基于数据运行，并可作为监控和告警功能整合到 Foundry 应用中。

设置并订阅通知

默认情况下，所有能够与本体论数据交互的用户都可以配置监控器，并让用户和组订阅以接收高度可自定义的通知。这些通知包括自定义的基于 HTML 的电子邮件，或在 Slack、Twilio、Teams 等第三方平台上发送的提醒消息。第三方通知可以通过操作和 webhook 轻松配置。

支持的通知媒介包括但不限于：

  • Foundry 通知中心内的平台内弹窗
  • 基于 HTML 的电子邮件
  • 短信，通过 webhooks 发送至第三方服务，例如 Twilio ↗
  • 即时消息，通过 webhooks 发送至第三方服务，例如 Slack ↗ 或 Microsoft Teams ↗

使用操作自动化您的工作流

可以将对象监控器设置为根据监控条件自动执行 操作 。操作可以对 Foundry 本体论中的数据进行编辑，或通过 webhook修改外部系统中的数据。以下是两个示例用例：

  • 检测数据异常，并自动将这些对象传入包含修复该问题逻辑的操作中。
  • 在满足预配置的事件和时间条件时自动应用操作。操作可以包括通过 webhook 向外部系统发起 API 调用，以直接在外部系统中应用更改。

在一个专用应用程序中管理对象监控器

对象监控应用程序提供了一个整合的单一视图，涵盖用户订阅的所有监控器。用户可以在此处监控已配置的工作流，并根据需要响应全局事件。通过该界面，您可以：

  • 查看统一的活动时间线，以跟踪您所有监控器中的事件。
  • 管理您的活动对象监控器。
  • 配置高级功能，包括：
    • 函数支撑的条件
    • 自定义通知渲染
  • 根据需要诊断并解决问题。

我应该在何时使用对象监控器

当本体论数据通过管道自动更新，且用户希望收到通知或根据这些变更触发操作时，可使用对象监控。当自动化需要由本体论数据变更触发，且预期效果可通过 Foundry 操作执行时，对象监控同样适用于工作流自动化。

如果您的工作流需要固定时间表触发、按用户配置的时间表进行评估，或观察时间序列属性的变化，那么 Foundry 的管道构建器、代码仓库和 Foundry Rules 仍最能满足您的需求。

要了解如何设置对象监控器以自动发送通知或触发操作，请查看 对象监控器文档。

Workshop：随时随地使用移动应用

发布日期：2023-01-17

通过手机轻松访问和采集数据

Workshop 现已支持移动端，帮助您随时随地使用手持设备利用来自本体论的对象类型数据——无需下载应用。您可以使用 Workshop 熟悉的点击式界面来配置应用，使其适用于触摸屏设备，并在用户通过专用的移动应用启动器启动应用时，提供无缝的浏览器内导航体验。

Workshop 以其面向桌面用户的众多交互式应用而闻名，如今 Workshop 应用可经过优化，实现随时随地访问——无论是在诊所、客户现场还是工厂车间——从而支持高度交互的闭环工作流。

解锁您的现场作业

除了作为灵活的应用构建器、支持高度可配置的布局和组件以实现各种工作流之外，Workshop 还可为移动用户提供全方位的额外优势，包括以下几点：

  • 来自本体论的数据可通过多种视图呈现，例如文本、列表、时间线等。
  • 通过专门构建的移动应用启动器，提供简洁流畅的落地体验。
  • 适合移动设备的界面，内置支持页面、抽屉以及多种页面布局选项。
  • 符合 iOS 和 Android 设计规范的直观导航体验。

物理数据增强

在传统桌面功能之外，移动支持使移动中的用户能够直接从物理环境捕获输入。例如，用户可以将手机拍摄的图像提交到 Foundry，通过 QR Code Reader 组件启用二维码扫描，甚至设置地理空间感知功能，例如从企业数据存储中呈现附近感兴趣的对象。

什么时候应该在 Workshop 中创建移动应用？

为了在任何类型的移动设备上为用户提供统一的体验，Workshop 应用现在可以通过移动应用包装器来使用，该包装器针对主流移动网页浏览器优化了呈现效果和访问方式。对于在日常工作中需要在外出或异地办公时访问或更新组织数据的用户，可以考虑在 Workshop 中为他们创建移动应用。启用后，请记得与您的 IT 部门合作， 为应用启用移动浏览器访问。

浏览 Foundry 文档，了解如何在移动模式下构建 Workshop 应用。

Slate：计算对象聚合

发布日期：2023-01-17

Slate 的“平台”选项卡 现在支持基于对象集定义配置 聚合 。这样就无需在 TypeScript 中将聚合逻辑编写为 Foundry 函数（尽管这仍然是一种强大而灵活的方法），并且无需离开 Slate 即可轻松计算总和、平均值等简单指标。详情请参阅 文档。

Pipeline Builder：使用自定义函数复用逻辑

发布日期：2023-01-17

逻辑通常需要在整个管道中重复使用，但当相同的逻辑分散在多个位置时，就很难维护单一事实来源。复制粘贴会导致逻辑重复，且维护负担会随着时间的推移而不断增加。此外，当大量业务逻辑以需要专业知识才能更新的代码形式保存时，加速跨组织协作便可能成为一项挑战。

现在，您可以在 Builder 管道中创建自己的函数套件，并将其用作管道中的一等转换。函数可以基于路径中的单个画板或多个画板来创建。这些函数由人类可读的部分组成，让组织中的非技术用户能够更轻松地参与和使用这些逻辑。您可以通过图视图中的 自定义函数 按钮创建新函数，也可以通过选中一组转换并点击转换路径中的 + 按钮来创建。

推出 Foundry Streaming：实时运营

发布日期：2023-01-01

Foundry Streaming 是指 Foundry 的一组功能，它跨越多个产品和工作流，可实现端到端的低延迟管道。从实时监控和警报到关键业务决策，Streaming 在保持一致的低延迟和高吞吐量的同时，还提供 Foundry 所应具备的所有原语和可扩展性。 要了解各个部分如何协同配合，请查看此 简短演示 ↗ ，其中汇集了流式传感器数据，用于警报、分析和运营应用程序。

与实时数据源的数据连接

流式数据源： Data Connection 应用程序现在支持通过简化设置连接到 Kafka 流。

推送式数据源： 借助流，Foundry 还支持 推送式摄取 以支持基于事件的工作流。Foundry 中的推送式记录摄取遵循与典型 REST 服务相同的原则。我们通过一系列 REST 端点公开了一个推送式 API，可接收记录并将其写入流和数据集。有关开始配置这些数据源的所有详细信息，请参阅 文档。

管道构建器中的流式转换

在流式数据源之上编写逻辑通常既复杂又脆弱，这使运营应用程序无法利用这些低延迟的事实来源。借助 管道构建器对流的支持 生产级管道易于配置且安全，支持流式数据的可用转换、连接和聚合操作日益增多。流式管道可用于支撑 时间序列 以及本体论对象类型。

对于无法在 Pipeline Builder 中表达的流式管道逻辑，Foundry Authoring 支持创建用户自定义函数 (UDF)。

使用流式数据进行分析和构建

建模为 时间序列 的流可在 Quiver 和 Vertex 中使用，以对实时运营数据和 IoT 数据进行实时分析。 Foundry Rules 支持基于流式时间序列构建告警和监控工作流。将流式数据建模为本体论对象类型的 时间序列属性 ，可将流式数据带到运营一线，并在 Workshop 的图表、地图、变量和其他应用构建组件中解锁更多功能。 将这些组件组合在一起，可将实时数据带入运营决策；请在此 简短演示 ↗中查看示例。

下一步是什么？

Foundry Streaming 已经释放了实时传感器和其他实时数据源的价值。以下是我们预计将在 2023 年底前推出的功能：

  • 有状态流式函数： 有状态流处理是正确构建难度最大的流处理形式。考虑到这一点，我们正在投入额外一个季度来强化 API，之后再将该功能广泛推出。
  • 从流中调用外部计算： 很多时候，您需要让低延迟应用走出 Foundry 并查询外部计算资源，例如外部模型或 Lambda 函数。我们正在为这一功能投入基础设施建设，并与早期采用者一起进行试点。
  • 更多数据连接器： Kafka 是一个良好的开端，但还有许多流数据源值得拥有一流的数据连接器。如果您需要特定的连接器，请联系 Palantir 代表。
  • 数据导出： 为了形成闭环，流数据有时需要在 Foundry 中经过富化和转换后回流到源系统。我们已推出其中部分导出连接器的测试版，并正在投入打造一流的导出解决方案。
