FTP/FTPS

将 Foundry 连接到 FTP 和 FTPS 服务器，以在文件夹与 Foundry 数据集之间同步数据。

数据模型

连接器可以将任何类型的文件传输到 Foundry 数据集中。文件格式会被保留，在传输过程中或传输完成后均不会应用任何 schema。请对输出数据集应用任何必要的 schema，或编写一个 下游转换 来访问数据。

性能与限制

可传输的文件大小没有限制。但是，网络问题可能导致大规模传输失败。特别是，在 Foundry worker 上运行超过两天的同步将被中断。为避免网络问题，我们建议使用较小的文件大小，并限制每次同步执行中摄取的文件数量。同步可以 被安排 频繁运行。

身份验证

FTP/FTPS 身份验证使用用户名和密码完成。如果 FTP 用户对为连接配置的根目录没有权限，FTP/FTPS 连接可能会失败。请参阅 配置选项 以了解有关根目录的更多详细信息。

网络

如果您的 FTP/FTPS 连接 在 Foundry 中运行，则您必须添加一个 网络出站策略 以将该连接加入白名单。

如果通过域名进行连接，应针对控制端口（通常为端口 21）和数据端口为 FTP 服务器域创建出站策略。我们建议创建两个网络策略：一个用于控制端口的单端口策略，以及一个用于数据端口的端口范围策略。数据端口由 FTP 服务器的管理员确定。如果在正确配置出站策略后仍持续出现错误， 请提交一个问题 并附上所应用的策略列表。

如果服务器的域名解析到多个域名和/或服务器，则需要将所有关联的域名及其相关 IP 加入白名单。要验证服务器是否解析到多个域名和/或服务器，请运行命令 dig <domain> 在您的终端中针对您尝试连接的服务器运行该命令，并查看应答（answer）部分。

证书与私钥

按照以下指南配置额外的客户端或服务器证书及私钥，以正确设置您的连接器。

SSL 与主机名验证

SSL 连接会验证服务器证书。通常，SSL 验证通过证书链完成；默认情况下，代理和 Foundry worker 均信任大多数行业标准证书链。如果您连接的服务器使用自签名证书，或者防火墙对该连接执行 TLS 拦截，则连接器必须信任该证书。了解更多关于 在 Data Connection 中使用证书.

服务器必须提供完整的证书链，SSL 验证才能正常工作。要获取 FTP 服务器的证书链，请运行命令 openssl s_client -connect {hostname}:{port} -showcerts -starttls ftp，然后使用 OpenSSL 命令行工具或任何其他可用工具验证该证书链。如果您使用的是 FTPS，请确保已将 FTPS 服务器的证书添加到代理的信任库中。

Foundry 会对所有出站路由尝试进行主机名验证。但是，FTP 无法被检查，这会导致连接挂起和/或超时错误。如果在正确配置出站策略后仍持续出现错误， 提交问题 并附上您希望禁用主机名验证的策略列表。

隐式/显式 SSL

FTP 服务器可配置为支持显式或隐式 SSL。运行在端口 990 上的服务器通常使用隐式 SSL。

请与服务器管理员确认服务器的设置。默认情况下，连接器采用显式 SSL；您可能需要根据您的环境更改此设置。

连接要求

FTP 需要 CONTROL 和 DATA 连接类型。 DATA 连接必须配置为 ACTIVE or PASSIVE 模式。

  • CONTROL（控制连接）： 客户端到服务器
  • DATA（数据连接）： 从某个范围内选择的数据（例如 1024–1123）
    • PASSIVE（被动模式）： 客户端到服务器
    • ACTIVE（主动模式）： 服务器到客户端
      • 仅适用于代理连接

默认 FTP/FTPS 连接器端口：

  • FTP：21
  • FTPS 显式：21
  • FTPS 隐式：990

主动模式和被动模式

我们建议使用 被动模式 网络连接。在被动模式下，所有连接均由客户端发起。使用被动模式时，请确保控制端口（通常为 21）和用于数据传输的端口范围（例如 1024–1123）已加入允许列表。请联系您的 FTP/FTPS 服务器管理员以获取连接详情。

主动模式 是一种较旧的文件传输建立方法。在主动模式下，客户端连接到服务器，同时服务器也连接到客户端。服务器和客户端相互依赖，需要 双向 网络连接。这种网络方法在大多数安全环境中通常难以实现，并且仅在使用代理连接时才可行。

故障排除

代理连接

  • 您在设置代理连接时遇到问题了吗？请安装一个 FTP/S 客户端，并尝试使用与数据源相同的配置连接到服务器。如果此连接失败，则问题并非连接器缺陷。在提交问题之前，请先排查网络连接、身份验证和 FTP 服务器配置。

  • 您是否在使用出口代理负载均衡器？FTP 是一种有状态协议，因此如果连续请求并非来自同一 IP，使用负载均衡器可能会导致同步（非确定性地）失败。

SSL 和 FTPS

  • 您的服务器是否使用自签名证书？您是否已将其添加到数据源信任库中？请参阅 SSL 与主机名验证 上方的章节。

  • 您的 FTP 服务器是否仅支持旧版 TLS（例如 TLS 1.1）？如果是，连接器运行时可能无法接受该服务器提供的任何密码套件。请提交工单，与 Palantir 代表探讨替代方案。
