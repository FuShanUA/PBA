添加地理时间序列输出

您可以将地理时间序列同步输出添加到管道中，使 Foundry 中的批量或流式地理时间数据可供下游应用程序（例如 Map 应用程序）使用。来自 Foundry 的地理时间观测数据在 Pipeline Builder 中写入。了解更多关于 不同输出类型 和 地理时间序列.

前提条件

要在 Pipeline Builder 中使用地理时间序列，必须为您的租户启用该功能。请联系您的 Palantir 代表以了解有关启用此功能的更多信息。

创建地理时间序列输出

打开 管道输出 面板位于 Pipeline Builder 界面的右侧。然后，选择 Add > Geotemporal series sync > Add 以创建新的地理时间序列。

如果您在 Pipeline Builder 中看不到地理时间序列输出类型，请检查您的租户是否满足上述 先决条件 。

映射主字段

Pipeline Builder 中的所有地理时间序列输出都有主字段（即固有字段），这些字段必须作为管道上游转换逻辑的一部分生成。这些字段控制从管道中的行到地理时间观测数据的转换。请参阅 地理时间序列数据建模 以了解有关主字段的更多信息。这些主字段包括：

  • 序列 ID： 一个字符串值，用作集成中每个轨迹的唯一标识符，例如用于区分不同航班的航班标识符。请参阅 地理时间序列数据建模 以获取有关选择序列 ID 的更多示例。
  • Timestamp： 表示给定观测时间的值。
  • 位置： 一个 GeoPoint 值，表示观测时的位置。Pipeline Builder 中的 GeoPoint 值可以使用 Construct geopoint column 表达式在上游转换逻辑中根据纬度和经度坐标创建。
  • 海拔： 一个可选的 Double 类型的值，表示距地球表面以上的高度（以米为单位）。

映射其他字段

除了上述必填字段外，您还可以将自定义字段映射到输出观测数据。为此，请导航到地理时间序列输出面板的 属性 部分并选择 添加属性。选择一个上游转换逻辑输出列，使相应的值出现在下游观测数据中。您必须指定名称、映射是实时的还是静态的，以及可选的字段说明文档。实时属性随每次观测而变化，例如飞机的航向。静态属性在整个序列中保持不变，用于反规范化以支持搜索和筛选功能，例如飞机类型。

除了 Pipeline Builder 中的标准数据类型外，地理时间序列输出还支持将特殊几何类型映射到地理时间序列数据模型中的对应类型。请参阅 Pipeline Builder 的地理空间文档 以了解有关这些类型的更多详细信息：

  • GeoPoint： 单个点，可在下游地图上渲染，并且可以与"位置"主字段中设置的点不同。
  • Geometry： 一个 GeoJSON 对象，可在下游地图上渲染。

部分中选择

除了基本输出映射外，地理时间序列输出还支持以下高级可选设置：

  • 生存时间： A long 类型值，表示数据被视为过期或失效前的时间量（以毫秒为单位）。过期数据不会在下游应用程序中渲染。这仅适用于 热存储功能.
  • 观测类型： A string 类型值，表示用于在下游应用程序中筛选数据的逻辑分类，例如"GPS ping"或"manual report"。
  • 样式配置： 允许用户配置观测数据在下游应用程序中的外观。支持的属性包括图标大小、不透明度、旋转、符号、标题、几何宽度、几何颜色、几何填充、几何不透明度和轨迹颜色。
  • 观测模式： 您可以选择一个现有的 观测模式 作为地理时间序列的一部分。这样做将预填充与该模式关联的所有字段作为要映射的属性。为了支持向后兼容，您将无法删除、更改现有字段，或在实时与静态之间切换现有字段。如果您不选择现有模式，则在管道输出首次成功部署后，将为您的集成创建一个新模式。
  • 源系统： 源系统是不同地理时间序列同步的分组，您可以选择重复使用。如果您选择一个现有源系统，则在成功部署后，生成的地理时间序列集成将被 upsert 到指定的源系统。源系统中的现有集成不会被修改。如果您不选择现有源系统，则在管道输出首次成功部署后将创建一个新的源系统。默认情况下，给定管道内的所有地理时间序列输出将被分组到与该管道对应的源系统中。
  • 目标命名空间： 如果用户有权访问配置了地理时间输出序列的多个命名空间，则可以指定管道将观测数据导出到的目标命名空间。更多详细信息请参阅 有关如何思考问题类别并识别它们的更多细节。请联系您的 Palantir 代表以获取配置其他目标的指导。

热存储和冷存储

地理时间序列同步可以写入两个专门的观测数据库：

  • 热存储： 默认设置，针对实时访问进行了优化。存储一定时间的观测数据最终将从存储中删除。
  • 冷存储： 将观测数据存储在 Foundry 数据集中，并遵循 数据保留策略。当观测数据必须长期存储以进行地理时间查询时，请使用冷存储。

在某些工作流中，从冷存储读取观测数据的支持有限。请根据您的用例联系 Palantir 支持以获取更多信息。

安全性

下游地理时间序列观测的安全性源自您的管道输入数据：

  • 强制权限：
    • 下游观测将由 Pipeline Builder 中地理时间序列输出数据集上的最新输出事务或流式视图保护。此资源将把从输入数据集继承的强制或分类标记传播到管道。
    • 如果上游输入数据的标记在地理时间序列输出的构建之间发生变化，则后续构建将失败，以防止先前集成的数据标记发生意外更改。在这种情况下，您必须删除并使用适当的标记重新创建地理时间序列输出。
    • 所有管道输入必须具有组织标记，且这些标记有权访问为相应地理时间序列输出配置的目标命名空间。地理时间序列输出上存在的组织标记必须是具有该输出命名空间访问权限的组织的超集。
  • 自主权限：
    • 当地理时间序列输出首次部署时，对父项目具有读取权限及更高权限的所有组将被授予对下游地理时间序列输出的查看权限。父项目自主权限的后续更改不会传播到下游观测。如果您的地理时间序列工作流需要更细粒度的自主权限，请联系您的 Palantir 代表。

地理时间序列同步 RID

在 Pipeline Builder 图中选择您的地理时间序列同步输出节点，以从 元数据 部分复制其 RID，位于 地理时间序列集成 RID.

故障排除

在管道部署并触发构建后，观测数据应很快流入您的地理时间序列。如果数据未出现在下游应用程序中，您可以使用以下步骤进行故障排除：

  • 验证数据是否已显示在 Pipeline Builder 的观测输出数据集中，方法是导航到 输出 右侧面板，选择输出旁边的三个点，然后选择 查看支撑数据集。
  • 通过选择以下选项检查错误数据集中是否存在错误 查看错误数据集 菜单中选择 输出 上述面板。
  • 检查错误日志，以确认当前正在运行的管道构建中是否存在运行时故障。可以通过以下入口访问 历史记录 Pipeline Builder 中的选项卡。
  • 通过确保下游资源包含必要的分类标记、强制标记和可自由裁定的组，以查看底层地理时间序列，从而验证下游应用程序中不存在安全配置错误。
