定义数据期望

数据期望 是在代码中对数据集、 虚拟表日 Iceberg 表 输入或输出上定义的一组要求。这些要求或“期望”可用于创建检查，以提高数据管道的稳定性。如果数据期望检查在数据集构建过程中失败，构建可以自动中止，以节省时间和资源，并避免下游数据出现问题。数据期望与 数据健康 集成以进行监控。

开始使用，请查看 指南 （位于 Python Transforms 文档中），或查看 参考 所有可用期望的列表。

使用数据期望的好处

  • 管道保护 - 由于期望作为构建的一部分运行，您可以在期望失败时中止构建，防止下游故障和坏数据传播到下游资源。
  • 变更管理 - 由于期望是在代码仓库中定义的，更改它们将需要与受保护分支上设置的相同的拉取请求审查流程。
  • 主动测试 - 在将更改合并到受保护分支之前，通过在开发分支上构建来预先发现检查失败

术语

  • 期望 - 对数据结构或内容的强类型要求（例如列不为空）
  • 检查 - 一个有意义的期望（可以是多个期望的组合），连接到转换中的单个数据集（输出或输入）。检查具有一个名称，用于识别和监控它（例如“对象模式验证”）。
    • 前置条件 - 分配给转换输入的检查，通常用于在继续构建之前验证对输入结构或内容的关键假设。
    • 后置条件 - 分配给转换输出的检查，通常用于保证数据集 SLA 得到维护并保护下游依赖项。
  • 检查结果 - 在检查运行（构建期间）时生成，包含期望结果及其明细信息。检查结果可以在 Data Health 中监控。

它是如何工作的？

对象

数据期望在相关代码仓库中的数据集转换上定义。检查可以应用于转换的输入和输出（详见 该指南 ）。检查名称在单个转换中必须唯一。

除了期望之外，检查还定义了构建期间如何处理失败。当检查失败时，构建可以中止，也可以在警告下继续。

检查在 CI 期间注册到相关分支上。更改受保护分支上的期望将需要拉取请求，就像任何其他代码更改一样。

在对受保护分支进行更改时，建议在开发分支上构建数据集，以确保在将更改合并到默认分支之前满足您的数据期望。

运行

注册的检查将作为构建作业的一部分运行。未满足数据期望的情况将在 构建应用程序 和数据集的 历史记录选项卡中突出显示。如果检查定义指示出错时失败（FAIL on error），作业状态将变为“已中止”并附带相应的错误。在作业时间线中，您可以找到“期望”指示器；点击该指示器将显示检查结果以及各个期望的明细。

当 前置条件 失败，转换的输出将被中止（而不是定义前置条件的输入）。要中止输入数据集的构建，数据期望必须定义为 后置条件 （在输入数据集转换上）。

监视器

每次检查运行都会产生一个 结果 ，该结果会报告给 数据健康。最近的数据期望结果将显示在数据集预览应用程序的 健康选项卡 中，您可以在其中设置通知和问题触发器（类似于其他 Data Health 检查）。

请记住，数据集上的检查通过其名称唯一标识。检查的历史记录及其各个监控设置，只在其名称不变的情况下才会保留。更改检查的名称等同于删除旧检查并在原位置创建一个新检查。

增量

所有检查都在完整数据集上运行，无论转换是否为增量式。

例如，假设我们对一个以增量方式运行的转换的输出进行主键检查。由于数据期望检查总是在 完整 数据集上运行，因此如果新事务（即将以增量方式写入）中包含一个新的主键，而相同的主键已经（在先前的事务中）被写入，则该检查将失败。
