Beta

SuperRepo 处于 beta 开发阶段，可能无法在您的注册中使用。在积极开发期间，功能可能会发生变化。

代码仓库要成为 SuperRepo，必须在其根目录下有一个 foundry.yml 文件，用于声明项目结构：每个组件的类型和路径。此文件还允许您声明输出产物（一个 Marketplace 产品）甚至多个输出。

添加多个产品

使用多产品配置时，请将 --product <bundle name> 选项传递给每条 Foundry CLI 命令，以指示要针对哪个产品运行。

要将某个产品从打包输出中排除，但不将其从文件中移除，请在该产品上设置 includeInBundle: false 。该选项默认为 true （省略时）。

打包多产品 SuperRepo

单产品 SuperRepo 可通过一条命令打包，即 foundry bundle --project-version <VERSION>。该命令不接受多产品配置：如果 foundry.yml 声明了多个产品，该命令将失败，并引导您改用下面的两个子命令。

分两个阶段打包多产品 SuperRepo：

  1. 运行 foundry bundle product --product <bundle name> --project-version <VERSION> 每个产品运行一次。每次调用都会将该产品的打包输出写入 build/<bundle name>/blockset.zip。由于 --project-version 是按每次调用提供的，因此同一仓库中的产品可以独立进行版本管理。
  2. 运行 foundry bundle store 以将这些输出组装为 build/store.zip。此命令不接受任何版本参数；传入 --output 以将存储写入其他位置。如果产品尚未捆绑，该命令将失败，并显示预期路径以及 foundry bundle product 生成该产品所需的调用。

这两个阶段均不由 foundry deploy隐含，该命令要求存储已经存在，否则将失败。请先捆绑，再部署。

定义种子数据

在预览期间， foundry 会启动一个本地 嵌入式本体论 服务器。该服务器可以识别在您的 SuperRepo 本体论组件中定义或导入的类型。但是，它并未连接到您注册的本体论。因此，您的对象类型的实例并非来自您的注册；它们仅在本地存在，且仅在本地有效。您可以通过调用与对象关联的创建操作来手动创建对象，也可以利用 SuperRepo 的自动种子数据填充基础设施。

种子数据是一个由 TypeScript 文件组成的目录，位于 ONTOLOGY 组件。本地预览服务器会通过项目所选编排框架（例如 Nx）指定的命令行参数来发现它。

只有顶层 .mts 文件会被编译，并按文件名排序后的顺序进行处理，这就是演示模板将它们编号为 001-、 002-和 003-。每个文件默认导出一个 createSeed 调用。传递给 seed.add 的第一个参数是为该对象类型生成的 SDK 常量，且每个不可为空的属性都是必需的，包括主键。在整个目录范围内，同一对象类型的主键必须唯一。 seed.link 函数会接收由 seed.add返回的引用，并且两端都必须在同一次调用中注册。

import { seller, superproduct } from "@ontology/sdk";
import { createSeed } from "@osdk/seed-helpers";

export default createSeed((seed) => {
  const charger = seed.add(superproduct, {
    pk: "prod-004",
    title: "USB-C 100W GaN Charger",
    price: 5900,
    newPrice: 4720,
    description: "Compact 100W USB-C GaN wall charger",
  });
  const halcyon = seed.add(seller, {
    pk: "seller-003",
    name: "Halcyon Desk Co.",
  });
  seed.link("charger-seller-link", charger, "sellers", halcyon, "superproducts");
});

每次运行都会使用一个全新的本地数据库，因此种子文件在每次启动时都会重新应用，而通过本地服务器编辑的对象在重启时会被丢弃。

更换编排框架

该 foundry create 命令会配置 Nx，但 CLI 既不读取 nx.json 文件，也不读取 project.json 文件。因此，SuperRepo 和 Foundry CLI 独立于您所选择的编排框架。默认模板使用 Nx 是因为它应用广泛；若要从 Nx 迁移到其他框架，请将 Foundry CLI 调用从 project.json 文件移植到另一个系统中。

在迁移过程中，您必须用 foundry run-with-auth来包装每一次 Node 安装。它会注入 FOUNDRY_HOSTNAME 以及 FOUNDRY_TOKEN 以便 .npmrc 文件可以依赖这些环境变量。

内容安全策略

当您的应用程序使用来自其他源的资源时，您必须在 Foundry 为您的产品托管的网站的内容安全策略（CSP）中允许这些源。否则，浏览器会拦截该请求。如需声明新增内容，请使用 contentSecurityPolicyAdditions 键：

Copied!
1
2
3
contentSecurityPolicyAdditions:
  img-src:
    - tile.openstreetmap.org

每个键都是标准的 CSP 指令名称，每个值都是允许的来源列表，例如 https://api.example.com 或 'self'。以下指令名称是有效的： connect-src、 frame-src、 img-src、 media-src、 script-src、 style-src、 font-src和 frame-ancestors。

contentSecurityPolicyAdditions 是一个按产品设置的键，与 components 和 bundle一起声明，并且仅当产品包含 APP 组件时才适用。在单产品 foundry.yml 中，该键因此出现在文件的顶层，如上所示。在多产品配置中，请在需要它的每个产品中进行声明，如 添加多个产品 部分所述。

平台 API 代理

应用程序通常会调用 通过本体论 SDK 访问的 Foundry 平台 API。SuperRepo 本地预览服务器实现了这些平台 API 中的一部分，但并非全部。例如，要使用平台 API 的 LLM 提供商代理 ，就必须向您的 Foundry 注册实例发起请求。

SuperRepo 预览支持将 API 调用代理到远程 Foundry 实例，方法是定义顶层 platformApiProxy 键，该键位于 foundry.yml 文件中，如以下示例所示：

platformApiProxy:
  passthrough:
    - path: /api/v2/admin/users/getCurrent
      methods: [GET]
    - path: /api/v2/llm/proxy/openai/v1/responses
      methods: [POST]

声明这些路径后，预览服务器会响应本体论 SDK 客户端针对上文列出的路径和方法发出的请求。这些请求将被代理到您的 Foundry 注册，所使用的是由 foundry login存储的凭据，而不是您在安装 Foundry CLI时导出的令牌。如果被代理的请求开始因授权错误而失败，则您存储的令牌很可能已过期；请运行 foundry login refresh 以重新授权。

该 platformApiProxy 配置不会影响已部署的产品，仅在预览期间有效。
