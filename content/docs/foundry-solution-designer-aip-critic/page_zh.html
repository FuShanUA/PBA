AIP Critic

AIP Critic 是一款由 AI 驱动的图表审查与分析工具，可通过交互式对话帮助您评估解决方案架构。AIP Critic 会检查您的图表，将其组织成逻辑分区，并解答有关架构设计、实施方式以及潜在改进的问题。在 Solution Designer 中，AIP Critic 提供基于聊天的界面，您可以在其中就图表提问并获得结合上下文的指导。该工具会自动分析图表结构、对组件进行分类，并基于 Palantir 平台的最佳实践提供洞察。

何时使用 AIP Critic

使用 AIP Critic 可以：

  • 验证您的架构设计并识别潜在问题。
  • 获取有关替代方案或改进的建议。
  • 了解您的解决方案中不同组件如何交互。
  • 根据您的图表生成实施建议。

打开 AIP Critic

要打开 AIP Critic，请选择您的 Solution Designer 图表工具栏中的 AIP Critic 图标。AIP Critic 面板会在您工作区的左侧打开。

图表组织

AIP Critic 会自动将您的图表中的节点组织成以下分区：

  • 外部系统： Foundry 之外的第三方系统、数据库或数据源。
  • 数据引入： 将数据引入 Foundry 的组件，例如在 Data Connection 中创建的数据源，或手动上传的文件。
  • 数据处理： 转换、管道和数据准备组件。
  • 建模： 机器学习模型、预测和优化组件。
  • 本体论： 对象类型、关联类型、操作、接口和语义数据模型。
  • 分析： 仪表板、报表和分析应用程序。
  • 应用程序构建： Workshop 应用程序、Slate 和其他面向用户的界面。
  • 平台管理： 管理、治理和平台配置工具。
  • 自定义组件： 不属于上述类别的任何其他组件。

这种组织方式有助于 AIP Critic 提供上下文感知的响应，并提出与您架构各部分相关的建议问题。

向 AIP Critic 提问

您可以用自然语言向 AIP Critic 询问有关图表的问题。在 AIP Critic 面板底部的文本输入框中输入您的问题，然后按 Enter 键，或选择 发送。

您可能会问的示例问题：

  • "此数据管道中的潜在瓶颈有哪些？"
  • "如何才能提升此工作流的性能？"
  • "此架构应遵循哪些最佳实践？"
  • "是否有任何需要考虑的缺失组件？"
  • "在此设计中应如何处理数据质量问题？"

AIP Critic 将分析您的图表，并根据您解决方案架构的组件、连接和整体结构提供响应。

下钻对话

收到 AIP Critic 的回复后，您可以通过提出后续问题来深入了解答案的具体部分。AIP Critic 会保留对话的上下文，让您能够更深入地探索相关主题。

要对回复进行深入探究，请先查看 AIP Critic 的初始回复，然后输入引用或扩展先前回复的后续问题。AIP Critic 将在保留对话上下文的同时提供更多细节。

深入探究对话允许您：

  • 请求澄清特定要点。
  • 探索所建议方法的替代方案。
  • 询问实现细节或示例。
  • 研究不同选项之间的权衡。

生成实施计划

AIP Critic 可以根据您的架构图生成结构化的实施计划。实施计划对话框提供了如何构建解决方案的分步说明，包括：

  • 阶段与任务： 用于实施图中每个组件的有条理的步骤。
  • 依赖关系： 哪些组件需要先于其他组件构建。
  • 最佳实践： 每个实施步骤的推荐方法。
  • 资源估算： 每个阶段的大致工作量或复杂程度。

要生成实施计划，请选择 生成实施计划 位于 AIP Critic 面板底部。AIP Critic 会分析您的图表，并在打开实施计划对话框之前创建结构化计划，以可折叠分区的形式展示每个阶段的计划。请审阅该计划，展开各分区以查看详情，并将其作为构建解决方案的指南。

在构建过程中，您可以同时参考实施计划和图表，这有助于确保您遵循最佳实践并按正确的顺序构建组件。此外，您可以使用 AI FDE 来加速架构中资源的实际构建。您还可以将实施计划导出为 PDF，用于文档记录或与团队共享。

审阅持久化

您与 AIP Critic 的对话会自动随图表一起保存。当您关闭并重新打开已保存的图表时，之前的对话历史将会恢复，让您可以从上次中断的地方继续审阅。

最佳实践

使用 AIP Critic 时，请考虑以下最佳实践：

  • 从宽泛的问题开始： 先就整体架构提出高层次的问题，然后再深入具体细节。
  • 提供背景信息： 如果您的图表代表特定的用例或具有独特的要求，请在问题中说明这一点。
  • 迭代设计： 使用 AIP Critic 的反馈来完善您的图表，然后针对更新后的设计提出后续问题。
  • 记录决策： 将实施计划导出为 PDF 文档，以保留架构决策记录。
  • 与 AIP Architect 结合使用： 使用 AIP Architect 来生成初始工作流计划，然后使用 AIP Critic 对其进行审查和完善。
