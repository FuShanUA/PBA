添加数据集输出

您可以选择在 Pipeline Builder 中添加数据集输出，以引导您的管道集成为干净、转换后的数据。了解更多关于 不同输出类型的信息.

创建数据集输出

首先，点击 将 （位于图右侧的输出面板中数据集类型旁边）。

现在您已创建了一个新的输出数据集。在管道首次构建后，您的数据集输出将在与管道相同的文件夹中创建。例如， Vendor Demo Pipeline 的数据集输出将具有以下文件路径： /Palantir/Pipeline Builder/Demo Pipeline/Vendor.

通过点击名称字段来重命名您的输出数据集。选择 添加列 以手动向输出架构中添加列，或连接一个转换节点以使用其输出架构，通过 使用更新后的架构.

添加输出架构后，使用 搜索列... 字段可快速查找数据集中的列。要仅查看输出架构中的错误，请切换 仅显示错误 按钮。

添加输出数据集后，点击 返回所有输出 以查看管道中所有输出的列表。一目了然地了解每个输出的状态，包括输出架构是否与输入转换节点架构匹配。以下三个输出展示了输出架构可能具有的不同状态：

  • 数据集 1 包含 5/5 个必需列，这意味着输入转换节点中的每一列都将在输出数据集中构建。
  • 数据集 2 包含 3/3 个必需列，其中 2 列被丢弃，这意味着输入转换节点有 5 列，但只有 3 列将在输出数据集中构建。当输入转换节点中存在不必要的列时，这是理想的做法。
  • 数据集 3 包含 5/7 个必需列，这是一种错误状态。在 2 个缺失的列映射到输入转换节点中的列之前，您将无法部署管道。

点击设置菜单下的 编辑 以随时更新输出架构。

了解更多关于数据集架构的信息，请参阅 数据集成.

要在数据集输出中包含媒体引用列，请添加一个 媒体集 作为管道输入，并将其媒体引用列连接到您的输出数据中。了解更多关于 在 Pipeline Builder 中转换媒体的信息.

配置输出设置

除架构配置外，每个单独的输出还有多种可自定义的默认设置。

配置期望

在输出数据集上添加期望以增强管道稳定性。如果在管道构建期间任何检查失败，构建将失败。

配置写入模式

定义在未来的部署中如何将数据添加到数据集输出。

默认： 建议大多数批处理管道使用此模式，无论是 快照还是增量。默认写入模式将在以下情况下将结果输出为 APPEND 事务：至少一个输入被标记为增量，且所有被标记为增量的输入自上次构建以来仅发生过 APPEND 或附加 UPDATE 事务。否则，默认写入模式将把结果输出为 SNAPSHOT 事务。了解更多关于 事务类型的信息.

快照替换： 将结果输出为 SNAPSHOT 事务，其中新数据与先前的输出合并。先前输出中已存在的主键将被丢弃，以优先使用新行。如果当前事务中存在重复行，则随机保留其中一行，其余均被丢弃，以确保输出中每个主键仅包含一行。

快照替换并移除： 这等同于 快照替换，随后是一个后过滤阶段，用于有选择地从旧数据中移除行。将结果输出为 SNAPSHOT 事务，其中新数据与先前的输出合并，随后是一个后过滤阶段，根据提供的布尔值从先前的事务中移除行 post_filtering_column。先前输出中已存在的主键将被丢弃，以优先保留新行，前提是 post_filtering_column = TRUE。但是，如果当前事务中存在某行，其 post_filtering_column = FALSE 对应于给定的主键，则旧数据中相应的行将被过滤掉。但是，这不会覆盖新行的存储，即带有 post_filtering_column = TRUE的新行。如果重复行带有 post_filtering_column = TRUE 存在于当前事务中，则除其中一行外，其余行将被随机丢弃，因此输出中每个主键仅包含一行。

变更日志： 输出一系列 APPEND 事务，其中包含所有记录的完整变更历史。在 Object Storage v1中，您可以通过将以这种方式配置的 Changelog 数据集设置为支撑数据源，来优化对象类型的同步性能。了解更多关于 Changelog 数据集.

仅追加新行： 将结果输出为 APPEND 事务，其中只有新行（定义为新出现的主键）会被添加到输出中。如果当前事务中存在重复行，则会随机丢弃其中一行。主键已存在于先前输出中的行将被丢弃。

直接变更日志： 输出行将被视为变更日志，从而可以完全控制变更日志的内容。变更日志元数据直接写入输出数据集。每行必须指定主键、时间戳和表示删除的布尔值。了解更多关于 Changelog 数据集.

对象存储 v2 会忽略提供的时间戳列，而是使用事务 ID 对具有相同主键的行进行去重。

仅快照新行： 将结果输出为 SNAPSHOT 事务，其中输出中仅保留具有新出现主键的行。如果当前事务中存在重复行，这些行将被保留。所有其他行将被丢弃。

始终追加行： 将结果输出为 APPEND 事务。

数据集写入格式

数据集的输出文件格式可以在初始部署后更改，并将在管道的下一次部署时生效。了解更多关于 文件格式.

覆盖数据集

一次性操作，将现有数据集的所有权授予 Pipeline Builder 中的新输出。此操作可能需要在 Pipeline Builder 之外执行额外的操作。

构建数据集输出

将数据集输出添加到管道后，请务必保存更改。如果您已完成数据转换和管道工作流的定义，就可以部署管道并构建数据集输出了。部署管道后，请在 本体论管理器.

本体论编辑： 部署您的管道.
