通过整体电网网络建模改善决策

行业领域： 公用事业

业务职能： 运营

在一家欧洲公用事业公司，Foundry 被用于创建丰富的数据资产，该数据资产进而推动下游的其他用例，包括：

  • 停电响应与根因分析
  • 以不同粒度报告资产和 KPI
  • 用于监管报告的停电审查与验证

挑战

公用事业公司的资产管理团队负责维护电网稳定性并缩短停电时间。这不仅涉及重要的监管要求（例如，德国要求公用事业公司的系统平均停电持续时间指数（SAIDI）得分低于每客户 12 分钟），而且对其能否续签供电特许经营合同也至关重要。

由于地理资产系统和电网系统相互孤立，这家公用事业公司缺乏对电网状态的全面、最新视图，从而延长了停电响应和根因分析的时间。

解决方案

该公司用于跟踪电网状态和地理信息的各种数据源被整合到 Foundry 中的一个本体论中，该本体论进而被应用于各种运营工作流，以更好地管理其资产。

利益相关者和用户群体

  • 资产管理
  • 资产管理数据团队
  • 针对电网不同部分的各个业务职能
  • 数据源所有者

影响

  • 电网数字孪生基于数万个坐标、电网、电缆、电路和关系构建而成。Foundry 的数据集成能力和互操作性意味着，除了解锁全新的资产管理工作流之外，Foundry 与其 PSI 控制系统的集成还能将丰富的数据回传到现有的运营系统中。
  • 这一版本的本体论耗时约 12 个月才得以实施，但随后已被转换为库，只需数周时间即可完成部署。

工作原理

来自 PSI 控制系统的电网资产数据和地理（GIS）数据首先通过转换实现统一，以确保二者相互匹配，并为两者启用了回写功能。利用这一统一的数据资产，对象创建于 Object Explorer。

网络拓扑是多个用例的基础，例如停电定位应用（在 Slate 中实现），该应用提供了一种新方法，用于确定造成停电的原因最可能出现的位置（例如，树木倒在某些电缆上）。

电网网络拓扑被建模为 本体论 对象和视图，用于表示不同的网络元素。可视化使用 Object Explorer 地图、 Quiver 图表以及其他常用的 Object Explorer 小部件。
