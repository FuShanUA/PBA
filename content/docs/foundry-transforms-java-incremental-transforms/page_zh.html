增量计算是一项高级功能。在使用此功能之前，请确保您已理解用户指南的其余部分。

如果有新数据添加到 /examples/students_hair_eye_color 输入数据集， filter() 将在整个输入上执行，而不是仅针对添加到输入的新数据。这在计算资源和时间上都是浪费的。

如果转换能够感知其构建历史，它就可以更智能地计算其输出。更具体地说，它可以使用对输入所做的更改来修改输出数据集。这种在重新物化表时使用已物化数据的过程称为 增量计算。如果没有增量计算，输出数据集总是会被转换的最新输出替换。

编写增量转换

我们将逐步指导您如何使用 transforms-java编写增量转换。与 transforms-python, transforms-java 不同，它不使用注解来自动验证增量性并以增量方式应用转换。在 Java 中编写增量转换的过程由用户更直接地控制，用户可以明确决定在哪种情况下转换应以增量方式执行，以及在哪种情况下不应如此。通过解释输入数据集是如何被修改的，用户可以决定是以增量方式还是以快照方式更新输出数据集。

解释您的输入

第一步涉及对输入的解释。输入数据集可能以多种方式被修改，而我们只能在某些特定情况下应用增量转换。DataFrameModificationType（或 FilesModificationType）表达了数据集可以被修改的不同方式。不同的模式包括：

  • APPENDED
  • UPDATED
  • NEW_VIEW
  • UNCHANGED

根据输入的变化方式，我们可以决定从输入数据集读取什么以及向输出数据集写入什么。

读取输入

了解输入是如何被修改的使我们能够相应地读取它。如果某个事务仅追加了数据，我们可以确定能够安全地以增量方式操作，并且仅读取被修改的部分。相反，如果输入数据集的更改包括对已存在行的修改，我们可能需要重新读取整个视图。 Transforms-Java API 借助 readForRange() 方法为输入数据集提供了不同的读取模式。ReadRange 公开了可能的读取范围。不同的模式包括：

  • UNPROCESSED
  • PROCESSED
  • ENTIRE_VIEW

通过解释输入修改类型，我们可以决定如何读取数据，如下面的示例所示。

private ReadRange getReadRange(FoundryInput input) {
     switch (input.asDataFrame().modificationType()) {
         case UNCHANGED:
             LOG.info("No changes in input dataset, read only unprocessed");
             return ReadRange.UNPROCESSED;
         case APPENDED:
             LOG.info("Append-only changes in input dataset, read only unprocessed");
             return ReadRange.UNPROCESSED;
         case UPDATED:
             LOG.info("Update-type changes in input dataset, read entire view");
             return ReadRange.ENTIRE_VIEW;
         case NEW_VIEW:
             LOG.info("New view in input dataset, read entire view");
             return ReadRange.ENTIRE_VIEW;
         default:
             throw new IllegalArgumentException("Unknown ModificationType for input dataset "
                 + input.asDataFrame().modificationType());
     }
}

WriteMode.UPDATE 和 DataFrameModificationType.UPDATED 并不等价

使用文件编写增量低级转换

通过 ReadOnlyLogicalFileSystem 和 WriteOnlyLogicalFileSystem（而不是通过 DataFrame）读取和写入原始文件的低级转换，遵循上述相同的增量原则。主要区别在于读取范围和写入模式的设置位置：在 FoundryFiles 和 FoundryOutput返回的文件系统对象上设置，而不是在 Dataset<Row> 读取器和 DataFrameWriter.

选择读取范围和写入模式

FoundryInput.asFiles() 返回一个 FoundryFiles 对象。其 modificationType() 方法返回一个 FilesModificationType，即基于文件的 DataFrameModificationType等价物。使用修改类型来选择这两个设置：

FilesModificationTypeReadRangeWriteMode
UNCHANGED or APPENDEDUNPROCESSEDUPDATE
UPDATED or NEW_VIEWENTIRE_VIEWSNAPSHOT

传入所选的 ReadRange to FoundryFiles.getFileSystem() 以获取一个限定于所需文件范围的 ReadOnlyLogicalFileSystem 。传入所选的 WriteMode to FoundryOutput.getFileSystem() 来更新或替换输出数据集。

省略写入模式会强制执行快照事务

调用无参数的 myOutput.getFileSystem() 始终会在输出上产生一个快照事务，无论输入使用的是哪种 ReadRange 。请显式传入 WriteMode 以进行增量写入。

package myproject.datasets;

import com.google.common.io.ByteStreams;
import com.palantir.transforms.lang.java.api.Compute;
import com.palantir.transforms.lang.java.api.FoundryFiles;
import com.palantir.transforms.lang.java.api.FoundryInput;
import com.palantir.transforms.lang.java.api.FoundryOutput;
import com.palantir.transforms.lang.java.api.Input;
import com.palantir.transforms.lang.java.api.Output;
import com.palantir.transforms.lang.java.api.ReadOnlyLogicalFileSystem;
import com.palantir.transforms.lang.java.api.ReadRange;
import com.palantir.transforms.lang.java.api.WriteMode;
import com.palantir.transforms.lang.java.api.WriteOnlyLogicalFileSystem;

public final class IncrementalFileCopyTransform {

    @Compute
    public void myComputeFunction(
            @Input("/examples/raw_files") FoundryInput myInput,
            @Output("/examples/raw_files_copy") FoundryOutput myOutput) {
        FoundryFiles inputFiles = myInput.asFiles();
        ReadRange readRange;
        WriteMode writeMode;
        switch (inputFiles.modificationType()) {
            case UNCHANGED:
            case APPENDED:
                readRange = ReadRange.UNPROCESSED;
                writeMode = WriteMode.UPDATE;
                break;
            case UPDATED:
            case NEW_VIEW:
                readRange = ReadRange.ENTIRE_VIEW;
                writeMode = WriteMode.SNAPSHOT;
                break;
            default:
                throw new IllegalArgumentException("Unknown FilesModificationType for input dataset "
                    + inputFiles.modificationType());
        }

        ReadOnlyLogicalFileSystem inputFileSystem = inputFiles.getFileSystem(readRange);
        WriteOnlyLogicalFileSystem outputFileSystem = myOutput.getFileSystem(writeMode);

        inputFileSystem.listAllFiles().forEach(path -> inputFileSystem.readFrom(path, inputStream -> {
            outputFileSystem.writeTo(path, outputStream -> ByteStreams.copy(inputStream, outputStream));
            return null;
        }));
    }
}

此转换仅读取所需的输入文件，并在输出的增量更新和完整快照之间进行选择。有关使用 ReadOnlyLogicalFileSystem 和 WriteOnlyLogicalFileSystem 读取和写入文件但不使用增量行为的更多示例，请参见 读取和写入非结构化文件.

最佳实践

在快照和增量之间切换

假设您大多时候希望运行增量转换，但有时需要对数据集重新运行快照。

为了避免手动硬编码所需的结果，您可以添加一个新的输入，使得每当该输入被修改时，输出都使用 SNAPSHOT 写入模式。这个新输入实际上将充当快照触发数据集，您需要根据此快照触发数据集的修改类型来调整转换其他输入的读取范围。

也可以通过创建一个不带溯源信息的空追加事务来从外部强制执行快照。但是， transforms-java 并未公开此类功能，因此这超出了本指南的范围。

高级功能

本节中的高级功能如果使用不当可能会产生严重的负面影响。如果您不能完全确定其影响，请 不 使用这些功能。如果在运行时没有采取适当的谨慎和小心，极有可能产生不良后果。如有任何疑问，请联系您的 Palantir 代表。

高级功能通常包含在您的 @Compute 函数之上的注解中。如果您的转换使用 手动注册，请改为将这些属性添加到 Transform Builder 中。

只有低级转换才能忽略架构更改。

与该转换相关的构建将成功或失败，具体取决于转换如何依赖于输入数据集。 更准确地说，如果转换依赖于架构更改中涉及的列，对这些列的修改将导致增量转换失败。 在这些情况下，需要新的快照才能再次使用增量转换。

该转换 卸载实体时，当没有阻止性约束。例如，Apollo在另一个依赖于它的实体已安装时，不会卸载该实体。请注意，Apollo可能在此计划之前对该实体执行其他计划。 在以下情况下依赖于某个列：

  • 它包含显式依赖于该列的修改（例如，如果我们有 filter("eye = 'Brown'") 并且该列 eye 在 RAW 数据集中被重命名或删除，那么如果我们重新触发 FilterTransform ，增量更新将失败）。
  • 被修改的列出现在输出数据集中（例如，如果我们删除该列 hair 在我们的示例 RAW 数据集中，我们的 FilterTransform 将失败）。

如果转换不依赖于架构更改，增量构建将成功。

例如，如果我们首先为 select 语句添加 id 和 eye 到我们的转换中，并从 RAW 数据集触发初始快照构建，然后删除 RAW 数据集中的该列 hair ，增量构建将成功，并且架构更改不会对增量转换产生任何影响。 在架构发生增量更改（例如添加新列）的情况下，构建也总是会成功。
