检查类型

本页面概述了 Data Health 中可用的各类检查，包括作业级检查、构建级检查、计划级检查和新鲜度检查。

作业级检查与计划级检查

本节描述 作业状态, 计划状态日 计划持续时间 检查。

以下定义阐明了在 Foundry 中作业和计划分别是什么：

  • 作业: 由单个转换中的逻辑定义的 Spark 计算。换言之，作业是生成单个数据集的单个转换（如果使用多输出转换，则可生成多个数据集）。作业会被分解为一系列阶段。
  • 计划: 一组具有已定义目标数据集、并被配置为定期运行的作业。计划可用于表示一起构建的管道的一个子集。

我们使用以下 Data Health 检查来确保作业和计划成功运行：

  • 作业状态： 每当安装了该检查的数据集被刷新，或作为任何构建的一部分被创建时，该检查就会被触发。只要目标数据集成功构建，作业状态检查就会成功，即使其所属的构建在下游失败。但是，如果构建在目标数据集的上游失败，目标数据集将记录为构建被取消，且不会对目标数据集评估作业状态。
  • 计划持续时间与计划状态： 这些检查允许您监控计划构建的状态（包括所有中间数据集），并且仅在检查所配置的计划运行时才会触发。
    • 一般而言，建议所有计划都配置计划状态检查。如果您已经配置了计划状态检查，则不建议在同一计划构建的其他数据集上安装作业状态检查，因为计划中任何作业失败都会触发计划状态检查。

在尝试确定何时何地放置作业或计划状态检查时，请参阅我们关于 应应用哪些健康检查.

的指南。有关这些检查本身的更多详细信息和进一步说明，请参阅以下对象的检查参考： 计划状态 和 作业状态.

新鲜度检查

本节描述 同步新鲜度, 数据新鲜度日 距上次更新的时间 检查。

这三种检查都与“新鲜度”（即数据的某些方面有多新）相关，但它们都使用不同的方法来评估新鲜度：

  • 距上次更新的时间： 评估 数据集的新鲜度。此检查计算当前时间与最后一次提交的事务之间经过了多少时间，即使该事务为空；空事务不会更改数据集中的数据。
  • 数据新鲜度： 评估 数据集中数据的新鲜度 ，方法是计算最后一次提交的事务与时间戳列的最大值之间经过了多少时间。此检查仅在提交事务时运行。
  • 同步新鲜度： 评估 同步数据集中数据的新鲜度 ，方法是计算数据集最近一次同步的时间与日期时间列的最大值之间经过了多少时间。

对于数据新鲜度和同步新鲜度，如果列中的时间戳表示行在源系统中被添加的时间，则最为理想。

在尝试确定何时何地放置新鲜度检查时，请参阅我们关于 应应用哪些健康检查.

健康检查失败时我可以中止构建吗？

大多数标准健康检查依赖于作业完成才能进行计算。如果您的数据集是在 Code Repository 中创建的，您可以使用 数据期望 来定义在构建期间运行的检查。这将允许您在出错时中止构建，并使用 Data Health 监控这些检查。
