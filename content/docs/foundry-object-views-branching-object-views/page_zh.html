对象视图分支

概述

对象视图与全局分支集成，支持以安全、隔离的方式开发对象视图配置。本文档介绍了如何在分支上使用对象视图，包括添加和修改资源、跨应用兼容性、合并要求、变基（rebase）以及已知限制。

有关全局分支概念和工作流的一般信息，请参阅 全局分支文档。

添加、移除和修改资源

要将对象视图添加到分支，请在分支上保存对象视图版本，此操作需在 对象视图编辑器.

对象视图支持两种类型的分支兼容资源：

  • OV 管理的模块： 捕获在分支上对对象视图所做的 Workshop 内容更改。系统会为每个完整对象视图选项卡、对象实例面板和对象集面板创建一个单独的 OV 管理模块。Workshop 应用程序中提供的所有支持分支的功能在对象视图中同样可用。
  • 完整对象视图选项卡： 捕获对象视图选项卡的结构性更改，包括添加、删除、重命名、配置文件更改以及可见性条件修改。

以下示例展示了以下对象视图在分支上的不同资源 Museum 对象类型。从上到下依次为：完整对象视图选项卡资源、 Museum 对象类型本身、完整对象视图的 “博物馆历史” 选项卡，以及 面板对象视图。

您可以使用分支任务栏单独从分支中移除任何对象视图资源。移除完整对象视图选项卡资源会自动从该分支中移除其所有关联的选项卡。

跨应用程序兼容性

可以针对分支上本体论的最新状态编辑对象视图，包括在分支上创建的对象类型和操作类型。对象视图小组件还可用于在独立的 Workshop 应用程序中嵌入分支对象视图。可以在分支上预览对象视图，预览位置为 Ontology Manager 中的 对象视图 选项卡。

合并要求

可部署性检查

在将对象视图从分支部署到 main 之前，必须通过以下可部署性检查：

  • 用户具有发布权限： 编辑对象视图的权限 是必需的。这与发布新对象视图版本时执行的权限检查相同，发布于 main。

  • 对象视图必须变基到 main： 合并之前，请基于最新更改对分支上的每个对象视图资源进行变基，这些更改位于 main。

  • 未修改旧版字段： 验证分支上未修改新对象视图编辑器不支持的任何功能。此检查应始终通过。如果该检查失败，请联系 Palantir 支持团队。

审批检查

对象视图使用 审批 来判断在分支上进行更改的用户是否拥有合并这些更改所需的权限。所需的具体权限取决于 权限模型 ，该模型由对象视图所关联的对象类型决定。

对象类型使用数据源派生的权限

当对象类型使用 数据源派生的权限，贡献者或批准的审核者必须具有：

  • View 对象类型的访问权限以及 Editor 对其 所有 支撑数据源的访问权限。
  • 该 Object View Admin 应用程序权限在 控制面板，这是在 Object Explorer 中发布对象视图所必需的权限。这也是在执行以下操作时所需的相同应用程序权限： 发布新的对象视图版本 于 main。
数据源权限在合并时更为严格

上述数据源权限要求比在分支之外使用的标准编辑权限检查更为严格。在 main 上编辑对象视图仅需 Editor 角色于 任一 对象类型的支撑数据源。合并来自分支的更改需要 Editor 角色于 每个 支撑数据源。

对象类型使用本体论角色或基于项目的权限

当对象类型使用 本体论角色 或 基于项目的权限，贡献者或审批审核人员只需对对象类型具有编辑访问权限。这通常通过 Ontology Editor 角色（位于本体论角色下）授予，或通过 Editor 项目角色（位于基于项目的权限下）授予。对对象类型的编辑访问权限已涵盖在 Object Explorer 中发布对象视图的操作，因此无需单独的 Object View Admin 应用权限。

继承的项目审批策略

对象视图以及构成对象视图标签页和面板的 Workshop 模块是父对象类型的逻辑子级。如果对象类型是 受保护的 ，并且位于一个具有 项目审批策略的项目中，该策略将适用于对象视图及其模块。两者的审批请求都必须满足该策略，然后提案才能合并。

继承自父对象类型的保护

继承资源保护功能正在开发中，即将发布。一旦可用，它将阻止对 main 对象视图或其模块进行直接编辑（只要父对象类型受保护）。在此之前，对象视图及构成其标签页和面板的模块仍可以直接在 main 即使父对象类型受保护。

变基与冲突解决

分支上的每个对象视图资源在部署之前必须先与 main 分支进行变基。对象视图模块资源可以使用 Workshop 变基。针对 完整对象视图选项卡资源 的选项卡配置更改必须与选项卡内容更改分开进行变基。当需要对完整对象视图进行变基时，对象视图部分下方将显示一条通知消息，该部分位于 对象视图编辑器。

对象视图变基对话框显示三列：

  • 主分支状态
  • 您的分支状态
  • 建议的变基结果

不冲突的更改介于 main 与您的分支之间，会被自动接受并包含在结果中。如果存在冲突，您必须选择保留来自 main 的版本还是来自您分支的版本（针对每个受影响的选项卡）。结果列会显示变基后最终状态的预览。您可以在完成变基之前修改任何自动接受的更改。

已知限制

旧版对象视图选项卡 无法在分支上编辑。
