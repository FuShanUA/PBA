通过智能重新定价提高留存率和催收绩效

行业领域： 金融服务

业务职能： 运营

一家支付处理商希望通过优化催收、对敏感度较低的商户重新定价以及留住有流失风险的高价值客户，来增加来自中小型商户的收入。由于数据环境极为分散且规模庞大，他们无法运行必要的分析来落实这些想法。

挑战

以这家支付处理商的运营规模来看，主要面临两大挑战：

  • 无法有效地对商户进行催收优先级排序或分级
  • 难以确定商户的最佳费率和费用

解决方案

  • 商户活动的完整视图 — 该公司通过整合大量关于客户活动、定价、支付终端、账单、欺诈和信用历史的数据，对其客户群形成了前所未有的深入了解。

  • 催收效果提升 — 分析人员构建统计模型，根据账户的还款可能性对其进行评级。可能性较高的账户被转给内部催收团队，而可能性较低的账户则被转给第三方催收机构。

  • 新的定价策略 — 分析人员进行大规模分析，评估不同费用结构对客户留存的影响。销售团队利用这些洞察为新账户制定更优的定价，并对现有账户重新定价以防止流失。

利益相关者和用户群体

  • 商户催收团队
  • 财务分析师
  • 数据科学家
  • 销售团队

一位财务分析师使用 Foundry 对商户进行重新定价演练，以确保客户留存的同时实现收入最大化。

影响

  • 通过将无法收回的账户过滤给第三方，并优先处理收回可能性高的高价值账户，催收绩效得到提升。得益于优先级排序的改进，预计每年可额外产生数百万美元的催收款。
  • 重新定价模型为商户的重新定价演练提供了支持，提高了客户留存率，并在目标收入之外额外创造了数百万美元的收入。

运作方式

  • 整合了客户关系管理（CRM）系统和其他数据源，在 Foundry 中构建了统一的 本体论 以了解商户活动。系统为客户、其活动、定价、支付终端、账单、欺诈、信用历史等创建了对象和关联。
  • Contour 以及其他 Foundry 分析工具被用于执行分析，以确定新的催收和定价方法。在 Contour and 代码仓库（Code Repositories）. 和 中，对不同定价选项进行情景分析非常直观，并且可以应用 Foundry Scenarios 来进一步支持这一流程。
  • 用于催收优先级排序和重新定价的机器学习模型是在 代码仓库. Foundry ML 中实现的，也可以考虑在此使用。
  • 重新定价应用是在 将收集到的信息存储在.
