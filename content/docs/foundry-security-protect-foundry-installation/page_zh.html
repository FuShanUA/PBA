保护您的自托管 Foundry 安装

Palantir Foundry 旨在为从云端到边缘的几乎任何环境提供安全协作。如果您在 Palantir 托管的 SaaS 平台之外运行 Foundry（例如在您自己的数据中心或您自己的云环境中），请遵循以下指导以保护您的安装。

物理访问

如果您的 Foundry 安装部署在裸机硬件上（例如在数据中心中），实施强有力的物理安全控制至关重要。对运行 Foundry 的服务器的访问应仅限于授权人员，访问应有时限且有记录，并应遵循行业最佳实践。

由于物理安全是信息安全的基础，未经授权访问运行 Foundry 的硬件可能会使攻击者有机会实施各种攻击并破坏安全控制。

数据加密

为了维护信息安全，您的数据必须进行加密，包括 静态数据 和 传输中的数据.

静态数据

虽然 Foundry 中的所有数据均已采用应用级加密进行静态加密，但您仍应对 Foundry 安装中使用的所有底层服务器和存储设备进行加密。

  • 您应使用符合行业标准的加密解决方案进行全盘加密。这可能包括开源项目（例如 LUKS ↗）、市售软件、自加密硬盘等硬件实现方式，或云服务提供商提供的解决方案。
  • 您应该将加密密钥材料存储在硬件中，例如硬件安全模块 (HSM)。
  • 您应该对磁盘加密使用强加密标准，例如 AES-256 或 AES-128。

传输中的数据

您的客户端与 Foundry 之间传输的所有数据都应使用强加密协议和密码算法进行保护。

  • 您应该使用由受信任的证书颁发机构颁发的有效证书，证书有效期为 90 天，最长不超过一年。
  • 您应该仅支持使用传输层安全协议 (TLS) 1.2 或更高版本的连接。
  • 您应该仅支持强 TLS 密码套件，并根据兼容性和安全需求进行相应调整。
  • 我们建议使用椭圆曲线 Diffie-Hellman 密钥交换 (ECDHE) 并结合 CHACHA-POLY1305 或 GCM 模式下的 AES-{128-256}。应尽可能避免使用 CBC 模式的密码套件。

身份安全

单点登录

您应该在单点登录提供程序中集中管理身份。

  • 应要求所有用户使用实名账户,账户不得共享。
  • 您应要求所有用户使用强多因素身份验证。在可能的情况下,应使用 FIDO2 等现代技术。不应使用基于短信或电子邮件的多因素身份验证。

凭据卫生

您应要求用户保持良好的凭据卫生习惯。强烈建议使用无密码身份验证。

  • 您应要求用户设置足够强、长且唯一的访问密码。
  • 您不应允许用户在您的环境之外的其他服务中重复使用其密码。
  • 如果密码被意外输入到未经授权的域，您应要求用户轮换密码。

零信任

您应使用现代零信任技术来保护您的 Foundry 安装。

  • 您应使用零信任技术，仅基于身份、设备健康和验证情况允许授权用户访问。
  • 您应拒绝不受信任、不健康或未知设备对您的 Foundry 安装的访问。

网络安全

网络分段

您的 Foundry 安装环境应与您环境的其余部分高度隔离。

  • 应使用防火墙或其他技术实现网络隔离。应使用经批准的协议、端口和子网的白名单来控制对服务的访问。
  • 默认情况下，应拒绝所有流向您的 Foundry 安装环境的入站流量。
  • 在可能的情况下，您应仅将 Foundry 安装环境暴露给最少量的网络。建议不要在没有附加控制措施（如入侵检测系统和 Web 应用防火墙）的情况下将 Foundry 安装环境暴露于公共互联网。
  • 您应将 Foundry 安装环境隔离在专用的私有网络（VLAN/子网）中。

出站控制

应严格管控源自您的 Foundry 安装环境的网络流量。

  • 您应要求所有来自 Foundry 的网络连接均通过代理或其他网络安全设备进行管控。
  • 您应维护一份允许列表，其中列出按 IP 或域名指定的许可目标，您的 Foundry 安装只能连接到这些目标。
  • 您应拒绝您的 Foundry 安装进行所有其他网络访问。

网络安全

您应使用网络安全控制措施来保护您的 Palantir Foundry 安装。

  • 您应使用网络安全控制措施（如入侵检测系统）来识别异常活动。
  • 您应使用防火墙来识别和阻止网络漏洞利用或攻击企图。
  • 您应使用数据丢失防护（DLP）技术来检测未经授权的数据传输。
  • 您应从您的网络中收集网络安全日志，以识别异常活动。

基础设施安全

服务器加固

用于 Foundry 安装的服务器应按照行业标准配置指南（如 CIS 或 NIST 控制措施）进行加固。

  • 您应仅使用受支持的现代操作系统。
  • 您应对用于 Foundry 安装的主机执行严格的漏洞管理和补丁更新。严重安全漏洞应在 30 天或更短时间内完成修补。

主机安全

您应使用主机安全控制措施来保护您的 Foundry 安装。

  • 您应从主机收集审计和安全日志，以识别异常活动。
  • 您应该使用基于主机的安全控制措施（例如入侵检测系统）来识别异常活动。
  • 您应使用数据丢失防护（DLP）技术来检测未经授权的数据传输。

特权访问

您应该严格控制对 Foundry 安装的特权访问。

  • 托管 Foundry 安装的后端基础设施应仅限于通过专用堡垒服务器或跳板机访问。
  • 所有对 Foundry 安装的基础设施级或云级访问都应要求多因素身份验证。

备份

为了保障组织业务连续性，您应该对 Foundry 安装进行定期的全盘备份。

  • Foundry 提供一项服务（“Rescue”），旨在执行应用程序备份和恢复。
  • 您应至少对 Rescue 服务数据执行全盘备份。强烈建议对 所有 Foundry 主机执行全盘备份。
  • 您应对备份进行加密，并确保将其存储在持久和/或离线的位置。勒索软件和其他恶意行为者通常会在执行其他恶意操作之前先尝试销毁备份。
  • 您应至少每年对备份和恢复流程进行一次测试。

应用程序补丁管理

您应尽快为您的 Foundry 安装应用安全补丁。

  • 如果您的 Foundry 安装已连接 Apollo，您的 Foundry 安装将自动接收安全更新。这些更新通常无需您采取任何操作。
  • 如果您不使用 Apollo，则应在安全更新发布后尽快应用。严重的安全漏洞应在 30 天或更短时间内完成修补。
