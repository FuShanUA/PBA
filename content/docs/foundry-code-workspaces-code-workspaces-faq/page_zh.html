我可以在 Code Workspaces 中使用 PySpark 吗？

可以，您可以在 Jupyter® Code Workspaces 中使用 PySpark。但是，它在您的工作区容器内以本地模式运行，仅使用可用的 CPU 和内存；它不会在分布式 Spark 集群上运行。我们建议使用 Foundry 应用程序，例如 如果希望用户在每次运行预览前手动确认，请开启 和 代码仓库 来运行分布式 Spark 工作负载。

要在您的 JupyterLab® Notebook 中安装 PySpark，请导航至 ”面板中找到。 例如，要使用 选项卡并安装 pyspark 和 openjdk。支持以下 OpenJDK 版本：

  • PySpark < 4.0.0： OpenJDK 8.x, 11.x，或 17.x
  • PySpark 4.0.0 及以上版本： OpenJDK 17.x or 21.x

如果您遇到如下错误 java.lang.UnsupportedOperationException: getSubject is supported only if a security manager is allowed，请确保将 OpenJDK 固定为您的 PySpark 版本所支持的版本。

from foundry.transforms import Dataset
from pyspark.sql import SparkSession
import pyspark.sql.functions as F

# Create the Spark context. The example below shows a 2 CPU, 16 GB workspace.
spark = (SparkSession.builder
    .appName("ParquetExample")
    .master("local[2]")  # Set to the CPUs available.
    .config("spark.driver.memory", "10g")  # Define the driver memory, around 50-65% of the container's total.
    .config("spark.driver.memoryOverhead", "4g")  # Define the overhead memory, about 20-35% of the container's total.
    .config("spark.sql.shuffle.partitions", "6")  # Optionally define partition count, ~3x the CPU total.
    .getOrCreate())
sc = spark.sparkContext

# Download a Foundry dataset of parquet files into the notebook.
parquet_foundry = Dataset.get("parquet_foundry_dataset")
files = parquet_foundry.files().download()

# Read the files into a Spark dataframe.
spark_df = spark.read.parquet(*list(files.values()))

# Apply PySpark transformations.
df_processed = spark_df.filter(F.col("col1") == 1)

# Write your output dataset.
spark_output = Dataset.get("spark_output")
spark_output.write_table(df_processed.toArrow())

我可以在 Code Workspaces 中进行 API 调用吗？

可以，您可以在 Code Workspaces 中使用 外部系统进行 API 调用，外部系统已取代网络策略成为工作区出站流量的首选方法。对于 已启用 CBAC 的环境 您应该使用在 控制面板.

Code Workspaces 支持哪些 IDE？

代码工作区目前支持 VS Code, JupyterLab®日 RStudio® Workbench.

代码查看器中会显示哪些代码？

代码查看器 显示存储在仓库中的已提交状态。在 VS Code、JupyterLab®、RStudio® Workbench、Code Repositories 或本地开发环境中所做的更改，只有在提交并同步之后才会显示。

代码查看器需要现有或正在运行的工作区吗？

不需要。您可以在代码查看器中浏览仓库，而无需创建或启动编辑器工作区。

为什么我启动 VS Code 工作区时代码查看器会打开？

默认情况下，当您打开 已停止的 VS Code 工作区时，代码查看器会打开，而其工作区会话会在后台启动。 VS Code 选项卡图标显示工作区状态。代码查看器将保持打开状态，直到您选择 VS Code 标签页。

要禁用此行为，请按照 在编辑器中继续.

Code Workspaces 不支持哪些软件包？

出于安全原因，不支持以下 Python 软件包：

  • folium
  • pandasgui

如果您对上述软件包有任何疑虑，请联系您的 Palantir 代表。

为什么我仓库中的代码采用 JSON 格式？

Code Repositories 应用程序以 IPython 格式从关联的 Code Workspaces 接收代码，并以 JSON 格式逐单元格呈现代码。

我可以使用自己的软件包吗？

可以；请参阅有关 导入软件包的文档。如果您的软件包托管在组织级的 Conda/PyPI/CRAN 频道上，Foundry 可以代理该频道并使其可用于您的项目。请联系您的 Palantir 代表了解更多信息。

为什么支撑我的 Code Workspace 的 Code Repository 没有 ”面板中找到。 例如，要使用 选项卡？

要将库导入您的 Code Workspace， 请使用 软件包 标签页 （位于您工作区的左侧面板中）。

我可以在 Code Repositories 中编写或编辑不是来自我的 Code Workspace 的代码吗？

可以，当代码源自 Code Workspaces 时，您可以直接在 Code Repositories 中编辑代码。提交后，您可以使用 Code Workspace 中的 同步 or 重置更改 功能来获取工作区中的远程更改。

从概念上讲，您可以将 Code Repositories 视为 Code Workspaces 的版本控制管理器，负责处理拉取请求、冲突解决和管理，而代码开发则可以在 Code Workspaces 中进行。

为什么我的同事看到的视图与我的不同？

出于安全目的，用户在 JupyterLab® 或 RStudio® 中工作时是相互隔离的。这意味着访问同一 Code Workspace 的每个用户都拥有自己的环境。协作通过 git 工作流进行：如果您希望将最新代码提供给同事使用，请选择 同步更改 以将您的更改与支撑代码仓库同步，当您的同事选择 同步 or 重置更改时，这些更改将对他们可用。当多个用户在同一工作区中工作时，我们建议他们在独立的分支上工作。

我们默认使用以下配置忽略某些文件 .gitignore 以确保没有数据与 git 仓库同步，并限制 git 仓库的大小。我们还会移除 JupyterLab® 中的所有输出 .ipynb 文件。

我可以导入额外的 LaTeX 软件包来渲染我的 R Markdown 文件吗？

可以。默认情况下，Code Workspaces 仅预装渲染常见 R Markdown 文件所需的依赖（如 TinyTex-1 ↗中所定义），但您可以自行安装其他 LaTeX 软件包：

  1. 下载或创建 TDS 归档文件。例如，您可以从 .tds.zip 下载文件，来源为 CTAN ↗.
  2. 将 TDS 归档文件上传到新的或现有的 Foundry 数据集中。您可以将文件夹中的文件拖放到新的 Foundry 数据集中进行上传。
  3. 选择 上传到不带 schema 的数据集。您可以同时将多个 TDS 归档文件上传到同一数据集。
  4. 在 Code Workspaces 中，前往 同步至数据集 选项卡，然后选择 读取现有数据集。选择包含 TDS 归档文件的数据集。
  5. （可选）更新数据集别名。在本示例中，我们假设您将数据集别名命名为 my_latex_packages.
  6. 复制代码片段，将其粘贴到您的 .Rprofile中，并对其进行更新以将文件解压到正确的位置。您需要将 my_latex_packages 替换为您的数据集别名，如下面的代码片段所示：
library(foundry)
my_latex_packages_files <- datasets.list_files("my_latex_packages")
my_latex_packages_local_files <- datasets.download_files("my_latex_packages", my_latex_packages_files)
texmflocal <- system("kpsewhich --var-value TEXMFLOCAL", intern = TRUE)
sapply(my_latex_packages_local_files, function(tds_file) { unzip(tds_file, exdir = texmflocal) })
  1. 现在您可以在 R Markdown 头部中包含您的软件包以使用它：
headers-include:
 - \usepackage{my_package}

我可以在 R Markdown 文件中使用自定义字体吗？

是的。

  1. 下载或创建您想要使用的 TTF 文件。
  2. 将 TTF 文件上传到新的或现有的 Foundry 数据集中。您可以将文件夹中的文件拖放到新的 Foundry 数据集中进行上传。
  3. 选择 上传到不带 schema 的数据集。您可以同时将多个 TTF 文件上传到同一数据集。
  4. 在 Code Workspaces 中，前往 同步至数据集 选项卡，然后选择 读取现有数据集。选择包含 TTF 文件的数据集。
  5. （可选）更新数据集别名。在本示例中，我们假设您将数据集别名命名为 my_fonts.
  6. 复制代码片段，在 R 控制台中运行它，并将文件复制到您的仓库中，以便版本控制可以跟踪它们。您需要将 my_fonts 替换为您的数据集别名，如下面的代码片段所示：
my_fonts_files <- datasets.list_files("my_fonts")
my_fonts_local_files <- datasets.download_files("my_fonts", my_fonts_files)
dir.create("fonts")
file.copy(unlist(my_fonts_local_files), "fonts")
  1. 现在您可以在 /home/user/repo/fonts 目录中引用这些字体，以便按照 R Markdown 的建议在您的 HTML 或 PDF 输出中使用它们。

要更改 HTML 的字体，请设置 font-family ，置于 自定义 CSS ↗.

要更改 PDF 的字体，您可以在 LaTeX 中使用以下命令加载字体 \newfontfamily 的定义，使用 自定义 LaTeX 代码 ↗ 将其放在导言区（preamble）中。

如何防止我的 Jupyter® 工作区在代码运行时暂停？

您可以利用 %%keep_alive 单元格魔法命令来防止 Code Workspaces 在单元格中的代码运行时暂停 Jupyter® 笔记本。

这将使单元格在代码运行期间保持活跃状态最多 24 小时。如果您的浏览器标签页被关闭或长时间闲置，JupyterLab® 将停止显示和保存单元格的输出。如果您希望稍后查看单元格的输出，可以使用 %%capture 单元格魔法命令将输出存储到变量中：

如何从我的 Jupyter 或 RStudio Code Workspace 下载文件？

为了确保管理员配置的下载限制得到执行，Palantir 平台已禁用 IDE 原生文件下载功能。

如需下载文件，请将文件写回 Foundry 数据集。为此，请在 Code Workspaces 侧边栏中导航至 同步至数据集 选项卡，然后选择 将数据写入新数据集，并为新数据集输入一个名称。确认数据集的别名后，选择 非表格数据集 作为数据集类型，输入您希望上传的文件或目录的位置，然后运行生成的代码片段。

文件上传到 Foundry 数据集后，您可以通过选择数据集链接导航到数据集预览，并从那里下载文件。 请记住，您的管理员可能要求在从平台导出数据之前提供理由说明，或限制导出的数据量。
