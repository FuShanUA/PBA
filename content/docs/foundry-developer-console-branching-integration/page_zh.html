为 Developer Console 应用程序创建分支

Developer Console 与 全局分支 集成，因此您可以在开发 Ontology SDK (OSDK) React 应用程序的同时对其本体论资源进行更改。在全局分支上，您可以更改 SDK 中包含的资源、根据分支上的本体论定义生成 SDK，并针对分支上的数据测试您的应用程序。

功能

您可以在全局分支上使用 Developer Console 来：

  • 修改生成的 SDK 中包含的资源集。
  • 根据分支上的本体论实体定义生成 SDK。
  • 在不生成新 SDK 的情况下读取全局分支上的数据。
  • 基于分支上的 SDK 进行开发。
  • 从开发服务器或拉取请求预览中读取和写入分支数据。

是否需要生成新的 SDK 取决于您要测试的更改：

您要测试的更改SDK 生成
使用 SDK 中已有的资源读取分支数据。完成仓库设置后，您可以使用现有的 SDK。
使用分支上已更改的本体论定义或新添加到 SDK 中的资源。在分支上生成 SDK，然后运行 npm install 以更新您的应用程序依赖项。

无论哪种情况，请先完成 索引先决条件 ，然后再在分支上测试操作。

局限性

Developer Console 集成支持在使用 Vite 的应用程序中通过 npm 安装的 TypeScript SDK 6, 7，或 8。目前不支持其他 SDK 语言或包管理器。

全局分支不支持嵌入在其他 OSDK 应用程序中的 OSDK 应用程序。嵌入的应用程序不会继承宿主应用程序的分支上下文，并且可能会发出将操作应用于 main的请求。嵌入的应用程序仅通过 双向 Workshop Iframe 小组件配置支持全局分支，且需要相应的客户端版本和选项。

前提条件

在全局分支上进行开发之前，请完成以下先决条件：

  • 确保您的 Developer Console 应用程序位于某个项目中。对于旧版应用程序，请按照 项目迁移说明操作，包括有关权限更改的指导。
  • 为您的workflow创建或选择一个 全局分支 。您的 Developer Console 应用程序必须已经在 main上拥有 Ontology SDK，因为您无法在全局分支上添加。全局分支必须使用与应用程序 SDK 相同的本体论。
  • 使用直方图中的 支持的依赖项版本，以及 Vite 6, 7，或 8。在配置分支之前，请升级较旧的 Vite 版本以及任何受影响的插件。如果您的应用程序使用 OSDK 1.x，请先按照 TypeScript OSDK 迁移指南.
  • 对于 Foundry 代码仓库，请使用支持全局分支并满足其最低模板版本要求的模板。例如，从最新版本的 Ontology SDK React Application 模板（osdk-react-app-v2）创建的仓库已包含所需的依赖项和 Vite 配置。
  • 如果您的仓库使用较旧的模板版本或缺少所需的配置，请按照 迁移现有仓库中的步骤操作，首先进行 模板升级。在将仓库添加到全局分支之前，请先将更改合并到默认分支。
  • 在测试操作之前，请对 这些操作编辑的每个对象类型 在全局分支上进行索引。要一次索引多个对象类型，请使用 Workflow Lineage 中的批量索引。在运行操作之前，请等待索引完成。在分支上运行操作仅用于测试。在分支上所做的操作编辑不会合并到 main.

在全局分支上运行应用程序之前，请完成所有仓库设置步骤。否则，您的应用程序的请求可能会读取 main 或其他分支的数据并将操作应用于这些分支。对于嵌入 Workshop 的应用程序，还须满足 嵌入应用程序要求.

跨分支的应用程序限制

应用程序限制 在所有分支（包括默认分支）之间共享， main。对这些限制的更改会影响应用程序在每个分支上的表现。

在非默认分支上，您只能向资源限制中添加该分支所需的本体论资源。您无法移除限制，因为移除限制可能会破坏其他分支，包括 main。项目对 Platform SDK 选项卡、操作限制、标记限制和 OAuth 客户端设置在非默认分支上均为只读。

审查未使用的资源限制

要审查当前 SDK 中不再包含的资源的限制：

  1. 在 Developer Console 中打开应用程序并切换到 main.
  2. 打开 “OAuth 与限制” 页面并选择 限制与访问 tab.
  3. 选择 审查资源 以打开 审查旧 SDK 资源 dialog.
  4. 审查列出的资源并选择不再需要的资源。移除其他 SDK 版本或分支仍在使用的资源可能会破坏该分支上的应用程序。
  5. 选择 移除资源.

在全局分支上开发

在 Developer Console 中为应用程序使用同一个全局分支，包括其本体论更改和源代码。全局分支在 Foundry 中协调资源；仅靠 Git 分支无法建立该上下文。

在分支上打开应用程序

  1. 在 Developer Console 中打开您的应用程序。
  2. 使用分支选择器为您的 workflow 创建或切换到全局分支。
  3. 在更改 SDK 中包含的资源之前，请确认所选分支。
  4. 在测试操作之前，请确认这些操作所编辑的每个对象类型的索引已完成，如 先决条件.

有关常规分支导航，请参阅 创建或访问分支.

更新资源并生成 SDK

要更改 SDK 中包含的资源并从分支的本体论定义生成 SDK：

  1. 在同一个全局分支上进行所需的本体论更改。请参阅 对本体论进行分支.
  2. 在 Developer Console 中，打开 本体论 SDK 页面，选择 “资源” 选项卡，并更新应用程序 SDK 中包含的资源。
  3. 打开 “SDK 版本” 选项卡并选择 “生成新版本” 以在该分支上生成 SDK 版本。如果 Developer Console 应用程序尚未加入全局分支，生成 SDK 会将其添加到该分支。
  4. 在应用程序仓库中，检出同一个全局分支，然后运行 npm install 以使用该分支上生成的最新 SDK。
  5. 审查、提交并推送更新后的 package.json and package-lock.json 文件，以便提案检查和预览构建使用更新后的 SDK 依赖项。

仓库的 postinstall 脚本会同步 SDK 依赖项。您无需手动将分支的 SDK 版本复制到 package.json.

运行开发服务器

完成 仓库设置 然后再开始开发。如果您的工作流的全局分支尚不存在，可以从代码仓库创建它。打开 提供了专为数据转换量身定制的版本控制体验，支持团队在同一工作簿中同时处理逻辑与数据。 标签页中，选择 新建分支，并选择 全局分支。您也可以使用 Palantir MCP 全局分支工具从本地开发环境创建全局分支。仅创建本地 Git 分支并不会创建全局分支。

使用 VS Code 工作区

打开您在 Foundry 上托管的 VS Code 工作区，并 为您的工作流检出全局分支 。每次工作区启动开发服务器时，其生成的配置会先运行 npm install 。在安装过程中， postinstall 脚本会将应用程序的 SDK 依赖项与所检出分支上生成的最新 SDK 同步。如果您在开发服务器启动后检出其他分支，请在预览工具栏中打开其他操作菜单并选择 重启开发服务器 以重新安装依赖项。

使用本地开发环境

如果全局分支尚不存在，请在 Foundry 中创建它，或使用 create_global_branch 工具，通过 Palantir MCP 在您的本地 AI 开发工具中。使用与您的 Developer Console 应用程序相同的本体论。请参阅 全局分支工具参考 以了解用于创建和检查分支及提案的工具。

确保您的源代码仓库位于同一个全局分支上，并遵循 资源分支工作流。在您的本地克隆中，获取并检出 Foundry 为该全局分支创建的仓库分支，并在本地保留相同的 Git 分支名称。要找到此名称，请在 Code Repositories 中打开该全局分支，并将鼠标悬停在分支选择器中的信息图标上。弹窗会在 在全局分支上进行本地开发下方列出 Code Repositories 分支名称。分支插件和 osdk branch sync 使用已检出的 Git 分支名称来确定分支上下文。然后安装依赖项并启动本地开发服务器：

预览拉取请求

为您的全局分支打开提案会创建一个源代码拉取请求。持续集成 (CI) 构建随后会部署一个 拉取请求预览 ，该预览从全局分支读取数据并向其写入数据。该预览需要一个 支持全局分支的仓库模板、所需的应用程序配置，以及 网站托管 已在 Developer Console 中为应用程序配置。与他人共享该预览，以便连同分支化的本体论资源一起测试应用程序。

  1. 创建提案 用于该全局分支。
  2. 打开为该提案创建的代码仓库拉取请求。
  3. 在应用程序发布检查成功后，选择 预览 位于该检查旁边。
  4. 打开预览并验证它是否显示了仅在预期全局分支上可用的更改或数据。在浏览器的网络工具中，确认应用程序的本体论请求包含一个 branch 查询参数，其中包含全局分支的资源标识符 (RID)。然后与审阅者共享该预览 URL。

您无法从全局分支标记发布或发布生产网站。这可以防止不稳定的更改进入生产网站。要共享您的更改，请创建提案并使用其拉取请求预览。

在 Workshop 中使用嵌入式应用程序

此集成仅支持 Workshop 的 Iframe 小组件的双向配置。 Iframe 小组件文档 推荐 来扩展 Workshop 应用程序，从而在无需离开 Workshop 的情况下添加量身定制、基于代码的组件。 用于新的集成，但此集成不涵盖自定义小组件。

除以下配置之外的 Iframe 配置 双向 不会继承 Workshop 模块的全局分支上下文。嵌入式应用程序还必须满足本节中的所有要求，包括 仓库设置。如果嵌入式应用程序不满足这些条件，其请求可能会读取数据并对主分支或其他分支执行操作。

当满足以下所有要求时，嵌入在 Workshop 中的 Developer Console 应用程序支持全局分支：

  • 应用程序的仓库满足 仓库设置前提条件.
  • 应用程序已配置为 与 Workshop 进行双向通信，而 Iframe 小组件使用 双向 option.
  • 应用程序使用 @osdk/client version 2.77.0 或更高版本。
  • 应用程序在初始化时在选项中传递 useHistory: false 在初始化时在选项中传递 createPublicOauthClient from @osdk/oauth.
  • OSDK 客户端不传递任何显式的分支覆盖。

在您的终端会话中将 useHistory: false 在 OAuth 客户端上，同时保留您现有的 OAuth 选项，例如 scopes:

当您在全局分支上预览 Workshop 模块时，双向 iframe 会将该分支上下文传递给嵌入式应用程序。iframe 仍会加载在其配置的 URL 上部署的网站，包括与该部署捆绑在一起的 SDK。切换 Workshop 分支不会重新生成 SDK，也不会重新构建和重新部署网站。

因此，已部署网站所使用的本体论架构必须在您预览的各个分支之间保持稳定。网站使用的每个对象类型、属性、操作类型和其他资源都必须与其捆绑的 SDK 保持兼容。要测试不兼容的架构更改，请为这些更改生成一个 SDK，更新应用程序，并将 iframe 指向兼容的部署。

满足本节要求并完成 仓库设置后，将所需的应用程序和仓库更改合并到仓库的默认分支。然后 发布一个版本 以进行部署。之后，您可以将您的生产网站嵌入到 Iframe 小部件。

如果嵌入式应用程序不满足本节要求，它将不会使用全局分支。其请求将发送到 main 且不会有任何警告：它会显示来自 main的数据，并且其应用的任何操作都会编辑 main 上的数据，而不是分支上的数据。

要验证分支上下文，请在全局分支上预览 Workshop 模块。在浏览器的网络工具中，确认嵌入式应用程序的本体论请求包含一个 branch 查询参数，其中包含全局分支的 RID。

迁移现有仓库

对于 Code Repositories 中受支持的 React 应用程序模板，请升级仓库模板以获取 CI 更改，然后手动更新应用程序依赖项和 Vite 配置。模板升级不会修改您的应用程序代码或依赖项文件。

请在从默认分支创建的 Code Repositories 分支上进行手动更改。在将仓库添加到全局分支之前，请先将模板升级和手动更改合并到默认分支。Foundry 会检查 package-lock.json 和 vite.config.ts 在仓库的 master 分支（通常是默认分支）上，以确定该仓库是否支持全局分支。

升级仓库模板

Foundry 会将仓库的模板版本与该模板支持全局分支所需的最低版本进行比较。仅更新 npm 依赖项并不能满足此模板要求。

  1. 在 Code Repositories 中打开您的仓库并选择其默认分支。
  2. 选择 升级 从仓库菜单中，如 手动分支升级.
  3. 中所述，查看升级更改 templateConfig.json。确认 parentTemplateId 识别出您的模板，并且新的 parentTemplateVersion 满足其全局分支的最低版本要求。
  4. 应用仓库升级，包括合并任何所需的升级拉取请求。参见 代码库升级 了解详情。

审查并合并更改

在全局分支中，你需要先在提案中审查更改，然后才能将其合并到 main。请参阅 创建并准备提案 以了解常规工作流程。

打开提案会创建一个源代码拉取请求。分享其 预览部署 以便审查者在合并前针对全局分支测试应用程序。合并提案不会部署生产网站。要部署已合并的更改， 发布一个版本 在仓库的默认分支上执行。

在提案的 更改 标签页中，选择 Developer Console 应用程序以审查添加到其 SDK 或从中移除的资源。

变基时解决冲突

如果资源在 main 上发生更改，在开发期间，请查看 有关变基和冲突解决的全局分支指南.

要解决应用程序 SDK 资源中的冲突：

  1. 在 本体论 SDK 页面中，选择 开始变基 以打开 变基应用程序 SDK dialog.
  2. 比较 点击单个编辑项，可并排查看 和你的分支上的资源，然后选择 保留此版本 以保留你想要的资源集。 保留此版本 适用于来自该侧的整个资源集。
  3. 选择 变基并保存.
  4. 在该分支上生成新的 SDK，然后运行 npm install 在源代码仓库中更新 SDK 依赖。
  5. 提交并推送更新后的 package.json and package-lock.json 文件，然后重新测试应用程序。

Developer Console 提案检查要求使用从最新应用程序 SDK 资源生成的 SDK。
