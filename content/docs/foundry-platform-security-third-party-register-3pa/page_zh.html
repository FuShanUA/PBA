注册第三方应用程序

用户应使用 自定义小部件 来注册新的应用程序配置。如果您需要与旧版独立 OAuth 客户端等效的功能，请按照以下步骤 创建不受限制的应用程序。该 控制面板 本页所述的流程仅适用于 自定义小部件 视图。

在第三方应用程序连接到 Foundry 之前，必须先在 Foundry 平台上注册。初始注册过程会为第三方应用程序创建名称、客户端 ID 和客户端密钥；参见 OAuth.com 文档 ↗ 以了解有关客户端 ID 和客户端密钥的更多信息，这些信息用于授权工作流程。然后，需要为第三方应用程序配置用于授权过程的重定向 URL，以及用于平台内展示的名称、描述和图标。

注册

  1. 要开始注册新应用程序的过程，请导航至 第三方应用 “代码” 控制面板 旁的复选框，并点击 新应用程序.

  1. 这将打开 注册新应用程序 向导。共有四个步骤，顺序如下： 详情, 客户端类型, 授权许可类型日 摘要.

  1. 在监听器设置向导的 详情 步骤中，为您的应用程序提供名称、描述（可选）和徽标（可选）。
  2. 在监听器设置向导的 客户端类型 步骤中，指定应用程序的客户端类型。客户端类型是指 OAuth2 标准中关于客户端应用程序能否安全存储密钥的规定。客户端类型有以下两个选项：
    • 机密客户端 ↗：适用于能够安全保存其凭据的客户端；例如，在安全服务器上实现且对客户端凭据访问受限的客户端。此客户端类型支持 授权码授予 and 客户端凭据许可 两种授权选项。
    • 公共客户端 ↗：适用于无法安全保存其凭据的客户端；例如，授权客户端直接在 Web 浏览器中运行的基于浏览器的应用程序。此客户端类型支持 授权码授予 与 PKCE，这意味着必须使用 code_verifier and code_challenge 参数。 客户端凭据许可 is 不 supported.

      有关这些客户端类型的更多信息，请参阅以下文档： 编写 OAuth2 客户端.
分布式二进制文件中的密钥可能被提取以冒充用户

原生应用程序或单页应用程序（如移动应用）会分发给用户进行部署。因此，应用程序二进制文件是可获取的，并且可以通过反汇编来提取客户端密钥。然后，该客户端密钥可能被用于在攻击中冒充已授权的用户。 代码交换证明密钥（PKCE）↗ 用于防止此类攻击。

  1. 在监听器设置向导的 授权许可类型 步骤中，您将看到上一步中所选客户端类型支持的许可类型。如果您选择启用 授权码模式，系统将要求您至少指定一个 重定向 URL.

    • 在授权过程中，OAuth2 使用浏览器重定向将用户从授权提供方（此处为 Foundry）发送回用户尝试授权的客户端（此处为第三方应用程序）。因此，指定重定向 URL 有助于在第三方应用程序请求访问 Foundry 资源时提供额外的安全保障。
    • 请注意，重定向 URL 可以稍后在 第三方应用用户界面 screen.

    如果您选择启用 客户端凭据许可 （仅机密客户端可用），系统将为该应用程序创建一个服务用户。可以为该服务用户授予访问 Foundry 资源的权限，以代表应用程序发起请求。

  2. 在监听器设置向导的 摘要 步骤中，将显示所提供的所有信息的概览，以及仍需补充的缺失内容。当必填字段填写完毕后，您可以点击 注册应用程序 （位于屏幕右下角）。

  3. 提交后，系统将向您显示新创建的客户端的 ID 和密钥（如适用）。

客户端密钥仅显示一次

如果使用 机密客户端，您 必须 ，请在此刻复制客户端密钥。离开此页面后，该密钥将无法再次获取。如果您丢失了客户端密钥，将需要轮换该密钥。

后续步骤

仅完成注册并不能使应用程序可用。在用户可以对其进行授权之前，必须为组织启用该应用程序；请参阅 启用第三方应用程序。项目访问权限和标记限制也是在该处设置的，而不是在注册期间设置。
