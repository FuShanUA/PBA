管理输出的 SQL 定义

与其他 Foundry 计算工作流不同，Furnace SQL 允许表格输出保留多个 SQL 定义。一个定义要么包含单个写入查询，要么包含 事务块中的多条语句。其中一个定义会被标记为 Active。

活跃定义是在表按计划或按需重建时运行的 SQL。选择不同的活跃定义会改变后续的重建行为，但不会立即运行该定义。

查看 SQL 定义

要查看与输出相关联的定义：

  1. 在 Dataset Preview中打开该输出。
  2. 选择 Details 标签页。
  3. 展开 Job spec 部分。

每个定义都会显示其 SQL 操作类型、上次运行、查询 ID 和 SQL。活跃定义由 Active 标签来标识。

在定义的选项菜单中，您可以：

  • 选择 Set as active definition ，以在后续的计划重建和按需重建中使用其 SQL。
  • 选择 Open in SQL Studio ，以在 SQL Studio中编辑或运行该 SQL。

创建更多定义

运行写入查询会为每个输出创建一个定义。输出的第一个定义会成为活跃定义。除了 CREATE OR REPLACE TABLE，后续每次写入都会保留现有定义、添加一个定义，并将新定义设为活动状态，除非你使用 adhoc 提示。 CREATE OR REPLACE TABLE 查询会替换重新创建的输出对应的现有定义。

使用 adhoc SQL 提示来运行一次性写入，并将其保留为附加定义，而不更改活动定义。

回填历史数据

考虑位于 /Sales/Orders 的 Iceberg 表，该表从每日输入接收新订单。其活动定义会在按计划或按需构建表时追加最新行：

Copied!
1
2
3
INSERT INTO `/Sales/Orders`
SELECT order_id, customer_id, order_date, total
FROM `/Sources/Orders daily`;

假设你后来发现某个历史输入包含输出中缺失的订单。请将回填作为临时定义运行：

Copied!
1
2
3
4
5
/*+ adhoc */
INSERT INTO `/Sales/Orders`
SELECT order_id, customer_id, order_date, total
FROM `/Sources/Orders history`
WHERE order_date < DATE '2026-01-01';

历史行会立即被追加，并且回填 SQL 会保留为附加定义。每日查询仍为活动定义，因此后续的定时构建和按需构建将继续追加数据，数据来源为 /Sources/Orders daily。

更改 Iceberg 表属性

考虑位于 /Manufacturing/Sensor readings 的 Iceberg 表，该表每小时接收传感器数据。其活动定义为：

Copied!
1
2
3
INSERT INTO `/Manufacturing/Sensor readings`
SELECT recorded_at, sensor_id, reading
FROM `/Sources/Sensor readings hourly`;

要使用 zstd 压缩来写入未来的数据文件，请将属性更改作为临时定义运行：

Copied!
1
2
3
4
5
/*+ adhoc */
ALTER TABLE `/Manufacturing/Sensor readings`
SET TBLPROPERTIES (
  'write.parquet.compression-codec' = 'zstd'
);

该属性仅会更新一次，而不会使 ALTER TABLE 语句处于活动状态。现有数据文件保持不变，而活动定义后续运行生成的数据文件将使用 zstd 压缩。

数据血缘

数据血缘 反映了所有保留的 SQL 定义所引用的输入，包括非活动定义和即席（ad hoc）定义。因此，即使某个输入未被活动定义引用，它也可能出现在血缘中。
