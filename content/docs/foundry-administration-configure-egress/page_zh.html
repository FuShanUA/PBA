配置网络出口

网络出口是指源自 Foundry 内部并尝试连接外部系统的任何网络流量。本页面概述了如何在 控制面板 中配置和管理网络出口，以及这些配置如何被 Foundry 中的用户工作负载使用。

从 Foundry 出口的网络流量仍可能导致数据双向流动。这意味着 Foundry 中被允许进行外部连接的工作负载可用于同步和导出数据。

与之相对， 网络 和 是指源自 Foundry 外部并尝试与 Foundry 建立连接的网络流量。网络入口同样在 Control Panel 中管理。

网络出口概述

Foundry 提供严格的网络防火墙来保护客户数据。客户管理的网络出口策略用于通过容器网络技术（Cilium ↗, eBPF ↗）将网络防火墙规则应用于各个工作负载。除了这些针对客户的特定规则外，Palantir 的信息安全团队还在基础设施代理层维护网络防火墙规则，以提供另一层安全保障。这些规则共同管理 Foundry 中用户工作负载的网络出口执行，包括以下内容：

  • 数据连接源 Automate 您必须正确配置出站策略（如果使用
  • 外部转换
  • 外部函数
  • 外部流式用户自定义函数（UDF）
  • 外部模型适配器 （用于建模实时部署）
  • 代码工作簿

打开网络出口路由始终存在安全风险。Foundry 注册的信息安全负责人应确保仅向受信任的目标开放网络路由，并将这些路由的访问权限限制在受信任的开发者群体中。即使是受信任的外部系统，也可能被恶意行为者滥用以绕过安全控制。信息安全负责人应利用 Foundry 的变更管理工具，确保对出口逻辑的变更由受信任的群体进行审查，并建立审计流程以确保出口逻辑持续安全。

网络出口策略创建后，其目标无法修改。网络出口策略创建后无法删除，只能被撤销。

存在多种出口策略类型，用于表示从 Foundry 到外部系统的不同网络路径：

  • 直接连接策略
  • 代理策略
  • 私有链接策略
  • 存储桶端点策略
  • 安全隧道出站策略

要创建出口策略，请导航至 选项卡,该选项卡位于 Control Panel 的 Control Panel 中的页面并选择 请求网络出口策略.

直接连接出口策略

直接连接策略支持从 Foundry 的网络直接向外部目标发起出口连接。对于托管在云端的 Foundry 实例，这意味着通过互联网建立的连接，例如 REST API 或托管在云端的系统。而对于本地部署的 Foundry 实例，这意味着连接到本地网络本身所连接的系统。外部系统必须允许来自 Foundry 的入站连接。

服务器名称指示（SNI）验证

Palantir 的网络基础设施默认会尝试对所有使用该端口的网络连接执行 SNI 验证 443 （默认 HTTPS 端口）。如果该端口上的流量没有 SNI（例如 FTP(S)、SFTP 以及大多数基于 TCP 的数据库连接就是这种情况），您可能会遇到连接挂起和/或超时错误。

如果您预期某个策略在端口 443 上存在非 HTTPS 流量，管理员可以禁用该策略上的 SNI 验证。

通配符出口策略

通配符地址允许您将域名的整个子域级别加入允许列表 （例如， *.domain.com），而无需逐个管理子域名。这在子域名是动态的或事先未知的情况下非常有用——例如 Azure SQL 重定向模式、Kafka 节点或 MongoDB SRV 连接。

通配符地址支持用于直接连接、代理和安道策略。 不支持用于私有链接或存储桶端点策略。

通配符必须作为单个元素出现在域名的最左侧标签中，并且不得 指向 公共后缀 （例如， *.com, *.co.uk, *.github.io）——如果是这样，该策略将 无法使用。一个通配符地址仅匹配一个子域级别。例如， *.domain.com 匹配 bar.domain.com 但不包括 domain.com or bar.baz.domain.com.

*.s3.amazonaws.com❌ 公共后缀
subdomain.*.com❌ 中间通配符
*.*.domain.com❌ 多个通配符

代理代理出站策略

代理代理出站策略支持通过 Data Connection 代理连接到本地部署或私有托管的系统。代理代理出站策略允许 Foundry 工作流运行 如同 直接连接到外部系统一样，无需任何额外配置；所有流量都通过代理透明地转发。

使用代理代理策略时，Foundry 不会向外部系统发起入站连接，外部系统也无需允许来自 Foundry 的入站连接。但是，代理主机必须具有通往目标外部系统的出站网络连接，并且目标外部系统必须允许来自代理主机的入站连接。

使用代理出站策略的数据源支持以下工作流：

  • 所有第一方 数据连接功能
    • 不支持的工作流：
      • 虚拟表
      • OIDC 身份验证
  • 外部转换 （仅 VS Code 支持预览）
  • 外部 已部署的函数。了解更多关于 外部函数.
  • 外部流式传输 用户自定义函数 (UDF)
  • 代码工作区
  • 计算模块

按照以下步骤成功应用网络策略：

  1. 在 Control Panel 中创建策略。如果您的 Foundry 策略由 Palantir 管理，请将您的出站策略详情提供给您的 Palantir 代表。这样 Palantir 可以在扩展网络访问之前评估安全风险。如果您的 Foundry 策略管理完全自助，该策略将自动应用到防火墙。

  2. 将策略分配给用户工作负载：

  • 使用 Foundry worker 的 Data Connection 数据源： 在创建 新数据源.
  • Code Workbook： 细粒度网络管理尚不可用，管理员必须改为创建全局策略。全局策略会不加区分地应用于所有工作负载，仅应为高度信任的网络路由进行配置。

要将策略分配给用户工作负载， 需要针对特定出站策略具有 Importer 权限。此权限通过相应出站策略上的 管理共享 设置按策略授予。

部分中选择

TCP 级别允许列表

出站控制可以在 HTTP 或 TCP 级别强制执行。除端口 80 和 443上的直接连接策略外，所有出站策略都需要 TCP 级别允许列表，这些端口是 HTTP 和 HTTPS 流量的标准端口。无论是否使用 TCP 级别允许列表，连接的安全性都不会改变。

如果非 HTTP(S) 流量通过使用端口 80 or 443的策略传输，您必须启用 TCP 级别允许列表才能成功出站。

常见边缘情况

当存在两个相同的策略，其中一个被暂停/撤销而另一个处于活跃状态时，会发生什么？

任何使用活跃策略的工作负载都将成功运行，而尝试使用已暂停/撤销策略的工作负载将无法运行。

如果策略相互重叠，其中一个被暂停/撤销而另一个处于活跃状态，会发生什么？

当使用单个 IP 地址的策略与指定 IP 地址 CIDR 块的策略重叠时，可能会发生这种情况。

在这种情况下，与相同策略一样，任何使用活跃策略的工作负载都将成功运行，而尝试使用已暂停/撤销策略的工作负载将无法运行。

如果我提议的策略已经存在，会发生什么？

允许重复策略，审查提议的信息安全官可以选择执行以下操作之一：

  1. 完全拒绝该提议。
  2. 拒绝该提议，并授予提议者对现有相同或重叠策略的“Importer 访问权限”。
  3. 批准该提议并允许重复或重叠的策略（不推荐）。

来自 Foundry 的连接使用哪些 IP？

当从 Foundry 向外部目的地发起连接时，这些连接来自特定的 IP 范围。有时需要将这些 IP 添加到允许列表中，来自 Foundry 的连接才会被接受。

当 Foundry 托管在 Palantir 的云基础设施中时，Foundry 流量发出的出口 IP 将显示在控制面板的网络出口管理页面上。在目标系统的允许列表中添加时，您应复制那里显示的 CIDR 范围。

Amazon S3 存储桶策略

S3 存储桶策略已被 存储桶端点策略 取代，未来将需要进行迁移。这两个概念之间的区别如下：

  • 范围： 存储桶端点 策略会为每个 注册（enrollment）创建一个 VPC 端点，而 S3 存储桶 策略则为每个 Palantir 平台 Foundry 实例创建一个。这意味着仅基于 VPC 端点允许访问的 S3 存储桶策略可能会允许您组织之外的用户进行未经授权的访问。
  • 限制： 您最多可以创建 1000 个 存储桶端点 策略，但只能创建 10 个 S3 存储桶 policies.
  • 控制： 存储桶端点 策略必须附加到 数据源 才能生效；只有使用这些数据源的工作负载才能通过它们路由流量。 S3 存储桶 策略则会立即生效，并适用于所有尝试从 Foundry 直接出口到该存储桶的工作负载。

对于托管在 AWS 中的 Foundry 实例，连接同一区域的 S3 存储桶时需要进行额外配置。这是由于 AWS 处理从 VPC 网关端点对同一区域 S3 的请求的网络方式所致。

要检查您的连接是否需要额外配置，请导航到控制面板中的 选项卡,该选项卡位于 Control Panel 的 页面。如果您发现一个名为 S3 存储桶策略的附加标签页，则说明您的实例托管在 AWS 中，您必须明确允许来自 Palantir 的 VPC 端点到同一区域中任何 S3 存储桶的流量。

如果存在， S3 存储桶策略 标签页还将显示您的实例所在的区域，以及用于将流量从 Foundry 路由到任何同区域 S3 存储桶的 VPC 端点的 Amazon 资源编号 (ARN)。

要成功连接到与 Foundry 位于同一区域的存储桶，您必须完成以下操作：

  1. 在 AWS 控制台中配置您的存储桶策略，以允许来自您 Foundry 实例的 VPC 端点的流量。了解更多关于 AWS 存储桶策略 ↗.
  2. 确保您所需的存储桶列在 Network egress > S3 bucket policies > AWS S3 Bucket Policies （在控制面板中）。
  3. 按照所述创建适当的网络出口策略 上文，并将其添加到 数据连接源 的配置详细信息中，您正在使用该源进行连接。

添加 S3 存储桶策略

要添加同区域存储桶，请选择 添加存储桶策略 并按照提示输入您所需的存储桶名称，如下所示：

表单将自动检查有效的存储桶名称以及区域。如果有效的存储桶名称与您的 Foundry 实例所在的区域匹配，您就可以保存。除了存储桶名称之外，您还必须提供以下策略： READ ONLY or READ WRITE。这决定了 Palantir 在建立与 S3 的连接时请求的访问级别。

将同区域 S3 存储桶添加到允许列表，以及所需的存储桶访问策略，应被视为 最低 级别的访问权限，保证可通过您 Foundry 实例的 VPC 终端节点使用。

S3 中的数据应通过 AWS 中适当的身份验证和授权进行保护，同时结合 Foundry 内的网络出口策略治理。

Palantir 可能会扩展所提供的列表以允许访问其他同区域存储桶，并且还可能将给定存储桶的访问策略从 READ ONLY to READ WRITE。使用时的正确身份验证和授权 S3 源类型 将确保您不会意外允许未经授权的 Foundry 用户访问您的 S3 存储桶。

使用 S3 存储桶策略

添加后，同区域存储桶策略将立即生效，并适用于所有尝试从 Foundry 直接出口到该存储桶的工作负载。 与网络出口策略不同，它们不需要附加到 Foundry 中的特定源或其他工作负载。

创建 S3 源时，配置界面会自动检查存储桶是否与 Foundry 位于同一区域，以及该存储桶是否已添加到 Control Panel 中。配置源的用户将看到绿色勾号（表示存储桶已正确添加）或红色勾号（表示需要由有权在 Control Panel 中添加 S3 存储桶策略的管理员采取操作）。

S3 存储桶策略限制

每个注册最多可以添加 10 个同区域存储桶。如果您需要从 Foundry 实例访问超过 10 个同区域 S3 存储桶，请联系 Palantir Support。
