配置网络出口

网络出口是指源自 Foundry 内部并尝试连接到外部系统的任何网络流量。本页概述了如何在 Control Panel 中配置和管理网络出口，以及这些配置如何被 Foundry 中的用户工作负载所使用。

网络 入口 指源自 Foundry 外部并尝试与 Foundry 建立连接的网络流量。网络入口也在 Control Panel 中进行管理。

网络出口概述

Foundry 提供严格的网络防火墙来保护客户数据。客户管理的网络出口策略用于通过容器网络技术（Cilium ↗、 eBPF ↗）将网络防火墙规则应用于各个工作负载。除这些特定于客户的规则外，Palantir 的信息安全团队还在基础架构代理层维护网络防火墙规则，以提供另一层安全保障。这些规则共同管控 Foundry 中用户工作负载的网络出口执行，包括以下内容：

  • 数据连接源 使用 Foundry worker
  • 外部转换
  • 外部函数
  • 外部流式用户定义函数（UDF）
  • 外部模型适配器 （用于模型在线部署）
  • Code Workbook

从 Foundry 出站的网络流量仍可能导致数据双向流动。这意味着 Foundry 中被允许连接外部的工作负载可能同时被用于同步和导出数据。

开启网络出站路由始终存在安全风险。Foundry 注册的信息安全负责人应确保仅向受信任的目标开放网络路由，并将这些路由的访问权限限制在受信任的开发者群体中。即使是受信任的外部系统，也可能被恶意行为者滥用来绕过安全控制。信息安全负责人应利用 Foundry 变更管理工具，确保出站逻辑的变更由受信任的群体进行审查，并建立审计流程以确保出站逻辑保持安全。

网络出站策略的目标在策略创建后即无法修改。网络出站策略创建后无法删除，只能撤销。

存在多种出站策略类型，用于表示从 Foundry 到外部系统的不同网络路径：

  • 直接连接策略
  • Agent 代理策略
  • 专用链接策略
  • 存储桶端点策略
  • 安全隧道策略

要创建出站策略，请导航至控制面板中的 网络出站 页面，然后选择 请求网络出口策略。

直接连接出口策略

直接连接策略允许建立从 Foundry 网络直接向外部目标发送出口流量的连接。对于托管在云中的 Foundry 实例而言,这意味着通过互联网建立的连接,例如 REST API 或托管在云中的系统;而对于本地部署的 Foundry 实例而言,则意味着连接到与本地网络本身相连的系统。

外部系统必须允许来自 Foundry 的入站连接。

服务器名称指示（SNI）验证

Palantir 的网络基础设施默认会尝试对所有使用端口 443 （默认 HTTPS 端口）的网络连接执行 SNI 验证。如果通过该端口的流量不带有 SNI——某些协议（如 FTP(S)、SFTP 以及大多数基于 TCP 的数据库连接）即属于这种情况——您可能会遇到连接挂起和/或超时错误。

如果预计某个策略的 443 端口上会出现非 HTTPS 流量，管理员可以禁用该策略的 SNI 验证。

通配符出口策略

通配符地址允许您将域名的整个子域级别加入允许列表 （例如， *.domain.com），而无需逐个管理子域名。当子域名是动态的或事先未知时（例如 Azure SQL 重定向模式、 Kafka 节点或 MongoDB SRV 连接），这会非常有用。

直接连接策略和 agent 代理策略支持通配符地址。 私有链接策略和存储桶端点策略则不支持通配符地址。

通配符必须作为单个元素出现在域名的最左侧标签中，且 不得针对 公共后缀 （例如， *.com, *.co.uk, *.github.io）——如果这样做，该策略 将无法使用。通配符地址仅匹配单个子域级别。例如， *.domain.com 匹配 bar.domain.com 但不匹配 domain.com 或 bar.baz.domain.com。

代理出站策略

代理出站策略支持通过 Data Connection 代理连接到本地部署或私有托管的系统。代理出站策略允许 Foundry 工作流 如同 直接连接到外部系统一样运行，无需任何额外配置；所有流量都将通过代理进行透明转发。

在此场景下，不会从 Foundry 向外部系统发起入站连接，外部系统也无需允许来自 Foundry 的入站连接。

但是，代理主机必须具有到目标外部系统的出站网络连接，且目标外部系统必须允许来自代理主机的入站连接。

以下工作流支持使用代理出站策略的源：

  • 所有原生支持的 数据连接功能
    • 不支持的工作流：
      • 虚拟表
      • OIDC 身份验证
  • 外部转换 （仅 VS code 支持预览）
  • 外部 已部署函数。了解有关 外部函数的更多信息。
  • 外部流式处理 用户自定义函数（UDF）
  • 代码工作区
  • 计算模块

安全隧道出口策略

Beta

安全隧道目前处于 beta 开发阶段，将取代 agent 代理出口策略。在积极开发期间，功能可能会发生变化，且该功能可能并非在所有 enrollment 上均可用。在生产工作负载中采用安全隧道之前，请联系您的 Palantir 代表或 Palantir Support。

安全隧道出口策略支持通过 安全隧道连接到本地部署或私有托管的系统。与 agent 代理一样，Foundry 工作负载的运行方式 如同 直接连接到外部系统；所有流量都通过 安全隧道发起程序进行透明中转，该程序在您的网络内运行。

在此场景下，不会从 Foundry 向外部系统发起入站连接，外部系统也无需允许来自 Foundry 的入站连接。

但是，安全隧道发起方必须具有通往目标外部系统的出站网络连接，且目标外部系统必须允许来自安全隧道发起方的入站连接。此外，该目标还必须获得在安全隧道发起方上配置的 出站允许列表 的许可。

存储桶端点出站策略

目前仅支持 Amazon AWS 存储桶策略。

当 Palantir 平台与您需要出站连接的外部系统（Amazon AWS、Azure 或 Google Cloud Platform）托管在同一云服务提供商上时，可能需要配置特定的允许列表，才能让流量在云服务提供商的特定端点之间流动。允许列表通过 存储桶端点 出站策略进行控制。

存储桶端点出站策略目前仅支持 AWS S3 存储桶。请阅读以下内容，了解 Azure 和 Google Cloud Platform 的特定出站配置。

网络出口的主要管理界面位于控制面板中的注册层级。有权访问 Manage network egress configuration 与注册管理员角色相关联的工作流的用户，将能够访问 网络出口 页面，以对出口策略执行任何管理操作。

此外，注册管理员和信息安全官始终可以查看某个出口策略已被导入到哪些项目中。无论管理用户本人是否拥有这些项目的访问权限，都可以查看此信息。提供此元数据是为了确保信息安全官对策略的使用情况具有足够的可见性，从而能够就是否撤销或以其他方式限制策略的使用做出治理决策。

在审批策略时，信息安全官必须决定应向哪些用户或组授予以下能力： View 或 Import 网络出口策略。之后，也可以在控制面板中使用策略详情页面上的 管理共享 按钮来管理这些设置。

默认情况下,策略采用“选择性加入”(opt-in)模式,必须附加到 Foundry 中的工作负载。例如,在创建数据连接源时,适用于该源的策略应由具有 Importer 该策略权限的用户显式附加到该源。这遵循 最小权限原则 ↗,确保工作负载仅被授予该工作负载成功运行所严格必需的出口规则。

有权 Import 访问网络出口策略的用户可以在 Foundry 中运行与目标地址通信的任意代码。 请确保被授予导入权限的所有用户均受信任,并已接受您所在组织信息安全策略方面的培训,以避免滥用此访问权限。

应用策略

请按照以下步骤操作，以成功应用网络策略：

  1. 在 Control Panel 中创建策略。如果您的 Foundry 策略由 Palantir 管理，请将出站策略的详细信息提供给您的 Palantir 代表。这样，Palantir 便可在扩大网络访问范围之前评估安全风险。如果您的 Foundry 策略管理完全采用自助服务模式，则该策略将自动应用于防火墙。

  2. 将策略分配给用户工作负载：

  • 使用 Foundry worker 的 Data Connection 数据源： 请在创建 新源时指定网络策略。
  • Code Workbook： 细粒度网络管理目前尚不可用，管理员必须改为创建全局策略。全局策略会无差别地应用于所有工作负载，因此仅应针对高度可信的网络路由进行配置。

要将策略分配给用户工作负载， Importer 权限是特定出站策略所必需的。此权限通过相应出站策略上的 管理共享 设置按策略逐一授予。

限制

您最多可以将 10 个源导入到代码资源或转换中，且使用 TCP 级别允许列表 的出站策略合计最多 50 个。

可观测性

要使用日志和指标来监控和排查网络出站策略，请查阅我们的 网络出站可观测性 文档。

高级设置

TCP 级别允许列表

出站控制可以在 HTTP 级别或 TCP 级别强制执行。所有出站策略都需要 TCP 级别允许列表，但在端口 80 和 443（即 HTTP 和 HTTPS 流量的标准端口）上的直接连接策略除外。无论是否使用 TCP 级别允许列表，连接的安全性都不会改变。

如果非 HTTP(S) 流量通过使用端口 80 或 443的策略进行传输，则必须启用 TCP 级别允许列表才能成功出站。

常见边缘情况

当存在两个完全相同的策略，其中一个已暂停/已撤销，而另一个处于活动状态时，会发生什么？

使用处于活动状态的策略的所有工作负载都将成功运行，而尝试使用已暂停/已撤销策略的工作负载将无法运行。

如果策略存在重叠，且其中一个被暂停/撤销，而另一个仍处于活跃状态，会发生什么？

如果一个策略使用单个 IP 地址，而另一个策略指定了 CIDR IP 地址块，两者发生重叠时，就可能出现这种情况。

在这种情况下，与策略完全相同的情况一样，使用活跃策略的所有工作负载都将成功运行，而尝试使用已暂停/撤销策略的工作负载将无法运行。

如果我提议的策略已经存在，会发生什么？

允许存在重复的策略，审查该提议的信息安全官可以选择执行以下操作之一：

  1. 完全拒绝该提议。
  2. 拒绝该提议，并授予提议者对现有相同或重叠策略的 "Importer access"（导入者访问权限）。
  3. 批准该提议并允许存在重复或重叠的策略（不推荐）。

来自 Foundry 的连接使用哪些 IP？

当从 Foundry 向外部目标发起连接时，这些连接来自特定的 IP 范围。有时，需要先将这些 IP 添加到允许列表中，来自 Foundry 的连接才会被接受。

当 Foundry 托管在 Palantir 的云基础设施中时，Foundry 流量来源的出口 IP 将显示在控制面板的网络出口管理页面上。在目标系统的允许列表中添加这些范围时，您应复制此处显示的 CIDR 范围。

请注意，通过 代理 进行的连接的处理方式有所不同。使用代理时，发往源系统的网络流量始终来自您基础设施上的代理主机；您有责任确保代理与目标系统之间的网络连通性。

云服务提供商出口

Amazon S3 存储桶策略

S3 存储桶策略已被 存储桶端点策略 取代，将来需要进行迁移。这两个概念之间的差异如下：

  • 范围： 存储桶端点 策略为每个 注册创建一个 VPC 端点，而 S3 存储桶 策略则为每个 Palantir 平台 Foundry 实例创建一个。这意味着，仅基于 VPC 端点允许访问的 S3 存储桶策略可能会允许您组织之外的用户进行未经授权的访问。
  • 限制： 您最多可以创建 1000 个 存储桶端点 策略，但只能创建 10 个 S3 存储桶 策略。
  • 控制： 存储桶端点 策略必须附加到 数据源 才能生效；只有使用这些源的工作负载才能通过它们路由流量。 S3 存储桶 策略则会立即生效，并适用于所有尝试从 Foundry 直接出口到该存储桶的工作负载。

对于托管在 AWS 中的 Foundry 实例，连接同一区域中的 S3 存储桶时需要进行额外配置。这是由于 AWS 处理从同一区域中的 VPC 网关端点到 S3 的请求的网络方式所致。

要检查您的连接是否需要额外配置，请导航至 网络出口 页面（位于控制面板中）。如果您发现一个名为 S3 存储桶策略的额外选项卡，则表示您的实例托管在 AWS 中，并且您必须明确允许从 Palantir 的 VPC 端点到同一区域中任何 S3 存储桶的流量。

如果存在， S3 存储桶策略 选项卡还将显示您的实例托管所在的区域，以及用于将流量从 Foundry 路由到任何同一区域 S3 存储桶的 VPC 端点的 Amazon 参考编号 (ARN)。

要成功连接到与 Foundry 位于同一区域的存储桶，您必须完成以下操作：

  1. 在 AWS 控制台中配置存储桶策略，以允许来自您 Foundry 实例的 VPC 终端节点的流量。了解有关 AWS 存储桶策略 ↗的更多信息。
  2. 请确保您所需的存储桶已列于控制面板的 网络出口 > S3 存储桶策略 > AWS S3 存储桶策略 中。
  3. 创建适当的网络出口策略，如 上文所述，并将其添加到您用于连接的 Data Connection 源 的配置详细信息中。
