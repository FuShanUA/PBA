useProjects 钩子

该 useProjects 钩子提供了一个全面的接口，用于在高级待办事项应用程序中获取和管理项目数据，重点在于计算实时任务统计信息。它利用本体论 SDK（OSDK）以类型安全的方式与后端服务交互，为组件提供了简洁的接口来访问项目数据以及聚合的任务指标。

该钩子实现了 运行时派生属性 ，以便高效计算每个项目的任务统计信息，例如任务总数及其在不同状态类别（已完成、进行中、未开始）中的分布情况。通过使用 SWR（stale-while-revalidate）进行数据获取，它可确保网络请求得到优化，同时通过可配置的缓存策略保持数据处于最新状态。

查看 useProjects 参考代码。

核心功能

  • 服务器端聚合： 使用运行时派生属性模式来执行服务器端聚合，从而最大限度地减少数据传输。
  • 类型安全： 通过 TypeScript 接口和 OSDK 类型实用工具，全程确保类型安全。
  • 状态过滤： 在服务器端聚合期间，根据任务的字面状态值（COMPLETED、 IN PROGRESS、 NOT STARTED）对任务进行过滤。
  • 错误处理： 通过 SWR 的 error 状态来呈现获取失败的情况，该钩子将其返回为 isError。
  • 性能优化： 使用自定义选项配置 SWR，以优化网络请求和缓存。
  • 简洁的返回接口： 提供一个结构良好的返回对象，便于组件轻松使用。
  • 对组件友好的数据： 将数据转换为可供组件直接使用、无需额外处理的格式。

const fetcher = useCallback(async () => {
  const projectsPage = await client(AdvanceTodoProject)
    .withProperties({
      // Runtime-derived property definitions for per-task-type counts
    })
    .fetchPage();

  const projects: IProject[] = projectsPage.data.map((project) => {
    return {
      ...project,
      numberOfTasks: Number(project.numberOfCodingTasks) + Number(project.numberOfLearningTasks),
      numberOfCompletedTasks: Number(project.numberOfCompletedCodingTasks) + Number(project.numberOfCompletedLearningTasks),
      numberOfInProgressTasks: Number(project.numberOfInProgressCodingTasks) + Number(project.numberOfInProgressLearningTasks),
      numberOfNotStartedTasks: Number(project.numberOfNotStartedCodingTasks) + Number(project.numberOfNotStartedLearningTasks),
    };
  });

  return projects;
}, [client]);

实现

运行时派生属性

运行时派生属性是一种强大的模式，它允许仅计算和获取运行时所需的数据，而不是检索整个对象并在客户端计算值。

在此 hook 中,运行时派生属性用于直接在服务器上计算任务统计信息:

.withProperties({
  "numberOfCodingTasks": (baseObjectSet) =>
    baseObjectSet.pivotTo("codingTasks").aggregate("$count"),
  "numberOfCompletedCodingTasks": (baseObjectSet) =>
    baseObjectSet.pivotTo("codingTasks").where({
      "status": { $eq: "COMPLETED" },
    }).aggregate("$count"),
  "numberOfLearningTasks": (baseObjectSet) =>
    baseObjectSet.pivotTo("learningTasks").aggregate("$count"),
  "numberOfCompletedLearningTasks": (baseObjectSet) =>
    baseObjectSet.pivotTo("learningTasks").where({
      "status": { $eq: "COMPLETED" },
    }).aggregate("$count"),
  // Additional properties for in progress and not started counts...
})

此实现使用了几个关键的 OSDK 模式:

  • pivotTo: 从项目导航至其关联的任务

    • 目的: 遍历项目与其任务之间的关系
    • 优点: 无需复杂的关系管理即可联接相关数据

  • where: 应用筛选器以选择具有特定状态的任务

    • 目的: 根据属性条件对集合进行筛选
    • 优点: 通过在服务器端进行筛选来减少数据传输

  • aggregate: 在筛选后的集合上计算计数

    • 目的: 执行服务器端数据聚合
    • 优点: 仅返回聚合结果,从而最大程度地减少数据传输

  • 客户端总计: 在映射结果时,对每种任务类型的计数使用 Number(...) 加法求和

    • 目的: 将编码任务和学习任务各自的计数合并为一个总数
    • 优点: 使每个运行时派生属性仅执行单一聚合,同时仍能提供合并后的总计

优点

  • 性能优化: 计数在服务器端进行,减少了数据传输
  • 减少客户端计算: 客户端仅接收最终计数
  • 单一请求模式: 所有统计数据均通过一次请求获取
  • 声明式数据需求: 代码具有自文档性

@advanced-to-do-application/sdk

用途： 特定于应用程序的 SDK，包含预定义的数据类型 优势：

  • 包含项目的数据模型（AdvanceTodoProject）
  • 提供对项目属性和关系的类型化访问
  • 在整个应用程序中实现一致的类型强制执行
  • 简化与应用程序数据模型的交互

@osdk/client & @osdk/react

用途： 用于与后端数据服务交互的本体论 SDK 客户端 优势：

  • 为数据模型提供类型安全的接口
  • 支持使用复杂筛选进行结构化数据查询
  • 支持用于服务器端计算的运行时派生属性模式
  • 提供了用于类型操作的实用工具，可通过 PropertyKeys 和 Osdk.Instance
  • 公开了类似 useOsdkClient 的钩子，用于访问客户端实例

useSWR

用途： 数据获取、缓存和状态管理 优势：

  • 提供了一种获取和缓存项目数据的优雅方式
  • 自动处理加载和错误状态
  • 提供内置的重新验证策略，并支持可配置的选项
  • 通过智能缓存减少网络请求
  • 通过自动错误处理简化数据获取

import React from 'react';
import useProjects, { type IProject } from '../dataServices/useProjects';

const ProjectsPage: React.FC = () => {
  const { projects, isLoading, isError } = useProjects();
  
  if (isLoading) return <div>Loading projects...</div>;
  if (isError) return <div>Error loading projects: {isError.message}</div>;
  
  return (
    <div className="projects-container">
      <h1>Projects ({projects.length})</h1>
      
      {projects.length === 0 ? (
        <div className="empty-state">No projects found</div>
      ) : (
        <div className="projects-grid">
          {projects.map(project => (
            <ProjectCard 
              key={project.$primaryKey} 
              project={project}
            />
          ))}
        </div>
      )}
    </div>
  );
};

// ProjectCard component using the data
const ProjectCard: React.FC<{ project: IProject }> = ({ project }) => {
    
  return (
    <div className="project-card">
      <h3>{project.name}</h3>
      <div className="progress-bar">
        <div 
          className="progress-fill" 
        />
      </div>
      <div className="task-stats">
        <div>Total Tasks: {project.numberOfTasks}</div>
        <div>Completed: {project.numberOfCompletedTasks}</div>
        <div>In Progress: {project.numberOfInProgressTasks}</div>
        <div>Not Started: {project.numberOfNotStartedTasks}</div>
      </div>
    </div>
  );
};

export default ProjectsPage;

边缘情况和限制

在使用 useProjects hook 时，请考虑以下场景和限制：

  • 空结果处理： 该实现能够妥善处理空结果集，返回空数组而不是抛出错误。
  • 错误恢复： 该 hook 依赖于 SWR 的默认错误重试行为，但复杂的故障场景可能需要额外的处理。
  • 分页限制： 当前实现会一次性获取所有项目，当项目数量较多时可能会出现问题。请考虑使用 fetchPage 选项为大型数据集实现分页。
  • 任务类型依赖： 该 hook 会专门查找 codingTasks 和 learningTasks 关系。如果系统中添加了新的任务类型，则需要更新运行时派生的属性查询。
  • 轮询更新： 该 hook 未实现轮询更新。对于需要实时更新的应用，请考虑添加轮询机制或集成 WebSocket。
  • 任务状态枚举耦合： 该 hook 与特定的任务状态值紧密耦合。如果后端更改了这些值，前端也需要相应地进行更新。
  • 数学派生属性： 虽然 numberOfTasks 是通过将不同任务类型的计数相加计算得出的，但也可以改为在后端预先计算。请考虑评估不同方法的性能权衡。
