多数据源对象类型 (MDO)

多数据源对象类型 (MDO) 由本体论中的多个数据源支撑，仅在 Object Storage v2 中可用。目前，只有 Foundry 数据集 or 受限视图 可用于 MDO。不支持流式数据源。

多数据源对象类型 (MDO) 的类型

MDO 分为两种不同的类别：

  • 列式 MDO： 一种类似连接 (join) 的 MDO 场景，其中对象类型的不同属性子集可以来自不同的数据源。列式 MDO 可用于支持需要列级访问控制的用例。
  • 行式 MDO： 一种类似联合 (union) 的 MDO 场景，其中完整对象（包含其所有属性的对象）可以来自共享相同数据源的多个数据源。行式 MDO 可用于支持需要行级访问控制的用例。在 Foundry 中， 受限视图 为可能使用行式 MDO 的用例提供支持。行式 MDO 本身不可用。

Foundry 仅支持列式 MDO，不支持行式 MDO。大多数行式 MDO 用例可以通过 受限视图来实现。如果您有无法通过受限视图实现的行式 MDO 用例 不能 ，请联系您的 Palantir 代表寻求帮助。

配置多数据源对象类型

晚于 创建对象类型 在 Ontology Manager 中使用 Object Storage v2 创建对象类型后，导航至 数据源 从左侧边栏进入对象类型的元数据部分。然后，选择 添加新的支撑数据源 以选择一个数据集。

直方图 映射主键 助手将会出现，并提示您选择一个其值与对象类型主键相匹配的列。选择列后，多个支撑数据集将显示在 支撑数据源 区域的字段中添加命令。

在 Data Connection 中导航至 属性 从左侧边栏进入元数据部分，为新增的数据集添加新字段。

FAQ

多数据源对象类型是否适用于索引到 Object Storage v1 (Phonograph) 的对象类型？

不适用。MDO 仅在 Object Storage v2 中受支持，在 Object Storage v1 (Phonograph) 中不可用。

列式 MDO 和行式 MDO 是否都受支持？

目前仅列式 MDO 可用。如果您有无法通过受限视图实现的行式 MDO 用例，请联系您的 Palantir 代表寻求帮助。

MDO 是否支持用户编辑和物化？

是的， 用户编辑 和 物化 在 MDO 中受支持。

如果用户无法查看某个对象类型的部分输入数据源，会发生什么？用户体验会是怎样的？

如果用户缺少 Viewer 对部分输入数据源的权限，则来自这些数据源的映射属性将显示为 null （在向用户显示对象时）。但是，用户仍然能够查看该对象类型的 schema（例如查看属性名称），因为对对象类型的访问与输入数据源是分开控制的。

了解更多关于对象类型权限的信息。

是否支持属性多重性？

属性多重性是指在列式 MDO 场景中，多个输入数据源为对象类型提供重叠的列/属性。目前不支持属性多重性。这意味着对象类型的某个特定属性必须来自其中一个输入数据源——且仅能来自一个（主键属性除外，主键属性必须存在于每个输入数据源中，以便连接所有数据源）。

如果多个受限视图数据源共享相同的策略，对应于受限视图策略的属性是否可以映射到多个受限视图数据源？

不支持；每个受限视图数据源都应在对象类型上拥有单独的策略属性。其中一些属性可以在 本体论管理器 中标记为隐藏，以避免前端应用过于杂乱。

MDO 与通过外键关系关联两个不同对象类型之间有什么区别？用户应如何在这些选项之间做出选择？

MDO 旨在提供一种用户友好的方式，将相同的设置配置为单一对象类型，以构建组织的数字孪生。对于用户以这种方式理解和交互其数据的场景，也可以使用多个对象类型及其之间的关联，但在多个对象类型之间查询和遍历关联比在同一对象类型上按属性进行过滤的开销更大。

如果某个对象的两个列式数据源具有不同的主键集合，会出现哪些对象？

如果某个对象的两个列式数据源具有不同的主键集合，其行为将类似于某些用户无法访问某些输入数据源的情况。在这些情况下，不存在于某个数据源中的主键，其从该特定输入数据源映射的属性将显示为 null.

一个对象类型可以拥有的数据源数量是否有限制？

对象类型最多可包含 70 个数据源。只有同步到对象存储的数据源才计入此限制，因此不包括媒体集或时间序列同步。

可以在流式对象类型中使用 MDO 吗？

不可以，MDO 不支持流式对象类型。这是 Object Storage v2 的已知限制。
