核心概念

我们建议在使用 Machinery 应用程序之前先了解以下概念。

流程

在真实世界的流程中，文档、设备或个人等实体会随着时间的推移在不同的 状态 之间转换。许多流程对象可以相互关联，以表示流程中涉及的多个实体。在 Machinery 中，您可以通过包含状态和操作的流程容器来对这些流程进行建模。这些流程容器可以相互关联，甚至可以嵌套。

流程中的实体，也称为“流程对象”，可以通过本体论中的对象类型来表示，例如 Claim， 航班，或 员工。该对象类型必须具有一个表示对象状态的字符串类型属性。

状态

状态描述对象的当前状况，例如 进行中 或 已送达 是包裹的一种状态。可能的状态必须是可枚举的。例如， Name 属性并不合适，因为可能的名称有无限多个。

状态转换显示为状态节点之间的边。

每个对象必须处于 一个 可能的状态（在任意给定时间）。并非如此的场景应建模为流程层级。例如，员工的状态可能是 新员工 还是 已入职，同时也 已付款 或 等待付款 同时。这些应该是独立的流程，并由一个父流程来跟踪该员工是否 payable.

在本体论中，状态被编码为 State 属性的字符串值。该值等同于 Machinery 中的状态 ID。要更改图中显示的状态标签，您可以覆盖显示名称。

Machinery 中的状态 ID 等同于您数据中的状态值。为避免输入错误或不一致，您可以通过枚举 值类型来支撑您的状态属性。这将确保本体论中的数据只能采用预定义的一组值。Machinery 会检测到该设置并使流程状态保持同步。

操作与自动化

操作是状态转换的原因。平台内发生的状态变化由一项 操作定义。您可以将它们导入到 Machinery 图中，并明确它们在流程中的角色。

流程日志

流程的本质在于实体会随着时间的推移发生变化。要识别对象所经路径中的模式，或获取诸如在某一状态下停留的平均时间等指标，捕捉变化的时间维度至关重要。Machinery 通过维护一个 Log 对象类型来跟踪对对象所做的每项更改，无论这些更改来自外部数据源还是 Foundry 操作。

您可以像查看任何其他对象类型一样查看此对象类型，但不应自行在其上定义操作，因为日志对象类型由 Machinery 自动维护。

每个日志对象类型跟踪单个对象类型属性的更改。每个流程都可以有自己的流程日志。

对于在平台之外发生的过程，您需要提供一个变更日志格式的数据集，以跟踪哪个对象在何时进入了哪个状态。Machinery 会计算分析和监控所需的派生数据，例如先前状态、状态之间的持续时间，以及对象迄今为止所经历的路径。
