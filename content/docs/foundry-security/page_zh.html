由于我们的软件支撑着大型企业和政府机构的关键任务运营，我们的威胁模型侧重于击败资源雄厚、技术精湛且持久顽固的攻击者。为了击败这些对手，我们秉持坚决鲜明的立场，并为所有客户强制执行高标准的安全基线。例如，多年来，我们一直强制要求所有托管式软件即服务（SaaS）平台客户使用多因素身份验证。

平台安全

Palantir 平台将安全视为核心开发理念。Palantir 安全模型支持严格实施细粒度访问控制，同时兼顾透明性和易用性，从而构建协作互信的生态系统：

  • 严格执行： 确保用户只能访问其被授权交互的数据。
  • 细粒度控制： 功能强大，足以实现灵活的访问控制粒度级别。
  • 透明性： 使用户能够了解 谁 有权访问 什么 资源以及 为什么。
  • 易用性： 使用户能够自信地理解和管理访问控制。

Palantir 安全模型同时涵盖身份验证和授权两个方面。身份验证用于核实用户的身份，而授权则根据用户的属性和权限授予相应的访问权限。

Palantir 平台的数据安全通过强制控制与自主控制的组合来提供，这两种控制在传播方式上有所不同。强制控制（标记、 基于分类的访问控制和 组织）会借助 Palantir 的溯源和血缘功能，在派生过程中随每个数据单元一起传播。自主控制则是按单个资源授予给用户的。这些控制包括资源级角色授予（所有者、编辑者、查看者、发现者），以及通过以下各项上的细粒度策略实现的行或列过滤： 受限视图、 对象安全策略和 属性安全策略。自主的行级和列级控制会过滤用户可读取的内容；这些控制不会延伸到下游输出或导出数据。有关完整模型，请参见 访问控制传播。

Palantir 平台中的数据和资源按项目进行组织。用户隶属于组织，并被编入由平台内部管理或通过外部身份提供商管理的群组。组织是应用于项目的一种强制控制形式，可在用户群组与资源之间实施严格的隔离。因此，除非已明确配置共享协议，否则一个组织的用户无法访问另一个组织的资源。

对于高度敏感的数据，标记是另一种形式的强制性控制，可应用于需要特殊保护的数据或资源（例如 PII 或财务敏感数据）。除了组织成员身份之外，用户还必须拥有特殊权限才能发现或访问此类数据。

企业安全

我们反对对审计日志、单点登录和多因素身份验证等核心安全控制功能设置访问门槛、付费墙或向上销售。无论您是小型企业还是联邦机构，您都可以在标准 Palantir 产品中使用每一项核心企业安全功能：

  • 强制 加密 所有数据，无论传输中还是静态存储，均采用强大、现代的密码学标准。
  • 强大的 身份验证 和身份保护控制，包括单点登录和多因素身份验证。
  • 强大的 授权 控制，包括强制访问控制和自主访问控制。
  • 稳健的 安全审计日志 用于检测和调查潜在的滥用行为。
  • 高度可扩展的 信息治理、管理和隐私控制 以满足任何用例的需求。

基础设施安全

如果您使用的是我们的托管 SaaS 平台，Palantir 的托管基础设施还具备额外的多层安全控制，以帮助保护您的数据：

  • 稳健的 安全架构 围绕零信任、最小权限和纵深防御原则构建。
  • 强制执行的 安全基线配置 ，并采用严格的变更管理和安全监控流程。
  • 强大的 网络安全 加固和分段。
  • 基于主机和基于网络的 入侵检测系统 ，用于检测和挫败异常活动。
  • 积极的 基础设施和应用程序漏洞管理与补丁修复，并提供业界领先的 SLA。
  • Web 应用防火墙 (WAF) 对传入的 Web 请求进行检查，以检测和拦截攻击。
  • 安全监控 覆盖环境各个层面，包括用户、主机、网络和应用程序。
