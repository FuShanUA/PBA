Checkpoints：安全变更的理由说明

发布日期：2023-03-31

借助 Checkpoints，平台治理和管理团队可以要求对 Foundry 中的某些操作提供额外的理由说明。这些详细信息随后会被记录下来，以供审计之用。随着时间推移，Palantir 正在逐步增加可启用此类理由说明的用户操作数量。

Foundry 现已支持在关键安全变更时要求提供这些理由说明，例如更新群组成员、更新有权访问标记的成员、在项目中授予角色等。为实现这一功能，引入了新的 Checkpoints 类型。

平台管理员可以配置其组织设置，以针对选定的安全变更收集理由说明。例如，管理员可以决定授予标记访问权限时必须提供理由——在这种情况下，尝试此操作的用户将被提示输入理由说明。

对于所有 Checkpoint 类型，理由说明提示完全可自定义；管理员还可以决定哪些特定安全变更需要提供理由说明，并自定义提示的标题和内容等。

目前，理由说明由执行变更的用户提供；而在实际操作中，这通常是由拥有提升权限的管理员代表权限受限的其他用户执行变更。我们正在以下产品中开发更多功能： Approvals - 目前可用于项目访问请求 - 以标准化这一基于请求的权限变更流程。

作用域会话介绍：沙箱数据访问

发布日期：2023-03-31

作用域会话 使用户能够选择一部分预定义的 标记 以在其 Foundry 会话期间进行访问，从而在不同类型的工作之间形成视觉分隔。作用域会话在 Foundry 文件系统和本体论工作区中均可正常运行。

作用域会话通过减少在 Foundry 中跨不同用途的工作发生意外交叉污染的可能性，提高了平台安全性。例如，跨多个医疗保健研究项目工作的用户可能会因法规或最佳实践而被禁止在项目 A 的情境中使用来自项目 B 的数据，即使他们拥有 权限 查看这两个项目中数据的权限。使用作用域会话时，用户在登录时选择要在其中开展工作的作用域，Foundry 将仅显示与当前活动作用域相关联的资源。

通过将用户的会话隔离到其当前正在处理的目标上，交叉污染的风险得以降低，用户可以更有信心地开展工作。例如，作用域会话可帮助实现以下模式和最佳实践：

  • 确保工作的有效性并避免交叉污染：研究人员可能同时参与多个研究项目，而这些项目对数据和资源的访问权限各不相同。在这种情况下，作用域会话有助于防止意外使用来自其他项目的研究成果，从而避免损害当前研究的有效性。
  • 数据保护/隐私要求：Foundry 可以配置为符合 GDPR 和 HIPAA 等数据保护法规，而作用域会话则提供了一种额外的工具，用于对敏感数据实施目的限制和数据最小化原则。
  • 限制用户的平台可见性：在大型企业中，对于试图完成特定目标的用户而言，可访问的数据量可能过于庞大。在可见性受限的情况下，作用域会话可以帮助用户专注于其主要目标。

配置作用域会话

管理员可以在 控制面板中为您的组织配置作用域会话。作用域会话应谨慎配置，因为它们会影响所有登录 Foundry 的用户，并可能导致显示 Foundry 工作区横幅。因此，作用域会话默认处于禁用状态。要开始审查您的标记配置并启用作用域会话，请遵循 文档 中的指导，如有其他疑问，请联系 Palantir 支持工程师。

Slate：公共应用程序

发布日期：2023-03-30

在受众最需要的地方触达他们

使用 Slate 的点击式功能，为您的合作伙伴、供应商和客户构建 Palantir Foundry 公共应用程序，无需 Palantir Foundry 账户即可访问。

应用构建者可以直接通过 Slate 构建公共应用，从而省去为特定目标受众开通和维护 Foundry 账户的额外工作。构建公共应用即可受益于动态资源扩展和 Foundry 的安全基元，同时无需为单一用途的应用设置专门的数据连接配置。

直达您的数据集，一切由您设计

在 Palantir Foundry 中构建的典型应用程序需要先通过 Foundry 账户验证才能访问。现在，只要应用程序被专门构建为公共应用程序，任何拥有该应用程序 URL 的人都可以使用它，而无需事先接受培训，也无需入驻 Foundry 平台。公共应用程序适合从广泛的用户群体收集输入，提交或上传的内容会直接导入 Foundry 数据集，以便在 Foundry 应用程序套件中进行转换和进一步分析。例如，您可以构建功能强大的调查问卷、引导用户入驻、接收数据上传等，应用场景不胜枚举。

此外，通过 Slate 对 层叠样式表 (CSS)的内置支持，应用程序构建者可以定制公共应用程序的外观和风格，使其符合公司的风格指南，让用户无需 Foundry 账户也能获得无缝体验。截图中展示了一个公共 Slate 应用程序示例，可供公司的供应商提交采购订单，这只是 Slate 公共应用程序功能所提供的灵活性的众多潜在用途之一。

我应该何时创建公共应用程序？

当您的网站受众为公众，且您可能需要将用户提交的信息直接导入您的 Foundry 数据集时，可以考虑构建由 Slate 提供支持的公共应用程序。

由于公共应用程序是通过 URI 直接访问的，因此目前尚不支持个性化 URI 和指标跟踪功能。如果这些需求对您的用例很重要，我们建议您改为构建集成应用程序。

要开始构建公共应用程序，请查看 我们的文档 中关于如何构建公共应用程序的内容，然后选择 Create new application > Public application （在 Slate 中）。

Foundry Rules 简介：让业务逻辑大众化

发布日期：2023-03-13

定义运行业务的逻辑

Foundry Rules 为业务逻辑的代码化和管理提供了一种简化的方法。借助点击式低代码界面，各种技术背景的用户都能够创建规则并将其应用于相关数据。这些规则可用于在相关系统中执行操作，从而驱动关键工作流。

以 Foundry 的核心数据基元（包括对象、时间序列和流数据）为基础，我们构建了 Foundry Rules，将往往耗时的工作流自动化，从而腾出更多时间专注于构建和推动设备监控、反洗钱等用例。

通过可扩展的监督机制定义业务逻辑

由跨职能团队组成的复杂企业常常面临专业知识脱节的问题，即理解组织运营逻辑的人员与能够将这些专业知识代码化并付诸实施的人员之间存在隔阂。Foundry Rules 旨在通过同时赋能运营部门用户和 IT 团队来弥合这一鸿沟。

IT 团队能够提供可供用户交互的基线，并大规模地设置、审查和运行规则，实质上是为非技术用户配备了通常仅限软件开发人员使用的工具。

与此同时，最终用户现在可以自主：

  • 通过工作流自动化掌控数据驱动的流程
  • 摆脱基于电子表格的、不可扩展的日常手动流程
  • 借助实时流式处理能力，驱动对时效性要求极高的工作流

Foundry Rules 可以加快构建与协作的进程，从而节省时间和精力。

复杂逻辑，简单部署

单一配置页面带来精简的体验，使各种技术水平的用户都能快速部署业务逻辑。过去需要工程师提供技术支持的工作，现在通过直观的 UI 即可轻松完成。Foundry Rules 具有以下特性：

  • 简化的部署： 几分钟内即可通过单一配置页面端到端部署全新的 Foundry Rules 工作流。
  • 部署到管道： Foundry Rules 开箱即用，无需与管道代码交互，同时在需要时保留了编写自定义代码的灵活性。
  • 实时流式处理： 原生流式支持意味着 Foundry Rules 能够支持对时间极其敏感的工作流。
  • 轻松修改与维护： 完善的版本管理与详细的调试信息意味着可以轻松完成对正在运行的规则的任何修改。

何时应该使用 Foundry Rules？

使用 Foundry Rules 可设置基于专业知识驱动的业务逻辑（如警报、分类和任务生成）的工作流。此外，通过定义明确的护栏，Foundry Rules 还能改善 IT 团队与最终用户在这些工作流中的协作。

对于调查性工作流或实验性的“假设分析”工作流，我们仍然推荐使用 Quiver 和 Contour 对数据集进行深入探究。从这些工作流中获得的重要洞察，在后续阶段仍可在 Foundry Rules 中固化为业务逻辑。

地图图层：栅格瓦片

发布日期：2023-03-10

地图图层编辑器 现在允许用户通过点击式界面将栅格瓦片数据添加到图层。配置完成后，地图图层即可供用户在 Map 应用程序 以及 Workshop 中的 Map 小组件 中使用。

这一全新界面让用户无需再编写复杂且容易出错的 Mapbox JSON 样式，即可将栅格图像添加到图层。取而代之的是，配置栅格图层只需指向地图瓦片服务器的 URL——请注意，管理员可能需要为该服务器地址范围配置网络 入站 和 出站 ——并使用滑块设置其他参数。

使用栅格图层可视化卫星影像、气象雷达、自定义地图或任何其他基于图像的数据！如需详细了解如何配置地图图层，请参阅 文档。
