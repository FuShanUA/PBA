使用 OData 进行 SAP SLT 同步

本指南介绍如何将 SAP SLT 复制同步配置为使用 OData API，以及如何将现有同步从旧版 ODP API 迁移到 OData。它涵盖以下两者的批量和流式同步： SAP SLT 源和 SAP（自定义源） 用于 SLT 复制的连接器。

背景

SAP SLT 同步从 SLT 复制服务器上的操作增量队列 (ODQ) 读取变更数据。Foundry 可以通过 Palantir Foundry Connector 2.0 for SAP Applications（"连接器"）上的两种 API 之一访问 ODQ：

  • ODP： 旧版 API，通过 RFC 使用 SAP 的 ODP 数据复制 API (ODP-RFC)。
  • OData： 替代 API，使用 SAP 的 通过 OData 进行基于 ODP 的数据提取 ↗。该 PALODATA 连接器的组件提供此 API。
SAP 正在限制对 ODP-RFC API 的访问

SAP 正在限制对 ODP-RFC API 的访问，如以下所述： SAP Note 3255746 ↗。客户和第三方应用程序不再被允许使用 ODP 数据复制 API 的 RFC 模块。SAP 的公开 ODP 常见问题解答说明，SAP 的安全补丁会拒绝未经授权的 ODP-RFC 调用。一旦该补丁应用到您的 SAP 系统，仍使用 ODP API 的 SLT 同步将失败。请咨询您的 SAP Basis 团队补丁何时会应用到您的每个系统，并在此之前完成迁移。

迁移条件

本指南仅适用于 SLT 复制同步：

  • 使用以下工具的批量同步和流式同步： SAP SLT 使用以下工具的源： SLT 复制服务器 对象类型。
  • 批量同步： SAP（自定义源） 使用以下工具的源： SLT SAP 对象类型。
  • 流式同步： SAP（自定义源） source.

本地表 在 SAP SLT 源和其他 SAP 对象类型（如 ERP 表、InfoProvider 或提取器）上的同步不使用本指南中所述的 API 选择。对于上面未列出的对象类型，请联系 Palantir 支持获取指导。

现有同步将就地迁移。同步保留其源及其输出数据集或流。

OData 和 ODP API 之间的差异

在迁移同步之前，请查看这些差异：

  • 每个表和 SAP 用户一个订阅： OData API 允许源进行身份验证所用的 SAP 用户在每个表上只有一个活动订阅。使用相同源凭据的两个同步不能都通过 OData 摄取同一个表，即使使用不同的筛选器或计划也是如此。使用 ODP API 时，多个同步可以独立订阅同一个表。
  • 无远程上下文或并行分页： OData 同步不使用 远程上下文 初始加载绕过或 从 SAP 检索数据时每页返回的行数。默认值为 50,000。最小值为 5,000。。页面按顺序检索，这可能会增加大型初始加载的持续时间。
  • 需要新的初始加载： OData 同步无法从 ODP 增量指针继续。将同步从 ODP 迁移到 OData 需要通过 OData 进行一次完整的初始加载，如下面的步骤所述。

检查 SAP 组件版本

请让您的 SAP Basis 团队确认 SLT 复制服务器上安装的组件版本：

  1. 使用 SAP GUI 登录 SLT 系统。
  2. 从菜单中选择 System > Status.
  3. 自动预览行为 SAP 系统数据，打开 组件信息.
  4. 确认以下各行：
    • SAP_BASIS: Release 750 且支持包为 SAPK-75009INSAPBASIS 或更高版本，或更高的发布版本。
    • PALANTIR and PALCONN：支持包级别为 SP34 或更高。建议使用 SP39 Fix Pack 4 或更高版本。
    • PALODATA：出现在列表中。

Foundry 还会检查连接器版本。在 API 版本 卡片中， OData 选项会在 Foundry 判定该附加组件不支持 OData 时显示以下消息之一：

  • This source's add-on is older than version 2.34 (SP34), which OData requires. 在选择 OData 之前升级连接器。
  • We couldn't confirm this source's add-on is version 2.34 (SP34) or newer, so OData might not work. 按照上述说明在 SAP 中确认组件版本。

检查 Foundry 支持

Foundry 连接器和用户界面更新由 Palantir 提供，没有需要您管理的版本号。要确认您的 Foundry 环境是否支持特定同步类型的 OData，请打开该类型的现有同步或开始创建一个新同步。然后检查 兼容性表.

如果 API 版本 卡片未在 SLT 同步中显示，则表示您的注册中该同步类型尚不支持 OData 选择。请勿尝试通过其他方式配置 OData。请联系 Palantir 支持团队，并提供源类型、同步类型和 SAP 组件版本。

批量同步

使用 OData 的批量 SLT 同步遵循标准的 Foundry 事务类型的信息:

  • APPEND: 增量同步。每次运行请求自上次成功运行以来在 ODQ 中记录的更改，并将其追加到数据集中。
  • SNAPSHOT: 每次运行都会用该运行的输出替换数据集的内容。
将增量同步切换为 SNAPSHOT 不会重新加载表

如果您将 APPEND 同步更改为 SNAPSHOT 但保留其增量设置，SAP 仍只会发送自上次运行以来的更改。 SNAPSHOT 事务随后会用这些更改替换整个数据集，因此数据集可能最终不完整或为空。要重新加载完整表，请开启 重置增量状态，它会自动将同步切换为 SNAPSHOT 以进行重新加载。禁用 重置增量状态 会将事务类型切换回 APPEND.

使用 OData 创建新的批量同步

  1. 仓库类型 SAP 前提条件 已满足，并且 API 版本 卡片适用于您的源和同步类型。请参阅 检查 Foundry 支持.
  2. 创建同步：
    • SAP SLT 源： 在源概览页面中，选择 + 新建 批量同步旁边，然后选择 SLT 复制服务器 对象类型。
    • SAP（自定义源）： 在源概览页面中，选择 + 新建 批量同步旁边，然后选择 SLT SAP 对象类型。
  3. 自动预览行为 API 版本中，选择 OData。在 SAP SLT 源上，新同步默认为 OData 除非 Foundry 判定该附加组件版本低于 2.34（SP34）。在 SAP（自定义源）同步上，新同步默认为 ODP，因此您必须选择 OData.
  4. 配置表和上下文：
    • SAP SLT 源： 并选择 表名。上下文来自源的 远程上下文 setting.
    • SAP（自定义源）： 选择 Context （SLT 队列别名）并输入 对象名称.
  5. 配置增量设置：
    • 对于增量摄取，请设置 事务类型 to APPEND。在 SAP（自定义源）同步上，设置 增量字段 to pointer。OData 同步不支持其他增量字段。
    • 要在每次运行时读取完整表而不使用订阅指针，请设置 事务类型 to SNAPSHOT.
    • （可选）设置 对于增量批量同步， （SAP SLT 源）或 maxRowsPerSync （SAP（自定义源） 高级 标签页），以将较大的初始加载拆分到多次运行中。参见 跨多次运行拆分的初始加载.
  6. 保存同步。暂不要添加计划。
  7. 如果您的 SAP 环境需要为新的 SLT 初始加载或新的 ODQ 订阅进行审批，请在继续之前从您的 SAP Basis 团队获取批准。此审批是一个组织流程，而非 Connector 的要求，许多环境并不需要。
  8. 手动运行同步。首次运行 APPEND 同步会执行表的初始加载。
  9. 验证初始加载。将数据集行数与 SAP 表中的行数进行比较，同时考虑任何筛选条件或被删除的列。如果您将初始加载拆分到多次运行中，请继续运行同步直到初始加载完成，然后再比较行数。
  10. 添加计划并确认后续运行是增量的。每个 APPEND 事务仅包含已更改的记录。后续的增量运行通常不需要 SAP Basis 的进一步批准。

SAP 的 ODQ 仅在有限时间内保留增量请求。如果增量 OData 同步的运行频率低于 ODQ 的保留期，增量指针可能会丢失，从而导致同步失败。请安排增量同步以比 ODQ 保留期（默认为 24 小时）更高的频率运行。详情请参阅 SAP Note 2888122 – 如果源系统中最新的 delta 请求被删除，则无法进行 ODATA ODP Delta.

将现有批量同步从 ODP 迁移到 OData

现有批量同步在迁移后会保留其源、输出数据集和事务类型。

  • SNAPSHOT 同步： 确认 SAP 前提条件 and Foundry 支持。对于 SAP（自定义源）同步，还需满足 配置要求。然后打开同步配置，选择 OData under API 版本，并保存。无需重置增量状态。
  • APPEND 同步： 请按照 迁移增量批量同步，该操作会通过 OData 重新加载一次表，然后恢复增量摄取。

迁移增量批量同步

对满足以下条件的现有批量同步使用此流程： 事务类型 is APPEND。它会通过 OData 对表执行一次完整重新加载，然后恢复增量摄取。

  1. 规划迁移。 完成以下检查：
    • 仓库类型 SAP 前提条件 已满足，并且 API 版本 卡片和 重置增量状态 可选属性可用于该同步。参见 检查 Foundry 支持.
    • 与您的 SAP Basis 团队商定迁移时间窗口。重新加载会以与初始加载相同的方式消耗 SLT 和 ODQ 资源。请查看 资源规模调整.
    • 检查响应的 SAP（自定义源）配置要求 （如果您正在迁移 SAP（自定义源）同步）。
  2. 防止运行重叠。 暂停包含该同步的所有计划，并等待任何正在进行的运行完成。
  3. 选择 OData。 打开同步配置，在 API 版本中，选择 OData.
  4. 启用“重置增量状态”。 将 重置增量状态 可选属性并将其开启。Foundry 会设置 事务类型 to SNAPSHOT 并锁定增量设置。保存之前请确认以下事项：
    • 事务类型 is SNAPSHOT.
    • 增量设置仍然存在。在 SAP（自定义源）同步上， 增量字段 remains pointer。请勿删除增量设置；同步需要这些设置以在重新加载后保留其订阅。
  5. 保存 同步配置。
  6. 如有需要，完成 SAP 端的订阅检查。 OData 允许每个表和每个 SAP 用户仅有一个活动订阅。如果同一表和 SAP 用户已存在另一个 OData 订阅，则运行会失败并报错，指出每个表每个技术用户仅允许一个活动的增量同步。参见 订阅冲突 以了解在运行同步之前如何解决此问题。
  7. 触发重新加载。 如果您的 SAP 环境需要为新的初始加载进行审批，请先获取批准。然后手动运行同步。该运行会通过 OData 执行完整的初始加载并替换数据集内容。
  8. 验证初始加载。 确认运行成功，并且数据集的行数与 SAP 表匹配（需考虑任何筛选条件或被删除的列）。如果您配置了 对于增量批量同步，，请参阅 跨多次运行拆分的初始加载 ，然后再比较行数。
  9. 禁用“重置增量状态”。 关闭 重置增量状态。Foundry 会将 事务类型 重置回 APPEND 并解锁增量设置。确认 事务类型 is APPEND，然后保存。
  10. 验证增量摄取。 再次手动运行同步，并确认新事务是一个 APPEND ，其中仅包含自重新加载以来所做的更改。如果没有记录发生更改，则预期会出现空事务。
  11. 恢复计划任务。
  12. 清理旧的 ODP 订阅。 在验证迁移后的同步之后，请让您的 SAP Basis 团队在事务 ODQMON中检查该表的传统 ODP 订阅。连接器不再从该订阅读取数据。终止未使用的订阅只会删除队列和订阅数据；不会删除 SAP 业务表中的数据。请勿终止属于其他使用者的订阅。了解更多关于 SLT 订阅清理的信息.

请勿让 重置增量状态 保持开启状态。当它开启时，每次运行都会在 SAP 中强制执行新的完整初始加载并替换数据集。

跨多次运行拆分的初始加载

本节适用于增量同步，包括 增量批处理迁移流程，其步骤在下文中被引用。如果增量同步使用 对于增量批量同步， （或 maxRowsPerSync），初始加载将通过多次运行交付：

  1. 重置运行（步骤 7）将表的第一部分写入为 SNAPSHOT.
  2. 关闭 重置增量状态 在首次成功运行之后，如步骤 9 所述。如果保持开启，每次运行都会重新启动初始加载，导致加载永远无法完成。
  3. 手动运行同步 APPEND ，直到剩余部分全部交付完毕。
  4. 仅在初始加载完成后再验证完整性（步骤 8），然后继续执行步骤 10。

SAP（自定义源）配置要求

在选择 OData之前，SAP（自定义源）批处理同步必须满足以下要求。如果未满足某项要求，运行将失败并显示指明该设置的错误。

  • 仅限 SLT 对象类型： OData 仅适用于使用 SLT SAP 对象类型。
  • 需要上下文： 同步必须指定一个 Context.
  • 增量字段： 如果已设置， 增量字段 必须在 pointer.
  • JSON 页面格式： 如果源使用 TSV 序列化，请在 useKernelJsonSerialization: true 选项卡中将 高级 添加到同步中。这会更改页面在传输时的编码方式，而不会更改提取哪些行。
  • 布尔标志： 直方图 timestamp, resourceCheck日 debug 设置必须为 true, false, ON，或 OFF.
  • 不支持的设置： 从同步 YAML 中删除以下设置，即使其值为空： filter, incrementalType, initialIncrementalValue, twinTable, twinMap, twinJoinConfigItems, incrementalSubTypes, incrementalComparator, trace日 continuousResourceCheck。仅适用于其他对象类型的设置（例如 BEx、函数或 TSV 特定设置）也必须删除。

如果同步使用了 filter，删除它会更改提取哪些行。在您拥有 OData API 支持的等效筛选条件之前，请勿迁移该同步。请联系 Palantir Support 以获取有关表达该筛选条件的帮助。

将现有流式同步从 ODP 迁移到 OData

使用此过程将现有的 SAP SLT 或 SAP（自定义源）流式同步切换到 OData，同时保留其源和输出流。迁移流会将完整表重新发送到现有流中，因此在启动之前请规划好重放。

过程

  1. 规划迁移。 完成以下检查：
    • 仓库类型 SAP 前提条件 已满足，并且 API 版本 卡片在流式同步编辑器中可用。
    • 对于 SAP（自定义源）流，请确认源的 SLT 连接类型.
    • 与您的 SAP Basis 团队商定迁移时间窗口。
    • 识别使用该流的下游管道。迁移后，表的每一行当前记录都会被重新发送。消费方必须能够容忍重复记录，例如根据表的主键和 /PALANTIR/TIMESTAMP 列（流式同步始终会添加该列）来去除重复记录。
    • 初始加载反映表的当前状态。流停止期间在 SAP 中删除的记录不会作为删除操作发出。如果下游消费者依赖删除记录，请计划在初始加载后对其进行核对。

订阅冲突

OData API 允许每个 SAP 用户对每张表仅持有一个活动订阅。当另一个使用相同 SAP 用户的同步已持有该表的 OData 订阅时，就会发生冲突。常见原因包括：

  • 另一个使用相同凭据且已通过 OData 摄取该表的 SAP SLT 或 SAP（自定义源）同步。
  • 在 Foundry 中已被删除或替换的同步，其订阅在 SAP 中仍处于活动状态。
  • 针对同一表和 SAP 用户的早期 OData 测试。

错误消息包含持有该订阅的同步的增量 ID、最近运行日期和创建者。请使用这些详细信息来识别所属的同步。

重置队列注册 无法解决冲突。它仅重置当前同步自身的订阅。如果是另一个同步持有该订阅，则运行将失败并显示 You cannot reset this sync, an active sync is already configured for this table.

要解决冲突，请选择以下选项之一：

  • 在 SAP 中释放订阅： 与冲突同步的所有者协调并先停止该同步。然后请您的 SAP Basis 团队在事务 ODQMON中终止该表和 SAP 用户的冲突 OData 订阅。这仅移除订阅；不会从 SAP 业务表中删除数据。持有该订阅的同步无法继续增量运行。如果仍需要该同步，则需要新的初始加载，且冲突会再次出现，因此请为其中一个同步改用其他 SAP 用户。
  • 使用其他 SAP 用户： 如果两个同步必须独立摄取同一张表，请使用以不同 SAP 用户进行身份验证的源。

故障排除

API 版本卡片未显示

  • 确认该同步使用的是 SLT 复制服务器 对象类型（SAP SLT 源）或 SLT SAP 对象类型（SAP（自定义源））。对于本地表或其他对象类型，该卡片不会显示。
  • 对于 SAP（自定义源）流式同步，请确认源具有 显式 SLT 连接类型.
  • 如果对象类型正确但卡片仍未显示，则说明您的注册尚未针对该同步类型启用 OData 选择。请联系 Palantir Support。

不支持该附加组件版本

直方图 API 版本 卡片可能会报告附加组件版本低于 2.34 (SP34)。运行也可能失败并显示错误，指出 OData 需要 SAP 附加组件 2.34.0 (SP34) 或更高版本。无论哪种情况，请升级 Connector 并安装 PALODATA 运行代理时（如 安装支持包 和 安装。然后 检查组件版本.

OData 服务不可用

如果 OData 运行在连接 SAP 时失败，而 ODP 在同一数据源上的运行成功：

  • 确认 PALODATA 已安装，并且 SAP_BASIS 为 7.50 SP09 或更高版本。
  • 确认 通过 OData 使用 ODP 中列出的 SAP Notes 已实施。
  • 确认 Connector 的 SICF 服务 处于活动状态。
  • 在 Add-on Cockpit中查看 Connector 日志，然后携带错误消息和 SAP 组件版本联系 Palantir Support。

运行报告该表存在活动订阅

诸如 Only one active incremental sync is permitted per table per technical user or You cannot reset this sync, an active sync is already configured for this table 之类的错误表明存在 订阅冲突。错误消息包含持有该订阅的同步的详细信息。

每次运行都会重新加载整个表

如果批量同步在每次运行时替换整个数据集，或流式同步重新发送整个表，请检查是否有设置被保留为开启状态：

  • 重置增量状态 （批量）。请将其关闭；Foundry 会将事务类型恢复为 APPEND.
  • 重置队列注册 （批量或流式）。请将其关闭。在流式同步上，此设置可能会在流运行期间反复重新初始化订阅。
  • （位于源概览页面上）。 （流式）。请将其关闭。

正在运行的流会保留其启动时的配置。要将更改应用于流，请停止该流，关闭该设置，保存，然后重新启动该流。

SNAPSHOT 运行后数据集不完整或为空

以 SNAPSHOT 未启用 重置增量状态 方式运行的增量 OData 同步仅写入最新的增量并替换数据集。要恢复，请按照 增量批处理迁移流程 中的步骤 2 重新加载整个表，然后返回到 APPEND.
