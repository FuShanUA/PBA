使用媒体集编写增量转换

媒体集可以进行增量读取和写入。有关增量转换及其使用时机的概述，请参阅 增量概述 和 增量参考。

要使输入和输出媒体集均为增量，请为转换添加 @incremental(v2_semantics=True)装饰器。

from transforms.api import transform, incremental
from transforms.mediasets import MediaSetInput, MediaSetOutput

@incremental(v2_semantics=True)
@transform(
    input_PNGs=MediaSetInput('/examples/input_PNGs'),
    output_PNGs=MediaSetOutput('/examples/output_PNGs'),
)
def upload_pngs(input_PNGs, output_PNGs):

    # Returns a dataframe that only includes the media items added since the last build
    listed_pngs = input_PNGs.dataframe()

    def fast_copy_media_item(row):
        output_PNGs.fast_copy_media_item(input_PNGs, row.media_item_rid, row.path)

    # Fast copies all of the items in `listed_pngs` into the output media set
    # These items will be appended to the output if this transform is running incrementally, or they will replace the
    # output if the transform is not running incrementally
    listed_pngs.foreach(fast_copy_media_item)

在上面的示例中，转换将写入到 output_PNGs ，并使用 modify 写入模式。仅会处理自上次构建以来添加到输入媒体集中的媒体项。如果转换无法以增量方式运行，则输出将使用 replace 写入模式进行写入，并且会读取整个输入。有关要求，请参见下文。

当 v2_semantics 设置为 True时，增量媒体集可以与任意数量的其他增量输入和输出结合使用。其中包括数据集和虚拟表。

增量计算的要求

每个增量输入和输出都会影响转换能否以增量方式运行。请参阅 增量转换参考 ，详细了解数据集何时会阻止转换以增量方式运行。

一个 媒体集输出 在以下情况下可能会阻止转换以增量方式运行：

  • 在多输出构建中，它最近一次是在与其他输出不同的转换中构建的。
  • 它是事务性媒体集，且自最近一次构建以来被修改过。这包括用户上传和删除操作。

一个 媒体集输入 在以下情况下可能会阻止转换增量运行：

  • 媒体集的内容已被替换。例如，如果它是使用 replace 写入模式写入的。

如果将媒体集输入作为 snapshot_input包含，则它不会阻止构建增量运行，即使其内容已被替换。请参阅 有关快照输入的文档。

与数据集不同，路径覆盖和媒体项删除 不会 阻止转换增量运行。

增量读取模式

在增量转换中，可以使用三种模式之一来列出媒体集输入：

  • added： 将仅包含自上次构建以来添加到分支的项目。
  • previous： 将仅包含上次构建运行时分支中已存在的项目。
  • current： 将包含媒体集分支中的所有项目。

对 added 和 previous 求并集的结果始终等于 current。

如果转换未以增量方式运行，例如，如果输入的内容自上次构建以来已被替换，则使用 previous 模式的列表将为空。该列表不会包含上次构建中存在的项。

默认读取模式为 added （增量运行时），而 current （非增量运行时）。但是，可以使用 mode 参数在任何列表方法中指定读取模式：

from transforms.api import transform, incremental
from transforms.mediasets import MediaSetInput, MediaSetOutput

@incremental(v2_semantics=True)
@transform(
    input_PNGs=MediaSetInput('/examples/input_PNGs'),
    output_PNGs=MediaSetOutput('/examples/output_PNGs'),
)
def upload_pngs(input_PNGs, output_PNGs):
    # Will use `added` if running incrementally, or `current` if not
    listed_pngs = input_PNGs.dataframe(deduplicate_by_path=False)

    # Will always read in `previous` mode
    previous_listed_pngs = input_PNGs.dataframe(deduplicate_by_path=False, mode="previous")

如果路径被覆盖且列表按路径去重，则将仅包含最新的项。如果要处理给定路径下的所有输入项，则必须始终指定 deduplicate_by_path=False。

增量写入模式

写入增量媒体集输出时，可以在运行时设置写入模式。如果转换中包含用于确定是否以增量方式运行构建的自定义逻辑，这将非常有用。在下面的示例中，如果自上次构建以来有任何路径被覆盖，则构建将不会以增量方式运行：

from transforms.api import transform, incremental
from transforms.mediasets import MediaSetInput, MediaSetOutput

@incremental(v2_semantics=True)
@transform(
    input_PNGs=MediaSetInput('/examples/input_PNGs'),
    output_PNGs=MediaSetOutput('/examples/output_PNGs'),
)
def upload_pngs(input_PNGs, output_PNGs):
    previous_dataframe = input_PNGs.dataframe(deduplicate_by_path=False, mode="previous")
    added_dataframe = input_PNGs.dataframe(deduplicate_by_path=False, mode="added")

    # Calculates if any paths have been overwritten in the `input_PNGs` media set since
    # the most recent run of this transform
    paths_overwritten = previous_dataframe.join(added_dataframe, mode="inner", on="path").count() > 0

    if paths_overwritten:
        # The full input media set will be read and the output media set will be replaced
        # with the items written in this transform
        read_mode = "current"
        output_PNGs.set_write_mode("replace")
    else:
        # Only the newly added items in the input media set will be read and the items written in this transform will
        # be appended to the output media set
        read_mode = "added"
        output_PNGs.set_write_mode("modify")

增量转换与分支

媒体集不支持增量回退分支。在新分支上运行增量转换时，增量装饰器会推荐快照，因为当前输出为空。因此，在主分支上运行相同的构建不一定会产生快照。

增量转换与无事务媒体集

无事务媒体集 使用 modify 写入模式，且无法使用 replace 写入模式。这意味着无事务媒体集无法成为快照。如果无事务媒体集是增量转换的输出，但该转换无法以增量方式运行，则构建将失败。在这种情况下，您应调查构建无法以增量方式运行的原因。

中止增量转换

在增量构建期间中止输出可能存在风险。有关更多信息，请参阅 关于中止事务的文档。

在构建期间无法中止单个媒体集输出。作为替代，我们建议使用 .abort_job() 方法（位于 TransformContext 上）来中止整个作业，而不是中止单个输出。这样，后续运行便能以增量方式进行。

限制增量输入的批量大小

增量媒体集输入的批量限制仅在 Spark 转换中受支持。

通常，对于增量转换，每个输入媒体集的所有未处理媒体项都会在同一个 作业中处理。但是，在某些情况下，一个作业处理的媒体项数量可能会有很大差异：

  • 增量转换以 SNAPSHOT 模式构建，并且会从头开始读取整个输入。例如，该转换的 语义版本 已提升。
  • 某个输入媒体集累积了大量媒体项，因此下游增量转换现在必须在单个作业中处理大量媒体项。

您可以在转换的每个增量输入媒体集上配置一个 批次限制 ，以限制每个作业中读取的媒体项数量。此概念类似于输入数据集的 事务限制 。

批次限制是每个作业所处理的媒体项数量的上限。此限制会在进行任何媒体项 路径去重之前施加。例如，如果批次限制为 100，并且转换按媒体项路径进行去重，则可能看起来处理的媒体项少于 100 个。

  • 两个增量媒体集输入，各自使用不同的批处理限制。
  • 不使用批处理限制的增量媒体集输入。
