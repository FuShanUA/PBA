通知效果

Automate 应用程序允许您在满足条件时自动向其他平台用户发送通知。

通知可以通过两种方式发送：直接在平台中发送以及通过电子邮件发送。内容可以静态定义，也可以通过函数动态确定。通知还可以包含 PDF 或内联附件。本页面包含有关通知选项的信息 收件人, 内容日 附件.

对象分组

当使用公开受影响对象的条件时，可以选择对象分组来定义在发送通知之前应如何对这些对象进行分组。

公开受影响对象的条件包括：

  • 已添加到集合的对象
  • 已从集合中移除的对象
  • 集合中已修改的对象

对所有对象执行一次

当多个对象同时触发条件时，每个收件人只会收到一条通知。

在下面截图所示的示例中，三个不同的 Support Ticket 对象触发了自动化，并发送了一条通知。函数支撑的通知可以访问包含所有三个对象的对象集。

对每组对象执行一次

当多个对象同时触发条件时，对象将按一组选定的属性进行分组。每组对象将向每个收件人发送一条通知。

分组基于属性值的精确匹配。对于数组类型的属性，值必须完全相同且顺序一致才能分为一组。

在下面显示的示例中，三个不同的 Support Ticket 对象同时触发了自动化。其中两个对象属于类别 计费 另一个属于 技术支持.

  • 自 类别 被选为分组属性，因此将发送两条通知：一条针对 计费 组，另一条针对 技术支持 group.
  • 对于第一条通知，函数支撑的通知将可以访问包含这两个 计费 Support Ticket 对象的对象集。
  • 对于第二条通知，函数支撑的通知将可以访问包含该 技术支持 object.

对每个对象执行一次

当多个对象同时触发条件时，将为每个对象发送一条通知。

例如，如果三个 Support ticket 对象触发了自动化，则将为每个 Support ticket发送单独的通知。函数支撑的通知将可以访问单个对象及其属性值。

收件人

配置通知时，您必须首先定义谁应接收通知。收件人可以是 Foundry 用户或组，可以在 静态收件人列表 or 中定义，也可以通过对象属性动态定义.

要符合接收自动化通知的资格，收件人必须具备以下权限：

  • 至少对该自动化具有 查看者 权限。静态和动态收件人均需满足此要求。
  • 查看者 对触发自动化的对象实例具有
  • 查看者 如果触发对象类型是 多数据源对象类型.
  • 查看者 权限，则需要对对象实例的所有属性具有权限。对函数支撑的通知中函数执行所访问的所有对象实例具有

上述要求适用于活跃用户和预注册用户。

手动执行自动化会绕过触发条件。因此，在手动运行期间不会检查触发对象上的权限。

静态收件人列表

定义通知收件人的第一种方法是在 选项。下以静态列表的形式提供这些收件人。要定义该列表，请点击关联的文本字段，并选择希望作为收件人的用户或组。

通过对象属性动态定义收件人

第二种方法是通过受影响对象的对象属性动态定义通知收件人。此配置选项需要公开效果输入的对象集条件。

动态收件人定义允许您指定包含 用户 ID or 组 ID 的对象属性，以便在运行时确定通知收件人。因此，对象属性类型必须为 String or Array of String.

内容

有两种方式可以定义通知的内容：作为 普通通知 或使用 函数生成的通知.

通知会为每个接收者单独渲染，因此每个用户看到的内容可能有所不同。

普通通知

普通通知提供了接口组件来直接指定通知内容。您必须提供 标题 和 消息。此外，您还可以选择修改 URL 链接。默认情况下，URL 链接是指向平台内通知的链接，仅显示在电子邮件中。

还可以使用 高级电子邮件配置 来为电子邮件配置不同的值。默认情况下， 标题, 消息日 URL 链接 将使用您在上面为平台内通知提供的值。如果需要，也可以在高级电子邮件配置中使用 HTML。

如果您的自动化使用了 数据集条件, 高级电子邮件配置 还提供 附加数据集预览。启用此选项可在邮件正文中包含数据集的最多 50 行数据，并可选择特定列。

添加内容时，您可以使用 / 键打开一个菜单，允许您将通知视为模板，在发送通知时替换接收者姓名等值。如果正在监控对象集并且选择了 逐对象执行 ，则关联对象属性的当前值和先前值也可以作为模板值，不过先前属性值仅在使用实时监控时可用。

您所做的所有更改都将在配置组件的右侧实时预览。

最后，您可以为通知定义一个 附件 。

函数生成的通知

作为使用普通通知的替代方案，您可以使用函数来支撑通知，动态生成通知内容。这仅适用于普通通知无法满足的通知需求。

要创建自定义通知函数，请按照 函数文档中的说明操作。该函数必须返回 Notification or Notification | undefined。当返回 undefined 时，Automate 将跳过该通知。可以在函数逻辑中使用此方式来有条件地决定是否发送通知。

编写并发布通知函数后，您可以在通知效果中使用它。首先选择您的函数和版本。之后，界面将根据函数定义更新，以显示所需的输入。

使用条件效果输入和接收者

根据输入参数的类型，您可以使用特殊的效果输入，而不仅仅是提供静态值。支持的效果输入包括：

  • 接收者： 可用于 User 类型的函数输入，并将为其渲染通知的接收者传递给函数。
  • 条件效果输入： 当条件公开效果输入时，您可以在此处使用这些效果输入。函数参数的类型必须与公开的效果输入的类型一致。条件公开的类型取决于条件类型和执行模式。

附件

您可以将通知效果配置为包含从 Notepad 文档, Notepad 模板文档，或 Contour 仪表板 生成的附件，并将其包含在通知电子邮件中。附件将在运行时为每个接收者自动生成。

选择 + 选择 在附件部分中，选择一个 Notepad 文档、Notepad 模板或 Contour 仪表板。然后，指定附件的 文件名 。根据所选的资源类型，您可能需要提供更多值，如以下部分所述。

您还可以为每个附件配置以下选项：

  • 内联渲染： 启用此开关可将渲染后的文档以图片形式直接嵌入到邮件正文中，而不是作为单独的 PDF 附件发送。
  • 附件渲染区域设置： 选择用于渲染附件的区域设置。这可能会改变渲染 Contour 和 Notepad 文件时日期、数字和文本的显示方式。

Notepad 模板

Notepad 模板可用于在执行通知效果时，动态生成 Notepad 文档并将其导出为 PDF。这是通过 Notepad 模板输入完成的。Notepad 模板输入可用于在生成步骤中将值传递到 Notepad 文档中。在以下文档中了解有关 Notepad 模板功能的更多信息 模板文档.

选择 Notepad 模板和 模板版本后，所需的 模板输入 将会显示。Automate 应用支持传递静态值和 条件效果输入 到 Notepad 模板输入。如果模板公开了对象或对象集模板输入，且条件公开了相同类型的条件效果输入，则可以将该条件效果输入传递到模板中。

Notepad 模板不会公开对象或对象集模板输入的对象类型信息。您必须自行确保所提供的对象值的类型匹配。
