实验

一个 实验 是一种制品，表示在模型训练作业期间产生的一组指标。实验使开发人员能够在训练作业期间记录超参数和指标，在模型页面上将其可视化，并在不同模型版本之间进行比较。

为什么要使用实验？

模型开发过程本质上是迭代式的，而要跟踪生成模型的不同尝试可能比较困难。实验提供了一个轻量级 Python API，用于记录与这些不同尝试相关的详细信息，包括指标和超参数。这些指标和超参数可以在不同模型版本之间进行可视化和比较，从而更好地了解不同参数如何影响模型的性能。下面简要介绍了如何创建实验并向其中写入数据。

创建实验

该 ModelOutput 类用于从 Jupyter® 代码工作区 和 代码仓库 发布模型，并为创建实验提供了钩子。

在代码工作区中创建实验：

from palantir_models.code_workspaces import ModelOutput
# `my-alias` is an alias to a model in the current workspace
model_output = ModelOutput("my-alias")
experiment = model_output.create_experiment(name="my-experiment")

在代码仓库中创建实验：

from transforms.api import configure, transform, Input
from palantir_models.transforms import ModelOutput

@transform(
    input_data=Input("..."),
    model_output=ModelOutput("..."),
)
def compute(input_data, model_output):
    experiment = model_output.create_experiment(name="my-experiment")

如果给定模型的任意两个实验使用了相同的名称，它们将被自动去重，这样便可以多次使用相同的代码，而无需担心重命名实验。

有时，模型训练代码在向实验写入数据时，可能会因网络错误或超出序列的最大大小而失败。尽管 Python 客户端力求尽可能优雅地处理这些错误，但在某些情况下可能无法做到。客户端可以选择错误的处理方式，从三种不同的错误处理变体中进行选择：

  • FAIL - 会立即重新抛出错误，代码将运行失败。
  • WARN （默认） - 会记录该错误的警告日志，随后抑制所有后续错误。
  • SUPPRESS - 不会记录任何日志。

可以在创建实验时设置错误处理模式，如下所示：

Copied!
1
2
from palantir_models.experiments import ErrorHandlerType
experiment = model_output.create_experiment(name="my-experiment", error_handler_type=ErrorHandlerType.FAIL)

发布实验

若要在模型页面中显示实验，必须将其与模型版本一同发布。发布后，即可在模型页面中查看实验。

Copied!
1
model_output.publish(model_adapter, experiment=experiment)

详细了解发布后如何可视化实验。

日志记录

实验支持五种类型的日志：超参数、指标、图像、图表和表格。

记录超参数

超参数可以使用 Experiment.log_param 和 Experiment.log_params 函数来记录。超参数是单个键值对，用于存储与模型训练作业相关的静态数据。

Copied!
1
2
3
4
5
6
experiment.log_param("learning_rate", 1e-3)
experiment.log_param("model_type", "CNN")
experiment.log_params({
    "batch_size": 12,
    "parallel": True
})

实验目前支持记录以下类型的超参数：

  • 布尔值
  • 日期/日期时间
  • 浮点数
  • 整数
  • 字符串

记录指标

可以使用 Experiment.log_metric 和 Experiment.log_metrics 函数来记录指标。指标会记录到一个序列中，该序列会以时间序列的形式跟踪每个记录的值。指标值必须是数值，并且 step 必须严格递增。

记录指标时，如果指标序列尚未创建，将会新建一个序列。此外，调用方可以传入一个 step 参数来设置要记录到的 step。

Copied!
1
2
3
4
5
6
experiment.log_metric("train/acc", 1.5)
experiment.log_metric("test/acc", 15, step=1)
experiment.log_metrics({
    "train/acc": 5,
    "train/loss": 0.9
})

记录图像

可以使用 Experiment.log_image来记录图像。图像会记录到一个序列中，该序列会以时间序列的形式跟踪每个记录的图像。图像必须为 PNG 格式或 Pillow ↗ 图像才能被记录；其他图像格式将被拒绝。

记录图像时，如果图像序列尚未创建，将会新建一个序列。此外，调用方可以传入一个 step 参数来设置要记录到的 step。

Copied!
1
2
3
4
5
6
7
experiment.log_image("train/bounding_boxes", pillow_image)
experiment.log_image("test/bounding_boxes", image_bytes_arr)
experiment.log_image(
    "test/segmentation",
    "path/to/image.png",
    caption="Segmentation Image",
    step=1)

图像记录也可以作为一种记录自定义图表的方式。

记录绘图

可以使用 Experiment.log_plot来记录绘图。绘图会记录到一个序列中，该序列会以时间序列的形式跟踪每个记录的绘图。绘图必须以 Plotly ↗ plotly.graph_objects.Figure对象的形式提供；其他绘图类型将被拒绝。

记录图表时，如果图表系列尚未创建，将会创建一个新系列。此外，调用者可以传递 step 参数来设置要记录到的步骤。

import plotly.express as px

fig = px.line(x=[1, 2, 3], y=[0.2, 0.4, 0.6])
experiment.log_plot("train/acc", fig)
experiment.log_plot("test/acc", fig, step=1)
experiment.log_plot(
    "validation/loss",
    fig,
    caption="Validation Loss over Epochs",
    step=2,
)

MLflow

MLflow ↗ 是一个用于模型训练指标跟踪的开源工具包，为各种机器学习库提供了广泛的内置日志记录支持。用户可以利用 MLflow 及其 自动日志记录功能 ↗ ，只需进行最少的必要更改，即可将实验集成到其模型训练代码中。

创建实验后，用户可以将该实验设置为当前活动的 MLflow 运行，然后使用 MLflow 的 Python API 向该实验写入日志。

experiment = model_output.create_experiment(name="my-experiment")

with experiment.as_mlflow_run():
    mlflow.sklearn.autolog()
    # training code

model_adapter = MyModelAdapter(trained_model)
model_output.publish(model_adapter, experiment=experiment)

import mlflow

    optimizer=keras.optimizers.Adam(0.001),

with experiment.as_mlflow_run():

        data,
        label,
        batch_size=16,
        epochs=8,
        callbacks=[mlflow.keras.MlflowCallback()],

model_adapter = MyModelAdapter(trained_model)
model_output.publish(model_adapter, experiment=experiment)

MLflow 集成的限制

目前，MLflow 与实验的集成尚不支持完整的 MLflow 工具套件。存在以下限制：

  • 只能在模型发布（训练）时进行日志记录。
  • 资产支持有限；任何非 PNG 的资产将被静默丢弃。
  • 标签将被静默忽略。
  • 不支持嵌套运行。

限制

下表列出了 Foundry 中与实验相关的限制。

描述限制
实验/指标/超参数名称的最大长度100 个字符
实验中所有指标序列的最大值数量100,000
每个实验的最大超参数数量500
每个表格的最大行数100,000

要提高这些限制，请联系 Palantir 支持团队。
