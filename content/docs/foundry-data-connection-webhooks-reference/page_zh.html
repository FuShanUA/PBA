为方便起见，在某些情况下，Webhook 任务的结果会自动转换为相应的输出参数类型：

  • 如果配置了 字符串 输出参数且 Webhook 任务结果不是字符串，则该结果将被转换为 JSON 字符串。

其他选项

除了指定 calls 和 output之外，REST Webhook 任务还提供了一些额外的配置选项：

  • 如果您在 REST Webhook 中进行多次调用，则只允许一次调用使用不安全的 HTTP 方法。不安全的调用是指可能修改外部系统状态的调用。默认情况下，只有 GET, OPTIONS日 HEAD 请求被视为安全的。您可以通过指定 POST or PUT作为调用的一个字段来覆盖不同类型调用（例如 "isHttpMethodSafe": true ）的安全性。这在您进行多个请求且其中一个较早的请求是 POST，而您在后续请求中使用其响应时非常有用。
  • 您可以指定一个 retryable-status-codes 数组，表示可以重试的 HTTP 状态码。
    • 例如，您可以配置 Webhook 在收到服务器的 503 响应时重试外部请求。此选项默认为空列表。
  • 您可以指定一个 external-system-not-changed-status-codes 表示您所连接的服务器尽管请求失败，但未更改任何数据。
    • 此选项默认为 400 到 431 之间的所有状态码。
    • 当 Webhook 执行失败时，会捕获外部系统是否可能已被更改的指示，以便调试写入失败。

限制

对于每个 Webhook，您可以设置三种类型的限制来约束 Webhook 的执行方式：时间限制、并发限制和速率限制。

A 时间限制 允许您设置 Webhook 执行的最长持续时间。这使您能够确保最终用户应用程序保持响应，并在您所连接的外部系统响应时间过长时显示超时错误。如果未提供任何值，默认超时时间为 20 秒。允许的最大超时值为 180 秒。

A 并发限制 指定同时运行的 Webhook 执行的最大数量。定义此限制可避免过多并发请求使外部系统过载。

A 速率限制 限制 Webhook 在您指定的时间窗口内可以执行的次数。如果您希望保证 Webhook 每秒、每分钟、每小时或每天仅执行特定次数，可以启用此类限制。

Webhook 函数

将 webhook 发布为函数会将其转变为可供其他应用程序使用的可重用函数。要发布，请在创建 webhook 时保持 函数配置 处于开启状态，或直接从现有 webhook 的 函数配置 部分进行发布。启用函数发布后创建的所有 webhook 版本也将作为函数版本发布。此操作不可逆，且从 webhook 发布的函数无法删除。

Webhook 与 OAuth 2.0

授权码模式

Palantir Webhooks 支持使用 OAuth 2.0 授权码许可流程调用端点。这需要使用一个 如果您的外部 API 需要 OAuth 2.0 授权，您可以在 Control Panel 中配置一个 来定义与 OAuth 2.0 服务器的交互。配置完成后，出站应用程序可用作 REST API Webhook 的身份验证，并会在尝试执行 Webhook 时提示各个用户向 OAuth 服务器进行身份验证。

授权码许可故障排查

如果在将出站应用程序与授权码许可一起使用时遇到错误，请检查以下常见问题。

"客户端无权请求授权码"

此错误表明第三方应用程序未配置为使用授权码流程。在 Developer Console 中，确保 授权码模式 已为该第三方应用程序启用。

"提供的重定向 URI 不是允许的重定向 URI"

当授权码许可设置中配置的重定向 URI 与出站应用程序期望的重定向 URI 不匹配时，会出现此错误。将授权码许可配置中的重定向 URL 设置为与出站应用程序的重定向页面 URL 完全一致：

https://<your-enrollment>.palantirfoundry.com/workspace/oauth2-clients/callback

一旦授权码许可块中的重定向 URL 与出站应用程序的重定向页面 URL 匹配，授权码请求就会成功。

创建源后，选择创建新 Webhook 的选项。

该 Webhook 将由两个链接的调用组成：

  • 对 令牌端点 的初始调用，以检索有效的持有者令牌
  • 后续调用会在向所需端点发出的请求中包含解析出的 bearer token 资源域.
