分支安全性

在全局分支中，对分支的访问主要由两种机制控制：角色和组织。

角色

角色控制用户可以在分支上执行哪些操作。

所有者

每个分支必须至少有一个 Owner。创建分支的用户会被自动分配 Owner 角色，但该角色也可以被分配。所有者对分支拥有完全控制权，可以：

  • 编辑分支和提案元数据（分支名称、提案名称和描述）
  • 在分支上分配和管理角色
  • 创建提案
  • 关闭现有提案
  • 管理分支的组织
  • 从分支中移除非活动标签
  • 归档或恢复分支
  • 在分支的提案上应用或移除 请勿合并 设置

分支所有者还会收到分支通知，例如非活动通知和数据删除通知。

Administrators （即分支所属空间的管理员）拥有与 Owner 角色相同的权限。但是，管理员不会自动收到分支通知。

分支角色仅控制对分支管理操作的访问权限，不授予编辑分支上资源的权限。要修改资源，用户必须在项目或资源级别拥有相应的权限。要查看分支或提案上的资源，您必须能够查看该资源。

管理角色

若要管理角色，请导航至 Global Branching 应用程序中分支页面上的 安全 标签页。只有所有者和空间管理员才能修改角色分配。

合并权限

任何可以查看提案的用户都可以合并该提案，前提是满足资源级别的审批和检查要求，并且未应用 请勿合并 设置。

所有者可以通过使用审批和 请勿合并 设置，对分支的合并保留实质性的控制权。

执行合并的人员提交的更改可能涉及他们自己无法编辑的资源。这是有意设计的：首先，修改分支资源仍然需要编辑权限；可以指定审阅者来验证并批准更改；并且合并仅应用预先编写且已批准的更改。

尚未迁移到项目的本体论资源目前不会强制执行“仅编辑者才能修改分支上的资源”这一约束。在这种情况下，需要获得编辑者的批准。

资源级批准

受保护的资源需要指定的审核者批准所有变更后才能进行合并。资源级保护由资源所有者设置，而批准策略由项目所有者定义。对于代码仓库和 Pipeline Builder 管道，批准策略在资源内部定义。了解更多关于 资源保护和批准策略。

“请勿合并”设置

分支所有者可以将 请勿合并 设置应用于分支上的提案。此设置会阻止提案被合并，直到移除该设置为止。只有分支所有者才能移除此设置。

组织

除角色要求外，用户还必须是分支上列出的至少一个组织的成员才能访问该分支。组织充当分支本身的访问关卡。分支的组织必须是该分支所属空间所关联组织的子集。

分支元数据（例如分支名称）可能会显示在添加到该分支的资源上，即使这些资源并未受到相同组织标记的保护。

创建分支

创建分支时，请选择不包含敏感信息的名称，因为分支名称可能会在分支的组织限制范围之外可见。

本体论

创建时选择的本体论决定了您可以在分支上进行修改的位置。您无法在所选本体论之外进行更改，并且分支创建后无法再更改本体论。

空间

在大多数情况下，无需额外配置——分支将自动分配到与所选本体论关联的空间。但是，如果您选择默认本体论，则需要手动选择空间。

空间会在多个方面影响分支：

  • 它决定了哪些组织可以被授予对分支的访问权限。
  • 空间管理员拥有与分支上所有者角色等同的权限。
  • 它决定了适用于分支的保留策略。

组织

组织决定了哪些用户可以访问分支。您可以从与所选空间关联的组织中进行选择。默认选择按以下方式确定：

  • 如果空间没有任何组织，或者您的组织属于与该空间关联的组织之一，系统将预先选择您的组织。
  • 否则，与该空间关联的所有组织都将被预先选择。

在完成分支创建之前，您可以调整所选内容。
