管理架构变更

更改对象类型的架构

基于 Foundry 本体论构建的工作流和应用程序应随着组织需求的变化而演进；在某些情况下，这种演进可能涉及更新对象类型的架构，从而需要在其他地方进行额外的更改（“破坏性变更”）。破坏性架构变更的示例包括：更改现有属性的数据类型、更改对象类型的支撑数据源，或更改对象类型的主键。请参见以下 破坏性架构变更的完整列表.

在对象存储 v1（Phonograph）中，用户界面不鼓励进行此类架构更改，尤其是当对象类型已接收用户编辑时。这是因为此类用户编辑无法在 OSv1 中迁移；相反，破坏性更改将导致现有用户编辑丢失，除非能够执行耗时且复杂的手动干预。

对象存储 v2 移除了对架构更改的这一限制，以便于灵活且迭代式的工作流构建。为此，OSv2 提供了一个架构迁移框架，其中包含一系列预定义的迁移，可在破坏性架构更改后应用于现有的用户编辑。本体论管理器会自动检测破坏性架构更改，并引导用户从预定义列表中选择迁移选项。有关更多信息，请参阅下文 受支持迁移的完整列表.

破坏性架构变更列表

本体论中的以下变更被视为破坏性架构变更：

  • 更改对象类型的输入数据源
  • 更改对象类型的主键
  • 更改属性的数据类型
  • 更改已被用户编辑过的属性的 ID
  • 删除已被用户编辑过的属性
  • 删除已被用户编辑过的 struct 字段
  • 更改 struct 字段的数据类型

非破坏性架构更改列表

以下对本体论的更改 不 会被视为破坏性架构更改：

  • 更改已收到用户编辑的属性的显示名称、标题键、渲染提示、类型类或可见性
  • 删除属性或对从未收到用户编辑的属性进行架构更改
  • 删除结构体字段或对从未收到用户编辑的结构体字段进行架构更改

OSv2 中支持的架构迁移列表

以下是对象存储 v2 中当前支持的所有架构迁移的完整列表。

  • 丢弃所有属性编辑： 此迁移指令会丢弃对象类型上某个特定属性的所有现有用户编辑。该对象类型上其他属性的用户编辑不受影响。此指令通常在从对象类型中删除属性且没有新属性作为替代时使用。

  • 丢弃所有结构体字段编辑： 此迁移指令会删除对象类型的结构体属性中特定结构体字段上的所有现有用户编辑。同一结构体属性中其他结构体字段上的用户编辑不受影响。此指令通常用于从结构体属性中删除某个结构体字段且没有新的替代结构体字段的情况。

  • 删除所有编辑： 此迁移指令会删除对象类型所有属性上的所有现有用户编辑。此迁移运行时，对象类型的所有对象的状态将重置为输入数据源中的数据。要执行此迁移，请导航至该对象类型的 数据源 选项卡，然后选择 删除编辑，位于 编辑 区域的字段中添加命令。

  • 移动编辑： 此迁移指令会移动特定属性或整个对象类型上的所有现有用户编辑。该指令通常用于以下两种情况：

    • 当现有属性被重命名或删除并被新属性替换时，或者
    • 当对象类型的输入数据源被另一个数据源替换时。

  • 移动 struct 字段编辑： 此迁移指令会将特定 struct 字段上的所有现有用户编辑移动到另一个 struct 字段。该指令通常用于现有 struct 字段被删除并被新 struct 字段替换的情况。

  • 将属性强制转换为新类型： 此迁移指令会将特定属性上现有用户编辑的数据类型转换为该属性的新数据类型。支持的数据类型转换列表如下：

    • Attachment → String
    • Boolean → String
    • Date → String
    • Double → Integer
    • Double → Long
    • Double → String
    • Geopoint → String
    • Geoshape → String
    • Integer → Long
    • Integer → Double
    • Integer → String
    • Long → Integer
    • Long → Double
    • Long → String
    • 强制标记 → String
    • String → Integer
    • String → Long
    • String → Double
    • String → Boolean
    • String → Date
    • String → Timestamp
    • String → Geopoint
    • String → Geoshape
    • Timestamp → String

  • 将结构体字段转换为新类型： 此迁移指令会将特定结构体字段上现有用户编辑的数据类型转换为该结构体字段的新数据类型。支持的数据类型转换列表如下：

    • Boolean → String
    • Date → String
    • Double → Integer
    • Double → Long
    • Double → String
    • Geopoint → String
    • Integer → Long
    • Integer → Double
    • Integer → String
    • Long → Integer
    • Long → Double
    • Long → String
    • String → Integer
    • String → Long
    • String → Double
    • String → Boolean
    • String → Date
    • String → Timestamp
    • String → Geopoint
    • Timestamp → String

  • 回填一个值： 此迁移指令会在用户编辑所创建的对象上，将某个属性设置为指定值，但仅在该属性未设置时生效。它不会覆盖现有值，包括显式设置为 null的值。此指令通常用于在向对象类型添加属性后，为用户编辑所创建的现有对象分配默认值。

  • 回滚迁移： 此迁移指令用于撤销之前已应用的架构迁移。当通过本体论管理器中的 历史记录 部分来撤销已保存的本体论更改时，通常会使用此指令。

    • 要撤销迁移，请在本体论管理器中导航至所需本体论的 历史记录 部分，展开历史事件中的 迁移 部分，然后打开 ... 菜单（位于迁移事件上），然后选择 还原。迁移回退完成后，请在 Ontology Manager 中保存修改。

一次最多只能应用 500 个架构迁移。如果架构变更数量超过此限制，则必须分批执行迁移。

当前的架构迁移框架不支持对对象类型的主键属性应用迁移指令。

  • 从失败的架构迁移中恢复： 当架构迁移未能完成时，替换管道上方的错误消息会显示在 数据源 选项卡上，提供帮助您从索引失败中恢复对象类型的信息。如果从失败中恢复需要暂存额外的架构迁移，错误消息将显示一个 修复架构迁移 选项，用于暂存必要的迁移。
