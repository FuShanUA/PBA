模型弃用

模型提供商经常弃用模型，这会影响依赖这些模型的工作流，并要求用户过渡到推荐的替代模型。当提供商宣布模型弃用时，Palantir 会通知受影响的用户，并识别依赖受影响模型的资源，此识别过程将使用 Upgrade Assistant。

收到通知后，我们建议用户提前规划，将所有使用即将弃用模型的现有工作流迁移到推荐的替代模型。用户将收到迁移截止日期的通知，此后将对该模型实施一系列阶段性访问限制（brownout），以帮助剩余工作流完成迁移。

如果在阶段性访问限制截止日期前仍未采取任何操作，使用已弃用模型的工作流将在阶段性访问限制期间失败，并输出以下错误消息：

阶段性访问限制（brownout）

模型临时降级（brownout）是一种策略，用于引导用户远离正在弃用的模型。临时降级会刻意引入短暂的不稳定，以预示即将发生的变更，并避免为尚未处理 Upgrade Assistant 中所列受影响资源的用户突然停止服务。

每个模型都遵循特定的临时降级时间表。要查看正在弃用的模型的临时降级时间表（包括阶段数量、开始日期和持续时间），请参阅该已弃用模型的 Upgrade Assistant 描述页面。

迁移模型

要成功完成从已弃用模型的迁移并避免关键工作流中断，请按照以下步骤操作：

  1. 识别需要迁移的资源。
  2. 导航到受影响的资源。
  3. 替换已弃用的模型。

识别需要迁移的资源

导航到 Upgrade Assistant，并在 进行中的升级 部分中打开相关的模型弃用页面。在已弃用模型的描述页面中，向下滚动到 资源 部分，查看受此模型弃用影响的资源列表。

资源识别标准

资源将根据以下标准被标记为需要迁移：

  • 如果资源调用了已弃用的模型，则该资源将被标记为 PENDING。这表示该资源中使用的模型仍需要迁移。
  • 如果之前调用过已弃用模型的资源转而调用其他模型， 并且 对已弃用模型的最后一次调用距今已超过 24 小时，则该资源将被标记为 COMPLETED，因为使用其他模型表明该资源已完成迁移。

在极少数情况下，资源可能会被标记为 COMPLETED，随后又恢复为 PENDING。如果资源对已弃用的模型发起新的调用，就可能出现这种情况。为避免这种情况，请确保 Workshop 模块等资源在函数保存并发布后更新至受影响函数的最新版本。

已配置为使用已弃用模型，但在迁移期间未被主动使用的资源将 不会 出现在升级助手资源列表中。例如，如果某个管道已配置为使用已弃用模型，但在迁移期间未被构建，则它将不会出现在升级助手资源列表中，因为它并未主动调用已弃用模型。在这种情况下，我们建议您对生产工作流进行盘点，并使用 以下章节 中的工具来了解资源使用情况，并评估是否需要进行迁移。

导航至受影响的资源

在升级助手描述页面中，选择一个资源以导航至相应的资源应用程序。根据资源类型的不同，迁移到新模型的过程可能有所不同。对于每个受影响的资源，您必须确定已弃用模型的使用方式，例如在 Use LLM Pipeline Builder 和 AIP Logic 中的节点，或转换中的代码引用。您可能需要导航至其他上游资源，为您的工作流选择新模型。

替换已弃用的模型

为防止已弃用模型对您的工作流造成中断，需要选择一个新模型。Upgrade Assistant 中每个已弃用模型的描述页面都会包含潜在的替代模型，但我们强烈建议您在 AIP Evals 中设置评估套件，以确保您使用的是最适合您用例的模型。

Upgrade Assistant 会识别使用即将弃用模型的资源，而每种资源类型需要以不同的方式处理。有些资源可以直接配置，并且可以使用模型选择器来选择新模型。在其他资源类型（例如 Workshop 模块或管道）中，模型可能是从上游资源调用的，例如 AIP Logic 函数 或 代码仓库转换。在这些情况下，需要在包含模型配置选项的上游资源中进行模型选择。请参阅以下章节，了解有关资源类型的更多详细信息。

用户必须对受影响的资源拥有查看和编辑权限。否则，将无法正确检查管道和 Workshop 模块等资源，以找到用于模型配置的根上游资源。

模型选择器支持的应用程序

如果已弃用的模型是通过模型选择器选择的，则可以用相同的方式选择新模型。导航到 Logic 函数和 AIP Chatbots（以前称为 AIP Agents）等资源时，打开资源配置设置，并使用模型选择器选择新模型。

支持模型选择器的应用程序包括：

  • Pipeline Builder
  • AIP Chatbot Studio
  • AIP Evals
  • AIP Logic
  • Workshop
  • Quiver
  • Marketplace
  • 代码工作区

资源配置设置将在受影响的模型旁显示警报，并将其标记为 日落.

要选择替代模型，请打开模型选择器并选择一个新模型。

Pipeline Builder 中的模型使用

对于 Pipeline Builder 资源，Upgrade Assistant 将链接到整个管道，而不是受影响的特定节点。为了在大型管道中高效查找相关节点，请使用 Pipeline Builder 的搜索功能。

  1. 在 Upgrade Assistant 的模型弃用页面中，从资源列表中选择受影响的管道，即可导航到该管道。

  2. 选择管道图右上角的搜索图标。



  3. 输入 “use LLM” 作为搜索词，以查看管道中所有 Use LLM 节点的列表。所有搜索结果也将以管道图图例中所示的颜色高亮显示。



  4. 从列出的结果中，选择每个节点以在管道图中将其高亮显示。右键单击所选节点，然后从上下文菜单中选择 编辑 。这将打开节点配置页面。

  5. 导航至 模型 部分，如果该模型即将被弃用，该部分将在模型名称旁边显示一个警告图标。如果出现此警告，请选择 显示配置 ，并从中选择一个新模型 模型类型 下拉菜单。

  6. 对管道中的所有 Use LLM 节点重复此过程。

  7. 保存、部署并重新构建您的管道。

Workshop 中的模型使用情况

Workshop 中的模型使用情况可能源自 AIP 小部件或引用的函数，例如 AIP Logic 函数。根据来源的不同，可以通过小部件配置设置或上游资源（例如 AIP Logic 函数或 AIP Chatbot）的配置设置来更改模型。您可以在 Upgrade Assistant 模型弃用页面的资源列表中选择受影响的 Workshop 模块，从而导航到这些模块。进入编辑模式以查看模块配置设置。

请注意，用户需要对受影响的 Workshop 模块拥有编辑权限。请按照以下说明处理基于函数和基于小部件的模型使用。

基于函数的模型使用

  1. 要识别 Workshop 模块中使用的函数，请打开 概览 面板（位于工作区左上角）。在 功能 部分中，选择 函数。



  2. 在 函数 面板中，选择每个函数以查看函数源。



  3. 选择函数源以导航至源应用程序，本例中为 AIP Logic。通过此源，您可以配置模型设置，并在函数使用已弃用的模型时选择新模型。

  4. 保存并发布函数的新版本。

  5. 返回 Workshop 后，导航至 函数 部分，位于 概览 面板（如步骤 1 所述）。选择更新后的函数，并使用 批量更新版本 部分下的函数版本下拉菜单，为所有变量或组件选择该函数的最新版本。



  6. 对列出的所有函数重复此过程。

基于组件的模型使用

基于组件的模型配置取决于所使用的组件类型。请查看以下选项，并按照适用于您的 Workshop 模块中所用组件的说明进行操作：

  • AIP 聊天机器人： AIP Chatbot 小组件使用聊天机器人，因此必须在 AIP Chatbot Studio 的聊天机器人配置设置中进行模型配置。

    1. 在小组件配置面板中，选择正在使用的聊天机器人，以在 Chatbot Studio 中将其打开。
    2. 在聊天机器人界面右上角选择“编辑”，即可编辑聊天机器人。
    3. 打开聊天机器人配置面板，并从模型选择器中选择新模型。
    4. 保存并发布您的聊天机器人。

  • AIP 生成内容： 对于 AIP 生成内容小组件，仅当该小组件使用 Direct to LLM 或 通过提示函数使用 LLM 选项。否则，可以在所引用的 Logic 函数中进行配置。



    • 直接使用 LLM/通过提示函数使用 LLM： 可以在组件配置设置中使用模型选择器来选择新模型。
    • Logic： 如果组件使用 Logic 选项，Logic 函数将列在该模块的函数下，位于 概览 面板。请参阅 基于函数的模型用法 部分以了解更多详情。

  • 自由形式分析： 自由形式分析小组件的模型用法可以直接在 Workshop 中配置。在小组件配置设置中，开启 AIP 选项 并选择 已启用 以配置模型设置。然后，从模型选择器中选择一个新模型。



  • Logic - 思维链： 此微件使用了 Logic 函数，这些函数列在 概览 面板中。请参阅 基于函数的模型使用 部分以了解更多详情。

请确保在进行任何更改后保存并发布您的 Workshop 模块。

基于代码的模型使用

对于基于代码的模型使用,升级助手将列出其所在的 代码仓库、 代码工作区或下游资源,而不是包含对已弃用模型引用的确切代码文件或函数。对于下游资源被标记的情况,请查看 Workshop 模型使用 和 附加工具 部分。如果代码仓库或工作区被标记，请打开 Upgrade Assistant 资源列表中列出的仓库或工作区。在仓库或工作区中，您可以将已弃用模型的使用实例替换为新模型。

Quiver 中的模型使用

Quiver 中的 LLM 使用可以在分析设置中进行配置。导航到受影响分析的侧边栏中的设置选项卡，并在 AIP 设置 部分中访问模型选择器。

其他工具

工作流可能会变得复杂且难以管理，从而很难直观地找到所有受影响资源的使用实例。请查看以下部分，进一步了解可帮助您识别工作流中 LLM 使用情况的工具。

工作流血缘

为了更好地了解各资源中的模型使用情况，您可以使用 工作流血缘。在工作流血缘中打开 Workshop 应用程序或函数仓库，可使用键盘快捷键 Cmd + I (macOS) 或 Ctrl + I (Windows)。在工作流血缘图中，您将能够查看为应用程序提供支撑的对象、操作和函数。

  • Workshop 应用程序： 对于 Workshop 应用，Workflow Lineage 将显示上游资源（例如 Logic 函数）及其配置使用的模型。Workflow Lineage 还允许用户查看使用特定函数的其他 Workshop 或 OSDK 应用，从而更轻松地了解受影响资源的完整范围。如果某个资源使用了已弃用的模型，Workflow Lineage 将显示警报图标和一条消息，提醒用户该模型已处于弃用状态。



    Workflow Lineage 可以通过其 批量更新功能来帮助您对 Workshop 执行模型迁移。如 基于函数的模型使用 部分所示更新函数后，您可以在 Workflow Lineage 中打开该 Workshop 应用，对一个或所有依赖的 Workshop 应用中使用的函数版本进行批量更新。此外，Workflow Lineage 还支持您 批量替换语言模型 ，只需在血缘图中执行单次操作，即可跨多个 AIP Logic 函数完成。

  • 函数仓库： 工作流血缘可以提供可视化呈现，帮助用户了解函数仓库中的模型使用情况。调用模型的函数将连接到一个模型节点，让用户能够一目了然地判断函数是否正在调用已弃用的模型。



有关工作流血缘完整功能集的更多信息，请参阅工作流血缘 使用文档。

本体论管理器

确定包含已弃用模型的函数后，您可以在 本体论管理器 来跟踪使用此函数的资源。然后，您可以导航至这些资源并更新函数版本，以确保服务不中断。对于 Workshop 应用程序，您可以使用上文所述的 Workflow Lineage 来批量更新函数版本。

要查看函数的使用情况，请导航至本体论管理器，并在侧边栏中选择 函数 。在函数页面上，您可以搜索函数名称，并从 函数 表中将其选中，以打开其概览页面。

在函数概览页面中，向下滚动到 使用历史 部分，查看使用此函数的资源列表。您可以按版本筛选，以找出可能正在使用该函数过时版本的资源。

然后，您可以导航至使用此函数的资源，将其更新至最新版本。更多信息，请参阅 Ontology Manager 函数类型视图 文档。
