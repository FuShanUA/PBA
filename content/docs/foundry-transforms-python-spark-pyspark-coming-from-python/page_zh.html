从 Python 过渡而来

如果您有 Python 使用经验，可能已经习惯以过程式或命令式的方式操作数据：即给出将数据从一种状态转换为另一种状态所需的确切步骤。相比之下，SQL 是声明式的，也就是说，您只需描述想要获得的结果，而由软件负责生成该结果。PySpark 是一个通过 Python 方便地构建复杂 SQL 查询的库：它尝试以 Python 的过程式语法提供对 SQL 概念的访问。这充分利用了 Python 的灵活性、SQL 的便利性以及 Spark 的并行处理能力。

将您的概念模型发展为以整个数据集为单位进行思考，并基于列而非行来处理数据，会对您很有帮助。您不再直接使用变量、列表、字典、循环等操作数据，而是围绕 DataFrame 开展工作。这意味着您不再使用 Python 的基本类型和运算符，而是使用 Spark 的内置运算符，以分布式方式大规模地处理 DataFrame。

示例

假设您在 Python 中有一个数字列表，并且想要将 5 加到每个数字上。

有趣的是， DataFrame 对象实际上并不在内存中包含您的数据：它是对 Spark 中数据的引用。DataFrame 是 惰性求值的。当我们要求 Spark 实际对 DataFrame 执行某些操作（例如将其写出到 Foundry）时，它会遍历我们创建的所有中间 DataFrame，生成优化的查询计划，并在 Spark 集群上执行该计划。这使得 Foundry 能够扩展到超出单台服务器或笔记本电脑内存所能容纳的数据量。

当您需要自定义 Python 逻辑时

如果 PySpark 的内置函数无法表达您的逻辑，请使用 用户自定义函数（UDF）。由于 UDF 比原生 PySpark 函数慢，请仅在必要时使用它们。
