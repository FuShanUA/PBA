下载控制

Foundry 提供多种方式来限制用户下载数据的能力。这些控制措施应与其他 安全 和 数据保护 策略进行规模化推广。

隐私最佳实践是：当本地副本会超出工作流的批准用途，或使访问和保留更难治理时，限制下载。请查看 实践中的隐私与公民自由 以决定哪些用户和数据需要下载控制。

了解下载控制

Foundry 使您能够控制用户下载数据的能力，以限制未经授权的数据传输或数据挪用。由于客户对其数据、谁可以访问数据以及如何在 共享安全责任模型中负最终责任，因此了解下载控制的优势和局限性非常重要。

什么是下载？

下载是用户在平台中可以将数据传输到本地计算机的操作。通常，这涉及在 Foundry 中选择一个 导出 or 和 按钮。例如，您可以在文件夹中右键单击某个数据集并选择 下载为 CSV 菜单中选择 操作 菜单，在 Contour 中使用导出板下载数据，以及在 Workshop 应用程序中将对象导出为 Excel 或 CSV。

何时限制下载是有帮助的？

根据您组织的 数据治理 要求和政策，限制哪些用户可以从 Foundry 下载某些数据可能是有帮助的。如果用户不需要下载数据，限制其执行下载操作的能力可以更好地维护最小权限原则并 进一步 防止意外的数据泄露。

为什么限制下载并不全面？

下载只是用户将数据从平台传输出去的一种操作类型。 自动导出, 对外部系统的调用日 。操作可以对 Foundry 本体论中的数据进行编辑，或通过 都是将数据直接导出到另一个系统的方法，它们各自有各自的控制措施。复制到剪贴板、截屏或打印浏览器页面是其他也可能被视为将数据传出平台的操作。

因此，仅限制下载并不能防范所有形式的数据传输和挪用。下载控制应始终与其他策略结合使用，例如实施最小权限访问控制、确保数据治理监督以及监控审计日志。

实施下载控制

Foundry 提供多种功能来控制和提高对平台中何时发生下载的感知。虽然每项功能都有其局限性，但组合使用时，它们提供了一种纵深防御方法，能够更好地控制 Foundry 中的下载操作。

  • 角色： 访问控制是防止用户执行未经授权下载操作的第一道防线。可以为用户分配一个 Discoverer 不包含对特定资源执行下载操作权限的角色。但是，您也可以创建自定义角色，在保留对该资源更特权操作的同时移除与下载相关的工作流。了解更多信息，请参阅 以下章节.
  • 检查点： 当授权用户执行下载时，检查点可以提醒他们有关数据传出 Foundry 的任何组织政策或限制。通过检查点，您可以要求用户在继续下载之前进行确认或提供理由。这降低了无意下载数据的可能性，并减少了用户意外下载数据的情况。了解更多信息，请参阅 以下章节.
  • Cipher： 对敏感数据进行混淆是另一种增强数据保护的方法，因为如果数据在加密状态下被意外下载，混淆可以限制数据的可用性。Cipher 使用户能够在整个数据集或数据集列的粒度级别上执行这种混淆。这确保了数据在管道和本体论中默认保持混淆状态，除非由授权用户解密。了解更多信息，请参阅 以下章节.
  • 审计日志： 审计日志是一种资源，使组织能够回顾性地分析何时可能发生了下载，以及这些下载是否得到了适当的授权和理由说明。了解更多信息，请参阅 以下章节.

授予用户限制下载操作的角色

角色 是权限的集合，用于定义用户可以在平台中执行的特定工作流程。在 Foundry 的默认角色中，拥有资源的 Viewer, Editor，或 Owner 角色的用户有权对该资源执行下载操作。只有 Discoverer 角色缺少下载操作，通常在用户不应查看和下载数据时授予。

在更高级的使用场景中，如果用户需要的权限超出了 Discoverer 角色的范围，但无权下载数据，您可以创建一个 自定义角色 基于现有角色的自定义角色，以限制允许下载数据的特定操作。

下载控制因部署环境而异。在配置为限制下载的部署环境中，从自定义角色中移除下载操作（包括 foundry-data-proxy:get-files (和）可以阻止下载。在其他部署环境中，如果角色仍授予读取权限，仅省略该操作可能无法阻止下载。在依赖自定义角色作为下载控制手段之前，请联系 Palantir Support 以确认您的部署环境如何实施下载控制。

当下载操作被强制执行时，请审查哪些平台工作流程确实需要读取底层数据。限制下载的部署环境通常会在自定义 角色集移除默认角色的下载操作。然后，管理员通过专用角色（例如 Exporter 角色）授予这些操作。用户在任何读取资源文件的工作流程中都需要该专用角色，包括在他们拥有的资源上。例如，将包含静态数据的数据集打包为 Marketplace 产品时会读取底层文件。打包该数据集的用户需要 foundry-data-proxy:get-files 操作，即使他们拥有该资源的 Owner 角色。更多信息，请参阅 数据集打包权限.

限制： 并非 Foundry 中的所有下载操作都由角色管控。例如，下载 SAML 元数据是在 Control Panel 中管理的。某些下载操作的强制执行也取决于部署环境配置，如上文所述。

使用 Checkpoints 提醒用户下载是敏感操作

检查点 要求用户确认或说明 Foundry 中敏感操作的理由，并可用于在用户在平台中执行操作之前提醒其注意组织政策。要为下载启用检查点， 创建检查点配置 为 所有检查点类型 菜单中选择 Download 类别。这些检查点类型的名称中通常包含“Export”一词（例如，Notepad Export）。

可以设置检查点以提醒用户有关下载的任何组织或治理政策。您可以明确要求用户确认此政策，或说明需要下载数据的原因。为下载启用检查点有助于确保下载是有意为之的操作；这进一步降低了用户在平台中无意触发下载操作的风险。

此外， Checkpoints 应用程序 使您能够查看针对下载操作提交的检查点记录。这可以为数据治理用户提供平台中触发的下载操作的实时信息。

限制： 并非 Foundry 中的所有下载操作都由检查点覆盖。

使用 Cipher 默认对数据进行混淆

Cipher 使您能够默认对敏感信息进行混淆，同时仍允许在 Foundry 的分析或操作应用程序中使用这些数据。默认对敏感数据进行混淆可以在数据被意外下载时限制其被挪用，因为下载的 Cipher 加密数据将以加密形式保存。只有对算法密钥拥有适当权限的用户才能在 Foundry 中揭示 Cipher 加密的信息。Cipher 使用标准加密算法进行混淆。请查阅 Cipher 文档 以了解有关算法选择的更多信息，从而理解每种可用算法的优势和局限性。

限制： 并非所有可下载的信息都可以使用 Cipher 加密。只有数据集和对象中的值可以被加密。

查看审计日志以了解下载发生的位置

审计日志 使审计人员能够回顾性地了解用户在 Foundry 中执行了哪些操作。 dataExport 审计类别 涵盖平台中的下载操作。请查阅 监控审计日志 文档，以了解如何利用这些日志来监控平台中的下载及其他相关事件的更多信息。
