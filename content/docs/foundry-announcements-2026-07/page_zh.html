Claude Sonnet 5 现已在 AIP 中可用

发布日期：2026-07-07

Claude Sonnet 5 现已在 AIP 中面向符合条件的商业和美国政府注册开放。

模型概述

作为 Anthropic 迄今最具智能体能力的 Sonnet 模型，Sonnet 5 在推理、工具使用、编码和知识工作方面缩小了与 Claude Opus 4.8 的差距，同时仍以更低的价格提供。对于生产级 AIP 用例，它在智能、速度和成本之间实现了出色的平衡。如需了解更多信息，请查阅：

  • Anthropic 的 Claude Sonnet 5 模型文档 ↗
  • Anthropic 的 Claude Sonnet 5 发布公告 ↗

可用性

Claude Sonnet 5 适用于通过以下方式启用 Anthropic 的商业注册：

  • 非地理限制注册上的 Microsoft Azure
  • 非地理限制或美国地理限制注册上的 Amazon Bedrock
  • 非地理限制或美国地理限制注册上的 Anthropic Direct
  • 非地理限制、美国地理限制或欧盟地理限制注册上的 Google Vertex

此外，对于在 IL2 或 IL4 注册上通过 Google Vertex 启用 Anthropic 的美国政府注册，Claude Sonnet 5 同样适用。

开始使用

要使用此模型：

  • 请确认您的注册管理员已启用相关的模型系列。
  • 查看 token 成本和定价。
  • 请查看完整的 AIP 可用模型列表。

模型评估功能介绍：在建模目标之外比较和评估模型

发布日期：2026-07-07

模型评估 是一款全新的 Python API，用于捕获模型版本在测试数据上的表现，并将结果直接呈现在模型页面上。评估是由您自行定义和记录的指标、图像、图表和表格组成的集合，使您能够跨版本并随时间推移比较模型性能。

此前，以结构化方式评估模型意味着需要在建模目标内部进行工作。模型评估移除了这一要求：您现在可以在构建模型的任何位置编写评估逻辑，并将结果附加到任何模型版本，而无需建模目标。

模型页面上的 model_performance 评估集显示了为每个模型版本记录的结果，并按版本分组，便于您比较各次运行之间的性能。

评估任意模型版本

每次评估都与单个模型版本绑定，即加载到您的转换中的版本，使用的是 ModelInput。由于结果附加到该特定版本，您可以获得模型性能在特定时间点的快照，并为模型重新训练时的质量比较奠定基础。

使用评估集跟踪各版本的性能

评估集 是采用相同评估方法的各项评估的逻辑分组。每次运行评估转换都会向同一个集合写入一项新的评估，因此您可以跟踪指标随模型变化在各版本间的演变。若要以多种方式分析模型（例如，在一个集合中分析整体误差，在另一个集合中分析各分段的误差），请为每种评估方法定义单独的集合。

快速入门

要评估模型，请将您的仓库升级到最新版本，将 palantir_models 库升级到 0.2384.0 或更高版本，然后参阅 模型评估文档。

下一步是什么？

在接下来的几个月中，我们将为评估功能引入以下改进：

  • 针对 AI 辅助模型开发循环的 AI FDE 支持
  • 根据评估表现发送警报的监控器，用于自动漂移检测
  • 用于对比评估的 UI/UX 增强功能

浏览文档以开始使用模型评估。

将 AIP Analyst 对话保存为分析资源

发布日期：2026-07-02

AIP Analyst 对话现在可以保存为 Compass 中的分析资源，让您能够回顾以往的分析、与协作者共享，并在独立版 AIP Analyst 和 Workshop 小组件中随时间推移持续迭代。当您重新打开一项分析时，AIP Analyst 会重新运行智能体的工具，并根据本体论的最新状态重新生成响应，因此结果始终反映当前状态，并遵循每位查看者的权限。

选择分析的保存位置，并查看将要存储的内容。

在 AIP Analyst 分析资源文档中了解更多信息。

平台管理员可以通过 AIP Analyst Control Panel 扩展在注册级别禁用分析保存功能。禁用后，用户将无法在 AIP Analyst 中创建或打开分析资源。

在 Control Panel 中配置分析设置。

AIP Analyst 可帮助用户将自然语言问题转化为 Foundry 中有据可依的分析。该智能体可以搜索本体论、构建和转换对象集、运行聚合和 SQL 查询、分析上传的文件和媒体，并生成摘要、图表和地图。借助分析资源，这些工作流现在可以回顾、共享，并随着时间推移不断扩展。

用于 AIP 容量管理的可配置用户速率限制

发布日期：2026-07-02

Enrollment 管理员现在可以查看和配置 AIP 中 LLM 使用情况的每用户速率限制，从而更精细地控制 Enrollment 容量的消耗方式。

背景

AIP 中的 LLM 容量通过三个级别进行管理。

  • 注册级别限制为贵组织的 token 和请求吞吐量设定了总体上限。
  • 项目速率限制控制每个项目可以使用多少注册容量。项目速率限制已可由管理员配置。
  • 每用户速率限制用于管控单个用户可以消耗的容量；用量可能来自交互式、归属于用户的工作流，来自 AIP Assist、AIP Analyst 或 AI FDE 等应用，来自原生助手功能（例如 Pipeline Builder 的 Explain 与 Generate），也可能来自 Continue 和 Claude Code 等 IDE 集成。

在此之前，每用户限制由 Palantir 设定为固定默认值，管理员无法调整。在推出可配置的用户速率限制之前，没有自助服务方式来解决诸如某个重度用户在特定模型上占用过多容量份额、或特定团队请求更多容量等问题。

新增功能

管理员现在可以直接从以下位置管理每用户速率限制 管理速率限制 标签页，位于 Resource Management 应用中的 AIP 用量与限制页面。管理员现在可以：

  • 设置自定义默认值 ，适用于所有模型中的每位用户，替代 Palantir 发布的默认值。
  • 添加按模型覆盖设置 ，可针对特定模型提高或降低限制，而无需更改适用于所有模型的限制。
  • 创建用户组覆盖设置 ，针对特定的 Foundry 用户组，每个用户组都拥有各自的默认值和可选的按模型配置。这使您能够为重度构建者群体提供更多容量，或限制实验性用户，使其仅在部分模型上拥有高容量。

用于管理 AIP 使用情况和限制的界面，显示默认的用户速率限制和模型覆盖配置。

Palantir 的内置默认设置仍是推荐且合理的选择，在未配置自定义覆盖的情况下将继续适用。我们建议从默认设置开始，仅在您的使用模式需要时进行调整，并在新模型发布时重新审视任何自定义限制。

该功能现已面向所有已开通 AIP 的客户在资源管理应用程序中提供。如需了解更多信息，请参阅 LLM 容量管理文档。
