批量构建与交互式构建

在 Code Workbook 中通过工作簿界面运行作业进行交互式使用时，所有作业都将使用与该工作簿关联的 Spark 模块。如下图所示，您可以在会话历史中查看 Spark 模块 ID 在任何会话的 对话框中查看。

由于每个用户在同一项目中使用相同环境的所有工作簿都会被分配同一个 Spark 模块，您的交互式作业可能会因其他工作簿的作业正在完成而排队。例如，同一模块上最多可以同时运行五个 Python 作业。第六个作业将显示为 "Queueing in Code Workbook."

在批量构建中（例如，计划构建或从数据集预览发起的构建），一次构建将在构建中的每个环境使用一个 Spark 模块。例如，如果计划构建包含在多个 Code Workbook 中创建的数据集，而这些 Code Workbook 都使用相同的环境，则该构建将对所有作业使用同一个 Spark 模块。不会有任何交互式作业被路由到该 Spark 模块。

当所需的输出保存为数据集，且您不需要逐个运行转换来迭代代码时，我们建议使用批量构建。这可能包括以下情况：

  • 您希望在同一个工作簿或使用相同交互式 Spark 模块的其他工作簿中构建一些长时间运行的转换。
  • 您希望数据集按一定的周期定期更新。例如，如果您希望在有新输入数据时或每天上午 9 点看到更新的数据，则应使用计划批量构建。

在工作簿中，使用 打开数据集 在数据集预览中查看数据集，并使用屏幕右上角的 构建 按钮进行构建。要构建多个数据集，请导航到页面顶部的齿轮图标，然后选择 探索数据血缘。然后，选择您要构建的数据集，并在右侧边栏中选择构建它们。

或者，使用同一侧边栏并点击日历图标，设置定期计划来构建这些数据集。 了解更多关于设置计划的信息。

要判断作业是以批量构建还是交互模式构建，请导航到 Builds 应用并点击 "Details" 按钮。

详细信息中将列出 Spark 模块的 ID，以及 isInteractive 是否为 true。如果为 true，则该作业以交互模式运行。如果为 false，则该作业以批量构建模式运行，且不与任何交互式作业共享 Spark 模块。
