转换表计算差异

以下章节记录了 Quiver 转换表 处理某些计算/可视化与它们在 对象集中处理方式的差异。

被视为字符串的属性类型

某些复杂属性类型没有与之关联的特定转换操作，但会被视为字符串，可用作 字符串操作的输入。本体论数组属性也会被字符串化。例如，如果某个对象有一个属性值为 ["a", "b", "c"]，那么在转换表中它将是一个单独的字符串 "[a, b, c]"。在这种情况下， 拆分转换 可用于将该字符串转换回数组。

以下属性在转换表中被视为字符串：

  • Geoshape
  • Vector
  • Struct
  • Byte
  • 任意数组属性

分类图表

转换表分类图表在每系列类别限制方面的行为略有不同。在对象集分类图表（例如 条形图），如果序列被分段，类别将根据对未分段序列的排序来确定。但在转换表卡片的分类图表中，如果序列被分段，类别将根据每个类别的分段总和的排序来确定。因此，对于相同的输入数据，所显示的类别可能有所不同。

透视表

该 透视转换表 与对象集 透视表相比有一个重大区别，即它会为没有值的行/列显示一个维度。因此，如果您要透视的是一个布尔属性，那么透视转换表中会有三个维度（true、false、无值），而对象集透视表只有两个维度（true 或 false）。

由于转换表会对数组进行字符串化，因此对于每个唯一的属性值，透视转换表只会有一个维度，而对象集透视表会将数组展开，使数组中的每个唯一值都有一个对应的维度。例如，假设您有一个包含数字数组属性的对象集，其中两个对象的该属性值分别为 [1, 2, 3] 和 [1, 2, 4] 那么在转换表中，您将有两个维度（分别为 "[1, 2, 3]" 和 "[1, 2, 4]"）而对象集数据透视表则有四个维度（1， 2， 3，以及 4 每一项都是其自身的维度）。

对象集数据透视表允许您按结构体/向量属性进行分桶，但由于这些属性在数据透视转换表中是以字符串形式表示的，因此您将无法执行相同的操作。
