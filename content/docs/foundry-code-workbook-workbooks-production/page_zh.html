迁移到生产环境

我们建议使用 Code Workbook 或 Code Workspaces 进行基于代码的分析和管道原型开发。对于稳健的生产管道以及需要额外治理和审查、高数据量或优化性能的工作流，我们建议使用 Pipeline Builder 和 Code Repositories。

有关在哪里编写管道的更多信息，请查阅我们的 Code Workbook、Code Workspaces 和 Code Repositories 的对比.

当您对在 Workbook 中得出的输出结果感到满意后，您应该强化您的逻辑和输出数据集，使其更加可靠。在 Code Workbook 中执行此操作非常简单。以下步骤可以帮助您使您的工作更加稳健并达到生产就绪状态：

  • 保护分支
  • 使用批量构建
  • 数据健康检查
  • 组织输出
  • 组织图表
  • 导出到 Code Repository

保护分支

要保护 Workbook 中的分支，您必须拥有该 Workbook 的所有者权限。

分支保护 允许锁定 Workbook 中的分支，防止任何人直接编辑该分支中的逻辑。相反，逻辑更改必须在另一个分支中创建，然后合并到受保护的分支中。通常，用户会保护 Workbook 中的 master 分支，但您也可以保护任何其他分支。

保存后，您的分支将被保护并变为只读。

使用批量构建

您可能希望定期刷新在 Code Workbook 中创建的输出数据集，可以基于输入数据集的更新，也可以基于时间周期。您可以通过在这些输出数据集上安排定期构建来实现。

  • 要在单个输出数据集上安排定期构建，请打开数据集操作并点击 管理调度.
  • 要在多个输出数据集上安排定期构建，请点击工作簿顶部的齿轮图标并选择 探索数据血缘。您现在应该能看到工作簿中的所有输入数据集和已保存的输出数据集。

这两个操作都会将您带到 Data Lineage 应用。点击右侧窗格中的日历图标以打开 管理调度 界面。按照提示设置定期计划。在下图中，显示了一个每天构建 dataset_1 和 dataset_2 的计划。

批量构建不会更新未保存为数据集的转换（例如未持久化的转换）。具体来说，考虑未持久化转换 A 是持久化转换 B 的父级的情况。如果我使用批量构建来构建转换 B，转换 B 将使用来自转换 A 的最新逻辑，以及来自上游输入数据集的最新数据。但是，工作簿中为转换 A 显示的预览以及转换 A 中创建的任何可视化，都不会由此批量构建更新。

数据健康检查

输出数据集的另一个最佳实践是添加 Data Health 检查。打开您的输出数据集并点击 Health 标签页以访问 Data Health 页面。设置健康检查后，如果数据集的构建失败、数据过期或不符合您指定的其他要求，您将收到通知。

组织输出

在项目中使用 Workbook 时，我们建议在项目中创建以下文件夹结构：

  • /data
  • /workbooks
  • /templates

设置好此文件夹结构后，您可以轻松地从您的主文件夹共享新的 Workbook：

  1. 将您的 Workbook 移动到 /workbooks directory.
  2. 如果您在 Workbook 中创建了任何模板，请将它们移动到 /templates directory.
  3. 要移动数据集，请点击 Workbook 左上角的 Output 下拉菜单，然后点击“更改文件夹…”以选择一个新输出数据集将添加到的文件夹。选择您项目中的 /data 文件夹。默认情况下，您在 Workbook 中派生的所有数据集都将移动到您选择的新文件夹。

组织图表

您可能需要整理和组织您的图表，以便其他用户能够轻松理解转换流程。Code Workbook 中提供的两种组织功能是节点着色和自动布局。

您可以使用节点着色在图表上对节点进行视觉分组。点击 颜色 按钮（位于右上角）可创建新的颜色分组，选中节点并使用 + 颜色分组上的按钮可将节点添加到该颜色分组。在工作簿内容助手（workbook contents helper）中，您还可以按颜色分组对数据集列表进行排序。

您还可以通过点击右上角的布局按钮对图表的各个部分进行自动布局。默认情况下，自动布局会排列整个图表，但您也可以选择特定节点并点击自动布局，仅排列这些节点。

导出到 Code Repository

如果您已在 Code Workbook 中完成管道的原型设计，并希望将代码移动到 Code Repositories，您可以使用 导出到 Code Repository 助手。 了解更多关于导出到 Code Repositories 的信息。

您可能出于多种原因希望将代码移动到 Code Repositories：

  • Code Repositories 提供完整的 Git 支持，允许用户查看和回退到之前的提交。
  • Code Repositories 支持增量转换和多输出转换。
  • Code Repositories 支持 取消标记工作流 ，并通过 分支设置.
