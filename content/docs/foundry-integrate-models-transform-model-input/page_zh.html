该 ModelInput 类允许您在 Python 转换中加载和使用模型，从而轻松地将模型推理逻辑整合到数据管道中。要了解有关在代码工作区中使用模型的更多信息， 您可以查看该 ModelInput 类在 Jupyter® 代码工作区中的详细信息。

ModelInput(
    alias,                  # (string) Path or RID of model to load
    model_version=None,     # (Optional) RID of specific model version
    use_sidecar=False,      # (Optional) Run model in separate container
    sidecar_resources=None  # (Optional) Resource configuration for sidecar
)

参数

参数类型描述版本 / 备注
aliasstr要从中加载模型资源的路径或资源 ID (RID)。
model_versionOptional[str]要使用的特定模型版本的 RID 或语义化版本。如果未指定，将使用最新版本。
use_sidecarOptional[bool]当 True时，将在单独的容器中运行模型，以防止模型适配器与转换环境之间产生依赖冲突。引入于 palantir_models 版本 0.1673.0
sidecar_resourcesOptional[Dict[str, Union[float, int]]]sidecar 容器的资源配置。此参数仅在 use_sidecar 设置为 True时可用。

支持以下选项：
选项类型描述

"memory_gb"floatsidecar 容器的内存（GB）
"gpus"intsidecar 容器的 GPU 数量

from transforms.api import Input, Output, transform, LightweightInput, LightweightOutput
from palantir_models import ModelAdapter
from palantir_models.transforms import ModelInput


# Using use_sidecar=True with @transform.using requires palantir_models version 0.2010.0 or higher.
@transform.using(
    data_in=Input("path/to/input"),
    model_input=ModelInput(
        "path/to/my/model",
        use_sidecar=True # runs the model as a sidecar container
    ),
    out=Output('path/to/output'),
)
def my_transform(data_in: LightweightInput, model_input: ModelAdapter, out: LightweightOutput) -> None:
    # Assuming the model's API has a single Pandas input
    # and a single pandas output named `df_out`.
    inference_results = model_input.transform(data_in)
    predictions = inference_results.df_out
    # Alternatively, you can use the predict method on
    # a Pandas DataFrame instance directly:
    # predictions = model_input.predict(data_in.pandas())
    out.write_pandas(predictions)

from palantir_models.transforms import ModelInput, DistributedInferenceWrapper

@transform.spark.using(
    input_df=Input("ri.foundry.main.dataset.3cd098b3-aae0-455a-9383-4eec810e0ac0"),

    model_input = DistributedInferenceWrapper(model_input, ctx, 'auto')
    # Use .predict with the DistributedInferenceWrapper and pass it a Spark DataFrame
    # It handles passing the data as pandas to the model and returns a Spark DataFrame
    predictions = model_input.predict(input_df.dataframe())
    # Write the output as a Spark DataFrame
    output.write_dataframe(predictions)

使用说明

在不使用 sidecar 容器时导入适配器代码

要实例化模型适配器类，环境必须能够访问模型适配器代码。特别是，如果模型是在其他仓库中创建的，则需要将随模型一起打包为 Python 库的适配器代码作为依赖项导入到您的仓库中。应用程序会提示您执行此操作，如下面的截图所示。

指定版本

您可以使用 model_version 参数。如果模型没有定期重新训练，则尤其建议采用此方式，因为这有助于防止非预期或有问题的模型进入生产环境。如果未指定模型版本，系统将默认使用构建分支上可用的最新模型。

请注意，如果未指定版本，则每次转换运行都会自动为模型输入获取最新的模型文件，但如果模型是在使用它的仓库之外生成的，则不会自动更新仓库中的适配器库版本（包含您为该版本编写的适配器逻辑及其 Python 依赖项）。要更新库版本，您需要在仓库的 库 侧边栏中选择合适的适配器版本，并确认所有检查均通过。每个模型版本对应的适配器版本可在模型页面的 推理配置。

如果此工作流程不符合您的需求，可以考虑在创建该模型的同一仓库中使用该模型，或者将 use_sidecar 设置为 True， 如下文所述。

以边车容器形式运行模型

在边车容器中运行模型（use_sidecar=True) 推荐用于大多数模型推理用例。

以 sidecar 方式运行模型的主要优势在于，生成模型时所使用的确切库版本同样将用于运行推理。相比之下，按照仓库用户界面的提示导入适配器代码会创建一个新的环境求解，将适配器代码和仓库的约束条件合并在一起。这可能导致使用不同的库版本。

此外，使用 sidecar 容器运行模型时，与所使用的模型版本对应的适配器代码将自动加载到 sidecar 中，用户无需在仓库中手动更新依赖并运行检查。

from transforms.api import transform, Input, Output, configure
from palantir_models.transforms import ModelInput, DistributedInferenceWrapper

@transform.spark.using(
    input_df=Input("ri.foundry.main.dataset.3cd098b3-aae0-455a-9383-4eec810e0ac0"),
    model_input=ModelInput("ri.models.main.model.5b758039-370c-4cfc-835e-5bd3f213454c"),
    output=Output("ri.foundry.main.dataset.c0a3edbc-c917-4f20-88f1-d797ebf27cb2"),
)
def compute(ctx, input_df, model_input, output):
    model_input = DistributedInferenceWrapper(model_input, ctx, 'auto')
    # Use .predict with the DistributedInferenceWrapper and pass it a Spark DataFrame
    # It handles passing the data as pandas to the model and returns a Spark DataFrame
    predictions = model_input.predict(input_df.dataframe())
    # Write the output as a Spark DataFrame
    output.write_dataframe(predictions)

请勿将 DistributedInferenceWrapper 用于需要多个输入行才能生成预测的模型。此类模型的一个示例是时间序列模型，它们需要历史数据才能进行推理。该 DistributedInferenceWrapper 将使用 Spark 原生分区机制向每个执行器发送行的子集，并且不保证预测所需的所有行（例如，给定时间序列中的所有行）会作为同一分区的一部分发送给模型。对于接受多行输入的模型，这可能会因输入数据不完整而导致错误的预测结果。

该 DistributedInferenceWrapper 类通过以下参数进行初始化：

参数类型描述备注
modelModelAdapter待封装的模型适配器实例。这通常是 model_input ，由 ModelInput提供。
ctxTransformContext转换上下文，用于访问 Spark 会话信息。这通常是您的转换函数的 ctx 参数。
num_partitionsUnion[Literal["auto"], int]用于 Spark DataFrame 的分区数量。如果 'auto'，它将被设置为与 Spark 执行器数量相匹配。如果遇到内存溢出（OOM）错误，请尝试增大此值。默认值： 'auto'
max_rows_per_chunkintSpark 在将每个分区发送给模型之前会将其拆分为多个数据块。此参数设置每个数据块允许的最大行数。每个数据块的行数越多，开销越小，但内存占用越大。默认值： 1,000,000

使用说明：

  • 您可以通过 Spark 配置文件来配置执行器的数量。
  • 分布式包装器使用 Spark 的用户自定义函数（UDF）。
  • 所提供的 DataFrame 必须是 Spark DataFrame。包装后的 predict 调用同样会返回一个 Spark DataFrame。
  • 模型适配器 API 应具有一个 pandas DataFrame 输入和一个 pandas DataFrame 输出，以及任意数量的输入参数。
  • 使用 use_sidecar 参数（如上文所述）是受支持的，但为可选项。
