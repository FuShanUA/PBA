网络文件系统 (NFS)

测试版

NFS 连接器目前处于 测试版 开发阶段，可能无法在您的注册租户中使用。功能在积极开发过程中可能会发生变化。

连接到网络文件系统 (NFS) 导出，以在文件夹和 Foundry 数据集之间同步数据。该连接器支持 NFS 版本 3 和 4.1。

数据模型

该连接器可以将任何类型的文件传输到 Foundry 数据集中。文件格式会被保留，并且在传输期间或之后不会应用任何 schema。请对输出数据集应用任何必要的 schema，或者 编写下游转换 来访问数据。

性能与限制

可传输的文件大小没有限制。但是，网络问题可能导致大规模传输失败。特别是，运行时间超过两天的直接云同步将被中断。为避免网络问题，我们建议使用较小的文件大小，并限制每次同步执行中摄取的文件数量。同步可以 被安排 频繁运行。

选项是否必填？默认值描述

只要 NFS 服务器支持，我们建议使用 NFSv4.1。NFSv4.1 支持在单个端口上使用基于 TLS 的 RPC 和 Kerberos，从而可以保护整个连接的安全。NFSv3 将其工作分散到多个 RPC 服务中，这些服务需要单独保护，无法保护整个连接。

NFSv3 设置

NFSv3 将其工作分散到四个 RPC 服务中，每个服务都在自己的端口上可达并独立保护。在一个服务上启用 TLS 并不会加密其他服务。

选项是否必填？默认值描述
Access UID是向 NFS 服务器提供的数字用户 ID。
Access GID是向 NFS 服务器提供的数字组 ID，同时作为唯一的补充组发送。
Portmapper portNo111portmapper（rpcbind）服务的 TCP 端口，用于发现未指定固定端口的任何服务的端口。Portmapper 流量永远不会被加密。
NFS service是NFS 程序，承载所有文件数据。
Mount service是MOUNT 程序，用于获取导出的根文件句柄。
Lock service是NLM（网络锁管理器）程序。
Status service是NSM（网络状态监视器）程序，用于锁恢复通知。

四个 NFSv3 服务各自提供以下选项：

在不使用 TLS 的情况下，NFSv3 会以未加密方式通过网络发送文件内容和 AUTH_SYS 身份，并且 MOUNT 服务以未加密方式传输根文件句柄和导出元数据。请确保网络完全受信任、在 NFS 服务器支持的服务上启用 TLS，或使用 NFSv4.1。

身份验证

NFSv3 源始终使用 AUTH_SYS进行身份验证。NFSv4.1 源可以使用 Kerberos or AUTH_SYS.

AUTH_SYS

AUTH_SYS 向 NFS 服务器提供数字用户 ID（Access UID）和组 ID（Access GID）。服务器不会验证此身份，因此访问完全由导出的权限控制。默认身份 0/0 仅在未配置为压缩 root 访问权限的导出上授予 root 访问权限。

选项是否必填？描述
Access UID是向 NFS 服务器提供的数字用户 ID，介于 0 and 4294967295.
Access GID是向 NFS 服务器提供的数字组 ID，介于 0 and 4294967295.

Kerberos

Kerberos 身份验证仅适用于 NFSv4.1，并使用密码对主体进行身份验证。

选项是否必填？默认值描述
Realm是Kerberos 领域，例如 EXAMPLE.COM。领域通常以大写形式书写。
KDC host是Kerberos 密钥分发中心 (KDC) 的主机名或 IP 地址。
KDC portNo88KDC 的 TCP 端口。
Principal是要进行身份验证的 Kerberos 主体。主体与领域组合用于身份验证，例如 nfsclient@EXAMPLE.COM.

可用的保护级别如下：

保护级别描述
Authentication (krb5)仅对连接进行身份验证。请求和文件内容既不受完整性保护，也不加密。
Integrity (krb5i)对连接进行身份验证并对每个请求进行完整性保护，但文件内容仍以未加密方式发送。
Encryption (krb5p)对连接进行身份验证并加密 RPC 负载，因此文件内容在传输过程中受到保护。

仅限 Encryption (krb5p) 在启用基于 TLS 的 RPC 时受支持。

TLS

TLS 要求 NFS 服务器支持基于 TLS 的 RPC，如 RFC 9289 ↗所述。如果在 NFS 服务器不支持基于 TLS 的 RPC 的源上启用 TLS，连接将失败。

启用 TLS 后，连接器会验证 NFS 服务器的证书，并检查证书的使用者备用名称是否与配置的 Host匹配。如果 NFS 服务器使用自签名证书或由私有证书颁发机构颁发的证书， 请将服务器证书添加 到源中。如果 NFS 服务器要求双向 TLS (mTLS)，请将客户端证书添加到源中。

网络

您必须添加一个 网络出口策略 以将连接加入允许列表。所需的出站策略取决于 NFS 版本：

  • NFSv4.1： 连接器必须能够访问 Host on NFS port （默认为 2049）。使用 Kerberos 身份验证时，连接器还必须能够访问 KDC host on KDC port （默认为 88）。
  • NFSv3： 连接器必须能够访问 Host on Portmapper port （默认为 111）以及每个 NFSv3 服务的端口。通过 portmapper 发现其端口的服务在连接时由 NFS 服务器分配端口，因此无法提前确定其出站策略。我们建议在 NFS 服务器上和源配置中为每个服务分配固定端口。

Data Connection 会根据源配置建议所需的出站策略。

从 NFS 同步数据

NFS 连接器将导出中的文件同步到 Foundry 数据集中。每次同步都会遍历所选子文件夹及其下嵌套的每个文件夹。了解更多关于 基于文件的摄取模式.

增量同步

启用增量同步后，每次运行都会记录其同步的最新文件的修改时间，下一次运行仅同步在该时间之后修改的文件。首次运行会同步所有与同步配置匹配的文件。修改时间由 NFS 服务器报告，因此增量同步不依赖于连接器和 NFS 服务器的时钟保持一致。

当增量同步使用 Maximum files per run时，文件始终按从最旧到最新的顺序同步，每次运行会从上次运行停止的地方继续。不会跳过任何文件，包括当限制值落在修改时间相同的文件之间的情况。带限制的增量同步必须将 Order by 留空或按 Last modified in Ascending 顺序排序；其他排序方式会导致同步失败。

增量同步应使用 APPEND or UPDATE 事务类型。使用默认的 SNAPSHOT 事务类型时，每次运行都会用该运行中找到的文件替换数据集。

媒体集

NFS 连接器不支持 媒体集同步。从 NFS 同步的文件会存入常规数据集。
