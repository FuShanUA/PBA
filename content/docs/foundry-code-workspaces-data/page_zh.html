与数据交互

Jupyter® 和 RStudio® Code Workspaces 允许您读取、分析、转换 Foundry 数据集并将数据写回数据集， Iceberg 表日 虚拟表。它们还允许您读取和分析 受限视图 和 时间序列属性.

安全性

Code Workspaces 遵循 Foundry 标记 和 基于分类的访问控制 应用于数据集的标记，工作区将继承加载到其中的所有数据集的标记和分类。这被称为 工作区血缘。这意味着要访问某个工作区，您还必须对该工作区中包含的所有数据集和其他输入拥有所需的权限。如果您失去对工作区中任一输入的访问权限，您将失去对整个工作区的访问权限。

受限视图 加载到 Code Workspace 中的受限视图受 受限输出模式的管控，该模式是受限视图导入所必需的，可防止发布从这些视图派生的输出。受限输出模式在工作区内对受限视图实施细粒度策略。它会过滤用户可读取的内容，并阻止工作区生成可能暴露策略原本会限制的数据的输出。有关完整的传播模型，请参阅 访问控制传播.

资源注意事项

Jupyter® 和 RStudio® 工作区专为交互式分析工作流和应用程序开发而设计。它们在单台虚拟机上运行，不会使用分布式 Spark 环境处理数据集。因此，您处理的数据必须适应机器的资源，默认最大为 8 个 CPU 和 64 GB 内存。使用 表批量同步示例 or SQL 在加载大型数据集之前减少所需的数据量，可以帮助您避免超出这些限制。 过滤数据集文件 是保持在您的工作区限制之内的另一种策略。

要开发大规模数据管道，请使用 使用 Spark 的 Python 转换 or 如果希望用户在每次运行预览前手动确认，请开启.

数据集分支

默认情况下，Code Workspaces 将从与工作区本身相同的分支加载数据集的数据，否则将回退到 master 分支。例如，当前位于分支 my-branch 上的代码工作区将尝试读取数据集的 my-branch 版本的数据集，如果 master 在数据集上不存在，则回退到 my-branch 分支。

要为特定导入的数据集固定数据集分支，请选择左侧边栏的选项 ••• 数据集旁边的图标，位于 同步至数据集 标签页。然后，选择 固定读取用的数据集分支 并为您的代码工作区选择所需的数据集分支。

读取数据

Code Workspaces 要求您为导入到工作区中的每个 Foundry 数据集或受限视图选择一个 别名 。该别名充当引用，允许您在代码中读取数据集或受限视图并向数据集写入数据。在 同步至数据集 标签页中注册数据集时，Code Workspaces 会在位于工作区的 /home/user/repo/.foundry 文件夹下的隐藏文件中创建所选数据集别名与 Foundry 资源唯一标识符之间的映射。

Code Workspaces 允许您加载表格数据集、非表格数据集、 Iceberg 表, 虚拟表日 受限视图。您可以使用 Add > Read data 按钮，位于 同步至数据集 标签页。

选择要添加到工作区的数据集后，您必须为该资源定义一个别名，以作为代码中的唯一标识符和引用。为数据集选择读取策略（如 pandas DataFrame、Polars LazyFrame 或原始文件访问）会生成一个代码片段，将数据集加载为指定的输入类型。

  • 您可以随时修改此读取策略并生成新的代码片段，即使在注册数据集之后也可以。
  • 默认情况下，代码工作区会建议使用与数据集本身名称相同的数据集别名。

选择 完成 将完成数据集注册过程，并允许您在代码中使用 运行代码片段 or 复制到剪贴板 选项。

本页面提供了相关示例，适用于 表格数据集, 非表格数据集日 受限视图.

读取数据集不需要您知道其文件名或文件数量。 一个 Foundry 数据集通常由许多底层文件支撑，这些文件可能是动态命名的，或者在多次运行之间数量会有所不同。当数据集由一个对其输出进行分区或在文件名中包含变量的管道生成时，这种情况很常见。

  • 如果数据集具有 schema，请使用以下方式将其作为表格读取： read_table or SQL这些方法会读取整个逻辑表，无论数据集由多少个文件支撑或这些文件如何命名，因此您无需逐个枚举文件。
  • 如果数据集没有 schema，或者您需要原始文件内容，请通过以下方式读取每个文件而无需硬编码文件名： 遍历数据集中的所有文件.

您不需要因为支撑文件数量众多或动态命名，就将结构化的、有 schema 支撑的数据视为非结构化文件。

表格数据集

以下代码片段是为 Cats 带有数据集别名的表格数据集 kittens生成的。请注意， Cats 在代码片段中没有被引用；Code Workspaces 会自动将其注册为您选择的别名。

from foundry.transforms import Dataset

kittens = Dataset.get("kittens")\
  .read_table(format="arrow")\
  .to_pandas()

有关 Jupyter® 工作区中可用的方法和属性的完整列表，请参阅 Dataset 类的文档 foundry.transforms.Dataset API 参考.

直方图 read_table 上面显示的方法支持以下参数：

  • arrow （推荐）： 将数据集转换为 Apache Arrow 表，可以在其上执行高效的筛选。然后您可以使用以下方式将该表转换为 pandas dataframe： .to_pandas().
  • pandas or dataframe: 将数据集转换为 pandas dataframe。
  • polars: 将数据集转换为 Polars dataframe。然后您可以使用以下方式将其转换为 pandas dataframe： .to_pandas().
  • lazy-polars: Polars dataframe 的惰性变体。 一个 无法在惰性 polars 上执行。
  • path: 输出数据集存储的本地路径。

要使给定格式可作为 read_table 操作的一部分使用，相应的软件包 pyarrow, pandas 和 polars 必须存在于环境中。这些软件包已自动包含在默认的 Code Workspaces 环境中，但可能需要手动添加到您的自定义环境中。

使用 SQL 查询表格数据集

您可以查询任何表格数据集、 数据集视图 （包括对象物化）、 Iceberg 表，或 虚拟表 支持 SQL 查询的 在 Python 中使用 SQL。

读取数据集中的所有文件

如果数据集具有 schema 并且您打算处理其表格内容，建议使用以下方式将其作为表格读取 read_table or SQL。这些方法会将所有支撑文件合并为一个逻辑表格，因此您无需下载并解析单个文件。

上面的示例通过确切名称访问文件。当数据集包含您事先不知道名称的文件时，例如由管道动态命名的文件或数量可变的输出文件，请下载所有文件并遍历返回的映射，而不是直接引用名称。 download() 方法返回一个从每个文件名（如当前数据集视图中所定义）到其下载位置的本地路径的映射，因此无论数据集包含多少文件或文件如何命名，代码都能正常工作。

受限视图

仅在 Jupyter® 工作区中支持查询受限视图。

您可以使用 上述 SQL 方法 通过 Python 查询受限视图。为此，请将受限视图导入您的工作区，并像处理任何其他表格数据集一样通过其别名进行查询。

将受限视图导入您的代码工作区需要启用 受限输出模式 以强制执行更高级别的数据安全。启用受限输出模式后，您可以对受限视图中包含的数据执行分析，但无法从工作区发布使用该数据的输出。

首次将受限视图添加到您的工作区时，系统会提示您安装特定的 Python 依赖项。然后，您可以定义别名（与数据集一样）并将受限视图添加到您的工作区。您必须启用受限输出模式并重启工作区才能查询受限视图。

受限视图的 策略 决定了用户可以查询哪些数据。例如，如果您将受限视图导入某个工作区，而另一个用户打开该工作区，他们看到的数据可能与您不同。如果在工作区中加载受限视图时您的访问权限发生变化，您将失去对该工作区的访问权限，需要重启工作区。

筛选表格数据集

Code Workspaces 使您能够在将数据集加载到内存之前对其应用筛选器。这可以减少导入到工作区的数据帧的内存消耗，使您能够专注于与分析相关的数据子集。Code Workspaces 提供了灵活的方式来处理选定的列、行或两者的组合。

何时对表格数据集使用筛选器

为确保您不超出工作区的 可用资源，我们建议采取以下做法：

  • 当您的未压缩数据可以容纳在工作区的内存中时，您可以在不加筛选器的情况下加载数据集，并在内存中应用转换，以获得最高效率。

  • 当您的未压缩数据超出工作区的内存时，您可以使用 列 和 行 筛选器将数据的一个子集加载到内存中。这些下推筛选器会在数据加载到工作区之前应用，从而减少导入数据的内存占用。这些筛选操作的速度取决于数据的规模和分区方式。您还可以使用 SQL 与 Python 结合 来查询任意大小的表格数据集，只要结果数据能够容纳在您计算机的内存限制之内。

    • 如果这种方法不适合您的使用场景，您还可以使用 基于 Spark 的应用程序 来处理您的数据，并生成一个较小的数据集，供您在 Code Workspaces 中使用。这通常会加快依赖于频繁使用同一数据子集或跨多个工作区使用数据的交互式工作流，因为数据集的 Parquet 文件只需下载一次，而每次将数据加载到工作区时都会进行筛选。

  • 对于更复杂的数据加载需求，您可以使用 非表格数据集语法 下载数据集背后的文件，并使用原生 Python or R 软件包来处理文件内容。

# OR / AND operators
.where((Column.get("column_name") == value1) | (Column.get("column_name") == value2))
.where((Column.get("column_name1") == value1) & (Column.get("column_name2") == value2))

# only retain rows whose value is not null
.where(~Column.get("column_name").isnull())

# only retain rows whose value is part of a given list
.where(Column.get("column_name").isin([value1, value2, value3]))

# only retain rows whose date is between two given inclusive bounds
.where(Column.get("date_column_name").between('lower_bound_incl', 'upper_bound_incl'))

# only retain the first N rows, where N is a number. This will be applied before other filters
.limit(N)

# select a subset of columns
.select("column_name1", "column_name2", "column_name3")

写入数据

要调度您的数据转换、查看数据血缘或进行增量写入，您可以将代码转换为 Jupyter® or RStudio 转换的代码中。

您可以按照以下步骤使用 Code Workspaces 以交互方式写入 Foundry 数据集。

  1. 通过打开 同步至数据集 选项卡并选择 保存到数据集 选项（位于 导入数据集.
  2. 为输出数据集选择一个名称以及保存该数据集的位置。
  3. 选择 保存.
  4. 一个新数据集将出现在 同步至数据集 选项卡中。默认情况下， 保存到数据集 选项将被选中，对于输出数据集应保持此设置。
  5. 系统还会提示您指定数据集别名，该别名将成为输出数据集在工作区中的名称，这与导入数据时别名的使用方式类似。
  • 对于表格输出数据集，系统还会提示您指定将填充该数据集的 dataframe 变量。
  • 对于非表格数据集，您需要改为指定要上传到该数据集的本地文件或文件夹路径。
  1. 设置好数据集类型、数据集别名和 dataframe 变量后，选择 复制并注册数据集 以在工作区中注册该数据集，这还会将代码片段保存到您的剪贴板。
  2. 将代码片段粘贴到您的工作区中，根据需要替换变量，然后执行代码以写入输出数据集。

以交互方式写回时，默认情况下，每个 SDK 函数调用将对应一个事务：

  • A SNAPSHOT 写回表格数据时将创建output_dataset_tabular.write_table(df_variable) 事务（在 Python 中为 datasets.write_table(df_variable, "output_dataset_tabular") 或在 R 中为
  • An UPDATE 写回文件时将创建output_dataset_non_tabular.upload_directory(path_to_file_variable) 事务（在 Python 中为 datasets.upload_files(path_to_file_variable, "output_dataset_non_tabular") 或在 R 中为

脚本注册为转换后，交互式调用将开始写入带有以下前缀的分支： code-workspace-sandbox/，而当前分支将在转换运行时更新。在这种情况下，即使有多个 SDK 函数调用，整个脚本执行也只会创建一个事务：

  • 默认情况下，事务类型为 SNAPSHOT.
  • 如果已配置增量设置，则事务类型为 APPEND.
