使用 Linter 生成可操作的建议，即将正式发布 [GA]

发布日期：2024-09-24

我们很高兴地宣布，Linter 将于 10 月 7 日当周面向所有租户正式发布。此次变更包括 UI 更新、可扩展性改进、建议的可见性功能，以及帮助用户根据建议采取行动的修复助手。当工作流设计产生不必要的成本、未使用 Palantir 平台的最新功能或未遵循最佳实践时，Linter 会生成具有明确主张的可操作建议。您可以使用这些建议来降低成本、优化您的本体论，并提高整个租户的管道稳定性和弹性。

借助 Linter，您可以更好地了解 Palantir 平台提供的广泛功能，同时监控可能有益于您用例目标的平台更新。Linter 默认启用；如果您是平台管理员，您可以 配置用户组对 Linter 的访问权限 ，方法是导航至 Control Panel > Application access （选择正确的组织），然后选择 管理 Linter 旁边的选项。

为什么创建 Linter？

Palantir 平台是托管工作流的最佳场所。虽然应用构建者旨在设计优化的工作流，但实际情况是，设计决策在实践中可能被证明并非最优。为了解决这一问题，我们创建了 Linter，以确保工作流使用可用的技术，并以更高效的资源和功能使用实现相同的结果。

何时应使用 Linter？

Linter 可以随时使用，无论您是刚开始使用 Palantir 平台，还是已经拥有复杂而广泛的工作流。Linter 将监控新的和现有的工作流并提供持续的建议，定期执行扫描以收集对租户状态的分析。这些扫描会识别符合预定义条件的资源列表 规则 并根据扫描结果生成 建议 列表。

Linter 的影响跟踪 UI 显示已执行操作的建议数量

由于 Palantir 平台功能经常更新，Linter 扫描的结果是动态的，可能每天都在变化。为了跟上这些变化，您可以设置 扫描计划 以定期对属于某个 空间.

降低成本并优化工作流

测试版中的 Linter 用户调查并消除了大量云成本中浪费的计算小时数，从而带来了量化的改进。对客户的影响与其平台使用情况相关，但即使是开发者基数相对较小的租户也受益于 Linter，达成了他们的云成本目标。

Linter 的影响跟踪 UI 显示已执行操作的建议数量

一些客户组织了冲刺来调查并根据 Linter 建议采取行动，而另一些客户则将 Linter 定位为资源使用的支持工具，在较长的时间内分散投入精力。许多客户现在专门投入时间根据 Linter 建议采取行动，将其作为其 Palantir 平台合作的核心部分。

除了降低成本之外，Linter 还被用于建议工作流更新，以使用 Palantir 平台中新增的可用功能。这些包括使用 轻量级转换 和 原生 Spark 加速的机会，这些功能在今年年初都还不存在。

推出简化的模型部署工作流，提升稳定性与速度

发布日期：2024-09-12

此前，部署机器学习模型进行实时推理需要投入精力和时间，通过以下工具设置实时部署 《建模目标》，这是我们用于管理生产级建模工作流的工具。现在，您可以在模型概览页面上，只需单击以下任一选项即可部署模型 开始部署 or 启动并运行 选项，无需经过 《建模目标》 应用流程。此外，我们对基础设施进行了多项改进，可实现更快的启动速度、更简洁的函数集成、通过以下功能实现自动扩缩容 Compute Modules、自动升级、推理类型安全等。

用户现在可以直接从模型的概览页面部署模型。

简化自动升级并支持缩容至零以节省成本

模型部署现在可以在模型的概览页面上进行完全管理。您可以在同一界面中启动、停止、更新模型扩缩容配置，并测试推理。由于部署现在由 Compute Modules 支撑，您可以受益于其自动扩缩容能力，该能力可根据模型的推理流量和使用情况动态启动或缩减副本。

例如，如果您的请求负载仅在特定时间出现，您现在可以设置可用副本的范围，并根据实际请求量进行扩缩容。如果您的模型部署会周期性地不被查询，您甚至可以将副本缩减至最少为零，从而节省成本。

根据模型部署需求配置运行时扩缩容和资源可用性。

模型部署遵循用户的模型分支，使更新无缝衔接。只需从 Code Repositories 或 Code Workspaces 发布新的模型版本，现有的模型部署就会自动升级，确保所有下游工作流始终指向最新模型。

无需 TypeScript 仓库即可实现函数集成

模型部署现在可以轻松注册为函数，并直接在以下环境中使用 来运行该专业代码代理。你还可以通过，为您节省构建和使用 TypeScript 仓库的时间和精力。此外，还可受益于对表格输入和输出的支持，现在有更多类型的模型可在 Modeling Objectives 应用中作为函数使用。具体而言，使用 pandas API（表格输入/输出）的模型现在可以直接集成到 Workshop 应用中，这意味着您不再需要从 pandas 数据帧到 TypeScript 参数的转换层。相应地，具有参数输入和输出的模型也继续受到支持。

Python 3.8 版本将于 2025 年 1 月 31 日弃用

发布日期：2024-09-12

根据开源 Python 的生命周期结束（EOL）时间表，Palantir 平台正在弃用 Python 3.8。因此，代码仓库中将尝试自动升级；代码工作簿和较旧的 foundry_ml 模型需要手动操作。从 Python 3.9 开始，我们将密切关注 Python 的 EOL 弃用时间表。请查看 Python 版本部分 文档以了解支持的版本及相应的弃用时间表。我们建议资源始终保持在最新支持的 Python 版本上。

为什么要弃用 Python 3.8？

开源 Python 每年都会将旧的 Python 版本标记为 生命周期结束（EOL）↗ 并停止官方支持。Python 3.8 即将到达其 EOL，继续使用 EOL 的 Python 版本会带来安全风险。此外，开源库不断发布不再兼容这些已弃用 Python 版本的新版本，可能导致未迁移工作流的检查和作业失败。

弃用对我作为用户意味着什么？

如果您拥有使用已弃用 Python 版本的资源，请注意以下重要日期：

  • 2025年1月31日： 依赖已弃用 Python 版本的工作流将不再受支持，如果出现故障，您将无法获得支持。如果事先与 Palantir 达成一致，可以将有限的资源加入白名单以获得延长支持。
  • 2025年4月30日： 所有依赖 Python 3.8 或更早版本的工作流将不再受支持，并且可能会出现故障。

Foundry 资源迁移到受支持的 Python 版本

Foundry 资源迁移将遵循以下模式：

  • 代码仓库：将尝试以自动补丁拉取请求的形式进行自动升级。对于所有使用 Python 3.8 的资源，无论优先级如何，都将尝试此操作。
  • 其他资源：将显示包含已弃用 Python 版本迁移说明的信息横幅。请查看 故障排除指南 的文档以获取更多信息。

目前，平台支持的最新 Python 版本是 Python 3.11。

未来 Python 版本的弃用

从 Python 3.9 开始，Palantir 平台将紧密跟随上游的停用时间表，并在 Python 版本达到上游停用时间后立即在平台内将其弃用。更多信息请参见 Python 版本 文档中的相关内容。

通过跳过已处理的行来优化 Pipeline Builder LLM 构建

发布日期：2024-09-10

我们很高兴地宣布，Pipeline Builder 现在可以为 Use LLM 节点和 Text to Embeddings 转换跳过之前已处理的行，从而节省成本并提升性能。此前，每行数据在管道构建期间都会被重新处理。而现在，行结果可以被缓存，即被存储并在后续构建中重复使用。通过跳过已处理的行，您可以同时节省时间和成本；经测试的用例显示，构建时间从 3 小时缩短到了仅 20 分钟。

要开始使用，请启用 跳过重新计算行 在配置 Use LLM 或 Text to Embeddings 时。启用此功能后，系统会根据传入输入提示的列和参数，将各行与之前已处理的行进行比较。列和参数值相同的匹配行将在未来的部署中获得缓存的输出值，而无需重新处理。

直方图 跳过重新计算行 选项。

如果对提示的更改需要重新计算所有行，用户可以手动清除缓存。在这种情况下，LLM 视图上方会出现一个警告横幅，只要输出类型保持不变，用户可以选择保留所有之前缓存的值。

LLM 视图带有警告横幅，提示用户提示或模型配置已更改。

在您的管道中的 Use LLM 节点和 Text to Embeddings 转换上启用此功能，可以提高工作流效率并降低计算成本。

在 Pipeline Builder 中使用多个受保护分支

发布日期：2024-09-03

您现在可以在 Pipeline Builder 中保护多个分支，以实现更高级别的治理，并防止意外更改。受保护分支只能通过拉取请求进行修改，并且必须经过指定的审批流程才能合并更改。通过实施受保护分支，您可以确保仅进行经授权的修改，并提高数据工作流的安全性和完整性。

要开始使用，请在以下位置配置受保护分支： Settings > Manage branches （位于 Pipeline Builder 中）：

直方图 管理分支 选项（位于设置下拉菜单中）。

选择 分支保护 选项卡，选择要保护的分支以及所需的审批策略。所有受保护分支将遵循相同的审批策略。

直方图 分支保护 选项卡，其中包含两个额外的受保护分支和审批策略选项。

使用多个受保护分支可最大限度地降低意外更改的风险，并创建更加可控的开发环境，让您更加安心。
