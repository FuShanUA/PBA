对象和属性安全策略现已正式发布

发布日期：2026-04-23

您现在可以在以下位置配置对象和属性安全策略： 本体论管理器 直接在对象类型上定义权限，这些对象类型由 批处理 或 流式 管道支撑。对象和属性安全策略现已在所有 Foundry 注册中正式推出，可为行级和列级安全管理提供统一的一流配置体验，且独立于对象类型支撑数据源上的权限。 通过配置对象和属性安全策略，确保用户只能看到其有权访问的数据：

  • 在对象级别控制访问 （行级安全），方法是直接在对象类型上配置安全策略。
  • 在属性级别限制可见性 （列级安全），方法是在创建对象安全策略后，对选定的属性配置安全策略。
  • 实现单元格级安全 ，通过组合对象 和 属性安全策略。

对象和属性安全策略由 细粒度策略组成 和强制控制。默认情况下，策略会从其数据源继承所有强制控制，包括 标记， 组织，或 分类 控制。您可以添加新的强制控制或移除已继承的强制控制，以进一步自定义安全策略。

在本体论管理器中制定细粒度的对象安全策略，以确定不同用户可以查看哪些对象。

在您 创建对象安全策略后，您可以使用除对象类型的主键以外的任何属性来配置属性安全策略。属性安全策略的配置设置与对象安全策略完全相同。

使用对象和属性安全策略代替受限视图

如果您的对象类型目前由 受限视图 支撑，且该视图未在您的本体论之外使用，那么您应考虑通过对象和属性安全策略来实施行级和列级安全，具体步骤请查看 迁移指南.

对于由 AIP 提供支持且符合条件的 Foundry 注册，LLM 容量现在默认可自动扩展至最高 2 倍

发布日期：2026-04-21

自动扩缩容量现已可用，并默认针对特定模型以及特定地理区域和合规级别中符合条件的注册启用。自动扩缩功能将提高注册的容量上限——最高可达当前配额的两倍。此扩展容量仅在 Palantir 已验证具备充足容量、能够可靠支持更高上限的区域提供。它们仍将接受持续的稳定性检查，以确保一致的性能和可靠性。

请在文档中了解有关自动扩缩的更多信息。

主要优势：

  • 更高的容量上限： 符合条件的注册和模型将为其工作负载获得更高的余量，从而降低在正常使用期间触发速率限制的可能性。
  • 自动为项目启用： 当有额外容量可用时，项目会自动访问。
  • 受保护的注册层级限制： 自动扩缩容只会提高容量限制，并保护已为您的注册层级分配的容量。

目前，自动扩缩容仅会影响下方列出的模型。

  • GPT-5
  • GPT-5 mini
  • GPT-5 nano
  • GPT-4.1
  • GPT-4.1 mini
  • GPT-4.1 nano

项目自动扩缩容覆盖

如果您需要按项目进行控制，请启用 项目自动扩缩容覆盖 设置。仅当启用自动扩缩容时，此设置才可用。通过项目自动扩缩容覆盖，您可以选择哪些项目速率限制启用自动扩缩容，哪些未启用。用户文件夹速率限制无法自动扩缩容。

如何管理自动扩缩容容量

您可以随时在 Resource Management 应用程序中启用或禁用自动扩缩容：

  • 导航至 Resource Management > AIP 用量与限制 > 自动扩缩容 （位于 Resource Management 应用程序的右上角）。
  • 根据需要打开或关闭自动扩缩容设置。
  • 如果您需要按项目进行控制，请启用 项目级自动扩缩容覆盖设置 ，并为各个项目的速率限制配置自动扩缩容。

关闭自动扩缩容后，所有项目将恢复为其标准容量限制。不符合条件的已注册项目将不会在应用程序中看到此设置。

Quiver 重新设计的图模式

发布日期：2026-04-14

Quiver 重新设计的图模式自 4 月 13 日当周起在所有注册中正式发布。重新设计的图模式提升了性能，并引入了用于浏览和组织大型分析的新工具。此次重新设计以紧凑的节点设计取代了内联节点预览，新增了组织复杂分析的功能，并采用更节省空间的从左到右布局。首次打开重新设计的图模式时，您将看到一个选项，可将现有节点重新定位以适应新布局。

Quiver 中重新设计的图模式预览。

有哪些新功能？

  • 紧凑节点与专用预览面板： 节点不再以内联方式呈现完整内容，而是显示标题、标识符、类型和基本操作的摘要。选择节点后，其输出将显示在专用的底部面板中。预览可以固定，以便在浏览图时保持可见，也可以在分屏布局中并排查看。
  • 颜色分组： 为相关节点分配颜色，以便直观地区分分析的各个部分。例如，将某个对象下游的所有节点设为蓝色，将另一个对象下游的节点设为红色，使图表一目了然。
  • 折叠和隐藏： 将整个颜色组折叠为单个节点以减少视觉杂乱，或隐藏单个节点和组以聚焦于图表的特定部分。需要查看全貌时，可将其展开或取消隐藏。
  • 筛选： “分析内容”面板包含筛选器，用于控制图表中哪些节点可见。可按节点类型进行筛选，也可以缩小范围，仅显示特定画布、仪表板或函数上的节点。这样可以聚焦于分析的某一区域，同时不会丢失整体背景。
  • 批量操作： 切换到选择模式，然后拖动以选择多个节点。接着可将它们添加到颜色组、隐藏、管理其在画布上的位置，或将其删除。
  • 图表和画布隔离： 在图形模式下添加的节点默认不再放置到画布上。您可以随时通过节点的操作菜单在画布中添加或移除节点。在画布模式下，删除卡片时，您可以选择仅将其从画布中移除，或将其从整个分析中完全移除。
  • 从图形中选择输入： 在图形模式下配置节点时，您可以直接从图形中选取节点来选择其输入，而无需在列表中搜索。

在管道构建器中使用托管配置文件缩放计算资源

发布日期：2026-04-14

管道构建器现已推出针对计算资源的托管配置文件策略。选择此策略后，管道构建器会分析您最近五次构建的资源使用情况，如果这些构建所使用的资源少于您当前的选择，则会调整您的计算资源。

例如，如果您选择了 large 配置文件，但您最近五次构建使用的资源明显更少，管道构建器将自动缩减您的计算资源，以匹配您的实际使用量。

详细了解管道构建器中的配置文件管理策略。

构建设置中“配置文件管理策略”下的“托管配置文件”选项。

如何启用托管配置文件功能

  • 前往 构建设置 （位于右侧面板中）。
  • 打开 默认计算配置文件。
  • 在 配置文件管理策略，选择 托管配置文件 （从下拉菜单中）。

配置文件管理策略会显示为标签，位于构建计算配置文件面板顶部、您的构建配置文件类型旁边。

关于该功能的其他注意事项

  • 托管配置文件只会缩减规模，不会扩展到超出您最初选择的配置文件。
  • 如果您的数据大小或工作负载在两次构建之间发生大幅变化，构建可能会失败，因为托管配置文件是根据以往的使用情况进行扩缩容的。
  • Pipeline Builder 中的托管配置文件目前不支持在原生加速构建中使用。

什么是电子邮件媒体集？

电子邮件媒体集允许您将 .eml 文件作为 Foundry 中的一等媒体项进行处理。当您需要从电子邮件中提取和处理附件（例如电子表格、文档或图像），同时还要保留对电子邮件元数据和正文内容的访问以供后续处理时，它们尤其有用。

核心功能

  • 上传和预览内容： 上传 .eml 将文件上传到媒体集，并查看可在 Foundry 中直接呈现电子邮件内容的交互式预览，例如在 Workshop 模块的 “媒体预览”小部件。该预览会显示邮件标头、内容、元数据以及附件列表。

上传到媒体集的电子邮件的预览。

  • 预览和下载附件： 直接在邮件预览中查看任何 受支持的媒体格式的附件预览。您可以下载不受支持的附件文件类型。

查看受支持媒体格式的附件预览，或下载不受支持的附件文件类型。

  • 在下游处理电子邮件文件： 使用 管道构建器 表达式或 Python 转换 在代码工作区中进行以下操作：
    • 提取电子邮件附件并将其输出到其他媒体集，以便进一步处理。
    • 将邮件内容提取为纯文本或 HTML，以便用于由 LLM 驱动的工作流。

管道构建器现已支持增量媒体集输入

发布日期：2026-04-07

管道构建器现在支持对媒体集输入进行增量处理。选择媒体集输入节点，然后选择 增量 以启用此功能。通过利用媒体集的构建历史，增量计算避免了每次运行转换时重新计算整个输出的需要，从而节省时间和计算成本。

选择了增量选项的媒体集输入。

工作原理

  • 首次构建： 管道构建器将照常处理您的整个媒体集。
  • 后续构建： 仅处理自上次构建以来新增或已更改的数据，从而节省您的时间和计算成本。

下一步是什么？

  • 混合增量数据集和媒体集输入： 目前尚不支持在同一管道中混用增量媒体集与增量数据集。团队正在积极努力，将在未来的更新中实现此功能。
  • 增量媒体集输出： 对媒体集输出进行增量处理的支持也即将推出。

Pipeline Builder 中的模型功能介绍：无代码模型推理

发布日期：2026-04-02

用户现在可以直接在 Pipeline Builder 中使用机器学习模型进行推理——无需编写代码。通过将模型引入 Pipeline Builder,我们显著降低了构建和迭代推理工作流的门槛。结合 Model Studio,即可实现从模型训练到生产推理的全程无代码路径。

仅支持 Spark(批处理)管道。流式管道和轻量级管道尚不可用。模型必须恰好具有一个表格输入和一个表格输出,且时间序列模型尚未得到完全支持。

主要功能

  • 更快迭代： 对推理管道进行更改并立即运行构建——无需等待 CI 检查，也无需调试代码。Pipeline Builder 让您可以轻松验证结果并快速迭代。
  • 分支感知自动升级： 在构建时，管道会自动从当前构建所在的分支解析最新发布的模型版本。如果该分支上不存在任何版本，解析将回退到您配置的回退分支。如果未配置回退分支，则默认使用 master。这可确保您的推理管道始终使用模型的最新训练版本，无需人工干预。
  • 资源配置： 模型作为隔离的 sidecar 进程与您的 Spark 执行器一同运行，每个进程均拥有专用的计算资源。您可以为模型 sidecar 独立于管道的计算配置来配置 CPU、内存和 GPU，确保即使是资源密集型模型也能可靠运行。

入门

1. 配置您的管道： 请确保您使用的是 Spark（批处理）管道，并且已关闭暖池（warm pool）。

已关闭预热池的批处理管道构建器。

2. 导入您的模型： 导航至 可复用项 > 已训练的模型 在导入菜单中，并按照资源导入流程操作，使您的模型可供管道使用。

可复用逻辑选择器。

3. 添加模型节点： 在您的管道画布中选择一个节点，然后选择 已训练模型 以将其插入。

从可用选项中，选择已训练模型。

4.配置输入和输出： 将您的输入和输出列映射到模型预期的 API 架构。

Pipeline Builder 中模型节点的输入和输出配置。

下一步是什么？

预览和流式传输支持即将推出。我们正在积极开发轻量级支持、更多输入类型、时间序列支持以及 Marketplace 集成。

要了解更多信息，请查阅 Pipeline Builder 文档中有关 Trained models 的内容。
