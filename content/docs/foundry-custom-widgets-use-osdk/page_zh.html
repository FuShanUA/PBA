在小部件集中使用本体论 SDK (OSDK)

您可以按照以下各部分中概述的步骤在小部件集中使用 OSDK。

为您的小部件集配置 OSDK

要为您的小部件集配置本体论 SDK (OSDK)，请导航到您的小部件集的概览页面，然后选择 配置 SDK （位于页面顶部栏中）。

然后，选择一个本体论以及您希望从小部件中访问的特定资源。

启用本体论 API

您还需要为您的小部件集启用本体论 API，以便从 OSDK 发出的 API 调用能够成功。此操作可由具有 信息安全官 默认注册角色的用户执行。或者，具有授予 Enable widget set unscoped API access 工作流权限的自定义注册角色的用户也可以执行此操作。

在您的小部件中安装 OSDK

完成上述步骤后，您就可以开始在小部件集中使用 OSDK。为此，请确保 @custom-widget/sdk 已列在您的 package.json 中，并使用以下 JSON 正确安装：

如果您在创建时选择了 在 Foundry 中 选项,则您使用的是 Foundry 代码仓库。您的项目 .npmrc 文件应该已经配置好,可以从 Foundry 解析 NPM 依赖项(包括您的 OSDK 包),并且此文件 不应被修改。

如果您在创建时选择了 在 Foundry 之外 选项且在创建过程中未生成 OSDK 包，则您必须手动配置 NPM，才能从 Foundry 解析您的 OSDK 包。这可以通过在您的项目根目录中创建 .npmrc 文件来完成，其内容如下：

//<EXAMPLE>.palantirfoundry.com/artifacts/api/:_authToken=${FOUNDRY_TOKEN}
@custom-widget:registry=https://<EXAMPLE>.palantirfoundry.com/artifacts/api/repositories/<ri.widgetregistry..widget-set.LOCATOR>/contents/release/npm/

上述代码片段告诉 NPM 从 Foundry 解析 @custom-widget 作用域，并使用 FOUNDRY_TOKEN 环境变量进行身份验证。您应当将 <EXAMPLE> 和 <ri.widgetregistry..widget-set.LOCATOR> 占位符替换为您的 Foundry 实例和小组件集 RID 的具体值。

在您的小组件中配置 OSDK

请确保您的客户端已配置 baseUrl 设置为 window.location.origin。您可以使用 createFoundryWidgetTokenProvider() 辅助函数来为身份验证令牌提供占位符值，因为对本体论的任何访问都会在运行时使用用户的令牌并遵循用户的权限。请查看以下代码片段：

    window.location.origin,
    $ontologyRid,
    createFoundryWidgetTokenProvider(),
);

使用 OSDK

请参阅您的 OSDK 文档以了解有关用法的更多信息，方法是选择 SDK 文档 选项，该选项位于您微件集的顶部栏上。

在操作时刷新宿主数据

当微件使用 OSDK 应用会修改对象集参数支撑数据的 Ontology 操作时，宿主应用程序的数据可能会过时。

要解决此问题，您可以启用 refreshHostDataOnAction 选项，该选项会使宿主应用程序（例如 Workshop）在微件应用 Ontology 操作后，自动刷新传递给该微件的所有对象集参数。在 Workshop 中，应用程序构建者无需进行额外配置。

新创建的微件集默认在插件级别启用此选项。对于现有的微件集，您可以按照下文所述手动启用该选项。

要将其设为微件集中所有微件的默认设置，请配置 defaults Vite 插件中的选项：

import FoundryWidgetPlugin from "@osdk/widget.vite-plugin";
import { defineConfig } from "vite";

export default defineConfig({
    plugins: [
        FoundryWidgetPlugin({
            defaults: {
                refreshHostDataOnAction: true,
            },
        }),
    ],
});

限制

目前，小部件不支持以下 Foundry API 功能：

  • 对象集订阅
  • 非本体论 API
