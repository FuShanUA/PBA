Spoke 控制平面

在 Apollo 管理的每个 Spoke 环境中，都需要存在一组最低限度的功能，Apollo 才能提供其工作流。这些功能由以下组件提供，它们共同构成了 Spoke 控制平面。

Apollo 代理

helm-chart-operator

一个 Apollo 代理，负责管理类型为 helm-chart 的 Apollo 实体。对于由 Apollo 管理并在环境中运行的 Helm Charts，执行生命周期操作（安装、配置更改）时它是必需的。

helm-chart-operator 还负责管理 Spoke 控制平面中的所有其他服务。它不依赖于 Spoke 控制平面中的其他任何服务，并且是安装到 Spoke 环境中的第一个服务。

Pod 注册表替换和镜像拉取密钥注入

helm-chart-operator 提供一项可选功能，允许您：

  • 重写容器镜像注册表，以使用您的Apollo Artifact Registry 镜像。
  • 为所有 Kubernetes Pod 资源注入镜像拉取密钥。

此功能适用于非 Helm chart 的 Pod，例如 Helm hook Pod 或动态部署的 Pod。该功能由一个 Kubernetes 变更准入 Webhook 提供，该 Webhook 会作用于部署在带有 apollo.palantir.com/env-id: <your env id> 标签的命名空间中的所有 Pod。这些命名空间可以由 Helm 或 Apollo 管理。

要启用此功能：

  1. 应用您的环境所需的任何网络配置（例如 CiliumNetworkPolicy），以便 API 服务器能够访问该 Webhook 服务。为此，您可能需要以下信息：

    • Webhook Kubernetes 服务名称：helm-chart-operator
    • Webhook Kubernetes 命名空间：<the namespace the helm-chart-operator product is installed into>
    • 端口：9111
    • 协议：TCP
    • Pod 标签选择器：rubix-app: helm-chart-operator

  2. 在 helm-chart-operator 上设置以下配置覆盖：

    • enablePodRegistryReplacementMutatingWebhook: true

启用该功能后，若要将某个 Pod 从变更 Webhook 中排除，请向该 Pod 添加以下标签：apollo.palantir.com/skip-registry-mutation: ""

apollo-auth-broker

一种 Apollo Agent，负责代表 Apollo Agent 在 Apollo Hub、Spoke 环境与任何制品注册表之间代理身份验证材料。

健康

expected-state-k8s

获取 Kubernetes 环境的当前状态，将 Kubernetes 对象模型转换为 Apollo 对象模型，并将该信息发送回 Apollo Hub。

例如，expected-state-k8s 会提供 Kubernetes 环境中有关 Pod 应运行多少个副本的信息，并将其反馈给 Hub。它还负责从所有受管实体收集健康信息，并将其转发给 Apollo Hub 以报告健康状况。
