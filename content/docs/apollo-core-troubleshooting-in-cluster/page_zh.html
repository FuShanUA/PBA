Kubernetes 集群中的故障排除

Apollo 利用核心的 Kubernetes 和 Helm API 对您环境中已部署的资源进行更改。Apollo 会在您的 Hub 中集中收集大量信息，帮助您跨集群进行大规模运营。但是，Apollo 并非要完全取代集群内的工具和专业知识。您最终仍需要调试某些问题为何出错。

本指南旨在重点介绍在对 Apollo 管理的 Helm chart 进行故障排除时，在您的集群中有用的关键命令。这不是一份详尽的列表，其目的是作为一个起点，将您连接到 Apollo 之外的宝贵资源。

Kubernetes

在开始使用 Apollo 之前，您应该熟悉 Kubernetes 的基础知识。我们建议您先查阅 概念 ↗ 页面，并尝试一些 Kubernetes 教程 ↗。您还可以参考 kubectl 速查表 ↗ 以了解有关这些命令的更多信息。

本指南旨在帮助您在使用 Apollo 管理 Helm charts 时排查问题，为您指明正确的方向。

Kubernetes 核心文档建议在学习 Kubernetes 时使用 minikube ↗。这适用于基本场景，但其局限性使得使用 Apollo 更具挑战性。我们建议您使用配置为基本多节点集群的 kind。

Pod 日志

Apollo 假定您有自己的方法来访问正在运行的 Pod 的日志。这些日志通常对排查已部署的 Helm chart 的问题至关重要。这些日志不会在 Apollo 中显示。Apollo 只会显示由 Helm 或 Kubernetes 发出的信息。如果您的 Pod 已启动且处于 Error 或 CrashLoopBackOff 状态，则应查看 Pod 日志以诊断问题。

如果您对集群内的 kubectl 至少具有读取权限，则可以通过上述 kubectl get pods 命令中的 NAME,针对相应的 Pod 运行 kubectl logs。

请注意，您可以使用诸如 --since 之类的附加标志来限制输出，仅显示较新且相关的日志。

常见问题与故障排除

某些 Helm chart 会对您的 Kubernetes 环境做出一些假设，以便正常工作。归根结底，这是 Helm chart、其部署环境或其配置方式的问题。您必须选择如何在您的每个环境和 Helm chart 中解决这些问题。

本节记录了您可能遇到的一些常见问题，并提供了相应的处理建议。请务必记住，这些只是入门选项，您必须自行确定正确的解决方案。

缺少 LoadBalancer

您可能遇到的一个常见问题是假设环境中已经存在 LoadBalancer。如果您在超大规模云提供商的 Kubernetes 环境（如 Google Kubernetes Engine (GKE) ↗、Azure Kubernetes Service (AKS) ↗ 或 Elastic Kubernetes Service (EKS) ↗）中运行 Helm chart，则会自动为您配置好此功能。

这是一项云提供商服务，可为您的服务分配 IP 地址。如果您按照我们针对本地开发的建议使用 kind，则不会有这项功能，而且在不向环境添加支持资源的情况下，Wordpress 等 Helm chart 将无法安装。

Service does not have load balancer ingress IP address: default/wordpress

您可以选择如何在各个环境和 Helm chart 中解决这些问题。对于基本的本地 kind 集群，我们建议部署类似 MetalLB ↗ 的 LoadBalancer。

Helm charts

在将 Helm chart 部署到 Apollo 之前，您应当先熟悉 Helm chart 的一般工作原理，以及如何在独立于 Apollo 的情况下将特定的 Helm chart 部署到 Kubernetes 集群。我们建议从官方的 Helm 快速入门指南 ↗ 开始。本指南将 Apollo 中发生的情况与 Helm 中发生的情况联系起来。

Apollo 使用 Helm 来管理部署在您环境中的 Helm chart 类型的 实体。这意味着，只要您拥有环境的访问权限，您通常使用的那些 Helm 命令仍然很有用。

环境

如果您使用本地 Kubernetes 集群设置了 Apollo 环境，则应确认您的代理是否已成功向 Apollo 报告。 即使代理的 Pod 正在运行，它们也可能未向 Apollo 报告。这将导致 Apollo 无法为环境下发计划。

重新应用清单

解决此问题的一种可能方法是将清单重新应用到您的环境。在 Apollo 中导航到您的环境，然后在右上角找到操作下拉菜单。选择操作以打开下拉菜单，然后选择环境设置说明。按照对话框中的说明操作。下载并应用清单后，请等待一分钟并重新加载页面。

创建新环境

如果您退出或重启了 Docker，或重启了计算机，您的环境中的代理可能无法重新连接到 Apollo。如果您已尝试上述故障排除步骤，但代理仍处于断开连接状态，则可能需要创建新环境。
