构建复杂布局

为应用程序设计外观和风格是一件令人兴奋的事情，Slate 让你能够灵活地自定义和覆盖小部件外观的许多方面。然而，许多项目在实现与设计稿像素级完美匹配变得比干净、高效地实现工作流功能更重要时，就会偏离正轨。

另一种思考方式是，每一次样式覆盖都是在应用程序的简洁性和可维护性上做出的权衡。在选择布局和样式时要谨慎且深思熟虑，并在开始新一轮功能开发之前，花时间定期重构和清理你的应用程序。

构建复杂布局

用途 容器小部件 来布局你的应用程序。在用足够的容器逻辑地组织应用程序与不必要地嵌套容器之间取得平衡。请记住，在构建应用程序时，每个小部件最终都会为 文档对象模型 (DOM) ↗ 增加若干层级，而 DOM 的复杂度与浏览器资源使用、页面加载以及应用程序的整体响应能力（即应用程序的“重量”）直接相关。如有疑问，请使用更少的小部件，并尽量避免嵌套容器超过 3 或 4 层深度。

在几乎所有情况下，你都应避免使用 CSS 来影响 如果配置了多个 你的应用程序的布局——远离 position ，并使用静态小部件定位或 flex 容器进行相对定位。在特定情况下有一些例外，但对于应用程序的整体布局而言，坚持使用内置定位工具可以避免不必要的复杂性，并提高应用程序的可读性。

对齐小部件

Slate 一个经常被忽视的功能是能够将小部件相互对齐。按住 CTRL 键（Mac 上为 CMD）并点击以选择一个或多个小部件。选中多个小部件后，右侧面板将不再显示小部件配置，而是显示若干用于对齐或分布小部件的选项。

此外，如果你希望布局“自动”完成，可以使用 Flex 容器 来布局子小部件。有关使用 Flex 容器的更多内容，请参阅下面关于响应式布局的章节。

显示和隐藏小部件

动态布局通常包括根据应用程序的状态显示或隐藏内容。有多种方法可以实现这一点。下面的三种模式分享了一些选项，并讨论了各自的优缺点。

简单：使用类隐藏

在最简单的情况下，你可以通过模板化 Additional Classes 小部件显示配置中的属性为 hidden来隐藏小部件。常见的模式是使用函数（或状态变量）判断小部件是否应显示，然后将该函数的输出模板化到小部件中。虽然这种方法很简单，但它不能很好地扩展到多个小部件，而且对于在页面加载时“隐藏”的小部件，你会看到短暂的闪烁，因为在依赖关系图解析并应用类之前，它们将保持可见。

改进：使用选项卡容器隐藏

更好的做法（尤其是在有多个小部件时）是使用选项卡容器，其中一个选项卡为空白，另一个包含要显示的小部件。此处的模式是应用一些 CSS 来隐藏容器边框和背景（即使容器相对于背景“不可见”）：

然后模板化 selectedTabIndex 属性以在隐藏和可见之间切换。使用此模式，页面加载时不会出现闪烁，小部件将立即隐藏。

复杂：从根元素隐藏

如果你需要一个小部件不仅“隐藏”，而是从 DOM 中完全移除，可以通过在父容器上模板化一个额外的类，利用根元素选择器来隐藏该小部件。这种模式最常见于需要隐藏小部件的响应式布局中 和 导致同一层级的其他子小部件重新定位。

每个 Slate 小部件的根元素都有一个格式如下的 ID 选择器： widget-[widgetName]。所以假设我们有一个名为 w_myHTMLWidget 的小部件，它是 w_sidebar 容器的子元素。要完全隐藏该小部件，你可以在全局样式中定义一个类：

.hide-myHTMLWidget {
    #widget-myHTMLWidget {
        display: none;
    }
}

然后在 w_sidebar 中，你可以有条件地添加这个类，整个小部件就会被隐藏。参见 使用样式 一节，了解更多使用条件 CSS 类的模式和示例。

“多页”应用程序

分割应用程序最常用的模式是使用 选项卡式容器。 每个容器选项卡都可以被视为一个单独的页面，但需要注意的是，这些“页面”只是 UI 功能——它不会影响依赖图的解析。例如，即使某个图表位于另一个选项卡上，填充该图表的查询仍会随依赖图的解析而运行。

如果你正在使用选项卡式容器构建多页应用程序，请务必勾选 Lazy rendering enabled 选项——这会将选项卡上小部件的渲染移至 选项卡打开时 而非 页面加载时。这对于非常庞大的应用程序尤其有用，因为在任意时刻大多数小部件都“隐藏”在另一个选项卡上，这可以显著缩短页面加载时间。

即使你不希望允许用户手动选择某个选项卡，也应该使用选项卡式容器——例如，当你构建工作流应用程序并需要控制用户何时切换到下一个选项卡时。在这种情况下，你可以取消勾选 Show tab titles 选项，然后使用 Handlebars 语句来模板化在任意时刻应显示哪个选项卡（从零开始索引）。一种常见的模式是将该选项卡作为应用程序状态的一部分进行跟踪（参见上文 构建有状态应用程序 ），这样你只需更新状态变量中当前选项卡的值，应用程序中的选项卡就会随之切换。
