跨仓库共享代码

本节介绍在仓库之间共享 Java 代码的基本工作流程。

前提条件

在继续阅读之前，请确保您已创建一个单独的仓库，其中包含您将在其他仓库中依赖的 Java 代码/宏。在本指南中，我们将把这个包含要共享的 Java 代码/宏的仓库称为 共享代码仓库，而我们将把任何依赖于 共享代码仓库 作为 依赖仓库.

在向您的 共享代码仓库添加 Java 代码/宏后，请务必通过提交更改来编译仓库。

权限设置

为了共享代码，您必须确保 依赖仓库 有权访问由 共享代码仓库生成的工件。要配置可从 依赖仓库。如果您位于 工件 已应用标签 设置 标签页。 了解更多关于工件设置的信息。

Gradle 设置

针对依赖仓库

每当您跨仓库共享代码（包括 Java 代码和宏）时，都需要为 依赖仓库 进行 Gradle 设置。

Jemma 会自动发布由 共享代码仓库生成的工件。因此，在完成上述所需权限的设置后， 依赖仓库 只需指向已发布的工件即可。这需要在 build.gradle 的语言特定子项目的 依赖仓库:

dependencies {
    compile '<SHARED_CODE_REPO_RID>:<SHARED_CODE_REPO_GRADLE_SUBPROJECT>:<SHARED_CODE_REPO_VERSION>'
}

文件末尾添加如下代码块。按照以下步骤获取所需信息并将其添加到 build.gradle 文件。

  1. 首先，您需要 SHARED_CODE_REPO_RID，即 共享代码仓库的 RID。您可以从仓库 URL 中获取该信息。或者，您也可以在“工件设置”选项卡中点击某个仓库条目，将上述 compile 行（已填入共享仓库 RID，例如 compile 'ri.stemma.repository.some-random-rid:<SHARED_CODE_REPO_GRADLE_SUBPROJECT>:<SHARED_CODE_REPO_VERSION>'）复制到剪贴板。




  2. 接下来，您需要获取 SHARED_CODE_REPO_GRADLE_SUBPROJECT 和 SHARED_CODE_REPO_VERSION的值。要获取这些值，请修改 ci.yml 文件中定义您的函数，该文件位于 共享代码仓库 ，在最后一行（以 --info 开头）添加 ./gradlew。例如：

    ./gradlew --no-daemon --build-cache --stacktrace patch publish

    变为：

    ./gradlew --no-daemon --build-cache --stacktrace patch publish --info

    然后，在 共享代码仓库中查看最新 Jemma 作业的 CI 输出。在 CI 输出中查找符合以下格式之一的行：

    Upload https://<MAVEN_REPO_URL>/maven-repository-proxy/authz/user-code/<SHARED_CODE_REPO_RID>/<SHARED_CODE_REPO_GRADLE_SUBPROJECT>/<SHARED_CODE_REPO_VERSION>/<SHARED_CODE_REPO_GRADLE_SUBPROJECT>-<SHARED_CODE_REPO_VERSION>.jar

    or

    Uploading: ri/stemma/main/repository/<SHARED_CODE_REPO_UUID>/<SHARED_CODE_REPO_GRADLE_SUBPROJECT>/<SHARED_CODE_REPO_VERSION>/<SHARED_CODE_REPO_GRADLE_SUBPROJECT>-<SHARED_CODE_REPO_VERSION>.jar to repository remote at https://<ARTIFACTS_URL>/artifacts/api/legacy/mrp/authz/user-code/

    or

    Uploading: ri/stemma/main/repository/<SHARED_CODE_REPO_UUID>/<SHARED_CODE_REPO_GRADLE_SUBPROJECT>/<SHARED_CODE_REPO_VERSION>/<SHARED_CODE_REPO_GRADLE_SUBPROJECT>-<SHARED_CODE_REPO_VERSION>.jar to repository remote at https://<ARTIFACTS_URL>/artifacts/api/repositories/<SHARED_CODE_REPO_UUID>/contents/release/maven/

    使用 CI 输出中的信息，您可以构建引用由您的 共享代码仓库。该 <SHARED_CODE_REPO_RID> 生成的工件的 Maven 坐标。您在 Maven 坐标中提供的 ri.stemma.main.repository.{RID_VALUE}.

现在，您应该能够访问来自 共享代码仓库 菜单中选择 依赖代码仓库!

共享代码更新需要手动提升版本号

当您更新 共享代码仓库中的代码时，您需要更新 Maven 坐标中的 <SHARED_CODE_REPO_VERSION> ，以确保您的 依赖仓库 使用的是最新版本的共享代码。每次编译 共享代码仓库时，请查看 CI 输出以找到您应引用的更新后的版本号。

结论

现在，您已准备好开始跨仓库共享代码。对于任何需要引用来自 依赖仓库 的代码的 共享代码仓库，请确保您已完成上述步骤以设置正确的权限和依赖项。

与 Python 不同，Code Repositories 不支持创建 Java 库，仅支持共享 Java 仓库。这意味着标记等功能也不支持 Java。
