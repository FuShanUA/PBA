评论

评论（Comments）小组件可在 Workshop 模块中实现协作。

引用

您可以在评论中使用引用来提及对象。引用是可交互的，选择一个引用可以在工具提示中显示所提及对象的属性，或者在模块中触发事件，例如打开模态框或显示 对象视图.

权限

评论不是独立的对象，它们直接附加到父对象上。它们不会显示在 对象浏览器 中，只能通过评论小组件显示。要使评论在 Ontology（本体论）中可搜索， 请查看下面的这一部分.

评论遵循父对象的权限，因此如果您可以访问该对象，就可以查看并在其下发布新评论。这意味着 受限视图 会自动获得支持。如果您无意中发布了某些内容，也可以删除自己的评论。

关于细粒度权限的说明

让我们通过一个医疗诊所的示例来探讨更细粒度的权限。医疗诊所可以配置一个 patient 具有列级权限的对象，使管理员只能看到基本字段，而医生既可以查看基本字段也可以查看敏感字段。为了防止管理员查看医生在敏感字段上留下的评论，诊所创建了一个单独的代理对象，称为 PatientSensitiveComments。这样，他们的模块中可以有两个评论线程，一个直接在 patient 对象上，管理员和医生都可以看到；另一个在代理对象 PatientSensitiveComments 上，只有医生可以看到。

（高级）使评论在 Ontology（本体论）中可搜索

您可以通过启用 操作日志来在 Ontology（本体论）中保留评论的历史记录。为此，请开启 评论后执行的操作 并导航到 Ontology（本体论）以配置诸如 评论文本, 父对象日 当前用户等字段。由于操作日志（Action Log）是只追加的，以这种方式存储的评论在写入后无法编辑或删除。

或者，您可以创建一个专用的对象类型（例如， Ticket Comment）来在 Ontology（本体论）中镜像评论，使其可搜索并可用于 Ontology 工作流。采用这种方法时，您需要配置 评论后执行的操作 来创建一个包含评论文本的新对象。

但是，评论服务仍然是事实来源：编辑或删除镜像对象不会影响小组件中显示的评论，也不会保留评论历史记录。如果您需要所有评论活动的不可变记录，请改用操作日志（Action Log）方法。

在添加 Comment text 导出到 操作日志:

  • 之前，有几件事需要考虑。如果父对象被配置为 受限视图 并且行级权限引用了一个可以更改的字段，您应当谨慎行事，因为操作日志（Action Log）是只追加的。例如，如果某个工单有一个名为 Sensitivity level 的字段，其值从 Public to Legal only发生变化，那么操作日志中已存储的评论仍将包含先前的值 Public。为确保您复制到 Ontology 层的评论遵循父对象的权限，您应该创建一个专用的 Ticket Comment 对象，并配置一个操作，在更改工单的 Sensitivity level 的同时，也更新存储在 Sensitivity level 中的评论的 Ticket Comment object.
  • 操作日志（Action Log）不会像评论小组件那样显示评论的富文本内容。

通知

在对某个对象发表评论后，系统会自动为您订阅通知，以便在其他用户对该对象发表评论时收到通知。在评论中提及某个用户也会向其发送通知，并使其订阅该对象后续评论的通知。通知会以电子邮件的形式发送给用户，并显示在 Foundry 中的通知收件箱里。

通知应被视为工作流的增强功能，不应成为通知用户存在待处理操作的唯一方式。用户应能够在您的 Workshop 应用程序中，通过 收件箱视图.

默认通知

评论小组件默认启用通知。默认通知包含指向 对象视图 的链接，即评论所针对的对象。为确保用户点击链接时能够看到评论，您应将 对象视图配置为由 Workshop 模块支撑 并包含评论小组件。要自定义通知文本或改为包含指向 Workshop 应用程序的链接，请按照 自定义通知.

自定义通知

要发送自定义通知，您可以禁用“发送默认通知”，并配置一个具有通知副作用的“评论后执行的操作”，请参阅 操作通知文档 以了解更多信息。评论小组件提供可传递给操作的特殊值： Users to notify （Multipass 用户 ID 列表）和 Comment text。这些值使您能够轻松构建自定义通知。要包含指向 Workshop 应用程序中特定位置的链接，您可以配置一个 module interface variable。以下示例展示了如何配置自定义通知：

附件

您可以在父对象下或直接在评论下上传附件（如文件和图片）。在评论下上传的附件仅在评论小组件中可见，最适合用于草稿文档和迭代。我们建议仅上传较小的附件；对于较大的附件，您会注意到上传时间较长，且存在 200 MB 的限制。我们建议将较大的附件直接上传到父对象上。

对于超过 200 MB 附件限制的文件，请考虑使用 多模态媒体集 。将您的文件存储在媒体集中，并使用 媒体引用 将它们与您的对象关联，而不是作为传统附件上传。

常见问题

当操作发生时，我可以自动创建评论吗？

评论小组件允许您在通用动态中与评论一起显示操作日志条目，因此自动化的“评论”应表示为操作日志条目。

我可以在 Workshop 的评论小组件中显示来自 Object Explorer 中评论助手的评论吗？

来自 Object Explorer 中评论助手的评论无法在 Workshop 的评论小组件中显示或重复使用。

如何防止自动刷新清除评论小组件中未发送的文本？

在模块中启用自动刷新时，刷新可能会清除用户在评论小组件中输入的未发送文本。为防止这种情况，请使用按钮驱动的事件来控制自动刷新，而不是让其始终保持开启。当用户导航到包含评论小组件的选项卡时禁用自动刷新，仅在切换回需要实时数据更新的选项卡时重新启用自动刷新。了解有关 通过事件控制自动刷新.
