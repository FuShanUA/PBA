Code Workspaces 入门

本教程通过为 JupyterLab® 或 RStudio® Workbench 设置工作区，介绍 Code Workspaces 的基础知识。

支撑代码仓库

所有代码工作区都由一个 Palantir 平台支撑 代码仓库。这使代码工作区具备行业标准版本控制功能，例如分支、合并和提交历史记录，允许其他用户查看代码并在同一工作区中安全地操作。

此前，代码工作区和关联的代码仓库由单独的资源表示。现在，代码工作区和关联的代码仓库由单一资源表示，即代码仓库。在 Foundry 中从任何文件夹选择代码仓库时，将自动打开关联的 Jupyter 或 RStudio® 工作区。

此更改适用于新的代码工作区，不影响现有的代码工作区和代码仓库，它们将继续作为单独的资源存在。

启动代码工作区

要启动代码工作区，请打开 Code Workspaces 应用程序并导航至 常规 选项卡。然后，选择要在其中创建代码工作区的文件夹。

具有……的用户 Editor or Owner 项目上的角色将能够修改代码工作区的设置。具有 Viewer 项目角色的用户将能够启动工作区。您可以选择您的主文件夹作为位置，但这可能会导致您的代码工作区和数据被限制在某个项目中。

选择要启动的工作区类型。目前支持的工作区为 JupyterLab 和 RStudio® Workbench。

然后，为要创建的工作区设置支撑代码仓库的名称和位置。如果您要创建 RStudio® 工作区，则可以选择许可证。在大多数情况下，许可证将被自动选择。

启动工作区的每个用户都将运行自己独立的会话。如果两个或更多用户将使用同一工作区，请确保所有用户对底层代码仓库具有 Viewer 权限或更高权限。有关代码工作区的更多信息，请参见上文 底层代码仓库.

部分中选择

高级设置允许您定义代码工作区的空闲时间和资源配置文件。这些设置可以随时在 设置 工作区的面板中修改，可通过选择右上角的齿轮图标访问该面板。

  • 自动关闭
    • 自动关闭设置定义了容器保持活动状态的时间段。在此不活动时间段之后，工作区将自动关闭以减少资源使用。自动关闭后，需要将软件包和数据集重新部署到您的容器，但您的代码将保留。
    • 默认的自动关闭时间为 30 分钟。自动关闭设置的最大值为 6 小时，最大会话长度为 24 小时。
    • 较长的自动关闭设置可能会产生更高的费用。我们建议设置较短的自动关闭时间以降低成本，并依赖提交到 Foundry 的代码，而不是跨会话恢复的未提交更改（参见 代码工作区生命周期文档 below).
  • 计算资源
    • 为您的工作区选择 CPU 和内存。您的选择可以扩展到 资源队列的项目中的训练任务 支撑您的项目的最大可用值。更大的资源配置文件可能会产生更高的费用。
    • 如果您的注册使用托管计算配置文件，则您可以选择的计算由导入到项目中的计算配置文件决定。参见 配置 Code Workspaces 计算配置文件.
  • 网络策略
    • 如果管理员已启用此功能，您将能够选择要附加到工作区的网络策略，以便从您的工作区进行外部 API 调用。

转换

您不能直接在底层代码仓库中发布转换，因为该仓库已被自定义为 Code Workspaces 的基础设施。所有代码都必须从代码工作区中发布。

导入数据

您可以直接从 Foundry 中的数据源导入数据，方法是导航至 同步至数据集 选项卡，然后选择 Add > Read data。这包括 Foundry 数据集、 Iceberg 表日 虚拟表。任何从代码工作区当前项目之外（包括用户的主文件夹）导入的数据，都需要添加引用。

或者，对于尚未导入 Foundry 的数据，请选择 上传数据 以直接从您的设备导入数据。

数据集视图不能在代码工作区中用作导入的数据集。如有需要，请将数据集视图复制到新的或现有的数据集中。

导入软件包

您可以通过导航至左侧面板中的 软件包 选项卡将软件包导入您的代码工作区，也可以直接使用 Conda 或 PyPI（适用于 Jupyter®）以及 CRAN（适用于 RStudio®）安装软件包。

JupyterLab® 软件包

JupyterLab® 工作区支持从 Conda 或 PyPI 安装软件包。默认情况下，Code Workspaces 会公开 conda-forge 和 pypi.org。您可以通过将其他频道添加到支撑代码仓库并重启代码工作区的方式，将其添加到代码工作区中。

使用托管环境，可以在 JupyterLab® 中的工作流、应用程序或转换之间一致地还原 JupyterLab® 中的 Conda/PyPI 环境。

您可以从 软件包 选项卡浏览软件包，并选择您想要安装的软件包。这将在新的 JupyterLab® 终端中自动为您执行安装命令。

要手动安装软件包，您可以使用 maestro env conda install <packages> 安装 Conda 软件包，并使用 maestro env pip install <packages> 在 JupyterLab® 终端中安装 PyPI 软件包。

审查 Jupyter® Notebooks 中的托管 Conda/PyPI 环境 的文档以获取更多信息。

直接使用 mamba 和 pip 安装软件包的方式现已弃用。

CRAN

RStudio® 工作区支持从 CRAN、Posit™ Package Manager 或 Bioconductor 安装软件包。默认情况下，Code Workspaces 会公开 Posit™ Public Package Manager ↗ 的全部内容以及 Bioconductor ↗。您可以通过将其他频道（如 MRAN）添加到支撑代码仓库并重启代码工作区的方式，将其添加到代码工作区中。

要安装软件包，您可以使用 renv 因为 renv 支持经过身份验证的 CRAN 频道。

您可以从 软件包 选项卡并选择您想要安装的软件包。这将为您生成一条安装命令，供您复制粘贴到 RStudio® Workbench 中执行。通常，CRAN 软件包使用 renv::install("<package>") 安装，而 Bioconductor 软件包使用 renv::install("bioc::<package>").

发布您的代码

为了让同一工作区的其他用户查看您的代码，您必须将代码发布到您正在工作的分支。

发布代码将触发 CI 检查，并为每个已注册的 Code Workspace 应用程序发布新版本。作为最佳实践，我们建议让代码工作区专注于单一类型的任务（例如构建应用程序、分析数据、编写数据转换或构建模型），而不是尝试在单个代码工作区中完成多个独立的工作流。

未发布的更改可以在 源代码管理 侧面板中查看。您可以选择性地提供提交消息，然后选择 同步更改 来发布您的代码。折叠时，文件更改的数量会显示在源代码管理图标上。

为代码工作区创建分支

您可以使用分支管理器为代码工作区创建分支、检出分支以及执行其他版本控制操作。

要创建或查找分支，请使用屏幕顶部的分支选择器。选择分支选择器会打开一个菜单，显示现有分支的列表。或者，也可以通过选择 创建新分支来创建新分支。如果您有未发布的代码更改，系统将提示您在检出所选分支之前先进行同步。

以与 在 Foundry 其他位置的分支操作相同的方式，代码工作区中可用的数据来自您当前所在的分支（带有 回退机制）。如果您将数据写入输出数据集，数据将写入您当前的分支。

您可以通过选择 提议更改来将您的分支合并到 master。提议更改后，将显示拉取请求（PR）预览。

共享您的代码工作区

您可以通过选择 共享 （位于界面右上角）来共享您的代码工作区。

如果代码工作区和代码仓库是独立的资源，您还必须共享底层仓库的权限，其他人才能看到您工作区中的代码。

具有……的用户 Editor or Owner 项目上的角色将能够修改代码工作区的设置。具有 Viewer 项目上的角色将能够启动该工作区。

重启代码工作区

您可以通过选择手动重启代码工作区（例如，以获取配置更改） Active > Restart workspace （位于界面右上角）来共享您的代码工作区。

这将生成一个处于初始状态的新会话。工作区将自动重启，并包含已提交到支撑代码仓库的所有更改。但是，工作区不会包含重启之前状态中的所有内容，包括导入的数据、存储在内存中的变量、已安装的软件包等。

在重启工作区之前，应用程序将自动创建一个检查点，并提示您同步最新的更改。

您可以在Carbon工作区中选择 Active > Restore checkpoint 以将工作区恢复到先前检查点的状态。请参阅 检查点 部分以了解更多信息。Code Workspaces 不会在工作区重启后自动将工作区恢复到先前的检查点。

代码工作区生命周期

首次打开 Code Workspaces 的用户将收到一个空白工作区，其中支撑仓库已克隆到 /home/user/repo.

当没有用户活动时，Code Workspaces 会话将自动关闭，并且最多可持续 24 小时（有关自动关闭的更多信息，请参阅 高级设置 文档）。

会话关闭时，所有相关状态都会持久保存在 Foundry 的 检查点 中，并在同一用户下次打开该代码工作区时恢复。这使用户能够从关闭时的状态继续工作。

在代码工作区中保存工作

Code Workspaces 有两种不同的保存现有工作的方式：手动代码同步和自动检查点。

我们建议依赖同步到底层代码仓库的代码（将所需的软件包安装作为代码的一部分），而不是依赖工作区检查点。代码同步有助于确保工作流程的弹性，并便于与其他可能无法访问特定检查点的用户协作。

代码同步

代码同步 是一种手动操作，也是在代码工作区中保存现有工作的推荐方式。同步代码意味着将您的文件提交到工作区的支撑代码仓库。通过代码同步保存的任何工作都会永久保存在仓库中，并且 /home/user/repo 文件夹中的所有内容都会作为该同步的一部分存储。代码同步不会保存现有状态，例如变量内容、环境中已安装的软件包、数据或代码单元格输出。可以通过工作区的支撑代码仓库查看工作区的同步历史记录。我们通常建议频繁同步您的代码，既可以维护更改历史记录，又可以确保所有相关的工作都得到正确且永久的存储。

要保存工作区中的所有现有更改，请选择 同步更改 （位于工作区右上角）。成功后，更改将提交到工作区的支撑仓库，您可以通过选择右上角的齿轮图标然后选择 打开代码仓库.

检查点

检查点 是一项自动对工作区现有状态进行快照的功能，以便在不同会话之间恢复状态。检查点有两种类型：数据检查点和代码检查点。

数据检查点

与仅存储已提交文件的代码同步不同，数据检查点会存储 /home/user/repo （包括未提交的代码更改）、 /home/user/libs （包括已安装的软件包）、 /home/user/envs （Conda 环境）以及 /home/user/data （用户下载的额外数据）的全部内容。对于 RStudio®，存储在内存中的变量会存储在 /home/user/repo/.RData.

受限输出模式 会禁用数据检查点。代码检查点在受限输出模式下仍可继续运行。

默认情况下，Code Workspaces 每十分钟为给定用户的会话保存一次数据检查点。数据检查点不会在不同用户之间共享。Code Workspaces 还会在工作区关闭之前创建数据检查点（例如通过 手动重启、手动关闭或自动关闭）。处于非活动状态的代码工作区不会生成任何新的数据检查点，且任何数据检查点最多保留 30 天。因此，如果工作区超过 30 天未被使用，由于没有可用的有效数据检查点，将只能从已同步到支撑仓库的内容或从 代码检查点中恢复工作。数据检查点旨在作为一种安全保障机制，用于在不同会话之间持久化工作区状态；不应将其作为主要的保存方式。我们强烈建议您经常同步工作区中的现有工作。

恢复数据检查点将重启工作区，并将主文件夹恢复到创建检查点时的状态。

代码检查点

代码检查点存储 唯一 工作区代码（而非数据），方法是保存 /home/user/repo （包括未提交的代码更改）的内容，同时排除超过一定大小或扩展名通常与数据相关联的文件。此过滤是尽力而为的。代码检查点仅在工作区关闭之前创建。与数据检查点不同，代码检查点没有保留期限。

代码检查点不受会阻止您将常见数据文件提交到工作区支撑仓库的过滤限制。您必须确保代码文件不包含数据。例如， .py 代码文件绝不应包含 Foundry 数据集中存在的表格数据。

管理数据文件

Code Workspaces 会自动扫描您的 /home/user/repo/ 文件夹，以查找大小较大或具有常见数据文件扩展名（例如 .csv, .gz, .parquet, .pdf，或 .xlsx）的文件。将这些文件移动到 data-checkpoint or data-tmp 目录可以优化工作区启动时间并提高安全性，在您或其他用户无意中将这些文件提交到工作区支撑仓库时起到保护作用。

  1. data-checkpoint: 用于存储您希望在不同会话之间保存和恢复的数据文件的推荐位置。这些文件将保存到检查点中，并在后台恢复，而不会阻塞工作区启动。此外，该文件夹将被排除在同步之外，以防止将大型、未受保护的数据提交到支撑代码仓库。
  2. data-tmp: 用于存储您不希望在不同会话之间保存的临时文件的推荐位置。这些文件不会保存到检查点或支撑代码仓库中；而是在工作区关闭时被丢弃。

如果您希望数据可供已发布的仪表板或转换使用，或供其他用户使用，我们建议您 将数据持久化到 Foundry 数据集 中，而不是将其保存在工作区中。

当工作区检测到数据文件时，您将看到一条警告，提示您将它们移动到 data-checkpoint or data-tmp 目录。选择您要移动的文件，并按照对话框提示进行移动。请记得使用新的路径前缀更新您的代码，否则当您在 /home/user/repo/ 文件夹。
