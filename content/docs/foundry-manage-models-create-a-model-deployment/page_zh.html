创建直接模型部署

直接模型部署是实时托管的端点，可将模型立即连接到用户应用程序，例如 来运行该专业代码代理。你还可以通过 和 将收集到的信息存储在。直接模型部署可通过 TypeScript 查询，方式为通过 模型上的函数 或通过 REST API 调用从外部系统查询。

以下各节介绍如何创建、配置和发布直接模型部署，并介绍在开始之前需要审查的一些调试步骤和功能注意事项。

要在全局分支上更改和测试直接模型部署配置，请参阅 直接模型部署的分支管理.

1. 创建直接模型部署

要创建并启动直接模型部署，请导航至 模型 并选择 实时部署。在 概述 标签页中，选择 开始部署。部署运行后，展开 查询实时部署，提供输入，然后选择 运行 进行测试。

2. 配置直接模型部署

要配置直接模型部署，请选择 配置 （来自 实时部署。您可以配置缩放、资源、环境变量和源。直接模型部署可配置为从零开始缩放。当部署达到 75% 容量时，它会创建额外的副本，直到达到缩放配置中指定的最大副本数。在没有实时请求 30 分钟后，部署也可以自动缩减。选择 更新 批量为实体添加标签

3. 为部署发布函数

您可以为该部署发布一个 函数 用于该模型，从而支持在 来运行该专业代码代理。你还可以通过, 和及其他最终用户应用中使用模型进行实时推理。

要发布函数，请选择 实时部署，然后选择 创建函数 菜单中选择 函数 已应用标签 概述 选项卡并提供函数名称。每个分支可以注册一个函数。这将创建一个与您的模型具有相同输入和输出 API 的包装函数，该函数可以 从函数仓库中导入并调用 以添加自定义业务逻辑。

有关函数行为、版本升级和配置选项的详细信息，请参阅 模型函数开发者指南.

要在全局分支上发布和测试模型函数，请参阅 直接模型部署函数.

要将模型与其直接部署和已发布的函数一起分发， 请将它们打包为 Marketplace 产品。Marketplace 支持在模型的默认分支上进行部署，并允许安装者选择是否自动启动部署。

自动升级

可以为每个 模型的分支创建一个直接模型部署。当新模型版本发布到该分支时，直接模型部署将自动升级到新端点，且不会停机。如果您不希望自动升级，请考虑使用 Modeling Objective 实时部署 并查看 下文所述的实时部署与直接部署之间的差异。如果为部署创建了函数，则会自动创建新版本。

对于仍是 Marketplace 安装产物的模型，在默认分支上发布新的模型版本会更新部署，但不会自动发布函数版本。 Marketplace 在安装和产品升级期间管理函数发布.

自动水平缩放

直接模型部署由 计算模块 支撑，因此在用户指定的最小和最大副本范围之间支持自动水平缩放，如 上文详述。Modeling Objective 实时部署也支持配置最小和最大副本范围，以便根据请求量自动缩放，如 资源配置部分.

配置计划覆盖

您可以为一周中特定日期和时间的最小和最大副本配置安排覆盖。当您预期会出现可预测的变化时（例如营业时间内流量较高或周末负载减少），此功能非常有用。

要配置计划覆盖：

  1. 导航到您的直接模型部署，选择 实时部署，然后选择 配置.
  2. 在监听器设置向导的 扩展性 部分，开启 启用计划覆盖 以显示计划覆盖设置。



  3. 为您的覆盖配置以下设置：
    • 覆盖最小副本数： 计划期间的最小副本数。
    • 覆盖最大副本数： 计划期间的最大副本数。
    • 生效日期： 应用覆盖的星期几。
    • 时间范围： 覆盖的开始和结束时间以及时区。
  4. 选择 更新 批量为实体添加标签

默认副本配置适用于配置的时间段之外。目前，您只能安排一个覆盖。

模型 API 类型安全

直接模型部署对所有推理请求强制执行类型安全，以确保模型 API 类型与输入类型匹配。所有输入类型都遵循类型安全，尤其是以下类型：

  • 数值： 如果模型的 API 被定义为类型 int，并且向模型传递值 3.6，则 0.6 将被截断，输入将为 3。
  • 日期和时间戳： 直接模型部署会在提供给 predict() 方法之前对日期和时间戳类型进行转换。时间戳字段现在需要采用 ISO 8601 格式的字符串。
  • 强制的 API 结构： 直接模型部署将明确要求模型 API 中标记为必填的字段。

模型类型安全与 Modeling Objective 实时部署不同，后者目前不支持类型转换。

调试直接模型部署

使用日志、指标和查询分析来调试您的直接模型部署。

查看日志和运行历史

在 日志 “代码” 实时部署，您可以流式传输、筛选和下载部署的日志。您还可以查看先前推理请求的运行历史。

查看指标

在 指标 选项卡中，您可以查看所选时间范围内的扩缩容、作业、容器和副本指标。

调试查询

要分析推理请求，请展开 查询实时部署，打开旁边的下拉菜单 运行，然后选择 Run with Flamegraph。火焰图显示了每个 Python 函数的耗时，可帮助识别性能瓶颈。

容器模型和返回错误的请求不支持火焰图。

监控直接模型部署

您可以使用 监控视图监控直接模型部署。直接模型部署在 实时部署 资源类型下进行监控，该资源类型支持 单个 范围。

Seven 实时部署规则 可用，涵盖心跳、副本预置、作业队列深度、CPU 使用率、内存不足重启和副本响应能力。

在 Workflow Lineage 中探索模型的使用情况

要了解模型的使用位置，请选择 在 Workflow Lineage 中打开 （从模型中），或使用 Cmd+I （macOS）或 Ctrl+I （Windows）。模型会显示在 工作流血缘 中，作为已训练模型节点，您可以在其中检查函数依赖关系、查看模型 API、查询实时部署，以及访问部署健康状况、日志和指标。
