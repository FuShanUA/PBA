Use ontology interfaces in Workshop

Date published: 2026-10-06

Support for ontology interfaces in Workshop is now generally available and enabled by default across enrollments. This enables you to build Workshop applications against interface properties and links shared by multiple object types without configuring the same workflow separately for every implementing object type.

Workflows enabled by interface support

In Workshop, you can now:

  • Create object set variables from interfaces.
  • Cast an object set variable as an interface or as its implementing object types.
  • Filter object sets using interface properties and traverse interface links.
  • Configure interface properties in most core widgets, such as the Object Table, Object List, Filter List, and Metric Card widgets.

An object table widget configured with an interface object set composed of two object types implementing a manufacturing asset interface.

For example, you can define an Alert interface implemented by Maintenance Alert, Inspection Alert, and Safety Alert object types. Then, you can create one interface-based object set variable, filter it by shared properties, such as Event Date or Status, and display the results with a single widget configuration. When another object type implements the interface, that object type is included in the same interface-based workflow without the need to change the object set variable or reconfigure the module. Previously, you needed to create a unioned object set with more complex conditional application logic to achieve a similar result.

An interface-based object set composed of two object types filtered to include acknowledged asset alerts.

Unsupported widgets

Currently, not all widgets support ontology interfaces. When you pass an interface-based object set to an unsupported widget, Workshop displays an Interfaces not yet supported notification. The widget treats the input as an object type–based object set with property selection options derived from the implementing object types rather than the interface.

A widget configuration displays an Interfaces not yet supported notification and explains how the widget treats the object set.

Learn more about how to use ontology interfaces in Workshop.

What's next

Ontology interface support will be broadened to include other major widgets, including the Map, Pivot Table, and Gantt Chart widgets. AIP Analyst adds organization defaults, group skills, model categories, and compact view

Date published: 2026-10-01

AIP Analyst now gives teams more ways to configure shared defaults and workflow guidance. New model categories simplify model selection, while compact view keeps conversations focused on your questions and the agent’s responses.

Configure organization defaults

Administrators can now set default search scopes and a default model category through the AIP Analyst extension in Control Panel. Users starting a new analysis directly in AIP Analyst inherit defaults from their primary organization for settings they have not configured. They can override these defaults in Settings.

Organizations can also require watermarks on PDF exports.

Users receive their primary organization's settings by default, user defaults can be updated in the settings dialog.

Share workflow guidance through group skills

Administrators can now assign AIP skills to user groups from Control Panel. Assigned skills automatically appear in members’ Skills settings, making shared guidance available without each user having to add it individually.

Use group skills to share instructions for common workflows, recommended object types and relationships, or guidance for interpreting results. Administrators choose which skills are enabled by default, and users can toggle inherited skills on or off. AIP Analyst loads an enabled skill’s full instructions when relevant to a question.

Configure skills for a group in the Control Panel app.

Choose between Fast, Balanced, and Smart

AIP Analyst now offers three model categories: Fast, Balanced, and Smart. The models behind these categories are updated as newer, more capable models become available.

Choose your preferred default category in Settings > Models, or switch categories from the chat. You can also configure a specific model for each category. Custom overrides do not receive automatic model updates, so you may miss newer models until you restore the category’s default.

Workshop builders can also configure the models used for each category and choose the default category for their widget.

Select a Fast, Balanced, or Smart model depending on the task.

Keep conversations focused with compact view

Enable Compact view in Settings > General to collapse tool activity under concise status labels that update as AIP Analyst works. Your questions and the agent’s text responses remain visible. Expand the activity summaries whenever you want to inspect tool results.

You can also enable Hide thinking details to hide the model’s thinking content. Workshop builders can configure both options through Compact tool views and Hide thinking details.

Compact mode minimizes tool views, keeping focus on the summaries.

Faster pipelines in Pipeline Builder now support Iceberg tables

Date published: 2026-10-01

We're excited to announce support for reading and writing Foundry Iceberg tables directly in Pipeline Builder's Faster pipelines. You can use Iceberg tables as inputs, perform custom logic and transforms, and output Iceberg tables. This new capability provides greater flexibility and performance when building data transformation pipelines.

A Faster pipeline with Iceberg inputs and an Iceberg output

What's new

Use Iceberg alongside existing Foundry datasets in Faster Pipelines. You can read datasets and write Iceberg outputs, or use Iceberg tables as inputs to downstream transformations.

Key Features

  • Encrypted Iceberg table support: Read and write both encrypted and unencrypted Iceberg tables in both Spark and Faster pipelines.
  • Overwrite or append to Iceberg outputs: Rebuild the table’s contents in a snapshot run, or append new results from an incremental run. Note that reading from incremental Iceberg inputs in Faster pipelines is not yet supported.
  • Data quality expectation support: Apply data quality expectations to Iceberg outputs with checks that can fail the build before publishing invalid results, ensuring data integrity.

Iceberg support in Pipeline Builder can help improve performance and provide additional flexibility when optimizing existing workflows or building new ones.
