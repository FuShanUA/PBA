Iceberg 表现已正式发布

发布日期：2026-09-15

托管 Iceberg 表和 Palantir 的 Iceberg REST 目录现已在部署于 AWS、Azure 和 GCP 的标准 Foundry 企业环境中正式发布。Palantir 的 Iceberg 目录支持存储在 Palantir 托管存储或客户提供的存储桶中的 Iceberg 表。这为您带来了开放式 Apache Iceberg 格式 ↗ 的优势，同时还享有 Palantir 的管道构建、治理、安全性和本体论功能。

为什么要使用 Iceberg 表？

Iceberg 表可提供：

  • 可扩展的性能： Iceberg 提供多项性能优势，尤其适用于大型表或包含许多小文件的表。通过表布局和压缩，可以对这些表进行优化，从而实现更快的读取。
  • 行级增量更新和处理： Iceberg 支持逐行增量插入、更新和删除操作，无需重新处理整个表。您可以使用 Iceberg 变更日志构建变更数据捕获管道，以处理插入、更新和删除的记录。
  • 开放、可互操作的表格式和目录： Iceberg 提供开放的表格式和目录，并受到不断壮大的计算引擎和数据平台生态系统的支持。这使您能够在 Foundry 内部和外部使用开源引擎以及双向零拷贝工作流。

了解有关 Iceberg 表的更多信息，以及它们与 Foundry 数据集的对比。

在整个 Palantir 平台上使用 Iceberg 进行构建

您可以在大多数常见的 Palantir 工作流中使用 Iceberg 表：

  • 构建管道 ，可使用 Python 转换或 Pipeline Builder。
  • 使用 Data Connection 从支持的数据源（包括 Custom JDBC、Microsoft SQL Server、Oracle、PostgreSQL 和 Snowflake）直接同步到 Iceberg 表中。
  • 创建本体论对象类型 ，由 Iceberg 表支撑。
  • 在 Contour 和 SQL 中分析 Iceberg 表。
  • 在 Data Lineage 中探索数据血缘和来源。

Iceberg 为 Palantir 平台解锁了新的工作流：

  • 配置维护流程，例如压缩和快照过期。
  • 构建管道，支持 行级更新和删除 以及 变更日志处理。
  • 查看快照历史，包括文件大小、架构、操作和行数变更。
  • 将外部工具和客户端 以原生方式连接到目录，从而读取和写入 Iceberg 表。
  • 新的文件系统存储控制功能，支持自带存储桶，并可在不同项目和空间中使用不同的文件系统。

Palantir 的 Iceberg 目录提供哪些功能？

除了开源 Iceberg 规范之外，Palantir 的 Iceberg 目录还提供了额外的功能与保障，包括：

  • 全有或全无的事务语义，确保包含多次写入的 Foundry 作业以原子方式成功或失败，从而使表保持一致且健康的状态。
  • 架构分支隔离，其中每个分支都可以独立跟踪自己的当前 schema、默认分区规范和默认排序顺序。这确保了 schema 变更被隔离在开发分支内，不会影响主分支上的使用者，从而改进了开发人员的工作流程。
  • 集成的访问控制与凭证发放。使用 Foundry 身份验证连接兼容的 Iceberg 客户端。Foundry 会检查表权限和适用的 标记，包括从管道输入继承的标记，然后才会授予读取权限。Foundry 会处理底层存储凭证，无需您将存储桶凭证分发给各个用户或工具，从而简化了访问流程。
  • 与 Foundry 的构建和血缘系统以及更广泛的 Foundry 生态系统深度集成。

开始使用

请让您的注册管理员或信息安全官配置 Iceberg，方法是选择 控制面板中的默认存储设置。然后开始 构建管道。如需了解当前的兼容性详情以及与 Foundry 数据集的差异，请查阅 Iceberg 表和 Foundry 数据集。

发布日期：2026-09-15

Foundry DevOps 产品商店中的“产品组”选项卡。

DevOps 依赖关系图，显示产品组中的产品。

以前，团队可能会在 安装过程中才发现这些问题，从而不得不重复开发、打包和部署步骤。该功能的早期用户已将验证和安装复杂产品组合所需的时间从数周缩短至数小时。

使用产品组的主要优势

使用产品组，您可以：

  • 对产品组合进行建模和可视化： 将来自多个商店的产品与现有安装一同组织，并使用依赖关系图了解它们如何协同工作。
  • 尽早识别安装阻碍因素： 在部署前发现缺失的输入、重复的输出、循环依赖、不兼容的关联产品版本以及其他兼容性问题。
  • 验证产品版本： 跟踪每个产品的最新发布版本、选定的发布渠道或固定版本。根据同一命名空间中已安装的依赖项验证本地构建的产品。
  • 定义部署边界： 识别哪些产品作为工作流的一部分进行安装和管理，以及哪些外部依赖项需要单独管理。
  • 保留已知配置： 创建包含确切成员版本和验证结果的不可变快照。使用快照来比较不同时期的工作流配置，并确定哪些版本可以成功一同安装。

推出 AIP Evolve：协调 AI FDE 代理以改进 Foundry 中的 AI 系统

发布日期：2026-09-08

AIP Evolve 现已正式发布，适用于已启用 AIP 且可访问 AI FDE 的租户。AIP Evolve 可协调 AI FDE 代理集群，以改进 AIP 中的 AI 系统。定义目标、优化目标、验证策略和运行约束，然后在合并更改之前审查生成的提案和代理活动。

早期用户已使用 AIP Evolve 自主降低 AI 成本、提升评估表现，并将工作负载迁移到开源模型。 了解更多关于 AIP Evolve 的信息。

核心功能

AIP Evolve 通过以下功能支持迭代式改进工作流：

  • 针对模型迁移、成本降低、延迟降低、评估分数提升和自定义目标的引导式设置。
  • 使用选定的测试用例或现有评估套件进行灵活验证。
  • 可配置的评分标准和可接受的输出偏差。
  • 代理约束，用于控制允许的更改类型和最大迭代次数。
  • 一个提案视图，其中包含提议的变更、验证结果、输出对比、支持性证据和置信度评估。
  • 一个交互式智能体图，用于监控进度并检查智能体的目标、洞察和产出物。
  • 与 Global Branching 集成，用于在合并前审查提议的变更。
  • 在 AI FDE 中通过补充指令恢复演化的能力。

要求

要使用 AIP Evolve：

  • 启用 AIP 并确保您可以访问 AI FDE。
  • 在某个本体论中安装 AIP Evolve Marketplace 产品。

基础级

  • 对 Foundry 核心平台组件的了解，包括数据管理、安全治理、应用开发、系统集成和工作流优化。
  • 对何时以及如何运用不同的 Foundry 工具和功能解决实际业务问题的理解，是本考试的必备知识。

助理级包含我们更新后的助理级 数据工程师 和 应用开发人员 考试，以及我们全新的 AI 工程师 考试。这些助理级认证要求学习者展示面向特定角色的基础知识。所有助理级考试均为限时选择题，有效期为两年。

隆重推出 Vulcan——一款面向本体论的 CAD 审阅应用程序

发布日期：2026-09-08

Vulcan 是一款 3D 可视化应用程序，可直接从本体论数据渲染工程几何图形。网格模型（GLB、 GLTF、 STL、 OBJ、 PLY以及 3MF）、2D 工程图纸（DXF），以及点云（LAS 和 LAZ）无需转换即可加载，并且单个场景可以包含工作流程所需的全部模型。Vulcan 测试版将于 9 月 7 日当周起面向所有租户推出。

保存后，在 Vulcan 中创建的标注、测量和剖切平面将作为对象写入本体论。标记出的缺陷可用于触发警报，关键尺寸可在仪表板中随时间进行跟踪，保存的横截面可供检索，也可与其他团队共享。Vulcan 可作为独立应用程序运行，也可作为小组件嵌入 Workshop 中，其中相机位置、零件选择和测量结果可与 Workshop 变量双向连接。

零件树列出了装配体中的每个零件实例；每个实例对应本体论中的一个对象。模型来源： Printables。根据 Creative Commons 公共领域许可发布。

Vulcan 拥有由本体论支撑的工具，可支持跨团队工作流：

  • 在模型上测量距离
  • 创建注释
  • 使用剖切平面切割模型
  • 使用本体论操作为零件着色

Vulcan 中 CAD 模型上的注释和测量结果。模型来源： Printables。根据 Creative Commons 公共领域许可发布。

了解 Vulcan 如何为您的生产工作流提供支持：

  • 为模型添加标记，以提供装配或维修流程的说明
  • 在设计评审团队之间共享注释和测量结果
  • 根据库存水平或故障率为模型着色
  • 在 Palantir 平台中可视化自动化设计验证运行的结果
  • 使用导入到 Vulcan 中的组件和模型，在整个 Foundry 应用套件中进行进一步分析

可视化变基让 Workshop 更改更易于解决

发布日期：2026-09-03

当多个构建者在不同分支上更新同一个 Workshop 模块时，变基会在该分支被合并之前将来自 main 的更改并入该分支。Workshop 现在提供可视化变基功能，帮助协调 main 与您的分支之间对小部件、区域和变量的细粒度更改。

以前，您必须在 变更日志面板 中检查模块的 JSON 定义，才能确定发生了哪些更改。可视化变基将这一工作流引入模块编辑器，您可以在其中接受、拒绝或合并更改，同时查看这些更改对模块的影响。

变基对话框允许构建者启动可视化变基或拒绝来自 main 的所有更改。

结合上下文了解更改

在变基过程中，小部件和区域配置面板中受影响的设置旁边会显示更改图标。这些图标可区分新增、修改、删除、移动和冲突，因此您无需离开正在查看的配置即可找到更改。选择图标即可打开 main 与您的分支的并排详细视图。

  • 冲突： 同一组件的同一属性在 main 和该分支上均进行了编辑。
  • 新增： 添加了属性或组件。
  • 修改： 编辑了属性或组件。
  • 删除： 删除了属性或组件。
  • 移动： 区域或小部件被移动到了不同的父级。
  • 分支： 属性或组件已使用分支版本解决。

更改图标图例用于标识两个版本之间的差异。

审阅更改对话框会将 main 上的指标卡配置与您分支上的配置进行比较。

变量冲突使用相同的工作流程。选择存在冲突的变量以打开其编辑器，并比较每个分支的完整定义和设置。

如何预览、接受和合并更改

默认情况下，Workshop 会自动接受来自 main 的非冲突更改，并将其合并到您的分支中。仅当相同的配置字段、变量定义或布局位置在两个分支上均被更改时，您才需要采取操作。

选择 主分支 或 您的分支 以临时预览某项配置并查看其对模块的影响。您可以按原样接受任一版本，也可以将其中一个版本用作进一步编辑的起点。这些编辑会创建一个 当前会话 状态，该状态可以合并来自两个分支的更改。

要将来自 main 的整个模块配置替换为分支配置，请选择 拒绝来自 main 的所有更改 （在开始变基时）。这会使分支配置在您合并分支时覆盖来自 main 的更改。仅当您想要丢弃所有传入的更改时，才使用此选项。
