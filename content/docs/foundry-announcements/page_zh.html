使用远程预览在 SuperRepo 应用中预览实时本体论数据

发布日期：2026-11-10

您现在可以使用 REMOTE_ONLY 模式，在 SuperRepo 预览 中本地运行您的 OSDK React 应用 和函数，直接访问本体论中的实时对象和关联。访问为只读模式，并使用您自己的权限。

此前，预览使用的是 种子数据，这要求您手动创建和维护逼真的合成数据，或者从本体论中复制您永远不会部署到生产环境的对象。而使用 远程预览，您可以直接基于实时数据进行开发，无需维护支撑种子对象的文件。

开始在 SuperRepo 中使用远程预览

要开始使用远程预览，请将 使开发者能够在开发过程中测试其跨越整个应用程序的变更，而无需在各个阶段之间等待。这提高了开发者循环的迭代速度，使问题或中断能够立即浮现。 更新到版本 0.351.0 或更高版本，使用 foundry update self。接下来，将以下配置添加到 foundry.yml，并将下方的示例 RID 替换为您本体论的 RID：

远程预览的工作原理

当处于 REMOTE_ONLY 模式时，SuperRepo 预览会从您的本体论中读取实时对象，而不使用嵌入式本体论。相反，SuperRepo 会将所有对象、关联、搜索、聚合和对象集请求路由到 ontologyRid: 块中指定的本体论，该块位于 foundry.yml.

配置 foundry.yml 文件中，以便针对本体论中的实时对象和关联运行预览。

SuperRepo 使用标准的 Foundry 项目权限和基于角色的权限发起请求，因此远程预览仅返回您有权访问的对象。此外，远程预览会将您 ONTOLOGY 组件中定义或导入的每个对象类型与目标本体论中具有相同 API 名称的类型进行比对。如果架构不一致，远程预览将报告 Foundry schema mismatch 错误，并且在两者匹配之前不提供任何数据。

Pipeline Builder 默认使用更快的管道，现已支持 LLM

发布日期：2026-11-03

更快的管道现已成为 Pipeline Builder 中的默认选项，并新增对 Use LLM 节点的支持。您现在可以在更快的管道中使用 Palantir 提供的模型或您自己注册的模型来构建大语言模型 (LLM) 工作流。

默认使用更快的管道

当您从 Pipeline Builder 落地页或通过 AI FDE 创建管道时， 更快速 现在是默认选择。更快的管道由以下技术驱动 DataFusion ↗驱动的后端，这是一个用 Rust ↗。与标准 Spark 管道相比，更快的管道可以减少执行时间和计算资源使用。

从 Pipeline Builder 落地页创建管道时，默认会选择更快的管道。

更快的管道中的 Use LLM 支持

更快的管道现在支持 Use LLM 节点和 Text to Embeddings 节点，既可使用 Palantir 提供的模型，也可使用您自己注册的模型。将 LLM 引入您的管道，为关键工作流提供支持。
