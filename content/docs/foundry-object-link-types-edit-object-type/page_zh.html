编辑对象类型

对象类型的编辑可能会破坏用户应用程序

编辑对象类型及其属性可能会产生 破坏应用程序的后果，从而中断用户工作流。请阅读下面关于 潜在破坏性变更 然后 的内容，然后再进行任何对象类型或属性编辑。

潜在破坏性变更

回写 是将用户对本体论对象的编辑持久化到持久 Foundry 数据集的过程。该数据集称为回写数据集。在 对象存储 v1（Phonograph）中，您必须为对象类型或具有联接表的多对多关联类型配置回写数据集。这是对象类型或关联类型接收用户编辑之前所必需的。了解有关回写数据集与 物化数据集 在 Object Storage v2 中的比较的更多信息。

无回写的对象类型

需要 Object Storage v1 (Phonograph) 注销并重新注册对象类型的支撑数据源的变更，将使该类型的对象在重建索引期间在用户应用程序中 不可用 ；这些变更如下所述。

保存时，以下变更将注销并重新注册（或删除）对象类型的支撑数据源：

  • 更改对象类型的支撑数据源。
  • 更改对象类型的主键。
  • 删除对象类型。

当您尝试保存任何此类变更时，系统将警告您对用户应用程序的潜在影响。

例如，如果某个对象类型用于 Workshop 应用程序，则该 Workshop 应用程序将在重建索引完成之前处于中断状态。您可以在对象类型的 Phonograph 面板中跟踪其重建索引的进度 数据源 页面预览同步的数据。

了解有关 Object Storage v1 (Phonograph) 的更多信息。

具有回写的对象类型

如果对象类型启用了回写，则在编辑该对象类型时应格外小心。对对象类型所做编辑的历史记录存储在 Object Storage v1 (Phonograph) 中。每次构建回写数据集时，都会重新应用编辑历史记录，以获得回写数据集中已编辑对象的最终状态。当对象类型的支撑数据源从 Object Storage v1 (Phonograph) 中注销时，Object Storage v1 (Phonograph) 中的编辑历史记录将被删除，并且回写数据集的后续构建将失败。

除了上一节中列出的需要注销的变更之外 上一节，当对具有回写的对象类型的 任意 属性进行模式变更时，如果该属性曾 接收过编辑 ，即使它当前未接收编辑，也需要注销。模式变更包括对属性 ID 和基础类型的变更。

以下变更 不需要 注销，因此不会冒丢失编辑历史记录的风险：

  • 更改已接收编辑的属性的显示名称、标题键、渲染提示、类型类和可见性将 不 要求注销对象类型。
  • 删除从未接收过编辑的字段或对其字段进行模式变更将 不 要求注销对象类型，因此不会擦除或撤销其他正在接收编辑的字段上的编辑。
在您撤销或手动重新注册数据源之前，重建索引将失败

Object Storage v1 (Phonograph) 将 不 自动注销对象类型的支撑数据源以响应其中一项模式变更。相反，重建索引将失败，只有在撤销已保存的模式变更，或者您在对象类型的 Phonograph 面板中手动注销并重新注册对象类型的支撑数据源时，重建索引才会成功 数据源 页面预览同步的数据。

属性编辑器中的属性面板会突出显示某个字段是否曾接收过编辑。

此外，当您尝试保存任何可能抹除编辑历史的更改时，系统会警告您这些更改对编辑内容的潜在影响。

现在您已经了解了编辑现有对象类型和属性时需要考虑的事项，可以安全地进行更改了。

导航到现有对象类型

您随时可以通过从主页侧边栏选择对象类型页面，并从列表中选择不同的对象类型，来更改您正在处理的对象类型。您也可以随时在应用程序顶部的搜索栏中搜索新的对象类型。 阅读更多关于导航的信息。

删除对象类型

您可以通过选择以下按钮来删除对象类型 （三个点）图标，该图标位于对象类型视图侧边栏的右上角（见下图），然后选择 删除 选项（来自下拉菜单）。系统将弹出一个对话框，确认您是否要将该对象类型及其所有关联的关联类型暂存以进行删除。

  • 对象类型的删除仅在您保存更改后才会生效，并且会中断任何引用该对象类型的视图或应用程序。
  • 具有以下状态的对象类型 active 状态的对象类型无法删除。 阅读更多关于状态的信息。

添加或移除支撑数据源

按照以下说明为以下对象添加支撑数据源 未创建支撑数据源的对象类型:

  1. 通过选择以下选项导航到属性编辑器 编辑属性映射 面板顶部或分析器模式横幅中选择 属性 对象类型的页面。
  2. 选择 添加支撑数据源 菜单中选择 数据源 窗格，然后选择一个可用的数据源。
  3. 将数据源列映射到现有的对象类型属性。
  4. 查看对象类型的 安全配置，然后保存您的更改。

要移除支撑数据源，请导航到相同的属性编辑器，并从以下位置移除该数据源 数据源 窗格。配置所需的 对象安全策略，然后保存您的更改。

只有当对象类型保存在项目中时，才能移除支撑数据源。这可确保对象类型使用 基于项目的权限模型 ，而不是从支撑数据源继承权限。之前映射到已移除数据源列的每个属性都将成为 仅编辑属性，因此其值将通过 操作 填充，而不是来自数据源列。

更改支撑数据源

您可以通过以下步骤更改支撑数据源：

  1. 通过选择以下选项导航到属性编辑器 编辑属性映射 面板顶部或分析器模式横幅中选择 属性 对象类型的页面。
  2. 选择 替换 按钮，位于 数据源 窗格的顶部。这将允许您浏览并选择 Foundry 中可用的数据源。
只有在架构匹配时，属性才会自动重新映射

更改对象类型的支撑数据源将移除旧数据源中的列与对象类型属性之间的任何连接。属性将自动为您重新映射 仅当 您切换到具有 相同架构 的新数据源（与旧数据源相同）时才会自动重新映射。否则，您需要将对象类型的属性重新映射到新数据源。

编辑对象类型的元数据

  2. 显示名称和描述： 选择现有的显示名称或描述以编辑文本。
  3. 状态： 选择现有状态以打开可用状态的下拉菜单。从中选择 deprecated, experimental日 active statuses.
    • 阅读更多关于 状态.

  5. API 名称： 点选现有的 API 名称即可更改其值。
    • 对于具有以下状态的对象类型，您无法更改其 API 名称 active status.
      • 阅读更多关于 状态.
      • 阅读更多关于 有效的 API 名称.

故障排除

错误： Phonograph2:FoundryColumnNameNotFound

如果您收到错误 Phonograph2:FoundryColumnNameNotFound，某个列已从支撑您尝试保存的对象类型的数据源中移除，导致某个属性未被映射。该属性需要被映射或删除。

错误： Phonograph2:InvalidColumnRemoval

如果您收到错误 Phonograph2:InvalidColumnRemoval，某个已被移除的列曾支撑一个已接收编辑的属性。需要将该列重新添加到数据源中，或者注销并重新注册该对象类型。

请参阅上文中关于 潜在破坏性变更 以了解更多信息。

错误： Phonograph2:InvalidColumnFieldSchemaChange

如果您收到错误 Phonograph2:InvalidColumnFieldSchemaChange，某个已接收编辑的属性的 ID 或键已被更改。需要撤销该更改，或者注销并重新注册该对象类型。

请参阅上文中关于 潜在破坏性变更 以了解更多信息。

错误： OntologyMetadata:IncompatibleFoundryFieldSchemaForPropertyType

如果您收到错误 OntologyMetadata:IncompatibleFoundryFieldSchemaForPropertyType，您尝试保存的属性的基本类型与支撑它的列类型不兼容。例如，列 X 的类型可能已被更改为“string”，但映射到基本类型为“integer”的属性 X。

错误： Phonograph2:SchemaMismatch

如果您收到错误 Phonograph2:SchemaMismatch，您可能对支撑该对象的架构进行了有意的更改，但尚未在 Ontology Manager 中更新该对象的属性类型。通过编辑属性的数据类型以接受新类型来修改本体论。发布更改并重建数据集，然后启动该对象的重新索引。

错误： FieldTypeIncompatibleWithOntologyPropertyType

如果您收到错误 FieldTypeIncompatibleWithOntologyPropertyType 或收到消息“Failed to Update Object Type in Phonograph”，则支撑您的对象的数据集中的数据类型与本体论期望的数据类型之间存在不匹配。您必须确保任何架构更新都反映在数据集和本体论中。

如果您确实对本体论或数据集进行了任何有意的更改，请与该对象及其支撑数据源的所有者沟通，以了解最近的更改。
