编辑对象类型

警告

编辑对象类型及其属性可能会 对应用程序造成破坏性后果，进而扰乱用户工作流。请阅读下文中关于 潜在破坏性变更 的章节，然后再 进行任何对象类型或属性编辑。

潜在破坏性变更

写回 是指将用户对本体论对象的编辑持久化到持久Foundry数据集的过程。该数据集称为写回数据集。在 Object Storage v1 (Phonograph)中，必须为对象类型或带联接表的多对多关联类型配置写回数据集。这是对象类型或关联类型接收用户编辑的前提条件。详细了解写回数据集与 物化数据集 在Object Storage v2中有何不同。

无写回的对象类型

需要Object Storage v1 (Phonograph)取消注册并重新注册对象类型的支撑数据源的更改，会使该类型的对象在重新索引期间在用户应用程序中 不可用 ；下文将介绍这些更改。

保存时，以下更改将取消注册并重新注册（或删除）对象类型的支撑数据源：

  • 更改对象类型的支撑数据源。
  • 更改对象类型的主键。
  • 删除对象类型。

当您尝试保存这些更改中的任何一项时，系统会警告您这些更改可能对用户应用程序造成的影响。

例如，如果某个对象类型在 Workshop 应用程序中使用，则该 Workshop 应用程序在重新索引完成之前将无法正常使用。您可以在 Phonograph 面板中跟踪对象类型的重新索引进度，该面板位于相应对象类型的 Datasources 页面。

了解有关 Object Storage v1 (Phonograph) 的更多信息。

具有回写功能的对象类型

如果某个对象类型启用了回写功能，则在编辑该对象类型时应格外谨慎。对对象类型所做的编辑历史记录存储在 Object Storage v1 (Phonograph) 中。每次构建回写数据集时，都会重新应用编辑历史记录，以获取回写数据集中被编辑对象的最终状态。当对象类型的支撑数据源从 Object Storage v1 (Phonograph) 中取消注册后，Object Storage v1 (Phonograph) 中的编辑历史记录将被删除，并且后续的回写数据集构建将会失败。

除了 上一节中列出的需要取消注册的更改之外，当对具有回写功能的对象类型的 任何 对象类型中 曾经 接收过编辑的属性，即使该属性当前未接收编辑。架构变更包括对属性的 ID 和基础类型的更改。

以下更改 无需 取消注册，因此不会有丢失编辑历史的风险：

  • 更改已接收过编辑的属性的显示名称、标题键、渲染提示、类型类别和可见性将 不会 要求该对象类型取消注册。
  • 删除从未接收过编辑的字段，或对这些字段进行架构更改将 不会 要求该对象类型取消注册，因此不会擦除或撤销对其他正在接收编辑的字段所做的编辑。
警告

Object Storage v1 (Phonograph) 将 不会 因这些架构变更之一而自动取消注册对象类型的支撑数据源。相反，重新索引将会失败，只有在撤销了已保存的架构变更，或者您在 Phonograph 面板（位于对象类型的 数据源 页面）中手动取消注册并重新注册了该对象类型的支撑数据源之后，才能成功。

属性编辑器中的“属性”面板会突出显示某个字段是否曾经接收过编辑。

此外，当您尝试保存任何有可能清除编辑历史的更改时，系统将就其对编辑的潜在影响向您发出警告。

现在您已经了解了编辑现有对象类型和属性时的注意事项，可以放心地进行更改了。

编辑现有对象类型

  • 导航到现有对象类型
  • 删除对象类型
  • 添加或移除支撑数据源
  • 更改支撑数据源
  • 编辑对象类型的元数据

导航到现有对象类型

您随时可以通过以下方式更改正在处理的对象类型：从主页侧边栏中选择对象类型页面，然后从列表中选择其他对象类型。此外，您也可以随时在应用程序顶栏的搜索栏中搜索新的对象类型。 了解更多关于导航的信息。

删除对象类型

您可以通过以下方式删除对象类型：选择 位于对象类型视图侧边栏右上角的（三个点）图标（参见下图），然后从下拉菜单中选择 删除 选项。将弹出一个对话框，确认您是否要将该对象类型及其所有关联类型暂存以待删除。

  • 请注意，删除对象类型的操作仅在保存更改后才会生效，并且会导致引用该对象类型的任何视图或应用程序无法正常工作。
  • 处于 active 状态的对象类型无法删除。 阅读更多有关状态的信息。

添加或移除支撑数据源

按照以下说明，将支撑数据源添加到 创建时未指定数据源的对象类型：

  1. 通过选择 编辑属性映射 （位于对象类型的 属性 页面顶部），即可导航到属性编辑器。
  2. 选择 添加支撑数据源 （位于 数据源 窗格中），然后选择一个可用的数据源。
  3. 将数据源列映射到对象类型的现有属性。
  4. 查看对象类型的 安全配置，然后保存更改。

若要移除支撑数据源，请导航到同一属性编辑器，并从 数据源 窗格中移除该数据源。配置所需的 对象安全策略，然后保存更改。

只有当对象类型保存在项目中时，才能移除支撑数据源。这可确保对象类型使用 基于项目的权限模型 ，而不是从支撑数据源继承权限。每个之前映射到已移除数据源中某一列的属性都会变为 仅编辑属性，因此其值通过 操作 进行填充，而不是从数据源列中填充。

更改支撑数据源

您可以通过以下步骤更改支撑数据源：

  1. 通过选择 编辑属性映射 （位于对象类型的 属性 页面顶部），即可导航至属性编辑器。
  2. 选择 替换 按钮（位于 数据源 窗格顶部）。这将允许您浏览并选择 Foundry 中可用的数据源。
警告

更改对象类型的支撑数据源将移除旧数据源中的列与对象类型属性之间的所有关联。系统会自动为您重新映射属性， 但前提是 您切换到与旧数据源 架构相同 的新数据源。否则，您需要将对象类型的属性重新映射到新数据源。

编辑对象类型的元数据

  1. 图标： 选择默认图标以自定义对象类型的图标和颜色；当用户查看此类型的对象时，这些图标和颜色将显示在用户应用程序中。
  2. 显示名称和描述： 选择现有的显示名称或描述即可编辑文本。
  3. 状态： 选择现有状态以打开包含可用状态的下拉列表。请从 deprecated、 experimental，以及 active 状态。
    • 详细了解 状态。
  4. 可见性： 选择现有的可见性，以打开可用可见性选项的下拉列表。可见性为 prominent 的对象类型将使应用程序优先向用户显示该对象类型。可见性为 hidden 的对象类型将不会出现在用户应用程序中。
  5. API 名称： 点击现有的 API 名称即可更改其值。
    • 请注意，对于状态为 active 的对象类型，无法更改其 API 名称。
      • 详细了解 状态。
      • 详细了解 有效的 API 名称。

在初始对象类型创建过程完成后，将无法再编辑对象类型的对象 ID。

故障排除

错误： Phonograph2:FoundryColumnNameNotFound

如果收到错误 Phonograph2:FoundryColumnNameNotFound，则表示已从支撑您尝试保存的对象类型的数据源中移除了某个列，导致某个属性处于未映射状态。该属性需要进行映射或删除。

错误： Phonograph2:InvalidColumnRemoval

如果收到错误 Phonograph2:InvalidColumnRemoval，则表示已移除了一个支撑某个已编辑属性的列。您需要将该列重新添加到数据源，或者取消注册并重新注册该对象类型。

请参阅上方有关 潜在的破坏性变更 的部分，以了解更多信息。

错误： Phonograph2:InvalidColumnFieldSchemaChange

如果收到错误 Phonograph2:InvalidColumnFieldSchemaChange，已被编辑的属性，其 ID 或键已被更改。您需要还原此更改，或者需要取消注册并重新注册该对象类型。

请参阅上文关于 潜在的重大变更 的章节以了解更多信息。

错误： OntologyMetadata:IncompatibleFoundryFieldSchemaForPropertyType

如果您收到错误 OntologyMetadata:IncompatibleFoundryFieldSchemaForPropertyType，则说明您正在尝试保存一个属性，其基础类型与支撑该属性的列类型不兼容。例如，列 X 的类型可能已被更改为“string”，但它映射到基础类型为“integer”的属性 X。

错误： Phonograph2:SchemaMismatch

如果您收到错误 Phonograph2:SchemaMismatch，则说明您很可能有意更改了支撑该对象的架构，但尚未在 Ontology Manager 中更新该对象的属性类型。请修改本体论，编辑该属性的数据类型以使其接受新类型。发布更改并重建数据集，然后启动该对象的重新索引。

错误： FieldTypeIncompatibleWithOntologyPropertyType

如果您收到错误 FieldTypeIncompatibleWithOntologyPropertyType 或者收到“在 Phonograph 中更新对象类型失败”的消息，则表明支撑您对象的数据集中的数据类型与本体论预期的数据类型之间存在不匹配。您必须确保任何架构更新都同时反映在数据集和本体论中。

如果您确实对本体论或数据集进行了任何有意的更改，请与对象及其支撑数据源的所有者沟通，以了解最近的更改。
