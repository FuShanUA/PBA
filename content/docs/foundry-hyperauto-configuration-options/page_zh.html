HyperAuto V2 配置选项

本页面介绍 HyperAuto V2 的配置选项。有关 HyperAuto V1 的配置参考，请参阅 旧版文档。以下步骤构成了 HyperAuto V2 的配置流程：

  • 名称和位置
  • 源配置
  • 输入配置
  • 管道配置

名称和位置

HyperAuto V2 配置向导的第一步是指定新管道的名称以及 Foundry 文件系统中所需的目标文件夹位置。HyperAuto 管道资源及相关的输出数据集将在该文件夹中创建。

源配置

HyperAuto V2 源配置页面可帮助您选择源系统和数据摄取方式。

源系统

此选项适用于具有子系统的源，用户必须在其中进行选择（例如 SAP 中的 "上下文（context）"）。子系统被定义为源中的一种配置，它会产生自己的一组可用表和元数据。因此，在不同子系统之间切换将完全改变其他可用的配置，例如所支持的 管道模式 （批处理与流式处理），以及可在 输入配置 页面预览同步的数据。

SAP 源系统

有三种主要的 架构模式 可将 Foundry 连接到 SAP 系统：

  • 直连（Direct）： 连接器安装在 ERP 系统自身的应用服务器上，可直接访问表。
  • SLT： 连接器安装在 SAP SLT 复制服务器上，该服务器连接到底层的 ERP 系统。使用流式 管道模式.
  • 远程（Remote）： 连接器安装在连接到底层 ERP 系统的"网关"应用服务器上。通常在 SAP 源不满足连接器 前提条件时使用。 在使用 SLT 或远程连接的情况下，用户必须选择一个上下文，用于标识要连接的 SAP 子系统。

管道模式

HyperAuto 支持两种同步和数据转换模式。您可以在初始 HyperAuto 管道设置的 源配置 页面预览同步的数据。

  • 批处理（Batch）： 管道每次运行都会重新处理所有输入并覆盖所有现有输出。这是默认模式，支持最广泛的功能，包括聚合和去重。大多数用例建议使用此模式。
  • 流式（Streaming）： 持续轮询源系统中尚未处理过的数据。数据一旦在源系统中可用，便会立即被处理，从而将同步到本体论的延迟降低到接近实时。这对于依赖本体论对流式数据进行去重的实时应用尤其有价值。

流式处理需要始终在线的计算来实时处理数据，因此可能会增加源系统和 Foundry 内部的负载。

输入配置

输入配置页面是用户为特定 HyperAuto 管道选择要处理的具体输入的地方。

为便于使用，输入选择界面支持多种浏览和发现相关源表的方法。对于 SAP，这些方法包括：

  • 模块（Modules）： 对源中的表进行的一种有主见的分类，提供分层视图，用户可以从中浏览和批量添加表。相关的表可以存在于多个模块中，但不能被重复选择。
  • 工作流（Workflows）： 另一种表分类形式，侧重于源的特定常见用例（例如 SAP 源的供应链管理）。同样，用户可以根据需要使用工作流进行浏览和批量添加，并且可以在工作流和模块之间切换，而不会丢失进度或意外重复选择。

同步创建也可以在输入配置页面上进行，允许用户为尚未配置同步的任何输入创建新的同步。这使用户只需点击几下即可从全新数据源构建完全配置的 HyperAuto 管道，而无需弄清楚每个同步应如何配置。

测试版

同步创建功能目前处于 测试版 开发阶段，您的租户中可能尚未提供此功能。在积极开发过程中，功能可能会发生变化。请联系 Palantir 支持团队以申请访问同步创建功能。

您的 Foundry 租户可能在 建议 标签页上启用了 AIP 功能；更多信息请参阅 AIP 文档.

管道配置

管道配置页面使您能够设置满足需求的管道，可用选项包括：

  • 语言选择
  • 配置选项
    • 自动关联
    • 人类可读的列名
    • 人类可读的输出数据集名称
    • 生成主键
    • 生成外键
    • 对行进行去重
    • 数据清洗
    • 增量
  • 批处理计算设置

语言选择

对于包含多语言数据表的源，HyperAuto 提供语言过滤步骤，以避免在输出中为每种可能的语言填充多行。此处选择的语言将在应用其他转换（例如与其他表的关联）之前，作为过滤器应用于相关表。

配置选项

您可以通过管道配置选项决定要对用户的所有源输入自动应用多少处理。默认情况下，所有配置选项均已启用，但可以根据需要禁用（例如，在功能和管道性能之间取得平衡）。

自动关联

HyperAuto 通过源的元数据接收表分类，将其拆分为对象表或增强表。在此定义中，增强表是指自身不具有独立价值，而是作为关联对象表的扩展或查找表的表（例如，文本描述表）。

通过这种方式，HyperAuto 能够查询源中的 object <-> enrichment 表关系，并生成从增强表到对象表的相应左关联。这为每个对象生成了一个丰富、全面的非规范化数据集，无需与其他表进行关联即可进行广泛的审查。

这在构建 Foundry 本体论时特别有用，因为标准方法是使用面向语义的非规范化数据模型。

SAP 中的自动关联

对于 SAP，"TEXT" 表被分类为 Enrichment 表，在 HyperAuto 的处理过程中。例如， MAKT （物料描述）可以关联到 MARA （常规物料数据）上。

流式处理

被分类为 Enrichment 的表将作为批处理输入而非流式输入使用。这允许管道从这些表创建指向核心流的"查找"左关联，从而增强流数据，而无需尝试同时关联两个实时流。

仅当 schema 符合 Foundry 流式处理及所使用的基础 Avro 文件格式时，才会为处于流式模式的 Enrichment 表提供现有同步（在配置相关输入时）。

对于 SAP 同步，将 cleanFieldNamesForAvro 配置选项设置为 true 可确保 schema 符合 Avro（流式）要求。HyperAuto 创建的同步默认启用此选项。

人类可读的列名

HyperAuto 可以使用源提供的列元数据，将源定义的列名重命名为自解释且易于被不熟悉源 schema 的用户使用的名称。

这是通过将列的人类可读名称连接到原始列名上来实现的，格式为 Human readable_|_original，在与数据交互时提供对两种形式的访问，以实现最大的可用性。

人类可读的输出数据集名称

启用后，HyperAuto 会根据源表元数据为新建的输出数据集生成描述性名称。这样无需引用原始源表名称，即可更轻松地识别和导航管道输出。对现有管道启用此选项时，已有的输出数据集不会被重命名。

生成主键

如果源没有单列主键，HyperAuto 可以动态生成主键。源的元数据包含说明表中哪些列共同构成主键的信息，HyperAuto 会利用这些信息构建拼接逻辑来创建一个 primary_key 列。

这些值会使用 _|_ 分隔符进行拼接。

要将输出用作本体论对象的支撑数据集，主键必须是单列的。

生成外键

HyperAuto 还可以访问源数据模型元数据中定义的对象间关系。利用这些元数据，可以在管道中创建逻辑，为每个关系生成一个外键列（通过拼接相关列，类似于 主键逻辑），该外键列可用于进行连接或构建本体论关联。

外键的命名形式为 column1_column2_|_foreign_key_tableA，具体如下：

  • 列值通过将 column1 and column2 与分隔符 _|_日
  • 存在一个外键关系，用户可以通过此列将此表与 tableA 通过其 primary_key.

外键用于在对象之间生成本体论关系。

当 自动连接 配置选项启用时，不会为对象与富化表之间的关系创建外键。

对行进行去重

HyperAuto 提供自动对包含重复行的表进行去重的逻辑。这在变更数据捕获（CDC）等每次发生变更时都会追加新行的系统中非常有用。HyperAuto 会进行去重，为每个主键选择最新的最新行。

流式处理

在流式模式下，去重的处理方式有所不同。系统会创建两个流式输出。主输出在被批处理或增量管道读取时将解析为去重后的数据集。变更日志输出在被批处理或增量管道读取时（如有需要）将提供未去重的数据集。两个输出都可以像平常一样被另一个流使用。

如果构成表主键的列不属于以下类型之一，它们将被转换为字符串以确保去重能够正常工作：

  • 字符串
  • 时间戳
  • 布尔
  • 二进制
  • 整数
  • 字节
  • 短整型
  • Float（浮点）
  • 长整数
  • 双精度浮点数

数据清洗

数据清洗配置选项可从所有表中移除常见的数据质量问题。有关所解决问题的类型的更多信息，请参见下文。

  • 空字符串处理： "" 字符串会被转换为 null （Foundry 中数据的标准做法）。
  • DECIMAL 转换： DECIMAL 数据类型会被转换为 DOUBLE，这在整个平台中都有好处（包括支持本体论属性）。

增量

实验性

HyperAuto 管道的增量处理目前处于 实验性 开发阶段，可能无法在您的租户中使用。功能在积极开发过程中可能会发生变化。

对于批处理 SAP 管道，您可以启用增量处理。启用后，管道仅处理自上次构建以来追加到输入数据集中的新数据，而不是在每次运行时重新处理所有输入。这可以减少具有大型、频繁更新的输入数据集的管道的计算资源使用量和构建时间。

增量处理仅适用于具有直接 SAP 连接的批处理管道。有关增量计算的更多信息，请参阅 批处理输入数据集的计算模式.

批处理计算设置

测试版

HyperAuto 管道的批处理计算设置目前处于 测试版 开发阶段。在积极开发期间,功能可能会发生变化。

对于批处理管道，您可以在 批处理计算设置 已应用标签 管道配置 页面中选择计算后端。此设置决定用于处理管道的计算方法。

可用的计算后端选项如下：

  • 标准： 默认后端由 Spark ↗驱动。此选项支持 Pipeline Builder 中可用的全部表达式和转换。
  • Faster: 一种替代后端，由 DataFusion ↗驱动，这是一个用 Rust 编写的开源查询引擎。Faster 管道经过专门设计，可优化构建时间并高效执行低延迟操作。特别是，运行时间在 15 分钟以内的管道将从 faster 管道配置中获益最多。

您可以在创建新的 HyperAuto 管道时选择 faster 后端，也可以通过编辑管道配置来切换现有管道的后端。
