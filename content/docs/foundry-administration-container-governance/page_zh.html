容器治理

开放容器倡议（Open Container Initiative）容器（通常称为 Docker 容器）是一种流行的与语言无关的软件应用打包方式，允许开发人员将来自多个工具链的依赖项组合到一个内聚的包中。Docker 容器在打包复杂应用、利用遗留技术或集成 Foundry 原生支持语言（Python、Java 和 R）中不可用的库方面尤为强大。

容器工作流会给您的组织带来额外的安全风险。由于容器镜像是在 Foundry 之外编写的，可能会引入并累积软件漏洞，因此管理员负责实施软件供应链控制，并定期审计在 Foundry 中运行的容器。

为了降低这些风险，Foundry 的计算基础设施实施了业界领先的控制和严格的 镜像要求 ，以限制用户可以运行的容器工作负载类型。特别是，容器镜像必须以非 root 数字用户 ID 运行，并且不得拥有内核权限。

Foundry 还提供管理工具来跟踪哪些容器正在生产环境中运行，并定期扫描活动容器以识别软件漏洞。 容器治理 页面中访问这些指标，该页面位于 控制面板 使管理员能够审计其 Foundry 安装中容器工作流的状态，并在必要时召回存在漏洞的容器。

通过 Foundry 计算基础设施运行的容器遵循与在 Apollo 平台中运行的容器类似的 元数据可见性 规则。

启用容器工作流

直方图 设置 Ontology Manager 容器治理 页面中访问这些指标，该页面位于 控制面板 允许资源管理员启用或禁用容器工作流。默认情况下，所有容器工作流均处于禁用状态。所有容器工作流都需要 Rubix ↗ 引擎作为支撑基础设施；如果未使用 Rubix，此开关将被禁用。

漏洞扫描

Foundry 会定期扫描所有正在使用的用户上传 Docker 容器以查找漏洞。影响您注册的漏洞概览可在 漏洞 Ontology Manager 容器治理 页面中访问这些指标，该页面位于 控制面板中查看。默认情况下，Foundry 不会根据发现的容器漏洞采取任何行动。

召回漏洞

直方图 漏洞 Ontology Manager 容器治理 页面中访问这些指标，该页面位于 控制面板 允许资源管理员召回或取消召回单个漏洞。任何使用受已召回漏洞影响的容器的 Foundry 作业都将被强制停止。同样，漏洞也可以被取消召回。
