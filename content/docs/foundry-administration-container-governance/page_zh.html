容器治理

Open Container Initiative 容器（通常称为 Docker 容器）是一种流行的、与语言无关的软件应用程序打包方式，允许开发人员将来自多个工具链的依赖项组合成一个统一的软件包。Docker 容器在打包复杂应用程序、利用遗留技术或集成 Foundry 原生支持语言（Python、Java 和 R）中不可用的库方面尤其强大。

容器工作流会给您的组织带来额外的安全风险。由于容器镜像是在 Foundry 之外构建的，可能会引入并累积软件漏洞，因此管理员有责任实施软件供应链控制措施，并定期审计在 Foundry 中运行的容器。

为了缓解这些风险，Foundry 的计算基础设施实施了业界领先的控制措施和严格的 镜像要求 ，以限制用户可运行的容器工作负载类型。具体而言，容器镜像必须以非 root 数字用户 ID 运行，并且不得拥有内核特权。

Foundry 还提供管理工具，用于跟踪哪些容器正在生产环境中运行，并定期扫描活动容器以识别软件漏洞。 容器治理 页面位于 Control Panel 中，使管理员能够审计其 Foundry 安装中容器工作流的状态，并在必要时召回存在漏洞的容器。

通过 Foundry 计算基础设施运行的容器所遵循的 元数据可见性 规则与在 Apollo 平台中运行的容器类似。

启用容器工作流

设置 选项卡（位于 容器治理 页面，该页面位于 控制面板 中）允许资源管理员启用或禁用容器工作流。默认情况下，所有容器工作流均处于禁用状态。所有容器工作流都需要 Rubix ↗ 引擎作为支撑基础设施；如果未使用 Rubix，此开关将被禁用。

漏洞扫描

Foundry 会定期对用户上传且正在使用的所有 Docker 容器进行漏洞扫描。影响您注册账户的漏洞概览可在 漏洞 选项卡中查看，该选项卡位于 容器治理 页面，而该页面位于 控制面板中。默认情况下，Foundry 不会根据发现的容器漏洞采取任何措施。

召回漏洞

漏洞 选项卡（位于 容器治理 页面，该页面位于 控制面板 中）允许资源管理员召回或取消召回单个漏洞。任何使用了受已召回漏洞影响的容器的 Foundry 作业都将被强制停止。同样，漏洞也可以被取消召回。
