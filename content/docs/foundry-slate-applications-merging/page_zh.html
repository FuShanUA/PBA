合并应用更改

当多个协作者共同开发一个 Slate 应用时，他们可能需要将各自的更改合并在一起以维护版本控制。当两个或更多用户同时开始编辑同一版本的应用，然后都尝试保存更改时，就需要进行版本控制。由于第二次保存尝试所基于的版本已被第一次保存更新为过期版本，因此如果不丢失某个用户的更改，应用就无法正常保存。要解决这种情况，第二个用户必须从以下选项中进行选择：

  • 放弃其更改。
  • 覆盖第一个用户的更改。
  • 以其他名称保存应用。
  • 将其更改与第一个用户的更改合并。

以下部分介绍合并流程。

合并冲突

当同一元素被多个用户修改或删除时，就会产生合并冲突。例如，如果一个 widget 被一个用户删除而被另一个用户修改，就会产生冲突。另一个冲突示例是两个用户修改了同一个查询。

当原本可以合并的 widget ID 发生冲突时也会产生冲突，迫使用户在两个版本之间做出选择。如果应用开发者未遵循使用语义化 widget 名称的最佳实践，而是依赖默认 widget 名称，则这种冲突更容易发生。

无冲突

如果保存时未检测到冲突，Slate 会自动合并应用 JSON 并显示合并后应用的预览。如果您对更改满意，请选择 接受并保存。如果需要更正，请选择 进行更改 以查看和编辑 JSON。

带冲突的合并

当保存时检测到合并冲突，系统会向您呈现更改的 JSON 视图。在合并视图中，三个独立的面板分别显示另一个用户所做的更改、合并结果以及您所做的更改。当识别到合并冲突时，Slate 不会尝试合并元素内部的更改，并且默认会包含另一个用户的更改。

对于每个冲突：

  1. 通过选择带有以下标记的元素来导航到冲突： Conflict tag.
  2. 修改生成的 JSON，使其包含您希望从自己的更改和另一个用户的更改中保留的内容。
  3. 当您对合并结果满意时，请选择 标记为已解决.

当所有冲突都已解决且您对 JSON 更改满意时，请选择 预览最终结果。随后系统会向您呈现合并后应用的可视化预览，并为您提供保存应用的选项。
