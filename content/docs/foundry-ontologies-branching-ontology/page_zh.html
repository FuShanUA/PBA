本体论分支

本体论与 Global Branching 集成，支持以安全且隔离的方式开发本体论资源。本文档介绍如何在分支上使用本体论，包括添加和修改资源、变基与冲突解决、评审与合并流程，以及已知限制。

有关 Global Branching 概念和工作流程的一般信息，请参阅 Global Branching 文档。

定义

有关分支、提案和变基的一般定义，请参阅 Global Branching 核心概念。以下术语专用于本体论分支：

  • 本体论提案： 当您 创建 Global Branching 提案 ，且该分支包含本体论更改时，系统会自动创建一个本体论提案来跟踪特定于本体论的更改。该本体论提案包含元数据，例如评审、名称以及正被合并到 main。

添加和修改资源

要在分支上修改本体论，您可以在 Ontology Manager 中创建一个新分支，也可以使用分支选择器访问现有分支。

要创建分支，请打开分支选择器并选择 创建新分支 ，以打开一个对话框，您可以在其中为分支添加标题和描述。

如果您已经对本体论进行了更改，并希望将这些更改包含在某个分支中，可以在保存对话框中选择 保存到新分支 ，从而创建一个包含这些更改的单独分支。请注意，如果您对任何 受保护的本体论资源进行更改，系统将要求您保存到新分支。

您只能从主本体论创建分支，该主本体论也称为 main 分支。

在分支上时，位于界面底部的 分支任务栏 将显示您当前的分支名称和其他元数据。

资源保护

分支保护支持的本体论资源类型包括：

  • 对象类型
  • 操作类型
  • 关联类型
  • 接口类型
  • 共享属性类型

以下资源不支持资源保护：

  • 类型组
  • 规则集（修改规则集时，将强制执行其所属对象类型的保护状态）

此外，本体论资源必须先迁移为使用项目权限，然后才能受到保护。有关更多信息，请查阅 本体论权限。

将本体论资源迁移为使用项目权限后，您可以通过父项目的 文件 选项卡查看并管理其保护状态。

启用保护后，您必须在单独的分支上进行更改，并创建提案以将这些更改合并到主分支。

保护状态也显示在 Ontology Manager 的 概览 选项卡中：

修改受保护的资源时， 保存 对话框将替换为 创建并保存到分支，要求您将更改保存到新分支。

变基与冲突解决

在您向自己的分支引入更改的同时， main 也可能收到来自其他人的新更改。变基会将 main 的最新更改合并到您当前的分支中，以使您当前的分支保持最新。

自动变基

如果您的全局分支不包含对本体论的更改，变基会自动进行。一旦您向您的分支引入了本体论更改（包括为对象类型建立索引），您将需要手动变基，以使您的分支与 main保持最新。

对分支进行变基

当 main有新的更改时，侧边栏中的 主分支更新 选项卡上会出现蓝色指示标记，提示您查看这些更改。

导航至 主分支更新 页面，以查看自您上次变基以来传入的更改——如果这是您首次手动变基，则查看自分支创建以来的更改。选择 变基分支 ，以将您的分支更新到最新版本的 main。

如果没有冲突或错误，变基将自动完成，您的分支将处于最新状态。

解决合并冲突

如果存在冲突，您的变基将保持进行中状态，您将被重定向到 “冲突”选项卡 ，以解决您的分支与 main之间任何冲突的更改。如果仅存在错误，您则会被重定向到 “错误”选项卡 。

在变基期间，来自 main 的更改会被加载到您的分支上，而您当前分支中先前保存的更改则会被重新加载回工作状态，您可以在 “所有更改” 选项卡中查看此状态。

此状态允许您查看和访问来自 main 以及您分支的更改。当本体论资源同时包含来自两个分支的更改时，它将默认显示您分支中的版本。

要解决冲突，您可以针对每个资源选择 使用主分支的更改 或 保留当前分支的更改 。或者，您也可以直接导航到该资源并应用 自定义更改 来解决其冲突。

在此示例中， Palantir employee 对象类型存在冲突，其显示名称在 main 分支和您的分支上均已被更改。要解决此冲突，请选择要保留该对象类型的哪个版本。

您也可以通过进行自定义更改来解决此冲突。在此示例中，您可以导航到该对象类型，并将其显示名称从 "Palantir employee" 更改为 "Current employee"。该冲突将因这项自定义更改而得到解决。

解决所有冲突后，请确保在完成 rebase 之前已处理所有错误。

完成 rebase

解决所有错误和冲突后，您可以选择 完成 rebase 并保存，您的分支将处于最新状态。

您可以继续在您的分支上工作并定期执行 rebase，以使您的分支与 main 分支的最新版本保持同步。

合并要求

准备您的分支以供审查

当您准备好在完成更改后将您的分支合并到 main 时，请通过选择分支任务栏中的 创建提案 图标来创建提案。请添加名称和描述以设置您的提案。

创建提案后， 合并检查 将运行以验证全局分支上的资源是否能够合并到 main 分支。失败的检查可能包括您的分支与 main 分支之间的冲突，这将要求您对您的分支进行变基。

请求审查

您可以通过分支任务栏、Global Branching 提案页面或本体论提案页面向您的提案添加审查者。

在本体论提案页面上，前往 审查变更 并选择 邀请审查者 以向您的提案添加审查者。对于已迁移到项目的本体论资源，选择 查看策略 以查看根据关联的项目策略，需要哪些审查者来审查某个资源。

每个本体论资源被视为一个单独的任务。资源名称旁边的状态标签表示整体审批状态，而右侧的 您的审查 版块允许您提交审查。

虽然在 Global Branching 中本体论实体被视为单独的资源，但它们被归组在单一的本体论提案下。这意味着向一个本体论资源添加审查者实际上等于向所有本体论资源添加了该审查者。

发表评论

您还可以对提案中的各项任务发表评论，以便为提议的更改提供背景信息。选择最右侧的评论侧边栏，即可访问任务的评论部分。

审查提案

在 审查更改 标签页中，审查人员可以批准或拒绝单个任务。没有权限的用户仍可审查任务，例如表达对更改的意见，但这不会影响任务的已批准状态。

批准权限

具有批准权限的用户即使未被添加为审查人员，也可以批准提案。审查人员列表用于跟踪应由谁来审查更改，而非用于限制批准。

在本体论提案中，审查人员可以查看提案详情，并批准或拒绝针对所有已修改资源或特定本体论资源的更改。

一旦满足策略要求，已批准的资源将从 In Progress 变为 Approved。如果所有其他检查均已通过，您随后即可合并提案。

合并您的分支

当您准备好将更改合并到 main时，您必须合并您的 Global Branching 提案。这将自动启动本体论的合并流程。

为此，请在分支任务栏中选择合并图标，或在 Global Branching 中导航至您的提案页面并选择 合并提案。

已知限制

  • 数据源删除： 当冲突发生在某个对象类型上，且该对象类型的支撑数据源已在 main 分支上被替换或删除时，选择保留您的分支更改将导致合并失败。在这种情况下，请选择 main 分支更改。
  • 条件格式删除： 当冲突发生在某个属性类型上，且该属性类型的条件格式规则集已在 main 分支上被替换或删除时，选择保留您的分支更改将导致合并失败。在这种情况下，请选择 main 分支更改。
  • Pipeline Builder 对象类型： 在 Pipeline Builder 中创建的对象类型在分支上无法通过 Ontology Manager 进行修改。
  • 索引算作一种修改： 为对象类型建立索引会被视为一项修改。如果资源受项目策略保护，您需要获得策略批准才能合并您的分支。若要绕过此要求，请在合并前移除索引更改。
  • 审阅者适用于所有本体论资源： 为一个本体论资源添加审阅者会将他们添加到整个提案中，因为本体论更改是组合在一起的。只有资源项目策略中的用户才需要批准该特定资源。
