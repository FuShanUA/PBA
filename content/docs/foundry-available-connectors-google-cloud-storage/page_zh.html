Google Cloud Storage

将 Foundry 连接到 Google Cloud Storage，以在 Foundry 数据集与存储桶之间同步文件。

受支持的功能

功能状态
探索🟢 正式可用
批量导入🟢 正式可用
增量🟢 正式可用
虚拟表🟢 正式可用
导出任务🟡 停用（Sunset）
文件导出🟢 正式可用
Lakehouse Iceberg REST 目录🟢 正式可用
Iceberg 表的自带存储桶（bring-your-own-bucket）存储🟢 正式可用

数据模型

该连接器可以将任何类型的文件传输到 Foundry 数据集中。文件格式会被保留，并且在传输期间或之后不会应用任何 schema。请对输出数据集应用任何必要的 schema，或者 编写下游转换 来访问数据。

性能与限制

可传输的文件大小没有限制。但是，网络问题可能导致大规模传输失败。特别是，运行时间超过两天的直接云同步将被中断。为避免网络问题，我们建议使用较小的文件大小，并限制每次同步执行中摄取的文件数量。同步可以 被安排 频繁运行。

设置

  1. 打开 数据连接 应用程序，然后选择 源 （位于屏幕右上角）。
  2. 选择 Google Cloud Storage （从可用的连接器类型中选择）。
  3. 请按照额外的配置提示，使用以下各节中的信息继续完成连接器的设置。

了解更多关于 设置连接器 （在 Foundry 中）的更多信息。

您必须拥有一个 Google Cloud IAM 服务账号 ↗ 才能继续进行 Google Cloud Storage 的身份验证和设置。

身份验证

在所访问的存储桶上需要以下角色：

  • Storage Object Viewer：读取数据。
  • Storage Object Creator：将数据导出到 Google Cloud Storage。
  • Storage Object Admin：在将文件从 Google Cloud Storage 导入 Foundry 后删除文件时需要，并且在使用 UPDATE 事务并覆盖文件的增量数据集导出时也需要。

在以下内容中了解有关所需角色的更多信息 Google Cloud 访问控制文档 ↗.

从以下可用的身份验证方法中选择一种：

  • GCP 实例： 请参阅 Google Cloud 文档 ↗ 了解如何设置基于实例的身份验证。

    • GCP 实例身份验证仅适用于通过在 GCP 中经过适当配置的实例上运行的代理进行操作的连接器。

  • JSON 凭据： 请参阅 Google Cloud 文档 ↗ 了解如何创建和下载 JSON 服务账号密钥文件。

  • PKCS8 身份验证： 需要输入 JSON 服务账号密钥文件中的特定凭据信息。请参阅 Google Cloud 文档 ↗ 了解创建密钥文件的相关信息。

  • Workload Identity Federation (OIDC)： 按照显示的源系统配置说明来设置 OIDC。请参阅 Google Cloud 文档 ↗ 了解 Workload Identity Federation 的详细信息，以及 我们的文档 以了解 OIDC 如何与 Foundry 配合使用的详细信息。

网络

Google Cloud Storage 连接器需要通过 443 端口访问以下域名：

  • storage.googleapis.com
  • biglake.googleapis.com （仅在使用 Lakehouse Iceberg REST 目录)
  • www.googleapis.com （仅在使用 Lakehouse Iceberg REST 目录)
  • oauth2.googleapis.com （仅在使用 JSON 凭据或 PKCS8 身份验证时需要）
  • sts.googleapis.com （仅在使用 Workload Identity Federation 时需要）
  • iamcredentials.googleapis.com （仅在使用 Workload Identity Federation 时需要）

Delta

要为基于虚拟表的管道启用增量支持，请确保在源 Delta 表上启用了 Change Data Feed ↗ 。支持 current 和 added 读取模式（在 创建更复杂的管道。 中）。 _change_type, _commit_version 和 _commit_timestamp 列将在 Python 转换中可用。

Iceberg

需要 Iceberg 目录才能加载由 Apache Iceberg 表支持的虚拟表。要了解有关 Iceberg 目录的更多信息，请参阅 Apache Iceberg 文档 ↗。在源上注册的所有 Iceberg 表必须使用同一个 Iceberg 目录。

对象存储目录

使用对象存储目录时，在注册表时提供一个 warehousePath 指向 Google Cloud Storage 中 Iceberg 元数据文件。

Lakehouse 目录

Lakehouse Iceberg REST 目录 当表存储在 Google Cloud Storage 中时，可用作 Iceberg 目录。Lakehouse 是表的目录，而 Iceberg 是表格式。从此目录注册表时，请设置 格式 to Iceberg.

当通过 Google Cloud Storage 连接器配置 Lakehouse 目录时：

  • Google Cloud Storage 存储桶名称将用作 Lakehouse 目录 ID。
  • 表名必须使用 namespace.table_id pattern.
  • 目录 ID 在源上配置，在注册单个虚拟表时无法更改。
  • 在源上配置的 Google Cloud 凭据必须有权访问 Lakehouse 目录以及存储 Iceberg 表数据和元数据的底层 Google Cloud Storage 存储桶。

要配置 Lakehouse 目录：

您不能将同一个 Google Cloud Storage 源同时用于 Lakehouse 目录和 自带存储桶（BYOB）Iceberg 存储。请为每个工作流创建单独的源。配置 Lakehouse 源时使用 目录 设置为 Lakehouse 目录，并配置 BYOB 源时不使用 目录 设置，对分支的合并保留实质性的控制权。

  1. 在 Data Connection 中打开 Google Cloud Storage 源。
  2. 打开源配置。
  3. 打开 其他设置 并添加 目录.
  4. 对于目录类型，请选择 Lakehouse 目录.
  5. 保存源。
注册 Lakehouse Iceberg 虚拟表

在保存带有 Lakehouse 目录配置的 Google Cloud Storage 源后，从该源的 虚拟表 标签页。

  1. 在 Data Connection 中打开已配置的 Google Cloud Storage 源。
  2. 选择 虚拟表 tab.
  3. 选择 创建虚拟表.
  4. 在监听器设置向导的 配置 部分中，设置 格式 to Iceberg。这会将该虚拟表标识为属于源上配置的 Lakehouse 目录的 Iceberg 表。
  5. In 表名中，使用 namespace.table_id 模式输入来自 Lakehouse 目录的 Iceberg 表标识符。例如，输入 analytics.orders.
  6. 确认 目录 ID（存储桶） 与源上配置的 Google Cloud Storage 存储桶匹配。此字段为只读。
  7. In 确认虚拟表的位置，输入 Foundry 虚拟表名称。
  8. 选择创建虚拟表的输出文件夹，或使用源的默认输出位置。
  9. 完成向导以创建虚拟表。

Foundry 虚拟表名称控制在 Foundry 中创建的资源的名称。它不会重命名 Lakehouse 中的表。

增量支持依赖于 Iceberg 增量读取 ↗ ，且目前仅支持追加。 current 和 added 读取模式（在 创建更复杂的管道。 受支持。

Parquet

使用 Parquet 的虚拟表依赖于模式推断。最多将使用 100 个文件来确定模式。

Iceberg 表的自带存储桶（bring-your-own-bucket）存储

Google Cloud Storage 可用作 自带存储桶 (BYOB) 存储位置 ，用于 Foundry Iceberg 表。为 BYOB Iceberg 存储配置 GCS 源时，您必须使用 JSON credentials or PKCS8 auth 进行身份验证的数据源。

将数据导出到 Google Cloud Storage

该连接器可以将文件从 Foundry 数据集复制到 Google Cloud Storage 存储桶上的任意位置。

要开始导出数据，您必须配置一个导出任务。导航到包含您要导出到的 Google Cloud Storage 连接器的 Project 文件夹。右键单击连接器名称，然后选择 Create Data Connection Task.

在数据连接视图的左侧面板中：

  1. 验证 Source 名称与您要使用的连接器相匹配。
  2. 添加一个 Input named inputDataset。该 输入数据集 是被导出的 Foundry 数据集。
  3. 添加一个 Output named outputDataset。该 输出数据集 用于运行、调度和监控任务。
  4. 最后，在文本字段中添加一个 YAML 块来定义任务配置。

左侧面板中显示的连接器和输入数据集的标签不会反映 YAML 中定义的名称。

创建导出任务 YAML 时使用以下选项：

选项是否必填？描述
directoryPath是Cloud Storage 中写入文件的目录。
excludePathsNo正则表达式列表；名称与这些表达式匹配的文件将不会被导出。
uploadConfirmationNo当值为 exportedFiles时，输出数据集将包含已导出文件的列表。
retriesPerFileNo如果遇到网络故障，请增加此数字，以允许导出作业在整项作业失败之前重试向 Cloud Storage 的上传。
createTransactionFoldersNo启用后，数据将写入指定 directoryPath内的子文件夹中。每个子文件夹都基于事务在 Foundry 中提交的时间，并且每个导出的事务都有唯一的名称。
threadsNo设置用于并行上传文件的线程数。增加该数字以使用更多资源。请确保在代理上运行的导出任务在代理上有足够的资源来处理增加的并行度。
incrementalTypeNo对于增量构建的数据集，设置为 incremental 以仅导出自上次导出以来发生的事务。
