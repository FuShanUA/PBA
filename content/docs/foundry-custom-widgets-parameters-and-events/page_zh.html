参数与事件

参数与事件是小组件与 Workshop 等宿主应用程序进行交互的主要机制。参数允许宿主应用程序向小组件传递数据，而事件则使小组件能够向宿主应用程序回传信息。

在开发自定义小组件时，您可以定义参数，以允许用户配置小组件行为并与宿主应用程序交互；同时定义事件，以实现双向通信。本页面介绍了可用的参数类型、其格式要求以及如何使用事件。

约束

小组件配置文件最多可包含 50 个参数和 50 个事件。参数和事件 ID 必须采用 camelCase 格式。

参数

参数允许小组件与宿主应用程序共享状态。参数可以定义为基本类型、基本类型数组以及对象集类型。

参数类型

类型描述格式示例
boolean布尔值（true/false）布尔值true 或 false
date日历日期ISO 8601 格式： YYYY-MM-DD"2023-12-31"
number数值数字42 或 3.14159
string文本值字符串"Hello World"
timestamp带时区的日期和时间ISO 8601 格式： YYYY-MM-DDThh:mm:ss.sssZ"2023-12-31T23:59:59.999Z"

对象集参数允许您在自定义小部件与其宿主应用程序之间传递一组对象。对象集可以包含零个或多个对象，其形式可以是固定列表，也可以是应用于对象类型或接口的一组筛选器。对象集参数应在小部件配置文件中使用本体论 SDK（OSDK）中的对象类型或接口进行定义。

场景参数允许您传递 本体论场景 在自定义小部件与其宿主应用程序之间。场景参数的值是场景引用（RID）。您的小部件可以将此 RID 与 OSDK 结合使用，在场景的隔离沙箱中读取对象并执行操作。

场景参数仅适用于 本体论场景。

不可用的参数类型

对象集筛选器和结构体等类型目前不支持作为自定义小部件的一等参数类型。

事件

事件允许微件与宿主应用程序（如 Workshop）进行通信，并触发副作用或更新参数。事件可以在微件配置文件中与参数一起定义。

定义事件

事件在微件配置文件中按以下结构定义：

Copied!
1

{
  events: {
    myEventId: {
      displayName: "Human-readable event name",
      parameterUpdateIds: ["parameter1", "parameter2"],
    },
  },
}

该 parameterUpdateIds 字段指定了触发此事件时可以更新哪些参数。

Workshop 中的参数和事件绑定

在 Workshop 中，微件参数可以绑定到 Workshop 变量，而微件事件可以在微件设置面板中绑定到 Workshop 事件。这样可以实现双向通信：

  1. Workshop 可以通过参数绑定向微件传递数据，微件可以通过发出事件来更新这些参数。
  2. Workshop 事件也可以绑定到微件事件，以便在 Workshop 中触发副作用。

import { useFoundryWidgetContext } from "@osdk/widget.client-react";
import React, { useCallback } from "react";
import type SimpleCounterConfig from "./simpleCounter.config.js";

const useWidgetContext = useFoundryWidgetContext.withTypes<typeof SimpleCounterConfig>();

export const Widget = () => {
  const { parameters, emitEvent } = useWidgetContext();

  const name = parameters.values.name ?? "World";
  const count = parameters.values.count ?? 0;

  const increment = useCallback(() => {
    emitEvent("updateCount", {
      parameterUpdates: { count: count + 1 },
    });
  }, [emitEvent, count]);

  return (
    <div>
      <h1>Hello, {name}!</h1>
      <p>Count: {count}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

import { Flight } from "@custom-widget/sdk";
import type { ObjectSet } from "@osdk/api";
import { useObjectSet } from "@osdk/react/experimental";
import { useFoundryWidgetContext } from "@osdk/widget.client-react";
import React from "react";
import type FlightsConfig from "./flights.config.js";

const useWidgetContext = useFoundryWidgetContext.withTypes<typeof FlightsConfig>();

export const Widget = () => {
  const { parameters } = useWidgetContext();

  const flightsParam = parameters.values.flights;

  if (flightsParam == null) {
    return <div>Select an object set</div>;
  }

  return <FlightsView objectSet={flightsParam.objectSet} />;
};

const FlightsView = ({ objectSet }: { objectSet: ObjectSet<Flight> }) => {
  const { data: flights, isLoading, error } = useObjectSet(objectSet);

  if (isLoading) {
    return <div>Loading flights...</div>;
  }

  if (error) {
    return <div>Error loading flights</div>;
  }

  return (
    <div>
      <p>Flights: {flights?.map(f => ...)}</p>
    </div>
  );
};

为方便使用，对象集参数的值同时包含对象集 RID 和实例化的 OSDK 对象集。当对象集定义发生变化，或宿主应用程序中的数据失效时，参数值中的对象集 RID 和实例化的 OSDK 对象集将会更新。

import { Flight } from "@custom-widget/sdk";
import { useFoundryWidgetContext } from "@osdk/widget.client-react";
import React, { useCallback } from "react";
import { client } from "./client.js";
import type FlightsConfig from "./flights.config.js";

const useWidgetContext = useFoundryWidgetContext.withTypes<typeof FlightsConfig>();

export const Widget = () => {
  const { parameters, emitEvent } = useWidgetContext();

  const filterToLongFlights = useCallback(() => {
    const longFlights = client(Flight).where({
      duration: { $gt: 500 },
    });

    emitEvent("updateFlights", {
      parameterUpdates: { flights: longFlights },
    });
  }, [emitEvent]);

  return (
    <div>
      <button onClick={filterToLongFlights}>Show Long Flights</button>
    </div>
  );
};
行为与限制

SDK 会根据您的 ObjectSet 定义创建一个临时对象集，并将生成的 RID 发送到宿主应用程序。如果同一事件在短时间内连续多次发出，则仅会发送最后一次调用。为防止竞态条件，较早的调用将被丢弃。

对象集创建过程中出现的错误（例如网络故障）不会呈现给调用方。

操作后刷新对象集数据

如果您的小组件使用 OSDK 来应用会修改对象集参数中数据的本体论操作，则可以启用自动数据刷新。请参阅 操作时刷新宿主数据 以了解详情。
