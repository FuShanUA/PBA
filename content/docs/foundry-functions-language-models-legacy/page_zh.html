函数中的旧版语言模型

旧版

此页面介绍 旧版 函数内语言模型。对于 TypeScript v2 和 Python，请参阅 使用代理端点和模型别名的工作流。更新后的 TypeScript v1 语言模型 支持视觉和流式传输等功能。要使用更新后的 TypeScript v1 模型，请参阅 升级说明。

Palantir 提供了一组可在函数中使用的语言模型。 了解有关 Palantir 提供的 LLM 的更多信息。

先决条件

要使用 Palantir 提供的语言模型， 必须先在您的注册中启用 AIP。此外，您还必须拥有相应的权限才能使用 AIP 构建器功能。

导入语言模型

要开始使用语言模型，您必须按照以下步骤将特定模型导入到您编写函数的代码仓库中：

  1. 导航至并打开 "模型导入" 侧边面板，以查看所有已导入的模型。
  1. 要导入新的语言模型，请选择 "添加" （位于 "资源导入" 面板右上角），然后选择 "模型"。这将会打开一个新窗口，您可以在其中查看可供您使用的 Palantir 提供的模型。

  1. 您还会看到一个标签页，您可以在其中查看之前通过 Modeling Objectives 应用或直接模型部署创建的自定义模型。有关使用这些模型的更多信息，请参阅 模型函数 文档。

  2. 选择您想要导入的模型，然后选择 确认选择 将这些模型导入到您的代码仓库。任务运行器将执行 localDev 任务，生成与这些模型交互的代码绑定。

  3. 导入语言模型后，您便可以通过添加以下导入语句在代码仓库中使用它们，并将 GPT_4o 替换为您导入到代码仓库中的语言模型的名称：

编写使用语言模型的函数

在此阶段，我们现在可以编写一个使用已导入语言模型的函数。在本示例中，我们假设已按上述方法导入了 GPT_4o。

我们首先在文件中添加以下导入语句：

Copied!
1
import { GPT_4o } from "@foundry/models-api/language-models"

每个语言模型都会提供具有强类型输入和输出的生成方法。例如,GPT_4o 模型提供了一个 createChatCompletion 方法,允许用户传递一组消息以及其他参数来修改模型的行为,例如温度或最大 token 数量。

在下面的示例中,我们使用提供的 GPT_4o 模型对用户提供的文本执行简单的情感分析。该函数会将文本分类为 "Good"、"Bad" 或 "Uncertain"。

@Function()
public async sentimentAnalysis(userPrompt: string): Promise<string> {
    const systemPrompt = "Provide an estimation of the sentiment the text the user has provided. \
    You may respond with either Good, Bad, or Uncertain. Only choose Good or Bad if you are overwhelmingly \
    sure that the text is either good or bad. If the text is neutral, or you are unable to determine, choose Uncertain."

    const systemMessage = { role: "SYSTEM", contents: [{ text: systemPrompt }] };
    const userMessage = { role: "USER", contents: [{ text: userPrompt }] };
    const gptResponse = await GPT_4o.createChatCompletion({messages: [systemMessage, userMessage], params: { temperature: 0.7 } });
    return gptResponse.choices[0].message.content ?? "Uncertain";
}

然后,该函数即可在整个平台中使用。

public async generateEmbeddingsForText(inputs: string[]): Promise<Double[][]> {
    const response = await TextEmbeddingAda_002.createEmbeddings({ inputs });
    return response.embeddings;
}

这最常用于执行 语义搜索 工作流。

性能注意事项

某些模型可能会应用速率限制,限制特定时间段内可传递的 token 数量。该限制将与适用于函数的所有标准限制一起强制执行。

注意:AIP 功能的可用性可能会发生变化,并且可能因客户而异。
