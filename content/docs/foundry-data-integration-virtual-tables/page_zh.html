虚拟表

虚拟表 允许您查询受支持数据平台中的表，而无需先将数据存储在 Foundry 中 数据集.

虚拟表充当指向 Foundry 之外源系统中表的指针。虚拟表抽象了底层源系统和存储格式，使您能够构建无缝组合来自不同源系统数据的工作流。虚拟表还可以与存储在 Foundry 中的数据集结合使用，作为灵活架构的一部分，数据无需集中在一处。您还可以创建新的虚拟表作为 Foundry 数据转换的输出，从而实现存储完全外置、由 Foundry 处理编排、安全和其他功能的工作流。

虚拟表由以下要素定义：

  • A 连接 到源存储系统（例如，源 URL 或凭证）。此连接通过以下方式建立： 设置源 在 Foundry 的数据连接应用程序中。
  • A 定位器 用于标识源系统中的表（例如，数据库、架构和表名称）。

与 Foundry 中的任何资源一样，虚拟表受 Foundry 的安全和权限模型管理，并可在各种 Foundry 应用程序中打开或使用。

为虚拟表设置连接

支持虚拟表的源在 数据连接 应用程序中进行设置。选择要使用的源，然后导航到 虚拟表 源配置中的选项卡。按照 源文档 以及其中列出的使用虚拟表的任何要求进行操作。

创建虚拟表

所有受支持的源都允许您在 Foundry 中注册来自源系统的单个表。表格类源类型还支持 批量注册 一次注册多个虚拟表。某些源还额外支持 自动注册，它将定期在指定项目中注册源中配置的凭据可访问的所有表。

要注册虚拟表，请选择 创建虚拟表 菜单中选择 虚拟表 源中的选项卡。浏览可用的表并选择要注册的表。除非您选择其他位置，否则虚拟表将在源的默认输出文件夹中创建。

批量注册

在使用诸如 Databricks, BigQuery日 Snowflake等表格源类型时，您可以 批量注册 多个虚拟表。首先，从左侧面板中选择一个或多个外部表。使用右侧面板可以更改新虚拟表的保存位置，或更新其名称。在 Foundry 中更改虚拟表的名称不会更改源中表的名称。

自动注册

启用 自动注册后，系统会创建一个新的 Foundry 项目 ，虚拟表将在其中自动创建。该项目中的文件夹层级将镜像源系统的结构，并随着源中新表的创建而定期更新。当源表被删除时，项目中相关的虚拟表不会被自动删除，但访问它们将不会加载任何数据。

要启用自动注册，您必须拥有 项目创建权限 （在 Foundry 中）的更多信息。

该项目由 Foundry 管理，用户无法在其中手动创建或更新资源。在此项目中注册的虚拟表可以导入到其他项目中，用于工作流开发。

启用自动注册后可以设置项目的权限和访问权限，之后项目所有者可以使用访问侧边栏进行管理。

Databricks 源的标签筛选

为 Databricks 源配置自动注册时，您可以选择指定一个用于筛选的表标签列表。只有在 Databricks TABLE_TAGS ↗ 系统表中至少设置了其中一个标签的表才会被注册。

虚拟表输入的更新检测

更新检测功能会监控虚拟表并检测源系统中表的变化。这使您可以将虚拟表用作依赖资源（如管道或对象）的构建触发器。

更新检测适用于虚拟表输入，即由外部管理并在 Foundry 中注册的表。更新检测对于以下情况不是必需的： 虚拟表输出 （由 Foundry 管道创建），因为 Foundry 会使用管道构建信息自动跟踪这些表的更新。

启用更新检测后，Foundry 会定期轮询源系统以检查表的更新。如果源表格式支持版本控制（例如 Delta 或 Iceberg），Foundry 可以检测到变更，并且仅在必要时触发下游构建。如果不支持版本控制，则每次轮询都会被视为潜在更新，这可能导致不必要的下游构建。

您可以通过以下方式检查您的虚拟表是否支持版本控制： 查看虚拟表详情.

更新检测仅控制 何时 是否触发下游构建。它并不决定生成的构建是快照构建还是 增量构建。支持版本控制的源也可以支持增量（仅追加）构建，即 Foundry 会识别自上次构建以来新增的具体行，并仅处理这些新数据，而不是重新处理整个表。虚拟表的增量支持目前仅限于仅追加变更，并且有额外的源特定前提条件，例如启用 Delta 的 Change Data Feed ↗ 或 Iceberg 的 增量读取 ↗对象，您的计算函数必须接受一个名为 特定源的文档 了解详情。如果源不支持版本控制，则基于该虚拟表构建的下游管道必须使用快照构建，即每次触发运行时都重新处理整个表。

启用更新检测

只有当您的虚拟表输入已被用于创建下游资源（例如下游表、数据集或对象）时，更新检测才可用。

要为虚拟表输入启用更新检测，请按照以下说明操作：

  1. 在以下位置打开虚拟表： 数据集预览.
  2. 转到左侧面板中的更新检测部分。
  3. 在控制面板中启用 更新检测 并设置所需的轮询计划（例如，每小时或每天）。

启用后，您可以将虚拟表输入用作下游表和数据集的 计划触发器 。任何由该虚拟表支撑的对象在检测到源更新时都会自动重新索引。

使用虚拟表与同步到数据集的对比

选择使用虚拟表还是同步到 Foundry 数据集，取决于您的架构目标和要支持的目标工作流。我们建议逐个工作流地考虑合适的集成模式。这两种方法可以结合使用，相互补充。

以下是关于使用虚拟表与将数据同步到数据集的潜在优势、劣势和局限性的一些注意事项。

使用虚拟表的优势

虚拟表具有多项优势，包括：

  • 通过不在 Foundry 中存储源数据来减少重复存储，不过 Foundry 仍会为任何下游创建的资源存储数据，例如作为 Foundry 管道输出的数据集和对象。
  • 查询可以下推到源系统，以限制总数据传输量。计算下推的可用性因源系统和查询类型而异。
  • 对于重复存储成本变得非常可观的超大型表，虚拟表可能尤其有益。
  • 使用虚拟表时，数据在使用时直接查询，无需同步数据或考虑数据过时的可能性。
  • 虚拟表提供了可选性，有助于使 Foundry 实现与目标架构模式保持一致。

使用虚拟表的劣势

虚拟表并非在所有情况下都是最佳选择。一些注意事项包括：

  • 交互式性能可能比处理存储在 Foundry 数据集中的数据要慢。
  • 计算使用量可能会增加，具体取决于在虚拟表上运行的查询类型。例如，用作计划管道输入的表，与在 Contour 分析中频繁以交互方式访问的表相比，可能产生较少的计算量。
  • 虚拟表无法受益于 Foundry 数据集功能，例如数据集版本控制或分支。

使用虚拟表的限制

虚拟表的限制包括：

  • 虚拟表并非适用于所有源。
  • 虚拟表需要 您必须正确配置出站策略（如果使用 源和 直接出站策略.
  • 使用 自助服务专用链接出口策略 的连接通常不受支持。但是， 私有链接 是受支持的。
  • 使用 代理代理策略 不受支持。
  • 使用 存储桶端点出口策略 不受支持。
  • 使用 ）或您的代理网络（如果使用 不受支持。
  • 并非所有 Foundry 应用程序和功能都支持使用虚拟表作为输入。但是，在虚拟表下游创建的任何物化资源（例如管道生成的数据集和对象输出）在 Foundry 生态系统中照常受到完全支持。
  • 使用 use_external_systems 装饰器的转换目前与虚拟表不兼容。请切换到 基于源的 external_transforms ，或将您的转换拆分为多个转换，一个使用虚拟表作为输入，另一个使用 use_external_systems decorator.

虚拟表查询的计算

对于直接在虚拟表上运行的查询，计算可能在 Foundry 和源系统之间进行拆分。具体行为取决于查询以及源系统所支持的下推计算程度。请参阅 特定源的文档 的文档以获取更多信息。
