Code Repositories 中的计算用量

在 Code Repositories 中运行构建需要使用 Foundry 计算，这是一种以计算秒为单位度量的资源。本文档详细说明了构建如何使用计算，并提供了在产品中调查和管理计算用量的相关信息。

运行一个 transforms 构建 （针对一个或多个 数据集）时，Foundry 会将转换逻辑拉取到其无服务器计算集群中并执行代码。构建的时长和规模取决于代码的复杂程度、输入和输出数据集的大小，以及代码上设置的 Spark 计算配置文件 。

在输入数据集上执行代码需要使用 Foundry 计算（以 Foundry 计算秒为单位度量）来运行并行计算，并在转换输出写入 Foundry Storage 时使用 Foundry 存储。编写代码本身不会产生计算用量；只有构建数据集才会产生计算用量。

度量 Foundry 计算

为 Code Repositories 提供支持的 transforms 引擎在后端使用并行计算，最常见的是 Spark 可扩展计算框架。Code Repositories 中的转换以作业在运行期间使用的 Foundry 计算秒 总数来度量。这些计算秒是在作业的整个持续时间内度量的，包括从输入数据集读取数据、执行代码（包括 I/O 等待等操作）以及将输出数据集写回 Foundry 所花费的时间。

您可以将转换配置为使用并行计算。计算秒度量的是计算运行时间，而非实际时间，因此并行转换每实际秒会产生多个计算秒。有关 Code Repositories 中作业的 Foundry 计算秒如何度量并行计算的详细说明，请查看 以下示例.

调查来自 Code Repositories 的 Foundry 计算用量

用量信息可以在 资源管理应用程序中找到，该应用程序支持对用量指标进行下钻分析。

虽然构建是 Foundry 计算用量的驱动因素，但用量会记录到与之关联的长期资源上。对于数据集转换，该资源是作业物化的数据集（或数据集集合）。您可以在数据集详情选项卡中的 资源用量指标.

下查看数据集的用量时间线。对于生成多个输出数据集的转换，计算用量会平均分配到所有数据集上。例如，如果某个转换作业创建了两个数据集，其中一个有五行数据，另一个有五百万行数据，则 Foundry 计算秒数将在两者之间平均分配。

了解 Foundry 计算用量的驱动因素

除非提前取消，Code Repositories 中的转换将一直运行，直到所有逻辑在所有数据上运行完毕且输出写回 Foundry 为止。影响此运行时间的两个主要因素是：(1) 输入数据的大小，以及 (2) 转换逻辑执行的计算操作的复杂程度。

  • 在逻辑相同的情况下，输入数据较大的作业比输入数据较小的作业需要更多计算。例如，对 100GB 数据执行列处理的作业将比对 10GB 数据执行相同处理的作业使用更多 Foundry 计算秒。
  • 对数据执行更复杂操作的作业将比执行相对较少操作的作业需要更多计算资源。这有时被称为“作业复杂度”。
    • 举一个基本的例子，考虑两个数学运算之间的运算次数， 5 * 5 and 5!. 5 * 5 是单次乘法运算。 5! 等同于 5 * 4 * 3 * 2 *1 （四次乘法运算），其复杂度是 5 * 5 示例的两倍。随着作业变得更加复杂，例如涉及聚合、连接或机器学习算法等任务，作业必须对数据完成的运算次数可能会增加。

使用 Code Repositories 管理 Foundry 计算用量

对于每个作业，您可以查看驱动该作业性能和计算用量的底层计算指标。更多详情，请查阅 了解 Spark 详情.

在作业中， Foundry 计算秒 由并行化执行器的大小和数量驱动。这两项设置均可针对每个作业进行完全配置。请查阅 Spark 计算配置文件 文档以了解如何针对每个作业进行设置。执行器的大小由其内存和 vCPU 数量决定。增加每个执行器的 vCPU 和内存将增加该执行器所产生的计算秒数。

同时任务的数量由配置的执行器数量及其相应的 vCPU 数量驱动。如果未指定任何配置覆盖，转换将使用默认的 Spark 配置文件。生成数据集的 Foundry 存储由所创建数据集的大小驱动。

最终，具有不同逻辑的作业可以通过截然不同的运算次数实现相同的结果。

优化代码以管理用量

有多种方法可以优化您的代码并管理作业所使用的计算秒数。本部分提供了指向常用优化技术更多信息的链接。

  • Spark 是 Foundry 为大多数类型的代码仓库批处理计算所采用的分布式集群计算框架，它支持多种优化技术。 了解有关优化 Spark 的更多信息。
  • 在 Spark 中，您可以优化分区以加快构建速度。最佳分区数取决于行数、列数、列的类型以及内容。我们建议大约每 128 MB 数据集大小对应一个分区。
  • 增量计算是执行转换以生成输出数据集的一种高效方法。通过利用转换的构建历史，增量计算避免了每次运行转换时重新计算整个输出数据集的需要。
    • 了解有关 Python 增量转换的更多信息。
    • 了解有关 Java 增量转换的更多信息。
  • 尤其是对于中小型数据集，在单节点应用的基准测试中，除 Spark 之外还有多种计算引擎的性能持续优于 Spark。因此，使用这些替代方案来运行您的管道可以提高处理速度并减少计算消耗。为了充分利用这些选项，我们建议您熟悉 轻量级转换.
  • 如果您的构建是通过 计划编排的，我们建议阅读我们的 计划最佳实践 以优化成本。

计算 Foundry 计算用量

使用示例 1：标准内存

此示例演示了如何针对具有标准内存请求的静态分配作业度量 Foundry 计算用量。

Driver profile:
    vCPUs: 1
    GiB_RAM: 6
Executor profile:
    vCPUs: 1
    GiB_RAM: 6
    Count: 4
Total Job Wall-Clock Runtime: 
    120 seconds



Calculation
driver_compute_seconds = max(num_vcpu, GiB_RAM/7.5) * num_seconds
                       = max(1vcpu, 6gib/7.5gib) * 120sec
                       = 120 compute-seconds

executor_compute_seconds = num_executors * max(num_vcpu, GiB_RAM/7.5) * num_seconds 

                         = 4 * max(1, 6/7.5) * 120sec 
                         = 480 compute-seconds

total_compute_seconds = 120 + 480 = 600 compute-seconds

使用示例 2：大内存

此示例演示了如何针对具有较大内存请求的静态分配作业度量 Foundry 计算用量。

Driver Profile:
    vCPUs: 2
    GiB_RAM: 6
Executor profile:
    vCPUs: 1
    GiB_RAM: 15
    Count: 4
Total Job Wall-Clock Runtime: 
    120 seconds



Calculation:
driver_compute_seconds = max(num_vcpu, GiB_RAM/7.5) * num_seconds
                       = max(2vcpu, 6gib/7.5gib) * 120sec
                       = 240 compute-seconds

executor_compute_seconds = num_executors * max(num_vcpu, GiB_RAM/7.5) * num_seconds 
                         = 4 * max(1, 15/7.5) * 120sec 
                         = 960 compute-seconds

total_compute_seconds = driver_compute_seconds + executor_compute_seconds
                      = 240 + 960 = 1200 compute-seconds

使用示例 3：动态执行器数量

此示例演示了如何针对动态分配的作业度量 Foundry 计算用量，其中部分作业执行时间使用两个执行器，其余作业时间使用四个执行器。

Driver Profile:
    vCPUs: 2
    GiB_RAM: 6
Executor profile:
    vCPUs: 1
    GiB_RAM: 6
    Count: 
        min: 2
        max: 4
Total Job Wall-Clock Runtime: 
    120 seconds:
        2 executors: 60 seconds
        4 executors: 60 seconds



Calculation:
driver_compute_seconds = max(num_vcpu, GiB_RAM/7.5) * num_seconds
                       = max(2vcpu, 6gib/7.5gib) * 120sec
                       = 240 compute-seconds

# Calculate compute seconds for job time with 2 executors
2_executor_compute_seconds = num_executors * max(num_vcpu, GiB_RAM/7.5) * num_seconds 
                           = 2 * max(1, 6/7.5) * 60sec 
                           = 120 compute-seconds 

# Calculate compute seconds for job time with 4 executors
4_executor_compute_seconds = num_executors * max(num_vcpu, GiB_RAM/7.5) * num_seconds 
                           = 4 * max(1, 6/7.5) * 60sec 
                           = 240 compute-seconds
                         

total_compute_seconds = driver_compute_seconds + 2_executor_compute_seconds + 4_executor_compute_seconds
                      = 240 + 120 + 240 = 600 compute-seconds

使用示例 4：GPU 计算

此示例演示了如何针对静态分配的作业度量 Foundry GPU 计算用量。

Driver profile:
    T4 GPU: 1
Executor profile:
    T4 GPU: 1
    Count: 4
Total Job Wall-Clock Runtime: 
    120 seconds


Calculation:
driver_compute_seconds = num_gpu * gpu_usage_rate * num_seconds
                       = 1gpu * 1.2 * 120sec
                       = 144 compute-seconds

executor_compute_seconds = num_executors * num_gpu * gpu_usage_rate * num_seconds 
                         = 4 * 1 * 1.2 * 120sec 
                         = 576 compute-seconds

total_compute_seconds = 144 + 576 = 720 compute-seconds
