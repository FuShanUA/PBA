编写 OAuth2 客户端

本文档面向希望编写 OAuth2 客户端以连接到平台的用户或管理员。本页面提供了 OAuth2 的描述以及有关 OAuth2 实现的详细信息。

OAuth2 概述

OAuth2 授权框架使第三方应用程序能够获得对服务的受控访问权限。OAuth2 对传统的客户端-服务器授权模型进行了改进，提供了一个额外的层，使客户端（如第三方应用程序）能够通过使用专门颁发的访问令牌和刷新令牌来请求访问权限，而不是使用用户的凭据或静态 Bearer 令牌。OAuth2 通过使用授权许可来管理这种访问，授权许可是获取访问令牌的方法。

支持 OAuth2 集成

以下部分介绍了如何在第三方应用程序中支持 OAuth2。在整篇文档中， 客户端 指的是第三方应用程序， 授权 服务器 指的是 Gotham 的授权服务器，而 用户 指的是第三方应用程序的最终用户。

要在 Gotham 中使用 OAuth2，您必须按照 注册第三方应用程序 中的说明注册您的应用程序，并在后续小节中选择一种授权选项。

授权码许可

授权码许可允许客户端代表现有 Gotham 用户执行操作。应用程序必须请求其需要访问的一组平台权限，然后必须由 Gotham 用户在其账户上明确授予客户端对这些权限的访问权限。Gotham 允许将客户端限制为一组有限的资源，或者允许其访问用户可访问的所有资源。

授权码许可的工作方式如下：

  1. 客户端创建一个 code_verifier 和 code_challenge。这是 推荐的 ，但并非必需 机密客户端 ↗（例如基于服务器的应用程序），此类客户端能够安全地存储客户端密钥。它是 必需的 ，适用于 公共客户端 ↗（例如原生应用），此类客户端无法安全地存储客户端密钥。
    • 该 code_verifier 是一个加密随机字符串，其中包含 A-Z、a-z、0-9、 - （连字符）、 . （句点）、 _ （下划线）以及 ~ （波浪号），并且长度为 43 到 128 个字符。
    • 该 code_challenge 是通过对 code_verifier 执行 SHA256 计算并将结果转换为不带填充的 Base64-URL 编码值而派生出来的。
  2. 客户端应用程序应打开浏览器并将用户引导至 授权端点 URL，并添加以下参数作为查询参数：
    • response_type：此参数应设置为 code。
    • client_id：此参数应设置为在 Gotham 中注册第三方应用程序时生成的 ID。
    • redirect_uri：此参数告知授权服务器在用户批准请求后将用户重定向到何处。如果未指定，则默认使用 Gotham 中第三方应用程序设置中的重定向 URI 值。
    • scope：此参数定义所请求的权限。公共 API 的作用域位于 API 文档。添加 offline_access 作用域以获取刷新令牌。如果需要多个作用域，请使用空格作为分隔符将各作用域连接起来。
    • state：这是应用程序生成的随机字符串，将被原样传回给该应用程序。应用程序应检查返回的值是否与原始字符串一致，以防止 CSRF 攻击。
    • code_challenge：如果客户端创建了 code_challenge，则应填充此参数。授权服务器将在内部将 code_challenge 参数与其生成的授权码进行关联。
    • code_challenge_method：应将其设置为 S256.
  3. 当用户访问该 URL 时,授权服务器会向用户显示类似以下的提示,用户随后可以选择批准应用的请求。

  1. 如果请求成功,授权服务器随后会将用户重定向到指定的重定向 URI,并添加以下参数作为查询参数:
    • code:这是授权服务器生成的授权码。
    • state:这是客户端在授权请求中传递的同一参数。客户端应检查其是否与请求中发送的原始 state 参数相匹配。
  2. 随后,客户端应使用授权码换取访问令牌,具体方法是调用 令牌端点。以下参数应使用 application/x-www-form-urlencoded 格式在请求体中发送。
    • grant_type：应设置为 authorization_code。
    • code：从授权服务器接收到的代码。
    • client_id：应设置为在 Gotham 中注册第三方应用程序时生成的 ID。
    • code_verifier：如果客户端生成了 code_verifier，则应在此请求中将其发送。授权服务器将验证 code_verifier 匹配 code_challenge 上一请求中发送的。
  3. 授权服务器随后会返回一个访问令牌，客户端即可使用该令牌来访问所请求的资源（例如 REST API）。响应包含以下参数：
    • access_token：客户端可用于访问所请求资源的令牌。
    • token_type：所颁发的令牌类型。
    • expires_in：访问令牌的有效期（以秒为单位）。
    • refresh_token：仅在请求的范围中包含了 offline_access。如果客户端希望在无需用户在场授权的情况下刷新访问令牌，则应使用此项。更多信息，请参阅 刷新访问令牌.

客户端凭证授权

客户端凭证授权专为非交互式的服务用户类型工作流而设计，在这类工作流中，客户端执行的操作不会与普通平台用户关联。客户端不会代表普通平台用户执行操作。

相反，这种授权类型会自动创建一个与客户端关联的服务用户，随后可为该服务用户授予访问平台资源的权限。通过此授权获取的令牌可用于代表所创建的服务用户访问资源。服务用户账户的用户名与应用的客户端 ID 相同。

默认情况下，服务账户无权访问任何资源。平台管理员必须为服务用户账户分配所需的角色和权限，客户端才能在 Gotham 中执行操作。

客户端凭证授权的工作原理如下：

  1. 客户端调用 令牌端点。以下参数应使用 application/x-www-form-urlencoded 格式在请求正文中发送：
    • grant_type：此项应设置为 client_credentials。
    • client_id：此项应设置为在 Gotham 中注册第三方应用程序时生成的 ID。
    • client_secret：此项应设置为在 Gotham 中注册第三方应用程序时生成的客户端密钥。
  2. 随后，授权服务器将返回以下内容：
    • access_token：客户端可用于访问所请求资源的令牌。
    • token_type：所颁发令牌的类型。
    • expires_in：访问令牌的有效期（以秒为单位）。
  3. 客户端随后可以使用访问令牌来访问所请求的资源。

刷新访问令牌

访问令牌在一段时间后会过期，需要重新获取。任何需要在用户不在场时访问 Gotham API 的客户端都需要刷新令牌。

可以按照以下步骤完成此操作：

  1. 客户端应按照以下内容中概述的步骤操作： 授权码许可 并指定 offline_access 作为所请求的 scope 参数的一部分。
  2. 客户端应保存返回的 refresh_token ，该值是在以下流程的最后一步中返回的： 授权码许可。
  3. 如果访问令牌过期，客户端便可以刷新令牌，方法是调用 令牌端点 端点，并使用以下参数：
    • grant_type：应设置为 refresh_token。
    • refresh_token：之前为给定用户获取的访问令牌。
    • client_id：应设置为在 Gotham 中注册第三方应用程序时生成的 ID。
    • client_secret：应设置为在 Gotham 中注册第三方应用程序时生成的客户端密钥。
  4. 授权服务器随后将返回以下内容：
    • access_token 客户端可用于访问所请求资源的令牌。
    • token_type：所颁发令牌的类型。
    • expires_in：访问令牌的有效期（以秒为单位）。
    • refresh_token：下次可用于再次刷新访问令牌的刷新令牌。请注意，平台会轮换 refresh_token ，每当 refresh_token grant 被调用时都会如此。请确保同时保存 access_token 和 refresh_token.

OAuth2 API 参考

以下端点可用于获取 OAuth2 令牌。

授权端点

GET /multipass/api/oauth2/authorize

授权端点，由客户端用于获取授权码。

查询参数

参数名称类型描述
response_typeString此值必须设置为 code。
client_idString客户端的唯一标识符。
redirect_uri字符串用户代理将被重定向到的绝对 URI。如果未指定，则默认使用第三方应用设置中的重定向 URI 值。
scope字符串要请求的权限范围。公共 API 的 scope 请参见 API 文档 ，并且应以空格分隔的字符串形式列出。
state字符串（可选）传递给服务器的任意字符串，服务器会将其原样传回客户端。这有助于防止跨站请求伪造。
code_challenge字符串（可选）由客户端生成的代码质询；用于 带代码交换证明密钥的授权码许可（PKCE）
code_challenge_method字符串（可选）应设置此项 S256 如果 code_challenge 被使用。

重定向查询参数

如果请求成功，用户浏览器将被重定向到第三方应用程序设置中指定的重定向 URI，或请求中传递的重定向 URI。重定向请求 URI 中将包含以下查询参数：

参数名称类型描述
codeString生成的授权码。该授权码将在 10 分钟后过期。
stateString（可选）如果 state 参数存在于授权请求中，则其中将包含该确切值。

令牌端点

POST /multipass/api/oauth2/token

客户端使用令牌端点，通过出示其授权许可或刷新令牌来获取访问令牌。

标头参数

参数名称描述
Content-Type必须为 application/x-www-form-urlencoded.

请求正文参数

参数名称类型描述
grant_type字符串值必须为 authorization_code， refresh_token，或 client_credentials
codeString（可选）从授权端点收到的授权码。此项为必需项，前提是授权类型为 authorization_code
refresh_tokenString（可选）此项为必需项，前提是 grant_type 为 refresh_token。该值应为 refresh_token 即在获取授权码时的原始请求中所获得的。
redirect_uri字符串（可选）用户代理将被重定向到的绝对 URI。如果未指定，将默认使用第三方应用程序设置中的重定向 URI 值。
scope字符串（可选）要请求的权限范围。公共 API 的权限范围请参见 API 文档 并且应以空格分隔的字符串形式列出。
client_id字符串客户端的唯一标识符。
client_secret字符串（可选）在应用程序注册期间颁发的应用程序客户端密钥。当 grant_type 为 client_credentials.
code_verifier字符串（可选）应用程序在发起授权请求之前生成的、用于 PKCE 请求的代码验证器。

响应正文

响应 JSON 包含以下字段。

字段名称type描述
access_token字符串用于访问资源的凭据。
token_type字符串所颁发令牌的类型。
expires_in字符串访问令牌的有效期（以秒为单位）。
refresh_token字符串（可选）用于获取新访问令牌的凭据。平台会轮换 refresh_token ，每次调用 refresh_token grant 时都会轮换。请务必同时保存 access_token 和 refresh_token.

端点错误

错误响应正文

如果请求失败，只有当访问请求被拒绝时，用户的浏览器才会被重定向。在所有其他情况下，将返回一个包含以下字段的 HTML 错误页面。

字段名称类型描述
error字符串下一节中定义的错误代码。
error_description字符串错误的人类可读描述

错误代码

错误代码值描述
invalid_request请求无效。
unauthorized_client客户端无权请求授权码。
access_denied服务器拒绝了该请求。
unsupported_response_type不支持所提供的响应类型。
invalid_scope所请求的作用域无效、未知或格式错误
server_error发生了意外的服务器错误。
