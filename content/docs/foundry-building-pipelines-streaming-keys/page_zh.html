流式键

Foundry 流允许您指定一个或多个列作为键列，并指定一个主键来标识已解析的记录。以下部分将说明如何为您的流式管道设置和维护分区键和主键。

分区键

通常， 主 键 在 Palantir 平台中用于唯一标识数据库记录。但是， 分区 Foundry 流中的键会对 记录 具有相同 键的记录进行分组，例如某个特定 读数 设备 的所有，或所有 事务 设备 增长，。与批处理管道中的主键不同，流中的分区键不会对记录进行去重，因为它们不能唯一标识记录。

Foundry 中的键允许用户确保某个特定键的所有记录保持顺序。当记录进入 Foundry 时，它会被内部存储在 Kafka 中。Kafka 保证写入同一分区的记录在读取和写入时保持顺序。如果发送到 Foundry 的记录没有键，该记录将以轮询（round-robin）方式写入内部 Kafka 主题的任意分区。但是，如果用户为记录指定了键，该记录将被写入该键的专用分区，从而在下游消费时保持顺序。

类似地，Flink 流式作业会根据输入源上设置的分区键列自动维护排序。Flink 转换作业在执行每个转换操作时可以使用一个或多个并行分区。对于按分区键分组的输入流，Flink 作业会自动将所有键列值相同的记录发送到同一个并行算子实例。除非特意重新指定键（例如使用 Key by 和构建数据的方法是应用一个联合操作。联合操作将两个数据集合并，以包含每个数据集的所有行。在Pipeline Builder中，联合操作会保留所有行，包括重复的行。），否则整个管道长度上的分区和排序都由源上的键列和行值决定，即使转换逻辑删除了列或覆盖了值。

主键：变更数据捕获（CDC）模式

Foundry 流中的主键与关系数据库和批处理数据集中使用的主键类似。但是，流式主键由一组唯一标识已解析记录的去重列组成，并且不指定排序列。

主键是 Foundry 中流 schema 里的一段元数据。该键不会影响存储数据的内容，也不会影响流式数据管道和转换的应用方式。主键控制某些 Foundry 消费者读取数据的方式；完整的 数据 可以被视为一个 变更日志（changelog），而 主键 告诉消费者如何计算去重后的 当前视图 （在应用所有变更之后）。

当前视图是数据的一个筛选视图，仅包含每个键最近流式传输的记录。某个键的完整最新记录将始终被保留，即使它包含 nulls。如果指定了已删除列，并且某个键最近流式传输的记录将该值设置为 true，则该记录将被过滤掉。

以下示例展示了一个主键和数据流，其中最近流式传输的行在表中位于更上方。

主键： {Dedeuplication column(s): [Key], isDeletedColumn: Optional[isDeleted]}

| Key | Value | isDeleted |
|------|-----------|-----------|
| Key2 | null | false | | Key1 | thirdVal | true | | Key2 | secondVal | false | | Key1 | firstVal | false |

当支持 CDC 的消费者读取这个变更日志流时，将被读取为以下当前视图：

| Key | Value | isDeleted |
|------|-----------|-----------|
| Key2 | null | false |

如果您选择为流式数据设置主键，则还必须将相同的列设置为分区键，以维护排序并正确解析去重后的数据视图。在流式设置界面中设置主键后，相同的列将自动添加为分区键列。

以下两个支持 CDC 的作业将自动把带主键的流式数据作为当前视图读取：

  1. 使用带主键的流为本体论（Ontology）填充数据： 新的更新记录将根据需要导致新对象的创建、更新或删除。
  2. 流的归档数据集可由任何 Spark 转换作业读取： 在进行任何转换之前，源数据将被去重。值得注意的是，几乎所有与归档数据集的交互都会运行 Spark 作业，包括数据集预览和 Contour 分析。查看归档数据集时，它始终显示为去重后的当前视图，即使数据本身包含完整的变更日志（如果您将数据下载为文件）。完整的变更日志将由任何不运行 Spark 的流式作业处理，包括重放。

键传播

Pipeline Builder 会通过管道转换跟踪分区键列和主键列的演变，并将任何有效的键写入输出流的 schema 中。如果您的转换不会使任何键列失效，则在任意数量的下游管道序列中，将自动维护相同的分区和去重指令。

如果您重命名某个键列，该键将更新为包含新的列名。同样，如果您应用某个转换来删除或覆盖键列，该列将从键中移除。由于键列内容的任何覆盖都可能表示新的排序保证或新的去重策略，Pipeline Builder 会将该列从键中完全移除。您必须应用 Key by 转换，才能保留之前被覆盖的键列。即使分区键列因删除或覆盖而被丢弃，除非您重新设置键，否则相同的排序保证将在管道的其余部分持续有效。

如果所有分区键或去重 CDC 键被删除或覆盖，该键将被完全丢弃。在删除或覆盖键列内容时请务必谨慎；这样做可能导致意外结果，包括失去排序保证或去重策略。

目前，键 绝不会 在用户自定义函数（UDF）中传播。由于该函数是用户自定义的，无法推断用户意图采用哪种键传播策略（如果有的话）。如果您打算传播键，请务必在 UDF 之后应用 Key by 转换。

此外，主键不会在有状态转换中传播（大多数转换是无状态的）。

使用流式键

在 Pipeline Builder 应用程序的流式管道中，将 Key by 转换添加到您的图中。值得注意的是，您在此处设置的任何键都将覆盖并替换输入数据上的任何现有键。

如果您只想设置分区键，请关闭 CDC mode 选项，仅提供 Key by columns 列表。除非您处于 CDC 模式，否则其他参数不是必需的，也不允许使用。

要同时设置主键和分区键，请开启 CDC 模式 选项。如果你有 isDeleted 列，可以选择在 主键已删除 字段中指定它。对于流式处理用例，我们强烈建议将可选的 主键排序列 参数留空。转换将同时设置分区键和主键，其中分区键列与主键去重列相同。 主键排序列 参数仅在批处理作业中消费归档数据集时才有意义，绝不会影响流式处理进行去重的方式。指定排序列的选项是为了向后兼容、供批处理转换用户或打算以特定仅批处理方式消费流归档的用户使用。

检查当前键

以下部分介绍如何在 Foundry 流中查找和验证流式键逻辑。

检查分区键

打开你的流式数据集，导航到 详情 标签页，然后打开 模式 标签页以查看 JSON 格式的数据架构。

搜索 includeInParitioning，它将出现在 fieldSchemaList 中作为主键一部分的每个列所对应的元素中：

"customMetadata": {
"includeInPartitioning": true
}

如果你没有看到任何带有 includeInParitioning的架构字段，则你的流没有键，并且无法保证数据存储或处理的顺序。要手动添加键，请以 JSON 文本形式编辑架构，并将自定义元数据（如上文所述）插入到你想要设置为分区键列的每个架构字段（列）中。

如果流已经有一个或多个分区键，添加新的分区键列将导致 较弱 的顺序保证，因为分区会更多；只有当所有分区键列的值都相同的行，才能保证维持其顺序。

在部署之前，如果在管道的输入流上设置了分区键列，则将为该源及其所有转换在整个管道中保证顺序，除非你有意重新设置键。分区键列在数据预览中可能会显示一个键符号。

检查主键

打开你的流式数据集，导航到 详情 标签页，然后打开 模式 标签页以查看 JSON 格式的数据架构。

你将看到一个名为 primaryKey的 JSON 属性。如果你的流有名为 uniqueCol1 和 uniqueCol2，而 isDeleted 列是 isDeletedCol，则架构应如下所示：

  "primaryKey": {
    "columns": [
      "uniqueCol1",
      "uniqueCol2"
    ],
    "resolution": {
      "type": "duplicate",
      "duplicate": {
        "resolutionStrategy": {
          "type": "customStrategy",
          "customStrategy": {}
        },
        "deletionColumn": "isDeletedCol"
      }
    }
  }

如果未设置主键，架构将显示 null:

"primaryKey": null

要手动设置或删除主键，你可以编辑架构 JSON 以按上述格式指定键，或使用 null 来删除键。如果你手动设置主键，我们强烈建议将相同的列设置为分区键列。

保证顺序的唯一方法是在整个流式数据血缘上设置分区键列。设置完成后，分区键列将自动向下游传播。即使流被配置为只有一个分区，由于 Flink 应用程序以非确定性方式扩展和处理记录，顺序也不一定能够得到保证。

流式键最佳实践

请谨慎选择分区键，因为导致记录分布低效的键会人为地增加负载并限制吞吐量。如果顺序对你的用例很重要，请将分区键设置为你想要维持顺序的通用分组标识符，例如电子邮件 ID、客户 ID 或组织 ID。如果顺序对你的用例不重要，你可以选择使用唯一 ID 作为键，或者根本不为你的流使用键。

最终流式输出的排序保证强度将与您的 最弱 流式系列（由 Kafka 主题支撑）以及通往输出的转换（Flink 作业）中的保证相同。因此，请确保在整个数据血缘中保持所需的排序，并设置正确的分区键，从最初将记录提取到 Foundry 的流式提取开始。排序保证不会强于您从中提取数据到 Foundry 的系统。例如，如果您使用 Kafka 连接器从 Kafka 提取数据，请将分区键列设置为与 Kafka 键列相同，以便 Foundry 在您的系统上保持同等的排序保证。

此外，如果在一系列数据转换过程中完全更改分区列（以及排序保证），也可能会出现问题。如果在应用新的 Key by 转换之前保证了不同的排序，则该转换将接收到相对于新添加的键列而言顺序错乱的记录；这些记录在整个转换系列中将保持错误的顺序。
