连接安全性

Data Connection 与外部数据源建立出站 TLS 连接。并非 TLS 连接中使用的所有密码套件都在整个平台中受支持。

支持的套件

Data Connection 支持以下用于出站连接的密码套件，前提是底层 Java 版本支持这些套件。根据环境的配置和连接发起点，可能还有其他可用的密码套件。

如需了解基于环境配置和连接发起点可能可用的其他密码套件，请联系 Palantir Support。

验证您的外部系统是否接受受支持的密码套件

要验证您的外部系统是否接受受支持的密码套件，请运行 openssl s_client -connect your-system.example.com:<port> -tls1_3 </dev/null （或 -tls1_2 用于 TLS 1.2）。协商的套件会显示在输出中 SSL-Session 块的 cipher 行上。要测试受支持列表中的特定套件，请添加 -ciphersuites '<cipher_iana_name>' 用于 TLS 1.3 或 -cipher '<cipher_openssl_name>' 以支持 TLS 1.2。一个 SSLHandshakeException 包含 handshake_failure、 no cipher match或 protocol is disabled or cipher suites are inappropriate 表明存在密码套件不匹配，因此您应该更新外部系统上的密码套件配置，以启用其中一个受支持的套件。您还可以运行 openssl ，该命令将针对您的源所使用的相同网络路径执行，起点为 源终端。

代理主机上的漏洞扫描发现结果

在代理主机上运行的漏洞扫描器可能会针对属于代理软件或连接器插件早期版本的文件报告发现结果。在几乎所有情况下，这些文件都是不再加载或运行的非活动文件。代理仅使用每个组件的当前版本，因此针对已被取代的文件报告发现结果并不意味着代理正在运行存在漏洞的代码。

这些文件是正常升级过程中遗留的。当代理升级到新版本时，被替换的旧版本会在主机上保留最多 30 天，然后自动删除。安全修复（包括针对已知通用漏洞披露 (CVE) 的修复）以新版本的形式交付，代理会自动升级到最新可用版本，具体时间为其各自的 升级窗口。为每个代理配置升级窗口可确保其运行最新的修复程序。要详细了解 Palantir 如何识别、披露和修补漏洞，请参阅 漏洞监控。

若要在不等待自动 30 天清理的情况下解决发现的问题，您可以自行删除受影响的备份、缓存和已归档的插件版本。请参阅 备份和缓存 以获取操作说明，包括如何识别仍在使用中的版本。
