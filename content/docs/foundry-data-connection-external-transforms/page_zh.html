外部转换

数据连接源 现在可以直接导入到代码仓库中，是与外部系统交互的首选方法，取代了 基于凭据的旧版外部转换

外部转换允许从 Python 转换 仓库连接到外部系统。

外部转换不支持使用 出站应用 进行身份验证的源。

外部转换主要用于执行 批量同步、 导出以及 媒体同步 工作流，前提是满足以下任一条件：

  • 没有可用的现有数据连接源类型。
  • 目标源类型不支持所需的功能。
  • 通过数据连接用户界面提供的功能不具备所需的特性。

针对这些情况的解决方案可能包括以下内容：

  • 通过互联网以及在专用网络内连接 REST API。
  • 连接到数据库，以配置数据连接用户界面目前无法实现的自定义查询逻辑。
  • 在同步或导出过程中根据需要转换数据。这可能包括在写入 Foundry 之前将文件合并成批、在传输过程中对数据进行自定义加密/解密等。

任何使用 虚拟表的转换 也被视为外部转换，因为转换作业必须能够连接到包含虚拟化数据的外部系统。要使用 虚拟表 进行 Python 转换，请按照以下说明详细了解如何设置数据源。

设置指南

在本设置指南中，我们将逐步讲解如何创建一个 Python 转换仓库，并将其连接到 免费公共词典 API ↗。随后的示例将使用该 API 来说明外部转换的各种功能，以及它们如何与该 API 配合使用。

本设置指南中使用的词典 API 与 Palantir 无关，且可能随时发生变化。本教程并非对在生产用例中使用该 API 的认可、推荐或建议。

前提条件：创建 Python 转换仓库

在遵循本指南之前，请务必先创建一个 Python 转换仓库，并参阅 我们的教程中关于如何编写 Python 转换的说明。Python 转换的所有功能均与外部转换兼容。

在从 Python 代码仓库连接外部系统之前，您必须先创建一个可导入到代码中的数据连接数据源。在本教程中，我们将创建一个连接到上述字典 API 的 REST API 数据源。

选项 1：在外部系统侧边栏中创建数据源

创建供外部转换使用的数据源的最快方法是通过 Python 转换代码仓库。初始化仓库后，请完成以下步骤来设置通用数据源：

如果您在 Python 转换仓库中工作，且该仓库位于 VS Code 工作区中，则 外部系统 设置位于顶部导航栏的 “设置” 标签页中。

  1. 在左侧面板中，打开 “外部系统” 标签页。
  2. 选择 “添加 > 新建”。

  1. 为您的数据源选择一个名称，并选择一个用于存储该数据源的项目。创建完成后，新创建的数据源将显示在左侧面板中。所有出口策略、密钥和可导出标记都可以直接在该面板中进行配置。

  1. 在本教程中，您需要添加一个 出口策略 ，用于字典 API： api.dictionaryapi.dev。此 API 不需要身份验证，因此您无需任何机密信息，而且暂时可以跳过导出控制。但是，需要提供它们才能 将 Foundry 数据输入与此数据源结合使用。

  2. 由于此连接指向 REST API，系统会自动提示您将通用连接器转换为 REST API 数据源，以便您使用内置的 Python requests 客户端。

先决条件：将源导入代码

包含多个域的 REST API 源可能无法导入。相反，如果同一外部转换中需要多个域，则应为每个域分别创建单独的 REST API 源。

  1. 首先，您必须允许将 REST API 源导入到代码中。要配置此设置，请在 Data Connection 中导航到该源，然后前往 连接设置 > 代码导入配置 选项卡。

from pandas import DataFrame
from transforms.api import transform
from transforms.api import Output, Input, TransformContext, transform_pandas
from transforms.external.systems import external_systems, Source
import pandas as pd
import logging

logger = logging.getLogger(__name__)


@external_systems(
    dictionary_api_source=Source(
        "<source_rid>"
    )
)
@transform_pandas(Output("<output_dataset_rid>"))
def compute(dictionary_api_source) -> DataFrame:
    dictionary_api_url = dictionary_api_source.get_https_connection().url
    dictionary_api_client = dictionary_api_source.get_https_connection().get_client()

    words = ["apple", "dog", "cat"]

    phonetics = []

    for word in words:
        logger.info("Fetching word from api.dictionaryapi.dev : " + word)

        response = dictionary_api_client.get(
            dictionary_api_url + "/api/v2/entries/en/" + word
        ).json()

        phonetics += [{"word": word, "phonetic": response[0]["phonetic"]}]

    return pd.DataFrame(phonetics)

在外部转换中使用 Foundry 输入

外部转换通常需要使用 Foundry 输入数据。例如，您可能希望查询 API 来为表格数据集中的每一行收集额外的元数据。或者，您可能有一个需要将 Foundry 数据导出到外部软件系统的工作流。

此类情况被视为 受出口管制的 工作流，因为它们开启了将受安全保护的 Foundry 数据导出到另一个系统的可能性，而该系统具有未知的安全保证，且数据溯源会被切断。在配置源连接时，源所有者必须指定是否允许导出 Foundry 数据，并提供可导出的安全标记和组织集合。Foundry 提供治理控制措施，确保开发人员能够清晰地编码安全意图，并让信息安全官可以审计与外部系统交互的工作流的范围和意图。

在源上配置导出控制

导出使用 安全标记进行控制。在配置源时，导出配置用于指定哪些安全标记和组织可以安全地导出到外部系统。具体做法是在数据连接应用程序中导航到该源，然后导航至 连接设置 > 导出配置 选项卡。然后,您应开启 启用导出到此源 选项,并选择可能被导出的标记和组织。

执行此操作需要拥有移除相关数据和组织上的标记的权限,因为导出被视为等同于移除 Foundry 中数据上的标记。

必须开启 启用导出到此源 设置,才能允许以下操作:

  • 将数据集、媒体集和流用作导入此数据源的 Python 转换代码的输入。
  • 在 Python 转换中使用注册在此数据源上的虚拟表。

您可以在下方看到 Dictionary API 数据源的导出配置示例,该配置允许将来自 Palantir 不带额外安全标记的组织的数据导出到 Dictionary API:

请注意, 启用导出到此源 设置必须处于开启状态, 即使您实际上并未向该系统导出数据,因为允许将 Foundry 数据输入引入与该系统保持开放连接的同一计算作业,意味着这些数据 可能会 被导出。

from pandas import DataFrame
from transforms.api import transform
from transforms.api import Output, Input, TransformContext, transform_pandas
from transforms.external.systems import external_systems, Source, ResolvedSource
import pandas as pd
import logging

logger = logging.getLogger(__name__)


@external_systems(
    dictionary_api_source=Source(
        "<source_rid>"
    )
)
@transform_pandas(
    Output("<output_dataset_rid>"),
    words_df=Input("<input_dataset_rid>"),
)
def compute(dictionary_api_source: ResolvedSource, words_df: DataFrame) -> DataFrame:
    dictionary_api_url = dictionary_api_source.get_https_connection().url
    dictionary_api_client = dictionary_api_source.get_https_connection().get_client()

    words = words_df["word"].tolist()

    phonetics= []

    for word in words:
        logger.info("Fetching word from api.dictionaryapi.dev: " + word)

        response = dictionary_api_client.get(
            dictionary_api_url + "/api/v2/entries/en/" + word
        )

        if response.status_code == 200:
            data = response.json()[0]

            if "phonetic" in data:
                phonetic_transcription = data["phonetic"]
            else:
                logger.warning(f"No phonetic transcription found for {word}.")
                phonetic_transcription = None
        else:
            logger.warning(f"Request for {words} failed with status code {response.status_code}.")
            phonetic_transcription = None

        phonetics += [{"word": word, "phonetic": phonetic_transcription}]

    return pd.DataFrame(phonetics)

外部转换与旧版外部转换的对比

以下是外部转换与旧版外部转换之间的一些关键工作流差异：

  • 对于外部转换，用于导入源的选项卡将始终自动显示。以前，只有在信息安全官在仓库设置中开启使用外部系统的功能后，添加出站策略和凭据的选项卡才会显示。
  • 允许外部连接和使用输入的设置不再位于仓库设置中，而是在每个单独的源上进行控制。
  • 凭据、出站策略和可导出标记不再在代码中指定。这些设置将改为从导入到转换中的源获取，并自动应用于作业。
    • 如果在源级别更改了此配置，导入该源的转换将自动获取更改，无需进行任何代码更改或版本升级。这样可以集中治理凭据、出站和可导出标记，并使其立即传播到下游工作流。
    • 更改将从构建开始时生效，且不会影响正在运行的构建。
  • 装饰器已从 @use_external_systems() 更改为 @external_systems()。

外部转换的主要优势包括：

  • 支持连接无法从互联网访问的系统
  • 支持轮换/更新凭据，无需更改代码
  • 支持在多个仓库间共享连接配置
  • 为选定的源类型提供开箱即用的 Python 客户端
  • 改进并简化了用于启用和管理外部转换仓库的治理工作流
  • 在以下位置可视化连接到外部源的外部转换： 数据血缘

迁移到外部转换

目前还没有将外部转换更新为外部转换的自动迁移路径。不过，对于大多数工作流而言，所需的手动操作预计会非常少。

以下是手动迁移到外部转换的主要步骤：

  1. 识别您现有旧版外部转换代码中使用的一组凭据、出站策略和出口管制标记。
  2. 识别或配置 Data Connection 数据源，以连接到您希望从外部转换中连接的系统。请确保这些数据源已配置为允许导入到代码中。
  3. 将步骤 2 中的相关数据源导入到您现有的 Python 转换仓库中。
  4. 修改您的代码，以导入并使用新的 @external_systems() 装饰器（带有数据源引用），然后移除 @use_external_systems() 装饰器的所有实例。这可能需要更新您的转换逻辑中对凭据的引用，改为引用从您现在导入的数据源中获取的凭据。
  5. 在分支上测试您的更改，以确保您的转换能够继续成功构建。
  6. 合并更新后的转换代码后，您现在可以取消勾选仓库设置。

转换不能同时包含外部转换及其旧版本。要解决此问题，您可以将所有旧版外部转换迁移为使用基于数据源的外部转换（推荐），或者将您的转换拆分为多个转换。转换可以拆分为一个使用 use_external_systems 装饰器的转换，另一个使用 external_systems 装饰器的转换。

import gc
import logging
from datetime import datetime

import pyarrow as pa
import pyarrow.parquet as pq
from pympler import asizeof

from transforms.api import Output, transform, LightweightOutput
from transforms.external.systems import external_systems, Source, ResolvedSource

logger = logging.getLogger(__name__)


class BufferedParquetWriter:
    """Buffers rows in memory and flushes them to Parquet files when the buffer
    exceeds a configurable size threshold."""

    def __init__(self, output: LightweightOutput, schema: pa.Schema, flush_threshold_mb: int = 64):
        self.output = output
        self.schema = schema
        self.flush_threshold_bytes = flush_threshold_mb * 1024 * 1024
        self.buffer = []
        self.buffer_size_bytes = 0
        self.file_index = 0
        self.row_size_estimate = None

    def append(self, row: dict):
        """Add a row to the buffer. If the buffer exceeds the threshold, flush to disk."""
        self.buffer.append(row)

        # Estimate row size from the first row, then use that estimate going forward
        if self.row_size_estimate is None:
            self.row_size_estimate = asizeof.asizeof(row)
        self.buffer_size_bytes += self.row_size_estimate

        if self.buffer_size_bytes >= self.flush_threshold_bytes:
            self.flush()

    def flush(self):
        """Write buffered rows to a Parquet file and clear the buffer."""
        if not self.buffer:
            return
        self.file_index += 1
        table = pa.Table.from_pylist(self.buffer, schema=self.schema)
        timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
        filename = f"output_{timestamp}_{self.file_index}.parquet"
        with self.output.filesystem().open(filename, "wb") as f:
            pq.write_table(table, f)
        logger.info(f"Flushed {len(self.buffer)} rows to {filename}")
        self.buffer = []
        self.buffer_size_bytes = 0
        gc.collect()

    def finalize(self):
        """Flush any remaining rows and trigger schema inference."""
        self.flush()
        if self.file_index > 0:
            self.output.put_metadata()

import csv

from transforms.api import Input, Output, transform, LightweightInput, LightweightOutput


@transform.using(
    source_data=Input("<input_dataset_rid>"),
    csv_output=Output("<output_dataset_rid>"),
)
def compute(source_data: LightweightInput, csv_output: LightweightOutput):
    OUTPUT_FILENAME = "export.csv"

    # Read the input dataset as a Polars DataFrame.
    df = source_data.polars()
    fieldnames = df.columns

    # Write the data as a CSV file.
    with csv_output.filesystem().open(OUTPUT_FILENAME, "w") as f:
        writer = csv.DictWriter(f, fieldnames=fieldnames)
        writer.writeheader()
        for row in df.iter_rows(named=True):
            writer.writerow(row)
