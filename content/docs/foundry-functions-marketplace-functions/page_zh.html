Marketplace 中的函数

您可以使用 Foundry DevOps 将您的函数包含在 Marketplace 产品 中，供其他用户安装和复用。

向产品添加函数

要向产品添加函数， 创建产品。然后，按如下所示添加函数输出。

系统将提示您选择函数和版本。

包含代码仓库的源代码

打包在代码仓库中编写的函数时，支撑仓库将自动作为附加输出包含在产品中。虽然您可以选择将代码仓库连同其源代码一起打包，但对于不打算安装在 bootstrap 模式中的产品，我们通常不建议包含其源代码。这是因为通过 Marketplace 安装的函数无需其支撑源代码即可成功执行。此外，代码仓库并不保证能够开箱即用地编译或构建。

如果您想在安装后对函数进行更改（例如，修复错误或增强功能），我们建议对原始函数进行这些更改，发布新版本的 Marketplace 产品，然后升级安装。如果您不拥有已安装的产品，则应联系其维护者并提交错误报告或功能请求。

扩展函数执行要求

使用扩展执行能力的函数需要满足额外的 Marketplace 安装要求。这些能力包括在函数内部调用 操作 以及获取具有延长生存时间（TTL）的身份验证令牌。在安装之前，管理员必须将目标项目添加到 扩展函数执行 允许列表（在 Functions 设置 下，位于 Control Panel中）。

有关允许列表的配置说明，请参阅 Functions 设置。

版本和 API 名称解析

当通过 Marketplace 安装函数时，其版本和 API 名称的解析方式有两种：去重模式和稳定模式。

去重模式

这是通过 Marketplace 安装函数时解析其版本和 API 名称的历史默认行为。

在去重模式下，函数版本的解析方式如下：

  • 当函数最初通过安装创建时，其第一个版本将发布为 0.1.0。
  • 在后续安装（例如升级）时，函数将发布为其最新版本递增一个次要版本后的版本。例如，如果已安装函数的最新版本为 1.1.0，则下一次安装将发布 1.2.0。

函数版本 是不可变的。换言之，一旦发布了函数的某个版本，便无法对其进行更改或覆盖。

函数 API 名称的解析方式如下：

  • 如果该 API 名称已绑定到安装的本体论中的另一个函数，则会通过附加递增的整数后缀来对该 API 名称进行去重。例如，如果 API 名称 myFunction 已被占用，则该函数将使用 API 名称 myFunction1进行安装。如果该 API 名称也已被占用，则将使用 API 名称 myFunction2进行安装，依此类推。
  • 一旦已安装的函数上存在某个 API 名称，该函数将在后续安装（例如升级）中保持该 API 名称。

函数 API 名称 在每个本体论中都是唯一的。准确地说，如果已经存在一个 API 名称为 myFunction 在本体论中，同一本体论内不能存在其他具有相同 API 名称的函数。

稳定模式

Beta

稳定模式处于 Beta 开发阶段，在您的注册中可能无法使用。功能在积极开发期间可能会发生变化。请联系 Palantir 支持团队以在您的注册中启用此功能。

版本和 API 名称是函数 API 不可或缺的组成部分。因此，在许多情况下，通过 Marketplace 打包和安装函数时，建议保留它们。在与静态引用函数依赖项的上游应用一同安装函数时，这一点尤为重要，例如 Developer Console 应用。

稳定模式不支持 计算模块函数 ，因为这些函数在 Foundry 中有自己的版本管理行为。

在稳定模式下，函数版本的解析方式如下：

  • 已安装的函数始终以其打包版本发布。
  • 如果该版本已存在于已安装的函数中，则会创建一个全新的函数；旧函数将被隐藏，其 API 名称将被移除。

创建新函数来解决版本冲突会影响上游应用。如果上游应用属于同一安装的一部分，它将自动更新以引用新函数。否则，您需要手动更新它。

函数的 API 名称按以下方式解析：

  • 已安装的函数始终以其打包时的 API 名称发布。
  • 如果 API 名称已被其他函数占用，将会发生安装错误。要解决此冲突，您必须删除现有函数或更改其 API 名称。

已部署的函数

函数以无服务器执行模式运行，或者被 部署 到长期运行的容器中。Marketplace 会将函数仓库的执行模式与函数本身一起打包，因此已安装的函数的运行方式与其在打包环境中的运行方式相同。

Marketplace 如何打包函数执行模式

函数执行模式是按仓库配置的，Marketplace 会将其打包 一次 供由同一部署支撑的所有函数使用。

对于处于已部署模式的仓库，Marketplace 会捕获环境变量、资源请求和限制、扩展限制以及其他关键部署配置详情。

Marketplace 不会将容器镜像打包为固定值。相反，容器镜像会在安装期间根据所安装函数的版本进行解析，因此已安装的部署始终运行所安装函数的镜像。

要打包其仓库处于已部署模式的函数，该仓库必须存在部署，且该部署必须正在运行您要打包的函数版本。否则，打包将失败。要解决此问题，请启动或更新部署，使其运行您要打包的版本，或将仓库切换为无服务器执行。

Marketplace 在安装期间如何应用配置

当您安装或升级产品时，Marketplace 会将打包的执行模式和部署配置应用于目标环境。这相当于解锁安装并手动配置执行，以匹配打包该产品时所在的环境。

如果打包的模式为 已部署，则 Marketplace 会为已安装的仓库创建部署（若尚不存在），并将打包的部署配置应用于该部署，然后启动该部署。

如果打包的模式为 无服务器，Marketplace 会将已安装的代码仓库设置为无服务器执行。如果该代码仓库已存在部署，Marketplace 将停止安装。

并非每个注册中都提供无服务器函数。如果产品以无服务器模式打包某个函数，但目标环境中不提供无服务器执行，则该函数会改为以部署模式安装。发生这种情况时，Marketplace 会创建并启动使用默认配置的部署。这可确保已安装的函数能够作为已部署的函数运行。

计算成本

只要部署处于运行状态，已部署的函数就会持续产生计算成本，而无服务器函数仅在执行时才产生成本。因此，如果因目标环境不支持无服务器执行而以部署模式安装某个无服务器函数，该函数将产生长期运行部署的计算成本。

Marketplace 中已部署函数的限制

Marketplace 中的已部署函数具有以下限制。

同一函数一次只能部署一个版本

部署运行函数的单个版本。当您升级包含已部署函数的 Marketplace 产品时，该函数会以新版本重新发布，并且新版本会自动部署以替代之前部署的版本。

正在升级的安装之外的产品不会通过该升级进行更新。如果某个外部产品，或既未包含在 Marketplace 产品中、也不属于某个 关联产品的产品，引用了已部署函数的特定版本，则其引用将继续指向旧版本。由于一次只能部署函数的一个版本，对旧版本函数的任何引用都将返回错误。

为避免这种情况，您必须：

  • 将已部署函数的调用方打包到同一产品或某个 关联产品 中，以便它们随函数一起升级。
  • 尽可能使用无服务器执行。无服务器函数可以按需执行函数的不同版本，因此升级不会使早期版本的引用失效。

升级期间部署会重启

对支撑已部署函数的长期运行容器所做的某些更改（例如更新为其配置的源）无法在该容器运行时应用。因此，每次作为 Marketplace 产品升级的一部分进行升级时，部署可能会被停止并重新启动，这意味着函数可能会经历停机时间。

静态函数输入

此功能仅在 TypeScript v1中受支持。

在安装时，可以通过提供本地定义的函数来修改函数行为的某些部分，该函数会覆盖随 Marketplace 产品一起提供的“静态”函数输入。为此，您可以指定某个特定函数可被覆盖，方法是使用 @Static 装饰器。

import { Function, Static, Double } from "@foundry/functions-api";

export class MyFunctions {

    @Function()
    public async modifyNumberByStaticFoo(
        n: Double,
        @Static() staticFunctionInput: (num: Double) => Promise<Double> = this.defaultFoo
    ): Promise<Double> {
        return await staticFunctionInput(n);
    }

    private async defaultFoo(n: number) {
        return -n;
    }

}

打包函数时，所有静态输入都会在安装过程中显示为函数输入。安装人员随后可以提供自己的函数逻辑来覆盖默认行为。

在被覆盖的静态函数中调用 查询 或 进行 API 调用 不受支持。

自定义别名

自定义别名 用于存储字符串值，例如配置参数、功能标志或特定于环境的设置。当您将带有自定义别名的函数添加到 Marketplace 产品时，这些别名会自动显示为可配置参数，位于 输入。安装人员可以设置特定于环境的值，而无需修改函数源代码。

TypeScript v2 和 Python 函数支持自定义别名。与 静态函数输入不同，自定义别名：

  • 同时适用于 TypeScript v2 和 Python
  • 允许安装人员配置字符串值而非函数逻辑
  • 在 Marketplace 安装体验中支持描述和预设值

有关在函数中定义和使用自定义别名的详细信息，请参阅 自定义别名。

模型别名

您可以通过 模型别名 将引用语言模型的函数添加到 Marketplace 产品中。Marketplace 对这些别名施加了特定的限制。

模型别名在安装过程中无法重新映射。如果别名引用的模型在目标环境中不可用，函数将无法在运行时解析该别名。

与 自定义别名不同，自定义别名在安装过程中会显示为可配置参数，而 Marketplace 会在运行时使用源仓库中配置的确切模型 RID 来解析模型别名。请确保别名引用的模型在产品将要安装的每个目标环境中均可用。

已知问题

Marketplace 函数中的接口输入

接受 接口 作为输入参数的函数可能会抛出 MarketplaceSdkObjectMappingNotFound 目标环境中的错误。Marketplace 要求 SDK 绑定包含具体的对象类型，而不仅仅是接口。

如果函数声明了接口输入，并且目标环境中存在实现该接口的具体类型的对象，则 SDK 将无法找到具体类型的映射。函数随后会在运行时失败。

变通方法： 请确保目标环境中使用的具体对象类型也存在于源环境中，然后在 Marketplace 打包的 SDK 中显式包含该类型。这将生成所需的映射，使函数能够解析并使用该对象类型。
