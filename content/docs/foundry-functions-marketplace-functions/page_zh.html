包含模型函数

您可以将由模型默认分支上的直接部署支撑的模型函数打包。将该函数添加为输出会包含对其模型版本和实时部署的依赖。您也可以通过选择以下选项自动包含该函数 是 位于 打包实时部署 在打包模型时。

安装的函数使用目标环境中的模型和部署。在函数可以提供推理请求服务之前，部署必须处于运行状态。有关打包要求、版本选择和升级行为，请参阅 Marketplace 中的模型函数。有关启动选项，请参阅 实时部署安装.

包含代码仓库的源代码

打包在代码仓库中编写的函数时，支撑仓库将自动作为附加输出包含在产品中。虽然您可以选择将代码仓库与其源代码一起打包，但我们通常不建议为不打算安装在 bootstrap 模式中的产品包含源代码。这是因为通过 Marketplace 安装的函数不需要其支撑源代码即可成功执行。此外，代码仓库不保证可以开箱即用地编译或构建。

如果您想在安装后对函数进行更改（例如修复错误或增强功能），我们建议对原始函数进行更改，发布新版本的 Marketplace 产品，然后升级安装。如果您不是已安装产品的所有者，应联系其维护者并提交错误报告或功能请求。

扩展函数执行要求

使用扩展执行功能的函数有额外的 Marketplace 安装要求。这些功能包括在函数内部调用 操作 以及获取具有延长生存时间 (TTL) 的身份验证令牌。在安装之前，管理员必须将目标项目添加到 扩展函数执行 允许列表中，位于 函数设置 in 控制面板.

有关允许列表的配置说明，请参阅 函数设置.

版本和 API 名称解析

当函数通过 Marketplace 安装时，其版本和 API 名称有两种解析方式：去重模式和稳定模式。

去重模式

这是通过 Marketplace 安装时解析函数版本和 API 名称的历史默认行为。

在去重模式下，函数版本的解析方式如下：

  • 当函数首次由安装创建时，其第一个版本发布于 0.1.0.
  • 在后续安装（例如升级）时，函数将以其最新版本递增一个次要版本发布。例如，如果已安装函数的最新版本是 1.1.0，则下次安装将发布于 1.2.0.

函数版本 是不可变的。换句话说，一旦函数的某个版本发布，就无法对其进行更改或覆盖。

去重是必要的，因为 函数 API 名称 在每个本体论中是唯一的：如果具有 API 名称 myFunction 的函数已存在于某个本体论中，则该本体论中的其他函数不能使用相同的 API 名称。

函数 API 名称的解析方式如下：

  • 如果 API 名称已绑定到安装的本体论中的另一个函数，则将通过附加递增的整数后缀对 API 名称进行去重。例如，如果 API 名称 myFunction 已被占用，则函数将以 API 名称 myFunction1安装。如果该 API 名称也被占用，则将以 API 名称 myFunction2的行开始，依此类推。
  • 一旦 API 名称存在于已安装的函数上，该函数将在后续安装（例如升级）中保持该 API 名称。

稳定模式

测试版

稳定模式处于 测试版 开发阶段，您的注册环境中可能无法使用。在积极开发过程中，功能可能会发生变化。请联系 Palantir 支持团队以在您的注册环境中启用此功能。

版本和 API 名称是函数 API 的重要组成部分。因此，在许多情况下，希望通过 Marketplace 打包和安装时保留它们。在将函数与静态引用函数依赖项的上游应用程序一起安装时，这一点尤为重要，例如在 Developer Console 应用程序中.

稳定模式不支持 计算模块函数 因为这些函数在 Foundry 中有自己的版本控制行为。

在稳定模式下，函数的版本按以下方式解析：

  • 已安装的函数始终以其打包版本发布。
  • 如果已安装函数的版本已存在，将创建一个全新的函数；旧函数将被隐藏，其 API 名称将被移除。

通过创建新函数来解决版本冲突会影响上游应用。如果上游应用属于同一安装的一部分，它将自动更新以引用新函数。否则，您需要手动更新。

函数的 API 名称按以下方式解析：

  • 已安装的函数始终以其打包时的 API 名称发布。
  • 如果该 API 名称已被另一个函数占用，将发生安装错误。要解决此冲突，您必须删除现有函数或更改其 API 名称。

已部署的函数

函数要么以无服务器执行模式运行，要么 部署 到长期运行的容器。Marketplace 会将函数仓库的执行模式与函数本身一起打包，因此已安装的函数的运行方式与其在打包环境中的运行方式相同。

Marketplace 如何打包函数执行模式

函数执行模式是按仓库配置的，Marketplace 会将其打包 一次 适用于由同一部署支撑的所有函数。

对于处于部署模式的仓库，Marketplace 会捕获环境变量、资源请求和限制、扩缩容限制以及其他关键部署配置详情。

Marketplace 不会将容器镜像打包为固定值。相反，容器镜像会在安装期间根据所安装函数的版本进行解析，因此已安装的部署始终运行已安装函数的镜像。

要打包仓库处于部署模式的函数，该仓库必须存在一个部署，并且该部署必须正在运行您要打包的函数版本。如果不是，打包将失败。要解决此问题，请启动或更新部署使其运行您要打包的版本，或将仓库切换为无服务器执行。

Marketplace 如何在安装期间应用配置

当您安装或升级产品时，Marketplace 会将打包的执行模式和部署配置应用到目标环境。这相当于解锁安装并手动配置执行以匹配产品打包时的环境。

如果打包的模式为 部署，Marketplace 会为已安装的仓库创建部署（如果尚不存在），将打包的部署配置应用于该部署，并启动该部署。

如果打包的模式为 无服务器，Marketplace 会将已安装的仓库设置为无服务器执行。如果该仓库已存在部署，Marketplace 将停止安装。

并非每个 enrollment 都支持无服务器函数。如果产品以无服务器模式打包函数，但目标环境不支持无服务器执行，则该函数将以部署模式安装。发生这种情况时，Marketplace 会使用默认配置创建并启动部署。这确保已安装的函数可以作为已部署的函数运行。

计算成本

已部署的函数在部署运行期间会持续产生计算成本，而无服务器函数仅在执行时产生成本。因此，由于目标环境不支持无服务器执行而以部署模式安装的无服务器函数，将承担长期运行部署的计算成本。

Marketplace 中已部署函数的限制

Marketplace 中的已部署函数存在以下限制。

一个函数一次只能部署一个版本

一个部署运行函数的单个版本。当您升级包含已部署函数的 Marketplace 产品时，该函数会以新版本重新发布，并且新版本会自动替换之前部署的版本进行部署。

正在升级的安装之外的产品不会通过该升级进行更新。这包括外部产品以及既未包含在 Marketplace 产品中也不属于 关联产品的产品。如果这些产品引用了已部署函数的特定版本，该引用将继续指向旧版本。由于一次只能部署一个版本的函数，任何对旧版本函数的引用都将返回错误。

为避免此问题，您必须：

  • 将已部署函数的消费者打包在同一个产品中，或打包在 关联产品 中，以便它们与函数一起升级。
  • 尽可能使用无服务器执行。无服务器函数可以按需执行函数的不同版本，因此升级不会使对早期版本的引用失效。

升级期间部署会重启

对支撑已部署函数的长期运行容器所做的某些更改（例如更新其配置的源）无法在该容器运行时应用。因此，每次作为 Marketplace 产品升级的一部分进行升级时，部署可能会被停止并重新启动，这意味着函数可能会经历停机时间。

静态函数输入

此功能仅在 TypeScript v2.

通过提供本地定义的函数来覆盖 Marketplace 产品随附的“静态”函数输入，可以在安装时修改函数行为的某些部分。为此，您可以使用 @Static 装饰器配合使用。

import { Function, Static, Double } from "@foundry/functions-api";

export class MyFunctions {

    @Function()
    public async modifyNumberByStaticFoo(
        n: Double,
        @Static() staticFunctionInput: (num: Double) => Promise<Double> = this.defaultFoo
    ): Promise<Double> {
        return await staticFunctionInput(n);
    }

    private async defaultFoo(n: number) {
        return -n;
    }

}

打包函数时，任何静态输入都会在安装过程中显示为函数输入。安装者随后可以提供自己的函数逻辑来覆盖默认行为。

调用 查询 or 进行 API 调用 在被覆盖的静态函数中不受支持。

自定义别名

自定义别名 存储字符串值，例如配置参数、功能开关或特定环境的设置。当您将带有自定义别名的函数添加到 Marketplace 产品时，这些别名会自动显示为 输入下的可配置参数。安装者可以设置特定环境的值，而无需修改函数源代码。

自定义别名在 TypeScript v2 和 Python 函数中受支持。与 静态函数输入不同，自定义别名：

  • 同时适用于 TypeScript v2 和 Python
  • 允许安装者配置字符串值而非函数逻辑
  • 在 Marketplace 安装体验中支持描述和预设值

有关在函数中定义和使用自定义别名的详细信息，请参阅 自定义别名.

模型别名

您可以通过 模型别名 将引用语言模型的函数添加到 Marketplace 产品中。Marketplace 对这些别名施加了特定限制。

模型别名在安装期间无法重新映射。如果别名引用的模型在目标环境中不可用，函数将在运行时无法解析该别名。

与 自定义别名不同（自定义别名在安装期间显示为可配置参数），Marketplace 在运行时使用源仓库中配置的确切模型 RID 来解析模型别名。请确保别名引用的模型在产品将要安装的每个目标环境中都可用。

已知问题

Marketplace 函数中的接口输入

接受 接口（interfaces） 作为输入参数的函数可能会在目标环境中抛出 MarketplaceSdkObjectMappingNotFound 错误。Marketplace 要求 SDK 绑定包含具体的对象类型，而不仅仅是接口。

如果函数声明了接口输入，而目标环境包含实现该接口的具体类型的对象，SDK 将无法找到具体类型映射。该函数随后会在运行时失败。

解决方法： 确保目标环境中使用的具体对象类型在源环境中也存在，然后在 Marketplace 打包的 SDK 中显式包含它。这将生成所需的映射，使函数能够解析并使用该对象类型。
