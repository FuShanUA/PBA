监控审计日志

有效的安全监控依赖于全面、及时的审计日志。本指南介绍如何摄取和分析 Foundry 审计日志，以保持对用户活动的监督、检测安全事件，并确保符合组织政策。

概述

审计日志会捕获在 Foundry 中执行的每项操作的关键信息，使您能够了解：

  • 谁 执行了操作（用户身份、会话或令牌）。
  • 什么 操作（按类型和意图分类）。
  • 何时 发生了操作（带有精确的时间戳）。
  • 何地 发生了操作（涉及哪些资源）。

这些日志可能包含上下文信息，其中包括姓名和电子邮件地址等个人身份信息（PII）。应仅限具有相应安全资质的人员访问。

审计日志交付

Foundry 提供灵活的交付机制，以支持多样化的安全基础设施和安全信息与事件管理（SIEM）需求。

选择您的交付方式

对于外部 SIEM 集成（仅限audit.3 ，首选）： 外部 SIEM 可以持续轮询 audit.3 日志，直接使用 Palantir 的审计 API 端点。其中， list-log-files 端点 列出按日期范围筛选的可用日志文件，而 get-log-file-content 端点 检索特定日志文件的内容。对于设有专门安全运营中心并已建立成熟 SIEM 平台的组织，首选此方法，其低延迟特性有助于实现及时的检测和响应。

对于基于 Foundry 的分析： 对于没有专用 SIEM 工具的组织或分析需求较轻的组织， audit.2 和 audit.3 日志均可导出到各组织专属的 Foundry 数据集。组织管理员会在设置过程中配置目标文件系统位置。导出后，可直接在 Foundry 中分析日志，或通过 Foundry 的 Data Connection 应用程序将日志转发到外部 SIEM。

请参阅我们的 审计交付 文档，以了解详细的 API 端点信息和导出设置说明。

数据完整性

审计日志从生成到存储所流经的基础设施在设计上为仅追加（append-only），以确保审计轨迹的完整性。对日志归档存储的访问受到严格限制。如果出于法律目的必须删除审计日志中捕获的信息，您可以直接与 Palantir 支持团队合作，确定补救方案，以就地清除审计日志存储中疑似不允许的数据。

常见监控用例

摄取审计日志后，安全和合规团队通常会重点关注以下各节中所述的主题。

安全监控与事件响应

检测并响应潜在的安全事件，包括以下内容：

  • 账号失陷： 异常的登录模式、地理位置异常或不可能行程场景。
  • 数据外泄尝试： 大规模数据加载后随即进行导出，尤其是在正常工作时间之外。
  • 权限提升： 意外的权限变更或访问超出正常范围的资源。
  • 恶意代码执行： 以可疑模式执行或来自意外来源的代码。

调查工作流示例：

安全分析师收到关于某个用户账号异常访问数据的警报。使用 audit.3 按类别筛选的日志：

  1. 查询某个 time 筛选器内的所有日志，其中 categories 包含 dataLoad ，以定位相关用户。
  2. 检查 resultFields ，以确定具体访问了哪些数据集。
  3. 查询 categories 包含 dataExport 的日志，以验证是否实际导出了任何数据。
  4. 查看 users 和 entities 字段，以了解完整的活动时间线。
  5. 联系该用户以了解业务背景，并判断相关活动是否正当。

结构化的审计日志类别使分析师无需了解具体要搜索哪些 Foundry 服务或事件名称；分析师可以专注于理解行为，而无需费力了解系统架构。

问责与合规

对于处理敏感或受监管数据的组织：

  • 访问审计： 验证数据仅在批准范围内且出于正当目的被访问。
  • 权限滥用检测： 识别授权用户何时超出其预期访问模式。
  • 监管合规： 通过全面的审计追踪证明遵守数据保护法规。
  • 法律保留支持： 快速检索特定用户或数据资产的完整活动记录。

合规工作流示例：

合规团队需要验证患者数据导出是否仅发生在具有相应培训认证的用户身上：

  1. 查询特定 time 筛选条件下的所有日志，其中 categories 包含 dataExport ，且资源与患者数据集匹配。
  2. 将 uid 字段与内部认证记录进行交叉核对。
  3. 设置持续监控，以便在用户执行任何导出操作时发出警报。
  4. 生成定期合规报告，展示所有数据访问和导出活动。

使用审计类别

审计日志被组织为 审计类别 ，这些类别按意图和操作类型对相关事件进行分组。类别提供了一种与产品无关的方式来识别相关事件；例如， dataExport 类别会捕获所有数据导出事件，无论执行导出的是哪个 Foundry 应用程序。

这种抽象使安全分析师无需深入了解 Foundry 的内部架构即可分析用户行为。例如，在调查潜在的数据外泄时，只需筛选 dataExport ，而无需枚举数十个特定于产品的事件名称。安全监控和合规工作流中常用的类别可能包括以下内容：

类别描述示例用例
authenticationCheck通过程序化或手动身份验证事件（例如令牌验证）来检查身份验证状态。检测可能表明撞库攻击的令牌验证模式。
dataCreate表示向平台中添加了之前不存在的某些新数据条目。此事件可能会以 dataPromote 的形式反映在单独的服务中（前提是该事件已被记录在落地服务中）。跟踪数据创建模式并执行治理策略。
dataDelete与数据删除相关，与删除的粒度无关。对关键或受保护资源的删除发出警报。
dataExport从平台导出数据。用于从平台下载数据之类的操作，例如下载到 Palantir 外部的系统、CSV 文件等。如果数据已导出到另一个 Palantir 系统，请使用 dataPromote category.对大规模导出、敏感数据导出或工作时间之外的导出发出警报。
dataImport导入到平台。与 dataPromote不同， dataImport 仅指从平台外部摄取的数据。这意味着，一个服务中的 dataImport 可能会以 dataPromote 的形式出现在单独的服务中。监控恶意文件上传或策略违规行为。
dataLoad指加载将返回给用户的数据。对于纯后端加载，请使用 internal。建立基准正常访问模式，并检测异常的批量数据访问。
tokenGeneration导致生成新令牌的操作。检测异常的令牌创建，这可能表明正在为批量数据访问做准备。
userLogin用户的登录事件。监控失败的登录尝试、异常登录时间或地理位置异常。
userLogout用户的注销事件。跟踪会话持续时间并识别异常长的会话。

有关包含详细字段规范的可用类别完整列表，请参阅我们完整的 审计日志类别文档。

性能提示： 审计日志数据集可能包含非常大量的数据。请务必先使用 time 列进行筛选，然后再执行聚合或可视化操作，以确保查询的高性能。

构建基于类别的查询

审计日志类别支持功能强大且易于维护的查询，可在所有 Foundry 产品中通用。用伪代码表示如下：

监控所有导出活动：

categories contains "dataExport"

调查潜在的凭据泄露：

categories contains "authenticationCheck" AND result = "FAILURE" 
GROUP BY uid
HAVING COUNT(*) > 5

跟踪敏感资源上的权限变更：

categories contains "managementPermissions" AND resource_id IN (sensitive_resource_list)

基于类别的方法可确保即使在添加新功能时查询仍然有效。我们开发的新导出功能将使用 dataExport 类别，而无需更新您分析中的查询。

审计监控的最佳实践

建立基准行为

在实施自动告警之前，请先为正常活动建立基准：

  • 每个用户或用户组的典型登录时间和位置。
  • 正常的数据访问模式（涉及哪些数据集、访问频率、数据量）。
  • 预期的导出行为（目的、时间、数据量）。
  • 标准权限变更工作流。

异常只有在特定上下文中才有意义。了解正常的行为模式和平台使用情况，才能实现高保真告警，并将误报降至最低。

实施纵深防御

分层部署多种检测机制：

  • 实时告警 用于关键安全事件（登录失败、敏感数据导出）。
  • 定期分析 用于趋势和模式检测（异常访问增长、权限漂移）。
  • 事件响应流程 用于调查告警和协调响应。
  • 定期审计 用于验证监控覆盖范围和告警有效性。

针对性能进行优化

在处理大型审计数据集时：

  • 始终先按 time 范围进行过滤，以减少数据量。
  • 在查询管道中尽早使用 categories 过滤器，然后再检查详细字段。
  • 在您的 SIEM 或分析平台中预先配置/索引常用的过滤字段。

与 Palantir CIRT 协调

作为 Foundry 的 共享安全模型的一部分，Palantir 的计算机事件响应团队（CIRT）会监控托管客户平台的安全威胁。CIRT 维护着一套 告警与检测策略 ↗ ，专门针对我们托管客户平台上的活动。如果 CIRT 在您的平台上发现可疑活动，将会联系您以核实该活动。

我们鼓励客户根据自身对正常用户行为的理解和组织安全要求，实施自己的审计日志监控；您拥有领域知识，能够识别平台级监控无法检测到的异常。只有您才能确保平台的使用是恰当的，并符合您自身的政策和义务。

入门

对于新的实施项目，请遵循以下步骤，这些步骤将在本文档中详细讨论：

  1. 选择交付方式： 在直接 API 摄取（适用于现有 SIEM 基础设施）与 Foundry 导出（适用于平台内分析）之间进行选择。
  2. 配置 API 访问或 Foundry 导出： 请按照您所选方法的设置说明进行操作。
  3. 确定优先类别： 确定哪些类别符合您的安全和合规要求。
  4. 构建初始查询： 首先使用基于类别的宽泛过滤器，然后再添加具体的字段条件。
  5. 建立基线： 对历史数据运行查询，以了解正常的活动模式。
  6. 实施告警： 为高优先级安全事件配置警报。
  7. 迭代和优化： 根据运维经验调整警报阈值，并添加新的检测规则。
