环境创建概述

这是一份详细介绍环境初始化流程的高级指南，面向对可能影响初始化性能的技术因素感兴趣的用户。有关环境相关常见问题的一般性指导，请参阅 环境故障排除指南.

Conda 是一个开源的、与语言无关的包和环境管理器。Mamba 是 Conda 包管理器的开源重新实现。Hawk 是 Palantir 开发的 Conda 包管理器的重新实现。Code Repositories 在 Commit 之后运行 Checks 时使用 Hawk 来解析包依赖。Hawk 在包解析方面相比 Mamba 和 Conda 具有多项优势，最显著的是速度更快，并且有持续的维护和开发。

本页面介绍了最重要的概念并概述了环境创建流程；欲了解更多信息，请查阅 官方 Conda 文档 ↗ 和 Mamba 文档 ↗.

重要术语

包

A 包 是文件集合，通常包含元数据、库和/或二进制文件。Code Repository 提供对大量可选包（numpy，例如）的访问，以补充核心语言功能。

包是 有版本控制的，并且几乎总是有一组依赖项——即必须同时安装才能使其正常运行的其他包。依赖项可能是包的特定版本、可接受的版本范围，或任意版本。

渠道

A 渠道，有时也称为仓库，是存储包的任何位置。一个渠道可以是本地文件系统中的目录，另一个渠道可以是托管在网络服务器上的目录。

无论类型如何，每个渠道都是一棵按平台架构分隔包的目录树。每个平台子目录都包含一个名为 repodata.json的文件，它是该子目录中所有包的索引。

Conda 在需要获取包时会搜索一组预配置的频道。有关 Foundry 中频道管理的更多信息，请参阅 包文档.

环境

Conda 环境 是包含特定包集合的目录。通过将 软件包标签页 到 Conda。Conda 会构建一组满足配置及所有依赖关系的软件包，并将这些软件包安装到您的转换运行所在的环境中。

性能

  • 创建环境
  • 局限性

创建环境

环境创建包含两个主要步骤： 解析步骤 和 安装步骤.

解析步骤

在监听器设置向导的 解析步骤，指定的软件包管理器（Conda、Mamba 或 Hawk）会尝试找到满足所有传递依赖关系的软件包和版本。传递依赖关系包括软件包标签页中指定的软件包的依赖关系、这些依赖关系的依赖关系，依此类推。此步骤包含四个阶段：

  1. 下载并处理包索引。包管理器将从每个已配置的频道下载相关的 repodata.json 文件，并将索引条目转换为内存中的对象。
  2. 缩减索引。包管理器会构建一个包含可能用于该环境的所有包的集合。为此，算法从提供的包规范开始，递归遍历所有依赖。所有不需要的包——主要是那些不在依赖图中的包——都会被剪除。
  3. 将依赖约束表示为布尔可满足性（SAT）问题。包管理器偏好某些类型的解，例如尽可能新的包版本，这些偏好会被写入子句构建中。
  4. 运行 SAT 求解器。

安装步骤

如果求解成功， 安装步骤 是下一步。在此步骤中，每个构件都会从相应的通道中检索，包管理器使用这些构件来构建环境。此步骤包含三个阶段：

  1. 下载并解压已解析环境中的所有包。
  2. 验证软件包内容。根据配置的不同，Conda 会使用校验和，或者验证文件大小是否正确。
  3. 将包链接到环境中。

局限性

在某些情况下，上述所有步骤都可能出现缓慢。导致缓慢的原因通常属于以下三类之一：

  • 上游变更
  • 环境规范
  • 软件包大小

上游变更

相当一部分缓慢是由 Foundry 之外的因素造成的。

  • 下载和处理通道索引的耗时随索引文件的总大小而增加；需要考虑的通道越多、这些通道越大，这些步骤所需的时间就越长。
  • 索引缩减也随传递依赖项的数量而增加；传递依赖项的数量取决于软件包选择声明哪些依赖项。

由于这些因素是外部且不透明的，因此对性能退化进行根因分析可能比较困难。某个环境可能突然需要更长的加载时间，原因可能是某个通道最近变大，或者某个软件包在其最新版本中声明了多个新依赖项。

环境规范

更常见的情况是，初始化缓慢与 环境规范 本身直接相关。求解步骤的耗时随环境大小呈超线性增长，因此作为一般经验法则，包含更多软件包的环境初始化所需的时间会不成比例地更长。

有两种方法可以缓解这些情况。

  • 首先，从环境定义中移除不需要的软件包。小型、专用的环境比大型、通用的环境性能要好得多。
  • 其次，尝试在软件包标签页中为某些软件包添加版本约束。对于具有许多现有构建版本的软件包（如 python ）以及具有复杂依赖关系图的包（如 scipy）固定版本最为有效。这样做可以让 Conda 更激进地缩减索引，这意味着 SAT 求解不需要考虑那么多的软件包版本。

软件包大小

软件包大小 通常比本节中的其他因素问题更小，但在某些情况下仍然相关。

即使只下载和解压单个软件包也可能并非易事。例如， pytorch 软件包的大小约为 460 MB，解压可能需要 35 秒以上。

下载、解压和验证的耗时都随环境中软件包的大小和数量呈线性增长。由于传递依赖项的存在，求解后的环境通常包含比环境定义中明确指定的多得多的软件包，软件包的增加可能导致缓慢。

这种情况下的缓解方法与针对 环境规范的建议类似：尽量保持环境尽可能小。
