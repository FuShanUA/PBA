部署应用程序

本页面将逐步介绍如何将 Pilot 应用程序部署到生产环境。部署是一个引导式三步流程，由 Pilot 部署面板进行管理。有关构建应用程序的信息，请参阅 构建应用程序。部署自定义小部件的流程有所不同：Pilot 会将小部件发布到 Widget Registry，而不是通过 Developer Console 进行发布。请参阅 部署自定义小部件。

部署需要项目、组织和注册级别的权限。您至少需要 Editor 角色（项目级）和 Third-party application administrator 角色（在 Control Panel 中创建 Developer Console 应用程序所需），以及一名注册管理员来批准子域名请求。有关详情，请参阅下文的相关章节；如果遇到权限错误，请联系您的管理员。

编辑器视图和部署视图

Pilot 有两种视图，用于控制应用程序显示哪些数据，可在工作区右上角进行切换。

有关编辑器视图和部署视图的概述，请参阅 工作区概述。

在编辑器视图中，Pilot 会显示在 Pilot 容器内生成的种子数据。如果您的应用程序在部署视图中显示为空，请验证本体论实体是否已在某个分支上创建，以及支撑数据集是否包含数据。

当您在部署视文中预览应用程序时，如果是在 Main，您正在查看并操作生产数据。您在应用程序中执行的任何操作（例如创建或编辑对象）均为本体论编辑，会立即生效。在部署分支上预览时，本体论编辑的作用范围仅限于该分支，不会传播到 Main。

检查可部署性

在开始部署流程之前，请确认您的应用程序已准备好部署。选择工作区右上角的状态指示器以打开状态监控弹出窗口。该 可部署性 状态必须为 Deployable ，然后才能创建分支。

常见的可部署性阻碍因素包括：

  • 无效的本体论实体： 存在配置错误的对象类型或操作类型，例如缺少必需属性或引用了不存在的实体
  • 过时的软件包依赖项： 需要在部署前升级的依赖项
  • 构建错误： 应用程序代码中的编译或运行时错误

要解决阻碍因素，请选择三点菜单（...），该菜单位于 可部署性 状态旁，然后选择 使用 Pilot 修复。Pilot 会诊断该问题并自动应用修复。如果该问题仍然存在，您可以在聊天面板中提示 Pilot 来描述并解决该问题。

开始部署

选择 部署 （位于 Pilot 工作区右上角）以打开部署面板。该面板包含三个步骤：

  1. 实现本体论实体
  2. 配置应用和子域名
  3. 通过所有 CI 检查

1. 实现本体论实体

在 Pilot 容器中创建的本体论变更必须先提升到主本体论，生产应用才能使用它们。Pilot 使用 全局分支 来完成此过程。全局分支让您能够在隔离的分支上进行本体论变更，使用真实数据对其进行测试，然后合并到 Main ，在您准备好之前不会影响生产环境。

创建部署分支

在 实现本体论实体 步骤中，Pilot 会显示需要在分支上创建哪些实体，包括对象类型、操作类型和关联类型。

  1. 选择 创建分支 以生成包含这些本体论变更的部署分支。
  2. 输入分支名称并确认。

创建完成后，Pilot 会将本体论定义推送到该分支并开始索引。索引使对象类型和操作在该分支上可用，因此您可以在部署视图中使用真实数据预览应用并执行操作，然后合并到 Main。

如果分支创建失败，请验证 可部署性 状态为通过。请检查本体论选项卡中是否还有需要解决的 Pilot 编辑。您也可以尝试使用其他名称创建新分支。

通过 Global Branching 进行审阅和合并

创建分支后，请审阅并合并本体论更改。

  1. 选择 查看分支 以打开 Global Branching，您可以在其中查看分支上的资源及其状态。
  2. 选择 创建提案 并输入提案名称和可选描述。
  3. 选择 创建 以提交提案。
  4. 检查通过后，选择 合并提案 以将本体论实体应用到 Main。

根据您的注册配置，提案审批可能会自动完成，也可能需要由具有相应权限的用户进行手动审核。

合并完成后，Pilot 会提示您切换回 Main。该 实现本体论实体 步骤随后会将所有实体显示为最新状态。

2. 配置应用程序和子域

在本体论实体位于 Main上后，您就可以配置将为生成的 UI 提供服务的托管应用程序。

创建 Developer Console 应用程序

在 配置应用程序和子域 步骤中，选择 配置应用程序。此时会出现一个对话框，其中包含以下字段：

  1. Developer Console 应用程序名称： Pilot 会建议一个与您的 Pilot 项目相关联的名称。
  2. 组织： 选择应用程序所属的组织。
  3. 子域： 为您的应用程序选择一个子域。Pilot 会检查其可用性，生成的 URL 遵循以下模式 <subdomain>.<enrollment>.palantirfoundry.com。

选择 创建应用程序 以继续。Pilot 会创建 Developer Console 应用程序记录并定义应用程序的限制，自动包含相关的对象类型和操作类型。

创建 Developer Console 应用程序需要特定权限。详情请参阅 Developer Console 权限。

批准子域请求

子域注册需要通过 Control Panel 进行审批。注册管理员必须导航至 Control Panel > Approvals 并完成以下操作：

  1. 查看子域请求的详细信息，包括 Foundry 域、所请求的子域以及托管的应用程序。
  2. 选择 批准。

批准后，托管域即会注册并映射到 Developer Console 应用程序。返回 Pilot 后， 配置应用程序和子域 步骤会确认应用程序的限制是否为最新。

子域审批时间因注册而异。如果您因等待审批而受阻，请联系您的注册管理员。在某些注册中，子域注册可能需要额外的安全审查。

3. 运行 CI 检查并发布

实现本体论实体并配置 Developer Console 应用程序后，您即可生成部署文件并发布应用程序。

生成部署文件

在 通过所有 CI 检查 步骤中，选择 生成部署文件以启用检查。Pilot 会在您的仓库中生成 CI 和环境配置文件，包括：

  • .env.production
  • ci.yml
  • foundry.config.json
  • 附加的构建和设置脚本

然后，Pilot 会使用生成的配置构建可用于生产环境的工件。CI 检查将自动开始。

CI 检查失败

如果 CI 检查失败，请尝试以下操作：

  1. 选择 生成部署文件 以重新生成配置文件。这样可以解决部署配置过时导致的问题。
  2. 切换到编辑器视图，并提示 Pilot 修复构建错误。例如， The CI checks are failing. Can you check the build output and fix any errors?
  3. 在 Pilot 应用修复后，切换回部署视图并选择 生成部署文件 以重新触发 CI 检查。

打标签并发布

当 CI 检查通过后，您可以为应用程序打标签并发布。

  1. 选择 打标签并发布。
  2. 在 打标签并发布 对话框中：
    • 确认 分支 或特定提交。
    • 选择版本类型： 补丁 用于向后兼容的修复， 次要 用于增量变更， 主要 用于破坏性变更，或 自定义 用于自定义标签。
    • 选择 打标签并发布 以开始发布。

Pilot 会跟踪发布进度，并在创建标签后显示确认信息。

打开您的生产应用程序

部署完成后，Pilot 会显示 “应用部署成功！” ，并附带指向 “查看应用”。选择 View app 以在您的子域中打开新部署的应用程序。

首次访问时，系统会显示 OAuth 同意屏幕。选择 Allow 以授予 Developer Console 应用程序访问所需本体论实体和媒体数据集的权限。随后您将进入生产应用程序，该应用程序通过本体论对真实数据进行操作。

部署之后

应用程序部署完成后，您可以继续在 Pilot 中进行迭代。

  1. 切换到 Editor 视图，并通过后续提示进行更改，就像您在初始构建期间所做的那样。
  2. 当您准备好发布更新时，切换到 Deploy 视图。
  3. 如果您的更改包含新增或修改的本体论实体，请创建新分支或重置现有分支，通过 Global Branching 进行合并，并标记新版本。
  4. 如果您的更改仅涉及代码（不修改本体论），请生成新的部署文件并直接标记新版本。

您的生产应用程序始终使用来自本体论的真实数据。Pilot 容器中的种子数据永远不会被部署，也无法在生产应用程序中访问。
