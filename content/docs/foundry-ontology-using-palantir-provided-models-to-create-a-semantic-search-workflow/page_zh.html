使用 Palantir 提供的模型创建语义搜索工作流

要使用 Palantir 提供的语言模型， 必须先在您的租户中启用 AIP。此外，您还必须拥有使用 AIP 开发者功能的权限。使用自定义模型？请改为查看 使用自定义模型创建语义搜索工作流 。

本页介绍了构建概念性端到端语义搜索工作流的过程，其中使用了 Palantir 提供的嵌入模型。

操作说明

首先，您需要生成嵌入向量，并将其存储在具有 vector 类型的对象类型中。然后，您可以在 Workshop中设置语义搜索工作流，构建一个 AIP Chatbot Workshop 小部件 解决方案，或创建一个自定义语义搜索函数，用于 Workshop 和 AIP Logic。

前提条件：

  • 生成嵌入向量并创建对象类型

选项：

  • 在 Workshop 中使用 KNN 对象集创建简单的语义搜索工作流（无代码）
  • 使 AIP Chatbot 能够对对象进行语义搜索（无代码）
  • 创建一个跨对象进行语义搜索的函数，供 Workshop 和/或 AIP Logic 使用

生成嵌入向量并创建对象类型

我们将使用 Pipeline Builder 将数据集中的文本嵌入为向量，其中会用到 Text to Embeddings 表达式。该表达式接受一个字符串，并使用 Palantir 提供的模型之一将其转换为向量；在本例中，这是 text-embedding-ada-002 嵌入模型。

然后可以将这些嵌入作为向量属性添加到本体论中。

如果您希望更好地控制使用 Palantir 提供的模型生成嵌入的过程，请参阅 Python 转换中的语言模型。

使用 KNN 对象集在 Workshop 中创建简单的语义搜索工作流（无代码）

KNN 对象集无法按相关性排序。如果需要有序的结果，请使用 函数方法 （搭配 TypeScript v1 或 TypeScript v2）。两个版本均支持按相关性排序。

配置 KNN 对象集 （在 Workshop 中）是构建语义搜索工作流的一种简单无代码方式。

  1. 创建一个对象集 变量 ，并选择包含嵌入属性的对象类型。
  2. 选择筛选器 + On a property 选项，然后从菜单中的属性列表中选择您的嵌入属性。
  3. 选中后，应会出现 K 近邻配置。如果未出现此配置，请确认您选择的属性是嵌入属性。

在此面板中，您可以配置：

  • K 值： 一个介于 1-100 之间的数字，用于指定语义搜索返回的对象数量。
  • 查询： 执行语义搜索时用作查询的字符串变量。
  1. 接下来，创建一个 文本输入 小部件，并将其输出变量添加到上文所示的 KNN 查询选项中。
  2. 最后，添加一个 对象表 小部件，并将其输入变量配置为新创建的 KNN 对象集。

如需自定义程度更高的语义搜索逻辑，请参阅 关于函数的章节。

使用 AIP Chatbot（无代码）

在 AIP Chatbot Studio 中创建的 AIP Chatbot（前身为 AIP Agents）非常适合开始对您的对象进行语义搜索，因为它们不需要任何代码。详细了解 如何整合语义搜索并对功能进行更多控制。

请按照 入门 指南中的说明创建一个 AIP Chatbot，并添加 本体论上下文 或一个 本体论语义搜索 工具。此初始设置将使您能够要求 AIP Chatbot 对对象进行语义搜索。

创建一个函数来跨对象进行语义搜索，以供 Workshop 和/或 AIP Logic 使用

创建一个 函数仓库 以及一个用于查询您的对象类型的函数。目标是获取用户输入并运行 KNN 搜索 在对象类型上。在 TypeScript v1 中，首先使用同一个 Palantir 提供的模型生成向量 先前使用的。要了解如何将 Palantir 提供的模型导入 TypeScript v1 函数，请参阅 TypeScript v1 函数中的语言模型。TypeScript v2 和 Python 接受文本形式的查询，如下所述。

为函数启用向量属性

在继续操作之前，请确保该条目 "enableVectorProperties": true 存在于 functions.json 文件中，该文件位于你的 Functions 代码仓库中。如果此条目不存在，请将其添加到 functions.json 并提交该更改以继续。如果需要进一步的帮助，请联系你的 Palantir 代表。

该 functions.json 配置文件是 TypeScript v1 仓库的工件。对于 TypeScript v2 或 Python 仓库，文档中并未记录等效的向量属性设置，因此请勿假定此条目对它们同样适用。如果在 TypeScript v2 或 Python 仓库中 KNN 搜索失败，请联系你的 Palantir 代表。

语义搜索函数示例

本节中的代码示例适用于 TypeScript v1、 TypeScript v2和 Python 函数；请选择与你的函数版本相匹配的选项卡。TypeScript v1 将每个函数定义为导出类上的方法，并将 @Function() 装饰器（来自 @foundry/functions-api ）应用于该方法，并查询本体论，通过 Objects.search()。TypeScript v2 使用 export default来定义函数，从 @osdk/functions导入类型，并通过作为参数传入的 Ontology SDK 客户端来查询本体论。Python 使用 @function 装饰器，并在函数体内构造 Ontology SDK 客户端。如需完整对比，请查阅 TypeScript v1 与 TypeScript v2 的对比。

这三个版本的区别在于查询嵌入向量在何处生成，以及函数必须在何处定义：

  • TypeScript v1 使用 Palantir 提供的嵌入模型对查询本身进行嵌入，然后将得到的向量传递给 nearestNeighbors。该函数是导出类中的一个方法，按照惯例定义在 functions-typescript/src/index.ts中。
  • TypeScript v2 将用户文本直接传递给 nearestNeighbors，它既可以接受查询向量，也可以接受查询文本。无需单独进行嵌入调用，因此两步工作流程合并为一步。该函数必须是 typescript-functions/src/functions 目录中某个文件的默认导出，且文件名必须与函数名一致；请查阅 编写函数 以了解完整要求。
  • Python 同样通过 nearest_neighbors以文本形式接受查询。该方法是一项 Beta 功能，因此函数使用 @function(beta=True)进行声明。

将嵌入作为单独的步骤来生成，正如 TypeScript v1 示例中使用 TextEmbeddingAda_002.createEmbeddings，没有文档记录的 TypeScript v2 等效实现。此工作流无需该实现，因为查询文本会在 KNN 搜索过程中被嵌入。若要出于其他目的在 TypeScript v2 或 Python 函数中直接调用 Palantir 提供的模型，请参阅 TypeScript v2 和 Python 函数中的语言模型。

不同 TypeScript 版本之间的邻居数量限制有所不同。TypeScript v1 将 k 值限制在 0 < K <= 100，而 TypeScript v2 的 numNeighbors 参数接受的值范围为 1 到 500。

TypeScript v1 使用单独的 .orderByRelevance() 调用来对匹配结果进行排序，然后取前 k 个结果。TypeScript v2 通过将 $orderBy: "relevance" 传递给 fetchPage()来请求按相关性排序。Python 没有文档记录的等效实现；取而代之的是，结果由传递给搜索的邻居数量来限定。Python nearest_neighbors 方法返回的对象还带有 _score 字段。

下方的 TypeScript v2 和 Python 示例接受与 TypeScript v1 示例相同的查询文本和邻居数量，并返回最近的对象。此外，TypeScript v2 函数还会接收一个本体论 SDK 客户端作为其第一个参数。

在下方每个代码片段中，将每一处 ObjectApiName 都替换为您独有的对象类型。该标识符有时可能显示为 objectApiName ，且首字母为小写。

import { Function, Integer } from "@foundry/functions-api";
import { Objects, ObjectApiName } from "@foundry/ontology-api";
import { TextEmbeddingAda_002 } from "@foundry/models-api/language-models"

export class MyFunctions {
    @Function()
    public async findRelevantObjects(
        query: string,
        kValue: Integer,
    ): Promise<ObjectApiName[]> {
        if (query.length < 1) {
            return []
        }
        const embedding = await TextEmbeddingAda_002.createEmbeddings({inputs: [query]}).then(r => r.embeddings[0]);

        return Objects.search()
                    .objectApiName()
                    .nearestNeighbors(obj => obj.embeddings.near(embedding, {kValue: kValue}))
                    .orderByRelevance()
                    .take(kValue);
    }
}

import { Client, Osdk } from "@osdk/client";
import { Integer } from "@osdk/functions";
import { ObjectApiName } from "@ontology/sdk";

export default async function findRelevantObjects(
    client: Client,
    query: string,
    kValue: Integer,
): Promise<Osdk.Instance<ObjectApiName>[]> {
    if (query.length < 1) {
        return [];
    }

    // nearestNeighbors embeds the query text, so no separate embedding call is needed.
    const page = await client(ObjectApiName)
        .nearestNeighbors(query, kValue, "embeddings")
        .fetchPage({ $pageSize: kValue, $orderBy: "relevance" });

    return page.data;
}

from functions.api import function, Integer
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.objects import ObjectApiName


@function(beta=True)
def find_relevant_objects(query: str, k_value: Integer) -> list[ObjectApiName]:
    if len(query) < 1:
        return []

    client = FoundryClient()
    # nearest_neighbors embeds the query text, so no separate embedding call is needed.
    return list(
        client.ontology.objects.ObjectApiName.nearest_neighbors(
            query=query,
            num_neighbors=k_value,
            vector_property=ObjectApiName.object_type.embeddings,
        )
    )
