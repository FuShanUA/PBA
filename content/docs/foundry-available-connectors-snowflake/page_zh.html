托管在 S3 上的 Snowflake 实例

如果您的 Snowflake 实例配置为通过 VPCE ↗路由内部 S3 暂存区流量，则必须手动配置 Snowflake JDBC 驱动程序以 不 使用自定义 VPCE 域。否则，驱动程序将被路由到自定义 VPCE 域（从 Foundry 的 VPC 无法访问该域），并且将无法连接到以下格式的 URL <bucketname>.bucket.vpce-<vpceid>.s3.<region>.vpce.amazonaws.com.

您可以在实例的 连接详情 中添加一个 JDBC 连接属性来手动配置此项，键为 S3_STAGE_VPCE_DNS_NAME ，值字段为空（相当于将其设置为 null）。 然后，S3 暂存区流量将通过 AWS S3 网关端点（<bucketname>.bucket.s3.<region>.vpce.amazonaws.com）进行路由，该端点可保持私有连接，因此流量不会通过公共互联网路由。

请查阅我们的 PrivateLink 出口流量文档 ↗ 的文档以获取更多信息。

对于依赖于与您的 Foundry 实例位于同一区域的 S3 存储桶的出口策略，请确保您已完成我们的 Amazon S3 存储桶策略文档 中详述的针对受影响存储桶的额外配置步骤。

托管在 Azure 上的 Snowflake 实例

Foundry Snowflake 连接器所使用的 Snowflake JDBC 驱动程序在获取数据时，可能会尝试直接连接到底层的“内部暂存区”存储桶。对于托管在 Azure 上的 Snowflake，由于 Azure 托管的 Foundry 注册通过 Azure 服务端点路由流量，因此必须按照以下说明明确允许从 Foundry 到底层暂存区存储桶的网络连接。

收集有关您的 Snowflake 仓库的所需信息

您将需要以下有关 Azure 托管的 Snowflake 仓库的信息，以建立与 Foundry 的网络连接：

  • 完整的 系统允许列表域名.
  • 您的 Azure 存储账户标识符，从 Snowflake 获取。
系统允许列表域名

使用直方图中的 SYSTEM$ALLOWLIST 命令，以获取成功连接可能需要的完整域名列表。

  • 注意：这与上文用于定义出口策略的命令相同，并在 Data Connection 的网络面板标注中进行了说明。
  • 此列表将包含用作您的 Snowflake 仓库暂存区的 Azure 存储桶的域名。
Azure 存储账户标识符

对于从 SYSTEM$ALLOWLIST 命令返回的 Azure 存储桶，您还需要检索存储账户标识符。

  • 如果您使用的是 Snowflake 标准版或企业版，则需要向 Snowflake 支持提交工单以请求存储账户标识符。
  • 如果您使用的是 Snowflake Business Critical Edition ↗，则可以通过以下步骤检索存储账户标识符：
    • 为该账户设置 ENABLE_INTERNAL_STAGES_PRIVATELINK ↗ 参数的值修改为 TRUE 。
    • 然后，调用 SYSTEM$GET_PRIVATELINK_CONFIG() ↗ 函数，该函数返回一个名为 privatelink-internal-stage 的字段，其中包含 Azure 存储账户资源标识符。
      • 即使您未通过 PrivateLink 进行连接，您仍需要检索并提供存储账户资源标识符。

完整的 Azure 存储账户资源标识符将采用以下格式：

/subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}/providers/Microsoft.Storage/storageAccounts/{storageAccountName}

有关如何直接在 Azure 控制台中查找 Azure 存储账户资源 ID 的更多信息，请参阅 Azure 文档 ↗。使用 VNET 规则和存储账户标识符来限制跨账户网络流量符合 Microsoft 发布的最佳实践 ↗，并且应用于从 Azure 计算实例内部连接到 Azure 托管的 Snowflake 仓库的所有连接。

允许从 Foundry 到与您的 Snowflake 仓库关联的 Azure 存储账户的出站流量

现在您已经收集了有关 Snowflake 仓库的所需信息，您可以创建必要的策略，以使 Foundry 能够访问您的 Snowflake 数据。

  1. 创建一个 标准出站策略 用于 Azure 存储内部暂存区，并将其附加到您的 Snowflake 源。

    • 您应为该命令返回的所有内容添加策略 SYSTEM$ALLOWLIST ，而不仅仅是存储桶域名。

  2. 创建一个 Azure 存储策略，并粘贴存储账户资源标识符。

返回到 Data Connection 中的 Snowflake 源，确认您可以浏览该源并运行同步。

虚拟表

本部分提供了有关使用 虚拟表 与 Snowflake 源的其他详细信息。本部分不适用于同步到 Foundry 数据集的情况。

Snowflake 连接器现在在使用虚拟表访问 Horizon Catalog 中注册的 Iceberg 表时提供了增强的功能。Foundry 使用 Horizon Catalog 中公开的 Iceberg REST API 来访问表，以及在底层存储位置（在 Snowflake 中配置为外部卷）中读取和写入数据。此外，Foundry 使用 Horizon Catalog 凭证分发来确保对云对象存储的安全访问。这还可以提高对这些表进行读取和写入的性能。

如果您满足以下条件，连接器会自动公开 Iceberg 功能：

  1. 配置允许从 Foundry 连接到存储表的外部卷的网络出站策略。
  2. 在源上配置有权从 Horizon Catalog 获取分发凭证的凭证。



Foundry 使用 Iceberg 客户端建立连接，直接读取表或将表写入存储位置 未启用 而不是使用 Snowflake 计算。但是，Foundry 仍会使用源上配置的仓库来执行某些元数据查询，例如确定所访问表的类型。

请参阅 Snowflake 官方文档 ↗ 以了解有关通过 Snowflake Horizon Catalog 使用外部引擎查询 Iceberg 表的更多信息。对 Horizon Catalog 的写入目前是一项 私人预览版 Snowflake 功能。请参阅 网络 本文档的部分，了解有关启用对外部卷的网络访问的详细信息。

如果不满足上述任何要求，Foundry 会将 Iceberg 表视为常规 Snowflake 表。与 Snowflake 的连接使用与其他 Snowflake 数据（如表、视图或物化视图）相同的机制，并依赖 Snowflake 计算仓库来读取和写入表。

Iceberg 同步

您可以将此源的数据直接同步到 Foundry Iceberg 表。Iceberg 同步支持非增量和增量批量摄取，以及多种写入模式，并在 您必须正确配置出站策略（如果使用 运行时上运行。有关配置详情和受支持的写入模式，请查阅 Iceberg 同步文档.

Iceberg 同步与 虚拟表 功能不同：同步将数据从 Snowflake 源写入 Foundry 管理的 Iceberg 表，而虚拟表则注册存储在 Snowflake Horizon Catalog 中的 Iceberg 表以供 Foundry 使用，而无需复制数据。

import polars as pl
from transforms.api import transform, Output, LightweightOutput
from transforms.external.systems import ResolvedSource, external_systems, Source
import snowflake.connector


@external_systems(
    snowflake_source=Source("<source_rid>")
)
@transform.using(
    output=Output("<output_dataset_rid>")
)
def read_from_snowflake(output: LightweightOutput, snowflake_source: ResolvedSource):
    conn = snowflake.connector.connect(
        authenticator="oauth",
        token=snowflake_source.get_session_credentials().get().access_token,
        account="<account_identifier>",
        warehouse="<warehouse_name>",
        database="<database_name>",
    )

    cursor = conn.cursor()
    try:
        cursor.execute("SELECT * FROM my_table LIMIT 100")
        columns = [col[0] for col in cursor.description]
        rows = cursor.fetchall()
    finally:
        cursor.close()
        conn.close()

    df = pl.DataFrame(rows, schema=columns)
    output.write_table(df)

import polars as pl
from transforms.api import transform, Input, Output, LightweightOutput
from transforms.external.systems import ResolvedSource, external_systems, Source
import snowflake.connector


@external_systems(
    snowflake_source=Source("<source_rid>")
)
@transform.using(
    output=Output("<output_dataset_rid>"),
    source_data=Input("<input_dataset_rid>"),
)
def write_to_snowflake(output: LightweightOutput, snowflake_source: ResolvedSource, source_data):
    conn = snowflake.connector.connect(
        authenticator="oauth",
        token=snowflake_source.get_session_credentials().get().access_token,
        account="<account_identifier>",
        warehouse="<warehouse_name>",
        database="<database_name>",
    )

    cursor = conn.cursor()
    try:
        df = source_data.dataframe()
        for row in df.iter_rows(named=True):
            cursor.execute(
                "INSERT INTO my_table (col1, col2) VALUES (%s, %s)",
                (row["col1"], row["col2"]),
            )
    finally:
        cursor.close()
        conn.close()

    output.write_table(df)

数据模型

类型为 array ↗, object ↗日 variant ↗ 的列将被 Foundry 解析为 string类型。这是由于数据源的可变类型所致。

例如，Snowflake 数组 [ 1, 2, 3 ] 将被 Foundry 解释为字符串 "[1,2,3]".

参见 Snowflake 的 官方文档 ↗ 以了解更多详情。
