受限视图

标记 和 角色（role） 提供强大的访问控制。但是，某些情况需要更细粒度的权限控制。例如，授予对某种类型的所有对象的访问权限可能是不够或不合适的。某些对象类型可能需要向不同用户展示不同的对象，例如公司限制销售代表只能查看其所属分行的客户。 受限视图 可以提供这种额外级别的访问控制。

用户在 Foundry 中与受限视图资源进行交互，而受限视图由细粒度策略驱动。受限视图将数据集访问限制为用户仅有权查看的行。受限视图构建在支撑数据集之上，不能用作 转换 或其他生成新数据集的批处理派生作业的输入。 策略 决定用户可以查看的具体行。它通常由具有 Owner 角色的用户在创建受限视图时定义。创建后，受限视图可用作 Ontology 中对象类型的支撑数据源。例如，如果一行代表一个对象，则受限视图基于其支撑的对象类型控制用户可以查看哪些对象。

受限视图策略会过滤用户可以读取的内容。它不适用于函数、操作、AIP Logic、OSDK 响应、写回操作或导出。完整模型请参见 访问控制传播.

受限视图策略

策略是受限视图的核心。受限视图策略使用 细粒度策略 来确定用户可以查看哪些行。细粒度策略是一组规则和逻辑运算符，用于比较用户属性、列和值。

  • 用户属性： 查看数据的用户的属性。
  • 列名： 受限视图的支撑数据集中的某一列。
  • 特定值： 字符串、布尔值、数字或数组。

大多数（如果不是全部）策略将至少涉及一个与用户属性进行比较的项。至少一个这样的项是基于用户的权限控制所必需的。

引用用户、组或 Organization 时，策略在策略列和策略定义中都需要唯一标识符 (UUID)。不支持指定名称而非 ID，以防止与重命名相关的问题。

避免使用 NOT 与组、标记或组织成员身份相关的条件。在这些情况下使用 NOT 条件属于配置错误。平台支持作用域令牌，这些令牌仅携带用户权限的一个子集。这些令牌可能缺少 NOT 条件所检查的属性，导致条件通过并授予超出预期的访问权限。

受限视图创建对话框包含以下步骤：

您可以使用以下内容创建基于规则的策略： 用户属性, 列名日 特定值。请参阅 受限视图策略 的文档以获取更多信息。

查看访问要求

只应通过受限视图访问敏感数据的用户不应拥有对上游数据集的访问权限。在此步骤中，您可以查看数据集和您正在创建的受限视图的访问要求。如果您拥有适当的标记权限，可以从受限视图中移除继承的标记，和/或对上游数据集应用标记。

摘要

摘要展示了数据集和受限视图的最终建议访问控制。如果您对摘要结果满意，请选择 创建 以开始受限视图的首次构建。

创建受限视图后，系统会在后台自动创建一个构建计划，每当输入数据集更新时都会重新构建。

按照以下步骤创建标记支撑的受限视图：

  1. 准备一个包含一个或多个标记列的数据集，该数据集将被保护为受限视图。每个单元格必须包含一个由标记 ID 组成的 STRING ARRAY。了解更多关于 上游数据集的预期格式.
  2. 通过转到 Dataset Preview 界面的 COLUMNS 标签页、选择相应列、选择 "Add typeclasses" 并输入以下内容，为每个标记列添加注释： marking_type.mandatory。此步骤对于细粒度权限的正常运行并非必需，但 Foundry 中的某些界面会将其作为提示，以便更恰当地渲染该列。

  1. 基于该数据集创建受限视图。策略规则的左侧应为“用户的标记”。对于右侧，选择“Columns”并选择标记列。如果您有多个列，请为每个列创建一条规则，并根据需要使用 AND 或 OR 规则进行组合。

上游数据集的预期格式

用于创建受限视图的数据集必须包含一个标记 ID 列。

  • 这些 ID 是通用唯一标识符 (UUID)。
  • 该列的类型必须为 STRING ARRAY（并包含一个标记 ID 列表）。
  • 您可以拥有多个标记 ID 列。
  • 您可以在同一列中混合使用标记和组织。

将受限视图添加到 Marketplace 产品

用途 Foundry DevOps 以将您的受限视图包含在 市场产品 中，以便其他用户安装和重用。 了解如何创建您的第一个产品。

支持的功能

仅 string 和 boolean 支持常量。常量只能与字段（列）或“用户所属组”用户属性进行比较。Marketplace 目前不支持使用同一字段的多个字段-常量比较条件。

向产品添加受限视图

要向产品添加受限视图，首先 创建一个产品，然后选择 功能，并选择。选择 添加文件 选项以从 Compass 文件系统中导航到 Cipher 资源，并将其添加到您的产品中。

将受限视图添加到产品时，会打包该受限视图的 策略, 不 数据。策略定义会在目标环境中应用，并在读取时根据本地用户的属性和组成员身份进行评估。Marketplace 不会（也无法）打包策略所依赖的用户属性或组成员身份状态。安装者需确保目标环境中存在必要的属性和组，以使策略按预期运行。该策略会筛选用户在目标环境中可读取的内容，但不会扩展到基于受限视图派生的下游工件。完整模型请参见 访问控制传播.
