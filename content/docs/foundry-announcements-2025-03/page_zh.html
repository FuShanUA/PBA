从 3 月 24 日当周开始，我们将推出全新的 MLflow ↗ 集成允许用户在 Palantir 平台中使用 MLflow 进行模型训练指标跟踪，在实验中记录图像以更好地支持计算机视觉工作流和自定义图表，并通过平行坐标图视图来更好地了解不同参数如何影响模型的性能。

代理变更历史现已推出

发布日期：2025-03-25

数据连接 代理 现在会显示配置更改和重启的历史记录，使代理操作更加透明，帮助您更好地诊断连接问题。代理变更历史现已推出 beta 版，并默认在所有注册中启用。

数据连接通常通过 直接连接 （不使用代理），但某些组织可能会选择使用代理，在 Foundry 与驻留在其网络中的数据源之间建立安全边界。为了遵循适当的代理维护规范，这些组织应使用维护窗口并频繁执行重启；然而，这些事件此前并未记录在历史记录中。因此，在调试失败的数据连接时，很难引用针对代理所执行的关键操作。借助代理变更历史，我们通过提供与代理健康状况相关的操作历史列表来解决这一问题。在许多用户可以访问同一代理的情况下，这种对变更历史的洞察尤其有用，因为您现在可以查看与每个代理事件关联的用户。

在此示例中，多名团队成员对代理的配置进行了更改。如果在代理重启时任何托管插件的版本发生了变化，我们可以查看与该更改关联的用户。

在首个版本中，我们捕获代理配置更改、重启请求和成功重启。随着工作的持续推进，我们预计将添加更多事件类型，以捕获与代理相关的更多种类的操作。

提醒一下，仅当无法建立 直接连接 时，才应使用代理。

新增和改进的派生序列创建和管理功能现已推出

发布日期：2025-03-20

我们很高兴地宣布推出多项适用于 派生序列：时间序列目录中的全新发现空间、全新的派生序列类型、精简的创建流程，以及 Workshop 小部件。

什么是派生序列？

派生序列允许您保存并复制应用于本体论中时间序列的计算和转换。进入本体论后，派生序列的行为与其他任何时间序列属性相同，但会按需进行计算，从而无需管理或存储派生数据，也无需在整个平台中重复这些计算。

时间序列目录

最近发布的 时间序列目录 时间序列目录充当多种时间序列资源类型（包括派生序列）的起始页和主页。时间序列目录允许您在无代码环境中创建新的时间序列，并管理本体论中的派生序列。

时间序列目录。导航至 派生序列 选项卡以查看所有可用的派生序列。

单个派生序列

借助全新的时间序列目录，您现在可以配置 单个派生序列 除模板化派生序列之外。单个派生序列允许您创建不要求所有输入都来自同一对象的逻辑。相反，单个派生序列不采用模板化，可以对多个对象进行操作。您还可以选择启用 自动保存到本体论 （适用于单个派生序列），而无需诉诸手动保存，让您轻松管理派生序列。

精简的创建流程

以前，您必须通过 Quiver 分析来创建派生序列。使用 Quiver 可以将某些时间序列分析的结果提升为派生序列。然而，由于可用操作数量庞大，很容易在 Quiver 中构建出派生序列实际上并不支持的逻辑。

现在，您可以使用 时间序列目录中全新的精简创建流程。此流程将引导您完成整个创建过程，从第一步选择您想要创建的派生序列类型开始。

时间序列目录中派生序列创建流程的第一步，您可以在其中选择派生序列类型。

选择类型后，您将进入时间序列逻辑编辑视图。在这里，只有派生序列支持的操作才能用于您的时间序列数据。

派生序列 Workshop 微件

最后，我们很高兴地宣布推出 Workshop 中的派生序列微件。借助该微件，您可以嵌入属于某个对象类型的派生序列的创建和管理细节及功能，然后在 Workshop 模块中使用该微件。

派生序列微件为管理派生序列提供了一个易于使用的平台，专注于构建时间序列逻辑。通过派生序列微件，用户可以查看简化版的派生序列管理选项，而非标准创建流程中使用的高级配置。

Workshop 中的派生序列微件，显示 Machine 对象类型的模板化派生序列详细信息。

在 Workflow Lineage 中批量发布 Workshop 模块

发布日期：2025-03-20

我们很高兴地宣布，您现在可以在 Workflow Lineage 中批量发布 Workshop 模块。此功能允许您一次性发布多个 Workshop 模块，无需再逐个更新每个模块，从而简化您的工作流程并节省时间。

开始使用

借助批量发布功能，您可以同时向不自动发布最新版本的 Workshop 模块发布更新。要开始使用，请导航至 Workflow Lineage，选择您要发布的 Workshop 节点，右键单击，然后从上下文菜单中选择 发布 选项。

发起批量发布后，将显示一个对话框，其中会通过以下标签显示您的 Workshop 模块的状态：

  • 已发布最新版本： 表示该 Workshop 应用程序已设置为自动发布最新版本。
  • 已发布： 表示尽管该 Workshop 应用程序未配置为自动更新，但它目前已是最新版本。

图中所示的 发布 Workshop 模块 对话框（位于 Workflow Lineage 中）显示了 已发布最新版本 和 已发布* 标签。

未标记有这些标签的 Workshop 模块尚未发布最新可用版本，将可在批量发布对话框中供您选择。然后，您可以选择 发布实体 以发布所选 Workshop 模块的最新版本。

与函数更新的无缝集成

除了发布 Workshop 模块的最新可用版本之外，您还可以更新模块中的函数，并直接从 Workflow Lineage 发布这些模块。更新函数后，请选择 “继续发布” 以打开 “发布 Workshop 模块” 对话框，您可以在其中选择 “发布实体” 以批量发布所选的 Workshop 模块。

该 “升级 Workshop 模块中的函数” 对话框，您可以在其中选择 “继续发布”。

利用 Workflow Lineage 中批量发布的便利与高效，让您的 Workshop 模块保持最新状态。识别存在未发布版本的模块，同时发布多个模块，并根据需要更新函数；所有这些操作都可以在一个集中位置完成。

探索 Time Series Catalog 应用程序中的时间序列功能

发布日期：2025-03-13

时间序列目录本周起面向所有租户开放，它是您在 Palantir 平台上创建、管理和发现时间序列的起点和核心枢纽。时间序列是一段时间内的一系列数据点，可以帮助您了解特定用例的趋势和模式。时间序列目录旨在为您处理时间序列同步、时间序列对象类型和派生序列提供便利。

在时间序列目录中，您可以查看最近访问的时间序列同步和派生序列、已保存的“收藏”时间序列同步和派生序列，以及“查看次数最多”的时间序列对象类型。导航至每种资源类型对应的选项卡，即可浏览该类型的所有资源。

了解更多关于时间序列目录的信息。

关于可在时间序列目录中浏览的现有资源类型的提醒

您可以使用改进后的时间序列目录查看以下现有资源类型：

时间序列同步

时间序列同步存储与多个时间序列关联的时间-值对，这些时间序列的标识依据是 seriesIds。您可以通过代码直接访问时间序列同步，也可以在时间序列同步资源查看器或 Quiver 等无代码应用程序中访问。

时间序列同步由数据集或流支撑，并需要映射以下三个列：序列标识符、时间和值。

了解有关时间序列同步的更多信息。

时间序列对象类型

时间序列对象类型是通过时间序列属性启用时间序列功能的对象类型。在使用本体论对象的应用程序中，时间序列属性值以图表形式显示。时间序列属性的支撑数据源是时间序列同步。

派生序列

派生序列使用户能够保存和复制应用于本体论对象内时间序列的计算和转换。这些派生序列存储为 Foundry 资源，可进行进一步管理，例如更新时间序列逻辑以及将派生序列保存到本体论对象。集成到本体论后，派生序列的功能类似于原始时间序列，但会实时计算。

派生序列使您能够保存和复制应用于本体论对象内时间序列的计算和转换。

适用于 Python 转换的 Palantir Visual Studio Code 扩展简介

发布日期：2025-03-13

我们很高兴地宣布，您现在可以开发 Python 转换 在本地 在您自己的 Visual Studio Code 实例中。此功能适用于所有通过 控制面板获得权限的用户。Palantir 扩展将 VS Code 与 Foundry 连接起来，让您能够在 VS Code 中原生执行和使用 Python 转换操作（例如转换预览、调试和库面板）。

本地 VS Code 实例中适用于 Visual Studio Code 的 Palantir 扩展。

扩展功能

  • 预览您的 Python 转换 ，直接在您的本地 Visual Studio Code 环境中即可完成。此外，适用于 Visual Studio Code 的 Palantir 扩展还支持 完整数据集（无采样预览），因此您可以使用完整数据集进行预览，且不会损失任何精度。注意：要在本地运行预览，您需要请平台管理员通过 控制面板启用本地预览。
  • 启动构建 ，直接在您自己的代码编辑器中轻松完成。
  • 调试您的代码 并直接在编辑器中运行测试。
  • 利用 库面板 来添加库。

使用 AIP 模型选择器为您的工作流选择最佳模型

发布日期：2025-03-04

AIP 全新的模型选择器让您能够更轻松地为工作流选择和部署最合适的 AI 模型。为帮助您做出模型选择，模型选择器提供了有关模型性能指标（例如模型类别、成本、速度和可用性）以及其他关键元数据的全面信息。自 2025 年 3 月 3 日当周起，模型选择器现已在所有租户中推出。

帮助您为用例选定合适模型的模型元数据

为了让您能够快速选择符合特定标准和需求的模型，模型选择器提供了每个模型的能力、上下文窗口和训练数据等信息。

当您将鼠标悬停在 LLM 选项上时，模型选择器会一目了然地显示模型元数据。

帮助您比较可用模型的模型关系属性

模型关系属性是一系列性能指标，旨在帮助您分析和比较模型，从而为特定用例确定最合适的模型。

在模型选择器中，您可以查看模型关系属性，帮助您从类别、成本、速度和可用性等方面对模型进行比较。

模型类别

每种模型类别都服务于不同的目的，需要在性能、资源消耗与任务复杂性之间进行权衡。一种 Lightweight 模型通常以更快、强度更低的计算为特点，使轻量级模型成为较小任务的理想选择。相比之下，一种 Heavyweight 模型旨在以更高的准确性和深度处理复杂任务，但代价是资源消耗更大。一种 Reasoning 模型专用于需要逻辑推理和决策能力的任务，在需要理解和处理复杂关系与抽象概念的应用中表现出色。

成本

成本属性用于衡量处理输入和生成输出 token 的平均开销。成本较低的模型，其值为 Low ，而成本较高的模型，其值为 High。

速度

速度属性用于衡量模型平均生成输出 token 并返回给用户所需的时间。速度较快的模型，其值为 High ，而速度较慢的模型，其值为 Low。

可用性

可用性属性反映了模型处理请求的容量与就绪程度，直接由其注册限额大小得出。可用性是通过比较每个模型在不触及速率限制的情况下可使用的每分钟最大令牌数（TPM）和每分钟请求数（RPM）来确定的。 High 可用性表示模型能够消耗大量 TPM/RPM，适用于高需求场景，而 Low 可用性则表示容量较为有限。有关每个模型具体注册限额大小的详细信息，请参阅 有关 LLM 容量管理的文档。
