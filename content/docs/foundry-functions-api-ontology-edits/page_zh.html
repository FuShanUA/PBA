本体论编辑

以下文档特定于 TypeScript v1 函数。有关此页面的 TypeScript v2 版本，请参阅 本体论编辑。如需更多 强大的功能，包括对本体论 SDK 的支持和可配置的资源请求，我们建议 迁移到 TypeScript v2。

除了编写基于本体论返回派生值的函数之外，您还可以编写用于编辑本体论中对象属性和关联的函数。本页面介绍了函数中可用的对象编辑 API。有关编辑函数工作原理的更多详细信息，请参阅 概述页面。

要在实际运营环境中使用， 本体论编辑函数必须配置为操作，称为 函数支撑的操作。以这种方式配置操作，您可以提供额外的元数据、配置权限，并在各种运营界面中访问该操作。如 文档中所述，在操作之外运行编辑函数实际上不会修改任何对象数据。

警告

编辑对象后搜索这些对象可能会返回意外结果。请参阅 注意事项部分 了解详情。

声明编辑函数

编辑本体论的函数必须：

  • 使用 @OntologyEditFunction() 装饰器，该装饰器导入自 @foundry/functions-api
  • 必须使用 @Edits([object type]) 装饰器（从 @foundry/functions-api 导入）进行装饰，以指定将要编辑的对象类型
  • 必须具有显式的 void 返回类型

更新属性

您只需为对象重新分配属性值，即可编辑属性值。例如：

1
employee.lastName = newName;

如果您访问 lastName 属性值，则稍后在同一函数执行中，将返回您刚刚设置的新值。

对象上的数组属性 是使用 ReadOnlyArray 类型生成的。要修改数组，请先创建其副本，修改该副本，然后更新属性：

创建对象

您可以使用 Objects.create() 接口来创建新对象，该接口可从 @foundry/ontology-api获取。创建新对象时，您必须为其主键指定一个值。

在本示例中，我们创建一个具有给定 ID 的新 Ticket 对象，设置其 dueDate 属性，并将其分配给给定的 Employee（通过修改 assignedTickets 关联）。

import { OntologyEditFunction, Edits } from "@foundry/functions-api";
import { Employee, Objects, Tickets } from "@foundry/ontology-api";

export class TicketActionFunctions {
    @Edits(Employee, Tickets)
    @OntologyEditFunction()
    public createNewTicketAndAssignToEmployee(employee: Employee, ticketId: Integer): void {
        const newTicket = Objects.create().ticket(ticketId);

        newTicket.dueDate = LocalDate.now().plusDays(7);

        employee.assignedTickets.add(newTicket);
    }
}

如何捕获编辑

当执行本体论编辑函数时，对对象的所有更新都会被函数基础设施捕获，并在函数执行结束时返回。这包括通过 Objects.create() API 进行的对象创建、所有属性更新以及对象删除。

编辑会被智能地合并，以便在操作中应用最小的一组编辑。例如，如果您创建一个新对象并随后更新其属性，则会返回单个 创建对象 编辑，其中包含这些属性更新。同样，更新现有对象的多个属性将返回单个 更新对象 编辑，其中包含所有属性编辑。删除对象将清除删除之前所做的任何其他属性编辑。整个函数必须成功执行，才能生成传递给执行原子事务的操作服务的编辑列表。

捕获的本体论编辑以列表形式从函数执行中返回，因此本体论编辑函数的返回类型必须为 void 或 Promise<void>。当它们被执行时，函数的实际返回类型是本体论编辑的列表，因此无法同时返回另一个值。

编辑会在单次函数执行的整个生命周期中被捕获到单个编辑存储中。这意味着可以调用创建、更新或删除对象的辅助函数，即使这些辅助函数并未发布为本体论编辑函数。例如：

export class HelperEditFunctions {

    @OntologyEditFunction()
    public createAndLink(): void {
        const objectA = this.createObjectA();
        const objectB = this.createObjectB();
        objectA.linkToB.set(objectB);
    }

    /**
     * Even though these helper functions are not annotated with @OntologyEditFunction(),
     * they can create new objects for use in other edit functions.
     */
    private createObjectA(): ObjectA {
        const objectA = Objects.create().objectA(this.generateRandomId());
        objectA.prop1 = "example";
        objectA.prop2 = 42;
        return objectA;
    }

    private createObjectB(): ObjectB {
        const objectB = Objects.create().objectB(this.generateRandomId());
        objectB.prop1 = "another example";
        return objectB;
    }

    /* Generate your primary keys as needed. For example,
    import { Uuid } from "@foundry/functions-utils";

}

检索已编辑的值

在函数中进行编辑后，函数基础设施会在你读取时返回已编辑的值。例如，设置对象的属性然后进行检索将返回新值：

airplane.departureTime = newDepartureTime;
console.log(airplane.departureTime); // Will log newDepartureTime

删除对象会将其从搜索结果中移除，并阻止访问其属性。

@Edits 装饰器

操作可能需要溯源信息来强制执行其权限。要向操作提供此信息，可以使用 @Edits 装饰器并指定函数返回编辑的对象类型。

使用 @Edits 装饰器时，请考虑以下事项：

  • 编辑属性时，应声明所编辑对象的类型。
  • 在编辑一对一或一对多关联时，应声明具有外键属性的对象的类型。
  • 在编辑联接表关联时，应同时声明源对象类型和目标对象类型。

函数会对您的代码执行静态分析，以自动检测所引用的对象类型。但是，静态分析 可能无法 正确检测到引用。我们强烈建议您始终使用 @Edits 装饰器来提供有关所引用对象类型的来源信息。

在以下示例中，对象类型 Employee 和 Aircraft 由函数进行编辑：

import { OntologyEditFunction } from "@foundry/functions-api";
import { Employee, Aircraft, Objects } from "@foundry/ontology-api";

export class MyOntologyEditFunction {
    @Edits(Aircraft, Employee)
    @OntologyEditFunction()
    public myFunction(): void {
        const x = Objects.search().aircraft().all()[0];
        x.businessCapacity = 3;
        const y = Objects.search().employee().all()[0];
        y.department = "HR";
    }
}

如果您通过 Objects.search() API 使用编辑未更改的标识符（例如其主键）来检索（或物化）先前编辑过的对象，则会返回编辑后的值。这是因为函数基础设施在物化对象时会将您待处理的编辑应用于该对象。这与对您所编辑的值进行过滤、搜索或聚合不同，这些操作在您的函数执行完成之前不会反映所做的编辑。请参阅 编辑与对象搜索 以了解详情。

import { OntologyEditFunction } from "@foundry/functions-api";
import { Employee, Objects } from "@foundry/ontology-api";

export class CaveatEditFunctions {
    @Edits(Employee)
    @OntologyEditFunction()
    public async editAndSearch(): Promise<void> {
        const employeeOne = Objects.search().employee().filter(e => e.id.exactMatch(1)).all()[0];
        employeeOne.name = "Bob";

        // Retrieve the already edited object
        const employeeOneAgain = Objects.search().employee().filter(e => e.id.exactMatch(1)).all()[0];
        console.log(employeeOneAgain.name); // Prints "Bob"
    }
}
