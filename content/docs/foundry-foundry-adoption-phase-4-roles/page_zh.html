第 4 阶段：角色和职责

以下是 Foundry Program 团队第 4 阶段新增的角色和职责，是对 第 1 阶段、 第 2 阶段以及 第 3 阶段中已确立角色的补充。

生产工程师

职责

  • 全面负责生产管道；管理发布流程，确保生产管道符合组织标准并可靠运行。
  • 与领域专家（SME）密切协作，处理针对本体论提出的任何变更请求，并收集有关管道在生产工作流中的性能与可用性的反馈。
  • 负责生产管道 master 分支 Pull Request（PR）合并的审批流程，并管理在 master 分支上运行管道构建的审批。
  • 与管道和数据源开发人员合作，为关键数据集定义健康检查，并在各版本发布中实现对健康检查的持续监控。
  • 生产工程师从根本上负责监控生产管道的健康运行。这包括监控不同数据源上的数据刷新、管道构建的执行情况，以及在必要时协助对支持请求进行分类处理。

人员画像与所需技能

  • 数据工程技能（SQL、Python、PySpark/Spark）
  • 了解数据清洗与数据质量的最佳实践
  • 了解版本控制的最佳实践
  • 熟悉代理 / 虚拟机 / 系统连接

相关的 Foundry 应用和资源

  • 数据连接
  • 管道构建器
  • 数据健康
  • Code Workbook
  • 数据血缘
  • Foundry 数据集成

管道开发人员

职责

  • 构建一个通用本体论层，为所有用例提供可供使用的数据资产。
  • 定义这一通用本体论层，并构建将数据从源结构转换为本体论结构所需的转换。
  • 与生产工程师和本体论管理员密切合作，实施由本体论管理员设计、并在提供给用例团队的数据中得到利用的本体论层。

岗位画像与所需技能

  • 数据工程技能（SQL、Python、PySpark/Spark）
  • 了解数据清洗和数据质量的最佳实践
  • 了解版本控制的最佳实践
  • 熟悉代理 / 虚拟机 / 系统连接

相关的 Foundry 应用和资源

  • 数据连接
  • 管道构建器
  • 数据健康
  • Code Workbook
  • 数据血缘
  • 本体论管理器
  • 对象浏览器
  • Foundry 数据集成

对象视图开发人员

职责

  • 对象视图开发人员基于本体论开发对象视图。
  • 受理来自平台管理团队、用例团队乃至业务负责人和最终用户的请求，包括在对象视图中新增功能的请求，以及为本体论中的新对象创建新对象视图的请求。与这些团队密切合作，了解业务需求，确保对象视图发挥最大效用。
  • 与本体论管理员深入协作，确定预计需要构建哪些对象和对象视图，以及创建它们所需的支撑数据集。
  • 与生产工程师和管道开发人员合作，建立信息共享流程，确保双方都能了解彼此的开发举措。
  • 在 Contour 中构建原型视图，最终将其升级为生产对象视图。
  • 建立一套关于如何对本体论对象和对象视图进行变更的流程，以支持扩展到多个开发人员，并提供对象视图开发需求、约束条件和最佳实践方面的可见性。

岗位概况与所需技能

  • 数据工程技能（SQL、Python、PySpark/Spark）
  • 熟悉版本控制最佳实践
  • 数据库知识
  • 业务领域知识
  • 项目管理和变更管理技能
  • 具备经过实践验证的全面技术文档撰写能力
  • 具备在技术和非技术利益相关者之间进行沟通的能力
