Polars 惰性 API

Polars 惰性 API ↗ 仅在查询被收集后才会对其进行求值。这使得引擎能够应用优化，从而在大多数情况下提升性能，同时也是使用 Polars 时推荐的计算模式。对于处理大量数据的管道，建议采用惰性执行。但是，不同查询的受益程度各不相同，因此在部署到生产系统之前，应始终验证各个管道的稳定性。

要在 Foundry 中使用 Polars 惰性 API，请在您的转换中将 lazy 标志设置为 True ，如下所示：

from transforms.api import transform, Input, Output


@transform.lightweight(
    output=Output("/Users/jsmith/output"),
    input=Input("/Users/jsmith/input"),
)
def compute(output, input):
    df = input.polars(lazy=True)
    # your data transformation logic
    output.write_table(df)

默认情况下，惰性执行处于 禁用状态。

Polars 流式引擎 ↗，通常在惰性计算过程中使用。这使得超出内存大小的数据也能得到处理，因为查询可以分批执行，而不是一次性全部执行。此外，启用数据流式传输后，查询的执行速度会更快。在惰性模式下使用 Polars 时，流式处理始终处于启用状态。

筛选下推

当可以使用筛选下推（也称为谓词下推）时，惰性执行尤其有益。筛选下推是指，例如 .filter()， .where()，或布尔索引，并不会立即执行，而是会被记录为查询计划的一部分。在执行查询时，Polars 会尝试将这些筛选条件尽早推入执行计划中。在某些情况下，它们可以被一直下推到数据扫描本身，从而完全避免数据输入/输出。管道中使用的数据比例越小，筛选下推的影响就越大。惰性计算期间使用的完整优化集可在 Polars 的 惰性优化 ↗ 文档中找到。

如果您的查询与下面的示例类似，强烈建议启用惰性执行，因为它能显著提升性能。

import polars as pl
from transforms.api import transform, Input, Output


@transform.lightweight(
    output=Output("/Users/jsmith/2025_06_sale_data"),
    sales_data=Input("/Users/jsmith/sales_data"),
)
def june_2025_sales(output, sales_data):
    df = (
        sales_data.polars(lazy=True)
        .filter(
            (pl.col("date") >= pl.lit("2025-06-01")) &
            (pl.col("date") <= pl.lit("2025-06-30"))
        )
    )
    output.write_table(df)

在流式数据集的增量转换中使用

当使用 polars(lazy=True) 在 增量转换 中处理流式数据集时，增量窗口有时可能不包含任何新文件。在这种情况下，对空输入调用 .polars(lazy=True) 可能会触发 BinderException。要处理此问题，请在使用惰性 API 之前检查输入是否为空：

from transforms.api import transform, incremental, Input, Output


@incremental()
@transform.using(
    my_output=Output('/path/to/output'),
    my_input=Input('/path/to/input'),
)
def compute(ctx, my_output, my_input):
    if ctx.is_incremental and my_input.polars().is_empty():
        return
    df = my_input.polars(lazy=True)
    my_output.write_table(df)

有关此已知限制的更多详细信息，请参阅 增量转换 文档。

GPU 加速

您可以通过 GPU 处理来加速 Polars 惰性 API 查询，方法是使用 cudf-polars，这是一种基于 GPU 的执行引擎。要使用 GPU 处理来运行现有的 Polars 惰性 API 查询，请将 pl.GPUEngine() 传递给 collect() 调用：

Copied!
1
result = df.collect(engine=pl.GPUEngine())

GPU 加速的收集操作支持 collect()，它会将结果完全物化到内存中。诸如 sink_parquet() 等流式操作不受支持。

有关详细的设置说明、支持的操作和代码示例，请参阅 基于 cuDF 的 GPU 加速 Polars。

何时使用惰性 API

为了在惰性计算中充分利用 Polars 的优化，您的 Foundry 数据集会通过内部对象存储代理进行公开，因此查询只会加载必要的数据。由于 Polars 在即时模式下不具备相同的优化，您的整个数据集会在 lazy=False时被预取到磁盘。

请考虑以下几点，以决定何时启用惰性执行。

  • 在以下情况下使用惰性执行（lazy=True）：
    • 您正在处理大型数据集或复杂的转换管道。
    • 您希望受益于诸如过滤下推、谓词下推、投影下推或流式处理等查询优化。
    • 您有多个链式操作，并希望 Polars 优化执行顺序。
    • 您需要处理无法载入内存的数据。
  • 使用急切执行 (lazy=False) 在以下情况下：
    • 您正在逐步进行原型设计或探索数据转换。
    • 您正在调试复杂的管道，并希望获得更可预测的行为。
