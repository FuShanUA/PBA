权限

在平台中编写和执行函数需要经过多种权限检查。本节概述了您应了解的不同类型的权限，以及您可能遇到的常见问题。

函数编写

函数仓库必须被授予适当的权限才能：

  1. 访问本体论，以便生成正确的代码绑定。
  2. 加载对象，以便运行函数执行的实时预览。

仓库权限必须被显式授予，且与授予您用户账户的权限不同。因此，您需要执行特定步骤，将对象类型、关联类型和支撑数据源导入到包含您仓库的 Project 中。

有关这些步骤的教程，请参阅 本节。下面我们将说明被导入的特定资源以及为这些资源授予的权限。

本体论实体权限

在仓库中，每当运行检查或 Code Assist 启动时，函数插件会根据仓库的权限加载最新的本体论，并为每个加载的对象和关联类型生成代码绑定。加载的对象和关联类型集合取决于以下资源类型的导入：

  • 本体论
  • 本体论分支
  • ,其中显示地图上各对象类型的对象数量。下方,每种属性类型各有一个部分,涵盖地图上存在的所有对象类型。面板顶部的筛选框允许您将结果筛选为名称匹配的属性。
  • 关联类型

在函数仓库中，您可以通过导航到 设置 > 本体论来导入所需的本体论资源。此界面允许您选择要导入到 Project 中的对象和关联类型。

如果您的用户账户有权访问多个本体论，您还可以选择要使用的本体论。目前，不支持将多个本体论导入到单个 Project 中。

本体论导入适用于整个 Project，而非单个仓库

尽管上述界面显示在函数仓库中，但您导入的任何本体论、对象类型和关联类型都是在 项目 级别添加的。这意味着在一个仓库中更改导入可能会影响同一 Project 中的其他仓库。如果您希望两个仓库依赖不同的本体论实体，应将它们分离到不同的 Project 中。

对象加载权限

直方图 函数助手 在仓库中允许用户以两种方式执行函数：执行已发布的函数，或在实时预览中执行代码。在实时预览中执行时，函数代码会在 Code Assist 中编译并执行，Code Assist 是一种旨在帮助代码作者快速迭代的基础设施。

由于 Code Assist 与仓库绑定，它受到与上述代码生成相同的权限要求。这意味着在实时预览中运行函数时，您希望使用的每个对象类型底层的支撑数据源必须导入到 Project 中。

已发布函数的执行

函数发布后，即可供更广泛的用户群体使用，并可配置为在诸如 来运行该专业代码代理。你还可以通过 和 操作等应用程序中执行。在执行已发布函数的权限方面，仍有一些注意事项需要牢记。

函数权限

为了执行函数，用户必须拥有 查看者 对发布该函数的仓库的角色权限。通常，最好将函数仓库与依赖该仓库中函数的最终用户应用程序放在同一个 Project 中，无论这些应用程序是使用 Workshop、Slate 还是其他工具创建的。如果用户遇到表明他们缺乏读取函数权限的错误（ReadFunctionsPermissionDenied），请检查他们是否拥有该仓库的读取权限。 了解有关如何移动和共享资源的更多信息。

相比之下， PERMISSION_DENIED 代码错误 FunctionRegistry:ReadOntologyFunctionPermissionDenied 通常意味着该函数未在 自定义小部件中注册或不可用，而不是表明存在文件夹级别的权限问题。请在 Developer Console 中添加并注册该函数，因为仅靠文件夹和仓库权限无法使函数可执行。

要更全面地审查访问权限，请使用 检查访问 侧边栏中的面板来检查某人对 Workshop 或 Slate 应用程序的访问权限，包括对依赖函数的访问权限。有关更多信息，请参阅 检查权限.

函数支撑的 Action 是一种特殊情况，最终用户不一定需要对该函数的读取权限即可应用使用该函数的 Action。管理用户在配置 Action 以使用某个函数时，必须拥有对该函数的读取权限。之后，用户将能够基于 Action 级别权限来应用该 Action，而无论他们对函数的访问权限如何。

对象加载权限

当函数加载对象数据时（无论是作为参数还是通过 对象搜索），运行该函数的最终用户的权限决定了加载哪些对象。对于使用行级权限保护的对象类型，这意味着不同用户执行同一函数可能会收到不同的结果。此行为是有意设计的——用户只应看到他们有权访问的对象，而此行为使单个函数能够适用于对不同对象具有不同访问权限的用户。

仅读取时强制执行

行和列访问控制（包括 受限视图, 对象安全策略日 属性安全策略）会在函数运行时过滤用户可以读取的内容。这些控制不会延伸到函数的输出。为了在数据向下游流动时保持受保护状态，请将这些控制与 标记 or 基于分类的访问控制配合使用。有关完整模型，请参阅 访问控制传播.

扩展函数执行

管理员通过 函数设置 in 控制面板来控制扩展执行功能。这些功能授予提升的访问权限，例如在函数内部调用 操作 或获取生存时间（TTL）最长为四小时的身份验证令牌。

要发布、执行或安装具有扩展功能的函数，管理员必须配置相应的允许列表：

  • 允许发布扩展函数的仓库： 只有此允许列表中的仓库才能发布具有扩展功能的函数。
  • 允许以扩展功能执行的函数： 只有此允许列表中的函数才能以扩展功能执行。Foundry 会在执行时检查此允许列表。
  • 允许通过 Marketplace 安装扩展函数的 Project： 只有此允许列表中的 Project 才能成功从 实现程序化 DevOps，使团队能够沿用现有流程，以自包含、可重现且经加密签名的捆绑包交付代码。.

安装具有扩展功能的函数。如果发布、执行或 Marketplace 安装对具有扩展功能的函数返回权限错误，请要求管理员验证相关的允许列表。
