权限

在平台中编写和执行函数需要经过多种权限检查。本节概述了您应了解的不同类型的权限，以及可能遇到的常见问题。

函数编写

函数代码仓库必须被授予适当的权限，才能：

  1. 访问本体论，以便生成正确的代码绑定。
  2. 加载对象，以便运行函数执行的实时预览。

请注意，代码仓库权限必须被显式授予，并且与授予给您用户账户的权限不同。因此，您必须采取特定步骤，将对象类型、关联类型和支撑数据源导入到包含您的代码仓库的项目中。

有关这些步骤的教程，请参见 此部分。下面，我们将解释导入的特定资源以及为这些资源授予的权限。

本体论实体权限

在代码仓库中，每当运行检查或 Code Assist 启动时，函数插件都会根据代码仓库的权限加载最新的本体论，并为已加载的每个对象类型和关联类型生成代码绑定。加载的对象类型和关联类型集合取决于以下资源类型的导入：

  • 本体论
  • 本体论分支
  • 对象类型
  • 关联类型

在函数仓库中，您可以通过导航至 设置 > 本体论来导入所需的本体论资源。此界面允许您选择要导入到项目中的对象类型和关联类型。

如果您的用户账户有权访问多个本体论，您还可以选择要使用的本体论。目前，不支持将多个本体论导入到单个项目中。

警告

尽管上述界面出现在函数仓库中，但您导入的任何本体论、对象类型和关联类型都会添加到 项目 级别。这意味着更改一个仓库中的导入内容可能会影响同一项目中的其他仓库。如果您希望两个仓库依赖不同的本体论实体，应将它们分到不同的项目中。

对象加载权限

仓库中的 函数助手 允许用户通过两种方式执行函数：执行已发布的函数，或在实时预览中执行代码。在实时预览中执行时，函数代码会在 Code Assist 中编译并执行，Code Assist 是专为帮助代码作者快速迭代而设计的基础设施。

由于 Code Assist 与代码仓库绑定，因此它需遵循与上文所述代码生成相同的权限要求。这意味着，在实时预览中运行函数时，您希望使用的每个对象类型底层的支撑数据源都必须导入到项目中。

在函数助手中，如果有对象类型已导入到您的项目中，但未导入相应的数据源，实时预览中将显示一条警告，提示您更新导入：

对于大多数对象类型， 导入支撑数据源 对话框将提示您导入 Foundry 数据集。对于已启用 行级安全性 的对象类型，系统将提示您导入 Restricted View。

已发布函数的执行

函数发布后，即可供更广泛的用户群体使用，并可配置为在 Workshop 和 Actions等应用程序中执行。不过，关于执行已发布函数的权限，仍有一些注意事项需要牢记。

函数权限

要执行函数，用户必须拥有 Viewer 发布该函数的仓库上的角色。通常，最好将函数仓库与依赖该仓库中函数的最终用户应用程序放在同一个项目中，无论这些应用程序是使用 Workshop、Slate 还是其他工具创建的。如果用户遇到表明其缺乏读取函数权限的错误（ReadFunctionsPermissionDenied），请检查他们是否拥有对该仓库的读取权限。 了解有关如何移动和共享资源的更多信息。

相比之下， PERMISSION_DENIED 代码错误 FunctionRegistry:ReadOntologyFunctionPermissionDenied 通常意味着该函数未在 Developer Console中注册或不可用，而不是表明存在文件夹级别的权限问题。请在 Developer Console 中添加并注册该函数，因为仅靠文件夹和仓库权限并不能使该函数可执行。

要更全面地审查访问权限，请使用侧边栏中的 检查访问 面板来检查某人对 Workshop 或 Slate 应用程序的访问权限，包括对所依赖函数的访问权限。更多信息，请参阅 检查权限。

由函数支撑的操作 是一种特殊情况，即最终用户不一定需要拥有对函数的读取权限，即可应用使用该函数的操作。管理用户在配置操作以使用某个函数时，必须对该函数拥有读取权限。此后，用户将能够根据 操作级权限来应用该操作，而无论其对该函数拥有何种访问权限。

对象加载权限

当函数加载对象数据时（无论是作为参数，还是通过 对象搜索），运行该函数的最终用户的权限将决定加载哪些对象。对于使用行级权限保护的对象类型，这意味着不同用户执行同一个函数可能会得到不同的结果。此行为是有意为之——用户只应看到其有权访问的对象，而这一行为使得单个函数能够适用于对各个对象拥有不同访问权限的用户。

仅在读取时强制执行

行和列访问控制（包括 受限视图、 对象安全策略和 属性安全策略）过滤函数运行时用户可以读取的内容。这些控制措施不会延伸到函数的输出。为了确保数据在向下游流动时受到保护，请将这些控制措施与 标记 或 基于分类的访问控制结合使用。有关完整模型，请参阅 访问控制传播。

扩展函数执行

管理员通过 函数设置 （位于 控制面板）来控制扩展执行能力。这些能力可授予提升的访问权限，例如在函数内调用 操作 ，或获取生存时间（TTL）长达四小时的身份验证令牌。

要发布、执行或安装具有扩展能力的函数，管理员必须配置相应的允许列表：

  • 允许发布扩展函数的代码仓库： 只有此允许列表中的代码仓库才能发布具有扩展能力的函数。
  • 允许以扩展能力执行的函数： 只有此允许列表中的函数才能以扩展能力执行。Foundry 会在执行时检查此允许列表。
  • 允许通过 Marketplace 安装扩展函数的项目： 只有此允许列表中的项目才能从 Marketplace 成功安装具有扩展能力的函数。

如果具有扩展能力的函数在发布、执行或 Marketplace 安装时返回权限错误，请联系管理员核实相关的允许列表。
