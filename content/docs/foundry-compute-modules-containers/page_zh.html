Docker 入门

要构建和发布镜像，您首先需要安装 Docker。请按照 Docker 文档 ↗中的官方说明操作。

要验证 Docker 是否正在运行，您可以运行 docker info 命令。如果您看到 Cannot connect to the Docker daemon，请访问 故障排除指南 ↗ 以进行修复。

什么是 Docker？

Docker 是一款用于打包和部署应用程序的工具。Docker 能够实现轻松分发、跨运行时环境的执行一致性，以及通过隔离保障的安全性。这是通过一个称为 容器化 的流程实现的，该流程会将运行应用程序所需的一切内容打包在一起，同时确保应用程序无论部署在何处都能一致地运行。Docker 容器化有两个核心原语：镜像和容器。

  • 镜像： 一个不可变的文件，其中包含运行应用程序所需的全部代码、依赖项及其他必要内容。换言之，镜像仅描述应运行的内容；它是创建容器的模板。
  • 容器： 镜像的单个运行实例。容器是一个实时、轻量级的隔离环境，您的应用程序实际在其中运行。

创建镜像

在 Docker 中创建镜像涉及将应用程序及其依赖项、库和配置文件打包到单个可移植的单元中。打包指令定义在 Dockerfile中。

Dockerfiles

Dockerfile 是一个由一系列顺序命令组成的文本文档，用于指示如何配置和运行您的应用程序。以下列表概述了您在为计算模块创建镜像时可能需要的最常见命令。如需完整指南，请访问 Dockerfile 参考文档 ↗：

  • FROM: 声明基础镜像。基础镜像是构建镜像配置的基础层。基础镜像可以是极简的（仅包含操作系统），也可以是更全面的（包括预装软件，如 Python）。 FROM 必须是 Dockerfile 中的第一条语句。您还可以添加 --platform linux/amd64 标志来指定目标平台。
  • WORKDIR: 设置工作目录。工作目录是镜像中命令运行的基础位置。
  • RUN: 在镜像构建期间运行 Shell 命令。Shell 命令通常用于安装依赖项、编译代码以及执行文件系统操作。
  • COPY: 将文件从您的计算机复制到镜像中。
  • USER: 为容器设置用户。该用户必须是非 root 的数值。
  • ENTRYPOINT： 设置容器启动时运行的默认命令。此命令指定了容器实际要执行的操作。
  • EXPOSE： 记录容器将监听的端口。所有暴露的端口必须介于 1024 和 65535 之间，但不包括 8945 和 8946。
  • ENV： 设置环境变量。这些变量可用于配置并提供运行时信息，供容器在执行期间读取。

计算模块的镜像要求

  • 镜像必须以非 root 数值用户身份运行。
  • 镜像必须针对 linux/amd64 平台构建。
  • 您必须使用摘要或任意标签 但不包括 latest。
  • 所有暴露的端口必须介于 1024 和 65535 之间，但不包括 8945 和 8946。

在计算模块中使用您的镜像

获得与计算模块兼容的镜像后，您可以按照以下步骤将其上传到 Foundry。如需完整说明，请查阅我们关于 发布 Artifact 的文档。

  • 创建 Artifacts 仓库。
  • 导航至 Publish 并选择 Docker。
  • 按照提供的说明将您的镜像推送到仓库。

构建镜像：示例

我们有一个应用程序，希望将其部署为计算模块，其结构如下：

项目结构

myapplication
├── Dockerfile
├── requirements.txt
└── src
    └── application.py

我们可以按照以下步骤逐行构建 Dockerfile：

  1. 指定基础镜像。
FROM python:3.12
  1. 设置当前目录。
WORKDIR /app
  1. 安装必要的依赖项。
COPY ./requirements.txt /app
RUN pip install --no-cache-dir -r requirements.txt
  1. 指定容器运行时使用的非 root 数字用户。
RUN adduser --uid 5001 user
USER 5001
  1. 复制应用程序代码。此步骤与依赖项分开执行，以利用 Docker 镜像层缓存。
COPY ./src/application.py /app
  1. 指定容器在启动时运行应用程序。
ENTRYPOINT ["python", "application.py"]

您的 Dockerfile 应大致如下所示：

FROM python:3.12
WORKDIR /app
COPY ./requirements.txt /app
RUN pip install --no-cache-dir -r requirements.txt
RUN adduser --uid 5001 user
USER 5001
COPY ./src/application.py /app
ENTRYPOINT ["python", "application.py"]

现在，您可以运行以下命令，从您的 Dockerfile 构建一个名为 myimage 、标签为 0.0.0 的镜像：

docker build . -t myimage:0.0.0 --platform linux/amd64

可以在容器级别配置日志记录，允许您为每个容器启用或禁用日志记录。这种细粒度的控制有助于优化资源使用，并聚焦于最相关的日志数据。要访问特定容器的日志记录配置，请在 容器 部分中选择该容器的行。这将打开一个侧面板，您可以在其中调整日志记录设置。

package myproject;

import com.palantir.interactive.module.api.SafeArg;
import com.palantir.interactive.module.api.UnsafeArg;
import com.palantir.interactive.module.tasks.deployedapps.DeployedAppRuntime;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

final class DeployedApp {

    private static final Logger log = LoggerFactory.getLogger(DeployedApp.class);

    public static void main(String[] _args) {
        DeployedAppRuntime.builder()
                .addQueryRunner(DeployedApp::hello, String.class, String.class, "hello")
                .buildAndStart();
    }

    static String hello(String name) {
        // SLS format for error
        log.error("This is an SLS error log with unsafe parameter", UnsafeArg.of("name", name));

        // This is not in SLS format. As a result, it won't be logged if SLS format is selected.
        System.out.println("This message will not be logged iff SLS format");

        // SLS format for info
        log.info("This is an SLS info log with safe parameter", SafeArg.of("name", name));

        return "Hello, " + name + "!";
    }

    private DeployedApp() {}
}

请注意，日志记录遵循以下样式和约束：

  • 使用 UnsafeArg 来记录可能敏感的数据，并使用 SafeArg 来记录非敏感数据。
  • Standard System.out.println() 语句不会以 SLS 格式捕获。

    x: int

@function

        return result
    except Exception as e:
        logger.error("There was an error")
        raise e

可使用以下日志级别，按从最详细到最不详细的顺序列出：

  • DEBUG：用于故障排除的详细诊断信息。
  • INFO：有关正常运行的一般性信息消息。
  • WARNING：表示发生了意外情况，或者在不久的将来可能发生。
  • ERROR：导致特定操作无法完成的严重问题。
  • CRITICAL：严重错误，表示应用程序可能无法继续运行。

纯文本格式

纯文本格式提供人类可读的日志，但没有特定的结构。纯文本日志更易于直接阅读，但以编程方式进行解析可能更具挑战性。

当配置纯文本时，输出会被插入到 SLS 日志的 message 字段中。这样既能兼容现有的基于 SLS 的工具，又能保持可读性。

默认采用纯文本日志记录，可确保同时捕获纯文本日志和 SLS 日志，其中 SLS 日志以 JSON 形式显示在 messages 字段中。

容器日志来源

容器日志可以从两个主要来源捕获。每个来源都有特定的要求和配置，以确保有效收集日志。

标准输出

标准输出（stdout）来源会直接从容器的标准输出流中收集日志。要启用此日志记录方法，请确保您的容器满足以下要求：

  • 必须在以下位置具有 shell 可执行文件： /bin/sh
  • 必须支持 shell 命令 set 和 tee

是否包含标准错误： 可选择将标准错误（stderr）包含在日志中。当设置为 true时， stdout 和 stderr 会同步并合并为单个流。

日志文件

日志文件来源会从容器内的特定文件中捕获日志。共有两个配置参数：

  • 目录路径： 日志文件所在的基础目录。
  • 文件路径模式： 用于匹配要捕获的日志文件的模式。此参数支持常见的通配符，可实现灵活的文件匹配。每个模式都应包含指定的目录路径。

示例： 要捕获所有 .log 文件（位于 /var/log/foo/ 中）以及特定文件 /var/log/bar.txt中的日志，请将 directoryPath 设置为 /var/log ，并将 filePathPatterns 设置为 /var/log/foo/*.log ，并且 /var/log/bar.txt

使用日志文件时，指定的目录路径在计算模块启动时必须为空。

环境变量

Docker 环境变量是动态的命名值，无需更改 Dockerfile 或容器镜像即可自定义 Docker 容器和应用程序的行为。环境变量可用于多种用途，包括以下内容：

  • 配置参数： 为 Docker 镜像设置参数，例如 CPU 集和 CPU 份额。
  • 定义行为： 定义应用程序或脚本的行为。
  • 存储凭据： 安全地存储 API 密钥和数据库凭据等敏感信息。
  • 创建可重用的配置： 使用环境变量和插值来创建可重用的配置，从而更轻松地管理和部署 Docker 化的应用程序。
  • 覆盖默认值： 在运行容器时覆盖 Dockerfile 中指定的默认配置值。
