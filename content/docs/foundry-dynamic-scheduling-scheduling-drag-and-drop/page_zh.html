拖放

排程甘特图小部件的拖放功能使最终用户能够将 "pucks" 分配或重新分配到不同的行和/或不同的时间点。拖放是在小部件中与 pucks 交互的主要方式。

设置拖放行为

要配置拖放行为，您必须在小部件配置选项中提供保存操作处理程序。拖放 puck 时，小部件将调用此操作。以下步骤将指导您针对最常见的操作类型设置拖放行为：一种简单操作，用于修改关联排程对象的开始、结束和所分配的行。在此示例中，我们将该排程层称为 Object type A。

设置说明

  1. 在 Ontology Manager 中，导航到 Object type A 并创建一个修改操作类型。该操作类型应包含以下参数：

    • 一个对象，对象类型为 A。
    • 该 Start timestamp 该对象引用的属性
    • 该 End timestamp 该对象引用的属性
    • 该对象引用的外键属性，对应于 Row ID 此排程对象被分配到的对象。 因此，应将该操作类型配置为使得输入一个 Start timestamp， End timestamp，和/或已更新的外键将调整对象类型 A 的对象上的值。

  2. 现在，在 Workshop 中，导航至 输入数据 (Pucks) > [您的日程安排层] > 拖放。

  3. 在 保存处理程序操作下，选择您配置的操作类型。

  4. 在您刚输入的操作类型下，选择 选择要配置的参数 并选择对象、开始时间戳、结束时间戳以及外键参数。您现在应该可以看到配置中列出的这四个参数。接下来，我们将选择 Scheduling Gantt 变量来预填充这些参数值。

    1. 对于 Object 参数，在 本地默认值下，在弹出窗口中选择 日程安排对象 ，以确保在拖放时，小部件会自动传入您正在拖放的日程安排对象。
    2. 对于 Start Timestamp 参数，在 本地默认值下，在弹出窗口中选择 所选开始时间戳 ，以确保在拖放时，小部件会自动传入您将日程安排对象拖至的新开始时间戳。
    3. 对于 End Timestamp 参数，在 本地默认值下，选择 所选结束时间戳 在弹窗中，以确保在拖放时，微件会自动传入您将日程对象拖到的新结束时间戳。
    4. 对于 foreign key 参数，在 本地默认值下，选择 RESOURCE ID 在弹窗中，以确保在拖放时，微件会自动传入您将日程对象拖到的新行（资源）。

您现在可以将此日程图层中的任何冰球拖放到新行（资源）和/或新的开始时间戳和结束时间戳。放置后，将触发此操作类型，并且参数会预先填充这些更新后的值。请参阅下一节以了解其他自定义。

拖放行为自定义

您可以自定义拖放行为，而不仅限于上一节中描述的简单配置。

更新吸附行为

默认情况下，在配置拖放功能后，可以按分钟级别拖动 puck。对齐行为可用于自定义拖动 puck 的粒度。例如，如果您希望启用拖放 puck 的功能，使其在视觉上向前或向后移动一天，而不是向前或向后移动一分钟。在通过拖动 puck 的边缘来延长或缩短其持续时间时，对齐行为同样适用。要进行设置，请按照以下说明操作：

  1. 导航至 输入数据（Pucks）> [您的日程层] > 拖放 > 对齐行为。
  2. 为对齐间隔大小提供一个数值变量。
  3. 选择时间单位。例如，如果对齐间隔大小的值为 3 ，时间单位为 Day ，则表示每当您在此层中拖放 puck 时，它将以 3 天为增量移动。

高级保存处理程序操作类型

在拖放时，小部件会使用所提供的参数调用您的保存处理程序操作类型。在标准情况下，这是一个直接修改这些属性的简单操作类型。但是，只要小部件能够传入 Schedule Object， Start Timestamp， End Timestamp，并且 Resource ID，操作类型的底层逻辑和结果可以是任何你想要的内容。这意味着，例如，你可以让此操作类型由对象上的函数来支撑，而不是进行简单的编辑。你还可以将 Workshop 中的其他参数或值传入你的操作类型。

在以下场景中，请考虑将函数支撑的操作类型用于拖放操作：

  • 你想要编辑排程对象，并有条件地触发对本体论中其他对象的编辑。
  • 你想要编辑排程对象并在本体论中创建其他对象。
  • 你想要编辑排程对象并调用 API。

建议函数

在将 puck 拖放到另一行和/或另一时间时，你可能希望为最终用户提供按需建议。 自定义建议 > 建议函数 使你能够定义一个在拖放时触发的函数。该函数可根据你的自定义逻辑，临时将甘特图上的时间段标为绿色或红色，以指示“好”或“坏”的放置位置。

查看 建议函数 以了解更多信息。
