容器转换

本页面假定您对容器化基础设施以及容器镜像等概念有一定的了解。如果您不熟悉这些主题，我们建议您先阅读 Docker 概述文档 ↗.

Foundry 通过两种方式与推送到平台中的容器进行交互：

  1. 使用 转换 sidecar 装饰器.
  2. 构建和使用 容器支撑的模型资产.

在这两种使用场景中，第一步都是按照下面列出的镜像要求，将镜像推送到 Foundry 内部托管的 Docker 注册表中。

镜像要求

  1. 镜像具有一个数字 userID.
  • 直方图 userID 在 Dockerfile 中定义的必须是数字且不能为 '0'。Foundry 不允许命令在容器内以 root 用户身份运行；在某些系统中，'0' 会被解释为零，而非数字 ID 可能会被设置为以 root 身份运行。
  • 对于 自带容器转换Workshop userID 必须具体为 '5001'。
  1. 镜像是为 linux/amd64 platform.
  • Foundry 仅支持运行为该平台构建的容器。Docker 的默认平台是 linux，因此请添加 --platform linux/amd64 选项卡中为 Docker build 命令 ↗ 来专门设置平台。
  1. 推送镜像时使用 digest 或除 latest.
  • 以外的任何标签。执行的 Docker push 命令应指定镜像的摘要，或使用一个不是 latest的标签。Foundry 不会执行标记为 latest 的镜像，因为没有任何机制可以确保给定的镜像确实是最新版本。
  1. 最大镜像层大小小于约 10 GB。
  • 强烈建议每个层的大小小于约 10 GB。如果您的使用场景需要更大的层大小，请联系您的 Palantir 代表。
  1. 任何暴露的端口都在 1024 到 65535 之间。
  • 0 到 1023 端口是知名端口，因此保留给 root 使用。Foundry 不允许命令在容器内以 root 用户身份运行；因此，在 Foundry 中启动镜像时，此范围内指定的任何端口都将不可用。
  1. [可选] 镜像已启用遥测。
  • 要启用来自容器的遥测日志记录：
    • 镜像必须在 /bin/sh.
    • 镜像必须支持 shell 命令 set and tee.
