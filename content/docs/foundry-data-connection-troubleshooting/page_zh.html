故障排除

当数据源表现不符合预期时，请使用此页面来诊断和解决问题。本页介绍了 Data Connection 中可用的故障排除工具、连接无法正常工作时应首先查看的位置，以及如何解决常见的连接和证书问题。

有关同步或代理特有的问题，请参阅 特定于功能的问题。

从何处入手

当数据源或连接无法正常工作时，请先使用此列表进行排查。

  1. 确认数据源可访问。 在源页面上，选择 预览 以确认连接已建立。如果失败，请打开 源终端 并运行 dig、 curl和 openssl s_client 以测试源的主机名和端口。
  2. 检查出站配置。 对于 Foundry worker 源，请确认正确的 出站策略 已附加，并且它们允许的地址、端口和协议与源所连接的目标相匹配。请查看 网络出站日志。
  3. 检查凭据。 如果您怀疑凭据已失效，请重新输入凭据，尤其是在迁移之后。
  4. 检查证书。 PKIX 或 SSLHandshakeException 错误表明未为数据源配置正确的证书。请参阅 证书与 TLS。
  5. 检查 OAuth 授权。 如果您的数据源使用 出站应用程序， HTTP 401: Unauthorized 则类似错误通常表明调用用户尚未完成交互式授权流程、出站应用程序已被禁用，或所配置的作用域不足。请参阅 OAuth 与出站应用程序。
  6. 转交给 AI FDE。 对于 Foundry worker 数据源，请使用 使用 AI FDE 进行调试 让 AI FDE 逐一走查这些检查并提供具体的修复方案。

如果您的数据源使用了 代理工作进程，另请确认该代理显示为 在线 （在 Data Connection 中），并查阅 代理故障排除参考 以获取针对特定状态的指导。

故障排除工具

Data Connection 提供多种内置工具，帮助您在不离开平台的情况下排查连接性、身份验证和数据移动问题。

使用 AI FDE 进行调试

对于 Foundry worker 源，您可以将调试工作交给 AI FDE，即 Palantir 的 AI 驱动的前置部署工程师。AI FDE 会将您的数据源及其关联的 出站策略 加载到上下文中，并使用与本页所述相同的出站日志和数据源调试工具，为您排查连接故障。

要从数据源启动 AI FDE 调试会话：

  1. 请在 数据连接 应用程序中打开您想要调试的数据源。
  2. 在 连接详细信息 面板中，选择 调试旁边的下拉箭头，然后选择 使用 AI FDE 进行调试。
  3. AI FDE 将在新标签页中打开，其中预加载了该数据源及其出站策略作为上下文，并提出一项调试计划，包括检查数据源配置、审查每个出站策略、检索网络出站日志以及运行实时连接测试。

AI FDE 将总结哪些部分正常运行、哪些部分出现故障，并建议具体的修复措施（例如：缺少出站策略、地址或端口不正确、TLS 配置问题或凭据问题）。

使用 AI FDE 进行调试 仅适用于使用 Foundry worker 运行时的源。AI FDE 要求在您的注册中 启用 AIP 。若要详细了解 AI FDE 的工作原理、它能做什么以及它如何管理上下文和权限，请参阅 AI FDE 概述。

源终端

系统提供了一个终端，该终端使用与您的源相同的连接设置，可帮助您测试与外部系统的网络连通性，可使用的命令包括 dig、 curl、 netcat和 openssl。

要打开该终端，请选择 调试 在 网络连接 面板中，位于 连接详情 下方（在源页面上）。

dig

该 dig 命令用于测试 DNS 解析，可用于检查您的源的主机名是否能正确解析。例如，要测试 DNS 是否解析 palantir.com，请运行 dig palantir.com。如果您在响应中看到 ANSWER SECTION ，则表示 DNS 解析成功。

以下是成功运行 dig 命令的示例：

appuser@localhost:/root$ dig palantir.com

; <<>> DiG 9.18.30-0ubuntu0.20.04.2-Ubuntu <<>> palantir.com
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 13561
;; flags: qr rd ra; QUERY: 1, ANSWER: 4, AUTHORITY: 0, ADDITIONAL: 0

;; QUESTION SECTION:
;palantir.com.                  IN      A

;; ANSWER SECTION:

palantir.com.           300     IN      A       151.101.1.170

;; SERVER: 10.100.0.53#53(10.100.0.53) (UDP)

;; MSG SIZE  rcvd: 142

curl

curl 命令用于测试与外部系统上特定主机和端口之间的 HTTP 连通性。如果未指定端口，则会根据协议推断端口（例如，HTTP 为 80，HTTPS 为 443）。例如，要测试能否连接到 https://palantir.com，请运行 curl https://palantir.com。

以下是成功执行 curl 命令的示例：

appuser@localhost:/root$ curl https://palantir.com
<HTML><HEAD><meta http-equiv="content-type" content="text/html;charset=utf-8">
<TITLE>301 Moved</TITLE></HEAD><BODY>
<H1>301 Moved</H1>
The document has moved
<A HREF="https://www.palantir.com/">here</A>.
</BODY></HTML>

如果 curl 命令挂起，请使用 --connect-timeout 标志设置超时时间（以秒为单位）：

Copied!
1curl --connect-timeout 10 https://palantir.com

openssl

该 openssl 命令用于测试 SSL/TLS 连通性，并验证 HTTPS 连接的证书。例如，要测试能否与 palantir.com 在端口 443，运行 openssl s_client -connect palantir.com:443 -servername palantir.com。

以下是成功 openssl 命令的示例：

appuser@localhost:/root$ openssl s_client -connect palantir.com:443 -servername palantir.com

---

如果连接成功，您将看到证书详细信息以及一条表明 SSL 握手已完成的消息。如果命令挂起或显示证书验证错误，则可能存在网络或证书配置问题。

在 UI 中配置的证书不会自动包含在终端环境中。要在终端中使用它们，请手动添加，可以采用内联方式，也可以使用 nano/vim:

Copied!
1echo "-----BEGIN CERTIFICATE-----
2MIIGXjCCBUagAwIBAgIQASByQ6gv8Z6X7wEqsyBb1DANBgkqhkiG9w0BAQsFADBY
3...
49lc=
5-----END CERTIFICATE-----" > server-cert.pem

要使用自定义证书（例如自签名证书或 mTLS）进行测试，请指定证书文件：

Copied!
1openssl s_client -connect my-server.example.com:443 \
2  -servername my-server.example.com \
3  -CAfile server-cert.pem \
4  -cert client-cert.pem \
5  -key client-key.pem

如果这些命令成功执行，但您的连接仍然无法正常工作，则可能是某些证书或源凭据配置不正确。

网络出口日志和指标

对于 Foundry worker 源，网络出口日志和指标可以让您了解源实际发出的网络调用。这些工具可以帮助识别仅通过基于终端的调试可能难以发现的网络问题。

  • 构建日志： 在构建页面中，选择 日志 并应用 网络出口日志 筛选器，以查看该构建的网络出口活动。
  • 控制面板： 导航至 控制面板 > 网络出口，选择一个策略，然后打开 可观测性 标签页，以查看每个源的聚合日志以及策略的使用指标。

源预览与探索

在深入调试之前，请先确认源是否从根本上可访问且配置正确：

  • 预览： 在源页面上，选择 预览 （位于右侧面板中），以确认连接已成功建立。
  • 探索： 使用 源探索 视图来检查源中的表、文件和预览。如果探索成功但特定同步失败，则问题更可能出在同步配置而非源本身。

作业跟踪器

要调查正在运行或最近完成的同步的状态，请打开 作业跟踪器 应用程序并选择该同步。从中您可以检查状态、阶段和日志，包括 _data-ingestion.log 用于 JDBC 同步。

连通性与出站流量

要使连接成功，必须允许 Foundry 通过网络访问您的外部系统。 Foundry 工作进程 上的数据源通过 出站策略来控制此行为，该策略会将允许数据源连接的特定主机、端口和协议列入白名单。在身份验证之前就失败的连接通常是出站问题。

要排查疑似出站问题：

  1. 确认已将正确的出站策略附加到源，并且这些策略允许的主机、端口和协议与您要连接的系统相匹配。
  2. 使用 源终端 测试主机是否可达，可使用 dig、 curl以及 openssl s_client。
  3. 查看 网络出口日志 以查看您的数据源实际发起的出站调用，并识别其中哪些被阻止。

要创建或请求出口策略，请参阅 配置出口策略。

证书与 TLS

本节假设 Foundry 作为客户端，与充当服务器的外部系统建立连接。有关底层概念的背景知识，请参阅 TLS ↗, mTLS ↗，以及 SSL ↗.

PKIX 和 SSL 异常

PKIX 异常和其他 SSLHandshakeException在 Foundry 缺少与源进行身份验证所需的证书时发生。请安装正确的证书：

  • Foundry 工作进程 数据源： 在数据源的设置中配置证书。请参阅 添加证书。
  • 代理工作进程 数据源： 请参阅 数据连接和证书。

对于仅支持已弃用的 TLSv1.0 或 TLSv1.1 协议的数据源，请参阅 使用不安全的 TLSv1.0 和 TLSv1.1 协议连接到数据源。Palantir 不建议使用已弃用的 TLS 版本。

服务器证书和客户端证书

了解服务器证书与客户端证书之间的区别非常重要。

服务器证书 (TLS)： 当 Foundry 客户端与外部系统建立 TLS 连接时，外部系统会出示证书以证明其身份，并提供建立加密连接所需的公钥。随后，Foundry 客户端会通过验证证书链直至受信任的根证书颁发机构（CA）来验证外部系统的身份。大多数系统默认信任一组知名的公共 CA。只有在以下情况下，您才需要将服务器证书添加到源配置（Foundry 的 truststore）：外部系统出示的证书并非由这些公共 CA 之一签发，例如自签名证书或由私有或内部 CA 颁发的证书。服务器证书仅提供证书本身，绝不提供私钥。

客户端证书（mTLS）： 客户端证书由 Foundry 客户端用于向外部系统证明其自身身份。使用 mTLS 时，外部系统和 Foundry 会相互验证对方的身份。客户端证书以证书和私钥对的形式提供。

要配置证书，请参阅 添加证书。

常见证书错误

[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self signed certificate in certificate chain

此错误表明源配置中缺少服务器证书。在 Python 环境中，整个 证书链 ↗ 都会在建立安全连接时由底层的 OpenSSL 库进行验证。

要获取外部系统的整个证书链，请运行以下命令：

Copied!
1openssl s_client -connect <external_systems_hostname>:<desired_port> -showcerts < /dev/null

此命令必须在能够通过网络访问外部系统的主机上运行。对于 Foundry worker 源，请在 源终端中运行。对于 agent worker 源，请在代理主机或其他能够访问代理网络的系统上运行此命令。

OAuth 与出站应用

当源配置了 出站应用时，身份验证将代表调用用户委托给外部 OAuth 2.0 提供程序。用户必须先完成 交互式授权流程 至少一次，之后才能在非交互式上下文（例如定时函数或 自动化）中使用该源。

常见 OAuth 错误

HTTP 401: Unauthorized

如果函数或工作流返回 HTTP 401: Unauthorized 尽管源已配置出站应用程序，请验证：

  • 调用该函数的用户已完成 交互式授权流程 至少一次。
  • 出站应用程序 已启用 在控制面板中。
  • 该 作用域 已在出站应用程序上配置，其中包含访问所请求的 API 资源所需的权限。

Credentials expired and no refresh handler provided

从 Python 或 TypeScript 函数调用源时会出现此错误。缓存的刷新令牌已过期，或已被外部 OAuth 2.0 服务器吊销。用户必须从交互式界面调用该函数（或由同一出站应用程序支撑的其他工作流），以重新完成授权流程。

Resolved source credentials are not present on the Source

从 Python 或 TypeScript 函数调用源时会出现此错误。这表明该源未配置出站应用程序，或者无法将调用身份解析为已授权的用户。请确认该源所属的域已配置 OAuth 2.0 身份验证，并且该函数是代表已通过身份验证的最终用户而非服务账号调用的。

特定功能相关的问题

上述指南适用于任何数据源。对于特定功能相关的问题，请参阅专门的参考文档：

  • 同步： 增量 JDBC 行为、间歇性失败和挂起， REQUEST_ENTITY_TOO_LARGE， BadPaddingException，以及意外的数据类型：请参阅 同步故障排除参考。
  • Agent 工作进程： Agent 状态、Agent Manager 和 Bootstrapper 启动错误、内存不足情况、下载问题以及权限：请参阅 Agent 故障排除参考。
  • 其他常见问题： 调度、重复行、架构不匹配以及 JDBC 数据类型：请参阅 数据连接常见问题。
