模型上的函数

您可以通过使用在运行时调用模型的函数，在本体论的上下文中部署模型。模型函数是围绕实时模型部署自动生成的包装器，可以导入到函数仓库中并从您的代码中调用。这使您能够围绕模型预测添加自定义业务逻辑、将模型与本体论对象集成，或编排多个模型调用。

概述

模型函数可以通过以下两种类型的部署发布：

  • 直接模型部署: 直接从模型页面发布。
  • Modeling Objective 实时部署: 从建模目标中的部署详情页面发布。

这两种方法都会创建一个与您的模型具有相同输入和输出 API 的函数。有关函数行为、版本升级和配置选项的详细信息，请参阅 模型函数开发者指南.

模型函数在 TypeScript v1、TypeScript v2 和 Python 函数中均受到完全支持。

在仓库中导入实时部署

为实时部署创建函数后，无论是 在模型本身上 还是在 建模目标中创建，都必须将其导入才能在特定仓库中使用。选择 将 和 查询函数 菜单中选择 资源导入 菜单（位于仓库左侧边栏）。可以通过发布时选择的函数名称搜索模型。Python 和 TypeScript v2 仓库仅支持与本体论绑定的模型函数，如下文所述。

对于 TypeScript v1 仓库，还可以通过选择以下方式导入模型函数 链接进行访问。，这在功能上等同于将其导入到 查询函数.

使用以下内容的模型旧版函数 API 名称 建模目标中的卡片，而非首选的 模型发布对话框 仍然可以在以下位置导入 《建模目标》 部分下，但正在逐步淘汰。

本体论绑定或空间绑定的函数

从 2026 年 2 月起，所有新的模型函数都将绑定到本体论。这是在以下环境中使用的前提条件 TypeScript v2 和 Python 函数，这些环境仅允许导入本体论资源。在此之前，模型函数绑定到模型的 空间。TypeScript v1 允许导入两种类型的模型函数，但导入和使用语义略有不同，具体 详见下文.

要检查函数是否绑定到本体论，请导航到您的模型：未绑定到本体论的模型函数会提示可以进行迁移。 了解有关将函数迁移为绑定到本体论的更多信息.

Marketplace 会跟踪导入到仓库中的模型函数。您可以 将支持的模型函数与其模型打包并直接部署，或将它们配置为用户在安装过程中选择的输入。Marketplace 不会跟踪通过 Platform SDK 直接查询而未导入的模型函数。

为实时部署创建函数后，必须将其导入才能在特定仓库中使用。然后可以对其进行查询 就像任何查询函数一样.

from functions.api import function, Double
from foundry_sdk_runtime import AllowBetaFeatures
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.objects import Flight


@function(beta=True)
def predict_flight_delays(flight: Flight) -> Double:
    # Prepare the input to match the model function's API.
    model_output = FoundryClient().ontology.queries.flight_model_deployment(
        df_in=[
            {
                "lastArrivalTime": flight.last_arrival_time,
                "lastExpectedArrivalTime": flight.last_expected_arrival_time,
            },
        ]
    )
    return model_output.df_out[0].prediction

import { Client } from "@osdk/client";
import { Double } from "@osdk/functions";
import { flightModelDeployment, Flight } from "@ontology/sdk";

async function predictFlightDelays(client: Client, flight: Flight): Promise<Double> {
    // Prepare the input to match the model function's API.
    const modelOutput = await client(flightModelDeployment).executeFunction({
        "df_in": [
            {
                "lastArrivalTime": flight.lastArrivalTime,
                "lastExpectedArrivalTime": flight.lastExpectedArrivalTime,
            },
        ]
    });
    return modelOutput.df_out[0].prediction;
}

export default predictFlightDelays;

然后，编写一个接收航班、为模型准备数据并解释模型执行结果的函数。模型作为遵循以下规范的异步函数导入 模型的输入和输出规范或 API。由此，TypeScript 可以在编译时确保向模型部署发送和从中接收正确的数据结构。

如果您的模型 API 声明了恰好一个表格输入和恰好一个表格输出，则关联的函数将接受单个 TypeScript 对象，其属性对应于为输入指定的列（如果 “启用逐行处理” 选项 已启用，这是默认设置。声明了任何其他输入或输出的模型 API 不符合逐行处理的条件。 predictFlightDelaysRowWise 下面的函数演示了这种模式。或者，可以考虑 在模型 API 中直接使用对象或对象集 以便在函数中更方便地将您的模型与对象结合使用。

直方图 predictFlightDelays 下面的函数返回一个 FunctionsMap，这是 TypeScript v1 中用于返回以对象或标量值为键的映射的类型。在此示例中，它将每个 Flight 对象映射到其预测的延迟值。

import { Function, Double, FunctionsMap } from "@foundry/functions-api";
import { Flight } from "@foundry/ontology-api";

@Function()
public async predictFlightDelaysRowWise(flight: Flight): Promise<Double> {
    // Prepare the input to match the model function's API.
    // This model function expects a single flight.
    // If you'd like to process multiple flights at a time,
    // publish a new model function version with row-wise processing disabled.

    // Note you can also use an Object directly in the model API
    // to avoid tedious mapping between a model API and an object type's properties.
    const modelInput = {
        "lastArrivalTime": flight.lastArrivalTime,
        "lastExpectedArrivalTime": flight.lastExpectedArrivalTime,
    };
    // Call the Live deployment.
    const modelOutput = await FlightModelDeploymentRowWise(modelInput);
    return modelOutput.prediction;
}

@Function()
public async predictFlightDelays(flights: Flight): Promise<FunctionsMap<Flight, Double>> {
    let functionsMap = new FunctionsMap();
    // Prepare the input to match the model function's API,
    // for the case where row-wise processing is not enabled.

    // Note you can also use an ObjectSet directly in the model API
    // to avoid tedious mapping between a model API and an object type's properties.
    const dfIn = flights.map(flight => ({
        "lastArrivalTime": flight.lastArrivalTime,
        "lastExpectedArrivalTime": flight.lastExpectedArrivalTime,
    }));
    // Call the Live deployment.
    const modelOutput = await FlightModelDeployment(
        {"df_in": dfIn}
    );
    for (let i = 0; i < flights.length; i++) {
        functionsMap.set(flights[i], modelOutput.df_out[i].prediction);
    }
    return functionsMap;
}

将模型函数迁移到绑定本体论的函数

当您通过用户界面将绑定空间的模型函数迁移到绑定本体论的函数时，使用该模型的 TypeScript v1 函数的现有已发布版本将继续工作。但是，导入语法将不再被识别，这意味着使用该模型函数的仓库的预览和标记新版本将不再有效。

迁移后更新您的 TypeScript v1 函数：

  1. 打开您的代码仓库并选择 资源导入 sidebar.
  2. 通过将 resources.json 文件更新为新版本，选择新创建的模型函数版本。
  3. 更新您的函数代码以使用上述查询函数语法，或参阅关于 调用查询函数 以了解更多详情。

通过 Foundry Platform SDK 和 Functions.Query ↗ 方法直接使用模型函数在迁移后会立即失效。这是因为这种使用模式通过 API 名称引用函数，而该名称会在所有模型函数版本中一次性全局迁移。要修复这些使用方，请在迁移后将 API 名称更新为其新值。

性能考量

模型作为函数运行时的一部分执行，因此所有标准的 限制 均适用。 如果您的函数支撑某个操作，则对生成的编辑数量存在 进一步的限制 。

对实时部署的调用会通过网络发送模型输入和输出数据，上限为 50 MB。此网络传输计入函数的 配置的时间限制。要增加函数的超时时间，请联系 Palantir Support。
