模型上的函数

您可以通过使用在运行时调用模型的函数，在本体论上下文中部署模型。模型函数是围绕实时模型部署自动生成的包装器，可导入到函数仓库中并在代码中调用。这使您能够围绕模型预测添加自定义业务逻辑、将模型与本体论对象集成，或者编排多个模型调用。

概述

模型函数可以通过两种类型的部署发布：

  • 直接模型部署： 直接从模型页面发布。
  • 建模目标实时部署： 从建模目标中的部署详情页面发布。

这两种方法都会创建一个与您的模型具有相同输入和输出 API 的函数。有关函数行为、版本升级和配置选项的详细信息，请参阅 模型函数开发者指南。

模型函数在 TypeScript v1、TypeScript v2 和 Python 函数中得到完全支持。

在仓库中导入实时部署

为实时部署创建函数后，无论是 在模型本身上 还是在 建模目标中，都必须先将其导入，才能在特定仓库中使用。请选择 添加 和 查询函数 ，位于 资源导入中 菜单（位于仓库左侧边栏中）。模型可通过发布时选定的函数名称进行搜索。请注意，Python 和 TypeScript v2 仓库仅支持与本体论绑定的模型函数，如下文所述。

备注

对于 TypeScript v1 仓库，还可以通过选择 模型来导入模型函数，这在功能上等同于在 查询函数下导入。

模型上的旧版函数，如果使用的是建模目标中的 API 名称 卡片而非首选的 模型发布对话框 ，则仍可在 建模目标 部分下导入，但正在逐步淘汰。

与本体论或空间绑定的函数

自 2026 年 2 月起，所有新的模型函数都将与本体论绑定。这是在 TypeScript v2 和 Python 函数中使用的先决条件，这些函数仅允许导入本体论资源。在此之前，模型函数绑定到模型的 空间。TypeScript v1 允许导入这两种类型的模型函数，但其导入和使用的语义略有不同，具体 如下文所述。

要检查函数是否绑定到本体论，请导航至您的模型：未绑定到本体论的模型函数将显示有可用的迁移。 了解有关将函数迁移为绑定本体论的详细信息.

Marketplace 会将导入到仓库中的模型函数识别为安装输入，从而实现结构化的依赖项跟踪。对于未导入模型函数而直接通过 Platform SDK 查询的模型函数，Marketplace 不会进行跟踪。

从 Python 或 TypeScript v2 函数调用模型函数

创建用于实时部署的函数后，必须先导入该函数才能在特定仓库中使用。随后即可对其进行查询 （如同任何查询函数一样）.

from foundry_sdk_runtime import AllowBetaFeatures
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.objects import Flight


@function(beta=True)
def predict_flight_delays(flight: Flight) -> Double:
    # Prepare the input to match the model function's API.
    model_output = FoundryClient().ontology.queries.flight_model_deployment(
        df_in=[
            {
                "lastArrivalTime": flight.last_arrival_time,
                "lastExpectedArrivalTime": flight.last_expected_arrival_time,
            },
        ]
    )
    return model_output.df_out[0].prediction

import { Client } from "@osdk/client";
import { Double } from "@osdk/functions";
import { flightModelDeployment, Flight } from "@ontology/sdk";

async function predictFlightDelays(client: Client, flight: Flight): Promise<Double> {
    // Prepare the input to match the model function's API.
    const modelOutput = await client(flightModelDeployment).executeFunction({
        "df_in": [
            {
                "lastArrivalTime": flight.lastArrivalTime,
                "lastExpectedArrivalTime": flight.lastExpectedArrivalTime,
            },
        ]
    });
    return modelOutput.df_out[0].prediction;
}

export default predictFlightDelays;

然后，编写一个接收航班、为模型准备数据并解读模型执行结果的函数。模型将作为异步函数导入，并遵循 模型的输入和输出规范或 API。由此，TypeScript 可以在编译时确保发送到模型部署以及从模型部署接收的数据结构均正确无误。

请注意，如果您的模型 API 恰好声明了一个表格输入和一个表格输出，则相关联的函数将接受单个 TypeScript 对象，这些对象的属性与为输入指定的列相对应，前提是 启用逐行处理 选项 已启用（此为默认设置）。声明任何额外输入或输出的模型 API 不符合逐行处理的条件。下面的 predictFlightDelaysRowWise 函数演示了此模式。或者，也可以考虑 在模型 API 中直接使用 Object 或 ObjectSet 以便在函数中将您的模型与对象配合使用。

下面的 predictFlightDelays 函数返回一个 FunctionsMap，这是 TypeScript v1 中用于返回以对象或标量值为键的映射的类型。在此示例中，它将每个 Flight 对象映射到其预测的延误值。

import { Function, Double, FunctionsMap } from "@foundry/functions-api";
import { Flight } from "@foundry/ontology-api";

@Function()
public async predictFlightDelaysRowWise(flight: Flight): Promise<Double> {
    // Prepare the input to match the model function's API.
    // This model function expects a single flight.
    // If you'd like to process multiple flights at a time,
    // publish a new model function version with row-wise processing disabled.

    // Note you can also use an Object directly in the model API
    // to avoid tedious mapping between a model API and an object type's properties.
    const modelInput = {
        "lastArrivalTime": flight.lastArrivalTime,
        "lastExpectedArrivalTime": flight.lastExpectedArrivalTime,
    };
    // Call the Live deployment.
    const modelOutput = await FlightModelDeploymentRowWise(modelInput);
    return modelOutput.prediction;
}

@Function()
public async predictFlightDelays(flights: Flight): Promise<FunctionsMap<Flight, Double>> {
    let functionsMap = new FunctionsMap();
    // Prepare the input to match the model function's API,
    // for the case where row-wise processing is not enabled.

    // Note you can also use an ObjectSet directly in the model API
    // to avoid tedious mapping between a model API and an object type's properties.
    const dfIn = flights.map(flight => ({
        "lastArrivalTime": flight.lastArrivalTime,
        "lastExpectedArrivalTime": flight.lastExpectedArrivalTime,
    }));
    // Call the Live deployment.
    const modelOutput = await FlightModelDeployment(
        {"df_in": dfIn}
    );
    for (let i = 0; i < flights.length; i++) {
        functionsMap.set(flights[i], modelOutput.df_out[i].prediction);
    }
    return functionsMap;
}

将模型函数迁移为绑定到本体论的函数

当您从用户界面将空间绑定的模型函数迁移为本体论绑定的函数时，使用该模型的现有已发布的 TypeScript v1 函数版本将继续正常工作。但是，导入语法将不再被识别，这意味着对使用该模型函数的仓库进行预览和标记新发布版本的操作将无法再正常进行。

要在迁移后更新您的 TypeScript v1 函数：

  1. 打开您的代码仓库并选择 资源导入 侧边栏。
  2. 通过将 resources.json 文件更新到新版本，选择新创建的模型函数版本。
  3. 更新您的函数代码，以使用上文详述的查询函数语法，或参阅关于 调用查询函数 的专门文档以了解更多详情。

通过 Foundry Platform SDK 和 Functions.Query ↗ 方法直接使用模型函数的方式将在迁移后立即失效。这是因为这种使用模式通过 API 名称引用函数，而该 API 名称会在所有模型函数版本中一次性全局迁移。要修复这些调用方，请在迁移后将 API 名称更新为新值。

性能注意事项

模型作为函数运行时的一部分执行，因此所有标准 限制 适用。 如果您的函数支撑某个操作，则对生成的编辑数量存在 更多限制 。

对在线部署的调用会通过网络发送模型输入和输出数据，上限为 50 MB。此网络传输计入函数的 配置时间限制。如需延长函数的超时时间，请联系 Palantir 支持团队。
