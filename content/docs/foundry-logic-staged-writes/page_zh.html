AIP Logic 中的暂存写入

Beta

暂存写入功能目前处于 beta 开发阶段，您的注册环境中可能无法使用此功能。在开发过程中，功能可能会有所变化。请联系 Palantir 支持团队以申请访问权限。

暂存写入为在本体论中编辑对象的 AIP Logic 函数提供了一种改进的执行模型。新创建的 Logic 函数即将默认启用暂存写入。

与旧版本体论编辑行为相比，暂存写入 Logic 函数：

  • 支持在嵌套函数和操作调用中编辑本体论。 暂存写入 Logic 函数可以调用其他暂存写入函数或直接进行本体论编辑的其他函数，也可以应用由进行本体论编辑的其他函数支撑的操作。这在以前是不受支持的。
  • 支持所有对象集筛选器。 现在支持所有对象集筛选器，包括 包含关键字 和 相对时间范围，这些筛选器在旧版模式下不受支持。

有关暂存写入语义的完整说明，请参阅 暂存写入文档。

与旧版行为的主要差异

暂存写入 Logic 函数与旧版本体论编辑行为之间存在若干显著差异。

嵌套函数和操作调用中的本体论编辑

启用暂存写入后，您的 Logic 函数可以调用其他暂存写入函数（例如其他 Logic 函数或 TypeScript v2 函数）或直接进行本体论编辑的其他函数，或应用由执行本体论编辑的其他函数支撑的操作。此前，不支持在 Logic 函数内调用由另一个同样进行本体论编辑的 Logic 函数支撑的操作。

嵌套调用所做的编辑在同一 Logic 执行中的后续读取中可见。所有编辑都会暂存到临时存储中，并在执行完成后应用于本体论。

例如，处理支持电子邮件的 Logic 函数可以创建一个 Support Ticket 对象，然后应用由单独的 Logic 函数支撑的分类操作。该分类函数可以分配工单并编辑相关对象。所有编辑会一起暂存，Logic 函数中稍后的代码块可以查询这两者的结果。

支持所有对象集筛选器看板

在旧版模式下，一旦您的 Logic 函数进行了编辑，在执行的剩余部分中，某些对象集筛选器看板将不再受支持：

  • 包含关键字
  • 包含关键字（按顺序）
  • 相对时间范围

启用暂存写入后，AIP Logic 执行过程中现已支持所有对象集筛选器。

函数输出不再是本体论编辑列表

编辑本体论的旧版 Logic 函数会返回本体论编辑列表作为其输出。而暂存写入型 Logic 函数则会将其编辑暂存到临时存储中，并在执行完成后将其应用于本体论。因此，函数不再返回本体论编辑，而是可以返回其他类型的值。

由于暂存写入型 Logic 函数不返回本体论编辑，因此无法在 Automate的 Logic 效果中选择它们。要从 Automate 调用暂存写入型 Logic 函数，请使用操作类型对其进行包装，并使用操作效果。请参见下方的 Automate 暂存写入型 Logic 函数 章节。

启用或禁用暂存写入

新的 Logic 函数很快将默认启用暂存写入。您可以使用 启用暂存写入模式 开关为 Logic 函数开启或关闭暂存写入，该开关位于 执行模式设置 下方（在 AIP Logic 中）。

禁用暂存写入会使函数恢复为传统行为，即函数返回本体论编辑列表作为输出。如果您的工作流依赖于在 Automate 中通过 Logic 效果直接调用 Logic 函数，则可能需要禁用暂存写入。

我们建议保持启用暂存写入，并通过操作类型调用函数。传统行为不支持在嵌套操作调用中进行本体论编辑，不支持在函数进行编辑后使用关键字和相对时间范围筛选器，并且将来会被弃用。

切换模式时的版本控制

启用或禁用暂存写入对版本控制的影响取决于函数的输出类型：

  • 输出类型为本体论编辑列表： 启用或禁用暂存写入将发布函数的新 主版本 ，因为根据 Logic 配置，输出类型将更改为不同的类型。在操作或 Automate 中配置的版本范围不会跨越主版本边界，因此现有使用者将继续针对之前发布的版本运行，且不会自动升级。请参阅 迁移现有自动化 （见下文）。
  • 输出类型不是本体论编辑列表： 切换暂存写入不会更改输出类型，因此不会发生主版本号提升。如果现有使用者配置为自动升级，则会自动获取新版本。

在 Automate 中使用暂存写入 Logic 函数

暂存写入 Logic 函数必须通过 操作类型 调用，才能在 Automate 中使用。该操作提供了暂存和应用编辑的执行上下文。

从您的 Logic 函数创建操作类型

AIP Logic 提供了 “创建操作” 按钮，供暂存写入 Logic 函数使用，该按钮会生成调用您的函数的操作类型：

  1. 在您的 AIP Logic 文件中，导航至 “用法” 选项卡，然后选择 “创建操作”。
  2. 查看生成的操作类型。该操作的参数由您的 Logic 函数输入映射而来。
  3. 保存操作类型。

然后，您可以在 Automate 的 操作效果 中使用此操作，或在支持操作的其他任何位置应用它，例如 Workshop。

创建操作类型并不会启用或禁用该函数的暂存写入；执行模式仅由 “启用暂存写入模式” 开关控制。

或者，您也可以在 本体论管理器中将现有操作类型配置为由您的 Logic 函数支撑。使用 “创建操作” 创建新的操作类型通常是更简单的做法。

创建自动化

对于暂存写入 Logic 函数，创建操作类型后，请导航至 Automate 并创建一个 操作效果。

在 Automate 中，与任何其他操作效果一样，根据触发自动化的对象或值来配置操作参数。所有可用于操作效果的 Automate 功能——包括将操作暂存为 供人工审核的提案、重试策略和回退效果——都适用于调用暂存写入 Logic 函数的操作。

迁移现有自动化

如果您在某个已通过 Logic 效果直接用于自动化的 Logic 函数上启用暂存写入：

  • 该自动化 将继续针对 该函数之前发布的旧版主版本运行。启用暂存写入不会破坏现有自动化。
  • 如果您尝试将自动化更新到该函数的暂存写入主版本，将会 被阻止保存，因为 Logic 效果仅支持旧版 Logic 函数。
  • Automate 中的 “自动升级到兼容版本” 设置不会将自动化迁移到暂存写入版本，因为自动升级绝不会跨越主版本边界。

要将现有自动化迁移到分阶段写入：

  1. 在您的 Logic 函数上启用分阶段写入并发布。如果函数的输出类型是本体论编辑列表，这将创建一个新的主版本。
  2. 在 AIP Logic 中，选择 创建操作 （在 使用情况 选项卡中），以从该函数生成操作类型。
  3. 在您的自动化中，将 Logic 效果替换为提交所生成操作的操作效果。
  4. 保存该自动化。
