查询安全概述

Foundry 查询 使用 Foundry Synchronizer，它对所有同步的表强制执行只读权限；此外，对单个表的访问遵循在 Foundry 中数据集级别授予的访问权限。

对于 Foundry 之外的数据源，在查询中使用 Handlebars 会带来安全隐患，因为恶意用户可能通过用有害代码替换模板内容来执行注入攻击。因此，这些查询需要针对 Handlebars 使用的额外安全规则——这些规则将在下文中详细描述 每次同步只能执行一个 SQL 查询。此查询应产生一个数据表作为输出，并且不应执行像调用存储过程这样的操作。查询结果将保存到 Foundry 的输出数据集。 和 HTTP JSON 查询 章节中。

此外，任何引用用户变量的模板（例如 {{user.firstName}}）都会从服务器获取其值，而不是接受登录时传递给浏览器的值。

查询结果大小限制

SQL 和 Foundry 查询结果默认限制为 5,000,000 字节（5 MB）。如果您预计结果量较大，请将其拆分为多个查询。结果超出限制的查询将失败，而不是返回部分数据，因此之前成功的查询可能会随着底层数据的增长而开始失败。

选择 测试 在查询面板中查看错误，该错误会报告 Size of query result exceeded specified maximum size of 以及配置的限制（以字节为单位）。

要减小结果的大小，请仅返回应用程序使用的列，添加 LIMIT 子句或筛选器，或在查询中进行聚合。如果您的工作流需要超出配置限制的结果，请联系 Palantir Support。

查询 partial

查询 partial 允许您编写可在文档中的多个查询中重复使用的查询代码。要创建 partial，请点击 + New Partial 查询面板中的按钮。

您可以通过编写以下内容将 partial 插入查询中 {{>partialName}}。例如，假设您有一个名为 columnFilter 的 partial，其内容为 WHERE column={{param w8.selectedValue}}。您可以使用以下代码创建另一个查询 SELECT * from table {{>columnFilter}}。这会渲染为查询 SELECT * from table WHERE column={{param w8.selectedValue}}.

。您还可以向 partial 传递参数，语法为 {{>partialName arg1=value1 arg2=value2 arg3=value3}}。partial 上下文中参数的值将被您在特定查询中提供的值替换。值可以是静态值（如字符串或数字），也可以是 Handlebars 引用（例如 w8.selectedValue）。在上面的示例中，如果您有两个完全相同的查询，只是按两个不同的选定值进行筛选，则可以重新定义 columnFilter 设置为 WHERE column={{param columnValue}}，并将查询设为 SELECT * from table {{>columnFilter columnValue=w8.selectedValue}}，其渲染结果为 SELECT * from table WHERE column={{param w8.selectedValue}}，与之前相同。

您还可以嵌套 partial，从而在代码重用中实现代码重用。

要重命名 partial，请在编辑器面板中打开该 partial 并直接更新其名称。重命名 partial 后，查询中对该 partial 的所有 Handlebars 引用都会自动更新以反映新名称。

Partial 是 Handlebars 的概念，Slate 实现使用 Handlebars 语法。请参阅 Handlebars partial 文档 ↗ 以了解更多信息。

排查 API Gateway 查询问题

当提供 API Gateway 查询 失败时,预览面板中显示的错误并不总是问题的真正来源。诸如裸 400, 500，或 An error occurred 之类的通用消息通常会包装底层服务返回的更具体的错误。请按照以下步骤查找实际原因。

检查请求

选择 预览渲染后的查询 以查看 Slate 发送的请求。确认每个参数都包含您期望的值,并且没有 Handlebars 引用解析为空值。选择 查看查询模板 以返回编辑器。

检查原始响应

选择 < / > (位于预览面板中)以查看原始 JSON 响应而非解析后的结果。Foundry API 错误会返回指明具体问题的 JSON 正文,即使 Slate 仅显示状态代码:

您应仅使用 对象集面板 菜单中选择 平台 选项卡（在可能的情况下）加载数据。对象集面板允许您轻松查询本体论，并以类似于下文所示示例的表格格式返回数据。下文介绍的 Postgres 工作流程仅作为旧版用法的参考保留。

在开始本教程之前，您必须将 last-mile-flights 和 airports 您上传到 Foundry 的数据集设为在 Slate 中可用。打开 变量 面板中的卡片上时显示的眼睛图标，然后选择 +添加 以打开 Foundry 资源选择器。

在 Data Connection 中导航至 last-mile-flights 数据集，方法是选择 All Files > Getting started data，或使用资源选择器中的搜索框。找到数据集后，选择 Select last-mile-flights 选项以开始导入配置。

要查看配置选项，请选择旁边的箭头 同步到 Postgres.

Postgres 中的默认表名将包含文件路径和混合大小写的数据集名称。为了处理特殊字符 /、大写字母和空格，Postgres 会将表名视为带引号的标识符。这意味着每当在查询中引用该表时，您都必须包含双引号，否则 Postgres 将抛出语法错误。我们建议在设置中包含一个 Postgresql table name ，采用蛇形命名法、小写字母和 _ ，以避免使用双引号。

由于尚未定义数据访问模式，且 last-mile-flights 数据集相对较小，我们不会在表上创建任何索引。您以后随时可以添加这些索引。选择 应用并同步 以开始同步。您可以使用 检查状态 按钮来监控同步。
