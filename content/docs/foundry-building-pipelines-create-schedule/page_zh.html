创建计划

直方图 调度指标 计划编辑器是您可以创建新计划并编辑现有计划的地方。您还可以查看现有计划的指标，并了解该计划将如何构建您的数据集。

导航到计划编辑器

以下步骤将引导您进入 Data Lineage 计划编辑器，您可以在其中创建新计划：

  1. 在 Data Connection 中导航至 ，并从 您想要为其安排构建的数据集的，打开 操作 菜单，然后选择 管理调度.



  2. 这将带您进入一个 调度指标 图，右侧的计划面板列出了影响该数据集的所有当前计划。

    要创建计划，请点击 创建计划 按钮。



  3. 这将带您进入计划编辑器。



定义计划

要定义计划，您需要完成以下部分。

当您在 Data Lineage 中创建计划时，它将应用于图中配置的分支（包括回退分支）。

目标数据集

目标数据集指定构建结束时的数据集。默认情况下，只会构建这些数据集。在其他配置中，这些数据集可能是正在构建的一系列数据集中的最后一批。

可以通过将目标数据集添加到图中并将其标记为目标来选择目标数据集。

数据集将在 Data Lineage 窗口右上角设置的分支上构建。图中的数据集将根据它们如何影响计划或受计划影响来进行着色。

排除的数据集

排除的数据集指定在确定要构建哪些数据集时，在图遍历过程中将被忽略的数据集。被忽略数据集的所有上游数据集都不会被构建。

何时构建

触发器指定构建应在何时运行。当触发器中定义的条件得到满足时，将运行构建。

有两种基本类型的触发器：

  • 时间： 时间触发器在指定的时间点得到满足。

    了解更多关于时间触发器的信息。

  • 当数据集更新时： 在平台中发生指定数据集的更新后即满足。

    了解更多关于事件触发器的信息。

触发器可以组合以创建更复杂的复合触发器。可以使用触发器编辑器中的菜单选择组合触发器的方法：

  • 以下任一触发器： 当任一组件触发器得到满足时，该触发器即得到满足。

  • 以下所有触发器： 当所有组件触发器都得到满足时，该触发器即得到满足。

  • 高级配置： 显式配置如何组合组件触发器。

    选择高级配置后，通过插入关键字来组合组件触发器 AND 和 OR 在两个触发器之间。复合触发器可以通过将其放在括号内来进一步组合 ( 和 ).

    • AND 表示当两个组件触发器都得到满足时，复合触发器才会得到满足。

    • OR 表示当任一组件触发器得到满足时，复合触发器即得到满足。

    了解更多关于复合触发器的信息。

构建类型

构建类型指定如何构建所选数据集：

  • 单一构建： 构建目标数据集（不会构建其他数据集）。

  • 完整构建（包含上游）： 构建所有目标数据集及该目标的所有上游数据集，排除的数据集除外。如果上游依赖项发生变化，构建的数据集可能会发生变化。

  • 连接构建： 构建输入数据集（排除）与目标数据集（包含）之间的所有数据集。如果某个数据集位于输入数据集和目标数据集之间，但被显式添加为输入，它仍将被计划构建。如果某个数据集被选为目标数据集，但从输入数据集到该目标数据集没有构建路径，则该目标数据集将不会被构建。

对于连接构建，连接目标数据集和上游数据集的所有数据集必须通过调度所设置分支上的作业规范路径进行连接。

下面我们通过一个包含数据集的示例血缘来演示上述内容 D1, ..., D6，其中数据集 D2 的两个不同分支分别用作 D3 和 D4 的输入。在 master 分支上，以 D1 为输入、以 D5 和 D6 为目标的连接构建调度将仅尝试构建 D2、D4 和 D6。

出现此行为的原因是，在 master 分支上从输入 D1 到目标 D6 的连接构建选择将选择数据集 D2、D4 和 D6，因为数据集 D1 和 D6 之间存在作业规范路径。但是，从输入 D1 到目标 D5 的连接构建选择将不存在，因为沿 master 分支的作业规范路径中断了。

D1 (master) --> D2 (master) --> D4 (master) --> D6 (master)
                 |
                 | D2 (develop)
                 |
                  --> D3 (master) --> D5 (master)

在此示例中，若要将数据集 D3 包含在计划构建中，应将构建更改为完整构建，这样将包含 D3 以及输入 D1（因为它是 D5 的上游）。或者，要保持为连接构建选择，可以编辑以 D2（develop）为输入、以 D3 为输出的转换，使其包含 master 分支上的一个额外虚拟输入 D7，如下所示。此时，master 分支上以 D1 为输入、以 D5 和 D6 为目标的连接计划构建将构建 D2、D3、D4、D5 和 D6。

D1 (master) --> D2 (master) --> D4 (master) --> D6 (master)
                 |
                 | D2 (develop)
                 |
D7 (master) -------> D3 (master) --> D5 (master)

更一般地，对于连接构建调度，如果您使用的数据集来自与包含调度的分支不同的分支，则输入和目标构建之间必须存在同一分支上的连接作业规范路径，这些数据集才能包含在构建中。

构建范围

为了适应数据管道的动态特性，每次触发调度时都会重新评估要包含在构建中的数据集集合。 构建范围 定义了调度构建的边界；即使管道的内容发生变化，这些边界也将保持不变。有两种可用的范围选项：

  1. 按项目： 调度将仅允许构建所选项目内的符合条件的数据集。
  2. 按用户账户： 调度将仅允许构建调度创建者/编辑者有权构建的数据集。

项目范围限定

项目范围限定确保调度仅在所选项目内的数据集上运行。它允许调度在用户权限发生变化时不受影响地运行。当构建内容不太可能变化到无法在所选项目内运行的程度时（如下所述），此选项最为可靠。

在以下情况下，构建无法进行项目范围限定：

  • 您没有在项目上创建调度的权限。
  • 您没有构建这些数据集的足够权限。
  • 调度设置涵盖的数据集 移除标记 （您可以在 调度指标 中看到这一点，当图形按权限着色时）。
  • 调度设置涵盖必须使用用户账户构建的数据集。
  • 调度内容无法解析为一组明确的项目。

用户范围限定

采用用户范围限定时，调度构建将代表最后编辑（或创建）调度的用户触发。因此，构建将仅包含该用户有权构建的数据集。当计划管道可能发生变化并导致项目范围限定无法实现时（例如数据集被移动到另一个项目、新数据集需要使用用户账户运行等），此选项最为可靠。

如果范围限定用户失去访问权限，调度构建将失败

如果用户被停用或失去了对构建所必需的数据集的权限，计划构建将无法启动。按用户账户进行范围限定时，请确保该账户拥有可靠的权限，并记住在用户即将被停用时更改所有权。

部分中选择

高级设置指定了其他构建选项：

  • 失败时中止构建： 如果构建中的任何作业未成功，则通过取消所有其他作业立即结束构建。

  • 自定义失败作业的尝试次数： 失败作业的运行尝试次数。重试的作业作为同一构建的一部分运行。在所有重试都已尝试或发生表明无法执行重试的错误之前，作业不会被视为失败。将此值设置为 1 将阻止重试，因为作业只会被尝试一次。请注意，并非所有类型的失败都可以重试。计划运行时的重试次数将被限制为管理员配置的最大值。

  • 强制构建： 运行构建时忽略过期信息。无论数据集是否过期，所有数据集都将被构建。几乎从不需要此选项。需要此选项的罕见情况包括：

    1. 数据连接同步： 数据连接同步始终被标记为最新，因为它们具有外部来源的输入；Foundry 不知道外部数据是否已更新。我们建议将数据连接同步与构建的其余部分分开安排，以确保只有同步会被强制构建。
    2. 对象存储 v1 (Phonograph) 同步
外部转换计划

进行 API 调用的转换与数据连接同步的行为不同。这些转换始终被视为过期，任何构建计划都会触发它们，而无需 强制构建 选项。

  • 构建成功后重新触发： 反复触发计划以持续构建，直到所有输入都已被处理且计划的目标不再过期。要使此设置生效，计划必须：

    1. 包含至少一个使用以下内容的目标输出： 增量事务限制 （用于数据集）或 增量批处理限制 （用于媒体集）。如果计划中没有此类输出，将显示带有以下文本的警告： No resources in this schedule require re-triggering 。
    2. 已禁用 强制构建 设置。

  • 允许重叠运行： 默认情况下，当同一计划的另一个运行正在进行时，计划不会启动新的运行。启用此设置可允许运行重叠。使用此设置可以：

    • 降低具有长作业序列的管道的延迟： 新的运行可以在较早的运行完成整个管道的数据处理之前，在管道的开头开始处理新的输入数据。
    • 使用一个计划使多个数据集保持最新： 单个计划根据需要为每个数据集启动构建，而无需为每个数据集单独设置计划。

  • 自定义作业失败时的行为： 默认情况下，当作业失败时，构建会取消其依赖作业。启用此设置可指定作业失败时不应取消依赖作业的数据集。如果其中一个指定数据集的作业失败，构建将继续运行其依赖作业。

保存计划

定义完计划后，点击 保存计划 按钮。

这将返回到计划页面，您应该会在其中看到已保存的计划。
