编辑关联类型

警告

编辑关联类型可能会产生 破坏应用程序的后果 ，进而中断用户工作流程。请阅读下方关于 潜在破坏性变更 的内容， 然后再进行任何关联类型编辑。

潜在破坏性变更

无回写的关联类型

需要 Object Storage v1（Phonograph）注销并重新注册关联类型的支撑数据源的变更，会使该类型的关联在此重新索引期间于用户应用程序中变为 不可用 ；这些变更如下所述。

以下变更在保存时会注销并重新注册（或删除）关联类型的支撑数据源：

  • 更改多对多关联类型的支撑数据源。
  • 更改关联类型的基数。
  • 更改关联类型的外键。
  • 删除关联类型。

当您尝试保存其中任何一项变更时，系统会就其对用户应用程序可能造成的影响向您发出警告。

例如，如果 Workshop 应用程序中的 search around 使用了某个关联类型，则在重新索引完成之前，该 Workshop 应用程序将无法正常使用。您可以在关联类型的 Phonograph 面板（位于其 数据源 页面）中跟踪重新索引的进度。

了解有关 Object Storage v1（Phonograph）的更多信息。

带回写的关联类型

如果某个关联类型启用了回写，则对该关联类型进行编辑时应采取额外的预防措施。对关联类型所做的编辑历史存储在 Object Storage v1 (Phonograph) 中。每次构建回写数据集时，都会重新应用编辑历史，以获取回写数据集中已编辑关联的最终状态。当关联类型的支撑数据源从 Object Storage v1 (Phonograph) 中注销后，Object Storage v1 (Phonograph) 中的编辑历史将被删除，且之后的回写数据集构建将会失败。

除了 上一节中列出的需要注销的更改之外，当对启用了回写的关联类型的支撑数据源的 任意 列进行架构更改时，如果该关联类型 曾经 接收过编辑，即使当前不再接收编辑，也需要注销。架构更改包括对列名称和基本类型的更改。

警告

Object Storage v1 (Phonograph) 将 不会 自动取消注册关联类型的支撑数据源，以响应这些架构更改中的任一项。相反，重新索引将会失败，只有在撤销已保存的架构更改后，或者在关联类型的“数据源”页面的 Phonograph 窗格中手动取消注册并重新注册关联类型的支撑数据源后，才能成功。

当您尝试保存任何可能清除编辑历史的更改时，系统将警告您这些更改可能对编辑造成的影响。

既然您已经了解了编辑现有关联类型时的注意事项，现在就可以安全地进行更改了。

编辑现有关联类型

  • 导航到现有关联类型
  • 删除关联类型
  • 更改支撑数据源
  • 编辑关联类型的元数据

导航到现有关联类型

您随时可以切换当前正在处理的关联类型，方法是从主页侧边栏中选择关联类型页面，然后从列表中选择其他关联类型。您也可以随时在应用程序顶部的搜索栏中搜索新的关联类型。阅读更多关于 导航。

删除关联类型

您可以删除对象类型，方法是选择 关联类型视图侧边栏右上角的（三个点）图标（见下图），然后从下拉菜单中选择 “删除” 选项。系统将弹出一个对话框，确认您是否要将该关联类型暂存以进行删除。

  • 请注意，关联类型的删除仅在保存更改后才会生效，并且会破坏引用该对象类型的任何视图或应用程序。
  • 请注意，具有 active 状态的关联类型无法删除。阅读更多关于 状态的信息。

更改支撑数据源

您可以更改支撑数据源：

  1. 前往关联类型视图的 数据源 页面。
  2. 选择现有数据源旁边的 “选择” 图标。这将允许您浏览并选择 Foundry 中可用的数据源。
警告

更改关联类型的支撑数据源将移除旧数据源中的列与定义该关联类型的键之间的任何连接。键将自动为您重新映射， 前提是 您切换到的新数据源具有与旧数据源 相同的架构 。否则，您需要将键重新映射到新数据源。

编辑关联类型的元数据

  1. 状态： 选择关联类型窗格顶部的现有状态,以打开可用状态的下拉列表。请从 deprecated、 experimental和 active 状态中进行选择。
    • 了解更多关于 状态的信息。
  2. 键: 从下拉列表中进行选择,以更改多对多关联类型中的外键或列映射。
    • 请注意,在具有多对多基数的关联类型中,支撑数据源中的列必须映射到对象类型的主键。如果对象类型的主键属性类型与该属性在关联类型支撑数据源中映射到的列类型不同,将会出现错误,导致您无法保存。
    • 在具有任何其他基数的关联类型中,应用程序要求其中一个对象类型的键必须映射到该对象类型的主键,以确保基数的“一”端是唯一的。
  3. API 名称: 点击现有 API 名称即可更改其值。
    • 请注意,对于状态为 active 的关联类型,您无法更改其 API 名称。
      • 了解更多关于 状态的信息。
      • 了解更多关于 有效 API 名称的信息。
  4. 可见性: 请从关联可见性列表中检查可见性。一个 prominent 关联类型将促使应用程序优先向用户显示该关联类型。一个 hidden 关联类型将不会出现在用户应用程序中。
  5. 类型类： 将类型类作为附加元数据应用，以便应用程序对其进行解析。
    • 请参阅 可用类型类列表 以了解更多信息。
