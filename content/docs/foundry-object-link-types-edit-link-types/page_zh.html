编辑关联类型

编辑关联类型可能会产生 破坏应用程序的后果 从而中断用户的工作流程。请阅读下方关于 潜在破坏性变更 然后 的内容，然后再进行任何关联类型编辑。

潜在破坏性变更

无回写的关联类型

需要 Object Storage v1 (Phonograph) 注销并重新注册关联类型的支撑数据源的变更，会使该类型的关联在重新索引期间 不可用 ；这些变更在下文中描述。

保存时，以下变更将注销并重新注册（或删除）关联类型的支撑数据源：

  • 更改多对多关联类型的支撑数据源。
  • 更改关联类型的基数。
  • 更改关联类型的外键。
  • 删除关联类型。

当您尝试保存任何此类变更时，系统将警告您对用户应用程序可能产生的影响。

例如，如果某个关联类型在 Workshop 应用程序的 search around 中使用，则该 Workshop 应用程序将在重新索引完成之前处于损坏状态。您可以在关联类型的 Phonograph 面板中跟踪其重新索引的进度，该面板位于其 数据源 页面预览同步的数据。

了解有关 Object Storage v1 (Phonograph) 的更多信息。

带回写的关联类型

如果关联类型启用了回写，在编辑该关联类型时应格外小心。对关联类型所做编辑的历史记录存储在 Object Storage v1 (Phonograph) 中。每次构建回写数据集时，都会重新应用编辑历史记录，以获得回写数据集中已编辑关联的最终状态。当关联类型的支撑数据源从 Object Storage v1 (Phonograph) 中注销时，Object Storage v1 (Phonograph) 中的编辑历史记录将被删除，并且回写数据集的后续构建将失败。

除了上一节中列出的需要注销的变更之外 上一节，当对具有回写的关联类型的支撑数据源进行 schema 变更时，也需要注销 任意 曾 接收过编辑的关联类型的支撑数据源列 即使该列当前未接收编辑。Schema 变更包括对列名称和基础类型的更改。

Schema 变更不会触发自动注销

Object Storage v1 (Phonograph) 不会 不 自动注销关联类型的支撑数据源以响应这些 schema 变更。相反，重新索引将失败，只有在撤销已保存的 schema 变更，或者您在关联类型的数据源页面的 Phonograph 面板中手动注销并重新注册关联类型的支撑数据源时，才能成功。

当您尝试保存任何可能抹除编辑历史记录的变更时，系统将警告您对编辑可能产生的影响。

现在您已经了解了编辑现有关联类型时的注意事项，可以安全地进行更改了。

编辑现有关联类型

  • 导航到现有关联类型
  • 删除关联类型
  • 更改支撑数据源
  • 编辑关联类型的元数据

导航到现有关联类型

您随时可以通过从主页侧边栏选择关联类型页面并从列表中选择其他关联类型，来更改正在处理的关联类型。您也可以随时在应用程序顶部的搜索栏中搜索新的关联类型。阅读更多关于 导航.

删除关联类型

您可以通过选择 （三个点）图标（位于关联类型视图侧边栏的右上角，见下图），然后选择 删除 选项（来自下拉菜单）来删除对象类型。系统将弹出对话框，确认您要将该关联类型暂存以进行删除。

  • 删除关联类型仅在保存更改后才会生效，并且会破坏任何引用该对象类型的视图或应用程序。
  • 具有 active 状态的关联类型无法删除。了解更多关于 状态的信息.

更改支撑数据源

您可以更改支撑数据源：

  1. 在 Data Connection 中导航至 数据源 关联类型视图的页面。
  2. 选择 选择 图标（位于现有数据源旁边）。这将允许您在 Foundry 中浏览并选择可用的数据源。
仅在 schema 匹配时键才会自动重新映射

更改关联类型的支撑数据源将删除旧数据源中的列与定义关联类型的键之间的任何连接。只有在以下情况下，键才会自动为您重新映射 仅当 您切换到具有 相同 schema 的新数据源（与旧数据源相同）时。否则，您需要将键重新映射到新数据源。

编辑关联类型的元数据

  1. 状态： 在关联类型窗格顶部选择现有状态，以打开可用状态的下拉列表。从 deprecated, experimental日 active statuses.
    • 了解更多关于 状态的信息.
  2. 键： 从下拉列表中进行选择以更改外键，或多对多关联类型中的列映射。
    • 在具有多对多基数（cardinality）的关联类型中，支撑数据源中的列必须映射到对象类型的主键。如果对象类型的主键属性类型与其在关联类型的支撑数据源中所映射列的类型不同，将出现错误并阻止您保存。
    • 在具有任何其他基数的关联类型中，应用程序要求其中一个对象类型的键必须映射到该对象类型的主键，以确保基数的“一”端是唯一的。
  3. API 名称： 点选现有的 API 名称即可更改其值。
    • 您无法更改具有 active status.
      • 了解更多关于 状态的信息.
      • 了解更多关于 有效的 API 名称.
  4. 可见性： 从关联可见性列表中检查可见性。 prominent 关联类型将提示应用程序优先向用户显示此关联类型。 hidden 关联类型不会出现在用户应用程序中。
  5. 类型类： 将类型类作为附加元数据应用，可由应用程序进行解析。
    • 请参阅 可用类型类别的列表 的文档以获取更多信息。
