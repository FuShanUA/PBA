Foundry Streaming 的计算用量

Foundry Streaming 是一种高吞吐量、低延迟的计算形式，它会持续监听新传入的消息，应用用户定义的逻辑，并将其推送到管道中的下一个阶段。

Foundry 流依赖于分布式并行 worker 架构，每个并行 worker 都拥有专用于其特定流式处理作业的资源。流资源需求随活动流的最大吞吐量及其处理的消息总数而扩展。

计算量的衡量方式

流式计算用量分为两种类型：

  • 实时处理计算： 在实时数据上运行用户定义的转换的过程。此源类型称为“streaming”。

  • 归档计算： 将数据从流式层移动到 Foundry 存储层的过程。归档计算是一个批处理过程，将显示为“transform”。

在为 Foundry 用量付费时，默认情况下 streaming_usage_rate is 0.5。这是用户定义的转换在实时数据上运行的速率。如果您与 Palantir 签订了企业合同，请在进行计算用量计算之前联系您的 Palantir 代表。

Foundry 中流的实时处理计算量是通过其在整个运行期间（按挂钟时间计）所使用的计算秒数来衡量的。因此，在流式处理作业中使用更多计算资源（例如 vCPU、内存、并行化）会增加该作业的成本。作业运行时间越长，使用的计算量就越多。由于流被设计为持续运行以连续处理数据，因此流将持续使用计算资源，直到用户将其结束。

流是静态分配的；在流运行期间，它们每挂钟秒将使用恒定数量的计算秒数。流通常也会进行调整以满足峰值需求，这意味着流的计算用量不受数据量变化的影响。即使没有数据流经该流，流也会使用计算秒数。

流用量可以计算为单个作业管理器和多个任务管理器所使用的总秒数之和。每个并行 worker 将拥有相同的计算资源。

作业管理器的计算秒数按以下方式计算：

  • max(num_vCPU, gib_ram / 7.5) * streaming_usage_rate * stream_duration_seconds

任务管理器的计算秒数按以下方式计算：

  • max(num_vCPU, gib_ram / 7.5) * streaming_usage_rate * stream_duration_seconds * (num_parallel_task_managers + 1)
  • compute_seconds = job_manager compute_seconds + task_manager_compute_seconds

了解有关用于计算计算用量的值的更多信息，包括 内存与核心比率.

归档作业是与每个流一起运行的批处理作业。归档作业会定期从流的热存储层读取数据，并将数据移动到 Foundry 存储中，以实现可靠的持久化和历史跟踪。由于归档作业不像流本身那样具有相同的低延迟要求，因此它们按计划运行，并且仅在有数据需要归档时才使用计算资源。

归档作业用量基于单个 Spark 驱动程序，可使用以下公式计算：

  • compute_seconds = max(num_vcpu, gib_ram / 7.5) * num_seconds
    • 归档作业很小。归档器始终以 1 个 vCPU 和 4 GiB RAM 的最小配置运行。

调查 Foundry Streaming 用量

要查看流的总用量，请首先导航到 Resource Management 应用程序。然后，在 按资源划分的用量 部分并选择 详情 下找到您的流，以查看各个数据集的用量。

流的成本归属于该流生成的检查点数据集。此数据集作为该流处理的永久用量记录。此数据集上的流式用量在 Resource Management 应用程序中归入“streaming”类别。

每次运行流时，它将持续运行，直到用户停止为止。当用户停止某个流时，该次运行将显示在数据集的 历史记录 选项卡下。您可以查看每个流的配置文件，以了解历史流运行的性能和计算资源使用情况。

每次运行历史归档时，它会在 构建应用程序中发布其计算指标。使用 Builds 应用程序来调查每个已运行归档的资源分配情况。

了解使用量的驱动因素

流使用量的主要驱动因素是流本身的计算资源占用。在这种情况下，计算资源包括每个任务管理器的 vCPU 数量、每个分区的 RAM GiB 数量以及流中的分区数量。这些资源在流的配置文件中设置，并在流的持续时间内保持不变。

  • 流资源应分配以满足传入流的峰值吞吐量。如果传入消息量过高而计算资源无法有效处理，流将出现滞后。
  • 要更改流使用的资源，必须更改资源配置文件并重启流。
  • 归档作业的计算使用量随流中传输的数据量而变化。归档作业会读取自上次归档以来的所有数据。如果没有数据流入，则归档作业将使用零计算资源。当流处于活动状态时，归档作业每 10 分钟运行一次。

使用 Foundry Streaming 管理使用量

了解何时选择流式处理以及何时选择批处理对于特定工作流非常重要。流式处理适用于需要秒级延迟和持续计算的工作流。如果数据可以每隔几分钟运行一次，请考虑使用小型微批处理作业，它可以推送与流相同数量的数据，但计算秒成本更低，而数据延迟则明显更高。

  • 流的大小会显著影响每次运行使用的总计算秒数。应为流配置足够的资源，以处理该流预期的最大同时负载。
  • 选择合适的流大小非常重要，既要确保能够满足峰值负载，又要避免过度配置。这涉及仔细配置每个作业的大小（vCPU 和内存）以及流的任务管理器总数。
  • 流将持续运行，直到被停止。请仔细监控流式计算资源，确保流仅在需要时运行。

计算使用情况

以下示例展示了如何为一个假设运行 10 分钟的流计算使用量，尽管大多数生产流是持续运行的。

流配置文件

  • 作业管理器 vCPU：0.5
  • 作业管理器 gib_ram：1
  • 任务管理器 vCPU：0.5
  • 任务管理器 gib_ram：2g
  • 并行度：2
  • gib_ram：4
  • 流持续时间：10 分钟（600 秒）
  • streaming_usage_rate：0.5

计算

  • 作业管理器计算秒数 = max(vCPUs, gib_ram / 7.5 gib_ram) * streaming_usage_rate * 600s = max(0.5, 0.133) * 0.5 * 600s = 150 计算秒
    • 或者，每秒 0.25 计算秒，或每小时 900 计算秒
  • 任务管理器计算秒数 = max(vCPUs, gib_ram / 7.5 gib_ram) * (parallelism + 1) * streaming_usage_rate * 600s = max(0.5, 0.267) * 3 * 0.5 * 600s = 450 计算秒
    • 或者，每秒 0.75 计算秒，或每小时 2700 计算秒

此流运行 10 分钟的总计算使用量为 150 作业管理器计算秒和 450 任务管理器计算秒。了解更多影响 Foundry 中计算使用量的因素.
