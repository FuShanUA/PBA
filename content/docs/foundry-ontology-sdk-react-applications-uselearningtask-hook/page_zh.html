useLearningTask 钩子

该 useLearningTask 钩子是一个自定义 React 钩子，用于在高级待办事项应用中获取和管理学习任务数据。它通过用户信息、媒体内容和元数据来丰富基础任务数据。

此钩子采用了处理不同媒体类型和二进制内容的模式，并展示了使用 Result 类型进行错误处理，以及 blob URL 的资源管理。它与应用程序的本体论无缝集成，同时为组件提供简洁的接口。

查看 useLearningTask 参考代码。

关键功能

  • 使用 React 的 useCallback 来对函数进行记忆化，以防止不必要的重新渲染
  • 利用 SWR（stale-while-revalidate）的缓存机制，配合自定义的重新验证选项来优化性能
  • 实现对二进制媒体内容的 blob URL 管理
  • 提供基于 MIME 类型的智能媒体类型检测
  • 处理多种内容交付机制（嵌入式和链接式）
  • 使用 Result 类型进行稳健的错误处理
  • 通过批量请求高效获取用户数据，借助 useAdmin

数据获取

该 useLearningTask 钩子利用 SWR 的数据获取功能，配合自定义的 fetcher 函数完成以下操作：

  1. 查询特定的学习任务，使用 fetchOneWithErrors 以实现稳健的错误处理
  2. 根据任务配置处理媒体内容：
    • 如果 mediaReference 存在，则获取二进制内容并创建 blob URL
    • 如果 contentUrl 存在，则将其用作外部链接
    • 处理没有可用媒体的情况
  3. 通过 MIME 类型检测确定媒体类型
  4. 通过批量请求获取任务创建者和受理人的用户详细信息
  5. 将所有数据合并到 LearningTaskEnriched 结构中

import useLearningTask, { SupportedMediaType } from '../dataServices/useLearningTask';
import type { ITask } from '../dataServices/useTasks';

function LearningTaskViewer({ task }: { task: ITask }) {
  const { learningTask, isLoading, isError, metadata } = useLearningTask(task);
  
  if (isLoading) return <div>Loading learning materials...</div>;
  if (isError) return <div>Error loading content: {isError.message}</div>;
  if (!learningTask) return <div>No learning content available</div>;
  
  // Render different media types appropriately
  const renderMedia = () => {
    switch (learningTask.mediaType) {
      case SupportedMediaType.PDF:
        return (
          <div className="pdf-viewer">
            <iframe 
              src={`${learningTask.mediaUrl}#toolbar=0`} 
              title="PDF Content"
              width="100%" 
              height="500px"
            />
          </div>
        );
      case SupportedMediaType.IMAGE:
        return (
          <div className="image-viewer">
            <img 
              src={learningTask.mediaUrl} 
              alt="Learning content" 
              className="learning-image"
            />
          </div>
        );
      case SupportedMediaType.VIDEO:
        return (
          <div className="video-player">
            <video 
              src={learningTask.mediaUrl} 
              controls 
              width="100%"
            />
          </div>
        );
      case SupportedMediaType.LINK:
        return (
          <div className="external-link">
            <a 
              href={learningTask.mediaUrl} 
              target="_blank" 
              rel="noopener noreferrer"
            >
              Open learning resource
            </a>
          </div>
        );
      default:
        return <div>No media content available</div>;
    }
  };
  
  return (
    <div className="learning-task-viewer">
      <h2>{learningTask.osdkLearningTask.title}</h2>
      
      <div className="content-section">
        <div className="content-type-badge">{learningTask.mediaType}</div>
        {renderMedia()}
      </div>
      
      <div className="description-section">
        <h3>Description</h3>
        <p>{learningTask.osdkLearningTask.description || "No description provided"}</p>
      </div>
      
      <div className="people-section">
        <div className="assigned-to">
          <span>Assigned to: </span>
          <span>{learningTask.assignedTo?.username ?? "Unassigned"}</span>
        </div>
        <div className="created-by">
          <span>Created by: </span>
          <span>{learningTask.createdBy?.username ?? "Unknown"}</span>
        </div>
      </div>
    </div>
  );
}

边界情况和限制

在使用 useLearningTask 钩子之前，请考虑以下场景和限制：

  • 内存管理： 该钩子会创建 blob URL，但目前尚未实现清理逻辑。在生产应用程序中，应在不再需要时使用 URL.revokeObjectURL() 释放这些 URL，以防止内存泄漏。
  • 媒体类型检测： 媒体类型检测基于 MIME 类型，可能无法覆盖所有可能的格式。默认回退值为 NONE，这对于某些特殊的媒体格式来说可能并不合适。
  • 媒体错误处理： 虽然该钩子处理了任务获取过程中的错误，但对媒体内容的检索或处理并没有专门的错误处理。如果媒体加载失败，可能会导致未处理的异常。
  • 网络依赖： 该钩子会发起多个相互依赖的网络请求（任务数据、用户数据、媒体内容）。在网络状况较差的情况下，这可能导致级联失败或超时。
  • 大型媒体文件： 对于大型媒体文件，将整个 blob 加载到内存中的做法可能会导致性能问题。请考虑为大型文件实现流式加载或渐进式加载。
  • 浏览器兼容性： Blob URL 支持和媒体播放功能因浏览器而异。要实现完整的跨浏览器兼容性，可能需要额外的回退策略。
  • 媒体内容没有缓存策略： 虽然 SWR 会缓存任务数据，但对媒体内容本身并没有特定的缓存策略。为媒体 Blob 实现专门的缓存机制可以提升性能。
