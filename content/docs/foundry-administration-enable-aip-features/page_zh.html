启用 AIP 功能

Palantir AIP（人工智能平台） 在新注册中默认启用。2024 年之前开始的注册可能需要在 控制面板中手动开启 AIP 功能的访问权限。如果您是注册管理员，可以在 控制面板 > AIP 设置 中管理您的 AIP 配置。

请注意，启用 AIP 可能 产生额外的计算用量。

查看支持的模型列表。

AIP 与自定义工作流功能

AIP 的 AI 功能可分为三类：

  • AIP Assist： 一款由 LLM 驱动的支持工具，旨在帮助用户熟悉、理解 Palantir 平台并利用该平台创造价值。用户可以用自然语言向 AIP Assist 提问，并获得针对其问题的实时帮助。
  • 平台应用中的 AIP 助手功能： 由 LLM 提供支持的原生功能，旨在帮助最终用户在 Palantir 平台上执行常规工作流。这些是高度专用的功能，可利用平台知识来加速用户的日常操作。
  • 用于自定义工作流的 AIP 功能： 一组功能，允许开发者构建自己的、由 LLM 提供支持的工作流或应用程序。这些是专为开发者或数据科学家构建的开放式功能。

AIP 权限

在 Palantir 平台上，AIP 的使用受两级权限管控：

  • AIP 和核心助手功能: 开启 AIP、 AIP Assist 以及相关助手功能，适用于 代码仓库、 Pipeline Builder 和 Workshop。

  • 用于自定义工作流的 AIP 功能： 启用 AIP 后，平台管理员可以启用额外的一层功能，使开发者和应用构建者能够创建自定义 AIP 工作流，并向用户授予使用这些自定义 AIP 工作流所需的权限。授予权限后解锁的功能如下：

    • 点击式界面中支持 LLM 的功能
      • AIP Logic：使用 LLM Board
      • Pipeline Builder：使用 LLM 节点 和 文本转嵌入向量
      • AIP Automate
      • AIP Model Catalog
      • AIP Chatbot Studio （原名 AIP Agent Studio）
      • AIP Workshop 小组件： AIP Chatbot、 AIP Generated Content
      • AIP Workshop 翻译
      • Quiver
      • AIP Threads
    • 使用基于代码的工具进行开发的功能
      • 使用 LLM 的转换
      • 使用 LLM 的函数
      • 代码工作区中支持 LLM 的 Jupyter®

限制 AIP 使用

平台管理员可以在两个不同层面限制 AIP 的使用：用户组和组织。

用户组

要在用户组层面限制 AIP 的使用，平台管理员可以选择 所有人、指定的 用户组，也可通过选择 无人来限制使用。

请注意，某些应用程序（例如 AIP Logic）可能需要先在 控制面板 > 应用程序访问 然后才能使用。

组织

要限制组织上的 AIP，平台管理员可以启用 “将 AIP 限制到组织” 选项，并从下拉列表中选择所需的组织。请记住，此设置 会将 AIP 限制到所选组织。因此，任何未选中的组织都将无法使用 AIP。此外，如果某个注册未启用 AIP，则所有组织都无法访问 AIP。

只有当资源所属项目的 所有 组织标记都启用了 AIP 时，该资源才会被视为已启用 AIP。

启用 LLM

注册管理员在 “模型启用” 选项卡下管理 LLM 的使用，该选项卡位于控制面板的 “AIP 设置” 扩展中。启用模型系列时，需要接受适用的条款和条件，其中包括针对提供这些模型的子处理者的条款。

了解模型状态

“模型启用”界面中的每个模型系列都会显示以下三种状态之一：

  • 已启用： 该模型系列处于活动状态，可供用户和工作流使用。无需进一步操作。
  • 已禁用： 该模型系列在您的注册中可用，但尚未由管理员激活。要启用它，请选择 “管理” 并接受条款和条件。
  • 不允许： 由于法律、地域或基础设施方面的限制，该模型系列受到限制。请联系 Palantir 支持团队讨论可用性选项。

在初次启用来自子处理者的模型之前，注册管理员必须先接受适用的条款和条件。处于 已禁用 状态的模型系列可以直接通过 Control Panel 启用，而 不允许的 模型则需要由 Palantir 支持团队手动配置后才能使用。

启用子处理者后，Palantir 可能会启用符合已接受条款和条件下资格要求的其他模型系列。启用其他模型系列不会产生额外费用。新的子处理者需要管理员单独接受。注册管理员可以在 Control Panel 中查看并禁用模型系列。

禁用某个模型系列组会破坏依赖于该组中模型的工作流。
