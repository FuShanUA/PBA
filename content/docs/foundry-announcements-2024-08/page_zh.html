接口简介：一种新的本体论类型 [Beta]

发布日期：2024-08-27

我们很高兴地宣布推出新的 接口 本体论类型，它是一种基元，允许用户描述对象类型的形状及其能力。接口提供了对象类型的多态性，从而可以对共享相同形状的对象类型进行一致的建模和交互。

接口由 共享属性, 接口关联类型、 和 元数据 组成。一个接口可以由多个对象类型实现，并且可以扩展以支持接口的组合性。

本体论管理器中的一个 Facility 接口示例。

接口的强大功能

对于数据集成人员，接口可以表示一个管道目标，用于集成相似但不同的对象类型。对于应用开发者，接口可以作为访问所有实现对象类型的 API 层。

  • 针对接口的 Object Set Service 搜索将返回实现对象类型的匹配对象。
  • 用户可以与实现对象类型的对象进行交互：当以具体对象类型引用时使用其本地 API 名称，当以接口类型引用时使用属性和关联的接口 API 名称。

简而言之，实现接口后，下游应用可以通过接口定义与任何及所有实现对象进行交互。这样，用户就可以将接口作为 API 层来编写应用代码，而无需应用单独支持每个实现对象类型。此外，通过将接口用作应用 API 层，只需让新的对象类型实现该应用接口，即可将其添加到应用中，而无需修改代码来显式支持新的对象类型。

接口示例：调度

接口的一个常见用例是指示某个对象类型具有特定能力，例如指示某个对象表示可调度的事件。通过实现 Schedulable Event 接口，支持本体论的应用就可以将该对象用于动态调度工作流、日历管理等场景。

本体论管理器中的一个 Schedulable Event 接口，实现于 Flight 对象类型，并带有共享的 Start Time 和 End Time 属性。

开始使用接口

要向您的本体论添加接口，您可以在本体论管理器中 创建 新建接口或 扩展现有接口。 创建接口后，您可以随后 实现 该接口，方法是使用具有相应形状的对象类型，或者 编辑 该接口，使其随着本体论的演进更好地适应您的组织。

接口声明完成后，您可以通过 Marketplace 打包并安装接口， 在 Pipeline Builder 中实现接口， 并在 应用中将其用作您的 API。 本体论 SDK 应用中使用。

要了解有关接口及其使用方法的更多信息，请查阅我们的 接口文档.

开发路线图的下一步是什么？

在接口类型正式发布（GA）的过程中，我们将扩展对接口的支持，使其可作为操作、函数和 Workshop 小组件的输入。

在 Pipeline Builder 中使用单元测试提高管道可靠性

发布日期：2024-08-20

我们很高兴地宣布，您现在可以在 Pipeline Builder 中为管道实现单元测试。单元测试是调试、检测破坏性变更以及最终确保更高质量管道的宝贵工具。直接在 Pipeline Builder 中创建并运行单元测试，可以尽早发现问题，并更有信心地部署您的管道。

什么是单元测试？

与代码中的单元测试类似，Pipeline Builder 中的单元测试允许您确认管道逻辑在使用预定义输入进行测试时是否产生预期输出。单元测试包括：

  • 测试输入
  • 转换节点
  • 预期输出

测试输入和预期输出可以使用手动输入的数据集和架构或现有的数据集和架构来创建，从而实现快速、流畅的单元测试创建。要测试的转换节点可以在 Pipeline Builder 工作区中选择。

单元测试工作流程示意图，显示测试输入、被测试的转换节点和预期输出。

单元测试功能

您可以通过选择 单元测试 图标来访问单元测试。在右侧面板中，您可以选择相关节点并提供输入和输出数据集，从而创建和微调单元测试。

右侧面板中的单元测试图标。

配置单元测试并创建输入和输出数据集后，选择 运行测试 以显示预期输出和实际收到的输出。在这里，您可以评估结果，并在必要时对管道或单元测试进行迭代，所有操作都可以在一个地方完成。

单元测试结果示例，右侧显示测试结果和配置，底部显示预期输出和实际收到的输出。

作为这一灵活且功能齐全的测试界面的一部分，您可以轻松编辑和删除单元测试，以跟上快速演变的管道。单元测试的更改也会显示在提案页面中，使您能够跟踪更改，并确保在合并提案之前所有测试都通过。

改进的 Pipeline Builder 与本体论集成

发布日期：2024-08-13

Pipeline Builder 变得更加强大；现在可以直接从您的管道中创建和编辑本体论对象和关联类型、解决冲突以及迁移架构。得益于改进的 Pipeline Builder 与本体论集成，用户在 Palantir 平台上进行构建时，现在可以享受更流畅的工作流程和更强的多功能性。

以前，无法在 Ontology Manager 中编辑 Pipeline Builder 所拥有的对象和关联。现在，您可以在 Pipeline Builder 和 Ontology Manager 中对 Pipeline Builder 所拥有的对象进行更改，并使用必要的冲突解决和架构迁移功能来确保一致性。请注意，虽然在 Pipeline Builder 中创建的对象可以在 Ontology Manager 中编辑，但在 Ontology Manager 中创建的对象 不能 尚无法在 Pipeline Builder 中编辑。

通过操作启用编辑

首先，在 Pipeline Builder 或 Ontology Manager 中启用编辑。切换 允许对此类型的对象进行编辑 以允许在 Pipeline Builder 和 Ontology Manager 中进行编辑。这还将在 Workshop 和其他应用程序中启用基于操作的本体论编辑。请注意，目前只有 Pipeline Builder 中创建的批量支撑对象支持此功能，流支撑对象类型目前不支持编辑。

在 Workshop 中使用 struct 变量以减少网络调用并加速您的工作流

发布日期：2024-08-06

Workshop 现在支持一种新的 循环布局支持遍历各种数组类型，包括字符串、布尔值、数字、日期、时间戳和 变量类型，这是一种复合变量，包含其他变量类型的字段，并由函数支撑。这项新功能使应用构建者能够从函数返回自定义类型，或从 Logic 函数返回 struct，从而减少需要调用的函数数量以及总网络调用次数。使用 struct 变量类型可以降低复杂度、增强生成式 AI 的响应，并提升 Workshop 模块的性能。

在 Workshop 中创建 struct 变量以支持您的工作流

您可以使用在代码仓库中编写的函数或 Logic 函数来创建 struct 变量。如果某个字段的类型在 Workshop 中不受支持，该字段将被忽略并从初始化变量的字段中省略。请注意，目前不支持以下情况：struct 嵌套（例如，在一个 person struct 中，不能再包含另一个 struct bestFriend），以及 struct 数组。

Struct 变量 student1 由一个返回字段的函数支撑 name, birthday, studentId, isGraduated, isHonors （字段类型分别为） string, date, number, boolean, boolean。不支持的字段 bestFriend （属于嵌套 struct 的一种类型）目前尚不受支持，因此被省略。

从 struct 变量中提取字段以在小组件中显示

由于小组件和变量转换操作无法整体使用 struct，因此需要提取各个 struct 字段以供使用。下图展示了如何将字符串类型的 name 字段从 person struct 变量中通过 提取 struct 字段变量转换提取出来，然后用于 指标卡片小组件.

字段 name （位于 struct 变量上） student1 被提取到一个字符串变量中，并显示在指标卡片小组件上。

将 struct 变量作为函数的输入传递

最后，请了解 struct 变量也可以用作函数的输入。在配置一个使用 struct 作为输入的函数时，可以通过将鼠标悬停在 Preview schema 标签上预览 struct 输入的必填字段。这样，应用构建者可以通过参考 struct 变量的原始数据，轻松验证预期的输入 schema 是否与所选 struct 变量匹配 Current value.

一个返回两名学生共有课程代码列表的函数，接收两个学生 struct 作为输入。

值类型现已在本体论和 Marketplace 中正式发布

发布日期：2024-08-01

值类型 现已正式发布，它为字段类型提供了语义包装，包含元数据和约束，以增强类型安全性、表达能力和上下文信息。这些值类型可在平台中的多种对象类型和管道中重复使用，无需重复验证逻辑。您可以通过全新的值类型应用程序轻松创建和管理值类型，然后使用 本体论管理器将其应用于本体论中的属性。随着值类型正式发布，您还可以将值类型打包并安装到 实现程序化 DevOps，使团队能够沿用现有流程，以自包含、可重现且经加密签名的捆绑包交付代码。 中，以便在您的 Marketplace 产品中使用。

值类型应用程序，显示给定命名空间中可用的值类型。

添加用户定义的语义类型

借助值类型，您可以在集中进行数据验证的同时捕获数据的上下文和语义含义。您可以直接从值类型直观地定义和使用语义含义，而无需依赖列名或属性描述等信息。值类型还会在 Pipeline Builder 管道和本体论中对数据强制执行验证约束，使数据集成者和本体论管理者能够确保其数据流和模型中正确的语义类型。

例如，您可以定义一个 email 值类型，并为其设置正则表达式约束，以确保使用该值类型的任何属性都表示有效的电子邮件地址。这样，该值类型便可在多个对象类型和管道中重复使用，而无需为每个给定属性重复验证逻辑。此外，使用该值类型的每个属性都会被明确地理解为包含电子邮件地址。

在平台中使用值类型

一旦您 创建了值类型，就可以在 Foundry 中使用它来提供数据验证。值类型可用于多种用例：

  • 将值类型分配给对象类型属性
  • 将值类型分配给共享属性
  • 将值类型作为逻辑类型分配给 Pipeline Builder 管道属性，使用 logical type cast 表达式，并在写入对象目标时在属性上选择该值类型。

要为属性分配值类型，请在属性配置过程中从下拉菜单中选择该值类型。

本体论管理器中的值类型选择器，允许用户为属性分配值类型。
