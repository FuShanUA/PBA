推出接口，一种全新的本体论类型 [Beta]

发布日期：2024-08-27

我们很高兴地宣布推出全新的 接口 本体论类型，它是一种基元，允许用户描述对象类型的结构及其能力。接口提供了对象类型多态性，从而支持对共享相同结构的对象类型进行一致的建模与交互。

接口由 共享属性、 接口关联类型 以及 元数据 组成，这些元数据用于描述接口本身。接口可由多个对象类型实现，并且可以扩展，以支持接口的可组合性。

Ontology Manager 中的 Facility 接口示例。

接口的强大之处

对于数据集成人员而言，接口可以作为一个管道目标，用于集成相似但不同的对象类型。对于应用开发人员而言，接口则可以充当一个 API 层，用于访问所有实现该接口的对象类型。

  • Object Set Service 针对该接口执行的搜索将返回实现该接口的对象类型中的匹配对象。
  • 用户可以与实现该接口的对象类型的对象进行交互：当对象作为具体对象类型时，可使用其本地 API 名称；当对象作为接口类型时，可使用属性和关联的接口 API 名称。

简而言之，实现接口后，下游应用程序便可通过接口定义与任何及所有实现该接口的对象进行交互。这样，用户便可以将接口用作 API 层来编写应用程序代码，而无需应用程序逐一支持每个实现该接口的对象类型。此外，通过将接口用作应用程序 API 层，只需让新的对象类型实现该应用程序接口，即可将其添加到应用程序中，而无需修改代码来显式支持新的对象类型。

示例接口：Scheduling

接口的一个常见用例是指明对象类型具备某种能力，例如指明某个对象表示可调度的事件。通过实现 Schedulable Event 接口，对象即可被感知本体论的应用程序用于动态调度工作流、日历管理等场景。

一个示例 Schedulable Event 接口，实现于 Flight 对象类型，具有共享的 Start Time 和 End Time 属性。

接口入门

要向您的本体论添加接口，您可以 创建 新接口，或 扩展 Ontology Manager 中的现有接口。获得接口后，您就可以使用形状合适的对象类型来 实现 该接口，或 编辑 它，使其随着本体论的发展更好地适应您的组织。

声明接口后，您可以通过 Marketplace 打包并安装它们，在 Pipeline Builder 中实现它们，并在 Ontology SDK 应用程序中将它们用作您的 API。

要了解有关接口及其使用方法的更多信息，请查看我们的 接口文档。

开发路线图的下一步是什么？

在我们努力使接口类型正式发布（GA）的过程中，我们将扩展对接口的支持，使其能够作为操作、函数和 Workshop 小组件的输入。

在 Pipeline Builder 中使用单元测试提高管道可靠性

发布日期：2024-08-20

我们很高兴地宣布，您现在可以在 Pipeline Builder 中为管道实现单元测试。单元测试是一种宝贵的工具，可用于调试、检测破坏性变更，并最终确保更高质量的管道。直接在 Pipeline Builder 中创建并运行单元测试，以便尽早发现问题，并更有信心地部署您的管道。

什么是单元测试？

与代码中的单元测试类似，Pipeline Builder 中的单元测试可让您确认管道逻辑在使用预定义输入进行测试时会产生预期输出。单元测试包括：

  • 测试输入
  • 转换节点
  • 预期输出

测试输入和预期输出可使用手动输入或现有的数据集和模式创建，从而实现快速、便捷的单元测试创建。要测试的转换节点可在 Pipeline Builder 工作区中选择。

一张展示单元测试工作流程的图表，显示了测试输入、被测试的转换节点和预期输出。

单元测试功能

您可以通过选择右侧面板上的 单元测试 图标来访问单元测试。在这里，您可以通过选择相关节点并提供输入和输出数据集来创建和微调单元测试。

右侧面板上的“单元测试”图标。

配置好单元测试并创建输入和输出数据集后，选择 运行测试 以显示预期输出和实际输出。您可以在此处评估结果，并在必要时迭代您的管道或单元测试，所有操作均可在一处完成。

单元测试结果示例，右侧显示测试结果和配置，底部显示预期输出和实际输出。

作为这一灵活且功能齐全的测试界面的一部分，您可以轻松编辑和删除单元测试，以跟上快速演进的管道。单元测试的更改也会显示在提案页面中，让您能够跟踪更改，并确保在合并提案之前所有测试均已通过。

改进的 Pipeline Builder 与本体论集成

发布日期：2024-08-13

Pipeline Builder 变得更加强大；现在可以直接在您的管道中创建和编辑本体论对象类型和关联类型、解决冲突以及迁移架构。得益于改进的 Pipeline Builder 与本体论集成，用户现在可以在 Palantir 平台上构建时享受更简化的工作流程和更高的灵活性。

此前，无法在 Ontology Manager 中编辑 Pipeline Builder 拥有的对象和关联。现在，您可以在 Pipeline Builder 和 Ontology Manager 中对 Pipeline Builder 拥有的对象进行更改，并借助必要的冲突解决和架构迁移功能来确保一致性。请注意，虽然在 Pipeline Builder 中创建的对象可以在 Ontology Manager 中编辑，但在 Ontology Manager 中创建的对象 尚无法 在 Pipeline Builder 中进行编辑。

通过操作启用编辑

要开始使用，请在 Pipeline Builder 或 Ontology Manager 中启用编辑。打开 允许编辑此类型的对象 开关，即可在 Pipeline Builder 和 Ontology Manager 中进行编辑。这还将在 Workshop 和其他应用程序中启用基于操作的本体论编辑。请注意，目前仅 Pipeline Builder 中创建的批量支撑对象支持此功能，而流式支撑的对象类型暂不支持编辑。

编辑对象类型面板中的 允许编辑 开关。

应用程序之间的双向更改同步

为支持来自 Pipeline Builder 和 Ontology Manager 的本体论更改，我们引入了以下功能，以确保冲突、验证错误和架构更改得到无缝处理。

合并冲突解决方案： 我们新增了合并冲突解决对话框，让本体论管理器和管道构建器之间的编辑更加顺畅，并防止并发更新被覆盖。

本体论管理器中的合并冲突解决页面。

验证错误解决： 在部署对本体论进行更改的管道之前，系统会向您告知验证错误并提供解决选项。这样，当您尝试将无效更改推送到本体论时，就可以避免在管道部署期间出现错误和失败。

部署前必须解决的验证失败示例。

模式迁移支持： 我们新增了模式迁移对话框，供您在需要时选择不同的模式迁移选项，例如丢弃对某个属性的编辑，或将编辑转换为其他数据类型。

模式迁移对话框，可在需要时提供启用模式迁移的不同选项。

共享与 Marketplace 完全兼容的管道

具有本体论输出的管道现在可以通过 Marketplace进行打包和安装。共享或下载包含本体论对象类型和关联类型的管道，以更轻松地设置和部署工作流。

在 Workshop 中使用 struct 变量，以减少网络调用并加快工作流速度

发布日期：2024-08-06

Workshop 现在支持一种新的 struct 变量类型。struct 变量是一种复合变量，其中包含其他变量类型的字段，并由函数提供支撑。这项新功能使应用构建者能够从函数返回自定义类型，或从 Logic 函数返回 struct，从而减少需要调用的函数数量以及网络调用总数。使用 struct 变量类型可以降低复杂度、增强生成式 AI 响应，并提升 Workshop 模块的性能。

在 Workshop 中创建 struct 变量以支持您的工作流

您可以使用在代码仓库中编写的函数或 Logic 函数来创建 struct 变量。如果某个字段的类型在 Workshop 中不受支持，该字段将被忽略，且不会包含在已初始化变量的字段中。请注意，目前不支持以下情况：struct 嵌套（例如，在一个 person struct 中不能再包含另一个 struct bestFriend），以及 struct 数组。

struct 变量 student1 由一个函数提供支撑，该函数返回字段 name， birthday， studentId， isGraduated， isHonors 其字段类型为 string， date， number， boolean， boolean，分别。不支持的字段 bestFriend 是一种嵌套结构体类型，目前尚不支持，因此会被省略。

从结构体变量中提取字段以在小组件中显示

由于小组件和变量转换操作无法将结构体作为一个整体来使用，因此需要提取各个结构体字段以供使用。下图展示了字符串类型 name 字段是如何从 person 结构体变量中提取出来的，其中使用了 “提取结构体字段”变量转换，然后将其用于 指标卡小组件。

字段 name 从结构体变量 student1 中被提取为字符串变量，并显示在指标卡小组件上。

将结构体变量作为输入传递给函数

最后，请了解结构体变量也可以用作函数的输入。在配置使用结构体作为输入的函数时，将鼠标悬停在 Preview schema 标签上，即可预览结构体输入的必需字段。这样一来，应用程序构建者便能轻松验证预期的输入 schema 是否与所选结构体变量的 schema 相匹配，只需参照该结构体变量的原始 Current value。

一个返回这两名学生共有的课程代码列表的函数，接收两个学生结构体作为输入。

值类型现已在本体论和 Marketplace 中正式发布

发布日期：2024-08-01

值类型 现已正式发布，为字段类型提供包含元数据和约束的语义包装，从而增强类型安全性、表达能力和上下文信息。这些值类型可在平台中的多个对象类型和管道中重复使用，无需重复编写验证逻辑。您可以通过全新的“值类型”应用程序轻松创建和管理值类型，然后使用 本体论管理器将其应用于本体论中的属性。随着值类型正式发布，您还可以将值类型打包并安装到 Marketplace ，以便在您的 Marketplace 产品中使用。

“值类型”应用程序，显示给定命名空间中可用的值类型。

添加用户定义的语义类型

借助值类型，您可以在集中进行数据验证的同时，捕获数据的上下文和语义含义。您可以直接从值类型中直观地定义和使用语义，而无需依赖列名或属性描述等信息。值类型还会对 Pipeline Builder 管道和本体论中的数据强制执行验证约束，使数据集成者和本体论管理者能够确保其数据流和模型中的语义类型正确无误。

例如，您可以定义一个 email 值类型，并为其设置正则表达式约束，以确保使用该值类型的任何属性都表示有效的电子邮件地址。随后，便可在多个对象类型和管道中重用此值类型，而无需为每个给定属性复制验证逻辑。此外，使用此值类型的每个属性都会被明确理解为包含电子邮件地址。

在平台中使用值类型

一旦您 创建值类型，您就可以使用它在整个 Foundry 中提供数据验证。您可以在各种用例中使用值类型：

  • 将值类型分配给对象类型属性
  • 将值类型分配给共享属性
  • 将值类型作为逻辑类型分配给管道构建器中的管道属性，使用 logical type cast 表达式，并在写入对象目标时在属性上选择值类型。

要为属性分配值类型，请在属性配置过程中从下拉菜单中选择值类型。

本体论管理器中的值类型选择器，允许用户为属性分配值类型。
