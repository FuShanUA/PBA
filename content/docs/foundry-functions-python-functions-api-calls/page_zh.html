从函数中进行 API 调用

可以在 TypeScript v1、TypeScript v2 和 Python 函数中对外部源进行 API 调用，但这样做需要进行额外的配置。下文详细介绍了此配置及外部源的使用方法。

源别名

对于 TypeScript v2 和 Python 函数，我们建议通过 源别名来引用源。源别名是一种可移植的命名引用，您可将其用作源标识符，以代替特定源。当您的函数通过 Marketplace 产品分发时，可按环境将别名重新映射到不同的源，从而保持函数代码的可移植性。TypeScript v1 函数使用生成的源符号，不支持别名。

配置对外部 API 的访问

默认情况下，不允许函数调用外部 API。要在函数中启用对外部系统的调用，您必须 配置一个源 ，需在 Data Connection 中进行，以允许 Foundry 连接外部系统。

为了使函数能够安全地连接到您的源的外部系统，您的源必须配置为 启用导出 并允许 将您的源导入代码仓库。这两项配置均可通过在 Data Connection 中导航到该源并打开 连接设置 部分。

对于 TypeScript v1 函数，源的 API 名称（在 代码导入配置 选项卡中配置，该选项卡位于 连接设置下）即为您在代码中引用的标识符。

请确保在您的源中完整配置证书链。

Webhook 和函数的运行时环境并不相同。

有时，Webhook 能正常工作，而函数发起的 API 调用却可能会遇到 UNABLE_TO_GET_ISSUER_CERT 错误。

请参阅我们关于在源终端中使用 openssl 命令的文档， 以验证证书。

在函数中使用外部源

要从函数中进行 API 调用，您必须先使用 资源导入侧边栏将您的源导入到函数仓库中。对于 TypeScript v2 和 Python 函数，我们建议随后 创建源别名 并使用其别名键作为源标识符。TypeScript v1 函数直接引用导入的源。然后，您必须声明您的函数使用该源，如下面的示例所示。

import { MySource } from "@foundry/external-systems/sources";

export class MyExternalFunctions {

将 OAuth 2.0 与出站应用结合使用

如果您的外部 API 需要 OAuth 2.0 授权，您可以在 Control Panel 中配置一个 出站应用 并将其用作 REST API 源的身份验证方法。当您的函数运行时，该源会以会话凭证的形式公开调用用户的 OAuth 访问令牌。然后，您的函数可以使用该令牌代表用户调用外部 API。

此模式在 Python 和 TypeScript v2 函数中受支持。请参阅 使用源的预配置客户端 （见下文）以获取代码示例。

限制

  • TypeScript v1： TypeScript v1 函数无法直接从数据源检索 OAuth 令牌。要从 TypeScript v1 函数向 OAuth 2.0 API 进行身份验证，请将调用封装在 webhook 中，该 webhook 需位于配置了出站应用程序的 REST API 数据源上。请考虑 迁移到 TypeScript v2 以直接访问令牌。
  • 部署模式： 当函数在 部署模式下运行时，无法刷新 OAuth 令牌。如果调用用户的访问令牌在执行期间过期，函数将无法自动刷新该令牌。请在 无服务器模式 下运行您的函数，以使用 OAuth 支撑的出站应用程序。
  • 在 Workshop 中直接使用函数： 直接在 Workshop 模块中使用的函数（例如 函数支撑变量 或填充小部件内容的函数）无法触发 OAuth 2.0 交互式授权提示。如果用户尚未对出站应用程序进行授权，函数将失败，而不会显示该提示。要在 Workshop 中使用 OAuth 支撑的函数，请将其封装在 函数支撑操作中。或者，请确保用户在 Workshop 中直接调用该函数之前，先通过其他交互式界面（例如针对同一出站应用程序的函数支撑操作）完成授权流程。

import requests
from functions.api import function
from functions.sources import get_source
from external_systems.sources import OauthCredentials, Refreshable, SourceCredentials

@function(sources=["myOAuthSourceAlias"])
def call_external_api() -> str:
    source = get_source("myOAuthSourceAlias")
    url = source.get_https_connection().url

    refreshable_credentials: Refreshable[SourceCredentials] = source.get_session_credentials()
    session_credentials: SourceCredentials = refreshable_credentials.get()

    if not isinstance(session_credentials, OauthCredentials):
        raise ValueError("Expected OAuth credentials")

    access_token: str = session_credentials.access_token

    response = requests.get(
        url + "/api/v1/resource",
        headers={"Authorization": f"Bearer {access_token}"},
        timeout=10,
    )
    return response.text

import { getSource, getHttpsConnection } from "@palantir/functions-sources";

export const config = {
    sources: ["myOAuthSourceAlias"]
};

export default async function callExternalApi(): Promise<string> {
    const source = await getSource("myOAuthSourceAlias");
    const credentials = await source.sessionCredentials?.get();

    if (!credentials || credentials.type !== "oauth") {
        throw new Error("Expected OAuth credentials");
    }

    const accessToken: string = credentials.accessToken;
    const { url } = getHttpsConnection(source);

    const response = await fetch(url + "/api/v1/resource", {
        headers: { Authorization: `Bearer ${accessToken}` },
    });

    return response.text();
}

在操作中使用由 OAuth 支撑的函数

一种常见的模式是调用由 OAuth 支撑的外部 API，并将结果输入到 本体论编辑中。然后，您可以通过 函数支撑的操作来公开该函数。当用户从 Workshop 或 AIP Studio 运行该操作时，系统会使用其 OAuth 令牌进行 API 调用，产生的对象编辑将归属于该用户。

from functions.api import function, OntologyEdit
from functions.sources import get_source
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.objects import UserProfile


@function(sources=["myOAuthSourceAlias"], edits=[UserProfile])
def link_user_profile() -> list[OntologyEdit]:
    source = get_source("myOAuthSourceAlias")
    url = source.get_https_connection().url
    client = source.get_https_connection().get_client()

    response = client.get(url + "/v1/me", timeout=10)
    response.raise_for_status()
    profile = response.json()

    ontology_edits = FoundryClient().ontology.edits()
    ontology_edits.objects.UserProfile.create(
        profile["id"],
        display_name=profile["display_name"],
    )
    return ontology_edits.get_edits()

import { getSource, getHttpsConnection, getFetch } from "@palantir/functions-sources";
import { UserProfile } from "@ontology/sdk";
import { Client } from "@osdk/client";
import { createEditBatch, Edits } from "@osdk/functions";

type OntologyEdit = Edits.Object<UserProfile>;

export const config = {
    sources: ["myOAuthSourceAlias"],
    edits: [UserProfile],
};

export default async function linkUserProfile(client: Client): Promise<OntologyEdit[]> {
    const source = await getSource("myOAuthSourceAlias");
    const { url } = getHttpsConnection(source);
    const fetch = await getFetch(source);

    const response = await fetch(url + "/v1/me");
    if (!response.ok) {
        throw new Error(`Failed to fetch profile: ${response.status}`);
    }
    const profile = await response.json();

    const batch = createEditBatch<OntologyEdit>(client);
    batch.create(UserProfile, {
        userProfileId: profile.id,
        displayName: profile.display_name,
    });
    return batch.getEdits();
}

排查常见错误

对于 OAuth 授权错误，例如 HTTP 401: Unauthorized、 Credentials expired and no refresh handler provided或 Resolved source credentials are not present on the Source，请参阅数据连接故障排除参考中的 OAuth 和出站应用程序 。

HTTP 407：需要代理身份验证

函数的网络请求必须符合您数据源的 出站策略。如果目标主机名与任何允许的策略都不匹配，请求可能会返回 HTTP 407: Proxy Authentication Required。

如果您的出站策略看起来没有问题，请检查请求 URL 是如何构建的。来自 getHttpsConnection() 的 URL 没有尾部斜杠，因此省略了前导 / 的追加路径会直接与主机名拼接在一起：

"https://example.com" + "api/v1"

最终得到的主机名（example.comapi）未被任何出站策略覆盖，因此请求被拒绝。请为路径添加前缀 / （例如 url + "/api/v1"）。
