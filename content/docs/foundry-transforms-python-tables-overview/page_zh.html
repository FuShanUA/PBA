虚拟表上的 Python 转换

虚拟表 允许您查询和写入受支持数据平台中的表，而无需将数据存储在 Foundry 中。您可以在 Python 转换中使用虚拟表，通过 transforms-tables 库。

Foundry 在虚拟表上支持两种计算模式：

  1. Foundry 原生 Spark 计算： 此模式可与来自一个或多个数据源的虚拟表输入或输出一起使用，并可与 Foundry 原生数据集输入和输出组合使用。虚拟表不支持 轻量级计算引擎 （例如 Foundry 中的 Polars 和 Pandas）。
  2. 计算下推： 在此模式下，Foundry 通过轻量级方式在源系统中编排外部计算。要使用计算下推，所有输入和输出必须是关联到同一数据源的虚拟表，且该数据源必须支持计算下推。

使用以下内容进行增量计算 @incremental 装饰器在使用计算下推时目前不受支持。

前提条件

要在 Python 转换中使用虚拟表，您必须：

  1. 将您的 Python 仓库升级 到最新版本。
  2. 安装 transforms-tables 来自 库选项卡.

使用以下内容的转换 use_external_systems 装饰器与虚拟表不兼容。请切换到 基于源的外部转换 或将您的转换拆分为多个转换，一个使用虚拟表，另一个使用 use_external_systems 装饰器配合使用。

在代码仓库中使用虚拟表时，使用这些虚拟表的转换将根据数据源上配置的 出站策略覆盖 自动获取网络出口权限。

必须在数据源上启用以下设置：

  • 代码导入： 这允许在代码仓库中导入并使用该数据源。有关此设置的更多信息，请参阅以下文档 将数据源导入代码.
  • 导出控制： 这控制允许哪些 安全标记 和组织用于使用虚拟表的 Python 转换的输入。请查阅以下文档 在数据源上配置导出控制 的文档以获取更多信息。

请记住使用侧边栏将输出数据源导入您的仓库。

在 Python 转换中用作输入和输出的表不需要来自同一数据源，甚至不需要来自同一平台。默认情况下，Python 转换将使用 Foundry 的计算来读取和写入表，这允许跨不同外部系统进行查询。请参阅 计算下推 部分，了解将计算完全联合到外部系统的详细信息。

API 参考

有关以下内容的详细信息 TableInput, TableOutput，以及可用的 Table 子类（例如 BigQueryTable, DatabricksTable, DeltaTable, FilesTable, IcebergTable日 SnowflakeTable），请参阅 API 概述 文档。

from transforms.api import transform
from transforms.tables import TableInput, TableOutput, TableTransformInput, TableTransformOutput, SnowflakeTable


@transform.spark.using(
    input_table=TableInput('/path/input_table_name'),
    output_table=TableOutput(
        '/path/output_table_name',  # Virtual table output in Foundry
        'ri.magritte..source.123...',  # The output source RID
        SnowflakeTable('DATABASE', 'SCHEMA', 'TABLE'),  # The output storage location
    ),
)
def compute(input_table: TableTransformInput, output_table: TableTransformOutput):
    output_table.write_dataframe(input_table.dataframe())

from snowflake.snowpark.functions import lit
import snowflake.snowpark as snow
from transforms.api import transform
from transforms.tables import (
    SnowflakeTable,
    TableInput,
    TableOutput,
    SnowflakeInput,
    SnowflakeOutput,
)

@transform.snowflake.using(
    input_table=TableInput('/path/input_table_name'),
    output_table=TableOutput(
        '/path/output_table_name',  # Virtual table output in Foundry
        'ri.magritte..source.123...',  # Output source RID
        SnowflakeTable('DATABASE', 'SCHEMA', 'TABLE'),  # Output storage location
    ),
)
def compute_in_snowflake(input_table: SnowflakeInput, output_table: SnowflakeOutput):

    # Get a Snowpark DataFrame instance
    df: snow.DataFrame = input_table.dataframe()

    # Example data transformation - create a new column
    df = df.with_column("NEW_COLUMN", lit("ABC"))

    # Write back to the new table
    output_table.write(df)

JDBC 分区

使用 JDBC 连接读取虚拟表数据时，您可以在 Python 转换中配置分区，以并行化读取并提高加载表的性能。

下面是一个在加载时添加分区的示例 input_table。这将基于 column_name 该列将在下界 1 和上界 100 之间被划分为三个大小相等的分区。

@transform(
    input_table=TableInput("/path/input_table_name"),
    output_df=Output("/path/output_dataset_name")
)
def compute(input_table: TableTransformInput, output_df: TransformOutput):
    input_df = input_table.dataframe(
        options={
            "numPartitions": "3",
            "partitionColumn": "column_name",
            "lowerBound": "1",
            "upperBound": "100"
        }
    )

    output_df.write_dataframe(input_df)

分区配置应通过 options 参数传递，在调用 .dataframe() 加载虚拟表输入时。 partitionColumn 必须是数值、日期或时间戳列。数据将被分布到由 numPartitions指定数量的分区中。这些分区将是在 lowerBound 和 upperBound 选项。

直方图 lowerBound 和 upperBound 选项仅用于计算分区步长，而不用于筛选行。表中的所有行都将被返回，包括值超出指定边界的行。

有关可用分区选项的更多详细信息，请参阅 Spark JDBC 文档 ↗.

测试版

文件模板配置向导中的虚拟表输出位于 测试版 开发阶段。在积极开发期间,功能可能会发生变化。

虚拟表输入和输出可以在 Code Repositories 文件模板配置向导 选项。 virtual table 模板变量类型中进行配置。创建虚拟表输出时，向导将引导您选择一个输出 源 进行写入，并为虚拟表选择一个 Foundry 位置。
