在本地开发与 VS Code 工作区之间进行选择

在 Foundry 中使用 VS Code 时，您可以在两种开发环境选项之间进行选择：使用部署在 Palantir 基础设施上的 VS Code 工作区，或者在本地 VS Code 应用中安装 Palantir 扩展。本指南将帮助您了解两者差异，并根据您的需求选择合适的选项。

快速比较

VS Code 工作区用于本地开发的 Palantir 扩展
设置无需安装；选择 在 VS Code 中打开在本地下载并安装扩展
环境部署在 Palantir 基础设施上在本地计算机上运行
数据处理数据保留在平台上（显示的预览结果除外）预览期间将数据流式传输到本地内存
访问要求已启用 Code Workspaces管理员批准以及下载权限
第三方扩展不支持支持（如果您的组织允许）

选项：VS Code 工作区

最适合以下情况：

  • 快速入门： 无需安装或配置；打开您的代码仓库即可开始编码。
  • 敏感数据工作流： 开发过程中，数据始终保留在 Palantir 基础设施上，并受到严格的安全控制。
  • 需要一致环境的团队： 所有人都在同一个标准化环境中工作。
  • 无下载权限的用户： 无需对数据集执行下载操作即可预览转换。

选项：用于本地开发的 Palantir 扩展

最适合以下情况：

  • 偏好本地工作流程的开发者： 使用您现有的本地设置和熟悉的工具开展工作。
  • 使用第三方工具和扩展时： 访问完整的 VS Code 扩展市场（如果您的组织允许）。
  • 需要自定义开发环境时： 完全掌控您的 IDE 配置和已安装的工具。

要求：

  • 平台管理员必须在 控制面板中启用本地预览。
  • 您必须拥有对所有输入数据集的下载权限（s3-proxy:datasets-read 和 api:datasets-read）。
    • 这些是允许将整个数据集下载到本地的特权操作。

数据安全

VS Code 工作区

数据处理： 开发过程中，数据始终保留在 Palantir 基础设施上。结果表中仅显示预览结果（最多 1000 行）。不会将任何输入数据集流式传输到您的计算机。

安全控制： 始终保持严格的访问控制和审计日志记录。不存在数据意外泄露到本地计算机的风险。

用于本地开发的 Palantir 扩展

请查阅我们的文档，了解 本地开发的安全注意事项。

如果您不确定哪个选项最适合您，我们建议从 VS Code 工作区开始。此选项无需任何设置，并维持最严格的安全控制。如果您日后需要更多灵活性，可以随时切换到本地开发。

快速入门

VS Code 工作区

  1. 在 VS Code 中打开一个 受支持的代码仓库 。
  2. 从代码仓库中，您可以选择 在 VS Code 中打开 位于右上角(显示于受支持的仓库)。
  3. 在创建新仓库时,选择 VS Code 将自动带你进入 VS Code 工作区。
  4. 你的环境已就绪,可以开始编码了。

用于本地开发的 Palantir 扩展

  1. 请与你的管理员确认已启用本地预览。
  2. 确保你拥有对数据集的必要下载权限。
  3. 下载并安装 Palantir 扩展。
  4. 克隆您的仓库并开始开发。

如需详细的本地预览设置说明（包括 Java 转换），请查阅我们的文档： 在本地开发中预览转换。
