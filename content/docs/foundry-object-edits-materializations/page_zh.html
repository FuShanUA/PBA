物化

最新的数据对许多 Foundry 工作流程至关重要。本体论用户可以创建 物化 来自本体论的索引数据，通过合并输入数据源的数据和用户编辑，包含每个对象的最新状态。

物化的使用场景

物化的两个主要使用场景是：

  • 构建需要每个对象最新状态（包括用户编辑）的下游 Foundry 管道。
  • 支持下载包含某个对象类型所有对象最新状态的本体论数据。

我们建议在 Foundry 中通过创建物化数据集并使用其他 Foundry 数据集现有的下载工作流程（例如 数据导出 以及通过 Foundry 转换.

进行的导出）来编排批量下载

在 Data Connection 中导航至 物化 选项卡，方法是切换 编辑 配置 菜单中选择 数据源 本体论管理器中的选项卡。在 物化 选项卡上，您可以根据 输入数据源类型创建具有各种配置的物化对象数据集或对象受限视图。物化将自动更新，无法从数据集预览中手动构建。

回写数据集与物化数据集的比较

在对象存储 v1（OSv1，也称为 phonograph）中， 回写数据集 等同于物化数据集。在 OSv1 中，需要回写数据集才能在对象类型或带有连接表的多对多关联类型上启用用户编辑。

对象存储 v2（OSv2）不需要物化数据集来启用用户编辑。相反，用户可以通过切换 编辑 配置来为对象类型启用用户编辑，该配置位于 数据源 本体论管理器中的选项卡。这使得物化在 OSv2 中成为可选功能，用户只需在需要上述两个主要使用场景时才创建物化。OSv2 还允许创建多个物化数据集，以便用户只物化对象类型中的一部分属性。

OSv1 回写数据集与 OSv2 物化数据集之间的其他行为差异如下所述。

回写数据集和物化数据集中的构建计划

OSv1（Phonograph）回写数据集和 OSv2 物化数据集对构建计划的处理方式不同。

  • 在 OSv1 中，当有新的用户编辑时，没有触发回写数据集构建的机制。相反，用户可以创建 计划 来按自己需要的频率构建回写数据集。当没有新数据时，这些构建会自动中止，以避免使用额外的计算资源。如果未设置计划且回写数据集未被构建，回写数据集中的数据可能无法准确反映本体论。
  • OSv2 旨在以不同的方式解决两个不同的使用场景。
    • 要让用户编辑尽快反映到物化数据集中， 在编辑应用后，用户可以启用 automatic 传播用户编辑。此模式会自动将用户编辑传播到配置的物化数据集（延迟为几分钟）。这可能会产生额外成本，因为根据新用户编辑的频率，可能会发生更频繁的构建。
    • 如果用户编辑传播到物化数据集的延迟并不关键，用户可以通过配置 定期 构建来降低成本。在此模式下，只要输入数据源有新数据或每 6 小时，物化数据集就会重新构建。

回写数据集和物化数据集的保留

回写数据集和物化数据集的保留机制并不相同。

  • 在 OSv1 中，回写数据集的行为类似于常规数据集，可以对其设置特定的 保留策略 ，这些策略可以在平台内指定。如果回写数据集定期构建，这使得用户可以回溯查看对象类型状态的历史快照。

  • 在 OSv2 中，物化数据集受不可自定义的保留策略约束。历史事务会被不断删除，仅保证最新快照可用。在这种情况下，如果需要保留对象类型状态的历史快照，用户必须在下游设置一个转换。该保留策略同样适用于对象类型删除的情况，此时也需要一个下游转换来保留已删除对象类型的物化数据集。

写回数据集和物化数据集中的数据集 schema

OSv1（Phonograph）写回数据集与 OSv2 物化数据集与输入数据源 schema 的关联方式不同。

  • 在 OSv1 中，输入数据源的 schema 会被复制并用作写回数据集的 schema。
  • OSv2 改变了这一行为，以提高 Foundry 本体论的可读性。由于用户是从本体论物化数据，物化数据集所使用的 schema 会从本体论定义中复制，而不是依赖于支撑数据源的配置。具体来说， API 名称 （API 名称）元数据会被用作物化数据集的 schema。如果您希望在从 OSv1 迁移到 OSv2 的过程中继续使用输入数据源的 schema，请联系您的 Palantir 代表 从 OSv1 迁移到 OSv2 （例如，为保证现有写回数据集的向后兼容性）。

__ 前缀列（例如 __is_deleted, __patch_offset）在物化数据集中是 Foundry 用于去重目的的元数据列，不代表对象类型状态的任何信息。这些列可能在未来的版本中被重命名或删除，恕不另行通知，因此不应在生产工作流中使用。

从受限视图限制物化数据集

如果 OSv2 中的受限视图包含以下任一策略，则无法配置物化数据集：

  1. 如果受限视图包含引用用户强制控制并应用于字符串属性的条件。此时，您必须将本体论中的字符串属性转换为 强制控制属性，以确保您最多可以配置 基于分类的访问控制 or 强制标记 set.
  2. 如果受限视图具有授权组 ID 条件。
  3. 如果受限视图数据源具有直接引用 组织 或以静态值形式引用标记的条件。此时，您必须确保组织和标记的细粒度条件引用强制控制属性，而不是字符串属性或静态值。

分支

物化可以与全局分支（Global Branches）一起使用，但有以下限制：

  • 无法在分支上创建物化。
  • 无法在分支上编辑物化。

对具有关联物化视图的对象类型所做的更改将在分支中被索引。来自该分支的任何更新都将写入物化数据集或受限视图。删除对象类型或将其从分支中移除，也将删除物化数据集中的分支。由于受限视图的限制，物化受限视图分支将不会被删除。针对此限制的解决方案目前正在开发中。

故障排除

Catalog:TransactionDataDeleted 读取物化数据集时出错

如果对 OSv2 物化数据集的读取失败，并出现 Catalog:TransactionDataDeleted 错误，且该错误引用了物化数据集以外的数据集，则可能是保留策略删除了物化过程仍在读取的内部数据。这是一个已知限制，可能会影响数据在较长时间内未发生更改的对象类型。在该对象类型的 Funnel 管道 下次运行并对其数据进行更改后，读取将恢复正常。

为防止此错误再次发生，请联系 Palantir Support 并提供对象类型 RID 和完整的错误消息。Palantir Support 可以为该对象类型启用增量空操作事务。启用此配置会增加该对象类型的 本体论索引计算用量.
