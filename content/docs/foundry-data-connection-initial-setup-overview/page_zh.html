初始设置概述

本指南将引导您完成将组织数据连接到 Foundry 的过程。

在开始之前，重要的是要认识到，将组织数据连接到 Foundry 的第一步从根本上说是一个 网络概念。初始设置最好由熟悉网络工程并了解组织网络拓扑和配置（例如防火墙规则）的人员来完成。

概念概述

将数据连接到 Foundry 需要按以下顺序配置三个组件：

1. 配置网络连接

您必须首先确保 Foundry 与外部系统之间存在有效的网络路径。

对于与 Foundry 网络托管在同一网络上的外部系统（对于云托管的 Foundry 实例，这通常是通过 Internet 可访问的系统），请定义 直接连接出站策略 来路由流量。请确保外部系统允许来自 Foundry 的入站连接。

对于托管在与 Foundry 网络分离的网络上的外部系统（对于云托管的 Foundry 实例，这通常是本地部署系统），需要 代理 。代理是在您的组织网络内运行的 Palantir 软件，充当组织数据源与 Foundry 实例之间的安全中介。请确保外部系统允许来自代理的入站连接，并且代理能够与外部系统以及 Foundry 建立出站连接。

2. 数据源配置

您必须 配置数据源或连接，才能在执行任何 功能之前将外部系统连接到 Foundry。外部系统可以是例如 Postgres 数据库、S3 存储桶、Linux 服务器上的文件系统、SAP 实例，或通过 Internet 可访问的 REST API。

3. 功能配置

一旦配置了数据源以连接到外部系统，您必须配置 功能 在该数据源上执行。功能包括批量数据同步、流式同步、webhook、导出等。

A 功能允许将外部系统的数据同步到Foundry例如，从外部系统读取特定数据并将其摄取到 Foundry 中。如果您的 PostgreSQL 数据库包含多个表，您可以配置同步以将某个特定表摄取到 Foundry 中。同步成功运行后，Foundry 中的结果将是一个 数据集 ，可在 Foundry 的所有数据管道、模型开发和分析工具中使用。

角色和工作流

大多数 Foundry 用户永远不需要自己设置新代理。代理设置需要以 IT 为重点的技能，但同一个代理可以重复使用以支持多个数据源和同步。一些组织可以长期使用在 Foundry 部署的第一周内设置的代理来运营。只有当现有代理无法访问数据（例如由于网络分段或数据规模）时才需要新代理，或者设置额外的代理以实现 高可用性.

高可用性

我们建议设置冗余硬件以建立高可用性（HA）架构。高可用性可提高弹性，并允许在运营时间内进行无停机维护。

Foundry 在源级别提供高可用性，这意味着如果一个源被分配给多个代理，Foundry 会将摄取任务分派给其中一个健康的代理。我们强烈建议在创建源之初就将代理配置为高可用性设置；向已创建的源添加额外的代理需要重新输入该源的凭据。

设置高可用性时，建议遵循以下最佳实践：

  • 始终成对安装代理，并使用相似的硬件。
  • 为一对中的每个代理指定相似的名称，例如 agent-1 and agent-2.
  • 系统地将一对中的两个代理都分配给每个源。
  • 为一对中的两个代理配置不重叠的升级窗口。升级窗口应安排在工作日，并提供充分的浸泡时间。这样可以确保更新中出现的任何意外问题都仅限于单个代理，并且能够被操作员或管理员检测到。
