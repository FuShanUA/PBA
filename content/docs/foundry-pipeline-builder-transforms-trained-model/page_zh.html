已训练模型节点

已训练模型节点允许您直接在 Pipeline Builder 管道中运行用户定义的 机器学习模型 ——无论是在 Foundry 内部还是外部训练的。这使机器学习团队和无代码用户无需编写任何代码,即可将模型推理无缝集成到其数据管道中。

入门

1. 配置您的管道

确保您使用的是 Spark(批处理)管道,并且 “预热池” 设置为 “关闭”。如果您的现有管道未配置为使用 Spark(批处理)模式,请创建一个新管道。

2. 导入您的模型

在导入菜单中导航至 可复用资源 > 已训练模型 ,然后按照资源导入流程操作,使您的模型可供管道使用。

您可以从通过多种方法注册的模型中进行选择,包括:

  • 在 Palantir 代码仓库中训练的模型
  • 通过 Data Connection 数据源注册的模型
  • 通过 Compute Module 数据源注册的模型
  • 以文件或容器形式上传的模型

3. 添加模型节点

在管道画布中选择一个节点,然后选择 “已训练模型” 以将其插入。

该 “已训练模型” 选项仅在您按照 步骤 2将至少一个模型导入管道后才会显示。

4. 配置输入和输出

将您的输入列和输出列映射到模型预期的 API 架构。

  • 输入列 支持表达式，而不仅仅是直接的列映射。您可以在输入数据传递给模型之前，对其应用强制类型转换、转换以及其他表达式。
  • 输出列 可以在结果数据集中设置别名。这使您能够重命名模型输出字段，而无需修改模型本身。

支持的模型

目前，仅支持在其 模型 API 中具有单个表格输入和单个表格输出的模型。模型必须至少有一个 必需的 输入列。

使用模型节点时，您的模型必须准确返回模型 API 中定义的列。模型 API 中未定义的额外列将被丢弃，而缺失的列则可能导致构建错误。

时间序列模型可能会产生意外结果。推理会在数据的每个分区上独立运行，因此如果数据被随机或不正确地分区，需要分组或序列数据的模型可能会在碎片化的批次上运行。

对其他 API 类型和时间序列模型的支持计划在未来版本中推出。

支持的列类型

此功能支持模型， 其 API 包含以下用于表格输入列和输出列的数据类型：

  • 基本类型： string, boolean, integer, long, float, double, date, timestamp
  • 复杂类型： array, map, struct （包括嵌套字段）
  • 媒体： mediaReference

一个 mediaReference 列允许模型在推理期间读取所引用的媒体项。有关在模型适配器中使用媒体引用的详细信息，请参阅 媒体引用。

不受支持的类型（例如 objectSet ）会在验证时被拒绝。

资源配置与计算成本

模型作为隔离的 sidecar 进程与您的 Spark 执行器一同运行，每个进程都拥有自己专用的资源。每个模型 sidecar 的默认资源分配为：

资源默认值
CPU1 核
内存8 GB
GPU无

如果构建速度较慢，您可以采取以下一项或两项操作：

  1. 调高您的管道所使用的 计算配置文件 。
  2. 增加分配给模型的资源。

要调整模型的资源，请打开 模型导入 窗口（可复用资源 > 已训练模型），然后选择 配置资源：

这将打开配置面板，您可以在其中调整 CPU、内存和 GPU 分配，以及模型启动超时覆盖值，该设置位于 高级配置 部分：

资源配置是按 Pipeline Builder 管道设置的，而不是按模型节点设置的。在同一构建/管道中，同一模型的所有节点共享相同的资源配置。

请注意，与标准转换相比，这种 sidecar 进程隔离会带来额外的计算开销。每个模型都会在每个 Spark 执行器和驱动程序上启动一个 sidecar —— 有关其扩展方式，请参见下图。

自动升级与分支

Pipeline Builder 始终使用构建分支上最新可用的模型版本。例如，位于 master 的构建将始终使用发布到 master的最新模型版本。如果在构建分支上找不到该模型版本，系统将回退到已配置的 回退分支，通常是 master 分支,除非另有配置。这使机器学习团队能够放心地重新训练和发布新的模型版本,并确信下游构建会自动采用最新版本。目前无法将模型节点固定到特定版本;静态版本固定已计划作为未来功能推出。

模型尚不支持 全局分支。当管道使用全局分支时,模型版本解析将回退到已配置的回退分支,默认为 master 如果未配置任何回退分支。

Marketplace

当您打包使用已训练模型节点的管道时,用作转换的模型会自动作为资源添加到 Marketplace 包中,使用的是 随内容包含 打包模式。这意味着安装者在单次安装中即可同时获得管道及其关联的模型——无需额外配置即可打包模型。

或者,也可以在 DevOps 中将模型配置为 产品输入 ,这样安装者便可以选择其 enrollment 中已有的模型,而不是以打包内容的形式接收模型。

有关将 Pipeline Builder 管道添加到 Marketplace 产品的更多详细信息,请参阅 将管道添加到 Marketplace 产品。

Sidecar 超时

构建开始时，每个模型 sidecar 必须先下载并加载模型，然后才能处理推理请求。默认情况下，系统允许 sidecar 最多有 10 分钟的时间准备就绪。如果 sidecar 在该时间窗口内未能就绪——无论是由于模型仍在加载，还是由于 sidecar 已终止（通常是因为内存耗尽）——构建将失败并报超时错误。

如果您的模型加载需要更多（或更少）时间，您可以覆盖默认的启动超时设置。在 配置模型 对话框中，在 高级配置下方，设置 模型启动超时覆盖 值（以秒为单位）。将该字段留空即可使用默认值。

启动超时覆盖是按模型、按管道配置的，并适用于构建中为该模型启动的每个 sidecar。

一旦 sidecar 就绪，单个推理请求将 没有超时限制。这意味着长时间运行的模型——例如执行复杂计算或处理大批量数据的模型——不受单请求时间限制的约束，将一直运行至完成。
