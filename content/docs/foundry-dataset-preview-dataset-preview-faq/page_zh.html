数据集预览常见问题

以下是有关数据集预览的一些常见问题。

有关一般信息，请参阅 数据集预览概述.

  • CSV 因引号字符不匹配而无法解析
  • 数据集因某些底层 CSV 包含更多列而无法解析
  • 为什么我在 Microsoft Excel 中打开下载的数据集时显示异常？

CSV 因引号字符不匹配而无法解析

上传包含嵌套双引号和嵌入换行符（\n）字符（位于带引号的字段内）的 CSV 时，模式推断将失败，并且您无法使用模式编辑器创建有效的模式。

要进行故障排除，请执行以下步骤：

  1. 将 CSV 上传到数据集，然后选择 编辑模式.
  2. 设置 列 and 引号 properties.
  3. 忽略模式验证错误，然后选择 不验证直接保存，该选项位于 保存并验证 选项旁边的下拉菜单中。这将创建一个具有正确列定义的模式。
  4. 在监听器设置向导的 详情 选项卡中，以编辑模式打开模式。
  5. 最后，选择所需的起始数据集。 dataFrameReaderClass to com.palantir.foundry.spark.input.DataSourceDataFrameReader.
  6. 将以下内容添加到 "customMetadata" object:
  "customMetadata": {
    "format": "csv",
    "options": {
      "header": true,
      "multiLine": true
    }
  }

数据集因某些底层 CSV 包含更多列而无法解析

当数据集由多个 CSV 组成时（例如，通过数据连接 APPEND 事务），并且其中某些 CSV 包含更多列时，模式推断将失败。一种选择是忽略锯齿行（例如缺少某些列的行）。为此，请选择 编辑模式，展开 解析选项 部分，然后勾选 忽略锯齿行.

但是，如果您想保留锯齿行并为数据集指定标准化的模式，则本节适用。如果 假设 一节中概述的条件适用于您的数据，那么故障排除步骤将生成一个具有由用户 定义的标准模式的数据集，其中锯齿行将自动填充 null 以补足其缺失的列。

解析失败的症状：

您可能会遇到如下错误消息："无法加载预览：解析输入的 CSV 数据时遇到错误。请确保所有数据的格式正确。"

选择 编辑模式 用户偏好 保存并验证后，您还可能遇到以下错误消息： "您的数据集在 x 行上验证失败。"

假设:

  1. 您可以定义所需的模式，例如数据集应包含的所有列名称和类型。

  2. 您的模式强制执行严格的列顺序。例如，如果您希望数据集包含并显示列 {a, b, c}，则底层 CSV 可以具有如下列结构：

  • {a}
  • {a, b}

而且 不能 具有如下列结构：

  • {b, a}
  1. 如果底层 CSV 包含 n第 n+1 (n+1) 列，则它必须包含该列之前的所有列。例如，如果您希望数据集包含并显示列 {a, b, c, d}，则底层 CSV 可以具有如下列结构：
  • {a}
  • {a, b}
  • {a, b, c}

而且 不能 具有如下列结构：

  • {b, c, d}
  • {a, c, d}
  • {a, b, d}

以下是一个适用且有用的故障排除步骤示例：

CSV 定期通过 APPEND 事务添加到数据集中。某天，添加了一个新列，并且该列是 CSV 中的新的最后一列。在数据集中，来自之前所有追加的 CSV 的行都应包含该新列，其字段值自动填充为 null ，而不是被视为锯齿行。

故障排除步骤无法复制 mergeSchema 选项（适用于原始 Parquet 数据集，使用 com.palantir.foundry.spark.input.ParquetDataFrameReader 作为 dataFrameReaderClass进行解析）的功能。要在原始 CSV 数据集上复制此类功能，需要用户编写的转换。

要进行故障排除，请执行以下步骤：

  1. 在监听器设置向导的 详情 选项卡中，打开 模式 选项卡，然后选择 编辑
  2. 修改 fieldSchemaList 以确保它包含数据集应具备的所有列。例如，如果数据集应包含列 {a, b, c}，且均为整数类型，则 fieldSchemaList 可能如下所示：
  "fieldSchemaList": [
    {
      "type": "INTEGER",
      "name": "a",
      "nullable": null,
      "userDefinedTypeClass": null,
      "customMetadata": {},
      "arraySubtype": null,
      "precision": null,
      "scale": null,
      "mapKeyType": null,
      "mapValueType": null,
      "subSchemas": null
    },
    {
      "type": "INTEGER",
      "name": "b",
      "nullable": null,
      "userDefinedTypeClass": null,
      "customMetadata": {},
      "arraySubtype": null,
      "precision": null,
      "scale": null,
      "mapKeyType": null,
      "mapValueType": null,
      "subSchemas": null
    },
    {
      "type": "INTEGER",
      "name": "c",
      "nullable": null,
      "userDefinedTypeClass": null,
      "customMetadata": {},
      "arraySubtype": null,
      "precision": null,
      "scale": null,
      "mapKeyType": null,
      "mapValueType": null,
      "subSchemas": null
    }
  ],
  1. 最后，选择所需的起始数据集。 "dataFrameReaderClass" 及其嵌套的 customMetadata 对象，使您的 schema JSON 结尾如下所示：
"dataFrameReaderClass": "com.palantir.foundry.spark.input.DataSourceDataFrameReader",
  "customMetadata": {
    "format": "csv",
    "options": {
      "multiLine": true,
      "header": true,
      "mode": "PERMISSIVE"
    }
  }
}
  1. 选择 保存.

为什么我在 Microsoft Excel 中打开下载的数据集时显示异常？

从平台导出数据集时，某些文件在打开时可能会显示为挤压在一起。此问题在某些地区已被观察到，是由 Excel 中使用的默认分隔符引起的。要解决此问题，您需要在导出设置中更改分隔符模式：

  1. 在 Excel 中打开该文件。
  2. 选择 同步至数据集 功能区中的选项卡。
  3. 选择 文本分列 中的 数据工具 group.
  4. 在监听器设置向导的 文本分列向导 窗口中，选择 分隔符号 选项，然后 属性，然后选择.
  5. 在监听器设置向导的 分隔符号 部分，选择您要使用的分隔符（如逗号、分号、制表符）。
  6. 选择 属性，然后选择 用户偏好 完成 以完成该过程。
