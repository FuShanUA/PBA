Palantir 模型迁移常见问题

为什么数据集支撑的模型可能不会显示在活动页面上？哪些模型被视为使用中，哪些会被忽略？

升级页面会显示所有满足以下条件的数据集支撑模型：

  • 构建于 默认分支 （在过去 90 天内），或者，
  • 在过去 90 天内曾作为默认分支上某次构建的输入（包括受建模目标控制的批量部署构建），或者，
  • 是带有活跃实时部署的建模目标上的最新发布版本。

作为此次干预的一部分，不符合这些标准的由数据集支撑的模型将被标记为 Ignored，并且在默认情况下会从活动视图中被过滤掉。

已选定替代模型的模型，其状态将设置为 Completed，这同样会在默认情况下将其从活动视图中过滤掉。

弃用日期之后会发生什么？

使用 foundry_ml 开发的模型在建模目标、Python 转换或建模目标部署中将不再受支持。更具体地说：

  • 将无法再发布新的 foundry_ml 模型
  • 使用 foundry_ml 的代码将不再可编辑，并且任何导入以下内容的代码都将无法通过检查： foundry_ml
  • 任何使用 foundry_ml 模型的作业或实时部署可能会中断，并且将不再受 Palantir 支持

是否可以在不重新训练的情况下迁移模型？

可以在不重新训练的情况下迁移模型。为此，请在已安装 foundry_ml 并使用 Python 3.9 的代码仓库中加载该模型并将其写入输出数据集：

1from transforms.api import Input, Output, transform
2# Pickle may not be the right choice depending on the class of the models.
3# Refer to the documentation of the modeling library you are using to select a serialization method.
4import pickle
5from foundry_ml import Model
6
7
8@transform(
9    output_dataset=Output("<path_to_output_dataset>"),
10    source_model=Input("<path_to_foundry_ml_model>"),
11)
12def compute(output_dataset, source_model):
13    MODEL_STAGE_ID = <index_of_stage_to_save>
14    model = Model.load(source_model)
15    # Select the relevant model stage.
16    model_stage = model.stages[MODEL_STAGE_ID].model
17    # Write it to the output dataset.
18    with output_dataset.filesystem().open("model.pkl", 'wb') as f:
19        pickle.dump(model_stage, f)

然后，您可以基于此输出数据集，从单独的代码仓库发布模型，使用 palantir_models 以及更新的 Python 版本。请参阅 此教程以了解更多信息。

AIP 驱动的代码建议是如何生成的？代码建议的资源占用情况如何？

如果您的环境中已启用此功能，AIP 驱动的代码建议将通过 AIP 自动生成，并由 GPT-4o 提供支持。

为了减少对 LLM 的不必要或重复调用，AIP 驱动的代码建议会按需生成，并进行缓存以便重复查看。

具体而言：

  • 首次在 Upgrade Assistant 资源列表中看到某个资源时，系统会执行发送给 LLM 的代码建议提示。结果随后会被缓存，任何访问该资源的用户都可以使用。
  • 当用户向下滚动 Upgrade Assistant 资源列表时，任何新进入视野的资源，如果尚无缓存结果，都将触发对 AIP 的调用，以生成其相关的代码建议。
  • 如有需要，用户可以覆盖资源上现有的缓存结果，并重新向 AIP 发送提示以获取新的响应，方法是打开现有的 AIP 代码建议并选择 重新生成修复。

AIP 驱动的代码建议的资源使用量基于 标准 AIP 计算度量。

为什么 AIP 无法提供建议？

在以下情况下，AIP 可能无法提供由 LLM 生成的建议：

  • 未在默认分支（在大多数环境中称为 master ）上找到模型的代码，这很可能是因为该分支为空。可以通过导航到默认分支上的模型来验证这一点：如果 Foundry 无法找到模型的代码，将不会有 View Code 选项。
  • 该模型是一个 已提交到目标的 TypeScript 函数。这些模型可以通过 模型执行计划 在模型页面上显示 foundryFunctionV2 作为其类型。
  • AIP 可能因 LLM 输出不正确而未能生成建议。如果重新加载页面后问题仍然存在，请联系 Palantir 支持团队。
