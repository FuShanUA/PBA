应用操作时的权限检查

应用操作时的权限检查取决于您正在编辑的是 单数据源对象 或 多数据源对象.

单数据源对象的编辑

如果对象类型由单个数据源支撑，只要满足以下条件，操作即允许用户编辑对象：

  • 用户可以查看/加载该对象（详见 对象权限管理 章节）， 和
  • 用户通过 提交标准 中定义的检查。

创建新对象时，用户必须能够查看该对象类型的输入数据源；如果用户没有输入数据源的访问权限，操作运行将失败。

多数据源对象的编辑

对象类型可以拥有来自 多个数据源的属性。在这些情况下，用户对给定对象可能拥有不同级别的访问权限，如下所示：

  • 用户可以查看整个对象；例如，用户可能拥有所有数据源以及这些数据源中所有行的访问权限。
  • 用户可以查看部分数据源；例如，用户可能拥有某些数据源中所有行的访问权限，但对其他数据源中的行没有任何访问权限。
  • 用户可以查看部分数据源中部分行的访问权限；例如，用户可能对某些行拥有完整对象的访问权限，对某些行拥有对象的部分访问权限，而对其余行的对象没有任何访问权限。

如果对象类型具有多个数据源，应用操作时的权限检查会更加复杂，因为强制要求用户必须能够查看整个对象才能对其进行编辑（如同单数据源对象那样）可能会非常严格。

针对可应用于对象的不同类型的操作，实现了以下权限规则。

创建对象

场景：给定对象存在于数据源 D[i..k, m..n]中。用户仅通过设置 D[i..k].

中的属性值来创建对象。除非用户能够查看 D[i..k]的支撑数据源，否则不允许创建对象。不会对 D[m..n]进行任何权限检查。 D[m..n] 的值默认为 null.

如果 D[i..k] 中的任何一个过去包含该对象（但现在该对象被标记为已删除），用户必须拥有在所有 D[i..k] 中查看该行/对象的权限，才能重新创建该对象。

创建关联

场景：对象1存在于数据源 D1[i..k] 中，对象2存在于数据源 D2[m..n].

只要用户能够在任意数据源中加载对象1和对象2，即允许其删除关联 D1[i..k] 和 D2[m..n]中，则不允许删除该对象。不会对单个属性或数据源进行任何权限检查。
