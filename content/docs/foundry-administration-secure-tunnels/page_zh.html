配置安全隧道

Beta

安全隧道正处于 beta 开发阶段,可替代 agent 代理。在积极开发过程中，功能和配置选项可能会发生变化，并且该功能可能并非在所有租户上都可用。在将安全隧道用于生产工作负载之前，请联系您的 Palantir 代表或 Palantir 支持团队。

安全隧道 为 Palantir 平台中的服务提供一条网络路径，使其能够访问独立的私有托管网络中的系统，而无需将这些系统暴露给入站连接。它们的作用与 agent 代理相同；应用程序连接到数据源时，就像该数据源可以通过平台网络直接访问一样，而所有流量都经由运行在您网络内部的组件进行中转。

与作为单个可下载程序的 agent 不同，安全隧道由一组托管组件构建而成。安全隧道的 发起程序 是唯一在您的网络内部运行的组件。本页介绍其角色以及如何在您的网络中安装和配置它。

安全隧道的工作原理

安全隧道由三个组件建立：

组件位置角色
发起程序您的网络在您的网络内部运行，并且仅建立 出站 与平台的连接。它会向控制平面发起出站连接，建立通往响应器的隧道，并将经代理的流量转发至您网络中的目标系统。
控制平面Palantir 平台对安全隧道发起器进行身份验证，签发并刷新其访问令牌，并充当其网络配置。
响应器Palantir 平台接受由安全隧道发起器打开的隧道。平台服务将出口流量路由至响应器，再由响应器通过隧道将其传回。

由于安全隧道发起器仅进行出站连接，您无需开放任何入站端口，也无需向平台暴露您网络中的任何端点。安全隧道发起器会打开 隧道 通往响应器；它以出站方式建立这些连接，随后平台通过已打开的连接回传请求流量。当平台服务连接到使用安全隧道的数据源时，流量按以下方式流动：

安全隧道发起器

安全隧道发起器是唯一在您的网络内运行的安全隧道组件。它是一个单一用途的 Envoy ↗ 代理，它为连接到平台而使用 Envoy 的 反向隧道 ↗ 能力。安全隧道发起方以出站方式建立所有连接，而平台则回传请求流量。它具有以下特性：

  • 仅出站： 安全隧道发起方从不接受来自平台的入站连接。它需要到平台的网络出站连接，但不需要任何入站防火墙规则。
  • 令牌认证： 安全隧道发起方使用短期访问令牌向平台进行身份验证。该令牌由控制平面自动签发和轮换，因此您的网络中不会存储任何长期凭证。
  • 默认拒绝出站： 安全隧道发起方只能访问 您明确允许的目标系统。

安全隧道集群和节点

安全隧道发起方按集群和节点进行组织：

  • 集群是安全隧道发起方的逻辑分组，其中的发起方提供对同一网络和目标系统的访问。出站策略与集群相关联，因此集群中的每个节点都提供相同的逻辑连接。

  • 节点代表集群内的单个安全隧道发起方部署。您可以添加多个节点来提高可用性并分散流量。每个节点都会建立并维护自己通往平台的出站隧道。

创建安全隧道集群和节点

在部署安全隧道发起程序之前，请先创建集群和节点，以在平台中建立其身份。发起程序使用生成的集群和节点资源标识符（RID） 向控制平面进行身份验证，并注册为正确的节点。

集群和节点名称在注册范围内必须唯一。请选择具有描述性的名称，以标识它们所代表的网络和发起程序部署。

  1. 前往控制面板的 网络出口 部分。

  2. 打开 安全隧道 选项卡。

  3. 选择 创建集群，输入唯一的集群名称，然后选择 创建集群。

  4. 选择 创建节点，输入唯一的节点名称，然后选择 创建。

部署模式

安全隧道发起程序在您网络内的环境中作为一个或多个节点运行。您可以使用 Data Connection 代理 或 Apollo 来管理这些节点的生命周期。无论采用哪种部署模式，在发起程序部署完成后，令牌签发、令牌轮换、TLS 证书预配和配置交付都将自动为您处理。

基础设施管理员或平台管理员负责以下事项：

  1. 在您的网络中提供一个可供安全隧道发起程序运行的环境。
  2. 允许 网络出口 流量从该环境流向平台。
  3. 定义 出口允许列表 用于确定安全隧道发起方可以访问哪些目标系统。

安全隧道发起方支持以下部署模型：

部署模型生命周期管理
由 Data Connection 代理管理现有或新建的 Data Connection 代理会自动重启并升级该节点。
由 Apollo 管理的 Helm chartApollo 会部署、重启和升级该节点。

前提条件

在安装安全隧道发起方之前，请确认以下事项：

  • 您的网络中有一个可供安全隧道发起方运行的环境。
  • 该环境能够与您的 Palantir 平台实例建立出站网络连接。请参阅 网络出口要求 以了解更多信息。
  • 您已了解 Palantir 平台工作负载需要通过隧道访问的目标系统集合（IP 范围和端口）。

网络出口要求

运行安全隧道发起方的环境必须能够与平台建立出站连接。无需建立指向您网络的入站连接。

允许从该环境向您的 Palantir 平台实例进行出站（出口）网络访问。如果您的网络默认拒绝出口流量，则可能需要开放防火墙或配置代理，以允许这些出站连接。

由 Data Connection 代理管理

您可以使用现有的 Data Connection 代理 或 设置新代理 以管理安全隧道节点。代理会在节点发生故障后自动重启节点，并在新版本发布时对其进行升级。该代理可以继续并行运行其常规的 Data Connection 作业。

要将 Data Connection 代理指定为节点的生命周期管理器：

  1. 打开节点并选择 编辑生命周期管理。

  2. 选择 使用 Data Connection 代理。

  3. 搜索并选择将管理该节点的代理。

  4. 选择 保存。

由 Apollo 管理的 Helm chart

安全隧道发起方作为通过 Apollo（即 Palantir 的持续部署系统）管理的 Helm chart 进行部署。Apollo 会将该 chart 部署到准备就绪的环境中，并为其配置以下内容：

  • 它所连接的控制平面地址。
  • 用于验证平台 TLS 证书的信任包。
  • 用于引导身份验证的初始访问令牌。之后，安全隧道发起方会自动轮换其自身的令牌。

安全隧道发起方运行后，会建立通往响应方的隧道并向 Apollo 报告其健康状态。无需进一步操作即可保持安全隧道发起方处于已认证和已更新状态。

配置出站白名单

安全隧道发起方会强制执行 默认拒绝 出站允许列表。只有当目标系统与允许列表中的某个条目匹配时，才能通过隧道访问该系统。如果允许列表为空，则所有出站流量都会被阻止。

允许列表是一个 CIDR 块列表，每个 CIDR 块都关联一个端口或端口范围。每个条目包含以下字段：

字段是否必填？描述
cidrBlock是要允许的 IP 范围，采用 CIDR 表示法。使用 /32 后缀即可允许单个 IPv4 地址。
port是要允许的目标端口。
endPort否包含性端口范围的结束端口，该范围始于 port。如果省略，则只有 port 才被允许。

如果目标与允许列表中的任何条目均不匹配，安全隧道发起方将拒绝通往该目标的连接。

始终被拒绝的目标

无论允许列表如何设置，安全隧道发起方始终会拒绝发往链路本地地址范围的出站流量，其中包括云实例元数据服务（例如， 169.254.169.254）。即使允许列表允许所有出站流量，这些目标也仍会被阻止，从而防止隧道流量到达安全隧道发起方运行环境中的敏感基础设施端点。

后续步骤

当安全隧道启动器运行且其出口允许列表配置完成后，在 Control Panel 中创建一个 安全隧道出口策略 ，并将其分配给某个 源 （在 Data Connection 中），以便通过隧道路由该源的流量。
