Pipeline Builder：新一代数据集成

发布日期：2022-08-18

旨在实现快速、灵活且可扩展的数据管道交付

大规模构建管道往往是一项成本高昂且门槛重重的工作，需要深厚的技术知识、充足的预算和时间投入，才能确保管道健康、完善。正因存在这些基础要求，数据集成对许多用户而言可能难以企及，执行成本高昂，而且维护难度极大。

我们打造了 Pipeline Builder，让用户能够专注于描述自己想要构建的管道，而无需为细节操心。

快速构建管道

Pipeline Builder 为批处理、微批处理和流式工作流提供托管的、无服务器的支持，覆盖所有类型的目标输出，同时以规模化方式统一处理构建、刷新及其他编排任务。

  • 立即对数据（结构化、非结构化、IoT）应用转换，无需启动环境或编写样板代码。
  • 即时获取构建失败的反馈，无需对整个数据集进行耗时耗资源的全面检查。
  • 凭借贯穿整个管道的细粒度列级溯源，调试变得更加轻松。
  • 得益于 Foundry 世界一流的安全基元，包括基于用途的访问控制、用于选择性加密的 Palantir Cipher 等。
  • Pipeline Builder 仅物化管道达成指定目标所需的数据，从而在大规模场景下节省计算和存储资源。

在不牺牲多功能性的前提下，实现精简的数据集成

Pipeline Builder 旨在满足各种数据集成需求，内置数百种常用函数，并支持轻松添加新函数。Pipeline Builder 还支持后端扩展，能够采用不同的执行引擎（例如：面向小规模数据的内存引擎；面向经典批处理管道的 Spark；面向低延迟流式管道的 Flink）。无论底层采用何种计算模式，Pipeline Builder 的后端都能确保一致的体验。

此外，多名用户现在可以通过管道构建流程提供输入，而不受各自技术能力的限制。协作和导出为代码等核心功能均为内置，有助于构思、创建和审查。如有需要，您可以使用“导出为代码”功能获取管道的 Java Spark 版本。

我应该何时使用 Pipeline Builder？

Pipeline Builder 利用 Palantir 全面的内置数据转换套件，创建从数据源到最终输出的端到端管道。当您为分析和应用构建集成数据时，可以使用它。

如果高度定制化的集成需要使用代码，可以使用 Authoring 通过 SQL、Python 和 Java 对数据应用转换。对于大多数工作流，管道构建器与 Authoring 相辅相成：Authoring 代码仓库的输出可用作构建器管道的输入，反之亦然。这两种工具都支持通过版本控制进行协作。集成完成后，如需进行分析，可以考虑使用以下工具：

  • Code Workbooks： 使用交互式控制台快速迭代转换逻辑、进行临时数据探索，并使用常用软件包（Matplotlib、Plotly、Seaborn）创建细节丰富的交互式图表。
  • Quiver： 用于对原生时间序列分析和对象数据进行搜索与可视化。通过可视化点击式界面和强大的图表库，充分利用本体论层中的高级分析工作流。Quiver 分析可以模板化为只读仪表板，供更广泛的用户使用。

管道构建器是一款功能强大的数据集成工具，可以涵盖管道的端到端创建和管理。要了解有关管道构建器的更多信息，请观看我们的 发布视频 ↗，或 查看我们有关管道构建器的文档。

Notepad：Foundry 中的现代化报告

发布日期：2022-08-15

快速分享洞察并自动生成报告

Notepad 是一款富文本编辑器，可帮助用户分享在 Foundry 平台中生成的洞察，并实现持续报告生成的自动化。Notepad 生成的报告由 Foundry 的本体论支撑，让用户能够快速了解文档中所使用的任何数据源的历史和背景。借助历史血缘，您的团队可以通过追溯原始输入，轻松解释过去的报告版本或决策。此外，Notepad 文档还会通过展示使用了相同输入数据的相关或关联内容，进一步帮助用户将各个信息点串联起来。

凭借现成可用的上下文和知识，用户可以在先前发现的基础上构建工作流，而无需完全从零开始。

借助 Notepad 实现下一代报告

Notepad 是一款富文本编辑器，可嵌入来自整个 Foundry 平台的越来越多的来源——包括 Contour、Quiver、Foundry Code Workbook 和 Object Explorer。Notepad 支持文档模板化，让您只需一键即可创建最新版本的定期报告。

  • 嵌入来自其他 Foundry 应用程序的图表、表格和图形。如需了解所有 受支持的集成，请参阅我们的公开文档。
  • 维护指向嵌入对象和资源的结构化关联，这些关联会自动成为底层本体论的一部分。围绕任何给定文档输入的清晰血缘关系有助于实现可重现性和可理解性。
  • 冻结内容以捕获特定时间点的上下文。
  • 将文档模板化，以便根据新输入轻松创建报告版本。
  • 导出为 PDF 并打印所有 Notepad 文档，同时可对导出呈现效果进行精细控制（嵌入外观、分页符等）。

充分利用 Notepad 的全部潜力

Notepad 旨在涵盖从临时记录到模板化周期性报告的各种用例：

  • 临时笔记记录： 集成来自其他 Foundry 分析应用（如 Quiver）的流程产物和结果。复制和粘贴图表与表格，以实现持久且精确的文档记录。
  • 平台内文档记录： 与平台资源的深度集成支持直接创建文档。
  • 周期性报告： 使用模板创建蓝图，只需一键即可生成最新报告。
  • 模板化导出： 文档和嵌入产物已针对导出进行优化。使用模板生成并下载适合导出共享的 PDF。

Notepad 与 Foundry 应用的强大集成以及灵活的编辑选项，使其能够满足各种用例的需求。

我应该在什么时候使用 Notepad？

使用 Notepad 整合洞察，并创建直观易构建、易使用的文档。请考虑您的最终输出，以确定最适合您的 Foundry 生态系统工具：对于大多数基于实时更新和静态文档的报告用例，建议使用 Notepad。若要根据用户输入或图表选择执行动态筛选（例如用于展示分析结果的仪表板），请考虑：

  • Quiver 仪表板 适用于对象或时间序列数据
  • Contour 仪表板模式 适用于表格数据
  • Workshop 适用于低代码或无代码的仪表板以及更高级的运营应用程序

如果您想了解如何无缝地构建跨 Foundry 生态系统中各产品集成的文档并进行报告，请参阅 Notepad 文档。

Slate：全局样式表

发布日期：2022-08-11

Slate 全局样式表为应用构建者提供了一站式解决方案，用于为多个 Slate 应用设置样式。

Slate 允许用户为任何应用创建并应用自定义样式，但在组织内的各种应用之间保持样式一致可能既具挑战性又耗费资源。借助全局样式表，应用构建者只需单击一次即可将自定义品牌样式应用于所有 Slate 应用。

一种样式，处处适用

即使由多人共同构建应用程序，您现在也可以打造出紧凑、一致且辨识度高的视觉品牌。

由于利益相关者通常会在工作流中使用多个 Slate 应用程序来深入探索数据，构建者现在可以使用全局样式表为所有应用程序打造一致的样式，以确保统一的观感。每当您需要在用户群体中实现应用程序的一致性和可访问性时，即可构建全局样式表。

  • 多个构建者可以访问为同一组织定制的设计库。
  • 选择一个全局样式表，并开启“在应用程序中使用”开关，使同一命名空间中的任何应用程序都采用相同的底层设计规范。
  • 以产品支持的方式，将应用程序设计作为一站式流程的一部分来构建。
  • 只需一次，即可轻松嵌入无障碍 UI 元素。

为每种所需的视图类型构建全局样式表，以实现灵活组合搭配的适用性

例如，这可能意味着为地图使用一个全局样式表，为收件箱视图使用另一个，再为图表或图形使用一个。在使用两个或更多相同组件的情况下，可以开启多个样式表以组合使用。例如，如果您有一个 Slate 仪表板，您可以应用“dashboard”样式。如果您有一个在深色模式下查看效果更佳的应用程序，只要应用程序构建者已完成该样式，您就可以选择“dark mode”样式。同样，同一组织的应用可以采用相同的品牌标识，并相应地调整其风格。

要在设计本地样式表还是全局样式表之间做出选择，请考虑您的样式需求

如果您正在为一个端到端使用多个应用程序的工作流进行构建，您可能需要构建全局样式表，供工作流链中的其他应用程序构建者应用，从而节省时间和精力。对于需要符合企业级品牌标识的稳定生产应用，请创建全局样式表，以确保从构建者到最终用户的每个人都能受益于一致的样式，这种一致性可增强 Slate 应用程序的熟悉度和可访问性。

如果您的自定义样式仅在单个本地应用中可用，且该应用必须保持独特的外观，请改为构建本地样式表。此外，如果您在持续迭代应用的外观和风格，也可以考虑继续使用本地样式表。待样式最终确定并获准在不同应用中使用后，您还可以将其转换为全局样式表。

无论应用的形态或规模如何，样式表都是提供优质用户体验的关键。请先阅读 Slate 样式表文档。

分析： Contour

允许设置默认分析视图 | 引入了一项新设置，用于更改打开分析时的默认视图。用户现在可以将分析配置为默认在仪表板中打开，或仅在查看者没有编辑权限时才在仪表板中打开。要更改此设置，请前往设置侧边栏，并从 默认打开位置 下拉菜单中选择一个选项。

在 Contour 分析中复制和粘贴看板 | 现在可以在单个 Contour 分析中复制、剪切和粘贴看板。要复制看板，请使用任一看板上的 ... 下拉菜单，然后选择 复制 或 剪切。然后，可以使用路径中看板之间的新 粘贴看板 选项，将看板粘贴到同一分析中的任意位置。
