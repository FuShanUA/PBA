导出与导入功能介绍

Apollo 导出与导入功能现已在所有 Apollo Hub 上可用。这些工作流的文档现已发布在 公开文档.

导出与导入提供了一种无缝的方式，可在缺乏网络访问或无法连接到源 Apollo Hub 的环境中部署软件。通过在大多数用户可访问的源 Hub 中管理软件目录和配置的唯一可信来源，您无需仅依赖具有受限环境访问权限的用户。这使开发者、运维人员和其他 Apollo 用户能够以统一的视图跨各种网络边界配置、管理和监控软件部署。

为实现此目标，请从另一个 Apollo Hub 指定一个目标 Hub，该 Hub 将充当源 Hub。源 Hub 将作为目标 Hub 部分或全部产品发布信息的唯一可信来源。变更首先在源 Hub 中进行，然后通过导出管道传输到目标 Hub。

通过创建导出管道开始使用。

2026-05-21

通过晋升管道和 Release Channel 跟踪来配置 Module 发布

Module 控制 Apollo Environment 的关键属性，例如安装哪些 Entity 及其配置。此前，Module 更新会立即传播到安装了该 Module 的每个 Environment。这意味着发布新的 Module 版本会对 Environment 产生重大影响，且一旦出现问题没有明确的缓解途径。

以下更新使您能够控制 Module 更新在您的 Environment 中的发布方式。

Module 晋升管道

Module 发布现在支持 晋升管道，并且可以像 Product 一样晋升到 Release Channel。请注意，目前仅支持 基于时间的晋升阶段 ，不过对 基于金丝雀的晋升 的支持已在开发路线图中。

您可以通过导航到 Module 页面的 Releases 标签页并选择 编辑 来为 Module 配置晋升管道。

配置了晋升管道的 Module。

Module 安装会跟踪 Release Channel

所有 Module 安装现在都会跟踪 Environment 默认 Release Channel。只有当 Module 发布被晋升到该 channel 后，Apollo 才会提议 Module 更新。您可以为新的和现有的 Module 安装覆盖所跟踪的 Release Channel。

使用 Select Release Channel 来创建一个临时的实体级别维护窗口。

为现有的 Module 安装覆盖默认 Release Channel，方法是选择 Update Release Channel.

我们建议保持默认 channel，因为 Module 安装应与其 Environment 具有相同的风险容忍度。

召回 Module

召回某个 Module 版本将取消所有将安装更新到该版本的未完成变更请求，并阻止 Apollo 提议升级到该版本。

Apollo 将 不 自动将处于已召回版本上的 Module 安装降级到未召回的版本。

在 Module 页面上选择 Recall Releases 来自 操作 来创建一个临时的实体级别维护窗口。
