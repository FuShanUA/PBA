单元测试

本页所述的 Python 仓库单元测试仅适用于批处理管道，不支持流式管道。

Python 仓库可以选择在检查中运行测试。这些测试使用流行的 Python 测试框架运行， pytest ↗.

CI 任务：condaPackRun

所有 CI 检查均包含 condaPackRun等任务。

直方图 condaPackRun 任务负责安装环境。每个构件都从相应的通道中检索，conda 使用这些构件来构建环境。

此任务的耗时很大程度上取决于仓库中添加了多少个包。添加的包越多，任务运行越慢。

此任务包含以下三个阶段：

  1. 下载并解压已解析环境中的所有包。
  2. 验证包内容。根据配置的不同，conda 将使用校验和或验证文件大小是否正确。
  3. 将包链接到环境中。

环境规范会作为缓存存储在下面列出的隐藏文件中，供后续构建使用。

  • conda-version-run.linux-64.lock
  • conda-version-test.linux-64.lock

缓存将保存 7 天。如果 meta.yaml 文件.

编写测试

Pytest 会识别以 test_ 开头或以 _test.py结尾的 Python 文件中的测试。我们建议将所有测试放在项目 test 目录下的 src 包中。测试是以 test_ 为前缀命名的 Python 函数，并包含使用 Python 的 assert 语句做出的断言。Pytest 还会运行使用 Python 内置 unittest ↗ 模块编写的测试。请参阅 pytest 文档 ↗ 以获取有关编写测试的详细信息。

在上面的 Spark 示例中，请注意 Pytest fixtures ↗的用法，这是一项强大的功能，可以通过添加同名参数将值注入测试函数。此功能用于提供一个 spark_session fixture 供测试函数使用。

直方图 spark_session fixture 的作用域是整个测试会话，而不是每个单独的测试，因此各测试共享一个 Spark 会话，而不是每次都接收一个新会话。测试对该共享会话配置所做的任何更改（例如设置本地会话时区）都会在使用它的后续测试中持续存在。如果测试修改了 Spark 配置，请在测试结束前恢复原始值。

并行化测试涉及将待处理的测试发送到任何可用的工作进程，不保证顺序。任何需要全局/共享状态并预期其他先前测试会进行更改的测试都应进行相应调整。

补充说明

  1. 启用测试后，提交时您应该会在 CI 日志中看到 :transforms-python:pytest 任务正在运行。
  2. 测试的发现基于文件名和函数名开头的 test_ 前缀。这是 pytest 的约定。
  3. 获取示例记录的一种快速方法是在 Code Workbook 控制台 中打开数据集并调用 .collect().
  4. 要获取 Python 格式的 schema，请打开数据集预览，然后打开 列 选项卡并选择 Copy > Copy PySpark Schema.
