小部件配置

小部件模式

日程安排日历小部件有两种模式：只读模式和动态模式。默认情况下，该小部件以只读模式启动，该模式专为在不进行任何更改的情况下查看和分析数据而设计。切换到动态模式后，您可以直接在小部件中添加、编辑或删除日程安排对象。

动态模式需要对您的日程安排对象类型进行特定的本体论设置。您需要为表示对象开始时间 (schedules:schedulable-start-time) 和结束时间 (schedules:schedulable-end-time) 的属性添加类型类别。您可以通过以下方式完成此操作：

  1. 在 Ontology Manager 中导航到您的日程安排对象类型。
  2. 在 属性 标签页中，选择需要添加类型类别的属性。
  3. 从右侧的属性详情面板中选择 交互 标签页。
  4. 向下滚动并选择 添加新类型类别，然后在提供的文本框中输入类型类别的种类和值。

输入数据 (pucks)

  • 日程名称： 图层的名称，用于在配置期间区分不同的图层。此值不会显示在小部件本身中。

  • 日程安排对象集： 这是 Scheduling Calendar 小组件的输入变量，用于确定要显示的数据。为该对象集选择的对象类型必须具有表示开始时间和结束时间的属性。

  • 开始时间（只读模式）： 选择要用作事件开始时间的日期或时间戳属性。在动态模式下，如果已应用正确的本体论设置，小组件将自动推断此值。

  • 结束时间（只读模式）： 选择要用作事件结束时间的日期或时间戳属性。在动态模式下，如果已应用正确的本体论设置，小组件将自动推断此值。

  • 标题： 选择一个属性，用作小组件中对象 puck 的显示标签值。

  • 颜色： 选择在图表中显示事件时要使用的颜色。

    • 静态： 为所有 puck 选择单一颜色。
    • 分段依据： 选择一个属性，小组件将根据所选属性的值自动为 puck 进行颜色编码。
    • 动态： 配置要应用于图表中 puck 的条件格式规则。

  • 弹出窗口属性： 此部分决定了当用户将光标悬停在日历上的标记点时,弹出卡片中将显示哪些属性。

  • 保存处理程序操作(动态模式): 选择将用于拖放交互的操作。该操作应为 Modify 操作,用于编辑日程对象的开始时间和结束时间属性。

    • 该操作必须包含用于修改日程对象开始时间和结束时间的参数。
    • 操作中的参数 ID 必须与您为开始时间和结束时间选择的属性 ID 完全一致。例如:
      • 如果您的开始时间属性为 start_time,则操作参数 ID 也必须为 start_time。
      • 如果您的结束时间属性为 end_time,则操作参数 ID 也必须为 end_time。
    • 操作参数必须与相应属性具有相同的类型类(schedules:schedulable-start-time 和 schedules:schedulable-end-time)。
    • 所有参数都应标记为可选。

  • 启用拖拽创建(动态模式): 选择一个操作,允许最终用户通过在日历的空白区域拖动来创建新的日程对象。参见 拖拽创建 了解设置和使用详情。

显示配置

  • 每周起始日: 此选择决定当图表处于周视图或月视图时，哪一天将作为一周的开始。

  • 间隔大小（仅限动态）： 默认情况下，用户可以在排程日历组件上将对象分配到任意时间，精确到分钟。吸附行为允许构建者为对象的分配时间设置固定间隔。一旦时间块被拖放到图表中的新位置，它将自动吸附到最近的间隔起点。

  • 开始时间： 此选择决定图表在日视图或周视图下的开始时间。

  • 结束时间： 此选择决定图表在日视图或周视图下的结束时间。

拖拽创建

日历组件允许最终用户通过按住修饰键并在日历上拖动来创建新的日程对象。

设置拖拽创建行为

  1. 在 Ontology Manager 中，为日历图层中显示的对象类型创建一个 Create Action 。该操作需要以下参数：

    • 该对象的 Start Time 属性
    • 该对象的 End Time 属性
    • （可选）您希望用户在创建对象时填写的任何其他属性。

    开始时间和结束时间参数可以设置为时间戳或日期类型，以匹配您的对象类型上的相应属性。

  2. 在 Workshop 中，导航至 输入数据 (Pucks) > [您的日历图层] > 交互 > 启用拖拽创建。

  3. 选择您配置的 Create Action 。

  4. 选择 选择要配置的参数，然后在 本地默认值下绑定开始时间和结束时间参数：

    • 对于开始时间参数，选择 SELECTED START TIMESTAMP （如果参数为日期类型，则选择 SELECTED START DATE ），这样在拖拽创建时，小部件将传入您拖拽的起始时间。
    • 对于结束时间参数，选择 SELECTED END TIMESTAMP （如果参数为日期类型，则选择 SELECTED END DATE），这样在拖拽创建时，小部件将传入您拖拽的结束时间。

使用

要创建新对象，请按住操作系统对应的修饰键，并在日历中的空白区域拖拽：

  • macOS： 按住 Cmd （⌘）并拖拽。
  • Windows： 按住 Windows 键并拖拽。

当您松开拖拽时，小部件会立即根据您拖拽的开始和结束时间显示拟创建的新对象。默认情况下，每次创建时都会弹出表单，以实现最大程度的可配置性。选择 如果有效，则隐藏表单并立即应用 配置将隐藏此表单。只有在保存更改后，才会在本体论中创建新对象。

常见配置问题

错误：“操作参数 ID 必须与所选属性的 ID 保持一致”

当保存处理程序操作的参数 ID 与小组件配置中使用的属性 ID 不完全匹配时，就会出现此错误。

原因： 小组件要求以下两者完全匹配：

  • 开始时间和结束时间属性的属性 ID
  • 保存处理程序操作中的参数 ID

解决方案：

  1. 在 Ontology Manager 中检查您的属性 ID：
    • 导航到您的日程对象类型。
    • 记下确切的属性 ID（例如， start_time, end_time）。
  2. 检查您的操作参数 ID：
    • 在 Ontology Manager 中打开您的保存处理程序操作。
    • 在操作的参数配置中，验证参数 ID 是否与您的属性 ID 完全匹配。
    • 参数名称可以不同，但 参数 ID 必须与属性 ID 完全一致。
  3. 验证类型类是否同时应用于属性和操作参数：
    • 属性应具有 schedules:schedulable-start-time 和 schedules:schedulable-end-time 类型类。
    • 相应的操作参数应具有相同的类型类。
  4. 如有需要，请编辑操作参数 ID，使其与您的属性 ID 匹配。
