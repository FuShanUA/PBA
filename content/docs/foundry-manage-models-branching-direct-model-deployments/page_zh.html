直接模型部署的分支管理

直接模型部署 与……集成 全局分支，使您能够在分支上更改和测试部署配置及其模型函数，然后再将更改合并到 main.

有关分支、提案和变基（rebase）的一般信息，请参阅 全局分支核心概念.

构建和修改部署配置

开始之前，请为该模型在 main.

要在全局分支上配置直接模型部署：

  1. 创建或打开一个全局分支，并在该分支上构建模型版本。
  2. 构建完成后，在同一全局分支上打开该模型，然后选择 实时部署 选项卡。Foundry 会自动创建一个已禁用的分支部署，方法是复制 main 上的配置，并将该部署配置添加到全局分支。
  3. 编辑并保存部署配置。
  4. 要测试分支部署，请选择 开始部署.

对部署配置的更改仅限于该全局分支。 main 和其他分支上的配置在提案合并之前保持不变。

要从全局分支中移除部署配置，请打开 已修改资源面板 （位于分支任务栏中），打开资源菜单，然后选择 从分支中移除。这将从分支提案中移除该部署配置。

在分支上发布和使用模型函数

您可以发布或更新 模型函数 ，该函数来自全局分支上的直接模型部署。Foundry 会发布一个分支本地函数版本，其版本后缀格式为 -branch-YYYYMMDD-HHMMSS。要查看此版本，请打开 模型 并选择 实时部署，然后选择 概述。该版本显示在 函数 部分。您可以在同一全局分支上受支持的应用程序中使用该函数版本，但它无法从 main 或其他分支访问。

Foundry 仅在全局分支上支持分支本地模型函数版本。未与全局分支关联的模型分支无法发布分支本地函数版本。

有关分支函数版本的更多信息，请参阅 函数分支管理.

保护部署配置

您可以 保护部署配置 ，方法是要求对 main 的更改必须通过全局分支和提案进行。当部署配置受到保护时，请在全局分支上构建模型，在该分支上进行部署更改，并创建提案以更新 main.

审查并批准更改

创建提案后， 实时部署 选项卡中的批准横幅会显示批准状态和必需的审查者。审查者可以并排比较 main 与全局分支上的部署配置，然后批准或拒绝更改。比较内容包括运行时配置和模型函数设置。

在合并提案之前，必须满足以下检查：

  • 必需的批准已满足。
  • 部署配置与 main.
  • 模型已在全局分支上构建。
  • 如果已发布模型函数，其目标稳定版本尚未在 main.

变基部署配置

如果 main 上的部署配置在您创建或变基全局分支后发生更改， 实时部署 选项卡会提示您进行变基。

要对部署配置进行变基：

  1. 选择 开始变基.
  2. 查看 main 与全局分支上配置的并排比较。
  3. 选择 使用主分支更改 or 保留当前分支更改.
  4. 选择 完成变基.

变基会保留一个完整的配置；您无法单独解析各个字段。如果您使用了来自 main 的更改，而这些更改在分支部署运行时修改了部署源，请选择 重启并变基 以使用更新后的源重启部署。

如果分支本地模型函数的目标稳定版本已在 main.

将更改合并到 main 分支

合并提案会将所选的部署配置应用于 main。如果模型尚未在 main上拥有直接部署，Foundry 会以禁用状态创建一个。准备好使用时即可启动该部署。

如果全局分支包含模型函数，合并时会将所选的分支本地函数配置发布为稳定函数版本到 main.
