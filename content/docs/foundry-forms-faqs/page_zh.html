常见问题

本页面讨论在使用 Foundry Forms 时可能有助于参考的一些常见问题和调试步骤。

我可以使用什么来替代 Foundry Forms？

Foundry Forms 不再是 Foundry 上数据录入或写回工作流的推荐方法。请改用 Foundry 本体论构建用户输入工作流，将相关数据结构表示为对象类型，并通过操作配置写回交互。

操作 对与添加、编辑和删除数据相关的权限提供更稳健、更细粒度的控制，包括遵循受限视图以及配置复杂的条件权限。此外，操作可以由 Foundry 函数支撑，从而实现更具表现力的写回逻辑。

除了操作配置中内置的表单构建器之外，操作还在 Workshop 和 Slate 中受到原生支持，可以在其中使用完整的应用构建工具套件打造复杂的数据录入用户体验。

操作还会自动为 Foundry API 生成 API 绑定，供外部应用将数据写入 Foundry，并与 webhook 交互，通过这些 webhook，操作可以将数据写入外部数据系统或触发其他下游效果。

目前没有弃用 Foundry Forms 的时间表，使用 Foundry Forms 的现有实现将继续获得支持。强烈建议新工作流使用基于本体论的方法，并且 Foundry Forms 预计不会获得新功能、增强或与非安全相关的修复。

如何存储多个值？

多种字段类型允许填写者选择多个值（例如， checkboxes, dropdown 和 list）。使用 Fusion 表格时，值会自动以数组形式存储在单个单元格中。使用对象类型时，需要进行一些额外的设置：

  • 在源数据集和写回数据集的 schema 中，相关列的类型必须为 Array<X>，其中 X 是一种基本类型，例如 String or Integer.
  • 在本体论配置中，相关属性必须具有相同的基本类型 X，并且复选框 Allow multiple values 必须勾选。

如何将多个值转换为目标数据集中的多行

在将字段配置为 存储多个值后，你可以使用 explode ↗ 函数将每个值拆分到各自的行中。此函数可在数据集的 SQL/Python 转换或 Contour 表达式中使用。

如何生成一个由其他字段拼接而成的字段？

使用模板字段配置以下内容：

- uri: display.Text1
  name: Text 1
  type: Text
  tag: X
- uri: display.Text2
  name: Text 2
  type: Text
  tag: Y
- uri: display.Template
  name: Text 1_Text 2
  type: Template
  options:
    inputs:
      a: X
      b: Y
    template: '{{a}}_{{b}}'

如何调试提交失败的问题？

保存由对象支撑的表单时，你可能会看到此错误： Submitting failed! Please try again or contact your Palantir support..

要进一步调试，请按照以下步骤操作：

  1. 右键单击页面并选择 “检查”。然后，打开 控制台 tab.
  2. 找到以以下内容开头的消息 Submitting failed! Reason ....
  3. 展开标题为以下内容的消息组 e and body.
    • 最常见的 errorName is FormEntries:PhonographEntryParseError，这可能由表单与数据集 schema/本体论配置之间的不一致引起。
  4. 展开标题为以下内容的消息组 parameters.
    • 在以下具体示例中 FormEntries:PhonographEntryParseError，这将突出显示导致问题的字段（PropertyId).

例如，如果类型为以下内容的列/属性 String 与允许输入多个值的字段配对，用户需要将类型更改为 Array<String> 或将字段更新为仅允许单个值。

是否支持移动端提交？

Forms 采用响应式网页设计，可在移动设备上使用；但 Forms 并非专为移动端设计，因此不受官方支持。
