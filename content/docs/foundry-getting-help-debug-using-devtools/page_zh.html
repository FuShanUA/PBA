使用 Chrome™ DevTools 进行调试

在本指南中，您将学习如何使用 Chrome™ 浏览器中的开发工具 (DevTools) 来帮助识别意外行为，或收集必要的浏览器日志以提供给 Palantir 支持。

在调试不明确的错误时，最重要的工具之一是 Chrome™ DevTools ↗。它为调试该问题提供了丰富的信息，并让您能够查看当前所浏览网页幕后运行情况的一些内部细节。可以将其想象成打开汽车的引擎盖——您可以查看内部，看看究竟发生了什么。

使用 Chrome™ DevTools

您可以通过以下步骤访问控制台日志：

  1. 右键单击您当前打开的网页上的任意元素。
  2. 选择 “检查”。这将在网页一侧打开一个面板。
  3. 在顶部，导航至 Console 标签页，大多数错误都会显示在这里。
  4. 失败的请求会显示为红色。找出与页面上出错内容相关的红色请求，或支持团队指示您提供的特定请求。您可能需要在执行相关操作时保持网络窗口处于打开状态，以便显示错误消息。
  5. 选择左侧的 V 形图标以展开该请求。展开后通常包含其他有用的信息，例如错误消息和 errorInstanceID。

目前重要的是顶部的工具栏。对于大多数故障排除， Console 和 网络 标签页中将包含相关的错误消息，对支持团队最有帮助。但是， 元素 标签页也有助于识别问题，因此我们也会对其进行介绍。

控制台选项卡

Chrome™ 控制台如下图所示，可通过工具栏中的 控制台 选项卡进行访问，它有两种主要用途。第一种用途是供 Web 应用程序本身使用。Web 应用程序可以在控制台中打印任何它想要的内容——调试信息、错误日志、信息性消息等。

第二个目的是让用户运行代码片段并查看结果。但是,这种用法超出了本指南的范围。

遇到错误时,打开控制台并向上滚动查看历史记录通常很有帮助,尤其要注意查找错误(通常以红色突出显示)。这些错误信息在报告问题时很有用,并且通常包含有关出错原因的更多信息。

“网络”标签页

当您在 Palantir 应用中选择按钮时，您的浏览器会向服务器发送一个请求，服务器在处理该请求后会发送响应。单个网页可能会发出许多请求，这些请求不会导致页面重新加载，但可能会（例如）更新您正在查看的数据或向服务器发送新数据。 “网络” 标签页可让您查看浏览器正在发出的所有请求，并检查收到的响应。

要访问特定页面的网络日志：

  1. 右键单击您当前打开的页面上的某个元素，然后选择 检查。这将在网页侧边打开一个界面。
  2. 导航到 网络 标签页（位于页面顶部附近）。
  3. 失败的请求将显示为红色。请找出看起来与页面上出现的故障相关的红色请求。
  4. 选择左侧的 V 形箭头以展开请求。通常其中会包含更多信息，例如错误消息和 errorInstanceID。
  5. 如果您没有看到任何相关错误，请尝试在打开控制台日志的情况下，重新触发导致失败的行为。

请注意 Status 列。其中包含该请求在响应中收到的 HTTP 状态码，如本文档前面所述。请注意有一个 404 错误，并且有许多请求以 2开头，这表示请求成功。

下面是一些最佳实践，可帮助您使用此视图获取有关该错误的更多信息。首先，请查看侧边栏左上角的两个按钮：

第一个红色图标表示 Network 选项卡当前正在记录。这意味着，当发出新请求时，该请求将被记录在下方的视图中。如果该图标不可用，您应该切换 记录 开启记录。类似地，如果您发现请求日志的填充速度超过了您查看的速度，可以再次选择它来关闭记录。

第二个符号（中间带有一条线的圆圈）用于清除日志。在执行重现问题的最少步骤之前先执行此操作非常有用。此操作会清除日志中当前已记录的所有请求，以便您只看到新进来的请求。

使用此日志的最佳方法是：

  1. 执行重现错误所需的最少步骤，但只执行到错误即将发生之前为止。
  2. 清除日志。
  3. 执行导致错误的最后一步。
  4. 检查新请求，特别留意任何 HTTP 错误代码。您可能希望将这些请求的截图附加到报告中。

在报告中附上与该请求等效的 cURL 命令也很有用。您可以通过右键单击该请求本身并依次选择 复制 > 复制为 cURL 菜单选项，即可复制该命令并将其包含在报告中。

cURL 是一款命令行工具，可让您通过命令行执行与该请求完全相同的操作。此按钮会将实际发出的请求原样复制到剪贴板，让调试人员能够在任何地方、以任何方式运行该 cURL 请求，从而便于检查请求，找出可能存在的问题。这对于排查 4xx 错误尤其有用。如果存在任何错误 ID，也请将其记录下来。您可以将此副本保存为 TEXT 文件，以便发送给 Palantir 支持团队，但请注意：

  • 出于安全原因，从日志中删除所有现有令牌，否则它们将被您的 Palantir 团队吊销。您可以通过搜索 "token" 和 "bearer" 来检查文件中是否包含令牌，并删除其后的字母字符串。
  • 在共享前对敏感信息进行脱敏。

报告中值得包含的最后一个元素是响应本身，您可以通过 复制响应 从同一个复制菜单中获取它。

要访问特定页面上的 网络 标签页：

  1. 在您当前打开的页面上右键单击某个元素，然后选择 “检查”。这将在网页一侧打开一个面板。
  2. 导航至 “网络” 标签页（位于页面顶部附近）。
  3. 有时打开“网络”标签页时，其中可能没有任何内容。请刷新页面或重新触发之前失败的操作，以填充该标签页。
  4. “网络”标签页中的第二列是“状态”。选择 状态 直到它们按降序排列。这会将失败的请求置于顶部，因为它们的状态码更高。失败的请求还会以红色显示。
  5. 找到可能与您页面上出错内容相关的请求。选择该请求可显示更多信息，例如错误消息或 errorInstanceID。

在网络选项卡中查找 trace ID

TraceID 是请求的唯一标识符，可用于将浏览器中发生的处理过程与日志中存储的记录进行匹配。

要查找 traceID，请按照上一节的说明打开网络选项卡。根据具体情况，不同的请求可能都值得调查；一般来说，当浏览器中显示错误时，红色（表示失败）的请求通常很有参考价值。
