条件

对象监视器已被 Automate取代。Automate 是一款完全向后兼容的产品，可为平台中的所有业务自动化提供统一入口。

对象监视器条件用于定义何时检测和记录新的受监视活动。 阈值 条件会产生持续的 true 或 false 状态，而 事件 条件会产生离散事件。条件可以包含多个子条件，并且可以引用多个 输入 对象集。对象监视器支持以下条件类型：

事件

事件条件是最常见的条件类型。事件条件包括从输入中添加或移除对象，以及指标增加或减少条件。每个事件都在特定时间发生，且是一个离散事件。因此，它们在活动图表中显示为点：

在下面的示例中，事件条件使用单个输入探索，并检查何时在该探索中使用了新对象。添加对象的原因可能是这些对象是新创建的，或者是经过更改后与用于定义输入的筛选器相匹配。

某些事件条件可能需要阈值子条件。在这些情况下，主条件和子条件都必须为真，才能检测到事件。例如，可以使用阈值子条件来检测输入对象数量何时增加，但前提是满足主条件，即输入集中已存在至少 N 个对象。

阈值

阈值条件会在输入上运行，随时间推移产生状态 true 或 false 。当阈值在任一方向上被跨越时，会记录活动。使用阈值的条件可以包含任意数量的嵌套子条件。

下方展示了 Object Monitors 应用程序中阈值条件的一个示例。在此示例中，该条件会检查 amount 在自定义 Sales Opportunities 群组中的总和何时大于 10,000。

阈值条件不支持 实时评估。

函数支撑

函数支撑条件旨在支持更复杂的条件定义，包括事件或阈值规则选项不支持的任何内容。函数支撑条件的工作原理是定义并发布一个函数，该函数返回布尔值 true 或 false。该函数将在评估监控器时被调用，并且响应必须指示该次执行的结果。如果状态发生了变化，则会记录一个事件。

该函数应接受一个属于被监控的对象类型的 ObjectSet<> ，并返回一个指示条件是否满足的布尔值。了解更多关于 编写函数 以供对象监控器使用的信息。

以下示例使用函数来计算何时 realized_amount 的总和小于 expected_amount 的总和（针对输入的一组销售机会对象）。

@Function()
/**
 * This function calculates if the realized amount for a set of sales opportunities is smaller than
 * the sum of all the opportunity amounts.
 */
public async calculateOpportunityUnderRealized(opportunities: ObjectSet<SalesOpportunity>): Promise<boolean> {
    let amount = await opportunities.sum(o => o.amount)
    let amountRealized = await opportunities.sum(o => o.amountRealized)
    if (amount !== null && amountRealized !== null && amountRealized < amount) {
        return true
    } else {
        return false
    }
}

基于函数的条件不支持 实时评估。此外，基于函数的条件只能与阈值条件一起使用，并且只能通过输出单个布尔值来使用。
