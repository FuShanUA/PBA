对象监视器已被 发布后，我们建议在取代。Automate 是一款完全向后兼容的产品，可为平台中的所有业务自动化提供统一入口。

对象监控条件定义了何时检测和记录新的受监控活动。 阈值 条件会生成持续的 true 或 false 状态，而 事件（event） 条件会产生离散事件。条件可以包含多个子条件，并且可以引用多个 输入 对象集。对象监控器支持以下条件类型：

事件

事件条件是最常见的条件类型。事件条件包括对象添加到输入或从输入中移除，以及指标增加或减少条件。每个事件都在特定时间发生，属于离散事件。因此，它们在活动图中显示为点：

在下面的示例中，事件条件使用单个输入探索，并检查该探索中何时使用了新对象。对象被添加可能是因为它们是新创建的，或者被更改为符合用于定义输入的筛选条件。

某些事件条件可能需要阈值子条件。在这些情况下，主条件和子条件都必须为 true 才能检测到事件。例如，可以使用阈值子条件来检测输入对象数量何时增加，但前提是满足至少包含 N 个对象的输入集这一主条件。

阈值

阈值条件在输入上运行以生成随时间变化的 true or false 状态。当阈值在任一方向被跨越时，将记录活动。使用阈值的条件可以包含任意数量的嵌套子条件。

下面展示了对象监控器应用程序中的一个阈值条件示例。在此示例中，该条件检查自定义销售机会群体中 amount 的总和何时大于 10,000.

阈值条件不支持 实时评估.

函数支持

函数支持的条件旨在允许更复杂的条件定义，包括事件或阈值规则选项不支持的任何内容。函数支持的条件通过定义并发布一个返回 true or false布尔值的函数来实现。该函数将在评估监控器时被调用，并且响应必须指示该次执行的结果。如果状态发生了变化，将记录一个事件。

该函数应接受一个 ObjectSet<> （即受监控的对象类型）并返回一个布尔值，指示是否满足条件。了解更多关于 编写函数 以配合对象监控器使用的信息。

下面的示例使用函数计算销售机会对象输入集中 realized_amount 的总和何时小于 expected_amount 的总和。

@Function()
/**
 * This function calculates if the realized amount for a set of sales opportunities is smaller than
 * the sum of all the opportunity amounts.
 */
public async calculateOpportunityUnderRealized(opportunities: ObjectSet<SalesOpportunity>): Promise<boolean> {
    let amount = await opportunities.sum(o => o.amount)
    let amountRealized = await opportunities.sum(o => o.amountRealized)
    if (amount !== null && amountRealized !== null && amountRealized < amount) {
        return true
    } else {
        return false
    }
}

函数支持的条件不支持 实时评估。此外，函数支持的条件只能与阈值条件一起使用，并且只能通过输出单个布尔值来实现。
