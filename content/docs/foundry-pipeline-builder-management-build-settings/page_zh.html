构建设置

本页面介绍 Pipeline Builder 中的构建设置，这些设置可用于调整批处理和流式管道的性能。

您可以编辑管道的 构建设置 ，只需点击 部署 按钮旁的设置图标（位于屏幕右上角）。

批处理管道

批处理计算配置文件

以下批处理计算配置文件可在 构建设置中进行选择。您还可以在所选计算配置文件下方的 规格 下拉菜单中查看这些规格。

计算配置文件权限

标准批处理 Spark 支撑管道的计算配置文件访问权限在项目级别配置。配置文件分为两个层级：

  • 自动导入的配置文件 （超小、小型和中型）：自动导入到项目，无需额外设置即可使用。
  • 非自动导入的配置文件 （大型和超大型）：使用前必须导入到项目中。导入需要 Compass 项目编辑者或所有者角色以及资源管理管理员角色。

如果您选择尚未导入到项目中的大型或超大型配置文件，Pipeline Builder 会在部署时显示错误。选择 导入计算配置文件 以在您拥有所需权限时导入缺失的配置文件。如果您缺少所需权限，大型和超大型配置文件在选择下拉菜单中将显示为禁用状态。

使用大型或超大型配置文件的现有管道将继续运行，无需任何操作。

您可以在控制面板的 Pipeline Builder 部分管理整个注册中的计算配置文件导入。了解更多信息，请参阅 配置计算配置文件权限.

计算配置文件的权限仅适用于标准的批处理 Spark 支撑管道。流式管道和更快的批处理管道不受这些权限要求的影响。

托管配置文件

对于任何标准计算配置文件，您还可以选择将其设为“托管配置文件”。托管配置文件旨在帮助优化资源使用：如果您的作业持续使用的资源少于分配的容量，系统会自动缩减您的计算资源。

启用托管配置文件选项后，平台会分析给定部署最近五次构建的资源使用情况。如果您的管道构建持续使用较少的计算资源，未来构建的计算资源将自动缩减。您的计算资源永远不会增加到超出最初选择的分配额度。调整不限于所选的预设配置文件；托管配置文件策略会根据您的实际使用模式分配自定义计算级别。

启用托管配置文件

要启用托管配置文件，请在构建设置中打开计算配置文件对话框并选择 托管配置文件 位于 配置文件管理策略.

暖池

暖池计算配置文件使用持续运行的虚拟机自动扩缩容池，以最大限度地缩短作业启动延迟。单台虚拟机上最多并发运行三个作业，每个作业将消耗该虚拟机上总可用资源的一部分。

通过利用暖池，作业可以立即开始处理，从而缩短总体构建时间。建议将其用于较小规模的构建，例如，在超小型配置文件上运行耗时不超过 30 分钟的作业。

暖池限制

暖池配置文件具有以下限制：

  • 配置文件支持： 超小和小型 Spark 配置文件支持暖池。中型及更大的配置文件不支持暖池。
  • UDF 支持： 使用用户自定义函数（UDF）的管道无法在暖池配置文件上运行。
  • 构建日志： 使用暖池配置文件时，构建日志可能显示不完整或内容减少。如果您需要完整日志来调试作业失败，请在计算配置文件上禁用暖池设置并重新运行作业，以获取完整的日志输出。

启用暖池

要启用暖池，请在计算配置文件对话框中开启 暖池 在计算配置文件对话框中。

原生加速

您可以在 Pipeline Builder 中为批量管道启用原生加速，从而提升性能，所使用的是 Velox ↗.

详细了解 Foundry 中的原生加速.

启用原生加速

您可以通过选择旁边的设置图标来编辑管道的构建设置 部署. 原生加速的设置中包含针对小型、中型和大型计算规模的预配置配置文件。这些配置文件与基于总内存占用的默认小型、中型和大型规模保持一致（没有本地模式）。如果您是首次尝试使用原生加速运行管道，建议使用这些预配置的配置文件。

此外，还有一个具有高级配置的原生加速配置文件，允许您完全指定堆内和堆外内存比例，以及影响构建的所有其他资源和计算相关配置。

在大多数情况下，选择预配置的原生加速配置文件应该足以加速您的管道。如果您遇到的 OOM 或性能回退问题在非原生加速构建中并未出现，则内存配置可能欠佳。通常，采用高级配置文件并降低分配给堆外的内存百分比即可解决该问题。如果问题仍然存在，则说明该管道可能不太适合原生加速，您应继续使用默认运行配置文件。

原生加速的内存配置注意事项

在 Foundry 中使用原生加速运行 Spark 需要与普通批处理管道稍有不同的配置。Spark 支持使用 堆外内存 ↗。堆外内存是指不由 JVM 管理的内存，可省去 GC 开销，从而带来更好的性能。

默认情况下，我们不会在 Foundry 中启用堆外内存，因为这样做可能会给管道带来额外的维护成本。启用堆外内存是使用原生加速的必要条件，因为被 Velox 修改的 DataFrame 必须位于堆外，才能被原生进程访问。

对于除 Velox 数据转换之外的所有操作，Foundry 仍需要充足的堆内内存（例如，编排、调度和构建管理代码仍在 JVM 中运行），但理想情况下，现在大部分工作将在堆外执行。将管道配置为使用原生加速，会在平衡堆内和堆外内存方面引入额外的维护成本。Pipeline Builder 将提供托管配置文件来协助解决这一问题，但可能仍需要进行自定义配置。

某些工作负载并不适合原生加速。特别是使用 LLM 或嵌入转换的管道——例如文本分块和嵌入生成——无法将这些操作卸载到原生堆外执行。当此类管道启用原生加速时，堆内内存的减少可能导致执行器在 shuffle 阶段出现内存不足错误，即使在使用更大计算配置文件的情况下也是如此。对于此类工作负载，请改用标准（非原生）计算配置文件。

最大持续时间

您可以为流式管道作业设置最大持续时间。此设置允许您指定一分钟到七天之间的最大运行时间。达到最大持续时间后，流式作业将自动停止。

配置最大持续时间：

  1. 选择旁边的设置图标 部署 按钮旁的设置图标（位于屏幕右上角）。
  2. 在流式管道设置下，找到 设置最大作业持续时间.
  3. 指定所需持续时间，范围为一分钟到七天。

对于非主分支， 设置最大作业持续时间 默认启用，持续时间限制为一天。

流行为

对于 Flink 管道，您可以使用以下选项配置数据一致性保证 流行为 部分（位于 构建设置 面板。此设置决定管道如何处理消息传递语义。

使用专用选择器选择一致性保证，例如 At Least Once。配置的一致性保证会显示在部署面板的预览行中。如果未配置一致性保证，部署面板将显示警告。

外部管道

外部管道将计算下推到外部引擎（如 Databricks 和 Snowflake）。外部管道的计算配置文件配置与批处理和流式管道不同。

有关为外部管道配置计算配置文件的信息（包括 Databricks 和 Snowflake 的选项），请参阅 Pipeline Builder 中的外部管道.
