创建自定义计算模块客户端（高级）

为什么我需要客户端？

如果您正在使用受支持的语言（Python、Java 或 TypeScript）编写计算模块，并且 使用我们提供的 SDK，则无需手动创建客户端逻辑。

但是，如果您没有使用 SDK，或者需要使用目前不支持的语言构建计算模块，则必须按照下文所述的流程自行创建计算模块客户端。

自定义客户端的职责

计算模块客户端负责管理计算模块内逻辑的执行，并处理以下三项主要职责：

发布计算模块的函数架构（可选）

在启动客户端的主执行循环之前，我们建议您发布计算模块函数的架构。这会将计算模块的架构公开给 Foundry 的其余部分。或者，您也可以在计算模块的 函数 选项卡中手动定义此函数架构。

有关更多信息，请查阅我们关于 自动函数架构推断的文档。

轮询新任务

客户端会持续轮询内部计算模块服务，以获取需要处理的新任务。如果存在任务，客户端将找到与该任务对应的函数，并使用关联的载荷调用该函数。

发布计算模块的结果（输出）

函数完成并将结果返回给客户端后，客户端负责将该输出报告回计算模块服务。

API 参考

首次尝试向内部计算模块服务发送 HTTP 请求时，可能会看到“connection refused”（连接被拒绝）错误。这是启动期间的预期行为，只需在短暂休眠后重试即可解决。

GET 任务

变量

MODULE_AUTH_TOKEN string

  • 请查阅我们的 环境变量 文档以了解更多信息。

DEFAULT_CA_PATH string

  • 请查阅我们的 环境变量 文档以了解更多信息。

GET_JOB_URI string

  • 请查阅我们的 环境变量 文档以了解更多信息。

预期状态码

  • 200: 存在待处理的新作业。
  • 204: 不存在待处理的新作业。
curl --header "Module-Auth-Token: $MODULE_AUTH_TOKEN" \
    --cacert $DEFAULT_CA_PATH \
    --request GET \
    $GET_JOB_URI

响应参数

jobId string

  • 给定待处理作业的唯一标识符。

queryType string

  • 要调用的函数名称。

query JSON object

  • 要传递给函数的有效负载。

temporaryCredentialsAuthToken string

  • 与 Foundry 数据 sidecar 一起使用的临时令牌。

authHeader string

  • 可用于调用 Foundry 中其他服务的 Foundry 授权令牌。
  • 仅在特定模式下可用。

66# Get's a job from the compute module service. Jobs are only present when
67# the status code is 200. If status code 204 is returned, try again.
68# This endpoint has long-polling enabled, and may be called without delay.
69def getJobBlocking():
70    while True:
71        response = requests.get(getJobUri, headers={"Module-Auth-Token": moduleAuthToken}, verify=certPath)
72        if response.status_code == 200:
73            return response.json()
74        elif response.status_code == 204:
75            log.info("No job found, trying again!")
76
77
78# Process the query based on type
79def get_result(query_type, query):
80    if query_type == "multiply":
81        return float(query["n"]) * 2
82    elif query_type == "divide":
83        return float(query["n"]) / 2
84    else:
85        log.info(f"Unknown query type: {query_type}")
86
87
88# Posts job results to the compute module service. All jobs received must have a result posted,
89# otherwise new jobs may not be routed to this worker.
90def postResult(jobId, result):
91    response = requests.post(
92        f"{postResultUri}/{jobId}",
93        data=json.dumps(result).encode("utf-8"),
94        headers={"Module-Auth-Token": moduleAuthToken, "Content-Type": "application/octet-stream"},
95        verify=certPath,
96    )
97    if response.status_code != 204:
98        log.info(f"Failed to post result: {response.status_code}")
99
100
101# Posts the schema of this compute module's function(s) to the compute module service.
102# This only needs to be called 1 time, thus we call it before entering the main loop.
103def postSchema():
104    num_tries = 0
105    success = False
106    while not success and num_tries < 5:
107        try:
108            response = requests.post(
109                postSchemaUri,
110                json=SCHEMAS,
111                headers={"Module-Auth-Token": moduleAuthToken, "Content-Type": "application/json"},
112                verify=certPath,
113            )
114            success = True
115            log.info(f"POST schema status: {response.status_code}")
116            log.info(f"POST schema text: {response.text} reason: {response.reason}")
117        except Exception as e:
118            log.error(f"Exception occurred posting schema: {e}")
119            time.sleep(2**num_tries)
120            num_tries += 1
121
122
123postSchema()
124
125# Try forever
126while True:
127    try:
128        job = getJobBlocking()
129        v1 = job["computeModuleJobV1"]
130        job_id = v1["jobId"]
131        query_type = v1["queryType"]
132        query = v1["query"]
133        result = get_result(query_type, query)
134        postResult(job_id, result)
135    except Exception as e:
136        log.info(f"Something failed {str(e)}")
137        time.sleep(1)
