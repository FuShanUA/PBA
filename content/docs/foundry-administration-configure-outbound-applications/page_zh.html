使用 OAuth 2.0 授权码许可配置出站应用程序

出站应用程序为管理员提供了一种管理 Foundry 中构建的工作流与外部系统之间 OAuth 2.0 连接的方式。出站应用程序在 Control Panel 的组织级别进行管理。

出站应用程序表示 Foundry 作为 OAuth 2.0 客户端运行所需的一组配置。该应用程序向另一个可作为 OAuth 2.0 服务器.

私有网络支持

出站应用程序支持使用 agent 代理出站策略连接到私有网络上的 OAuth 2.0 服务器。这允许 Foundry 通过安装在您网络中的 Data Connection 代理 路由流量。请参阅 出站策略配置选项文档 了解详情。

出站策略仅控制 Foundry 如何连接到 OAuth 2.0 服务器。要完成授权码许可流程，授权页面会在您自己计算机上的浏览器中打开，因此发起授权的计算机也必须能够通过网络访问 OAuth 2.0 服务器。

创建出站应用程序

要创建出站应用程序，请先在 Control Panel 中导航至 Outbound 应用程序 中的 Control Panel 内创建，位于 组织设置下。如果您有权访问多个组织，请务必选择要在其中创建出站应用程序的组织。该组织中所有有权在 Data Connection 中设置数据源的用户，都将能够选择任何出站应用程序作为其连接的身份验证机制。

要查看 Outbound 应用程序 页面，您需要拥有“管理出站应用程序”工作流的访问权限，该权限默认授予 Control Panel 中的 Organization administrator 角色。

测试授权

保存并启用出站应用程序后， 您的授权 部分将显示您是否已 获得授权 or 未获得授权。如果您尚未获得授权，请选择 设置授权 以在不将应用程序附加到源的情况下测试 OAuth 2.0 授权流程。完成该流程后，您的授权将被存储，供使用该应用程序的工作流使用。

管理出站应用程序

创建出站应用程序后，该组织中的所有用户都可以将其用作 REST API 源 in 数据连接的授权方法。具有管理出站应用程序权限的管理员可以使用以下选项。

删除出站应用程序

删除出站应用程序将永久移除所有已授权该应用程序的用户所存储的令牌和刷新令牌。应用程序配置（包括客户端密钥）也将被永久删除。此操作无法撤销。

重置出站应用程序

重置出站应用程序将永久移除所有已授权该应用程序的用户所存储的令牌和刷新令牌。这实际上会将应用程序恢复到初始设置完成后的状态，即尚无用户完成交互式授权流程的状态。下次用户尝试执行需要来自该出站应用程序的令牌的工作流时，系统将提示他们再次完成授权流程。

启用出站应用程序

启用出站应用程序意味着用户可以对该外部系统执行交互式授权流程。禁用应用程序将阻止使用任何先前存储的令牌和刷新令牌。但是，这些令牌不会被删除，并且可以在应用程序重新启用后再次使用。

在出站应用程序被禁用期间，之前未授权过该应用程序的新用户将无法执行交互式授权流程。

新创建的应用程序默认处于启用状态，并且只能在创建后被禁用。

出站应用程序不支持来自多个组织的用户使用。如果多个组织中的用户需要针对同一 OAuth 2.0 服务器进行授权，您必须为每个组织中的用户创建一个使用不同 REST API 源的单独出站应用程序。

创建并启用出站应用程序后，可将其用作 REST API 源中某个域的身份验证方法。配置域时，选择 OAuth 2.0 ，然后从下拉列表中选择所需的出站应用程序。

任何使用配置了 OAuth 2.0 的域的 webhook 都会在每个用户首次尝试运行时触发交互式提示。Webhook 最常通过 操作 （来自 来运行该专业代码代理。你还可以通过调用；在这种情况下，在 Workshop 中运行操作时，用户将看到一个弹出窗口，其中显示 OAuth 2.0 服务器的身份验证页面，提示他们授权 Foundry 代表他们与此系统进行交互。

如果配置了令牌刷新工作流，除非在外部系统中撤销授权或重置出站应用程序，否则用户不太可能再次看到此提示。如果未配置刷新工作流，最终用户将在生成的令牌每次过期时看到身份验证弹窗。令牌通常会在几分钟或几小时内过期，我们建议使用刷新流程以获得更好的用户体验。

为了在函数支撑的 Action 中调用由 OAuth 2.0 支撑的 webhook，请导航到您的 Action 的规则配置页面，并将 webhook 作为第一条规则直接调用，随后使用一个函数来处理 webhook 响应。您还可以将 webhook 调用配置为接受 来自函数的输入.

出站应用程序也可与自动化工作流（如 Automate 和定时 Functions）配合使用，前提是用户持有有效的令牌。用户必须首先在交互式 UI 环境（如 Workshop、AIP Studio 或 控制面板）中完成授权流程。如果刷新令牌在自动化工作流运行之前过期，用户必须在交互式 UI 环境中重新进行授权。
