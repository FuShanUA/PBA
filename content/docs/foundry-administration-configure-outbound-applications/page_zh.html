使用 OAuth 2.0 授权码许可配置出站应用程序

出站应用程序为管理员提供了一种方式，用于管理从 Foundry 中构建的工作流到外部系统的 OAuth 2.0 连接。出站应用程序在 Control Panel 中的组织级别进行管理。

出站应用程序表示使 Foundry 能够充当 OAuth 2.0 客户端所需的一组配置。该应用程序会向另一个系统发出请求，该系统可以充当 OAuth 2.0 服务器。

Foundry 中的出站应用程序仅支持 OAuth 2.0 授权码许可 ↗ 类型。 要设置 OAuth 2.0 客户端凭证许可，请参阅 这些资源 ，以在 webhook 中手动建立握手过程。

私有网络支持

出站应用程序支持使用 代理出口策略连接到私有网络中的 OAuth 2.0 服务器。这使得 Foundry 能够通过安装在您网络中的 Data Connection agent 来路由流量。请参阅 出口策略配置选项文档 了解详情。

出口策略仅控制 Foundry 连接 OAuth 2.0 服务器的方式。要完成授权码授予流程，授权页面将在您自己计算机上的浏览器中打开，因此发起授权的计算机也必须拥有对 OAuth 2.0 服务器的网络访问权限。

创建出站应用

要创建出站应用，请先导航至 出站应用 页面（位于 Control Panel 中的 组织设置下）。如果您有权访问多个组织，请务必选择您希望在其中创建出站应用的组织。该组织中所有有权在 Data Connection 中设置数据源的用户，都可以选择任意出站应用作为其连接的授权机制。

要查看 出站应用 页面，您需要有权访问“管理出站应用”工作流，该工作流默认授予 Control Panel 中的 Organization administrator 角色。

了解有关 配置角色的更多信息。

选择 新建应用 ，然后提供设置出站应用所需的输入。下方列出了详细的配置选项。

(旧版)基于自定义 webhook 的 OAuth 2.0 握手

旧版

基于自定义 webhook 的 OAuth 2.0 配置处于开发的 旧版 阶段,预计不会再进行额外的开发。目前仍提供完整支持。此配置在您的 enrollment 中可能不可用。如果 OAuth 2.0 服务器实现了标准的授权码许可流程,请使用 标准配置选项 并搭配 直接连接 或 agent 代理出站策略 作为替代。

如果 OAuth 2.0 服务器需要非标准的令牌握手,您可以使用自定义 webhook 手动实现 OAuth 2.0 流程。此方法会将握手请求通过 REST API 源进行路由,该源会使用 agent worker 连接到服务器。

管理出站应用程序

创建出站应用程序后，该应用程序将可供该组织中的所有用户用作 REST API 源 （位于 Data Connection中）的授权方法。以下选项适用于有权管理出站应用程序的管理员。

删除出站应用程序

删除出站应用程序将永久移除所有已授权该应用程序的用户存储的令牌和刷新令牌。应用程序配置（包括客户端密钥）也将被永久删除。此操作无法撤销。

重置出站应用程序

重置出站应用程序将永久删除所有已授权该应用程序的用户所存储的令牌和刷新令牌。这实际上会将应用程序恢复到初始设置刚完成、尚无任何用户完成交互式授权流程时的状态。当用户下次尝试执行需要此出站应用程序令牌的工作流时,系统将提示其再次完成授权流程。

启用出站应用程序

启用出站应用程序意味着用户可以对此外部系统执行交互式授权流程。禁用应用程序后,任何先前存储的令牌和刷新令牌都将无法使用。但是,这些令牌不会被删除,并且在应用程序重新启用后可以再次使用。

在出站应用程序处于禁用状态期间,之前未授权过该应用程序的新用户将无法执行交互式授权流程。

新创建的应用程序默认处于启用状态,且只能在创建后被禁用。

在 Data Connection 中使用出站应用程序

有关如何在函数、操作、Workshop 和 AIP 聊天机器人中使用出站应用程序的详细信息,请参见 支持的工作流 见下文。

出站应用程序不支持来自多个组织的用户使用。如果多个组织的用户需要针对同一个 OAuth 2.0 服务器进行授权，则必须为每个组织的用户分别创建一个使用不同 REST API 数据源的单独出站应用程序。

出站应用程序创建并启用后，可用作 REST API 数据源中某个域的身份验证方法。配置域时，请选择 OAuth 2.0 ，然后从下拉列表中选择所需的出站应用程序。

任何使用配置了 OAuth 2.0 的域的 Webhook，在每位用户首次尝试运行时都会触发交互式提示。Webhook 最常通过 操作 从 Workshop中调用；在这种情况下，当用户在 Workshop 中运行操作时，会看到一个弹出窗口，其中显示 OAuth 2.0 服务器的身份验证页面，提示他们授权 Foundry 代表其与该系统进行交互。

为了在由函数支撑的操作中调用由 OAuth 2.0 支撑的 webhook，请导航至操作的规则配置页面，将 webhook 作为第一条规则直接调用，随后使用一个函数来处理 webhook 响应。您还可以将 webhook 调用配置为接受 来自函数的输入。

如果配置了令牌刷新工作流，除非在外部系统中撤销授权或重置出站应用，否则用户不太可能再次看到此提示。如果未配置刷新工作流，最终用户将在生成的令牌每次过期时看到身份验证弹出窗口。令牌通常会在几分钟或几小时内过期，我们建议使用刷新流程以获得更好的用户体验。

只要用户持有有效的令牌，出站应用也可以与自动化工作流（如 Automate 和计划函数）配合使用。用户必须先在交互式 UI 环境（如 Workshop 或 AIP Studio）中完成授权流程。如果刷新令牌在自动化工作流运行之前过期，则用户必须通过交互式工作流重新授权。

支持的工作流

REST API 数据源配置出站应用程序后，OAuth 令牌即可在以下 Foundry 功能中使用：

  • 函数：在 Python 和 TypeScript v2 函数中使用来自数据源的 OAuth 令牌，直接通过代码与外部系统进行身份验证。TypeScript v1 函数必须使用 webhook 作为替代。
  • 函数支撑的操作：如果操作的支撑函数调用了 OAuth 配置的数据源，则会自动传递该令牌。
  • Webhook 副作用：OAuth 配置的 REST API 数据源上的 Webhook 会在传出请求中包含令牌。
  • Workshop：在 Workshop 中应用的、需要 OAuth 令牌的操作，在不存在有效令牌时会触发授权提示，在用户已授权的情况下则会自动运行。直接从 Workshop 调用的函数（例如，作为 函数支撑的变量 或用于填充小部件内容）无法触发授权提示；请将该函数包装到 函数支撑的操作 中，以便在 Workshop 中使用 OAuth 支撑的数据源。
  • AIP 聊天机器人：调用 OAuth 支撑操作工具的代理使用与其他工作流相同的令牌生命周期。
