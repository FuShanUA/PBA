开始使用

在本指南中，我们将创建一个简单的操作类型，用于更改工单的优先级。

我们将配置提交条件，以确保优先级为 P0, P1，或 P2，并且工单状态为 Open.

前提条件

在本指南中，我们将使用一个 Demo Ticket 对象类型，它具有四个属性：

  • Ticket ID
  • Title
  • Priority
  • Status

为了让用户能够执行操作类型配置中定义的操作， 需要进行额外的配置。如果运行的是 Object Storage v2，用户必须通过开关启用编辑功能。如果运行的是 Object Storage v1（Phonograph），则必须创建一个回写数据集。 Object Storage v1 处于 计划弃用 开发阶段； 迁移到 Object Storage v2.

创建新的操作类型

我们首先创建一个用于更改工单优先级的新操作类型。在 Ontology Manager 中，选择 操作类型 在左侧边栏中，然后选择 新建操作类型 在视图的右上角。

创建向导允许您配置操作类型的最重要特性。在 操作类型 步骤中，打开 对象 分支，然后浏览文件。请确保您能看到您在分支中所做的更改。 Demo Ticket 对象类型，然后选择 修改对象 位于 对象操作。在 映射 步骤中，添加 Priority 属性，方法是选择 添加属性。在 元数据 步骤中，输入 操作类型名称 为您的操作类型命名。继续到最后一步并选择 创建.

您现在可以看到操作类型的完整详细视图。您可以进行其他调整，例如添加 描述 菜单中选择 概述 选项卡，或在 规则 标签页。

编辑参数

选择 参数 选项卡以查看参数的概览。 Ticket 和 Priority 参数已基于 规则.

选择 Priority 参数来限制其可取的值。将约束条件从 用户输入 to 多选。这将允许您选择此参数可选取的值。添加 P0, P1日 P2 作为选项。如果您现在将操作应用于某个对象，就可以将工单的优先级更改为 P0, P1，或 P2。您现在将添加提交条件，限制只能更改处于打开状态的工单的优先级。

添加提交条件

在 安全与提交条件 选项卡中打开提交条件部分。通过选择 条件 菜单中选择 执行 部分来创建新条件。使用 参数 条件模板，在 Ticket 对象参数的 Status 属性上设置条件。使用 is 运算符，您可以在工单状态与特定值之间进行精确的字符串比较 Open.

添加失败消息，以便用户了解操作失败的原因。您的操作定义现已完成，您可以将其配置为在 Object Explorer 的对象视图中显示。

将操作添加到对象视图

控制面板 演示工单一 并编辑其对象视图。在顶部添加一个新的 widget，然后选择 操作 widget。在侧边栏中，选择 额外仪表板输入。从 Ontology Manager 复制操作 RID 并粘贴到 Action RID 字段中。将标签命名为 "Change Ticket Priority"。

默认情况下，操作表单会将每个参数显示为操作表单中的一个字段，包括 Ticket 参数。此外，操作并不知道应将当前对象填入 Ticket 参数。我们将配置操作表单以隐藏 ticket 字段（这样用户就无法更改其他工单的状态），并将其值设置为当前对象。 在 默认值中，选择 额外仪表板输入下。输入 Ticket 参数的参数 ID——在本教程中，我们将其设置为 ticket。将值类型更改为 环境变量 并选择 当前对象。最后，将显示选项更改为 隐藏.

解决用户编辑（操作）与数据源更新之间的冲突

Foundry 本体论中的对象实例既可以由输入数据源创建和修改，也可以由用户编辑/操作创建和修改。当单个对象实例（即具有特定主键值的行或对象）同时接收来自输入数据源和用户编辑的数据时，必须通过冲突解决策略透明地解决这些接收到的值。

有两种解决冲突的策略：

  • 策略 1：应用用户编辑（默认）
  • 策略 2：应用最新值（你的注册中可能不提供此功能）
