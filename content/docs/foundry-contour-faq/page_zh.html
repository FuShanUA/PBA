如何开始一个新的分析？

在 Foundry 中，每个用户都有自己的文件夹，称为 您的文件。这是一个用户可以使用数据进行原型设计并与其他用户分享结果的文件夹。在该文件夹中，用户可以创建他们的第一个分析：

  1. 在 Data Connection 中导航至 文件 部分，位于您的工作区导航栏中。
  2. 在 Data Connection 中导航至 您的文件 tab.
  3. 通过选择以下选项来创建新分析： +新建 并选择 了解如何通过 从下拉菜单中。
  4. 选择 +创建新路径 在您的新分析生成之后。
  5. 在相应的文件夹中选择您想要分析的数据集。

如何在平台中查找相关数据？

有两种主要的数据发现方法：

  • 搜索： Foundry 拥有一个平台范围的搜索工具，位于页面左侧的工作区侧边栏中。该工具将搜索平台中的所有资源，包括电子表格、Contour 分析和代码工作簿，是您已知数据集名称时查找数据的绝佳方法。

  • 数据目录： Foundry 的 数据目录 包含经过清理和整理的数据集，可供业务分析师和数据科学家直接使用。 数据目录 是您想了解平台中已存在哪些数据时的绝佳起点，可以直接从主页访问。您可以通过选择以下选项返回主页： 主页 在工作区侧边栏中。

如何创建一个用于分析的初始数据集？

鉴于数据在 Foundry 平台中通常以其原始形式提供，在开始创建分析之前了解如何筛选数据非常重要。数据筛选将使您能够专注于对分析重要的元素，而不会受到无关数据的干扰。

  • 排序和筛选：直方图数据筛选：
    • 在 Foundry 中，排序和筛选是最常用的功能之一。您可以在直方图面板中查看给定列中的所有不同选项，然后选择您想要使用的特定类别。
  • 属性数据筛选：
    • 用途 KEEP 如果您只想筛选出符合设定条件的数据。
    • 用途 REMOVE 如果您想要 排除 仅符合所设条件的数据。
  • 多个数据筛选器：
    • 用途 AND 匹配 如果您想要筛选同时满足多个条件的数据。
    • 用途 OR 匹配 如果您想要筛选满足多个条件、但不一定同时满足/不一定在同一行数据中满足的数据。
  • 调整筛选器：
    • 当用户针对特定筛选器创建新的分析时（例如， carrier_code = DL），其他用户可以通过将筛选器更改为符合其用例的筛选器（例如， carrier_code = UA）或完全移除筛选器来轻松复制其分析，以获得全局分析。

默认情况下，分析操作会应用于整个列，以便于分析大型数据集。如果您想对较小范围的行进行分析（类似于在 Excel 中选择特定的单元格区域），请先筛选出所需的行，然后再应用这些操作。

要查看更多筛选选项，请查阅我们的 筛选数据 文档。

如何应用计算？

要在 Contour 中执行新的计算，您需要选择 添加列 （在表达式面板中）。但是，Foundry 执行的是列级操作，而非单元格级操作。公式不是将 A1 * B1 相乘以返回到单元格 C1，而是 Foundry 会将 column1 * column2 相乘（将 column1 和 column2中每个对应的行级条目相乘）以返回 column3.

Foundry 中有哪些常见的 Microsoft Excel 分析等价功能？

下面列出了一些最常见的 Microsoft Excel 函数及其在 Contour 中的表达式等效项。您可以按照 如何应用计算？.

  • Excel: IF(logical_test, value_if_true, [value_if_false])

    • Foundry: 
      CASE
    WHEN logical_test THEN value_if_true
    ELSE value_if_false
END
    • 示例：如果我想创建一个返回 yes 的列（当航班从 JFK and no 出发时），否则返回其他值，则表达式如下所示： 
      CASE
    WHEN "origin" = 'JFK' THEN 'yes'
    ELSE 'no'
END

  • Excel: CONCAT(cell1, [cell2],…)

    • Foundry: CONCAT("col1", ["col2"],...)
    • 示例：如果我想通过连接 timestamp and order_ID_number 列为每个订单创建一个唯一键，则表达式如下所示：
      • CONCAT("timestamp","order_ID_number")

  • Excel: VALUE(text)

    • Foundry: CAST("col1" AS DOUBLE)
    • 注意：您可以将列的数据类型转换为 STRING, INTEGER, BOOLEAN, DATE, TIMESTAMP，或 LONG ，方法是替换表达式中的 DOUBLE 类型
    • 示例：如果我想对某些列执行乘法运算，但其中一个必需的列 cost 被归类为字符串，则表达式如下所示：
      • CAST("cost" AS DOUBLE)

  • Excel: LEFT(text, [num_chars])

    • Foundry: SUBSTRING("col1", num2, num3)
    • 注意： num2 是起始索引， num3 是子字符串的长度
    • 示例：如果我想从 airport_display_name 列中提取括号内的字母，例如 [ALB] Albany International + Albany, NY, [AZA] Phoenix - Mesa Gateway + Phoenix, AZ, [CLT] Charlotte Douglas International + Charlotte, NC，则表达式如下所示：
      • SUBSTRING("airport_display_name", 2, 3) ，并将返回一个包含 ALB, AZA日 CLT.

阅读 表达式面板 和 支持表达式语法 文档以了解更多信息。

在 Contour 中保存数据集与在 Code Repositories 或 Code Workbook 中创建数据集有什么区别？

从 Contour 分析保存数据集的过程与从代码仓库或 Code Workbook 创建数据集的过程基本相同——逻辑会被转换为一系列 Spark 转换，在集群上执行，并保存到存储在分布式文件系统中的数据集里。将分析保存为新数据集时没有行数限制。话虽如此，数据规模越大，保存所需的时间就越长，因为底层计算的计算成本会更高。但是，从 Contour 导出数据时有行数限制，这与将路径保存为数据集是不同的。

当我尝试导出时，系统提示 100,000 行的限制。这是正确的吗？

是的，没错。从 Contour 导出的行数限制为 10 万行。如果您需要导出更多数据，可以将 Contour 的结果保存为数据集，然后从 操作 下拉菜单中下载该 数据集预览 页面预览同步的数据。

Contour 导出和数据集下载的限制可能因 Foundry 注册而异，具体取决于合作伙伴的要求。

我可以自动更新 Contour 分析路径吗？

目前，无法自动更新 Contour 分析路径；这必须手动完成。但是，可以为分析生成的数据集设置计划。保存数据集后，您可以打开数据集预览，然后从 操作 下拉菜单中选择 管理调度。生成的数据集将根据您配置的计划进行构建。

数据透视表未显示所有数据

数据透视表预览不会显示表中的所有数据。数据透视表会对 整个 数据集计算聚合，并将输出缩减为前 100 列或 10,000 个值，以防止浏览器性能变慢。要获取这些大型数据透视表的准确结果，您需要 切换到数据透视数据。您可以在 数据透视表文档.

中阅读更多相关信息。要进行故障排除，请执行以下步骤：

  1. 尝试 切换到透视数据，这将强制 Contour 计算整个数据集。
  2. 在表格看板中查看数据；透视看板仍将不完整。
  3. 如果可能，在数据透视表上方插入一个筛选看板，以缩减您传递的数据（这通常也会提升整体性能），但同样，这并不能改变数据透视表看板只会对数据透视表的前 10,000 个单元格进行计算的事实（出于性能原因）。
  4. 要获取完整的导出，请选择 切换到数据透视数据，然后使用导出看板，或使用当前路径末端的导出选项。

数据透视表中发现重复列

我的数据透视表因重复列而无法计算。这通常是因为存在除大小写外名称相同的列名。

中阅读更多相关信息。要进行故障排除，请执行以下步骤：

  1. 检查数据透视表的列部分中是否有任何列包含除大小写外相同的值（例如， Test and test）。Foundry 数据集列名不区分大小写，因此当列被透视时，这些列 Test and test 会被视为重复列。
  2. 将任何此类值映射到统一的大小写形式，以便在列被透视时不会发生冲突。

一般性能问题

您的 Contour 运行缓慢，您想找出导致性能下降的原因。

中阅读更多相关信息。要进行故障排除，请执行以下步骤：

  1. 首先，检查确定您的分析中使用的输入数据集是否使用 Parquet 或 Avro 文件；如果不是，请确保您使用的是适当且干净的数据集版本。

  2. 检查您是否使用的是以 CSV 文件存储的原始摄取版本的数据集，这种格式性能较差。这是导致此问题的最常见原因。

  3. 检查输入数据集的分区。如果您的分析中使用的数据集分区不合理，则会导致性能变慢。

  4. 要检查输入数据集中文件的大小，请前往 数据集 → 详情 → 文件 → 数据集文件.

  5. 每个文件应至少为 128 MB。如果文件太小或太大，您需要对其进行重新分区。

  6. 如果您的路径非常长，则应将中间数据集物化，并创建以这些新物化的数据集为起点的新路径。这将减少逻辑执行中的冗余，因为每个看板都会执行创建该看板所需的完整查询路径（例如所有先前看板中使用的转换逻辑，如果有的话）。

  7. 请考虑减少分析中的路径数量。这可能会降低浏览器性能，尤其是在使用路径概览界面时。

如需进一步阅读，请查阅我们的 Contour 分析性能优化 文档。

count_distinct() 在表达式面板的窗口函数中失败

直方图 count_distinct() 由于 Spark 的限制，函数在窗口函数中不可用。请查阅 官方 Spark 文档 ↗.

您可以在透视表看板中实现相同的功能（取决于您想要使用的窗口逻辑），该看板提供了唯一计数聚合选项。您可以将“窗口”定义为行/列组合，然后为每个交叉点生成唯一计数。
