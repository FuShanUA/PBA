模型推理历史

模型推理历史是 Foundry 中的一个数据集，用于捕获发送到 Modeling Objective 实时部署的所有推理请求（输入）和推理结果（输出）。它可以支持许多工作流程，例如以下几种：

  • 漂移检测： 模型推理历史可以帮助您检测模型性能随时间的变化，这可能表明底层数据分布发生了漂移。检查推理历史可以为模型准确性的演变提供有价值的洞察。
  • 持续再训练： 模型推理历史可用于持续再训练场景，即基于模型先前的预测，使用新数据对模型进行迭代训练。
  • 模型性能评估： 推理输入和输出的历史记录可用于评估模型随时间的性能表现。推理历史可以帮助您识别模型性能中的模式和趋势。
  • 使用分析： 推理历史可以帮助您了解模型在何处被调用以及调用的频率。这些对模型使用模式的洞察可以为资源分配和优化决策提供依据。

模型推理历史的使用

要创建模型推理历史，请导航至您的 Modeling Objective 的 部署 页面，并选择您想要添加模型推理历史的实时部署。在 模型推理历史 卡片下，点击 创建数据集。这将打开 创建新的模型推理历史 对话框。

在监听器设置向导的 创建新的模型推理历史 对话框中，为模型推理历史输入数据集名称和位置。我们强烈建议添加 安全标记 ，因为输入和输出可能包含敏感信息，应仅允许具有相应安全权限的人员访问。

创建模型推理历史后，以下信息将被记录到数据集中：

  • timestamp：输入请求的时间戳
  • user_id：发送请求的用户的 Foundry 用户 ID
  • request_uuid：请求的唯一标识符
  • live_rid：建模实时部署资源标识符
  • objective_rid：建模目标资源标识符
  • model_rid：模型资产资源标识符
  • model_version_rid：模型资产版本资源标识符
  • input：发送给模型的输入的 JSON 表示
  • output：模型输出的 JSON 表示
  • error：模型在针对提供的输入运行推理时遇到的详细错误消息或堆栈跟踪

要临时启用或禁用模型推理历史，请点击 模型推理历史 卡片右上角的开关，该卡片标记为 启用记录.

要永久禁用模型推理历史，请选择 移除 ，位于 模型推理历史 卡片。

移除模型推理历史是永久性的，无法撤销。一旦数据集被移除作为模型推理历史，该数据集仍将存在，但无法重新添加到部署中。

常见问题 (FAQ)

在我的实时部署上设置模型推理历史需要哪些权限？

要启用模型推理历史，用户需要 gatekeeper 权限 foundry-ml-live:edit-inference-ledger。通常，该权限通过建模目标上的“owner”角色授予。

我可以在哪里保存模型推理历史数据集？

由于输入和输出可能包含敏感信息，您需要将该数据集保存到与其父建模目标相同的项目中。

我可以将模型推理历史的输入和输出写入现有数据集吗？

为确保模型推理历史符合指定的 schema，您无法为模型推理历史选择现有数据集。

如果我移除模型推理历史会发生什么？

如果您移除模型推理历史，数据集不会被删除，但 Foundry 将停止向其写入新记录。

如何临时启用/禁用我的模型推理历史？

您可以使用录制开关来临时启用或禁用您的模型推理历史记录。

是否保证所有推理输入都会被记录到模型推理历史中？

并非所有输入和输出都保证会出现在推理历史中。为了保持平台性能，写入模型推理历史失败的请求不会重试。
