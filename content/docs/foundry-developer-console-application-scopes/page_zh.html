应用程序限制

每个 Developer Console 应用程序都对应一个 OAuth 客户端，该客户端负责处理 Foundry 授权。在 OAuth 授权过程中，第三方应用程序会被授予令牌，这些令牌受 作用域 限制，仅允许特定的操作和资源。给定令牌的作用域在运行时确定，是以下各项的交集：

  1. 特定应用程序用户(用于授权码授予)或服务用户(用于客户端凭证授予)在 Foundry 中的权限。请查阅 身份验证授予类型文档 以了解更多详情。
  2. 在 Developer Console 中为给定应用程序配置的最大 限制 ,其定义了该应用程序所能拥有的最大作用域。应用程序也可以保持 不受限制。
  3. 第三方应用程序在代码中作为 令牌请求(也称为“授权时间”)的一部分而请求的操作作用域。未请求作用域的令牌请求将默认允许该用户在 OAuth 客户端限制允许范围内的全部权限。在授权时不会应用额外的限制。

所有令牌的作用域必须在 OAuth 客户端级别（通过应用程序限制）或在授权时（通过令牌请求）受到限制。尝试请求不带作用域限制的令牌将生成一个没有任何权限的令牌。

配置应用程序限制

应用程序可设置为 受限 或 不受限。

  • 受限应用程序 是默认创建的。这意味着 Developer Console 会控制应用程序在 Foundry 中可使用的 资源 和 操作 。
  • 不受限应用程序 没有最大允许资源或操作控制。仅根据用户权限以及在授权时 请求的操作 来确定访问权限。

受限或不受限设置不是应用程序创建向导的一部分。应用程序创建后，您可以在应用程序的 OAuth & restrictions 页面上更改此设置：

  1. 在 Developer Console中打开您的应用程序。
  2. 从左侧导航面板中选择 OAuth & restrictions 。
  3. 在 应用程序限制下，选择 受限 或 不受限。

请注意，切换为不受限应用程序将移除您当前的项目访问权限和操作限制配置。

从非受限应用切换为受限应用时，您需要配置项目访问权限和平台 API 操作。如果您的应用使用了在此配置过程中未添加的资源，则可能会出现故障。

受限应用

受限应用控制应用的 OAuth 客户端可请求的最大资源和操作。例如，假设某用户拥有读取某个 Foundry 数据集的权限，并正在通过一个受限的第三方应用查询该数据集，该应用请求 api:use-datasets-read。在以下两项内容被添加到应用的限制之前，该用户将无法访问：

  1. 包含该数据集的项目被添加到应用的 资源限制
  2. api:use-datasets-read 被添加到应用的 操作限制。

受限应用程序通过在构建时定义应用程序可代表其用户执行的所有操作,从而在一开始就提供了更高的清晰度。这最大限度地减少了权限提升的情况,即应用程序代码利用其用户的访问权限执行应用程序构建者本身无权访问的操作。此外,限制还可对 Foundry 能够发送到特定设备或系统的数据设定保证上限。例如,限制可以保证在控制室中显示的应用程序绝不会显示敏感内容,无论登录该应用程序的用户是谁。

资源限制

资源限制定义应用程序可以访问哪些 Foundry 资源。请在 Developer Console 的以下位置(可通过左侧导航面板访问)配置资源限制。

  • Ontology SDK 标签页: 如果您的应用程序与本体论交互(通常使用 OSDK),可使用此标签页将对象类型、接口、操作和函数添加到应用程序资源列表中。添加本体论资源将在两个方面更改 Developer Console 应用程序:
    1. 应用程序的资源限制将允许访问所列出的资源。
    2. 为应用程序生成的任何新 SDK 都将包含所列出的资源。
  • Platform SDK 标签页: 如果您的应用程序与平台 API 交互（通常使用 平台 SDK），请使用此选项卡将 Foundry 项目添加到资源限制中。受限应用程序只能读取或写入这些项目内的资源。如果应用程序必须与 Foundry 资源交互，而该资源 不在 项目内，请考虑使用 非受限应用程序。

操作限制

操作限制定义应用程序可以执行哪些 API 操作。与资源限制不同，您只能在 Platform SDK 选项卡中配置操作限制。

在此处通过 API 命名空间添加允许的操作。选择应用程序可用于与所选项目资源交互的方法。操作按 API 命名空间分组，命名空间对应于端点的路径；例如， /admin/ API 命名空间包含路径为 /api/{version}/admin/的所有端点。有关 API 命名空间的更多详细信息，请参阅 API 文档。

针对客户端允许操作的 API 级别安全性

Developer Console 应用程序会对受限应用程序强制执行 API 级别安全性，确保这些应用程序调用的每个端点都必须明确添加到 Platform SDK 面板中的操作限制列表。 非受限应用程序 不受这些更改的影响，并将继续能够调用用户拥有必要权限可访问的端点。请注意，不受限应用程序通常应仅用于程序化、平台级的工作流。

不受限应用程序

不受限 应用程序在确定访问权限时仅考虑应用程序用户的权限，而不是将访问权限限制为一组预定义的资源。

默认情况下，自定义应用程序会受到限制，以鼓励更严格的安全保证。在以下情况下使用不受限应用程序：

  • 资源无法在部署时定义（例如，尚不存在的项目）。
  • 您的应用程序必须访问项目之外的管理原语（例如，空间、组织或注册）。
  • 您需要使用平台 API 中尚未发布的端点。

不受限应用程序可以与应用程序用户有权访问的任何资源进行交互。请仅将不受限应用程序与受信任的代码一起使用。

创建不受限应用程序

不受限应用程序是 独立 OAuth 客户端的推荐替代方案，此类客户端已无法再创建。创建向导不提供受限或不受限的选择，因此在创建应用程序时无需选择任何内容。请先创建应用程序，然后更改其限制设置。

  1. 创建 Developer Console 应用程序，请按照 创建一个新的 Developer Console 应用程序，并在创建向导中进行以下选择。 应用程序类型 和 权限 的选择决定了应用程序如何进行身份验证；请查看 权限 以了解这两项的完整说明。
    • 在 应用程序类型 页面中，选择 后端服务 （适用于可以安全存储客户端凭据的应用程序），或选择 面向客户端的应用程序 （适用于无法安全存储客户端凭据的前端）。
    • 在 权限 页面中，选择 应用程序权限 （适用于通过自身生成的服务用户执行操作的应用程序），或选择 用户权限 （适用于以登录用户身份执行操作的应用程序）。面向客户端的应用程序必须使用 用户权限。
    • 在 资源 页面中，选择 否，我不会使用本体论 SDK （如果您的应用程序仅调用平台 API）。您也可以跳过添加 Foundry 项目和平台 API 操作，因为在第 3 步中将应用程序设为不受限制后，该配置将被移除。
  2. 如果您选择的是 后端服务，请复制创建应用程序时显示的客户端密钥。这是唯一一次可以看到该密钥；如果密钥丢失，您必须 轮换该密钥。仅配置为 面向客户端的应用程序 的应用程序会使用公共 OAuth 客户端，并且没有客户端密钥。
  3. 要将新应用程序更改为不受限制，请按照 配置应用程序限制中的步骤操作。正是这一步骤使应用程序变为不受限制，且仅在应用程序创建后才可用。
  4. 在应用程序代码中请求您的应用程序所需的操作范围，具体方法请参阅 在授权时请求范围。使用授权码模式(authorization code grant)的不受限制应用程序必须请求一个范围。

在授权时请求范围

除了 在 Developer Console 中配置的限制之外，第三方应用程序还可以在身份验证过程中请求操作范围。如 上文所述，在确定访问权限时，所请求的范围会与应用程序的限制以及用户自身的权限取交集。请注意，Foundry 第三方应用程序只能请求 operations ，且只能在授权时进行。 Resource 访问权限仅由应用程序的资源限制和用户权限决定，无需请求。

迁移到 API 安全

如 上文所述，2025 年 6 月 1 日之后创建的 Developer Console 应用程序会强制执行 API 级别的安全措施，以确保受限第三方应用程序调用的每个端点都必须单独添加到客户端允许的操作列表中。请按照以下 迁移步骤 处理 2025 年 6 月 1 日之前创建的应用程序。

任何新建或迁移的应用程序现在都会限制此前允许的两类应用程序访问： 底层服务端点 和 隐式操作授权。

无法访问底层服务端点

受限应用程序不得调用底层服务 API，这些端点未明确记录在文档中，也未向用户公开。

Developer Console 应用程序客户端所使用的作用域现在包含前缀 use-；例如： api:use-ontologies-read 而不是 api:ontologies-read。这些新权限仅允许您调用 Foundry 平台 API，并且会被阻止调用底层服务端点。

API 安全的一个重要例外是一组 管理 端点，这些端点旨在始终可供用户访问，用于身份识别、授权或访问调试。这些端点并非为广泛的公共使用而设计，因此未包含在公开的 Foundry API 文档或 Platform SDK 资源 面板中。此类端点包括以下内容：

  • OAuth2： /multipass/api/oauth2/...
  • 用户信息： /multipass/api/me/...
  • 资源访问信息： /multipass/api/authz/...
  • 令牌 TTL： /multipass/api/token/...
  • 组织： /multipass/api/organizations/...

这些端点始终可由受限应用程序调用。

无隐式操作授权

随着高级 API 级别安全性的加入，每个 API 命名空间都受到严格隔离。在这些更改之前，授予 API 命名空间作用域会使应用程序能够访问该命名空间中的端点以及任何 依赖端点 （位于其他命名空间中）。新的、更安全的 API 作用域（带有前缀 use-）仅提供对直接授予的 API 命名空间的访问权限。这确保了应用程序管理员能够严格控制应用程序在其组织内可能执行的操作。

例如,一个被授予 /ontologies/ API 命名空间权限(api:use-ontologies-read)的旧版应用程序可以使用 /api/v2/admin/users/getCurrent 端点查询基本用户身份信息,该端点位于 /admin/ 命名空间中,因为多个本体论端点出于身份验证目的需要这些操作。迁移到改进后的安全协议后,如果应用程序仅被授予 api:use-ontologies-read 和 api:use-ontologies-write 作用域,则该应用程序将被阻止访问此用户信息,并会收到 ApiUsageDenied 错误。

默认情况下,在安全更新后创建或已迁移为使用高级 API 级别保护的所有 Developer Console 应用程序都将配置为具有 api:use-ontologies-read 和 api:use-ontologies-write 作用域。

迁移步骤

请按照以下步骤迁移您的 Developer Console 应用程序以使用高级 API 安全功能:

  1. 导航到 Platform SDK resources 标签页并选择 Migrate。
  1. 按照对话框中的说明更新您的应用程序代码。如果您使用的是 TypeScript SDK,请将请求的操作作用域更改为使用符合升级后安全模型的新作用域。为防止临时中断, 请勿 在添加新作用域的同时移除任何原始操作作用域。
  1. 应用程序成功迁移后,您可以从应用程序代码中移除原始的过时作用域。

作用域前缀

Foundry 为 API 权限使用两种作用域前缀:

范围模式示例用例
api:use-*-read/writeapi:use-ontologies-read新建的受限 Developer Console 应用程序。仅允许调用公共 API。
api:*-read/writeapi:ontologies-read独立 OAuth 客户端 以及某些非受限应用程序。允许调用公共 API 和访问内部服务端点。

在选择要使用的范围时:

  • 受限应用程序 应使用 api:use-* 范围(例如, api:use-ontologies-read)。
  • 独立 OAuth 客户端 应使用 api:* 范围(例如, api:ontologies-read)因为它们直接调用 Foundry,如上文所述。注意:独立 OAuth 客户端是一种旧版原语,正在被非受限应用程序取代。
  • 非受限应用程序 应使用 api:use-* 范围,除非它们需要查询底层的 Foundry 服务端点。

此模式适用于所有 API 命名空间,包括 admin、 ontologies、 datasets、 streams等。

独立 OAuth 客户端[旧版]

无法再在 Developer Console 中创建独立 OAuth 客户端。请改为按照以下步骤 创建非受限应用程序。

独立 OAuth 客户端是自定义应用程序的一种旧版轻量级替代方案。除了身份验证客户端本身之外,独立 OAuth 客户端不提供诸如限制、指标或 SDK 生成之类的应用程序构建功能。

非受限应用程序通过在功能齐全的自定义应用程序中提供同等的访问灵活性,取代了独立 OAuth 客户端。

要将现有的独立 OAuth 客户端迁移到 Developer Console 应用程序:

  1. 打开您现有的独立 OAuth 客户端。
  2. 选择 迁移到 Developer Console 应用程序。
  3. 在迁移向导中选择位置和最高分类（如适用）。
  4. 查看 Developer Console 应用程序的用户权限。
  5. 选择 提交.

迁移完成后，新创建的应用程序将显示在所选位置。你可以像对任何其他 Developer Console 应用程序一样对该应用程序执行操作。使用你客户端的现有工作流不受影响。
