代码工作区

代码工作区将 JupyterLab®、RStudio® Workbench 和 VS Code 等第三方 IDE 引入 Palantir Foundry，使用户能够在 Foundry 本体论的高质量数据上使用其偏好的工具，从而提升生产力并加速数据科学与统计工作流。代码工作区容器与 Foundry 生态系统的其余部分原生集成，将熟悉的 IDE 与 Foundry 平台的优势（例如数据安全、分支、构建调度和资源管理）相结合。

代码工作区为平台管理员提供了一种易于部署、完全托管、安全且可用于生产环境的方式，向用户提供 JupyterLab®、RStudio® Workbench 和 VS Code，并内置 Foundry 的数据治理以及符合 FedRAMP、GxP 和其他标准的合规性。借助代码工作区，用户可以安全地连接到现有内部系统，并在 Foundry 的访问控制和数据权限管理下，基于数据构建分析、转换、模型、应用程序或完整的工作流。

主要功能

代码工作区的主要功能包括：

  • 安全性： 代码工作区构建于以下核心组件之上： Foundry 安全 ，例如权限和细粒度访问控制等，支撑着整个平台。这为代码工作区中可用的第三方 IDE 提供了 Foundry 的安全模型。例如，如果在 Foundry 中限制了对某个数据集的访问，该限制同样适用于代码工作区 IDE，从而确保各工具之间的权限一致。

  • 可自定义的环境： 代码工作区允许用户定义自定义环境配置，并根据需要增加或减少其工作区的计算资源。

  • Git 工作流支持： 代码工作区由 代码仓库 基础设施提供支撑，具备分支、合并和提交历史等符合行业标准的版本控制功能。这些功能使多个用户能够更轻松、更安全地在同一工作区中操作。

  • 代码查看器： 该 代码查看器 提供了一个只读界面，用于浏览、搜索、比较和共享仓库的已提交状态，而无需启动编辑器工作区。

  • 应用程序： 代码工作区目前支持 Dash ↗ 和 Streamlit ↗ （用于 Python 应用程序）以及 Shiny® ↗ （用于 R 应用程序）。用户可以在代码工作区中直接创建应用程序工作流，并使用内置的 Foundry 版本控制、分支和数据治理功能。

  • 模型集成： 用户可以在代码工作区内创建模型资产，并在跟踪这些资产时使用 建模目标。可以从同一工作区创建多个模型。

  • 转换/构建集成： 代码工作区可用作转换的开发环境。在代码工作区中编写的逻辑可以发布为数据转换管道，并与 Foundry 的 数据集成 工具包相集成，其中包括构建、调度、数据血缘和健康检查。代码工作区同时支持 R 转换和 Python/Jupyter® 转换。

  • AIP 辅助编码： JupyterLab® 和 RStudio® 代码工作区在工作区侧边栏中包含一个 AIP 代理，该代理可连接到 受支持的 AIP LLM。该代理可以生成和解释代码、分析数据、自动执行重复性任务（例如安装库和清理数据），并帮助您构建 Dash 和 Streamlit 应用程序。此功能在 启用 AIP 时可用。

  • 通过数据源与外部系统集成： 数据源让您能够安全地与外部系统交互，并为交互式工作流和已发布的应用程序管理机密、出口流量和导出控制。了解更多信息，请参阅 与外部系统交互。

何时使用代码工作区

Foundry 提供了多种可用于分析或编码的应用程序。例如，如果您是分析师，那么 Contour（Foundry 用于数据集分析的点击式低代码界面）可能最适合您。

如果您需要编写大规模数据管道、设置数据连接或处理流式数据，其他 Foundry 工具比代码工作区具备更多功能；对于这些用例，我们建议分别使用 Pipeline Builder、 Data Connection和 Foundry Streaming。

具体而言，代码工作区在单个节点上运行，而其他 Foundry 应用程序则利用 Spark 基础设施。因此，我们建议执行大规模数据转换的用户选择 Pipeline Builder 或 代码仓库 而非代码工作区。

使用代码工作区在 VS Code、JupyterLab® 或 RStudio® Workbench 中结合 Foundry 数据和服务编写代码。使用 代码查看器 来查看或共享已提交的仓库代码，而无需启动编辑器工作区。
