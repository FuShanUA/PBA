核心概念

本页面介绍与 Pipeline Builder 相关的 Foundry 数据集成核心概念。

构建

以下概念： 数据集, 分支, 转换日 输出 是 Pipeline Builder 的基础。我们建议在构建您的第一个管道之前，以及在转换数据和集成到管道输出时，先了解这些主题。

数据集

数据集是管道的构建模块。在数据集成过程中，数据以 Foundry 数据集 的形式存在，从数据进入 Foundry 开始，直到数据被映射到 本体论 对象模型中。

从根本上讲， Foundry 数据集 是对存储在 支撑文件系统中的一组文件的封装。Pipeline Builder 主要面向结构化数据，但也可用于半结构化数据。

了解有关 Pipeline Builder 中输入数据集的更多信息。

提供了专为数据转换量身定制的版本控制体验，支持团队在同一工作簿中同时处理逻辑与数据。

版本控制对于维护健康的管道工作流至关重要。在 Pipeline Builder 中，版本控制通过管道 分支来实现，其运作方式类似于 Git 版本控制中的代码分支。

管道分支是管道的一个副本，用户可以在该副本上进行迭代，而无需保存回主管道，这类似于 Git 中的代码分支。用户可以在其分支上进行更改、预览、保存和构建。一旦对更改满意，他们可以提议合并回 主 分支，这类似于合并 Git 拉取请求。

创建分支时，您可以选择 Pipeline Builder 分支（仅限于您正在处理的管道）或 全局分支，后者允许您在单个分支上对多个应用程序进行更改。Pipeline Builder 分支还可以配置为与 Code Repositories 分支名称匹配，从而在两个应用程序之间实现共享迭代。您可以配置回退分支，以控制在当前分支上尚未构建输入数据集时使用哪个分支。

了解有关 Pipeline Builder 中分支的更多信息。

转换

转换可以被视为一个函数定义；也就是说，转换接受一组输入（例如数据集）并产生一组输出。管道是由数据集、数据期望和目标数据输出组成的链接，它们通过转换连接在一起。

了解有关 Pipeline Builder 中转换的更多信息。

管道输出

Pipeline Builder 中的输出是管道中执行的转换的结果，可以是数据集、文件、 虚拟表或本体论组件（例如对象类型、对象关联类型或时间序列）。输出可以在其他 Foundry 应用程序中使用，例如 Quiver 或 Code Workbook。

了解有关 Pipeline Builder 中管道输出的更多信息。

管理

以下概念： 计划 和 数据期望 有助于维护健康、稳定的管道。我们建议在构建您的第一个管道后进一步了解这些主题。

计划

计划 用于运行 数据集构建 以定期方式运行，从而保持数据在 Foundry 中持续流动。在 Pipeline Builder 中，可以在特定时间、按特定频率或根据父资源的状态来计划构建；例如，您可以设置在上游数据集更新时执行构建。

了解有关 Pipeline Builder 中计划的更多信息。

数据期望

Pipeline Builder 通过单元测试支持对输出和中间转换的数据期望。数据期望是可以应用于数据集输出的要求。这些要求（称为“期望”）可用于创建检查，以提高数据管道的稳定性。

可以在每个管道输出上设置数据期望，以对生成的输出定义期望。Pipeline Builder 支持多种数据期望类型，包括主键、行数和行级期望。

如果任何期望失败，构建将失败。作业期望窗格将显示哪些数据期望通过、哪些失败。
