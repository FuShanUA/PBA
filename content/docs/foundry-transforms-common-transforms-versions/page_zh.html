Transforms 版本

在 transforms 中，构建时所使用的 Spark、Java 和 Scala 版本取决于 transforms 版本。Transforms 会在后台自动升级，以确保作业始终与最新的安全性和性能改进保持同步。根据 Spark 版本控制策略 ↗，API 在各版本之间保持一致，并启用旧版配置以防止行为变化。这些配置记录在 Spark 迁移指南 ↗.

环境页面

可以通过在作业跟踪器中选择以下内容来访问环境页面： Spark Details > Environment。在这里，您将看到构建的关键配置详情，包括 transforms 和 Spark 版本。

直方图 sparkModuleVersion 对应于 transform 版本，而 sparkVersion 对应于构建中使用的 Spark 版本。

运行时版本控制

每次运行构建时都会选择一个 transforms 运行时版本。系统会使用一种称为“裁决（adjudication）”的机制，以确保您的构建不会升级到不再可用的版本；裁决过程会有选择地测试升级，并在必要时回退到旧版本。当新的 Spark 版本发布时，如果可行，它将自动在您的管道中进行测试和实施，无需任何用户干预。如果升级不成功，您的管道将继续在旧的 Spark 版本上运行。每次 Spark 版本升级都将附带一份 公告。要暂时保留在现有的 Spark 版本上，请使用 模块固定（module pinning） 将管道固定到特定版本。

在运行时版本发布大约一个月后，系统将发送仓库升级提示，告知用户无法自动升级的问题。您应该能够根据仓库中的检查错误来调试这些情况。

调试作业

如果您怀疑 transforms 升级导致管道中断，请使用调试作业来诊断问题。在失败的作业上，选择 操作 和 以调试作业重新运行 来指定之前成功的版本，并确认 transform 版本的更改是否是导致中断的原因。如果您遇到 transforms 升级破坏管道的情况，请联系 Palantir 支持团队以获取进一步帮助。

目前，以下情况不支持运行调试作业：

  • 外部 transforms 使用包含密钥的源。
  • 旧版外部 transforms 使用凭据。
