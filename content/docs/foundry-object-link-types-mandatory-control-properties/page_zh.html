强制控制属性

强制控制属性是一种对象类型属性，可对存储在对象中的数据进行细粒度的访问控制。您可以使用强制控制属性来限制给定对象在同一数据源中所有其他属性的访问，使这些属性仅对满足强制控制要求的用户可见。

注意： 强制控制属性 仅在 Object Storage v2 上可用。

如何使用强制控制属性

  1. 首先，创建由标记支撑的受限视图（RV）。详细了解 如何创建由标记支撑的受限视图。
  2. 导航到本体论管理器。
  3. 选择要限制其属性访问的对象类型，然后创建或选择要设置为强制控制属性的属性。
  4. 在属性侧边栏中，确保该属性已映射到相应的 标记列 （位于您的受限视图中）。
  5. 将该属性类型的基本类型设置为 强制控制。
    1. 默认情况下，强制控制属性支持通过 标记 和/或 组织 来限制访问。
    2. 如果您已启用 CBAC，则可以选择基于 分类 的强制控制。
  6. 在数据源上选择 允许的标记 和/或 允许的组织 。对于分类，请选择 最高分类。
  7. 如果对象类型具有多个数据源，请为其他每个数据源选择一个强制控制属性，以同样保护其属性。
  8. 保存对本体论的更改，并等待重新索引完成。

强制控制属性的类型

可对属性设置三种类型的强制控制：

  • 标记
  • 组织
  • 分类

标记

标记是一种强制控制，要求用户必须拥有特定的标记才能访问数据，以此限制访问。如果某个资源具有多个标记，则用户必须拥有所有这些标记才能访问该资源。了解更多关于 标记。

要使用标记，您需要提供一组允许的标记。只有此集合中的标记才会被允许用于数据源上的任何强制控制属性。

组织

组织是一种访问要求，可在用户群体与资源群体之间强制实施严格隔离。每个用户都是一个 成员 ，仅属于一个组织，但也可以是 访客成员 多个组织。要访问带有组织标记的数据，用户必须是该组织的成员。如果资源具有多个组织，则用户必须是应用于该资源的至少一个组织的成员。进一步了解 组织。

要使用组织，您需要提供一组允许的组织。只有此集合中的组织才允许用于数据源上的任何强制控制属性。

标记和组织可以在同一个强制控制属性上一起使用。在这种情况下，用户必须满足所有标记以及至少一个组织，才能访问该资源。

分类

分类标记是用于保护敏感政府信息的强制控制。它们用于限制对敏感信息的访问，这类信息的敏感度是按层级方式定义的。每个用户只能访问分类级别不高于其自身分类级别的数据。

只有在您的注册中启用了 CBAC，您才能配置 CBAC 标记。进一步了解 CBAC（基于分类的访问控制）。

要使用分类，您需要提供最高分类。只有满足该最高分类的标记才允许用于数据源上任何基于分类的强制控制属性。

分类不能与标记或组织同时用于同一个强制控制属性。

数据源级别的权限管理

强制控制属性会保护同一数据源中的所有其他属性。对于只有单个数据源的对象类型，这意味着用户只有满足强制控制属性中的值时才能查看对象。

但是，对于多数据源支撑的对象类型（MDO），每个数据源都可以有自己的强制控制属性。只有由特定数据源支撑的属性才会受到该数据源中强制控制的保护。

这意味着用户可能只拥有查看对象上部分属性的权限。在这种情况下，用户只能看到从这些数据源映射而来的属性。当向用户显示对象实例时，其他属性将显示为 null。

要有效使用强制控制属性，支撑数据源的结构应确保只有需要共享同一强制控制的属性才会位于同一数据源中。

验证

对强制控制属性强制执行以下验证：

  • 强制控制属性必须映射到 标记列 ，该列位于 受限视图上。 强制控制是通过用受限视图支撑对象类型来实施的，该受限视图具有一项策略，要求用户满足所映射列中的标记才能查看某一行。请参见 受限视图 以了解更多信息。
  • 强制控制属性必须为必填属性。 这可确保如果数据源上存在带有强制控制属性的对象，则必须定义强制控制，以帮助维护数据的一致性和完整性。所有强制控制属性不得为 null。但是，标记和组织值可以设置为空数组。在这种情况下，所有用户都将满足标记要求并能够查看该行。了解更多关于 必填属性的信息。
    • 如果要向没有支撑数据源但已有编辑的对象类型添加强制控制属性，则无法直接创建该属性，因为强制控制属性不能为空。解决方法如下：
      1. 添加一个可为空的字符串数组属性。
      2. 使用 操作回填其值。
      3. 将该属性的基础类型更改为 强制控制。
  • 每个包含强制控制属性的数据源都必须定义一项约束，规定可为这些属性添加哪些值。这些约束的形式为：针对基于分类的强制控制的最大分类，或者一组允许的标记和/或允许的组织。对强制控制属性所做的任何编辑，以及从支撑数据集获取的值，都必须遵守数据源上设置的约束。
    • 此约束在对象存储层面强制执行，因此即使您或许能够使用本体论管理器保存违反此约束的对象类型，但如果数据集中的现有值不满足这些约束，或者数据集中的值更新后包含强制控制的无效值，该对象类型仍将无法编制索引。此外，任何试图为强制控制属性设置无效值的编辑都将被拒绝，且该操作将无法提交。
    • 这些允许的标记、允许的组织或最高密级将用于标记从该对象类型物化得到的任何导出数据集。这可确保只有能够查看该对象类型中所有行的用户才能查看物化后的数据集。

请注意，强制控制属性默认设置为 Hidden 。这是因为强制控制属性旨在用作其他字段的标记，因此通常无需在对象视图或表格中显示这些属性。不过，如有需要，仍可以启用强制控制属性的可见性。

操作中的强制控制

您可以为操作类型添加强制控制参数。该参数可以是标记参数，或者在启用 CBAC 的情况下为分类参数。目前不支持组织参数。

强制控制参数通常用于为操作创建的对象设置强制控制属性。在这种情况下，所提供的值必须符合该属性允许的值；如果提供了无效值，操作提交将失败。

对于基于分类的强制控制参数，您还可以在参数级别添加最大分类。这是一种操作类型验证，因此如果所提供的值不满足最大分类，将阻止操作的提交；这与依赖数据源验证不同，后者允许操作提交，但操作将无法完成。

由操作创建的对象将通过为强制控制属性提供的值获得保护，就像从支撑数据源派生的对象一样。

Marketplace 用法

具有强制控制属性的对象类型和具有强制控制参数的操作类型可以通过 Marketplace 进行打包和安装。

在打包包含强制控制属性的对象类型时，允许的标记或最高密级将被声明为该产品的安装输入。

类似地，如果打包的操作类型包含基于密级的强制控制参数并设置了最高密级，则该最高密级将被声明为安装输入。

安装产品时，系统将提示您为每个强制控制属性选择允许的标记或最高密级。所选值将在安装时被设置为强制控制属性的允许标记或最高密级。

请注意，如果打包的多个强制控制属性和/或参数具有相同的值，则只会声明一个强制控制输入。
