本体论提案 [旧版]

本体论分支（以前称为本体论提案）即将停用。在启用了全局分支功能的租户中，您无法再创建本体论分支。请改用 全局分支 来修改本体论并获取扩展功能，包括为数据源创建分支、在受支持的应用程序中测试下游变更，以及在统一的工作流中同时管理数据和本体论的修改。

本体论分支允许您在分支上对本体论进行更改，该分支基于 Main 该本体论的版本。此流程可确保所有修改在并入主本体论之前都经过审查和批准。

要创建分支，您需要对包含相应资源的项目拥有编辑者权限。

定义

  • 分支： 本体论上的一个 分支 是该本体论的独立版本，由主版本派生而来，旨在支持在不影响主分支的情况下进行试验和更改。这样，用户可以在隔离环境中测试和完善对本体论的调整，然后再将其合并回主分支。

  • 提案： 一项 提案 类似于版本控制系统中的拉取请求，专为本体论分支量身定制。提案会随分支一起自动创建，并包含元数据，例如评审、名称以及将要合并到主分支的变更描述。提案提供了一种机制，用于在单独分支中所做的变更被集成到主本体论之前对其进行评审和批准。

本体论分支工作流

常规的本体论分支工作流包含五个步骤：

  1. 创建您的分支
  2. 准备您的提案以供评审
  3. 请求评审
  4. 评审提案
  5. 发布提案

以下各节概述了每个步骤。

1. 创建您的分支

您可以通过选择 创建分支 来打开一个对话框，您可以在其中为提案选择标题和描述。

或者，如果您已经对本体论做了更改并希望将其包含在提案中，可以点击保存并切换 提议您的更改 选项（位于保存对话框中）。

如果您位于本体论的主分支上且没有任何更改，也可以通过选择分支选择组件并输入新分支的名称来创建分支。

提案分支只能在主本体论配置上创建。无法基于另一个提案创建新分支。

在分支上时，位于工作区界面上方的分支导航顶部栏会反映您当前所在的分支。

2. 准备提案以供审核

此时，根据您创建提案的方式，您的分支上可能已经存在一些更改。在分支上，您可以继续对本体论资源进行更改，包括创建和删除。

每个修改后的本体论实体都将在您的提案中构成一个单独的 任务 ，并可供审核。

对于已迁移为使用 本体论角色的资源，查看者可以在提案中对资源进行更改。如果资源使用数据源派生的权限，则只有编辑者或所有者才能在提案中对这些资源进行更改。

在分支上，当您持有编辑者或所有者权限时，可以编辑资源。

3. 请求审核

对分支进行更改后，您可以为提案添加审核者。为此，请导航至您的 提案视图，方法是选择 打开提案详情 （位于顶部栏）。

如果您已退出分支，可以通过以下方式转到您的提案概览：导航到 提案 选项卡并选择您的提案，或者使用分支选择组件。

接下来，在 审阅者 部分中分配审阅者。

在提案进入 In review 阶段之前，审阅者不会收到通知。

您还可以对提案中的各项任务添加评论，为所提议的变更提供背景信息。要访问任务的 评论 部分，请选择 审阅 选项卡，然后选择最右侧的 评论 侧边栏。

4. 审阅提案

审阅者可以在 审阅 选项卡中批准或拒绝各个任务，并可以添加评论来支持其审阅意见。

审阅者必须拥有所有者或编辑权限，才能批准变更。

没有权限的用户仍可以审阅该任务，例如表达自己对变更的看法，但这不会影响该任务的已批准状态。

如果提案的创建者对所有已编辑的资源均拥有所有者或编辑者权限，则他们可以批准自己的变更。

即使编辑者或所有者未被明确添加为审阅者，他们仍然可以批准您的提案。我们建议将审阅者列表用作跟踪应由谁审阅更改的方式，而不是用作保护本体论的方式。相反，应通过谨慎分配角色和权限来保护本体论。

5. 发布提案

您的更改经过审阅和批准后，即可将该提案合并到本体论中。

将更改合并到本体论不需要特殊权限。提案获得批准后，任何可以编辑该分支的用户都可以将该提案合并到本体论中。

提案合并后，它会从 审阅中 部分移动到 已合并 部分（位于侧边栏中）。

在合并提案之前的任何时间，您都可以通过从侧边栏中选择 删除 来关闭提案。

提案只能合并到主本体论配置中。

提案无法自动回退。要撤销提案，您必须撤销其中的各项更改。

提案一旦关闭，便无法重新打开。
