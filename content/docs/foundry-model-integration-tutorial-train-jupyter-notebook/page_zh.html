2b.4 如何从 Code Workspaces 发布模型

现在我们已经创建了一个模型，可以将其发布到 Foundry 以便与我们的生产应用集成。要发布模型，我们需要在 Foundry 中创建用于保存模型的模型资源，然后将模型封装在模型适配器中，以便 Foundry 知道如何与您的模型交互。

这有助于在需要时与其他团队有效沟通上游问题和平台问题，并减少解决问题的时间。它还可以提高平台的调试技能。 在监听器设置向导的 链接进行访问。 标签页中，选择 添加模型 > 创建新模型 并为其命名 linear_regression_model。您可以将模型保存到 models 之前创建的文件夹中，然后选择 创建 以创建该资源。

创建模型资源后，Foundry 会自动为您创建一个 Python 骨架文件，供您在其中实现模型适配器。 模型适配器 为 Foundry 中的所有模型提供标准接口。该标准接口确保所有模型都可以立即在生产应用中使用，因为 Foundry 将负责加载模型及其 Python 依赖项的基础设施、公开其 API 以及与您的模型交互。

Code Workspaces 中的模型适配器必须定义在 Python（.py）文件中，与 notebook 分开，并导入到 notebook 中。Foundry 会为您生成此文件，其文件名和类名源自您选择的模型别名。对于名为 linear_regression_model的模型，Foundry 会生成文件 linear_regression_model_adapter.py 其中包含一个名为 LinearRegressionModelAdapter的类。如果您为模型使用了不同的名称，请在下面的代码片段中替换为您自己的名称。

请在 Foundry 生成的文件中实现您的适配器，而不是创建额外的适配器文件。 发布模型版本 代码片段会使用生成的文件名和类名导入适配器，因此不会使用名称不同的其他文件。因此，生成的骨架代码将继续抛出 NotImplementedError: Model adapter api not defined.

要创建模型适配器，您需要实现四个函数：

  1. 模型保存和加载： 要复用您的模型，您必须定义模型的保存和加载方式。Palantir 提供了许多 默认方法 用于序列化（保存），在更复杂的情况下，您可以 实现自定义序列化 logic.
  2. api: 定义模型的 API，并告知 Foundry 您的模型需要什么类型的输入数据。
  3. predict: 由 Foundry 调用以向您的模型提供数据。您可以在此处将输入数据传递给模型并生成推断（预测）。

import palantir_models as pm
from palantir_models.serializers import DillSerializer


class LinearRegressionModelAdapter(pm.ModelAdapter):

    @pm.auto_serialize(
        model=DillSerializer()
    )
    def __init__(self, model):
        self.model = model

    @classmethod
    def api(cls):
        columns = [
            ('median_income', float),
            ('housing_median_age', float),
            ('total_rooms', float),
        ]
        return {"df_in": pm.Pandas(columns)}, \
               {"df_out": pm.Pandas(columns + [('prediction', float)])}

    def predict(self, df_in):
        df_in['prediction'] = self.model.predict(
            df_in[['median_income', 'housing_median_age', 'total_rooms']]
        )
        return df_in

故障排除

本节介绍从 Jupyter® 笔记本发布模型时常见的问题。

NotImplementedError: Model adapter api not defined

运行发布或转换代码片段时，您将看到类似以下的错误：

NotImplementedError: Model adapter api not defined. Edit linear_regression_model_adapter.py to define api.

解决方案： 打开错误消息中指定的适配器文件，并实现 api 和 predict 方法，然后重新运行该单元格。这是您创建模型时 Foundry 生成的骨架文件；在您实现它之前，它会抛出此错误。

详细信息： 当您使用以下方式创建模型时 Add model > Create new model，Foundry 会生成一个骨架适配器文件，其中的 api 和 predict 方法会抛出 NotImplementedError。该文件和类以您的模型别名命名。例如，别名为 linear_regression_model 会生成 linear_regression_model_adapter.py ，其中包含一个名为 LinearRegressionModelAdapter的类。此错误的两个常见原因是：

  • 您在与 Foundry 生成的文件不同的文件中实现了适配器。请将您的实现移到生成的文件中，或者更新 发布模型版本 代码片段中的导入，使其指向您的文件和类。文件名、类名和导入语句必须全部匹配。
  • 内核仍在运行旧版本的文件。请确认 autoreload lines %load_ext autoreload and %autoreload 2 已存在并已运行，或者使用以下命令重启内核 Kernel > Restart Kernel... ，然后重新运行导入单元格。

NotImplementedError: Model adapter predict method not defined

解决方案： 生成的文件还包含一个骨架 predict 方法，该方法会抛出 NotImplementedError。请实现 predict ，使其输入签名与 api 中定义的输入相匹配，并且其返回值与声明的输出相匹配。

导入适配器时出现 ModuleNotFoundError 或 ImportError

解决方案： 请确认您 from ... import ... 语句中的文件名与适配器文件完全匹配，并且该文件与您的笔记本保存在同一目录中。如果您最近安装了依赖项，请使用以下命令重启内核 Kernel > Restart Kernel... ，以便环境获取更改。
