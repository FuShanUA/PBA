开始使用

本指南演示了如何访问 AIP Logic，介绍了 AIP Logic 界面，并说明了如何设置基本的 Logic 函数：通过组合 LLM 模块并检查 LLM 的 思维链 (CoT) （在调试器中进行）。

访问 AIP Logic

可以通过平台的工作区导航栏访问 AIP Logic，也可以使用快速搜索快捷键 CMD + J （macOS）或 CTRL + J (Windows)。或者，您也可以创建新的 Logic 函数，从您的 文件 通过选择 +新建 然后选择 AIP 逻辑，如下所示。

打开 AIP Logic 后，您可以创建一个新的 Logic 文件，该文件必须保存在项目文件夹中，而不是您的主文件夹中。

应用程序界面

AIP Logic 界面有三个主要组成部分，在下方的示意图中按从左到右的顺序编号：

  1. 输入、区块和输出配置
  2. 调试器
  3. 运行面板

工作流概览

典型的 AIP Logic 工作流程从配置 输入 (A)、区块 (B) 和输出 (C) 开始（位于左侧面板 (1)）。使用 运行面板 (3) 生成示例输出。Logic 运行后， 调试器 (2) 会显示 LLM 生成输出所使用的思维链 (CoT) 提示和步骤。将 Debugger 与 Run 面板结合使用可以可视化最终输出。Run 面板还会显示最近的 Logic 运行记录，并允许您创建单元测试。右侧边栏提供了与 发布后，我们建议在 和 AIP 评估.

输入、区块和输出配置

初次使用 AIP 时，您将看到 运行 面板位于右侧，左侧则有三种类型的板块： 输入，用于根据需要选择对象及其属性， 区块 用于定义逻辑指令，以及 输出 用于表示期望的逻辑函数结果。一个区块的输出可以馈送到后续区块中。

下图显示了输入、区块和输出的配置区域，其中 运行 面板处于折叠状态。

输入

AIP Logic 支持多种 输入。在 输入 块（在 应用程序界面指南），您可以指定输入的名称和类型。支持的输入类型包括 array、boolean、date、double、float、integer、long、media reference、model、object、object list、object set、short、string、struct 和 timestamp。要在 使用 LLM 块中引用输入，请参阅 提示词是用自然语言编写的 LLM 指令。我们建议从最重要的信息开始（例如 LLM 应完成任务的概述），然后是 LLM 所需的数据，以及关于何时使用.

块

AIP Logic 函数由多个块组成（在 应用程序界面指南）。块类型包括 创建变量, 应用操作, 执行函数, 使用 LLM, 循环日 条件。块的输出可以在后续块中使用。更多信息请参阅 块.

输出

您可以为每个 Logic 块定义中间输出。Logic 路径中的最后一个块是 Logic 函数的输出，在 应用程序界面指南.

  • 块输出： 在块之间传递的中间输出。块的输出可以是原始值或对象，供后续块使用。

  • Logic 函数输出： 您希望返回的 Logic 函数输出。该输出可以是 标题可将排序方式切换为 （原始类型或对象）或全部 本体论编辑 （由您的函数做出）。

调试器

构建好 Logic 函数后，要测试该 Logic 函数，您可以选择 运行 在视图右侧。运行 Logic 后，调试器将打开并显示 LLM 的 思维链（CoT）.

调试器允许您展开和折叠区块卡片、清除工具调用，并轻松查看生成的提示词，从而更容易解读思维链。

运行面板

在 运行 面板中，您可以运行并评估您的 Logic，还可以查看最近的运行记录。右侧边栏允许您设置单元测试、运行 自动化，并查看运行历史记录。

在 运行 面板底部，您还可以选择最近的任意一次运行，以查看其输出和调试日志。

执行日志的可见性取决于 Logic 函数的 执行模式设置。在用户范围模式（默认模式）下，您只能查看自己的执行日志。在项目范围模式下，拥有项目访问权限的所有人都可以查看日志。

选择单元测试图标（）以保存输入的一个版本，用于性能评估。

要编辑测试用例参数的名称、类型和可选性，请选择 修改列。在 schema 编辑器中添加参数。

In 运行历史中，选择 添加为测试用例 ，将历史执行结果转换为新评估套件或现有评估套件的测试用例。

使用 AIP Evals 评估您的 Logic

要为您的 Logic 函数生成评估套件，请打开右侧边栏中的 Evals 标签页并选择 使用 AI FDE 生成. AI FDE 在新标签页中打开，并根据您的函数创建测试用例和评估器。您可以编辑生成的测试用例和评估器，以优化覆盖范围和评分。详情请参阅 AIP Evals：入门.

使用 Logic 函数

Logic 函数的使用方式与您在平台中使用常规 对象函数（FoO） 的方式相同。

  • 您可以使用 Logic 函数来支撑某个操作，然后在 Workshop 中调用该操作。
  • 您也可以调用 Logic 函数来支撑 Workshop 中的 Markdown 小部件；在这种情况下，Logic 函数的输出类型必须为字符串。
  • 您可以在其他 Logic 函数以及对象函数中调用 Logic 函数，方法是使用 AIP Logic 中的 本体论函数 工具。

通过命令行运行 Logic 函数

在监听器设置向导的 用途 标签页中，您可以复制 curl 请求，以便在终端中于 Foundry 之外运行该 logic。请注意，此功能不适用于返回本体论编辑的 Logic。

调用函数

在 Logic 中运行该函数时，您将在调试器内的场景中看到所有拟定的本体论编辑。这些编辑实际上并不会被执行。如果您希望将编辑应用于本体论，可以：

  • 从操作中调用您的 Logic 函数；或者，
  • 从自动化中调用您的 Logic 函数。您可以在 Logic 仪表板中开始创建新的自动化，方法是使用 Automations 选项，位于右侧。

要让 Logic 函数能够编辑本体论，您必须：

  1. 设置一个 Apply actions 工具 ，置于 使用 LLM 块中，Logic 函数可以调用该块。这样，LLM 就可以编辑本体论。

  1. 完成 Logic 函数的迭代后，找到并选择 发布 选项（位于“保存”旁边），即可发布该 Logic 函数。

  2. 接下来，创建一个由您刚刚发布的 Logic 函数 支撑的新操作。

  1. 现在，您可以在 Workshop 模块中使用这个新操作来驱动运营工作流。

分支

使用 Foundry 分支功能来隔离开发和测试 Logic 函数。您可以将它们发布到支持分支的应用程序（如 Workshop）中使用，并通过已批准的提案合并更改。更多信息请参阅 AIP Logic 分支.

对比视图

在版本历史选项卡中，您可以比较某个逻辑的两个版本，以查看它们之间发生了哪些变化，具体是哪些块被编辑、添加或删除。

后续步骤

如果您有权访问 AIP Logic，我们建议您开始尝试使用 LLM 块与您的本体论进行交互，并构建您自己的用例。您可能会发现查看平台中有关 函数 的方式相同。
