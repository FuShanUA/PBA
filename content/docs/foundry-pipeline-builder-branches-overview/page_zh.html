提供了专为数据转换量身定制的版本控制体验，支持团队在同一工作簿中同时处理逻辑与数据。

带有分支的版本控制在整个 Foundry 中被广泛使用，也是 Pipeline Builder 的关键组成部分。版本控制对于维护健康的管道工作流、支持安全协作以及确保主生产分支受到保护至关重要。

Pipeline Builder 将管道工作流的每个唯一版本称为一个管道 分支 （类似于 Git 中的分支），其中一个分支用作 main.

A 分支 是管道的一个副本，用户可以在其上进行迭代，而无需保存回主管道。Pipeline Builder 中的分支类似于 Git 仓库中的代码分支；用户在自己的分支中进行编辑和测试更改，而不会对管道产生负面影响的风险。每个管道工作流都从一个 main 分支开始，当用户想要协作时，可以从主分支创建其他分支。一旦用户对分支中的更改感到满意，他们可以提议将该分支合并到 main 分支的情况下对分支执行操作。

全局分支与 Pipeline Builder 分支

创建分支时，您可以选择 Pipeline Builder 分支或 全局分支。全局分支允许您在单个分支上对多个应用程序进行更改，而 Pipeline Builder 分支的作用域仅限于您正在处理的管道。在 Pipeline Builder 中创建的对象类型无法在 Ontology Manager 的分支上进行修改。

您可以创建一个与 Code Repositories 分支同名的 Pipeline Builder 分支，使您的 Pipeline Builder 转换从该匹配分支读取输入数据集。这允许您在共享的分支名称上同时迭代您的 Pipeline Builder 管道和 Code Repositories 转换。您还可以在 Pipeline Builder 中配置 代码仓库 ，以控制在当前分支上尚未构建输入数据集时使用哪个分支，其功能与 Code Repositories 中的创作回退.

活动分支

在监听器设置向导的 活动分支 选项卡，查看当前所有活动分支，或选择归档某个活动分支。已归档的分支不会显示在管道图中的分支下拉菜单中，除非恢复，否则无法编辑或使用。要恢复已归档的分支，请选择 查看已归档分支 菜单中选择 活动分支 选项卡。找到要恢复的分支，然后选择右侧的 恢复分支 图标。

分支保护

在此选项卡中，启用 Require proposals... 以保护一个或多个分支，防止用户直接对指定分支进行更改。此选项要求用户先在单独的分支上进行更改，然后才能将其合并到任何受保护的分支中。

选择 Require at least one approval... 以增加一层保护，在提议的更改合并到主分支之前，需要额外的用户批准。有效的批准者是拥有该管道 Edit 权限且未参与提议更改的用户。在 分支保护文档.

提案模板

在此选项卡中添加或查看提议模板。在可用的文本框中用 Markdown 编写新的提议，或在 预览 选项卡中预览您的文本。如果添加了模板，它将包含在管道中所有新提议的正文中。
