入门

OpenID Connect 1.0 (OIDC) ↗ 协议是 OAuth 2.0 协议之上的一个简单身份层。它允许 Foundry 等客户端验证最终用户的身份，并获取基本的用户资料信息。

某些 OIDC 提供商是公开可用的，允许任何个人创建账户。公共提供商配置不当可能会让不受欢迎的用户访问您的注册环境。请谨慎操作。

网络出站

OIDC 身份验证和元数据收集需要出站调用。您可以选择一个出站策略，或者 配置网络出站策略。

OIDC 概念

以下部分将概述 Foundry 中常见的 OIDC 身份验证概念。

重定向 URL

重定向 URL 需要在 OIDC 提供商处注册。它允许提供商将授权请求的结果传回 Foundry。提供商会在发送给最终用户的授权请求中包含重定向 URL，而最终用户在授权过程中会被重定向到该 URL。随后，Foundry 便可以处理来自提供商的响应。

登出 URL

Foundry 提供前通道和后通道 URL。在 OIDC 提供商处注册哪个登出 URL，取决于所需的登出行为。

OIDC 集成元数据

OIDC 集成元数据是传递给 Foundry 的有关您身份提供商的信息。如果提供元数据发现 URI，Foundry 可以自动获取所需的元数据字段。

或者，您也可以手动提供所需的元数据。此信息包括：

  • 颁发者： 这是 OIDC 提供商的 URL，用于标识该提供商及其位置。Foundry 使用此 URL 来定位 OIDC 发现文档，该文档除其他内容外，还可指定提供商的 OIDC 端点、声明、支持的作用域和公钥。
  • 授权端点： 提供商的授权端点，用于重定向最终用户以获取授权码。
  • 令牌端点： 该提供商的令牌端点，用于将授权码交换为访问令牌和 ID 令牌。
  • JWKS URI： 这是提供商的 JSON Web Key Set (JWKS) 文档的 URL，其中包含用于验证 ID 令牌签名的公钥。
  • 用户信息端点 （如适用）：提供商的用户信息端点，用于检索最终用户的个人资料信息。并非所有提供商都支持此端点，而在支持该端点的提供商中，有些需要使用它。
  • 结束会话端点 （可选）：提供商的结束会话端点，用于将最终用户从提供商的会话中注销。此端点为可选项，并非所有提供商都支持。

客户端凭据

客户端凭据是指 OIDC 提供商颁发给 Foundry 的客户端 ID 和客户端密钥。Foundry 使用这些凭据向提供商进行身份验证，并获取对最终用户资源的访问权限。

获取这些凭据的方式因提供商而异，因此请查阅您所使用提供商的文档。

身份验证方法

选择 Foundry 向令牌端点发出请求时的身份验证方式。选项包括：

  • HTTP 基本身份验证方案。
  • POST：将凭据作为表单值包含在请求中。

作用域

OIDC 作用域决定 ID 令牌和用户信息响应中包含的信息。每个作用域都会返回一组用户属性（即声明）。

必须包含 openid、 email和 profile 作用域。

电子邮件域名

这些是与所配置身份验证提供商相关联的电子邮件域名。这些域名限制了哪些用户可以使用该提供商登录，并决定在登录时是否将该提供商作为选项显示给用户。

支持的主机

受支持的主机用于确保该集成仅显示给使用这些主机登录的用户。

您可以从为您的注册配置的主机中进行选择。

属性映射

将身份提供商中定义的属性映射到它们在 Foundry 中的表示形式。

用户属性

用户属性（也称为“声明”）包括姓名、电子邮件等字段以及其他可用的附加信息。这些属性以属性键到单个或多个值的映射形式发送，例如 email → user@example.com。

为了让 Foundry 获取正确的用户属性值，您必须将身份提供商属性（也称为“声明”）映射到匹配的 Foundry 属性。Foundry 需要以下映射：

  • ID： 默认设置为 sub ，但可以更改为其他稳定的标识符。此值应始终存在于 OIDC 断言中，且具有静态唯一值。请注意，如果您正在设置 Microsoft Entra ID OIDC 提供商，请将此值改为 oid ，因为 Entra 不会在 SCIM 请求中发送 sub 值。
  • 用户名： 默认设置为 preferred_username 。您可以将该值更改为其他人类可读的属性。
  • 电子邮件： 默认设置为 email 。应将其映射到电子邮件属性。
  • 名字： 默认设置为 given_name （默认）。应将其映射到名字属性。
  • 姓氏： 设置为 family_name （默认）。应将其映射到姓氏属性。

您可以在 Foundry 中创建更多映射来设置更多用户属性，方法是选择 添加属性映射。在左侧字段中输入 Foundry 中的属性名称，在右侧字段中输入 JSON Web Token (JWT) 中声明的路径。

对于高级用法，支持使用 JSONPath 语法来指定您的提供商所返回 JWT 中的声明路径。默认情况下，声明值将被提取为单个字符串。附加 [*] 到路径末尾，即可分别提取各个值。示例： groups 可以提取 "[group1, group2]"，而 groups[*] 则会提取 ["group1", "group2"]。

在 Foundry 中，每个映射都有一个切换开关，供您选择当属性在 OIDC 响应中包含多个值时的行为。选项包括：

  • 第一个： 使用收到的第一个值填充该属性。
  • 全部： 使用收到的所有值填充该属性。

您可以通过勾选标有以下字样的复选框来导入用户的提供商组： 从身份提供商导入用户组 并在 JWT 中提供与用户组对应的声明的相应路径。用户登录时,所配置属性的每个值都将镜像为提供商组,并且该用户将被登记为成员。如果此复选框未选中,提供商组成员身份在登录时将不会保持最新。如果您决定保持不选中状态,我们建议启用 SCIM 以更新提供商组成员身份,而无需交互式登录。

高级设置

提示(可选)

prompt 参数用于请求在身份验证期间提示用户执行特定操作。prompt 参数的可能取值包括:

  • none:身份验证无需更多用户输入。
  • login:系统将提示用户输入其凭据以进行身份验证。
  • consent:系统将提示用户授予权限,以便完成身份验证。
  • select_account:系统将提示用户选择其想要用于身份验证的账户。这通常用于用户在同一提供商处拥有多个账户的情况。

您可以选择多个提示。如果未选择任何提示,默认行为取决于提供商。

异步用户管理器

异步用户管理器（AUM）是登录流程中可配置的额外步骤。展开 异步用户管理器 以查看可用的 AUM。

Checkpoints 登录

创建 登录检查点 会在用户登录时将其重定向到一个可配置的提示，在允许登录继续之前要求用户提供理由。要启用登录检查点，请先开启 Checkpoints 登录 AUM，然后按照步骤 创建检查点。
