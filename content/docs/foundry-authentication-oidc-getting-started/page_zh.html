OIDC 概念

以下部分将概述 Foundry 中常见的 OIDC 身份验证概念。

重定向 URL

重定向 URL 需要在 OIDC 提供商处注册。它允许提供商将授权请求的结果传回 Foundry。提供商在发送给最终用户的授权请求中包含该重定向 URL，最终用户在授权过程中会被重定向到该 URL。然后 Foundry 可以处理来自提供商的响应。

登出 URL

Foundry 提供前通道（front-channel）和后通道（back-channel）URL。向 OIDC 提供商注册哪个登出 URL 取决于所需的登出行为。

OIDC 集成元数据

OIDC 集成元数据是传递给 Foundry 的有关您的身份提供商的信息。如果提供了元数据发现 URI，Foundry 可以自动获取所需的元数据字段。

或者，您也可以手动提供所需的元数据。这些信息包括：

  • 颁发者（Issuer）： 这是 OIDC 提供商的 URL，用于标识该提供商及其位置。Foundry 使用此 URL 来定位 OIDC 发现文档，该文档除其他内容外，还可以指定提供商的 OIDC 端点、声明、支持的作用域和公钥。
  • 授权端点： 提供商的授权端点，用于重定向最终用户以获取授权码。
  • 令牌端点： 该提供商的令牌端点，用于将授权码交换为访问令牌和 ID 令牌。
  • JWKS URI： 这是提供商的 JSON Web Key Set (JWKS) 文档的 URL，其中包含用于验证 ID 令牌签名的公钥。
  • 用户信息端点 （如适用）：提供商的用户信息端点，用于检索最终用户的资料信息。并非所有提供商都支持此端点，而某些支持它的提供商可能要求使用此端点。
  • 结束会话端点 （可选）：提供商的结束会话端点，用于将最终用户从提供商的会话中登出。此端点是可选的，并非所有提供商都支持。

客户端凭据

客户端凭据是指 OIDC 提供商向 Foundry 颁发的客户端 ID 和客户端密钥。Foundry 使用这些凭据向提供商进行身份验证，并获取对最终用户资源的访问权限。

获取这些凭据的方式因提供商而异，因此请查阅您的提供商的文档。

身份验证方法

选择 Foundry 如何向令牌端点验证请求。选项包括：

  • HTTP 基本身份验证方案。
  • POST：将凭据作为表单值包含在请求中。

作用域

OIDC 作用域决定 ID 令牌和用户信息响应中包含哪些信息。每个作用域返回一组用户属性（即声明）。

直方图 openid, email日 profile 作用域必须包含在内。

电子邮件域名匹配

电子邮件域名用于决定向用户展示哪些身份提供商集成作为登录选项。当用户在登录界面输入其电子邮件或用户名时，Foundry 会通过检查所有已配置身份提供商的电子邮件域名来确定将显示哪些身份提供商集成。只有与用户电子邮件域名匹配的已配置身份提供商集成才会显示。

电子邮件域名可以是正则表达式，但通常采用简单形式 @example.com，它将被自动转换为 .*@example\.com来查找覆盖缺口；具有该键的节点是您工作流中没有任何监控视图在监视的资源。 .* 。

电子邮件域名的简单形式（@example.com）和正则表达式（.*@example\.com）默认均区分大小写。可以通过在正则表达式开头添加 (?i) 来使电子邮件域名不区分大小写，因此简单形式 @example.com 将是 (?i).*@example\.com or (?i)@example\.com.

支持的域名主机

支持的主机用于确保仅向使用这些主机登录的用户展示该身份验证提供商。

您可以从为您的部署配置的域名主机中进行选择。

属性映射

将身份提供商中定义的属性映射到其在 Foundry 中的表示形式。

用户属性

用户属性（也称为"声明"）包括姓名、电子邮件以及其他可用的附加信息等字段。这些属性以属性键到值或多个值的映射形式发送，例如 email → user@example.com.

为了让 Foundry 获得正确的用户属性值，您必须将身份提供商属性（也称为"声明"）映射到匹配的 Foundry 属性。Foundry 需要以下映射：

  • ID： 设置为 sub 默认情况下，但可以更改为其他稳定标识符。Foundry 使用此值将登录与现有账户进行匹配。该值必须非空、始终存在于 OIDC 断言中，并且格式保持一致（包括大小写）。它必须在账户的整个生命周期内保持稳定，并永久且唯一地标识单个用户。请避免使用可能更改的值（例如电子邮件地址或用户名），因为更改可能会中断账户访问。如果您正在设置 Microsoft Entra ID OIDC 提供商，请将此值设置为 oid 因为 Entra 不会在 SCIM 请求中发送 sub 值。
  • 用户名： 设置为 preferred_username 默认情况下。您可以将该值更改为其他人类可读的属性。
  • 电子邮件： 设置为 email 默认情况下。此属性应映射到电子邮件属性。
  • 名字： 设置为 given_name 默认情况下。此属性应映射到名字属性。
  • 姓氏： 设置为 family_name 默认情况下。此属性应映射到姓氏属性。

您可以通过选择以下选项在 Foundry 中创建其他映射以设置更多用户属性 添加属性映射。在左侧字段中输入 Foundry 中的属性名称，在右侧字段中输入 JSON Web 令牌 (JWT) 中声明的路径。

对于高级用法，支持使用 JSONPath 语法来指定提供商返回的 JWT 中声明的路径。默认情况下，声明值将被提取为单个字符串。在路径末尾附加 [*] 以单独提取各个值。示例： groups 可以提取 "[group1, group2]"创建一个 VPC 端点，而 groups[*] 将提取 ["group1", "group2"].

每个映射在 Foundry 中都有一个开关，您可以选择当属性在 OIDC 响应中具有多个值时的行为。选项包括：

  • 差值： 使用收到的第一个值填充该属性。
  • 图中任何对象上的所有操作均可用。 使用收到的所有值填充该属性。

您可以通过勾选以下复选框来导入用户的提供商组 从身份提供程序导入用户组 并提供 JWT 中与用户组对应的声明路径。当用户登录时，所配置属性的每个值都将被镜像为提供商组，并且该用户将被注册为成员。如果未勾选此复选框，提供商组成员身份将不会在登录时保持更新。如果您决定保持不勾选，我们建议启用 SCIM 以在无需交互式登录的情况下更新提供程序组成员身份。

部分中选择

提示（可选）

prompt 参数用于请求用户在身份验证过程中执行特定操作。prompt 参数的可能值包括：

  • none：身份验证无需进一步的用户输入。
  • login：用户将被提示输入其凭据以进行身份验证。
  • consent：用户将被提示授予同意以完成身份验证。
  • select_account：用户将被提示选择其想要用于身份验证的账户。这通常用于用户在同一提供商处拥有多个账户的情况。

您可以选择多个提示。如果未选择任何提示，默认行为取决于提供商。
