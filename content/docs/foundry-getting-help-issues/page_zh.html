Issues 应用程序

Issues 应用程序是一个支持系统，使用户能够在 Palantir 平台内部获取帮助。

使用 Issues 应用程序，您可以：

  • 提出有关应用程序或平台本身的问题。
  • 以透明的方式对问题、请求和疑问进行分类和解决。
  • 在平台内的任意位置报告资源问题，并查看哪些资源存在未解决的问题。
  • 请求在平台内集成更多数据。

访问 Issues 应用程序

从平台主页：

  1. 在左侧导航栏中，选择 查看全部 位于 Platform Apps 部分的右侧。
  2. 选择 问题 从下方 支持。

搜索问题

在“问题”主页上，您可以筛选并搜索特定问题，以缩小范围至您感兴趣的问题。默认情况下，您将看到 开启 问题概览页面。您也可以选择 已关闭 或 全部 以查看相应的视图。

  1. 侧边栏筛选：左侧的侧边栏提供按以下条件筛选的选项：

    • 优先级
    • 负责人
    • 报告人
    • 提及
    • 标签
    • 截止日期
    • 报告日期
    • 最后更新日期

  2. 搜索问题：此搜索栏允许您搜索所有用户输入的字段，包括 标题 和 评论.

  3. 选择筛选器：选择筛选器选项允许您按与您相关的问题进行筛选（例如，分配给您的问题、由您报告的问题或提及您的问题）。在 Issues 应用中，可以通过多种方式对显示的问题进行排序，包括：

    • 最佳匹配
    • 最近更新（默认）
    • 最久未更新
    • 最近创建
    • 最早创建
    • 最高优先级
    • 最低优先级
    • 最早到期日
    • 最晚到期日

报告问题

要报告问题，请导航至 支持 部分（位于您的工作区侧边栏中），然后选择 报告问题 或 联系支持团队。如需查看现有工单，请选择 查看支持工单。

工单创建完成后，您将被带回至 工单 概览页面，其中列出了最近的工单，这些工单将由相关经办人进行审核。选择工单即可进入该工单的详情页面，并添加评论以提供更多更新信息，或编辑其状态、优先级、截止日期、经办人、咨询类型、（相关）应用程序或标签。否则，请选择 关闭问题 如果问题已得到解决。

创建问题时：

  1. 选择最能准确反映您需求的支持类型。
  1. 请提供尽可能多的信息，包括 标题， 描述， 优先级，以及任何其他详细信息，例如 关联资源 或 附件 （如适用）。然后，选择 创建问题。

受理人只能在问题创建后进行修改，除非所选的 支持类型 未配置初始受理人，在这种情况下，需由报告人负责选择合适的用户或组来处理其问题。

问题权限

问题通常可供您组织中的所有其他用户访问。但是，如果问题与数据集或资源相关，则可以通过数据集或资源所在项目上的 角色 来控制访问权限。您可以根据用户对数据集或资源所拥有的文件系统权限，控制该用户是否可以查看问题。

注意： 在数据集或资源上创建问题并不会授予其他用户访问该数据集或资源的权限。

跨组织协作

对问题的访问权限取决于与其关联的组织。默认情况下，所有问题都与报告人的组织相关联。将问题分配给该组织以外的用户或群组时，更新问题的用户可以将与被分配者关联的某个组织添加到该问题中。只有当问题与被分配者所属的组织（例如，他们自己的组织或被授予访客成员身份的组织）相关联时，被分配者才能查看该问题。重新分配问题时也是如此。

将问题分配给组时,无法严格保证被分配组中的任何单个用户都能查看该问题。这是因为被分配组的单个成员可能无权访问与该问题关联的任何组织。

组与组织的关联并不会授予该组的所有成员访问该组织的权限。这只能通过授予组织的访客成员身份来实现。将组分配给问题时,您应调查组成员的权限,以确认需要将哪些组织(如果有)添加到该问题中,从而确保成员有权回应该问题。

评论标签

查看问题评论时,您可能会看到评论者姓名旁显示的彩色标签。这些标签有助于识别评论者在该问题中的角色或关系,让您更容易了解回复者的身份及其背景。

可用标签

标签描述
经办人为直接或通过群组分配被指派到该问题的用户显示。
报告人为最初创建该问题的用户显示。
自动化显示于系统自动生成的评论。

标签显示规则

  • 如果评论者拥有多个角色，单条评论可以带有多个标签。例如，报告了问题同时又被指派处理该问题的用户将同时看到 报告人 和 负责人 标签。
  • 标签会根据评论者与问题的关系自动确定，无法手动分配或移除。
