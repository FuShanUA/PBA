Helm chart 部署策略与超时

本页面概述了 Helm chart 的部署策略与超时。有关这些机制的工作原理及其配置方法的详细信息，请参见下文。

部署策略

Apollo 为 Helm chart 支持两种部署策略：

  • manageRollout（默认）：Apollo helm-chart-operator 将应用 Kubernetes 资源变更，然后等待所有资源就绪后才使 Plan 成功。如果 Kubernetes 资源变更未能成功应用，或资源未能在资源就绪超时时间内就绪（例如，某个 deployment 的所有 pod 均未就绪），helm-chart-operator 将回滚变更并使 Plan 失败。
    • 我们建议在生产环境中使用此部署策略，因为它会尽快回滚影响服务可用性的不良变更。
  • applyChangesNoWait：Apollo helm-chart-operator 将应用 Kubernetes 资源更改，然后立即使 Plan 成功，而不考虑所创建资源的“就绪”状态。例如，使用此策略时，如果 pod 未在超时时间内就绪，helm-chart-operator 将不会使 Plan 失败。如果 Kubernetes 资源更改应用失败，helm-chart-operator 仍会回滚更改并使 Plan 失败。
    • 在迭代使新服务正常运行的过程中，此策略可能很有用，此时服务的可用性尚不是关注重点。只要 Kubernetes 资源成功应用，helm-chart-operator 就会将其保留在原处，从而更便于调试更改失败的原因。
    • 请注意，Helm install 和 upgrade 有五分钟的超时时间，因此如果长时间运行的 Helm 钩子运行时间超过此限制，仍可能导致 Plan 超时。

你可以通过两种方式配置这些策略：

  • 在全局范围内，覆盖 helm-chart-operator 配置中的 capabilities.defaultRolloutStrategy 字段。
  • 针对每个 chart，在 Helm chart 的 manifest 扩展中设置 rollout-strategy。例如，你可以设置 rollout-strategy: applyChangesNoWait。使用 Apollo CLI，可在初始化新的 Helm chart Product 时通过 --rollout-strategy 标志进行设置。

在首次迭代新环境时，您可能会发现全局覆盖默认发布策略很有用。但是，我们建议在进入生产环境之前恢复为默认的托管发布策略。之后，可根据需要按 chart 进行覆盖。

托管发布期间的资源就绪超时

资源就绪超时是指在发布策略为托管时，helm-chart-operator 在将资源变更应用到 Kubernetes 后等待资源就绪的时间长度。此超时与 Helm 应用变更（包括任何 Helm hooks）所需的时间是不同的。Helm 操作有其自身的 5 分钟超时。

您可以根据 Plan 类型（安装或升级），使用以下覆盖项为 helm-chart-operator 实体配置资源就绪的默认超时：

  • 对于安装 Plan，使用 capabilities.scopedResourceReadinessTimeouts.install 覆盖项来指定默认的资源就绪超时。
  • 对于升级 Plan，使用 capabilities.scopedResourceReadinessTimeouts.upgrade 在版本变更或配置 Plan 上指定默认的资源就绪超时。

您还可以在单个 Helm chart 产品的产品清单扩展中设置 resource-readiness-timeout,以覆盖默认的资源就绪超时。例如,resource-readiness-timeout: 1h。设置后，该设置将始终覆盖 helm-chart-operator 自身的配置。使用 Apollo CLI 时，也可以在初始化新的 Helm chart 产品时通过 --resource-readiness-timeout 标志进行设置。

镜像预拉取

Apollo 的 helm-chart-operator 会在应用 Helm chart 之前预拉取容器镜像。这有助于防止因 Pod 启动时镜像拉取缓慢而导致的服务停机。您可以在 helm-chart-operator 的实体配置中，通过在 capabilities.imagePrePullEnsurer 下设置以下字段来配置预拉取机制：

  • enabled:用于控制预拉取是否处于启用状态的布尔值。
  • timeout:helm-chart-operator 在使计划失败之前尝试预拉取镜像的最长持续时间。

默认情况下，预拉取功能处于启用状态，超时时间为 15 分钟。预拉取机制的配置示例如下：

capabilities:
  imagePrePullEnsurer:
    enabled: true
    timeout: 15m

您还可以通过向 Helm chart 清单添加 image-pre-pull-config 扩展并设置 image-pre-pull-config.timeout 字段，来按产品覆盖预拉取超时时间。按产品设置的超时时间必须至少为 1 分钟，最多为 90 分钟。这种灵活性使您能够根据每个产品的特定需求调整预拉取行为。

以下是用于镜像预拉取的 Helm 扩展示例：

  image-pre-pull-config:
    timeout: "3m"
