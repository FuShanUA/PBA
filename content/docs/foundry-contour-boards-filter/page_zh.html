筛选数据

您可以使用 Contour 的许多可视化看板来筛选和可视化数据。本文档探讨如何使用直方图、筛选器和图表看板来实现这一点。高级用户可能需要查看 Contour 的 表达式语言 以获取更强大的筛选选项。本页面上的截图使用的是开源航空数据。

在 Foundry 中，分析操作默认应用于整列，以便于分析大型数据集。如果您只想对较小范围的行进行分析（类似于在 Excel 中选择特定的单元格区域），请先筛选出所需的行，然后再应用这些操作。

调整筛选器

当有人为特定筛选器创建新的分析时（例如 carrier_code = DL），其他人可以通过将筛选器更改为符合其用例（例如 carrier_code = UA）或完全移除筛选器来执行全局分析，从而轻松复制他们的分析。

字符串筛选器中的通配符

某些字符串筛选器类型支持使用 ? 和 * 作为通配符。 ? 表示恰好一个任意字符，而 * 表示任意数量的任意字符序列（该数量可以为 0）。

支持使用通配符的筛选器如下：

  • contains
  • contains (with wildcards)
  • is (with wildcards)

尽管命名不够直观，但两者 contains 和 contains (with wildcards) 都支持通配符。这两个过滤器之间的区别在于， contains 允许使用两个正斜杠字符（\\）来转义通配符，而 contains (with wildcards) 不允许转义通配符。例如，一个 contains 过滤器，其值为 apples\\*pears 将匹配字符串 apples*pears 但不匹配字符串 apples_pears。相反，无法构造一个匹配 apples*pears 但不匹配 apples_pears Automate contains (with wildcards) 的过滤器，因为 contains (with wildcards) 过滤器始终会将 * 视为通配符。

由于这两种过滤器在行为上的差异 contains 和 contains (with wildcards) 可能并不明显，因此依赖此行为的 Contour 分析中的过滤逻辑可能难以理解和维护。如果您需要表达复杂的字符串匹配条件，我们建议使用 matches （正则表达式）过滤器，而不是使用带通配符转义的 contains 过滤器。
