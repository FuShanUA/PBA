检索上下文

AIP Chatbot 可以配置检索上下文。检索上下文会确定性地随 每一个 新的用户消息一起运行，检索到的信息将传递给 LLM。

您可以为聊天机器人配置任意数量的以下检索上下文类型：

  • 本体论上下文
  • 文档上下文
  • 函数支撑的上下文

本体论上下文

本体论上下文为您的聊天机器人提供来自本体论中对象的上下文。您可以提供一组固定的 N 对象，或执行语义搜索以识别 K 与用户查询最相关的对象，前提是您的对象类型具有向量嵌入属性。

配置本体论上下文时，您可以选择起始对象集为 静态输入（包含完整对象类型）或 变量输入（可以由作为应用状态变量传入的筛选对象集组成）。

您还可以配置对象属性列表，以确定为每个检索到的对象打印哪些属性并作为上下文传递给 LLM。默认情况下，所有属性都会被选中，但不包括无法打印的属性（例如媒体引用或向量嵌入）。

此外，您可以通过为对象集输出和引用变量输出配置变量，将本体论上下文与应用状态集成。有关更多信息，请参阅 应用状态 和 引用变量更新.

文档上下文

文档上下文允许用户在发送给 LLM 的每条消息中包含文档中的相关文本。在 AIP Chatbot 的配置中，可以选择并添加文档，其方式与在 AIP Threads.

对话中添加文档的方式相同。

  1. 提供文档上下文有两种模式： 完整文档文本模式：
  2. 此模式将文档的全部文本内容提供给 LLM 作为上下文。 相关片段模式： K 此模式对文档执行语义搜索，将最相关的片段返回给 LLM 作为上下文。
测试版

相关片段模式目前处于 测试版 开发阶段，您的环境中可能无法使用。功能在积极开发过程中可能会发生变化。请联系您的 Palantir 代表或 Palantir Support 以申请访问此功能。

函数支撑的上下文

函数支撑的上下文使用户能够对每个查询执行自己的检索。当通过本体论上下文或文档上下文提供的开箱即用检索方法无法满足特定用例时，这是理想的选择。例如，如果用户想要组合不同的检索方法（如关键词搜索和语义搜索），则需要编写一个函数来实现，因为 Chatbot Studio 目前不支持此功能。

您可以在 TypeScript v1 中编写这些函数，位置在 代码仓库。为此，请导航到 TypeScript v1 仓库并导入 AipAgentsContextRetrieval 函数接口。TypeScript v2 仓库不支持函数接口。

然后，编写一个满足如下所示接口的函数。该函数必须具有 messages 作为唯一必需的输入，以满足契约要求。

@AipAgentsContextRetrieval()
public exampleRetrievalFunction(messages: MessageList): RetrievedContext {
    let combinedText: string[] = [];
    messages.forEach((message) => {

    return {

}

检索函数必须输出一个 retrievedPrompt 字符串，AIP Chatbot 会将其粘贴到 LLM 系统提示中以回答用户查询。

发布函数后，请在 Chatbot Studio 中的 函数支撑的上下文 面板下选择 检索上下文 以选择用于检索的函数。

检索函数中的应用变量

检索函数还可以将聊天机器人的 应用变量 的值作为输入。要进行配置，请在函数定义中添加可选参数。目前仅支持字符串和对象集应用变量，因此函数输入必须是这些类型之一。

使用对象类型的 API 名称。该名称可在 Ontology Manager 中找到。然后,您可以配置聊天机器人上的应用变量与函数输入之间的映射,使其匹配各自的类型。

要创建应用变量,请导航至 应用变量 面板(位于 Chatbot Studio 中)。

在 AIP Logic 中编写检索函数

用户很快就能在 AIP Logic 中编写这些函数。AIP Logic 提供了一个易于上手的界面,用于开发无代码的 LLM 驱动函数。在此期间,如需使用检索函数,我们建议编写一个满足该接口的 TypeScript 函数,并在底层调用 Logic 函数。

自定义引用

如果 LLM 以特定的 XML 格式返回引用,AIP Chatbot 界面将渲染引用气泡。借助函数支持的上下文,用户可以让其函数返回一个字符串,提示 LLM 以指定格式编写引用,从而渲染这些引用。请参阅 引用格式 以查看提供的格式列表,以及 引用变量更新 以了解如何在每次选择对象引用时更新 Workshop 变量。

在上面的示例中,该函数接受一组以本体论对象形式表示的文档块。然后,它对这些对象进行语义搜索,并按照上文提到的引用样式格式化返回最相关的五个结果。
