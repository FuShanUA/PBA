与外部系统交互

代码工作区允许您使用 Python 与存在于 Foundry 平台之外的外部系统进行交互，方法是使用 源。

源允许您存储和访问机密信息、同时配置多个出站策略、监控其在整个平台代码中的使用情况、管理数据导出控制等。由于可以将 Foundry 数据从代码工作区传出到外部系统，因此您必须考虑一些 额外的安全注意事项 （在将源与 Foundry 数据结合使用时）。

源已取代 网络出口策略 作为交互式工作流和发布应用程序过程中与外部系统交互的首选方法，但不适用于 已启用 CBAC 的环境。 对于从代码工作区发布的转换，尚不支持源。

设置源

要在 Jupyter 或 RStudio® 工作区中与外部系统交互，请先在以下位置创建源： 数据连接 应用程序，提供 API 名称，并切换该设置以允许将源导入代码仓库。将源添加到您的工作区并重启一次工作区后，您就可以与源交互，使用 Palantir 的 external-systems Python 库。

Jupyter 工作区中的源

要在 Jupyter 工作区中使用源，请确保 containers-external-systems-python 库已安装。然后使用外部系统侧面板中的代码片段与源交互，从以下代码开始：

Copied!
1from containers_external_systems_python import get_source
2
3my_source = get_source("SourceApiName")

要在 Jupyter 工作区中从源获取凭据，请使用以下方法：

Copied!
1some_secret: str = my_source.get_secret("secretName")

RStudio® 工作区中的源

要在 RStudio® 工作区中使用某个源，请确保 containers-external-systems-python 库已随 reticulate 和 python一同安装。随后在 R 中使用提供的代码片段（使用经 reticulate 改编的 Python 语法），例如如下所示：

Copied!
1library(reticulate)
2
3source <- import("containers_external_systems_python")$get_source("SourceApiName")
4https_connection <- source$get_https_connection()
5client <- https_connection$get_client()
6response <- client$get(https_connection$url, timeout=10)
7
8response$ok

要从 RStudio® 工作区中的源检索凭据，请使用以下方法：

Copied!
1some_secret <- source$get_secret("secretName)

已发布应用程序中的源

在发布应用程序时（例如 Streamlit）需要源时，您必须将该源包含在应用程序的“advanced”配置设置中。用户必须有权访问所有已包含的源，否则将无法打开该应用程序。

源与工作区安全

导入源 （在启用导出的情况下） 会对您工作区的安全性强制执行额外的检查。最重要的是， 如果数据集带有未列在源的可导出标记列表中的标记，则该数据集无法与该源在同一工作区中使用。

例如，如果您有一个用于电子健康记录系统的数据源，名为 Hospital A，您可能会被允许使用它来导出带有标记 Hospital A Patient Data的数据。但假设您的工作区中还加载了一个带有标记 Hospital B Patient Data 的数据集：如果您也在使用 Hospital A 数据源，在没有检查的情况下，您将能够把不允许的 Hospital B Patient Data 导出到 Hospital A 外部系统。代码工作区会在 整个工作区级别上强制执行这些检查，也称为 工作区血缘，在工作区启动期间。也就是说，无法在工作区中同时访问不兼容的源和数据集。

如果您的工作区中已加载了一个带有强制执行的可导出标记列表的源，然后又添加了一个带有不可导出标记的数据集，工作区将阻止您访问该数据集；例如， Dataset.get() 将抛出错误。

如果您初始化或重启的工作区中包含不兼容的源和数据集，系统将提示您移除其中一个源或数据集，直到冲突解决为止。随后，您必须在不使用检查点的情况下重启工作区，以解决此冲突。
