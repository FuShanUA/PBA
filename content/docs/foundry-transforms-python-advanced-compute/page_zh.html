高级单节点计算选项

以下集成的基本原理是，您可以访问 表格形式的 Foundry 数据集 ，支持多种格式，例如 pandas DataFrame、Arrow Table、Polars DataFrame，甚至原始的 Parquet 或 CSV 文件。这一点也显示在 转换概览中。将表从内存保存到 Foundry 时，我们可以按读取时所用的任意一种格式将其传入。

请参阅 计算引擎选择 ，以在单节点计算引擎（pandas 和 Polars）与分布式计算（Spark）之间做出选择。本页面上的集成针对特定用例扩展了单节点功能。

Pandas 有时可以读取 Spark 无法处理的 Parquet 文件。例如，使用某些时间戳格式（如 INT64 (TIMESTAMP(NANOS,false)) ）的 Parquet 文件会导致 Spark 失败，并出现 org.apache.spark.sql.AnalysisException: Illegal Parquet type。作为变通方法，可以直接使用 pandas 读取该 Parquet 文件：

import pandas as pd

df = pd.read_parquet(my_input.path())

使用 Apache DataFusion

有时，省去数据反序列化步骤、直接将底层的原始数据集文件传递给我们的计算引擎会更容易。我们可以获取文件在磁盘上的路径，这些文件会通过调用 my_input.path()按需下载。在将原始文件写回 Foundry 时，有两点限制需要牢记：

  • 通过此 API 只能将 Parquet 文件存储到 Foundry 数据集中。
  • 文件必须放置在以下值所指定的文件夹中： my_output.path_for_write_table。

当这两个条件都得到满足时，我们就可以调用 write_table 并传入该文件夹的路径，如下所示：

Copied!
1
my_output.write_table(my_output.path_for_write_table)

import datafusion
from datafusion import lit
from datafusion.functions import col, starts_with
from transforms.api import transform, Output, Input


@transform.using(my_input=Input('my-input'), my_output=Output('my-output'))
def my_datafusion_transform(my_input, my_output):
    ctx = datafusion.SessionContext()
    table = ctx.read_parquet(my_input.path())
    my_output.write_table(
        table
        .filter(starts_with(col("name"), lit("John")))
        .to_arrow_table()
    )

使用 cuDF

您也可以通过使用 pandas.DataFrame来实现集成。以下代码片段展示了一个使用 cuDF ↗ 的轻量级转换实例。这实质上会尽可能在 GPU 上以高度并行化的方式运行 pandas 代码。

@transform.using(
    my_input=Input('my-input'),
    my_output=Output('my-output')
).with_resources(
    cpu_cores=4,
    memory_gb=32,
    gpu_type='NVIDIA_T4'
)
def my_cudf_transform(my_input, my_output):
    import cudf  # Only import CUDF at runtime, not during CI
    df = cudf.from_pandas(my_input.pandas()[['name']])
    filtered_df = df[df['name'].str.startswith('John')]
    sorted_df = filtered_df.sort_values(by='name')
    my_output.write_table(sorted_df)

上述代码片段假设您的 Foundry 注册环境配备了 NVIDIA T4 GPU，并且该 GPU 可通过 资源队列供您的项目使用。

借助 cuDF 实现 GPU 加速的 Polars

您的 Foundry 注册环境必须配备受支持的 NVIDIA GPU，并且该 GPU 必须可通过 资源队列 供您的项目使用，才能使用此功能。请参阅 GPU 预配 以查看可用 GPU 类型的列表。

您可以在 GPU 上加速 Polars lazy API 查询，方法是使用 cudf-polars ↗，这是一款基于 GPU 的 Polars 执行引擎。通过将 pl.GPUEngine() 传递给 collect() 调用，您只需进行极少的代码更改，即可在 GPU 上运行现有的 Polars 惰性 API 查询。有关支持的操作和性能特征的详细信息，请参阅 Polars GPU 支持文档 ↗。

GPU 加速的收集操作目前仅支持 collect()，它会将结果完全物化在内存中。诸如 sink_parquet() 之类的流式操作目前尚不支持。请确保您的输出数据能够放入可用的 GPU 内存和系统内存中。

设置

要在 Polars 惰性 API 中使用 GPU 加速，请将 cudf-polars 包添加到 run 依赖项中，这些依赖项位于您的 conda_recipe/meta.yaml 文件中。有关添加包的详细信息，请参阅 Python 库文档。

import polars as pl
from transforms.api import transform, Output, Input

@transform.using(
    output=Output("/Users/jsmith/output"),
    my_input=Input("/Users/jsmith/input"),
).with_resources(
    gpu_type="NVIDIA_T4",
    memory_gb=32,
)
def compute(output, my_input):
    lf = my_input.polars(lazy=True)

    result = (
        lf.with_columns(
            (pl.col("a") * pl.col("b")).alias("product"),
            (pl.col("a").pow(2) + pl.col("b").pow(2)).sqrt().alias("norm"),
        )
        .group_by("category")
        .agg(
            pl.col("product").sum().alias("total_product"),
            pl.col("norm").mean().alias("mean_norm"),
            pl.len().alias("n"),
        )
        .sort("total_product", descending=True)
    )

    output.write_table(result, engine="gpu")

GPU 引擎仅支持部分 Polars 操作。如需完整列表，请参阅 Polars GPU 支持文档 ↗。默认情况下，不受支持的查询会静默回退到 CPU 引擎。若要改为抛出错误，请使用 raise_on_fail=True 手动收集，并将生成的 DataFrame 传递给 write_table()：

df = lf.collect(engine=pl.GPUEngine(raise_on_fail=True))
