第一部分：丰富传感器读数数据

将传感器读数数据集添加到新管道后，您需要添加一些元数据。

1. 应用转换以重新格式化传感器读数

从传感器读数数据集中，按照以下步骤应用转换。

逆透视数据以合并序列值

由于此数据集在不同列中包含时间序列数据，您必须使用逆透视转换将其合并到一个值列中，以便数据能够符合时间序列同步所需的模式，如下所示：

  • 序列 ID： string | TSP 所引用的时间戳和值对集合的序列 ID，必须与 TSP 的序列 ID 匹配。
  • 时间戳： timestamp or long | 测量该数量的时间。
  • 值： integer, float, double, string | 该数量在测量时刻的值。字符串类型表示分类时间序列；每个分类时间序列最多可以有 10,000 个唯一变体。

下面显示的逆透视转换将两者的值放入同一个 altitude 和 speed 列中。这些原始列名将输出到新的 series_value 列，以便父根对象能够识别每个传感器所代表的内容（ series_name ）。altitude，例如）来引用它们。

转换后的数据集应预览显示新的 series_value 和 series_id 列：

连接主键以创建序列 ID

现在，您可以使用连接字符串转换来创建序列 ID（相关时间序列值的标识符）。使用该转换将 series_name （每个传感器所代表的内容）与每个对象的主键组合在一起。

speed_021fcdbsd...speed114.002023-01-11T23...021fcdbsd...YX4472...

移除空值

应用筛选转换以移除任何包含 null 值的行，这些值不会用于我们的时间序列计算。

2. 向数据集添加单位

某些传感器读数数据集确实包含单位；在这些情况下，您可以跳过此步骤，直接进行 创建传感器对象类型支撑数据集.

手动上传单位数据集

由于原始示例传感器读数数据集不包含单位，您必须添加一个生成的数据集来将单位映射到序列名称。从 Pipeline Builder 图表的左上角，选择 添加数据，然后选择 手动输入数据。创建一个名为 series_name 的列，以及另一个名为 units的列。如有必要，您可以对内部插值重复此步骤（尽管我们的示例中并不需要）。

内部插值 用于启用 的流可在 以推断相邻数据点之间的序列值。内部插值列将为本体论提供一个属性，用于保存每个传感器对象的插值设置。Quiver 在可视化时间序列数据时将依赖该属性。查看 我们关于插值的文档 的文档以获取更多信息。

创建一个连接（join）以合并 units 和 sensor 数据集

使用连接面板（join board）创建一个连接，合并来自 units 和 sensor 数据集的数据。请确保设置了以下配置：

  • 添加一个 左连接 并按以下字段匹配 series_name.
  • 自动从左侧数据集中选择列。
  • 仅选择 units 列作为右侧列。

第二部分：创建传感器对象类型支撑数据集

现在，您可以创建传感器对象类型了。请按照以下步骤对连接输出应用转换，以创建一个最终支撑传感器对象类型的数据集。

1. 删除重复项以为每个传感器创建一行

一个传感器对象表示且仅表示一组相关的时间序列数据（例如某次特定航班的 altitude ）。由于每组相关时间序列数据都由一个 flight_sensor_series_id唯一标识，因此可以假设每个唯一的航班传感器序列 ID 仅保留一行即对应一个传感器对象。对生成的 flight_sensor_series_id使用删除重复项转换，您可以为每个传感器对象创建一行。其余的序列数据（时间戳和值）将在后续步骤中移除。

数据集应如下所示：

flight_sensor_series_idseries_nameseries_valuetimestampflight_idflight_ titleunits
altitude_021fcdbsd...altitude1342023-01-11T23...021fcdbsd...YX4472...ft
speed_021fcdbsd...speed114.002023-01-11T23...021fcdbsd...YX4472...mph

2. 对序列 ID 进行哈希处理以创建主键

由于每个传感器对象必须可唯一标识，因此您必须使用 hash sha256 转换为每个对象创建主键。您可以复用 series_id 因为它在所有这些传感器对象中应该是唯一的，但进行哈希处理更能直接表明该 series_id 仅应用作唯一标识符。

数据集预览应如下所示：

unique_sensor_flight_idflight_sensor_series_idseries_nameseries_valuetimestampflight_idflight_ titleunits
2492af5a2fe62c78ad8d...altitude_021fcdbsd...altitude134.002023-01-11T23...021fcdbsd...YX4472...ft
ec4808668f4b48cc5104...altitude_011794756...altitude0.00002023-01-22T17...011794756...UA1878...ft

3. 连接字符串以为对象创建标题属性

现在，您应使用连接字符串转换为我们的传感器对象创建人类可读的标题属性。尽管传感器对象将嵌入到另一个 Flight 对象的对象视图中，但为传感器对象创建专用名称将使用户在平台中构建和分析传感器时更加直观。

数据集预览应如下所示：

YX4472 的高度传感器...2492af5a2fe62c78ad8d...altitude_021fcdbsd...altitude134.002023-01-11T23...021fcdbsd...YX4472...ft
UA1878 的高度传感器...ec4808668f4b48cc5104...altitude_011794756...altitude0.00002023-01-22T17...011794756...UA1878...ft

4. 删除不必要的列

由于我们的传感器对象仅代表传感器本身，您可以移除剩余的 series_value 和 timestamp 列（使用删除列转换）。这些列将体现在时间序列属性上，并根据 flight_sensor_series 值在本体论中与传感器关联。此外，您还将删除 flight_title 列，因为我们的传感器对象类型不需要它。

您将保留 flight_id 以便传感器对象（Flight Sensors）能够关联到其根对象（Flights).

数据集预览应如下所示：

UA1878 的高度传感器...ec4808668f4b48cc5104...altitude_011794756...altitude011794756...ft

5. 添加数据集输出以支撑传感器对象类型

选择 Add output 然后选择 Add dataset。生成的数据集应与转换中创建的架构保持一致。任何较新的更改可能需要更新生成数据集中的架构。

第三部分：创建传感器对象类型时间序列同步

1. 将传感器读数转换为时间序列同步格式

使用选择列转换，您将只保留时间序列同步所需的列： series_id, timestamp日 value。请将此转换应用于第二部分开始时所用的第一部分输出，而不是第二部分的输出，因为后者已不再包含 timestamp 和 series_value 列。支撑数据集将保存所有传感器的值，无论它们测量的是什么（包括 altitude 和 speed，例如）。您可以使用生成的 flight_sensor_series_id 选项卡中为 series_id 作为特定一组传感器数据的唯一标识符。例如，从 LGA 飞往 LAX 的航班 A445B 将拥有一个关联的传感器对象，用于 speed 该对象将保存该航班的速度传感器数据。同样，它还将拥有一个关联的传感器对象，用于 altitude.

数据集输出应预览如下：

flight_sensor_series_idseries_valuetimestamp
altitude_021fcdbsd...134.002023-01-11T23...
altitude_011794756...0.00002023-01-22T17...

2. 配置时间序列同步

现在，创建一个 时间序列同步 通过选择 将 从屏幕右侧的管道输出部分。然后，选择 时间序列同步。填写新时间序列同步所需的数据，并注意以下事项：

  • 选择 flight_sensor_series_id 列，用于 序列 ID field.
  • 添加已创建的 timestamp 列，在 时间 field.
  • 将 series_value 导出到 标题可将排序方式切换为 field.

现在， 保存并构建 管道。输出将在与管道相同的文件夹中创建。

3. 使用时间序列同步向传感器对象类型添加属性

现在您已创建了一个带有时间序列同步的管道，可以使用该同步向传感器对象类型添加时间序列属性了。请继续阅读我们关于 向传感器对象类型添加时间序列属性 的文档以获取更多指导。
