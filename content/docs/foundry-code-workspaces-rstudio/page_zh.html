Shiny®

借助 Code Workspaces，您可以创建 Shiny® 应用程序，并直接在 RStudio® UI 中进行预览。

默认情况下，RStudio® 会在主文件夹（/home/user）中生成 Shiny® 应用程序，但 Foundry 要求应用程序位于 git 仓库中 /home/user/repo 以便在会话之间持久保存并发布。

在 Code Workspaces 中，选择 发布应用程序，在您的 文件和项目 中为新应用程序选择一个位置，并输入要在其中自动创建新 Shiny® app.R 文件的目录名称（相对于仓库根目录） /home/user/repo。此字段可以留空，以在仓库根目录下创建应用程序。默认情况下，应用程序设置将与 RStudio® 工作区设置一致，配置高级设置为可选操作。

已发布的 Shiny 应用程序受 30 秒超时限制，即 Shiny 服务器必须在执行 Shiny 应用程序文件后 30 秒内启动。否则，您的 Shiny 应用程序将无法启动。

选择 发布并同步 以注册您的新 Shiny® 应用程序，并将代码同步到支撑代码仓库。CI 检查和发布完成后，您可以在 Applications 面板中选择关联以查看已发布的应用程序。

要在本地针对 Shiny® 应用程序进行开发：

  1. 打开 app.R 在 RStudio® 中。
  2. 选择 Run App。应用程序的预览将显示在新窗口中。

Markdown 报告

在 RStudio® 工作区中编写的 R Markdown 或 Quarto 文件可以作为报告与其他 Palantir 平台用户共享。报告是通过转换从 Markdown 文件构建的数据集，该转换包含使用 Quarto ↗.

报告通过转换构建，因此可以配置为使用 计划任务根据 Markdown 文件的最新更改自动更新。这可确保您的分析和可视化保持最新，并通过与 Palantir 平台其余部分集成的可重现、可自定义的工作流进行构建。

从 RStudio® 工作区发布报告

可以按照以下步骤从 RStudio® 工作区发布 Markdown 报告：

  1. 创建您希望用于生成报告的 Markdown 文件（.Rmd or .qmd）。该 Markdown 文件可以读取已通过 数据侧面板.
  2. 打开 应用程序 侧面板，然后选择 报告 tab.
  3. 选择 将 以打开报告配置对话框。
  4. 提供名称和位置；这将决定包含该报告的数据集的保存位置。
  5. 选择用于生成报告的 Markdown 文件。如果您的 Markdown 读取 Foundry 数据集，请将这些数据集添加为报告输入。选择 自动配置输入和输出 以自动解析您的 Markdown 文件，并使用检测到的任何数据集填充表单。
  6. 选择 创建。这将在指定位置创建一个数据集。随后，用于生成报告的转换将开始运行，这可能需要几分钟才能完成。
  7. 报告生成完成后，在 应用程序 侧面板中选择报告名称，以在新标签页中打开该报告。此链接可与其他用户共享。

要编辑或删除现有报告，请选择 ... （位于报告卡片右侧）。这将打开一个菜单，其中包含编辑或删除报告的选项，以及复制报告链接的选项。

查看以前的报告版本

报告支持完整的版本历史记录。要查看报告的以前版本，请在 应用程序 侧面板中展开报告卡片，或在新标签页中查看报告时使用页面顶部的版本选择器。

选择某个报告版本将更新用于共享该报告的链接，使您能够共享报告的特定历史版本；即使底层 Markdown 被修改，该版本也不会更新。

默认情况下将选择报告的最新版本，因此报告的读者会自动收到最新的更改。

RStudio® 中的托管 conda 环境

使用 托管环境，可以在 RStudio® 工作区、Shiny 应用程序、转换和模型输出之间一致地还原 RStudio® conda 环境。托管环境在 Code Workspace 工作流中保持一致，无需在每次重启工作区、启动 Shiny 应用程序或运行 RStudio® 转换时重新运行相同的 renv::install 命令。

托管环境还包括通过 Maestro 进行的 CRAN 库管理。Maestro 是一个 Foundry 库管理工具，可与 conda 和 CRAN 集成，以处理库安装并维护托管环境。新安装的 CRAN 库将被记录在您的环境文件中，并在相同的工作流之间一致地还原，从而提高环境的可重现性。请参阅 开始使用 以下章节以启用托管的 conda 和 CRAN 环境。

要将库安装命令转换为 Maestro，请参阅以下关于 或 or CRAN的说明。使用托管环境时，您工作环境中已安装的库将通过以下文件进行跟踪，使环境能够在各工作流之间还原到其原始状态：

  1. /home/user/repo/.envs/maestro/meta.yaml：被称为环境 清单，其中包含一组 请求的 适用于您环境的库和版本。
  2. /home/user/repo/.envs/maestro/hawk.lock：被称为环境 "锁定文件"，其中包含一组 "已解析" 适用于您环境的库和版本，根据清单中指定的约束解析而来。该 hawk.lock 文件取代 conda.lock，该文件已被弃用。

当您在 conda 环境中同步任何新代码时，上述文件也将被同步。当您开始下一次会话时，还原的代码将包括 maestro 文件，并且您的环境将被重新创建。

我们不建议修改 hawk.lock 锁定文件。相反，请依靠安装命令为您更新这些文件。除非出现 git 冲突，否则您也无需修改 meta.yaml 文件；当以交互方式安装库时，该文件会自动更新。如果您确实修改了这些文件，则可能导致还原过时的 conda 环境或环境构建失败。

您的托管环境安装在您的 /home/user/envs/default 文件夹。此环境将在以下任何事件之前被还原：

  • RStudio® 工作区的启动
  • 从您的工作区生成的 Shiny 应用程序的启动
  • 从您的工作区生成的 RStudio® 转换的运行
  • 的渲染 Markdown 报告
