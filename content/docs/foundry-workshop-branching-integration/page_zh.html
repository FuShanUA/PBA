对 Workshop 模块进行分支操作

Workshop 与全局分支（Global Branching）集成，让您能够安全且相互隔离地开发模块及其配置。本页介绍如何在分支上处理 Workshop 模块，包括向分支添加资源、资源保护和审批，以及变基（rebase）和冲突解决。

有关全局分支概念和工作流的一般信息，请参阅 全局分支文档。

将 Workshop 模块添加到分支

要将 Workshop 模块添加到分支，请使用分支选择器切换到该分支，打开该模块，然后保存所做的更改。此时，该模块已成为分支上的一个资源。

如果您的 Workshop 模块包含不支持全局分支的非 Workshop 元素（例如 Quiver 仪表板），则这些元素在分支上将不可修改。

资源保护

在 main 分支上时，受保护的 Workshop 模块会显示 保存到新分支 选项，而不是 保存并发布，这要求所有更改都必须在分支上进行，而不是直接提交到 main。

选择 保存到新分支 以打开新建分支对话框。为该分支命名，并为其选择一个本体论。

当您准备好将更改合并到 main， 创建提案。

审批流程

创建提案后，系统会通知指定的评审人员审阅更改。导航到 Workshop 模块的分支版本后，评审人员将被引导至 Workshop 中的 变更日志 选项卡。

在 变更日志 选项卡中，评审人员可以查看对模块所做的更改。随后，评审人员若要批准或拒绝该更改，可选择相应的 批准 或 拒绝 按钮，该按钮位于左侧面板的 审查提议的更改 部分。

变基与冲突解决

Workshop 变基功能使多个构建者能够同时编辑同一个模块，而无需担心覆盖彼此的更改。

在将一个分支上的 Workshop 更改合并到 main，您必须进行变基，如果 main 在模块保存到分支之后发生了更改。

变基用户界面使用 变更日志面板 来展示模块中所做的更改。

开始变基

如果在合并前需要进行变基， 变更日志 面板会显示一个可视化通知圆点。选择该面板即可显示开始变基的选项。

变基前保存

变基不会保留未保存的 Workshop 编辑内容。请在开始变基之前将您的更改保存到分支；任何尚未保存的进行中编辑内容都将丢失。

变基会将分支上所做的更改应用到最新的 main 模块版本。请手动解决所有合并冲突以继续。

解决合并冲突

当一项更改在 main 和分支上均被编辑时，会被标记为合并冲突。

Workshop 会自动合并不重叠的更改。只有当同一个小部件、变量、部分或布局位置在 main 和您的分支上均被编辑时，该更改才会被标记为合并冲突；对于这些更改，您必须按照下文所述手动选择一个版本。

合并冲突的常见示例包括：

  • 一个小部件或变量在 main 和您的分支上均被修改。
  • 一个部分在 main 上被删除，但在该分支上进行了编辑。
  • 一个小部件从位置 A 到 B 在 main 并从 A 到 C 在您的分支上。

要解决合并冲突，请在三种状态之间切换，以实时测试每个选项对模块的影响：

  • 主分支： 该修改在 main.
  • 分支： 该修改在分支上的显示形式。
  • 修改： 你在变基期间对组件所做的编辑，有助于将来自 main 的更改与你的分支合并。

完成变基

当你对模块的外观满意并已解决所有合并冲突后，保存模块即可完成变基。

完成此操作后，您就可以安全地将您分支中的 Workshop 更改合并到 main。
