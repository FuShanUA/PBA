训练模型并与模型交互

与模型交互仅在 JupyterLab® 代码工作区中受支持.

代码工作区允许您训练和发布模型，也可以导入模型以与之前发布的模型进行交互。

代码工作区要求您为工作区中引用的每个 Foundry 模型别名 创建一个 模型资产 。模型别名充当对特定模型的引用，使您能够与模型交互以发布新版本或下载已保存的模型文件。

在 链接进行访问。 标签页中注册模型时，代码工作区会在位于工作区的 /home/user/repo/.foundry 文件夹下的隐藏文件中，创建所选模型别名与 Foundry 模型唯一标识符之间的映射。

要了解如何从 Jupyter® 笔记本发布模型，请查阅 模型集成文档.

将模型添加到工作区

可以在 链接进行访问。 选项将其选中。

中创建新模型或将模型导入工作区。要创建新模型，请打开 链接进行访问。 侧边栏面板并选择 将 > 创建新模型。这将引导您完成创建新模型、注册别名，并提供用于发布到模型的代码片段。这还会生成一个骨架 模型适配器 Python 文件，您必须实现该文件才能将模型发布回 Foundry。

要导入现有模型，请打开 链接进行访问。 侧边栏面板并选择 将 > 导入现有模型。这将引导您完成导入模型和注册别名，并提供用于下载已保存模型状态文件的代码片段。

导入的模型会从给定的模型版本加载序列化的模型状态。代码工作区为导入模型时使用的模型版本提供了不同的控制选项，允许您选择当前工作区分支上的最新版本、指定分支上的最新版本或特定的模型版本。

可用代码片段

直方图 链接进行访问。 侧边栏面板提供可复制并粘贴到笔记本中的代码片段，用于常见工作流。所有代码片段都会指示您安装 palantir_models，这是 Palantir 提供的用于开发和与模型交互的库。

侧边栏中的每个模型卡片都会创建特定于该模型的唯一代码片段。选择模型卡片会展开该卡片，并显示一个选择器，用于选择显示特定任务的代码片段。

发布模型版本

要发布模型版本，您必须首先 开发模型适配器。对于在代码工作区内创建的模型，系统会为您创建一个骨架适配器，供您在以模型别名命名的 Python 文件中实现。模型卡片将提供有关 开发模型适配器 和 将模型发布回 Foundry.

from palantir_models.code_workspaces import ModelOutput

# Model adapter api has been defined in linear_regression_model_adapter.py
from linear_regression_model_adapter import LinearRegressionModelAdapter

# sklearn_model is a model trained in another cell
linear_regression_model_adapter = LinearRegressionModelAdapter(sklearn_model)

model_output = ModelOutput("linear_regression_model")
model_output.publish(linear_regression_model_adapter)

下载模型

要下载之前发布的模型版本，请将代码片段选择器更改为 下载模型。这将提供用于解析模型版本的控制选项，该选项将决定下载模型文件时使用哪个模型版本。

  • 当前分支上的最新版本： 所选模型版本将为当前工作区分支上的最新版本。
  • 指定分支上的最新版本： 所选模型版本将为所选分支上的最新版本。
  • 特定模型版本： 所选模型版本将固定为给定的模型版本 RID。

代码片段会自动更新以支持所选的模型版本解析控制选项。请查阅下面的 ModelInput 类文档以了解更多信息。

部署模型以进行推理

模型可以在 Code Workspaces 中部署以进行推理。这些部署按模型版本共享，即一个给定的模型版本最多只能有一个关联的部署，并且这些部署与现有的 建模目标实时部署 和 模型部署完全分离。部署可以通过代码进行完全配置，并具有默认的缩放策略，在 20 分钟无使用后将关闭部署。

要加载给定模型版本的部署，请使用 Select snippets 下拉菜单，并将选项更改为 Deploy for inference。这将加载用于部署模型的代码片段，并显示与 Download files 选项相同的用于选择模型版本的选择器。这些代码片段将引导您完成模型的部署以及对其运行推理。

要在 Code Workspaces 中监控部署，请展开您正在使用的模型的模型卡片，然后选择 Deployments。在部署选项卡中，将显示已部署模型版本的列表。选择某个模型版本后，右侧将展开一个新面板，其中包含有关该部署的信息，例如使用的资源、日志等。

有关构建自定义主题的示例，请参阅 ModelInput 类文档以了解更多信息。

开发模型适配器

模型适配器用于指导 Foundry 如何在整个平台中保存、加载和执行模型。发布模型时，必须使用模型适配器对模型进行封装。

在 Code Workspaces 中，模型适配器必须在单独的 .py 文件中定义。当新模型添加到工作区时，会根据给定的别名生成一个文件。例如，如果别名为 my_model，则会生成一个名为 my_model_adapter.py 的文件，其中包含一个名为以下名称的模型适配器骨架类 MyModelAdapter.

在 链接进行访问。 面板中提供的代码片段是在假定别名、文件名和类名匹配的前提下生成的。如果文件被移动或适配器类被重命名，您可能需要手动编辑生成的代码片段。

了解更多关于开发模型适配器的信息。

推理输入大小限制

单个推理请求的大小限制为 40 MB，因为此方法适用于涉及其他模型的快速迭代，而非生产规模的推理。实际上，这通常相当于平均约 100,000 行的数据集，具体取决于行的大小。

如果您需要在更大的数据集上运行模型，可以启用 分块（chunking），它会将大型数据集分解为可管理的小块，并一次一个分块地发送给模型。您可以通过将 client.use_chunking 方法设置为 True 来启用分块，如下所示：

Copied!
1
2
client.use_chunking = True
client.predict(...)

分块目前仅支持一个数据集作为输入，但您可以包含任意数量的其他参数。如果您的数据集超出这些限制，或者分块方法无法满足您的工作流程需求，请考虑使用代码仓库（Code Repositories）和转换来处理更大规模的数据处理。

转换

生成模型输出的 Jupyter® 笔记本也可用于从代码工作区（Code Workspaces）创建的转换中。请按照以下步骤为模型输出注册一个转换：

  1. 在监听器设置向导的 链接进行访问。 面板中，找到您希望通过转换输出的模型对应的模型卡片，然后选择 发布为转换输出 （在菜单中）。

  1. 在监听器设置向导的 创建转换 面板中，您可以配置要执行的文件以及转换所需的输入和输出。在下面的示例中，训练数据用作输入，测试数据集和模型用作输出。

  1. 配置完成后，选择 同步并运行 （位于配置页面底部）以保存当前的代码更改并创建转换。转换将开始运行，作业的状态将显示在相关联的数据集和模型中，位于 链接进行访问。 panel.

然后您可以选择 查看构建 来查看正在运行的转换作业。如果您更改了笔记本代码并希望重新构建模型，请在模型卡片中选择 重新构建 以重新运行构建。使用转换创建的模型和数据集可以像平台其他位置创建的转换一样进行调度。 了解更多关于调度转换的信息。
