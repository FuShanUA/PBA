注册函数

如果在 函数执行模式中运行，您必须在计算模块中注册函数，才能在 Foundry 中的其他位置调用它们。本页面介绍了手动注册计算模块函数的两种不同方法。

计算模块 SDK 可自动推断函数的 schema，从而简化函数注册。如果您正在使用计算模块 SDK，请查看下方的 自动函数 schema 推断 部分。

从 Compute Modules 应用程序注册函数

您可以在 函数 页面中为计算模块手动注册函数。选择 添加函数 以打开 创建函数 面板：

  1. 函数名称： 要调用的函数的名称。通常，该名称应与计算模块中函数的名称一致。
  2. 输入： 将作为参数传递给计算模块函数的输入参数。

计算模块函数的输入会被打包到一个 JSON 对象中；您添加的每个输入都对应于传入函数的输入对象上的一个属性。在下面的示例中，函数输入位于左侧，而传递给相应函数的 JSON 对象位于右侧。

  1. 输出： 函数的返回类型。
  2. API 名称： API 名称是函数定位符，使您能够从 Foundry 中的其他代码调用该函数，例如通过 TypeScript 函数进行调用。 计算模块 API 格式遵循以下结构 com.<namespace>.computemodules.<MyApiName> ，并且必须遵守以下命名规则：
  • namespace： 必须全部为小写字母，且不包含特殊字符。
  • MyApiName： 必须采用驼峰式命名法，且不包含特殊字符。

更改 API 名称会导致调用方代码失效。仅支持查询的最新发布版本。

定义函数后，您可以切换到 测试 标签页以尝试调用该函数，和/或选择 保存 以保存该函数并使其可在 Foundry 中调用。

计算模块函数始终以版本 0.0.0注册。如果您更新该函数，函数的版本将被您的更改覆盖。

使用 JSON 注册函数

您还可以通过在计算模块内发送 HTTP POST 请求来手动定义函数 schema。通常，只有在创建您自己的客户端时才需要这样做。有关该 HTTP 请求的信息，请查阅我们的 POST function schema 文档。

此端点接受 JSON 数组作为负载,数组中的每个元素对应于计算模块中某个函数的规范。我们的 Python SDK ↗ 为如何组装此 JSON 负载提供了很好的参考。

自动函数模式推断

计算模块提供了一种简化的方式来定义和注册函数,支持自动模式推断,并可与 Foundry 的 Compute Module 应用集成。本节将深入介绍函数的自动注册和高级使用场景,确保获得更流畅的开发体验。

导入的函数架构只有在您的计算模块处于运行状态且响应正常后，才会显示在 Compute Modules 界面中。这意味着您必须部署并运行计算模块，函数才能在 Foundry 中可见且可访问。请查阅我们关于 使用副本状态进行调试 的文档以了解更多详情。

在您的计算模块中，您可以直接在代码中使用 JSON 结构来定义函数架构。这种方法具有以下几项优势：

  • 集中式架构定义
  • 易于维护和更新
  • 与 Foundry 自动集成

只需在您的计算模块启动时进行一次简单的 POST 调用，模块便会自动从端点调用中推断出架构，并将其作为函数在 Computes Modules 应用程序中提供。这样，开发人员只需定义一次端点架构，即可轻松将其导入 Foundry。

通过计算模块 SDK 自动发现函数

计算模块 SDK 包含自动函数发现功能。它会检查已定义的函数及其输入/输出类型,然后将其转换为 FunctionSpecs ,从而无需修改即可作为 Foundry Functions 导入。

为了确保此功能无缝运行，您应当了解 SDK 中类型推断的工作原理以及如何正确定义输入和输出类型。请查看以下注意事项：

  • 输入类必须是复杂类型。Foundry 函数规范要求函数的输入类型为复杂类型。如果您的函数仅接受单个基元类型作为输入，请务必将该参数包装在复杂类型中，以便正确推断函数架构。
  • 输入类型定义

集成服务器

在计算模块中集成服务器目前处于 实验性 开发阶段，您的注册环境中可能无法使用此功能。在积极开发期间，功能可能会发生变化。

通常，计算模块会使用客户端从计算模块 API 拉取作业。但是，你也可以在计算模块中使用 HTTP 服务器，而无需客户端、适配器或 SDK。

OpenAPI 规范

该 OpenAPI 规范（OAS）↗ 是一个用于枚举 HTTP API 的开源框架。你需要先为服务器提供 OpenAPI 规范。为服务器创建 OpenAPI 规范的方式有很多：你可以按照 OpenAPI 文档手动创建，或借助 LLM 助手创建，也可以使用通用的 OpenAPI 生成器或特定语言的库。

要与计算模块配合使用，你的 OpenAPI 规范必须遵循以下所有约束：

  • 使用 3.0.0 或更高版本的 OpenAPI 规范。
  • 包含单个服务器，其 URL 形式为 http://localhost:port。
  • 在每个操作中包含一个 operationId ，它将成为 Foundry 中函数的名称。
  • 仅使用 GET、 PUT、 POST和 DELETE 动词。
  • 在所有参数中包含 schema 字段，并且不使用任何带有 cookie 位置的参数。
  • 不得使用 anyOf、 oneOf或 allOf 模式，也不得使用具有多个类型的模式。
  • 在所有端点上仅包含单个响应代码（因为 Foundry 中的函数仅支持单一输出 schema），该响应代码必须为 application/json 内容类型。

from flask import Flask, request, jsonify
import uuid

app = Flask(__name__)

books = {}


@app.route('/books', methods=['POST'])
def add_book():
    data = request.json

    user_id = request.headers.get('User-ID')
    title = data.get('title')
    author = data.get('author')
    published_year = int(data.get('published_year'))

    book_id = str(uuid.uuid4())

    books[book_id] = {
        'title': title,
        'author': author,
        'published_year': published_year,
        'added_by': user_id
    }
    return jsonify(book_id), 200


@app.route('/books/<book_id>', methods=['GET'])
def get_book(book_id):
    return jsonify(books.get(book_id)), 200


if __name__ == '__main__':
    app.run(port=8000)

函数 CLI

函数 CLI 是一款独立工具，可帮助您发布计算模块工件。它具有两项核心职责：

  1. 对您的源代码运行静态推断，以生成函数规范。
  2. 构建并发布包含 Foundry 所需元数据标签的 Docker 镜像。

您可以在本地开发工作流中使用 Functions CLI，或将其集成到 CI/CD 管道中，以自动化计算模块的构建和发布流程。

推断

Functions CLI 可以对您的源代码执行静态推断，以自动生成函数规范。当您想要检查或验证将在 Foundry 中注册的函数架构时，这非常有用。

使用 --opt functions 标志来运行函数规范推断。对于使用 SDK 的 Python 计算模块，请指定 --plugin python_cm 标志。

以下示例将对 ./src 目录中的 Python 源代码执行推断：

Copied!
1

您还可以使用计划文件来配置推断：

Copied!
1

输出是一个包含函数规范的 JSON 数组。每个规范都包括函数名称、输入参数及其数据类型，以及输出类型。

在 TypeScript 函数中使用计算模块函数

前提条件：

  • 您必须在 Compute Module 应用程序中使用 API 名称注册您的函数。
  • 计算模块必须处于运行状态，实时预览才能正常工作。
  • 您必须初始化一个 TypeScript 代码仓库。

启用资源生成

开始之前，请确保您的 TypeScript 代码仓库中已启用资源生成：

  • 打开您的 functions.json 文件。
  • 将 enableResourceGeneration 属性设置为 true。

导入您的计算模块函数

要在 TypeScript 中导入计算模块函数，请按照以下步骤操作：

  1. 在 TypeScript 代码仓库的左侧面板中，找到并选择 资源导入 选项卡。
  2. 选择 添加，然后选择 查询函数 ，以显示用于选择本体论的弹出窗口。

  1. 尽管计算模块并不绑定到特定的本体论，但您必须在导入过程中选择一个本体论。请选择适合您使用场景的任意本体论。
  2. 搜索您的计算模块函数的 API 名称。
  3. 选择该函数。

  1. 选择 确认选择。

重新构建您的代码工作区

导入并使用该函数

下面的示例展示了如何导入并使用计算模块函数：

// index.ts
import { Function } from "@foundry/functions-api";

// API Name: com.mycustomnamespace.computemodules.Add
import { add } from "@mycustomnamespace/computemodules";

export class MyFunctions {
    @Function()
    public async myFunction(): Promise<string> {
        return await add({ x: 50, y: 50 });
    }
}

重要注意事项

  • 项目位置： 确保计算模块与您的 TypeScript 代码位于同一个 Project 中，以便实时预览正常工作。
  • 类型一致性： TypeScript 实施严格的类型检查。请确保声明的返回类型与您的计算模块函数的实际返回类型相匹配。例如，如果您声明一个 string 返回类型，您注册的计算模块函数必须返回一个 string，而不是 struct 类型。
  • 异步操作： 计算模块函数通常是异步的。请使用 async/await 语法进行正确处理。

由于 TypeScript 函数会经过 function-executor，因此只有运行时间少于五分钟的计算模块函数才能成功执行。如果函数运行时间超过五分钟，将会超时。
