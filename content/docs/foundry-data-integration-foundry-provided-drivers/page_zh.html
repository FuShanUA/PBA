CData 提供的驱动程序的配置选项

许多 Foundry 提供的驱动程序由以下开发商开发： CData ↗。CData 为每个驱动程序提供完整的文档，包括在源系统上生成凭据的详细说明。您可以从任何 CData 驱动程序的文档页面导航到这些说明。

以下各节包含有关 CData 特定配置选项的信息，这些选项可以帮助您成功连接到外部系统。

使用 CData 连接器导出数据

用途 。对于在 z/OS 或 LUW（Linux, Unix, Windows）上运行的 Db2 数据库，不需要额外配置。但是，对于在 IBM iSeries 或 AS/400 上运行的 Db2 数据库， 将 Foundry 数据集中的行添加到现有的外部表中。表导出支持因连接器而异；请查看连接器的文档以了解可用性。

CData 表导出仅支持 不截断的导出模式 且不支持按键进行更新、删除或 upsert 操作。在导出生产数据之前，请查看 表导出要求和限制 并针对非生产目标测试一行数据。

对于 Foundry-worker 源，请使用经验证的、特定于连接器的 基于代码的连接选项 以执行更复杂的操作。请遵循连接器的文档以了解支持的操作和身份验证。

在源探索时自动执行测试连接

默认情况下，CData 驱动程序会延迟到实际执行查询时才建立连接。这可能导致对源探索产生错误的假设，因为驱动程序中存储的静态元数据表的显示可能让您认为探索已成功，而实际上由于缺少凭据、缺少出口策略或其他问题，与底层系统的连接并未成功。

您可以通过设置以下属性，强制驱动程序执行无操作测试连接，即使仅在探索数据源时也是如此： ConnectOnOpen JDBC 属性设置为 true。建议这样做，以确保在探索数据源时发现所有连接问题。

ConnectOnOpen: true 不能与以下功能同时使用： OAuth 2.0 身份验证.

ConnectOnOpen: true 可能是连接失败的原因，因为用于连接的凭据权限范围非常有限，不允许执行用于测试连接的无操作命令。

证书身份验证

许多 CData 驱动程序支持证书身份验证，尤其是对于基于 Azure 的系统。

要使用证书进行连接，除了特定于连接的配置要求外，还必须定义以下 JDBC 属性：

  • AuthScheme: AzureServicePrincipalCert
  • OAuthJWTCertType: PFXBLOB
  • OAuthJWTCert: base64-encoded_cert/pfx/pem_file_content
  • （可选） OAuthJWTCertPassword: password_for_the_cert/pfx/pem_file

要在 Windows 计算机上将证书文件转换为 Base64 格式，请使用以下命令： [Convert]::ToBase64String([IO.File]::ReadAllBytes("\path\to\file.pfx"))

存储过程

一些连接到基于文件的源系统（如 Amazon Marketplace or Microsoft OneDrive ）的 CData 驱动程序依赖于调用存储过程来摄取数据。

运行存储过程将生成一个表，其中文件内容以 Base64 编码字符串的形式存储。您可以在下游数据转换中对其进行解码，例如在 Pipeline Builder 中使用 Base64 解码 看板，快速计算数据在多个维度上的多个聚合值。

OAuth 2.0 身份验证

某些 CData 驱动程序支持 OAuth 2.0 ↗ 授权码授予流程。这使用户能够使用自己的凭据进行身份验证并代表其执行操作，从而实现与外部系统的安全连接。 可用驱动程序列表 详细说明了哪些驱动程序支持 OAuth 2.0 身份验证。

仅当在 您必须正确配置出站策略（如果使用上运行源时才支持 OAuth 2.0 身份验证。在 ）或您的代理网络（如果使用 上运行的源不支持 OAuth 2.0 身份验证。

要使用 OAuth 2.0 身份验证：

  1. 将 CallbackUrl JDBC 属性添加到源配置中。该属性值将自动填充为以下形式的 URL https://<YOUR_FOUNDRY_URL>/workspace/oauth2-clients/callback.

  2. 在外部系统中，注册一个自定义 OAuth 应用程序并提供回调 URL。

    • 注册自定义 OAuth 应用程序的具体步骤取决于各个外部系统。例如，对于 GitHub ↗，请导航至 Settings > Developer Settings > OAuth Apps添加依赖项。然后选择 New OAuth App.

  3. 复制生成的 OAuth 客户端 ID 和 OAuth 客户端密钥 并将其粘贴到源配置的 JDBC 属性中。



  4. 保存配置后，导航到源概览页面。选择 授权 在顶部横幅中标记为 需要授权才能开始使用此源 以启动 OAuth 流程。



    您可以在源概览页面的右侧面板中续订或撤销授权。



默认情况下，启动、续订或撤销 OAuth 流程需要源上的 Owner 角色。仅具有 Viewer or Editor 的用户在选择 授权时会看到权限被拒绝的错误。如果您需要授予这些操作权限而不授予完整的 Owner 权限，可以定义一个包含源管理操作的自定义角色。
