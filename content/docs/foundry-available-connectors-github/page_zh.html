GitHub

GitHub 连接器是一种 由 Palantir 提供的驱动程序 ，用于 GitHub。

要创建新的 GitHub 源，请按照 Palantir 提供的驱动程序的标准设置流程，然后使用以下各节进行 GitHub 特定的配置和网络设置。完整的属性参考，请参阅 官方 GitHub 驱动文档 ↗.

受支持的功能

功能状态
探索🟢 正式可用
批量同步🟢 正式可用
增量🟢 正式可用
OAuth 2.0 身份验证🟢 正式可用
表导出🟢 正式可用

简介

GitHub 连接器最适合 批量读取 数据。它将 GitHub 数据模型——仓库、议题、拉取请求、提交及相关实体——呈现为关系表。您可以在源资源管理器中浏览这些表，并使用 功能允许将外部系统的数据同步到Foundry将其拉取到 Foundry 中。这使其非常适合将整个仓库或组织镜像到 Foundry 中以进行下游分析。

要在 GitHub 中创建或更新记录，请复用您现有的 GitHub 源并调用 GitHub REST API ↗ ，可通过 外部转换 or 外部函数。无需第二个源。请参阅 在代码中使用 GitHub 源 使用布局事件切换页面

身份验证

连接器通过 OAuth 2.0 向 GitHub 进行身份验证。您需要在 GitHub 上注册一个应用程序，然后将其 客户端 ID 和 Client secret 输入到 Foundry 源中（OAuthClientId / OAuthClientSecret）。启用 InitiateOAuth 设置为 REFRESH后，驱动程序会在首次同步时运行 GitHub 的 OAuth Web 应用程序流程 ↗ ，并保持令牌持续刷新。

GitHub 提供两种应用程序类型，两者均基于 OAuth 2.0，配置方式相同。 GitHub App （推荐）可添加细粒度的、按资源的权限——例如，对单个仓库议题的只读访问——以及短期有效的令牌。 OAuth app 则使用宽泛的账户级作用域，例如 repo。以下步骤使用 GitHub App；OAuth app 与之完全相同，只是在权限配置工作流中，您需要改为选择 OAuth app （来自 Settings > Developer settings。如需完整比较，请参阅 GitHub Apps 与 OAuth apps 的区别 ↗.

创建应用程序

在 GitHub 中，选择 Settings > Developer settings > GitHub Apps > New GitHub App ↗ ，并将 Callback URL 设置为 Foundry 源设置页面上显示的值。

自动预览行为 权限与事件，仅授予同步所需的权限（例如，只读 内容 和 问题），创建应用程序，并从目标仓库或组织的 Install App 标签页安装它。然后，在应用程序的 General 页面上，复制 客户端 ID 并生成 Client secret.

将您的 GitHub 客户端 ID 和密钥添加到源中

在 Foundry 中导航到 Data Connection，并输入 客户端 ID 和 Client secret 到源的 OAuthClientId 和 OAuthClientSecret 属性中，并保持 InitiateOAuth 设置为 REFRESH.

在代码中使用 GitHub 源

要在 GitHub 中创建或更新记录，或使用任何部分的 GitHub REST API ↗ 超出批量读取的功能，请通过 外部转换 or 外部函数调用 API。复用您现有的 GitHub 源，并使用在代码中生成的短期（存活时间约为一小时）GitHub App 安装令牌进行身份验证。无需第二个源。

接下来，将该源导入您的 外部转换 or 函数 仓库。该源不提供内置的 HTTPS 客户端（get_https_connection().get_client()），但它继承其 api.github.com 出口流量，该流量受上述 网络出口策略约束。您可以直接使用 requests ↗ 在 Python 中调用 GitHub REST API，或使用该源的 fetch 在 TypeScript 中调用。

读取 GitHub issue

以下示例通过 GitHub App 使用 Python 或 TypeScript 读取 GitHub issue。

此工作流不受 OAuth 应用支持，后者需要个人访问令牌。

首先，导航到您的源的 连接详情 页面（位于 Data Connection 中），并通过选择以下选项添加 GitHub App 的私钥 Add property > New encrypted property。将该属性命名为 Other，以便能够通过以下方式读取回来 get_secret("Other").

接下来，将 APP_ID 在 Python 示例中设置为 GitHub App ID 或客户端 ID。此标识符是公开的，无需进行机密存储。TypeScript 示例则从该源的 OAuthClientId 属性。

函数预览失败

助手并选择 无法将 源 绑定到函数，因此这些示例 始终 在预览期间报错。请改为部署该函数，并从 Workshop 应用程序或通过任何无服务器执行来运行它，以确认其正常工作。

import time

import jwt
import pandas as pd
import requests
from transforms.api import LightweightOutput, Output, transform
from transforms.external.systems import ResolvedSource, Source, external_systems

API = "https://api.github.com"
APP_ID = "<github_app_id_or_client_id>"
OWNER = "<owner>"
REPOSITORY = "<repository>"


def github_headers(github: ResolvedSource) -> dict[str, str]:
    now = int(time.time())
    app_jwt = jwt.encode(
        {"iat": now - 60, "exp": now + 540, "iss": APP_ID},
        github.get_secret("Other"),
        algorithm="RS256",
    )
    headers = {
        "Accept": "application/vnd.github+json",
        "X-GitHub-Api-Version": "2022-11-28",
        "Authorization": f"Bearer {app_jwt}",
    }
    installation_id = requests.get(
        f"{API}/repos/{OWNER}/{REPOSITORY}/installation", headers=headers
    ).json()["id"]
    token = requests.post(
        f"{API}/app/installations/{installation_id}/access_tokens",
        headers=headers,
    ).json()["token"]
    return {**headers, "Authorization": f"Bearer {token}"}


@external_systems(github=Source("<source_rid>"))
@transform.using(output=Output("<issues_output_dataset_rid>"))
def get_issues(github: ResolvedSource, output: LightweightOutput) -> None:

        params={"state": "all", "per_page": 100},

    output.write_table(pd.DataFrame([{
        "number": issue["number"],
        "title": issue["title"],
        "body": issue["body"],
        "state": issue["state"],
    } for issue in response.json()]))

import { ExternalSystems, Function, Integer } from "@foundry/functions-api";
import { GitHubSource } from "@foundry/external-systems/sources";
import * as jwt from "jsonwebtoken";

const API = "https://api.github.com";

export interface GitHubIssue {
    number: Integer;
    title: string;
    body?: string;
    state: string;
}

async function githubHeaders(owner: string, repository: string): Promise<Record<string, string>> {
    const now = Math.floor(Date.now() / 1000);
    const appJwt = jwt.sign(
        { iat: now - 60, exp: now + 540, iss: GitHubSource.getSecret("OAuthClientId") },
        GitHubSource.getSecret("Other"),
        { algorithm: "RS256" },
    );
    const headers = {
        Accept: "application/vnd.github+json",
        "X-GitHub-Api-Version": "2022-11-28",
        Authorization: `Bearer ${appJwt}`,
    };
    const installation = await GitHubSource.fetch(
        `${API}/repos/${owner}/${repository}/installation`, { method: "GET", headers }
    );
    const { id } = await installation.json() as { id: number };
    const tokenResponse = await GitHubSource.fetch(
        `${API}/app/installations/${id}/access_tokens`, { method: "POST", headers }
    );
    const { token } = await tokenResponse.json() as { token: string };
    return { ...headers, Authorization: `Bearer ${token}` };
}

export class GitHubFunctions {
    @ExternalSystems({ sources: [GitHubSource] })
    @Function()
    public async getIssues(owner: string, repository: string): Promise<GitHubIssue[]> {
        const response = await GitHubSource.fetch(
            `${API}/repos/${owner}/${repository}/issues?state=all&per_page=100`,
            { method: "GET", headers: await githubHeaders(owner, repository) },
        );
        if (!response.ok) throw new Error(`GitHub returned ${response.status}`);
        const issues = await response.json() as Array<{
            number: number; title: string; body: string | null; state: string;
        }>;
        return issues.map(({ number, title, body, state }) => ({
            number, title, body: body ?? undefined, state,
        }));
    }
}

            headers: { ...headers, "Content-Type": "application/json" },
            body: JSON.stringify({ body }),
        },
    );
    if (!response.ok) throw new Error(`GitHub returned ${response.status}`);
    return body;
}
