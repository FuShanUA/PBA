编写并运行评估

本页面介绍如何编写一个计算并记录评估指标的转换 评估，如何控制评估哪个模型版本，如何将结果拆分为 子集，以及如何评估其他分支上的版本。

编写评估逻辑的代码仓库必须与被评估的模型位于 同一个项目 中。如果模型和仓库位于不同的项目中，编写评估时会因权限错误而失败。请移动模型或仓库，使它们共享同一个项目。

完整示例

下面的示例评估一个预测房价的回归模型，并将其与一个留出的测试数据集进行对比。测试数据集包含输入特征、一个 actual_price 真实值（ground-truth）列，以及一个 price_tier 将每行标记为 affordable, mid_range，或 luxury.

确保您已 升级您的代码仓库 并升级了 palantir_models 库至 >= 0.2384.0 然后再编写评估逻辑。

import plotly.express as px
import palantir_models as pm
from palantir_models.transforms import ModelInput
from transforms.api import transform, Input


@pm.transforms.evaluation("error_analysis")
@transform.using(
    test_data=Input("/Housing/clean/test_set"),
    housing_model=ModelInput("/Housing/models/price_regressor", use_sidecar=True),
)
def compute(test_data, housing_model):
    df = test_data.pandas()

    # Run inference. The exact call depends on your model adapter's API.
    predictions = housing_model.transform(df)["predicted_price"]
    residuals = df["actual_price"] - predictions

    evaluation = housing_model.create_evaluation(name="nationwide")

    # Aggregate error metrics across all predictions.
    evaluation.log_metrics({
        "mae": residuals.abs().mean(),
        "rmse": (residuals ** 2).mean() ** 0.5,
    })

    # A residual distribution plot.
    evaluation.log_plot(
        "residual_distribution",
        px.histogram(residuals, nbins=50, title="Residual distribution"),
    )

您可以像运行任何其他 Python 转换一样，通过运行该转换来触发评估。当构建成功时，评估将被提交到 error_analysis 模型上的 price_regressor 评估集中。如果构建失败，评估将被中止，且不会发布任何内容。

确定评估哪个模型版本

评估始终关联到单个模型版本：即由 ModelInput 解析并加载到转换中的版本。该版本也是评估在评估集中所附加到的版本，这使得可以跨版本比较相同的分析结果。

组织管理员 ModelInput 解析构建所在分支上的最新模型版本。您可以通过 ModelInput 参数来控制解析的版本：

  • model_version 固定（pin）特定版本。这会覆盖 branch argument.
  • branch 解析其他分支上的最新版本。

构建子集

子集 将相关的结果归组到一个共享的 prefix/name下。一种常见的模式是按某一列对测试数据集进行分区，并为每个分区记录相同的指标，使用分区值作为前缀。

# Group the test set by price tier and log per-tier error metrics.
for tier, group in df.groupby("price_tier"):
    tier_predictions = housing_model.transform(group)["predicted_price"]
    tier_residuals = group["actual_price"] - tier_predictions

    evaluation.log_metrics({
        f"{tier}/mae": tier_residuals.abs().mean(),
        f"{tier}/rmse": (tier_residuals ** 2).mean() ** 0.5,
    })

    evaluation.log_plot(
        f"{tier}/residuals",
        px.histogram(tier_residuals, nbins=50),
    )

这会生成 affordable/mae, mid_range/mae日 luxury/mae 指标（以及相应的残差图），可以在模型页面上并排比较。前缀是任意的，如何将数据划分为子集完全由您决定。

评估其他分支上的版本

要评估位于其他分支上的模型版本，您有两种选择：

  • 在该分支上运行转换。 当构建在某个分支上运行时， ModelInput 默认会解析该分支上的最新模型版本，因此评估会附加到该版本。
  • 从 ModelInput. 设置 branch 参数中指定目标分支，即可在不更改构建所在分支的情况下解析特定分支上的最新版本。

运行内置评估器

如果您评估的是标准的回归或分类模型，可以使用 内置评估器 而无需手动计算指标。它们会运行推理，将预测结果与真实值列进行比较，并为您将一组标准指标记录到评估中。

请查阅 模型评估 Python API 参考 以获取完整的方法签名。
