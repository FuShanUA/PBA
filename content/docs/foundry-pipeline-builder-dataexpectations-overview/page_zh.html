数据期望

数据期望是可以应用于数据集输出的要求。这些要求（称为“期望”）可用于创建检查，以提高数据管道的稳定性。

可以在每个管道输出上设置数据期望，以对生成的输出定义期望。Pipeline Builder 支持以下数据期望类型：

  • 主键： 验证所选列不包含空值，且其组合是唯一的。
  • 行数： 验证输出包含的行数在预期范围内。
  • 值属于以下之一： 验证所选列中的每个值都属于允许的值列表。
  • 值不为空： 验证所选列不包含空值。
  • 浮点数和双精度数不是 NaN： 验证所选浮点列不包含 NaN values.
  • 行级： 接受一个返回布尔值的列表达式，并验证该条件对输出的每一行都成立。

如果任何期望失败，构建将失败。作业期望窗格将显示哪些数据期望通过、哪些失败。

主键数据期望

主键期望提供一个或多个列名，并验证：

  • 每列都没有空值。
  • 列的组合是唯一的。

如果您使用增量构建，并且主键检查耗时较长，请尝试 添加投影 到您的主键列。

主键数据期望示例

在选定的特定列中，我们检查其下的每个条目是否唯一。

如果选择了两列，我们检查这两列的组合是否唯一。

在此示例中， id 和 time 是数据集中存在的两列。

示例数据集：

idtime
18pm
19pm
28pm
38pm

上面的示例将通过检查。这是因为即使 1 和 8pm 单独出现重复， id 和 time 的组合仍然是唯一的。

相反，以下情况将失败：

idtime
18pm
29pm
18pm

此表将无法通过检查，因为 1 和 8pm 组合出现了重复。

行数数据期望

行数期望提供最小和/或最大行数。

如果提供了最小行数，该期望将验证至少存在指定数量的行。

如果提供了最大行数，该期望将验证最多存在这么多行。

值属于以下之一的数据期望

直方图 值属于以下之一 期望提供一个列和一个允许的值列表。它验证每行中该列的值与允许的值之一匹配。

使用此期望来保护假定固定类别集合的下游逻辑，例如必须仅包含以下值的状态列 ACTIVE, INACTIVE，或 PENDING.

例如，如果允许的值是 ACTIVE 和 INACTIVE，则下表将通过检查：

idstatus
1ACTIVE
2INACTIVE
3ACTIVE

相反，下表将无法通过检查，因为 PENDING 不属于允许的值：

idstatus
1ACTIVE
2PENDING

值不为空的数据期望

直方图 值不为空 期望提供一个列，并验证输出中没有任何行在该列中存在缺失值。

此期望仅检查空值。空字符串是一个值而不是缺失值，因此包含空字符串的行将通过。如果某列必须既有值又唯一，请使用 主键期望 来替代。

浮点数和双精度数不是 NaN 的数据期望

直方图 浮点数和双精度数不是 NaN 期望验证浮点列不包含 NaN （“非数字”）值。 NaN 值通常由未定义的算术运算引入，例如零除以零，或将非数值转换为浮点数或双精度数。

因为 NaN 是一个有效的浮点数值而不是缺失值，一个 值不为空 期望将无法检测到它。 NaN 值也会在聚合中传播，这意味着单个 NaN 值可以将聚合结果（例如总和或平均值）变为 NaN。请在下游消费者（例如仪表板或模型）依赖明确定义的数值的数值输出中添加此期望。

具有 NaN 属性值的对象将无法索引。Object Storage v2 (OSv2) 不允许 NaN or ±infinity 作为属性值，因此 NaN 值到达对象类型数据源时，会导致批处理数据源的索引作业失败，而流式数据源的违规记录将被丢弃。如果您的输出支撑某个对象类型，请添加此期望以在 NaN 值到达本体论之前捕获它们。请查看 数据限制 的文档以获取更多信息。

行级数据期望

行级期望通过一个返回布尔值的列表达式提供，并对输出的每一行运行该条件。在配置期望时，从下拉列表中选择要评估的表达式。只有当条件对每一行都评估为 true 时，期望才会通过。

当您要验证的条件未被其他期望类型覆盖，或者它依赖于多个列时，请使用行级期望。例如，您可以验证 quantity 列始终大于零，或者 end_time 值始终晚于同一行中相应的 start_time 值。
