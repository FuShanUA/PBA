保障数据基础安全

Foundry 的总体目标是提供组织内部客观事实的规范化视图。构建这一事实的第一步是构建并为您的数据基础设置权限。为了解释如何保护您的数据基础，我们将通过一家名为 Sky Industries 的飞机制造商的示例进行说明。我们将扮演一位 Sky Industries 的开发人员，他正在集成原始的 Flight、Runway、Airport、Alert、Route 和 Passenger 数据，为其准备本体论，然后将其提供给整个 Sky Industries 组织使用。

创建项目

设计数据基础的一个关键部分是决定需要为生产数据管道创建哪些项目，以便实现未来的扩展和易于维护。在我们的示例中，我们将使用 推荐的项目设置 并拥有 3 个 项目 ，它们各有不同的用途：

  • Flight Control System [Datasource]： 原始数据从交通运输统计局（BTS）摄取并在此项目中进行清理。
  • Flight Delays [Transform]： 数据集从 Flight Control System [Datasource] 项目导入并进行转换，以生成可重用的数据集。
  • Aviation [Ontology]： 数据集从 Flight Delays [Transform] 项目导入并进行转换，以表示离散的组织对象。

根据您的 Foundry 实例，您可以同时创建项目和/或组。目标是为每个项目设置三个组，每个组映射到一个默认角色（例如， Viewer）。我们希望我们的项目能被组织中的其他用户发现，因此我们将项目的默认角色设置为 Discoverer ，并且我们不会向项目添加标记。此外，我们将在每个项目中创建一个代码仓库，用于存放我们的转换。以下是我们最终的 Flight Delays [Transform] 项目设置。

共享数据

我们建议通过与同事共享数据和资源时，将其添加到正确的 Project 组中，以便他们对 Project 拥有统一的访问权限。这种方法比直接共享资源更清晰、更易于管理。除了通过正确的 Project 组成员身份提供合适的角色外，您还应检查是否满足其他访问要求，例如标记（Marking）和组织成员身份。请查看 检查权限 参数
