数据建模

地理时间序列应对实体位置随时间的变化进行建模，例如一架飞机从旧金山飞往纽约市的过程。如果您的数据不包含时间戳、位置或用于唯一标识的 序列 ID，则地理时间序列可能不适合您的使用场景。

观测架构

每一行在 地理时间序列同步 中都遵循相同的架构，该架构是在 Pipeline Builder中创建同步时定义的。架构至少包含以下 必填 字段：

列类型描述
序列 IDString[必填] 观测序列的标识符，由地理时间序列引用（GTSR）进行引用。长度必须在 1-100 个字符之间（含 1 和 100）。
时间戳Timestamp[必填] 观测由传感器发出的时间。该时间也可称为事件时间戳。
位置GeoPoint[必填] 观测的经纬度坐标。
海拔Double[可选] 观测高出地球表面的高度，以米为单位。在需要渲染时，海拔被假定为高于椭球面的高度（HAE），以米为单位。

观测时通常会同时记录附加数据，例如飞机报告其航向或速度。地理时间序列允许在所需的地理时间序列列之外同时捕获这些附加数据点。

选择序列 ID

在地理时间序列同步中，您应选择一个 序列 ID 来对来自移动实体的观测进行分组。传入的数据应包含一个在多次观测之间保持不变的给定实体标识符。如果未提供此类标识符，您可以根据数据创建一个标识符，例如，通过拼接航班号、出发地、目的地和日期。通过在序列 ID 中包含日期，可以确保每天的航班被视为一个单独的序列，而不是将多天的航班关联到同一个序列中。

序列 ID 用于检索最新点、轨迹以及与该序列相关的其他属性。序列 ID 冲突会导致地图渲染效果不佳或数据不正确。

实时属性与静态属性

时空序列架构上的属性（如速度或航向）默认均为“实时”属性，这意味着它们预计在每次观测时都会发生变化。通常，不会发生变化的属性（即“静态”属性，例如飞机的呼号或国旗）应放置在 时空序列对象类型 上，而不是作为时空序列本身的属性。在极少数情况下，将静态属性反规范化到观测中以支持搜索工作流可能很有用。为此，请将时空序列属性标记为“静态”而非“实时”，以此向 Foundry 的时空序列数据库表明：在压缩或降采样轨迹时，该属性的采样频率可以低于“实时”属性。此类“静态”属性仍须在每条传入的观测中指定，即使它们在各次观测之间保持不变。
