多重性

Foundry Forms 旨在让从各种来源收集信息尽可能简单。在大多数情况下，这涉及配置一个表单，填写者填写一次并根据输入的值创建一个新行（或对象）。这可能或多或少有些复杂，但基本的预期是填写者必须与表单的单个实例进行交互。

这种预期不适用于同一用户必须反复填写同一表单的用例。

然而，如果需要记录的观察结果很多，这种行为就会变得乏味且重复。为表单的每个实例进行相同的选择（在本例中为 Date 和 Primary Category）并提交响应会浪费时间。

这些用例最好通过 多重条目来解决。用户无需一次填写一个表单，而是指定哪些字段是“共享的”，哪些字段对表单的每个实例是“唯一的”：

请注意以下几点：

  1. 共享字段被提取出来，并在页眉中输入一次。
  2. 然后，每个表单实例仅显示唯一的字段。
  3. 所有表单填写完成后，一次提交即可使用共享值和唯一值创建行（或对象）。

多重条目表单不支持 Default Value or UrlParams 配置。

配置自由多重条目表单

按照以下步骤创建一个在自由形式上下文中接受多重条目的表单：

  1. 选择 + 在现有字段的上方或下方继续添加更多共享字段。
  2. 选择 + 在最后一个字段的下方并选择 插入新工作表.
  3. 双击新工作表标题以打开可视化编辑器。
  4. 切换 多重性配置 为开启状态（按钮将显示为蓝色）。
  5. 选择 自由多重性 从下拉菜单中选择，并根据需要调整设置。
  6. 选择右下角的绿色 保存 button.
  7. 选择 + 在新工作表标题的正下方添加唯一字段。

在上面的示例中，每个 Measurement 和 Measurement Type 实例都会在支撑电子表格中生成一个新条目，因为它们位于不同的工作表中。 Date 和 Primary Category（存在于工作表之外）已被捕获为此次提交创建的三个条目中每个条目的公共值。

配置参数化多重条目表单

除了在所有表单实例之间共享公共值之外，参数化多重条目表单还使用共享字段来确定要显示多少个表单实例，并在每个实例中设置一个唯一值。

与自由多重条目表单不同，参数化多重条目表单需要额外的配置来将共享字段与将捕获其唯一值的字段连接起来：

按照以下步骤创建一个在参数化上下文中接受多重条目的表单：

  1. 选择 + 在现有字段的上方或下方继续添加更多共享字段。
  2. 选择 + 在最后一个字段的下方并选择 插入新工作表.
  3. 选择 + 在新工作表标题的正下方添加该字段（例如 Text）来保存该值。
  4. 双击新工作表标题以打开可视化编辑器。
  5. 切换 多重性配置 为开启状态（按钮将显示为蓝色）。
  6. 选择 参数化多重性 创建维护覆盖
  7. 在监听器设置向导的 参数化 URI 字段中，输入工作表中字段的 URI。
  8. 将下一个下拉菜单从 常量 to 标记.
  9. 选择 当前 tag() 没有字段。可用字段将以紫色高亮显示。
  10. 选择将填充该值的共享字段。
  11. 选择右下角的绿色 保存 button.

要使预填值不可编辑，请打开接收字段的可视化编辑器并切换开启 将此字段设为只读.

高级：使用对象进行配置

要为对象的每个实例接收一个表单，您可以使用 Objects Provider 字段，按照以下步骤操作：

  1. 选择 + 在现有字段的上方或下方，并添加一个 Objects Provider 字段。您可以根据另一个字段的值来筛选此字段。
  2. 选择 + 在最后一个字段的下方并选择 插入新工作表.
  3. 选择 + 紧接在新工作表标题的下方，并添加一个 Text field.
  4. 双击新工作表标题以打开可视化编辑器。
  5. 切换 多重性配置 为开启状态（按钮将显示为蓝色）。
  6. 选择 参数化多重性 创建维护覆盖
  7. 在监听器设置向导的 参数化 URI 字段，输入其 URI Text field.
  8. 将下一个下拉菜单从 常量 to 标记.
  9. 选择 当前 tag() 没有字段。可用字段将以紫色高亮显示。
  10. 选择 Objects Provider field.
  11. 选择右下角的绿色 保存 button.
