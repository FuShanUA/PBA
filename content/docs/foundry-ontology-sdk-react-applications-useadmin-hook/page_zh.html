useAdmin 钩子

该 useAdmin 钩子是一个自定义 React 钩子，提供与 Foundry Admin API 用户数据进行交互的功能。它将用户相关操作集中化，例如检索当前已认证的用户、批量获取多个用户以及管理个人资料图片。

此钩子利用 SWR（stale-while-revalidate）实现高效的数据获取与缓存策略，有助于优化网络请求，并在整个应用程序中为用户数据提供一致的接口。通过将 SWR 与 Foundry Admin SDK 相结合，它为用户管理创建了一个稳健的解决方案，可自动处理加载状态、缓存和错误处理。

查看 useAdmin 参考代码。

核心功能

  • 使用 React 的 useCallback 对函数进行记忆化，防止不必要的重新渲染并优化性能
  • 通过 SWR 实现智能缓存策略，以最大限度减少 API 调用并提高应用程序的响应速度
  • 为个人资料图片创建 blob URL，从而实现二进制图像数据的高效渲染
  • 妥善处理空的用户 ID 数组，在不发起请求的情况下返回空结果
  • 支持批量获取用户，以在需要加载多个用户时减少 API 调用次数
  • 提供加载、验证和错误状态，以实现全面的 UI 反馈
  • 使用 TypeScript 为所有数据结构和函数签名提供强类型支持

const getBatchUserDetails: (userIds: string[]) => Promise<UserDetails> =
  useCallback(async (userIds) => {
    const cachedUsers: UserDetails = {};
    const usersToFetch: string[] = [];

    // Check cache first for each requested user
    userIds.forEach((userId) => {
      const cachedUser: State<unknown, unknown> | undefined = cache.get(`user-${userId}`);
      if (cachedUser && cachedUser.data) {
        cachedUsers[userId] = cachedUser.data as User;
      } else {
        usersToFetch.push(userId);
      }
    });

    // Only fetch users not found in cache
    if (usersToFetch.length > 0) {
      const usersRequest = await getBatch(client, usersToFetch.map((userId) => ({ userId })));
      // Store results in cache for future use
      Object.entries(usersRequest.data).forEach(([userId, user]) => {
        cachedUsers[userId] = user;
        mutate(`user-${userId}`, user, { revalidate: false });
      });
    }

    return cachedUsers;
  }, [cache, client]);

此策略通过以下步骤提升性能：

  1. 检查请求的数据是否存在于缓存中
  2. 仅获取尚未存在的数据
  3. 使用新获取的数据更新缓存
  4. 返回缓存数据与新获取数据的组合

外部包

以下外部包可与 useAdmin hook 一起使用。

@osdk/react (useOsdkClient)

用途： 用于访问 OSDK 客户端实例的 React hook 优势：

  • 提供所有 API 调用所需的已验证客户端的访问权限
  • 管理身份验证上下文，无需手动逐层传递 props
  • 确保在整个应用程序中 API 访问的一致性
  • 与 Foundry 的身份验证机制集成

@osdk/foundry.admin

用途： 用于与用户相关服务交互的 Foundry Admin SDK。 优势：

  • 为用户数据提供类型安全的接口，使用 User 类型
  • 包含用于用户操作的专用函数（getCurrent、 profilePicture、 getBatch）
  • 将复杂的 API 交互抽象为简单的函数调用
  • 确保与 Foundry 的后端服务和数据模型兼容

SWR：useSWR、mutate、useSWRConfig

用途： 数据获取、缓存和状态管理库 优势：

  • 通过简单的 API 提供优雅的数据获取、缓存和重新验证方式
  • 自动管理加载、错误和验证状态，无需额外代码
  • 实现乐观 UI 更新和后台重新验证策略
  • 提供一个可在整个应用程序中访问和操作的全局缓存
  • 通过智能缓存减少不必要的网络请求

import useAdmin from '../dataServices/useAdmin';
import { useState, useEffect } from 'react';
import type { User } from '@osdk/foundry.admin';

// Example 1: Display current user information with profile picture
function UserProfile() {
  const { currentUser, isLoading, isError, getCurrentProfilePictureUrl } = useAdmin();
  const [profilePicUrl, setProfilePicUrl] = useState<string | null>(null);

  useEffect(() => {
    async function loadProfilePic() {
      if (currentUser) {
        try {
          const url = await getCurrentProfilePictureUrl(currentUser);
          setProfilePicUrl(url);
        } catch (error) {
          console.error("Failed to load profile picture", error);
        }
      }
    }
    
    loadProfilePic();
  }, [currentUser, getCurrentProfilePictureUrl]);

  if (isLoading) return <div>Loading user information...</div>;
  if (isError) return <div>Error loading user information</div>;
  if (!currentUser) return <div>No user found</div>;
  
  return (
    <div className="user-profile">
      {profilePicUrl && <img src={profilePicUrl} alt="Profile" className="profile-pic" />}
      <h1>{currentUser.username}</h1>
      <p>Email: {currentUser.email ?? "Not set"}</p>
      <p>User ID: {currentUser.id}</p>
    </div>
  );
}

// Example 2: Display a list of collaborators
function CollaboratorsList({ userIds }: { userIds: string[] }) {
  const { getBatchUserDetails, isLoading } = useAdmin();
  const [users, setUsers] = useState<Record<string, User>>({});
  const [error, setError] = useState<unknown>(null);
  
  useEffect(() => {
    async function fetchUsers() {
      if (userIds.length > 0) {
        try {
          const fetchedUsers = await getBatchUserDetails(userIds);
          setUsers(fetchedUsers);
        } catch (err) {
          setError(err);
        }
      }
    }
    
    fetchUsers();
  }, [userIds, getBatchUserDetails]);
  
  if (isLoading) return <div>Loading collaborators...</div>;
  if (error) return <div>Error loading collaborators</div>;
  
  return (
    <div className="collaborators">
      <h2>Project Collaborators</h2>
      <ul>
        {Object.entries(users).map(([userId, user]) => (
          <li key={userId} className="collaborator-item">
            <span className="name">{user.username}</span>
            <span className="email">{user.email ?? "Not set"}</span>
          </li>
        ))}
      </ul>
    </div>
  );
}

边缘情况和限制

在使用 useAdmin hook 之前，请考虑以下场景和限制：

  • 头像内存管理： 该 hook 在为头像创建 blob URL 时使用了 URL.createObjectURL() ，但不处理这些 URL 的撤销。如果加载了许多头像，这可能会导致内存泄漏。使用者应调用 URL.revokeObjectURL() （当不再需要这些 URL 时）。
  • 竞态条件： 在快速连续获取多个用户时，可能会出现竞态条件，即较新的请求先于较旧的请求完成。该 hook 未实现请求取消，因此偶尔可能会显示过时的数据。
  • 错误处理粒度： 该 hook 为获取当前用户提供单一的错误状态，但对批量操作中单个用户的获取没有详细的错误处理。使用者需要为批量操作自行实现错误处理。
  • 缓存失效： 没有用于使过时的用户数据失效的显式机制。该 hook 依赖 SWR 内置的重新验证策略，而这些策略可能不足以满足所有用例。
  • 受限的用户操作： 此钩子专注于读取用户数据,但不提供更新或修改用户信息的方法。需要用户管理功能的应用程序将需要额外的钩子或扩展。
  • 空用户 ID 处理: 当 getBatchUserDetails 以空数组被调用时,会返回一个空对象,且不会发起任何请求。调用方必须处理空结果,而不能期望得到回退用户。
