代码仓库开发体验改进

发布日期：2023-09-21

Palantir Foundry 的代码仓库（Code Repositories）应用的开发体验已通过一系列改进得到优化，具体如下：

  • Task Runner，一项新的代码仓库功能，允许用户运行支持的命令，例如 install, formatCode, tasks日 whoneeds。启用 Task Runner 后，在左侧面板的“库”选项卡中添加软件包时，将在当前环境的基础上安装所请求的软件包，而不是像以前那样配置 Code Assist 工作区。在此阶段生成的额外日志有助于在需要调试时提供清晰的排查依据。此外，复杂筛选器和预览输入配置界面也得到了改进，更易于使用。

使用 Task Runner 添加并安装软件包

复杂筛选器和预览输入配置界面改进

  • 更快速的 Python 开发： 平均而言， 检查在云环境中现在快了 20-30 秒，初始检查受益于创建新仓库时新增的锁文件，而非立即执行“已取代”检查。库安装整体上更快，用户现在可以将软件包添加以便稍后安装，或在 Conda 和当前运行环境中安装软件包而无需重新创建工作区。测试环境不会在此步骤中更新。
  • Artifacts 速度改进： Code Assist 可以持久化缓存，并在环境没有变化时加快检查速度。ZSTD 压缩支持已扩展到 Artifacts 和 Mamba，从而使环境解析和安装比以前更快。
  • 非 Linux 本地开发体验改进： 新增 conda-forge 作为所有仓库开箱即用的 artifacts 支撑仓库。此外， noarch Python 库模板使开发者更容易创建和管理跨平台库。
  • 新增 Python 格式化支持： 在 black and ruff 代码检查工具之间进行选择，以确保编码风格的一致性。
  • 自动生成相关配置： 您现在可以在本地运行 vscode Gradle 任务。
  • 增强 macOS 和 Windows 上的本地开发支持： 通过 Gradle 支持本地预览。此外，仓库升级和 Code Assist 现在拥有更精简的前端界面。
  • Spark Preview Loader 优化： 现在可以预览多达 100 万行（此前为 1 万行），同时加载速度提升了 4-5 倍。
  • 更轻松地在检查日志中导航： 通过直接在检查日志中选择 buildRID，可以直接导航到 Job tracker 中的构建。

本体论 SDK（TypeScript 和 Developer Console）[正式发布]，Python SDK [Beta]

发布日期：2023-09-19

本体论 SDK（OSDK）的 TypeScript 版本和新的 Developer Console 应用现已在所有堆栈上正式发布（GA）。Python SDK 目前处于 Beta 阶段，计划于 2023 年 10 月底正式发布。

本体论软件开发工具包（OSDK）允许您直接从开发环境中访问本体论的全部能力。您可以使用 Developer Console 生成本体论 SDK，这是一个用于使用 Palantir API 创建和管理第三方应用的新门户。更多详情和说明，请参阅我们的 公开文档.

什么是本体论 SDK 和 Developer Console？

Developer Console 是一款新应用，可让您生成本体论 SDK，以便便捷地访问本体论 API。SDK 可以生成为 TypeScript NPM 包以及 Python PyPi/Conda 包（Beta）。本体论 SDK 包仅包含开发者 Developer Console 中定义的本体论中的实体。

开发者可以使用本体论 SDK 轻松读取本体论、通过操作（Actions）向 Foundry 写回数据、执行本体论函数等。使用 SDK 提供了一种类型安全的方式与我们的 API 进行交互。

开发人员随后可以有效地将 Foundry 视为后端，依赖 Foundry 提供的基础设施和集中式本体论管理，从而将更多精力专注于其组织特有的应用程序开发。

一张 GIF 动图，展示了本体论 SDK 在代码编辑器中集成 Foundry 本体论资源。

为什么使用本体论 SDK？

  • 加速开发： OSDK 提供了对本体论 API 的便捷访问，只需几行代码即可读取数据并写回本体论。
  • 强大的类型安全性： 为 OSDK 生成的函数和类型基于您开发时所选择的本体论子集。所有内容都源自您的本体论，因此您可以直接在编辑器中查询和探索数据。
  • 集中化维护： 充分利用本体论在 Foundry 中集中构建和管理这一优势，让您专注于应用程序构建，而无需在为应用程序维护和构建数据基础方面投入重复的工作。
  • 跨团队感知： 使用 Developer Console 将使应用程序像原生 Slate 或 Workshop 应用一样出现在 Foundry 的溯源系统中，确保任何对本体论的更改（如果影响到您的应用程序）都可以根据其影响进行评估。
  • 设计即安全： OSDK 生成时所使用的令牌仅限定于您希望应用程序访问的本体论实体。

如何使用它？

本体论 SDK 通过 Developer Console 生成，这是一个全新的 Foundry 工具，您可以通过它创建和管理使用 Palantir API 构建的应用程序。从工作区导航栏中的 Applications Portal 打开 Developer Console，或使用搜索功能 CMD + J （MacOS）或 CTRL + J (Windows)。

在 Applications Portal 中搜索 Developer Console。

虽然本体论 SDK 和 Developer Console 将对所有注册用户开放，但您可以选择退出 Developer Console，方法是在 控制面板 中将其禁用，或在 中为特定组配置细粒度访问权限 页面预览同步的数据。

有关如何使用 本体论 SDK 和 Developer Console 的文档现已提供，其中包括针对不同应用程序工作流程的详细演练。此外，还有一个 基于 TypeScript/React 的入门应用程序，位于我们的公共代码仓库 ↗ ，可帮助您快速上手。

Developer Console 会根据所选的本体论实体为每个应用程序提供定制的文档。

敏感数据扫描器 [Beta] 介绍

发布日期：2023-09-19

敏感数据扫描器（SDS，前身为 "Foundry Inference"）可帮助组织发现并保护其 Palantir Foundry 数据集中的敏感数据。现已可在 测试版中使用，治理用户可以使用 SDS 指定要识别的敏感数据模式，以及在发现匹配数据时要执行的自动化操作。此外，用户还可以受益于更新后的界面，以准确跟踪和监控已启动的扫描。

改进的着陆页界面

敏感数据扫描器的着陆页现在包含一个进度条，用作每次一次性扫描所扫描数据集的状态摘要。彩色编码的进度条会根据符合特定条件的数据集数量相对于队列中待扫描数据集总数的比例进行填充：

  • 蓝色： 当前正在扫描或等待扫描的数据集。
  • 橙色： 符合某个条件的数据集。
  • 绿色： 不符合任何条件的数据集。
  • 红色： 扫描失败或被跳过的数据集。
  • 灰色： 已取消的扫描。

此外，您可以通过选择每个扫描项右侧的下拉箭头，轻松查看特定扫描下每个数据集的分类情况。

一次性扫描的详细视图，显示文件的不同分类

估算您的扫描计算时间

用户还可以查看 Sensitive Data Scanner 排队等待扫描的数据集数量，从而估算扫描可能需要的时间，并在必要时鼓励审查扫描范围。

设置扫描的最后一步会显示将要扫描的数据集数量，并为用户提供创建一次性扫描或定期扫描的选项。

使用 AIP 生成正则表达式匹配条件

您现在可以使用 AIP（在启用了 AIP 的堆栈上）生成正则表达式匹配条件，而无需自己编写正则表达式。要使用此功能，请提供描述所需数据格式的自然语言提示，然后选择 生成 在 选择匹配条件 步骤（创建一次性扫描时）。

用户使用 AIP 为电子邮件地址生成正则表达式匹配条件

有关更多信息，请查阅 Sensitive Data Scanner 文档。

针对 Python 仓库的改进检查现已生效

发布日期：2023-09-19

我们针对 Foundry 堆栈上的 Python 仓库进行了有针对性的改进，更新了检查性能。值得注意的是，内部堆栈上所有 Python 作业的平均 P95 检查完成时间（从头到尾运行检查所需的时间）从 2023 年 3 月的 2 分 15 秒降至 2023 年 6 月的大约 1 分 15 秒，降幅达 44.4%。

更快速检查的改进

我们近期为提高检查效率所做的工作包括以下更新。

Conda 包的 Zstandard (ZST) 压缩

此前，“gzip 压缩”，现已实现 ZST，从而为 conda-pack ↗实现显著更快的压缩和解压缩，这对于运行 condaPackRun 和/或 condaPackTest 检查中的任务至关重要。

一张图表，显示平均 P95 检查完成时间（从 2023 年 3 月的 2 分 15 秒降至 2023 年 6 月的约 1 分 15 秒）

Jemma 管理的缓存不再被双重压缩

Jemma（我们的检查运行器）不再对文件进行双重压缩。现在文件使用 ZST 压缩，从而减少了资源使用和 CPU 时间。

避免双重压缩并使用 zst 压缩缓存目录可显著提高压缩速度（20MB/s → 80MB/s）。下图显示了压缩缓存目录并存储压缩文件所需的时间。

更快的 Gradle Conda 任务

以下常见任务将通过利用基础 Docker 镜像并在指定位置更新 Gradle 任务来更快运行：

  • condaInfo：将 Conda 安装程序打包到用于运行检查的 Docker 镜像中。
  • setupPythonEnv：将支持的 Python 版本（主版本和次版本）的 Conda 安装程序打包到用于检查的 Docker 镜像中。
  • vscode：从 Gradle 的 @InputFiles to @Input 切换，将任务执行时间从 13 秒缩短至不到 1 秒。

Conda 包的自定义 Gradle 缓存

使用自定义 Gradle 缓存来避免导致 Conda 包双重压缩的低效问题，从而减少计算时间浪费并提升整体性能。此改进还受益于 artifacts 缓存布局能够根据使用情况刷新条目 TTL 的能力。

下面是一张来自早期原型的图表，显示了使用我们的自定义缓存机制运行任务所需的时间。请注意，随着环境规模增大（例如在建模相关的包中），改进效果会更加显著。
