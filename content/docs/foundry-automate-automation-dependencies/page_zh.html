自动化依赖项

Foundry Automate 中的自动化依赖项功能允许您安排自动化在父自动化完成后运行。此功能旨在通过自动触发后续流程来简化工作流，无论父自动化成功还是失败。

有两种自动化依赖项，其区别在于是否配置了对象集条件：

  • 无动态对象集条件： 每次父自动化完成时，依赖的自动化都会执行，无需人工干预。不会向其效果传递任何对象集。
  • 具有对象集条件： 将对象集条件（已添加到集合的对象、 已从集合中移除的对象或 对所有对象运行）与父依赖项配对。每次父自动化完成时都会评估该条件。其行为类似于 定时监控，区别在于每项 依赖自动化的 评估在父自动化完成时发生，而不是按固定计划进行。

举个例子，设想这样一个场景：您有一个用于处理传入数据文件的自动化。该自动化完成后，无论其是成功处理了所有文件还是遇到了错误，均可触发依赖的自动化来通知数据团队并记录结果以供进一步分析。此外，您还可以指定对象集条件，以确保仅在满足特定标准（例如出现严重错误）时才发送通知。

设置自动化依赖

按照以下步骤设置自动化依赖。

  1. 定义父自动化： 首先定义父自动化，它将在完成后触发依赖的自动化。
  2. 配置依赖的自动化： 设置依赖的自动化，并指定自动化继续执行所需满足的任何其他对象集条件。
  3. 关联自动化： 将依赖的自动化关联到父自动化，以确保其在父自动化完成后触发。
  4. 配置等待时间（可选）： 启用 配置等待时间 切换开关，以在父自动化完成后、依赖的自动化被评估之前添加延迟，延迟时长以分钟和秒为单位指定。

自动化完成后始终触发效果

配置对象集条件后，您可以启用 自动化完成时始终触发效果 设置，在 Automate 界面中描述为 无论对象条件是否已触发，关联的自动化完成时都会执行效果。此设置仅在配置了对象集条件时才适用；对没有对象集条件的依赖项无效。

该设置决定当父级自动化完成、但自上次父级自动化完成以来没有对象匹配对象集条件时会发生什么：

  • 关闭时： 不会发生任何事情。只有当对象匹配条件时才会执行效果。
  • 开启时： 无论对象条件是否被触发，效果都会执行。结果取决于效果的输入形式：
    • 没有动态对象输入的效果（例如静态通知）会运行一次。
    • 针对每个对象运行的效果不会运行任何内容，因为没有对象匹配。
    • 对所有对象运行单次执行的效果会运行一次，并传入一个空对象集。

注意事项

以下是设置自动化依赖项时需要注意的一些事项：

  • 在成功或失败时触发： 当父自动化完成时，依赖的自动化即会触发，无论父自动化成功还是失败。您无法将触发限制为仅在父运行成功或仅在父运行失败时触发，因此请相应地规划您的自动化逻辑。效果随后是否执行取决于对象集条件以及 自动化完成时始终触发效果 设置。
  • 对象集条件： 确保为依赖的自动化指定的所有对象集条件均已正确定义，以避免出现意外行为。

通过利用自动化依赖关系，您可以创建更高效、更灵敏的工作流，以适应先前流程的结果。

已知限制

自动化依赖关系存在以下限制：

  • 仅支持单一依赖： 自动化依赖关系仅支持单一依赖（父级 → 子级）。不支持多级链（父级 → 子级 → 孙级）。
  • 需要支持项目范围划分的对象类型： 受监控的对象类型必须支持项目范围划分。
  • 在分支上不受支持： 在分支上构建自动化时，无法使用自动化依赖关系条件。有关自动化分支支持的更多信息，请参阅 分支自动化。
