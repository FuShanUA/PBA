导出

Data Connection 支持导出 数据集 和 流 从 Foundry 到外部系统。这在多种场景下都很有用：

  • 在 Foundry 中使用数据管道清洗和转换的数据可以同步到数据仓库或数据湖等系统。此模式在 《Palantir Foundry 如何为您的数据平台提供动力》↗.
  • 使用以下方式创建的机器学习模型的推理结果 批量部署 可以导出到其他系统，以便在整个组织内实现 ML 项目的落地应用。
  • 在以下系统中从最终用户处捕获的运营数据 本体论 可以写入其他系统，以便在 Foundry 之外进行分析。

导出会创建另一个可以访问、保留和共享数据的位置。在配置导出之前，请确认目的地和接收方支持经批准的用途，尽量减少导出的字段，并应用适当的访问限制。查看 实践中的隐私与公民自由 以获取有关用途限制和负责任共享的指导。

Data Connection 导出尚未支持所有源类型。请查看 源类型概览 文档中列出的各个源类型页面以确认可用性。每个源类型页面将列出 文件导出, 流式导出, 表导出，或 旧版导出任务 支持（如果导出功能可用）。例如， Amazon S3 源类型支持 文件导出 而 BigQuery 源需要使用导出任务。

一些尚不支持文件、流式或表导出功能的源可能支持 旧版导出任务配置。对于已实现更新版导出功能的源类型，不再推荐使用导出任务。

更新后的导出行为

在 2025 年 6 月之前，如果构建期间没有新文件或新行需要导出，导出会被标记为 failed 。从 2025 年 6 月起，如果没有新文件或新行需要导出，导出将被标记为 success。此变更可能会影响依赖于原始失败行为的工作流；用户需要相应地调整受影响的工作流。

导出类型

导出的行为取决于目标系统可接受的数据类型。

导出类型摘要
文件导出用于导出到无 schema 的系统。数据集中的原始文件会按计划复制并写入目标系统。
流式导出用于持续导出到支持事件流的系统。Foundry 流中的记录会持续推送到目标系统。
表导出用于导出到有 schema 的系统。数据集中的行会按计划根据所选的 导出模式.

文件导出

支持文件导出的系统示例包括 S3.

文件导出会将所选 Foundry 数据集中的文件写入配置的目标位置。默认情况下，只有自上游数据集上最后一次成功导出的事务以来被修改过的文件才会被写入。这意味着，如果某个文件在给定事务中未被更新，则在后续任何计划或手动运行下游导出时，都不会重新导出该文件。

如果必须重新导出整个数据集，请在同一源上设置新的导出，或确保上游转换覆盖所有必须导出的文件。

默认情况下，如果目标位置已存在同名文件，导出作业将使用导出的数据覆盖该文件。此行为可能因源类型而异。为避免意外覆盖存储在目标系统中的数据，我们建议创建一个专用子文件夹，用于存放从 Foundry 导出的数据。

流式导出

只要导出作业在 Foundry 中运行，导出到流式目标的操作就会持续将记录流式传输到目标。如果作业停止并重新启动，它将从上次中断的位置继续流式传输记录。

以下源类型支持流式导出：

  • Amazon Kinesis
  • Amazon SQS
  • Google Pub/Sub
  • Kafka
  • PostgreSQL
  • Solace

导出到 Kafka 时，您可以启用对流记录的 Base64 解码。请查看完整的 Kafka 连接器文档 以了解有关 Kafka 导出的更多信息。

流式导出重放行为

在配置导出到流式目标时，您必须指定在 Foundry 中重放（replay）流时的所需行为。通常，流会在 重放 对处理逻辑进行破坏性更改之后进行。在这种情况下，之前已处理的记录必须使用新逻辑以下列方式之一重新处理：

  • 导出重放的记录： 在重放流时重新导出所有记录。之前已导出的记录将被再次导出，外部系统必须配置为能够处理重复数据。

  • 不导出重放的记录： 暂停导出，直到重放的偏移量与导出作业中的最新偏移量匹配。由于重放的流之间的偏移量不保证匹配，此选项通常会导致一定数量的记录被丢弃而永远不会被导出。

表导出

表导出自 2024 年 6 月起正式可用，但可能并非对所有源类型都可用。如果可用，建议使用表导出而非 导出任务。要检查某个源类型是否支持表导出，请在 Data Connection 中查看其源页面上的 Table exports 标签。您也可以查看相应源类型的文档页面。

表导出允许导出到包含具有已知架构（schema）的表格数据的系统，其中外部目标架构与您希望导出的 Foundry 数据集的架构相匹配。表导出将执行特定于系统的 INSERT 语句或等效的 API 调用，按照下文所述的所选表导出模式将行写入目标表。

所选的 导出模式 指定在表导出期间如何导出数据。以下导出模式适用于所有表导出，并在 Data Connection 的导出设置页面中进行了说明。

表导出的特殊注意事项

  • 从 Foundry 导出的数据集必须与外部源 1:1 匹配，包括完全一致的列名（区分大小写）和数据类型。例如，导出 COLUMN_ABC 类型为 LONG 到目标位置，而该处 COLUMN_ABC 的类型为 STRING 将在运行时失败。
  • 设置表导出时，请确保 DATABASE, SCHEMA日 TABLE 字段在源需要时已填写。缺少其中任何字段都会导致导出在运行时失败。同样，包含不必要的字段也可能导致失败。为获得最高可靠性，请使用 explore source 和自动填充来选择源中的目标位置。
  • 使用 ）或您的代理网络（如果使用 进行表导出时，代理必须运行在 Linux 主机上。不支持使用 Windows 代理运行表导出。
  • 导出到表格目标位置的数据集，其底层文件必须为 Parquet 格式。CSV 及其他支持 schema 的文件类型将无法导出。
  • 目标表必须已存在于源系统中；Foundry 不会自动创建该表。
  • 使用会执行截断（truncation）的导出模式时，在 Foundry 源配置中输入的凭据必须具有在外部系统中截断该表的权限。
  • Array, Map日 Struct 类型不支持导出。如果您要导出的数据集包含类型为 Array, Map，或 Struct的列，导出将失败。

INSERT 语句示例

以下示例提供了有关表导出所用语法的更多信息。如果您的源系统不支持此格式的 INSERT 语句，则 INSERT 语句将在运行时失败。

假设我们的源系统中存在一个 target_table ，其 schema 与 Foundry 中相应的数据集相同。外部源与 Foundry 之间的列名和数据类型都必须匹配。以下是 Foundry 中数据集的模拟示例：

column1column2column3
value1value2value3
value4value5value6
value7value8value9

直方图 INSERT 单行数据的 INSERT 语句遵循以下一般格式：

INSERT INTO target_table (column1, column2, column3) VALUES ('value1', 'value2', 'value3');

根据源类型的不同，insert 语句将应用于一行或多行数据。例如，Snowflake 支持 batch inserts 因此允许一次写入多行数据。

INSERT INTO target_table (column1, column2, column3) VALUES ('value1', 'value2', 'value3'), ('value4', 'value5', 'value6'), ('value7', 'value8', 'value9');

相比之下，像 Apache Hive 这样的源对 batch inserts 的支持有限，将通过三个连续的 insert 语句执行导出。

INSERT INTO target_table (column1, column2, column3) VALUES ('value1', 'value2', 'value3');
INSERT INTO target_table (column1, column2, column3) VALUES ('value4', 'value5', 'value6');
INSERT INTO target_table (column1, column2, column3) VALUES ('value7', 'value8', 'value9');
TRUNCATE TABLE 语句示例

诸如 Full dataset with truncation 之类的导出选项会先截断外部源中的目标表，然后运行 insert 语句。实现此操作的实际代码如下例所示：

TRUNCATE TABLE table_name;
INSERT INTO target_table (column1, column2, column3) VALUES ('value1', 'value2', 'value3');

如果需要更具体的方言，我们建议使用 Foundry 的 基于代码的连接选项 例如 外部转换.

多线程表导出

某些源类型支持多线程表导出，这可以提升导出性能。使用多线程导出时，Foundry 会在目标系统中创建一个临时暂存表以保持原子性。数据将并行写入该暂存表，然后在导出完成后复制到最终目标表。导出结束后，暂存表会被自动删除。

使用多线程导出时，凭据必须具有对目标系统中表的 CREATE, READ, UPDATE日 DELETE 权限。

如果希望用户在每次运行预览前手动确认，请开启 和 代码仓库 是 Foundry 用于构建数据转换管道的工具；这两个应用程序都应提供你为导出准备数据所需的完整工具，包括作业可扩展性、监控、版本控制，以及根据需要编写任意逻辑的灵活性。

控制输出文件结构

包含结构化数据的 Foundry 数据集默认将其底层文件存储在 spark/ 目录下。如果你需要文件在导出时落在特定的目录结构中——例如按日期分区组织——你可以使用 Python 转换 在导出之前以所需的布局写入数据集。

from transforms.api import transform, Input, Output
import datetime
import shutil

@transform(
    output_dataset=Output("/path/to/output/dataset"),
    input_dataset=Input("/path/to/input/dataset"),
)
def compute(input_dataset, output_dataset):
    dt = datetime.date.today().strftime("%Y%m%d")
    for file_status in input_dataset.filesystem().ls():
        relative_path = file_status.path[len("spark/"):] if file_status.path.startswith("spark/") else file_status.path
        with input_dataset.filesystem().open(file_status.path, "rb") as in_f:
            with output_dataset.filesystem().open(f"data_dt={dt}/{relative_path}", "wb") as out_f:
                shutil.copyfileobj(in_f, out_f)

使用此转换后，导出的数据集将包含位于如下路径的文件 data_dt=20240101/part-00000-xxx.parquet 而非 spark/part-00000-xxx.parquet。将文件导出配置为使用此转换后的数据集作为要导出的数据集。首次构建后，选择 应用 schema 以使其在 Foundry 中可作为表格数据查看。
