本体论角色迁移 [旧版]

遗留版

本页面描述的是一个旧版流程，已不再是本体论资源权限管理的最新方法。本体论资源现在可以 使用 Compass 文件系统进行权限管理。要进行迁移， 请查看迁移指南。

本体论角色 是一种旧版授权模型，用于本体论资源，取代了 数据源派生的权限。本体论角色适用于对象类型、关联类型和操作类型，这些统称为“本体论资源”。使用本体论的最新功能（包括共享属性类型、接口等）需要本体论角色。默认情况下，自 2023 年 9 月以来创建的所有新租户均已使用本体论角色。

本体论角色允许您直接在每个本体论资源及其元数据上授予角色 直接 。所有元数据权限都在 Ontology Manager 中管理。本体论角色允许您将本体论资源（例如 Aircraft 对象类型）与这些资源的 数据 解耦，例如 对象实例 （例如表示为本体论对象的特定飞机）和关联实例；这些数据实例仍由其输入数据源的权限管理。了解更多信息，请参阅 本体论权限.

每个本体论都关联到一个或多个 Foundry 组织.

角色权限的详细信息请参阅 本体论角色文档.

迁移到本体论角色的每个对象类型、关联类型和操作类型，对于有权访问该特定本体论的所有用户都将具有查看权限。因此，该本体论的所有用户都可以访问本体论资源信息。

将本体论资源迁移到本体论角色没有明确的顺序要求，因此可能存在部分对象类型使用 数据源派生的权限，而其他对象类型使用本体论角色的情况。因此，就本次迁移而言，我们将 able to edit an object type 定义如下：

  • 使用数据源派生权限的对象类型： 用户对该对象类型的输入数据源具有 Editor 权限。
  • 使用本体论角色的对象类型： 用户对该对象类型的输入数据源具有 Ontology Editor 权限，且不需要输入数据源上的任何权限。此权限仅允许编辑本体论资源及其元数据，不会授予数据/数据源本身的任何权限。对对象 数据 (not 元数据）的访问仍由输入数据源上授予的权限管理。

迁移到本体论角色

如果您的租户已启用本体论角色，但您尚未将您拥有的本体论资源迁移到角色授权模型，您将在 Ontology Manager 中看到提示您进行迁移的横幅。 或者，在查看本体论资源表格时，您可以筛选出您拥有的、仍在使用“与支撑数据源相同权限”的资源。

本体论角色尚未对所有 Foundry 租户开放。如果您无权使用本体论角色，请联系 Palantir Support。

前提条件

要执行迁移，用户必须具有以下权限：

  1. 在 Foundry 本体论中进行更改的权限。

  2. 对每个单独资源的以下权限：

    • 对于对象类型，用户必须对输入数据源具有 Owner 权限。
    • 对于一对多关联类型，用户不需要额外权限。只需对关联类型中引用的两个对象类型具有 Viewer 权限，并且用户必须是关联类型本身或本体论级别的 Owner 。
    • 对于多对多关联类型，用户还必须对关联类型的输入数据源具有 Owner 权限。
    • 操作类型不需要额外权限。

迁移到本体论角色后， 修改操作类型 需要额外权限。您需要对操作类型所编辑的任何对象类型以及操作类型本身具有权限，才能使用角色修改操作类型。

迁移通知

迁移到本体论角色是通过以下方式管理的 升级助手。一个专门的升级助手任务会显示必须迁移的本体论资源列表，以及有权执行迁移的负责人。从升级助手打开某个资源会将用户引导至该资源的 安全性 选项卡，以便在 Ontology Manager 应用程序中进行迁移。

如果用户有权设置本体论角色，尚未迁移的本体论资源将显示在迁移界面的 安全性 选项卡中，以便首次设置本体论角色。本体论资源迁移完成后，本体论角色选择器将显示在 安全性 选项卡下，并且可以由 Ontology Owners.

使用 Ontology Manager 进行迁移

有两种方法可以将本体论资源（对象类型、操作类型、关联类型）迁移到角色： 批量迁移 本体论资源，或者对所有本体论资源进行 逐一迁移 。

批量迁移本体论资源

您可以将本体论资源批量迁移到角色。请先参阅 前提条件 列表。每次最多只能迁移 500 个资源。

要进行批量迁移，请前往 高级 在 Ontology Manager 中，并选择 继续使用迁移助手 （位于“迁移”部分）。

迁移向导将显示以下步骤。

  1. 选择资源： 选择您希望应用相同角色的所有对象类型、关联类型或操作类型。下图显示了迁移向导中选择资源的界面：

  1. 相关资源： 仅当存在可迁移的相关资源（关联类型或操作类型）时，才会显示此步骤。
  2. 分配角色： 您可以手动设置组/用户以及要分配给这些对象类型的默认角色。目前角色迁移工具无法批量建议角色。我们强烈建议在授予角色时使用 用户组 over 用户 。在迁移操作类型时，仅向对所引用的对象类型以及操作类型部署的所有用例有充分了解的用户授予权限。
  3. 摘要： 查看摘要、确认迁移的影响，并完成迁移以应用角色。
迁移到本体论角色是不可逆的

当您确认迁移的影响时，即表示您确认之前从支撑数据源派生的权限将被新分配的角色授权覆盖，并且该迁移是不可逆的。

批量迁移的例外情况

某些操作类型无法在没有额外步骤的情况下进行批量迁移。

在以下情况下，操作类型无法迁移到角色：

  • 该操作类型没有检查当前用户权限的提交条件。
    • 解决方案：在 Ontology Manager 中该操作类型的 安全与提交标准 选项卡（位于 提交标准 部分）中添加基于当前用户的条件，并在重新尝试迁移之前保存到本体论。
  • 该操作类型由函数支撑，必须在迁移之前使用 @edits decorators 重新发布。
    • 解决方案：请参阅 装饰器 documentation.

要解决这些问题，请前往 操作类型 页面并筛选为 与支撑数据源权限相同，这将显示因问题而尚未迁移的操作类型。解决所有未解决的问题，然后再次对剩余的操作类型进行批量迁移。

对所有本体论资源进行逐一迁移

在 Ontology Manager 主页中，选择您要迁移的本体论资源（对象类型、关联类型或操作类型），并按 Security setup to Same permissions as backing datasource 以及按 permissions = owner.

进行筛选。选择要迁移的实体，然后选择 迁移到角色 （位于页眉上）或 开始使用角色 （位于“安全”选项卡上）。

迁移向导将显示两个建议的角色选项： 数据源角色 和 本体论管理员和数据源角色。这些选项允许用户使用和配置与其现有本体论设置相一致的角色。选择其中一个选项会预填建议角色列表；这些角色稍后可以更改。

  • 数据源角色： 此选项会将在输入数据源上拥有 Editor or Owner 角色的所有用户和用户组添加进来。
  • 本体论管理员和数据源角色： 此选项会添加当前可以基于 数据源派生的权限修改给定本体论资源的所有用户。这些用户属于 Ontology Administrators 用户组，并且在输入数据源上拥有 Editor 或 Owner 角色。

例外情况

在以下情况下，您可能无法尝试将操作类型迁移到角色：

  • 该操作类型没有检查当前用户权限的提交条件。
    • 解决方案：在 Ontology Manager 中该操作类型的 安全与提交标准 在 Ontology Manager 中操作类型的 提交标准 部分）中添加基于当前用户的条件，并在重新尝试迁移之前保存到本体论。
  • 该操作类型由函数支撑，必须在迁移之前使用 @edits decorators 重新发布。
    • 解决方案：请参阅 装饰器 documentation.

如果不再需要某些本体论资源怎么办

如果您不再需要某个需要操作的本体论资源，可以使用 本体论清理工具删除该资源。此工具可根据一组标准（例如，数据源是否已被删除、弃用日期是否已过、索引是否失败、是否正在使用本体论角色等）帮助您识别哪些对象类型可以安全删除。

迁移函数支撑的操作类型

函数支撑的操作类型需要先迁移其支撑的函数。Foundry 会尝试自动迁移函数，从而允许您同时迁移操作类型。但是，某些函数可能无法自动迁移，需要在函数中手动声明所编辑的对象类型。将操作类型迁移到本体论角色后，如果您的函数支撑操作出现失败，请查看 FAQ 部分。

迁移常见问题

对象感知应用会有任何变化吗？

用户可能会在 本体论管理器 中访问到他们之前无法查看的对象类型和关联类型的元数据，因为他们此前没有 Viewer 对输入数据源的访问权限。这并不意味着他们将获得输入数据源中数据的访问权限，这些数据始终由相应数据源上的角色管控。他们能够看到哪些元数据的具体细节由其 本体论角色.

决定。当对象类型迁移后，Object Explorer 也会更新编辑对象视图的权限检查。在对象类型迁移之前，用户需要属于 Object View Administrators 组并拥有 Editor 对输入数据源的访问权限才能编辑对象视图。对象类型迁移完成后，Object Explorer 将只检查用户是否对该对象类型本身拥有 Ontology Editor 权限。

如何解决迁移后失败的函数支撑操作？

要解决此错误，请按照 函数文档.
