关联类型

一个 关联类型 是两个对象类型之间关系的模式定义。一个 关联 是指同一本体论中两个对象之间该关系的单个实例。

例如，在 Ontology Manager 中，您可以在 Employee 对象类型和 Company 对象类型之间创建一个关联类型，用于定义 Employee 和 Employer之间的关系。一个关联是指 Employee → Employer 关联类型的单个实例，比如虚构员工“Melissa Chang”与其雇主“Acme, Inc.”之间的关系。

同样，在 Ontology Manager 中，您可以在 Flight 对象类型和 Aircraft 对象类型之间创建一个关联类型，用于定义 Scheduled Flight 和 Assigned Aircraft之间的关系。一个关联是指 Scheduled Flight → Assigned Aircraft 关联类型的单个实例，比如“JFK → SFO 24-02-2021”与分配给它的飞机“Boeing 737-123”之间的关系。

关联也可以存在于相同类型的两个对象之间。关联类型 Direct Report ↔ Manager 可以定义在 Employee 对象类型与其自身之间。

请注意，不支持跨不同本体论的对象类型之间的关联。在这种情况下，您可能更倾向于利用共享本体论。

方向性

关联类型是双向的：它始终具有两 端，其所关联的两个对象类型各对应一侧。关联类型的每一侧都可以独立遍历，并拥有各自的显示名称和 API 名称。例如，一个 Flight ↔ Aircraft 关联类型包含一个 Flight 侧和一个 Aircraft 侧。在代码中，调用 flight.assignedAircraft.get() 会遍历该关联类型的 Aircraft 侧，以获取分配给某个航班的飞机，而调用 aircraft.flights.all() 会遍历 Flight 侧，以获取分配给该飞机的航班。

注意

在两个对象类型之间创建单个关联类型并不会隐式创建第二个反向关联类型。相反，该单个关联类型已经通过其两侧支持双向遍历，因此无需单独定义一个从 Aircraft 到 Flight 的关联类型，以及另一个从 Flight 到 Aircraft 的关联类型来表示相同的关系。

您可以在相同的两个对象类型之间定义多个不同的关联类型，但每个关联类型都代表现实世界中的一种独立关系，而非现有关系的反向。例如，除了表示所分配飞机的 Flight ↔ Aircraft 关联类型之外，您还可以定义第二个独立的 Flight ↔ Aircraft 关联类型来表示计划维护记录。每个关联类型都需要唯一的 API 名称 在其两侧，以便应用程序能够区分这些关系。

支撑本体论的概念在数据集的结构中有着类似的概念。本体论中关联类型的定义类似于两个数据集之间的连接，而关联的定义则类似于一行与另一个数据集中同一行的字段相连接。例如，您可以将 Employee 数据集与 Company 数据集连接起来，以探索 Employees 及其 Employers之间的关系。在连接后的数据集中，将“Melissa Chang”与其雇主“Acme, Inc.”连接起来的单独一行表示一个关联。

Foundry 本体论并非一个抽象的数据模型，而是将每个本体概念映射到组织的实际数据，使这一数据资产能够驱动现实世界的应用程序。通过在本体论管理器中向关联类型所引用的对象类型添加支撑数据源，可以在用户应用程序中创建和显示关联。当关联类型中的对象类型以多对多基数相互关联时，数据源支撑的是关联类型本身。要创建类型为 Employee → Employer的关联，组织将把支撑数据源添加到 Employee 和 Company 对象类型，并将其员工目录和其他企业数据接入本体论。
