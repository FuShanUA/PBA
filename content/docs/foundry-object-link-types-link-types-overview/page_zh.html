关联类型

A 关联类型 是两种对象类型之间关系的模式定义。 链接 指的是同一本体论中两个对象之间该关系的单个实例。

例如，在本体论管理器中，您可以在 Employee 对象类型和 Company 对象类型之间创建关联类型，以定义 Employee 和 Employer之间的关系。关联指的是 Employee → Employer 关联类型的单个实例，例如虚构员工“Melissa Chang”与其雇主“Acme, Inc.”之间的关系。

类似地，在本体论管理器中，您可以在 Flight 对象类型和 Aircraft 对象类型之间创建关联类型，以定义 Scheduled Flight 和 Assigned Aircraft之间的关系。关联指的是 Scheduled Flight → Assigned Aircraft 关联类型的单个实例，例如“JFK → SFO 24-02-2021”与其指定飞机“Boeing 737-123”之间的关系。

关联也可以存在于两个相同类型的对象之间。关联类型 Direct Report ↔ Manager 可以在 Employee 对象类型与其自身之间定义。

不支持在不同本体论的对象类型之间创建关联。在这种情况下，您可能更倾向于使用共享本体论。

方向性

关联类型是双向的：它始终有两个 侧，分别对应它所关联的两种对象类型。关联类型的每一侧都可以独立遍历，并拥有自己的显示名称和 API 名称 (TSv1)。例如，一个 Flight ↔ Aircraft 关联类型包含一个 Flight 侧和一个 Aircraft 侧。在代码中，调用 flight.assignedAircraft.get() 会遍历关联类型的 Aircraft 侧以检索分配给某个航班的飞机，而调用 aircraft.flights.all() 会遍历关联类型的 Flight 侧以检索分配给该飞机的航班。这些示例使用 TSv1 语法；其他语言遍历的是相同的两侧。

在两种对象类型之间创建单个关联类型并不会隐式地创建第二个反向关联类型。相反，该单个关联类型已经通过其两侧支持双向遍历，因此无需分别定义一个从 Aircraft to Flight 出发的关联类型和另一个从 Flight to Aircraft 出发的关联类型来表示同一关系。

您可以在相同的两种对象类型之间定义多个不同的关联类型，但每个关联类型代表的是独立的现实世界关系，而不是现有关系的反向。例如，除了表示指定飞机的 Flight ↔ Aircraft 关联类型之外，您还可以定义第二个独立的 Flight ↔ Aircraft 关联类型来表示计划维护记录。每个关联类型的两侧需要唯一的 API 名称 ，以便应用程序能够区分这些关系。

本体论背后的概念与数据集结构中的概念有相似之处。本体论中关联类型的定义类似于两个数据集之间的连接（join），而关联的定义类似于一行数据与另一个数据集中同一行的字段相连接。例如，您可以将 Employee 数据集与 Company 数据集进行连接，以探索 Employees 与其 Employers之间的关系。在连接后的数据集中，将“Melissa Chang”与其雇主“Acme, Inc.”连接起来的一行即代表一个关联。

Foundry 本体论并非抽象的数据模型，而是将每个本体论概念映射到组织的实际数据，使这一数据资产能够为现实世界的应用程序提供支持。通过在本体论管理器中为关联类型所引用的对象类型添加支撑数据源，可以在用户应用程序中创建和显示关联。对于对象类型之间以多对多基数关联的关联类型，数据源直接支撑关联类型本身。要创建 Employee → Employer类型的关联，组织需要为 Employee 和 Company 对象类型添加支撑数据源，并将其员工目录和其他企业数据接入本体论。
