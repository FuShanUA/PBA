使用 Iceberg 的增量 Python 转换

本页面提供了在 Iceberg 表上使用 增量 Python 转换 的语法介绍。请参阅 使用 Iceberg 表进行增量处理 ，以了解增量处理 Iceberg 表的概念性概述。

在构建使用 Iceberg 表的增量转换时，需要注意以下三个关键方面：

  1. 添加 增量装饰器和读取模式
  2. 使用 增量运行时对象
  3. 使用 增量计算逻辑

增量装饰器和读取模式

通过在转换定义的正上方添加增量装饰器，可以将转换设置为增量运行。

以下标准 @incremental 参数与 Iceberg 表的使用相关：

参数描述
v2_semantics必须为 True。Iceberg 表输入和输出仅在 v2 增量语义下受支持。
require_incremental默认值为 False。如果 True，则当转换无法以增量方式解析时，将直接失败而非回退到完整的非增量读取。
semantic_version每当您更改转换逻辑而导致现有输出失效时，请增加此数字。更改该数字会强制下一次运行采用非增量方式。
snapshot_inputs完整重写不会使输出失效的输入名称，例如参考表。这些输入始终会被完整读取。

此外，您还可以链式连接 .with_table_incremental_options(table_read_mode="...") 传递给装饰器，以控制转换能够增量消费哪些类型的上游变更：

table_read_mode行为
append_only
（默认）		转换在读取范围内对追加和替换（压缩）快照进行增量运行。如果读取范围内存在覆盖或删除快照，则转换无法以增量方式解析，将以非增量方式构建或失败，具体取决于您的 require_incremental 设置。
changelog转换在读取范围内对追加、替换、覆盖和删除快照进行增量运行。需要使用变更日志读取模式才能调用 .changelog() API。变更日志模式仅适用于 Spark 转换。

with_table_incremental_options 需要 transforms-tables 版本 0.1390.0 或更高版本。

增量运行时对象

Foundry 提供以下运行时对象，用于在转换中增量读取和写入 Iceberg 表：

  • 单节点 API： IncrementalIcebergInput, IncrementalIcebergOutput
  • PySpark API： IncrementalTableTransformInput, TableTransformOutput

增量计算逻辑

在增量运行中，增量输入运行时对象默认提供“新增”的行。若要读取其他内容，请调用其他方法，例如 .changelog().

1
added_rows = source.polars()

1
added_rows = source.arrow()

1
added_rows = source.pandas()

1
2
added_rows = source.dataframe()
changelog = source.changelog(["id"])

您可以使用这些运行时对象，根据需要编写增量计算逻辑，无论是写入新增的行、应用 变更日志，还是使用原生 Iceberg 操作来执行 upsert 和删除。请参阅 增量代码示例 ，以了解各种增量转换。
