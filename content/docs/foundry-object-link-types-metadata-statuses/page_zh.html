状态

本体论中的每个对象类型、属性、关联类型、操作或接口都有一个 状态 用于指示开发状态。本体论资源的状态可以是激活、实验性、已弃用或示例;对象类型还可以被归类为 已提升。状态元数据可帮助编辑本体论的用户了解哪些资源正被用户应用程序积极依赖。这些状态可在 Object Explorer、 Object Views和 Workshop 中查看,以提供有关哪些对象类型旨在用于用户应用程序的更多信息。

状态可以取以下五个值之一:

可用状态值

  • 已提升(仅限对象类型): 表示该对象类型是经本体论所有者审核的核心可信资源。 Promoted 对象类型会继承与 active 对象类型类似的针对 API 名称的保护。
  • 激活: 表示该资源正在面向用户的应用程序中被积极使用,且不会在 Ontology Manager 中对其进行重大破坏性更改。
  • 实验性: 表示该资源仍在开发中。可能会对其进行更改,导致该实验性项目在面向用户的应用程序中不可用。
  • 已弃用: 表示该资源即将被删除。不应在面向用户的应用程序中依赖已弃用的项目。
    • 已弃用的资源还包含以下元数据：
      • 关于其被弃用原因的描述；
      • 预计将其从系统中删除的截止日期；以及
      • 旨在替代已弃用资源的资源。
  • 示例： 表示该资源已作为示例安装。示例资源是概念性的，仅适用于培训或早期阶段的探索性使用。示例 并非 旨在用于生产工作流。

Promoted 状态（仅限对象类型）

对象类型支持一种特殊的 promoted 状态，以表示在本体论中具有更高的信任度和正式地位。此状态以新的紫色对勾图标表示，可帮助用户将核心的、可复用的对象类型与更针对特定用例或更具实验性的对象类型区分开来。

该 promoted 状态提供了超越标准 active 状态的显著地位。具有此状态的对象类型应被视为“核心”资源，须达到高标准并由中央团队管理。 Promoted 对象类型会继承与 active 状态类似的运维保护措施，例如删除限制。

该 promoted 状态的关键特征包括：

  • 范围： 该 promoted 状态仅适用于对象类型。它不可用于属性、关联类型、操作类型或接口。
  • 可见性： 将对象类型的状态设置为 promoted 会自动将其可见性设置为 prominent，从而提高其在整个平台上的可发现性。用户可以选择将该对象类型的所有属性移动到 active 状态。
  • 权限：
    • 仅在本体论级别拥有 Ontology Owner 角色的用户才能直接应用 promoted 状态。
    • 其他用户必须提交提案，由本体论级别的 Ontology Owner 进行审核和批准，才能应用该状态。

不允许的操作

鉴于应用程序依赖于本体论资源，当资源处于某种状态时，将不允许执行若干可能具有破坏性的操作，该状态为 active：

  • 该资源无法被删除。资源状态必须为 experimental 或 deprecated 才能被删除。
  • 处于活动状态的资源无法更改其 API 名称。若要更改 API 名称，资源必须被标记为 experimental。

编辑状态

默认情况下，任何新的本体论资源都将被赋予 experimental 状态。若要更改状态：

  1. 选择当前状态旁边的下拉菜单。
  2. 选择新状态。

将资源更改为 deprecated 状态时，系统将提示您：

  • 填写关于其为何被弃用的描述，
  • 输入您预计将其从系统中删除的截止日期，以及
  • （可选）选择一个资源，用于替代您正在弃用的资源。

这些状态可在 Object Explorer、Object Views 和 Workshop 中查看，以提供更多关于哪些对象类型适用于用户应用程序的信息。

Ontology Manager 可确保对象类型与其相关属性或关联类型之间的状态一致性。例如，如果对象类型从 active 更改为 experimental，其所有属性也将被标记为 experimental 。

  • 如果关联类型中至少有一个对象类型更改为 experimental，则该关联类型将自动更改为 experimental。
  • 如果关联类型中至少有一个对象类型更改为 example，则该关联类型将自动更改为 example。
  • 如果关联类型中至少有一个对象类型更改为 deprecated，则该关联类型将自动更改为 deprecated。

同样的要求也适用于关联类型的外键。在更改属性时，应用程序将更改关联类型的状态：

  • 如果外键属性被更改为 experimental，则其关联类型将被更改为 experimental。
  • 如果外键属性被更改为 example，则其关联类型将被更改为 example。
  • 如果外键属性被更改为 deprecated，则其关联类型将被更改为 deprecated。

应用程序更改状态是为了防止出现无效状态。如果外键属性 experimental 且仍在开发中，则其关联类型不应被标记为 active 并在生产环境中被依赖。相比之下，在将属性标记为 active时，应用程序不会将引用该属性作为外键的关联类型更改为 active，因为外键属性处于生产状态是有效的，而关联类型及其支撑数据源仍在开发中。

属性

当您将对象类型更改为 example，其所有属性也将自动变为 example 。

对象类型中各属性的状态也可以在该对象类型的 属性 页面中批量编辑。 了解有关批量编辑属性的更多信息。

对象类型

各对象类型的状态也可以在主页的对象视图页面中批量编辑：选中要编辑的对象类型的复选框，然后选择表格右上角的 编辑状态 按钮。

故障排除

属性状态与关联类型状态之间的冲突

如果您收到错误 OntologyMetadata:ConflictBetweenLinkTypeStatusAndPropertyTypeStatus，则表示关联类型上的状态与属性上的状态之间存在冲突。例如，如果外键为 deprecated，则引用该外键的关联类型也应为 deprecated。

对象类型状态与关联类型状态之间的冲突

如果您收到错误 OntologyMetadata:ConflictBetweenLinkTypeStatusAndObjectTypeStatus，则表示关联类型上的状态与其关联的某个对象类型的状态之间存在冲突。当根据上表判定对象类型-关联类型组合无效时，就可能发生这种情况。例如， experimental 对象类型不能具有 active 关联类型。
