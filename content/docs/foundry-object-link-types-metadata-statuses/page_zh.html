状态（Statuses）

本体论中的每个对象类型、属性、关联类型、操作或接口都有一个 状态 ，用于指示其开发状态。本体论资源的状态可以是 active（活跃）、experimental（实验性）、deprecated（已弃用）或 example（示例）；对象类型还可以被归类为 promoted（已提升）。状态元数据可帮助编辑本体论的用户了解哪些资源正被用户应用程序积极使用。这些状态可在 对象浏览器, 对象视图日 来运行该专业代码代理。你还可以通过 中查看，以提供更多关于哪些对象类型旨在用于用户应用程序的信息。

状态可以取以下五个值之一：

可用的状态值

  • Promoted（已提升，仅限对象类型）： 表示该对象类型是经过本体论所有者审查的核心、可信资源。 Promoted 对象类型在 API 名称方面继承与 active 对象类型类似的保护。
  • Active（活跃）： 表示该资源正在面向用户的应用程序中被积极使用，并且在 Ontology Manager 中不会进行重大的破坏性更改。
  • Experimental（实验性）： 表示该资源仍在开发中。可能会进行某些更改，导致该实验性项目在面向用户的应用程序中不可用。
  • Deprecated（已弃用）： 表示该资源即将被删除。不应在面向用户的应用程序中依赖已弃用的项目。
    • 已弃用的资源还包含以下元数据：
      • 弃用原因的描述；
      • 预计从系统中删除的截止日期；以及
      • 旨在替换被弃用资源的替代资源。
  • 示例： 表示该资源已作为示例安装。示例资源是概念性的，仅适用于培训或早期的探索性使用。示例 不 旨在用于生产工作流。

Promoted 状态（仅限对象类型）

对象类型支持一种特殊的 promoted 状态，以表示在本体论中更高的信任级别和官方地位。该状态由一个新的紫色对勾图标表示，可帮助用户区分核心的、可重用的对象类型与更针对特定用例或实验性的对象类型。

直方图 promoted 状态提供了超越标准 active 状态的显著性。具有此状态的对象类型应被视为“核心”资源，需保持高标准并由中央团队管理。 Promoted 对象类型继承 active 状态的类似操作保护，例如删除限制。

该 promoted 状态的主要特征包括：

  • 范围： 直方图 promoted 状态仅适用于对象类型。不适用于属性、关联类型、操作类型或接口。
  • 可见性： 将对象类型的状态设置为 promoted 将自动将其可见性设置为 prominent，从而提高其在整个平台中的可发现性。用户可以选择将对象类型的所有属性移动到 active status.
  • 权限：
    • 只有在本体论级别拥有 Ontology Owner 角色的用户才能直接应用 promoted status.
    • 其他用户必须提交提案，由本体论级别的 Ontology Owner 进行审核和批准才能应用该状态。

不允许的操作

鉴于应用程序依赖于本体论资源，当资源具有 active:

  • 状态时，不允许执行以下几项可能具有破坏性的操作。它不能被删除。资源的状态必须为 experimental or deprecated 才能被删除。

编辑状态

默认情况下，任何新的本体论资源都将被赋予 experimental 状态。要更改状态：

  1. 选择当前状态旁边的下拉菜单。
  2. 选择新的状态。

将资源更改为 deprecated 状态时，系统将提示您：

  • 填写弃用原因的描述，
  • 输入您预计将其从系统中删除的截止日期，以及
  • （可选）选择一个旨在替换您正在弃用的资源的替代资源。

这些状态可在 Object Explorer、Object Views 和 Workshop 中查看，以提供有关哪些对象类型旨在用于用户应用程序的更多信息。

Ontology Manager 可确保对象类型与其相关属性或关联类型之间的状态一致性。例如，如果某个对象类型从 active to experimental更改为其他状态，其所有属性都将被标记为 experimental 。

  • 如果关联类型中至少有一个对象类型被更改为 experimental，则该关联类型将自动更改为 experimental.
  • 如果关联类型中至少有一个对象类型被更改为 example，则该关联类型将自动更改为 example.

关联类型的外键同样需要满足这些要求。更改属性时，应用程序将更改关联类型的状态：

  • 如果某个外键属性被更改为 experimental，其关联类型将被更改为 experimental.
  • 如果某个外键属性被更改为 example，其关联类型将被更改为 example.
  • 如果某个外键属性被更改为 deprecated，其关联类型将被更改为 deprecated.

应用程序会更改状态以防止出现无效状态。如果某个外键属性为 experimental 且仍在开发中，则其关联类型不应被标记为 active 并在生产环境中使用。相反，在将某个属性标记为 active时，应用程序不会将引用该属性作为外键的关联类型更改为 active，因为外键属性处于生产环境中是有效的，而关联类型及其支撑数据源仍处于开发中。

故障排除

属性状态与关联类型状态之间的冲突

如果您收到错误 OntologyMetadata:ConflictBetweenLinkTypeStatusAndPropertyTypeStatus时，关联类型的状态与属性的状态之间存在冲突。例如，如果某个外键为 deprecated，则引用该外键的关联类型也应为 deprecated.

对象类型状态与关联类型状态之间的冲突

如果您收到错误 OntologyMetadata:ConflictBetweenLinkTypeStatusAndObjectTypeStatus时，关联类型的状态与其某个关联对象类型的状态之间存在冲突。当出现上表中无效的对象类型-关联类型组合时，就可能发生这种情况。例如， experimental 对象类型不能具有 active 关联类型。
