尽管两者 Integer 和 Long 都对应于 Python 类型 int，但任何直接在函数签名中标记为 int 的字段都将以类型注册 Integer。因此，我们建议改用 API 中的 Integer or Long 类型来注册数值数据类型。类似的准则也适用于 Float 和 Double；如果 Python 类型 float 直接出现在函数签名中，默认情况下它将被注册为 Float 。

标量类型

标量类型表示单个值，通常用于保存文本、数值或时间数据。

在 JavaScript 和 TypeScript 中，有一种 number 类型通常用于同时表示整数和浮点数值。为了提供进一步的类型验证和结构，我们仅支持从 @foundry/functions-api 包（用于 TypeScript v1 函数）和 @osdk/functions 包（用于 TypeScript v2 函数）导出的数值别名。类似地，在 Python 函数中处理数值类型时，我们建议使用从 functions.api 模块导出的类型别名。

from ontology_sdk import FoundryClient

@function
def edit_mandatory_markings(markings: list[MandatoryMarking]) -> list[OntologyEdit]:

    employee: Optional[Employee] = client.ontology.objects.Employee.get("primary_key")
    if employee is None:

    return ontology_edits.get_edits()

  • 在 TypeScript 和 Python 函数中，参数化类型 T 必须被指定，并且必须是另一个受支持的类型。

结构体/自定义类型

自定义类型由其他受支持的类型（包括其他自定义类型）组成，并可在函数签名中使用。

在函数签名中使用的自定义类型与用于本体论（Ontology）结构体属性生成的类不同。要在 Python 函数中编辑本体论结构体属性，请使用生成的结构体属性类，具体说明见 编辑结构体属性.

  • 在 TypeScript 函数中，自定义类型是使用 interface 关键字定义的用户自定义 TypeScript 接口。

    • 可选字段可以通过以下方式支持：使用 ? 可选标记，或与 undefined.

  • 在 Python 函数中，自定义类型是用户自定义的 Python 类。

    • 要成为有效的自定义类型，该类必须符合以下要求：
      • 该类的所有字段都必须有类型注解。
      • 字段类型必须是受支持的类型；可以使用原始 API 类型或原生 Python 类型（如上表所定义）。
      • 直方图 __init__ 方法必须只接受与字段同名且具有相同类型注解的命名参数。

聚合类型

聚合类型可以从函数中返回，供平台的其他部分使用，例如 来运行该专业代码代理。你还可以通过.

中的图表。支持两种聚合类型：

  • A 二维聚合 将单个桶键映射到一个数值。例如，可用于表示诸如具有特定职位的员工数量之类的聚合。
  • A 三维聚合 将两个桶键映射到一个数值。例如，可用于表示按每个员工的职位和所属办事处统计的员工数量之类的聚合。

聚合可以按多种类型作为键：

  • 布尔 桶表示的值为 true or false.
  • 字符串 桶可用于表示分类值。
  • 范围 桶表示桶键为值范围的聚合。这些可用于表示图表中的直方图或日期轴。
    • 数值范围，包括 整数 and 双精度浮点数，表示对数值进行分桶的聚合。
    • 日期和时间范围，包括基于 日期 and 时间戳的，表示对日期范围进行分桶的聚合。

已为对象参数加载属性

当函数将对象类型声明为参数时，平台会在函数运行之前加载该对象。以下版本会加载对象的所有属性，包括 本体论定义的派生属性:

  • TypeScript v2： TypeScript 函数运行时（@foundry/functions-typescript-runtime) 0.367.0 或更高版本。
  • Python： 使用 Python OSDK 生成器生成的本体论 SDK（foundry-sdk-generator) 2.246.0 或更高版本。

早期版本加载对象时不包含本体论定义的派生属性，因此读取此类属性不会返回任何值。要从对象参数读取本体论定义的派生属性，请升级到上面列出的版本；无需更改代码。

TypeScript v1 函数不会加载本体论定义的派生属性，无论对象是作为参数传入还是在函数内部加载。要读取本体论定义的派生属性，请使用 Python or 或 函数。

对象集

有两种方式可以将对象集合传入和传出函数：对象的具体集合（例如数组），或对象集。

向函数传递对象数组可以在具体对象列表上执行逻辑，但需要预先将对象加载到函数执行环境中。而对象集（object set）则允许您执行筛选、search-around 和聚合操作，并且仅在您请求时才加载最终结果。

通知

函数可以返回通知类型，以便灵活地配置应在平台中发送的通知。例如，您可以编写一个函数，接受诸如 User 和对象类型等参数，并返回带有已配置消息的通知。

  • A Notification 由两个字段组成：一个 ShortNotification and EmailNotificationContent.
  • A ShortNotification 表示通知的摘要版本，将在 Foundry 平台内显示。它包括一个简短的 heading, content，以及一组 Links.
  • EmailNotificationContent 表示通知的富文本版本，可以通过电子邮件在外部发送。它包括一个 subject要发布的组件集版本包含在此清单文件中。当使用 body （由无头 HTML 组成），以及一组 Links.
  • A Link 具有一个面向用户的 label 以及一份 linkTarget。该 LinkTarget 可以是 URL、 OntologyObject，或 rid （指向 Foundry 中的任何资源）。

有关如何使用 Notifications API 的示例，请查阅 我们的指南.

用户、组和主体

主体（Principal）表示 Foundry 用户账户或组。这些类型可以传入函数，以允许访问与用户或组关联的信息，例如组的名称，或用户的名字、姓氏或电子邮件地址。所有主体类型均从 @foundry/functions-api 包中导入。

  • A User 始终具有用户名，并且可能具有 firstName, lastName，或 email。它还包括与 Principal.
  • A Group 关联的所有字段。它具有一个名称，还包括与 Principal.
  • A Principal 可以是 User 或 Group。您可以检查 type 字段来确定给定的 Principal 是否为 User 或 Group。除了 User and Group特定的字段外， Principal 还具有 id, realm，以及 attributes.

几何类型

几何类型表示函数中的空间数据和地理形状。支持两种几何类型：

  • GeoPoint 表示具有纬度和经度坐标的单个地理位置。
  • 地理形状 表示任何有效的 GeoJSON 几何图形，包括点（Point）、多边形（Polygon）、线串（LineString）及其他形状。

这些类型遵循 GeoJSON 规范 ↗ ，可用于空间操作、映射和地理分析。根据 GeoJSON 规范，位置参数遵循经度、纬度的顺序。

An 本体论编辑函数 可以从 GeoJSON 字符串设置 geoshape 属性，但转换步骤因语言而异：

  • 限制 GeoShape.fromGeoJson() 接受已解析的 GeoJSON 几何图形或几何图形集合，因此请在传入之前先解析该字符串。
  • TypeScript v2： Geometry 是一个普通的 GeoJSON 对象，因此不需要转换函数；直接分配解析后的值即可。
  • Python： 每个具体的几何图形类，例如 Polygon or LineString，都提供一个 from_geo_json() 方法，该方法直接接受 JSON 字符串。 GeoShape 类型不提供此方法，因此请使用与您期望的几何图形相匹配的类。

import { Region } from "@ontology/sdk";
import { Client, Osdk } from "@osdk/client";
import { createEditBatch, Edits, Geometry } from "@osdk/functions";

type RegionEdit = Edits.Object<Region>;

function updateBoundary(
    client: Client,
    region: Osdk.Instance<Region>,
    boundary: string
): RegionEdit[] {
    const batch = createEditBatch<RegionEdit>(client);

    batch.update(region, { boundary: JSON.parse(boundary) as Geometry });

    return batch.getEdits();
}

export default updateBoundary;

from ontology_sdk.ontology.objects import Region
