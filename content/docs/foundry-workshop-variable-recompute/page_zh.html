变量重算行为

重算变量会根据其定义和当前输入重新计算其值。例如，总成本变量可能使用数量变量作为输入。重算行为控制更改数量时是自动更新总计，还是等待用户请求更新。

选择重算行为

打开 变量 在 Workshop 编辑器的面板中，选择一个变量，然后在以下选项中选择 重新计算变量值。此设置适用于以下 支持的变量定义 中列出的类型。

选项行为使用示例
自动在需要时计算，并在输入更改时重算。这是默认行为。数据刷新也可能导致重算，即使输入值看起来没有变化。使总计或汇总与用户的选择保持同步。
仅在事件触发时等待显式 重新计算 {variable name} 事件来请求计算。输入更改和上游变量的数据刷新不会自动重算该值。在用户完成多个输入并选择按钮后运行计算。
在模块加载时，以及在事件触发时在模块加载时计算初始值（受延迟加载影响）。此后，仅在显式 重新计算 {variable name} 事件触发时重算，而不是在输入更改或上游变量数据刷新时重算。以计算出的默认值开始，然后让用户决定何时更新。

触发重算

添加一个 重新计算 {variable name} 事件（event） 添加到控件（例如 按钮组）。无论选择了哪种重算选项，该事件都会使用变量的定义和当前输入请求新值。

对于仅事件计算，请在用户需要其结果之前提供触发该事件的方法。重算变量不会强制其输入重算（如果输入自身的设置需要事件）。请先确保这些输入已就绪。

支持的变量定义类型

可用性取决于所使用的定义类型，以下定义类型支持此功能：

  • 函数
  • 对象集聚合
  • 对象属性
  • 变量转换
  • 场景
  • SQL 查询

加载和数据刷新

Workshop 使用 延迟变量加载 来避免不必要的计算。自动计算可以等到可见的控件或布局需要某个变量时再进行，包括当另一个必需变量依赖于它时。因此， 在模块加载时，以及在事件触发时 可以在首次需要时计算其初始值，而不是在您打开模块时立即计算。

可见性不仅限于屏幕上显示的值。控制布局的变量（例如条件可见性）即使其控制的部分处于隐藏状态，也可被视为可见。因此，隐藏某个部分并不能保证所有相关计算都停止。

提交操作或刷新模块数据可能导致自动变量重算。这包括函数、聚合、对象属性和转换。这些变量也可以在 自动刷新 更新后重算，即使结果值没有变化。

对象集变量的值与控件显示的对象数据是分开的。控制返回对象集的函数的重算并不会冻结表中显示的对象。控件仍可以在操作或数据刷新后重新加载其数据。
