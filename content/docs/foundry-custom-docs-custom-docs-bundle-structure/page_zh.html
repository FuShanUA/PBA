自定义文档包结构

自定义文档包的 ordering.md 文件决定了该包中页面的结构和组织方式。必须为文档包中的每个页面指定一个 章节注解 ； 可用的章节注解集合 是预先确定的，无法更改。

文件结构

在您的文档仓库中，您的项目结构可能如下所示：

docs/
├── product-A/
│   └── concepts
│       └── concept-doc.md
│   └── tutorials
│       └── tutorial-doc.md
│   └── ordering.md
│   └── overview.md
└── product-B/
    └── ...
  • 所有文档必须嵌套在 docs/ 文件夹下，作为捆绑包（例如 product-A 如上所示）。
  • 这些捆绑包文件夹对应于平台内自定义文档主页上显示的产品集合。
  • 所有捆绑包都应包含一个 ordering.md 和 overview.md 文件，且位于产品文件夹级别。
  • 嵌套在每个"产品"下的实际文件夹和文件（例如上例中的 concepts 和 tutorials 文件夹）可以根据您的需求进行自定义。

目录和 ordering.md

捆绑包中的每个文档页面都必须列在 ordering.md 文件中，并附带章节注释和文件名（不含 .md 扩展名）。当自定义文档服务发现并编译文档时，这些章节注释将用于构建左侧目录。

章节注释

平台内自定义文档具有一系列 章节注释 ，您可以在 ordering.md 文件中使用，以确定如何组织您的内容页面。

目前存在的 章节注释 如下：

  • @quickstart
  • @howto
  • @tutorial
  • @concept
  • @resource
  • @api
  • @reference

并不要求在文档包中使用每一个章节注释。但是，文档包中的每个页面都必须具有一个章节注释。

章节注释摘要

平台内置的自定义文档服务对文档强制采用标准结构，该结构通过章节注释来实施。以下是可用章节的一般性指南；不过，您可以放心地按照自己认为合适的方式使用这些章节。

  • 概述： 生成自 overview.md，这是自定义文档包的主页。
  • 快速入门： 关于产品基础知识的简要指南。初次使用的用户可以从这里开始，掌握足够的知识后即可开始使用该产品。
  • 概念： 与应用/服务相关的核心思想和概念。这不一定是可操作的内容，但所描述的关键概念可能有助于解释某事物如何以及为何以特定方式运作。
  • 操作指南： 帮助用户完成常见、通用且独立任务的指南。
  • 教程： 用户可以按照说明完成一组任务以实现特定结果的分步指南。教程可用于概述端到端工作流，且通常使用示例数据来帮助用户跟随操作。
  • 参考： 有关语法、类型及其他信息的技术参考。
  • 资源： 内部和外部资源，例如有用的链接或常见问题解答。
  • API： 产品的 API 端点。

示例 ordering.md

文档捆绑包中的每个页面都必须列在 ordering.md 中，并附带分节注解和文件名（不含 .md 文件扩展名）。例如，Contour 的排序文件可能如下所示：

@quickstart getting-started
@concept core-concepts
@resource faq
@howto boards-add
@howto boards-filter
@howto boards-join
@howto boards-verify-results
@reference boards-descriptions
@tutorial boards-map

文件名在 ordering.md 决定目录的顺序。上述示例 ordering.md 文件的目录将包含一个“How Tos”标题，其中“Add boards”（@howto boards-add）排在最前面，然后是“Filter boards”（@howto boards-filter），依此类推。

使用子页面嵌套文档

如果您不希望某个文档页面显示在目录的顶层，而是希望将该页面嵌套在另一个页面之下，可以使用子页面。在自定义文档中，有两种方法可以声明子<>父关系：

  • [推荐] 在父页面上声明子页面
  • [不推荐] 在子页面中声明父页面

在父页面中声明子页面

您可以使用父页面上的 @child 注解将页面嵌套为子页面。这允许您指定这些子页面在父页面下方嵌套显示的顺序。例如，我们可能会有 example-parent-page.md ，其内容如下：

@title Parent

@child page-one
@child page-two
@child page-three

这些 @child 注解的顺序决定了页面在目录中列出的顺序。子页面无需包含在您的 ordering.md 文件。只要列出了父页面，文档服务就会发布子页面。

在子页面中声明父页面

如果您引用的是同一捆绑包中的文件，则应使用 @child 而不是 @parent。 @child 允许您指定子页面的顺序，因此 @child 的表达能力严格强于 @parent。 @parent 应仅用于向不知道该子页面存在的父页面添加子页面（例如，将自定义 Contour 看板添加为另一个 bundle 中 Contour 看板页面下的子页面）。

如果您正在编写页面，并且知道另一个页面将成为其父页面，可以使用 @parent 注解，将其放在文件顶部，如下所示： @parent parent-filename。您只需使用 @child 或 @parent其中之一；无需同时使用两者。
