在 Pipeline Builder 中创建唯一 ID

在 Pipeline Builder 中，唯一 ID 便于对数据进行跟踪、处理和分析，确保每条记录都可以被单独识别并妥善处理。因此，通常需要为记录创建唯一标识符（ID）。本节将解释为什么使用单调递增的 ID 并非最佳方法，以及为什么生成唯一 ID 的首选方法是将字符串列拼接后再进行 SHA256 哈希运算。

使用字符串列拼接和 SHA256 哈希

生成唯一 ID 的最佳方法是先拼接输入数据中的字符串列，然后对拼接后的字符串创建 SHA256 哈希。

要在 Pipeline Builder 中使用此方法生成唯一 ID，请在 Pipeline Builder 转换路径中执行以下步骤：

  1. 确定那些组合后能够唯一标识数据集中每条记录的字符串列。
  2. 将选定的字符串列拼接起来，为每条记录形成一个单独的字符串。
  3. 使用“Hash sha256”计算拼接后字符串的 SHA256 哈希。生成的 256 位哈希可以表示为 64 个字符的十六进制字符串，它将作为每条记录的唯一 ID。

此方法具有以下几个优点：

  • 一致性： 相同的输入数据将始终产生相同的唯一 ID，从而确保数据管道在不同运行之间的一致性。这使得跟踪记录、识别重复数据以及执行数据对账更加容易。值得注意的是，如果这些 ID 被用作对象的主键，您不会希望这些主键因重新构建管道而发生变化。此外，还应考虑下游处理数据的人员是否在任何时候都可能依赖这些 ID 保持稳定。
  • 分布式生成： 由于唯一 ID 源自数据本身，多个进程可以并发生成唯一 ID，而无需同步或集中协调。这提高了分布式数据处理环境中的可扩展性和性能。

通过使用字符串列拼接加 SHA256 哈希的方法，您可以生成可扩展、安全且一致的唯一 ID，使其成为数据管道应用的理想选择。

使用 UUID V5 生成确定性的唯一 ID

生成确定性唯一 ID 的另一种方法是使用 UUID V5 函数。UUID V5 使用 SHA-1 哈希（RFC 4122）根据命名空间 UUID 和名称字符串生成确定性的 UUID。相同的命名空间和名称始终会产生相同的 UUID，因此适用于需要标准化、可重现标识符的场景。

要在 Pipeline Builder 中使用 UUID V5 生成唯一 ID：

  1. 选择一个代表您数据域的命名空间 UUID。您可以使用标准的命名空间 UUID，也可以创建自己的命名空间 UUID。
  2. 使用标识列的拼接结果作为名称字符串。
  3. 应用 "UUID V5" 表达式来生成确定性的 UUID。

此方法提供：

  • 符合标准： UUID V5 遵循 RFC 4122，使生成的 ID 能够与其他期望标准 UUID 的系统互操作。
  • 一致性： 相同的命名空间和名称组合始终会产生相同的 UUID。
  • 确定性生成： 与 SHA256 一样，在给定相同输入的情况下，多个进程可以独立生成相同的 UUID。

单调递增 ID 的缺点

虽然 Pipeline Builder 不支持单调递增的 ID，但熟悉 Spark 的数据工程师经常使用它们。单调递增的 ID 是按顺序生成的，例如 1、2、3 等。虽然这种方法具有内在的简单性，但它也有以下几个缺点：

  • 构建之间的不一致性： 在 Spark 中使用单调递增 ID 时，同一应用程序在不同运行中生成的 ID 可能会发生变化。这是因为 Spark 将任务分配给其执行器的方式可能不同，从而导致不同的 ID 分配顺序。因此，这种不一致性会使结果难以重现、难以比较不同的运行或执行增量更新，使其作为 ID 列的可靠性较低。如果将其用作本体论对象的主键，则每次构建都会强制进行完整重新索引。
  • 对状态的依赖： 生成单调递增 ID 需要在行之间维护状态。

这些缺点表明，使用单调递增 ID 并不是在数据管道应用程序中生成唯一标识符的最佳方法。相反，如前面各节所述，我们建议使用字符串列的拼接，然后进行 SHA256 哈希或使用 UUID V5。

如果没有可用于哈希的一组唯一列

请注意，这种方法在不同构建或预览之间不一致。如果无法识别出一组唯一的列，此方法应作为绝对最后的选择。

如果您没有一组可以定义数据中唯一行的列，可以使用随机数的哈希来创建 ID。要以这种方式创建 ID，请在 Pipeline Builder 转换路径中按照以下步骤操作：

  1. 使用“均匀随机数”创建一个随机数。
  2. 将该列转换为字符串。
  3. 使用“Hash sha256”对该列进行哈希。
