属性与关联

本页面讨论所有以简单表格视图显示对象数据模型和本体论的小组件，这些小组件突出显示当前对象的属性，以及该对象与其他对象之间的关联。

此类别还包括用于呈现统计数据、指标或 KPI 的小组件，这些统计数据、指标或 KPI 要么在对象的管道中预先计算并作为对象的一个属性提供，要么需要对与当前对象相关联的对象进行聚合计算。

属性小组件

该 属性 小组件显示对象或关联对象的属性。对于任何新定义的对象类型，都会创建一个包含此小组件的标签页，作为默认的对象视图。

属性小组件配置

本体论管理器中的属性定义

属性小组件配置与本体论管理器中的属性定义密切相关。在“编辑属性和支撑数据集”时，每个属性都有一个单独的设置面板，您可以在其中定义该属性在对象视图中的显示方式。

有几项设置会影响属性小组件中的显示：

  • 属性可见性
    • 突出：该属性将显示在属性小部件中，并且小部件中有一个配置选项，可仅显示突出属性。此选项用于对象最重要的核心属性。
    • 普通：该属性将显示在属性小部件中。此选项用于大多数属性。
    • 隐藏：该属性不会显示在属性小部件中（也不会显示在对象视图或对象资源管理器中的任何位置）。此选项用于诸如内部 ID、与其他对象关联的关系列等属性。
  • 渲染提示
    • 长文本：此选项会将属性标记为长文本（通常用于长字符串，例如描述、注释等），从而支持在属性小部件的单独部分中显示文本。
    • 关键词：将属性渲染为关键词，这会改变其在属性小部件中的查看方式，还允许您在小部件内的单独部分中显示该属性。
  • 类型类：这允许您为属性定义类型类，从而影响其功能。
  • 使属性可编辑：如果您希望使属性可编辑，请设置一个 操作类型 或 内联操作。

属性小组件本身的配置

在小组件配置中,首先选择您希望显示的是当前对象的属性，还是关联对象的属性：

  • 如果要显示关联对象，请先选择您希望显示的关联。
  • 只有当当前对象仅关联到一个对象时，才能显示关联对象的属性，而这种情况只可能出现在:(1)一对一关系中;(2)多对一关系中，且当前对象被定义为“多”的一方。
    • 示例：在配置航班对象时，可以显示与该航班关联的飞机的属性(航班到飞机为多对一关系)。但是，在查看飞机对象时，则无法显示关联航班的属性，因为任何单架飞机都关联了多个航班对象。

选择当前对象 / 关联对象后，还需要配置 3 个部分：数据(Data)、分区(Sections)和视图选项(View Options)。

数据
  • 选择您希望显示的属性：
    • 所有属性：显示所有定义为“显著”(Prominent)或“常规”(Normal)的属性，但不包括“隐藏”(Hidden)的属性。允许使用 Properties to Exclude 选择器(见下文)排除特定的一组属性。
    • 突出属性：仅显示在本体论管理器中被定义为“突出”的属性。允许使用 properties to exclude 选择器（见下文）排除特定的一组属性。
    • 特定属性：打开一个包含该关联对象所有属性的多选下拉列表，供您从中选择。
    • 无属性：不显示任何属性。
  • 要排除的属性：选择您希望在显示中排除的属性——仅适用于前两个选项，即“所有属性”和“突出属性”。
分区

默认情况下，共有三个属性分区，分别是：

  • 普通属性：所有普通和突出属性；
  • 长文本属性：仅长文本属性，即在本体论管理器中被定义为长文本的属性（详见上文）；
  • 关键字属性：将对象的关键字属性显示为标签。只有在本体论管理器中“编辑属性和支撑数据集”下被标记为关键字的属性才会显示在此处。

您可以移除这些分区或更改其顺序。除这三种分区外，没有其他类型的分区。

视图选项
  • 用户可编辑： 是否允许用户编辑属性。这需要事先在本体论管理器中进行两项设置（更多详细信息见上文）：
    • 数据集级别：必须在对象类型上启用编辑。
    • 属性级别：必须将一个 行内编辑操作 附加到该属性。
  • 隐藏未定义值： 隐藏所有具有未定义（null）值的属性。如果此开关处于关闭状态，该属性将显示灰色的“无值”文本。
  • 包含指向“更多属性”的链接： 此选项将渲染一个 查看全部 按钮，用户点击后将进入同一对象视图中的 属性 标签页。

常见问题与注意事项

  • 属性的显示顺序按字母顺序排列。若要以其他方式对属性进行排序，主要方法是使用上述小部件配置中提到的“分区”（Sections）。
  • 有关如何将属性设置为“突出”（Prominent）、将属性设置为“长文本”（Long Text）或“关键词”（Keyword）、或使属性可由用户编辑的更多详细信息，请参阅 有关编辑属性的文档。

属性卡片

该 属性卡片 小部件可让您可视化包含属性以及关联对象聚合数据的卡片。

使用“属性卡片”小部件可显示当前对象或与其关联的对象的重要属性（数值、时间戳、日期、字符串等）、聚合、统计信息、指标、KPI 以及任何其他关键信息。

  • 此小部件受筛选器影响，筛选器会应用于关联对象的任何聚合。
  • “属性卡片”组件为 条件格式设置 和 值格式设置提供了丰富的 UI，包括全局选项（基于本体论编辑器中的本体论级配置）和局部覆盖选项。

属性卡片配置

首先，为每个属性 / 关联对象聚合的可视化添加一张新卡片。然后，配置 组件内所有卡片的整体布局。

每张卡片的配置

  • 属性卡片可以显示 属性 或 关联属性的聚合。
    • 显示属性时，卡片不仅可以显示当前对象的属性，还可以显示与当前对象具有一对一或多对一关系的关联对象的属性（例如，如果当前对象是 Flight，且与 Aircraft 之间存在多对一关系，则可以显示 Aircraft 对象的属性）。
    • 显示关联对象时，卡片可以显示通过一对多或多对多关系与当前对象关联的任意对象的聚合。
  • 如果是聚合，请选择聚合类型：计数、唯一计数 / 基数、平均值、最小值、最大值、总和。
  • 添加将显示在卡片上的标签，以及图标和图标颜色。
  • 条件格式设置和值格式设置： 默认情况下，该小组件使用为该特定对象和属性在本体论级别定义的全局本体论格式化规则。
    • 该小组件支持条件格式化（例如根据预定义规则将值颜色设置为红色/绿色）。支持的选项包括全局格式化（如在 Ontology Manager 中所配置的（参见 条件格式化文档）以及可选的本地覆盖。请注意，这仅适用于属性，不适用于聚合。
    • Property Cards 小组件支持值格式化（例如 $3.6M 而不是 3,625,329）。支持的选项包括全局值格式化（如在 Ontology Manager 中所配置的；参见 值格式化文档）以及本地覆盖。请注意，这适用于属性以及关联属性的聚合。
    • 对于本地覆盖，值格式化和条件格式化均使用与本体论级别格式化相同的 UI；有关更多详细信息，请查看本体论文档（链接见上文）。

Property Cards 小组件上所有卡片的配置

  • 配置好所有属性卡片和聚合卡片后，使用布局配置来确定卡片显示时的背景、大小、样式、对齐方式和图标样式。
  • 如果您希望为不同的卡片使用不同类型的视觉配置，请考虑为每种不同的配置添加一个新的小组件实例。

常见问题和注意事项

  • 属性卡片是受支持的微件，可用于可视化当前对象和关联对象的重要属性、聚合、统计数据、指标、KPI 以及任何其他关键信息。
    • 在可视化单个关键属性和聚合方面，此微件是优于其他任何微件的首选解决方案。请考虑使用属性卡片微件，而不是以下微件：统计、上下文统计部分、关联统计、高级统计或 Property Plus。
  • 属性卡片微件不支持 对象上的函数。如果需要此支持，请考虑使用 Workshop 或 Quiver，并使用专用微件将其嵌入到对象视图中。

关联

关联 微件以树状视图显示对象的关联，支持遍历关联并导航至关联对象。其中包括：

  • 显示所有关联对象的树状结构，并且可以展开每个关联对象的视图，以显示与其关联的所有对象，并继续在关联之间跳转（“嵌套关联”）；
  • 将鼠标悬停在任意对象上，即可查看包含该对象所有重要属性的工具提示；
  • 点击任意对象即可跳转至其对象视图。

请参见以下示例，其中包含 3 个步骤：

  • 从机场对象开始；
  • 移动到所有关联航班；
  • 转到其中一个航班的全部关联对象：飞机、目的地机场以及所有相关的飞行后回顾。

关联部件配置

  • 关联类型（仅第一层关联） - 允许您确定将在部件上显示哪些类型的关联。用户可以遍历关联并跳转到其他关联对象（例如：从机场 → 到所有航班 → 到执飞这些航班的飞机 → 到拥有这些飞机的航空公司等）
  • 按类型筛选嵌套关联 - 此设置允许您仅显示在“关联类型（仅第一层关联）”下选择的关联对象。

常见问题与说明

  • 目前无法对以下内容进行排序或确定其顺序
    • 关联对象的值列表（例如按字母顺序显示所有关联航班）。
    • 该部件下关联对象的 类型 （例如先显示关联航班，再显示关联飞机）。
  • 该部件目前不受筛选器的影响。显示的关联始终为 所有 与当前对象相关联的对象。

编辑历史

该 编辑历史 小组件会显示一个列表视图，其中包含当前查看的对象的全部编辑历史。如果该对象从未被编辑过，或者所选列的子集（详见下文）没有编辑记录，此小组件将显示一条 No Edits 消息。

编辑历史配置

选项描述
所有属性显示给定对象类型上所有属性的编辑。
特定属性特定属性，仅显示通过小组件配置中的 Properties to Include 选择器所选属性的编辑。

常见问题与注意事项

  • 只有通过操作对对象所做的更改才会显示在编辑历史中。在支撑数据集或上游管道中所做的更改不会反映在此小组件上。
  • 只有在 Ontology Manager 中启用 跟踪用户编辑历史 开关后，索引到 Object Storage v2 中的对象所做的更改才会反映在编辑历史中。
  • 目前尚不支持为具有标记属性的对象类型跟踪用户编辑。
  • 每个提交的值都会被记录为一次编辑，即使该值来自操作参数中配置的默认值。
