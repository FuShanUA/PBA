分析变更的影响

代码编辑可能会导致数据集内容、权限和结构发生意外变更。我们建议保护生产分支，并要求在合并前对提议的变更进行审查；这些选项可以在 分支设置中找到。拉取请求页面随后将提供多种方法来分析代码变更对受影响数据集的影响。

过时的数据集

评估变更的影响需要使用最新的代码变更构建受影响的数据集。此构建在头分支（开发）和基础分支（目标）上都是必需的：

  • 在头分支（开发）上构建 以验证代码是否正确构建、输出是否符合预期，以及是否满足所有数据期望。
  • 在基础分支（目标）上构建 以将输出与目标的最新版本进行比较。

当受影响的数据集过时时，拉取请求页面会向您发出警告。点击 配置并构建 将允许您查看过时的数据集，并在头分支和基础分支上构建它们。

过时警告仅涵盖此仓库中的数据集

拉取请求页面的过时警告仅涵盖特定代码仓库内受影响的数据集。拉取请求页面不会对仓库外的过时父数据集或未提交的变更发出警告。

影响分析

直方图 影响分析 选项卡提供有关受拉取请求影响的数据集的信息。默认情况下，它仅显示直接受影响的数据集，不包括可能受影响的派生数据集。您可以通过点击 将数据集添加到分析.

来检查对其他表的影响。仓库如何确定受影响数据集的列表可能因您使用的语言而异。Python 仓库使用 转换逻辑级别版本控制（TLLV） 来生成该列表。在 Java 转换中，如果数据集的源文件被拉取请求更改，则该数据集被视为直接受影响。

审查受影响的数据集需要访问数据的权限。您无法访问的数据集在界面中会显示为不可访问。

影响分析选项卡显示以下信息：

  • 选项卡，选择 - 查看源文件的变更（不包括可能被引用或使用的其他文件）。
  • 模式 - 查看数据集列的变更。
  • 安全性 - 查看应用于输出数据集的标记的变更。
  • 期望 - 查看头分支上的数据期望。
  • 已删除的数据集 - 被拉取请求更新的已删除数据集将以淡显方式显示。

查看对派生数据集的影响

点击 将数据集添加到分析 将分析拉取请求对派生数据集的影响。所选数据集与受影响数据集之间的所有中间数据集也将被添加。

添加的数据集必须不是过时的，才能显示影响信息。点击 配置并构建 以查看更新后的过时数据集列表并触发构建。

管道审查

管道审查选项卡提供受拉取请求影响的数据集的谱系视图。

当选择某个数据集节点时，将显示生成该数据集的转换代码文件的变更，以及该代码文件生成的每个数据集的架构变更。按照数据流的顺序浏览受影响的数据集可以帮助您理解不同文件和数据集的变更之间的对应关系。

为了在审查拉取请求中的变更时跟踪您的进度，您可以逐个批准或拒绝每个文件。对于转换源文件，此审查状态会在管道图中显示为相应输出数据集节点上的指示器。
