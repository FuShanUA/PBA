分支保护

当多个作者共同使用同一个 Pipeline Builder 实例，或管道支撑关键数据资产时，您可以 保护 您的分支，以实现更高级别的治理并防止意外更改。 受保护的分支 只能通过拉取请求进行修改，并且必须满足一组预定义的要求。

如何保护分支

在 Data Connection 中导航至 设置 左上角的下拉菜单。选择 管理分支.

选择 分支保护 选项卡。在此选项卡中，启用 Require proposals... 以保护 main 分支以及下方文本框中指定的任何其他分支。完成后选择 保存 。

所有受保护的分支都要求用户先在单独的分支上进行更改，然后才能将这些更改合并到受保护的分支中。目前，Pipeline Builder 中的所有受保护分支共享相同的审批规则。

直方图 解决更改 操作允许您将目标分支合并到当前分支中，但当目标分支受保护时，该操作不起作用。这是有意设计的，因为 解决更改 会直接将更改保存到管道中，而这对受保护的分支是不允许的。请改用提议流程将更改合并到受保护的分支。

与安全审批和标记移除的交互

当为管道启用安全标记更改时，分支保护设置将受到额外的治理：

  • 为输出上的标记和组织更改启用安全审批需要受保护分支工作流。启用此设置后，您无法更改分支保护设置或禁用提议审批要求。
  • 如果受保护的分支包含标记移除，则必须先撤销这些移除，然后才能禁用允许在管道中更改安全标记的设置。
  • 在具有多个受保护分支的管道中，标记移除会针对所有受保护的分支。如果任何分支上存在标记移除，请在保护或取消保护分支之前，先停止从所有分支中移除标记。

注册级别的分支保护

管理员可以为注册中所有新管道的 main 分支启用默认分支保护。分支保护要求提议在获得批准后才能对受保护的分支进行任何更改，从而增强仓库的安全性和完整性。

启用注册级别的分支保护将 不 影响现有管道。要更改现有管道的分支保护，请参阅 如何保护分支 部分。

前往 Control Panel 并导航至 如果希望用户在每次运行预览前手动确认，请开启。然后，切换以下设置： 默认为新管道启用分支保护。这将使 main 新管道上的分支成为受保护的分支，因此在合并更改之前需要先提交提议。

项目审批策略

除了上述本地分支保护设置外，Pipeline Builder 管道还可以受 项目审批策略的治理。项目审批策略在项目级别为受保护的资源定义审批要求，与本地分支保护设置一起提供额外的治理层。
