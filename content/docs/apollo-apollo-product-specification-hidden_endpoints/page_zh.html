端点 [Beta]

端点目前处于 Beta 状态，可能无法在您的 Apollo Hub 上使用。请联系您的 Palantir 代表以了解更多信息。

本规范的此扩展定义了服务应如何为以下目的声明端点：

  • 与其他服务通信。
  • 满足就绪/存活/健康检查。
  • 接收来自公共互联网的流量。

定义

产品必须在 configuration.yml 文件中的顶级键 endpoints 下声明 1 个或多个端点。 endpoints 块包含以下键：

  • sls-status-endpoint：字符串值，用于将 definitions 块中的特定端点声明为 SLS 状态端点。如果 definitions 块中只有 1 个端点，则可以省略此键。
  • definitions：端点名称到端点对象的映射。端点名称是满足字符集 [a-z0-9] 的 kebab-case 字符串，并且在服务内必须唯一。所有端点对象均假定协议为 TCP。

端点对象具有以下字段：

  • desired-port（必需）：一个整数值。该值必须介于 1024 和 19999 之间（包含边界值）。
  • path（可选）：一个字符串值，可用于指定传入请求到达该端点的路径。该值必须以 / 开头。如果未提供，此值默认为 /。
  • external-port（必需）：对于 TCP/UDP 端点，为一个整数值。HTTP(S) 端点禁止使用。在环境上命中此外部端口的流量将被转发到此端点。

一个产品可以拥有多个使用相同端口的端点，只要这些端点的路径不同即可。

服务可以使用替换语言中对引用端点定义的支持来访问其端点。

endpoints:

                                              //            serves SLS status checks, can
                                              //            be omitted if definitions only have 1 endpoint
  definitions:                                // (required) defines a map of endpoints for
                                              //            the service, must have at least 1
    version-endpoint:                         // (required) names are unique across a service
      desired-port: 9000                      // (required) port number
      path: /version                          // (optional) context path if applicable, defaults to /
    ping-endpoint:
      desired-port: 9001
    upgrade-endpoint:
      desired-port: 90001
      path: /upgrade
    service-endpoint:
      desired-port: 8080
      path: /my-app

清单扩展字段

以下可选字段将添加到清单的 extensions 块中：

  • public-proxy-endpoints：要在面向互联网的代理上挂载的服务端点列表；默认情况下，不包含任何端点。
    • 在此字段下列出的端点必须在 configuration.yml 的 endpoints 块中具有相应的定义。
    • 端点名称只能出现在 public-tcp-endpoints 和 public-proxy-endpoints 中的一个。
    • 此列表中的端点不得指定外部端口。
  • require-stable-hostname：布尔值，默认为 false。
    • 控制此服务的各个副本是否接收稳定的主机名。
    • 默认情况下，副本主机名是动态的，并且在副本替换时可能会更改。
  • public-tcp-endpoints：要挂载到面向互联网的代理上的服务端点列表，这些端点接收 TCP 流量。
    • 在此字段下列出的端点必须在 configuration.yml 的 endpoints 块中具有相应的定义。
    • 端点名称只能出现在 public-tcp-endpoints 和 public-proxy-endpoints 中的一个。
    • 如果端点希望在相同的 external-port 上接收 UDP/TCP 流量，则该端点可以同时出现在 public-udp-endpoints 和 public-tcp-endpoints 中。
    • 此列表中的端点不得指定路径。
    • 此列表中的端点必须指定外部端口。
  • public-udp-endpoints：要挂载到面向互联网的代理上的服务端点列表，这些端点接收 UDP 流量。
    • 在此字段下列出但在配置中缺少相应定义的端点将被忽略。
    • 端点名称只能出现在 public-udp-endpoints 和 public-proxy-endpoints 其中之一中。
    • 如果端点希望在同一个 external-port 上接收 UDP/TCP 流量，则该端点可以同时出现在 public-udp-endpoints 和 public-tcp-endpoints 中。
    • 此列表中的端点不得指定路径。
    • 此列表中的端点必须指定外部端口。

# configuration.yml
endpoints:
  definitions:
    service-endpoint:
      desired-port: 8080
      path: /my-service-endpoint-path
    tcp-service-endpoint:
      desired-port: 4567
      external-port: 22
    udp-service-endpoint:
      desired-port: 5678
      external-port: 1234
default_conf:
  server:
    my-service:
      port: '{{ endpoints.definitions.service-endpoint.port}}'
      path: '{{ endpoints.definitions.service-endpoint.path }}'
    my-tcp:
      port: '{{ endpoints.definitions.tcp-service-endpoint.port}}'
    my-udp:
      port: '{{ endpoints.definitions.udp-service-endpoint.port}}'

根据上述定义，SLS 存活性和就绪性检查将访问服务的 8080 端口。 由于 public-proxy-endpoints 列出了 service-endpoint，服务端点将通过路径 /my-service-endpoint-path 在集群外部公开。
