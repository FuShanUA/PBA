接口操作类型约束 [Beta]

Beta

接口操作类型约束目前处于 Beta 开发阶段，在您的注册环境中可能无法使用。功能特性和平台支持在积极开发期间可能会发生变化。

接口操作类型约束定义了实现某接口的对象类型所共有的预期操作能力。该约束描述了该操作面向用户的含义、API 名称和参数结构。然后，每个实现该接口的对象类型都可以将该约束映射到该对象类型上的具体操作类型。

例如，一个 Ticket 接口定义了一个 Create ticket 操作类型约束。 Bug 对象类型通过 Create bug 操作类型满足该约束，而 Feature request 对象类型通过 Create feature request 操作类型满足该约束。两种操作类型都实现了相同的接口级功能，尽管具体的操作逻辑特定于各个对象类型。

接口操作类型约束不定义操作执行逻辑、提交条件、副作用或表单布局。要配置这些行为，请在满足该约束的具体操作类型上进行配置。有关作用于接口对象的操作规则的更多信息，请参阅 接口上的操作。

目前，操作类型约束在描述满足条件的操作类型应如何表现方面的表达能力有限。请使用约束描述告知应用程序构建者满足条件的操作类型应实现什么功能，包括预期的编辑、副作用、提交行为，或约束模型未强制执行的其他语义要求。更具表达力的行为约束正在积极开发中。

操作类型约束

操作类型约束定义接口级操作能力的参数。这些参数包括以下内容：

  • 显示名称： 操作类型约束面向用户的名称。
  • 描述： 关于满足条件的操作类型应执行什么操作的用户可读描述。
  • API 名称： 在代码和平台配置中用于引用该约束的 API 名称。
  • 参数约束： 满足条件的操作类型必须公开的参数。
  • 作为对象类型实现的一部分，是否需要该操作类型约束。

如果操作类型约束是必需的，那么实现该接口的每个对象类型都必须将该约束映射到具体的操作类型。可选的操作类型约束可在实现对象类型支持相应功能时进行映射，而在该功能不适用时可以跳过。

参数约束

参数约束定义了满足条件的操作类型必须提供的操作参数的结构。每个参数约束包括：

  • 类型： 参数类型，例如字符串、时间戳、对象引用、接口引用、对象集、附件、媒体引用或结构体。
  • 单值或列表值： 该参数是接受单个值还是值的列表。
  • 显示名称： 参数约束面向用户的名称。
  • API 名称： 用于指代参数约束的 API 名称。
  • 该参数是否必须由实现的对象类型进行映射。

创建参数约束时，您可以手动定义新参数，或从现有接口属性中添加参数。从接口属性添加参数时，将根据所选属性的显示名称、类型和必填状态创建参数约束。参数 API 名称由显示名称生成，并且可以进行编辑。

必填参数约束必须映射到具体操作类型上的必填参数。在适用的情况下，您可以映射可选参数约束。请注意，同一个具体操作参数无法满足同一操作类型约束上的多个参数约束。

对于对象引用、接口引用、对象集和结构体参数，接口操作类型约束描述的是参数的一般类型，而非每个具体的实现细节。例如，对象引用参数约束要求满足该约束的操作类型上具有兼容的对象引用参数，但该约束本身并不绑定到某个特定的对象类型。

实现操作类型约束

当对象类型实现带有操作类型约束的接口时，该对象类型必须选择满足所有必需约束的具体操作类型。当具体操作类型具有与约束的必需参数兼容的参数时，即视为满足该约束。

在 Ontology Manager 中添加接口实现后，该对象类型的 接口 标签页会在 操作 子标签页中列出该接口的操作类型约束。请在实现该接口的对象类型上为每个必需约束选择一个具体操作类型。您可以跳过可选约束或对其进行映射。

要配置参数映射，请选择已映射操作类型约束的设置图标以打开 配置参数 对话框。将每个必需的参数约束映射到所选操作类型上兼容的必需参数。当应用程序需要通过接口操作功能传递或预填这些值时，也可以映射可选参数约束。

当您保存对本体论的更改时，本体论管理器会验证操作类型约束映射。在以下情况下，将不允许保存：

  • 必需的操作类型约束未被实现对象类型映射。
  • 必需的参数约束未被映射。
  • 映射的参数具有不兼容的参数类型。
  • 同一具体操作参数被映射到多个参数约束。
  • 所映射的操作类型约束或参数约束已不存在。

接口扩展

操作类型约束通过 接口扩展继承。如果子接口扩展了带有操作类型约束的基接口，则实现该子接口的对象类型必须满足所继承的必需操作类型约束，以及直接在该子接口上声明的任何约束。

当能力适用于宽泛的接口且应通过更具体的接口提供时，请使用继承的操作类型约束。当能力特定于该子接口时，请在该子接口上定义新的操作类型约束。

选择必需约束还是可选约束

当实现该接口的每个对象类型都必须支持某项能力，基于接口的应用程序才能正常工作时，请使用必需的操作类型约束。

当能力有用但并非普遍适用时，请使用可选的操作类型约束。在迭代 beta 接口模型时，可选约束也很有用，因为它们允许对象类型采用该能力，而不会阻碍尚未准备好支持该能力的实现。

对于参数约束，仅当每个满足该约束的操作类型都必须将该参数公开为必填操作输入时，才应将该参数标记为必填。如果实现可能会在内部计算该值、使用默认值或根本不需要该值，请将参数约束保持为可选。

局限性

接口操作类型约束目前在本体论管理器（Ontology Manager）中进行配置和映射。管道构建器（Pipeline Builder）目前不支持在实现接口时进行操作类型约束映射。如果您的接口包含必填的操作类型约束，请通过本体论管理器实现并映射该接口。更多平台集成功能正在积极开发中。

最终用户目前无法从 Foundry 应用程序中发现或调用接口操作类型约束。用户可以通过任何支持相应操作类型的应用程序直接运行满足该约束的具体操作类型。

本体论 SDK 目前不支持接口操作类型约束。您目前无法在 OSDK 中使用接口操作类型约束来发现或调用满足该约束的具体操作类型。

接口操作类型约束定义了具体操作类型的预期形态。它们并不会使特定于对象类型的操作逻辑统一化。请审查每个满足该约束的操作类型的规则、提交标准、权限和副作用，以确保它们与接口约束所描述的语义相匹配。
