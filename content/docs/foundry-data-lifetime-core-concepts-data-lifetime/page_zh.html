核心概念

在您的 enrollment 中使用或配置 Data Lifetime 之前，理解下面解释的概念非常重要。

Data Lifetime 策略

Data Lifetime 允许您在命名空间级别定义“感知血缘”的保留策略，并将其应用于这些命名空间内的数据集。策略应用后，Data Lifetime 会根据策略配置为数据集中的所有事务分配删除日期。可以配置两种类型的策略：

  • 固定删除日期: 默认情况下，根数据集中的所有事务都会被分配相同的指定删除时间（除非配置了 截止日期 ）。
  • 仅最新视图: 根数据集中所有 不 位于该数据集当前视图中的事务将被分配等于当前时间的删除日期。这意味着所有历史事务都将被标记为立即删除，而数据集最新视图中的事务不会被分配删除日期。

保留策略与感知血缘的保留策略

Foundry 提供两种从系统中系统性删除数据的方法：

  • 保留策略，在 保留 应用程序中定义，基于特定规则应用于数据集事务，并可以系统地删除数据。但是，这些策略 不允许 不感知血缘，因此不会传播到下游数据集。了解更多关于 保留策略.

  • Data Lifetime 策略 的信息 保留 策略不同。 感知数据血缘的 Data Lifetime 策略的删除机制确保在删除某个事务时，从该事务派生的所有下游事务也会被删除。两种方法的一个关键区别在于，Data Lifetime 建议将策略应用于根数据集或其他上游数据集，而通过 保留 管理的策略没有此要求。

虽然可以在同一 enrollment 上同时配置多种策略，但 Data Lifetime 在显示事务的删除日期时不会考虑其他保留策略。例如，如果某个保留策略计划在周二删除特定事务，而 Data Lifetime 设置在周三删除同一事务，则 Data Lifetime 将报告周三为该事务的删除日期。即使实际上该事务会根据保留策略在周二被删除，情况也是如此。

权限和角色

理解权限和角色是使用 Data Lifetime 的关键部分。了解更多关于 保护策略.

Data Lifetime 中权限的默认角色如下所述：

  • Namespace Viewer： 查看保留策略。
  • Dataset Editor： 在数据集上设置/移除保留策略。
  • Data Governance Officer：
    • 为其可查看的命名空间创建/更新/删除保留策略。
    • 为其可查看的数据集设置/移除保留策略和策略覆盖。

Data Governance Officer 角色对于管理和保护 Data Lifetime 策略尤为重要。了解更多关于 在 Control Panel 中分配权限的信息。此外，我们建议所有组织审查并理解我们在 平台内的数据治理原则与实施 。
