接口关联类型约束

接口关联类型约束定义了实现某接口的所有对象类型之间共同的对象到对象关系。用户可以为关联指定描述，并为关联类型指定 API 名称，以便在代码中作为引用。当对象实现带有接口关联类型约束的接口时，对象类型上的具体关联类型将用于满足接口关联类型约束。

如上例所示，为了对设施与其所服务的航空公司之间的关系进行建模， Facility 接口在实现该接口的任意对象与 Facility 对象类型之间声明了一个可选的一对多关联类型约束。 Airline 这意味着，如果实现该接口的对象类型（例如 Airport）具有指向 Airlines 对象类型的具体关联类型，则可以通过接口关联类型的 API 名称访问该关联。

关联类型约束

关联类型约束定义了接口关联类型的参数。如果该关联类型是必需的，则所有实现该接口的对象类型都必须具有满足这些约束的关联。这些参数包括以下内容：

  • 关联目标类型： 接口或对象类型。
  • 目标： 特定的接口或对象类型。
  • 基数： 一对一或一对多。
  • 该关联是否作为对象类型实现的一部分而必需。

关联目标：接口

当您想要对两个抽象对象类型之间的关系进行建模时，应使用类型为 interface 的关联目标。

例如，您可以使用接口关联目标来对 Facility 和 Alert 之间的关系进行建模。由于设施和警报都有多种类型，如果关联的每一端只能使用单一对象类型，就无法对两者之间的连接进行建模。相反，您可以通过定义一个 Facility 接口、一个 Alert 接口，以及在 Facility 上设置关联到 Alert 接口的接口关联来对此关系进行建模。然后，您可以定义一个实现 Airport 接口的 Facility 对象类型，以及一个实现 Flight Alert 接口的 Alert 对象。接下来，您可以定义一个从 Airport to Flight Alert 出发的具体关联类型，以满足 Facility 接口的关联类型约束。

关联目标：对象类型

当您想要对两个抽象对象类型之间的关系进行建模时，应使用类型为 object type 当接口与目标之间的关系是具体的，且该具体性应由关联类型约束强制执行时。

例如，您可以定义一个 Facility 接口，该接口关联到 Airlines 对象类型。此接口关联将对以下事实进行建模：无论设施类型是什么，您都期望它具有指向其所服务的特定航空公司的关联。

基数

接口关联类型还可以进一步指定为具有 ONE or MANY 基数。这些基数分别类似于一对一和一对多建模。 ONE 基数表示实现该接口的每个对象都应关联到目标类型的一个对象。 MANY 基数表示实现该接口的每个对象可以关联到任意数量的目标类型对象。

您应根据本体论的建模需求在 ONE or MANY 之间进行选择。在某些情况下，将关联的基数限制为单个对象可能更有意义。例如，您可能想要对 Driver's License 以及一份 Person 作为 SINGLE 基数关联，因为每个许可证只能属于单个具体的个人。如果该关系允许更大的灵活性，例如 Company 与其 Shareholders之间的关系，您可能需要使用 MANY 基数关联，以表示每个公司可以拥有一个或多个具体的股东。
