Logic 效果

Logic 效果允许您在自动化触发或恢复时自动运行 AIP Logic 函数 。Logic 函数支持 AI 驱动的工作流，这类工作流可以分析数据、做出决策，并建议或自动执行本体论编辑。

Logic 效果只能调用以本体论编辑列表作为输出的 AIP Logic 函数。启用了 暂存写入 的 Logic 函数不会返回本体论编辑，而必须包装为操作类型，并通过 操作效果来调用。AIP Logic 提供了 “创建操作” 按钮，用于从启用了暂存写入的 Logic 函数生成操作类型。

配置

要设置 Logic 效果，请打开自动化配置向导。在 “效果” 页面中，添加一个 Logic 效果；这将带您进入 Logic 效果配置页面。

或者，您也可以在 AIP Logic 的 “使用情况” 选项卡中直接创建自动化。详细了解 从 Logic 文件创建自动化。

Logic 函数

选择一个 Logic 函数并指定版本。您可以切换 “自动升级到兼容版本”，该选项将自动升级非预发布版本，直至下一个主版本为止。这使自动化功能能够在更新的兼容 Logic 函数版本可用时使用它们。请注意，项目范围模式下不支持自动升级。

界面将显示所选 Logic 函数所需的参数。然后，配置所需的函数输入。

Logic 函数的输出必须返回本体论编辑列表，自动化功能才能正确执行。启用了 暂存写入 的 Logic 函数不会返回本体论编辑。这些函数在函数选择器中显示为禁用状态，无法在 Logic 效果中使用。要在 Automate 中使用此类函数，请前往 AIP Logic 中的 用法 选项卡，并使用 创建操作 按钮来生成操作类型，或直接在 Ontology Manager中创建由该函数支撑的操作类型。然后，改为配置 操作效果 。或者，您也可以在该函数上禁用暂存写入，以恢复为传统行为。

启用 暂存写入 在返回本体论编辑列表的 Logic 函数上将发布一个新的主版本，因为输出类型将根据 Logic 配置更改为不同的类型。由于自动升级绝不会跨越主版本边界，现有自动化将不会自动升级到分阶段写入版本，并将继续针对旧版本运行。要将自动化迁移到 Logic 函数的分阶段写入版本，请参阅 迁移现有自动化。

执行模式

根据您的 Logic 函数配置，该函数将对 所有 新增的对象执行一次，或对 每个 新增的对象各执行一次。

对每个对象执行一次

当您的 Logic 函数使用单个受影响对象参数时，该函数将针对触发自动化的每个对象执行一次。例如，如果自动化由三个 Support Ticket 对象触发，则 Logic 函数将分别执行三次——每个对象各执行一次 Support Ticket。

对于每个对象各执行一次的执行方式，您可以选择自定义函数并行化。

自定义函数并行化

启用此设置可自定义一次执行的 Logic 函数数量。默认情况下，Logic 函数将以 20 个为一组执行。降低并行度可能会减少函数编辑之间的冲突，但代价是运行时间更长。请注意，此并行度设置仅在每个单独的自动化触发器内生效。

错误处理

您可以配置多种方式来处理失败的 Logic 函数，包括重试策略。可用的重试策略包括：

  • 固定退避： 自动重试，各次尝试之间保持固定的等待时间。
  • 指数退避： 重试之间的等待时间呈指数级增长。

您还可以配置 抖动量，即重试之间延迟时间的变化，用于防止重试同时发生。

有关 Logic 效果执行保证以及如何处理潜在重复执行的信息，请查看执行设置文档中的 执行保证 部分。

您还可以配置 回退效果 ，以便在主 Logic 函数失败时执行替代操作，从而妥善处理故障。有关 Logic 错误的更多信息，请查看 错误参考 文档。

权限

Logic 函数与自动化的所有者关联。这意味着 Logic 函数将代表自动化的所有者运行。Logic 函数配置的所有者必须拥有执行该函数以及执行由此产生的任何本体论编辑所需的权限。

由于 Logic 函数代表特定用户（即自动化的所有者）运行，如果关联的用户账户被禁用或删除，Logic 函数将不再运行。
