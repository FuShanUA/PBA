Flink 基础知识

Apache Flink 是一个分布式计算引擎，能够以低延迟处理无界数据集，因此可以处理常见的流式工作流。Foundry 流式处理使用 Flink 作为底层引擎来执行用户代码和其他平台内的流式应用，例如实时填充本体论（Ontology）以及流式时间序列数据摄取。

为了判断您的流式处理用例是否需要额外的作业配置，了解 Flink 的工作原理会很有帮助。

有关 Flink 的更详细文档可以在 Flink 主页 ↗.

Flink 作业

所有流式作业都被描述为一系列作用于数据源集合的操作，并将结果写入数据接收器。这些操作包括聚合、连接以及其他行级操作（如字符串解析或算术运算）。每个操作在 Flink 中由 运算符 抽象表示。在 Flink 中，数据源和数据接收器也由算子来描述。

Flink 作业在内部以“作业图”或“逻辑图”的形式表示。作业图是有向图，其节点由算子组成，边定义了算子之间的关系。当作业提交给 Flink 时，Flink 会创建作业图。您的 Flink 作业的作业图预览会显示在 详情 Foundry Job Tracker 中作业的相应部分。

在实际执行作业时，Flink 会将逻辑图转换为 物理图，即算子在计算运行时上如何执行的表示。物理图由 任务组成，任务是 Flink 作业中的基本工作单元，可以表示单个算子实例或多个链接在一起的算子。

Job Manager 和 Task Manager

与 Spark 类似，Flink 的运行时架构包含不同类型的工作进程。Spark 使用 driver 来协调和管理作业，使用 executor 来执行作业任务；而 Flink 使用 Job Manager 和 Task Manager，它们的作用与 Spark 的 driver 和 executor 大致类似。

Flink Job Manager 负责调度任务、为任务分配资源、处理已完成或失败的任务、协调 作业检查点 和故障恢复，以及提供对作业信息的编程访问。通常在任何给定时刻只有一个活跃的 Job Manager（即 leader），并保持热备状态的备份，以应对不可恢复的错误。

Flink Task Manager 负责执行任务，以及在流之间缓冲和交换数据。至少始终存在一个 Task Manager，但为了并行化流处理，可能会有多个。当 Task Manager 需要处理非常大的记录时，可能需要额外的资源。如果您的流具有极高的吞吐量，您可能需要增加作业的并行度，这会导致 Task Manager 数量的增加。

作业状态

虽然某些 Flink 操作只需单独查看单个事件，但其他操作需要记住跨多个事件的信息。这些是 有状态操作。有状态操作的一些示例如下：

  • Aggregations： 例如，统计滚动五分钟窗口内的事件总数，或计算所有已知事件的滚动平均值。
  • 连接： 执行引擎需要了解之前见过的事件，以便将它们与当前正在摄取的事件进行连接。

有状态操作所需的信息称为 作业状态，由 Flink 使用状态后端进行存储。状态由 Task Manager 管理和存储，并由 Job Manager 以 检查点的形式进行协调。当状态较大时（例如聚合或连接具有非常大的窗口时），您的 Job Manager 和 Task Manager 可能需要额外的资源。
