迁移并停用"传播视图要求"设置 [计划弃用]

计划弃用

直方图 传播视图要求 安全设置位于 计划弃用 开发阶段，自 2024 年 10 月起，大多数注册租户已无法使用此功能。仍在使用 传播视图要求 设置的租户强烈建议按照以下指南迁移此用法，转而使用 项目 和 标记，后者提供了更好的安全可读性和管理能力。

如果您在此迁移过程中需要额外帮助，请联系 Palantir Support。

当项目上启用了"传播视图要求"设置时，项目中的每个数据集都要求用户具有查看其下游数据集的访问权限，无论这些下游数据集位于本项目内还是其他项目中。

我们建议停用"传播视图要求"设置，并在必要时用标记（Marking）替代。与"传播视图要求"设置不同，标记能更清晰地定义查看底层数据所需的要求。如果只有部分数据集包含敏感数据，请考虑为这些特定数据集添加相应的标记。如果整个项目都是敏感的，请在项目级别添加标记。

以下是迁移并停用"传播视图要求"设置的步骤概要：

  1. 首先在 升级助手 应用程序中选择一个需要迁移的项目。
  2. 考虑您的迁移选项，并决定哪种最适合您的情况。
  3. 执行迁移。
  4. 在项目上停用"传播视图要求"。
  5. 返回 Upgrade Assistant，确认不再存在与该项目对应的待处理操作。

迁移步骤

1. Upgrade Assistant

在 Foundry 中前往 Upgrade Assistant 应用程序，并选择一个启用了"传播视图要求"的特定项目以开始迁移流程。

2. 选择如何迁移所选项目

有多种不同的方法可以迁移并停用"传播视图要求"设置。您选择的方法取决于数据的敏感程度、平台上已有的项目和标记，以及您企业的安全架构。以下是迁移选项列表以及您应该提出的问题，以帮助决定后续步骤。由于您的决定可能对隐私产生重大影响，我们强烈建议您通读所有提供的选项。

对敏感数据进行分类

首先，确定该项目是否包含敏感数据。上下文很重要；某些数据是否被视为敏感取决于您组织相关的隐私法规和标准。

在 Palantir，敏感数据被定义为任何被广泛分类和/或需要额外安全保护的数据。一些法律正式将特定数据元素指定为敏感数据（例如， 欧盟《通用数据保护条例》↗），而另一些则由数据所有者或普遍共识决定，无论其法律地位如何（例如社会安全号码）。数据是否被归类为敏感通常取决于数据的类型或分类（例如，个人身份信息（PII））、工作流的类型（例如仅限于特定用途的工作流），或任何可能触发受限访问控制的内容（包括敏感的企业信息）。

如上所述，敏感数据的一个常见示例是个人身份信息（PII），其中包括直接标识符以及其他可用于重新识别或单独识别个人的信息。

在此，您应该识别这样的情况：限制对项目中数据的访问也应限制对由此派生的任何下游数据集、对象或资源的访问。如果项目中的数据都没有 PII 属性，您可以直接跳至 停用"传播视图要求"设置 （针对该项目）。

如果项目中存在数据敏感性，请对其进行分类。例如：“此项目中的数据集 X、Y 和 Z 包含 PII（个人身份信息），而此项目中的数据集 A、B 和 C 包含财务信息”。

验证敏感数据是否已应用标记

标记 是 Foundry 中的一种安全控制，用于定义资格条件，以限制用户对数据和操作的可见性与访问权限。

与“传播查看要求”设置类似， 标记 是一种安全原语，会传播到下游数据集和资源。在考虑为此项目关闭“传播查看要求”设置是否安全时，我们建议检查此项目中的敏感数据是否已受到相应标记的保护。如果是这种情况，则关闭“传播查看要求”可能是合适的。

使用直方图中的 调度指标 应用程序来验证数据集上的标记。首先，将项目中的一个或多个数据集添加到图表中。然后，选择 权限 节点着色选项。受标记保护的资源旁边将在图表中显示盾牌图标。选择一个节点，然后选择 访问信息 在右侧边栏中展开该节点上标记的详细信息。

例如，如果您确定某个启用了“传播查看要求”设置的项目仅包含一个敏感数据类别（PII），并且 PII 标记已应用于项目中的每个相关数据集（直接应用或通过从数据依赖项或文件层级继承），那么“传播查看要求”设置很可能是冗余的，可以安全地 为该项目禁用.

确定数据敏感性是在上游引入的还是在此项目内部引入的

如果项目包含敏感数据，且该数据尚未受到 标记的保护，那么我们建议在禁用“传播查看要求”设置之前先应用标记，以确保下游数据通过传播安全控制得到持续保护。

但是，项目未必是向数据应用标记的正确位置。

示例

在下面的示例中，某个启用了“传播查看要求”设置的项目中的一个敏感数据集未应用标记。但是，该敏感数据集实际上派生自一个上游数据集。

方法 1（不正确）： 如果您直接将标记应用于此项目中的敏感数据，则上游数据将不会被正确标记；这会影响安全可读性。

方法 2（推荐）： 如果您改为将标记应用于 上游 数据，则标记将自动传播到此项目中的数据；两个数据集都将被正确标记。

如果您项目中的任何敏感数据应受到标记保护，我们建议尽可能在上游保护该数据，以确保敏感数据在平台中出现的任何位置都得到一致的保护。请务必先在上游采取适当的措施，然后再返回您的项目继续迁移。

在合适的情况下复用现有标记

如果您的项目是某些敏感数据的源头（最上游位置），且该数据未受到标记保护，那么该项目可能是向数据应用标记以替代“传播查看要求”设置的正确位置。对于每个敏感数据类别， 验证平台上是否已存在 能够正确表示该数据的标记。

从数据治理的角度来看，如果数据是 PII 且平台上已存在 PII 标记，我们建议应用现有标记而不是创建第二个 PII 标记；这确保了用户授权可以在单一位置进行管理。

在继续迁移之前，记录您计划复用哪些标记的决定 继续迁移.

创建新的标记

如果不存在适用于您 Project 中敏感数据类型的标记，请考虑创建新的标记。只有在以下情况属实时才有必要这样做：

  • Project 中的数据是唯一的，且不存在可用的现有标记。
  • 数据源自该 Project；如果不是，则应将标记应用于派生该数据的上游数据集，

记录您的决定，并按照以下各节中的步骤完成迁移。

3. 完成迁移

接下来的各节将介绍如何根据上述讨论的选项完成迁移。

禁用"传播视图要求"

无需操作。继续 4. 在 Project 上禁用"传播视图要求".

应用现有标记

将 Project 中有权访问特定类别敏感数据集的所有用户（例如包含 PII 的数据集）添加为现有标记（PII）的成员。这可确保迁移后没有人会失去对 Project 的访问权限。请注意，一旦这些用户被添加为现有标记的成员，他们可能会看到整个平台上应用了该标记的任何数据。

在应用现有标记之前，请查看以下步骤： 应用标记。请考虑应用标记的下游影响，以及可能将其他下游用户锁定在外的情况。

准备好后，在需要该标记的资源集上应用标记。如果 Project 中只有一类敏感数据且所有数据都属于该类别，则将标记应用于 Project 本身。否则，将标记直接应用于敏感数据集，或应用于它们的父文件夹（如果它们位于同一位置）。

创建新的标记

首先， 创建新的标记。然后，将所有应有权访问其所述数据的用户和/或组添加为此新标记的成员。这可确保迁移后没有人会失去访问权限。

在尝试应用任何标记之前，请查看 相关步骤.

4. 在 Project 上禁用"传播视图要求"

晚于 完成迁移 根据 Project 中敏感数据类型的数量按需多次执行上述操作后，请务必从 设置 Project 视图右侧面板中的选项卡中禁用"传播视图要求"设置。

禁用后，您将无法重新启用"传播视图要求"设置。

5. 确认操作已完成

返回 Upgrade Assistant，确认不再存在与该项目对应的待处理操作。
