对象标识符

在 Foundry 中，对象的标识有多种不同的表示方式，理解这些不同的表示方式对于在函数中编写正确的代码可能十分重要。本节将介绍对象的各种标识方式及其对代码的影响。

标识符类型

对象 RID

"RID" 指的是 资源标识符 ↗，即 Palantir 用于标识实体的开源规范。本体论对象在创建时会被分配一个 RID，无论是通过索引支撑数据集创建，还是作为操作的一部分创建。

在函数中，每个 本体论对象 都有一个 rid 字段，其类型为 string | undefined。RID 之所以可能未定义，是因为可以在函数中使用 对象创建 API 来创建新对象。新创建的对象的 rid 值始终为 undefined，而现有对象始终具有已定义的 rid。

主键

对象也可以通过其对象类型和主键来唯一标识。主键是一个唯一的 propertyId 和值对。例如，Employee 对象类型可以通过一个 string 属性来唯一标识，该属性名为 employeeId。

所有本体论对象始终都有 typeId 和 primaryKey 字段是存在的，包括新创建的对象在内。这是因为创建新对象时需要提供主键。

对代码的影响

检查相等性

在函数中，每个本体论对象都表示为一个 JavaScript 对象 ↗。一个本体论对象可能会被表示为多个 JavaScript 对象。例如，如果您从 对象搜索 中多次加载该本体论对象，或者除了将它作为参数传入之外，还从对象搜索中加载该对象，就可能出现这种情况：

public myFunction(employee: Employee): void {
    const employee2 = Objects.search().employee()
        .filter(e => e.id.exactMatch(employee.id))
        .all()[0];
    console.log(employee == employee2); // false
    console.log(employee === employee2); // false
    console.log(employee.id === employee2.id); // true
}

尽管 employee 和 employee2 在上面的示例中都引用概念上相同的本体论对象，但使用 == 和 === 运算符对它们进行比较会返回 false ，因为这些变量引用的是两个不同的 JavaScript 对象。直接比较 rid 字段可能会有问题，因为新创建的对象的 rid 为 undefined。

因此，比较两个本体论对象是否相等的最佳方式是比较 typeId 和 primaryKey：

function isEqual(o1: OntologyObject, o2: OntologyObject) {
    return o1.typeId === o2.typeId
        && JSON.stringify(o1.primaryKey) == JSON.stringify(o2.primaryKey);
}

对象映射

存储从对象到某个值的映射通常很有用。例如，您可能希望遍历对象数组并存储相应的值，以便更高效地进行查找。

由于上述相等性检查问题，您无法简单地使用 JavaScript Map 来为每个对象存储值。相反，您可以使用 FunctionsMap ，它专为支持将 OntologyObjects 作为键而设计。
