DuckDB API

Foundry 支持使用 DuckDB 进行流式、惰性执行，类似于 Polars 惰性 API。

使用 @transform.using(...) 定义的转换默认为 轻量级转换 ，因此您无需 @lightweight 装饰器。其注入的 ctx 是一个 LightweightContext，其输出为 LightweightOutput 对象，具有诸如 path_for_write_table 和 path_for_object_store_write_table等属性。

要在转换中访问预配置的 DuckDB 连接，请按如下所示使用 Context 对象：

from transforms.api import transform, Input, Output

@transform.using(
    output=Output("/Users/jsmith/output"),
    my_input=Input("/Users/jsmith/input"),
)
def compute(ctx, output, my_input):
    conn = ctx.duckdb().conn
    query = conn.sql("""SELECT * FROM my_input""")
    output.write_table(query)

DuckDB 连接已预先配置好，所有输入数据集均已注册为未物化的 DuckDB 表，并使用输入名称作为表名。这样，无需手动配置即可轻松访问输入数据。

何时使用 DuckDB

DuckDB 是一款高性能、高效的查询引擎，在许多工作负载下，其性能通常优于 Pandas 或 Polars 等其他单节点计算引擎。建议在以下情况下使用 DuckDB：

  • 处理超大规模数据的单节点转换。
  • 需要对内存使用进行严格控制的转换。

然而，DuckDB 目前尚不支持类似 Polars 或 Pandas 的 Python DataFrame API，而是需要使用原生 SQL 查询来进行数据操作。可以使用 Ibis 等第三方库在 DuckDB 之上提供 DataFrame API，请参见下文的 在 DuckDB 中使用 Ibis 部分。

增量工作流

与其他计算引擎类似，DuckDB API 允许您对输入配置增量读取模式。

与其他计算引擎一样，其默认值为 added （以增量方式运行时），而 current （以非增量方式 运行时）。

@incremental()
@transform.using(
    output=Output("/Users/jsmith/output"),
    my_input=Input("/Users/jsmith/input"),
)
def compute(ctx, output, my_input):
    ddb = ctx.duckdb(read_modes={my_input: "current"})
    result = ddb.conn.sql("""SELECT * FROM my_input""")
    output.write_table(result)

在 DuckDB 中使用 Ibis

Ibis 是与 Palantir 无关联的第三方依赖项。在 DuckDB 转换中使用它不附带任何产品支持保证。

Ibis ↗ 是一个 Python 库，提供可移植的 dataframe API，可与近 20 种不同的后端配合使用。其中支持 DuckDB，从而在其原本仅基于 SQL 的后端之上提供了 dataframe API。

要使用 Ibis，请先在您的环境中安装 ibis-framework 和 ibis-duckdb 软件包。有关向仓库添加软件包的详细信息，请参阅 软件包选项卡文档。

@transform.using(
    output=Output("/Users/jsmith/output"),
    my_input=Input("/Users/jsmith/input"),

    sql = ibis.to_sql(table, dialect="duckdb")
    output.write_table(conn.sql(sql))

from transforms.api import transform, Input, Output, LightweightContext
from sqlframe import activate

@transform.using(
    output=Output("/Users/jsmith/meteorite_enriched"),
    meteorite_landings=Input("/Users/jsmith/meteorite_landings"),
    meteorite_stats=Input("/Users/jsmith/meteorite_stats"),
)
def enriched(ctx: LightweightContext, output, meteorite_landings, meteorite_stats):
    conn = ctx.duckdb().conn
    activate("duckdb", conn=conn)

    from pyspark.sql import SparkSession, functions as F

    session = SparkSession.builder.getOrCreate()

    df_landings = session.table("meteorite_landings")
    df_stats = session.table("meteorite_stats")

    # PySpark DataFrame transformations work as-is
    enriched_together = df_landings.join(df_stats, "class")
    greater_mass = enriched_together.withColumn(
        'greater_mass', F.col("mass") > F.col("avg_mass_per_class")
    )
    result = greater_mass.filter(F.col("greater_mass")).select(
        F.col("name"),
        F.col("class"),
        F.col("mass"),
        F.col("greater_mass")
    )

    # Convert to SQL and write
    sql = result.sql(optimize=True, dialect="duckdb")
    output.write_table(conn.sql(sql))

DuckDB 配置

与许多其他单节点计算引擎不同，DuckDB 支持通过资源配置来控制内存使用和并行度，从而能够针对不同的工作负载进行细粒度优化。这在内存受限的环境中尤为重要，因为在这类环境中，DuckDB 可以自行限制其内存消耗以避免内存不足错误，但代价是性能会有所下降。

您可以在初始化 DuckDB 连接时，通过 Context 对象上的 duckdb 方法设置这些选项。配置选项的完整列表请参阅 官方文档 ↗。

1
2

conn = ctx.duckdb().conn
conn.execute("SET memory_limit='2GB';")
conn.execute("SET threads=4;")

高级用例

某些 DuckDB 工作流需要访问比简单引用输入数据集更底层的 API。示例包括

  • 自定义格式化，需要配置 DuckDB 的 read_parquet ↗ 或 read_csv ↗ 方法
  • 自定义 写入设置 ↗，例如分区或压缩选项。

对于这些用例，您可以使用名为 <input_name>_files()的预配置 DuckDB UDF 来读取数据集的原始 Parquet 或 CSV 字段。 此函数会返回输入数据集底层数据文件的路径列表，随后可将这些路径连同自定义参数一起传递给 DuckDB 的读取函数。

然后，您可以将输出复制到磁盘上的某个中间位置，或者使用 DuckDB 的 COPY TO 命令直接将输出流式传输回 Foundry。

本节中的示例使用 output.path_for_write_table 和 output.path_for_object_store_write_table ，均来自 LightweightOutput。

要从通过 COPY TO 手动上传的文件中推断 schema，而无需调用 write_table，您可以使用 Output 对象上的 put_metadata() 方法。

import uuid

from transforms.api import transform, Input, Output

@transform.using(
    output=Output("/Users/jsmith/output"),
    my_input=Input("/Users/jsmith/input"),
)
def compute(ctx, output, my_input):
    conn = ctx.duckdb().conn

    # Write to disk, then upload dataset from disk
    query = conn.sql(f"""
    COPY (
        SELECT *
        FROM read_parquet(my_input_files(), file_row_number=True)
        WHERE my_column = 'abc'
        LIMIT 10
    ) TO '{output.path_for_write_table}'
    (FORMAT 'parquet', PER_THREAD_OUTPUT TRUE)
    """)
    output.write_table(output.path_for_write_table)

    # Directly stream inputs and outputs
    path_uuid = str(uuid.uuid4())
    conn.execute(f"""
        COPY (
            SELECT *
            FROM read_parquet(my_input_files(), file_row_number=True)
            WHERE my_column = 'abc'
            LIMIT 10
        ) TO '{output.path_for_object_store_write_table}'
        (FORMAT PARQUET, PARTITION_BY (date), WRITE_PARTITION_COLUMNS true, FILENAME_PATTERN 'file_{path_uuid}')
        """
    )
    output.put_metadata()

增量输出

用户可以直接控制输出到其数据集的内容，方法是使用 COPY TO 语法（包括输出文件的文件名）。对于增量工作流，用户应确保顺序写入不与之前的事务共用文件名，以避免文件之间的冲突和覆盖。DuckDB 提供了指定 文件名模式 ↗ （用于输出）的功能，建议用户按照上述示例在文件名后附加 UUID，以确保唯一性。

分区输出

请注意，DuckDB 的分区行为与 Polars 或 Spark 等常用库的默认行为不同。在写入分区数据集时，强烈建议您将 WRITE_PARTITION_COLUMNS 设置为 true，如上例所示，以确保与其他转换的兼容性。您还应注意，DuckDB 使用字符串 null 来表示 Hive 文件路径中的缺失值，而不是 Hive 标准的 __HIVE_DEFAULT_PARTITION__，请特别注意确保下游转换能够正确解析这些分区，通常的做法是在使用 DuckDB 写入输出之前，先对分区列中的空值进行填充。

立即下载

默认情况下，Foundry 的 DuckDB 集成对输入数据集采用惰性流式下载，以优化性能和资源使用。但是，在某些场景中，用户可能希望在转换开始时将所有输入数据预先下载到磁盘。您可以通过调用 path() 来将输入拉取到磁盘并进行查询：

import duckdb
from transforms.api import transform, Output, Input


@transform.using(my_input=Input('my-input'), my_output=Output('my-output'))
def my_duckdb_transform(my_input, my_output):
    duckdb.connect(database=':memory:').execute(f"""
        COPY
        (
            SELECT *
            FROM parquet_scan('{my_input.path()}/**/*.parquet')
            WHERE Name LIKE 'John%'
        )
        TO '{my_output.path_for_write_table}'
        (FORMAT 'parquet', PER_THREAD_OUTPUT TRUE)
    """)  # Optimize performance by writing a separate Parquet file per thread in parallel

    my_output.write_table(my_output.path_for_write_table)
