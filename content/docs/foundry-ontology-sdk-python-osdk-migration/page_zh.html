Python OSDK 迁移指南（1.x 到 2.x）

本指南旨在帮助您将使用 Python OSDK 1.x 的应用程序迁移到 Python OSDK 2.x。以下各节将介绍这两个版本之间的差异，并重点说明语法和结构方面的相关变更。

Python OSDK 文档也可以在平台内的 Developer Console 中获取，地址为 /workspace/developer-console/。请使用版本选择器选择 2.x ，以查看 Python OSDK 2.x 的文档。

为什么要从 Python OSDK 1.x 升级到 2.x？

从 Python OSDK 1.x 升级到 2.x 有四个主要原因：

  • Python Platform SDK 和 OSDK 共用的客户端
  • 改进了查询、关联、聚合和附件上传的返回类型
  • 能够编辑客户端配置
  • Beta 功能

Python Platform SDK 和 OSDK 共用的客户端

同时使用 OSDK 和 Platform SDK 进行开发不再需要用户管理两个独立的客户端。现在，这两个 SDK 都可以通过单个客户端进行访问。

改进了查询、关联、聚合和附件上传的返回类型

  • 查询可以返回对象、对象集、附件、二维聚合、三维聚合和映射类型。
    • 在 Python OSDK V1 中，返回类型为对象、对象集和附件的函数查询会返回这些类型各自的对象标识符。例如，如果某个查询返回一个对象，那么在 V1 中，该查询实际返回的是该对象的主键，而不是对象的实例。现在，查询会返回相应类型的实例。
    • Python OSDK V1 不支持二维聚合、三维聚合或映射类型。OSDK V2 现已支持这些类型。
  • 关联返回对象集或 Optional[Objects]
    • 一对多/多对多类型的关联现在返回对象集，而一对一/多对一类型的关联返回 Optional[Objects].
    • 对于一对一/多对一类型的关联，用户不再需要使用 .get 来获取被关联的对象。关联本身即为该对象。
    • 对于一对多/多对多类型的关联，对象集可用的所有方法（例如 .page, .where，或 .group_by）现在都可用于这些关联。在 Python OSDK V1 中，只有方法 .iterate and .get 可用。
  • 聚合返回一个 AggregateObjectsResponse
    • 在 Python OSDK V1 中，聚合响应的类型为 dict[str, Any]，其中键为排除项、精度、数据等字段。在 Python OSDK V2 中，聚合现在返回一个 AggregateObjectsResponse的实例，其字段与 V1 的 dict 类型相同，但类型安全性更高。该 AggregateObjectsResponse 在 Python OSDK V2 中具有一个 .to_dict 方法，该方法将返回与 V1 中相同的响应。
    • 要在 Python OSDK V1 中执行“按范围分组（group by range）”，您需要输入一个字典列表，其中每个字典的键为 "start_value" 和 "end_value"，值为范围的起始值和结束值。在 V2 中，输入类型现在是一个由元组组成的集合，其中元组的第一个元素会被推断为 "start_value"，第二个元素会被推断为 "end_value"。
  • 附件上传返回一个 Attachment
    • 在 Python OSDK V1 中， client.ontology.attachments.upload(...) 返回一个 AttachmentMetadata。在 V2 中，上传附件会返回一个 Attachment.

能够编辑客户端配置

在 Python OSDK V1 中，发送请求时没有简便的方法来编辑客户端配置。例如，如果用户想要编辑请求的 user-agent，就必须访问其客户端上预留的 ._session 方法才能做到这一点。为避免此问题，Python OSDK V2 提供了一个 Config 类，用户可以导入该类并将其传递给客户端。

Beta 功能

Beta 功能可能会发生变化，且不保证其语法、稳定性和存在性。Python OSDK V2 的稳定版本包含 Beta 功能，供您试用并提供反馈。要使用 Beta 功能，您必须导入 AllowBetaFeatures （来自 foundry_sdk_runtime ），并且要么在它的上下文中编写您的代码，要么使用 @AllowBetaFeatures()来装饰您的代码。在使用 Foundry Python 函数时， @function 装饰器包含一个 beta 布尔值。

使用 Beta 功能需要用到 AllowBetaFeatures

Copied!
1from foundry_sdk_runtime.decorators import AllowBetaFeatures
2
3with AllowBetaFeatures():
4    <your code>

通过装饰方法来使用 Beta 功能，装饰器为 AllowBetaFeatures

Copied!
1from foundry_sdk_runtime.decorators import AllowBetaFeatures
2
3@AllowBetaFeatures()
4my_func():
5    <your code>

在 Foundry Python 函数中使用 Beta 功能

需要以下代码才能使 Python 函数接受带有 Beta 属性的本体论对象。

Copied!
1from functions.api import function
2
3@function(beta=True)
4def my_function():
5    <your code>

如何从 Python OSDK 1.x 升级到 2.x

您可以为现有的 Developer Console 应用程序生成新的 SDK 版本，方法是使用 Python OSDK 2.x 生成器（可通过 “生成新版本” 选项进行访问），该选项位于您应用程序的 “SDK 版本” 选项卡中。

现有应用程序还必须具备所需的依赖项才能使用新生成的 SDK。在 Developer Console 中创建的新应用程序将默认使用 Python OSDK 2.x 生成器生成 SDK。您可以按照 “开始开发” 选项卡中的说明快速开始。

从 Python OSDK 1.x 到 2.x 的语法转换和返回类型变更

本节包含一些简单的示例，说明如何在 Python OSDK 1.x 与 2.x 之间进行映射。

筛选

  • 在引用要筛选的属性时，您必须将 .object_type 包含在 where 表达式中。
  • .is_member_of 已重命名为 .in_.
  • .starts_with 已重命名为 .contains_all_terms_in_order_prefix_last_term.

使用 Python OSDK 1.x 进行筛选（旧版）

Copied!
1client.ontology.object.where(Object.id.is_member_of([1, 2, 3])).take(1)

使用 Python OSDK 2.x 进行筛选

Copied!
1client.ontology.object.where(Object.object_type.id.in_([1, 2, 3])).take(1)

分组依据

在 OSDK V1 中，按范围分组时，接受的输入是一个字典列表，其中每个字典的键为 start_value 和 end_value，而值是每个范围的起点和终点。在 V2 中，新的输入类型是由元组组成的集合，其中元组的第一个元素是 start_value ，而第二个元素是 end_value （对应每个范围）。

使用 Python OSDK 1.x（旧版）按范围分组

Copied!
1from ontology_sdk.ontology.objects import Object
2
3client.ontology.objects.Object.group_by(
4    Object.object_type.int_property.ranges(
5        [{"start_value": 1, "end_value": 2}, {"start_value": 3, "end_value": 4}]
6    )
7)

使用 Python OSDK 2.x 按范围分组

Copied!
1from ontology_sdk.ontology.objects import Object
2
3client.ontology.objects.Object.group_by(
4    Object.object_type.int_property.ranges({(1, 2), (3, 4)})
5)
