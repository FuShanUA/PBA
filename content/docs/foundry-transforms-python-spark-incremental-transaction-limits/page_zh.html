限制增量输入的批次大小

通常，当输出数据集以增量方式构建时，每个输入数据集的所有未处理事务都会在同一个 作业中处理。但是，在某些情况下，一个作业处理的事务数量可能会有显著差异：

  • 增量转换在 SNAPSHOT 模式下构建，并且会从头读取整个输入（例如，转换的 语义版本 被提升了）。
  • 一个输入数据集已经累积了许多 事务 的数据，因此下游的增量转换现在必须在单个作业中处理许多事务。

您可以在转换的每个增量输入上配置一个 事务限制 ，以限制每个作业中读取的数据量。

  • 两个增量输入，各自具有不同的事务限制
  • 一个不使用事务限制的增量输入
  • 一个快照输入

创建构建计划以使输出保持最新

启用事务限制后，由于仅会处理一部分数据，即使构建成功，数据集仍可能未与最新的上游数据保持同步。您可以按照以下步骤配置计划，持续构建输出数据集，直至其与输入数据保持同步：

  1. 导航至 数据血缘。
  2. 打开 管理计划 标签页（位于右侧面板中），并选择 创建新计划。
  3. 将 目标资源 设置为配置了事务限制的增量转换的输出数据集。
  4. 在 何时构建 部分中，选择一个选项并配置其他频率详细信息：
  • 当特定资源更新时
  • 在特定时间
  • 手动触发时
  • 当满足多个时间或事件条件时
  1. 向下滚动至并展开 高级选项 部分（位于面板底部）。
  2. 启用以下选项： “成功构建完成后重新触发计划”。
  3. 选择 保存 （位于屏幕右上角）以保存计划配置。
  • 无法在计划中同时配置 “成功构建完成后重新触发计划” 和 “强制构建” 选项同时启用，因为其中一个选项的逻辑会与另一个选项相矛盾。重新触发的构建只会持续到数据集不再过期为止，而强制构建则无论数据是否过期都会发生。因此，如果两个选项同时启用，调度将永远不会停止提示重新构建。
  • 如果新事务在输入数据集上以高频率到达，调度将提示持续重新构建。
  • 在成功构建完成后重新触发调度 选项只有在至少一个目标资源配置为使用事务限制时，才会显示在调度配置中。

查看作业事务范围

您可以按照以下步骤验证增量作业中每个输入所读取的事务范围：

  1. 导航至您要检查的作业的 Spark 详情 页面。
  2. 选择 快照/增量 选项卡。

在此页面上，事务范围会按输入进行报告，显示每个输入在当前作业和上一个作业中分别处理的部分：

  • 当前视图的范围： 此范围表示在当前作业中读取的输入视图的起始事务和结束事务。
  • 已处理批次的范围： 此范围表示当前作业中在"当前视图范围"内处理的批次的起始事务和结束事务。
  • 上一个结束事务： 此事务表示上一个作业中输入视图的最终事务。
  • 最后读取的事务： 此事务表示在上一个作业中处理的输入的最后一个事务。此事务将为以下之一：
    • 与"上一个结束事务"相同，前提是满足以下任一条件：
      • 在上一个作业中处理输入时未使用事务限制。
      • 在上一个作业中，输入配置为使用事务限制，且所处理的批次是该输入的最后一个批次。
    • 位于"上一个结束事务"之前的事务；这种情况发生在以下情形：输入使用了事务限制，且所处理的批次 并非 该输入的最后一个批次。

选择一个事务以导航到该输入的 历史 页面 ，其中相应的事务将被高亮显示。

了解具有事务限制的输入的读取范围

尽管相同的 added、 current和 previous 读取范围在输入配置有或 没有事务限制时都会提供，它们的行为略有不同。

在下面的示例中，考虑一个增量转换，其中您已经处理了事务 A 到 C。现在，假设有相对较多的事务， D 到 J，被添加到输入中。

如果您在读取输入时 不设置事务限制，那么下一个作业中每种读取模式的事务范围将如下所示：

  • 已添加： D 到 J
  • 先前： A 到 C
  • 当前： A 到 J

但是，如果您在读取输入时 将事务限制设置为三，您将需要 三个 作业才能赶上输入。每个作业中每种读取模式的事务范围将如下所示：

第一个作业：

  • 已添加： D 到 F （接下来的三笔未处理事务）
  • 先前： A 到 C （上一个作业中已处理的所有事务）
  • 当前： A 到 F （截至并包含本批次已处理的所有事务）

第二个作业：

  • 已添加： G 到 I
  • 先前： A 到 F
  • 当前： A 到 I

第三个作业：

  • 已添加： J
  • 先前： A 到 I
  • 当前： A 到 J

现在，如果对输出进行了快照（例如，如果语义版本发生了更改），事务将从输入的起始事务开始重新处理，并得到以下解析后的范围：

不设置事务限制时：

  • 已添加： A 到 J （所有事务现在都处于“未处理”状态）
  • 先前： 无
  • 当前： A 至 J

使用增量输入时：

第一个作业：

  • 新增： A 至 C
  • 之前： 无
  • 当前： A 至 C （已处理的所有事务，直至并包含此批次）

第二个作业：

  • 新增： D 至 F
  • 之前： A 至 C
  • 当前： A 至 F

第三个作业：

  • 新增： G 至 I
  • 之前： A 至 F
  • 当前： A 至 I

第四个作业：

  • 新增： J
  • 之前： A 至 I
  • 当前： A 至 J

要求和限制

要在增量转换中使用事务限制，请确保您有权访问必要的工具和服务，并且转换和数据集满足以下要求。

该转换必须满足以下条件：

  • 使用 incremental 装饰器，并将 v2_semantics 参数设置为 True。
  • 它配置为使用 Python transforms 版本 3.25.0 或更高版本。请通过 模块固定 配置作业，以使用特定版本的 Python transforms。
  • 它不能是 轻量级转换。

在现有增量转换上启用 v2_semantics 将导致后续构建作为 SNAPSHOT运行。 这种情况只会发生一次。

输入数据集必须满足以下条件才能配置事务限制：

  • 它必须是 事务性数据集 输入。
  • 在 数据集的当前视图中，它必须仅包含 APPEND 事务；但是，起始事务可以是 SNAPSHOT。
  • 它不能是 快照输入。

如果 任何 当前视图中的事务是 DELETE 或 UPDATE 事务，该作业 将失败 并出现 Build2:InvalidTransactionTypeForBatchInputResolution 错误。
