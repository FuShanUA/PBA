在 Foundry 上托管 OSDK 应用

Developer Console 中的网站托管功能为使用 OSDK 构建纯前端应用的开发者新增了一个选项，可将这些应用托管在 Foundry 上，从而无需额外的托管基础设施。

网站托管功能仅支持托管静态资源，不支持运行服务器，这一点与 GitHub Pages 类似。这意味着您可以托管：

  • HTML、CSS 和 JavaScript 文件
  • 完全在浏览器中运行的单页应用（React、Vue、Angular 等）
  • 图像、字体和其他静态资源

您无法使用此功能运行服务器端代码，例如 Node.js 后端、Python 服务器或服务器端渲染。如需任何服务器端功能，您的应用必须通过 OSDK 或其他外部服务向 Foundry 发起 API 调用。

网站托管仅适用于配置为 面向客户端的应用。如果您的应用同时配置为 后端服务，则不会显示网站托管选项，因为这种组合会创建用于服务器端应用的机密客户端。

每个托管的网站既可以通过您 Foundry 注册域名的子域名提供服务，也可以通过您拥有的自定义域名提供服务。默认情况下，您将选择一个子域名，您的应用将通过以下域名提供服务 <YOUR-APPLICATION-SUBDOMAIN>.[YOUR-ENROLLMENT].palantirfoundry.com。或者，您也可以将应用程序托管在自定义域名上，例如 [your-organization].com。请参阅 在自定义域名上托管网站 以了解更多详情。

如果您的 Foundry enrollment 并非通过以 .palantirfoundry.com结尾的域名提供服务，则需要进行额外的协调；请联系 Palantir 支持团队协助设置网站托管。请查阅 外部管理域名上的网站托管 ，了解此类 enrollment 通常所需的 DNS、证书和网络入口配置。

在 IL5 和 FedRAMP 环境中，Developer Console 中的网站托管可能显示为已禁用。在这些环境中启用网站托管需要额外的审批，以及针对自定义 TLS 证书和托管网站的配置。请联系 Palantir 支持团队以开始此流程，并与您的网络基础设施团队协调所需的变更。

准备您的应用程序

以下部分介绍了在 Foundry 上托管 Developer Console 应用程序所需的步骤。

单页应用渲染

如果您的应用程序中不包含 自定义 404 页面 ，Foundry 会将其视为 单页应用 ↗ ，并将该子域名下任意路径的请求路由到 index.html。

更新重定向 URL

作为身份验证流程的一部分，您需要更新重定向 URL，使其包含您的托管域名，后跟 /auth/callback。如果您使用的是注册子域名，则为 <YOUR-APPLICATION-SUBDOMAIN>.[YOUR-ENROLLMENT].palantirfoundry.com/auth/callback。如果您使用的是自定义域名，则为 <YOUR-CUSTOM-DOMAIN>/auth/callback。 您还必须在 Developer Console 中为您的应用程序添加相同的重定向 URL。请查看 创建新的 OSDK 以获取更多信息。

请始终使用 https:// （而非 http://）来配置您的重定向 URL。平台不会自动将 http URL 升级为 https，而使用 http 可能会导致违反内容安全策略（Content Security Policy）以及其他安全问题。

准备资产

压缩包含网站文件生产构建版本的目录内容。 请勿 包含目录本身。该目录通常为 dist/ （适用于常见的 Web 框架）。

如果您在压缩文件中包含任何目录，这些目录将包含在您网站的路径中。

限制

在 Foundry 上托管网站时，适用以下限制：

限制最大值
文件数量1,000
总上传大小20 MB

如果您的应用程序超出这些限制，则必须在上传之前减少文件数量或缩小文件大小。请考虑对资源进行打包和压缩、删除未使用的文件或压缩图片，以确保符合这些限制。

检查子域名支持的可用性

在构建依赖子域名托管的功能之前，请先通过编程方式检查您的 enrollment 是否已启用子域名托管。

要检查子域名支持状态，请使用 Control Panel 中的 enrollment subdomain API 或 Developer Console 中的网站托管支持状态实用工具。这两种方法都会返回给定 enrollment 是否支持子域名和网站托管。

设置域名

在 Developer Console 中您的应用程序内，选择 网站托管 （位于左侧菜单中）。

在子域名上托管您的网站

要将您的网站托管在您 enrollment 域名下的子域名上，请按照以下步骤操作。

  1. 为您的应用程序选择子域名；该子域名可以是应用程序名称，也可以是您选择的任何其他名称。然后，选择 请求应用程序域名。在下面的示例中，我们选择的是 my-first-hosted-app.example.palantirfoundry.com：



子域名请求提交后便无法再编辑。如果您需要更改子域名，必须取消或关闭现有请求，然后使用正确的子域名提交新请求。

  1. 请向您所在注册中的 信息安全官 请求审批；或者，如果您具有必要的权限，也可以自行选择 查看请求进行审批。注册管理员可以在 Control Panel 中管理注册权限。



  2. 请求获批后，请刷新页面。此时， 域名就绪 应会显示，表示域名已准备就绪可供使用。此过程可能需要几分钟才能完成。



在自定义域名上托管您的网站

您可以不使用注册子域名，而是将应用程序托管在自己拥有的自定义域名上，例如 [your-organization].com。当您希望应用程序能够通过品牌域名或面向公众的域名访问时，这会很有用。

并非所有注册都提供自定义域名托管功能。如果该选项未显示在您的 Developer Console 应用中，请联系 Palantir 支持团队寻求帮助。

前提条件

在为您的应用程序申请自定义域名之前，请确保已在 Control Panel 中创建了涵盖您的域名的证书。如果该域名没有相应的证书，审批请求将无法成功。请参阅 配置域名和证书 以了解创建证书的说明。

申请自定义域名

在 Developer Console 中的应用程序内，选择 网站托管 （位于左侧菜单中）。

  1. 选择 申请在自定义域名上托管。该选项显示在注册子域名的注册表单下方。



  2. 在出现的对话框中，输入您的自定义域名（例如， [your-organization].com）、请求标题和可选描述。然后选择 申请。



  3. 这将创建一个审批任务，该任务必须由 信息安全官 在您的注册中进行审批。您可以在成功通知中选择 查看 ，以导航至 Control Panel 中的审批请求。



  4. 请求获得批准后，自定义域名将与您的应用程序关联。您可能需要刷新页面才能看到更新后的状态。请注意，您用于登录 Foundry 的域名将与您配置的自定义域名相关联。换言之，网络入口和身份验证提供程序配置将继承自该域名。



您还必须更新自定义域的 DNS 设置，使其指向您的 Foundry 环境。请参阅 配置域和证书 以获取有关更新 DNS 记录的指导。

在自定义域下注册子域

在自定义域获得批准并完成配置后，您可能需要在该自定义域下注册更多子域。要在自定义域下注册子域，您必须通过该特定自定义域登录 Foundry。如果您通过其他域（例如默认注册域）登录，则 Developer Console 中将不会提供在自定义域下注册子域的选项。

例如，如果您想将 app.your-organization.com 注册为您的自定义域下的子域 your-organization.com，您必须先导航到 Foundry 并使用 your-organization.com登录，然后在 Developer Console 中请求该子域。

在外部管理的域上托管网站

某些 Foundry 部署（尤其是物理隔离或其他网络受限的环境）可能未通过标准自动化流程配置通配符 DNS 或证书。在这些情况下，如果您的注册支持网站托管，并且您的基础设施团队已配置：

  • 指向您的 Foundry 环境的自定义 DNS 记录
  • 覆盖所需子域的 TLS 证书
  • 将子域流量路由到您的 Foundry 环境的网络入口

然后，请联系 Palantir 支持团队，请求为您的注册启用针对外部管理域名的网站托管功能。

启用网站托管后，您可以按照标准工作流程为您的 Developer Console 应用程序请求并关联子域，相关说明请参阅 在子域上托管您的网站。Developer Console 配置保持不变——额外的基础设施配置（入口路由、TLS 证书和 DNS）必须与您的网络基础设施团队协调，并与 Developer Console 设置分开进行。

此配置通常适用于未通过以 .palantirfoundry.com结尾的域名提供服务的部署。请联系 Palantir 支持团队或您的基础设施团队，获取此设置方面的帮助。

用于异步扫描的仅上传模式

在某些 Foundry 注册中，站点资产或漏洞扫描会在部署上线之前异步运行。如果您的注册强制执行此扫描，则在上传后立即部署可能会失败，因为扫描尚未完成。

将 site.uploadOnly 设置为 true ，在您的 foundry.config.json中：

  "site": {
    "uploadOnly": true

使用此设置后，发布步骤仅会上传新版本，而不会尝试立即部署到生产环境。异步扫描完成后，您可以从开发者控制台手动将所需版本部署为线上版本。

如果 site.uploadOnly 设置为 false （默认值），发布过程将上传并立即尝试部署到生产环境。在启用了异步扫描的注册中，即使上传成功，这也可能导致标签状态失败。

授予网站访问权限

由 Foundry 托管的网站仅对拥有 Foundry 登录凭据的用户可用。默认情况下，任何有权访问您的 Developer Console 应用程序的用户也将有权访问已部署的网站，但这可能仅包括您和您的开发团队。 若要使您的网站可供其他 Foundry 用户访问，请导航至 共享与令牌 菜单（左侧）。在页面的 共享托管网站 部分添加用户名，如下所示。

内容安全策略

默认情况下，您的应用程序将附带受限的 内容安全策略 (CSP) ↗ 该策略仅允许从您的子域加载资源。如有需要，您可以为应用程序中的特定交互配置额外的 CSP 规则，这些规则将与默认策略合并。但请注意，进行这些更改可能会增加应用程序遭受跨站脚本（XSS）攻击和数据注入攻击的风险。

跨域资源共享（CORS）

如果您的托管应用程序需要加载资源或向另一个由 Foundry 托管的应用程序发出请求——例如，在微前端架构中，父应用程序从 remoteEntry.js 子应用程序获取——您必须配置 CORS 策略以允许这些跨域请求。

您可以在 Control Panel 中为 Artifact 网站子域配置 CORS。要在托管应用程序之间启用跨域请求：

  1. 导航至 Control Panel 并打开 CORS 标签页。
  2. 找到需要被访问的应用程序（即“子”应用程序）的子域。
  3. 将发出请求的应用程序（“父”应用程序）的来源添加到允许的来源列表中。

例如，如果 parent-app.example.palantirfoundry.com 需要从 child-app.example.palantirfoundry.com获取资源，请将 https://parent-app.example.palantirfoundry.com 添加为子应用程序子域的允许来源。

有关更多信息，请参阅 配置 CORS。

路由匹配规则

Foundry 支持在带有或不带有扩展名和尾部斜杠的路由上提供 HTML 页面。

假设网站文件布局如下：

├── file.html
├── folder
│   └── index.html
├── both.html
└── both
    └── index.html

Foundry 在以下路由上提供这些 HTML 页面：

路由文件
/file/file.html
/file//file.html
/file.html/file.html
/folder/folder/index.html
/folder//folder/index.html
/folder/index.html/folder/index.html
/both/both.html
/both.html/both.html
/both//both/index.html
/both/index.html/both/index.html

Foundry 不会重定向到首选的路由格式，例如强制使用尾部斜杠或从路由中移除扩展名。

自定义 404 页面

您可以将 404.html 页面添加到网站的根目录，用作路由未匹配时的自定义错误页面。这将禁用为未匹配的路由提供根 index.html 页面的默认行为，详见 单页应用程序（SPA）渲染。

故障排除

您的环境不支持网站托管

如果您在部署托管式前端应用时遇到问题——例如在编辑网站设置时看到“页面未找到”、发布版本无限期挂起，或出现明确警告“您的环境目前不支持网站托管”——请按照以下步骤解决该问题：

  1. 验证应用类型： 网站托管仅适用于配置为 面向客户端应用的应用。如果您的应用同时配置为 后端服务，则网站托管选项将不可用，因为这种组合会创建一个面向服务器端应用的机密客户端。请确保应用使用的 OAuth 客户端是公共客户端，而非机密客户端。
  2. 确认已启用网站托管： 必须在您的 enrollment 上启用针对外部管理域名的网站托管功能。请联系 Palantir 支持团队，确认该功能是否已启用，并在必要时请求启用。
  3. 验证环境支持： 请确认您的 enrollment 支持网站托管。某些环境（尤其是具有特定合规要求的环境）可能需要额外配置才能使用网站托管。

在您的 enrollment 上启用网站托管且您的应用使用公共 OAuth 客户端后，您应该就能成功部署托管式前端应用。

SiteAssetScanning:ScanningInProgress 错误

首次部署 OSDK 应用时，您可能会遇到一个 SiteAssetScanning:ScanningInProgress 错误。出现此错误是因为站点资产扫描仍在运行，从而阻止了初始部署。

要解决此问题：

  1. 等待资产扫描完成。您可以通过查询扫描端点来监控扫描状态。
  2. 扫描完成后，重试部署。

初始扫描完成后，后续部署应不会再遇到此问题。
