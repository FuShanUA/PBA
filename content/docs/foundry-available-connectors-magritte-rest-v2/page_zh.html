旧版 REST API 插件 (magritte-rest-v2)

此处记录的使用自定义 magritte-rest-v2 源类型的旧版 REST API 选项仅供历史参考。此功能不再处于活跃开发状态，不应再使用。

请改用 REST API 源类型 ，它支持：

  • Webhook
  • 通过以下方式进行同步和导出： 外部转换

REST API 源类型还可用于通过以下方式连接到本地部署的 REST API： agent 代理出站策略.

架构

以下概念说明了使用 magritte-rest-v2 源时信息的流动方式。

  • 直方图 源 定义如何建立连接，包括请求应如何进行身份验证。
  • 直方图 同步 由一系列 调用组成。每个调用定义应发出何种请求，并实现围绕此请求所需的任何逻辑。调用可以简单到只是一个 GET 请求，也可以更复杂，例如用于分页的请求循环。
  • An 提取器 定义如何解析身份验证调用和同步调用的响应。对于同步调用，它可以将响应中的字段保存到 状态.
  • 生成的 状态 会传递给下一个调用。此 state 中的变量随后可注入到后续调用中，从而实现相互依赖的请求。

  my_api:
    type: magritte-rest-auth-call-source
    url: "https://some-api.com/"
    headers:
      Authorization: 'Bearer {%token%}'
    authCalls:
      - type: magritte-rest-call

        method: POST
        formBody:
          username: '{{username}}'
          password: '{{password}}'
        extractor:
          - type: magritte-rest-json-extractor
            assign:
              token: /token

TLS 版本

默认情况下，插件仅通过较新的 TLS 版本（TLSv1.2 和 TLSv1.3）进行连接。

要使用较旧的版本，请在配置中指定 TLS 版本：

Copied!

3

sourceMap:
  my_api:
    type: magritte-rest
    url: https://example.com
    tlsVersion: 'TLSv1.1'

支持的版本： TLSv1.3, TLSv1.2, TLSv1.1, TLSv1, SSLv3.

创建同步

要创建同步，请在您的 magritte-rest-v2 Source 顶部点击“Create Sync”按钮。基本视图将引导您创建一个或多个调用来获取数据。高级视图使您能够直接编辑 YAML 配置。您可以在页面右上角在这些视图之间切换。

一个同步至少需要一个调用。在基本视图中，您可以通过点击“Perform calls in sequence”标题下的“Add”按钮来创建新的调用。 然后，您可以通过选择“Single Call”指定调用仅执行一次，或者基于循环、时间范围、日期范围、列表或对结果进行分页来执行多次调用。 每个调用都需要一个路径，该路径在查询时会附加到源 URL 后面。例如，如果源的 URL 为 https://my-ap-source.com 使用路径 /api/v1/get-documents 将导致调用查询 https://my-ap-source.com/api/v1/get-documents.

假设有一个 API 在以下地址为每个日期提供 CSV 报告 /daily_data?date=2020-01-01。在此示例中，我们希望在这些报告可用时将其摄取。为此，我们可以安排一个每日同步，记住上次同步报告的日期，以便自动获取截至今天尚未同步的日期的报告：

      date: '{%date_to_query%}'
    extractor:
      - type: magritte-rest-string-extractor
        fromStateVar: 'date_to_query'
        var: 'incremental_date_to_query'

import requests
from datetime import datetime, timedelta

incremental_state = load_incremental_state()
if incremental_state is None:
  incremental_state = {'incremental_date_to_query': '2020-01-01'}

yesterday = datetime.utcnow() - timedelta(days=1)

date_to_query = incremental_state['incremental_date_to_query']
date_to_query = datetime.strptime(date_to_query, '%Y-%m-%d')
while yesterday >= date_to_query:
  response = requests.get(source.url + '/daily_data', params={
    'date': date_to_query.strftime('%Y-%m-%d')
  })
  upload(response)
  date_to_query += timedelta(days=1)
  incremental_date_to_query = date_to_query

save_incremental_state({'incremental_date_to_query': incremental_date_to_query})

触发并下载报告

在派生系列逻辑中支持哪些 Quiver 卡片？ sync 适用于需要三个相互依赖步骤的 API。

  • 向某个端点发送一个请求体，该端点返回包含 ID 的响应。
  • 此 ID 需要在下一个端点中使用以获取报告。但是，报告不会立即就绪，因此响应中包含一个名为 status 的字段，用于定义报告是否完成。
  • 报告完成后，我们可以从第三个端点获取报告。

outputFileType: json
restCalls:
  - type: magritte-rest-call
    path: '/findRelevantId'
    method: POST
    requestMimeType: application/json
    extractor:
      - type: json
        assign:
          id: /id
    body: >
      body
    saveResponse: false
  - type: magritte-do-while-call
    path: '/reportReady'
    method: GET
    parameters:
      id: '{%id%}'
    extractor:
      - type: magritte-rest-json-extractor
        assign:
          status: /status
    condition:
      type: "magritte-rest-regex-condition"
      var: status
      matches: "(processing|queued)"
    timeBetweenCalls: 8s
    saveResponse: false
  - type: magritte-rest-call
    path: '/getReport/{%id%}'
    method: GET
    requestMimeType: application/json

Extractor 定义了要在状态中保存哪些字段，这些变量可在后续所有 REST 调用中使用。要注入已保存的变量，请用 {%%} 将变量名包围起来。第二个 do-while 调用实现了一个循环，不断发送请求，直到状态变量不再是排队中或处理中。

      until: '{%currentTime%}'
    extractor:
    # Update the last modified time to be the current time
      - type: magritte-rest-string-extractor
        var: lastModifiedTime
        fromStateVar: currentTime

JSON 提取器

所有 JSON 提取器都使用 Jackson JsonNode ↗ 并遵循相同的表示法。

字段引用快速指南： 给定 JSON {"id":1}:

  • 使用 "/id" 将返回 1
  • 使用 "/" 将返回 {"id":1}

给定一个列表，例如 [1,2,3] or [{"id":1},{"id":2}]:

  • 使用 "" 将返回该列表。

可以使用通配符来引用列表中所有项的子索引或字段。例如：

给定一个包含嵌套列表的字段，例如 { "result": [[1], [2, 3, 4]] }:

  • 使用 "/result/*/0" 将返回 [1,2].

给定一个包含对象列表的字段，例如 { "result": [{ "foo": 1}, {"foo": 2}]}:

  • 使用 "/result/*/foo" 将返回 [1,2].

from pyspark.sql import functions as F
import json
import re


def flattenSchema(df, dontFlattenCols=[], jsonCols=[]):
    new_cols = []
    for col in df.schema:
        _flattenSchema(col, [], new_cols, dontFlattenCols + jsonCols, jsonCols)
    print(new_cols)
    return df.select(new_cols)


def _flattenSchema(field, path, cols, dontFlattenCols, jsonCols):
    curentPath = path + [field.name]
    currentPathStr = '.'.join(curentPath)
    if field.dataType.typeName() == 'struct' and currentPathStr not in dontFlattenCols:
        for field2 in field.dataType.fields:
            _flattenSchema(field2, curentPath, cols, dontFlattenCols, jsonCols)
    else:
        fullPath = '.'.join(['`{0}`'.format(col) for col in curentPath])
        newName = '_'.join(curentPath)
        sanitized = re.sub('[ ,;{}()\n\t\\.]', '_', newName)
        if currentPathStr in jsonCols:
            cols.append(F.to_json(fullPath).alias(sanitized))
        else:
            cols.append(F.col(fullPath).alias(sanitized))


def parse_json(df, node_path, spark):
    rdd = df.dataframe().rdd.flatMap(get_json_rows(node_path))
    df = spark.read.json(rdd)
    return df


def get_json_rows(node_path):
    def _get_json_object(row):
        parsed_json = json.loads(row[0])
        node = parsed_json
        for segment in node_path:
            node = node[segment]
        return [json.dumps(x) for x in node]
    return _get_json_object
