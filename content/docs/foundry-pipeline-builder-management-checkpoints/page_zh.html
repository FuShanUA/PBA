检查点

在构建管道时，您经常会在多个输出之间使用共享的转换节点。此逻辑通常会针对每个输出重新计算一次。借助 Pipeline Builder 中的检查点功能，您可以将转换节点标记为“检查点”，以便在下次构建期间保存中间结果。该检查点节点上游的逻辑将仅针对其所有共享输出计算一次，从而节省计算资源并缩短构建时间。

检查点有时可能导致性能下降。例如，将数据写入磁盘然后再次读取的成本可能低于多次重新计算逻辑的成本。此外，将查询拆分为多个部分可能会减少可对管道执行的优化数量。

输出必须位于同一作业组中，检查点节点才能提高管道效率。了解更多关于 Pipeline Builder 中的作业组.

添加检查点节点

下面是一个生成两个输出的管道示例： Attachment 和 Request。该转换节点 Checkpoint 在两个输出之间共享。在当前状态下，逻辑节点 Clean 和 Checkpoint 将被计算两次，每个输出各一次。

但是，我们希望两个输出仅计算 Clean 和 Checkpoint 一次。为此，请右键单击 Checkpoint 并选择 标记为检查点.

检查点策略

有三种可用的检查点策略：

  • 保存到短期磁盘 [默认]： 将每个输出临时存储在磁盘上。这是标记为检查点的节点的默认策略。
  • 保存到内存 [最快]： 将结果临时存储在内存中以便更快地访问；这对于小型数据集特别有用，但对于较大的数据集，可能会因内存限制而失败。
  • 保存为输出数据： 将检查点的最新事务保存在专用数据集中。该数据集在检查点首次部署时创建。

直方图 保存到内存 检查点策略不支持更快的管道。

默认情况下，标记为检查点的节点将对每个输出使用 保存到短期磁盘 策略。要进行配置，请选择 检查点 然后选择 配置策略.

当转换具有多个输出时（例如，如果标记为检查点的节点是 Split 转换），可以选择为每个输出选择一种检查点策略。

对于只有一个输出的节点，您必须选择一种检查点策略，或者取消该节点的检查点标记。

现在， Checkpoint 节点的顶部角落将显示一个浅蓝色徽章。

现在，将两个输出添加到同一作业组以验证检查点行为。右键单击其中一个输出（Request）以 分配作业组。选择 新建组 以打开 构建设置 面板中进行管理。

由于数据集默认位于不同的作业分组中，检查点将针对每个输出重新计算，从而抵消任何收益。要解决此问题，请将另一个输出（Attachment）添加到同一作业组，方法是选择该输出，然后选择 添加到组... （位于面板底部）。

配置节点的信息

对于 保存到短期磁盘 检查点策略下，检查点会将转换的整个结果推送到存储中，例如推送到 Hadoop 分布式文件系统 (HDFS)。例如，如果您使用此策略对连接操作设置检查点，则连接的整个结果将输出到存储中。这可能导致存储大量数据，即使数据集输出很小。
