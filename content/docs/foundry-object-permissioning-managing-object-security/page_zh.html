管理对象安全

本体论数据可以通过以下方式进行保护： 对象和属性策略 or 数据源策略。两种方法均支持 单元格级安全，即行级和列级安全的组合。

例如，考虑一个 Passenger 航空公司管理平台中的对象类型，其属性包括 User ID, Flight Number, Seat Assignment, Name, Address日 Phone Number.

  • 行级安全： 某些用户是 VIP，其对象实例（对应于支撑数据集中的行）只有在用户拥有 VIP marking.
  • 列级安全： 属性 Name, Address and Phone number 包含用户数据，只有拥有 PII marking.

你可以利用代码库升级拉取请求中的 检查访问 侧边栏中的面板，以检查某人对 Workshop 或 Slate 应用程序的访问权限，包括对依赖对象类型、其数据源以及细粒度访问控制的访问权限。更多信息请参阅 检查访问面板文档.

某些属性值引用了存储在本体论之外的其他资源中的数据。本节所述的访问控制机制仅控制属性值的可见性，而不控制这些其他资源的可见性。例如，媒体引用属性可以引用存储在媒体集中的媒体项。如果媒体集与对象类型具有不同的权限，则用户可能无法访问媒体引用属性，但仍能直接从媒体集中获取该媒体项。因此，在本体论中使用这些其他资源时，务必确保为其配置适当的权限。

对象和属性安全策略

对象和属性安全策略允许您对对象实例及其属性设置查看权限，以实现单元格级权限。这些策略可以在对象类型的 Ontology Manager 视图中直接管理，并且独立于支撑数据源的权限。

对象实例的可见性由其对象安全策略控制，而属性值的可见性由其属性安全策略控制。强制访问控制、基于分类的访问控制以及细粒度访问控制均可应用于对象和属性安全策略。它们共同实现了本体论中的单元格级安全。

仅读取时强制执行

对象或属性安全策略中的细粒度行和列控制会过滤用户可以读取的内容。这些控制不会延伸到下游输出或导出。但是，同一策略中的强制控制和基于分类的控制仍会继续应用于派生数据。为了在数据流向下游时保持行和列数据受到保护，请将这些控制与 标记 or 基于分类的访问控制。完整模型请参阅 访问控制传播.

数据源策略

对象类型的数据权限由应用于该对象类型输入数据源的权限隐式控制。

没有支撑数据源的对象类型 无法使用数据源策略。创建对象类型时，您必须配置对象安全策略。

对象和属性策略与数据源策略的对比

在大多数情况下，建议使用对象和属性安全策略来管理对象安全。它们直接在对象类型上提供统一的单元格级安全（行、列和单元格级权限）方法。与数据源策略相比，这使得它们更易于配置和维护。

对象和属性安全策略的优势

对象和属性安全策略解决了使用数据源策略时出现的若干挑战：

  • 统一的单元格级安全： 单一功能即可提供行级（对象安全策略）、列级（属性安全策略）和单元格级权限，而无需组合使用受限视图（RV）和多数据源对象类型（MDO）。
  • 简化的配置： 安全直接在 Ontology Manager 中的对象类型上进行管理，独立于支撑数据源。这降低了复杂性和维护负担。
  • 近乎即时的策略更新： 对象和属性安全策略的更改几乎立即生效。使用 RV 时，策略更改需要重新构建管道，读取操作才会遵循新策略。Multipass 中的更改（例如组成员身份或其他用户属性）仍会在短时间内缓存。
  • 流式支持： 对象安全策略可应用于由流支撑的对象类型，从而为流式数据启用行级和列级权限。
  • 分支兼容性： 对象安全策略可与 全局分支集成，支持在合并前先在分支上测试安全配置的开发工作流。

何时使用数据源策略

依赖 RV 和 MDO 的数据源策略适用于以下情况：

  1. 本体论之外的细粒度访问控制： 如果支撑数据集在本体论之外使用，并且在这些场景中需要细粒度访问控制，RV 仍然是合适的解决方案。例如，RV 可以为具有不同访问级别的用户保护对支撑数据集的读取 代码工作区。对象和属性安全策略的作用域仅限于本体论，不控制非本体论场景中对原始数据集的访问。
  2. 具有特定要求的 MDO： 如果您的对象类型出于某些原因需要 MDO，例如不同的解析策略或每个数据源不同的构建计划，则可能需要数据源策略。 了解有关此配置的更多信息.

对象输入数据源

数据集和流是最广泛使用的输入数据源资源，用于 对象类型（object types）。这些数据源的数据权限按以下方式确定：

  • 数据集: 数据集中的每一行对应于本体论中的一个对象实例，任何至少对数据集及其事务拥有 Viewer 权限的用户都将有权访问从该数据集创建的所有对象实例。
  • 流: 流是本体论中用于低延迟流式数据的输入数据源。任何至少对流数据源拥有 Viewer 权限的用户都有权访问从该流数据源创建的所有对象实例。

如果您需要使用数据源策略进行行级或列级权限控制，可以使用 受限视图（RV） 和 多数据源对象类型（MDO）.

使用 RV 和 MDO 配置数据源策略

受限视图

受限视图可对数据集中的特定行以及从这些行创建的相应对象实例启用 行级访问控制 。受限视图只能构建在数据集上，而不能构建在流或其他数据源类型上。对具有特定主键的对象实例的访问权限由谁可以访问受限视图输入数据源中的该特定行决定。

例如，可以允许某医疗机构的员工查看到其护理中心就诊的患者的数据集行和对象实例，但限制其查看仅到其他护理中心就诊的患者的数据，即使这两类数据存在于同一数据集和对象类型中。

如果某个数据集 care_event_info具有 patient_id, doctor_id日 care_center 列，则可以在其上构建受限视图，策略为 user.userAttribute('care_center') == care_center。该受限视图将仅允许访问 care_event_info 中与用户护理中心相同的行。

使用 Ontology Manager 时，可以像选择数据集一样选择受限视图作为对象类型的输入数据源。

了解有关设置受限视图以及管理对象行级权限的更多信息。

多数据源对象类型

本体论支持将多个输入数据源映射到单个对象类型。此类对象类型称为多数据源对象类型（MDO），仅在 Object Storage v2 中可用。

MDO 使您能够将来自不同数据源的列映射到对象类型的各个属性。这使您能够将与不同输入数据源对应的多种访问控制应用于单一对象类型。这些输入数据源可以是数据集或受限视图的任意组合。

例如，对于给定的护理事件对象类型，某些医疗保健员工可能需要访问包含个人健康信息的对象属性（PHI），而其他员工则不应具有访问权限。这种访问控制可以通过用 Care Event 两个独立的输入数据源支撑对象类型，并对每个输入数据源应用不同的访问控制和权限来实现。该 Care Event 对象类型以 Patient ID 作为其主键，并由数据源 patient_info 和 care_event_info.

  • patient_info 支撑，其包含列 patient_id, name, address, contact_number日 age。该数据集具有 PHI 标记。只有具有 PHI 标记访问权限的用户才能访问来自 patient_info.
  • care_event_info 的属性值。该数据集包含列 patient_id, doctor_id日 care_center。该数据集未加标记。用户无需任何标记权限即可访问来自该数据集的属性值。

这些不同的权限将被遵守并应用于对象实例。用户将无法访问映射自 patient_info的源（例如 name, address, contact_number日 age的属性，除非其具有 PHI 标记。
