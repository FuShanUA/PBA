提供上下文和附件

当您在提示词中提供相关上下文时，Pilot 会产生更好的结果。本页面介绍了您可以附加的上下文类型，以及有效编写提示词的最佳实践。

本体论上下文

您可以附加现有的 本体论 实体到您的提示词中，让 Pilot 使用现有的数据模型，而不是创建重复的实体。请按照以下步骤附加本体论上下文：

  1. 选择 添加 （在聊天面板中）。
  2. 选择要附加的实体类型：
    • 对象类型： 来自您本体论的现有对象类型
    • 操作类型： 来自您本体论的现有操作类型
    • 函数： 现有的 Foundry 函数（如果有）
  3. 搜索并选择您想要包含的实体。

选定的实体将显示为提示词输入框下方上下文区域中的标签。每个标签都会显示实体名称以及编辑权限指示器。

提供本体论上下文可以让 Pilot 使用现有的数据模型。在构建扩展或集成本体论中已有数据的应用程序时，这尤其有用。

文档上传

您可以上传文档，为您的应用程序提供额外的上下文。支持的格式包括：

  • PDF： 需求文档、规格说明、数据字典
  • Markdown： 技术文档、API 参考
  • 纯文本： 笔记、需求或任何基于文本的参考资料

要上传文档，请在聊天面板中选择 添加 ，然后选择 文件。您也可以将文件拖放到聊天面板中，或从剪贴板粘贴内容。

Pilot 会读取上传的文档，并利用这些文档为应用程序的设计和实现提供参考。

图片上传

您可以上传图片，以引导 Pilot 的设计和布局决策。常见用例包括：

  • 您想要复现或改进的现有应用程序的屏幕截图
  • 展示预期布局的线框图和原型图
  • 展示配色方案和组件样式的设计系统参考资料

Pilot 会解读上传的图片，并将视觉元素融入设计规范和前端生成中。要上传图片，请选择 添加 ，然后选择 文件，或直接从剪贴板粘贴图片。

提示词编写技巧

提示词的质量直接影响所生成应用程序的质量。请参考以下准则：

  • 具体说明数据模型： 描述您的应用程序所需的实体、属性和关系。例如，与其使用 Build a project tracker，不如尝试 Build a project tracker with projects that have a name, description, status (Active, Completed, On Hold), and a list of tasks with priorities and due dates。
  • 描述用户工作流，而不仅仅是屏幕界面： 说明用户应能完成的操作，而不仅仅是界面的外观。例如： Users should be able to filter tasks by status and assignee, drag tasks between status columns, and receive a notification when a task is overdue。
  • 引用已上传的上下文： 附加文档或图像时，请描述它们包含的内容以及 Pilot 应如何使用它们。例如： Use the attached wireframe as the layout for the main dashboard. The sidebar should match the navigation structure shown in the image。
  • 逐步迭代： 从核心功能开始，通过后续提示添加更多功能，而不是试图一次性描述所有内容。
