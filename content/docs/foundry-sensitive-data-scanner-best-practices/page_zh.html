最佳实践

敏感数据扫描器（SDS）可自动将 Foundry 的许多最强大功能（如标记）进行可配置的集成，因此应由具备一定 Foundry 基础使用能力的人员使用。以下是在使用该工具时需要牢记的一组最佳实践和指南。

优化计算资源

由于 SDS 可以配置为扫描整个 空间，可能会引发对每次一次性扫描或周期性扫描的计算成本/时间的担忧。在考虑计算时间时，需要考虑两个因素：数据集的数量和匹配条件的类型。 我们已在下面针对这两个因素提供了扫描优化指南：

(A) 优化扫描的数据集数量：

  • 仅在数据进入平台的位置进行扫描（也称为 "boundary"数据集).
  • 排除整个子文件夹 使其不被扫描，前提是内容的敏感度已知。
  • 排除带有特定标记的数据集 使其不被扫描，例如，当数据集带有 PII 或 PHI 标记、表明其中存在敏感数据时。

(B) 优化应用于每次扫描的匹配条件

对整个数据集运行基于内容的正则表达式搜索是穷尽式的，且往往非常消耗资源。SDS 通过在执行基于内容的正则表达式搜索之前，优先检查 schema 中的列名来优化计算。在实践中，这意味着在使用以下任一正则表达式匹配条件时，如果根据列判断不可能出现匹配，SDS 将阻止构建：

  • 仅匹配列名
  • 同时匹配列名和内容

对于使用语言模型匹配条件的扫描，请考虑使用 行子集 来调整提示词，或在不需要全面覆盖时使用。使用 扫描所有行 在应用之前需要完整检测时使用 匹配操作.

标记

对某个标记的访问授权是二元的（全有或全无）。无论角色如何，用户必须满足所有标记要求才能访问相应资源。 了解有关标记的更多信息. 当扫描发现匹配的数据集时，会自动应用标记。错误地使用限制性标记可能会阻碍用户使用关键工作流，且难以修复。用户应谨慎操作，将匹配操作的范围限制在特定子集内。

敏感数据扫描器中的权限模型

敏感数据扫描器可在 Foundry 中发现并保护敏感数据。权限经过精心设置，用户只能使用 SDS 执行其被允许的操作，而不会超出其对资源本身的个人权限。数据治理官可以监控整个组织的数据，而无需在每个资源上获取有风险的所有者（Owner）权限。

以下部分介绍了用户使用 SDS 与 Foundry 资源进行交互的两种方式：

  1. 通过特定的 空间角色
  2. 被指定为某个组织的 数据治理官 属于某个组织，并在该空间中拥有 Viewer 角色

要运行或配置带有 应用标记 匹配操作的扫描，您必须同时拥有 应用标记 和 移除标记 权限 对操作所使用的每个标记的权限。即使您不打算撤销该操作，也需要这两种权限。除上述空间级权限外，还需要这些权限。

作为资源所有者，用户对 SDS 扫描拥有完全控制权，并且可以管理与资源的交互，包括配置设置和取消扫描。编辑者只能根据所有者的偏好设置请求 SDS 交互——例如使用预先配置的匹配条件运行扫描，而查看者只能查看 SDS 结果。但是，“数据治理官”角色会授予与空间所有者类似的扫描权限。
