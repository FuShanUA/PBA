构建支持语音功能的 OSDK 应用程序

录音与征得同意由您自行负责

在部署任何录制或转写人类语音的应用程序之前，请确保已通知相关参与者，并已根据您所运营司法管辖区的法律要求建立了相应的同意流程。无论参与者是应用程序用户、通话中的第三方，还是任何其他声音被采集的人员，此要求都可能适用。请参阅 录音、转写与同意.

本教程将逐步介绍如何构建一个 OSDK 应用程序，用于采集麦克风音频、将其流式传输到实时模型，并播放模型的语音回复。该应用程序以 Foundry 用户的身份进行身份验证，因此所有交互都基于该用户的权限及其可访问的本体论。有关 Foundry 上实时音频的整体概览，请参阅 实时音频.

您将构建的内容

完成本教程后，您将拥有一个在浏览器中运行的 TypeScript 应用程序，它能够：

  1. 通过标准 OSDK OAuth 流程对用户进行身份验证。
  2. 直接从浏览器建立到 Foundry 代理端点的 WebSocket 连接，该端点会转发至实时模型。
  3. 为智能体提供一个从本体论读取数据的工具，并以用户权限运行。
  4. 将麦克风音频流式传输至模型，并播放模型的语音回复。

先决条件

开始之前，请确保您具备以下条件：

  • 一个通过 @osdk/create-app创建的 OSDK 应用程序。生成的应用程序包含本教程所依赖的 OAuth 脚手架。有关 OSDK 本身的完整参考，请参阅 Ontology SDK。
  • 一个 不受限制的自定义应用程序 ，已在 Developer Console 中注册。OSDK 前端通过此应用程序进行身份验证。之所以需要不受限制的应用程序，是为了让访问令牌能够包含 language-model-service:use-model 作用域，该作用域用于 第 1 步。
  • 已在您的注册中启用的实时模型。请参阅 可用音频模型 以查看列表。本教程使用 gpt-realtime-2。
  • 该 @openai/agents 包已安装在您的应用程序中：

步骤 1：获取 OAuth 访问令牌

由 @osdk/create-app 生成的 OSDK 应用程序在 src/client.ts中包含一个 OAuth 客户端。该客户端使用 createPublicOauthClient （来自 @osdk/oauth ）创建，并公开一个用于获取当前访问令牌的方法。以下各项的值： clientId、 foundryUrl 和 redirectUrl 在运行时从 osdk-* meta 标签中读取，这些标签会被注入到 index.html ，由 @osdk/create-app 根据您的 .env 配置注入。

为 OAuth 客户端配置 language-model-service:use-model 作用域，以便生成的访问令牌有权连接到实时端点。如果没有此作用域，实时端点会在身份验证期间拒绝 WebSocket 连接。此作用域仅适用于 不受限制的自定义应用程序 — 在继续之前，请确认您的应用程序未受限制。

以下代码片段展示了 src/client.ts 在添加实时音频作用域后的完整结构。该文件的大部分内容由 @osdk/create-app生成；本教程中唯一需要做的更改是将 language-model-service:use-model 包含在 scopes 数组中。这些导出在本教程的其他地方也会用到： auth 用于在下文中获取令牌， foundryUrl 用于在以下位置构建 WebSocket URL： 第 2 步，并 client 用于 OSDK 查询，在 第 3 步。

4function getMetaTagContent(tagName: string): string {
5  const elements = document.querySelectorAll(`meta[name="${tagName}"]`);
6  const element = elements.item(elements.length - 1);
7  const value = element ? element.getAttribute("content") : null;
8  if (value == null || value === "") {
9    throw new Error(`Meta tag ${tagName} not found or empty`);
10  }
11  return value;
12}

步骤 2：连接到实时端点

实时端点在以下 URL 接受 WebSocket 连接，其中 <your-foundry-domain> 是您 Foundry 环境的主机名（与 foundryUrl 在 src/client.ts中的值相同），而 model 查询参数用于选择要使用的实时模型：

wss://<your-foundry-domain>/language-model-service/ws/v1/open-ai/realtime?model=gpt-realtime-2

这是一个 Foundry 代理端点，类似于 REST LLM 提供商兼容 API 但通过 WebSocket 暴露。代理会把会话转发给底层提供商（OpenAI Direct 或 Azure OpenAI，具体取决于您的注册情况），并保留该提供商的原生实时协议。因此，您可以使用 OpenAI 实时 SDK（@openai/agents/realtime）而无需修改。

访问令牌作为 WebSocket 子协议值 传递，因为浏览器无法在 WebSocket 连接上设置自定义 Authorization 标头。请将子协议值格式化为 Bearer-<access-token>。

请将子协议值视为凭证

访问令牌作为 WebSocket 子协议值的一部分，在浏览器的开发者工具网络面板中可见。请将其视为凭据：不要将其记录到日志中，不要在面向用户的字符串中显示它，也不要将其传输到除 Foundry 端点之外的任何系统。访问令牌的有效期较短；WebSocket 会话使用其建立时所用的令牌，因此在令牌过期时，长时间运行的会话可能需要重新连接。

使用 OpenAI realtime SDK 打开连接，并提供一个自定义 createWebSocket 函数，用于构造浏览器的 WebSocket ，并传入子协议值。完整的连接流程封装在一个 async 函数中，名为 startVoiceSession ，该函数在会话就绪后返回。此函数由三个小型的命名部分组成，这些部分在下方定义，然后在本节末尾进行组合。将结果保存为，例如 src/voice/session.ts。

首先从导入语句和常量开始：

Copied!
1import {
2  RealtimeAgent,
3  RealtimeSession,
4  OpenAIRealtimeWebSocket,
5} from "@openai/agents/realtime";
6import { foundryUrl } from "../client";
7
8const PROXY_URL =
9  `wss://${new URL(foundryUrl).host}/language-model-service/ws/v1/open-ai/realtime` +
10  `?model=gpt-realtime-2`;
11const CONNECT_TIMEOUT_MS = 10_000;

定义 createTransport 来构建传输层。该 createWebSocket 回调会构建浏览器 WebSocket ，使用 bearer 令牌子协议，并附加用于记录诊断信息的错误和关闭处理程序。该 useInsecureApiKey: true 标志会禁用 SDK 中针对使用非临时 OpenAI 密钥的仅浏览器防护。该标志在此处不适用，因为身份验证由 WebSocket 子协议处理，而非由 OpenAI 密钥处理。

Copied!
1function createTransport(token: string): OpenAIRealtimeWebSocket {
2  return new OpenAIRealtimeWebSocket({
3    url: PROXY_URL,
4    useInsecureApiKey: true, // auth is via the subprotocol below, not OpenAI's apiKey
5    // eslint-disable-next-line @typescript-eslint/no-explicit-any
6    createWebSocket: async ({ url }: { url: string }): Promise<any> => {
7      const ws = new WebSocket(url, [`Bearer-${token}`]);
8
9      ws.addEventListener("error", () => {
10        console.error("WebSocket connection failed (check network tab for details)");
11      });
12
13      ws.addEventListener("close", (ev) => {
14        // 1000 = normal close, do not surface as an error.
15        if (ev.code !== 1000) {
16          console.error(`WebSocket closed: ${ev.code}${ev.reason ? ` (${ev.reason})` : ""}`);
17        }
18      });
19
20      return ws;
21    },
22  });
23}

定义 createSession 来构建会话，指定音频输入/输出格式、服务端语音活动检测以及内联转录模型，从而在对话进行的同时转录用户的语音：

Copied!
1function createSession(
2  agent: RealtimeAgent,
3  transport: OpenAIRealtimeWebSocket,
4): RealtimeSession {
5  return new RealtimeSession(agent, {
6    transport,
7    model: "gpt-realtime-2",
8    tracingDisabled: true,
9    config: {
10      outputModalities: ["audio"],
11      audio: {
12        input: {
13          format: "pcm16",
14          transcription: { model: "whisper-1" },
15          turnDetection: {
16            type: "server_vad",
17            threshold: 0.8,
18            silenceDurationMs: 500,
19            prefixPaddingMs: 300,
20          },
21        },
22        output: { format: "pcm16" },
23      },
24    },
25  });
26}

定义 awaitSessionReady 来等待会话进入可用状态。调用 session.connect() 会在会话能够发送和接收音频之前返回，因此请等待 session.created ，然后等待第一个 session.updated 事件。此后的 200 毫秒延迟让 SDK 有时间稳定下来；若没有这一延迟，最初的音频数据块可能会丢失。如果会话在 CONNECT_TIMEOUT_MS内未达到此状态，则 promise 将以超时错误拒绝。该 apiKey 字段未被使用，因为身份验证由 WebSocket 子协议处理；SDK 只要求一个非空字符串：

Copied!
1function awaitSessionReady(session: RealtimeSession): Promise<RealtimeSession> {
2  return new Promise<RealtimeSession>((resolve, reject) => {
3    const timeout = setTimeout(() => {
4      reject(new Error("Connection timeout"));
5    }, CONNECT_TIMEOUT_MS);
6
7    let created = false;
8    let updatedCount = 0;
9
10    session.on("transport_event", (ev) => {
11      if (ev.type === "session.created") {
12        created = true;
13      }
14      if (ev.type === "session.updated" && created) {
15        updatedCount++;
16        if (updatedCount === 1) {
17          setTimeout(() => {
18            clearTimeout(timeout);
19            resolve(session);
20          }, 200);
21        }
22      }
23    });
24
25    session.connect({ apiKey: "unused" });
26  });
27}

最后，将这三个部分组合成 startVoiceSession：

Copied!
1export async function startVoiceSession(
2  agent: RealtimeAgent,
3  token: string,
4): Promise<RealtimeSession> {
5  const transport = createTransport(token);
6  const session = createSession(agent, transport);
7  return awaitSessionReady(session);
8}

调用 startVoiceSession(agent, token) 在您从步骤 1 获得访问令牌并拥有智能体定义（参见步骤 3）后。当会话准备好发送和接收音频时，该函数便会返回。

步骤 3：为智能体提供一个从本体论读取数据的工具

上面的示例设置了一个通用助手。要使其发挥作用，可以为智能体提供从本体论读取数据和向本体论写入数据的工具。OpenAI 实时 SDK 支持工具调用：定义一个工具，将其注册到智能体上，模型就会调用该工具的 execute 函数（当它决定需要这些信息时）。

该工具的 execute 函数在浏览器中使用用户的 OAuth 令牌和 OSDK 客户端运行。模型永远不会直接看到本体论——它只能看到工具返回的内容。您可以决定公开哪些数据、应用哪些筛选条件，以及写回哪些内容。

将此智能体传入 startVoiceSession(agent, token) （来自第 2 步）。当用户发言时，模型会决定是否调用该工具。该工具的 execute 函数会在浏览器中针对 OSDK 客户端运行，其结果将被反馈给模型以生成响应。

工具也可以写入本体论。为此，请调用一个 操作 从工具的 execute 函数内部。操作会经过标准的 Foundry 权限和验证路径。

步骤 4：流式传输麦克风音频并播放响应

有了 RealtimeSession （由 startVoiceSession返回）后，连接麦克风采集和音频播放。使用浏览器的 MediaDevices API 采集麦克风音频，将其转换为 24 kHz 的 16 位 PCM，并在每个数据块到达时通过 session.sendAudio(chunk) 将其转发到会话。应用程序会将从会话接收到的音频数据块加入播放队列。

麦克风采集和播放队列的实现不在本教程的讨论范围内。接收音频的会话级连接方式如下：
