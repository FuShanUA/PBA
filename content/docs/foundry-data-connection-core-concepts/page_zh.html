数据源支持两种策略类型：

  • 直接连接策略: 用于可从 Foundry 直接访问的系统。对于云端托管的 Foundry 实例，这意味着公共互联网；对于私有部署的 Foundry，这意味着 Foundry 所安装的网络。

直接连接策略和代理策略都可以分配给同一个数据源，以满足需要两种网络路径的使用场景。例如，某些使用场景需要从互联网托管的系统获取凭据，并使用该凭据向本地系统进行身份验证。

批量同步

批量同步 从外部系统读取数据并将其写入 Foundry 数据集。批量同步定义了应读取哪些数据以及在 Foundry 中输出到哪个数据集。批量同步可以配置为增量同步数据，并支持在有或没有对应结构的情况下同步数据。 了解如何设置同步。

批量同步是 事务性的。每次同步运行会在输出数据集上的单个事务中写入数据。如果同步在执行过程中的任何时刻失败，事务将被中止，该次运行的数据不会被提交。这意味着部分失败不会导致部分数据；输出数据集将保持失败同步之前的状态。具体错误取决于失败的原因。您可以在同步的 运行 标签页上查看失败运行的错误消息和完整堆栈跟踪。对于常见的失败模式，请了解如何 对同步进行故障排除.

总体而言，批量同步主要有两种类型：

  • 文件批量同步： 允许将不带 schema 的文件直接同步到 Foundry 数据集中。这些文件随后可以在下游转换中使用；例如，使用 基于文件的转换。支持文件批量同步的最常见系统是文件系统和 blob 存储服务，例如 S3, ABFS, Google Cloud Storage, SMB日 SharePoint online. 了解更多关于文件批量同步的信息。
  • 表批量同步： 允许将带 schema 的数据同步到 Foundry 数据集中。在这种情况下，同步定义的一部分还包括如何在外部系统 schema 与 Foundry 支持的 schema 选项之间转换类型。支持表批量同步的最常见系统是数据库和 SaaS 提供商，例如 进行表批量同步的配置, Postgres, SAP, Salesforce日 NetSuite.

Iceberg 同步

Iceberg 同步 从外部源读取数据并直接写入 Foundry Iceberg 表，而不是标准的 数据集。Iceberg 同步支持非增量和增量两种数据摄取方式，以及多种写入模式。Iceberg 同步仅在 您必须正确配置出站策略（如果使用 运行时上受支持，并且仅适用于部分连接器。 从 Data Connection 了解更多关于将数据同步到 Iceberg 表的信息。

流式同步

流式同步 提供从提供低延迟数据源的系统流式传输数据的能力。数据会被传送到 流式数据集中。支持流式同步的系统示例包括 Kafka, Amazon Kinesis日 Google Pub/Sub.

了解更多关于流式同步的信息。

变更数据捕获同步

变更数据捕获（CDC）同步 与流式同步类似，但会自动将额外的变更日志元数据传播到数据传送到的流式数据集中。这种类型的同步通常用于支持某种形式低延迟复制的数据库。 了解更多关于变更数据捕获同步的信息。

媒体同步

媒体同步 允许将媒体数据导入到 媒体集中。与标准数据集相比，媒体数据集为在整个 Foundry 中摄取、转换和使用媒体数据提供了更好的工具。在处理 PDF、图像、视频和其他媒体时，我们建议使用媒体数据集而非普通数据集。 了解更多关于媒体同步的信息。

HyperAuto

HyperAuto 是一项专用功能，可以动态发现您的 SAP 系统的 schema，并自动完成同步、管道以及 Foundry 中相应本体论的创建。HyperAuto 目前仅支持 SAP。 了解更多关于 HyperAuto 的信息。

文件导出

文件导出 与文件批量同步相反。执行文件导出时，数据直接取自 Foundry 数据集中包含的底层文件，并按原样写入目标系统中的文件系统位置。 了解更多关于文件导出的信息。

表导出

表导出 与表批量同步相反。执行表导出时，数据以行的形式从带 schema 的 Foundry 数据集中导出，然后写入目标系统中的表。 了解更多关于表导出的信息。

流式导出

流式导出 与流式同步相反。执行流式导出时，数据从 Foundry 流中导出，记录被写入目标系统中指定的流式队列或主题。 了解更多关于流式导出的信息。

Webhook

Webhook 表示向 Foundry 之外的源系统发出的请求。Webhook 请求可以在 Data Connection 中灵活定义，以实现与外部系统的广泛连接。 了解更多关于 webhook 的信息。

虚拟表

虚拟表 表示将外部系统中的表格数据注册为 Foundry 中虚拟表资源的能力。

除了注册单个虚拟表之外，此功能还支持动态发现并自动注册外部系统中的所有表。

了解更多关于虚拟表的信息。

虚拟媒体

虚拟媒体 的工作方式类似于 媒体同步，允许在 媒体集 中使用来自外部系统的媒体，但无需将数据复制到 Foundry 中。相反，外部系统中包含的媒体文件可以注册为特定媒体集中的虚拟媒体项。

了解更多关于虚拟媒体的信息。

探索

交互式 探索 功能允许您在执行同步、导出或其他与该系统交互的功能之前，查看外部系统中包含的数据。

探索最常用于检查连接是否按预期工作，以及是否使用了正确的权限和凭据进行连接。

在代码中使用

在代码中使用连接的能力旨在让开发者扩展和自定义从 Foundry 到其他系统的连接。Palantir 的总体原则是：平台上通过专用连接器和点击式配置选项实现的任何功能，都应能通过编写自定义代码来实现。开发者随时可以切换到基于代码的连接方式，以便对执行外部连接的工作流的功能或性能进行更精细的控制。

任何连接器都可以在代码中使用；在大多数情况下，我们建议使用 REST API 源 or 通用连接器 在代码中进行连接。

Agent worker 连接不能在代码中使用。此外，某些凭据类型（如云身份、出站应用程序和 OIDC）目前可能无法在代码中使用。
