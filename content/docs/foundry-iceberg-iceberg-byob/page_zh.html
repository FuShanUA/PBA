为 Iceberg 表配置自带存储桶（BYOB）存储

本指南介绍了如何配置客户管理的存储桶，以供 Foundry Iceberg 表使用。这些步骤仅在使用自带存储桶（BYOB）存储时才需要执行。如果您使用的是 Foundry 管理的存储，则无需进行额外的配置。

Foundry 支持在 AWS（S3）、Azure（ADLS）和 Google（GCS）上使用 BYOB 存储。

步骤 1：创建您的存储桶

理想情况下，应在与 Foundry 实例相同的区域中预配您的存储桶。虽然这不是必需的，但为了获得最佳性能，建议这样做。

在存储账户上配置适当的网络访问权限，以允许从 Foundry 进行连接。

AWS S3

  1. 预配一个 S3 存储桶。

  2. 创建一个 IAM 角色，使其在 S3 存储桶和用于加密该存储桶的 KMS 密钥上具有以下权限：

    权限资源
    s3:DeleteObjectS3 存储桶
    s3:GetObjectS3 存储桶
    s3:ListBucketS3 存储桶
    s3:PutObjectS3 存储桶
    kms:DecryptKMS 密钥
    kms:EncryptKMS 密钥
    kms:GenerateDataKeyKMS 密钥
    sts:GetFederationToken—

  3. 创建一个可以担任您所创建角色的 IAM 用户或 OIDC 身份提供商。在配置 Data Connection 源时，您将使用该 IAM 用户的凭证或该 OIDC 提供商的令牌。请参阅 S3 源 文档，以了解有关受支持的身份验证机制的更多详细信息。

若要设置托管在与您的 Foundry 注册相同区域中的 S3 存储桶,需要进行额外配置。您必须在 网络出口 (位于 控制面板中)明确允许来自 Palantir 的 VPC 终端节点的流量访问该存储桶。请在 网络出口文档中详细了解这些要求。

Azure ABFS

  1. 预配存储帐户和容器。

  2. 预配用于身份验证的客户端凭据。请参阅 ABFS 源文档 ,以详细了解支持的身份验证机制。

    对于 Iceberg BYOB,请在源中配置 ADLS 终端节点,即 dfs.core.windows.net。 blob.core.windows.net 终端节点不受支持。

  3. 授予服务主体对存储位置的访问权限:

    • 请在用于存储数据的容器上分配 Storage Blob Data Contributor ↗ 角色。
    • 请确保服务主体在存储帐户级别至少具有 Delegator 权限。仅容器级别的权限不足以满足 Foundry 的要求。

Google GCS

  1. 预配 Google Cloud Storage 存储桶。

  2. 创建 Google Cloud IAM 服务帐号。

  3. 授予服务帐号对存储桶的访问权限:

    • 在存储桶上分配 Storage Object Admin ↗ 角色,以允许 Foundry Iceberg 读取、写入和删除 Iceberg 元数据文件和数据文件。
    • 分配 Service Account Token Creator ↗ 在服务账户本身上，以便 Foundry 能够向 Iceberg 客户端发放短期有效且限定作用域的凭据。

  4. 为服务账户创建 JSON 服务账户密钥或等效的 PKCS8 凭据值。在为 BYOB Iceberg 存储使用 GCS 源时，这些是受支持的身份验证方法。

第 2 步：创建 Data Connection 源

存储桶预配完成后，创建一个 Data Connection 源，以将 Foundry 连接到您的存储。为 BYOB 用途配置源需要该源上的 所有者 角色。如果您没有所有者角色，请联系源所有者或您的平台管理员来更新这些设置。有关更多信息，请参阅 源权限。

BYOB 源和凭据具有很高的特权，因此请为其配置限制性的访问设置，例如将它们放置在仅限管理员访问的项目中。限制访问可以控制哪些人能够访问这些凭据，并防止未经授权的修改，这类修改可能会中断您对 BYOB Iceberg 数据的访问。

当存储桶用作 Iceberg 表的支撑存储时，在该存储桶上配置的所有出站策略都将可供访问这些表的工作流使用。这些工作流中由用户编写的代码将被允许出站到这些策略所允许的目的地。

  1. 在 Data Connection 中创建新源（可以是 S3、 ABFS或 Google Cloud Storage），使用您配置的凭证。
  2. 可选：为您的 Iceberg 表指定基本路径前缀，方法是将其附加到源 URL（例如， s3://bucket-name/base-path/）。如果源中未提供基本路径，Foundry 会将 foundry-iceberg 设置为 Iceberg 基本路径。 在将源配置为 Iceberg 存储位置后，请勿修改基本路径，否则可能会破坏对现有表的访问。
  3. 使用所选源支持的身份验证方法：
    • 对于 ADLS 和 S3： Data Connection 提供的任何身份验证机制均受支持，包括 access key and secret 或 OIDC。
    • 对于 GCS： JSON credentials 或 PKCS8 auth 是受支持的选项。
  4. 在源上开启 启用导出到此源 设置。
  5. 将 代码导入配置 设置保持为禁用状态。即使您从代码仓库访问 Iceberg 表，Foundry Iceberg 也不需要在源上进行代码导入。
安全注意事项

请勿将存储桶的凭证直接授予 Iceberg 客户端或其他工具。相反，应利用 Foundry Iceberg 目录的凭证分发机制来提供限定范围的短期访问权限，详情请参阅 访问委托与凭证分发。

步骤 3：在 Control Panel 中添加存储桶

创建数据连接源后，请在 Control Panel 中将该存储桶添加到您的 Iceberg 存储配置中。请参阅 配置存储位置 以了解具体操作说明。
