TypeScript OSDK 迁移指南（1.x 到 2.0）

本指南旨在帮助您将使用 TypeScript OSDK 1.x 的应用程序迁移到 TypeScript OSDK 2.0。以下章节将说明两个版本之间的差异，并重点介绍语法和结构方面的相关变更。

TypeScript 文档也可在平台内的 Developer Console 中查看，地址为 /workspace/developer-console/。请使用版本选择器选择 2.0 以获取 TypeScript OSDK 2.0 的文档。

为什么要从 TypeScript OSDK 1.x 升级到 2.0？

性能与可扩展性

TypeScript OSDK 1.x 使用户能够在 Palantir 平台之外与本体论进行交互。但是，此初始版本的可扩展性有限：

  • TypeScript OSDK 1.x 会为任何对象、操作或其他本体论条目生成完整的代码实现。这意味着 OSDK 1.x 的规模会随您整个本体论的大小而扩展，而本体论可能非常庞大。
  • TypeScript OSDK 1.x 将客户端与生成的本体论紧密耦合。

TypeScript OSDK 2.0 通过彻底重构 SDK 的生成方式以及访问本体论的方式，提供了多项性能和易用性改进。

  • TypeScript OSDK 2.0 的规模随本体论的形状和元数据（而非实际本体论）线性扩展。这显著提升了 OSDK 的性能，因为 OSDK 不再与本体论中的所有条目绑定。TypeScript OSDK 2.0 还支持延迟加载，这意味着应用程序只需在需要时加载所使用的内容。
  • TypeScript OSDK 2.0 将客户端与生成的代码分离，通过支持更快的库依赖更新而无需重新生成 SDK，使部署快速热修复变得更加容易。TypeScript OSDK 2.0 还通过 OSDK 代码库以指数级提升了代码复用能力。
  • TypeScript OSDK 2.0 提供了精简的代码生成，在基于大型本体论进行构建时可以显著提高迭代速度。

有关两个版本之间主要设计差异及其背后原因的更多详细信息，请查阅 开发者文档 ↗ （位于开源 TypeScript OSDK 代码仓库中）。

支持与功能

新版 TypeScript 版本的 OSDK 增强了与本体论的交互能力。因此，新的功能发布（例如 接口（interfaces） 和 媒体集 将需要 TypeScript OSDK 2.0。

在 TypeScript OSDK 2.0 发布后，Palantir 将至少在一年内继续支持 TypeScript OSDK 1.x 版本。

如何从 TypeScript OSDK 1.x 升级到 2.0？

您可以在 Developer Console 中为现有应用程序生成新版本的 SDK，方法是使用 “SDK 版本” 标签页中的 TypeScript OSDK 2.0 生成器。现有应用程序还必须安装 所需的依赖项 才能使用新生成的 SDK。在 Developer Console 中创建的新应用程序将默认使用 TypeScript OSDK 2.0 生成器生成 SDK，开发者可以按照 “开始开发” 标签页。

从 TypeScript OSDK 1.x 迁移到 2.0

  1. 确保您已安装 所有新需要的依赖项 到您的项目中。
  2. 实例化一个 新的 TypeScript OSDK 2.0 客户端.
  3. 修改您项目的 查询调用，重点更新调用的语法，并根据需要调整返回类型的处理方式。
  4. 修改您项目的 操作调用。除语法外，这里的主要变更是更新可能正在处理验证或操作编辑响应的代码。
  5. 迁移 对象类型（object types）.
    1. 全面审查代码中如何使用 OSDK 对象类型。
      1. 确定您在哪些地方依赖于 OSDK 1.x 版本生成的对象类型，并了解 它们与 2.0 版本使用的类型有何不同 。
      2. 为您的代码库选择一个 最优的解决方案路径 。
    2. 接下来，审查您的 OSDK 使用情况，并修改对象加载以使用新客户端。请按照 对象语法转换章节 中的步骤操作，并注意属性类型的任何变更。
  6. 审查 其他差异 两个版本的 OSDK 之间的差异。

用法和常规语法

TypeScript OSDK 1.x（旧版）

在 TypeScript OSDK 1.x 中，您可以通过嵌套的对象结构访问客户端上的方法。例如：

Copied!
1
 legacyClient.objects.legacyObject.fetchPage();

TypeScript OSDK 2.0

在 TypeScript OSDK 2.0 中，客户端现在可以直接调用。这意味着您可以与客户端进行交互，传入您想要处理的对象或操作。新的使用模式通常遵循以下语法：

Copied!
1
2
client(myObject).fetchPage()
client($Objects.myObject).fetchPage()

对象

TypeScript 1.x 版本和 2.0 版本中对象类型的主要区别在于用于访问对象数据的不同类型。在 1.x 版本中，您可以通过与 myObject 类型交互来访问对象的属性。然而，在 2.0 版本中，与旧版对象类型类似的功能存在于包装类型中： Osdk.Instance<myObject>.

这反映在整个 SDK 的方法返回类型中。例如，TypeScript OSDK 1.x 的页面结果类型是 Page<myObject>，而 TypeScript OSDK 2.0 的页面结果类型是 PageResult<Osdk.Instance<myObject>>.

这在转换代码时会产生几个您可能遇到的兼容性问题。

问题： Osdk.Instance<myObject> 不等同于 legacyMyObject

两个对象内的属性发生了重大变化。

  • TypeScript OSDK 1.x 使用 GeoShape and GeoPoint 而 TypeScript OSDK 2.0 使用 GeoJSON
  • TypeScript OSDK 1.x 使用 Timestamp and LocalDate 而 TypeScript OSDK 2.0 将这些类型视为 strings

假设您想用新客户端替换对象加载调用，但不想更改任何期望旧版 TypeScript OSDK 1.x 对象类型的辅助函数。假设您仍在从旧版 TypeScript OSDK 1.x 导入对象类型；在这种情况下，由于两种类型不兼容，您将遇到错误。

const objectResult: Result<legacyMyObject, GetObjectError> =

这是因为 Osdk.Instance<myObjectV2> 与 legacyMyObject.

问题： ObjectType ≠ Osdk.Instance<ObjectType>

在 TypeScript OSDK 2.0 中，将对象类型包装在 Osdk.Instance<> 中对于访问各种属性至关重要。 Osdk 包装器将这些属性提升到类型的顶层，使其更类似于 TypeScript OSDK 1.x 中的旧版类型。

然而，如果您将对象类型导入修改为来自 TypeScript OSDK 2.0，则会出现问题。如果没有 Osdk 包装器，您将无法在顶层访问对象属性，并且导入将缺少上面列出的其他字段。

Copied!
1

3
4

const object = client(myObjectV2).fetchOne("<primaryKey>");
    -> returns Osdk.Instance<myObjectV2>
const locationName = getObjectLocation(object)

function getLocation(obj: myObjectV2){ ... }

这是因为 Osdk.Instance<myObjectV2> 与 myObjectV2.

解决方案路径

考虑以下几种方式来编辑您的代码，以便在 TypeScript OSDK 2.0 中使用新的 OSDK 对象类型：

  1. 直接替换： 在修改对象检索时，将代码库中所有旧版对象类型的实例替换为相应的 TypeScript OSDK 2.0 对象类型。这对于简单的用例是最优的，但对于大量使用 TypeScript OSDK 1.x 对象类型的代码库来说则具有挑战性。
  2. 自定义前端类型： 在将对象迁移到 TypeScript OSDK 2.0 之前，请先重构你的代码，使用自定义前端类型来替代内置的旧版 TypeScript OSDK 1.x 类型。然后，开发一个转换器函数，将旧版 TypeScript OSDK 1.x 类型映射到你的自定义类型。当你开始迁移到 TypeScript OSDK 2.0 时，只需更新该转换器函数，代码库的其余部分保持不变。

    await legacyClient.ontology.objects.legacyObject.fetchOneWithErrors("<primaryKey>");

访问对象 RID

在 TypeScript OSDK 2.0 中，获取对象时默认不包含对象 RID。要访问对象的 RID，你需要使用 $includeRid: true 选项在你的 fetch 调用中显式请求，并对返回的实例进行相应的类型标注。

TypeScript OSDK 2.0

Copied!
1
2
3
4
5
const objectWithRid: Osdk.Instance<myObject, "$rid"> =
    await client(myObject).fetchOne("<primaryKey>", { $includeRid: true });

// The RID is now available on the returned object
const rid = objectWithRid.$rid;

直方图 $includeRid 选项也可以与 fetchPage 及其他 fetch 方法一起使用。请确保使用 Osdk.Instance<ObjectType, "$rid"> 在 $rid 属性对返回的对象进行类型标注。

操作验证和编辑

如果你在 OSDK 1.x 中验证输入或接收 ActionEdits ，现在可以通过指定 $returnEdits 和 $validateOnly 属性 在 Options 对象。无法同时返回编辑内容和 validateOnly 。

Copied!

    { mode: ActionExecutionMode.VALIDATE_AND_EXECUTE,
    returnEdits: ReturnEditsMode.ALL });

    { mode: ActionExecutionMode.VALIDATE_ONLY });

其他差异

DateTime 处理

TypeScript OSDK 的 1.x 版本提供了用于处理日期和时间的自定义类型，例如 LocalDate 和 Timestamp。TypeScript OSDK 2.0 不提供 DateTime的具体类型。相反，对于 OSDK 中返回和接受 DateTime 值的操作，我们改用符合国际标准 ISO 8601 ↗.

的原始字符串。使用 DateTime 属性时，OSDK 期望格式正确的 ISO 8601 字符串。例如，当使用 where 子句过滤对象集时，如果使用 DateTime 属性，您必须提供格式正确的字符串：

Copied!
1
2
3
4
5
client(myObject).where({
    "dateTimeProperty": {
        "$gt": "2010-10-01T00:00:00Z",
    }
});

DateTime 来自各种 OSDK 方法的值也将以此格式返回。例如，加载对象时， DateTime 对象上的属性将以日期时间字符串的形式返回。
