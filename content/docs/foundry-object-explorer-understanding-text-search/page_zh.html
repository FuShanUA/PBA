了解文本搜索

Foundry 平台上的文本搜索（包括 Object Explorer、Workshop 和 Functions API 中的搜索）依赖于底层搜索引擎，该引擎通过一种称为 分析器的机制来处理文本。了解分析器的工作原理有助于您编写更有效的搜索查询，并在应用程序中构建更好的搜索体验。

文本分析的工作原理

当字符串属性被编入索引以供搜索时，平台会通过分析器处理其值。默认分析器称为 标准分析器 （参见 Lucene StandardAnalyzer ↗），会执行以下步骤：

  1. 将文本拆分为单个单词，这些单词称为 词元，拆分发生在空白字符和标点符号的边界处。
  2. 将所有词元转换为小写。

例如，属性值 The Quick Brown Fox 会被存储为词元 the、 quick、 brown和 fox。当您搜索 quick时，搜索引擎会将该词元与已存储的词元进行匹配，并找到匹配项。

这种基于词元的方法具有重要影响：

  • 默认情况下，搜索 不区分大小写 ，因为在建立索引时所有词元都会被转换为小写。
  • 非短语查询会独立匹配各个词元。例如，搜索 brown fox 会评估 brown 和 fox 词元是分开匹配的，因此无论顺序或邻近程度如何，只要属性同时包含这两个词元，就会匹配。若要求这些词元按顺序连续出现，请使用短语搜索（"brown fox"）。
  • 搜索 rown 并 不会 匹配 brown ，因为 rown 不是一个完整的词元。

分析器类型

字符串属性使用的分析器在本体论中进行配置。可用的分析器类型如下：

分析器行为示例值生成的词元
标准（默认）按空白字符和标点符号拆分，并转换为小写The Quick-Brown Foxthe、 quick、 brown、 fox
简单按任意非字母字符拆分，并转换为小写（数字和标点符号会被丢弃）The Quick-Brown Fox 42the、 quick、 brown、 fox
不分析将整个值存储为单个词元The Quick-Brown FoxThe Quick-Brown Fox
空白仅按空白字符拆分，并保留大小写The Quick-Brown FoxThe、 Quick-Brown、 Fox
语言应用特定于语言的分词、词干提取和停用词移除Running quickly （英语）run、 quick

语言分析器支持以下语言： english、 french、 german、 japanese、 korean、 arabic以及 combined_arabic_english。

您可以在 Ontology Manager 中查看或更改属性的分析器，相关设置位于属性的搜索配置下。属性必须启用 Searchable 渲染提示才能被搜索。

词元中的特殊字符处理

标准分析器将下划线和句点视为词元的一部分，而非分隔符。这意味着：

  • banana_pudding 被存储为单个词元 banana_pudding，而不是 banana 和 pudding。
  • user.name 被存储为单个词元 user.name，而不是 user 和 name。

搜索 banana 将 不会 匹配值 banana_pudding （使用基于词元的搜索方法时）。如果您需要匹配此类值，请使用通配符搜索，例如 banana* ，或考虑使用空格分析器。

在 Object Explorer 中搜索

Object Explorer 仍是用于本体论发现、全局搜索和查看单个对象的主要界面。 Insight 在 Object Explorer 的基础上构建，提供更丰富的分析功能，并可与其一同使用。

Object Explorer 提供两种搜索界面，每种界面具有不同的匹配行为。

全局搜索栏

Object Explorer 主页和结果页面上的全局搜索栏会对所有对象类型的所有可搜索属性执行基于词元的搜索。默认情况下，查询中的每个单词都将使用 OR 逻辑进行独立搜索。例如，搜索 yellow cab 返回的对象将匹配 yellow 或 cab。

您可以使用以下搜索语法功能来修改此行为（详见 搜索语法）：

  • 短语搜索： 将词语括在引号中（"yellow cab"），以要求精确匹配整个短语。
  • 逻辑运算符： 使用 AND、 OR和 NOT 来组合搜索条件。
  • 通配符： 使用 * 来匹配零个或多个字符，或者 ? 来匹配单个字符。支持尾部通配符（term*）。请注意，不支持组合使用前导和尾部通配符（例如 *row*）。
  • 模糊搜索： 将 ~ 附加到词项以查找近似匹配项。

前导通配符搜索在全局搜索栏中 不 受支持。该功能仅在探索中对单个字符串属性进行筛选时可用，且仅适用于具有“ 启用前导通配符 ”渲染提示（该提示已在 本体论管理器中启用）的字符串属性。还必须选中“ 可搜索 ”渲染提示。有关配置渲染提示的更多信息，请参阅 渲染提示。

探索中的属性筛选器

在探索特定对象类型时，您可以为单个字符串属性添加关键字筛选器。这些筛选器提供以下匹配模式：

模式行为
包含（默认）匹配其属性包含所有搜索词元的对象
开头为匹配其属性包含以搜索词开头的词元的对象（等效于 term*）
精确匹配匹配其属性值与搜索词完全一致的对象
不是排除其属性包含搜索词元的对象

属性关键字筛选器与属性分析器生成的各个词元进行匹配。如果属性使用了 未分析 分析器，整个值会被视为单个词元，并且必须相应地进行匹配。

前导通配符搜索

前导通配符搜索可让您查找属性值以特定词语结尾的对象。例如，搜索 *smith 会匹配如下值： Goldsmith、 Blacksmith和 smith。

启用前导通配符搜索

要使用前导通配符搜索，您必须在相关字符串属性上启用 启用前导通配符 渲染提示：

  1. 在 Ontology Manager中，导航到对象类型，然后选择您要配置的字符串属性。
  2. 在属性编辑器中，选择 启用前导通配符 渲染提示。
  3. 确保 可搜索 渲染提示也处于选中状态，因为前导通配符需要该提示才能正常运行。
  4. 保存更改，并将该对象类型的支撑数据源重新索引到 Object Storage v1 (Phonograph) 中。您可以等待下一次触发的重新索引，也可以从 数据源 选项卡中手动启动一次。

有关可用渲染提示的完整列表，请参阅 渲染提示。

使用前导通配符搜索

启用该渲染提示后，您便可在 Object Explorer 的属性筛选器中使用前导通配符，只需在搜索词前面加上 *。例如：

  • *smith 会匹配 Goldsmith、 Blacksmith和 smith。
  • *ing 会匹配 running、 swimming和 ing。

组合使用前导和尾随通配符（*term*） 不 受支持。您可以使用前导通配符（*term）或尾随通配符（term*），但不能同时使用两者。如果需要部分字符串匹配，请考虑使用 Contour 或 Workshop 筛选列表中的正则表达式模式。

在 Workshop 中搜索

Workshop 提供了多种搜索和筛选对象的方法，每种方法各有不同的功能。

筛选列表关键词搜索

筛选列表 关键词搜索组件支持五种搜索模式，用户可在查询时选择：

模式行为
全部搜索范围最广。结合 token 匹配、通配符匹配和前缀匹配，返回与查询部分或完全匹配的任何结果。通配符子匹配会将查询直接与已索引的 token 进行比较，而不会对查询应用分析器，因此通配符查询在使用 Not analyzed 或 Whitespace 分析器的属性上表现最为可预测。
任意匹配属性包含任意搜索 token 的对象
精确匹配属性按顺序以精确短语形式包含所有搜索 token 的对象
高级支持布尔语法，可使用 AND、 OR、 NOT、引号和括号进行复杂查询
正则表达式通过将正则表达式模式应用于属性 token 来匹配对象

有关高级筛选的更多详细信息，请参阅 Filter List 高级筛选 文档。

Exploration 搜索栏小组件

Exploration Search Bar 小组件在 Workshop 中使用与 Object Explorer 全局搜索栏相同的搜索基础设施。它支持相同的语法，包括用于短语搜索的引号、逻辑运算符、通配符和模糊搜索。

对象集筛选变量

对象集筛选变量 支持一种 CONTAIN 执行仅前缀匹配的筛选器。例如，如果属性值为 id000123 ，而筛选查询为 id0001，则视为匹配。但是，查询 d0001 将 不会 匹配，因为它并非从值的开头开始。

在函数 API 中搜索

函数 API 通过其字符串筛选方法对文本搜索行为提供最精细的控制：

方法行为
.exactMatch()匹配属性值与查询字符串完全匹配的对象
.phrase()将查询拆分为多个词元，并匹配按顺序包含所有词元且其间没有其他词元的值
.phrasePrefix()与 .phrase()相同，但最后一个词元还会匹配以其开头的词元
.prefixOnLastToken()将查询拆分为多个词元，并匹配以任意顺序包含所有词元的值，其中最后一个词元还会匹配以其开头的词元
.matchAnyToken()将查询拆分为多个词元，并匹配包含其中任意词元的值
.matchAllTokens()将查询拆分为多个词元，并匹配包含所有词元（不限顺序）的值
.fuzzyMatchAnyToken()与 .matchAnyToken() 相同，但允许编辑距离内的近似匹配
.fuzzyMatchAllTokens()与 .matchAllTokens() 相同，但允许编辑距离内的近似匹配

.phrase() 和 .phrasePrefix() 方法不会跨过由下划线或句点形成的词元边界进行匹配。例如， .phrase("banana") 无法匹配值 banana_pudding ，因为 banana_pudding 是单个词元。

常见陷阱

  • 部分单词搜索无法匹配词元： 搜索 app 不会匹配 application ，除非使用通配符（app*）或前缀搜索方法。这是因为标准分析器会生成词元 application，而 app 并非精确的词元匹配。
  • 下划线和句点可防止词元被拆分： 标准分析器会将 first_name 和 user.name 视为单个词元。如果需要搜索 first （位于 first_name中），请使用通配符，或考虑更改该属性的分析器。
  • 在 Object Explorer 中，不带引号的多词查询使用 OR 逻辑： 搜索 New York 时，Object Explorer 全局搜索栏会返回匹配 new OR york的对象，其中可能包含您意料之外的结果。请使用 "New York" 进行精确短语匹配。
  • 通配符筛选器不会对查询进行分析： 在使用通配符搜索（例如 Quick*）时，查询字符串不会经过分析器处理，而是逐字符地与已建立索引的词元进行比较。这会带来两个后果：
    • 大小写必须与索引中的形式一致。 对于使用标准分析器（会将所有词元转换为小写）的属性，包含大写字母的通配符查询将无法匹配，即使原始文本在分析将其转换为小写之前包含这些字母。
    • 多词通配符查询无法匹配。 由于每个已建立索引的词元都是单个词，因此包含空格的通配符查询（例如 a search term*）会与各个词元进行比较，且无法匹配。因此，通配符搜索实际上仅限于单个词的查询。如需进行跨词的部分匹配，请考虑使用 Contour 或 Workshop 筛选列表中的正则表达式模式。
  • 前导通配符需要渲染提示： 前导通配符搜索（*term）仅适用于已启用 Enable leading wildcards 渲染提示的字符串属性，该提示需在 本体论管理器中启用。若没有此渲染提示，前导通配符查询将不会返回结果。
  • 不支持同时使用前导和尾部通配符： 您无法在对象浏览器或 Workshop 中搜索 *term* 。如需部分字符串匹配，请考虑使用 Contour 或 Workshop 筛选列表中的正则表达式模式。
