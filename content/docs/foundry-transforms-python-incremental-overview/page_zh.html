增量转换

增量计算是一种对输入数据集执行转换以生成输出数据集的高效方法。通过利用转换的构建历史，增量计算避免了每次运行转换时都重新计算整个输出数据集的需要。输入数据集和输出数据集不能相同；输入和输出数据集必须不同，以避免创建循环（环形）依赖。

有关如何创建和管理增量管道的端到端指导，请参阅 构建管道 区域的字段中添加命令。

在本节中，我们将通过一个不使用增量转换的代码示例来考察增量转换的优势：

from transforms.api import transform, Input, Output


@transform.spark.using(
    students=Input('/examples/students_hair_eye_color'),
    processed=Output('/examples/hair_eye_color_processed')
)
def filter_hair_color(students, processed):
    students_df = students.dataframe()

    # This is inefficient because the filter function is performed over the entire input rather than on new data only
    processed.write_dataframe(students_df.filter(students_df.hair == 'Brown'))

如果有新数据添加到 /examples/students_hair_eye_color 输入数据集， filter() 将在整个输入上执行，而不仅仅是对添加到输入中的新数据执行。这既浪费计算资源又浪费时间。

如果转换能够感知其构建历史，它就可以更智能地计算其输出。更具体地说，它可以使用对输入所做的更改来修改输出数据集。这种在重新物化表时使用已物化数据的过程称为 增量计算。如果没有增量计算，输出数据集总是会被最新的转换输出替换。

回到上面显示的示例转换。该转换对 filter() 数据集执行 students 以写出棕色头发的学生。使用增量计算时，如果有关两名新学生的数据被追加到 students，该转换可以利用其构建历史的信息，仅将新的棕色头发学生追加到输出中：

+---+-----+-----+------+                  +---+-----+-----+------+
| id| hair|  eye|   sex|                  | id| hair|  eye|   sex|
+---+-----+-----+------+     Build 1      +---+-----+-----+------+
| 17|Black|Green|Female|    --------->    | 18|Brown|Green|Female|
| 18|Brown|Green|Female|                  +---+-----+-----+------+
| 19|  Red|Black|Female|
+---+-----+-----+------+
        ...                                         ...
+---+-----+-----+------+     Build 2      +---+-----+-----+------+
| 20|Brown|Amber|Female|    --------->    | 20|Brown|Amber|Female|
| 21|Black|Blue |Male  |                  +---+-----+-----+------+
+---+-----+-----+------+

def filter_hair_color(students, processed):
    students_df = students.polars('added')
    processed.write_table(students_df.filter(pl.col('hair') == 'Brown'))

限制和注意事项

Code Repositories 预览功能始终以非增量模式运行转换，即使你向 require_incremental=True 装饰器传入了 incremental() 装饰器。 VS Code 预览 支持增量行为。

当参与连接的数据集之一是会被 完整读取 的引用表，而另一个是以增量方式读取的增量数据集时，计算连接是安全的。但是，以增量方式读取参与连接的两个数据集需要特殊处理。请参阅示例 利用增量转换来连接大型数据集 的文档以获取更多信息。

当对流式数据集运行增量轻量级转换时，增量窗口中可能没有要处理的新文件，此时对空输入调用 .polars(lazy=True) 可能会触发 BinderException ，因为底层集成需要一个非空的文件列表。为避免此错误，请使用 is_incremental 上下文中的属性，并在调用之前检查输入是否有数据 .polars(lazy=True):

from transforms.api import transform, incremental, Input, Output


@incremental()
@transform.using(
    my_output=Output('/path/to/output'),
    my_input=Input('/path/to/input'),
)
def compute(ctx, my_output, my_input):
    if ctx.is_incremental and my_input.polars().is_empty():
        return
    df = my_input.polars(lazy=True)
    my_output.write_table(df)

或者，你可以在运行转换之前确保增量窗口始终至少包含一个文件。有关惰性 API 的更多信息，请查阅 Polars 惰性 API 文档.

与媒体集一起使用

支持增量计算的功能包括 媒体集。请参阅 增量媒体集文档 了解详情。

限制增量输入的批处理大小

你可以配置 事务性数据集 为增量转换（包括媒体集输入）进行批处理。请查阅有关 限制增量输入的批处理大小 的文档以了解更多详情。具体针对媒体集，请参阅 限制增量媒体集输入的批处理大小.
