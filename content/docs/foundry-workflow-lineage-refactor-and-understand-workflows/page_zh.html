执行重构并了解您的工作流

以前称为 Workflow Builder 的应用程序现在称为 Workflow Lineage。

要开始使用 Workflow Lineage，请打开 Workshop 应用程序或函数仓库，并使用键盘快捷键 Command + I (macOS) 或 Ctrl + I (Windows) 以查看相关的 Workflow Lineage 图，该图展示了支撑应用程序的对象、操作和函数。

您还可以直接导航到 Workflow Lineage 应用程序，并手动将资源添加到图中。

为了帮助您理解工作流并轻松执行其中的重构，Workflow Lineage 为您提供了一种简单的方法来了解附加属性、更新过时的变量和由操作支撑的函数，或批量编辑操作的提交条件。

属性来源

您可以在整个工作流中跟踪每个属性在任何对象中的使用情况。在图表上选择对象，然后查看 选择详情 面板（位于左侧），即可查看每个属性的使用位置。

每个属性旁边显示的数字表示函数、操作、关联、Workshop 应用等的数量，具体取决于上下文。

函数支撑的操作升级

要识别并升级过时的函数支撑操作，请先导航到颜色图例。然后，选择 过时的函数 选项。此操作将以红色突出显示所有过时的函数，为您提供清晰的视觉指示。接下来，选择您希望为其升级支撑函数的特定操作。选择后，与您的选择相关的所有过时操作都将显示在屏幕底部的面板中，以供进一步处理。

如果某个操作配置了操作日志，且新函数版本编辑了新的对象类型，则该操作无法在 Workflow Lineage 中更新，而必须在 Ontology Manager 中升级。

升级操作后，将在 Ontology Manager 中创建一个提案。在这里，您可以请求审核更改（例如函数升级），一旦获得批准，您就可以合并该提案。

函数支撑的 Workshop 应用程序升级

要升级 Workshop 应用程序中使用的函数，请选择 Workshop 节点并打开 更新 Workshop 应用程序 （位于底部面板）。

有两种升级选项：

  • 全有或全无： 仅当 Workshop 中的所有函数都能在不产生破坏性变更的情况下升级时，才会升级这些函数。如果存在任何破坏性变更，则不会进行任何升级。
  • 部分： 仅升级不会产生破坏性变更的函数。会导致破坏性变更的函数将不会被升级。

要为待升级的函数选择所需版本，请选择 选择版本……。这将打开一个弹出窗口，您可以在其中为每个函数仓库选择所需版本，并为由 AIP Logic 或计算模块创建的所有函数选择版本。如果未指定任何版本，系统将自动采用仓库的最新版本。

当函数无法升级时，该函数旁边将显示黄色警告图标。

当函数已是最新版本时，该函数旁边将显示灰色勾选图标。

如果函数可以成功更新，将会显示一个绿色对勾图标。

选择蓝色的 升级 选项，以将您的 Workshop 模块函数升级到目标版本。此操作将打开一个弹出窗口，其中列出了将要升级的 Workshop 模块。

选择 升级 以使更改生效。成功升级的 Workshop 应用程序将显示在弹出窗口中。

在函数更新后，您还可以选择批量发布 Workshop。了解具体操作方法，请参阅相关文档： 批量发布 Workshop 应用程序.

批量发布 Workshop 应用程序

Workshop 应用程序可以配置为始终发布最新版本；对于不会自动发布最新版本的 Workshop 应用程序，可以进行“批量发布”，一次性更新所有选定的应用程序。要批量发布 Workshop 应用程序，请选择 Workshop 节点，然后右键单击并选择 发布 [number of] 个 Workshop 模块.

一次性发布多个 Workshop 模块将打开一个窗口，显示哪些 Workshop 应用程序已经是最新版本。如果某个 Workshop 应用程序带有蓝色复选标记，并且带有以下任一标记 最新发布 或 已发布 旁边，则表示该 workshop 已处于最新版本。

具体来说：

  • 最新已发布 表示 Workshop 始终自动发布最新版本。这是可以在 Workshop 应用程序中切换的设置。
  • 已发布 表示 Workshop 不会自动发布最新版本，但该应用程序目前已发布最新版本。

对于未处于 已发布 或 最新发布状态的 Workshop 应用，您可以选择要将哪些应用发布到最新版本，然后选择 发布 [number of] 个实体。

在 Workflow Lineage 中更新函数后，您还可以批量发布 Workshop 模块。为此，请在更新函数后选择 继续发布。

这将带您进入一个页面，其中列出了尚未发布到最新版本的所有 Workshop 模块。确认您要发布这些模块的最新版本，然后选择 发布 [number of] 个实体。

成功完成此操作后，选择 完成。

批量替换模型

您可以在 Workflow Lineage 中通过单次操作，一次性替换多个 AIP Logic 函数所使用的模型，而无需逐个打开每个函数并单独更新模型。这在需要从 已弃用的模型 迁移出去，或在工作流中评估新模型时非常有用。

Workflow Lineage 中的批量模型替换目前仅支持 AIP Logic 节点。对其他资源类型的支持正在开发中。

要跨多个 AIP Logic 函数替换模型：

  1. 在 Workflow Lineage 中打开您的工作流。
  2. 在图中选择要替换的语言模型节点。
  3. 如果尚未添加，请将要更新的 AIP Logic 节点添加到图中。选择模型节点上的 AIP Logic 图标，可直接在图中筛选使用所选模型的节点。不在图中的 AIP Logic 节点将不会显示在 “替换模型” 选项卡中。



  4. 打开 “替换模型” 选项卡（位于底部面板中）。源模型显示在左侧，使用该模型的 AIP Logic 函数显示在右侧的 “使用位置” 下方。
  5. 在以下位置选择替换模型： 替换为。
  6. 使用 使用位置 列表中的复选框，以取消勾选您想要从模型替换中排除的任何 AIP Logic 函数。



  7. 选择 替换模型。

批量替换模型时的注意事项

  • Workflow Lineage 会跳过您无法编辑的 AIP Logic 函数。
  • Workflow Lineage 会将更改直接应用于受影响的 AIP Logic 函数。没有提议或审核步骤。
  • 成功替换后，图连接可能需要片刻才能刷新。
  • 替换模型必须是 Palantir 提供的。

批量删除对象和操作

要批量删除对象和操作，请在图表上选择节点，右键单击，然后选择 删除资源。

这将提示您创建提案。您还会看到与要删除的对象相关联的关联类型数量。这些关联也将包含在删除提案中。

请按照 Ontology Manager 中的提示合并提案。

Marketplace 产品

导航至 Marketplace 产品 侧边栏，并在下拉菜单中选择您的商店。请注意，该侧边栏仅会搜索本地商店，而不会搜索远程商店。

选择 添加产品 以添加您希望检查的产品，并在图表中添加所有相应的节点，方法是选择 将所有节点添加到图中.

其他工作流更新

除了上文所述的各种重构操作之外，您还可以直接在 Workflow Lineage 中为工作流执行安全更新。请查阅我们的 Workflow Lineage 安全文档，了解如何 批量更新工作流资源上的本体论角色 以及 操作提交条件.
