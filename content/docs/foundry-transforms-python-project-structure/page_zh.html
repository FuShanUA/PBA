项目结构

请确保您已阅读 入门指南 后再继续阅读。此外，本页面假设您使用的是引导式创建的 Python transforms 仓库中包含的默认项目结构。

默认引导式创建的仓库

以下是引导式创建的 Python transforms 仓库的标准结构：

transforms-python
├── conda_recipe
│   └── meta.yaml
└── src
    ├── myproject
    │   ├── __init__.py
    │   ├── datasets
    │   │   ├── __init__.py
    │   │   └── examples.py
    │   └── pipeline.py
    ├── setup.cfg

仓库中还有其他文件，可以通过以下方式查看：在 Code Repositories 的 File Explorer 选项卡中点击 设置 齿轮图标并选择 “显示隐藏文件和文件夹”。在几乎所有情况下，都不应编辑这些隐藏文件；Palantir 不为对这些隐藏文件进行了自定义更改的仓库提供支持。

仓库升级文件更改

首次创建仓库时，会使用当时最新版本的 Python transforms 模板的默认内容对其进行引导式初始化。在后续的 仓库升级过程中，仓库中的文件会升级为与最新版本的 Python transforms 模板内容保持一致。为确保一致性，用户对这些文件的自定义更改可能会在升级到新模板时被覆盖。我们不支持对这些文件进行自定义更改，因为这可能导致意外行为。

以下文件将 不 在仓库升级时被覆盖：

  • 以下目录中的默认文件： conda_recipe and src folders
  • 内部和外部 build.gradle files

以下文件将在仓库升级期间与最新的 Python 模板文件合并。如果存在相同的键，将采用 Python 模板中的版本：

  • gradle.properties
  • versions.properties

其余文件将在升级时被覆盖，以与最新 Python 模板版本的文件保持一致。

pipeline.py

在此文件中，您可以定义项目的管道（Pipeline），它是与您的数据转换相关联的 Transform 对象的注册表。以下是默认的 src/myproject/pipeline.py 文件：

Copied!
1
2
3
4
from transforms.api import Pipeline
from myproject import datasets
my_pipeline = Pipeline()
my_pipeline.discover_transforms(datasets)

默认的 pipeline.py 文件使用 自动注册 将您的 Transform 对象添加到项目的管道中。自动注册会发现项目 datasets 包中的所有 Transform 对象。因此，如果您重构项目，使转换逻辑不再包含在 datasets 文件夹中，请务必相应地更新您的 src/myproject/pipeline.py 文件。

或者，您可以自行将每个 Transform 对象（即您用装饰器修饰的每个函数） @transform添加到您项目的 Pipeline 中，方法是使用 手动注册。除非您的工作流需要这样做，否则请使用自动注册。有关 Pipeline 的更多背景信息，请参阅 管道.

setup.py

在此文件中，您可以定义一个 transforms.pipelines 入口点，名为 root ，它与项目的管道相关联——这使 Python transforms 能够发现您项目的管道。以下是默认的 src/setup.py 文件：

#!/usr/bin/env python
"""Python project setup script."""

import os
from setuptools import find_packages, setup

setup(
    name=os.environ["PKG_NAME"],
    version=os.environ["PKG_VERSION"],
    description="Python data transformation project",
    author="{{REPOSITORY_PROJECT_NAME}}",
    packages=find_packages(exclude=["contrib", "docs", "test"]),
    # Please specify your dependencies in conda_recipe/meta.yaml instead.
    install_requires=[],
    entry_points={"transforms.pipelines": ["root = myproject.pipeline:my_pipeline"]},
)

请将 #!/usr/bin/env python 行保留在文件顶部。Foundry 使用它来识别 setup.py ，以便定位项目的源目录。

如果您修改了默认项目结构，可能需要修改 src/setup.py 文件中的内容。有关更多信息，请参阅 介绍 transforms.pipelines 入口点的部分.

from transforms.api import Input, Output, transform, LightweightInput, LightweightOutput


@transform.using(
    output_dataset=Output("/path/to/output/dataset"),
    input_dataset=Input("/path/to/input/dataset"),
)
def compute(input_dataset: LightweightInput, output_dataset: LightweightOutput) -> None:
    output_dataset.write_table(input_dataset.polars(lazy=True))

的取消注释版本。取消注释示例代码后，您可以将 /path/to/input/dataset 和 /path/to/output/dataset 分别替换为输入和输出数据集的完整路径。如果您的数据转换依赖于多个数据集，可以提供额外的输入数据集。您可以更新 compute 函数，使其包含将输入数据集转换为输出数据集的代码。另外，请记住，单个 Python 文件支持创建多个输出数据集。

示例代码使用 Polars 计算引擎。您也可以修改代码以使用其他计算选项。请参阅 计算引擎 了解有关计算选项的更多详细信息，以及 开始使用 查看所有引擎的代码示例。

有关创建转换对象的更多信息（这些对象描述您的输入和输出数据集以及您的转换逻辑），请参阅 描述转换的章节.

meta.yaml

# If you need to modify the runtime requirements for your package,
# update the 'requirements.run' section in this file.

package:
  name: "{{ PACKAGE_NAME }}"
  version: "{{ PACKAGE_VERSION }}"

source:
  path: ../src

requirements:
  # Tools required to build the package. These packages are run on the build system and include
  # things such as revision control systems (Git, SVN) make tools (GNU make, Autotool, CMake) and
  # compilers (real cross, pseudo-cross, or native when not cross-compiling), and any source pre-processors.
  # https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html#build
  build:
    - python 3.9.*
    - setuptools

  # Packages required to run the package. These are the dependencies that are installed automatically
  # whenever the package is installed.
  # https://docs.conda.io/projects/conda-build/en/latest/resources/define-metadata.html#run
  run:
    - python 3.9.*
    - transforms {{ PYTHON_TRANSFORMS_VERSION }}
    - transforms-expectations
    - transforms-verbs

build:
  script: python setup.py install --single-version-externally-managed --record=record.txt

如果您的 Python 转换项目需要任何额外的构建依赖项，您可以使用 软件包标签页 来发现可用的包，并按照 meta.yml 文件中所述的方式自动将其添加到您的 有关共享 Python 库的文档。此步骤将自动检测生成您尝试导入的包的渠道，并将其添加为 支撑仓库.

也可以手动更新此文件中的 "requirements" 部分。但是，强烈建议不要手动操作，因为您可能会请求不可用的包和版本，随后导致您的仓库上的检查失败。对于您添加的任何依赖项，请确保 您的依赖项所需的包可用.

您不太可能需要修改 "requirements" 之外的其他部分。

支持的 Python 3 版本

Palantir 支持处于活跃维护期的 Python 版本，并遵循 Python 软件基金会的生命周期结束时间表。请参阅 Python 版本支持页面 以了解更多详情。

  • 诸如 python >=3.9 or python >3.9,<=3.10.11 之类的范围不适用于 Python 版本。

固定运行时版本

如果您的转换需要固定特定的库版本，而您希望手动添加而不是使用推荐的 软件包标签页，您可以在 requirements 块中将其与库名称一起显式指定。以下是一个固定版本的示例：

requirements:
  run:
    # The below pins an explicit version
    - mylibrary 1.0.1

    # The below specifies a maximum version (version equal or lower):
    - scipy <=1.4.0

注意：

  • 运算符后不允许有空格。例如 scipy <= 1.4.0 将导致 CI 检查失败。
  • 运算符 >= 在 Foundry 中尚不支持用于版本。

使用 pip 管理的依赖项

如果您的转换需要通过 Conda 无法获取、但可以使用 pip ↗安装的特定库，您可以在额外的 pip 部分中声明它们。该依赖项将安装在您的 Conda 环境之上。以下是添加 pip 依赖项的示例：

requirements:
  build:
    - python 3.9.*
    - setuptools

  run:
    - python 3.9.*
    - transforms {{ PYTHON_TRANSFORMS_VERSION }}

  pip:
    - pypicloud

注意：

  • 添加到 pip 部分的依赖项将安装在由 run 部分中的包派生的 Conda 环境之上。因此，删除 run or build 将导致失败。
  • 直方图 pip 部分只能在 Python 转换仓库中使用，不能在 Python 库中使用。
