核心概念

Sensitive Data Scanner 构建于以下核心概念之上： 匹配条件, 匹配操作，以及扫描。扫描可以分为 一次性 or 定期.

匹配条件

匹配条件是 Sensitive Data Scanner 根据数据格式、数据值或基于模型的分类来识别敏感数据的规则。共有三种类型的匹配条件：

  • 正则表达式匹配条件： 通过正则表达式（regex）指定的匹配条件。正则表达式是表示文本匹配模式的字符序列。对于不熟悉正则表达式的用户，AIP 可以帮助创建与目标敏感数据相匹配的有效正则表达式。
  • 重叠匹配条件： 重叠匹配条件允许用户通过匹配现有 Foundry 数据集中某一列的值，来搜索预定义敏感数据（例如姓名列表）的完全重复项，该数据集已知包含此类数据。
  • 语言模型匹配条件： 语言模型匹配条件使用大型语言模型（LLM）和自然语言提示，对扫描的内容、列名或两者进行分类，判断是否应视为匹配。

用户可以创建自己的 自定义 匹配条件，以覆盖他们所关注的个人身份信息（PII）类型。Sensitive Data Scanner 还提供一系列预定义的 内置 匹配条件，用于检测常见类型的 PII，例如社会安全号码、电子邮件地址和电话号码。

匹配操作

匹配操作允许用户定义自动化操作，以规定敏感数据在平台内的处理方式。用户可以创建三种类型的匹配操作：

  • 创建 Issue： 用户可以设置匹配操作，在发现匹配项的列上创建 Issue，使治理团队能够手动审查和分类 Sensitive Data Scanner 检测到的匹配项。
  • 应用标记： 用户可以设置匹配操作，以应用一个或多个 标记 到任何发现匹配项的数据集，以确保访问控制。
  • 混淆数据： 用户可以设置匹配操作，通过加密或哈希处理来混淆匹配的数据，使用 密码.

一次性扫描

一次性敏感数据扫描会根据匹配条件对用户选择的数据集执行单次搜索，并对发现的任何匹配项执行指定的匹配操作。一次性扫描有助于识别 Foundry 中已存在的、不符合组织数据治理政策的数据。

定期扫描

定期敏感数据扫描与一次性扫描类似，不同之处在于，每当用户选择的数据集新增数据时，都会执行定期扫描。即使平台中不断添加新数据，定期扫描也能持续不断地帮助识别可能不合规的数据。
