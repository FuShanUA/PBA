角色

角色是授予不同资源访问级别的权限集合。角色属于自主性权限，通常在项目级别授予，以便在项目范围内的所有资源上提供统一的能力。然而，强制性控制（组织、标记以及 基于分类的访问控制）将 始终 阻止不符合条件的用户访问资源，无论该用户的角色如何。这些控制也会通过派生传播，因此下游资源会继承相同的要求。相比之下，角色管理的是对资源本身的访问；它们不会延伸到从资源中读取之后的数据。

从权限最大到最小，Foundry 中的默认角色为：Owner、Editor、Viewer 和 Discoverer。每个角色都可以向其他用户分配相同或更低的角色。例如，Owner 可以向任何其他用户授予 Owner、Editor、Viewer 或 Discoverer 角色，而 Discoverer 只能向其他用户授予 Discoverer 角色。这些默认设置可以自定义，以包含完全 新的角色。角色是独立的操作集合，而不是严格的层级结构。在自定义角色集中，权限更大的角色并不保证包含另一个角色授予的所有操作。

重要的是，与强制性控制一样，角色授予会继承到子资源。例如，向用户授予某个项目或文件夹的 Viewer 角色，会使其获得该项目或文件夹中包含的所有资源的 Viewer 角色。而且，通常是以用户组为单位在项目上授予角色。

文件夹和文件上的角色授予

如上所述，我们建议仅在项目级别授予角色，以便在项目范围内的所有资源上提供统一的能力。为了强制执行此行为，您可以在 设置 项目视图中的部分使用开关来禁用文件夹和文件角色授予。当此设置被禁用时，角色授予只能在项目级别进行，而不能在文件夹或文件级别进行。拥有该项目 Owner 角色的用户可以设置此开关。

如果对已包含带角色授予资源的项目禁用了角色授予设置，则针对这些单个资源的角色授予将被移除。一旦现有的角色授予被移除，在重新启用该设置之前将无法重新添加。类似地，如果带有角色授予的资源被移动到角色授予设置已禁用的项目中，资源级别的角色授予将被移除。在禁用角色授予设置以及将资源移动到角色授予设置已禁用的项目时，用户会收到关于此行为的警告。

此外，项目链接共享功能也将被移除，因为链接共享会为链接的接收者授予对单个文件夹或文件的直接角色。

默认情况下，文件夹和文件上的角色授予处于禁用状态。空间管理员可以在空间级别更改默认行为。我们建议保持禁用文件夹和文件上的角色授予。
