用户自定义函数 (UDF)

如果您无法使用 Pipeline Builder 中现有的转换选项来处理数据、想要引入外部 Java 或 Python 库，或者有希望在多个管道中复用的复杂逻辑，您可以创建自己的用户自定义函数 (UDF)。用户自定义函数允许您在 Pipeline Builder 或 Code Repositories 中运行您自己的任意 Java 或 Python 代码，并且这些代码可以进行版本管理和升级。 了解有关在 Pipeline Builder 中使用 Python UDF 的更多信息.

用户自定义函数应仅在必要时使用，我们建议尽可能使用现有的转换 如果希望用户在每次运行预览前手动确认，请开启 or Java 转换仓库 中的现有转换。

注册环境必须位于 Palantir 的云托管基础设施上才能使用 UDF。Pipeline Builder 目前支持行映射 (row map)、平面映射 (flat map)、键控处理 (keyed process) 和键控协同处理 (keyed co-process) UDF；尚不支持异步 UDF。用户自定义函数是一项高级功能。请务必仔细阅读以下文档，以了解在管道中使用用户自定义函数的影响。

要创建用户自定义函数仓库，请首先导航到您想要保存该仓库的 Project。

然后,选择 新建 ，然后选择 分支回退。在 Foundry UDF Definitions 选项下，选择 Map UDF Definition/Implementation 以使用 UDF 模板初始化您的仓库。最后，选择 初始化仓库.

定义用户自定义函数

UDF 在一个文件中定义，该文件指定其名称、输入 schema、输出 schema 和参数类型。Java 类将基于此文件生成，并且文件名在您发布后将在 Pipeline Builder 中可见。

要创建新的 UDF，请添加一个名为 <YourUdfName>.yml 位于 src/main/resources/udfs/definitions/ 的文件，包含以下字段：

  • name：UDF 的名称，代码生成将使用该名称创建描述其输入、输出和参数的类。该名称也将用于在部署仓库的 deployment.yml 文件中引用此 UDF，并在 Pipeline Builder 中作为一个转换可见。
  • customTypes （可选）：一个用于定义自定义类型的代码块，可在整个 inputSchema and outputSchema 定义中重复使用。详情请参阅 自定义类型 部分。
  • inputSchema：输入行在针对 UDF 运行时必须遵循的 schema。如果运行时可以选取到该 schema 中，则具有更多列的数据集也会被接受。代码生成将基于此 schema 创建强类型的输入对象。参数将在 Pipeline Builder 中可见。详情请参阅 schema 定义部分 。详情请参阅下方的
  • outputSchema：此 UDF 输出行的 schema。代码生成将基于此 schema 创建强类型的输出对象。详情请参阅 schema 定义部分 。详情请参阅下方的
  • arguments：UDF 参数的描述。这些参数将由用户在 Pipeline Builder 或相应的部署仓库中在构建时指定。代码生成将基于此定义创建强类型的参数对象。

您的仓库模板中提供了一个示例定义，位于 src/main/resources/udfs/definitions/Multiply.yml。请在以下位置阅读有关参数的更多信息 下方的 UDF 定义部分.

package myproject;

import com.palantir.foundry.duplicaterows.config.DuplicateRowsConfiguration;
import com.palantir.foundry.duplicaterows.DuplicateRowsFlatMapUdf;
import com.palantir.foundry.duplicaterows.input.InputRow;
import com.palantir.foundry.duplicaterows.output.OutputRow;
import com.palantir.foundry.udf.api.flatmap.Collector;
/**
 * Implementation for the "DuplicateRows" UDF logic.
 */
public final class DuplicateRowsFlatMapUdfImpl implements DuplicateRowsFlatMapUdf {

    private final DuplicateRowsConfiguration config;

    public DuplicateRowsFlatMapUdfImpl(DuplicateRowsConfiguration config) {
        this.config = config;
    }

    @Override
    public void flatMap(Context ctx, InputRow input, Collector<OutputRow> out) throws Exception {
        OutputRow outputRow = OutputRow.create(ctx.getRowBuilderFactory())
                .key(input.key())
                .value(input.value());
        // Duplicate all input rows by collecting twice
        out.collect(outputRow);
        out.collect(outputRow);
    }
}

部署用户自定义函数

您可以通过 Pipeline Builder（推荐）或标准的 UDF 部署仓库来部署 UDF。

发布到 Pipeline Builder（推荐）

目前，在 Rubix 注册中，发布到 Pipeline Builder 适用于 row map、flat map、keyed process 和 keyed co-process UDF。异步 UDF（async custom 和 async deployed app）尚不支持。

按照以下步骤将您的 UDF 发布到 Pipeline Builder：

  1. 从底部面板打开 Task Runner。然后，选择 Python 选项卡并输入 generateEddieLockfile 以生成一个文件，其中包含供 Pipeline Builder 注册您仓库中每个 UDF 的唯一标识符。

直方图 generateEddieLockfile 命令会根据 UDF 名称返回一个随机的唯一标识符。如果您在发布后重命名 UDF，代码将作为新的 UDF 发布，而不是覆盖之前的 UDF。同样，如果您删除并重新生成 lockfile，UDF 将获得新的唯一标识符并注册为新的 UDF。所有版本的 UDF（包括旧名称、新名称和新 lockfile）都将显示在 Pipeline Builder 中导入 UDF 时出现的弹出窗口中。

  1. 提交 lockfile 和您的更改。
  2. 为您的发布标记一个版本（0.0.1，例如）来引用它们。
  3. 验证检查是否通过。如果检查失败，UDF 将不会发布到 Pipeline Builder。

如果不存在 lockfile，UDF 将不会注册到 Pipeline Builder 以导入到管道中。要生成 lockfile，请运行 generateEddieLockfile。如果您在 Code Repositories 中工作，则不需要 lockfile。

  1. 检查通过后，导航到当前的或新建的 Pipeline Builder 管道。
  2. 控制面板 Reusables > User-defined functions > Import UDF.
  3. 从列表中选择您的 UDF，然后选择 Add。您的 UDF 应出现在 Pipeline Builder 转换选择器中，并且可以像管道中的任何其他转换一样使用。

要在 UDF 的第一个版本之后部署新的更改或修复（包括对定义 YML 的编辑），请重复上述实现和发布步骤。然后，在您的 Pipeline Builder 管道中：

  1. 控制面板 Reusables > User-defined functions.
  2. 选择 编辑版本 （针对您的 UDF），并选择更新后的版本。

发布到部署仓库

按照以下步骤将您的 UDF 发布到 Code Repositories：

  1. 选择 提交 您的更改并 标记版本 为您的发布设置版本。
  2. 标签检查通过后，使用流式处理模板创建另一个仓库，或使用 Foundry UDF Definitions > Foundry Streaming UDF Deployment 流式处理模板或 Foundry UDF Definitions > Foundry Batch UDF Deployment 批处理模板
  3. 按照模板中的说明部署 UDF。

要在 UDF 的第一个版本之后部署新的更改或修复（包括对定义 YAML 的编辑），请重复上述实现和发布步骤。然后，更新部署仓库的 build.gradle 依赖项中引用的标签版本。

自定义结构体是使用自定义类型的一大优势；当输入代码生成类型与输出代码生成类型在结构上相同时，无需额外工作即可完成转换。

故障排除

本节介绍用户自定义函数实现和部署中的一些常见问题及调试步骤。

代码生成未运行

通常，这是由无法解析的 UDF 定义 YAML 导致的。

请按照以下步骤解决：

  1. 检查 Code Assist 中是否有以红色 Code Assist task failed pop-up.
  2. 标识的可识别错误。确认所有字段均已提供且没有拼写错误。您可以与初始示例定义进行交叉核对。
  3. 如果仍然失败，请将鼠标悬停在代码编辑器底部的 Code Assist running 消息上并选择 刷新.
  4. 将仓库下载到本地，并执行 ./gradlew idea or ./gradlew eclipse 命令以查看输出到控制台的错误。

我可以取消注册 UDF 吗？

UDF 一旦发布，就无法从 Pipeline Builder 中取消发布。如果您删除锁定文件条目并重新运行 generateEddieLockfile 命令，您的 UDF 将被授予一个新的 ID，这会导致它在 UDF 部分（Pipeline Builder 转换列表中）出现两次。

本地环境：不支持的类文件主版本

If ./gradlew idea open or ./gradlew eclipse open 失败并报错 Could not open proj generic class cache for build file <build.gradle> ... Unsupported class file major version 则您运行的 Java 版本很可能与 Gradle 不兼容。

请按照以下步骤解决：

  • 运行以下命令检查您的 Java 和 Gradle 版本 ./gradlew --version.
  • 交叉核对您的 JVM 版本是否与 Gradle 文档 ↗.
  • 中列出的 Gradle 版本兼容。如果您的 JVM 版本不兼容，且本地没有其他兼容版本， 下载兼容的 Java 版本 ↗.
  • 将您的 JAVA_HOME 设置为 export JAVA_HOME=<jdk install directory>/Contents/Home/.

现在您应该能够成功运行 open 命令了。

我无法在 Task Runner 中运行 generateEddieLockfile 任务

如果您收到 Failed to start Java server 错误，或者无法在 Task Runner 中运行该命令，请验证以下事项：

  1. 您的仓库模板版本为 0.517.0 或更高。
    • 要检查这一点，请导航到文件编辑器，然后选择 Display settings > Show hidden files and folders。templateConfig.json 文件将出现在文件列表中。
    • 如果仓库版本不兼容，请从仓库视图的最右侧选择 ... > Upgrade 以生成包含最新模板的拉取请求。批准该拉取请求，然后在请求合并并通过检查后重新构建您的工作区。

  1. 您的工作区已连接。
    • 如果您的工作区未连接，请重新构建您的工作区。
  2. 您选择了 Python Task Runner 中的标签页，而不是 Eclipse Java.
