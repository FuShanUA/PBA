告警工作流

无论是检测欺诈还是 发现收入机会，告警工作流都会自动呈现需要最终用户审查的问题，用户只需点击按钮即可做出决策。这些工作流使团队能够将注意力集中在解决当前最紧迫的问题上，而不是花时间手动拼凑数据。

Foundry 的 数据连接 和 本体论 使组织能够在几天（而非几个月）内实现这一模式，并持续安全、高效地实施、定制和维护该模式。

解决方案

告警工作流旨在自动呈现告警（更新、问题、机会等）供用户审查和决策。通常，用户会看到按优先级排序的告警及与告警相关的数据，并通过审查这些内容来做出决策。用户使用按钮记录其决策，将决策（写回）到 Foundry 数据中，并在适当的情况下有时也写入生产系统。

以欺诈检测为例，用户可能会收到一份按可能性从高到低排序的欺诈警报列表，以供审查。点击某条警报会显示所有佐证信息，用户可据此通过一个简单的按钮来指明其是否为欺诈。

对于花费大量时间筛选各种数据源并手动拼凑数据点来识别问题（其最终目标是针对所发现的问题做出决策）的用户而言，警报框架是极佳的解决方案。有时，最终用户会通过基本的 SQL 查询来呈现其中部分问题；或者，由于工作过于复杂，用户根本不会去筛选数据。

警报可用于各种用例，从检测欺诈到 发掘收入机会。这些警报可以通过数据管道、机器学习模型、Foundry Rules 或它们的任意组合来生成。

本体论

以下是本体论相关概念的列表，这些概念与警报工作流的搭建相关。

对象

警报工作流通常包括用作触发器的对象类型（例如客户、金融交易、制造流程或服务类型），以及与其关联的特定警报对象（例如潜在欺诈警报、与服务类型相关的收入机会，或与制造流程相关的流程优化机会）。

相关产品：

  • 本体论
  • Object Explorer

操作

操作是此工作流的核心，因为它们记录了最终用户的决定。从用户的角度来看，这些就是他们点击的按钮。在后端，这些按钮由 本体论 操作驱动，这些操作被配置为记录用户所做的决定。典型的操作字段包括：

  • 用户 ID
  • 决定的时间戳
  • 对其做出决定的警报对象
  • 决定本身（True/False、Accept/Reject 等）
  • （可选）决定的解释说明（有助于在跟踪器中进行审查）

在欺诈检测中，操作会记录案件是否被判定为欺诈、做出决定的用户、做出决定的时间、做出该决定的原因（即解释说明），以及所审查的具体案件 ID。

相关产品：

  • Foundry 操作

回写

回写是 Foundry 中用于记录决定的术语。相关文档可在回写页面中找到。本质上，警报对象支撑数据集的副本是通过 本体论 应用程序。Actions 会将 Actions 部分中定义的字段记录到复制的（回写）数据集中。在欺诈检测中，针对特定案件采取的操作随后会更新本体论和相关数据集，以反映所做出的决策（例如，设置警报是否识别出欺诈以及调查结果的解释）。

除了回写到 Foundry 之外，通常还会回写到 SAP、Oracle 等生产系统。这通常涉及建立与生产系统的直接连接（具有读取和写入权限），并通过该连接传送回写数据集的结果。如需了解更多详细信息，请与您的 Palantir 团队联系。

Foundry Rules

Foundry Rules 是一组组件，允许用户对数据创建和维护规则，而无论其编码背景或能力如何。Foundry Rules 可用于基于任何所需条件定义各种不同类型的警报。然后可以将 Foundry Rules 的输出转换为警报对象。

下方展示了 Foundry Rules 接口的一个示例。

在欺诈检测中，一些客户选择使用 Foundry Rules 来定义某种欺诈活动类型，并呈现所有适用该规则的相关案例。例如，一条规则可能是：当客户有一笔超过 1 万美元的消费，或当客户在同一天内在两个不同城市连续进行两笔消费时。

相关产品：

数据管道

有时，用于创建警报的逻辑可能规定得非常具体，并涉及复杂的规则，这类规则最适合通过在数据管道中编码来实现。

例如，保险公司必须按照与医疗服务提供商签订的合同费率支付理赔，这些费率在其系统中体现为一组代码。当合同重新谈判后，应针对新的时间跨度记录一组新的代码。在这种情况下，最佳做法是将所有用于确定何时应用哪些代码的逻辑编写成代码，并在 Foundry 中创建一个提案对象，建议以重新谈判后合同中的新代码集来拆分时间跨度。

相关产品：

  • 代码仓库
  • Code Workbook

要求

无论采用哪种模式,底层数据基础都是由管道以及到外部源系统的同步构建而成的。

数据集成管道

数据集成管道以 SQL、Python 和 Java 等多种语言编写,用于将数据源集成到主题本体论中。

数据连接器

Foundry 可以 从各种数据源同步数据,包括 FTP、JDBC、REST API 和 S3。从多种来源同步数据并汇集尽可能完整的事实来源,是实现最高价值决策的关键。
