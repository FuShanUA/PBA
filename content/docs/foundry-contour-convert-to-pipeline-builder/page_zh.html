将 Contour 逻辑导出到 Pipeline Builder

在 Foundry 中，您可以将复杂的 Contour 分析及其底层逻辑导出到 如果希望用户在每次运行预览前手动确认，请开启。虽然 Contour 是进行探索性分析和深入探究特定问题的理想工具，但它并不适合用于生产管道的维护。如果您的分析逻辑在您的使用场景中不会频繁变更，我们建议将其导出到 Pipeline Builder，以便对生产管道进行更灵活的维护配置。

下面的指南提供了在决定导出 Contour 分析时需要考虑的要点，并引导您逐步了解如何轻松地将逻辑导出到 Pipeline Builder。

Contour 到 Pipeline Builder 的工具无法保证导出后逻辑保持不变。对于依赖严格逻辑的敏感使用场景，我们建议您自行进行验证。

注意事项

在决定将 Contour 逻辑导出到 Pipeline Builder 之前，请先查看以下优势、不支持的功能以及可能出现的破坏性变更。

优势

如果希望用户在每次运行预览前手动确认，请开启 是大多数使用场景中 Foundry 推荐的管道构建和维护工具。当您开始使用稳态管道，并且有下游应用程序或用户依赖一致的 schema 时，您可能会发现 Pipeline Builder 是一个更加灵活、更可配置的管道维护和性能工具，并可使用各种生产级实用功能，包括以下内容：

  • 使用分支和拉取请求轻松协作。
  • 安全、一致的 schema。
  • 种类繁多的类型安全函数。
  • 自定义的强大计算配置文件。
  • 增量转换模式，避免重复构建相同的数据。

不支持的功能

转换器目前不支持 SPLIT 函数或透视转换。透视看板中的聚合操作将按预期工作。

除上述不支持的配置外，其他函数也可能因各种原因不受支持。在这些情况下，转换器应返回一个解释失败原因的错误。如果您仍希望将不受支持的逻辑移至 Pipeline Builder，请先移除不受支持的看板，直到转换成功。然后，将逻辑添加到 Pipeline Builder 图.

破坏性变更

在尝试将 Contour 逻辑转换为 Pipeline Builder 时，可能会出现以下破坏性变更：

  • Contour 极其灵活的类型系统可能与 Pipeline Builder 中使用的强类型不匹配。在大多数情况下，转换会失败并显示修复类型错误的消息。在某些极端情况下，Pipeline Builder 可能会为您的 schema 选择不同的输出类型。
  • Contour 中的某些参数无法转换为 Pipeline Builder 参数。如果发生这种情况，转换器将创建一个空白参数供您填写。
  • Pipeline Builder 中对时区的处理方式可能与 Contour 不同。转换分析后，请务必确认时区行为。

将 Contour 分析转换为 Pipeline Builder

请按照以下步骤将您的 Contour 分析转换为 Pipeline Builder：

  1. 在 Foundry 中导航到某个 Contour 分析。

  2. 滚动到分析底部，然后选择 转换为 Pipeline Builder.



  3. 在出现的对话框中，为新管道选择一个目标文件夹，然后选择 保存.



  4. 进入 Pipeline Builder 后， 预览 和 构建 您的管道。

故障排除

分析转换失败

在大多数情况下，当您的分析转换失败时，您会收到明确的错误提示。这意味着该行为是已知的缺陷。如果解决此问题对您的使用场景至关重要，请联系 Palantir Support，看看是否可以解决此问题。

当错误未知或不在预期之内时，您将收到一条尽力而为的消息，告知您可能失败的操作类型，并再次提醒您 Pipeline Builder 的类型检查比 Contour 严格得多（这很可能是您错误的根本原因）。
