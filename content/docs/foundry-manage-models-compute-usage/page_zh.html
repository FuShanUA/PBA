实时部署计算用量

Foundry 机器学习实时部署是一种持久、可扩展的模型发布部署方式，可通过 API 端点与之交互。实时部署会持续保留专用计算资源，以确保部署能够快速响应传入的流量。因此，在部署处于活动状态时，托管实时部署会消耗 Foundry 计算秒数。

以下文档仅涵盖由 Modeling Objective 支撑的实时部署。JavaScript 函数支撑的部署和 直接部署 均不在本文档的涵盖范围内。直接部署由计算模块支撑，因此 遵循相应的原则；但是，关于 容器支撑的模型 需要同时占用部署资源和模型资源的注意事项仍然适用。

在实时运行时，Foundry 机器学习的计算用量会归属于 Modeling Objective 本身，并在包含该 Modeling Objective 的项目层级进行汇总。要深入了解 Foundry 中计算秒数的定义以及用量计算公式的来源，请查阅 用量类型 文档。

计算秒数的衡量

Foundry 机器学习实时部署将其基础设施托管在 Foundry 基于容器的计算集群中运行的专用“副本”上。每个副本都会被分配一组计算资源，以 vCPU 和 RAM 的 GiB 数进行衡量。每个副本在本地托管模型，并使用计算资源来处理传入的请求。

对于 容器支撑的模型，每个副本都附带一个容器，拥有其专用的 GPU 或 vCPU 资源，具体如容器 模型版本的运行时配置.

导入到 Modeling Objective 中的 Foundry 机器学习实时部署在处于活动状态时会消耗计算秒数，无论其接收到的传入请求数量是多少。部署在启动后即被视为“活动”状态，并保持“活动”状态，直到通过图形界面或 API 将其关闭。如果与实时部署关联的 Modeling Objective 被移入平台回收站，该实时部署将被关闭。另外， 从模型资源而非 Modeling Objective 启动的直接部署 将根据请求量自动扩缩容，并且可以配置为在没有使用量时支持零个最小副本。了解更多关于 从 Modeling Objective 进行的实时部署与直接部署之间的差异 和 直接部署自动扩缩容行为的信息。

实时部署将使用的计算秒数取决于三个主要因素：

  • 每个副本的 vCPU 数量
    • 对于实时部署，vCPU 以毫核为单位进行衡量，每个毫核为 1/1000 个 vCPU
  • 每个副本的 RAM GiB 数
  • 每个副本的 GPU 数量
  • 副本数量
    • 部署中的每个副本将具有相同数量的 vCPU 和 RAM GiB 数

以下公式用于衡量 vCPU 计算秒数：

live_deployment_vcpu_compute_seconds = max(vCPUs_per_replica, GiB_RAM_per_replica / 7.5) * num_replicas * live_model_vcpu_usage_rate * time_active_in_seconds

以下公式用于衡量 GPU 计算秒数：

live_deployment_gpu_compute_seconds = GPUs_per_replica * num_replicas * live_model_gpu_usage_rate * time_active_in_seconds

调查 Modeling Objective 的用量

平台中的所有计算秒数用量均可在 资源管理应用程序.

中查看。部署的计算用量归属于其部署所在的 Modeling Objective。任何给定的 Modeling Objective 都可以同时有多个实时部署处于活动状态。可以在 Modeling Objective 的 部署 部分下找到其实时部署。请参见下方的截图示例。

用量增加或减少的驱动因素

实时部署在处于活动状态时会使用计算秒数。以下策略可帮助控制部署的总体使用量：

  • 确保部署针对您预期的请求负载进行了正确调整。部署应针对预期的峰值同时请求数进行调整。如果部署资源不足，它将开始对请求返回失败的响应。但是，为部署分配过多资源可能会使用超出必要的计算秒数。
    • 我们建议实时部署管理员对实时部署端点运行压力测试，以在将模型部署到运营关键环境之前确定正确的资源配置。
  • 实时部署将持续运行，直到被显式停止或取消。监控实时部署的使用情况非常重要，以确保部署在不需要时不会被错误地保持运行。这在暂存部署中很常见。
  • 在不更改部署配置文件的情况下增加/减少部署上的 API 负载不会影响其计算使用量。实时部署将在其资源允许的范围内处理尽可能多的请求，而不会更改其使用的计算秒数。

配置使用量

实时部署的资源使用量由其配置文件定义。可以在创建实时部署时设置配置文件。部署处于活动状态时也可以更改配置文件。部署将自动接收更新后的配置文件，且不会停机。

管理使用量

在通过以下方式管理计算的注册中 资源队列，资源管理管理员可以使用以下步骤查看给定队列中当前正在运行的实时部署：

  1. 打开资源管理应用程序。
  2. 选择 如何检查某人在项目、文件夹或文件上的权限.
  3. 从左侧边栏中选择一个队列。
  4. 从左侧面板中选择 计算类型 页面中间的选项卡。
  5. 选择最右侧的筛选器图标，然后选择按以下条件筛选 实时部署.

使用量计算示例

示例 1：vCPU 计算

以下示例显示了一个具有两个副本的默认副本配置文件的实时部署，使用“low-cpu-lowest-memory”配置文件活动 20 秒：

resource_config:
    num_replicas: 2
    vcpu_per_replica: 0.5 vCPU
    GiB_RAM_per_replica: 1 GiB
seconds_active: 20 seconds
live_model_vcpu_usage_rate: 0.2

compute seconds = max(vcpu_per_replica, GiB_RAM_per_replica / 7.5) * num_replicas * live_model_vcpu_usage_rate * time_active_in_seconds
                = max(0.5vCPU, 1GiB / 7.5) * 2replicas * 0.2 * 20sec
                = 0.5 * 2 * 0.2 * 20
                = 4 compute-seconds

示例 2：GPU 计算

以下示例显示了实时部署的使用率。该实时部署具有包含两个副本的默认副本配置文件，并使用 GPU V100 配置文件活动 20 秒。

resource_config:
    num_replicas: 2
    gpu_per_replica: 1 V100 GPU
seconds_active: 20 seconds
live_model_gpu_usage_rate: 3

compute seconds = gpu_per_replica * num_replicas * live_model_gpu_usage_rate * time_active_in_seconds
                = 1 * 2replicas * 3 * 20sec
                = 1 * 2 * 3 * 20
                = 120 compute-seconds

示例 3：容器支撑的模型计算

Deployment resource_config:
    num_replicas: 2
    vcpu_per_replica: 0.5 vCPU
    GiB_RAM_per_replica: 1 GiB

Model image resource_config:
    CPU: 4 cores
    Memory: 30 GiB

seconds_active: 20 seconds
live_model_vpcu_usage_rate: 0.2

total compute seconds = (compute seconds deployment resource) + (compute seconds model resource)

compute seconds deployment resource = max(vcpu_per_replica, GiB_RAM_per_replica / 7.5) * num_replicas * live_model_vcpu_usage_rate * time_active_in_seconds
                = 0.5 * 2replicas * 0.2 * 20sec
                = 0.5 * 2replicas * 0.2 * 20sec
                = 4 compute seconds

compute seconds model resources = max(cores, Memory / 7.5) * num_replicas * live_model_vcpu_usage_rate * time_active_in_seconds
compute seconds model resources = 30 / 7.5 * 2 * 0.2 * 20
compute seconds model resources = 32 compute seconds

total compute seconds = 36 compute seconds
