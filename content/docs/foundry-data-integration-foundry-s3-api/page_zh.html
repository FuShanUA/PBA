用于 Foundry 数据集的 S3 兼容 API

Foundry 数据集的 S3 兼容 API 允许您像操作 S3 存储桶一样与 Foundry 数据集进行交互。了解数据集通过该 API 访问时的行为，并查看 设置指南 和 示例.

与数据集交互的完整支持可通过平台的 REST API 和 SDK 获得。这些工具提供了对分支和事务管理的控制，而 S3 兼容 API 并不提供这些功能。

Foundry 公开了 Amazon Simple Storage Service (S3) API ↗ 的一个子集，允许您使用能够与 S3 存储服务通信的客户端与 Foundry 数据集进行交互。示例包括 AWS CLI、AWS SDK、Hadoop S3 文件系统和 Cyberduck。

S3 API 并未完全实现，因为并非所有 S3 概念都能自然地映射到 Foundry 中的概念。例如，目前不支持创建和删除存储桶（存储桶代表 Foundry 数据集）；数据集应在使用该 API 之前在 Foundry 中创建。但是，大多数文件读取/写入/删除工作流都受支持，包括分段上传。请参阅 支持的操作 以查看支持的 S3 操作列表。

概念

本节概述 S3 概念如何映射到 Foundry 数据集概念。

S3 存储桶对应于 Foundry 数据集

S3 存储桶 对应于 Foundry 数据集，存储桶名称即 Foundry 数据集的唯一标识符（例如， ri.foundry.main.dataset.bafb7e96-84f1-4d23-a4a5-40b17c6912e7).

S3 对象键 对应于 Foundry 数据集中文件的逻辑路径 （例如， top-level-file.csv or subfolder/nested-file.csv).

只有 Foundry 数据集可以用作 S3 存储桶。Compass 文件夹和项目是组织容器，不是数据集，不能用作存储桶名称。为了将上传的文件分开组织，例如将应用程序日志与其他输出分开，请写入现有数据集中的嵌套对象键路径（例如， logs/nested-file.csv）。或者，为此目的创建一个新数据集。避免为此创建新的 Compass 文件夹。

提供了专为数据转换量身定制的版本控制体验，支持团队在同一工作簿中同时处理逻辑与数据。

该 API 支持访问名称为字母数字（仅包含 a-z, A-Z，或 0-9）或特殊字符 - 和 _的数据集分支。要指定分支，请在存储桶名称后附加分支名称，以句点分隔： <dataset-rid>.<branch-name>。如果未指定分支，则使用默认分支。

例如，要访问 RID 为 mybranch 的数据集的 ri.foundry.main.dataset.bafb7e96-84f1-4d23-a4a5-40b17c6912e7分支，请使用存储桶名称 ri.foundry.main.dataset.bafb7e96-84f1-4d23-a4a5-40b17c6912e7.mybranch.

S3 存储桶名称验证强制执行前面描述的字符限制。如果您的分支包含不允许的字符，例如 /，您可以使用 Base64 编码对分支名称进行编码。您应省略任何尾部的 = 字符。例如， feature/my-branch 被 Base64 编码为 ZmVhdHVyZS9teS1icmFuY2g=. ZmVhdHVyZS9teS1icmFuY2g （不含 = 字符）可用于在存储桶名称中引用此分支。

该 API 不支持分支创建；指定的分支必须已存在于数据集上。

事务

该 API 以类似于分支的方式支持访问数据集事务。这允许用户访问数据集的历史版本。例如，要访问 RID 为 ri.foundry.main.transaction.0cdfe8c9-f595-4859-a194-7daecff9d6fe 的数据集的 ri.foundry.main.dataset.bafb7e96-84f1-4d23-a4a5-40b17c6912e7分支，请使用存储桶名称 ri.foundry.main.dataset.bafb7e96-84f1-4d23-a4a5-40b17c6912e7.ri.foundry.main.transaction.0cdfe8c9-f595-4859-a194-7daecff9d6fe.

事务。只有已提交的事务才能以这种方式访问。因此，存储桶将是只读的；在使用包含事务标识符的存储桶名称时，无法放置或删除对象。

事务管理

S3 没有事务的概念，因此 Foundry 数据集事务 会自动按以下行为处理：

  1. 当用户写入或删除文件时，事务会延迟开启。
  2. 该 API 支持并发写入多个文件 or 并发删除多个文件。文件将在同一个打开的事务中被修改，其中写入使用 UPDATE 事务，删除使用 DELETE transactions.
  3. 该 API 不支持并发写入 和 删除，因为这需要两个 UPDATE and DELETE 事务同时处于活动状态。这是平台级保证的结果，即一个分支最多只能有 一个打开的事务。无论哪个写入或删除请求先到达平台，都会打开相应的事务；在第一个事务提交之前（遵循下文所述的自动提交行为），另一类型的请求将无法打开自己的事务。这不会使数据集面临不一致状态的风险：写入和删除永远不会并发或交错应用，只是两种请求类型被处理的顺序取决于时间。
  4. 事务在写入或删除后的一段短暂不活动期后会自动提交。这使您可以在同一事务中上传多个文件，避免产生许多只包含少量文件的事务。为了避免事务被无限期地保持打开状态，例如在文件持续上传而没有不活动期的情况下，只要没有正在进行的上传，事务将在一定时间后被提交。如果文件以并行方式持续上传，则事务将保持打开，直到所有上传完成。
  5. 如果事务处于打开状态时在不活动期内收到读取请求， UPDATE and DELETE 事务将在可能的情况下立即提交。这旨在保留 S3 通常预期的读后写语义。但是，如果在打开的事务仍有活动的写入请求时尝试读取，则读取将来自最新提交的视图。要保证事务在所有写入或删除完成后提交，您可以在发出任何新的写入或删除请求之前发出后续的读取请求。

鉴于上述行为，读后写语义无法得到保证。但是，我们会尽一切可能在可行的情况下提供这些语义。

身份验证

通过 API 的连接使用访问密钥 ID 和秘密访问密钥凭据进行身份验证。

静态凭据

静态凭据类似于标准的 AWS 访问密钥 ID 和秘密访问密钥凭据。静态凭据是长期有效的，并且在 Foundry 的情况下，与以下对象的服务用户相关联 第三方应用程序 在 Foundry 的控制面板中注册。

使用静态访问密钥 ID 和秘密访问密钥通过兼容 S3 的 API 连接到数据集时，访问级别由授予第三方应用程序服务用户的访问权限决定。静态凭据必须限制为单个 项目。项目限制在生成新的一组凭据时指定。使用生成的凭据只能访问指定项目内的数据集。

有关构建自定义主题的示例，请参阅 设置指南 以下内容提供了使用 /io/s3/api/v2/credentials API 端点生成这些凭据的指导。

临时凭据

我们建议使用 静态凭据 用于任何需要长期有效凭据的工作流，或将访问权限与服务用户绑定有益的场景。如果您希望以常规 Foundry 用户身份向 API 进行身份验证，我们支持将 用户身份验证令牌 交换为临时 S3 凭据。该令牌也可以通过以下方式之一获取 OAuth2 授权，用于 第三方应用程序.

使用标准方式获取临时凭据 AssumeRoleWithWebIdentity ↗ 安全令牌服务 (STS) API。我们仅要求 WebIdentityToken 请求参数存在，并按上述说明配置为常规 Foundry 令牌。返回的临时凭据将具有与所提供令牌相同的范围。 DurationSeconds 参数可用于指定凭据的有效期。凭据的最长有效期为一小时，并且绝不会超过用于获取临时凭据的 Foundry 令牌的有效期。

STS API 可通过以下地址访问： https://<FOUNDRY_URL>/io/s3。如果您希望以编程方式获取 STS 凭证，应将此 URL 配置到标准 STS 客户端或凭证提供程序的端点配置中。例如：

要通过 S3 兼容 API 读取或写入数据，用户需要 s3-proxy:datasets-read 和 s3-proxy:datasets-write 权限，默认情况下，这些权限会授予 Viewer 和 Editor 角色。使用静态凭证时，需要为第三方应用对应的服务用户授予相关角色。使用临时凭证时，获取凭证的用户需要拥有相关角色。

路径式 URL 访问

该 API 仅支持 路径式 ↗ 存储桶访问。您的存储桶 URL 将采用以下格式 https://<FOUNDRY_URL>/io/s3/<bucket-name>/<key-name>.

用 Foundry 的术语来说，这意味着 https://<FOUNDRY_URL>/io/s3/<dataset-rid>/<logical-filepath>.

目前不支持虚拟主机式存储桶访问（即存储桶名称包含在 URL 的子域中）。

预签名 URL

以下操作支持预签名 URL putObject 运算。

设置指南

按照以下步骤设置从您的 S3 客户端到该 API 的连接。

  1. 在 Foundry 中注册第三方应用
  2. 为您的第三方应用的服务用户授予权限
  3. 生成 S3 访问密钥 ID 和秘密访问密钥
  4. 配置 S3 客户端

查看特定 S3 客户端的示例配置设置.

步骤 1：在 Foundry 中注册第三方应用

要获取 S3 兼容 API 的凭证，您首先需要获取以下对象的客户端 ID 和密钥 第三方应用程序 该对象已在 Foundry 的 Control Panel 中创建。请查看 身份验证概念 以了解项目限制的要求和行为，以及所生成凭证的范围。要注册该应用：

  1. 打开 控制面板 （在 Foundry 中）的更多信息。
  2. 选择 第三方应用程序 在侧边栏中。
  3. 选择 新建应用，然后使用以下参数完成设置向导：
    • 客户端类型： 选择 机密客户端.
    • 授权许可类型： 启用 客户端凭证许可.
  4. 选择 注册应用 在以下页面的右下角 摘要 page.
  5. 在完成页面上，请记录 客户端 ID 因为后续步骤中会用到。然后选择 启用应用使用 并使用切换开关来 启用 it.

步骤 2：为您的第三方应用的服务用户授予权限

用户应使用 自定义小部件 管理应用配置。仅当未为用户启用 控制面板 时，才适用 自定义小部件 视图。

在上一步中创建第三方应用时，Foundry 会自动创建一个服务用户。要通过 S3 API 访问数据集，该服务用户必须对相关项目和标记（Marking）拥有足够的权限。

要为服务用户设置权限：

  1. 查找服务用户的名称和 ID。您可以在应用的“管理应用”页面上找到这些详细信息，位于 授权许可类型 > 客户端凭证许可 > 服务用户.
  2. 为服务用户授予权限，可以直接将该用户添加到项目和标记（Marking）中，也可以将该用户添加到已被授予这些权限的组中。

步骤 3：生成 S3 访问密钥 ID 和秘密访问密钥

要生成凭证，您需要拥有 User experience administrator 在以下位置的 Organization 上的角色 控制面板.

运行以下终端命令（使用 curl 或 PowerShell）以接收访问密钥 ID 和秘密访问密钥。请替换命令中的以下占位符：

  • <TOKEN>：您的用户帐户的有效令牌。
  • <CLIENT_ID>：上一步中生成的第三方应用的客户端 ID。
  • <PROJECT_RID>：凭据应能够访问的 项目 的资源标识符（RID）。请参阅 查找项目 RID 以了解如何找到此值。

直方图 projectRestrictions 值可以接受多个项目，允许您在需要时列出更多项目 RID。必须至少指定一个项目。生成的凭据将只能访问所列项目内的数据集。

查找项目 RID

直方图 <PROJECT_RID> 值必须是顶级 项目的 RID，而不是项目内嵌套的文件夹或其他资源的 RID。项目和文件夹都使用 RID 格式 ri.compass.main.folder.{RID_VALUE}，因此仅凭格式无法区分它们。

提供嵌套文件夹、数据集或任何本身不是项目的资源的 RID，会在您使用生成的凭据时导致权限错误。即使该 RID 具有预期的 ri.compass.main.folder.{RID_VALUE} 格式，也会发生这种情况。如果遇到权限错误，请确认 projectRestrictions 中的值是项目本身的 RID，而不是其中某个资源的 RID。

要查找项目的 RID：

  1. 使用以下任一方法复制项目的 RID：
    • 选择 文件 在工作区导航侧边栏中，然后打开 项目 标签页。右键单击项目并选择 复制 RID。此列表仅包含项目，因此该值不可能属于项目内的文件夹。个人文件夹中的项目不会被列出，并且 复制 RID 对已回收（trashed）的项目不可用。
    • 打开项目并选择 操作 （位于文件列表上方），然后选择 复制 RID。如果 操作 不可见，请清除列表中的任何选定内容。
    • 打开项目并选择页面的空白区域以清除任何选定内容。 项目详细信息面板 随后描述的是您正在查看的文件夹，而不是其中的某个项目。复制 RID 字段（位于其 元数据 section.
  2. 直方图 操作 菜单和详细信息面板都适用于您当前打开的文件夹，因此请在根级别打开项目。详细信息面板会指明它所描述的资源，因此您可以用它来确认该值属于该项目。

直方图 projectRestrictions 值决定了凭据可以访问哪些数据集；它并不控制文件在数据集中的写入位置。由于 S3 存储桶对应于 Foundry 数据集，您需要使用对象键（逻辑文件路径）来组织数据集内的文件，而不是通过指定 Foundry 文件夹。要将文件发送到特定位置，请选择目标数据集作为存储桶，并使用键前缀（例如 logs/ ）对其中的文件进行分组。

指定组织

默认情况下， /v2/credentials 端点假定进行身份验证的用户是在自己的 配置中为第三方应用程序生成凭据。如果第三方应用程序存在于不同的组织中，请在 URL 中将组织 ID 指定为查询参数： https://<FOUNDRY_URL>/io/s3/api/v2/credentials?organizationRid=<ORGANIZATION_ID>.

客户端设置示例

如上所述，您必须确保客户端/SDK/连接器配置为使用路径式存储桶访问。如果客户端不支持路径式存储桶访问，则目前与此 API 不兼容。 例如，使用 S3A Hadoop 客户端 ↗ 时，可以通过 fs.s3a.path.style.access 标志进行配置。

import boto3
import pandas as pd

s3 = boto3.client(
    's3',
    aws_access_key_id="<ACCESS_KEY_ID>",
    aws_secret_access_key="<SECRET_ACCESS_KEY>",
    # aws_session_token="<SESSION_TOKEN>", only needed when using temporary credentials
    endpoint_url="https://<FOUNDRY_URL>/io/s3",
    region_name="foundry"
)

bucket = 'ri.foundry.main.dataset.<uuid>'
key = 'iris.csv'

obj = s3.get_object(Bucket=bucket, Key=key)
df = pd.read_csv(obj['Body'])
print(df)

from pyspark.sql import SparkSession

hostname = "https://<FOUNDRY_URL>/io/s3"
access_key_id = "<ACCESS_KEY_ID>"
secret_access_key = "<SECRET_ACCESS_KEY>"

# ensure dataset RID can be parsed as a valid hostname
dataset_rid = "ri.foundry.main.dataset.<uuid>".replace('.', '-')

spark_session = (
    SparkSession.builder
        .config("fs.s3a.access.key", access_key_id)
        .config("fs.s3a.secret.key", secret_access_key)
        # .config("fs.s3a.session.token", session_token) only needed when using temporary credentials
        .config("fs.s3a.endpoint", hostname)
        .config("fs.s3a.endpoint.region", "foundry")
        .config("fs.s3a.path.style.access", "true")
        .getOrCreate()
)

df = spark_session.read.parquet(f"s3a://{dataset_rid}/*")
df.show()

Google Storage Transfer Service

Google Cloud 的 Storage Transfer Service ↗ 可以将 Foundry 视为 S3 兼容数据源 ↗。您可以按照以下步骤将数据从 Foundry 数据集传输到 Cloud Storage 存储桶。

  1. 按照 Google Cloud 的说明 ↗.

  2. 设置代理池和传输代理。创建一个传输作业，然后选择 S3 兼容对象存储 作为 源类型。然后选择您在步骤 (1) 中创建的代理池，并确保设置了以下配置：

    • 存储桶： ri.foundry.main.dataset.<uuid>.
    • 端点： https://<FOUNDRY_URL>/io/s3
    • 签名区域： foundry
    • 签名流程： Signature Version 4 (SigV4)
    • 寻址样式： 路径样式请求
    • 网络协议： HTTPS
    • 列表 API 版本： ListObjectsV2

完成设置，以配置 Cloud Storage 存储桶目标、计划以及传输作业的设置。

Apache NiFi

您可以使用 Apache NiFi 在 Foundry 数据集中读取和写入文件。以下示例展示了如何配置 PutS3Object 处理器类型以进行写入：

  • 对象键： 数据集中的逻辑文件路径，格式为 path/to/file.csv
  • 存储桶： 数据集 RID，例如 ri.foundry.main.dataset.<uuid>
  • 访问密钥 ID： <ACCESS_KEY_ID>
  • 秘密访问密钥： <SECRET_ACCESS_KEY>
  • 地区： "US East (N. Virginia)"，对应于 us-east-1
  • 使用路径样式访问： true
  • 端点覆盖 URL： https://<FOUNDRY_URL>/io/s3

请参阅 Apache NiFi 文档 ↗ 以了解有关 PutS3Object 处理器及其他支持 S3 兼容数据源的处理器的更多信息。

Airbyte

Airbyte ↗对 S3 目标的支持可用于将文件写入 Foundry 数据集。请设置以下目标设置：

  • 目标类型： S3
  • S3 Key ID： <ACCESS_KEY_ID>
  • S3 Access Key： <SECRET_ACCESS_KEY>
  • S3 Bucket Name： ri.foundry.main.dataset.<uuid>
  • S3 Bucket Path： 任何有效的子目录路径。Airbyte 会将文件写入 Foundry 数据集中的该子目录。
  • S3 Bucket Region： us-east-1
  • 输出格式： Airbyte 的所有输出格式均与 Foundry 数据集兼容。
  • 端点： https://<FOUNDRY_URL>/io/s3

有关更多信息和配置选项，请参阅 Airbyte 的文档 S3 目标 ↗ 。

Polars

DuckDB ↗对 S3 的支持可用于查询 Foundry 数据集。您可以使用 DuckDB secrets 管理凭据，并使用 s3:// 前缀的 URL 查询数据集。

CREATE SECRET foundry_secret (
    TYPE S3,
    KEY_ID '<ACCESS_KEY_ID>',
    SECRET '<SECRET_ACCESS_KEY>',
    REGION 'foundry',
    ENDPOINT '<FOUNDRY_URL>/io/s3',
    URL_STYLE 'path'
);

CREATE TABLE new_tbl AS SELECT * FROM 's3://ri.foundry.main.dataset.<uuid>/spark/*.parquet';

请参阅 DuckDB 文档 ↗ 的文档以获取更多信息。

在上面的 secret 配置中， ENDPOINT 配置参数不应包含 https:// 方案（scheme）。URL 方案由 USE_SSL 参数自动处理，其默认值为 true.
