会话历史和会话固定

会话

在 Spark 模块中初始化 Code Workbook 环境时，会有一系列元数据归属于该模块。这些元数据可分为两类：计算信息和环境信息。 的行进行分组。如果行共享同一个键，且在事件时间中该键对应的行未出现超过用户指定会话间隔的断档，则这些行属于同一会话。例如，在包含流媒体平台用户行为数据的数据集中，可以将用户一次工作流中的所有行归为一组，直到用户休息为止。 是这些设置在 Spark 模块生命周期中的一次实例化，或者非正式地说，“在给定 Spark 模块的生命周期内什么是真实的”。

计算信息包括归属于 Spark 模块的 Spark 设置的详细信息，以及其他相关信息，例如 jar 依赖项、资源标识符和所启动模块的类型。另一方面，环境信息可进一步细分为两类：请求的环境和解析后的环境。 请求的环境 是一组 conda 规范，例如请求 pandas=2.* or python<3.10，而 解析后的环境 是满足请求环境所设定约束的一组已解析的包。请求的环境是非确定性的，而解析后的环境根据定义是给定请求环境的永久解决方案。因此，两个相同的请求环境可能会导致不同的解析后环境。例如，在 2017 年请求 python>=3.6 可能会解析为 Python 3.6，而今天发出相同的请求可能会得到 Python 3.10。

会话历史

Code Workbook 提供有关 Workbook 所有近期会话的信息。要查看 Workbook 的会话历史，请选择 环境 Code Workbook 的下拉菜单并选择 查看会话历史.

直方图 会话历史 窗口通过三个不同的选项卡提供信息： 计算信息, 请求的环境日 解析后的环境。左侧窗格提供会话的 ID 以及会话初始化时的时间戳。会话 ID 左侧的图标将指示其是否成功初始化（绿色）、失败（红色）或其他（蓝色）。蓝色会话通常表示会话尚未完成初始化，因此既未达到失败状态也未达到成功状态。

计算信息

直方图 计算信息 选项卡提供有关给定会话所请求的 Spark 模块类型的信息：

  • moduleAssignmentInfo: 有关环境是由特定用户为交互式 Workbook 使用而启动，还是由后台作业（例如计划构建）启动的一般信息。有关交互式模块和构建模块之间区别的更多信息，请参见 批量构建和交互式构建.
  • moduleLaunchInfo: 有关分配给 Spark 模块本身的属性的元数据。这包括以下字段：
    • sparkModuleRid: Spark 模块的唯一标识符。鉴于模块与会话之间存在 1:1 的映射关系，您会注意到 sparkModuleRid 和 sessionId 将共享相同的唯一标识符
    • profileRid: 初始化 Spark 模块时所使用的配置文件的唯一标识符。
    • isCustomEnv: 该会话是否使用自定义环境进行初始化。请注意，Code Workbook 中的自定义环境定义为在 Code Workbook 界面的环境配置菜单中直接修改过的任何标准配置文件。
    • jarDependencies: 在配置文件中手动添加的所有 jar 依赖项的列表，位于 控制面板.
    • moduleLaunchType: 可以是 WARM_MODULE or ON_DEMAND_MODULE。指示该会话是使用了预热模块队列中已初始化的模块，还是请求了一个新模块来启动其初始化过程。
    • moduleResources: 与该模块相关的所有计算信息，包括驱动程序和执行器内存、执行器数量等。

请求的环境

直方图 请求的环境 选项卡提供有关初始化开始之前所需环境设置的信息：

  • 初始化模式： 要为该会话执行的 Code Workbook 初始化类型。它可以是 solve, file，或 docker。有关 Code Workbook 中初始化类型的更多信息，请参阅有关 环境优化的文档.
  • 环境仓库： 所讨论的环境存储所用的键。对于非自定义环境，这将是会话所使用的 profileRid 。对于自定义环境，这将是 workbookRid 自定义该配置文件的工作簿的。
  • 请求的软件包： 初始化过程中提交的请求软件包列表。此列表将包括配置文件明确请求的软件包，以及 Code Workbook 为正常运行而自动请求的任何其他软件包。
  • 支撑仓库： 已安装软件包的来源通道列表。

解析后的环境

直方图 已解析环境 选项卡提供有关初始化过程中使用的环境软件包的信息。这包括初始化环境所需的时间，以及最终安装到模块上的软件包及其版本。此信息尤为重要，因为 Code Workbook 的会话回滚功能借用的是先前会话的已解析环境，而非请求环境。

比较会话

比较两个给定会话通常有助于理解给定环境可能发生的变化。 会话历史 窗口允许您将当前会话与任何历史会话进行比较。您可以通过选择 比较会话 （位于会话历史窗口右上角）来访问会话历史比较选项卡。

会话比较菜单将并排提供两个窗口。右侧显示当前会话的信息。左侧可以显示 会话 列表中的任何会话以进行比较。要切换左侧要比较的会话，请从会话列表中选择任意会话。您可以随时通过选择 退出比较 （位于窗口右上角）来退出比较视图。左侧选定的会话将保持选中状态。

可以在所有三个可用选项卡之间比较会话。比较两个会话的 计算信息 有助于理解模块可用内存的变化。比较 请求的环境 有助于理解两个给定会话的环境之间手动进行了哪些更改，而比较 解析后的环境 则有助于理解两个会话之间安装的不同版本。

在下面的示例中，使用会话比较的各个选项卡可以揭示有关两个会话的以下信息：

  • 使用了不同的配置文件。
  • 配置文件已自定义。
  • 模块上采用了较小的内存设置。

  • 请求了更新的 Python 和 pandas 软件包版本（除其他外）。

  • 环境中最终安装的 Python 版本不同。

会话固定

在某些情况下，您可能希望临时回滚到历史会话的完全相同设置。Code Workbook 通过提供固定会话的机会来允许此行为。固定会话意味着使用与历史会话相同的元数据初始化一个全新的会话和 Spark 模块，以重现看似相同的环境。固定的会话将借用历史会话的 "已解析" 信息来初始化一个新模块。这一点尤为重要，因为使用相同的已解析环境可保证安装的软件包相同，而使用相同的请求环境则不能。因此，固定会话可模拟回滚到先前正常工作的环境的效果。少数几项元数据（例如初始化模式）不会从历史会话中借用。

如何固定会话

要固定会话，请导航至 会话历史 窗口并选择要固定的会话。然后选择 固定会话 （位于面板右下角）。Workbook 的当前分支将拥有一个固定会话覆盖，最长可持续 24 小时。横幅将显示覆盖的剩余时间，以及移除固定状态的选项。在此期间，后续每次交互式环境初始化都将借用该固定会话的信息。当该期限到期或会话被手动取消固定时，Workbook 将恢复使用其当前配置的环境。

会话固定专为调试目的而设计，不应依赖其用于长期的、可用于生产环境的管道。因此，固定会话只会影响 交互式 环境。在 Code Workbook 界面之外执行的构建（例如计划构建）不会受到固定会话覆盖的影响。我们建议您将会话固定限制在偶尔的故障排除和实验中。请改用 会话历史 功能来了解各个会话之间的差异，并直接编辑环境定义。

会话固定的限制

固定会话时存在某些限制。固定会话不会无限期持续，并非每个会话都可以固定，也并非每次初始化都会受到固定会话的影响。以下是考虑固定会话时需要注意的限制列表：

  • 会话固定最长可持续 24 小时。要进一步延长此时间，您需要重新固定该会话。重新固定会话将导致启动一个新模块，并且模块上的所有本地状态都将丢失。
  • 固定会话不会从其附加的历史会话中借用所有元数据。初始化模式等设置可能会有所不同。
  • 只有先前成功的会话才能被固定。未完成或不成功的会话不允许固定。此外，由于版本不兼容、列入黑名单的包版本、API 中断等原因，Code Workbook 可能会防御性地阻止您选择要固定的版本。红色横幅将告知您无法固定的会话。
  • 固定会话仅影响交互式作业，不影响构建作业。
  • 只有使用 Artifacts Profiles 的会话才能被固定

基于上述原因，固定会话是一项调试功能，不应依赖其用于长期的、可用于生产环境的管道。

使用会话历史排查环境故障

直方图 会话历史, 会话比较日 会话固定 上述功能对于排查环境故障非常有用。特别是，它们有助于解决之前正常工作的环境出现的故障。请按照以下步骤处理此类情况：

  1. 该环境过去是否正常工作？

    • 如果没有，请参阅 环境故障排除指南.
    • 如果是，但现在出现故障，请继续下一步。

  2. 使用 比较会话 功能，选择当前失败的会话与之前成功的会话进行对比，并观察环境中的差异。

    • 如果计算信息详情发生变化，模块设置中的内存可能不足，导致模块无法正确初始化。
    • 如果请求的环境详情发生变化，则说明环境中引入了手动破坏性变更，从而导致故障。
    • 如果请求的环境详情没有变化，但解析后的环境发生变化并导致故障，则所使用的某个包的新版本可能包含破坏性变更。这些包通常来自开源。您可以直接调查有问题的包，或修改您的环境以避免请求相关的包或版本。
    • 如果环境没有明显变化，或者上述步骤没有帮助，请查阅 环境故障排除指南 或联系 Palantir Support 以获取进一步帮助。

  3. （可选）在上一步骤中进行故障排除时，使用 会话固定 功能首先确保固定版本的环境可以正常工作，并在找到更持久的解决方案之前临时恢复 Workbook 的功能。

  4. 在发现环境故障的根本原因后，相应地调整您的配置文件设置，以永久解决该情况。
