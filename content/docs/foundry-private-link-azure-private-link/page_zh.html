Azure Private Link

Azure Private Link ↗ 通过确保对 Foundry 的访问经由专用 IP 地址进行，提供与 Foundry 的专用连接。Azure Private Link 支持不同虚拟网络（VNet）区域之间的连接。请注意，Azure Private Link 是一项 Microsoft 服务。

在入口、出口或两者之间进行选择

在设置 Azure Private Link 之前，您需要确定您的使用场景需要哪种类型的专用连接。

入口指从您的网络流入 Foundry 的流量。例如，您 VNet 中回连到 Foundry 的 Data Connection 代理，或从专用网络访问 Foundry UI 的用户。

出口指从 Foundry 流向您环境中资源的流量。例如，Foundry 从 Azure SQL 数据库或其他 VNet 托管的服务同步数据。这两个方向用途不同，且各自需要单独设置。

如果您的数据源是 Azure Blob Storage 或 Azure Data Lake Storage Gen2，您可能完全不需要 Private Link。Azure Storage 网络策略是自助式的，可直接在 Control Panel 中进行配置。仅当您的组织有特定需求且无法通过存储策略将 VNet 子网加入允许列表时，才为 Azure Storage 设置出口 Private Link。

您的环境可能涉及多个用例，每个用例都需要入口或出口连接。 入口 和 出口 是相互独立的设置，可以单独配置，也可以一起配置。请参阅以下相关章节，了解各自的设置步骤。

通过 Azure Private Link 实现到 Foundry 的入口

流量可以从您的非 Foundry 虚拟网络（VNet）经由 Microsoft 骨干网络传输到 Foundry VNet。若要同时支持 Private Link 流量和到 Foundry 的公共互联网流量，请配置额外的 IP 白名单，方法是使用 Control Panel 中的入口配置。

设置通过 Azure Private Link 到 Foundry 的入口

  1. 请将您的 Azure 订阅 ID 提供给您的 Palantir 代表。您可以在 Azure 门户 ↗中找到 Azure 订阅 ID，相关说明请参阅 获取订阅 ID 的 Azure 文档 ↗。
  2. Palantir 将向您提供您 Foundry 注册的 专用链接别名 ↗。该别名通常采用以下格式： ingress-privatelink.<GUID>.<REGION>.azure.privatelinkservice。
  3. 在您的 Azure 门户 ↗中创建新的专用终结点。以下步骤遵循 Azure 创建专用终结点指南 ↗。
  4. 选择 新建服务，然后选择 专用终结点，然后选择 创建。
  5. 填写您的资源组详细信息并为您的专用链接命名，然后选择 下一步。
  6. 选择 通过资源 ID 或别名连接到 Azure 资源 ，并填写您之前从 Palantir 收到的 Foundry 实例的专用链接别名，然后选择 下一步。
  7. 选择您的虚拟网络和子网。在大多数情况下， 专用终结点的网络策略 设置应处于禁用状态；请参阅 Azure 文档 ↗ 以了解有关此设置的更多信息。 应用程序安全组 可以留空。
  8. 在 DNS 部分中，可以将专用 DNS 集成保持为“禁用”状态，除非已经设置了要与该终结点配合使用的专用 DNS 区域。也可以在创建专用终结点之后再设置专用 DNS 集成。
  9. 如果在 Azure 环境中使用了标签，可以选择性地添加标签。选择性地添加标签后，选择 查看 + 创建。
  10. 您应该会看到一条 “验证通过” 消息显示在屏幕顶部。如果是这样，请查看配置并选择 创建 以开始部署过程。
  11. 部署完成后，您应该会看到“部署完成”消息；部署完成后，请选择 转到资源。
  12. 在专用链接概述中，选择 设置 > 属性，然后复制“资源 ID”字段并将其发送给您的 Palantir 代表。例如，资源 ID 可能如下所示： /subscriptions/<SUBSCRIPTION_UUID>/resourceGroups/<RESOURCE_GROUP_NAME>/providers/Microsoft.Network/privateEndpoints/<PRIVATE_ENDPOINT_NAME>
  13. 创建一条 DNS 记录，将 Foundry 域指向专用链接 IP 地址。如有需要，请先创建一个连接到包含该专用链接的资源组的专用 DNS 区域。创建完成后，它将显示在 DNS 区域视图中。更多信息请参阅 Azure 专用终结点 DNS 集成文档 ↗。
  14. 在 DNS 区域中，创建一条指向专用链接专用 IP 的 A 记录（可在专用链接的 DNS 配置 部分中找到）。请注意，您可以将 名称 字段留空，如果您的 DNS 区域已包含完整的 Foundry 域名（例如 <your-enrollment>.palantirfoundry.com）。否则，请添加子域前缀以匹配完整的 Foundry 域名。
  15. （有条件）如果 Foundry 域名 由您拥有 （即该域名并非 Palantir 所拥有的域名，例如 *.palantirfoundry.com），则还需要额外配置来将内部 Foundry 服务也通过该端点进行传输，相关步骤在以下文档中定义： 客户自有域名专用链接。
  16. 刷新并清除浏览器缓存，之后从您的 Azure VNet 到 Foundry 的所有流量都将通过专用链接而非公共互联网进行路由。

用于 Azure 专用链接的 Foundry 出站流量

从 Foundry 到其他 Azure VNet 的流量可以配置为通过 Azure 主干网络而非公共互联网进行路由，无论 Foundry 实例的 VNet 和目标 VNet 位于相同还是不同的 Azure 区域。

设置用于 Azure 专用链接的 Foundry 出站流量

有关设置用于 Azure 专用链接的 Foundry 出站流量的说明，请参阅 为 Azure 配置专用链接出站流量的文档。

某些 Azure 服务支持通过 Azure 主干网络发送所有流量 而无需承担使用自定义 Private Link 所产生的额外 Azure 费用，只需使用 Azure 网关即可。目前支持的 Azure 服务包括：

  • Azure 存储： 这项操作可在 Palantir Foundry 中自助完成，方法是创建 Azure 存储策略，相关说明请参见 Azure 存储策略文档。

如需与所有其他 Azure 服务或需要设置出口 Private Link 的 Azure VNet 建立专用连接，请参阅 有关为 Azure 配置 Private Link 出口的文档。
