添加本体论输出

您可以选择添加本体论输出，以引导您的管道集成朝着干净、结构化的数据方向发展，这些数据定义了全局本体论的新元素。添加输出引导有助于节省计算检查的时间，并有助于为工作流的端到端创建提供信息。

Pipeline Builder 目前支持从批处理和流式数据集创建本体论对象和关联。但是，在 Pipeline Builder 中，无法为基于流式数据集的对象启用编辑或配置多对多关联。

添加对象类型输出

有两种方法可以添加对象类型输出。您可以通过管道输出面板创建一个空白对象，或者在图上创建一个连接到转换节点的已填充对象。

打开 管道输出 面板位于 Pipeline Builder 的右侧，然后选择 Object type > Add 以创建一个空白对象模板，您可以在其中编辑对象名称、图标和属性。

您现在可以通过选择以下方式为对象填充数据 手动输入数据 或者将现有数据集或转换的输出拖动到此节点的输入。

编辑对象类型 API 名称

您可以在 Pipeline Builder 的对象类型编辑器中直接编辑对象类型的 API 名称。要编辑 API 名称，请将鼠标悬停在右侧面板中的对象类型上，然后选择 编辑，然后修改 API 名称 字段中，复制在 Quiver 仪表板中定义的对象输入名称。

直方图 API 名称 字段会在提交时验证名称，检查以下内容：

  • 当前本体论中的重复项
  • 有效的格式要求
  • 最大长度为 100 个字符

首次部署后，对象类型 ID 无法修改。但是，您仍然可以编辑管道所拥有的对象类型的 API 名称。

在对象类型上启用编辑

如果对象是在 Pipeline Builder 中创建的并且由批处理数据集支撑，您可以在 Pipeline Builder 或 Ontology Manager 中启用对象类型的编辑。

流式支撑的对象类型 目前不支持编辑。要在流式支撑的对象类型上启用编辑，请使用 直接数据源 功能来自动映射所有列。

要启用编辑，请将鼠标悬停在右侧面板中的对象类型上，然后选择 编辑。切换 允许编辑此类型的对象。保存并部署您的管道以使其生效。

测试版

  2. 根据需要配置对象目标，然后部署。部署完成后，该对象类型将显示在 本体论管理器中，其对象可在 Insight and 对象浏览器.

中查看。了解有关部署后监控和调试直接数据源的更多信息。.

已知限制

作为正在积极开发中的 Beta 功能，直接数据源目前存在以下限制：

  • 重放会清除对象视图： 重放流式管道会移除现有对象视图，以便立即提供新视图。由于切换是即时的，新视图尚未完全填充，因此对象视图可能会暂时不完整或为空。完整视图将随时间逐渐填充。用于解决此限制的重放功能正在开发中，本文档将相应更新。
  • 初始部署超时： 在初始部署时，或在使用重置输出进行重放时，流式作业可能在提交前失败，因为部署期间执行的初始设置可能导致超时。
  • 不支持分支： 直接数据源不能在分支上使用。
  • 回填可能较慢： 重放后回填数据可能较慢。相关改进正在开发中。

有关修复步骤和其他常见问题，请参阅 直接数据源常见问题解答.

添加关联类型输出

添加对象类型输出后，您可以定义关联类型输出。与对象输出类似，这些输出可以在面板中或在图上创建。

使用管道输出面板

在监听器设置向导的 管道输出 面板中，选择 Link type > Add。这将打开一个表单，您可以在其中定义关联类型的左侧和右侧。

在 Pipeline Builder 中定义的关联只能使用在同一管道中创建的对象。在 Ontology Manager 应用程序本身中，您可以创建 Pipeline Builder 中创建的对象与 Ontology Manager 中创建的对象之间的关联。
首次部署后，关联类型 ID 或源和目标对象类型将无法再修改。

解决本体论验证错误

用户可能对管道进行更改，从而导致本体论中出现验证错误。错误的一些示例包括：

  • 在 Pipeline Builder 和 Ontology Manager 中对同一对象类型或关联类型进行了冲突的更改。
  • 更改了被管道外部的关联类型引用的对象类型的主键。
  • 对对象类型的架构进行了破坏性更改，以至于需要进行 架构迁移 。

任何错误都将显示在右侧面板的 部署此管道 部分下。在 错误 标签页中，将有一条消息描述在部署之前需要执行哪种类型的解决操作。

您必须先解决这些错误，然后才能部署您的管道。

当 解决 按钮显示箭头时，选择它将带您进入 Ontology Manager 以解决验证错误。否则，您将能够直接在 Pipeline Builder 中解决这些错误。

在 Ontology Manager 中解决合并冲突

按照 Ontology Manager 中的提示应用合并冲突解决操作。如果您的更改影响潜在的编辑，您可以决定是放弃这些编辑还是使您的编辑与最新版本的对象兼容。否则，无需额外的规范即可解决合并冲突，您可以选择 保存您的更改。.

更改应用后，本体论将更新为最新更改，您可以选择 返回管道.

解决冲突后，您偶尔可能会遇到错误 Ontology type outputs are out of date with the ontology 当返回到您的管道时。这是因为管道尚未获取通过上述冲突解决工作流对您的本体论输出所做的更改。

选择 解决 应该可以解决此问题，并允许您部署您的管道。

在 Pipeline Builder 中解决冲突

某些本体论验证错误不需要切换到 Ontology Manager。在下面的示例中，需要进行 schema 迁移，当 Pipeline Builder 中的对象类型 schema 与本体论主分支上的最新 schema 不一致时，就会发生这种情况。选择 解决 以直接在 Pipeline Builder 中选择迁移策略。

对于受影响的属性，您可以选择是否 从属性中丢弃编辑 或迁移您的编辑，使其与该属性的最新版本兼容。

选择最佳方案后，选择 应用迁移.

将对象类型输出重新引入 Pipeline Builder

您可以按照以下步骤，将管道中由数据集输出支撑的对象类型重新引入 Pipeline Builder：

在右侧面板中，选择旁边的齿轮图标 管道输出.

选择 替换为对象。这将打开 将数据集替换为本体论类型输出 对话框中搜索该表格。

选择您想要转换回管道中相应对象的数据集输出，然后选择 导入所选输出.

保存您的更改并部署您的管道。

在 Pipeline Builder 中取消认领本体论类型输出

在 Pipeline Builder 中放弃本体论类型输出会将这些本体论类型的管理权转移给 Ontology Manager。这意味着对这些本体论类型的所有后续修改只能在 Ontology Manager 中进行。当您需要 Pipeline Builder 不支持的对象类型配置（例如共享属性类型或运行时派生属性）时，这非常有用。要放弃本体论类型，请选择您想要放弃的对象类型。任何引用所选对象类型的关联类型都将自动转移到 Ontology Manager。

只有当 main 分支的最新保存版本成功部署后，本体论类型输出才能被替换为数据集输出。

选择 放弃所选的对象和关联类型.

在此管道中， 对象类型 输出节点将转换为 数据集 支撑 Ontology Manager 中对象类型的输出节点。在最右侧的面板中，通过选择输出旁边的图标，导航到 Ontology Manager 中的对象类型。

如果您放弃一个 直接数据源支撑的 对象目标，图中被放弃的节点将显示为流数据集。但是，此节点代表支撑该对象类型的直接数据源，而不是流数据集。与流数据集不同，直接数据源不直接存储数据；数据存储在本体论中。放弃后，您仍然可以在 Ontology Manager 或 Insight 中导航到该对象类型。

放弃所选对象后，部署您的管道。

支撑数据源中的列名必须与为给定对象类型的属性配置的支撑列名完全匹配。列名不匹配将导致数据缺失或索引作业失败。例如，一个支撑列为 routeId 的属性要求在支撑数据源中有一个名为 routeId 的列。

配置细粒度安全权限

您可以通过使用 受限视图策略 或 对象安全策略:

  • 受限视图 （RV）实现行级安全。
  • 对象安全策略 同时实现行级和列级安全。

Pipeline Builder 中的对象安全策略目前支持 Ontology Manager 中对象安全策略可用功能的一个子集。以下部分描述了 Pipeline Builder 支持的功能。

仅读取时强制执行

行和列访问控制（包括 受限视图 和 对象安全策略）用于过滤用户可以从 Pipeline Builder 输出中读取的内容。这些控制不会延伸到下游输出或导出。为了在数据流向下游时保持受保护状态，请将这些控制与 标记 or 基于分类的访问控制配合使用。有关完整模型，请参阅 访问控制传播.

要设置细粒度安全策略，请转到输出对象并选择 配置细粒度安全.

在弹出窗口中选择 受限视图策略 or 对象安全策略 。

对象安全策略

直方图 对象安全策略 选项允许您使用行级策略、属性安全策略、标记移除管理和分类更改来配置单元格级别的细粒度安全。

默认情况下，对象安全策略会应用于所有属性。当属性安全策略包含某个属性时，用户必须同时通过对象安全策略和属性安全策略才能查看该属性值。

要添加行级策略，请选择+旁边的加号（ 细粒度安全.

在策略编辑器中，您可以创建比较属性值、用户属性或常量值的规则来定义安全条件。

要基于 标记或分类 用户属性创建策略，请确保值类型设置为 标记 or 分类.

要强制使用正确的类型，请使用 Logical Type Cast 转换节点中的表达式。

此外，标记和分类必须包装在数组中才能与本体论兼容。将单个标记或分类直接映射到对象属性会导致错误。

标记必须使用关联的标记 ID。详细了解 标记 ID 的预期格式.

您可以转到 强制控制 以移除任何继承的标记或 分类 以调整分类。

Pipeline Builder 目前不支持调整手动输入的表的分类。

属性安全策略可以以类似的方式添加。选择 将 菜单中选择 属性安全策略 部分。这将创建一个新的属性安全策略。要配置属性安全策略，请选择要编辑的策略上的箭头。
