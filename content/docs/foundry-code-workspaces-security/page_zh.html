安全性

Code Workspaces 将 Foundry 的安全和权限模型应用于托管的第三方集成开发环境（IDE）。代码工作区是一个具有代码执行和终端访问权限的开发环境；第三方 IDE 可以在代码工作区内运行。工作区中的代码、扩展和其他开发者工具可以代表用户发起受支持的请求。因此，组织应将对 Code Workspaces 的访问权限评估为对通用创作环境的访问权限。

身份和平台权限

关于身份和平台权限，需要牢记三个主要原则：

  • Foundry 代表当前用户授权由工作区发起的请求。
  • 访问权限既要求相应操作包含在工作区凭证范围内，也要求用户对所请求的资源具有权限。
  • 通过受支持的工作流导入和导出的数据会保留数据溯源和强制控制。

每个工作区会话都代表当前用户运行。Foundry 为会话提供一个用户凭证，其范围限定为 Code Workspaces 所支持的操作和资源。每个 Foundry 服务都会根据凭证的操作和资源范围，以及用户对所请求资源的权限，对请求进行授权。

Code Workspaces 根据受支持的创作工作流所需的操作和资源约束来定义凭证范围。某些操作仅限于与工作区关联的特定资源，例如其支撑仓库或容器。其他操作则支持更广泛的资源发现和元数据访问。该范围还支持仓库开发、基于分支的变更管理、预览以及选定的平台集成。与受支持的 Code Workspaces 工作流无关的操作（包括广泛的管理操作）不在范围内。某些功能仅在其为工作区启用时才会添加到范围内。该凭证并非只读：当用户具有相应权限时，创作所需的选定写操作仍然可用。

可能影响安全数据血缘的数据访问会单独处理。在加载受支持的数据之前，Foundry 会将该资源注册为工作区会话的输入，并使用限定于该输入的凭证来解析访问权限。这会记录数据溯源，并将强制控制（例如标记）传播到工作区及其受支持的输出。试图绕过此处理的请求不允许通过工作区凭证执行。因此，通过受支持的 Code Workspaces 工作流进行的数据导入和导出都会在 Foundry 中被跟踪。

其他项目中的资源通常通过以下方式提供： 项目引用 导入到工作区所在项目中。仅当凭证范围允许对该资源执行相应操作且用户具有访问权限时，工作区中的代码才能访问此类资源。资源与工作区位于同一项目本身并不授予访问权限。项目角色、组织、标记、细粒度访问控制和资源权限仍然适用。

Foundry 会根据用户的权限以及从已注册输入传播的安全控制，对打开或使用工作区的请求进行验证。如果用户对工作区的访问权限被撤销，Foundry 将拒绝其访问该应用程序。如果用户对任何已注册数据输入的强制控制（例如标记）失去访问权限，Foundry 也将拒绝其访问该工作区及其受支持的输出。权限更改可能需要一小段时间才能传播。

会话隔离和数据控制

Code Workspaces 围绕 IDE 会话提供以下控制：

  • 每个打开工作区的用户都会获得一个隔离的会话。Foundry 会根据该用户的身份和权限验证来自会话的请求。会话状态和数据检查点不会在用户之间共享。
  • 通过 Code Workspaces 加载的数据由 Foundry 跟踪。数据下载和上传受到限制，除非通过 受 Foundry 数据治理和访问控制管理的方法.
  • 从 Code Workspaces 写入的数据由 Foundry 跟踪。权限和数据血缘控制适用于受支持的输出。
  • 外部网络访问受限于为工作区配置的 源和出口策略 。Foundry 会根据用户权限验证对这些资源的访问。在支持的情况下，源会将外部系统的凭证与代码分开保存。

开发工具和 AI 辅助功能

工作区中可用的开发工具（包括 IDE 扩展、命令行工具、模型上下文协议（MCP）服务器和 AI 编码助手）在工作区会话内运行。根据其功能和配置，这些工具可能会读取工作区内容、执行命令或调用已启用的 Foundry 工具。它们不会独立扩展用户的 Foundry 权限，但可以在工作区凭证支持的操作范围内行使用户可用的访问权限。

工作区中可用的工具、模型和审批流程可能因注册和发布版本而异。在评估工作区时，请考虑已启用开发工具的完整集合以及这些工具可以访问的数据或操作。

审计和使用情况可见性

从工作区到 Foundry 服务的请求由为这些服务提供的审计日志记录覆盖，并保留可用的用户和请求上下文。审计日志描述 Foundry 服务收到的操作；它们不是本地编辑器、终端或 AI 对话活动的完整记录。通过 AI 辅助工具发起的一个操作可能会导致多个服务请求。有关更多信息，请查阅 审计日志概述 和 审计监控指南.

受限输出模式

受限输出模式在处理敏感数据时提供增强的保护。受限输出模式是一种“只读”模式，它限制写入操作和外部源连接，以确保数据无法从代码工作区导出。具体而言，它允许您加载 受限视图 到工作区中。

您只能在 JupyterLab® 工作区中读取受限视图。

启用后，受限输出模式将：

  • 阻止写入操作 到所有 Foundry 输出，包括数据集、模型和表。
  • 禁用遥测收集和日志以及数据检查点上传，同时仍保留 代码检查点.
  • 禁用网络策略和数据源 这些资源仍保留在工作区中，但在受限输出模式下处于停用状态。

如相关文档中所述 代码检查点，您有责任确保在受限输出模式下编写的代码文件不包含数据。

要启用或禁用受限输出模式：

  1. 打开 设置 在您的代码工作区中的侧面板。
  2. 找到 受限输出模式 toggle.
  3. 根据需要打开或关闭该设置。
  4. 保存您的更改，并在提示时重启您的工作区。

启用受限输出模式后，您的工作区将提示您重启。您的设置将在未来的工作区重启中持续保留，直到您明确将其禁用。
