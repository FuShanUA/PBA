客户端凭据应用程序

客户端凭据应用程序是外部托管的 OAuth 或 OSDK 应用程序，它们使用客户端凭据进行身份验证。此类应用程序非常适合需要最大用户规模、并允许在 Foundry 之外使用客户自定义身份验证和授权逻辑的专业代码解决方案。

客户端凭据应用程序适用于以下使用场景：

  • 不需要用户登录的服务器间集成。
  • 需要以编程方式访问 Foundry 数据的自动化系统。
  • 处理数据或触发工作流的后端服务。
  • 与外部平台的 API 集成。
  • 无需单独身份验证即可为大量用户提供服务的面向公众的应用程序。

架构

客户端凭据应用程序使用客户端 ID 和客户端密钥进行身份验证。随后，它们将获得与服务用户绑定的访问令牌，并使用该令牌通过该服务用户的权限向 Foundry 发起 API 调用。

External application → OAuth Client Credentials → Service user → Foundry APIs

先决条件

在设置客户端凭据应用程序之前，请确保您具备以下条件：

  • 在 Control Panel 中对您的组织拥有的第三方应用程序管理权限。
  • 用于应用程序的外部托管环境。

设置

步骤 1：为客户端凭据设置 Developer Console 应用程序

OAuth 客户端现在作为 Developer Console 应用程序创建。请按照 创建新的 Developer Console 应用程序 以完成创建向导的操作，然后为客户端凭据设置选择以下选项：

  1. 在 应用类型 页面上，选择 后端服务。
  2. 在 权限 页面上，选择 应用权限。正是此选择使应用程序使用 Client credentials grant 工作流并生成其服务用户。
  3. 请记下客户端 ID，并在应用程序创建时复制客户端密钥。这是唯一一次可以看到该密钥的机会。
  4. 应用程序创建完成后，将其设置为 不受限制 ，该选项位于 OAuth 与限制 页面，前提是应用程序需要访问预定义项目集和操作集之外的内容。此设置在创建过程中不可用；请参阅 配置应用程序限制。

第 2 步：了解服务用户的影响

对于客户端凭据应用程序，Foundry 会创建一个 服务用户 ，该用户代表您的应用程序执行操作。这带来了以下优势：

  • 无需用户登录： 由于您的应用程序显示的信息并非限定于单个用户的范围，因此所有操作均由服务用户处理。
  • 服务用户权限： 默认情况下，服务账户无权访问任何资源。Foundry 管理员必须为该服务用户账户分配所需的角色和权限，客户端才能在 Foundry 中执行操作。
  • 授权责任： 您必须在应用程序中实现授权逻辑，因为用户无法单独登录。您的应用程序将收到一个用于所有操作的令牌。
  • 权限管理： 授予服务用户对您的应用程序所需的特定项目、对象类型和数据集的访问权限。

步骤 3：配置服务用户权限

创建应用程序后，为服务用户配置以下权限：

  • 项目访问权限： 授予服务用户对包含所需资源的项目的访问权限。
  • 本体论类型访问权限： 授予对所需本体论类型的访问权限。确保服务用户可以提交操作。
  • 数据集访问权限： 授予对所需数据集的访问权限。
  • 角色分配： 分配可提供必要 API 操作的适当角色。

步骤 4：OSDK 应用程序实现

对于 TypeScript 应用程序，请使用 OSDK 为您的应用程序生成自定义 SDK 库。请参阅 引导服务器端 TypeScript 应用程序 指南以了解更多信息。

OSDK 引导过程包括以下步骤：

  1. 创建 OSDK 包： 使用 Developer Console 生成 OSDK 包。
  2. 将本体论资源添加到 SDK： 将您的应用程序需要访问的实体添加到 OSDK 资源中。
  3. 安装 OSDK： 在您的应用程序中安装生成的 OSDK 包。
  4. 配置身份验证： 使用 OSDK 身份验证客户端配合您的 OAuth 客户端凭据来访问 Foundry。
  5. 查询数据： 使用 OSDK 客户端以服务用户的权限查询本体论数据。

与直接调用 REST API 相比，OSDK 客户端提供类型安全、自动序列化以及简化的 API 交互。

步骤 5：验证应用访问权限

  1. 验证身份验证： 确保您的应用能够成功获取访问令牌。
  2. 测试 API 调用： 确认您的应用可以访问所需的 Foundry 资源。

使用客户端凭据授权时，请务必妥善保管 OAuth2 客户端密钥。切勿将密钥存储在公开的代码仓库中，或存储在应用程序内可公开访问的代码中。

如果密钥泄露，请立即轮换密钥。

故障排除

身份验证问题

  • 客户端凭据无效： 验证客户端 ID 和密钥是否正确。如有必要，请重新生成密钥以确认其正确性。
  • 范围错误： 确保所请求的范围已授予 OSDK 客户端应用。
  • 网络连接： 检查防火墙和网络策略，确保您的请求能够到达 Foundry。

权限错误

  • 403 Forbidden： 在 Developer Console 中查看应用权限。403 错误表示用户没有查看该应用的权限。
  • 资源未找到： 如果用户无法访问您期望其看到的资源，请验证应用程序服务用户是否有权访问这些资源，以及这些资源是否已添加到应用程序的本体论资源中。

您现在拥有了一个可正常运行的客户端凭证应用程序，本体论的强大功能触手可及。您的外部应用程序可以通过服务用户的权限安全地访问 Foundry 数据和功能，使您能够构建可扩展的面向消费者的应用程序，并实现稳健的后端集成。
