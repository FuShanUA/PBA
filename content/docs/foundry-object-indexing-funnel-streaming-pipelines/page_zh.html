流式对象类型的当前产品限制

对象存储 v2 中的流式处理采用“最新更新优先”策略，即每个流都被视为变更日志流。如果您的事件从源端乱序到达，则本体论中的数据将不正确。如果您可以保证输入流中的顺序，对象存储 v2 的流式处理将以相同的顺序处理您的更新。

本体论流式行为及其功能集仍在积极开发中；以下是在使用本体论流式处理之前需要考虑的一些当前产品限制：

  • 流式对象类型不支持用户编辑。作为一种变通方法，您可以将用户编辑作为数据变更推送到输入流中，或者配置一个使用非流式输入数据源的附加对象类型，让用户在该辅助对象类型上进行编辑。或者，您可以通过将对象切换为由以下内容支撑，来启用对流支撑对象类型的编辑： 直接数据源.
  • 多数据源对象类型（MDO） 在流式对象类型上不受支持。
  • 除 来运行该专业代码代理。你还可以通过之外，没有其他 Foundry 前端应用程序支持实时数据刷新，因为从历史上看，它们并不期望接收流式更新。尽管流式对象类型的底层本体论数据在不断变化，但在 Workshop 之外，您需要在需要新数据时手动刷新。
  • 在监听器设置向导的 数据源 选项卡中，用户可以配置 监控器 ，用于监控 Funnel 批量管道故障和无效记录。目前，不支持为使用流数据源的对象类型提供监控器或指标（例如，管道延迟）。
  • 记录大小不能超过 1MB，且对象类型不能包含超过 250 个属性。如果您需要将更大的记录流式传输到本体论中，应考虑采用对象类型更小的其他本体论模型。

配置流式对象类型

使用流输入数据源的对象类型可直接在 如果希望用户在每次运行预览前手动确认，请开启 或 本体论管理器中进行配置，与任何其他 Foundry 本体论对象类型类似。

流数据源还可以配置用于 多对多关联类型.

如果您尚未配置输入流，可以通过 在 Data Connection 应用程序中与现有流集成 或通过 在 Pipeline Builder 中构建流管道来创建一个。 :::

创建新对象类型（或使用现有对象类型）后，导航到 数据源 选项卡，在 Ontology Manager 中的 支撑数据源 部分中选择一个流输入数据源（如下所示），并将您的更改保存到 Foundry 本体论中。

如需对输入数据源流进行其他配置，请选择省略号按钮以查看更多选项（如下所示）。

直方图 流配置 部分提供了用于优化对象类型流式作业的选项。

  • 流计算配置文件： 默认情况下，对象类型的流式作业使用适用于大多数输入流的计算配置文件。但是，由超高吞吐量流支撑的对象类型可能需要更多资源，以防止管道滞后。或者，由低吞吐量流支撑的对象类型可以使用较小的配置文件，以节省计算资源成本。如果没有合适的可用选项，请联系您的 Palantir 代表。
  • 流一致性保证： 默认情况下，对象类型的流式处理作业使用 exactly-once 一致性保证，与 at-least-once 相比会产生额外的延迟，但可确保 Foundry 应用程序恰好接收一次对象集更新。启用 at-least-once 一致性保证可以降低延迟；但在极少数情况下，当对象集发生更改时，Foundry 应用程序可能会收到重复的更新。例如，基于对象集的自动化操作可能会被触发多次。对于延迟敏感的对象类型，请考虑启用 at-least-once。

修改对象类型的流配置将重启其关联的流式处理作业，导致新流式记录的处理出现短暂延迟。

调试流式管道

流与本体论之间的接口在概念上可以被视为类似于 变更日志数据集输入流中的每条记录都包含要写入本体论的每个属性的数据。每条记录将更新给定对象的所有属性，由主键指定。可以通过在输入流上设置元数据，在输入记录上指定删除操作。

Funnel 将按照记录写入数据源流的顺序对其进行索引，因此这些流应按主键分区，并按事件时间戳排序，这可以在上游 如果希望用户在每次运行预览前手动确认，请开启 管道中完成。
