警报工作流

无论是检测欺诈还是 挖掘收入机会，告警工作流都会自动向最终用户呈现需要审查的问题，用户只需点击按钮即可做出决策。这些工作流使团队能够将注意力集中在解决当前最紧迫的问题上，而不是花费时间手动拼凑数据。

Foundry 的 数据连接 和 本体论 使组织能够在几天而非几个月内实现这一模式，并安全高效地持续实施、定制和维护它。

解决方案

告警工作流旨在自动向用户呈现告警（更新、问题、机会等）以供审查和决策。通常，用户会看到按优先级排序的告警以及与告警相关的数据，并通过审查这些数据来做出决策。他们的决策通过按钮记录下来，并将决策（回写）写入 Foundry 数据，有时（在合适的情况下）还会写入生产系统。

以欺诈检测为例，用户可能会收到一份按欺诈可能性从高到低排序的告警列表以供审查。点击某个告警会显示所有支撑信息，用户可以基于这些信息使用一个简单的按钮来指示其是否为欺诈。

告警框架非常适合那些花费大量时间筛选各种数据源并手动拼凑数据点以识别问题的用户，其最终目标是针对发现的问题做出决策。有时，最终用户会使用基本的 SQL 查询来呈现其中一部分问题；或者由于工作过于复杂，用户根本不进行数据筛选。

告警可用于从检测欺诈到 挖掘收入机会的各种用例。这些告警可以通过数据管道、机器学习模型、Foundry Rules 或它们的任意组合来生成。

本体论

以下是本体论相关概念的列表，这些概念与告警工作流的设置相关。

对象

告警工作流通常包括一个作为触发器的对象类型（例如客户、金融交易、制造流程或服务类型），以及一个与之关联的特定告警对象（例如潜在欺诈告警、与服务类型相关的收入机会，或与制造流程相关的流程优化机会）。

相关产品：

  • 本体论
  • 对象浏览器

操作

操作是此工作流的核心，因为它们记录了最终用户的决策。从用户的角度来看，这些是他们点击的按钮。在后端，这些按钮由 本体论 配置用于记录用户所做决策的操作。典型的操作字段包括：

  • 用户 ID
  • 决策时间戳
  • 做出决策所针对的告警对象
  • 决策本身（True/False、Accept/Reject 等）
  • （可选）决策的说明（有助于在追踪器中进行审查）

在欺诈检测中，操作将记录案件是否被判定为欺诈、做出决策的用户、决策的时间、做出该决策的原因（说明）以及所审查的具体案件 ID。

相关产品：

  • Foundry 操作

回写

回写是 Foundry 中用于记录决策的术语。相关文档可在回写页面找到。本质上，告警对象支撑数据集的副本是通过 本体论 应用程序创建的。操作将在复制的（回写）数据集中记录操作部分中定义的字段。在欺诈检测中，针对特定案件采取的操作将更新本体论和相关数据集，以反映所做出的决策（例如设置告警是否识别出欺诈以及调查结果的说明）。

除了回写到 Foundry 之外，通常还需要回写到生产系统，例如 SAP、Oracle 等。这通常涉及建立与生产系统的直接连接（具有读写权限），并通过该连接回传回写数据集的结果。请与您的 Palantir 团队联系以了解更多详情。

数据管道

有时，创建告警的逻辑可能非常具体，并涉及复杂的规则，这些规则最适合在数据管道中通过编码实现。

例如，保险公司必须根据与医疗服务提供方的合同费率支付理赔款，这些费率在他们的系统中体现为一组代码。当合同重新谈判时，应为新的时间段记录一组新的代码。在这种情况下，最好将确定何时应应用哪些代码的所有逻辑进行编码，并在 Foundry 中创建一个提案对象，建议使用重新谈判合同中的新代码集来拆分时间段。

要求

无论使用哪种模式，底层数据基础都是由管道以及与外部源系统的同步构建而成的。

数据集成管道

数据集成管道以多种语言编写，包括 SQL、Python 和 Java，用于将数据源集成到主题本体论中。

数据连接器

Foundry 可以 从多种来源同步数据，包括 FTP、JDBC、REST API 和 S3。从各种来源同步数据并尽可能编译最完整的真实数据源，是实现最高价值决策的关键。
