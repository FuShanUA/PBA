迁移说明：将 foundry_ml [计划弃用] 迁移至 palantir_models

本页面提供了将使用 foundry_ml 构建的模型迁移至 palantir_models 框架的最佳实践和说明。首先，我们会分享一些需要考虑的指导，然后再提供一个 示例 迁移。在示例中，我们提供了在代码仓库中使用 foundry_ml构建模型的代码，并演示如何使用 palantir_models重写此代码。

最佳实践

在以下部分中，我们列出了有关如何执行迁移以及需要考虑哪些事项的指南。

迁移方法

您可以通过以下方式构建迁移后的模型：

  • 在新的代码仓库或 Jupyter® 代码工作区中构建模型，或者；
  • 通过编辑现有的代码仓库来构建模型。

两种方法各有优势，哪种方法最佳取决于您的具体情况，但有几点需要注意：

  • 如果初始模型是在 Code Workbooks 中构建的，您将需要在新的代码仓库或 Jupyter® 代码工作区中构建它，因为后两种产品支持 palantir_models。
  • 通常情况下，在构建模型时所用的代码仓库或代码工作区中使用该模型进行推理更为容易，因为将模型导入到另一个仓库或工作区需要导入其 Python 依赖项，并可能导致环境冲突。

要了解如何使用新的代码仓库来构建模型，请查看 以下示例。

如何就地迁移建模仓库

要保留现有的建模仓库并将其从 foundry_ml 迁移到 palantir_models 就绪后，请按照以下步骤操作：

  1. 请注释掉或删除任何引用 foundry_ml的代码。
  2. 请将 foundry_ml 库从 Libraries 侧边栏中移除。
  3. 请将仓库升级到最新配置。
  4. 要将 Python 升级到 3.10 或更高的主版本，请选择 推荐 （位于 运行方式 和 构建方式 菜单中），或者直接编辑 conda_recipe/meta.yaml 文件，并将现有的 Python 依赖项更新为 python >=3.11.* （或 3.10.*，如有需要）在 build 和 run 两个块中。请注意，Python 3.9 将 于 2025 年 10 月被弃用 ，这是专门的迁移活动的一部分。
  5. 请安装推荐的 palantir_models 版本，可从 Libraries 侧边栏。请勿通过直接编辑 meta.yaml 的方式完成此操作，因为这样不会导入所需的支撑仓库。

如果使用现有的 Pipeline 类型的仓库，而非 Model training 或 Model adapter library 来创建您的模型适配器，您将无法享受最新的建模功能，除非您 升级您的仓库。必须执行此升级操作，您的模型才能支持 直接部署.

迁移使用 foundry_ml 在 Code Repositories 中构建的模型

以下是从 foundry_ml 到 palantir_models 在 Code Repositories 中的迁移示例。

以下代码片段演示了一个 scikit-learn 线性回归模型，编写该模型是为了使用 foundry_ml，我们将迁移到 palantir_models：

Copied!
1from transforms.api import transform, Input, Output
2from foundry_ml import Model, Stage
3from sklearn.linear_model import LinearRegression
4from sklearn.pipeline import Pipeline
5from sklearn.preprocessing import StandardScaler
6
7
8@transform(
9    training_data_input=Input("<YOUR_PROJECT_PATH>/data/housing_train_data"),
10    model_output=Output("<YOUR_PROJECT_PATH>/models/linear_regression_foundry_ml"),
11)
12def create_model(training_data_input, model_output):
13    training_df = training_data_input.pandas()
14    numeric_features = ['median_income', 'housing_median_age', 'total_rooms']
15
16    pipeline = Pipeline([
17    ("scaler", StandardScaler()),
18    ("regressor", LinearRegression())])
19
20    X_train = training_df[numeric_features]
21    y_train = training_df['median_house_value']
22
23    pipeline.fit(X_train, y_train)
24
25    model = Model(Stage(pipeline["scaler"], output_column_name="features"),
26            Stage(pipeline["regressor"]))
27
28    model.save(model_output)

要将上述代码从 foundry_ml 迁移到 palantir_models，请按照以下列出的步骤操作。

第 2 步：编写模型适配器

模型适配器 为 Foundry 中的所有模型提供标准接口。该标准接口确保所有模型均可立即用于生产应用。Palantir 平台将负责相关基础设施，以加载模型及其 Python 依赖项、与模型进行交互并公开其 API。

为此，您必须创建一个 ModelAdapter 类的实例，以充当此通信层。

需要实现三个函数：

  1. 模型保存和加载： 为了复用您的模型，您需要定义模型的保存和加载方式。Palantir 提供了多种 默认方法 来执行序列化（保存），而在更复杂的情况下，您可以 实现自定义序列化 逻辑。
  2. API： 定义模型的 API，并告知 Palantir 平台您的模型需要何种类型的输入数据。
  3. 预测： 由 Palantir 平台调用，用于向您的模型提供数据。您可以在此处将输入数据传递给模型并生成推断（预测）。

打开 model_adapters/adapter.py 文件并编写模型适配器：

Copied!
1import palantir_models as pm
2from palantir_models.serializers import DillSerializer
3
4
5class SklearnRegressionAdapter(pm.ModelAdapter):
6
7    @pm.auto_serialize(
8        model=DillSerializer()
9    )
10    def __init__(self, model):
11        self.model = model
12
13    @classmethod
14    def api(cls):
15        columns = [
16            ('median_income', float),
17            ('housing_median_age', float),
18            ('total_rooms', float)
19        ]
20        return {'df_in': pm.Pandas(columns=columns)}, \
21                {'df_out': pm.Pandas(columns=columns + [('prediction', float)])}
22
23    def predict(self, df_in):
24        df_in['prediction'] = self.model.predict(df_in[['median_income', 'housing_median_age', 'total_rooms']])
25        return df_in

有关模型适配器逻辑的更多信息，请参阅 编写模型适配器。

步骤 3：编写模型训练逻辑

在下面的示例中， train_model 函数包含未更改的训练逻辑示例，该示例来自 foundry_ml。该 compute 函数使用模型适配器封装模型，并发布该模型。

1from transforms.api import transform, Input, lightweight
2from palantir_models.transforms import ModelOutput
3from main.model_adapters.adapter import SklearnRegressionAdapter
4from sklearn.linear_model import LinearRegression
5from sklearn.pipeline import Pipeline
6from sklearn.preprocessing import StandardScaler
7
8def train_model(training_df):
9    """Training logic is unchanged from the original foundry_ml example."""
10
11    numeric_features = ['median_income', 'housing_median_age', 'total_rooms']
12
13
14    pipeline = Pipeline([
15        ("scaler", StandardScaler()),
16        ("regressor", LinearRegression())]
17    )
18
19    X_train = training_df[numeric_features]
20    y_train = training_df['median_house_value']
21
22    pipeline.fit(X_train, y_train)
23    return pipeline
24
25
26# Use the lightweight decorator unless your model natively supports Spark inputs
27# (i.e. uses Spark ML). Without it, the input data will first be loaded in Spark
28# and will require conversion to Pandas for use in the model, which is a slow and
29# memory-intensive operation.
30
31# Lightweight requires the foundry-transforms-lib-python package
32# and for the repository to be up-to-date.
33# https://palantir.com/docs/foundry/code-repositories/repository-upgrades
34@lightweight()
35@transform(
36    training_data_input=Input("<YOUR_PROJECT_PATH>/data/housing_train_data"),
37    model_output=ModelOutput("<YOUR_PROJECT_PATH>/models/linear_regression_model"),
38)
39def compute(training_data_input, model_output):
40    training_df = training_data_input.pandas()
41
42   # train model
43    model = train_model(training_df)
44
45   # wrap model with model adapter
46    foundry_model = SklearnRegressionAdapter(model)
47
48   # publish the model
49    model_output.publish(model_adapter=foundry_model)

步骤 4：编写模型推理逻辑

打开 model_training/run_inference.py 文件（位于您的仓库中），并编写模型推理逻辑。更新路径以正确指向模型和测试数据集。选择 Build （位于右上角）以运行代码。

要在未定义该模型的转换仓库中运行模型，请设置 use_sidecar = True 于 ModelInput。这将自动导入模型适配器及其依赖项，并在单独的环境中运行它们，以防止依赖冲突。 use_sidecar 在轻量级转换中不可用。请查阅 该 ModelInput 类参考 以获取更多详细信息。

如果 use_sidecar 未设置为 True，则必须将模型适配器及其依赖项导入到当前代码仓库中或在其中定义。

Copied!
1from transforms.api import transform, Input, Output, lightweight
2from palantir_models.transforms import ModelInput
3
4
5# Lightweight requires the foundry-transforms-lib-python package
6# and for the repository to be up-to-date.
7# https://palantir.com/docs/foundry/code-repositories/repository-upgrades
8@lightweight()
9@transform(
10    testing_data_input=Input("<YOUR_PROJECT_PATH>/data/housing_test_data"),
11    model_input=ModelInput("<YOUR_PROJECT_PATH>/models/linear_regression_model_asset"),
12    predictions_output=Output("<YOUR_PROJECT_PATH>/data/housing_testing_data_inferences")
13)
14def compute(testing_data_input, model_input, predictions_output):
15    inference_outputs = model_input.transform(testing_data_input)
16    predictions_output.write_pandas(inference_outputs.df_out)

按照上述步骤操作，即可完成将 foundry_ml Code Repositories 中的现有模型迁移到 palantir_models。

迁移使用 MetricSets 的模型

我们建议将 MetricSets 替换为 experiments 在可能的情况下。但是，虽然实验现已支持 图像 指标，但请注意，它们尚不支持 图表 指标，这一点与 MetricSets 不同。虽然对于使用 palantir_models构建的模型，MetricSets 不会显示在模型页面上，但仍然可以 针对模型编写 MetricSets 并在以下位置查看指标： 建模目标。

为此，请在代码仓库中编写模型，并将 foundry_ml_metrics 库添加到您的环境中。下面举例说明如何结合使用 MetricSet 和 palantir_models：

Copied!
1import uuid
2from transforms.api import transform, Input, Output
3from palantir_models.transforms import ModelInput
4
5from foundry_ml_metrics import MetricSet # add foundry_ml_metrics to your environment
6
7@transform(
8    evaluation_data_input=Input("path_to_input"),
9    model_input=ModelInput("path_to_model"),
10    metric_set_output=Output("path_to_output"),
11)
12def compute(training_data_input, model_input, metric_set_output):
13    metric_set = MetricSet(
14        # Pass the "hash" part of the model version identifier, for example, given
15        # ri.models.main.model-version.6c0f17a8-ad73-46a4-b86e-8d0a13327ef2,
16        # only pass 6c0f17a8-ad73-46a4-b86e-8d0a13327ef2.
17        model=uuid.UUID(
18            # The model_version_rid property is only available on the ModelInput class
19            # for versions of palantir_models greater or equal to 0.1602.0.
20            model_input.model_version_rid.replace("ri.models.main.model-version.", "")
21        ),
22        input_data=evaluation_data_input
23    )
24    metric_set.add(name='Accuracy', value=0.8)
25    metric_set.add(name='F1', value=0.95)
26    metric_set.save(metric_set_output)

接下来，将 evaluation_data_input 数据集配置为建模目标的评估配置中的评估数据集。随后，这些指标将显示在建模目标的评估视图中该数据集的下方。
