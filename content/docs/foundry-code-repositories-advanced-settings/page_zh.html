高级仓库设置

大多数 Code Repositories 设置可以在 设置 标签页中找到。一些其他值使用 repoSettings.json 文件在仓库根目录下进行配置。如果该文件不存在，你可以创建一个名为 repoSettings.json 的文件放在仓库根目录下。

自定义标签名称验证

为了强制仓库中所有新创建的标签在 Code Repositories 默认约束之外遵循特定的命名方案，你可以配置一个自定义正则表达式，以及当正则表达式不满足时向用户显示的错误消息。例如：

"tagNameValidation": {
    "regex": "^(0|[1-9]\\d*)\\.(0|[1-9]\\d*)\\.(0|[1-9]\\d*)(-rc\\d+)?$",
    "errorMessage": "Tag name must have the format x.x.x or x.x.x-rcx"
}

如果你为 tagNameValidation设置了值，你必须配置 同时 a regex 以及一个 errorMessage.

拉取请求描述模板

为了在打开新的拉取请求时帮助保持最佳实践，你可以配置一个描述模板，用于预填充创建拉取请求时的 Description 字段：

Copied!
1
"prDescriptionTemplate": "First line of the description template\nAnd another line with instructions"

新转换的输出数据集路径

默认情况下，新转换文件的模板使用文件路径作为初始输出数据集路径。例如，对于 Python 转换 /path/to/your/repository/transforms-python/src/myproject/datasets/name_of_file。你可以通过配置一个 outputPathPrefix:

Copied!
1
"outputPathPrefix": "/My/Custom/Prefix"

将其更改为更方便的位置，例如项目中的特定文件夹。使用上述设置后，输出数据集路径将被设置为 /My/Custom/Prefix/name_of_file 来替代。

拉取请求验证规则

你可以通过添加 prValidation 条目到你的 repoSettings.json 文件来为仓库中的拉取请求强制执行规则。创建拉取请求时，将根据基础分支上的 repoSettings.json 文件对其进行验证。

拉取请求验证规则由一个正则表达式、一个要与该表达式匹配的拉取请求字段列表，以及当字段不符合规则时要呈现的错误消息组成。
