TypeScript 本体论 SDK 2.0 正式发布，现已全面可用

发布日期：2024-10-29

TypeScript 本体论 SDK（OSDK）2.0 将于 10 月 28 日当周正式全面可用，提供精简的语法以提升性能、支持更复杂的应用程序，并加快开发流程。默认情况下，在 自定义小部件 中新建的任何 TypeScript 应用程序都将使用最新的 2.0.x 生成器。

将现有应用程序迁移到 TypeScript 2.0

直方图 TypeScript OSDK 2.0 迁移指南 介绍了版本差异，重点说明了相关的语法和结构变化，并提供代码示例，帮助您更新使用旧版本构建的应用程序。

Palantir 将在 2.0 版本发布后至少一年内继续为旧版 TypeScript 应用程序提供支持。

使用 AIP Assist Agents [Beta] 创建自定义 LLM 驱动的助手

发布日期：2024-10-10

我们很高兴地宣布名为“AIP Assist Agents”的自定义 LLM 驱动助手的测试版发布。此功能允许用户创建仅专注于自定义内容源的 LLM 驱动助手，无需任何编程经验。这建立在向 AIP Assist 注册自定义内容源的能力之上，该能力允许用户将 Notepad 文档或平台内自定义文档添加到 AIP Assist 的知识库中。

由自定义源支持的 AIP Assist Agents

需要注意的是，此功能与现有的 AIP Assist 对自定义内容源的支持有何不同。通过 AIP Assist 提供自定义源，可以在 AIP Assist 回答用户查询时将内容作为资源提供，同时提供的还有 Palantir 平台和开发者文档。在没有 AIP Assist Agents 的情况下，可以将自定义源配置为在 AIP Assist 的默认模式下可用。

AIP Assist 模式选择器。

相比之下，必须先从 AIP Assist 模式选择器中选择 AIP Assist Agents（如下所示），并且仅使用所提供的自定义源来回答用户的问题。因此，AIP Assist Agents 是高度专注且专门构建的，能够仅基于专业化的内容源为用户提供更高质量的响应。对于支持团队、开发者团队和平台管理员来说，这是一项强大的新功能。

AIP Assist 模式选择器，显示了一个示例库存管理 AIP Assist Agent。

只需点击几下即可创建自定义 LLM 驱动的助手

要开始使用 AIP Assist Agents，您必须先从 Notepad 或平台内自定义文档中注册自定义内容源。完成此操作后，您可以在 AIP Assist Agent 在 Agent Studio 应用程序中创建，并授予其访问您的自定义内容源的权限。

在 Agent Studio 应用程序中创建 AIP Assist Agent。

创建 AIP Assist Agent 并授予其访问自定义内容源的权限后，您就可以开始在 AIP Assist 中与其进行交互。创建专业化的 LLM 驱动助手现在是一个精简的无代码流程，您可以利用它来满足您的运营需求，并为您的用户提供更多的应用程序支持。

请注意，这些功能是 Palantir AIP 产品的一部分，并且要求您的注册具有 在控制面板中启用 AIP。AIP Assist Agents 和 Agent Studio 目前可能并非在所有注册中都可用。请联系您的 Palantir 代表以确定您的注册是否符合条件。

Code Workspaces 中的模型输入功能介绍

在 Jupyter® 笔记本中下载模型

使用 AIP Agent Studio 构建交互式助手 [Beta]

发布日期：2024-10-01

注意： 自 2026 年 4 月 27 日当周起，AIP Agent Studio 已更名为 AIP Chatbot Studio。所有现有功能和特性保持不变。

AIP Agent Studio 是一款全新的无代码工具，使用户能够构建和部署交互式助手（称为 AIP Agents），这些助手配备了企业特定的信息和工具。AIP Agent Studio 提供自然语言界面，通过 AIP Agents 利用本体论、文档和 LLM，这些助手可以获取和更新参数（例如本体论对象或文本字符串）。

目前作为 Beta 版本提供，请联系您的 Palantir 代表以在您的注册中安装。

一个由 LLM 驱动的 AIP Agent，它使用参数获取经过筛选的本体论对象集（包含客户支持对话记录），作为回答用户有关当前产品问题时的上下文。

上述 AIP Agent 可以部署在 Workshop 应用中，并将代理参数链接到变量。

专为交互式协助和轻松集成而设计的多功能代理

AIP Agent Studio 提供多项引人注目的功能：

  • 可自定义的代理： 根据您的企业需求，创建和配置具有特定提示、参数和工具的 AIP Agents。
  • 交互式协助： 部署能够以对话方式与用户交互、提供洞察并执行任务的代理。
  • 无缝集成： 利用本体论、文档、自定义内容源和 LLM 构建功能强大的代理，这些代理可以部署在 Workshop、 AIP Threads日 AIP Assist.
  • 安全性： 构建于 同样严格的安全模型 之上，该模型与 Palantir 平台的其余部分一致，确保数据完整性和访问控制。

一个配备本体论语义搜索工具和对象查询工具的 AIP Agent，可从供应链通信中查找相关信息，并将其与特定订单关联起来。

什么时候应该使用 AIP Agent Studio？

我们建议在以下场景使用 AIP Agent Studio：

  • 分组文档检索增强生成（RAG）Agent： 非常适合分析大量文档或非结构化数据。无论是处理采购文档、环境影响评估、保险理赔还是交接班日志，AIP Agent 都能提供具备上下文感知能力的回答和洞察。
  • 本体论上下文过滤： 适用于需要根据应用上下文进行额外过滤的任务。例如，在起草或头脑风暴场景中，可以使用 Agent 来遵循不同利益相关方发布的特定风格指南。这样可以实现一致且个性化的文档生成，例如创建符合特定上级偏好的简报。
  • 自定义文档协助： By 与 AIP Assist 集成，AIP Agent 可以专门基于自定义内容源来回答查询，这对支持团队、开发团队和平台管理员来说极具价值。此功能将 AIP Agent 的能力扩展到了自定义文档。
  • 常规提示与模板化： 非常适合需要常规起草或模板化的场景，例如编码协助或生成领域特定语言（DSL）规则。使用特定指南或模板对 Agent 进行预提示，可以显著提升性能和一致性。

AIP Agent Studio 不适合需要重复性、定义明确的流程的任务。对于此类用例，AIP Logic 或 AIP Automate 等其他工具可能更为合适。

使用派生序列存储时间序列逻辑，现已正式发布 [GA]

发布日期：2024-10-01

我们很高兴地宣布正式发布 派生时间序列，将于 10 月 7 日当周在所有租户上可用。

在此功能发布之前，在 Quiver 中执行的时间序列分析结果无法用于涉及其他 Foundry 应用程序的工作流。现在，您可以从原始传感器数据派生新序列并将其保存回本体论，从而在所有支持本体论的应用程序中使用该派生序列。一旦进入本体论，派生序列的行为与原始时间序列相同，但会实时计算。这消除了在整个平台中管理或存储派生数据或重复这些计算的需要。

关于如何对原始数据执行操作以生成派生序列的通用概述。

派生序列有哪些新功能？

在先前测试版的派生序列中，您需要通过 Pipeline Builder 或 Code Repositories 手动将派生时间序列保存到本体论中。现在，您可以使用 保存派生序列 设置便捷地自动保存到本体论，该设置位于任意 派生序列选项 部分中的任意 受支持的时间序列卡片 （在 Quiver 中）。

直方图 保存派生序列 选项（位于 Quiver 卡片中），以及在配置选项中自动保存到本体论的设置。

我们还更新了派生序列管理体验，推出了功能丰富的时间序列逻辑编辑器，如下所示：

用于 Delta 压力派生序列的更新版时间序列逻辑编辑器。

最后，我们现在提供用于管理已保存到本体论中的派生序列的工具：

用于配置自动将本体论保存到传感器对象类型的新本体论选项卡。

为什么要使用派生序列？

在派生序列出现之前，平台中缺乏用于创建和管理派生序列的用户友好工具。此外，如果不将转换后的数据物化并手动将新序列添加到本体论中，就无法在不同 Palantir 应用程序之间直观地使用转换后的时间序列。

现在，用户可以在 Quiver 中派生新序列，并将其保存到本体论中，供 Foundry 中的运营和分析应用程序使用。用户还可以在专用工具中管理派生序列的逻辑和本体论保存，并且仅在用户请求派生序列时才执行计算。

示例用例

派生序列的一个当前用例聚焦于污水处理厂的过程优化，利用数据科学来优化能源和化学品消耗。通过将派生序列作为机器学习模型的特征，我们可以简化这些模型的部署，使其利用实时流式传输的时间序列数据，为大规模的安全水厂运营决策提供依据。
