TypeScript 本体论 SDK 2.0 现已正式发布

发布日期：2024-10-29

TypeScript 本体论 SDK（OSDK）2.0 于 10 月 28 日当周正式发布，提供精简的语法，可提升性能、支持更复杂的应用，并加快开发流程。默认情况下，在 Developer Console 中创建的任何新 TypeScript 应用现在都将使用最新的 2.0.x 生成器。

将现有应用迁移到 TypeScript 2.0

该 TypeScript OSDK 2.0 迁移指南 介绍了版本差异，重点说明了相关的语法和结构变化，并提供了代码示例，帮助您更新使用旧版本构建的应用。

虽然目前并不强制要求将旧版应用迁移到 2.0 版语法，但即将推出的 TypeScript OSDK 2.0 版本（包括对 接口 和 媒体集的支持）将要求进行迁移。

Palantir 将自 2.0 版本发布起至少一年内为旧版 TypeScript 应用提供支持。

要为现有应用程序生成 TypeScript OSDK 2.0，请选择 SDK 版本 菜单，该菜单位于 Developer Console 中您的应用程序的左侧面板。

在 Developer Console 中为现有旧版本应用程序生成 TypeScript OSDK 2.0。

获取支持

该 本体论 SDK 开发者社区 ↗ 为 Foundry 用户提供了一个论坛，供其提出和解答有关本体论 SDK 功能套件的问题。如果您在社区论坛或迁移指南中找不到问题答案，请联系 Palantir 支持团队以获取更多帮助。

使用 AIP Assist Agents [Beta] 创建自定义 LLM 驱动的助手

发布日期：2024-10-10

我们很高兴地宣布，名为“AIP Assist Agents”的自定义 LLM 驱动助手现已推出测试版。此功能允许用户创建仅专注于自定义内容源的 LLM 驱动助手，无需任何编程经验。此功能建立在向 AIP Assist 注册自定义内容源的能力之上，允许用户将 Notepad 文档或平台内自定义文档添加到 AIP Assist 的知识库中。

由自定义内容源支持的 AIP Assist Agents

需要注意的是，此功能与 AIP Assist 现有的自定义内容源支持有何不同。将自定义内容源接入 AIP Assist 后，AIP Assist 在回答用户查询时便可以将这些内容与 Palantir 平台文档和开发者文档一起作为资源使用。在不使用 AIP Assist Agents 的情况下，可以将自定义内容源配置为在 AIP Assist 的默认模式下可用。

AIP Assist 模式选择器。

相比之下，必须先从 AIP Assist 模式选择器中选择 AIP Assist Agents（如下所示），且它们仅使用所提供的自定义内容源来回答用户的问题。因此，AIP Assist Agents 高度聚焦且专为特定用途打造，仅基于专门的内容源为用户提供更高质量的回复。对于支持团队、开发团队和平台管理员而言，这是一项强大的新功能。

AIP Assist 模式选择器，其中显示了一个库存管理 AIP Assist Agent 示例。

只需点击几下即可创建由 LLM 驱动的自定义助手

要开始使用 AIP Assist Agents，您必须先注册来自 Notepad 或平台内自定义文档的自定义内容源。完成此操作后，您可以创建一个 AIP Assist Agent ，并在 Agent Studio 应用程序中为其授予对自定义内容源的访问权限。

在 Agent Studio 应用程序中创建 AIP Assist Agent。

创建 AIP Assist Agent 并为其提供对自定义内容源的访问权限后，您就可以开始在 AIP Assist 中与它进行交互。现在，创建由 LLM 驱动的专用助手已成为一个精简的无代码流程，您可以利用该流程来满足您的运营需求，并为您的用户提供更多应用支持。

请注意，这些功能是 Palantir AIP 产品的一部分，并且要求您的租户已 在 Control Panel 中启用 AIP。AIP Assist Agents 和 Agent Studio 目前可能并非在所有租户中都可用。请联系您的 Palantir 代表，以确定您的租户是否符合使用资格。

详细了解 AIP Assist 自定义源 和 AIP Assist Agents。

Quiver 中 AIP 的访问和易用性改进 [Beta]

发布日期：2024-10-10

此功能现已正式发布。 阅读最新公告。

自 2023 年 7 月，用户已经能够在 Quiver 中借助 AIP 的强大功能，通过自然语言提示让 AIP 在其画布上生成新卡片或配置现有卡片，从而轻松探索数据。Quiver 的两项主要大语言模型驱动功能将于10月7日当周在大多数启用 AIP 的租户中以测试版形式推出—— AIP Generate 和 AIP Configure ——除了此前已在 Quiver 工作区顶部功能区以及选定卡片中可用之外，现在还可以在卡片下方使用。

AIP Generate 根据用户提示创建分析，对本体论中可用的数据提供快速洞察。除了 Object Explorer 和 Contour原生具备的功能之外，它还提供了另一种对象集分析方法。AIP Configure 应用用户提示来更新卡片配置，并将分析输出定制为符合用户需求，无论用户对 Quiver 可视化设置的熟悉程度如何。

在卡片搜索栏中，能够利用 AIP 的 Quiver 卡片现在会在其右侧显示 AIP 徽标。

由 AIP 分析功能支撑的 Quiver 卡片会在其右侧显示 AIP 徽标。

从 Quiver 卡片访问 AIP Generate

在 Quiver 中选择要分析的对象集后，您将看到一个输入框 with an AIP logo 位于卡片选择下方，提示您 Enter a query to continue the exploration。当您选择该输入框时，AIP Generate 会生成一系列建议的 queries 以支持您的分析。在大多数已启用 AIP 的注册租户上，Quiver 的两项主要的大语言模型驱动功能将于 10 月 7 日当周以测试版形式推出 - AIP Generate 和 AIP Configure - 除了此前可在 Quiver 工作区的顶部功能区以及所选卡片中使用之外，现在还可以在卡片下方访问。

用户可以在 Quiver 卡片下方访问 AIP Generate，以创建新的分析。

您可以选择建议的查询，也可以输入自己的查询。选择建议的查询或输入您自己的查询后，AIP Generate 会为分析生成潜在的后续步骤，您可以通过编辑 query 直接在您输入原始查询的输入栏中完善这些后续步骤。接下来，选择结果或按下 Enter 键，以指示 AIP 将卡片添加到画布并代表您完成所有配置。

从新创建的分析中访问 AIP Configure

要配置现有卡片，请将光标悬停在卡片上，然后选择 修改 按钮，然后再将您的配置提示词输入到 AIP 图标右侧的文本字段中。在选择建议的修改之前，请先验证 AIP 的建议是否回答了您的提示词。

用户可以在分析卡片下方访问 AIP Configure。

如果您无法在自己的注册环境中访问这些功能，请联系 Palantir 支持团队以启用相关功能。

您可以在 Quiver 的现有文档中查阅有关 AIP Generate 和 AIP Configure 的更多详细信息。

面向 Java 开发的本体论 SDK [GA]

发布日期：2024-10-08

Java 支持将于 10 月 7 日当周在 本体论 SDK 和 开发者控制台中正式发布。。Java 开发人员现在可以生成一个 Java 库，以便轻松与本体论对象、关联、操作、聚合和函数进行交互。用户可以将 Java OSDK 添加到现有的 Java 服务中，或创建全新的应用程序，以实现与 Palantir 平台上数据的无缝集成。

该 本体论软件开发工具包（SDK） 允许您直接在开发环境中访问本体论的全部功能。您可以使用 Developer Console 生成 Java OSDK，它是一个通过 Palantir API 创建和管理应用程序的门户。凭借对 Java OSDK 的全新支持，您可以构建基于 Java 的程序，例如与本体论交互的后端服务。这些服务将使用机密客户端向 Palantir 平台进行身份验证，并根据授予用户的权限提供数据。

这是一个代码示例，展示了为 Aircraft 本体论对象生成的 Java OSDK 的部分功能。

开始使用 Java 软件包

Java 支持已作为一种附加语言包含在 Developer Console 中，后者还支持 Typescript 和 Python 开发。想要使用 Java OSDK 的开发人员可以按照文档中记录的步骤 创建 Developer Console 应用程序 并生成新版本。该 SDK 版本 页面现在包含一个 maven 选项卡，其中列出了所有已生成的 Java 包。

在生成 Java OSDK 之前，您必须先在以下位置设置 Maven 组 ID： SDK 版本 > 设置。 生成后，请按照 API 文档 > 入门 中的说明，将 Java OSDK 导入到您的 Java 环境中。

要引导创建应用程序，您可以参阅 《新建本体论 SDK (OSDK) Java 应用程序引导指南》。

要生成 SDK，请先选择 SDK 版本选项卡以查看所有已生成的 SDK，选择 设置 以设置 Maven 组 ID，然后通过 生成新版本 来完成 Java OSDK 的生成。

我该如何学习使用它？

如需了解 Java OSDK 的使用入门以及一些 示例 功能，您可以在 Developer Console 中生成 Java OSDK 教程。该教程将为您概述 Java OSDK 提供的一些 功能 ，以及如何通过 Java 客户端与本体论进行交互。

首先，通过 Developer Console 中的顶部选项卡生成一个本体论 SDK 教程示例应用。

Developer Console 主页，您可以在其中选择通过“本体论 SDK 教程 - 待办事项应用”生成教程。

生成后，您将进入一系列课程。在访问 Java 教程之前，您必须先在以下位置设置 Maven 组 ID： SDK Versions > Settings。 生成后，请按照 Lessons > 0: Getting Started 中的说明，使用控制台生成示例教程 Java 应用程序并完成各项任务。从这里开始，请完成每节课及其相关任务。如需提示，请参考示例解决方案。

要使用 OSDK 创建 Java 课程，请选择一门课程，然后选择 Java 作为语言，最后配置 Maven 组并生成 Java OSDK。

需要支持？

Developer Console 包含为本体论 SDK 支持的所有语言动态生成的 API 文档。请使用语言下拉菜单切换到特定于 Java 的文档。

此外，有关所有 Java OSDK 功能的公开文档，请参阅 Palantir 公开的 Java OSDK 文档。

我们始终乐意与您 互动 ，方式是通过我们的 Palantir Community Forum ↗。请使用 #ontology-sdk 标签提交与本体论 SDK 或 Developer Console 相关的反馈和任何问题。

通过 RStudio® Code Workspaces 中的报告分享数据洞察

发布日期：2024-10-03

Code Workspaces 中的 R Markdown 报表现已正式发布，使 RStudio® 用户能够根据 R Markdown 文件无缝地生成、可视化和分享报告。报告以可共享网页的形式生成，使 RStudio® 用户能够将分析和关键发现分发给同事和利益相关者。生成的报告可以配置为在底层 R Markdown 文件被编辑时自动更新，让相关人员随时了解最新变化。

一种用户友好的交付结果选项

通过导航至 R Markdown 文件并打开 报告 标签页（位于 应用程序 侧边栏中，该侧边栏属于代码工作区），即可利用用户友好的报告创建功能。

报告标签页位于 应用程序 侧边栏中，其中显示了 创建新报告 选项。

该 报告 标签页是您查看、编辑和创建报告的首选之地。在这里，您可以选择一份报告，在新标签页中将其打开，并分享报告链接，以传递洞察与分析结果。

回顾并分享历史报告

此外，借助内置的版本历史记录，用户可以分享过往的报告版本，并评估报告随时间的变化。这使用户能够持续更新底层的 R Markdown 文件，同时仍能回溯过去、展示先前的发现。以往报告的记录让用户在修改底层文件时更加安心；如果先前的某份报告特别有用或影响深远，您始终可以查看或分享它。

版本选择器显示在报告卡片上，该卡片位于 报告 标签页中。

在 Control Panel 中配置您的支持团队

发布日期：2024-10-03

为了提高可发现性，支持团队配置已从 Foundry Issues 应用程序迁移至 Control Panel。

您现在可以在控制面板中配置支持团队。

使用 AIP Agent Studio 构建交互式助手 [Beta]

发布日期：2024-10-01

注意： 自2026年4月27日当周起，AIP Agent Studio 已更名为 AIP Chatbot Studio。所有现有特性和功能均保持不变。

AIP Agent Studio 是一款全新的无代码工具，使用户能够构建和部署配备企业特定信息和工具的交互式助手（称为 AIP Agents）。AIP Agent Studio 提供自然语言界面，可通过 AIP Agents 利用本体论、文档和 LLM，这些代理能够接收和更新参数（例如本体论对象或文本字符串）。

目前作为测试版提供，请联系您的 Palantir 代表在您的环境中进行安装。

一个由 LLM 驱动的 AIP Agent，在回答用户有关当前产品问题的提问时，使用参数来获取经过筛选的客户支持记录本体论对象集并将其作为上下文。

上述 AIP Agent 可以部署在 Workshop 应用程序中，并将代理参数与变量相关联。

专为交互式协助和轻松集成而设计的多功能代理

AIP Agent Studio 提供多项极具吸引力的功能：

  • 可自定义的代理： 创建和配置具有特定提示、参数和工具的 AIP Agents，以满足您的企业需求。
  • 交互式协助： 部署能够以对话方式与用户交互、提供洞察并执行任务的代理。
  • 无缝集成： 利用本体论、文档、自定义内容源和 LLM 构建强大的智能体，并将其部署到 Workshop、 AIP Threads以及 AIP Assist。
  • 安全性： 基于 同样严格的安全模型 构建而成，该模型治理着 Palantir 平台的其余部分，确保数据完整性和访问控制。

一个配备本体论语义搜索工具和对象查询工具的 AIP Agent，用于从供应链通信中查找相关信息，并将其与特定订单关联起来。

您应该何时使用 AIP Agent Studio？

我们建议在以下场景中使用 AIP Agent Studio：

  • 分组文档检索增强生成（RAG）智能体： 非常适合分析大量文档或非结构化数据。无论是处理采购文档、环境影响评估、保险理赔还是交接班日志，AIP Agent 都能提供上下文感知的回复和洞察。
  • 本体论上下文过滤： 适用于需要基于应用上下文进行额外过滤的任务。例如，在起草或头脑风暴场景中，可以使用智能体来遵循不同利益相关者发布的特定风格指南。这样可以实现一致且个性化的文档生成，比如创建根据特定上级偏好量身定制的简报。
  • 自定义文档协助： 通过 与 AIP Assist 集成，AIP Agent 可以专门针对仅基于自定义内容源的查询进行响应，使其成为支持团队、开发团队和平台管理员不可或缺的工具。此功能将 AIP Agent 的能力扩展至自定义文档。
  • 例行提示与模板化： 非常适合需要例行起草或模板化的场景，例如编程辅助或生成领域特定语言（DSL）规则。使用特定的指南或模板对 Agent 进行预先提示，可以显著提升性能和一致性。

AIP Agent Studio 不适用于需要重复且定义明确的流程的任务。对于此类用例，AIP Logic 或 AIP Automate 等其他工具可能更为合适。

我们正在积极开发 AIP Agent Studio，并将很快推出通过本体论 SDK（OSDK）在外部部署 AIP Agent 的支持。敬请关注后续更新。

使用派生序列存储时间序列逻辑，现已正式发布 [GA]

发布日期：2024-10-01

我们很高兴地宣布， 派生时间序列的 GA 版本现已发布，将于 10 月 7 日当周在所有租户上可用。

在此功能发布之前，在 Quiver 中执行的时间序列分析结果无法用于涉及其他 Foundry 应用程序的工作流。现在，您可以从原始传感器数据派生新序列并将其保存回本体论，从而可在所有支持本体论的应用程序中使用派生序列。进入本体论后，派生序列的行为与原始时间序列相同，但计算是即时进行的。这样就无需管理或存储派生数据，也无需在整个平台中重复这些计算。

关于如何对原始数据执行操作以生成派生序列的通用概述。

派生序列有哪些新功能？

在之前的派生序列测试版中，您需要通过 Pipeline Builder 或代码仓库手动将派生时间序列保存到本体论。现在，您可以使用 保存派生序列 设置方便地自动保存到本体论，该设置位于 派生序列选项 部分中，该部分存在于任何 受支持的时间序列卡片 （在 Quiver 中）。

该 保存派生序列 选项（位于 Quiver 卡片中），以及配置选项中用于自动保存到本体论的设置。

我们还更新了派生序列管理体验，推出了功能丰富的时间序列逻辑编辑器，如下所示：

适用于 Delta 压力派生序列的更新版时间序列逻辑编辑器。

最后，我们现在提供了用于管理已保存到本体论中的派生序列的工具：

用于配置自动保存到本体论中传感器对象类型的新“本体论”标签页。

为什么要使用派生序列？

在推出派生序列之前，平台缺乏用于创建和管理派生序列的易于使用的工具。此外，如果不将转换后的数据物化并手动将新序列添加到本体论中，就没有直观的方法在不同 Palantir 应用程序中使用转换后的时间序列。

现在，用户可以在 Quiver 中派生新序列并将其保存到本体论中，以便在整个 Foundry 的运营和分析应用程序中使用。用户还可以在专用工具中管理派生序列的逻辑和本体论保存，且仅当用户请求派生序列时才执行计算。

示例用例

派生序列目前的一个用例侧重于废水处理厂的工艺优化，利用数据科学来优化能源和化学品消耗。通过将派生序列用作机器学习模型的特征，我们可以简化此类模型的部署，这些模型利用实时流式传输的时序数据，大规模地为安全水厂的运营决策提供依据。

隆重推出 AIP Threads [Beta]，您的企业生产力工具

发布日期：2024-10-01

AIP Threads 是一款面向企业的新型通用生产力工具，使用户能够借助大语言模型（LLM）的力量完成各种任务和临时分析。无需特殊配置或专业技术知识，即可与文档（例如 PDF）和 AIP Agents（配备企业专属信息和工具的交互式助手）进行交互。要开始使用 AIP Threads，只需将文档拖放到界面中、从您有权访问的已上传文档中进行选择，或者选择您和您的组织创建的 AIP Agent，然后即可开始提问。

AIP Threads 目前以测试版（beta）形式提供，您可以联系您的 Palantir 代表将其安装到您的租户中使用。

AIP Threads 界面展示了与文档和 AIP Agents 的交互。

AIP Threads 中显示的 PDF 文档引用。

快速进行文档分析并获取专业协助

AIP Threads 适用于：

  • 快速、临时的文档分析： 从技术手册、供应商合同、情报报告等文档中提取并总结关键信息。
  • 交互式协助： 使用 AIP Agents 以获取基于特定企业数据的动态帮助和洞察。
  • 迭代式工作流： 执行需要详细文档分析和交互的迭代任务。

AIP Threads 不适用于需要高度结构化、重复性任务的工作流。对于此类情况，AIP Logic 或 AIP Automate 等其他工具可能更为合适。
