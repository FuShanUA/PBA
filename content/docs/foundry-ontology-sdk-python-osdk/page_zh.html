分页加载示例餐厅

在给定页面令牌（如果存在）之后，加载所请求页面大小的对象列表。 page_size 设置的是单个页面的大小，而不是对对象总数的限制。

当数据仅作为样本或用于显示时，加载单个页面通常是正确的选择，因为用户界面一次只能显示有限数量的对象。加载适合当前视图的页面，并在用户滚动时获取更多数据，而不是预先加载每个对象。

此端点使用对象类型的底层对象同步技术。如果 Example Restaurant 对象类型由 Object Storage v2 支撑，则没有请求限制。如果由 Object Storage v1（Phonograph）支撑，则有 10,000 条结果的限制：请求超过 10,000 个 Example Restaurant 对象会返回一个 ObjectsExceededLimit 有时，Webhook 可以正常工作，而来自函数的 API 调用可能会遇到

参数：

  • pageSize integer （可选）：要请求的页面大小，最大为 10,000。如果未提供，请求将加载最多 10,000 Example Restaurant 个对象。后续页面使用 pageSize 初始页面的
  • pageToken string （可选）：如果提供，则请求一个大小小于或等于 pageSize 首次请求页面大小的页面。
  • properties list （可选）：要加载的属性，以 ExampleRestaurant.object_type.<property> 引用的形式指定。如果省略，API 会使用其 默认属性选择.

page() 不会请求自己的快照，但为函数运行配置的快照仍然适用。当没有快照适用时，页面之间的变化可能导致 重复或遗漏.

加载所有示例餐厅

iterate() 返回一个迭代器，从 一致的快照 中连续获取页面，直到返回每个匹配的对象。直接迭代对象集（如 for restaurant in client.ontology.objects.ExampleRestaurant中所示）的行为方式相同。

要将固定数量的对象作为列表获取，请使用 take(n) 来替代。 take(n) 最多返回 n 个对象，并静默丢弃其余对象，因此仅当部分结果是正确的时候才使用它，例如样本或用于显示的列表。

在加载每个对象之前，请考虑您是否需要：

  • 计算计数、总和或其他汇总值： 用途 现在支持基于对象集定义配置 代替，它们在后端运行而无需加载对象。
  • 在用户界面中显示样本或列表： 用途 take(n) or 加载单个页面 instead.
  • 仅读取某些属性： 传入 properties to 仅加载这些属性.
  • 同时在内存中持有每个对象： 在循环中逐个处理到达的对象，而不是将迭代器包装在 list(...)中，除非您的代码需要同时使用所有对象。

此端点使用对象类型的底层对象同步技术。如果 Example Restaurant 对象类型由 Object Storage v2 支撑，则没有请求限制。如果由 Object Storage v1（Phonograph）支撑，则有 10,000 条结果的限制：请求超过 10,000 个 Example Restaurant 对象会返回一个 ObjectsExceededLimit 有时，Webhook 可以正常工作，而来自函数的 API 调用可能会遇到

获取选项

Python OSDK 的加载方法接受用于控制返回哪些属性和对象元数据的参数。下表列出了同步方法；相应的异步方法接受相同的参数。

参数支持的方法描述
propertiesget(), page(), iterate(), take()仅返回列出的生成的属性引用。
apply_modifiersget(), page(), iterate(), take()为特定属性请求不同的返回表示形式，例如由已配置的 reducer 选择的值。
include_ridget(), page(), iterate(), take()填充返回对象的 rid 属性。默认值为 False.
load_property_securitiesget(), page(), iterate(), take()为返回的对象加载属性级别的安全元数据。默认值为 False.
load_ontology_defined_derived_propertiesget(), page(), iterate(), take()当 properties 被省略时，设置为 True 以同时返回 本体论定义的派生属性。在以下情况下无效： properties 另有指定。
page_sizepage()设置每页对象的最大数量。
page_tokenpage()从上一个页面迭代器的 next_page_token.
num_itemstake()设置要返回的对象的最大数量。

选择属性

将生成的属性引用传递给 properties 参数以限制返回哪些属性。当 properties 被省略或为空时，OSDK 返回对象类型的原生属性，但不包括向量属性。 本体论定义的派生属性 默认不会返回，必须显式选择。以下示例仅返回 restaurant_id 和 restaurant_name:

    page_size=30,

选择数组属性会返回其完整的、未经缩减的值，即使 属性 reducer 已在 Ontology Manager 中配置。同样的行为也适用于原生属性和本体论定义的派生属性。

属性在请求运行时加载，无论您的代码之后是否读取它们。对于具有大型文本、数组或其他宽属性的对象类型，加载不需要的属性可能比仅加载您读取的属性慢得多，并使用更多网络带宽。传入 properties 以及您的代码读取的属性，以仅加载这些属性。即使未选择主键属性，API 也会返回该属性。

应用属性修饰符

测试版

Python OSDK 中的属性修饰符位于 测试版 开发阶段。在积极开发期间,功能可能会发生变化。

每个具有受支持属性配置的生成对象类型都包含一个 ApplyModifiers 类。将该类的一个实例传递给 apply_modifiers。生成的类将每个属性限制为其本体论配置所支持的修饰符：

  • "applyReducers": 对于配置了 reducer 的数组属性，返回所选的数组元素而非完整数组。
  • "extractMainValue": 对于配置了 主值的结构体属性，仅返回主值字段。
  • "applyReducersAndExtractMainValue": 对于同时配置了这两种功能的结构体数组，先使用 reducer 选择一个结构体，然后返回其主值字段。

如果你还传递了 properties，则包含其中指定的每个属性 apply_modifiers。否则，OSDK 会抛出 ValueError.

例如，假设某个 Equipment 对象类型具有一个可为空的 maintenance_history 属性，其类型为 Date 数组，并配置了用于选择最近日期的 reducer。在不使用 apply_modifiers 的情况下选择该属性会返回完整数组：

from ontology_sdk.ontology.objects.equipment import EquipmentApplyModifiers

equipment = client.ontology.objects.Equipment.get(
    "E-100",
    properties=[
        Equipment.object_type.equipment_id,
        Equipment.object_type.maintenance_history,

        equipment.modified_properties.maintenance_history

加载有序结果

通过为特定属性指定排序方向，加载有序的 Example Restaurant 对象列表。通过 API 调用时，您在 fields 数组中指定排序条件。通过 SDK 调用时，您可以将多个 order_by 调用链接在一起。字符串的排序顺序区分大小写，即数字在大写字母之前，大写字母在小写字母之前。例如， Cat 位于 bat.

参数：

  • field string：您要排序的属性。使用 SDK 时，将其引用为 ExampleRestaurant.object_type.<property>.
  • direction asc | desc：您要排序的方向，升序或降序。使用 SDK 时，使用 asc() and desc() 属性访问器上的方法。

ordered_restaurants = (

分页一致性与快照

当您跨多个页面加载对象时，数据可能在请求之间发生变化。下表描述了每种加载方法是否请求自己的快照。为函数运行配置的快照仍然适用，无论使用哪种加载方法：

Method请求自己的快照数据在页面之间发生变化时的行为
iterate()，或直接迭代对象集是每个页面反映同一时间点，因此每个对象恰好返回一次。如果无法维护快照，请求将失败。这些保证不适用于具有流式输入数据源的对象类型。
page() and take()No当没有快照适用时，页面之间的变化可能导致重复或遗漏。

此表描述的是同步方法。异步方法目前处于测试阶段，其行为可能有所不同；例如， async_take() 在某些 SDK 版本中会从快照读取。

遍历可能因 PagingInconsistencyDetected 而失败，如果服务检测到页面之间的不一致。长时间运行的遍历也可能因其快照过期而失败。对于流式数据源，不保证一致的快照。 iterate() 无法配置为跳过快照。

如果对频繁更新的对象类型进行完整遍历时因快照错误而失败，请选择其权衡您的 工作流可以容忍的方法：

  • 改为聚合： 如果您需要计数、总和或其他汇总值，请使用 现在支持基于对象集定义配置，它们不会逐页遍历对象。
  • 更快地遍历： 用途 properties 以加载更少的属性，并通过筛选器缩小对象集，使遍历在快照过期之前完成。
  • 筛选到稳定的子集： 对于仅追加的数据，使用固定的时间截点来排除最近的对象，前提是在遍历期间，迟到数据或回填不会在截点之前添加对象。
  • 不请求快照进行分页： 迭代由 page() 返回的页面，而不是调用 iterate(). page() 不会请求自己的快照，但为函数运行配置的快照仍然适用。当没有快照适用时，页面之间的更改可能导致重复或遗漏。

以下示例在不请求自己的快照的情况下获取连续的页面，并跳过主键已被处理过的对象：

当没有快照适用时，页面之间的更改可能导致对象被遗漏。去重无法恢复这些对象。

函数和操作中的快照

当 OSDK 在 Python 函数中使用时，函数自身的 一致性快照配置 同样适用。当 OSDK 客户端为函数运行携带快照时，无论加载方法如何，该快照都会适用。

  • 快照隔离操作： 配置了 快照隔离 的函数支撑操作会使用该操作的快照进行函数运行。这些操作要求保持启用快照。
  • 读已提交操作： 使用 读已提交隔离时，操作不会为运行提供快照，但 iterate() 仍会为其自身的遍历请求快照。
  • 过期的快照： 快照的生命周期有限。如果长时间运行的函数因其快照过期而失败，请重新评估工作流是否需要跨读取的一致视图。如果不需要，可以在函数配置中禁用快照。如果需要，请保持启用快照，并确保读取在快照过期之前完成。禁用快照并不能防止 iterate()的分页不一致错误，因为无论函数配置如何，它都会请求自己的快照。

使用场景作用域客户端

实验性

本体论场景支持位于 实验性 开发阶段，可能无法在您的注册租户中使用。功能在积极开发过程中可能会发生变化。

OSDK 还可用于创建和交互 直接在您的应用程序代码中使用。场景作用域客户端的行为与常规 OSDK 客户端相同：您读取的每个对象、计算的每个聚合以及应用的每个操作都会自动针对场景的隔离沙箱而非主本体论进行评估。。你可以使用场景来构建假设分析，而无需更改主本体论。通过 RID 创建场景作用域客户端或附加到现有场景。Foundry 会针对该场景的隔离沙箱评估来自此客户端的调用。
