对比：Code Repositories 与 Code Workspaces 与 Code Workbook

Foundry 提供三种用于编写基于代码的数据转换的产品：Code Workbook、Code Workspaces 和 Code Repositories。虽然这些产品之间存在一些功能重叠，但每种产品都面向不同的工作流和用户类型。下面的指南旨在帮助您确定哪种工具最适合您的需求。

代码仓库 推荐用于创建稳健的生产管道，并支持需要额外治理和审查层的工作流。借助 Code Repositories，数据工程师可以批量创建高效的管道。适合使用 Code Repositories 的示例工作流包括：

  • 在高数据规模下需要增量计算的每日管道。
  • 具有严格治理要求的高可见性管道，需要能够回退到历史代码的先前版本，或在单元测试通过后才允许代码变更。

代码工作区 推荐用于使用 JupyterLab® 和 RStudio® Workbench 进行快速高效的探索性分析，将熟悉的 IDE 与 Foundry 平台的优势（如数据安全、分支、构建调度和资源管理）相结合。适合使用 Code Workspaces 的示例工作流包括：

  • 逐单元格运行数据分析并将其内容导出为可共享的报告
  • 对数据转换管道或机器学习模型进行原型设计

代码仓库（Code Repositories） 推荐用于对大规模数据执行基于代码的分析，而这些数据原本不适合在 Code Workspaces 中处理。这些分析可以是一次性使用，也可以生成定期更新的产出物。Code Workbook 还可用于对管道进行原型设计，然后将其 提升为仓库。适合使用 Code Workbook 的示例工作流包括：

  • 通过测试不同的 p 值来研究临床试验的结果。
  • 创建可与他人共享的交互式可视化。

除上述基于代码的产品外， 如果希望用户在每次运行预览前手动确认，请开启 是 Palantir 平台主要的无代码应用程序，用于构建和维护生产数据管道。Pipeline Builder 使用图形和表单界面，使用户无需编写代码即可集成数据并创建业务逻辑转换。如果您正在评估在管道中使用 Pipeline Builder 还是 Code Repositories，请参阅 注意事项：Pipeline Builder 与 Code Repositories.

表格摘要
Code Repositories 功能
  • Code Repositories 具备高级管道功能，支持在长期运行的数据管道中构建复杂工作流，并在性能优化和代码生成方面提供灵活性。
  • Code Repositories 支持的语言包括 Python、SQL、Java 和 Mesa。
  • Code Repositories 支持 增量计算, 转换生成, 多输出转换日 文件系统访问.
  • Code Repositories 不支持可视化。
Code Workspaces 功能
  • Code Workspaces 具备快速高效的探索性工作流，在 Foundry 中嵌入支持 JupyterLab® 和 RStudio® Workbench。
  • Code Workspaces 支持的语言包括 Python 和 R。
  • Code Workspaces 支持 文件系统访问 并为基于笔记本的分析提供完全的灵活性。
  • Code Workspaces 不支持分布式 Spark，因此更适合可容纳在工作区 计算限制.
Code Workbook 功能
  • Code Workbook 具备高级分析工作流，支持常用分析语言和可视化库。
  • Code Workbook 支持的语言包括 Python、R 和 SQL。
  • Code Workbook 支持 文件系统访问 and 可视化.
  • Code Workbook 不支持增量计算、转换生成或多输出转换。
Code Repositories 迭代周期
  • Code Repositories 旨在帮助迭代代码逻辑。构建完成后，可在 Foundry 中分析数据。
  • Code Repositories 支持数据示例预览以验证转换逻辑，并支持对输入示例进行预过滤。
  • Code Repositories 支持 运行时调试.
  • 在 Code Repositories 中，Spark 模块在作业级别启动。
Code Workspaces 迭代周期
  • Code Workspaces 旨在帮助探索和分析数据。结果随后可以共享、发布到仪表板、转换为可复用的转换，或导出到可用于生产环境的管道工具（如 Code Repositories 或 Pipeline Builder）。
  • Code Workspaces 提供 JupyterLab® 和 RStudio® Workbench IDE 的完全灵活性，包括完整的代码和数据预览。
  • Code Workspaces 提供逐单元格迭代，可即时反馈代码执行结果。
  • 在 Code Workspaces 中，无需 Spark 模块，并且提供完全可自定义的内核，便于对环境进行临时调整。
Code Workbook 迭代周期
  • Code Workbook 旨在帮助从数据中生成洞察。所有转换都在完整输入数据上运行，并且 Spark 执行模型针对快速迭代进行了优化。
  • Code Workbook 支持完整数据预览。
  • Code Workbook 提供 控制台支持 用于对转换进行临时分析。
  • 在 Code Workbook 中，Spark 模块保持热启动状态以实现即时交互，并在工作簿级别启动。
Code Repositories 操作
  • Code Repositories 支持 Foundry 数据管理库和自定义 Python 库。
  • Code Repositories 支持 数据期望, 发布 自定义库以及使用自定义库。
  • Code Repositories 不支持点击式代码模板。
Code Workspaces 操作
  • Code Workspaces 可以使用 pip、CRAN 和 conda 库，包括从 Code Repositories 发布的库，并且可以快速修改环境。
  • Code Workspaces 不支持数据期望或发布自定义库。
  • Code Workspaces 不支持点击式代码模板。
Code Workbook 操作
  • Code Workbook 可以使用从 Code Repositories 发布的自定义库，用户可以将部分逻辑保存为代码模板，供其他用户进行点击式分析。
  • Code Workbook 不支持数据期望或发布自定义库。
  • Code Workbook 支持 使用自定义库 （适用于部分 Spark 环境）。
  • Code Workbook 支持 点击式模板.
Code Repositories 变更管理
  • Code Repositories 优先考虑变更可追溯性和治理，以确保关键管道保持安全且稳健。
  • Code Repositories 提供完整的变更日志。
  • Code Repositories 提供 完整的 Git 工作流、安全标记管理和 移除, 影响分析 views, 高级代码审查 工作流，以及 单元测试.
  • Code Repositories 不支持在合并后复制数据。
Code Workspaces 变更管理
  • Code Workspaces 优先考虑快速灵活的迭代，提供完整的分支支持和自动 Git 版本控制。
  • Code Workspaces 完全由 Code Repositories 支撑，并受益于其 完整的 Git 工作流.
  • Code Workspaces 不支持在合并后复制数据。
  • Code Workspaces 会将其笔记本内容的安全检查点保存 30 天，让用户能够安全地保留和检索任何给定状态，同时还提供将代码备份永久存储在 Git 仓库中的机会。
Code Workbook 变更管理
  • Code Workbook 优先考虑快速迭代和协作，采用轻量级分支工作流。Code Workbook 不需要 CI 检查或单元测试。
  • Code Workbook 支持在合并后复制数据。
  • Code Workbook 不提供完整的 Git 工作流、安全标记管理或移除、影响分析视图、高级代码审查工作流或单元测试。
