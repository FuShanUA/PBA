Workshop 中的自动刷新

Workshop 自动刷新让构建者能够轻松创建随 Foundry 中数据变化而自动更新的应用程序。为用户提供可靠、最新的信息对于支持运营工作流至关重要，而 Workshop 只需点击几下即可实现这一点。

通过自动刷新，您可以在模块中注册对象集，以便监视来自 Foundry 中任何位置的更新。当发生更新时，当前模块中的所有数据将自动刷新，无需用户交互。更新源的示例包括：其他用户执行操作导致的本体论数据更新、来自上游数据集成的编辑，或来自流式数据源的新记录。在这些情况下，自动刷新将更新当前模块中的数据。

在数据新鲜度优先的场景中，自动刷新非常有价值，包括但不限于实时仪表板和协作工作流。

要在模块的 UI 中直接展示数据时效性，请使用 数据新鲜度（Data Freshness）小部件。它会根据最近的索引时间，为配置的对象类型及其数据源显示最后更新时间戳：24 小时内的更新以相对时间显示（例如“2 小时前”），超过 24 小时的更新以绝对时间显示（例如“2025 年 7 月 17 日，星期四，下午 1:52”）。

您可以在特定的 Workshop 模块中启用自动刷新。在 Workshop 编辑器中，导航至 设置 面板底部的自动刷新配置选项。

自动刷新可能会导致数据加载量及相关成本的增加。对于不太需要实时数据的工作流，构建者可以选择不启用该功能。

设置

要更新自动刷新设置，请选择 自动刷新 菜单中选择 设置 面板。然后展开 设置 面板底部的部分。

刷新之间的最小秒数

此设置允许模块构建者配置数据刷新之间的最小时间间隔。该设置不会影响初始刷新延迟，而是确保模块不会持续不断地重新加载。当前的最小（即最频繁的）刷新频率为 10 秒，这是为了在自动刷新带来的负载增加下确保服务的稳定性。

在编辑模式下禁用

此设置允许模块构建者在编辑模式下关闭自动刷新行为。如果编辑模式下的数据自动刷新会干扰构建体验或并无必要，构建者可以使用此设置。启用此设置后，自动刷新在查看模式下仍将保持配置并处于活动状态。

使用事件控制自动刷新更新

您可以通过配置 Workshop 事件（例如通过按钮组（Button Group）小部件），让用户在会话期间暂停或恢复自动刷新更新的应用：

  • 启用自动刷新更新： 允许自动刷新的更新生效。
  • 禁用自动刷新更新： 阻止自动刷新的更新生效。

局限性

对象存储 v2（OSv2）

自动刷新仅限于由 OSv2 支撑的对象类型。此限制包括对象集定义中使用的、带有 OSv1 支撑对象类型关联对象的对象集。

了解更多关于 从 OSv1 迁移到 OSv2.

涉及用户输入的工作流

在使用自动刷新的模块中，并不禁止涉及用户输入的工作流。但是，您可能会遇到变量或小部件状态在刷新后被重置的问题。要解决此问题，应避免在出现此问题的变量中使用自动重新计算行为。如果这还不够，您可以使用 iFrame 小部件 来嵌入一个单独的模块，作为不会自动刷新的沙盒环境。您可以设置 URL 查询参数 embedded=true 来隐藏 Foundry 侧边栏。另一种方法是使用一个单独的 Workshop 模块，在新的浏览器或 Carbon 标签页中打开，以完成工作流中涉及用户输入的部分。

关联对象类型的自动刷新

自动刷新不会自动监视关联对象类型的更新。这意味着，除非也显式监视关联对象类型，否则被监视对象集的关联对象属性和关联对象聚合将不会自动刷新。

要为关联对象属性或函数支撑的列触发自动刷新，请在简单小部件（如对象集标题小部件）中使用关联对象类型变量，并将其放置在高度或宽度为零的区块中。这样可以在不向用户显示小部件的情况下触发刷新。

一个

自动刷新目前不支持某些对象集筛选器类型，例如 terms, phrase, multiMatch, prefixOnLastToken日 objectSetLink。对这些筛选器类型的支持可能会在未来添加。

使用受支持的筛选器类型可将刷新限制到特定对象。例如，按主键筛选对象集，使模块仅在该对象发生更改时刷新。

作为不受支持的筛选器类型的变通方法，您可以监视同一类型的未筛选对象集。这可能会导致刷新频率超出必要范围，但在其他方面应能确保对象类型在模块中保持最新。

模块中的可见性

目前，启用了自动刷新的对象集需要在模块内的可见小部件中使用才能触发自动刷新。这可以防止在监视更新的对象集不在屏幕上时触发自动刷新。例如，如果注册的对象集仅在隐藏的抽屉中使用，则只有在该抽屉打开时才会发生自动刷新。

如果自动刷新通知在变量处于隐藏状态时发生，它将被延迟到变量再次可见时，届时将立即触发重新加载。

如果浏览器标签页处于最小化状态，或不是当前活动标签页，此行为同样适用。

自动刷新配置不会从嵌入模块继承

嵌入 Workshop 模块 不会继承嵌入模块的自动刷新配置。对于您打算使用自动刷新的每个模块，都必须显式配置自动刷新。这也意味着自动刷新将无法在嵌入模块的上下文中专门运行。

要在不会自动刷新的父模块中嵌入一个会自动刷新的模块，您可以使用 iFrame 小部件 来嵌入一个单独的模块，该模块充当会自动刷新的沙盒环境。您可以设置 URL 查询参数 embedded=true 来隐藏 Foundry 侧边栏。

故障排除

如果出现任何似乎与自动刷新问题相关的错误，请考虑以下几点：

  • 确保所有对象类型和关联类型都由 Object Storage v2 支撑。特别要注意两个由 OSv2 支撑的对象类型之间存在由 OSv1 支撑的关联类型的情况，因为这可能导致自动刷新出错。
  • 确保无效的对象集无法在运行时被设置，例如向对象集添加无效的筛选器类型。对象集最初可能与自动刷新兼容，但由于用户与应用程序的交互，它最终可能处于无法监视更新的状态。
  • 改善网络连接的稳定性将直接提升自动刷新功能的稳定性。如果网络不断断开并重新连接，您可能会看到自动刷新被禁用时通知用户的错误。
  • 如果您没有看到预期的刷新，可能是您监视的对象集过于具体。请尝试监视更广泛的对象集，例如给定类型的基础对象集，或更宽泛的筛选器。然后，您可以在这个被监视的更广泛的对象集的下游定义一个具有更具体筛选器的变量。
  • 请查看浏览器控制台以获取更详细的错误消息。下面，您可以查看使用自动刷新时可能发生的一些常见错误的详细信息：
    • InvalidObjectSetForPlanning：被监视的对象集包含对在对象存储 v1 中建立索引的实体（对象类型或关联类型）的引用。
