监控视图

大规模监控通过引入增强功能来减少监控 Foundry 资源所需的时间。监控视图是监控规则和健康检查的集合。

监控视图提供了超出检查组可用功能的扩展功能，我们建议 将所有现有的检查组升级 为监控视图。

创建新的监控视图

要创建新的监控视图，请导航至 监控视图 选项卡，位于右上角的 数据健康 应用程序，然后选择 新建监控视图.

添加监控规则

在您的新监控视图中，您可以 添加监控规则 ，该选项位于 管理监控 选项卡。首先，选择您要监控的资源类型，然后选择范围。

使用 静态 范围时，您可以选择要监控的特定资源。使用 动态 范围时，监控器会随着资源的添加或移除自动更新，无需手动更改。动态范围包括 文件夹, 项目, 工作流血缘, 来运行该专业代码代理。你还可以通过日 OSDK 应用，但可用性因资源类型而异。请参阅 支持的范围表 了解详情。

要对本体论资源使用项目范围，您必须首先 将您的本体论迁移到基于项目的权限.

某些监控规则具有由 AND连接的多个条件。对于这些复合规则，请为每个警报严重级别配置每个条件的阈值。只有当所有条件都达到该严重级别时，规则才会触发。如果条件达到不同的严重级别，则规则在所有条件达到的最低严重级别触发。

您必须拥有 Viewer 对资源的权限才能对其进行监控。要 接收警报 （由监控规则触发的），您必须拥有 Viewer 对资源和监控视图的权限。

此外，您可以 查看监控规则资源参考.

配置监控器

监控器是基于资源发出的指标设置的。在设置监控器时，我们会根据 Foundry 的健康标准建议某些配置。但是，您可以更改这些值或选择仅监控某些指标。您还可以确定警报的严重级别：低、中、高。

编辑监控器

您可以从监控器列表中进行选择并选择 编辑 在出现的侧面板上。

添加现有健康检查

您可以从 数据健康 应用程序中将现有健康检查添加到监控视图：

  1. 打开监控视图并选择 添加健康检查 在右上角。
  2. 在监听器设置向导的 添加健康检查 对话框中，使用筛选器或搜索数据集来查找您要添加的健康检查。
  3. 选择一个或多个健康检查，然后选择 添加检查。所选的健康检查将被添加到监控视图中。

此对话框仅添加已存在的健康检查。要创建新的健康检查，请从 健康 标签页将其添加到数据集。要同时在多个数据集上创建相同的健康检查，请参阅 向多个数据集添加新的健康检查.

设置和管理警报通知

配置监控规则后，您需要设置在检测到问题时如何以及在何处传递警报。

订阅警报

要订阅警报，请导航至 管理订阅 选项卡，其中列出了所有已订阅的用户。您可以添加用户和用户组，并根据严重程度配置其警报。当监控规则触发警报时，订阅了包含该警报的监控视图的用户将通过电子邮件和 Foundry 通知收到通知。您必须拥有 Viewer 对资源和监控视图的权限才能接收警报。

与外部系统集成

您可以通过内置集成或使用 webhook 调用任意 REST 端点，将警报发送到 PagerDuty 或 Slack 等外部系统。了解更多关于 将警报发送到外部系统.

故障排除警报

在 故障排除警报 选项卡中，您可以按警报名称、资源、失败原因和警报报告时间来查看警报。此外，您可以 查看选项, 按项目分组，或 按类型筛选 （仅适用于检查）。

对于单个监控规则，您可以打开 警报调试页面 以查看详细指标、警报历史和诊断信息。

警报触发后暂停警报

对于健康检查和监控，您可以在警报触发后暂停单个警报，以临时抑制通知。要暂停警报，请从 故障排除警报 面板中选择它，然后选择 暂停 （位于屏幕底部显示的工具栏中）。此外，您可以在 关于 Ontology Manager 上下文面板 中选择铃铛图标，该面板在选择警报后呈现。配置暂停持续时间并提供暂停原因，然后选择 暂停.

已暂停的警报包含一个内联铃铛图标标签，鼠标悬停时会显示谁暂停了该警报、何时暂停以及为何暂停。使用 隐藏已暂停的警报 右上角的开关可以在视图中隐藏已暂停的警报。隐藏后， 故障排除警报 面板底部的横幅会显示当前已暂停的警报数量。

要恢复警报的通知，请选择 取消暂停 （位于屏幕底部的工具栏中），或等待暂停持续时间到期。

与健康检查警报不同，已暂停的监控警报即使重新触发也会保持暂停状态。

暂停监控规则

除了暂停单个警报外，您还可以暂停整个监控规则，以一次性静音该规则范围内所有目标的警报。当您已知某个问题并希望通过单个操作抑制与特定规则相关的所有警报时，这尤其有用。

要暂停监控规则，请导航至 管理监控 监控视图中的选项卡，选择要暂停的规则，然后选择 暂停 （从可用操作中选择）。

当您暂停监控规则时，该规则的任何现有目标级暂停将被新的规则级暂停取代。

从警报导航到资源谱系

从 故障排除警报 选项卡或 警报调试页面上的警报，您可以直接导航到资源的血缘视图。

  • 数据集、调度和对象类型将在数据血缘中打开。
  • 函数、操作类型和自动化将在工作流血缘中打开，并选中 运行历史 选项卡。

工作流血缘中的监控状态

虽然监控警报会通知您某个特定监控器正在触发，您也可以查看整个工作流的监控覆盖情况。为此，请在 工作流血缘中以图表形式打开该工作流，选择颜色图例，然后选择 监控状态 位于 健康。每个节点都按当前针对该资源触发的监控器中的最高严重性进行着色。

图例键含义

在解读颜色时，有三种行为值得了解：

只有触发中的监控器会影响颜色。具有多个监控器的资源会呈现当前触发的监控器中的最高严重性级别。

  • 尚未首次计算状态的监控规则会被视为健康，因此新创建的规则在运行之前不会为其目标着色。
  • AIP Logic 节点采用其支撑函数的状态。在函数上设置的监控器会为使用该函数的 Logic 节点着色。
  • 监控状态基于您有权访问的监控视图中的最高严重性警报。某个资源可能存在您无法看到的其他警报。

监控状态颜色模式要求您的注册中提供监控视图。如果不可用，该选项不会出现在 Workflow Lineage 颜色图例中。

将现有检查组升级为监控视图

要升级

现有检查组 ，请在应用程序中打开您的检查组。在顶部横幅中，选择 数据健康 升级为监控视图 您可以创建新的监控视图，或将所有检查移至现有监控视图。.

监控视图是文件系统资源。如果您要创建新的监控视图，请务必将其存储在潜在订阅者可以访问的项目中。

  • 升级检查组后，检查将继续按现在的方式获得支持。电子邮件摘要、警报、订阅或与健康检查相关的任何其他工作流均无变化。
  • 每个检查组只能关联到一个监控视图，反之亦然；因此，您只能将一个检查组升级到单个现有监控视图，或者在不存在合适监控视图时创建新的监控视图。
  • 升级后，检查组将保持不变，监控视图会继承其配置。
