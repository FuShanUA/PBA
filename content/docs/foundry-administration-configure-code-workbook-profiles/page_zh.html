配置 Code Workbook 配置文件

可用性

在某些环境中，Code Workbook 配置文件只能在控制面板中配置。如有任何疑问，请联系您的 Palantir 代表。

Code Workbook 配置文件可以被视为针对特定用例或用户群体的一组实用的默认 Conda 包和 Spark 设置。Code Workbook 配置文件将显示在 Code Workbook 的 “环境配置”对话框 中，供用户选择。您可以根据需要为特定配置文件指定预热模块，以缩短启动时间。

在控制面板中创建的新 Code Workbook 配置文件由 Artifacts 支撑。有关 Artifacts 配置文件的详细信息，请参阅下文。

Artifacts 配置文件

在控制面板中创建的所有新配置文件都由 Artifacts 支撑。Artifacts 配置文件的配置与现有旧版配置文件的配置基本相同，不同之处在于 Artifacts 配置文件支持使用通过 Artifacts 安全发布的库，包括在 Foundry 中创建但未发布到 shared 该频道的 Python 库。

在 Artifacts 配置文件中，Conda 环境既包含包列表，也包含支撑仓库列表。要在 Code Workbook 中使用某个配置文件，必须将该配置文件中列出的所有支撑仓库导入到工作簿所在的项目中。

在编辑配置文件的 Conda 环境时，UI 会自动查找所需的支撑仓库列表，并告知用户这些仓库将被添加到该配置文件中。

配置 Code Workbook 配置文件

Conda 环境

在 Conda 环境选项卡中，指定使用此配置文件时的默认软件包。用户可以根据需要在自己的工作簿中自定义其 Conda 环境。

为了执行 Python 和 R 转换，Code Workbook 需要软件包 vector-spark-module-py 和 vector-spark-module-r 分别存在于该配置文件的环境中。要添加这些软件包，您可以在 Conda 环境选项卡中勾选 Python 和 R 复选框，也可以在 添加软件包 下拉菜单中手动添加它们。SQL 不需要任何额外的软件包，因此在任何配置文件上都始终可用。

在更改配置文件的 Conda 环境之前，请务必通过在工作簿中自定义环境来确保所提议的环境能够成功解析。保存对 Conda 环境的更改时，系统会要求您确认已执行此操作。

Code Workbook 会自动添加默认版本的 pandas、 matplotlib和 numpy （如果启用了 Python），以及默认版本的 r-base 如果已启用 R。如果您需要不同的版本，请在控制面板的 Conda 环境选项卡中手动添加这些软件包，或直接在 Code Workbook 中通过 Environment > Configure environment > Customize Profile 并从下拉菜单中为每个软件包选择一个版本，以满足您的版本要求。

此外，默认情况下 R 尚不可自助使用。请联系 Palantir 支持团队进行启用。

Spark 设置

在最初迁移到由控制面板支持的 Code Workbook 配置文件时，您原有的 Spark 设置将被保留。但是，如果您选择对 Spark 设置进行任何更改，则需要使用 Spark Configuration Service 配置文件重新创建这些覆盖设置。

您必须对 Spark 配置文件拥有导入权限，才能将其添加到 Code Workbook 配置文件中。 了解有关可用 Spark 配置文件的更多信息。

预热

对于每个配置文件，您可以选择预热一定数量的模块，使其随时可用。如果未定义任何预热的模块，选择该配置文件的用户将需要等待其环境初始化。

在“预热”选项卡中，您将看到用于预热交互式模块和批处理模块的选项。交互式模块用于工作簿会话。批处理模块用于构建，包括定时构建。 详细了解批量构建与交互式构建之间的区别。

权限

配置文件的所有者可以编辑该配置文件，而导入者可以将该配置文件导入到项目中。所有者会自动包含在导入者组中。您可以选择允许注册中的所有用户导入该配置文件，方法是选中 此注册中的所有人。

一旦导入者将配置文件导入到项目中，项目中的任何人都可以使用该配置文件。您可以为配置文件添加标记，以将该配置文件限制到特定组织。

常见问题

谁可以配置 Code Workbook 配置文件？

允许为注册创建 Code Workbook 配置文件的用户集可在 Control Panel 的“注册权限”选项卡中进行配置。

  • 要创建配置文件，用户必须拥有 Manage Code Workbook profiles 工作流，该工作流是 Analytical applications administrator 角色的一部分（或者是注册管理员）。
  • 要编辑现有的配置文件配置（例如 Spark 或 Conda 环境配置），用户必须拥有该配置文件资源上的所有者角色。

谁可以配置预热模块队列？

要配置预热模块队列，用户必须对配置文件拥有 "manage" 权限 (Manage Code Workbook profiles 工作流加上是该配置文件的所有者）以及 Manage Code Workbook warm module queues 工作流，该工作流是 Resource management administrator 角色的一部分。

所有用户默认使用哪个配置文件？

名为 default 的配置文件是该注册中各组织用户的默认环境。

我在控制面板中可以看到哪些配置文件？

您对其拥有所有者访问权限的所有配置文件都将列在控制面板的 Code Workbook 标签页中。可能还有一些额外的配置文件，您对它们拥有导入者访问权限但没有所有者访问权限；您可以在 Code Workbook 中使用这些配置文件，但无法在控制面板中查看它们。
