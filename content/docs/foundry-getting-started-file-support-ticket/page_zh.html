提交支持工单

如果您在查阅 可用资源后仍未能找到适合您问题的解决方案，那么就该提交支持工单了。

提交工单可确保您的问题或请求得到跟踪、适当排序优先级，并在必要时进行升级处理。

为了使支持流程更加高效，请按照以下步骤整理有价值的信息以提交支持工单：

  • 1. 创建示例
  • 2. 分享相关资产
  • 3. 报告问题

前提条件

在按照以下说明操作之前，请确保您已经：

  • 使用 获取帮助页面.
  • 上提供的步骤诊断了您的问题，并查阅了 使用 Chrome™ DevTools 调试 and HTTP 错误代码.

1. 创建示例

在就遇到的问题提问时，提供我们可以用来重现该问题的清晰步骤将确保快速解决。这些步骤应具备以下特点：

  • 最小化： 使用尽可能少的步骤，同时仍能产生该问题。
  • 完整性： 提供重现该问题所需的所有部分。
  • 可验证性： 测试您即将提供的工作流，确保它能重现该问题。

一个最小、完整且可验证的示例有助于我们在您的环境之外重现问题，从而更容易找到问题的根本原因并更快地解决。

在 Palantir 的语境中，此类示例可以是重现该行为的一系列步骤，或者是重现该问题的最小资源。通常，在示例中包含预期行为与实际观察到的行为的对比会很有帮助。

提示

以下是创建最小、完整且可验证示例的一些技巧：

  • 首先确定重现该问题所需的步骤。这些步骤越具体、越详细，其他人就越容易重现该问题。
  • 确保您的示例是最小的，即仅包含重现该问题所需的最少量信息。这有助于缩小问题的潜在原因范围，并使修复更容易。
  • 包含您所提供步骤的预期结果以及实际结果。这有助于其他人理解问题，并判断他们是否遇到了相同的问题。
  • 确保您的示例是完整的，即包含重现该问题所需的所有信息。如果您遗漏了任何重要细节，其他人将难以重现该问题并帮助您解决。
  • 最后，确保您的示例是可验证的，即其他人可以使用您提供的信息轻松重现该问题。如果您的示例不可验证，其他人将难以帮助您修复该问题。

示例

以下是一个已解决的最小、完整且可验证问题的历史示例。

当时重现该问题的步骤：

  1. 打开 Code Repositories 应用。
  2. 使用侧边栏添加 Graphframes 库。
  3. 对仓库运行检查。

预期行为：该库应被添加到 Code Repositories 中，且不出现任何错误。

实际的问题行为：显示错误消息，内容为 "o257.loadClass.: java.lang.ClassNotFoundException:"

附加信息：

  • 以下是我配置文件中的其他软件包：Python 3.12.* 等。
  • 我已经尝试过 x、y 和 z。
  • 除添加此软件包外，此 Code Repositories 最近没有其他更改。
  • 这似乎影响了此软件包的用户。

此示例仅包含重现该问题所需的最少步骤，且不需要任何专有数据。该示例被认为是完整的，因为它包含了所有必要的信息，例如预期行为和实际行为，以及已经执行的故障排除等额外背景信息。它是可验证的，因为可以使用相同的步骤重现错误消息。通过提供这些信息，Support 将能够快速重现该问题并着手解决。

如果您对此问题的修复方案感兴趣， 查看同时需要 Conda 包和 jar 的软件包.

2. 分享相关资产

在文本中提供可验证的示例后，请为 Support 编译以下附加资源：

  • 包含您在第 1 步中自行调查所得的任何发现。
  • 提供显示的任何构建错误或错误消息的完整文本。
  • 复制并粘贴任何 errorID/errorInstanceID 的文本，以便我们进行后端审查。
  • 在可能且适当的情况下，与 Palantir Support 共享所有相关资源。
    • 相关资源（Slate 仪表板、Analysis、Code Repository）。
    • 这些资源所依赖的数据集。
    • 这些资源所依赖的任何上游数据集。

3. 报告问题

要在指定应用程序中报告问题，请导航至 Support > Report issue （或 Support > Contact support），并 按照向导操作.
