什么是 HTTP 错误代码?

当您尝试打开网页时，浏览器会向服务器发出一系列请求以获取页面内容。其目的是让服务器接收您的请求，并对其进行检查以确定应向您提供什么内容，然后发送包含正确内容的响应。随后，浏览器会将这些内容组合在一起以显示页面。

本指南稍后将深入探讨请求的概念，但这里我们重点关注的是响应。服务器返回的每个响应都始终包含一个状态码。状态码表示服务器向你返回的响应的状态。它以三位数字表示，每个数字都有对应的含义（通常由互联网工程任务组定义）。你可能在页面加载失败时见过这些代码——诸如 "404" 这样的术语你可能已经熟悉。在这里，我们将进一步探讨每个代码的含义，以及你如何利用这些信息找到一些简单的解决方法，或报告更有价值的错误信息。

响应中发送的三位数字的首位数字表示状态的类别。本指南涉及的重要类别如下：

  • 2xx：如果代码以 2 开头，则表示请求成功。完整的代码通常就是 200，它代表一次通用的成功请求和响应。
  • 4xx：如果代码以 4 开头，则表示请求由于客户端错误而失败。客户端是指发出请求的实体，通常是您当时正在使用的浏览器或网页。我们将在下面看到此类代码的一些示例。
  • 5xx：如果代码以 5 开头，则表示请求由于服务器错误而失败。这通常意味着您的请求格式正确且构造无误，但当服务器对其进行检查并尝试确定要返回什么响应时，出现了问题。我们将在下面看到此类代码的一些示例。

现在让我们深入了解一些实际的代码。请注意，此列表并非详尽无遗，如果您遇到此处未列出的编号，可以参考 HTTP 状态代码完整列表 ↗.

客户端错误

400 - 错误请求

此错误消息表明您发送至服务器的请求存在内部问题。Palantir 开发人员致力于确保此错误代码极少出现，因为其最常见的原因是请求语法格式错误，而请求语法通常定义在底层代码中。不过，导致“错误请求”错误的一个常见原因是请求过大，即请求中包含的数据过多，服务器难以处理。

403 - 禁止访问

禁止访问错误表示您发出了一个您无权发出的请求。在 Palantir 平台中，如果存在一条 ACL（访问控制列表）规则规定您不得访问您正在尝试访问的资源，您就可能会遇到此错误。例如，这可能是您的用户无权查看的某些数据，但该规则同样适用于服务。例如，如果您的用户无权访问 Data Lineage 应用程序，那么在您尝试访问时，就可能会看到“403 - 禁止访问”。

404 - 未找到

此错误表示您请求的内容并不存在。例如，如果某个特定资产已被移除，那么访问该资产时会显示“404 - 未找到”，因为您所请求的资源并不存在。

服务器错误代码

500 - 内部服务器错误

此错误表示服务器已收到请求，并需要执行内部操作以生成响应。然而，服务器在此过程中发生了内部错误。

例如，假设你的服务器的任务是接收一个包含两个数字的请求，然后将第一个数字除以第二个数字。在这个例子中，如果你向服务器发送包含数字“8”和“2”的请求，服务器将返回状态码为 200（成功）的响应，其中包含答案“4”。但是，如果你发送的是“5”和“0”，你可能会看到“500 - 内部服务器错误”，这是因为服务器在尝试计算 5/0 时内部发生了错误。在 Palantir 平台的语境中，这意味着你需要查看相关服务的内部情况，以便弄清内部发生了什么错误。

502 - 错误网关

术语“网关”(Gateway)指的是，服务之间的连接在幕后存在一定的“间接”成分。假设您在尝试打开 https://foundry.link/workspace/magic-app时遇到了此错误。实际发生的情况是，您的请求会先到达一台服务器(即“网关”服务器)，然后由该网关服务器将您的请求继续转发。值得注意的是，magic-app 很可能运行在与网关不同的服务器上，因此网关必须向该服务器(称为“上游服务器”)请求响应，以便将该响应返回给您。此错误意味着上游服务器返回了无效的响应。

503 - 服务不可用

此错误表明该服务是存在的，否则您将收到 404 错误。但是，该服务无法处理您的请求，最常见的原因是服务已停机或过载。例如，如果 Contour 接收到过多的请求，无法再处理更多请求，您可能会收到“503 - 服务不可用”错误。这可能是因为计算资源不足，或者是因为内部 bug（例如内存泄漏）。

504 - 网关超时

此错误与“502 - Bad Gateway”类似，不同之处在于网关服务器发出了正确的请求，但未收到上游服务器的及时响应。这种情况可能由多种原因引起，包括网络连接问题、服务器停机或服务器过载。当出现 504 错误时，通常表示您尝试访问的网站或 Web 应用程序暂时不可用。这通常不是您自己的设备或互联网连接的问题。
