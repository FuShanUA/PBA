阶段 3：通过自主性实现平台增长

组织对 Foundry 的使用情况如何？

  • 用例显著扩展，且往往遍布众多业务领域。Foundry 的使用量也大幅增长；在此阶段，组织通常拥有数百名常规用户。
  • 治理和项目流程已得到实施和规范化，既包括支持项目团队日常运作的内部流程，也包括确保整个组织持续增长以及与多个业务领域进行结构化协作的跨职能流程。
  • 项目团队应扩展其职责范围，包括：明确平台维护的权责归属；为数据安全和权限流程及架构配备专职资源；以及监控 Foundry 的使用情况，包括计算优化和存储增长。
  • 教育和培训举措应正常运行，并有明确的负责人到位，同时在各类用例和工作流程中建立了成熟的培训内容。
  • Foundry 项目应在整个组织内得到充分确立。项目目标聚焦于可扩展性和各业务领域的持续增长，同时确保新用例的开发与整个组织的数据战略保持一致。在此期间，关键在于向领导层及各业务领域汇报进展，以维持对项目的信心。

Foundry 项目团队是什么样的？

  • Foundry 项目团队应配备强有力的团队，负责管理用例实施、与业务团队之间的反馈循环（以将新需求和项目纳入路线图），以及数据集成和本体论维护。本阶段的重点应是为平台管理建设专门的资源配置；在此之前，平台管理通常由项目团队之外的 IT 和技术团队负责。
  • 将平台管理职责纳入项目团队，并配备专门资源负责 IT 服务、权限管理和技术合规等领域，使项目团队能够按照项目的整体战略和目标来运营 Foundry 平台。
  • 专门的平台管理团队可确保拥有具备 Foundry 平台设置与运营专业知识的专职人员；这些主题专家能够在平台内部及其与更广泛业务 IT 基础设施的连接中，规划、构建并修复 IT、权限和合规方面的问题。项目内的平台管理创造了自主性，并为下一阶段解锁了全新水平的可扩展性。
  • 此外，在此阶段，Foundry 的使用应达到需要建立内部支持结构的程度。每个组织的用例和工作流都是独一无二的，因此内部支持团队应作为第一道防线，负责对问题进行分诊、解决问题并解答疑问。由内部承担支持职责还能形成强大的反馈回路，融入规划和维护流程，供数据和实施团队在 Foundry 中进行构建时加以利用。

我们如何聚焦资源投入？

  • 物色一位得力的平台负责人，此人应能够成功组建并领导团队，并与组织更广泛的 IT 部门保持紧密联系。这一角色对于 Foundry 计划中平台团队的成功至关重要；平台负责人必须了解组织现有的 IT 架构和流程，并根据组织的期望为 Foundry 制定平台管理流程。此外，他们还必须熟悉 Foundry 成本管理、围绕平台成本的报告结构，以及权限管理要求和最佳实践。
  • 开始组建支持团队。利用培训和教育资源，确保建立调查和问题修复的 SOP，并围绕支持问题制定监控和指标。组建一个内部支持团队，使其能够与数据团队和实施团队保持紧密关系，目标是根据内部用户反馈，随时间推移持续改进组织对 Foundry 的使用。
