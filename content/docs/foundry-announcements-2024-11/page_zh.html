使用 Cipher 中的视觉混淆算法保护敏感图像数据 [GA]

发布日期：2024-11-21

该 视觉混淆 算法现已正式发布，当您 创建 Cipher 通道 时，即可对图像的部分区域进行可逆混淆。作为 Foundry 的核心安全与治理服务，Cipher 使用户能够通过加密操作来混淆数据，而这些操作的管理通过 通道，用于描述加密框架的特定协议。与传统的图像脱敏不同，视觉混淆算法具有可交换性和可逆性，并通过打乱 RGB 像素值来遮蔽图像的部分内容。用户可以使用相应的 Cipher 许可证 来控制使用通道中所定义加密操作的权限。此外，您可以在 Python 转换 中使用视觉混淆算法，对整个图像或包含敏感内容的图像部分进行脱敏。

在创建新的 Cipher 通道时，视觉混淆算法现已正式可用。

媒体集 是支持各种 Foundry 工作流的关键数据资产。媒体集中包含的图像与表格式文本数据类似，通常需要通过细粒度的数据治理来严格保护其潜在的敏感内容。视觉混淆的可逆性为图像的敏感内容提供了额外层级的数据最小化和权限管理，因为通过 Cipher 解密许可证 可以恢复图像中被混淆的部分。用户可以将图像作为单一数据资产在不同访问组之间共享以供分析——某一组的用户可能能够查看图像的原始内容，而另一组的用户则只能查看默认已对敏感区域进行混淆处理的图像。

应用视觉混淆以提升图像安全性和访问能力

管理员可以配置视觉混淆解密许可证，以对解密频率施加限制。管理员还可以要求用户 提交检查点 作为查看敏感图像的正当理由，该检查点会收集图像交互的记录。

例如，一名接受过汽车受损区域标注培训的用户，可以通过查看将敏感区域（如车牌和显示车内情况的车窗）进行混淆处理的汽车图像来完成其工作流程。另一名接受过客户支持培训的用户可以访问同一图像并解密车牌区域，以确认该车辆属于特定客户。此外，管理员可以验证该客户支持用户的交互是否符合解密许可证所规定的数据治理策略。

用户可以应用视觉混淆算法来遮蔽图像中可能敏感的区域。图像来源： Car Parts and Car Damages ↗ 基于 CC0 许可证提供。

如何以及何时使用视觉混淆

自测试版发布以来，Foundry 用户已将视觉混淆与对象检测模型结合使用，在人工访问图像之前识别并遮蔽其中可识别个人身份的属性，从而减少分析工作流程中的偏差。您应使用 PNG 文件，因为其他图像文件类型在加密和解密过程中可能不支持像素扰乱。

您可以使用视觉混淆来：

  • 在将图像提供给 OCR（光学字符识别）或文本提取模型之前，遮盖图像中包含 PII（个人身份信息）或 PHI（受保护健康信息）的部分。
  • 通过对某些部分进行选择性混淆来降低图像的敏感度级别，从而扩大用户访问范围以支持分析。
  • 隐藏可能在工作流程中引入偏差的图像部分，并要求提供合理理由才能显示被混淆的部分。
  • 增加一层额外保护，以防范可能的数据泄露或权限配置错误。
  • [测试版] 使用 Workshop 中的 Image Display 小部件与混淆后的图像进行交互，如下所示。

经过视觉混淆的窗口区域可以在 Workshop 中使用 beta Image Display 小部件进行选择和解密。

如果您的 Foundry 注册环境当前尚未安装视觉混淆功能，请联系您的 Palantir 代表进行安装。

如需了解更多信息，请查阅 Cipher 的 视觉混淆文档。

推出项目组合（Portfolios）：一种组织项目的新方式 [GA]

发布日期：2024-11-21

我们很高兴推出项目组合（Portfolios）——一种组织项目的新方式。空间的编辑者可以将项目添加到项目组合中，创建一个汇集数据集、应用程序和其他重要资源的一站式目录。这对于拥有大量项目的注册环境尤其有用，因为管理员可以策划几个项目组合供用户浏览，而不是让用户面对数百个项目。

项目组合可以通过多种方式对项目进行分组。管理员可以策划项目组合来表示：

  • 业务单元或部门。该团队监管下的所有资源归入一组，方便用户浏览和发现。
  • 特定产品或工作流。产品或工作流的所有资源都汇集到单一视图中，同时保持各项目的关注点分离，这些项目分别负责数据集成、分析和运营应用程序。

针对不同用例的项目组合示例。

每个项目组合包含多个项目，但每个项目最多只能属于一个项目组合。任何有权访问空间的用户都可以查看该空间的项目组合，但用户仍需单独获得权限才能查看项目组合内的项目。

包含四个项目的示例项目组合。

已添加到项目目录或集合中的重要资源会显示在项目组合目录中，便于访问。

项目组合的主要功能

  • 用户可以轻松发现并导航至其工作方向中的项目。
  • 用户可以按项目组合查看项目，无需再一次性浏览整个项目列表。
  • 项目组合为构成一个工作区域的所有项目提供统一视图。

更多信息，请参阅 项目组合文档。

我们很高兴地宣布,在所有注册中,您现在都可以直接在 Pipeline Builder 用户界面中创建和配置数据源并同步数据集。

导入数据源的两种新方法

您现在可以轻松地将任何 Data Connection 数据源导入到您的 Pipeline Builder 管道中。有两种方法:如果您的输入数据是通过 Data Connection 同步创建的,您可以通过选择输入数据节点并使用 将数据源添加到图中 选项,将该数据源添加到 Pipeline Builder 图中。

该 “将数据源添加到图中”选项 可让您轻松导入任何 Data Connection 数据源。

或者,您也可以使用 添加数据 工具栏按钮或 将数据导入 Foundry 操作来搜索、导入或创建数据源。请选择 将数据导入 Foundry,然后选择要创建的新数据源类型,或搜索要连接的现有数据源。

从多种选项中进行选择,将您的数据引入 Foundry。

总体而言,这提升了集成各种数据源的便捷性。这确保您无需经历漫长的配置过程即可快速连接并使用您的数据,从而提高数据操作效率并缩短设置时间。

直接输入源配置

使用“配置源”部分输入源特定配置。

这通过将所有必要的配置与数据管道逻辑集中在一起来简化源的创建，从而确保最佳的数据流。

通过集成的同步创建功能提升专注度

在管道构建器中直接探索源并为批处理数据集创建同步的功能显著增强了您的数据管理能力。此功能使您能够轻松识别和同步所需的数据，提高数据可访问性并确保您的数据集保持最新状态。简化的同步流程意味着您可以专注于利用数据，而不是管理数据。

Compute Modules 应用程序位于 「配置」 页面。

主要功能

计算模块直接面向开发人员而构建，提供多种重要功能，让您在使用自己的逻辑和首选语言的同时，充分利用 Foundry 的各项功能：

  • 自定义 API 和函数： 设置您自己的 API 和函数，以便在 Workshop、 Slate、 本体论 SDK 应用程序和其他 Foundry 环境中无缝使用。
  • 动态与预测性水平扩展： 如果您预计需处理的请求数量会发生变化，计算模块可根据当前和历史负载增加或减少可用副本的数量，从而确保更高的可用性。
  • 内部连接： 使用 Foundry API 端点创建跨产品的复杂 Foundry 编排，涵盖数据集、本体论资源、调度任务和构建。
  • 外部连接： 编写自定义逻辑，利用外部系统支持的任意协议（例如 REST、WebSockets 和 SSE）以编程方式建立到这些系统的连接。
  • 无停机升级： 更新计算模块时不会产生任何停机时间。
  • 与 Marketplace 兼容： 计算模块可以发布到 Marketplace，以便其他人利用您的工作成果。

实际应用

开始使用计算模块后，即可利用它来拓展关键工作流的潜力：

  • 实时数据流传输： 连接到任意数据源，并将数据实时摄取到流、数据集或媒体集中。
  • 快速代码集成： 引入使用 任何 语言编写的关键业务代码，无需翻译。使用这些代码来支撑管道、Workshop 模块、AIP Logic 函数或自定义本体论 SDK 应用程序。
  • 模型部署： 托管来自 Hugging Face ↗等平台的自定义模型或开源模型；可在管道中调用它们，或将其作为函数调用。
  • 第三方集成： 引入来自其他公司的重要专有逻辑，并为这些公司提供在 Marketplace中销售其产品的机会。

Palantir 平台是由本体论驱动的现代企业操作系统，如今它还配备了强大的开发者工具，让用户能够以编程方式与平台交互。除了现有的正式发布功能、API 和 SDK 之外，我们还推出了新的测试版功能，并将在未来数周和数月中持续扩展我们的开发者工具套件，这是我们致力于构建契合您业务和运营需求的开发生态系统的一部分。

本体论 API 和 SDK

Palantir 平台作为开发生态系统的基础是 本体论。借助本体论，您无需在脑海中维护数据表或数据源的心智模型；相反，您可以围绕对您的运营至关重要的现实世界对象和概念进行思考。由此形成的开发生态系统中，对象和方法即是您的业务运营，您只需极少的代码即可对本体论进行读写。

为了充分发挥本体论在大规模查询和细粒度治理控制方面的强大能力，我们提供了本体论 API 和 SDK ，可将您组织的概念置于核心位置。例如，如果您需要管理机场的降落时段，请添加一个 Airport 对象和一个 landingSlots 关联到您的本体论，我们的 SDK 将基于您的特定本体论生成类型和函数，供您在平台上的各类应用程序中使用。

全新的 Palantir 平台 API 和 SDK

我们收到了大量来自工作依赖 Palantir 平台的用户反馈，我们正在大力投入开发者工具建设，以支持这些用户并创造使用 Palantir 平台进行构建的新方式。为便于支持这些用户工作流，除现有的本体论 API 外，我们现在还提供可通过编程方式管理平台访问权限以及支撑您本体论的数据的 API。

这些 API 包括：

  • 数据集
  • 用户
  • 群组
  • 构建 [测试版]
  • 调度 [测试版]

Beta 平台 SDK 也支持 Python ↗ 和 Typescript ↗。这些 SDK 可与本体论 SDK 一起使用，并共用相同的 Palantir 平台客户端，但需要一个未绑定到本体论的 Developer Console 应用程序。这些 Beta SDK 的文档即将推出；目前，早期采用者可以使用各代码仓库中的 README 入门。

模块化开发者工具

除 API 和 SDK 外，我们还提供模块化开发者工具，为您提供构建强大应用所需的一切，这些应用可充分利用本体论和其他 Palantir 平台功能：

  • Developer Console： 帮助用户使用我们的 SDK 和 OAuth 客户端开发能够充分利用 Palantir 平台的应用程序。
  • Web 托管： 允许开发者将使用我们的 SDK 构建的纯前端应用程序托管在 Palantir 平台上，从而无需额外的托管基础设施。
  • 应用程序专属文档： 每个本体论 SDK 应用程序均附带根据 SDK 内容定制的 API 文档。
  • 托管的 Git 仓库： 代码仓库应用程序提供了一个基于 Web 的集成开发环境（IDE），用于编写生产级代码并开展协作，同时以用户友好的方式与底层 Git 仓库进行交互。

这些开发工具的模块化特性使用户能够按需选用所需功能，并将其与现有工具和工作流程相结合，从而提供灵活性并促进无缝集成。
