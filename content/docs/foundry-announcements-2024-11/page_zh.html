使用 Cipher 中的视觉混淆算法保护敏感图像数据 [GA]

发布日期：2024-11-21

直方图 视觉混淆 算法现已正式发布，您可以在 创建 Cipher 通道 时使用该算法对图像的局部进行可逆混淆。作为 Foundry 核心的安全与治理服务，Cipher 使用户能够通过由 通道管理的加密操作来混淆数据，通道描述了加密框架的特定协议。与传统的图像涂黑不同，视觉混淆算法是可交换且可逆的，它通过打乱图像的 RGB 像素值来遮蔽图像的局部。用户可以使用相应的 Cipher 许可证 对图像进行加密和解密，这些许可证控制着使用通道中定义的加密操作的权限。此外，您还可以在 Python 转换 中使用视觉混淆算法，对整个图像或包含敏感内容的局部进行涂黑处理。

创建新的 Cipher 通道时,视觉混淆算法现已正式发布。

媒体集 作为关键数据资产,为各种 Foundry 工作流提供支持。媒体集中包含的图像与基于表格文本的数据一样,通常需要通过细粒度的数据治理对其潜在敏感内容进行严格保护。视觉混淆的可逆性为图像敏感内容提供了额外的数据最小化和权限管理级别,因为通过 Cipher 解密许可证 获得必要访问权限的用户可以恢复图像中被混淆的部分。用户可以在不同的访问组之间共享同一图像作为单一数据资产进行分析——一个组中的用户可以查看图像的原始内容,而另一个组中的用户默认只能查看敏感区域被混淆后的图像。

应用视觉混淆以提升图像安全性和访问控制

管理员可以配置视觉混淆解密许可证,以限制解密频率。管理员还可以要求用户 提交检查点 作为查看敏感图像的正当理由,该操作会收集图像交互的记录。

举例来说,经过培训可标记汽车受损区域的用户可以通过查看敏感区域(如车牌和显示车内部的窗户)被混淆的汽车图像来完成其工作流。另一位经过培训可提供客户支持的用户可以访问同一图像并解密车牌区域,以确认该车辆属于特定客户。此外,管理员可以验证客户支持用户的交互是否符合解密许可证规定的数据治理策略。

用户可以应用视觉混淆算法来模糊图像中可能敏感的区域。图像来源: Car Parts and Car Damages ↗ 根据 CC0 许可证提供。

如何以及何时使用视觉混淆

自测试版发布以来,Foundry 用户已将视觉混淆与对象检测模型结合使用,在人工访问之前识别并模糊图像中个人可识别的属性,从而减少分析工作流中的偏差。您应使用 PNG 文件,因为其他图像文件类型在加密和解密过程中可能不支持像素扰乱。

您可以使用视觉混淆来:

  • 在将图像提供给 OCR(光学字符识别)或文本提取模型之前,对包含 PII(个人可识别信息)或 PHI(受保护健康信息)的图像部分进行脱敏处理。
  • 通过对特定部分进行选择性混淆来降低图像的敏感级别,从而扩大用户访问范围以支持分析。
  • 隐藏可能在工作流中引入偏差的图像部分,并要求提供正当理由才能显示被混淆的部分。
  • 增加一层额外保护,以防止可能的数据泄露或权限配置错误。
  • [测试版] 使用 Workshop 中的图像显示(Image Display)小组件与被混淆的图像进行交互,如下所示。

使用 Workshop 中的测试版图像显示小组件选择并解密已被视觉混淆的窗户区域。

如果您的 Foundry 注册中目前无法使用视觉混淆,请联系您的 Palantir 代表进行安装。

有关更多信息,请查阅 Cipher 的 视觉混淆文档.

发布日期：2024-11-21

我们很高兴地推出 Portfolios(项目组合),一种组织项目的新方式。空间的编辑者可以将项目添加到项目组合中,以创建数据集、应用程序和其他重要资源的一站式目录。这对于拥有大量项目的注册环境尤其有用,因为管理员可以精心策划几个项目组合供用户浏览,而不是数百个项目。

项目组合可以通过多种方式对项目进行分组。管理员可以策划项目组合来表示:

  • 业务单元或部门。该团队监管下的所有资源被归组在一起，方便用户浏览和发现。
  • 特定的产品或工作流。该产品或工作流的所有资源被汇集到单一视图中，同时保持各 Project 的关注点分离，分别处理数据集成、分析和运营应用。

针对不同用例的 Portfolios 示例。

每个 Portfolio 包含多个 Project，但每个 Project 最多属于一个 Portfolio。任何有权访问 Space 的用户都可以查看其中的 Portfolios，但用户仍需单独获得权限才能查看 Portfolio 内的 Projects。

包含四个 Project 的 Portfolio 示例。

已添加到 Project 目录或集合中的重要资源会出现在 Portfolio 目录中，便于访问。

Portfolios 的主要功能

  • 用户可以轻松发现并浏览其工作范围内的的工作流中的 Projects。
  • 用户可以按 Portfolio 查看 Projects，无需一次性浏览整个 Project 列表。
  • Portfolios 为构成一个工作区域的所有 Projects 提供单窗格视图。

Palantir 平台现已成为一个功能完备的开发生态系统

发布日期：2024-11-04

Palantir 平台是由本体论驱动的现代企业操作系统，现在配备了强大的开发者工具，允许用户以编程方式与平台交互。除了现有的正式发布功能、API 和 SDK 之外，我们还发布了新的测试版功能，并将在未来几周和几个月内继续扩展我们的开发者工具套件，这是我们致力于打造满足您的业务和运营需求的开发生态系统的一部分。

本体论 API 和 SDK

Palantir 平台作为开发生态系统的基础是 本体论。借助本体论，您无需维护表或数据源的心智模型；相反，您可以用对您的运营至关重要的现实世界对象和概念来思考。这使得开发生态系统中的对象和方法就是您企业的业务运营，您可以用最少的代码对本体论进行读写。

为了利用本体论执行大规模查询和细粒度治理控制的强大能力，我们提供本体论 数据集端点 和 SDK ，将您组织的概念置于核心位置。例如，如果您需要管理机场的降落时段，可以向您的本体论添加一个 Airport 对象和一个 landingSlots 关联，我们的 SDK 将根据您的特定本体论生成类型和函数，可在平台的各个应用中使用。

新的 Palantir 平台 API 和 SDK

我们收到了大量来自工作依赖 Palantir 平台的用户的反馈，我们正在大力投资开发者工具以支持这些用户，并创造使用 Palantir 平台进行构建的新方式。为了支持这些用户工作流程，我们现在提供支持以编程方式管理平台访问权限以及支撑本体论的数据的 API，以及现有的本体论 API。

这些 API 包括：

  • 数据集
  • 用户
  • 组
  • 构建 [Beta]
  • 计划 [Beta]

测试版平台 SDK 也可用于 Python ↗ 和 Typescript ↗。这些 SDK 可与本体论 SDK 配合使用，采用相同的 Palantir 平台客户端，但需要一个未绑定到本体论的 Developer Console 应用程序。这些测试版 SDK 的文档即将推出；目前，早期采用者可以使用各代码仓库中的 README 开始使用。

来自 AIP Assist 的按需开发者支持

AIP Assist 配备了 Developer Assist（开发者助手）模式，该模式旨在提供即时、量身定制的协助，以支持开发工作。从 11 月 11 日当周开始，Developer Assist 将直接从平台 API 参考文档中提供深入的解释和示例，帮助开发者充分利用我们的功能和 API。Developer Assist 包含 AIP Assist 用于加速您工作流程的各项功能，包括多语言支持、用户友好的界面，以及基于用户反馈的迭代改进。

模块化开发者工具

除 API 和 SDK 外，我们还提供模块化开发者工具，为您提供构建强大应用所需的一切，这些应用可利用本体论和其他 Palantir 平台功能：

  • Developer Console（开发者控制台）： 帮助用户使用我们的 SDK 和 OAuth 客户端开发利用 Palantir 平台的应用。
  • Web 托管： 允许开发者将使用我们的 SDK 构建的纯前端应用托管在 Palantir 平台上，无需额外的托管基础设施。
  • 应用专属文档： 每个本体论 SDK 应用都附带根据 SDK 内容定制的 API 文档。
  • 托管的 Git 仓库： Code Repositories 应用提供了一个基于 Web 的集成开发环境（IDE），用于编写和协作开发可用于生产环境的代码，并以用户友好的方式与底层 Git 仓库进行交互。
  • 托管的 Visual Studio Code： VS Code Workspaces 在 Palantir 平台上提供了一个用于编写和协作开发可用于生产环境代码的 IDE。

这些开发者工具的模块化特性允许用户按需使用，并与现有工具和工作流程相结合，提供了灵活性并促进无缝集成。
