管理已发布的函数

发布后，所有类型的函数都可以在 Ontology Manager 中查看和管理。

搜索函数

要搜索函数，请导航至 Ontology Manager 并选择 函数 选项卡。 您可以使用函数的大部分元数据来搜索函数，包括但不限于函数名称、描述、API 名称和 RID。

函数概览页面

在 Ontology Manager 中，选择一个函数以查看其输入、输出、使用历史记录以及 函数指标，包括成功和失败次数以及 P95 执行时长。

函数配置页面

某些类型的函数允许您配置超时或内存限制等资源。 如果您的函数支持任何配置选项，您可以在 配置 选项卡中查看并编辑这些选项。 如果此选项卡不存在，则该函数不支持任何配置选项。

配置覆盖按函数版本应用。根据您发布函数时所使用的应用程序，新版本可能采用默认配置，您可能需要重新应用已有的配置覆盖。

配置继承

函数为在发布新版本时继承配置覆盖提供了开箱即用的支持。根据语义化版本规范，配置将从上一个稳定版本继承。如果发布的是非稳定版本，则配置将从上一个版本继承，而无论该版本是否为稳定版本。

配置继承要求您的仓库包含已更新的模板配置。您可以查看隐藏的 templateConfiguration.json 文件，以确认您的仓库所处的版本。

  • 对于 TypeScript v1 函数仓库，您必须拥有 parentTemplateVersion >= 3.512.0
  • 对于 Python 函数仓库，您必须拥有 parentTemplateVersion >= 0.423.0

一致性快照

基于函数的操作会在单次运行中自动为所有读取请求使用同一个本体论快照。

一致性快照提供以下特性：

  • 数据一致性： 在没有快照的情况下，如果底层数据在请求之间发生了变化，函数内的连续本体论查询可能会返回不同版本的数据。使用快照时，您的函数将在一致的本体论视图上运行，这类似于数据库事务中的快照隔离。
  • 性能提升： 在所有本体论请求中重用单个快照可显著提升本体论读取性能。单个基于函数的操作以及其中的任何查询都将获得此优势。

快照配置

如果需要为高级用例显式管理快照，可以在 函数配置页面 上使用以下选项配置快照行为：

  • 默认（推荐）： 除非遇到与快照相关的错误，否则请保持选择此选项。
  • 禁用快照： 在需要运行期间每次查询都获取最新数据，或因长时间运行的工作负载而遇到快照错误时使用。
  • 启用快照： 在需要对所有读取操作保持一致的时间点视图、希望获得更好的读取性能，且函数可以容忍数据在运行期间不更新时使用。大多数用例不建议使用此选项。

默认情况下，带有数据源的函数会基于实时数据运行，而不使用快照。不建议强制使用快照，因为函数可能会执行写入操作或调用外部系统。

强制限制

已设置多项限制，以防止函数在执行时消耗过多资源。

时间限制

默认情况下，函数的已用运行时间限制为 60秒 。这些限制可以在 函数配置页面上修改。

在实时预览中运行时，函数最多可以运行 280秒 ，即使已在函数配置页面上修改了限制。

通过 Automate 执行的函数将以异步方式运行，最长可运行 4 小时，超出标准执行限制。

TypeScript v1 函数还受到 30 秒 CPU 时间的限制，该限制不可配置。当函数超过此阈值时，原因通常是数据加载逻辑效率低下。请参阅 优化性能 部分，了解如何避免 CPU 超时的技巧。

内存限制

TypeScript v1、TypeScript v2 和 Python 函数的内存限制各不相同。

TypeScript v1

函数执行限制为 128 MB 的内存使用量。很少会达到此限制；通常，函数会先遇到时间限制或对象加载限制，之后才会遇到内存限制。

已部署的 Python 函数

已部署的 Python 函数默认具有 2 GB 的内存使用量。目前，已部署的 Python 函数无法在函数配置页面上配置内存使用量。

无服务器 Python 和 TypeScript v2 函数

无服务器函数默认具有 1024 MiB 的内存使用量。可在 512 MiB 到 5120 MiB 之间进行配置，此配置在 函数配置页面上完成。

多线程

对于 TypeScript v1，函数执行在单线程上进行，任意时刻只能执行一项计算。但是，您可以并行加载对象集或关联。请参阅 优化性能 以了解更多信息。

对于 TypeScript v2 和 Python 函数，您可以将多线程与内置的 Node.js worker_threads 和 Python threading 库结合使用。

TypeScript v1 的对象集限制

使用 对象集时，调用 .all() 或 .allAsync() 在以下情况下将抛出错误：

  • 超过 100,000 个对象 一次性从对象集中加载。一般来说，即使加载数万个对象也会遇到时间限制或内存限制。如果您的用例遇到此限制，请考虑使用 聚合 获取摘要数据，或使用 排序和限制获取对象的子集。
  • 超过 3 次搜索周边（search around） 同时使用。

某些聚合和分桶操作存在限制。请参阅 聚合 部分了解详情。
