AIP Logic 分支

AIP Logic 与 Global Branching 集成，支持对 Logic 函数进行安全、隔离的开发。本文档介绍如何在分支上使用 Logic，包括添加和修改资源、跨应用兼容性、变基以及审批流程。

有关 Global Branching 概念和工作流程的一般信息，请参阅 Global Branching 文档。

添加、移除和修改资源

将 Logic 函数添加到分支

要将 Logic 函数添加到分支：

  1. 导航到分支上的 Logic 文件，或使用页面右上角的分支选择器选择指定的分支。
  2. 对 Logic 文件进行编辑并保存。该 Logic 函数现在已作为资源保存到分支上。

移除 Logic 函数

要从分支中移除 Logic 函数，请使用右下角的侧边栏并选择 从分支中移除。

修改 Logic 函数

要修改分支上的 Logic 函数，只需像在主分支上一样进行任意更改并保存。

在分支上发布

您可以按照与在 main 上相同的流程在分支上发布 Logic 函数。在分支上成功发布函数后，您便可以在 Workshop 和函数支撑的操作中使用该分支上的新函数版本。此函数版本带有 Branched pre-release 标签。请注意，在您的分支上发布的函数将无法从其他分支访问，包括 main。

跨应用程序兼容性

使用分支版 Logic 函数

分支版 Logic 函数可与以下内容配合使用：

  • 本体论对象： 函数可以与同一分支上的本体论对象进行交互。
  • 其他支持分支的应用程序： 任何使用 Logic 函数并支持分支的 Foundry 应用程序（例如 Workshop）。

合并要求

可部署性检查

Logic 函数必须满足以下条件才能部署：

  • 与 main 分支保持最新（无需 rebase）
  • 已在分支上发布
  • 处于可发布状态（无错误）
  • 没有待处理的审批

审批与审阅者流程

受保护的主分支

您可以保护主分支，以禁用 Logic 函数在 main上的直接编辑。启用保护后，所有更改都必须在分支上进行，经审阅后通过提案流程合并。

要保护分支，请在 Compass 中导航到相应资源并选择 分支保护 > 使用项目策略进行保护。

若要默认保护项目中的所有 Logic 文件，请在项目级别启用保护。在该项目中创建的任何新 Logic 文件都将自动受到保护。

审阅者体验

创建提案后，即可在 Global Branching 应用程序中将审阅者添加到 Logic 文件。被添加为审阅者的用户将收到一封请求其审阅的电子邮件，其中包含指向该提案的链接。

从那里，审阅者可以：

  • 通过选择文件右上角的 审阅 选项，即可访问审阅页面。当 Logic 函数需要审阅时，此选项可见。
  • 查看并排对比： main 与分支更改。
  • 查看对 Logic 函数的所有修改。
  • 批准或拒绝更改。
  • 编辑其评审。

变基与冲突解决

如果自您的分支创建或上次变基以来，主分支已被修改，则需要进行变基。如果您的 Logic 函数需要变基，您将在 Logic 文件的顶部看到一条通知。

如何变基

  1. 导航到需要变基的 Logic 函数， 然后选择 Rebase 选项。

  2. 在分屏对比视图中查看变更。 左侧显示当前 main 版本，右侧显示您的分支版本。

  3. 进行必要的修改 到您的分支，并可能合并来自 main 如果存在合并冲突。

  4. 完成变基 通过选择 完成。

已知限制

  • 分支只能创建自 main。您无法从其他分支创建分支。
  • 在分支上无法更改 API 名称。跨分支的所有 Logic 函数均共享相同的 API 名称。
  • 在分支上时，无法删除已发布的 Logic 函数。
  • 合并冲突的解决需要人工干预。在变基过程中发生冲突时，您必须使用分屏对比视图，手动将来自 main 的更改合并到您的分支版本中，并在完成变基之前解决所有冲突的修改。
