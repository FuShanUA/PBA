1. 创建并优化时间序列输入数据

时间序列同步可以基于以下任一方式构建 数据集 or 流。此选择通常取决于吞吐量和延迟方面的考虑。请查看 流式处理与批处理的比较 以获取更详细的分析。

在这两种情况下，当您手动设置管道时，必须显式生成包含格式化后 时间序列 数据的时间序列数据集或流；这是创建时间序列同步所必需的。数据集或流必须包含 Series ID, Value日 Timestamp 列，具体规范见 术语表 以便这些值可以在时间序列同步中进行映射。

数据集时间序列

时间序列数据集通常配置为在有实时数据时进行 以增量方式 增量构建。增量构建可以节省计算成本，并大幅缩短从原始数据摄取到可读取最新数据之间的延迟， 时间序列常见问题解答 对此有更详细的说明。

同一序列 ID 的所有值应包含在同一个数据集中。由于值是通过其序列 ID 获取的，因此单个时间序列数据集可以包含多个序列 ID 的所有值。例如：

+------------------------+---------------------+---------+
| series_id              | timestamp           | value   |
+------------------------+---------------------+---------+
| Machine123_temperature | 01/01/2023 12:00:00 | 100     |
| Machine123_temperature | 01/01/2023 12:01:00 | 99      |
| Machine123_temperature | 01/01/2023 12:02:00 | 101     |
| Machine463_temperature | 01/01/2023 12:00:00 | 105     |
| Machine123_pressure    | 01/01/2023 12:00:00 | 3       |
| ...                    | ...                 | ...     |
+------------------------+---------------------+---------+

package myproject.datasets;

import com.palantir.transforms.lang.java.api.Compute;
import com.palantir.transforms.lang.java.api.FoundryInput;
import com.palantir.transforms.lang.java.api.FoundryOutput;
import com.palantir.transforms.lang.java.api.Input;
import com.palantir.transforms.lang.java.api.Output;
import com.palantir.foundry.spark.api.DatasetFormatSettings;
import org.apache.spark.sql.Dataset;
import org.apache.spark.sql.Row;

import java.util.Collections;

public final class TimeSeriesWriter {
    @Compute
    public void writePartitioned(
            @Input("/path/to/input/dataset") FoundryInput inputDataset,
            @Output("/path/to/output/dataset") FoundryOutput outputDataset) {
        Dataset<Row> inputDataframe = inputDataset.asDataFrame().read();

        Dataset<Row> outputDataframe = inputDataframe
            .repartitionByRange(inputDataframe.col("seriesId"))
            .sortWithinPartitions("seriesId", "timestamp");

        outputDataset.getDataFrameWriter(outputDataframe)
            .setFormatSettings(DatasetFormatSettings.builder()
                .format("soho")
                .build())
            .write();
    }
}

运行此重新分区和排序将优化您的数据集，使其作为时间序列使用时具有高性能。至少，您的数据集也应格式化为 Soho （如所示），以便在数据 尚未投影时，新数据可以被索引到时间序列数据库。您还应根据以下指导原则，将 repartitionByRange() ↗ 写入的分区数量配置为适合您管道的数值：

  • 尽可能少地写入分区。
  • 分区应大于 128 MB。
  • 通常，分区应少于 50 亿行。

可写入的最少分区数的限制取决于分区是否足够小以适应单个 执行器，同时分区数量又要足够多，使您的作业能够充分并行化，以满足您期望的管道延迟。写入更多分区会产生更小的分区和更快的作业，但不如较大的分区那样高效。

时间序列同步上的视图优化

同步大量数据时，我们建议使用离散的时间间隔（例如按小时、按天或按周分区）将数据分割为较小的数据集。然后，您可以将这些分区合并为一个统一的 视图 并可将其同步到时间序列。这种方法有助于在下游（FoundryTS 库或 Quiver 中）请求时间序列数据时确保良好的性能。较小的数据集最终会通过统一视图合并为单个时间序列同步。

由于视图包含所有分段的支撑数据集，因此允许序列 ID 分布或交错在不同的支撑数据集中。

您可以在时间序列同步的 高级设置.

中配置视图优化的使用。请按照以下步骤配置视图优化：

  1. 设置包含支撑序列数据集的视图。
  2. 将该视图用作您正在设置的时间序列同步的输入。
  3. 切换 索引视图数据集输入 中的 部分中选择 时间序列设置对话框中的部分。

流式时间序列

为了优化流式时间序列性能，我们建议采取以下步骤：

  • 使用 序列 ID 列为您的流设置键（keying）；这可确保平台在索引时间序列数据时从最少数量的分区读取数据。有关流式键的更多信息，请参阅 流式键文档.
  • 设置更多的 分区，对于吞吐量要求较高的流式时间序列同步，我们建议至少配置 3 个分区。

确保您的流仅使用 序列 ID 列作为键，而不使用任何其他列。这可确保时间序列索引的最佳排序保证。

流式管道

我们建议使用 流式管道来设置流式时间序列同步。您可以通过将时间序列同步设为管道的输出来实现。

  • 使用 Series ID 列为您的流设置键： 创建一个 按转换设置键 using 唯一 the Series ID column.
  • 设置分区数量： 自定义应用程序的 流式配置文件 under Build settings > Advanced configuration > Number of Output Partitions.

流式同步

配置流式时间序列输入的另一种方法是 设置流式同步.

  • 使用 Series ID 列为您的流设置键： 自动预览行为 Configuration > Keys，请选择 Series ID column.
  • 设置分区数量： 自动预览行为 吞吐量中，选择 非常高 并根据吞吐量要求选择一个值。

如果您的流已摄取记录，更改键或分区设置将需要 重置流.

2. 设置时间序列同步

如果您正在使用设置助手，请选择 前往 Builder.

请参阅 使用时间序列目录创建时间序列同步 以获取更多详细信息。

创建时间序列同步后，返回 Ontology Manager 并将该时间序列同步添加为时间序列属性的数据源。如果您的同步包含所有序列 ID，则可以为新的时间序列属性选择相同的同步，而无需创建新的同步。

请务必在 Ontology Manager 中选择 保存 以保存您的更改。如果您创建了新的对象类型且这是首次保存更改，则需要等待初始索引完成后才能分析 TSP。通过导航到 Ontology Manager 中该对象类型的 数据源 标签页来检查索引状态。

3. 创建时间序列对象类型支撑数据集

您可以通过您偏好的方法生成时间序列对象类型支撑数据集，该数据集应符合 词汇表中指定的架构.

要自动生成时间序列对象类型支撑数据集，您可以在与时间序列数据集相同的转换中生成它，在其中可以获取不重复的序列 ID 集合并从中提取/映射元数据。在增量管道中，您可以使用 合并与追加 模式来实现这一点。

4. 设置时间序列对象类型

端到端教程 标准流程 在您的时间序列对象类型支撑数据集上创建对象类型。也可以通过选择以下选项直接从数据集生成对象类型： 所有操作 > 创建对象类型 菜单中选择 ，并从。创建对象类型时，请通过指定哪些属性应为 时间序列属性.
