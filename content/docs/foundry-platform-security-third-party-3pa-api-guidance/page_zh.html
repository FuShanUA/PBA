Foundry 第三方应用程序与 API 指南

Foundry 的第三方应用程序身份验证和授权功能使非 Foundry 应用程序和脚本能安全地与 Foundry 的 API 进行交互。这些功能的核心是对外部应用程序的 OAuth2 支持。 本文档提供了 Palantir 关于如何使用这些功能的建议，以及可能不当使用场景的示例。

通过授权第三方应用程序和 API，用户同意遵守 Palantir 与客户以书面形式共同商定的适当使用条款。如果您对预期用途有任何疑问，或不确定您的计划是否适当、安全或可靠，请联系您的 Palantir 代表。

适当的使用场景

  • 替代服务用户账户
    • OAuth2 授权码流程允许外部应用程序代表单个 Foundry 用户执行操作。这可确保权限正确无误，并提供清晰的审计路径。使用 OAuth2 流程还可确保用户已明确授予应用程序代表其执行操作的权限，同样提供了清晰的审计路径。
    • 我们强烈建议现有使用服务账户在 Foundry 中执行操作的应用程序尽可能迁移到 OAuth2 授权流程。
  • 与外部系统对接
    • 示例：监控内部客户系统中的变更并在 Foundry 本体论中执行操作的应用程序。
  • 面向特定用户工作流的自定义应用程序
    • 示例：与 Foundry 的本体论和操作 API 交互的移动应用程序，为关键工作流提供简化的用户体验。
  • 监控或控制 Foundry 管道或工作流
    • 示例：连接到 Foundry 的监控和数据健康 API 以评估关键管道状态，并允许其用户在需要时触发构建的应用程序。

不当的使用场景

集成第三方应用程序以及使用 Foundry API 会带来数据安全风险，只有在充分理解技术和合同方面的考量后才应进行。在规划代表用户访问数据或执行操作的开发项目时，请联系您的系统管理员，以确定您的计划是否适当、安全、可靠，并符合 Foundry 适当使用条款。

以下示例概述了不当使用 API 访问数据或执行操作可能损害 Foundry 中管理的数据完整性或安全性的典型场景。

  • 规避数据控制
    • 示例：使用一个用户的令牌读取数据，再使用另一个用户的令牌写回。
    • Foundry 拥有先进且细粒度的用户授权功能。在您的应用程序中在用户账户之间共享数据可能会规避这些控制。
    • 保持各个 Foundry 账户的使用完全隔离非常重要。您不得使用一个用户的令牌访问数据，并允许另一个用户读取、发现、写入或以任何方式与该数据交互。如果您希望允许用户共享数据，应在 Foundry 中进行，而不是在第三方应用程序中。
  • 在用户不知情和未同意的情况下执行操作。
    • 您的应用程序不得欺骗用户。您的应用程序在使用 Foundry 用户账户时，必须清晰准确地描述其正在执行的操作。
    • 您的应用程序必须仅请求其执行功能所需的最小角色和权限集合，不得请求更多。此外，当将在 Foundry 中执行操作时，它还必须向用户明确说明这些操作将在何时执行以及这些操作将执行什么内容。
    • 任何不明确、意外、恶意或具有破坏性的应用程序行为都是被禁止的。
  • 在不考虑访问控制的情况下在 Foundry 之外检索或存储数据。
    • Foundry 的客户依赖 Foundry 安全地存储关键数据；您的应用程序必须尊重这些数据的敏感性和价值，并仅检索其执行功能所需的最少数据集。
    • 如果可能，您的应用程序还应避免存储或缓存从 Foundry 检索到的数据。一个可能的例外是离线缓存，但应谨慎处理并获得用户的明确同意。
    • 如果 Foundry 数据被移动到另一个数据存储系统中，请注意，这些数据将不再根据您组织在 Foundry 内的数据保护配置进行访问控制或审计。
