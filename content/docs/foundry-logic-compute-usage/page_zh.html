AIP Logic 中的计算用量

AIP Logic 是一款 Palantir 工具，可让您快速且可维护地构建由 LLM 驱动的流程，同时通过本体论和计算功能与您组织的数据进行交互。AIP Logic 围绕 LLM 指令"块"的概念构建，这些块可以线性组合，创建能够查询数据、执行操作和函数并为您的用例生成全新信息的思维链工作流。AIP Logic 以 LLM token、LLM 块执行和工具调用为单位衡量使用量。块和工具还可以运行本体论查询、操作和函数，这些会使用各自的计算秒数。

如果您与 Palantir 签订了企业合同，请在进行算力使用量计算之前联系您的 Palantir 代表。

核心概念：资源、块和工具

一个 AIP Logic 资源 由一个或多个 AIP Logic 区块组成。运行资源将运行实现所需输出所需的块。块可以使用 ，以及 例如本体论查询、函数和操作来产生输出。

使用 AIP Logic 度量 Foundry 计算

AIP LLM token

AIP 中的 LLM token 以底层模型的方式（例如 OpenAI ↗）进行度量，并取决于提示和响应的大小以及发出的提示数量。更多信息请查阅 各模型类型的用量表.

LLM 块执行

除 LLM token 用量之外，AIP Logic 还为每次 LLM 块执行和每次工具调用使用固定数量的计算秒数。这些费用是累加的：一个调用工具的 LLM 块会同时产生两种费用。

用法计算秒数适用情形
LLM 块执行4每次 使用 LLM 块运行时（无论是否调用工具）
工具调用8当 使用 LLM 块中的 LLM 调用工具时，在 LLM 块执行费用之外另行计费

LLM 会在运行时决定调用哪些工具以及调用的频率，因此一次块执行可能包含多次工具调用，每次调用单独计费。 使用 LLM 循环内的 循环 块在每次迭代中计为一次 LLM 块执行。要查看一次运行进行了多少次工具调用，请测试该函数并查看 调试器 面板中进行管理。

额外的 Foundry 计算用量

当 AIP Logic 块将计算联合到外部工具（例如本体论查询或函数）时，在执行这些应用程序期间可能会使用额外的计算。

管理 AIP Logic 对 Foundry 计算的使用

AIP Logic 中的某些操作可能会显著影响计算用量。下面，我们提供关于通过谨慎控制 token 用量Workshop 逻辑块执行总数以及 Foundry 计算.

  • Token 用量
  • 处理大量文本会显著增加整体计算用量。请注意与 LLM 一起使用的输入提示的大小。当从本体论中提取大型文本块时，这一点尤其重要。

要控制 token 用量，您应努力减少注入提示中的文本量，并确保提示本身仅包含相关文本。在处理大型文档时，这一点尤为重要。

  • 逻辑块执行总数
  • 运行许多逻辑块可能会使用大量计算，尤其是当这些块通过函数以编程方式触发时（即非由人工操作触发）。

Foundry 计算

  • 要控制逻辑块执行，请考虑将多个块合并到单个提示中（在适当的情况下），并且仅在必要时使用额外的块。操作、函数和数据转换块本身不会产生计算用量。
  • 对 Foundry 应用程序（例如本体论查询、函数或操作）进行大量调用可能会使用大量计算。如果逻辑资源需要多次重试，或在每次执行时调用许多函数或操作，则可能发生这种情况。
    • 要控制来自其他应用程序的计算用量，请确保您了解逻辑块链中对其他工具的调用次数。可以调用 Foundry 其他部分的潜在工具有：
    • 本体论查询
    • 操作执行
    • 函数执行

1 run = (2 LLM block executions * 4 compute-seconds) + (1 tool call * 8 compute-seconds)
1 run = 8 + 8 = 16 compute-seconds

2 runs = 2 * 16 compute-seconds = 32 compute-seconds

这两次运行共使用 32 计算秒数用于 LLM 块执行和工具调用。此金额不包括 LLM token 用量或操作本身使用的计算量。有关操作计算用量，请参见 本体论查询计算.

如果 LLM 在每次运行中调用该操作两次而不是一次，则每次运行将使用 (2 * 4) + (2 * 8) = 24 计算秒数，即两次运行共 48 计算秒数。
