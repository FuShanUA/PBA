设置通知

本教程演示如何设置一个带有通知的操作。

我们将使用一个操作来更新 Alert 对象的 Priority 属性，并通知 Assignee（一位 Foundry 用户），该用户作为属性存储在该 Alert 对象上。如果您想跟随本教程操作，您需要提前完成以下设置：

  • 一个具有正确属性并配置为可通过操作进行编辑的对象
  • 一个操作，该操作接收您的某个对象以及一个包含新优先级的参数，并更新指定对象上的优先级属性。如果您之前已经完成了操作入门教程，那么您应该已经完成了此设置。

如果您是初次接触对象管理，可以阅读如何设置对象类型相关内容。

前提条件

完成入门教程

本教程假定您已完成有关操作的入门教程。

向您的对象类型添加 assignee 属性

在本教程中，您需要在 Alert 对象上有一个名为 Case Managers 的属性，该属性包含当前被分配用户的 Foundry 用户 ID。通常，如果您使用操作来构建工作流，则可以通过应用程序中的用户选择器组件捕获并存储用户 ID。无论在 Foundry 中的何处显示，这些都会显示为完整的用户名。

添加通知

首先，导航到更新工单优先级的操作。在规则部分下，选择添加新规则，然后选择通知。这将打开用于添加通知的配置对话框。

配置收件人

在本示例中，您将把通知发送给受派人，该受派人作为正在编辑的 Alert 对象的一个属性进行存储。为此，请在收件人下拉列表中使用“来自对象参数属性的收件人”选项。选择可用作操作参数的 Alert 对象，然后在出现提示时选择 Case managers 属性。

您应会看到所选的对象参数和属性显示在配置的收件人部分。请记住，收件人必须始终是 Foundry 用户 ID。如果此属性包含其他内容（例如字符串形式的电子邮件地址），则不会发送任何通知。

为了进行测试，您最初可能希望为操作配置硬编码的收件人，以便验证逻辑和通知内容是否按预期配置。

详细了解其他收件人配置选项。

配置通知内容

接下来，您将配置通知的内容，自定义通知以按姓名称呼收件人，并在内容中包含Alert对象的新旧优先级。下方提供了一个通知配置示例。

首先，从内容选项中选择 "Template"。这是配置内容最直接的方式，无需编写任何代码。

对于主题行，输入您想要的消息。要添加参数引用，请输入正斜杠/，然后从下拉列表中选择所需的参数。如果您选择的是对象参数，系统会要求您选择要引用的属性。

对于正文，请输入按姓名称呼收件人、指明进行更改的用户并报告先前状态和更新后状态的文本。

与主题中的对象引用一样，您可以从下拉列表中选择 "Recipient"、"Current User" 以及任何参数选项，以生成对这些用户属性的正确引用。

了解如何生成满足更复杂要求的通知内容。

配置关联

最后，您将在 Object Explorer 中为指定的 Alert 添加一个指向其 Object View 的关联。选择“Object View”，然后从下拉菜单中选择您的工单对象参数。然后，为关联按钮添加标签，内容为 View Ticket。

发送测试通知

要进行验证，请创建一个将您自己指定为经办人的测试警报。为了运行该操作，您随后需要在 Object Explorer 中公开该操作，或通过 Workshop 模块中的按钮将其公开，如操作文档中所述。

完成测试更改后，您应会同时收到平台内推送通知以及发送至您 Foundry 用户个人资料中所指定电子邮件账户的电子邮件通知。平台内通知和电子邮件通知的预览均会显示在通知配置视图中。

如果您没有收到电子邮件，可能是因为您禁用了电子邮件和/或平台内通知。您可以在用户设置下的通知中进行验证。
