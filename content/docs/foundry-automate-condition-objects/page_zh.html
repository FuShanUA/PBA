对象集条件

当预定义对象集中的对象数据发生变化时，自动化效果可以自动触发。

数据源： 变更可以来自 支撑数据集, 操作类型（action types），或 外部应用程序.

评估频率： 数据变更通常会在几分钟内被捕获。 了解更多

效果输入参数： 某些对象集条件会公开效果输入参数。这些变量可以在效果内部使用，以访问触发自动化的对象。

可用条件

  • 已添加到集合的对象: 当新对象出现在集合中时触发。
  • 已从集合中移除的对象: 当对象离开集合时触发。
  • 集合中已修改的对象: 当集合中的对象被修改时触发。
  • 对所有对象运行: 定期对给定对象集中的所有对象运行效果。
  • 阈值跨越: 当指标阈值被跨越或函数返回 true 时触发。
  • 指标变更 [已弃用]： 当聚合指标增加或减少时触发。

对象集定义

大多数对象集条件类型需要指定要监视的对象集。您可以：

  • 动态定义对象集；
  • 选择已保存的对象集；或
  • 选择返回对象集的函数。
    • 函数是更高级地使用 Automate 的强大构建模块。

定义要监视的对象集后，选择 预览 以验证该对象集是否包含预期的对象。

动态定义对象集时，选择所需的对象类型，然后可以选择添加筛选器以缩小集合范围。例如，您可以监视 Support Ticket 对象类型（如下所示），并筛选为 "Status = Open"。未选择任何筛选器时，您将监视该类型的所有对象。对象类型和筛选器的选择决定了该对象集是可以实时监视还是按计划监视。 了解有关评估频率的更多信息.

条件类型

已添加到集合的对象

直方图 已添加到集合的对象 条件在每次有对象被添加到您的预定义对象集时触发。首先根据 对象集定义部分 部分。

指定对象集。如果您指定了对象集筛选器，其他用户的新对象或对象编辑可能会触发您的对象已添加到集合条件。在下面显示的示例中，我们监视一个 Support Tickets 的对象集，其状态属性值为 Open。该条件可以通过两种方式触发：创建一个状态为 Support Ticket 的新 Open 对象，或者一个现有的 Support Ticket 将其状态更改为 Open.

如果您未在对象集上指定任何筛选器，则实际上是在监视该类型的所有对象。这意味着只有当全新的对象被添加到本体论中时，自动化才会触发。

直方图 已添加到集合的对象 条件将触发条件的对象作为效果输入公开。这可以是单个 Added object、一个 Added objects的对象集，或 Added objects. 的属性。了解有关如何使用效果输入的更多信息。

支持 评估频率:

  • 实时评估
  • 计划评估

已从集合中移除的对象

直方图 已从集合中移除的对象 条件在每次有对象从您的预定义对象集中被移除时触发。首先根据 对象集定义部分 部分。

指定对象集。如果您指定了对象集筛选器，用户的对象编辑可能会触发您的对象从集合条件中移除。例如，如果我们监视一个 Support Tickets 的对象集，其状态属性值为 Open的对象集，那么当 Open 工单的状态更改为任何其他状态时，该条件将触发。

直方图 已从集合中移除的对象 条件会将触发该条件的对象作为效果输入公开。这可以是单个 Removed object 或一个对象集 Removed objects. 的属性。了解有关如何使用效果输入的更多信息。

支持 评估频率:

  • 实时评估
  • 计划评估

集合中已修改的对象

直方图 集合中已修改的对象 条件会在预定义对象集中的对象被修改时触发。使用此条件类型可监控对象集中任何属性值的变化。如果您只想监控对 特定 值的变化，请使用 对象添加到集 条件。

首先，根据 对象集定义部分 指定您的对象集。然后，您可以选择要监控的特定属性。如果未选择任何属性，被监控对象集中的任何属性变化都将触发自动化。

自动预览行为 同时在以下情况触发，您可以启用其他触发器：

  • 对象添加到集合： 当对象进入受监控的集合时触发，包括符合其筛选条件的新建对象。
  • 对象从集合中移除： 当对象离开受监控的集合但仍存在于本体论中时触发。
  • 对象从集合中删除： 当曾属于受监控集合的对象从本体论中被删除时触发。

当所有三个选项均被禁用时，仅对仍保留在受监控集合中的对象的修改才会触发自动化。

直方图 集合中已修改的对象 条件会将触发该条件的单个 Modified object 或一组 Modified objects 作为效果输入公开。 了解更多关于效果输入的信息。

支持 评估频率:

  • 实时评估

在下面的示例中，我们监控 Support Tickets 集中位置为 USA.

  • 包含添加的对象： 已启用。 添加到对象集中的对象被视为已修改。因此，一个 Support Ticket 将其位置从 UK to USA 更改的将触发自动化，任何位置为 USA.
  • 包含移除的对象：已禁用。状态属性从 Open to Closed 变化而位置同时变化（例如，从 USA to UK）的工单不会触发自动化，因为这些对象已离开该集。
  • 已删除的 Support Tickets 不会触发自动化，因为它们已不在被监控的对象集中。

对所有对象运行

直方图 对所有对象运行 条件可以定期对给定对象集中的所有对象运行效果。此条件与计划结合配置。

使用此条件时，可以设置受影响的对象参数，以将对象注入任何效果。使用此条件时会遵循批处理大小和并行化设置。此条件允许您对大量对象运行效果，同时避免函数或操作超时，因为批处理将被自动处理。

支持 评估频率:

  • 计划评估
  • 依赖于自动化的评估

阈值跨越

直方图 阈值跨越 条件会在所有定义的检查返回 true时触发。每当阈值在任一方向被跨越时，都会触发效果并记录活动。

您可以组合由 Automate 定义的逻辑, 函数支持的逻辑或两者组成的条件。

支持 评估频率:

  • 计划评估

Automate 定义的逻辑

要在 Automation 界面中定义阈值条件，请按照以下步骤操作：

  1. 在监听器设置向导的 条件组合 部分中，选择 添加条件.
  2. 选择 条件 作为 条件类型.
  3. 指定一个 已保存的对象集 用作指标输入。
  4. 在监听器设置向导的 选择一个指标 下拉菜单中，选择您要比较的属性。
  5. 选择一个比较运算符。
  6. 选择一个指标或静态值来与该属性进行比较。

下面展示了一个在 Automate 界面中定义逻辑的阈值跨越条件示例。该条件检查纽约所有空气质量传感器的最大值是否小于 0.05.

函数支持的逻辑

用途 函数支持的 逻辑条件，以应对界面定义条件不支持的复杂场景。函数支持的条件通过定义并发布一个 函数 来工作，该函数返回一个布尔值（true or false）。该函数在评估期间被调用，并在状态变化时记录事件。

/**
 * This function calculates whether more than 50% of the passed air quality sensors are considered unhealthy.
 * A sensor is considered unhealthy when the carbon monoxide value passes `0.05`.
 */
@Function()
public async areMoreThanFiftyPercentOfSensorsUnhealthy (airQualitySensors: ObjectSet<automateExampleAirQualitySensor>): Promise<boolean> {
    const totalSensorCount = await airQualitySensors.count();
    const unhealthySensorCount = await airQualitySensors.filter(sensor => sensor.carbonMonoxide.range().gt(0.05)).count();
    if (totalSensorCount === null) {
        return false;
    }

    return ((unhealthySensorCount ?? 0) / totalSensorCount) > 0.5;
}
