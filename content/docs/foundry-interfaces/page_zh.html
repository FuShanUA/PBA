接口

接口 是一种本体论类型，用于描述对象类型的结构及其能力。接口支持对具有共同结构的对象类型进行一致的建模和交互。例如， Facility 接口可能包含 Facility Name 和 Location 属性。 Facility 可由诸如 Airport、 Manufacturing Plant或 Maintenance Hangar等对象类型实现，其中每种对象类型还可以包含特定于其类型的其他属性。

通过使用 Facility 接口，工作流可以与 Airport、 Manufacturing Plant和 Maintenance Hangar 对象类型进行交互（无论是整体还是单独），而无需了解这些对象类型的具体细节。此外，如果引入了实现 Facility 接口的新对象类型，工作流将立即与新对象类型兼容，无需进行额外的重构。

请查看 当前支持级别 ，以详细了解在平台中的哪些地方可以使用接口。

接口功能

接口由接口属性、 关联类型约束、 操作类型约束以及 元数据 组成，用于提供有关接口的信息。接口属性可以在接口上本地定义（推荐），也可以使用 共享属性进行定义。接口可以由多个对象类型实现。

与编程语言中的接口类似，您可以 扩展接口 以创建一个继承原始接口属性的子接口，然后向该子接口添加新的、更具体的属性。对象类型随后可以 实现该接口 以表明它们符合接口定义。对象类型可以实现多个接口，以便在不同的工作流中使用。接口还可以扩展多个其他接口，包括自身也扩展了其他接口的接口，从而产生通过多层接口继承而来的属性。

接口与对象类型之间的差异

在本体论中，接口与对象类型之间既有功能上的差异，也有样式上的差异。

对象类型是具体的；它们具有由共享属性或本地属性定义的架构，由包含属性值的数据集支撑，并且可以实例化为对象。

相比之下，接口是抽象的；它们具有由接口属性定义的架构，不由数据集支撑，并且不能直接实例化，而必须作为特定的对象类型进行实例化。

从样式上看，平台中的接口通过在其图标周围显示虚线边框，在视觉上与对象类型区分开来。

接口权限

接口的权限通过 本体论角色进行控制。

当前支持级别

随着对接口本体论类型的支持不断扩展，其在 Palantir 平台各处的可用性将有所不同。

接口目前在以下应用程序和服务中受支持：

  • Ontology Manager： 定义、编辑和实现接口。
  • Marketplace： 打包和安装接口。
  • Functions： TypeScript v2 函数。

接口在以下应用程序和服务中受到部分支持：

  • Actions： 定义操作，以创建、修改、删除或关联实现接口的对象。接口操作类型约束目前处于测试阶段，可用于为实现接口的各对象类型定义预期的操作能力。
  • Object Set Service： 按接口搜索和排序对象。对按接口聚合的支持正在开发中。对接口关联类型的支持正在开发中。
  • Ontology SDK： 将接口用作与实现接口的对象类型进行交互的 API 层。支持情况因语言而异；目前支持 TypeScript，对 Java 和 Python 的支持正在开发中。

接口正在积极开发中，但目前在以下应用中尚不受支持：

  • Workshop
  • Functions： TypeScript v1 和 Python 函数

接口入门

要向您的本体论添加接口，您可以 创建 新接口，或 扩展 现有接口。拥有接口后，您便可以 实现 该接口（使用具有适当形状的对象类型）或 编辑 它，以便随着本体论的演进更好地契合您的组织。
