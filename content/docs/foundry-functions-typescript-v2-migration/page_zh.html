从 TypeScript v1 迁移到 TypeScript v2

本指南介绍了在将现有 TypeScript 函数从 v1 迁移到 v2 时可能遇到的语法和结构差异。请参阅 功能支持文档 ，以了解 v2 的增强功能以及各版本支持的内容。

声明函数

要在 TypeScript v1 中将函数发布到平台，你必须使用 @Function() 装饰器（来自 @foundry/functions-api 包）对其进行标注。此外，该函数必须是某个类的方法，且该类需从仓库的根 index.ts 文件中导出。

// src/index.ts

import { Function } from "@foundry/functions-api";

export class MyFunctions {

    @Function()
    public reverseStringArray(arr: string[]): string[] {
        return arr.reverse();
    }
}

要在 TypeScript v2 中将函数发布到平台，你必须将其写在 src/functions 目录下的一个文件中，并使用 export default将其导出。每个文件只能导出一个函数。

    arr: string[]
): string[] {
    return arr.reverse();
}

请参阅我们关于 TypeScript v2 函数入门 的文档，以了解更多信息。

使用 @osdk/functions 包

在 TypeScript v1 中，你必须导入诸如 Integer 和 Double 这样的基本类型（来自 @foundry/functions-api 包），以便在签名中使用。但在 TypeScript v2 中，你必须改用 @osdk/functions 包。

以下示例导入了 Integer 类型，该类型来自 @foundry/functions-api 包，并在 TypeScript v1 函数的签名中使用它来计算两个整数的最大公约数：

import { Function, Integer } from "@foundry/functions-api";

export class MyFunctions {

    @Function()
    public gcd(a: Integer, b: Integer): Integer {
        if (b === 0) {
            return a;
        }
        return gcd(b, a % b);
    }
}

在 TypeScript v2 中，核心 TypeScript 逻辑相同，但你必须使用 Integer 类型，该类型来自 @osdk/functions 包：

    if (b === 0) {
        return a;
    }
    return gcd(b, a % b);
}

日期和时间戳

TypeScript v1 使用 LocalDate 和 Timestamp 类型，这些类型来自 @foundry/functions-api 包，用于处理时间数据。TypeScript v2 将这些类型替换为 DateISOString 和 TimestampISOString 类型，这些类型来自 @osdk/functions 包，它们将日期和时间戳表示为 ISO 8601 ↗ 字符串。

TypeScript v2 函数可以使用 NPM 生态系统中可用的任何日期和时间戳库，例如 dayjs ↗、 date-fns ↗以及 luxon ↗。

生成 Ontology SDK

TypeScript v2 函数提供一流支持，可通过 Ontology SDK查询和编辑本体论。与 TypeScript v1 一样，TypeScript v2 代码仓库允许你通过 Resource imports 侧边栏导入本体论实体。添加对象类型和关联类型后，系统会提示你创建 Ontology SDK 的初始版本。

选择 创建，然后为本体论 SDK 选择一个名称。生成首个版本后，此名称将无法更改。选择 创建新版本 以生成本体论 SDK。

创建本体论 SDK 后，您将看到一个将其安装到工作区中的选项。选择 安装 会将本体论 SDK 作为依赖项添加到 package.json 文件中，并使其可在 TypeScript 代码中使用。

查看 文档 选项卡（位于侧边栏），以获取在 TypeScript 中使用本体论的全面示例。

查询本体论

在 TypeScript v1 中，您必须导入 Objects （来自 @foundry/ontology-api 包），才能针对本体论执行搜索：

import { Function, Integer } from "@foundry/functions-api";
import { Objects } from "@foundry/ontology-api";

export class MyFunctions {

    @Function()
    public async countAircraft(): Promise<Integer> {
        const count = await Objects.search().aircraft().count() ?? 0;

        return count;
    }
}

import { Aircraft } from "@ontology/sdk";
import { Client } from "@osdk/client";
import { Integer } from "@osdk/functions";

export default async function countAircraft(client: Client): Promise<Integer> {
    const aircraft = await client(Aircraft).aggregate({
        $select: {
            $count: "unordered"
        }
    });

    return aircraft.$count;
}

编辑本体论

要在 TypeScript v1 中编写本体论编辑函数，您必须使用 @OntologyEditFunction() 装饰器（来自 @foundry/functions-api 包）对其进行注解，并为其指定 void 返回类型。您还必须应用 @Edits decorator ，以预先声明所有要编辑的对象类型，从而在调用由函数支持的操作之前，对这些对象类型强制执行相应权限。

import { Edits, OntologyEditFunction } from "@foundry/functions-api";
import { Aircraft, Employee } from "@foundry/ontology-api";

export class MyOntologyEditFunctions {

    @Edits(Aircraft, Employee)
    @OntologyEditFunction()
    public myFunction(aircraft: Aircraft, employee: Employee): void {
        aircraft.businessCapacity = 3;
        employee.department = "HR";
    }
}

在 TypeScript v2 中，您必须导入 createEditBatch 函数（来自 @osdk/functions 包来构建一个在执行期间使用的编辑存储。您必须使用 Edits 类型来声明允许您的函数编辑哪些实体。这会在编译时强制实施类型安全；如果您尝试编辑的对象或关联的类型未被您的 Edits 类型涵盖，TypeScript 编译器将返回错误。

import { createEditBatch, Edits } from "@osdk/functions";
import { Aircraft, Employee } from "@ontology/sdk";
import { Client, Osdk } from "@osdk/client";

type OntologyEdit = Edits.Object<Aircraft> | Edits.Object<Employee>;

export default function myFunction(
    client: Client, 
    aircraft: Osdk.Instance<Aircraft>, 
    employee: Osdk.Instance<Employee>
): OntologyEdit[] {

    const batch = createEditBatch<OntologyEdit>(client);

    batch.update(aircraft, { businessCapacity: 3 });
    batch.update(employee, { department: "HR" });

    return batch.getEdits();
}

在 TypeScript v2 中，使用 Edits.Interface<MyInterface> 来创建、更新和删除对象，这些操作通过 本体论接口 属性完成。详情请参阅 本体论编辑。

在 TypeScript v1 中，编辑 并不会 在函数执行期间应用于本体论。正如我们的 编辑与对象搜索文档中所述，对对象和关联的更改仅在函数执行完毕后才会传播，且仅在由函数支撑的操作中调用时才会传播。

TypeScript v2 使这一行为更加明确。您的函数不再隐式累积编辑，而是必须使用编辑批次来跟踪这些编辑，并在完成时将其返回。

请参阅 TypeScript v2 文档中的 本体论编辑 部分，以获取所支持操作的完整列表。

TypeScript v2 还支持 暂存写入，这是一种提供写后读保证的替代执行模型。暂存写入函数使用 WriteableClient 而不是 createEditBatch ，并且无需显式返回编辑。

为对象生成唯一 ID

要在 TypeScript v1 中为新创建的对象生成唯一 ID，请使用 Uuid 实用工具，它来自 @foundry/functions-utils 包。

import { Edits, OntologyEditFunction } from "@foundry/functions-api";
import { Uuid } from "@foundry/functions-utils";
import { FlightScenario, Objects } from "@foundry/ontology-api";

export class ExampleEditFunctions {

    @Edits(FlightScenario)
    @OntologyEditFunction()
    public createFlightScenario(): void {
        const scenario = Objects.create().flightScenarios(Uuid.random());
        scenario.scenarioName = "New scenario";
    }
}

import { FlightScenario } from "@ontology/sdk";
import { Client } from "@osdk/client";
import { createEditBatch, Edits } from "@osdk/functions";
import { randomUUID } from "node:crypto";

type OntologyEdit = Edits.Object<FlightScenario>;

export default function createFlightScenario(client: Client): OntologyEdit[] {

    const batch = createEditBatch<OntologyEdit>(client);

    batch.create(FlightScenario, { 
        id: randomUUID(),
        scenarioName: "New scenario",
    });

    return batch.getEdits();
}

避免在函数体之外的模块顶层调用 randomUUID 或其他随机值生成器。TypeScript v2 函数采用暖调用（warm invocation）模式，其中所有模块级代码在初始化期间仅求值一次，随后在后续调用中复用。这意味着， randomUUID 在模块级别的调用只会被求值一次，并在每次暖调用中产生相同的值。请务必在函数体内生成随机值，以确保唯一性。

将对象加载到内存中

TypeScript v1 函数提供了 .all() 和 .allAsync() API，用于将特定类型的所有对象加载到内存中进行处理。但是，随着本体论中对象数量的增长，这种方法可能导致内存占用过高和性能下降。

import { Edits, OntologyEditFunction } from "@foundry/functions-api";
import { Aircraft, Objects } from "@foundry/ontology-api";

export class MyFunctions {

    @Edits(Aircraft)
    @OntologyEditFunction()
    public editAircraft(): void {

        const aircraft = Objects.search().aircraft().all();

        aircraft.forEach(a => {
            a.arrived = true;
        });
    }
}

TypeScript v2 函数支持通过本体论 SDK 进行流式对象处理，无需一次性将整套对象保留在内存中。我们建议在可能的情况下采用此方法。

import { Aircraft } from "@ontology/sdk";
import { Client } from "@osdk/client";
import { createEditBatch, Edits } from "@osdk/functions";

type OntologyEdit = Edits.Object<Aircraft>;

export default async function editAircraft(client: Client): Promise<OntologyEdit[]> {

    const batch = createEditBatch<OntologyEdit>(client);
    
    for await (const a of client(Aircraft).asyncIter()) {
        batch.update(a, { arrived: true });
    }

    return batch.getEdits();
}

import { Aircraft } from "@ontology/sdk";

import { createEditBatch, Edits } from "@osdk/functions";

type OntologyEdit = Edits.Object<Aircraft>;

export default async function editAircraft(client: Client): Promise<OntologyEdit[]> {

    const batch = createEditBatch<OntologyEdit>(client);
   
    const aircraft = await Array.fromAsync(client(Aircraft).asyncIter());

    aircraft.forEach(a => {
        batch.update(a, { arrived: true });
    });

    return batch.getEdits();
}
