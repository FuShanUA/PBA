函数接口

函数接口 允许函数作者将其自定义逻辑与 Foundry 原生功能集成，并提供了一种在调用方应用程序与函数之间定义契约的强大方式。

函数接口定义了应用程序或用户应如何与函数进行交互。其中包括函数的输入、输出和错误。换言之，函数接口描述的是函数的签名，但函数接口本身并不是函数。函数接口旨在由函数来实现。

某些 Foundry 应用程序会使用函数接口，在执行实现该接口的函数时，基于已知的输入、输出和错误提供专门的行为。用户可以为某些函数接口提供自己的实现，而 Foundry 仍可继续提供这种专门行为。Foundry 中依赖特定函数接口的应用程序可以发现所有实现该接口的函数。

例如，AIP Logic 依赖函数接口，让用户能够将自己的 LLM 引入 Logic 函数。具体来说， 使用 LLM 块（位于 AIP Logic 中）允许用户选择 Palantir 提供的 LLM 或 已注册的 LLM。注册模型是用户编写的、实现了 Foundry 提供的函数接口的函数；例如，聊天补全函数接口。这使 AIP Logic 能够发现那些被明确定义为聊天补全实现、具有通用 LLM 典型签名并且返回 AIP Logic 可妥善处理的错误的函数。未来，用户提供的聊天补全实现将可在平台的其他部分使用，例如 Pipeline Builder 和 Model Catalog。

了解如何通过注册模型功能注册 LLM。 有关使用函数接口的传统方法，请参阅 使用函数接口注册 LLM [传统]。

类型自定义

为了提供更大的灵活性，在实现函数接口时，您并不局限于所提供的类型。在某些情况下，您可能希望创建自己的 自定义类型. 只要函数 兼容 ↗ 于函数接口上定义的函数，该函数就会被编译器接受并成功发布。如果函数接口定义了一个所有字段均为可选的输入类型，则在自定义该类型时必须至少共享一个共同的可选字段。

故障排除

函数接口的设计十分灵活，支持多种多样的实现方式。但是，在实现函数接口时，您可能会遇到错误。以下是一些有关 TypeScript 函数的技巧，可帮助您在自定义实现时避免这些错误。

错误： Function input name does not match the required input name of the function interface at the specific input position

每个参数的输入名称必须与函数接口在每个特定输入位置上定义的输入名称相匹配。正如 lint 检查所提示的，请确保每个输入名称与函数接口在相应位置上声明的输入名称完全一致。

错误： Function is missing input parameter of the function interface

如果实现函数未包含函数接口上定义的每个必需输入，就会出现此错误。要解决此错误，请确保实现函数包含函数接口上声明的每个输入。

错误： Type {type1} is not assignable to type {type2}

编译器可能会拒绝实现函数,认为其与接口上定义的函数不兼容。如果是这样,请确保您的实现函数与函数接口上定义的函数 兼容 ↗ ,具体方法是检查每个类型的结构,并将其与函数接口上定义的类型进行比较。
