Iceberg 表权限

本页面列出的默认角色是 Palantir 提供的开箱即用默认设置。您的管理员可能已通过 自定义角色集为您的环境配置了自定义设置。

本页面描述的操作决定了您可以对 Foundry Iceberg 表执行哪些操作。操作是 Foundry 在允许某项操作之前所检查的单项权限，而 角色 是可以授予用户的操作集合。有关操作与角色之间关系的更多信息，请参阅 了解角色与操作。

读取和写入 Iceberg 表

更宽泛的 table:read 和 table:write 操作控制着 Iceberg 表的读取和写入。这些操作同时适用于 Iceberg 表和虚拟表。

主分支保护

Iceberg 表的主分支保护支持目前处于 Beta 阶段，可能尚未在您的环境中提供。

如果您的 主分支保护 已在 Iceberg 表资源上启用，则您必须拥有以下操作，才能在拥有该表的 Foundry 作业规范之外进行更改。

Foundry 会自动从创建该表的管道（例如创建该资源的 Pipeline Builder 或 Python 转换逻辑）生成作业规范。要在此所属资源之外进行更改，您必须拥有可绕过该表主分支保护的额外提升权限。

操作显示名称默认角色
iceberg:bypass-branch-protection绕过分支保护Owner

您通常需要此操作来对受分支保护的表进行更改，无论是通过 维护任务 还是通过 外部客户端。

主分支保护特指表上的 资源 分支保护，而不是支撑代码上的 代码 分支保护。

维护任务操作

这些操作控制谁可以对 Iceberg 表上的 维护任务 进行读取和写入。

操作显示名称默认角色
iceberg:read-maintenance-tasks读取表维护任务Viewer
iceberg:write-maintenance-tasks写入表维护任务Editor
iceberg:write-sql-maintenance-tasks写入自定义 SQL 维护任务Editor
iceberg:write-data-altering-maintenance-tasks写入数据变更维护任务Editor
iceberg:schedule-maintenance-tasks为维护任务（任意类型）创建新调度Editor

这三个 write 操作是累积的。写入或编辑任何维护任务始终需要 iceberg:write-maintenance-tasks。根据任务类别，Foundry 还会检查更具体的 iceberg:write-sql-maintenance-tasks 和 iceberg:write-data-altering-maintenance-tasks 操作。因此，移除 iceberg:write-maintenance-tasks 从角色中移除后，将完全丧失创建维护任务的能力，即使该角色仍然包含其他两项操作。

创建或编辑任务还需要对底层表数据的读写权限。在受分支保护的表上， 主分支保护 同样适用。

实践中的维护操作

下表列出了编写每种任务所需的操作：

任务类型所需操作
基于表单的流程：
例如， Rewrite data files 或 Expire snapshots		iceberg:write-maintenance-tasks
Custom SQL （不会在逻辑上更改当前快照）：
例如， CALL system.rewrite_data_files(...)		iceberg:write-maintenance-tasks
+ iceberg:write-sql-maintenance-tasks
Custom SQL （会在逻辑上更改当前快照）：
例如， INSERT, UPDATE, DELETE		iceberg:write-maintenance-tasks
+ iceberg:write-sql-maintenance-tasks
+ iceberg:write-data-altering-maintenance-tasks

将分支保护与维护操作相结合

Foundry 会分别检查绕过 主分支保护 的操作，以及 编辑维护任务 的操作。这使您可以将能够创建某类更改的人员与可以应用该更改的表区分开来。

例如：

  • 要针对 未受分支保护的表编写 Custom SQL 维护任务，用户需要 iceberg:write-sql-maintenance-tasks 和 iceberg:write-maintenance-tasks。
  • 要针对 受分支保护的表编写同一任务，用户需要上述相同的两项操作，此外还需要 iceberg:bypass-branch-protection。
