监控规则参考

监控规则基于每个资源进行配置，包括针对以下资源的规则：

  • 代理
  • 调度
  • 对象和关联
  • 流式数据集
  • 实时部署
  • 时间序列同步
  • 地理时空观测
  • 自动化
  • 数据集
  • 函数
  • 操作

所有监控规则都包含一个名为 警报严重性 的可配置字段，即当其条件被触发时赋予警报的严重性。监控视图可以配置为仅发送达到或超过特定严重性的警报。

规则组件描述示例选项
告警严重程度严重程度 监控报告条件的低、中、高

计划规则

连续计划失败

当连续计划失败的次数达到或超过设定的阈值时发出警报。此规则不统计导致构建取消的计划运行。

规则组件描述示例选项
如果值大于或等于连续计划失败次数的阈值1

此监控器的默认行为是在失败一次时发出中等严重程度的警报，在失败三次时发出高严重程度的警报，但这些阈值在很大程度上取决于监控规则范围内所含计划的频率和稳定性。

计划持续时间

当计划的运行时间超过设定阈值时发出警报。

规则组件描述示例选项
如果值大于或等于计划的持续时间2 小时
此监控器通常用于高度关键的计划，可快速告知计划能否在预期时间内完成。由于计划具有可变性，此监控器通常以单个计划为作用域。

对象和关联规则

一个 用户导致的失败 是一种因配置或输入数据问题而导致的作业失败，例如无效的架构、格式错误的行或权限不足。这类失败有别于暂时性失败或与基础设施相关的失败，后者不会显示在这些警报中，因为它们通常会通过重试自动解决。

Changelog 作业失败

当 "changelog" 作业 （针对对象或关联）在 活动管道 或 替换管道上失败时发出警报。仅针对用户导致的失败发出警报。

规则组件描述示例选项
如果值大于或等于用户导致的连续变更日志作业失败次数的阈值1

此监视器的默认行为是:失败一次时以中等严重性发出警报,失败三次时以高严重性发出警报。

合并更改作业失败

当 "merge changes"作业 （针对该对象或关联）在 活动管道 或 替换管道上失败时发出警报。仅针对用户造成的失败发出警报。

规则组件描述示例选项
如果值大于或等于用户导致的连续合并作业失败次数阈值1

此监视器的默认行为是：失败一次时以中等严重性发出警报，失败三次时以高严重性发出警报。

同步作业失败

在以下情况下发出警报： "sync" 作业 （针对该对象或关联）在 当前管道 或 替换管道上运行失败。

规则组件描述示例选项
如果值大于或等于连续同步作业失败的阈值3

此监控器的默认行为是：失败一次时以低严重性发出警报，失败三次时以中等严重性发出警报，失败七次时以高严重性发出警报。

管道上的 Scroll 作业失败

发生以下情况时发出警报： "scroll" 作业 对象或关联的当前管道或替换管道失败。Scroll 作业负责将数据从支撑数据源流式传输到对象数据库。

规则组件描述示例选项
如果值大于或等于连续 Scroll 作业失败的阈值3

此监控器的默认行为是：失败一次时以低严重性发出警报，失败三次时以中等严重性发出警报，失败七次时以高严重性发出警报，且这些值均可配置。

同步传播延迟

当支撑对象的数据集存在同步时间超过设定阈值的事务时发出警报。

规则组件描述示例选项
如果值大于或等于同步事务所需时间的阈值1 天

检测到无效的流记录

当输入流中的记录包含格式违规时发出警报。scroll 作业会忽略这些记录。此规则不可配置,当被忽略的行数大于或等于 1 时,将以严重(critical)级别发出警报。

数据集规则

作业上次成功以来的时间

当数据集上的作业在指定的时间阈值内未成功时，会发出警报。与“上次更新以来的时间”健康检查不同，以下情况对于该监控器而言始终计为通过状态：

  • 作业已成功，但事务已中止
  • 作业已成功，但未添加新数据
规则组件描述示例选项
如果值大于数据集上次更新以来经过的时间1 天

我们建议根据数据集的预期更新频率设置此监控值。对于每日更新，请将其设置为 1 天。

自动化规则

以下规则适用于自动化和时间序列流式自动化。

自动化没有新评估

如果在超过配置阈值的时间内没有新的评估，则会发出警报。使用此规则可检测本应已评估但未评估的自动化中的性能下降。当自动化未被触发时，此规则不会发出警报。

规则组件描述示例选项
如果值大于或等于自上次自动化评估以来经过的时间阈值1 小时

自动化没有新触发器

如果在配置的阈值内没有新的监控触发，则发出警报。使用此规则可检测自动化何时未按预期触发。

规则组件描述示例选项
如果值大于或等于自上次自动化触发以来经过的时间阈值1 天

单个最新事件超过了自动化的失败阈值

如果最近单次执行的失败次数至少达到配置的数量，则发出警报。此规则不会考虑多个事件。

规则组件描述示例选项
如果值大于最近一次自动化执行中的失败次数阈值10

自动化已被系统禁用

在自动化因达到限制或触发循环而被系统禁用时发出警报。此规则不可配置，当自动化被禁用时会以高严重性发出警报。

自动化在时间窗口内出现多次执行失败

当时间窗口内自动化执行失败的次数超过配置的阈值时发出警报。使用此规则可发现持续运行且反复失败的自动化，而非已被系统禁用的自动化。

规则组件描述示例选项
如果值大于失败执行次数的阈值0
时间窗口用于统计失败执行次数的时间段1 小时

自动化在时间窗口内发生多次评估失败

当窗口内失败的自动化评估次数超过配置的阈值时发出警报。使用此规则可以捕获触发条件评估失败的自动化，并将其与执行期间发生的失败区分开来。

规则组件描述示例选项
如果值大于失败评估次数的阈值0
时间窗口用于统计失败评估的时间段1 小时

自动化在某个时间窗口内出现大量效果执行失败

当时间窗口内失败的效果执行次数超过配置的阈值时发出警报。效果是自动化运行的下游操作或通知。使用此规则可以捕获那些触发器和评估均已成功、但效果仍然失败的自动化。

规则组件描述示例选项
如果值大于失败效果执行次数的阈值0
时间窗口统计失败效果执行的时间段1 小时

函数规则

函数执行可能因多种原因而失败。有关失败类型的完整列表，请参阅 函数失败类型。

该 窗口内函数失败次数 规则会跟踪 所有 失败类型。 窗口内面向用户的函数失败次数 规则仅跟踪面向用户的错误。 窗口内非面向用户的函数失败次数 规则会跟踪所有失败类型 除外 面向用户的错误。

当 p95 函数持续时间超过指定阈值时发出警报。p95 基于近期数据的滑动窗口进行测量。

规则组件描述示例选项
如果值大于失败次数阈值0
时间窗口用于统计失败次数的时间段1 小时

时间窗口内面向用户的函数失败次数

当给定时间窗口内面向用户的函数失败次数超过指定阈值时发出告警。此规则仅跟踪 面向用户的错误 （由函数代码抛出）。

规则组件描述示例选项
如果值大于失败次数阈值0
时间窗口用于统计失败次数的时间段1 小时

时间窗口内非面向用户的函数失败次数

在给定时间窗口内的函数失败次数超过指定阈值时发出警报，不包括函数代码抛出的面向用户的错误。此规则有助于监控基础设施和系统级故障，同时避免因预期的用户输入错误而产生的干扰。

规则组件描述示例选项
如果值大于失败次数阈值0
时间窗口统计失败次数的时间段1 小时
