对象模型

有两个与 Foundry Rules 相关的主要对象模型概念：

  • 规则，应用于数据；而
  • 提案，提供了一种更改规则的方式。

规则

规则是标准对象，由以下部分组成：

  • 一组 规则元数据属性 ，例如名称、描述、作者、规则类型等。
  • 一组 自定义属性 ，将应用于筛选后的数据集或传递给转换。
    • 对于“告警”模式，这些可能是 alert_severity、 alert_assignee或 priority。
    • 对于“分类”模式，这些可能是 group、 sub-group等。
  • 一个 逻辑属性 ，其中包含该规则的匹配条件。
    • 该逻辑以压缩 JSON blob 的形式存储，并遵循特定语法以实现一致的序列化。

了解如何 自定义属性 以适应您自己的工作流。

提案

许多规则管理用例都要求有相应的审计和审查流程，用于管理规则的创建、编辑和删除。为了满足这些需求，Foundry Rules 支持 规则提案 作为一种提交、审查和监控规则变更的方法。规则提案类似于软件开发中的 "拉取请求" ↗，因此在任意给定时间，每条规则都可以同时有多个提案。

提案是 Foundry Rules 的一项功能，而非必需要求。由于 Foundry Rules 采用标准对象和操作来创建此审批流程，因此可以根据需要自定义该工作流，以满足规则变更管理方面的任何运营或监管要求。

提案表示为包含以下内容的对象：

  • 该 规则 ID 待编辑、创建或删除。
  • 提案元数据 例如提案作者、时间戳、状态（open、approved、rejected）和审阅者。
  • 该 变更差异 （即提案中的变更列表），记录在以下属性中： old_rule_name， new_rule_name， old_logic， new_logic，等。
