Workshop 中的变更日志面板

Workshop 变更日志面板允许构建者可视化模块版本之间的变更。这对于跟踪随时间推移所做的修改以及在调试模块问题时识别哪个变更可能导致了问题非常有用。

了解变更日志

如果所选模块版本之间存在变更，面板将填充变更日志节点。共有 5 种不同类型的变更：

  • 已更改： 节点已被修改（例如，按钮上的文本发生了变化）。
  • 新增： 节点被添加到模块中。
  • 删除： 节点已从模块中移除。
  • 已移动： 节点已被重新定位（例如，从第 1 页移动到第 2 页）。
  • 变为未使用： 小部件已被删除但未从模块中移除，将其移至 unused widgets.

选择模块版本有两种方式：

  • 范围选择： 选择起始版本和结束版本以查看两者之间的变更。例如，您可以选择 0.1.0 和 0.4.0 以查看版本 0.1.0 和 0.4.0.

  • 单一选择： 单一选择允许您查看特定模块版本与上一版本相比的变更。例如，如果您选择版本 0.5.0，变更日志将填充 0.4.0 和 0.5.0.

在变基（rebase）过程中使用变更日志面板

当在将分支的变更合并到 main之前需要先进行变基时，变更日志面板会显示一个可视化通知圆点，并提供开始变基的选项。

如果您需要合并来自 main的变更，请按照 变基与冲突解决可视化指南 查看差异图标、比较分支配置并解决冲突。

在变基过程中，变更日志面板描述了从您的分支应用到最新 main 模块版本的变更，并突出显示合并冲突。当某个变更同时在 main 和您的分支上被修改时，该变更会被标记为冲突。常见示例包括：

  • 小部件或变量在 main 和您的分支上都被修改了。
  • 某个部分在 main 上被删除，而在分支上被编辑了。
  • 小部件从位置 A to B on main 以及从 A to C 在您的分支上被移动了。

在解决冲突时，您可以在三种状态之间切换模块，以实时评估结果：

开始变基后您为协调差异所做的变更。冲突解决完毕且您对模块满意后，保存以完成变基。然后您就可以安全地将您的分支合并到 main.
