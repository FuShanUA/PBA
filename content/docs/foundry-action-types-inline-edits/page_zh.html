内联编辑

操作支撑的行内编辑在验证和提交方式上与标准操作不同 操作。对于标准操作，需要设置多个参数才能使操作有效。然而，对于操作支撑的行内编辑，每个参数都是可选的，并默认为对象的现有值，因此用户可以一次对单个属性进行逐一修改。

本文档讨论在使用行内编辑时如何避免意外结果。行内编辑在 Workshop 和 Object Explorer 中均可用。行内编辑操作的配置取决于操作的使用位置。

Object Explorer 行内编辑

行内编辑允许用户快速编辑对象在 Object Explorer 结果视图 或原生对象视图小部件（如属性卡片或指标卡片小部件）中的值。

配置

要设置行内编辑操作，请导航到您的对象类型的 属性 选项卡，然后进入 Ontology Manager 中的 该 选项卡。选择一个属性并导航到侧边栏中的 行内编辑 。在下拉菜单中，选择一个可用的操作类型或创建新的操作类型。创建新操作类型将触发操作类型创建工作流。每个属性只能有一个行内编辑操作类型。

您可以将同一操作类型用作多个属性的行内编辑，也可以为不同的属性使用不同的操作类型。

行内编辑的操作类型要求

并非所有操作类型都可以用作行内编辑操作类型。要被接受，操作类型必须满足以下要求：

  • 只能修改单个对象类型的单个对象。
  • 必须启用默认值。
  • 默认值必须来自定义行内操作的对象引用参数。因此，在操作中被更改的属性不能映射到静态值或特殊值（如“当前用户”或“当前时间”）。
  • 可以设置可见性状态和覆盖；但是，如果行内编辑在 Object Explorer 和对象视图中使用，这些设置将被忽略。
  • 副作用 Webhook or 副作用通知 不能被启用。

Workshop 行内编辑

在 Workshop 中将操作类型用作行内编辑不需要额外配置，但并非所有操作都适合单元格级别的编辑。有关如何配置行内编辑的信息，请参阅 Workshop 文档.

背景

运行单个操作时，编辑会逐一（按顺序）进行验证和提交。行内编辑的不同之处在于它们是批量验证和提交的。因此，并非所有操作都适合行内编辑。可能因行内编辑而失败或产生意外结果的操作包括：

  • 任何试图读取另一个操作可能已写入的数据的操作，或
  • 两个试图写入同一对象的操作。

当行内编辑应用于 加载对象数据。时，提交的操作会按顺序（以非确定性顺序）应用，而不是同时应用（这通常是行内编辑的情况）。因此，通常因多个操作尝试写入同一对象而失败的行内编辑操作在应用于场景时可能会成功，但我们不建议构建依赖于此行为差异的应用程序。

有效的行内操作

操作必须提交不冲突的编辑，才能有效地作为操作支撑的行内编辑。在实践中，这意味着在同一表格编辑小部件中配置的多个操作不得：

  • 写入同一对象，
  • 创建同一关联，或
  • 尝试保持聚合值的一致性。

无效的行内操作

如果内联编辑尝试对同一对象进行两次编辑，操作将返回错误。 此外，内联编辑不支持添加或删除连接表关联，这将导致面向用户的错误消息。

当用户应用内联编辑时， 提交标准 将应用于每次编辑，但编辑将批量提交。参数和全局提交条件将针对每个被编辑的对象进行评估，但引用共享对象或关联对象的提交条件与内联编辑不兼容。这是因为在应用内联编辑时，累积提交条件会将编辑后的值与该列未编辑的值进行比较。在最终提交时，所有编辑将一次性提交，并且只有当它们全部通过相应对象的参数和全局提交条件时才会成功。

因此，在多个操作类型之间共享的对象或关联对象上的提交条件，会在进行任何编辑之前，针对每次编辑进行一次评估。

由于内联编辑是批量提交的，它们可能会违反在按顺序（一次一个）应用操作时正常工作的提交条件。

示例：无效的内联操作

设想一个 Delay Flight 操作，该操作可以在机场将单个航班最多延误 20 分钟，而该机场所有航班的总延误最多为 50 分钟。

  • 两个提交条件——20 分钟的要求和 50 分钟的总额——将在每次更新单元格时进行评估。
    • 由于尚未提交任何编辑，50 分钟的总额会将新的延误与该列中未编辑延误的总和（即内联编辑开始之前的延误）进行比较。
  • 第二个提交条件（机场所有延误的总和小于 50 分钟）依赖于聚合值，并由该列中的所有对象共享。
    • 由于内联编辑是批量提交的，这第二个提交条件将无法有效限制给定机场航班延误的总时长；最终的编辑结果总和可能会超过第二个提交条件所允许的 50 分钟。
  • 此操作不适合表格编辑，因为与对每个单元格单独运行该操作相比，它会导致不一致的结果。
