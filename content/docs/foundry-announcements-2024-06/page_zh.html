JDBC 系统的表导出功能现已推出

发布日期:2024-06-25

现在,数据集可以通过 表导出 功能导出到外部 JDBC 系统,该功能位于数据连接中。表导出为配置表格数据导出带来了全新的用户体验,提供直观的界面、丰富的导出模式选择,以及探索目标系统以配置导出的能力。表导出可配合 自定义 JDBC 系统 使用,无论系统是通过直接连接还是代理运行时配置的。

导出模式

表导出支持六种不同的导出模式,以满足您的独特需求:

  • 高效地将数据集镜像到外部表(推荐): 外部表将始终与您在 Foundry 数据集中看到的内容保持一致。
  • 完整数据集(不截断): 始终导出 Foundry 数据集整个视图的快照,而不先截断外部表。
  • 完整数据集(截断): 截断（删除）目标表，然后导出当前数据集视图的完整快照。
  • 增量导出： 导出 仅限 当前视图中尚未导出的事务，而不截断目标表。
  • 增量导出并截断： 截断（删除）目标表，然后仅导出当前视图中之前未导出过的事务。
  • 增量导出，若不满足条件则失败 APPEND： 仅导出当前视图中尚未导出的事务，若存在 SNAPSHOT、 UPDATE或 DELETE 事务（首次运行后），则会失败。

如需了解 各导出模式的详细信息 ，请参阅我们的文档。

Data Connection 中导出模式选择的示例。

探索目标系统

若要导出数据集，其架构 必须 与目标系统上某个表的架构相匹配。为帮助您配置正确的表，您可以使用源浏览器来浏览目标源上所有可用的架构和表。

源浏览器对话框的示例。

从导出任务迁移

新增的表导出功能旨在取代现已停用的 导出任务 来导出表格数据，我们鼓励所有导出任务用户迁移到表导出。请详细了解 Data Connection 导出与导出任务之间的差异，并了解如何 迁移您的工作流。

Pipeline Builder 中的预览速度更快

发布日期：2024-06-17

得益于缓存增强，Pipeline Builder 的预览速度现已显著提升。内部测试显示，计算时间从 40 秒缩短至 1 秒，资源密集型预览的速度提升了 40 倍。此功能现已在所有 enrollment 中正式可用。

缓存改进带来更快的预览

缓存改进现在允许 Pipeline Builder 中的节点使用来自已预览上游节点的缓存（即“存储”）结果。这样，下游节点便可以跳过重新计算，快速显示您的数据预览。

Pipeline Builder 改进后的缓存功能包括：

  • 减少冗余计算： 现在，在 Pipeline Builder 中对缓存节点的下游进行预览时，仅会计算额外的节点。
  • 高效缓存： 计算开销较大的节点（例如联接和 use LLM ）现在会被主动缓存，从而使下游节点避免重复且耗时的计算。

用户将受益于迅捷的预览和更低的处理成本，在开销较大的节点下游工作时可节省时间和资源。使用缓存上游预览结果的预览上会出现闪电图标，如下所示：

改进的节点缓存

在此更改之前，如果您在不进行任何逻辑更改的情况下两次预览同一节点，系统会缓存第一次预览的结果，并在第二次预览时复用这些结果。但如果您随后预览某个下游节点，该节点将无法访问其他节点的缓存结果。上游节点需要从头开始重新计算。

现在，管道构建器中的所有节点预览都可以利用缓存的结果，因此只需计算额外的下游节点。

请看以下示例数据集：

如果您预览 C，则节点 Dataset → A → B → C 会被计算。在此更改之前，如果您随后预览 D：

  • 节点 Dataset → A → B → C 会被重新计算，此外还有 D。

在此更改之后，如果您预览 D ，且之前预览过 C：

  • 只有节点 C → D 会被计算，因为节点 D 现在可以使用缓存的结果，这些结果来自节点 C。

请注意，所有节点预览最多计算 500 行。无法从此功能中受益的操作包括：改变行数的操作、联接、聚合或逻辑更改。
