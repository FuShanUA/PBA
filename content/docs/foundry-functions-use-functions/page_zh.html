变量

大多数 Workshop 变量 可以由 Function 支撑，使应用构建者能够使用函数计算值，然后在 Workshop 中使用这些值。默认情况下，当某个变量依赖的另一变量更新时，该变量的值会重新计算。这使得能够根据用户反馈灵活地重新计算值——例如，当用户编辑输入组件时，依赖它的 Function 支撑的对象集变量将自动重新计算。

Function 支撑的变量会对相同输入缓存结果，而不是重新计算。配置变量的 重新计算行为，或使用 设置变量值 事件来显式触发重新计算。

要了解更多信息，请参阅 关于如何使用函数支撑 Workshop 变量的教程.

对象表格：派生属性

Workshop 的 对象表格 组件可以配置为计算 Function 支撑的列，该列可根据用户输入更新，并在最终用户滚动浏览表格时实时重新计算。您可以查看 使用此功能的完整教程.

Function 支撑的列可以返回媒体引用。当函数返回带有 mediaReference 属性的 mimeType 和 reference 类型时，对象表格会自动将结果渲染为媒体，而不是原始数据。这支持基于自定义函数逻辑在表格列中动态展示媒体。

图表：派生聚合

Workshop 的 图表：XY（Chart: XY） 组件支持使用 Function 支撑的聚合按需计算聚合值。如果您希望聚合数据基于用户选择，这将非常有用。要在图表组件中使用函数，只需点击配置图表图层并选择 时间序列集.

操作

操作类型 使应用能够以灵活且安全的方式更改 Foundry 本体论中的对象，并分发外部通知和副作用。在操作中，函数提供了完全的灵活性，使代码作者能够定义应如何更新对象或如何配置副作用。

Function 支撑的操作

Function 支撑的操作使用 本体论编辑 API 来定义对象更新的逻辑。这使您能够用代码表达复杂的编辑——例如，更新与某个起始对象关联的每个对象。 请参阅关于如何端到端使用 Function 支撑的操作的教程。

副作用：通知

操作可以配置为向指定用户发送通知。您可以使用函数计算哪些用户应接收通知，以及通知本身的内容。这提供了灵活性，例如加载存储在对象中的接收者用户 ID，或基于对象数据渲染电子邮件内容。要了解更多信息，请查阅 有关通知的完整文档 以及一份 关于如何使用函数配置通知的指南.

副作用：Webhook

还可以将 Action 配置为在应用时触发 Webhook。Webhook 支持将 Foundry 与其他系统集成，使用户应用的 Action 能够写回 Foundry 之外的 API。您可以使用函数来计算应发送给将要执行的 Webhook 的参数，从而实现诸如基于对象数据填充 Webhook 参数之类的工作流。 查看有关 Webhook 的完整文档。

由于历史原因，Slate 产品有自己的“函数”概念，即位于每个 Slate 文档中的 JavaScript 逻辑代码片段。这就是函数产品被称为“Foundry functions”并位于 平台 标签页下的原因。Slate 的函数功能支持在文档内进行快速、简便的数据操作，但不原生支持对象。

您可以将 Slate 的函数与 Foundry 函数结合使用——例如，可以从 Foundry 函数返回数据并在 Slate 函数中进行处理，或者使用 Slate 函数计算应传递给 Foundry 函数的参数。

发布后，我们建议在 允许您创建函数支撑的自动化，当满足指定条件时自动执行函数。

配置函数效果时，您可以选择一个函数并指定其版本。对于稳定版本（1.0.0 及更高版本），您可以启用到兼容版本的自动升级。Automate 中的函数异步执行，最长可运行 4 小时。

具有本体论编辑返回类型的函数在 Automate 中用作效果时，其编辑不会被应用。欲了解更多信息，请参阅 函数效果文档.
