建立连接

General

为什么 Connector 需要在源 SAP 系统的 SAP ABAP 平台上安装 ABAP 附加组件？

这种方法具有诸多优势，包括：

  • 能够监控 SAP 资源使用情况，防止系统过载。
  • 可以更广泛地访问 / 查询 SAP 工件（例如视图、BW InfoProviders 和 BEx 查询，而不仅仅是原始数据）。
  • 在 Foundry 中提供丰富的源探索体验，显著加快在 SAP 中查找相关数据的速度，并支持批量创建数据同步。
  • 对增量数据同步（变更数据捕获）提供更广泛的支持。
  • 提供更多调试工具，用于排查数据同步失败时的问题。

系统与版本

Connector 支持哪些 SAP 系统？

  • SAP R/3、SAP ECC 和 SAP S/4HANA
  • SAP SLT 复制服务器（用于变更数据捕获）
  • SAP BW（包括 APO 等工具）

Connector 支持哪些版本的 SAP？

ABAP 附加组件运行在 SAP ABAP 平台（前身为 SAP NetWeaver Application Server）上，因此 SAP_BASIS 组件版本最为相关。SAP_BASIS 是技术组件版本，适用于 SAP NetWeaver 和 SAP S/4HANA 系统。 我们推荐的最低 SAP_BASIS 版本如下：

  • SAP_BASIS 7.4 SP5 或更高版本
  • SAP_BASIS 7.5(无最低 SP 级别要求)

这些均为最低版本。连接器支持所有更高的 SAP_BASIS 版本,包括基于 SAP_BASIS 8.x 的 SAP S/4HANA 版本(例如 SAP_BASIS 816)。

如果您计划使用 通过 OData 的 SLT,OData 组件(PALODATA)需要 SAP_BASIS 7.50 SP09 或更高版本。

如果您的主 SAP 系统运行的 SAP_BASIS 版本低于 7.4，我们提供一种解决方案，可公开 Connector 功能的一个子集。但是，该解决方案仍需要一个 SAP_BASIS 版本为 7.4 或更高的系统充当网关，Foundry 将通过该网关连接到较低版本的系统；此应用服务器可以是空的，也可以是较新 SAP 系统（如 BW）正在使用的服务器。

Connector 是否支持 SAP IBP / SAP Ariba / ... ？

如果 SAP 系统或模块运行在 SAP ABAP 平台上，则 Connector 可以从中提取数据。

但是，如果 SAP 系统基于云（例如 SAP IBP）或不基于 ABAP 平台（如 SAP Ariba），则此 Connector 并非合适的数据提取解决方案。请联系 Palantir Support，了解从这些系统提取数据的其他方案。

卸载

附加组件可以卸载吗？

是的。该附加组件使用自己的命名空间，卸载后会从 SAP 系统中移除所有内容。唯一残留的痕迹将出现在 SAINT 安装日志中，用于显示附加组件的安装和卸载时间。

负载与性能

我们如何确保 Connector 不会使我们的 SAP 系统过载？

Connector 在设计时将 SAP 系统的负载和性能作为首要考虑因素。它提供资源检查功能，旨在确保从 SAP 系统复制数据不会危及最终用户体验或其他关键流程。

数据提取采用分页方式，并且在每次页面请求之前，附加组件会评估内存利用率、CPU 利用率（系统和用户）以及正在运行的工作进程数量（对话和后台）。如果这些指标中的任何一个超出一组完全可配置的阈值，提取将被中止，并在稍后资源可用性可能充足时重试。

此功能已在许多大型企业的复杂生产 SAP 系统环境中使用——在这些环境中，Connector 正在复制数十亿行数据——并且已被证明可以保护这些系统免受过量负载的影响，避免对最终用户或其他正在运行的进程造成干扰。

许可

使用 Connector 是否需要额外的 SAP 许可证？

SAP 许可合规性由您负责

由于 Palantir 与 SAP 无关联，也无法就您的 SAP 许可提供法律建议，因此评估您现有或潜在 SAP 系统及 Connector 使用情况的范围和细节，以及其对您的 SAP 许可和合同的影响，完全由您自行负责。

根据我们的经验，通过应用层从 SAP ERP 系统定期提取数据可能被视为 SAP 所称的“间接静态读取”，而在第三方非 SAP 系统中使用这些数据可能无需获得许可。但是，用户从第三方非 SAP 系统将数据写回 SAP 时，通常可能需要额外的 SAP 许可。

如有任何疑虑，请咨询您的法律顾问和/或 SAP 代表，讨论您的 SAP 使用情况和许可。

安全性

所有数据在传输中和静态存储时是否都经过加密？

是的：从 SAP 到 Data Connection 代理以及从代理到 Foundry 的数据传输均通过 HTTPS 进行；临时暂存在 Data Connection 代理主机上的数据是加密的。

附加组件使用哪些类型的授权角色？

附加组件使用四种类型的授权角色：

  • 服务角色： 这些角色是附加组件运行所必需的。请勿修改这些角色。
  • 内容角色： 从 SAP 系统提取数据需要这些角色。可以通过复制这些角色并根据业务需求进行修改。
  • 写回角色： 如果启用从 Foundry 到 SAP 系统的写回功能，则需要这些角色。
  • 监控和调试角色： 这些角色是向 Foundry 公开 SAP 系统信息以启用远程监控所必需的。

更多详情，请参阅 授权角色.

在尝试将数据同步到 Foundry 时遇到 SSL 问题，该如何解决？

  • javax.net.ssl.SSLHandshakeException: PKIX path building failed
    • 这意味着 Data Connection 代理没有足够的信息来验证与 SAP 系统的 HTTPS 连接是否有效。
    • 通常，可以通过将相关的 SSL 证书上传到 Data Connection 代理的信任库来解决此问题。
    • 要下载 SSL 证书，请在安装了 Data Connection 代理的（虚拟）机器上运行以下命令（将 $HOST and $PORT 替换为 SAP 系统的主机和端口号）：
    openssl s_client -showcerts -servername $HOST -connect $HOST:$PORT </dev/null 2>/dev/null |sed -ne '/-BEGIN CERTIFICATE-/,/-END CERTIFICATE-/p' | python3 -c "from sys import stdin; text = stdin.read(); ca_cert = text.split('-----BEGIN CERTIFICATE-----')[-1][:-26]; ca_cert = ca_cert.replace('\n', ''); print('\n' + ca_cert)"
    请注意，这假定 openssl 和 python3 已安装在机器上。
    • 该命令将输出 SSL 证书的长字符串表示形式；请将此字符串复制到剪贴板。
    • 现在，导航到 Foundry UI 中 Data Connection 代理的配置页面。
    • 点击 代理设置 > 管理代理证书 > 添加新证书.
    • 为证书指定一个别名（例如其来源的 SAP 系统的名称），并将剪贴板中的证书粘贴到标题为“pem...”.
    • 保存更改，然后重启代理。
  • javax.net.ssl.SSLPeerUnverifiedException: Hostname XXXXX not verified
    • 这通常意味着证书没有配置任何 SAN（主题备用名称）。
    • 由于使用 CN（通用名称）验证域名的做法已被弃用，我们建议您要求 SAP Basis 团队（或安全团队）使用 SAN 签发新证书。
    • 虽然不推荐，但对于非生产场景，可以在 Foundry 中的 SAP 源配置上使用以下设置来启用旧版主机名验证器： useLegacyHostnameVerifier: true.

数据集成方法

为什么我们应该从源 ERP（而不是例如 SAP BW）中提取数据？

从最细粒度的可用源数据开始，有助于确保数据集成在下游应用中最灵活、最有用。使用预处理数据看似是一条捷径，但这样做会立即缩小未来可解决的问题范围。

如果您想使用现有的 BW 报表或查询，一个好的模式是同时提取原始 ERP 数据 和 和 BW 数据。

技术细节

在 Foundry 中针对给定 SAP 源运行数据同步时会发生什么？

当 Foundry 针对给定的 SAP 源运行数据同步时，会发生以下步骤：

  1. Data Connection 协调器会尝试联系合适的 Data Connection 代理以启动同步。
  2. 在 Data Connection 代理上运行的 SAP 插件被触发并启动同步过程。
  3. 发送到 SAP 附加组件的第一个请求是分页初始化请求，该请求会使 SAP 附加组件查询相关的表或对象，并开始将数据页（高度压缩）写入 /PALANTIR/ 空间.
  4. 随后发送到 SAP 附加组件的请求会按顺序轮询数据页（如果给定页面尚不可用，则暂停并重试），直到到达最后一个数据页——这些数据页会以加密的 Apache Parquet 文件形式写入 Data Connection 代理主机上。
  5. 在检索到最后一页数据后，会向 SAP 附加组件发送分页关闭请求。
  6. Data Connection 代理随后开始将 Apache Parquet 文件上传到 Foundry，直到所有数据都已传输到目标数据集。

如何解决以下数据同步错误？

  • Unexpected value encountered in SAP data Failed to parse value XXX in field YYY
    • 如果日期或数值格式错误且无法解析，则可能出现此情况。启用 的模式规则，这些规则由 Foundry 流使用。如果数据集将在流式管道中使用，则需要启用此设置。 同步选项，将无法解析的值设置为 null 并继续。
  • Current CPU user load(X%) is higher than the max. CPU user parameter(Y%)., Please increase CPU_USER threshold value!, System resources are below threshold values.
    • 当 CPU、内存或工作进程资源检查失败时，您可能会看到此类错误。问题在于，根据为防止系统过载而定义的阈值，相关系统资源不足。有时这可能是理想的结果——正确的解决方案是等到系统负载较低时再重试同步。但是，也可能是所涉及的资源检查阈值过于保守。要了解如何重新配置阈值，请参阅 性能参数.
  • ERROR : User XXXXX does not have enough authorization for this service call.
    • 此错误表明尚未为 SAP 附加组件所使用的技术用户生成必要的授权角色，或者角色未被正确分配。请查看 授权角色.

在为 SAP 中的任意表/对象设置增量同步时，选择哪个字段作为 incrementalField?

理想情况下，提供的增量字段应为单调递增的值；然而，并不总是能找到这样的字段。最佳选择可能是日期字段（不含时间部分）。因此，系统使用“大于或等于”比较（而不仅仅是“大于”），以便在上一次同步在某个日期中途运行时不会遗漏任何数据。因此，Foundry 中生成的数据集中可能出现重复值。这些重复值应在 Foundry 的数据转换管道中作为第一步予以删除；例如，通过主键检查重复行。请参阅 的信息。 以了解更多详情。

从事务类型切换时，为什么整个表被复制了 SNAPSHOT to APPEND （以启动增量数据同步）？

如果数据同步以 SNAPSHOT 事务类型开始，则连接器不会跟踪任何增量状态。随后切换到 APPEND 将导致首次增量同步从 SAP 系统中提取所有数据，之后才继续仅提取“增量”（自上次同步以来发生更改的内容）。因此，建议提前规划哪些数据同步应为增量同步，并以 APPEND 事务类型启动这些同步。

如果数据集由于从 SNAPSHOT to APPEND切换而导致数据重复，请按照 重置增量状态 步骤操作。

重试次数、重试延迟和请求超时。

有哪些类型的资源检查可用？

有三种不同的资源检查可用：

  • CPU_CHECK： 防止在 CPU 利用率超过给定阈值时运行同步
  • MEMORY_CHECK： 防止在内存利用率超过给定阈值时运行同步
  • PROCESS_CHECK： 防止在可用进程数低于给定阈值时运行同步

默认行为是什么，如何覆盖它？

默认情况下，所有资源检查均已开启 和 这些资源检查是“持续”应用的，即在请求每个页面之前都会进行检查，而不仅仅是在同步开始时。

要在单个数据同步级别覆盖默认行为，请在 Data Connection UI 中执行以下步骤： Extras > 资源检查 / 持续资源检查 > 关闭.

SAP 业务数据仓库（BW）功能

支持哪些 SAP BW 功能？

可以从以下位置提取数据：

  • SAP BW InfoProviders – 包括 DataStore 对象 (DSO)、InfoCube 和 InfoObject
  • SAP BW BEx 查询

敏感数据

有哪些选项可以确保敏感数据不会离开 SAP 系统，同时又不阻碍所需非敏感数据的提取？

在最高层级上，可以修改附加组件的内容 授权角色 以防止提取整个表或对象。

可以使用筛选器在行级别限制可提取的数据，这些筛选器在 然后 数据离开 SAP 系统之前应用：

  • 可以在 Foundry 的 Data Connection UI 中的同步配置中定义筛选器。
  • 但是，也可以在 SAP 系统本身的 Connector Cockpit 中设置“预筛选器”——这些筛选器将应用于表 此外还叠加 来自 Foundry 的任何筛选器，这意味着它们也将应用于 Source Explorer 和同步配置 UI 中显示的数据预览。更多详情，请参见 预筛选器.

有两种按列限制数据提取的方法（这些方法与上述筛选器一样，在 然后 数据离开 SAP 系统之前应用）：

  • 同步配置 UI 提供“删除列”功能，用于选择要从数据提取中排除的列。
  • Connector Cockpit 提供一系列 加密和数据脱敏 configurations.

回写

技术细节

如何实现从 Foundry 到 SAP 的写回？

ABAP 附加组件支持从 Foundry 调用 SAP 函数。建议使用 BAPI（Business API）函数，因为其结构定义清晰且失败信息明确，但如有需要，该附加组件也支持调用任何类型的函数模块。

要设置写回，您需要创建一个 Foundry Webhook。更多详情，请参见 Webhook 以了解概览，以及 Webhook 配置 - SAP 以了解 SAP 特定的详细信息。

具名用户归属

是否可以以具名用户（而非技术用户 / 服务账户）的身份从 Foundry 写回 SAP？

可以 – 通过 OAuth 2.0 授权码流程支持此功能。在此场景中，SAP 系统充当 OAuth 2.0 服务器，而 Foundry 充当 OAuth 2.0 客户端。当用户首次尝试从 Foundry 向 SAP 写回数据时，他们将被重定向到 SAP 系统中的授权对话框，以确认是否允许 Foundry 代表其向 SAP 写回数据。

请参阅 使用 OAuth 2.0 的用户归属 SAP 写回 以了解更多详情。

升级

SAP 附加组件如何升级？

您将获得一个新的支持包 (SP)。请按照 文档说明进行升级.

SAP 附加组件多久发布一次新版本？

没有固定的发布计划，但通常会每 2-3 个月交付一个新的支持包 (SP)。

日常维护

SAP 附加组件是否确保其日志表会定期截断，以避免表空间被填满？

是的，但您需要启用相关的清理作业，因为安装过程无法自动开启这些作业。 SAINT 有关更多详细信息，请参阅 设置和配置清理作业.
