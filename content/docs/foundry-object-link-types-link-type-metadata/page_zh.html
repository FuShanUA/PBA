元数据参考

关联类型在 Foundry 本体论中由以下元数据表示：

  • ID： 关联类型的唯一标识符，主要用于在配置应用程序时引用此类型的关联。例如， employee-employer 可能是在 Employee 和 Company 对象类型之间定义的关联类型的 ID。
  • RID： 在 Foundry 中为每个资源自动生成的唯一标识符。关联类型的 RID 将在整个平台的错误消息中被引用。
  • 状态： 向用户和其他本体论构建者发出的信号，表明关联类型在开发过程中所处的阶段。它可以是 active、 experimental或 deprecated。默认情况下， Employee → Employer 关联类型的状态将为 experimental。详细了解 状态。
  • 对象类型： 通过关联类型定义相关联的对象类型。例如， Employee → Employer 关联类型将引用 Employee 和 Company 对象类型。
  • 基数： 向应用程序指示关联类型中的每个对象类型是具有一个还是多个对象。例如，Employee 对象类型在关联类型 Employee → Employer 中的基数为 many ，而 Company 对象类型的基数为 one，因为多个员工关联到同一个雇主。Employee 对象类型在关联类型 Direct Report ↔ Manager 中各自的基数为 many 直接下属是否可以有多个经理，以及经理是否可以有多个直接下属。
  • 键： 用于创建关联的属性或列。
    • 在一对一或一对多基数关联类型中，一个对象类型的属性（外键）引用另一个对象类型的主键属性。外键与主键之间的这种引用关系定义了对象之间的关联。例如，在 Employee → Employer 关联类型中， Employee 对象类型可能有一个 employer ID 属性（外键），该外键引用 company ID 属性（主键），该主键属于 Company 对象类型。
    • 在多对多基数关联类型中，一个包含成对主键的表定义了两个对象之间的关联。这些关联类型需要指定一个联接表，并对这些键进行映射，以告知应用程序联接表中的哪些列引用关联类型中哪些对象类型的主键。例如，支撑 Direct Report ↔ Manager 关联类型的联接表可能包含成对的 employee numbers，其中每一对表示一个 Direct Report ↔ Manager 关联。
  • 显示名称： 在用户应用程序中，任何人访问此类关联时所看到的名称。关联类型的每一侧都有一个显示名称。关联类型的一侧表示 指向 该对象类型的关联。例如，在 Employee → Employer 关联类型中， Employee 对象类型的显示名称为 Employee ，而 Company 对象类型的显示名称为 Employer。
  • 复数显示名称： 在用户应用程序中，任何人访问包含多个关联对象类型的此类关联时所看到的名称。例如，在 Employee → Employer 关联类型中， Employee 对象类型的复数显示名称为 Employees ，而 Company 对象类型则没有复数显示名称，因为每个员工只能对应一家公司。
  • API 名称： 在代码中以编程方式引用关联类型时使用的名称。关联类型某一侧的 API 名称可用于返回该类型的对象。例如，如果 Employee → Employer 关联类型 Employee 一侧的 API 名称为 employee，那么调用 Company.employee.get() 将返回 Employee 对象，它们与那些 Company 对象相关联。阅读更多关于 API 名称的信息。
  • 可见性： 向用户应用程序发出的指示，用于说明应以何种显著程度显示关联类型的一侧（指关联 指向 该侧的对象类型）。 prominent 关联类型的一侧将使应用程序优先向用户显示关联类型的这一侧。 hidden 关联类型的一侧将不会出现在用户应用程序中。默认情况下，关联类型的 Employee 侧和 Company 侧将具有可见性 normal。
  • 类型类： 由用户应用程序解释的附加元数据。请阅读有关 类型类的更多信息。
