在 Workshop 中使用函数

对象函数 (FOO) 让代码作者在对象数据上编写业务逻辑。函数可以读取对象属性、聚合或编辑这些数据，并遍历本体论中定义的关联。 了解有关如何定义和使用函数的更多信息。

在 Workshop 模块中，函数可以以多种方式使用。函数支撑的操作使模块能够触发复杂的对象编辑和写回。诸如指标卡片之类的组件可以在模块内显示函数的输出，以帮助引导用户决策。函数还可以定义用于在模块中加载对象数据的复杂对象集。

Workshop 中的函数支撑操作

在 Ontology Manager 中定义新的操作类型时，可以将函数用作操作类型规则逻辑的一部分。这通常有助于在操作类型中实现比内置选项（添加对象、删除对象、修改对象、添加关联或删除关联）更复杂的写回。 了解有关如何定义函数支撑操作类型的更多信息。

定义函数支撑操作类型后，即可像使用其他任何操作类型一样在 Workshop 中使用它。 了解有关如何在 Workshop 中公开操作类型的更多信息。

Workshop 中的函数支撑变量

函数还可以在 Workshop 中用于填充模块中变量的值。以下示例将引导你创建一个数值变量，并使用一个计算飞机飞往给定机场的航班数量的函数的输出来填充该变量。

此示例仅用于说明，你可能无法完全按照所述完成每个步骤。由于你的 Foundry 本体论是针对你的组织定制的，你可能无法访问完成本教程所需的本体论对象。

首先，看一下我们将从 Workshop 模块中调用的函数。如下所示，该函数名为 flightsForAircraftToDestination。它接受一个 ExampleAircraft 对象和一个表示目的地机场三字母机场代码的字符串作为输入，然后返回该飞机飞往目标机场的航班数量。

本页面上的函数示例显示在 TypeScript v2, Python日 或中。选择与你的函数编写方式匹配的标签页；随后的 Workshop 配置步骤适用于所有三种方式，但 Python 函数会将其输入暴露在其 snake_case 名称下。如需完整比较，请查看 TypeScript v1 与 TypeScript v2 的对比.

这三种实现在计数方式上有所不同。TypeScript v1 使用 .all() 加载每个关联的航班，并在内存中对生成的数组进行过滤。而 TypeScript v2 和 Python 则将过滤器应用于关联的对象集，并向本体论请求计数。因此，函数返回的是一个数字，而不是每个航班对象。由于函数支撑的变量在其输入发生变化时会重新计算，在服务器上进行计数可以随着航班数量的增长保持变量的响应速度。

TypeScript v1 使用 @Function() 装饰器在类方法上注册函数，TypeScript v2 将其注册为文件的默认导出，而 Python 使用 @function 装饰器配合使用。

import { Function, Integer } from "@foundry/functions-api";
import { ExampleAircraft } from "@foundry/ontology-api";

export class MyFunctions {
    @Function()
    public flightsForAircraftToDestination(aircraft: ExampleAircraft, destinationAirportCode: string): Integer {
        return aircraft.flights.all()
        .filter(flight => flight.destinationAirport === destinationAirportCode)
        .length
    }
}

import { Osdk } from "@osdk/client";
import { Integer } from "@osdk/functions";
import { ExampleAircraft } from "@ontology/sdk";

export default async function flightsForAircraftToDestination(
    aircraft: Osdk.Instance<ExampleAircraft>,
    destinationAirportCode: string
): Promise<Integer> {
    const result = await aircraft.$link.flights
        .where({ destinationAirport: { $eq: destinationAirportCode } })
        .aggregate({ $select: { $count: "unordered" } });
    return result.$count;
}

from functions.api import function, Float
from ontology_sdk.ontology.objects import ExampleAircraft, ExampleFlight

@function
def flights_for_aircraft_to_destination(
    aircraft: ExampleAircraft,
    destination_airport_code: str,
) -> Float:
    return (
        aircraft.flights()
        .where(ExampleFlight.object_type.destination_airport == destination_airport_code)
        .count()
        .compute()
    )

接下来，开始在 Workshop 模块中连接此函数。目标是从模块传入函数输入，然后在微件中显示函数输出。

首先，从屏幕左上角的 变量 菜单创建一个新的数值变量。使用 + 选项旁边的 变量 标题来创建一个新变量，选择 数值，然后选择 函数 ，如下所示。

接下来，查找并选择要用于此变量的函数。使用函数选择器搜索你的函数，该函数必须标记有发布版本才会显示在此列表中。了解有关 函数版本控制的更多信息.

选择所需函数后，配置其输入。在下面的示例中， aircraft 输入由模块中当前选定的飞机对象填充，而 destinationAirportCode 输入由一个变量填充，该变量在应用程序的其他位置捕获所选航班的目的地机场。请务必为变量命名，并将其放置在变量文件夹中，以便更容易找到。

函数支撑的变量会缓存其结果。当函数接收到相同的输入时，Workshop 会返回缓存的结果，而不是重新运行计算。如果您需要重新计算该值，请使用 set variable value 事件，或配置变量的 重新计算行为 来控制其何时重新计算。

OAuth 支撑的函数

调用使用 OAuth 2.0 出站应用程序 配置的源的函数在 Workshop 中直接使用时（包括作为函数支撑的变量或填充小部件内容），无法触发交互式授权提示。如果用户尚未授权该出站应用程序，函数将失败。要在 Workshop 中使用 OAuth 支撑的源，请将函数包装在 或填充小组件内容的函数）无法触发 OAuth 2.0 交互式授权提示。如果用户尚未对出站应用程序进行授权，函数将失败，而不会显示提示。要在 Workshop 中使用 OAuth 支撑的函数，请将其封装在 中，它可以在操作执行过程中显示授权提示。

要向用户显示此函数的输出，请使用下文所述的 Metric Card 小部件。

带函数的 Metric Card

Metric Card 小部件为构建者提供了一种在模块中显示关键信息的方式。让此处显示的统计数据由函数生成会很有帮助。在 Metric Card 配置中，将给定指标设置为从您在上述步骤中定义的函数支撑的数值变量填充。

下面的截图显示了生成的模块，右侧是我们带函数的 Metric Card。当用户在左侧的甘特图上更改选择不同的航班时，Metric Card 会动态更新，显示所选飞机飞往目的地机场的航班总数。在本例中，该飞机飞往休斯顿（IAH）的航班总数为 680。
