基于文件的同步

在使用以下工具创建基于文件的同步后 exploration，你可以在同步页面的 配置 标签页中更新配置。

基于文件的概念性摄取模式

虽然 Foundry 基于文件的同步提供了低级设置以实现更大的灵活性和可配置性，但大多数用例都会遵循已知的模式。下表记录了已知模式以及实现所需行为所需的低级设置，以及可能与这些模式相矛盾的设置。

批量镜像，使用 SNAPSHOT （默认）

  • 事务类型： SNAPSHOT
  • 筛选器： None

每次运行都将 摄取所有文件 （嵌套在外部系统的子目录中，包括之前运行中已摄取的文件），并提交一个 SNAPSHOT 事务到输出数据集，其中恰好包含这些文件。输出的 Foundry 数据集视图 将包含单个 SNAPSHOT 事务，其中包含所有文件。

矛盾的设置

  • 筛选器： Exclude files already synced
    • 会导致 尾随窗口摄取模式.
  • 筛选器： Limit number of files
    • 如果限制低于可用文件的总数，会导致输出的 Foundry 数据集视图仅包含所需文件的一个非确定性子集。
  • 筛选器： At least N files
    • 如果外部系统指定子文件夹中没有 N 嵌套文件，此设置将产生一个空事务，并导致摄取 0 个文件。否则，此设置没有任何效果。

增量镜像，使用 APPEND

  • 事务类型： APPEND
  • 筛选器： Exclude files already synced

输出的 数据集视图 将包含一系列 APPEND 事务，这些事务聚合起来包含指定子文件夹中任何作业运行期间曾存在的所有嵌套文件。每次运行将摄取 所有尚未摄取的文件（以文件路径名为键），并提交一个 APPEND 事务到输出数据集。

矛盾的设置

  • 筛选器： Exclude files already synced 使用 Last modified date or File size option
    • 当现有文件的 APPEND 发生变化时，这些选项会尝试在 Last modified date or File size 事务中错误地重新摄取以文件路径名为键的现有文件。要允许更新现有文件，请查看 增量，使用 UPDATE 摄取模式。

增量镜像，使用 UPDATE

  • 事务类型： UPDATE
  • 筛选器： Exclude files already synced
  • 以下一项或多项：
    • 筛选器： Exclude files already synced 使用 Last modified date option
    • 筛选器： Exclude files already synced 使用 File size option

输出的 数据集视图 将包含一系列 UPDATE 事务，这些事务聚合起来包含指定子文件夹中任何作业运行期间曾存在的所有嵌套文件的最新版本。每次运行将摄取所有尚未摄取的文件 or 以及此后发生变化的文件（以文件路径名为键），并提交一个 UPDATE 事务到输出数据集。

注意事项

仅当对现有文件的修改是外部系统不可协商的行为时才使用此模式。虽然从某种意义上说摄取是增量的，即每次运行仅摄取新增或已更改的文件，但下游管道无法增量运行，因为输出数据集（下游管道的输入）不是 仅追加.

尾随窗口，使用 SNAPSHOT

  • 事务类型： SNAPSHOT
  • 筛选器： Exclude files already synced

输出的 数据集视图 将包含单个 SNAPSHOT 事务，其中仅包含 之前任何作业运行中从未出现过的文件。每次运行将摄取所有尚未摄取的文件（以文件路径名为键），并提交一个 SNAPSHOT 事务到输出数据集，其中恰好包含这些文件。

当只有“最近”的文件（在外部系统中于倒数第二次和最后一次运行之间创建的文件）与下游管道和操作相关时，此模式非常有用。之前运行中摄取的文件在输出数据集视图中将不可见。

矛盾的设置

  • 筛选器： Limit number of files
    • 当在给定窗口期间外部系统中创建的文件数量超过指定限制时，将摄取这些文件的一个非确定性子集，其余文件将推迟到后续窗口。此数量可能随时间快速增长，从而破坏输出数据集中预期的“时效性”。

除了限制输出中所需文件类型的过滤器之外，始终可以安全地指定子文件夹和可选的正则表达式。此类过滤器包括 Last modified after 以排除过时的文件，或 Path does not match 以排除具有特定文件扩展名的文件，例如 .sh 可执行文件。

只有 Exclude files already synced, At least N files日 Limit number of files 过滤器与所需的同步模式紧密耦合，可能会对其产生干扰。

同步失败行为

与所有 批量同步一样，基于文件的同步是事务性的。如果同步在任何时刻失败，事务将被中止，该次运行中的所有文件都不会提交到数据集。

例如，如果同步配置为上传一百万个文件，而在上传完除一个文件之外的所有文件后发生网络错误，则整个事务将被中止。所有已上传的文件都不会提交，数据集视图也不会被修改。

由于这种行为，在单次运行中处理大量文件的同步更容易受到瞬时故障的影响。为了减少同步失败的影响，请考虑使用 增量式 APPEND 同步 并配合文件数量限制过滤器，这样每次运行只处理较小批量的文件。这样，发生故障时只需重新同步当前批次，而无需重新同步所有文件。

一个

过滤器允许您在源文件导入 Foundry 之前对其进行过滤。支持的过滤器类型包括：

  • 排除已同步的文件： 仅同步自上次同步以来新增或大小/日期发生修改的文件。

Exclude files already synced 存在已知的规模限制，因为它在每次同步运行时都需要扫描所有文件。对于摄取大量文件的同步，我们建议将其拆分为一个 SNAPSHOT 用于历史数据的同步和一个 INCREMENTAL 同步，并配合 Exclude files already synced，这样过滤器只会应用于较新的少量文件子集。如果连接器支持，请考虑改用 Modified since last sync 过滤器。

  • 自上次同步以来已修改： 仅同步自上次同步以来新增或修改的文件。相比 Exclude files already synced 这是一种轻量且更快的替代方案，目前支持 S3 and Google Cloud Storage sources.

此过滤器依赖于源报告的最后修改时间戳。在兼容 S3 的端点上，请与您的提供商确认：每当文件内容发生变化时时间戳都会更新，且时间戳时钟稳定准确；否则，请使用 Exclude files already synced.

  • 路径匹配： 仅同步路径（相对于连接器根目录）与正则表达式匹配的文件。
  • 路径不匹配： 仅同步路径（相对于连接器根目录）与正则表达式不匹配的文件。
  • 最后修改时间晚于： 仅同步在指定日期和时间之后修改过的文件。
  • 文件大小介于： 仅同步大小介于指定的最小和最大字节值之间的文件。
  • 任一文件路径匹配： 如果任一文件的相对路径与正则表达式匹配，则同步该子文件夹中未被其他过滤器过滤的所有文件。
  • 至少 N 个文件： 仅当剩余文件至少为 N 个时，才同步所有已过滤的文件。
  • 限制文件数量： 限制每个事务中保留的文件数量。此选项可以提高增量同步的可靠性。

转换器

转换器允许您在上传到 Foundry 之前执行基本的文件转换（例如压缩或解密）。在同步过程中，被选择摄取的文件将根据所选的转换器进行修改。

我们建议不要使用 Data Connection 转换器，而是使用 Foundry 中的 如果希望用户在每次运行预览前手动确认，请开启 和 代码仓库 来执行数据转换，以受益于数据溯源和分支功能。

Data Connection 支持以下转换器：

  • 使用 Gzip 压缩
  • 合并多个文件
    • 将多个文件合并为单个文件。
  • 重命名文件
    • 将文件名中所有出现的给定子字符串替换为新的子字符串。
    • 通过替换的方式从文件名中去掉目录路径 ^(.*/) with /.
  • 使用 PGP 解密
    • 解密使用 PGP 加密的文件。
    • 要求代理系统已配置 PGP 密钥。
    • 不适用于在 Foundry worker 上运行的同步。
  • 在文件名后追加时间戳
    • 以自定义格式为每个摄取文件的文件名添加时间戳。

完成策略

遗留版

完成策略处于 遗留 开发阶段，预计不会再进行额外的开发。完成策略在现有同步上为只读，且无法在新的同步上进行配置。我们建议使用下游 外部转换 作为替代方案。

完成策略是一种在文件成功批量同步到 Foundry 数据集后尝试删除这些文件及其空父目录的机制。完成策略为只读，且无法在新的同步上进行配置。带有完成策略的现有同步将继续运行，但其配置无法修改。

当数据从中间暂存区（例如文件存储系统）同步而非直接从外部记录系统同步时，此工作流程可能有用。不建议使用此工作流程。Foundry 应直接连接到外部记录系统。在 Foundry 作为记录系统的情况下，数据应直接推送到 Foundry，而不是推送到中间暂存区。

完成策略的限制与替代方案

完成策略存在若干重要的限制和注意事项。这些限制以及可能的缓解措施或替代方案如下所述。

完成策略支持

完成策略处于 遗留 开发阶段，预计不会再进行额外的开发。完成策略在现有同步上为只读，且无法在新的同步上进行配置。完成策略仅适用于使用 ）或您的代理网络（如果使用的源。我们建议改为通过下游转换来实现完成策略提供的功能。

举例来说，假设您有一个 直接连接 指向包含这些文件的 S3 存储桶 foo.txt 和 bar.txt。您想使用文件批量同步将它们复制到数据集，然后从 S3 中删除这些文件。您不应使用完成策略，而应执行以下操作：

  • 配置一个不带任何完成策略的批量同步，并安排其运行。
  • 编写一个下游 外部转换 作业，该作业计划在同步输出数据集更新时运行，并将同步的数据作为输入。
  • 在该外部转换中，编写 Python 转换代码来遍历同步数据集中出现的文件，并调用 S3 从存储桶中删除这些文件。

如果任何删除调用失败，此方法可以重试，并确保在尝试执行任何删除之前数据已成功提交到 Foundry。此方法还与增量文件批量同步兼容。

完成策略是尽力而为的

现有同步上的完成策略是尽力而为的。这意味着它们不保证数据会被有效删除。以下是一些可能导致完成策略失败的情况：

  1. 如果代理 worker 在批量同步将数据提交到 Foundry 之后、但在完成策略运行之前崩溃或重启，完成策略将不会被重试。
  2. 如果用于连接的凭据没有写入权限，批量同步可能会成功读取数据并提交到 Foundry，但无法执行完成策略指定的删除操作。

总体而言，我们建议尽可能使用完成策略的替代方案。不再支持自定义完成策略。

对于目录源，如果您需要确保文件在摄取后被删除，请考虑使用 外部转换通过 SSH 删除文件 来替代。

优化基于文件的同步

本指南适用于正在设置新同步或排查缓慢或不可靠同步问题的用户。如果您的同步已经可靠运行，则无需采取任何操作。

将大量文件同步到单个数据集可能速度缓慢且容易受到瞬时故障的影响。如 同步失败行为中所述，任何时刻的失败都会中止整个事务，这意味着同步规模越大，丢失的工作就越多。

如果数据集随时间不断增长，将数据同步为 SNAPSHOT 所需的时间会增加，因为 SNAPSHOT 事务会将所有数据同步到 Foundry。相反，请使用配置为事务类型 APPEND 的同步来增量导入数据。由于您将同步较小的、离散的数据块，您将创建一个有效的检查点；同步失败只会导致最少量的重复工作，而无需完全重新运行。此外，您的数据集同步将运行得更快，因为您不再需要为每次同步上传所有数据。

配置增量 APPEND 同步

APPEND 事务需要额外的配置才能成功运行。

默认情况下，同步到 Foundry 的文件不会被过滤。但是， APPEND 同步需要过滤器以防止重复导入相同的文件。我们建议使用 Exclude files already synced 和 Limit number of files 过滤器来控制在单次同步中导入到 Foundry 的文件数量。最后， 安排您的同步 以保持与源系统保持最新。
