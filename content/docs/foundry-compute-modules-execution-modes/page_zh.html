执行模式

函数执行模式与管道执行模式

函数模式管道模块
使用您的计算模块将逻辑托管为函数。借助本体论 SDK，在整个 Foundry 中的 Workshop 或 Developer Console 等应用程序中使用这些函数。针对流式传输和实时媒体用例，读取 Foundry 输入并写入 Foundry 输出。此模块将以作业令牌的形式传递，并具有您可指定的访问权限。
使用计算模块函数为您的 Foundry 应用程序提供支持。使用 Foundry 资源权限系统。
从另一个函数执行计算模块函数。在 Data Lineage 应用程序中获取整个 Foundry 的数据溯源。

函数模式权限

无平台权限： 不会为您提供使用本体论 SDK 或平台 API 的访问权限。 应用程序权限： 您的应用程序将使用服务用户进行权限控制，而不是依赖用户权限。

管道模式权限

Foundry 作业令牌将附加到计算模块。作业令牌的作用域仅限于输入和输出资源，可用于获取数据。

函数执行模式

函数模式允许您使用计算模块来托管逻辑，供 Foundry 中的各类应用使用，例如在 Workshop 应用程序中使用，或通过本体论 SDK 调用。您可以使用任何语言定义和编写逻辑， 将其注册为函数，然后通过平台中的函数调用来执行这些逻辑。

函数模式可通过两种权限模式运行：

  • 无平台权限： 您的应用程序将不会被授予访问任何平台 API 或本体论 SDK 的权限。请使用此模式运行无需与 Foundry 交互的逻辑。在此模式下，您仍然可以配置到外部系统的出口。请查阅 来源 以了解更多信息。
  • 应用程序权限： 您的应用程序将使用其随附的服务用户来确定其访问平台 API 和本体论 SDK 的权限。无论计算模块用户是谁，权限都将保持不变。请使用此模式运行需要与 Foundry 交互的逻辑，并为整个应用程序使用一组统一的权限。

使用应用程序权限

应用程序权限可能并非在所有注册中都可用。

创建服务用户

  1. 导航到您计算模块的 配置 页面。
  2. 在 执行模式下，选择一个 函数模块 ，并将其权限设置为 应用程序权限。

  1. 保存您的计算模块配置。系统将自动为您的计算模块创建一个第三方应用程序，并显示其客户端 ID 和服务用户名。

4. [可选] 根据需要配置服务用户，例如限制其对特定标记的访问权限，此操作可在 第三方应用程序 部分中进行，该部分位于 控制面板中。

只有您组织中拥有 Manage OAuth 2.0 clients 权限的用户才能执行此步骤。请参阅 第三方应用程序文档 以了解更多信息。

在您的计算模块中使用服务用户

  1. 添加一个源，其网络策略允许访问您 Foundry 环境的 URL。

  2. 使用客户端 ID 和密钥换取具有所需权限的访问令牌。

管道执行模式

以管道模式执行的计算模块旨在为需要高数据安全性和溯源控制的数据管道工作流提供计算支持。管道模式的工作方式是接收 Foundry 输入，执行用户指定的计算，随后生成输出。整个过程严格遵循 Foundry 构建系统所建立的协议和工作流。

与函数模式不同——在函数模式下，用户通过发送查询直接与计算模块交互——管道模式下的输入、输出及其权限均通过 Foundry 构建系统进行管理。这确保了计算过程中涉及的所有数据都能得到系统性跟踪。通过强制所有输入和输出都经由构建系统，该模块保持了高度的数据完整性和可追溯性，这对 Foundry 数据溯源控制和安全性至关重要。

由于溯源控制要求，管道模式计算模块是非交互式的，这意味着用户无法直接向计算模块发送查询。因此，计算模块在运行后仅对构建系统自动提供的输入执行计算。构建系统还管理来自计算模块输出的信息流。系统提供了接口，用于在以管道模式运行的计算模块容器内与输入和输出进行交互。

总而言之，管道模式强制执行数据安全和溯源控制。如果满足以下条件，用户应选择管道模式：

  • 相关数据高度敏感，必须严格遵守溯源控制、标记控制等要求。
  • 用户希望追踪数据血缘。

添加输入和输出

管道模式计算模块严格遵循 Foundry 构建系统建立的溯源控制和安全模型。默认情况下，计算模块无权与任何 Foundry 资源进行交互。用户必须显式添加 Foundry 资源作为输入和输出，随后系统将授予这些已添加资源的相应权限。

  1. 在管道模式的配置详细信息中，选择添加输入或输出资源。

  1. 从下拉菜单中选择一个资源并为其指定一个唯一标识符。该标识符将用于在容器内检索资源信息。资源必须与计算模块来自同一个项目。当前支持的输入/输出为 Foundry 数据集、流式数据集和媒体集。

与计算模块内的输入和输出进行交互

  1. 持有者令牌将挂载到容器中的一个文件，文件名存储在 BUILD2_TOKEN 环境变量中。该令牌将拥有对输入和输出的权限，并且是访问它们的唯一方式。

In app.py:

with open(os.environ['BUILD2_TOKEN']) as f:
    bearer_token = f.read()
  1. 输入和输出的唯一标识符及其信息的映射将挂载到容器中的一个文件，文件名存储在 RESOURCE_ALIAS_MAP 环境变量中。您可以使用在配置中指定的唯一标识符获取资源信息。资源信息是由 RID 和分支组成的元组（分支可以为 none）。

In app.py:

with open(os.environ['RESOURCE_ALIAS_MAP']) as f:
    resource_alias_map = json.load(f)

input_info = resource_alias_map['identifier you put in the config']
output_info = resource_alias_map['identifier you put in the config']

# structure of resource info
# {
#     'rid': rid
#     'branch': branch (can be none)
# }

input_rid = input_info['rid']
input_branch = input_info['branch'] or "master"
output_rid = output_info['rid']
output_branch = output_info['branch'] or "master"
  1. 现在，您可以使用令牌和资源信息与输入和输出进行交互。例如，如果您的输入是流式数据集，则可以通过请求 stream-proxy 服务来获取最新记录。

In app.py:

FOUNDRY_URL = "yourenrollment.palantirfoundry.com"
url = f"https://{FOUNDRY_URL}/stream-proxy/api/streams/{input_rid}/branches/{input_branch}/records"
response = requests.get(url, headers={"Authorization": f"Bearer {bearer_token}"})

数据溯源与可观测性

管道模式通过 Foundry 构建系统提供内置的数据溯源与可观测性。由于所有输入和输出都经过构建系统，每个数据转换都会被跟踪，并显示在 Data Lineage 应用程序中。这使您能够追踪数据在管道中的流动方式，并审计任何输出的来源。

在管道执行期间，构建系统会在输出数据集上开启事务。这些事务会被自动管理，并在管道成功完成时提交。

其他注意事项

  1. 缩放： 由于没有向计算模块发送任何查询，自动缩放器最终可能会将其缩减至零个副本。要让计算模块持续运行，请将 最小副本数 设置为至少 1，此选项位于 缩放 配置中。
  2. 计算模块客户端： 由于不会有查询发送到计算模块，因此您无需实现 计算模块客户端。请查阅我们关于 计算模块客户端 的文档，以了解更多信息。
