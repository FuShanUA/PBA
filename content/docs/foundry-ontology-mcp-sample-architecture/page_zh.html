示例架构

下图说明了 Ontology MCP (OMCP) 和 Palantir MCP (PMCP) 如何融入横跨 Palantir Foundry 和外部云的更广泛的智能体架构。

使用本体论的智能体

该图展示了接入 Foundry 本体论的两条集成路径。

第一种是无代码集成，来自 外部智能体应用 部分。Microsoft Copilot Studio、 Claude Cowork ↗和 Google Gemini Enterprise 等平台通过 Ontology MCP (OMCP) 直接连接到本体论，无需任何自定义智能体代码。这使得 OMCP 成为希望向现有企业 AI 助手开放本体论数据和操作的团队的实用切入点。

第二种是来自 Cloud A (Azure / GCP)的专业代码集成。两个智能体AlertCreator 和 AlertResolver在 Foundry 之外运行，并使用框架构建，例如 LangChain ↗。它们也可以托管在 Foundry 内部，作为一个 计算模块。无论在何处运行，每个智能体都会通过以下两个 MCP 服务器之一连接到 Foundry 本体论：

  • 本体论 MCP (OMCP)： AlertCreator 使用本体论 MCP 将数据写入本体论，执行预定义操作以创建新 Alert 对象。本体论 MCP 公开了为 Developer Console 应用程序定义的对象类型、操作类型和查询函数，这使其非常适合必须安全地 写入 数据，且操作受到控制和限制。
  • Palantir MCP（PMCP）： AlertResolver 使用 Palantir MCP 与平台本身进行交互，例如更新本体论 类型 或在开发工作流中处理数据集、转换和其他平台资源。

在 Foundry 内部，一个 编排智能体 在容器中运行，从本体论中读取数据，并将工作委派给其他智能体。这种模式允许您将本体论作为记录系统，同时让专用智能体处理各项任务。

使用外部 MCP 服务器的 Foundry 托管代理

编排代理展示了 MCP 的出站方向。Foundry 托管的代理并非向外部客户端公开 Foundry 资源，而是充当 MCP 客户端，向外连接到运行于 Cloud B (GCP)的 MCP 服务器。该 MCP 服务器进而从 PostgreSQL 数据库读取数据，而该数据库本身也是通过一个 MCP 服务器公开的。此模式使 Foundry 托管的代理能够通过标准化的 MCP 接口访问外部系统和远程代理，而无需为每个后端开发自定义连接器。

通过本体论 MCP 公开的工具

本体论 MCP 会将您在 Developer Console 应用中配置的资源转换为代理可调用的 MCP 工具：

  • 对象类型： Developer Console 应用中包含的每个对象类型均可通过 SQL 工具访问，该工具允许代理针对已公开的对象类型发出 SQL 查询，从而读取本体论数据。
  • 操作类型： 应用程序中包含的每种操作类型都会成为独立的 MCP 工具，因此智能体可以调用特定的预定义操作，将数据写入本体论。
  • 查询函数： 各个查询函数可以作为独立的 MCP 工具公开，让智能体能够访问您编写的定制读取或计算逻辑。

将智能体作为工具

本体论 MCP 还支持将其他智能体公开为工具。当您构建智能体逻辑时，使用 AIP Logic 或 AIP 聊天机器人，您可以将该逻辑保存为函数，然后通过 MCP 将其公开。从调用方智能体的角度来看，AIP Logic 函数或聊天机器人只是它可以调用的另一个工具，让您能够在已在 Foundry 中构建的智能体之上组合更高层级的智能体。
