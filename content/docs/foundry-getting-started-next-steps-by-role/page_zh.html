按用户角色划分的后续步骤

现在您已经熟悉了 Palantir 平台并理解了其核心概念，接下来可以探索与您的角色最相关的平台功能。

Palantir 平台中各角色之间的界限可能会发生变化，某些职责和工作流程可能无法完全归入单一角色。您最终可能会承担不同的角色；如果您的组织刚刚开始使用 Palantir，或者您在一个小型实施团队中工作，您可能会在日常工作中使用平台的许多部分。

或者，您也可以通过查看 应用程序参考来探索 Palantir 平台，其中提供了主要平台应用程序的高层次概述。

标准用户角色

基于这一点，以下角色是大多数使用 Palantir 的组织普遍采用的。下面我们将讨论这些高层次角色，以及每类用户如何入门：

  • 数据工程师
  • 应用程序构建者
  • 分析师
  • 数据科学家
  • 平台管理员
  • 数据治理

如果您想立即开始， 可以直接进入 Palantir 平台。

数据工程师

Palantir 的数据集成层为平台中所有其他工作奠定了基础。通过构建和维护数据管道，数据工程师可以产出高质量、相关且频繁更新的数据集，以满足组织的需求。平台提供了多种工具来长期维护数据管道的稳定性，包括程序化的健康检查以及对底层计算的透明可见。

数据工程师使用的主要工具包括 如果希望用户在每次运行预览前手动确认，请开启 和 代码仓库 用于编写数据管道，以及 调度指标 用于端到端地可视化管道。数据工程师还应了解如何使用 推荐的健康检查, 监控视图以及数据血缘，以便在管道部署后对其进行运维。数据工程师需要熟悉数据管道的概念，并理解在平台中什么样的管道才算是高质量管道。

了解更多关于数据管道的信息。

应用程序构建者

Palantir 的本体论和应用程序构建功能使您能够为最终用户创建量身定制的应用程序。这些最终用户通常是组织中的操作人员，需要做出可以借助数据来支持的决策。除了向用户展示数据之外，您还可以使用自定义应用程序，以本体论中配置的操作类型的形式从用户那里获取信息。

应用程序构建者需要熟悉 Palantir 的 本体论，这通常是应用程序构建者与数据工程师协作建立工作流开发数据基础的层。构建者可以在 本体论管理器中创建和维护其组织的本体论，然后使用 工作流血缘 来理解对象、操作、函数、大语言模型（LLM）和应用程序是如何组合在一起的。

要创建和交付应用程序，构建者可以使用 来运行该专业代码代理。你还可以通过 在本体论之上进行点击式应用程序构建，使用 来扩展 Workshop 应用程序，从而在无需离开 Workshop 的情况下添加量身定制、基于代码的组件。扩展 Workshop，或使用 提供了一种精简的、由 AI 驱动的方式，可通过自然语言提示来构建这些 OSDK 应用程序。 从自然语言描述开始。对于代码优先的开发，构建者可以使用 OSDK 和 OSDK React 应用，在 自定义小部件中管理应用程序配置和 SDK 生成，编写 函数 以实现共享的业务逻辑，或在 将收集到的信息存储在中构建应用程序。构建者还可以使用 AIP 逻辑 创建由 LLM 支撑的工作流，并使用 发布后，我们建议在.

数据科学家

Palantir 平台支持使用代码分析数据，以及开发、评估和部署机器学习模型。此功能建立在数据集成层的严谨性之上，以与数据集相同的方式为模型提供数据血缘和可复现性。其结果是一个分析和机器学习可以建立在高质量数据和共享建模工作流之上的环境。

在 Palantir 平台中，数据科学家通常使用 代码仓库（Code Repositories），这是一款旨在支持基于代码的分析和机器学习模型开发的应用程序。Code Workbook 使您能够使用 Python、R 和 SQL 编写代码，以访问、规范化和分析由数据工程师准备的高质量数据集。由此产生的分析和模型随后可以连接到 模型集成，通过 Model Catalog共享，使用 AIP 评估进行评估，并集成到本体论中，以供应用程序和工作流使用。

作为替代方案，数据科学家可以在他们偏好的第三方 IDE 中使用 代码工作区。Code Workspaces 容器与 Palantir 生态系统的其余部分集成，将 JupyterLab® 和 RStudio® Workbench IDE 与 Palantir 平台的安全性、分支和资源管理优势相结合。

了解更多关于 模型集成 和 基于代码的分析.

分析师

由于 Palantir 可用于构建安全且高质量的数据基础，分析师可以找到并探索与他们需要回答的问题相关的数据。平台提供了丰富的工具集，可用于分析各种格式的数据——表格、关系、时间、地理空间等。一旦您的分析产生了洞察，您可以通过创建 仪表板 使其可重复，或使用 报告 工具展示您的发现。

分析师通常使用 Contour 来探索平台中的数据集并进行大规模的开放式分析，并使用 的流可在 来分析本体论中的数据以及相关的时间序列。分析师还可以使用 AIP Analyst 以自然语言探索基于本体论的问题。这些应用程序支持从临时分析过渡到仪表板、报告或 或 文档，与同事共享结果。

平台管理员

平台管理员可以使用 Palantir 专用的管理工具来配置平台、管理和了解平台的使用情况，并确保组织的数据得到安全管理。

平台管理员通常首先设置 身份验证 以连接到组织的身份提供商，配置 应用程序访问，然后设置 数据连接 以使数据流入平台。随着平台使用的成熟，管理员可以使用 资源管理 来管理资源消耗， 自定义小部件 来支持自定义应用程序开发，以及 监控视图 来帮助团队观察运行状况。管理员还应了解 Palantir MCP 和 本体论 MCP 在启用这些功能时的访问注意事项。

了解有关平台管理的更多信息。

数据治理

Palantir 提供用于保护数据并向数据治理负责人提供透明度的工具。这些工具保证了数据在 Palantir 平台中进行转换以及用于面向用户的应用程序时如何受到保护。它们还保留了内省和验证谁有权访问哪些信息的能力。

担任数据治理角色的用户应了解平台中广泛的数据安全工作流，包括 项目和资源 to 保护敏感数据。这些功能建立在 Palantir 的数据安全概念之上，即 项目 和 标记。治理负责人还应了解 对象权限管理, 应用程序限制, OSDK 权限, 本体论 MCP 限制日 工作流血缘安全可见性 （当这些控制措施是其组织工作流的一部分时）。

以 Foundry 中的隐私与公民自由 以理解为什么最小化、目的、访问、监督、可追溯性和保留应影响治理决策。然后查看详细的 数据保护与治理 指南。
