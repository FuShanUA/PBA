优化 JDBC 同步

本指南提供了提升 JDBC 同步速度和可靠性的技巧。

如果您的同步已经可靠运行，则无需采取下述操作。如果您正在设置新的同步，或者您的同步耗时过长或无法可靠完成，我们建议您遵循本指南。

有两种加速 JDBC 同步的主要方法。我们建议先使同步变为增量同步，只有在增量同步不足以满足需求时，再对 SQL 查询进行并行化处理：

  • 使同步变为增量同步
  • 并行化 SQL 查询

如果网络吞吐量限制了数据摄取速度，请参阅 优化网络吞吐量.

增量同步

默认情况下，批量同步会同步目标表中的所有匹配行。 增量同步则相反，会保留最近一次同步的状态，因此可用于仅摄取 新的 匹配行。对于行数较多的表，这可以显著提升同步性能。增量同步的工作方式是将数据作为 APPEND 事务 添加到已同步的数据集中。

以下是增量批量同步的示例配置：

请按照以下步骤设置增量批量同步：

  1. 导航到您要转换的同步的配置页面，并确保预览正常运行。

  2. 将事务类型设置为 APPEND。这是为了避免覆盖之前同步的行。

  3. 选择 在控制面板中启用 菜单中选择 增量 复选框。确保此同步的预览已成功运行。预览正常运行后， 增量 复选框会展开，允许您为同步配置初始增量状态。

  4. 配置同步的增量状态。此状态由一个 增量列 以及一个 初始值组成，可在用户界面中进行配置。设置这些值时，请牢记以下重要注意事项：

    • 直方图 增量列 必须在 严格递增 各次同步之间。如果您的行是 是 （即现有行无法就地更新），则任何一致递增的列（例如自增 ID 或指示行添加时间的时间戳）都足够了。如果您的行是 可变的 （即您的表允许更新现有行，而不仅允许插入新行），您将需要一个随每次数据变更而递增的列（例如 update_time column).
    • 为避免重复摄取行， 初始值 增量列的值必须大于 所有行 之前运行中已同步的值。例如，如果最近一次 SNAPSHOT 同步引入的行中某个整数 id 列的值最大达到 1999，则您可以将初始值设置为 2000.

当您摄取现有行的更新版本时，Foundry 数据集仍会包含该行的先前版本（请记住，此同步使用 APPEND 事务类型）。如果您只想要每行的 最新 版本，则需要使用 Foundry 中的其他工具（例如 Transforms）来清理数据。请参阅关于 增量管道 以了解更多信息。

  1. 最后，更新查询以使用通配符 ?。如何在查询中包含通配符取决于您的查询逻辑；请参见下面的简单示例，并注意以下事项：
    • 在第一次增量运行中，此通配符将被替换为 初始值 我们在上一步中指定的
    • 在后续的任何运行中，通配符将被替换为 最大 上一次运行中已同步的 增量列 的最大值。

如上所述，增量状态界面仅在同步预览成功运行后才可用。这意味着，如果您从头创建增量同步或复制现有的增量同步，您需要运行一个 不包含通配符 ? 的查询.

并行化 SQL 查询

并行查询可能会不一致地读取实时更新的表

由于并行功能会针对目标数据库运行多个独立的查询，因此需要仔细考虑实时更新的表在时间略有不同的查询中被不同处理的情况。

并行功能允许你轻松地将 SQL 查询拆分为多个较小的查询，由代理并行执行。

为了实现此行为，你需要将 SQL 语句更改为以下结构：

    column1,

WHERE
    {{condition}}
    /* ALREADY_HAS_WHERE_CLAUSE(TRUE) */

查询的关键部分是：

  • FORCED_PARALLELISM_COLUMN({{column}})
    • 这指定了表将被划分所依据的列。
    • 它应该是一个数值列（或产生数值列的列表达式），其分布应尽可能 均匀.
  • FORCED_PARALLELISM_SIZE({{size}})
    • 指定并行度，例如 4 将产生五个同时进行的查询：四个用于拆分指定并行列的值，外加一个针对并行列中 NULL 值的查询。
  • ALREADY_HAS_WHERE_CLAUSE(TRUE)
    • 这指定了是否已经存在 WHERE 子句，或者是否需要生成一个。如果这是 FALSE, WHERE column%size = X 将被添加到每个生成的查询中。如果这是 TRUE，则此条件将改为通过 AND.

包含 OR 条件的 WHERE 子句的并行化

当并行化与包含 OR 条件的 WHERE 子句一起使用时，你应该将条件用括号括起来，以指示条件应如何求值。例如，检查下面提供的同步：

col2

WHERE
condition1 = TRUE OR condition2 = TRUE
/* ALREADY_HAS_WHERE_CLAUSE(TRUE) */

condition1 = TRUE OR condition2 = TRUE AND col1 % X = 0

但是，该语句可能会被逻辑解释为 condition1 = TRUE OR (condition2 = TRUE AND col1 % X = 0)，而不是期望的 (condition1 = TRUE OR condition2 = TRUE) AND col1 % X = 0。你可以通过将整个 WHERE 子句用括号括起来来确保预期的解释。对于上面的示例，这意味着：
