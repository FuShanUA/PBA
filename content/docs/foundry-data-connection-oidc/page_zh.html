OpenID Connect (OIDC) 身份验证

OpenID Connect (OIDC) ↗，也称为 OIDC，是一种开放的身份验证协议，允许您在不使用静态凭据的情况下对外部源资源进行身份验证。

使用 OIDC 时，您无需在 Foundry 中为源系统配置凭据。因此，您可以避免将源系统凭据作为长期有效的密钥复制到 Foundry 中。相反，您将在 Foundry 与源系统之间配置信任关系。Foundry 充当 OIDC 身份提供者；每当 Foundry 中的工作流需要向源系统进行身份验证时（例如 Data Connection 同步），Foundry 都会颁发一个 OIDC 令牌，其中包含标识所使用的 Data Connection 源的声明。源系统能够验证这些声明，并提供一个短期有效的访问令牌，用于后续与源系统的交互。该访问令牌的范围（例如允许访问的资源）完全在源系统中使用可用的原生身份验证和授权工具进行管理。配置信任关系时，您可以添加条件来过滤传入的请求。不受信任的 Foundry 源无法为其不应访问的源系统资源请求访问令牌。

支持的数据源

以下源支持 OIDC 身份验证。有关如何设置 OIDC 与 Palantir 之间信任关系的更多详细信息，请参阅各个源的文档。

  • OneLake 和 Azure Data Lake Storage Gen2（Azure Blob Storage）
  • BigQuery
  • Databricks
  • Google Cloud Storage
  • S3
  • Snowflake

OIDC 身份令牌

以下是由 Foundry 生成的 OIDC 令牌示例：

{
  "iss": "https://pltroidcpublicexample.blob.store.com/foundry",
  "sub": "ri.magritte..source.7f3b8e21-4d9a-6c2e-1b7d-8a5f3c9e0b4f",
  "aud": "your-source-system-audience",
  "iat": <issued-at>,
  "nbf": <not-before>,
  "exp": <expiry>,
  "jti": "<token-unique-identifier>",
  "scp": "<additional-scope>",
}
理赔声明类型描述
iss颁发者 URL将 Foundry 标识为 OIDC 身份提供者的 URL。
subsubject连接到您的源系统的 Foundry 源的源 RID。
audaudience标识您的源系统的已配置受众。

直方图 source-rid 应用于过滤传入请求，以使不受信任的 Foundry 源无法访问您的资源。

由 Foundry 生成的 OIDC 令牌在一小时后过期。

在代码中使用身份令牌

OIDC 令牌可用于 Data Connection 同步，也可用于 Python 环境，例如 外部转换、外部函数和计算模块。使用 get_session_credentials() 在源上检索和续订令牌，详见 Python 中的源 文档。

如何使用令牌取决于源系统。某些系统直接接受 Foundry 签发的令牌作为 OAuth 令牌，而其他系统则要求您先将其交换为源系统签发的凭据，然后再发起请求。请查看您的源类型对应的文档以获取完整示例：

  • Databricks
  • Snowflake

由于令牌在一小时后过期，长时间运行的作业应从源请求新令牌，而不是重复使用作业开始时获取的令牌。
