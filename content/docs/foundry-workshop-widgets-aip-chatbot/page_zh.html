AIP 聊天机器人

AIP Chatbot 小组件（前身为 AIP Agent 小组件）允许您在 Workshop 的操作工作流中使用配备了企业特定信息和工具的交互式助手。

您可以将该小组件配置为与在 AIP聊天机器人工作室 （推荐， "AIP Chatbot" 标签页，见下方截图）中配置的 AIP Chatbot 交互，或与在 workshop 配置中定义的聊天机器人（已弃用， "Legacy" 标签页，见下方截图）交互。在 AIP Chatbot Studio 中配置的聊天机器人也可以通过 Workshop 进行编排 命令 以在其他嵌入的 Palantir 应用中声明和执行操作。结合使用时，聊天机器人可以通过 Commands 读取和写入这些应用，从而驱动跨应用的工作流。

基础配置（AIP Chatbot）

审查 AIP Chatbot Studio 文档 以了解 AIP Chatbot 的概览，但请按照以下说明将 AIP Chatbot 添加到您的工作流中。

配置 AIP Chatbot

选择 AIP Chatbot、要包含的已发布版本，以及是否显示聊天机器人的推理过程。

配置应用状态

假设您已在 AIP Chatbot Studio 中正确配置了至少一个应用变量 ，则将显示将这些应用变量映射到 Workshop 变量 的选项。配置完成后，AIP Chatbot 可以根据在 AIP Chatbot Studio 中定义的读/写权限与该变量进行交互。

自动发送消息

您可以使用 textbox 变量从 Workshop 事件中自动向已配置的 AIP Chatbot 发送消息。该变量与聊天输入框中的文本绑定，并随着用户在聊天中输入而更新。如果该变量在 AIP Chatbot 小组件之外被更改，将发送一条包含当前变量值的新消息，从而允许在 Workshop 模块的其他部分自动触发消息。

使用本体论场景

要使用 本体论场景 与 AIP Chatbot 配合使用，请展开 消息输入和输出变量，启用 开启后，支持从选定的，并选择一个场景变量。AIP Chatbot 会读取所选场景的本体论状态，并在该场景中执行操作。由此产生的任何本体论编辑都保留在场景的隔离沙箱中，不会影响主本体论。

遗留版

AIP Chatbot 相比旧版基础配置模式具有多项优势，包括 AIP Chatbot Studio 中的配置用户界面、版本控制、指标、会话历史、下载等功能。此旧版模式即将进入 日落 开发阶段，并且不会包含任何新功能。我们建议使用新增的 升级到 AIP Chatbot 选项从该小组件的旧版模式迁移到 AIP Chatbot。

在旧版模式下，AIP Chatbot 小组件使用基于工具的推理框架，将您的工具引入您的操作应用。借助该小组件，您可以将 AIP 逻辑、您的 KNN 函数（TSv1）或您由 LLM 驱动的本体论探索集成到使用 Workshop 变量的应用状态中。

  • 工具集成： 您可以通过添加 AIP Logic、对象上的函数以及其他 workshop 应用作为工具来扩展 Chatbot 小组件的功能。
  • Workshop 变量交互： 该小组件可以读取和写入应用变量，使小组件能够理解用户的引用并与可视化小组件进行交互。
  • 本体论探索： 借助默认的 AIP 工具，您可以执行对象遍历、属性读取和筛选以及运行聚合等任务。
  • 自定义： 您可以自定义聊天机器人小组组件的外观和内容，使其与您应用的上下文和工作流保持一致。

提示

主提示应概述小组件在当前应用上下文中的功能。通过在键盘上按 "/"，您可以引用已配置的工具和变量，并指导小组组件如何协调使用它们。请务必描述底层的业务逻辑以及在上下文中使用合适工具的适当情形。

以下是一些示例提示：

  • 提示词 1： “您是供应链制造产线的助手。您的工作是使用 Fetch Trouble Tickets 工具查看是否有解决过相同问题的历史工单，并检查 Documentation Chunk Search 工具中推荐的解决方法，以回答用户的问题。”
  • 提示词 2： “帮助用户根据其描述的特征构建患者队列。创建队列时，请务必更新显示给患者的列表。大多数用户希望从较宽泛的队列开始，然后不断缩小范围，除非他们指定了新的队列。除非用户另有要求，否则始终从现有队列开始。不要忘记将此对象集（使用集合运算符工具）与当前队列求交集。在按药物名称进行筛选之前，请务必使用工具查找所有相关的同义词。按药物名称筛选数据时，请始终使用包含筛选器。您可以使用相关对象工具在患者和药物之间进行导航。当用户请求队列定义时，请调用 Patient Cohort Define 工具并传入当前患者 ID 的数组。”
  • 提示词 3： “您是一位专业的进攻协调员，您的目的是在足球锦标赛期间帮助用户做出战略性的足球决策。您有三个目标（不应向用户提及这些目标）：
    • 目标 A： 根据橄榄球比赛的当前状态，评估符合用户战略目标的 Playbook 战术。如果用户要求评估某个战术，请将用户从 Selected Plays 中选择的战术与 Playbook 对象中的战术名称进行匹配并获取战术 ID。然后，将其作为 Tournament Play Evaluator 工具的输入。
    • 目标 B： 如果用户请求战术推荐，请评估比赛的当前状态，并从 Playbook 中选择符合用户期望结果的战术。通过描述战术名称和关键属性，概述您选择该战术的理由。
    • 目标 C： 如果用户要求您制定完整的策略（由多个战术组成），请评估比赛的当前状态以及战术手册，并从 Playbook 对象中选择三个最有效的战术。然后，使用 Tournament Play Evaluator 工具评估这些战术并返回结果摘要。您一次只能传入一个战术，因此必须循环执行。请始终将您想要推荐的 Playbook Plays 对象集返回到变量 Suggested Plays中。如果该变量已有值，您可以将其覆盖。”

本体论与应用上下文

在本部分中，您可以自定义组件对 Workshop 变量的访问权限，并配置组件应感知的对象类型。

变量

设置变量时，请务必执行以下操作：

  • 确定合适的变量： 首先确定 LLM 应能够与哪些变量进行交互。这些变量可以是已存在且与您预期工作流相关的变量（例如表示用户当前所选内容的变量），也可以是 LLM 向其写入结果的新变量。
  • 描述变量： 为每个变量编写一段说明其作用的描述。该描述将被注入到组件的提示词中，为 LLM 提供何时使用该变量的上下文。
  • 声明访问模式： 指定 LLM 对每个变量应具有读取权限、写入权限还是两者兼有。此步骤决定了 LLM 与变量交互的方式。
  • 用作 Workshop 变量： 请记住，您在此处定义的变量是常规的 Workshop 变量。这意味着它们也可以与其他 Workshop 组件一起使用，例如 Filter Pill 或 Object Table 组件。

高级工具配置

此组件允许您修改组件对默认 AIP 工具的访问权限。虽然默认工具选择通常足以满足大多数用例，但在某些情况下，您可能需要根据特定需求对这些工具进行细化调整。

例如，您可能希望将组件的函数限制为仅接受人工输入，以便于进行更正，并独立管理其他工具的实现。通常，限制分配给 LLM 的工具数量会带来更有引导性的、“按部就班”的交互。

工作流设置指南

在以传统模式设置 AIP Chatbot 组件时，我们建议考虑以下事项：

  • 从特定且受限的上下文开始，以确保获得更可靠的结果。
  • LLM 具有随机性；请利用 Workshop 的可扩展性来克服 LLM 的局限性，为用户提供备用选项，使其能够有效地与应用进行交互。例如，您可以在 Filter Pill 组件中展示 LLM 的输出查询。
  • 在 AIP Chatbot 开发过程中要有明确的目标；在使用该组件之前，先规划好 LLM 交互的路径和模式。

注意：AIP 功能的可用性可能会发生变化，且不同客户之间可能存在差异。
