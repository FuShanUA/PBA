架构

本页面记录了原始 Spark 和 Direct Read SQL 引擎的架构。Foundry 正在过渡到 Furnace，这是一款具有增强性能、灵活性和兼容性的下一代 SQL 引擎。此过渡是自动的，无需对现有工作流进行任何更改。

本节中的外部 SQL 连接和 BI 工具集成由一项名为 Foundry SQL Server 的服务提供支持。该服务为针对 Foundry 数据集的只读查询提供轻量级的 SQL 会话和语句管理。Palantir 提供 JDBC 和 ODBC 驱动程序，以便客户端使用开放标准与此服务进行交互，同时还为某些利用这些驱动程序的第三方平台提供插件实现。

支持的 SQL 方言

支持的 SQL 方言为 ANSI, ODBC日 SparkSQL，且仅支持只读功能。

执行引擎

Foundry SQL Server 将根据查询的复杂程度自动选择执行引擎。每个执行引擎在整体性能、结果大小限制和支持的查询复杂度方面都各有取舍。

Spark 引擎

默认的查询执行引擎利用 Spark SQL 功能。该引擎支持完整的 SQL 计算功能，例如聚合、连接、排序、筛选等。需要使用此执行引擎的查询将受到数据规模方面的限制，因为在将结果交付给客户端应用程序之前，结果必须先收集到 Spark 驱动程序的内存中。这些限制取决于计算结果中的行数和字节数。

Direct Read 引擎

在可能的情况下，Foundry SQL Server 将使用直接读取引擎来执行查询。当查询不需要 SQL 计算时，Foundry SQL Server 将绕过 Spark SQL，直接从数据集的支撑文件流式传输记录。直接读取查询不受与需要完整 SQL 计算的查询相同的规模限制。

查询在满足以下条件时符合直接读取条件：

  1. 在数据集上执行。 视图 目前不受支持。
  2. 数据集文件采用受支持的格式。目前直接读取支持的格式包括 Parquet、CSV、Avro 和 Soho。
  3. 查询不需要 SQL 计算。包含聚合、筛选、连接和排序谓词的查询不符合直接读取条件。
  4. 查询不从包含不符合直接读取条件的类型的列中进行选择。 array, map日 struct 不符合直接读取条件。

直接读取查询区分大小写。
