初始化一个新的 OSDK Python 应用程序

在本页面中，我们将逐步介绍创建使用 OSDK 的 Python 应用程序的过程。下面的示例可用于许多 Python 框架，例如 Flask ↗， Streamlit ↗，以及 Jupyter ↗。

1：前提条件

创建 Developer Console 应用程序

请按照 创建新的 Developer Console 应用程序 页面中列出的步骤操作。

设置您的令牌

在您的本地环境中导出令牌。下面是一个使用示例个人访问令牌的示例，但您可以在 Developer Console 中生成一个有效期更长的令牌。由于此令牌是您的个人访问令牌，因此不应将其提交到源代码管理中。

Copied!
1
export FOUNDRY_TOKEN=<YOUR-TOKEN-FROM-GETTING-STARTED-PAGE>

检查 Python 版本

Python SDK 要求 Python 版本为 >=3.10 且 <3.15。要查看您使用的 Python 版本，请输入以下命令：

Copied!
1
python3 --version

可选：设置证书

如果您的组织要求网络流量使用证书，您可能需要告知 Python 该证书所在的位置。

Copied!
1
2
export SSL_CERT_FILE="/path/to/my.crt"
export REQUESTS_CA_BUNDLE="/path/to/my.crt"

如果 pip install 在您设置证书环境变量后仍然失败并出现 certificate verify failed 错误，则您的证书颁发机构 (CA) 信任配置不完整。请修正该配置，而不是绕过验证。

要临时确认证书信任是否是问题所在，请使用 --trusted-host 标志运行一次安装。此标志会禁用对指定主机的证书验证，因此仅可用于诊断，切勿在生产或自动化环境中使用。

Copied!
1
pip install <YOUR-PACKAGE-NAME> --upgrade --extra-index-url "https://:$FOUNDRY_TOKEN@<INDEX-URL>" --trusted-host <YOUR-FOUNDRY-HOSTNAME>

请将 <YOUR-FOUNDRY-HOSTNAME> 替换为您的 Foundry 环境主机名。如果使用该标志后安装成功，即可确认缺少信任链。请与网络管理员协作，将完整的 CA 证书链添加到 SSL_CERT_FILE 和 REQUESTS_CA_BUNDLE所引用的文件中。然后重新安装时不使用 --trusted-host。

2：安装最新版本的 SDK

运行以下命令以安装最新版本的 SDK，将任何 < > 替换为特定于您应用程序的值，该值可在您应用程序的 概览 页面中找到。

Copied!
1
pip install <YOUR-PACKAGE-NAME> --upgrade --extra-index-url "https://:$FOUNDRY_TOKEN@<INDEX-URL>"

开发您的前端应用程序

在您的应用程序中，初始化 Foundry 客户端并开始开发。

import os
from <PACKAGE-NAME> import FoundryClient
from <PACKAGE-NAME>.core.api import UserTokenAuth

auth = UserTokenAuth(hostname="<YOUR-FOUNDRY-URL>", token=os.environ["FOUNDRY_TOKEN"])

client = FoundryClient(auth=auth, hostname="<YOUR-FOUNDRY-URL>")

object = client.ontology.objects.<ANY-OBJECT>
print(object.take(1))
