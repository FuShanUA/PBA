使用代码仓库创建数据集批处理管道

本指南将引导您逐步完成一个使用 代码仓库 应用程序的简单数据转换示例。您将学习如何编写和编辑 SQL 代码以及如何构建数据集。您还将学习如何在分支上工作，以便与同事协作。

1. 创建仓库

首先，创建一个新仓库。为此，请导航到 Foundry 中的一个 项目 ，然后选择 + 新建 （位于右上角），然后选择 代码仓库.

在本指南中，我们将编写一个 SQL 转换。为您的代码仓库命名，然后选择 SQL （位于 “语言模板”下方的下拉菜单中）。然后，选择 初始化仓库.

如果您已经导入了将要使用的原始数据集，可以直接进入下一步。否则，您可以下载此示例数据集：

3. 创建分支

通过创建个人 分支 来进行更改，而不是直接编辑代码的主版本，您就可以与同事在同一个代码仓库中安全地进行协作。您可以跟踪和撤销更改，也可以将更改合并到主代码中。代码可以逐行审查，这意味着对生产管道的更改可以轻松地在团队成员之间进行讨论。要了解 Foundry 中分支的更多信息，请参见 此页面.

当您导航到代码仓库时，您将默认位于 master 分支。最佳实践是让 master 分支受保护，这意味着无法直接在该分支上编辑代码。您可以在受保护的分支上读取文件，但不能编辑或创建文件。

在向您的代码仓库添加更改之前，您必须先创建自己的分支，其中包含 master 分支上代码的副本。要创建您的分支，请点击当前分支名称旁边的 图标。

这将打开一个对话框，用于选择现有分支并为新分支指定自定义名称：

创建新分支后，您将在左侧看到一个完全相同的文件树。您只是创建了 master 分支（即您最初所在的分支）上的代码复制了一份。您现在可以在自己的分支中编辑文件。

4. 编辑代码

创建新文件

现在您已经在自己的分支中工作，将鼠标悬停在某个文件夹上并点击省略号图标，然后选择以创建一个新的 SQL 文件 新建文件。选择 新建文件后，系统将提示您选择文件类型并为其命名。在本示例中，请选择 SQL 转换 并输入一个文件名（不含空格或特殊字符）：

请注意，在文件树中，您的新 SQL 文件被高亮显示的位置，就是构建后生成的数据集将要存在的位置。

如果文件树中的文件名是绿色的，则表示它是您分支中新建的文件，不存在于 master 您开始时所在的分支上。如果文件名是橙色的，则表示该文件存在于 master 上，但在您的分支中已被修改。

您新创建的 .sql 文件将根据您提供的文件名声明输出数据集。例如，如果您的代码仓库位于 /Public/Authoring ，并且您创建了 titanicAnalysis.sql，您的新文件将自动声明输出数据集 /Public/Authoring/titanicAnalysis.

编辑您的文件

接下来，将占位符文本替换为您的实际数据转换代码。首先，将 `SOURCE_DATASET_PATH` 替换为实际输入数据集的路径。在本示例中，您将使用 titanic 您在本教程步骤 (2) 中导入的数据集。

请注意，当您开始输入反引号时，自动完成功能会显示一个交互式菜单，其中列出了您可以使用的数据集。当您从列表中选择某个数据集时，该数据集引用将被替换为该数据集的唯一 ID。这样，即使数据集日后被移动，您的转换代码仍能继续正常工作。

在反引号中输入您的项目名称，找到 titanic 数据集，然后从菜单中选择它。

继续编写 SQL 代码，以对数据执行转换。输入 SQL 函数时，您会看到各种帮助对话框出现。例如，假设您想在“titanic”数据集中创建一个新列，用单字母缩写表示乘客的性别。您可以查看有关如何使用 SUBSTRING 函数：

在继续之前，请先完成数据转换代码的编写，选择“Name”、“Age”、“Survived”和“Ticket”列，以及一个名为“Gender”的派生列。“Gender”列表示乘客性别的缩写；要创建此列，请对“Sex”列调用 SUBSTRING 函数。

5. 测试您的更改

现在您已经编写了数据转换代码，应该测试您在分支中所做的更改。在将更改合并到 master 分支的情况下对分支执行操作。

在 Foundry 中，数据集可以像代码一样进行分支。这对于测试多步骤数据管道的设计非常有用。例如，您可以在不影响不依赖您分支的任何人的下游依赖项的情况下，隔离地测试对数据管道各部分的更改。

使用预览来迭代您的更改

在编写代码时,您可以使用 预览 功能可加速开发周期并快速迭代更改。预览会在采样输入上运行您的代码，并提供示例输出，而无需提交更改、运行检查或在 Foundry 中物化数据集。示例输出可能无法代表构建的结果，但可用于确认您的代码是否正常工作并产生预期结果。

要使用，请单击 预览 （位于顶部栏），或打开 预览 Code Editor 底部栏中的助手。可以预览基于文件的数据集或带有 schema 的数据集。

对于带架构的数据集，您可以自定义预览更改时使用的输入，方法是单击 设置图标 用于您希望编辑的输入。选项包括：

  • 原始输入： 使用原始输入的样本。
  • 上一次预览： 对于在同一仓库中生成的数据集，您可以将预览的更改串联起来，并将该数据集的预览用作您预览的输入。
  • 应用自定义筛选条件： 对受支持的列应用筛选条件，以便在输入的特定子集上测试您的更改。例如："时间戳位于给定时间窗口内的所有行"，或"具有给定字符串值的所有行"。
  • 选择其他数据集： 选择另一个包含您的代码所需所有列的数据集，以测试特定情况，或提供任何其他自定义样本作为您的输入。

首次对包含文件的数据集运行预览时，您必须配置将在样本中使用的文件。选择样本文件后，可以通过选择相应的输入来重新配置这些文件。保存配置后，预览将对所选的文件样本执行代码。

再次运行预览时，无需重新配置输入文件。预览执行完成后，您可以以行或文件的形式查看样本输出。如果您拥有所需权限，还可以选择下载输出文件。

提交您的更改

编写新代码后，您可以提交更改。在 Code Repositories 中，当您想要标记已完成的工作时，可以提交更改。即使在提交之前，您的工作默认也会自动保存。提交会在您到达一个停止点时，专门为您的更改集添加标签。

Build 也会提交您的更改

点击 提交 按钮会提交您的更改，并对您的代码运行自动检查。点击 构建 按钮也会提交您的更改。具体来说，点击 构建 会运行自动代码检查并开始构建您的输出数据集。如果您想在不构建数据集的情况下快速测试您的更改，以确保您的代码通过代码检查，请点击 提交。否则，您可以直接跳到 构建您的数据集.

要提交您所做的更改，请点击 右上角的按钮，并输入您所做更改的摘要。提交更改会触发对代码运行的自动检查。右上角的图标会显示这些检查的状态；将鼠标悬停在其上可查看更多详细信息。

在您的分支上构建数据集

要测试您的更改，请点击屏幕顶部的 按钮。

点击构建按钮后，会发生两件事：系统将对您的代码运行自动检查，同时您的输出数据集将开始构建。在此期间，系统会根据您分支中的代码创建新的输出数据集，或者更新现有输出数据集以反映您的更改。您可以在 构建 助手中查看正在运行的任务的进度。任务完成后， 图标表示每个任务均已成功完成。如果您看到的是 图标，请点击 详情 按钮，位于 构建 助手中进一步了解问题所在。这将带您进入 检查 选项卡，您可以在其中查找错误消息，也可以重新触发构建。

以下是关于测试更改和构建数据集的一些重要信息：

  • 点击 构建 右上角的按钮等同于点击 构建 按钮，位于 构建 助手中（代码仓库界面底部）。
  • 您必须先选择包含数据转换逻辑的文件，然后才能真正点击构建按钮来运行检查并开始构建输出数据集。
  • 每次在您的分支上触发构建时，该构建都会排在已在运行的现有构建之后。

预览您的数据集

6. 提出您的更改以供审查

至此，您已经：

  • 创建了自己的分支来进行更改，
  • 创建了包含数据转换代码的新 SQL 文件，
  • 在您的分支中测试了更改并构建了数据集，以及
  • 预览了已构建的输出数据集。

现在，您将提议您的更改供团队成员审查。在测试了您的更改并对生成的输出数据集感到满意后，您可以提议您的更改供团队成员审查。

所有者可以在拉取请求上启用自动合并

具有……的用户 所有者 权限的用户在创建 拉取请求时将能够启用“自动合并更改”选项。仅当您的代码仓库分支至少配置并通过一个必需检查时，此选项才可用。如果您启用“自动合并更改”选项，您的 拉取请求 将在创建后自动合并到主代码中。当您分支中的更改合并到主代码后，您的分支也将被自动删除。

要创建新的 拉取请求，点击 右上角的按钮。这将打开“新建拉取请求”页面，您可以在其中撰写更改说明，然后点击 创建拉取请求 按钮。

这将创建一个新的拉取请求，其中包含您提议的更改。拉取请求页面提供了丰富的工具，供您审查提议的更改将如何影响您的数据管道：

  • 直方图 已更改的文件 标签页允许团队成员逐行审查您的代码
  • 直方图 影响分析 选项卡显示受影响的数据集在您的分支上发生了哪些变化，包括对数据集架构和健康检查的更改
  • 直方图 管道审查 选项卡显示您的数据管道图形，并以可视化方式突出显示此拉取请求中的更改对管道的影响。

了解更多关于理解拉取请求中更改影响的信息。

一般来说，在将更改合并到 master 分支之前，邀请他人审查您的更改非常重要。用户可以逐个文件批准或拒绝，以便跟踪在拉取请求合并之前仍需调整哪些文件。要查看哪些用户已经批准或拒绝了某个特定文件，请将鼠标悬停在相应的指示图标上。

使用单个文件审查按钮是可选的，但当您拒绝其中一个文件时，会自动拒绝整个拉取请求。同样，当您批准拉取请求时，所有单个文件都会被批准。

如果您发现已经合并到 master 分支的代码更改存在问题,有一种简单的方法可以撤销这些更改。您可以通过在 master 分支的提交历史记录中找到特定提交来将其还原。在您仓库的 提供了专为数据转换量身定制的版本控制体验，支持团队在同一工作簿中同时处理逻辑与数据。 标签页中,点击 master 以查看按时间顺序排列的所有提交列表。

您可以通过点击提交哈希值来查看某个提交的代码更改。找到要还原的提交后,请点击 还原。这将在 master 分支上发起一个拉取请求，您可以对其进行审阅和合并。
