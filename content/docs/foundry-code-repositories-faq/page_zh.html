如需一般信息，请查看 Code Repositories 文档.

我可以在不要求打标签的情况下，从分支的最新提交发布 Python 包吗？

可以。您可以通过修改包的根目录 build.gradle 文件来发布该分支的最新提交。例如，要发布 master 分支上的最新提交，请修改 build.gradle 文件，如下所示：

1
condaLibraryPublish.onlyIf { versionDetails().branchName == "master" }

如何恢复代码仓库中之前删除的代码？

如果这些转换已构建到数据集中，您可以使用 比较 功能，在生成的数据集预览中查看当时的代码。然后，您可以将相关的转换复制粘贴过去。或者，您可以导航到 提供了专为数据转换量身定制的版本控制体验，支持团队在同一工作簿中同时处理逻辑与数据。 在您的代码仓库中，打开特定分支，并查看那里的完整更改历史。

我可以复制我的代码仓库吗？

平台中没有内置的复制代码仓库的功能。但是，您可以将仓库克隆到本地计算机，然后将该代码推送到一个新的代码仓库。如果这样做，请记得将所有输入作为引用添加到新项目中。 了解如何克隆仓库.

如何知道我是否需要升级我的分支？

您可以通过选择 ... 在代码仓库右上角的位置，并确认 升级 是否显示为一个选项。如果 升级 选项不可用，则说明该仓库已经是最新的。

我的转换可以在每次构建开始时动态选择输入和输出吗？

不支持此功能。持续集成 (CI) 检查会在代码仓库中添加新提交时定义输入和输出集。

在 Code Preview 中，代码可以运行但构建失败

您的 Code Preview 成功，但构建失败。Code Preview 在数据子集上运行，这很可能意味着完整构建运行时，子集中不存在的某些数据值会导致您的代码出错。

要进行故障排除，请执行以下步骤：

  1. 检查失败构建中的构建错误。查找以“Caused by”开头的行并仔细阅读。有时它们会指出转换文件中的具体代码行。
  2. 尝试 升级您的代码仓库。为此，在仓库的右上角选择 ... > Upgrade。这将创建一个用于升级分支的 PR。请务必合并该升级 PR，以便您的分支真正得到升级。您可以升级任何分支，但将升级提交合并到受保护的分支需要经过审查和批准。

代码在 Code Workbook 中可以运行，但在 Code Repositories 中不行

有时，将代码从 code workbook 移植到代码仓库时，如果不修改代码以使其在代码仓库中运行，就无法正常工作。

要进行故障排除，请执行以下步骤：

  1. 您是否已验证您的 transform 装饰器与函数读取输入和返回数据的方式相匹配？例如， @transform_df 期望函数返回一个 DataFrame，而 @transform 则期望您自行写入输出。
  2. 您是否已验证您的输入都已声明并作为参数传递给您的计算函数？
  3. 您的数据框名称是否与 workbook 中的一致？您的代码仓库是否确实返回了该数据框？
  4. 检查 code workbook 代码中使用的库在代码仓库中是否也可用。
  5. 验证 code workbook 单元格的输入和分支实际上与代码仓库中使用的数据集相同。

查看我们的常见问题解答： 构建和检查错误 以了解更多详情。

检查因缺少 Python 库而失败，而该库之前在代码仓库中是可以正常使用的

有时，一个原本正常运行的仓库会开始遇到问题，仓库检查开始失败并显示无法获取 Conda 包的错误。这可能是 PackageNotFoundError，或者是 MD5MismatchError 由于 Conda 缓存损坏所致。

要进行故障排除，请执行以下步骤：

  1. 在大多数情况下，只需在代码仓库中创建一个新的提交即可解除 Conda 缓存的卡顿。打开仓库并进行任意更改（即使只是一个新的空行），然后按 提交.
  2. 如果在执行新空行提交后症状仍然出现，可能是 Conda 缓存导致更高级别的缓存也损坏了。以下步骤将清除代码仓库的 Gradle 缓存。
  3. 在代码仓库中，按设置（齿轮）图标，并启用 隐藏文件.
  4. 找到 conda-versions.run.linux-64.lock 在您的 Python 子项目中，将其删除，然后按 提交.
  5. 如果清除这两个缓存后症状仍然出现，请联系 Palantir Support。
