发布日期：2023-08-22

Retention Policies 应用将于 2023 年 9 月正式发布（GA）并在所有堆栈上可用。Retention Policies 应用使命名空间所有者能够定义和管理静态保留策略以及数据生命周期策略。此新应用取代了旧版基于 YAML 的仓库的使用。

直方图 命名空间设置 页面，其中包含指向 Retention Policies 应用的链接。

该应用列出了在该命名空间上定义的所有保留策略，包括系统策略、旧版策略和自定义策略。

  1. 系统策略： 由平台管理的保留策略。这些策略不可配置，仅针对旧版本的数据。如果您的用例需要移除这些策略，请联系您的 Palantir 代表。
  2. 旧版策略： 由命名空间管理员通过 Code Repositories 管理的保留策略。这些策略已被视为弃用。我们建议将这些策略迁移到新的自定义策略，并使用旧版策略页面上的迁移选项从仓库中删除策略定义。
  3. 自定义策略： 由命名空间管理员使用 Retention Policies 应用管理的策略。

Retention Policies 应用显示系统策略、旧版策略和自定义策略。

保留策略的优势

Retention Policies 提供直观的点击式界面来定义和管理保留策略。这些策略通过自动删除冗余数据并满足法规和删除要求，帮助管理员降低存储成本。

在管理保留策略时，您可以选择添加数据集选择器来标识策略所需的数据集，以及添加事务选择器来缩小策略所需的数据集事务范围。

HyperAuto V2 简介 [Beta]

发布日期：2023-08-22

HyperAuto V2 将于 2023 年 8 月底开放安装，并在发布时支持 SAP。

HyperAuto 是 Foundry 用于集成 ERP 和 CRM 系统的自动化套件，提供点击式工作流，从源系统的原始数据动态生成有价值、可用的输出（数据集或本体论）。

HyperAuto V2 为自动化 SAP 相关的数据摄取和数据转换带来了显著更新的用户体验、性能和稳定性。

自 2023 年 8 月 22 日起，在 HyperAuto V1 中创建新 SAP 管道的功能将被弃用。基于 HyperAuto V1 的现有 SAP 管道和非 SAP 系统将继续可用且保持不变。

实时 HyperAuto 管道概览。

点击式配置

HyperAuto V2 以易用性为核心进行了重构。要创建和配置 HyperAuto 管道，用户只需与直观的分步向导进行交互。系统已预配置开箱即用的默认设置以简化流程，但用户可以根据需要在必要时调整设置。

HyperAuto 的关键自动化功能包括：

  • 通过自动对数据模型进行反规范化，并与包含相关元数据和附加信息的表进行连接，来丰富核心表。
  • 对源数据进行格式化和清理，确保列类型准确、列名称直观，并且空值数据得到正确处理。
  • 智能地对变更日志源数据进行去重，确保每个表都存在最新、整洁的版本，可供运营使用和分析

欲了解更多信息，请查阅 HyperAuto V2 文档.

应用了默认设置的管道配置。

通过 Pipeline Builder 进行数据转换

HyperAuto V2 动态生成 如果希望用户在每次运行预览前手动确认，请开启 管道以按需处理源数据。这提供了一个熟悉且易于理解的界面，使用户能够完全透明地了解数据的处理方式，并更容易理解用户可能希望在 HyperAuto 中更改哪些配置。

对现有 HyperAuto 管道配置的任何更改都会在底层的 Builder 管道中创建一个新的提案，该提案必须由用户批准并合并后才能部署到实时管道。Pipeline Builder 附带全面的变更管理工作流程，HyperAuto 充分利用了这一点，为关键工作流程提供质量保证。

动态生成的 Pipeline Builder 管道，用于处理源数据。

来自 SAP 的实时数据处理

HyperAuto V2 支持 SAP 源的实时流连接和数据转换（需要 SLT Replication Server），从而支持需要对相关 SAP 数据进行实时视图的关键运营应用。此外，HyperAuto V2 还为批量管道带来了显著的性能提升。

如果您想启用 SAP 流式传输，请联系您的 Palantir 代表。

流式转换迁移至 Java 17 计划于 2023 年 9 月底进行 [迁移/弃用]

发布日期：2023-08-17

2023 年 9 月底，所有 Foundry 流式转换的运行时将从 Java 11 迁移到 Java 17，以利用 Java 17 在性能和安全性方面的改进。Java 17 运行时引入了一项重大变更，阻止对 JDK 内部类成员的反射访问。大多数流式转换不会受到此变更的影响，但此公告被广泛发布以提高整体知晓度。

虽然我们预计大多数 Foundry 流式转换不会受到此次迁移的影响，但在用户自定义函数（UDF）流式转换中，如果其实现（或其关联的外部库）以反射方式访问 JDK 内部类，则可能出现中断。Palantir 将努力识别存在风险的 UDF 实现，并联系可能受影响的管道所有者。

如果您拥有在任何 Foundry 流式管道中使用的 Foundry UDF 定义仓库，请按照以下步骤验证您的 UDF 是否与 Java 17 兼容：

  1. 如果您的 UDF 定义依赖于任何外部库，请验证这些库的版本是否与 Java 17 兼容。

    • 打开隐藏的 versions.properties 文件（位于您的 UDF 定义仓库的根目录中）。
    • 识别任何从外部仓库手动添加的依赖项（即不是由仓库模板默认添加的依赖项）。
    • 对于每个此类依赖项，验证其在 versions.properties 文件中声明的最低版本是否与 Java 17 运行时兼容。这可能需要查看依赖项的发布说明。

  2. 验证 UDF 实现不会以反射方式访问 JDK 内部类。

    • 如果您的 UDF 实现不使用反射，则无需进一步操作。
    • 如果您的 UDF 实现确实使用了反射，请确保满足以下任一条件：
      • 被访问的类不是 JDK 内部类。
      • 您的实现能够正确处理 IllegalAccessException ，并且在某些反射操作开始抛出此异常时不会中断。

如果您在修复 UDF 定义仓库时遇到任何问题，或者对此通知有任何疑问或顾虑，请联系您的 Palantir 管理员。

Quiver 中的 AIP：透明的假设和增强的歧义处理

发布日期：2023-08-09

Quiver 中的 AIP 现在可以回答含糊、主观或使用相对术语的提示，例如“筛选高消费金额的交易”或“按最重要的客户分组”。此外，凭借更强的上下文感知能力，AIP 现在可以通过从对象集架构和数据中推断正确的值，来处理列名和数据值中的拼写错误。

AIP 配置所做的透明假设

建议的 AIP Configure 卡片配置分为两类：配置建议和需要假设的配置建议。如果请求不够具体，例如“让这个图表更美观”，AIP 会对提示中含糊的部分（在此示例中，含糊性源于“美观”一词的含义）做出假设，以推断哪些更改可能是合适的。用户在接受建议的更改之前，可以查看提示中 AIP 做出假设的部分以及这些假设的具体内容。

AIP Configure 建议的配置更改，显示了为回答提示而做出的假设

接受建议的配置更改后条形图的状态

AIP 如何使用本体论数据

连同用户提示一起，Quiver 现在会向 AIP 发送对象集数据的摘要版本（即“属性值提示”）以进行处理。属性值提示仅针对被发现与回答用户提示相关的属性进行计算，具体如下：

  • 字符串属性类型：最多计算 100 个唯一值
  • 数值属性类型：计算最小值、最大值和平均值

以前，在没有有效值样本的情况下，LLM 过滤的对象集会使用不在集合中的值。这通常会导致过滤后的对象集为空，进而影响所生成图表中的下游卡片。通过这些改进，AIP 现在可以使用属性值提示来纠正列名和属性值的拼写错误，并在进行定量描述（如高、低和最大值）时确定阈值。

旧版数据连接代理将被弃用，以支持优化的直接连接 2023 年 8 月 [停止支持]

发布日期：2023-08-07

Palantir Foundry 正在弃用其旧版数据连接代理，转而将数据连接迁移至 Rubix ↗，这是一项在 Kubernetes 上运行的更安全、更可靠、更高效的云服务。此次更新意味着不再需要数据连接代理，因为它们只是 Palantir 用于连接外部客户网络的临时解决方案。

因此，所有安装在 Palantir 提供的 AWS 主机上的代理必须在 2023 年 8 月底之前停用，所有受影响的工作流都需要迁移到直接连接。Palantir 工程师目前正在为那些拥有可运行云摄取的 Rubix 安装的客户完成迁移。

将工作流迁移到直接连接的好处包括：

  • 高可靠性： 直接连接比代理更可靠且更易于管理。无需每周的维护窗口，从而消除了停机时间。
  • 更好的并行性： 直接连接能够更好地处理多个并行同步，并直接利用 Foundry 中的自动扩展功能，因为每个同步都作为独立的作业运行。
  • 更好的网络管理： 作业只能访问其运行所需的端点，而基于代理的连接则需要单个代理主机满足所有需要通过该代理运行的作业的网络要求。
  • 自助服务： 直接连接消除了对 Palantir 支持的依赖，因为其管理可以直接在 Foundry 的 UI 中完成。

如果您希望继续使用基于代理的工作流，可以在您自己的硬件上创建一个新代理，并将您的代理分配给受影响的源。

要完成迁移，请按照文档中提供的说明操作： 将源从代理工作器运行时切换到直接连接.

模型训练模板现已在 Code Repositories 中提供 | Code Repositories 应用程序现在提供模型训练模板。新的模型训练模板允许您在 模型适配器 与模型训练逻辑相同的仓库中编写代码，从而在 Foundry 中为 ML 和 AI 模型带来更快的迭代和更直接的开发流程。

要开始使用新的训练模板开发 ML 和 AI 模型，请参阅 文档.
