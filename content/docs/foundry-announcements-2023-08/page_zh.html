HyperAuto V2 [Beta] 简介

发布日期：2023-08-22

HyperAuto V2 将于 2023 年 8 月底前可供安装，并在发布时支持 SAP。

HyperAuto 是 Foundry 的自动化套件，用于集成 ERP 和 CRM 系统，提供点击式工作流，从源系统的原始数据中动态生成有价值、可用的输出（数据集或本体论）。

HyperAuto V2 引入了显著更新的用户体验、性能和稳定性，适用于自动化的 SAP 相关数据摄取和数据转换。

自 2023 年 8 月 22 日起，HyperAuto V1 中创建新 SAP 管道的功能将被弃用。基于 HyperAuto V1 的现有 SAP 管道和非 SAP 系统仍将可用且保持不变。

实时 HyperAuto 管道的概览。

点击式配置

HyperAuto V2 的重构以易用性为核心设计理念。要创建和配置 HyperAuto 管道，用户只需与直观的分步向导进行交互即可。系统已预先配置了合理的默认设置以简化流程，但用户在需要时可以按自己的判断调整设置。

HyperAuto 的主要自动化功能包括：

  • 通过自动对数据模型进行反规范化，并与包含相关元数据和附加信息的表进行连接，来丰富核心表。
  • 对源数据进行格式化和清理，确保列类型准确、列名称直观，并且正确处理空值数据。
  • 智能地对变更日志源数据进行去重，确保每个表都存在可供操作和分析使用的最新、无冗余版本

如需了解更多信息，请查阅 HyperAuto V2 文档。

已应用预设默认值的管道配置。

通过 Pipeline Builder 进行数据转换

HyperAuto V2 会动态生成 Pipeline Builder 管道来按需处理源数据。这提供了一个熟悉且易于理解的 UI，可完全透明地展示数据的处理过程，并让用户更容易了解自己可能需要在 HyperAuto 中更改哪些配置。

对现有 HyperAuto 管道配置的任何更改都会在底层 Builder 管道中创建一个新提案，该提案必须经用户批准并合并后，才能部署到实际运行的管道。Pipeline Builder 附带全面的变更管理工作流程，HyperAuto 会加以利用，为关键工作流程提供质量保证。

动态生成的 Pipeline Builder 管道，用于处理源数据。

来自 SAP 的实时数据处理

HyperAuto V2 支持针对 SAP 数据源的实时流式连接和数据转换（需要 SLT Replication Server），能够满足需要实时查看相关 SAP 数据的关键运营应用的需求。此外，HyperAuto V2 还为批量管道带来了显著的性能提升。

如果您想启用 SAP 流式传输，请联系您的 Palantir 代表。

流式转换将于 2023 年 9 月底迁移至 Java 17 [迁移/弃用]

发布日期：2023-08-17

2023 年 9 月底，所有 Foundry 流式转换的运行时将从 Java 11 迁移至 Java 17，以利用 Java 17 改进的性能和安全态势。Java 17 运行时引入了一项破坏性变更，阻止了对 JDK 内部类成员的反射访问。大多数流式转换不会受到此变更的影响，但此公告将广泛发布，以使广大用户普遍知悉。

虽然我们预计大多数 Foundry 流式转换不会受到此次迁移的影响，但在用户自定义函数（UDF）流式转换中，如果实现（或其关联的外部库）通过反射方式访问 JDK 内部结构，则可能出现中断。Palantir 将努力识别存在风险的 UDF 实现，并联系可能受影响的管道所有者。

如果您拥有在任意 Foundry 流式管道中使用的 Foundry UDF 定义仓库，请通过完成以下步骤来验证您的 UDF 是否与 Java 17 兼容：

  1. 如果您的 UDF 定义依赖于任何外部库，请验证这些库的版本是否与 Java 17 兼容。

    • 打开隐藏的 versions.properties 文件（位于您 UDF 定义仓库的根目录）。
    • 识别从外部仓库手动添加的所有依赖项（即并非由仓库模板默认添加的依赖项）。
    • 对于每个此类依赖项，请验证其在 versions.properties 文件中声明的最低版本是否与 Java 17 运行时兼容。这可能需要查看该依赖项的发行说明。

  2. 验证 UDF 实现没有通过反射访问 JDK 内部类。

    • 如果您的 UDF 实现未使用反射，则无需执行其他步骤。
    • 如果您的 UDF 实现确实使用了反射，请确保满足以下任一条件：
      • 所访问的类不是 JDK 内部类。
      • 您的实现能够正确处理 IllegalAccessException 异常，并且在某些反射操作开始抛出该异常时不会出错。

如果您在修复 UDF 定义仓库时遇到任何问题，或者对此通知有任何疑问或顾虑，请联系您的 Palantir 管理员。

Quiver 中的 AIP：透明的假设与增强的歧义处理

发布日期：2023-08-09

Quiver 中的 AIP 现在可以回答含糊、主观或使用相对性词语的提示，例如“筛选出支出金额较高的交易”或“按最重要的客户分组”。此外，凭借更强的上下文感知能力，AIP 现在能够根据对象集架构和数据推断出正确的值，从而处理列名和数据值中的拼写错误。

AIP Configure 所做假设的透明化

AIP Configure 建议的卡片配置现已分为两类：配置建议和需要做出假设的配置建议。如果请求不够具体，例如“让这个图表更美观”，AIP 将对提示中含糊的部分做出假设（在此示例中，歧义源于“美观”一词本身的含义），以推断哪些更改可能合适。在用户接受建议的更改之前，他们可以查看提示中 AIP 做出假设的部分以及这些假设的具体内容。

AIP Configure 建议的配置更改，其中显示了为回答提示而做出的假设

接受建议的配置更改后的条形图状态

AIP 如何使用本体论数据

现在，Quiver 会将用户提示连同对象集数据的摘要版本（即“属性值提示”）一起发送给 AIP 进行处理。属性值提示仅针对被判定与回答用户提示相关的属性进行计算，具体如下：

  • 字符串属性类型：最多计算 100 个唯一值
  • 数值属性类型：计算最小值、最大值和平均值

以前，由于没有有效值样本，经 LLM 筛选的对象集会使用不在集合中的值。这通常会导致筛选后的对象集为空，进而影响所生成图中的下游卡片。借助这些改进，AIP 现在可以使用属性值提示来纠正列名和属性值中的拼写错误，并在进行“高”、“低”、“最大值”等定量描述时确定阈值。

旧版数据连接代理将被弃用，取而代之的是经过优化的直接连接 2023 年 8 月 [Sunset]

发布日期：2023-08-07

Palantir Foundry 正在弃用其旧版数据连接代理，转而将数据连接迁移至 Rubix ↗，这是一项在 Kubernetes 上运行的安全、更可靠且更高效的云服务。此次更新意味着不再需要数据连接代理，因为它们只是允许 Palantir 连接外部客户网络的临时解决方案。

因此，所有安装在 Palantir 提供的 AWS 主机上的代理必须在 2023 年 8 月底之前停用，并且所有受影响的工作流都需要迁移到直接连接。Palantir 工程师目前正在为堆栈上已安装可运行云数据摄取的 Rubix 的客户完成迁移。

将工作流迁移到直接连接的优势包括：

  • 高可靠性： 直接连接比代理更可靠、更易于管理。它无需每周的维护窗口，从而消除了停机时间。
  • 更好的并行性： 直接连接能够更好地处理多个并行同步，并且可以直接利用 Foundry 中的自动扩缩容功能，因为每个同步都作为独立的作业运行。
  • 更好的网络管理： 作业只能访问其运行所需的端点，而在基于代理的连接中，单个代理主机必须满足所有需要通过该代理运行的作业的网络要求。
  • 自助服务： 直接连接消除了对 Palantir 支持的依赖，因为其管理可直接在 Foundry 的用户界面中完成。

如果您希望继续使用基于代理的工作流，可以创建一个托管在您自己硬件上的新代理，并将您的代理分配给受影响的数据源。

要完成迁移，请按照文档中有关 将数据源从代理工作器运行时切换为直接连接的说明进行操作。
