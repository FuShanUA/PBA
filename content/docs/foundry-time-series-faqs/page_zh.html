如何为时间序列属性（TSP）设置单位和插值方式？

您可以通过格式化工具为每个 TSP 配置单位和插值方式。要找到该格式化工具，请在 Ontology Manager 中导航到时间序列对象类型，并找到 时间序列属性 已应用标签 功能 标签页。或者，您也可以在 属性 标签页中编辑单位和插值方式，与其他任何 值格式化工具.

什么是度量（Measures）？什么时候应该使用它们？

在 传感器对象类型开发之前，平台使用度量（Measures）作为时间序列模型。度量正在被弃用，您可以在类似的工作流中使用传感器对象类型。更多信息请参阅以下页面：

  • 本体论编辑： 从度量迁移到传感器对象类型.
  • 本体论编辑： 在本体论中存储时间序列.

时间序列数据是否被索引？

创建 时间序列同步 应用于您的 时间序列数据集 将自动创建一个 时间序列投影 。时间序列投影是数据集的物化副本，可提供类似于 SQL 数据库索引的优化。

当时间序列同步构建时，它会生成有关其派生自的时间序列数据集事务的元数据，从而告知 Foundry 的时间序列数据库有哪些可供索引的数据。

当 使用时间序列，您将从时间序列数据库读取索引数据。时间序列数据库类似于缓存；数据仅在读取时进行水合（hydrate）。

什么是时间序列投影？

A 投影 是数据集的物化副本，可针对某些查询进行优化。就时间序列而言，该投影针对在读取时间序列数据集以向时间序列数据库加载数据时所执行的查询进行了优化。此过程涉及对时间序列数据集进行过滤，以选择正在加载的 序列 ID 以及时间范围。通过这种方式，投影保持了良好的分区以及对时间序列数据的排序，从而有效地按序列 ID 和时间戳对时间序列数据集进行索引。

为什么我的时间序列加载失败？

如果错误提示“不存在时间序列数据”，则可能是您的时间序列数据集/同步与 和之间的序列 ID 映射不正确。每个数据集中的序列 ID 集合应该相交，理想情况下应该是相等的集合，以便 时间序列属性 能够正确引用时间序列数据。请同时检查您的时间序列对象类型上的序列 ID 属性是否 配置正确.

尤其是在处理大规模时间序列时，向时间序列数据库加载数据可能会彻底失败。这可能是由于优化失败（或缺少优化）导致的：

  • 如果时间序列数据集上的时间序列投影已 过时，则会从 规范数据集中读取未投影的事务。这意味着投影的优化未被应用；数据分区将分散在更多的文件中，并且需要扫描更多的行才能加载所需的数据。系统配置了内置限制以防止这种不希望出现的访问方式，因为它很可能导致查询超时，并对服务健康产生负面影响。请检查时间序列投影的计划任务是否持续且定期运行。您可以从数据集预览页面手动重建投影。
  • 如果时间序列数据集未正确 分区和排序，在极端情况下，这可能会导致类似的问题，即必须扫描过多的行才能索引所需的数据，您将面临内置的服务限制。为帮助防止此问题，在 Pipeline Builder 中转换数据并将其映射到时间序列同步输出时，时间序列数据集将自动为您正确格式化。您也可以通过更新时间序列投影或手动向管道添加正确的格式来解决此问题。

为什么我的时间序列加载时间很长？

时间序列数据加载缓慢的最常见原因是数据尚未在时间序列数据库中建立索引。索引水合（hydration）发生在首次查询某个时间序列（序列 ID）时，或在任何后续 快照事务 由时间序列同步进行同步。同步的快照事务会通知时间序列数据库将某个序列从完整数据集视图水合（hydrate）到其索引中。

为提高水合速度，请为查询添加时间过滤器，以便仅水合指定时间范围内的数据点，而不是整个序列。您可以使用 Quiver 中的筛选时间序列卡片 或 time_range FoundryTS 中的函数.

在时间序列初始水合之后，查询速度应该会快得多。如果您的管道正在 以增量方式 添加时间序列数据，则新数据将由时间序列数据库增量水合，并且在数据的首次快照水合之后，您的时间序列应该能够快速加载。

我们建议运行 增量管道 以提高后续索引性能。

如果有大量数据需要增量水合，查询仍可能需要很长时间才能加载。例如，如果增量事务非常大，或者由于时间序列未被定期查询而存在许多尚未水合的增量事务，加载时间将会增加。

在某些极端情况下，如果未对时间序列数据集应用 时间序列重新分区或排序 ，或者相对于数据量写入了过多的分区（因为这可能需要读取许多文件），则快照水合和增量水合都会很慢。这仅适用于尚未被时间序列投影投影的事务。在 Pipeline Builder 中转换数据并将其映射到时间序列同步输出时，时间序列数据集会自动为您正确格式化。

为什么我的时间序列缺少数据？

要使所有时间序列数据都索引到时间序列数据库中，其时间序列同步必须是最新的。这意味着同步必须在时间序列数据集上的最新事务构建之后进行构建，否则这些事务中的数据将无法被水合。

如果您的时间序列数据集未以 Soho 格式格式存储，则不会有任何未投影的数据被水合到时间序列数据库中。在 Pipeline Builder 中转换数据并将其映射到时间序列同步输出时，支撑该同步的物化时间序列数据集将自动为您转换为 Soho 格式。您还可以完成以下任一任务，以获取更多最新数据：

  • 将您的时间序列数据集转换为 Soho 格式。这需要一个快照来转换所有数据。
  • 安排时间序列投影在时间序列数据集每次更新时进行构建。这将为最新数据的查询引入一些延迟。
