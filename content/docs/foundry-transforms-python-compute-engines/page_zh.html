计算引擎选择

Python 转换支持多种查询引擎，以满足不同的数据处理需求。为您的用例选择合适的引擎，可以确保获得最佳性能、成本效率和开发人员生产力。

可用的查询引擎包括 DuckDB ↗、 pandas ↗、 Polars ↗，以及 Spark ↗。这些引擎都提供相应的 Python 库，可通过简单直观的 API 进行数据操作。

DuckDB、Pandas 和 Polars 可通过我们的标准单节点计算产品使用，该产品也称为 lightweight。Spark 可用于分布式计算方法。更多信息请参阅 PySpark 文档。

可用的查询引擎

Pandas

最适合： 快速迭代、探索性分析和小型数据集

Pandas ↗ 是 Python 生态系统中常用的数据处理库。它擅长快速原型开发，并提供丰富的兼容库生态系统。在刚开始开发新转换时，或团队需要使用熟悉的工具快速推进时，可以使用 pandas。

主要特点：

  • 开发过程中的即时反馈
  • 丰富的文档和社区支持
  • 丰富的时间序列和统计运算功能
  • 单线程执行模型

Polars（推荐）

最适合： 生产数据管道和中等规模数据处理

Polars ↗ 应作为生产转换的默认选择。它基于 Apache Arrow 构建，以 Rust 为核心，通过列式存储和惰性求值实现了出色的性能。Polars 将 DataFrame 操作的易用性与生产工作负载所需的性能相结合。

主要特性：

  • 通过惰性求值实现自动查询优化

  • 单节点上的多线程执行

  • 内存高效的列式存储

  • 可预测的性能特征

  • 可通过 cudf-polars 为受支持的操作提供 GPU 加速——请参阅 高级计算选项 了解详情

DuckDB

最适用于： 具有严格延迟限制的中等规模数据

DuckDB ↗ 是一款高性能的单节点 SQL 查询引擎，专为分析型工作负载而优化。DuckDB 特别适合需要低延迟和高效资源使用的中大规模数据处理任务。但是，DuckDB 缺少 Python DataFrame API，需要用户编写原始 SQL 查询来进行数据操作。

主要特性：

  • 通过惰性求值实现自动查询优化
  • 自动内存管理，支持溢写至磁盘
  • 处理原始 SQL 字符串而非 DataFrame API

Spark

最适用于： 大规模数据处理和组织级数据基础

Spark ↗ 专为大规模分布式计算而设计。虽然它在小型操作上开销较高，但当数据超出单节点容量，或构建需要最大可扩展性的关键组织数据集时，它是唯一的选择。

主要特性：

  • 跨多节点的分布式处理
  • 自动内存管理，支持溢写至磁盘
  • 在 PB 级规模上经过实战检验
  • 用于复杂查询规划的 Catalyst 优化器

选择合适的引擎

以下数据规模建议仅作为一般经验法则，并不适用于所有查询。对于形态合适的转换，轻量级引擎甚至可以在单个节点上处理 TB 级别的输入。请参阅 Polars 惰性 API 文档中关于大于内存的数据转换的内容，以详细了解如何使用 Polars 流式处理。无需将所有数据一次性加载到内存中的查询，可在单个节点上扩展至任意规模。

我们建议以 Polars 作为生产转换的默认选择。当需要快速迭代或使用特定生态系统的库时，可以切换到 pandas。DuckDB 是使用 SQL API 或最大化单节点性能的绝佳选择。迁移到 Spark 仅 在数据规模需要时，通常为数据量超过 50 GB 且无法使用诸如 过滤下推等优化时。

高级计算选项

高级集成包括 Ibis ↗ （支持多种后端）、 Apache DataFusion ↗，通过 DuckDB 直接访问 Parquet 文件，以及用于 GPU 加速处理的 cuDF ↗。

请参阅 高级单节点计算选项 以获取示例和指导。

从 Spark 迁移到单节点计算

现有转换中有很大一部分使用 Spark，因为在 Python 转换中，Spark 获得支持的时间比单节点引擎更长。如果迁移到单节点计算引擎，其中许多管道可能运行得更快或消耗更少的资源。然而，很难判断这种迁移会产生多大的影响，而且翻译可能是一个成本高昂的过程。为了初步了解单节点性能，我们建议 使用 SQLFrame 将管道迁移到 DuckDB ，然后再决定是否进行全面翻译。
