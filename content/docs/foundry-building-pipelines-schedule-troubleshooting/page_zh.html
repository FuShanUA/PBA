故障排除参考

本页面介绍常见的调度问题及调试步骤。

计划构建问题

调度指标页面

排查调度问题的最佳方式之一是查看 调度指标页面。指标页面可以告诉你失败的来源。常见的失败包括：

  • 直方图 计划构建失败。你将在 运行历史 选项卡中看到构建失败的证据。选择这些构建将导航到构建报告，位于 构建应用程序 以查看完整日志。
  • 直方图 计划构建被忽略。该 运行历史 选项卡将显示 Ignored 在状态列中，对于任何已触发但未构建的构建。
  • 直方图 调度未触发 在预期的时间或频率。对于这种情况， 运行历史 选项卡可能不会在你预期的时间显示构建已被触发。

另一个有用的选项卡是 版本 选项卡，它显示过去的调度版本和编辑记录。如果你的调度突然开始表现异常，请检查与此变化相符的调度版本变更，并考虑将调度恢复到之前正常工作的状态。

计划构建失败

你可以通过查看 运行历史 选项卡来验证调度是否在预期时间被触发，位于 调度指标页面.

如果调度已触发但构建随后失败，你可以在 构建应用程序 中调试此构建，与其他构建类似。

如果未设置适当的权限，调度也将无法构建。调度的权限取决于其使用的令牌模式。了解更多关于 项目范围的调度.

计划构建被忽略

你可以通过查看 运行历史 选项卡来验证调度是否在预期时间被触发，位于 调度指标页面。此信息通常会给出调度被忽略的原因。

所有数据集均为最新

如果所有目标数据集都是最新的（即自上次构建以来其输入未更新），调度运行将被忽略。如果是这种情况，你将在 运行历史 选项卡中看到此原因。在 调度编辑器中，导航到调度列表。然后你可以选择按 Out-of-date为数据血缘图着色，这将让你概览哪些作业规范被视为过期。

在特殊情况下，可以使用 强制构建 选项覆盖此行为，位于 高级设置中，但在此类情况之外使用会造成计算资源浪费。如果任何目标数据集由 Object Storage v1 (Phonograph) 同步、带 API 调用的转换或 Data Connection 同步构建，它们可能不会显示为过期，并且可能需要启用 强制构建 选项才能运行调度。

调度构建部分作业规范

如果调度仅触发部分作业规范，你将在 运行历史 选项卡来验证调度是否在预期时间被触发，位于 调度指标页面.

中看到相关证据。此行为的一个原因是只有部分作业规范已过期。调度将仅构建过期的作业规范，而最新的作业规范将在构建过程中被忽略。参见 所有数据集均为最新 以了解更多故障排除详情。构建 Ignored 的情况发生在所有这些作业规范均为最新时。

另一个原因可能是该作业规范未包含在构建的作业规范图中。当在 调度编辑器中选择给定调度时，要构建的作业规范会在数据血缘图中高亮显示。作业规范的选择取决于 构建类型。如果使用 连接构建，请务必验证对于在多个分支上使用相同数据集的调度，是否存在连接作业规范。

调度未触发

你可以通过查看 运行历史 选项卡来验证调度是否在预期时间被触发，位于 调度指标页面。一些常见的调试步骤包括：

  • 请检查 计划未处于暂停状态。暂停的计划在取消暂停之前不会触发。
  • 检查 计划触发器配置。如果该计划之前曾成功触发，请检查计划历史记录，以查看触发器最近是否有变更。
  • 如果计划使用的是 Event 触发器，请验证预期的事件是否确实发生了。
    • 例如，如果构建应在输入更新时触发，请检查输入上的最后一次构建是否成功运行，以及该构建中的事务是否已成功提交到 数据集预览历史记录视图.
    • 如果构建应在多个输入更新后触发，请检查 所有 输入上的构建和时间安排。例如，假设某个计划具有输入触发器 A1 和 A2，并且已启用“等待所有这些数据集更新”。假设该计划之前在时间 T1 运行。要使该计划在时间 T2 再次运行，A1 和 A2 都需要在 (T1, T2) 时间段内更新。



计划重试与配置的

不同。并非所有类型的失败都可以重试。计划运行时的重试次数将受管理员配置的最大值限制。了解更多关于 高级计划设置.

可重试的错误代码包括：

  • INTERNAL
  • TIMEOUT
  • CUSTOM_SERVER
  • FAILED_PRECONDITION

计划失败并出现 JobSpecInputsTrashed 或 JobSpecOutputsTrashed，或者数据血缘警告某些数据集已被移入回收站

此错误表示计划包含或读取了已移入回收站的资源。您可以执行以下操作之一来解决：

  • 恢复 已删除的数据集（从回收站中）。
  • 将该已删除的数据集从计划中排除。如果此数据集被用作计划中另一个下游数据集的输入，您还需要执行以下操作之一：
    • 将该下游数据集与已移入回收站的数据集一并排除。
    • 修改下游数据集的逻辑，使其不再以已移入回收站的数据集作为输入。

计划编辑器问题

计划权限

要在 项目范围模式下编辑计划，您必须对目标数据集具有 Editor 权限，对触发器数据集具有 Viewer 权限，并对计划所属的项目具有 Editor 权限。如果您失去了某个数据集的权限，请在保存更改之前将该数据集从计划中移除。

要编辑、删除或暂停计划，您需要对目标数据集具有 Editor 权限，并对计划所属的项目具有 Editor 权限。要查看计划，您需要对目标数据集具有 Viewer 权限。

计划计算信息不可用

查看计划时，可能会出现消息“并非所有计算信息均可用。实际计算使用量可能高于所示值。”，原因可能是以下之一：

  • 一个或多个计划构建仍在进行中，总计算使用量尚未最终确定。
  • 缺少关于至少一个计划构建所用资源的信息。

显示此消息时，无需用户采取任何操作。此消息的目的是表明在特定时间点所显示的总计算使用量可能不准确。
