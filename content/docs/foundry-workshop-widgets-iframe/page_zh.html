Iframe

在尝试开发自定义 widget 时，我们建议使用 自定义 widget 而不是 Iframe widget 的双向选项。

直方图 Iframe widget 支持在 Workshop 中嵌入外部整页应用程序，为构建者提供了一种向其模块添加自定义视图的方式。

嵌入的应用程序还可以使用 Workshop 变量和事件进行双向通信，使嵌入的应用能够像自定义 widget 一样运行。请参阅 双向 配置选项，了解如何以 iframe 方式嵌入一个能够读取和写入 Workshop 的应用程序的更多详情。

由于 iframe 需要额外的内存和处理资源，Workshop 模块的稳定性和性能可能会受到影响。我们不建议在屏幕上嵌入多个 iframe widget。

您需要配置 内容安全策略（CSP） 才能在您的 Foundry 环境中以 iframe 方式嵌入外部资源。外部资源本身还必须设置 Content-Security-Policy 标头的 frame-ancestors 指令 ↗ 以允许您的 Foundry URL 嵌入该资源。如果您使用的是 Foundry 环境外部并向 Foundry API 发起请求的 URL，则还必须配置 跨源资源共享（CORS）.

URL

以静态字符串或字符串变量的形式输入应用程序的 URL。在嵌入另一个 Foundry 应用程序时，您可以通过添加 embedded=true URL 查询参数来隐藏 Foundry 侧边栏。

如果您粘贴标准的 YouTube URL（例如， https://www.youtube.com/watch?v=VIDEO_ID），Workshop 将检测该 URL 格式，并提供一键选项将其转换为正确的嵌入格式（https://www.youtube.com/embed/VIDEO_ID），以便在 iframe 中显示。

将收集到的信息存储在

Slate 配置选项允许您将 Slate 应用程序嵌入到您的 Workshop 模块中。可以使用参数让嵌入的 Slate 应用程序与 Workshop 模块相互交互。

以下各节详细介绍了如何使用 iframe widget 嵌入 Slate 应用程序。

Slate 来源

Slate 来源定义了引用模块中嵌入的 Slate 的方法。您可以选择使用 Compass 引用 or 永久链接 作为您的 Slate 来源。

  • Compass 引用： 允许您使用 Foundry 资源选择器选择要嵌入的 Slate 应用程序。
  • 永久链接： 允许您输入 Slate 应用程序的永久链接或 RID 来选择要嵌入的应用程序。您可以在您的 URL 中找到 Slate RID： /workspace/slate/documents/<slate-permalink>/latest.

URL 参数

URL 参数会附加到您的 Slate URL，用于在 Slate 中设置变量。更改 URL 参数会导致整个页面重新加载，因此我们建议仅对很少需要修改的变量使用 URL 参数。要在 Slate 中引用 URL 参数，请设置一个与 URL 参数同名的变量，并使用 handlebars 引用它： {{username}}。静态字符串 URL 参数应进行 URI 编码，因为它们会直接作为 URL 参数传递。

示例： 在加载时根据用户名和 ID 更改嵌入的 Slate 应用程序的外观。

输入参数

输入参数从 Workshop 模块传递到嵌入的 Slate 应用程序中。输入参数由其键和值类型定义。可以将静态字符串、字符串变量、数字和对象集传递给嵌入的 Slate 应用程序。

在您的 Slate 应用程序中，您可以通过使用 Slate.getMessage 事件（位于 事件面板 中）以及下面的代码示例作为参考，从您的 Workshop 模块中检索信息。 parameter_key 必须与您在 Workshop 的 iframe widget 中定义的键相匹配。

输出参数

输出参数从 Slate 嵌入传递到 Workshop 模块中。输出参数由其键和值类型定义。对象集、对象集过滤器和字符串变量可以传递到 Workshop 模块。在 Workshop 模块中，您可以通过将 Workshop 变量分配给该参数来从 Slate 应用程序中检索信息。在 Slate 应用程序中，您需要使用 Slate.sendMessage 事件和下面的代码片段来启动信息传输。代码中的参数键必须与您在 Workshop 小部件中定义的键相匹配。

return {
    type: "WORKSHOP//SET_OUTPUT_VALUE",
    outputParameterKey: "<parameter_key>",
    value: {{<data_to_be_sent>}}
}

某些 JavaScript 原始类型在将值存储到字符串变量中时会被映射到相应的 Workshop 类型。 undefined 将被映射到 undefined （实际上将变量重置回其默认值），并且 null 将清除字符串变量的值。

示例： 使用嵌入式 Slate 应用程序中的选择状态来更改 Workshop 中的过滤器集状态。

return {
    type: "WORKSHOP//SET_OUTPUT_VALUE",
    outputParameterKey: "selected-objects",
    value: {{f_selection}}
}

可触发事件

您可以触发任何 Workshop 事件 （从 Slate 触发）。可触发事件由其键和事件类型定义。您可以触发打开覆盖层、重置变量等事件。

在您的 Workshop 模块中，定义 event_key 以及您想要触发的事件。在您的 Slate 应用程序中，使用 Slate.sendMessage 事件面板中的事件，并参考下面的代码片段。 event_key 必须与 iframe 小部件中定义的键相匹配。

return {
    type: "WORKSHOP//TRIGGER_WORKSHOP_EVENT",
    eventKey: "<event_key>",
}

示例： 通过 Slate 中的按钮点击来切换 Workshop 中的可折叠部分。

return {
    type: "WORKSHOP//TRIGGER_WORKSHOP_EVENT",
    eventKey: "<event_key>",
}

双向

双向配置选项允许您嵌入自定义构建的应用程序，并使用定义的配置字段启用与 Workshop 的双向通信。这使嵌入式应用程序能够像任何其他 Workshop 小部件一样运行，可以读取和写入 Workshop 变量，以及执行 Workshop 事件。为了在您的应用程序中访问本体论，请使用 本体论 SDK.

要在全局分支上使用嵌入式 Developer Console 应用程序，请遵循 分支上下文要求。其他 iframe 配置不会继承 Workshop 模块的全局分支上下文，并可能对 main.

何时使用

虽然 Workshop 提供了 多种可用小部件，但某些情况可能需要超出 Workshop 内置小部件所提供的特定功能。此双向小部件选项允许您创建自己的应用程序、定义配置字段，并像任何其他小部件一样将其嵌入 Workshop 中。

配置双向小部件

要启用双向通信，您必须在将自定义应用程序作为双向小部件嵌入 iframe 之前配置其源代码。

步骤 1：修改您的自定义应用程序以与 Workshop 通信

您的自定义应用程序与 Workshop 之间的通信使用 npm 包 @osdk/workshop-iframe-custom-widget ↗来完成。使用以下命令将该包安装到您的自定义应用程序中：

npm i @osdk/workshop-iframe-custom-widget

此包提供了通过函数与 Workshop 进行双向通信的方法 useWorkshopContext ，该函数接收您的应用程序希望从 Workshop 接收的变量和事件的定义，并返回一个上下文对象，该对象具有读取 Workshop 变量值、写入 Workshop 变量值以及执行 Workshop 事件的接口。请查看 npm 包页面以获取 @osdk/workshop-iframe-custom-widget ↗ 的详细信息和进一步说明。

步骤 2：配置双向小部件

在您的应用程序部署了与 Workshop 双向通信的更改后，向您的 Workshop 模块添加一个 Iframe 小部件，并选择 双向 选项。

以静态字符串或字符串变量的形式输入您应用程序的 URL。小部件的配置面板在等待接收嵌入式应用程序所需的变量和事件定义时会显示加载状态。

接收到所需变量和事件的定义后，小部件的配置面板将为每个请求的变量和事件显示变量选择器和事件选择器，允许对每个变量和事件进行设置。

每次 Workshop 变量的值或加载状态发生变化时，所设置的 Workshop 变量的值将被发送到自定义应用程序。所设置的事件将决定可以从自定义应用程序内执行哪些事件。

局限性

  • 由 iframe 嵌入的应用程序发送的对象集字段定义使用单一预设对象类型指定。在 Workshop 中配置该变量时，该变量所约束的对象类型将显示在对象集变量的配置面板中。如果 Workshop 对象集变量包含不属于预设对象类型的对象，这些对象将在发送到 iframe 嵌入的应用程序之前被过滤掉。

  • 对象集变量在发送到 iframe 嵌入的应用程序时限制为 10,000 个对象。如果您尝试将包含超过 10,000 个对象的 Workshop 对象集变量传递给 iframe 嵌入的应用程序，或者尝试从 iframe 嵌入的应用程序内部设置包含超过 10,000 个对象的 Workshop 变量，第 10,000 个对象之后的对象将被截断，不会发送给接收方。

  • 目前不支持结构体变量。

  • iframe 每次从页面中移除并随后再次显示时都会重新加载，这会丢弃 iframe 内部保存的任何状态。为防止小组件在这种情况下被重置，您可以配置小组件的 显示优化 设置以使其保持挂载状态，或者将双向小组件数据存储在传递给小组件的 Workshop 变量中。

本地网络访问

默认情况下，浏览器安全策略会限制嵌入式应用程序请求 localhost 或其他本地网络地址。如果您的嵌入式应用程序必须与本地服务通信，请启用本地网络访问。

要允许本地网络访问，请启用 iframe 小组件配置中的 允许本地网络访问 选项。启用后，iframe 将在其 local-network 属性中包含 allow 权限，允许嵌入式应用程序向 localhost 地址发出请求。

启用本地网络访问将允许嵌入式应用程序与用户本地机器上的服务进行通信。仅在必要且您信任该嵌入式应用程序时才启用此选项。
