增量使用指南

增量装饰器

本指南涉及增量构建与非增量构建。假定在所有情况下都使用了 incremental() 装饰器。因此，这一术语仅指转换是否实际以增量方式运行。

该 incremental() 装饰器可用于通过启用增量计算的逻辑来包装转换的计算函数：

from transforms.api import transform, incremental, Input, Output

@incremental()
@transform.spark.using(
    students=Input('/examples/students_hair_eye_color'),
    processed=Output('/examples/hair_eye_color_processed')
)
def filter_hair_color(students, processed):
    students_df = students.dataframe('added')
    processed.write_dataframe(students_df.filter(students_df.hair == 'Brown'))

该 incremental() 装饰器可用于包装任何使用了 transform()， transform.using()， transform_df()，或 transform_pandas() 装饰器的现有转换。请注意，你的转换的计算函数 必须 支持以增量与非增量两种方式运行。该 incremental() 装饰器会执行两项关键操作：

  • 它允许转换查询其上一次构建的相关信息。利用这些信息，该 incremental() 装饰器随后会决定转换能否以增量方式运行，具体依据是 下文所述的要求。
  • 它会将输入、输出和上下文对象转换为提供额外功能的增量子类。具体来说， TransformInput 变为 IncrementalTransformInput， TransformOutput 变为 IncrementalTransformOutput，而 TransformContext 变为 IncrementalTransformContext。这些增量对象随后会被传入由装饰器包装的转换。

将 require_incremental 参数设置为 True 使转换在无法以增量方式运行时失败。有两种情况允许转换以快照方式运行，即使 require_incremental=True：

  1. 其中一个输出从未构建过。
  2. 语义版本已更改，这意味着已明确请求快照。

要调试转换无法以增量方式运行的原因，请在驱动程序日志中查找警告 transforms.api._incremental: Not running incrementally。

该 semantic_version 参数（位于 :func:~transforms.api.incremental 装饰器上）允许您强制转换的下一次运行以非增量方式进行。

  • 如果当前运行的语义版本与上一次运行的语义版本不同，则转换将以非增量方式运行。
  • 如果未指定，语义版本将设置为 1。
  • 如果上一次运行的语义版本不存在（例如，将现有转换转换为增量转换时），则假定值为 1 。这使得转换无需新的快照即可开始以增量方式运行。
  • 要强制转换的后续运行以非增量方式进行，您可以提升 semantic_version 参数的值，该参数位于 @incremental() 装饰器上。

该 snapshot_inputs 参数允许您将某些输入定义为快照输入，与非快照输入不同，这类输入支持更新和删除修改。请参见 快照输入 以获取更多信息。

将 allow_retention 参数设置为 True ，即可在保持转换增量性的同时，通过保留策略删除输入和输出数据集中的文件。

将 allow_user_deletes 参数设置为 True ，即可在保持转换增量性的同时，删除输入数据集中保留策略范围之外的文件。此参数需要 v2_semantics=True ，且在轻量级转换中不受支持。

如果 strict_append 参数设置为 True 且输入数据集为增量数据集，则底层的 Foundry 事务 类型将被设置为 APPEND，并且将使用 APPEND 事务进行增量写入。尝试覆盖现有文件将导致异常。 如果输入数据集不是增量数据集， strict_append 将作为 SNAPSHOT运行。你应该使用 require_incremental=True 来确保代码以 APPEND方式增量运行。尝试覆盖现有文件将会成功。 请注意，写入操作可能不会覆盖任何文件，即使是辅助文件，例如 Parquet 摘要元数据或 Hadoop SUCCESS 文件。所有 Foundry 格式的增量写入都应支持 strict_append 模式。

如果 v2_semantics 参数设置为 True，则会使用 v2 增量语义。v2 与 v1 增量语义在行为上应无差异，我们建议所有用户将其设置为 True。非 Catalog 的输入和输出资源仅在使用 v2 语义时才能以增量方式读取/写入。

重要信息

如上文所述，您的转换中使用 incremental() 装饰器包装的计算函数 必须 支持以增量和非增量两种方式运行。默认的读取和写入模式（本指南其余部分将进行更详细的说明）可帮助满足这一双重逻辑要求，但仍可能需要根据 is_incremental 属性进行分支处理，该属性属于 计算上下文。

另一个要点是，使用 incremental() 装饰器并配合 transform_df() 或 transform_pandas() 只会让您访问默认的读取和写入模式。如果您有一个转换，其新增的输出行仅是新增输入行的函数，那么这就足够了（请参阅 追加示例）。但是，如果您的转换执行更复杂的逻辑（例如连接、聚合或去重），且需要您设置输入读取模式或输出写入模式，则应使用 incremental() 装饰器并配合 transform()。将增量装饰器与 transform() 配合使用，即可让您设置读取和写入模式。

警告

代码仓库预览功能始终以非增量模式运行转换，即使您将 require_incremental=True 传入 incremental() 装饰器。VS Code 预览遵循增量行为，并支持 Spark 和轻量级转换的 v1 和 v2 增量语义。

输入和输出的增量模式

增量转换是一项强大的功能。但是，该 API 在首次使用时可能不太直观。增量转换在 VS Code 预览 中的行为方式与在构建期间的行为相同。我们建议使用 VS Code 预览 来试验该 API 并在实践中理解它。

IncrementalTransformInput

该 transforms.api.IncrementalTransformInput 对象扩展了数据读取方法，可接受一个可选的读取模式参数。

如果您使用增量装饰器定义转换，则读取模式的行为将有所不同，具体取决于转换是以增量方式还是非增量方式运行：

读取模式增量行为非增量行为
added *返回一个 DataFrame ↗ ，其中包含自上次运行转换以来追加到输入中的所有新行。返回一个 DataFrame ↗ ，其中包含整个数据集，因为所有行都被视为 未见过。
previous返回一个 DataFrame ↗ ，其中包含上次运行时提供给转换的整个输入。返回一个空的 DataFrame ↗。
current返回一个 DataFrame ↗ ，其中包含当前运行的整个输入数据集。返回一个 DataFrame ↗ ，其中包含当前运行的整个输入数据集。这等同于 added。

默认读取模式为 added。请查看 增量转换示例 ，其中包含展示每种读取模式返回结果的代码。

在某些情况下，尽管转换已被标记为 incremental()，但仍不希望以增量方式处理某些输入。请参阅 快照输入 部分，了解更多信息以及这些类型的输入在读取模式行为上有何不同。

请注意，默认输出读取模式为 current，可用的输出读取模式有 added、 current和 previous。有关输出读取模式的更多信息，请参阅下方部分。

增量转换的特性意味着，我们会加载输入数据集自上一次 SNAPSHOT 事务以来的所有过往事务，以构建输入视图。如果您开始发现增量转换逐渐变慢，我们建议对您的增量输入数据集运行 SNAPSHOT 构建。

IncrementalTransformOutput

该 transforms.api.IncrementalTransformOutput 对象提供对输出数据集的读取和写入模式的访问。编写同时兼容增量构建和非增量构建的逻辑，关键在于默认写入模式 modify。共有两种写入模式：

  • modify：此模式会使用构建期间写入的数据修改现有输出。例如，调用 write_dataframe() 或 write_table() 时，如果输出处于 modify 模式，则会将写入的 DataFrame 追加到现有输出中。
  • replace：此模式会使用构建期间写入的数据完全替换输出。

当转换以增量方式运行时，输出的默认写入模式将设置为 modify。当转换以非增量方式运行时，输出的默认写入模式将设置为 replace。

请记住，输入 DataFrame 的默认读取模式为 added。由于默认输入读取模式为 added ，且默认输出写入模式为 modify，编写兼容增量构建和非增量构建的写入逻辑就会变得容易得多：

import polars as pl

@incremental()
@transform.using(
    students=Input('/examples/students_hair_eye_color'),
    processed=Output('/examples/hair_eye_color_processed')
)
def incremental_filter(students, processed):
    # Read only the rows we haven't seen before.
    new_students_df = students.polars()  # this is equivalent to students.polars('added')

    # When non-incremental, we read all rows and replace the output.
    # When incremental, we read only new rows, and append them to the output.
    processed.write_table(
        new_students_df.filter(pl.col("hair") == 'Brown')
    )

增量计算还有一些更复杂的用例，其中可能需要计算正确的写入模式并手动进行设置。这可以使用增量输出上的 set_mode() 方法来完成，并且在使用 transform() 或 transform.using() 装饰器时受支持。使用这些装饰器，您可以先调用 set_mode() ，然后再显式调用写入方法来保存输出。但是， transform_df() 和 transform_pandas() 装饰器会调用 write_dataframe() 和 write_pandas() 以保存 DataFrame 输出，因此使用这些装饰器时，所使用的写入模式将由 incremental() 装饰器决定。

警告

在使用 set_mode()时，请确保无论转换以增量方式还是非增量方式运行，此行为均为有效。如果不是这种情况，您应当使用 is_incremental 属性。

除写入模式外， transforms.api.IncrementalTransformOutput 还使您能够从输出数据集读取 DataFrame。这可以通过诸如 pandas()、 polars()或 dataframe()等数据读取方法来完成，这些方法接受一个可选的读取模式参数。在使用 transform.using()时，请将该模式指定为关键字参数： output.pandas(mode='previous')。默认读取模式设置为 current ，其他可用的输出读取模式为 added 和 previous。读取模式的行为会因数据集写入模式的设置不同而有所差异。

尽管默认读取模式为 current，但在大多数情况下，您应当使用 previous。其他读取模式应当用于在向数据集写入数据之后读取该数据集。

从上一次运行中读取数据的有效组合

转换必须以增量方式运行（ctx.is_incremental is True) 以访问转换的上一次输出。如果转换以非增量方式运行，通常允许访问上一次输出的读取模式将不会返回上一次输出数据中的任何行。下表所述行为源于增量性语义以及以下事实： current 和 previous 读取模式的事务在转换运行开始时即被解析。

currentmodify否这些设置没有任何用例。请改用 previous 模式。
currentmodify是dataframe() 返回转换输出的完整内容（即构建开始时的内容），外加当前正在运行的构建中写入到输出的数据。
currentreplace否这些设置没有任何用例。请改用 previous 模式。
currentreplace是dataframe() 返回当前正在运行的构建中写入到输出的数据。

IncrementalTransformContext

与 TransformContext 对象相比， IncrementalTransformContext 对象提供了一个额外的属性： is_incremental。如果转换以增量方式运行，该属性会被设置为 True ，这意味着：

  • 默认输出写入模式会被设置为 modify，并且
  • 输入的默认读取模式会被设置为 added。

增量模式概要

增量装饰器允许您通过指定读取模式 "previous" 来访问转换先前的输入和输出。这样，您就可以将当前构建建立在历史上下文的基础上。如果转换以快照模式运行，"previous" 数据帧将为空，因为这是首次运行，或者因为逻辑或数据发生了重大变化而需要重新计算。

不过，最常见的情况是为输入使用 "added" 模式，为输出使用 "modify" 模式。默认情况下会使用这些模式。它们允许您从输入数据集中检索新增的行，对其进行处理，然后将其追加到输出数据集中。

您可能不想向输出追加行，而是希望修改输出数据集中已存在的某些行。为此，请使用 "replace" 模式，具体演示请参见 常见场景示例。

假设 /examples/students_hair_eye_color 输入数据集会被一组全新的学生数据完全替换。正如我们所见，将这组新的学生数据追加到先前的输出中会导致不正确的输出数据集。这就是一种示例情况，其中 incremental() 装饰器会决定 不 以增量方式运行转换。

要让转换以增量方式运行，必须满足以下要求：

  • 转换的所有非快照输入数据集 自上次运行以来仅添加了文件， 发生了因数据保留策略而产生的删除，或 发生了被允许的用户删除 allow_user_deletes。
  • 如果输入的最后一个事务是 UPDATE 修改了现有文件或某个 DELETE 删除了未被允许的文件，允许方为 allow_retention 或 allow_user_deletes，此输入仅在它被标记为 快照输入时才会以增量方式运行。
  • 转换的 输入列表可能会被修改 而不会损害构建的增量性。
  • 对于多输出转换，所有 输出的最近一次构建均通过同一转换完成。

如果转换具有 incremental() 装饰器，但未满足上述任何要求，则该转换将自动以非增量方式运行。这意味着默认的输出写入模式将被设置为 replace 而不是 modify 且输入将以非增量方式呈现。这也意味着在转换中读取输出将返回空的 dataframe，因为无法访问之前的历史记录。同样，输入也将以非增量方式呈现。

要强制转换仅以增量方式运行，请将 require_incremental=True 参数传递给 incremental() 装饰器。如果转换无法以增量方式运行，它将有意失败，而不是尝试以非增量方式运行，除非该转换此前从未运行过或语义版本已升级，在这种情况下，仍允许其作为快照运行。

通常希望允许完全重写某些输入，而不影响以增量方式运行转换的能力。为此，请将这些输入配置为 快照输入。

仅追加的输入变更

如果转换的所有增量输入自上次运行以来仅添加了文件（带有 APPEND 或 UPDATE 事务），则可以增量运行该转换。

相反，如果转换的增量输入存在以下任一情况，则无法增量运行该转换：

  • 增量输入被完全重写（例如，进行了 SNAPSHOT 事务）。
  • 增量输入有 UPDATE 修改或覆盖现有文件（而非仅添加新文件）的事务，或者包含 DELETE 未被允许使用的事务 allow_retention 或 allow_user_deletes。

例如，如果学生列表在 students_hair_eye_color 中完全发生变化，之前筛选出的学生输出就会失效，必须予以替换。

包含来自保留策略的删除操作的输入

如果上游数据集无限增长，而您希望能够删除旧行（使用 Foundry 中的保留）而不影响下游计算的增量性，依赖于该数据集的增量转换必须被显式设置为允许保留输入。这可以通过使用 allow_retention 参数来完成，该参数属于 transforms.api.incremental 装饰器。

  • 如果此字段设置为 True，则在评估输入是否保持增量性时，来自保留策略的所有删除都将被忽略。这意味着，文件 removed 因保留而从输入数据集中删除不会损害增量性，并且如果输入数据集仅有的非added 文件更改均为保留删除，则该转换仍将以增量方式运行。
  • 如果该字段为 False （默认），任何 removed-类型的更改出现在输入数据集中时，都会导致转换运行快照。

  • 如果此字段设置为 True，在评估输入是否保持增量性时，保留策略之外的所有删除操作都将被忽略。这意味着，来自输入数据集且超出保留范围的文件 removed 不会损害增量性，并且如果输入数据集仅有的非added 文件更改是用户删除操作，则转换仍将以增量方式运行。

警告

指定 allow_user_deletes=True 仅防止增量性受到 removed 并非来自保留策略的更改的影响。删除输入数据可能会使现有输出数据失效。仅当删除输入文件后转换逻辑仍保持正确时，才使用此参数。

快照输入

在某些情况下，输入可以被完全重写，而不会使转换的增量性失效。例如，假设您有一个简单的参考数据集，该数据集将电话号码的国家/地区代码映射到相应的国家/地区，并且会定期重写。对该数据集的更改不一定会使任何先前计算的结果失效，因此不应阻止以增量方式运行转换。

默认情况下，如上文所述，如果自转换上次运行以来有任何输入被完全重写，则无法以增量方式运行该转换。快照输入被排除在此检查之外，允许其起始事务在不同运行之间有所不同。

快照输入可以通过使用 snapshot_inputs 参数来配置，该参数位于 incremental() 装饰器上。

如果您的增量转换使用了 Cipher 资源 以及 bellaso_python_lib，这些加密器、解密器和哈希器需要列为快照输入。

@transform.spark.using(

    country_codes=Input('/examples/country_codes'),
    output=Output('/examples/phone_numbers_to_country')

无论转换以增量方式还是非增量方式运行，快照输入的行为都是相同的。因此， added 和 current 读取模式将始终返回整个数据集。所有其他读取模式将返回空数据集。

鉴于对快照输入的先前已见版本没有任何约束，因此可以在添加或移除快照输入的同时，保留以增量方式运行转换的能力。请记住，如果对输入的修改从根本上改变了转换的语义，则值得重新审查是否 semantic_version 上的参数 incremental() 应更新 decorator。

对输入的更改

可以修改现有输入的列表。在满足以下任一条件的情况下，增量性将得以保留：

  • 添加了新输入或新的快照输入。
  • 移除了现有输入或现有快照输入。

请注意，增量转换必须至少有一个输入。

每个非快照输入数据集的起始事务必须与上一次运行中使用的事务保持一致。

上次由同一转换构建的输出

对于 多输出增量转换，每个先前构建的输出的最后一次已提交事务必须由同一转换生成。

没有先前构建历史的输出将不受上述条件限制，并且不会阻止构建以增量方式运行。

转换的输入和输出数据集必须不同

数据转换接受一个输入数据集，执行操作，并生成一个输出数据集。转换的输入数据集和输出数据集必须不同。将同一数据集同时用作输入和输出会导致循环（环形）依赖，从而使转换无法执行。

增量计算要求摘要

当且仅当转换的所有增量输入仅追加了文件时，转换才能以增量方式运行；在文件被删除的情况下，这些文件是使用保留策略配合 allow_retention=True 或超出保留期且带有 allow_user_deletes=True。快照输入不包含在此检查中。
