单元测试

Java Transforms 支持在 CI 检查中运行单元测试。本页所述的 Java 单元测试仅适用于批处理管道，不支持流式管道。Java Transforms 目前不支持交互式单元测试或调试；如果您的用例需要此功能，请考虑使用 创建更复杂的管道。 来替代。

默认情况下，当您将 com.palantir.transforms.lang.java-defaults 插件应用于您的 Java 转换子项目时，单元测试环境即已设置完成。它会添加常用的 Java 单元测试库 JUnit ↗, Mockito ↗ 和 AssertJ ↗ 到子项目的 testCompile 配置中。 您应将测试文件放在 src/test/java 目录下，以便 Gradle 自动识别它们。具体步骤请参见 Python 测试 ，了解有关如何向您的环境添加插件的更多详细信息。

使用 Spark 进行测试

我们提供了 JUnit5 扩展和 JUnit4 规则，帮助您轻松访问托管的 SparkSession.

如果您使用的是 JUnit5，可以像声明任何常规扩展一样声明该扩展：

import com.palantir.transforms.lang.java.testing.api.SparkSessionExtension;
import org.junit.jupiter.api.extension.RegisterExtension;

@RegisterExtension
public static SparkSessionExtension sparkSession = new SparkSessionExtension();

在 JUnit4 中， ClassRule 和 Rule 有所不同：如果您声明 SparkSession 作为 ClassRule，同一个 SparkSession 将在测试类中的所有测试之间共享。这样可以节省重新创建 SparkSession, 的一些时间，但类路径会从先前运行的测试中继承。 相反，如果您声明 SparkSession 作为 Rule，每个单独的测试都会获得一个新的隔离的 SparkSession 。如果在一个类中有许多测试使用 SparkSession ，这可能会导致显著的性能下降。

优先使用 ClassRule 或 JUnit5 扩展，而非 Rule

如果在一个类中有大量测试使用 SparkSession 作为 Rule ，声明 SparkSession 可能会导致显著的性能下降。因此，我们强烈建议尽可能使用 ClassRule ，或使用 JUnit5 的 Extension 而不是 JUnit4 规则。
