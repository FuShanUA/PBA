创建对象类型

创建和配置新对象类型的主要方式是使用 分步引导式帮助程序。引导式帮助程序是推荐的方法，但如果您在完成对象创建过程之前退出帮助程序，也可以 手动 完成该过程：为新对象类型指定元数据、支撑数据源、属性映射以及键（主键和标题键）。如果您打算使用 操作 来填充每个属性，则可以改为 创建不带支撑数据源的对象类型。

创建新对象类型后，您可以 更改 API 名称 ，使其不再使用默认分配的名称。

本页还包含 故障排除 信息，涉及新对象类型创建过程。

如果您希望以编程方式创建对象类型，请使用 SuperRepo。SuperRepo 使用 本体论即代码（Ontology-as-code）在代码中定义对象类型，而在 Ontology Manager 中创建的对象类型可以 导入 到 SuperRepo 中。

创建新对象类型

要创建新对象类型，请选择 创建您的第一个对象类型 选项（位于 Ontology Manager 主页上），或选择 新建 > 创建对象类型 （位于同一页面右上角）。

该 创建新对象类型 辅助工具将会出现。

选择支撑数据源

如果您在 Foundry 中已有包含可用于支撑该对象类型的数据的现有数据源，则可以选择它。这将自动填充该对象类型的元数据。它还会将支撑数据源的每一列映射到一个属性，但您可以在 属性 步骤中丢弃已添加的属性。

警告

对象类型的支撑数据源不得包含 MapType 或 StructType 列。

如果您没有包含该对象类型数据的现有数据源，可以选择在不使用现有数据源的情况下继续，并选择一个位置来生成用于权限的数据集。如果您使用的是 Object Storage v1，则此选项不可用。由于数据源支撑类型的对象权限由其支撑数据源的位置决定，系统将提示您选择一个用于保存空数据集的位置。

创建不带支撑数据源的对象类型

如果您将使用操作来填充每个属性，则可以在不生成空支撑数据集的情况下创建对象类型。

在 数据源 步骤中，选择在不使用支撑数据源的情况下继续。该助手要求您：

  • 将对象类型保存到项目中，以便其使用 基于项目的权限模型。
  • 配置 对象安全策略 以确定谁可以查看通过操作创建的对象。

按照下文所述完成助手的其余步骤。每个对象类型仍需要主键，且通过操作创建的每个对象必须具有唯一的主键值。

对象类型元数据

在此步骤中，提供有关新对象类型的以下信息：

  • 图标： 选择默认图标以自定义对象类型的图标和颜色；当用户查看此类型的对象时，该图标和颜色将显示在用户应用程序中。
  • 名称： 在用户应用程序中访问此类型对象的所有人看到的名称。
  • 复数名称： 在用户应用程序中访问此类型的多个对象的所有人看到的名称。
  • 描述： 为在用户应用程序中访问此类型对象的任何人提供的说明文本。例如，在 Object Explorer 中搜索的用户将在其搜索结果中看到该对象类型的描述。
  • 组： 选择此对象类型是否将成为任何组的一部分。这是一种组织本体论的机制，可让您更轻松地筛选稍后要使用的对象类型。

为对象类型创建属性

在对话框的第三步中，您可以自定义对象类型将具有哪些属性。如果您选择了现有的 Foundry 数据源，各列将自动映射，但可以在此步骤中将其舍弃。

每个对象类型至少需要一个属性。这是因为对象类型需要主键来唯一标识它们。该向导允许您添加任何其他所需的属性。

请注意，需要高级配置的属性类型（例如媒体）无法作为引导向导的一部分生成，必须在退出向导后添加。

配置主键和标题键

作为 属性 步骤的一部分，您需要选择主键和标题键：

  • 标题键： 用作此类对象显示名称的属性。
    • 例如，选择 full name 属性作为 Employee 对象类型的标题键后，将使用该属性的值（如“Melissa Chang”、“Akriti Patel”或“Diego Rodriguez”）作为每个相应的虚拟 Employee 对象的显示名称。
  • 主键： 用作对象类型每个实例唯一标识符的属性。每个对象的该属性值都必须唯一。对于数据源支撑的对象类型，支撑数据源中的每一行都必须具有不同的值。
    • 例如， employee ID 属性的值将用于把“Melissa Chang”标识为组织内的唯一员工。

受支持的属性类型列表可在 对象类型属性文档中找到。

在分配主键之前，请务必检查支撑数据源中是否存在重复项。您选择的主键必须对数据源中的每条记录都是唯一的。如果您的本体论使用的是 Object Storage v2，重复的主键将导致 Funnel 批处理管道 错误，进而导致构建失败。如果您使用的是 Object Storage v1 (Phonograph)，更新将显示为成功；但是，重复的主键可能会导致您的本体论发生意外变更。

除了唯一性之外，主键还应具有确定性。如果主键是非确定性的并在构建时发生更改，则编辑可能会丢失，关联也可能会消失。编辑可能会丢失，因为本体论中的编辑与对象的主键相关联；而如果构建之间未协调更新关联 ID，则对象之间的关联可能会消失。为了确保主键具有确定性，您应该定义管道逻辑，使主键成为单列或多列的函数。避免使用行编号或随机键生成，因为这些方式可能导致主键在不同构建运行之间发生变化。

生成操作

您可以选择生成一组标准操作来编辑此类型的对象，并指派可以运行这些操作的特定用户或组。

请注意，即使您已最终确定对象类型并退出助手，您仍然可以编辑这些操作或创建新的附加操作。

如果您使用的是 Object Storage v1，则此步骤不可用。

保存位置

选择用于保存此对象类型的项目。然后，选择 创建。选择 创建 只会暂存您的更改，而 不会保存 它们。

配置安全策略

仅当您创建的对象类型 没有支撑数据源时，才需要执行此步骤。数据源支撑类型的对象会从支撑数据源所在的位置继承权限，因此无需配置策略。

配置 对象安全策略 以确定谁可以查看此类型的对象。请查阅 对象和属性安全策略配置文档 以了解如何设置并 测试 授予您所期望访问权限的策略。

将更改保存到本体论

返回本体论管理器后，选择右上角的 保存 ，以 将更改应用到您的本体论。

手动创建新的对象类型

使用助手创建新的对象类型时，可以先选择 创建 ，而无需完成上述 创建新的对象类型 助手说明中的所有步骤。 如果在流程完成之前选择 创建 ，将会退出助手并将您带到 概览 页面。

此时，对象类型尚未保存，在完成以下所有步骤之前无法保存。手动完成创建过程的步骤（在 创建新的对象类型 助手之外）如下所述：

  • 为新的对象类型添加元数据
  • 为新的对象类型添加支撑数据源
  • 添加新属性
  • 将单个属性映射到数据
  • 将所有未映射的列映射为新属性
  • 配置主键和标题键

为新的对象类型添加元数据

在 概览 页面的元数据部分中，您可以编辑对象类型的显示名称、复数显示名称、描述和 ID：

  1. 显示名称： 在用户应用程序中访问此类型对象的任何用户所看到的名称。
  2. 复数显示名称： 在用户应用程序中访问此类型多个对象的任何用户所看到的名称。
  3. 别名： 用户搜索时可用于查找此对象类型的其他词语。
  4. 描述： 供在用户应用中访问此类型对象的任何人查看的说明性文字。例如，用户在 Object Explorer 中搜索时，将在搜索结果中看到该对象类型的描述。
  5. 分组： 一个或多个有助于对此对象类型进行分类的标签。
  6. ID： 对象类型的唯一标识符，主要用于在配置用户应用时引用此类型的对象。
    • ID 可包含小写字母、数字和连字符。
    • ID 的第一个字符 必须 为小写字母。
    • 一旦属性的 ID 已保存且该属性已在用户应用中被引用， 任何 对属性 ID 的更改都会导致应用程序无法正常运行。
  7. 图标： 在对象类型视图的侧边栏中选择默认图标，以自定义对象类型的图标和颜色；当用户查看此类型的对象时，该图标和颜色将显示在用户应用中。
  8. 支撑数据源： 用作此类型对象属性值的数据来源。创建时未设置支撑数据源的对象类型不会显示此字段的值。

向对象类型添加分组

组 是有助于对对象类型进行分类的标签。在对象类型元数据小部件中，您可以：

  • 从现有组列表中添加组。
  • 通过输入该组的名称来创建新组。
  • 从对象类型中移除组。

组可在 本体论管理器的 搜索 栏和 搜索 栏对话框中进行搜索。本体论管理器中的对象类型表格支持按组显示和筛选。组也会显示在 对象浏览器主页。

警告

对象类型元数据中用作标签的组取代了此前向主键属性添加 oe_home_page_object_type_group 类型类的方法；此前的这种方法已不再可用。

为新的对象类型添加支撑数据源

为了用数据填充此类型对象的属性值，您必须添加支撑数据源。您可以通过以下方式完成此操作：

  • 通过选择 新建 进入属性编辑器，该选项位于 属性 部分（ 概览 页面）；或者通过选择 编辑属性映射 按钮，该按钮位于 属性 页面（在对象类型视图的侧边栏中）。
  • 然后，选择 添加支撑数据源 按钮（如下图所示）。这将允许您选择 Foundry 中的任何可用数据源作为支撑数据源。
    • 请注意，单个数据源只能用于支撑一个对象类型。

添加新属性

在属性编辑器中，选择 添加 在 属性 窗格（位于屏幕右侧）中。这将为该对象类型添加一个新属性。

将单个属性映射到数据

可以通过以下任一方式将属性映射到支撑数据源中的列：

  • 将列映射到新属性
  • 将列映射到现有属性
  • 将属性映射到列

将列映射到新属性

在屏幕左侧的数据源窗格中（见下图），您可以看到该数据源的所有列。将鼠标悬停在要映射的列上，然后选择 添加为新属性 按钮，以创建映射到该列的新属性。属性 ID、显示名称和基本类型将从列名称中推断得出。

将列映射到现有属性

在屏幕左侧的数据源窗格中，您可以查看数据源的所有列。将鼠标悬停在未映射的列上，然后选择 添加为新属性 按钮。如果已存在属性 ID 与列名匹配的属性，则该列将被映射到现有属性。

将属性映射到列

在屏幕右侧的属性窗格中，将鼠标悬停在您想要映射到列的属性上，然后选择 映射到列。这将打开一个下拉菜单，您可以从中选择要映射到该属性的列。

将所有未映射的列映射为新属性

在数据源窗格中的数据源名称旁边，您会看到一个 将所有未映射的列添加为新属性 按钮。选择该按钮将为数据源中的所有未映射列创建属性。这些属性的 ID、显示名称和基础类型将根据数据源中相应的列推断得出。

  • 一旦属性 ID 已保存且该属性已在用户应用程序中被引用， 任何 对属性 ID 的更改都将导致应用程序无法正常运行。

配置主键和标题键

现在，您已经创建了新的对象类型、添加了支撑数据源并将其映射到新属性，但在保存对象类型之前，您仍需配置主键和标题键。您可以导航到属性编辑器中的属性元数据面板（见下图），将某个属性设置为主键和标题键：

  • 主键： 用作对象类型每个实例唯一标识符的属性。每个对象在该属性上的值都必须唯一。对于由数据源支撑的对象类型，支撑数据源中的每一行都必须具有不同的值。
    • 例如， employee ID 属性的值将用于把“Melissa Chang”标识为组织内一名唯一（虚构）的员工。
    • 要配置主键，请在属性编辑器的属性面板中选择您想要指定为主键的属性，然后勾选 主键 选项。
    • 编辑会永久附加到您为其进行编辑的主键值上。每当您更改对象类型的主键时，系统都会提示您删除所有现有的编辑。
  • 标题键： 用作此类型对象显示名称的属性。
    • 例如，选择 full name 属性作为 Employee 对象类型的标题键后，将使用该属性的值（例如 “Melissa Chang”、“Akriti Patel” 或 “Diego Rodriguez”）作为每个相应概念 Employee 对象的显示名称。
    • 要配置标题键，请在属性编辑器的属性窗格中选择要分配给标题键的属性，并勾选 标题键 选项。 请注意，到目前为止，您的更改已暂存，但 尚未保存。要将新对象类型保存到本体论，请参阅 如何将更改保存到本体论。

在分配主键之前，请务必检查您的支撑数据源中是否存在重复项，并使用确定性主键。请参阅 主键和唯一性 ，以了解 Object Storage v2 在索引期间强制执行的限制。

配置 API 名称

API 名称是在代码中以编程方式引用对象类型或属性时使用的名称。所有新的对象类型和属性都会自动获得根据其显示名称推断出的 API 名称。 了解更多关于 API 名称的信息。

您可以按以下方式更改自动分配的 API 名称：

  • 对象类型的 API 名称可以在对象类型的 概览 页面中进行编辑。
  • 属性的 API 名称可以在属性编辑器的属性窗格中进行编辑。

命名指南

对象类型 API 名称遵循功能编码标准。对象类型的 API 名称必须：

  • 以大写字符开头，且仅包含字母数字字符。
  • 采用 PascalCase（也称为 UpperCamelCase，即复合词中每个单词的首字母大写；例如“ThisExampleName”）格式书写。
  • 在所有对象类型中保持唯一。
  • 长度在 1 到 100 个字符之间。

属性的 API 名称必须：

  • 以小写字符开头，且仅包含字母数字字符。
  • 采用 camelCase（即复合词中第一个单词之后的每个单词的首字母大写；例如“thisExampleName”）格式书写。
  • 在属于同一对象类型的所有属性中保持唯一。
  • 长度在 1 到 100 个字符之间。

故障排除

必填的对象类型字段

要保存新的对象类型，以下对象类型字段不能为空：

  • ID
  • 显示名称
  • 复数显示名称
  • 支撑数据源，除非您创建的对象类型不使用数据源
  • API 名称

此外，以下属性字段不得为空：

  • 属性 ID
  • 属性显示名称
  • 支撑列，除非该属性仅通过操作填充
  • 属性 API 名称
  • 标题键
  • 主键

有效 ID 检查清单

对象类型 ID

对象类型 ID：

  • 可由小写字母、数字和短横线组成。
  • 应以字母开头。
  • 必须在所有对象类型中保持唯一。

属性类型 ID

属性类型 ID：

  • 可由小写或大写字母、数字、短横线和下划线组成。
  • 应以字母开头。
  • 必须在属于同一对象类型的所有属性中保持唯一。

API 名称

为符合功能编码规范，对象类型的 API 名称必须：

  • 仅由字母数字字符和下划线组成。
  • 在所有对象类型中保持唯一。
  • 长度介于 1 到 100 个字符之间。

属性的 API 名称必须：

  • 为有效的 Unicode。
  • 在属于同一对象类型的所有属性中保持唯一。
  • 长度介于 1 到 100 个字符之间。

请注意，有一些保留关键字不能用作 API 名称。它们是： ontology、 object、 property、 link、 relation、 rid、 primaryKey、 typeId，以及 ontologyObject。

错误

错误： Phonograph2:DatasetAndBranchAlreadyRegistered

如果您收到错误 Phonograph2:DatasetAndBranchAlreadyRegistered，您尝试保存的对象类型的支撑数据源已支撑本体论中的另一个对象类型，无法再次使用。
