创建新对象类型

要创建新对象类型，请选择 创建您的第一个对象类型 Ontology Manager 主页上的选项，或选择 New > Create object type 位于同一页面右上角。

直方图 创建新对象类型 助手将会出现。

选择支撑数据源

如果您在 Foundry 中有一个包含用于支撑该对象类型的数据的现有数据源，则可以选择它。这将自动填充对象类型的元数据。它还会将支撑数据源的每一列映射到一个属性，但您可以在 属性 步骤中丢弃已添加的属性。

对象类型的支撑数据源不得包含 MapType or StructType 列。

如果您没有包含该对象类型数据的现有数据源，可以选择在没有现有数据源的情况下继续，并选择一个位置来生成用于权限的数据集。如果您使用的是 Object Storage v1，则此选项不可用。由于由数据源支撑的类型其对象的权限由其支撑数据源的位置决定，系统将提示您选择一个要保存空数据集的位置。

创建没有支撑数据源的对象类型

如果您将使用操作来填充每个属性，则可以创建一个不生成空支撑数据集的对象类型。

在监听器设置向导的 数据源 步骤中，选择在没有支撑数据源的情况下继续。该助手要求您：

  • 将对象类型保存在项目中，以便其使用 基于项目的权限模型.
  • 配置一个 对象安全策略 来确定谁可以查看通过操作创建的对象。

按照下文所述完成助手的其余步骤。每个对象类型仍需要一个主键，并且通过操作创建的每个对象必须具有唯一的主键值。

在此步骤中，请提供有关您的新对象类型的以下信息：

  • 图标： 选择默认图标以自定义对象类型的图标和颜色；当用户在用户应用程序中查看该类型的对象时，将显示此图标和颜色。
  • 名称： 在用户应用程序中访问该类型对象的任何人所看到的名称。
  • 复数名称： 在用户应用程序中访问该类型多个对象的任何人所看到的名称。
  • 描述： 在用户应用程序中访问该类型对象的任何人所看到的说明文字。例如，在 Object Explorer 中搜索的用户将在其搜索结果中看到该对象类型的描述。
  • 分组： 选择此对象类型是否属于任何分组。这是一种组织本体论的机制，便于您稍后筛选要使用的对象类型。

为对象类型创建属性

在对话框的第三步中，您可以自定义对象类型将具有哪些属性。如果您选择了现有的 Foundry 数据源，任何列都将被自动映射，但可以在此步骤中被舍弃。

每个对象类型至少需要一个属性。这是因为对象类型需要主键来唯一标识它们。向导允许您添加任何其他所需的属性。

需要高级配置的属性类型（例如媒体）无法作为引导向导的一部分生成，必须在退出向导后添加。

配置主键和标题键

作为 属性 步骤的一部分，您需要选择主键和标题键：

  • 标题键： 用作此类型对象显示名称的属性。
    • 例如，选择 full name 属性作为 Employee 对象类型的标题键，将使用该属性的值（例如“Melissa Chang”、“Akriti Patel”或“Diego Rodriguez”）作为各自概念 Employee object.
  • 主键： 用作对象类型每个实例唯一标识符的属性。每个对象在该属性上必须具有唯一的值。对于由数据源支撑的对象类型，支撑数据源中的每一行必须具有不同的值。
    • 例如， employee ID 属性的值将用于将“Melissa Chang”标识为组织内的一名唯一员工。

支持的属性类型列表可在 对象类型属性文档.

中找到。在分配主键之前，请务必检查支撑数据源中是否存在重复项。您选择的主键必须在数据源中的每条记录中唯一。如果您的本体论使用的是 对象存储 v2，重复的主键将导致 Funnel 批处理管道 错误，从而导致构建失败。如果您使用的是 Object Storage v1（Phonograph），更新将显示为成功；但是，重复的主键可能会导致本体论发生意外更改。

除了唯一性之外，主键还应是确定性的。如果主键是非确定性的并在构建时发生变化，编辑可能会丢失，关联也可能消失。编辑可能丢失是因为本体论编辑与对象的主键相关联，而如果构建未协调更新关联 ID，对象之间的关联可能会消失。为确保主键的确定性，您应定义管道逻辑，使主键是单个列或多个列的函数。避免使用编号行或随机键生成，因为这些会导致主键在构建运行之间发生变化。

生成操作

您可以选择生成一组标准操作来编辑此类型的对象，并指定可以运行这些操作的特定用户或分组。

即使您已最终确定对象类型并退出了助手，您仍然可以对这些操作进行编辑或创建新的附加操作。

如果您使用的是 Object Storage v1，则此步骤不可用。

保存位置

选择一个项目来保存此对象类型。然后，选择 创建新建画布 创建 只会暂存您的更改，而 不会保存 它们。

配置安全策略

仅当您创建的对象类型 没有支撑数据源时，才需要此步骤。由数据源支撑的类型会从支撑数据源的位置继承权限，因此无需配置策略。

配置一个 对象安全策略 ，以确定谁可以查看此类型的对象。请查阅 对象和属性安全策略配置文档 ，了解如何设置和 测试 一个授予您所期望访问权限的策略。

将更改保存到本体论

回到 Ontology Manager，选择 保存 右上角的按钮以 将更改应用到您的本体论.

手动创建新的对象类型

使用助手创建新对象类型时，可以选择 创建 在完成 创建新对象类型 助手说明 中的所有步骤之前。选择 创建 在流程完成之前退出助手并进入 概述 页面预览同步的数据。

此时，对象类型尚未保存，并且在完成以下所有步骤之前无法保存。手动完成创建流程（在 创建新对象类型 助手之外）的步骤如下所述：

  • 为新对象类型添加元数据
  • 为新对象类型添加支撑数据源
  • 添加新属性
  • 将单个属性映射到数据
  • 将所有未映射的列映射为新属性
  • 配置主键和标题键

为新对象类型添加元数据

在 概述 页面的元数据部分，您可以编辑对象类型的显示名称、复数显示名称、描述和 ID：

  1. 显示名称： 在用户应用程序中访问该类型对象的任何人所看到的名称。
  2. 复数显示名称： 在用户应用程序中访问该类型多个对象的任何人所看到的名称。
  3. 别名： 用户搜索这些附加词条时可以找到此对象类型。
  4. 描述： 在用户应用程序中访问该类型对象的任何人所看到的说明文字。例如，在 Object Explorer 中搜索的用户将在其搜索结果中看到该对象类型的描述。
  5. 分组： 一个或多个帮助对对象类型进行分类的标签。
  6. ID： 对象类型的唯一标识符，主要用于在配置用户应用程序时引用此类型的对象。
    • ID 可以包含小写字母、数字和连字符。
    • ID 的第一个字符 必须 必须是小写字母。
    • 一旦属性的 ID 已保存且该属性在用户应用程序中被引用， 任意 更改属性 ID 将导致应用程序出错。
  7. 图标： 从对象类型视图的侧边栏中选择默认图标，以自定义对象类型的图标和颜色；当用户查看此类型的对象时，该图标和颜色将显示在用户应用程序中。
  8. 支撑数据源： 用作此类型对象属性值的数据来源。创建时未指定支撑数据源的对象类型不会显示此字段的值。

向对象类型添加分组

组 是帮助对对象类型进行分类的标签。在对象类型元数据小部件中，您可以：

  • 从现有分组列表中添加分组。
  • 通过输入分组名称来创建新分组。
  • 从您的对象类型中移除分组。

分组可在 本体论管理器的 搜索 栏和 搜索 栏对话框中搜索中搜索。Ontology Manager 中的对象类型表支持按分组显示和筛选。分组也会显示在 对象浏览器主页.

对象类型元数据中作为标签的分组取代了之前向主键属性添加 oe_home_page_object_type_group 类型类别的做法；此前的这种方法已不再可用。

添加新属性

在属性编辑器中，选择 将 菜单中选择 属性 屏幕右侧的面板。这将为对象类型添加一个新属性。

将单个属性映射到数据

可以通过以下任一方式将属性映射到支撑数据源中的列：

  • 将列映射到新属性
  • 将列映射到现有属性
  • 将属性映射到列

将列映射到新属性

在屏幕左侧的数据源面板中（见下图），您可以查看数据源的所有列。将鼠标悬停在您想要映射的列上，然后选择 添加为新属性 按钮，以创建映射到该列的新属性。属性 ID、显示名称和基础类型将根据列名自动推断。

将列映射到现有属性

在屏幕左侧的数据源面板中，您可以查看数据源的所有列。将鼠标悬停在未映射的列上，然后选择 添加为新属性 按钮。如果已存在属性 ID 与该列名匹配的属性，则该列将映射到现有属性。

将属性映射到列

在屏幕右侧的属性面板中，将鼠标悬停在您想要映射到某列的属性上，然后选择 映射到列。这将打开一个下拉菜单，您可以从中选择要映射到您的属性的列。

将所有未映射的列映射为新属性

在数据源面板中数据源名称的旁边，您会找到一个 将所有未映射的列添加为新属性 按钮。选择该按钮将为数据源中所有未映射的列创建属性。这些属性的 ID、显示名称和基础类型将根据数据源中相应的列自动推断。

  • 一旦属性的 ID 已保存且该属性在用户应用程序中被引用， 任意 更改属性 ID 将导致应用程序出错。

配置主键和标题键

现在您已经创建了新的对象类型、添加了支撑数据源并将其映射到新属性，在保存对象类型之前，您还需要配置主键和标题键。您可以在属性编辑器的属性元数据面板中（见下图）将某个属性设置为主键和标题键：

  • 主键： 用作对象类型每个实例唯一标识符的属性。每个对象在该属性上必须具有唯一的值。对于由数据源支撑的对象类型，支撑数据源中的每一行必须具有不同的值。
    • 例如， employee ID 属性将用于将“Melissa Chang”标识为组织内唯一的（概念上的）员工。
    • 要配置主键，请在属性编辑器的属性面板中选择您想要指定为主键的属性，然后勾选 主键 option.
    • 编辑将永久附加到您为其创建编辑的主键值上。每当您更改对象类型的主键时，系统都会提示您删除所有现有的编辑。
  • 标题键： 用作此类型对象显示名称的属性。
    • 例如，选择 full name 属性作为 Employee 对象类型将使用该属性的值（例如“Melissa Chang”、“Akriti Patel”或“Diego Rodriguez”）作为每个相应概念 Employee object.
    • 要配置标题键，请在属性编辑器的属性面板中选择您想要指定为标题键的属性，然后勾选 标题键 选项。 到目前为止，您的更改已暂存，但 尚未保存。要将新对象类型保存到本体论，请按照以下说明操作： 如何将更改保存到本体论.

在指定主键之前，请务必检查支撑数据源中是否存在重复项，并使用确定性的主键。请查看 主键与唯一性 以了解 Object Storage v2 在索引期间强制执行的限制。

配置 API 名称

API 名称是在代码中以编程方式引用对象类型或属性时使用的名称。所有新的对象类型和属性都会自动分配根据其显示名称推断出的 API 名称。 了解更多关于 API 名称的信息（TSv1）。

您可以按以下方式更改自动分配的 API 名称：

  • 对象类型的 API 名称可以在该对象类型的 概述 page.
  • 属性的 API 名称可以在属性编辑器的属性面板中进行编辑。

命名指南

对象类型 API 名称遵循功能性编码标准。对象类型的 API 名称必须：

  • 以大写字符开头，且仅由字母数字字符组成。
  • 采用 PascalCase（也称为 UpperCamelCase，即复合词中每个单词的首字母大写；例如 “ThisExampleName”）编写。
  • 在所有对象类型中唯一。
  • 长度介于 1 到 100 个字符之间。

属性的 API 名称必须：

  • 以小写字符开头，且仅包含字母数字字符。
  • 采用 camelCase（即复合词中第一个单词之后的每个单词的首字母大写；例如 “thisExampleName”）编写。
  • 在同一对象类型的所有属性中唯一。
  • 长度介于 1 到 100 个字符之间。

故障排除

必填的对象类型字段

要保存新的对象类型，以下对象类型字段不能为空：

  • ID
  • 显示名称
  • 复数显示名称
  • 支撑数据源，除非您创建的对象类型不使用数据源
  • API 名称

此外，以下属性字段不能为空：

  • 属性 ID
  • 属性显示名称
  • 支撑列，除非该属性仅通过操作填充
  • 属性 API 名称
  • 标题键
  • 主键

有效 ID 检查清单

对象类型 ID

对象类型 ID：

  • 可以由小写字母、数字和短横线组成。
  • 应以字母开头。
  • 必须在所有对象类型中唯一。

属性类型 ID

属性类型 ID：

  • 可以由小写或大写字母、数字、短横线和下划线组成。
  • 应以字母开头。
  • 必须在属于同一对象类型的所有属性中唯一。

API 名称

根据函数式编码标准，对象类型的 API 名称必须：

  • 仅包含字母数字字符和下划线。
  • 在所有对象类型中唯一。
  • 长度介于 1 到 100 个字符之间。

属性的 API 名称必须：

  • 必须是有效的 Unicode。
  • 在同一对象类型的所有属性中唯一。
  • 长度介于 1 到 100 个字符之间。

许多保留关键字不能用作 API 名称： ontology, object, property, link, relation, rid, primaryKey, typeId日 ontologyObject.

错误

错误： Phonograph2:DatasetAndBranchAlreadyRegistered

如果您收到错误 Phonograph2:DatasetAndBranchAlreadyRegistered，您尝试保存的对象类型所使用的支撑数据源已经在本体论中支撑另一个对象类型，因此不能再次使用。
