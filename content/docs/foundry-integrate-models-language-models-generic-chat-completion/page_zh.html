在转换中通过 Python 进行通用聊天补全

用途 GenericChatCompletionRequest ，使用 GenericChatCompletionLanguageModel 通过通用 API 将文本对话发送给语言模型。模型输入用于选择模型，请求中包含消息和生成参数。

本页面记录了以下 Python 类： palantir_models 和 language-model-service-api。有关仓库设置和模型选择，请参阅 在转换中使用语言模型.

示例

将 palantir_models 添加到你的仓库。将 <model-rid> 替换为你可访问的模型的完整资源标识符，并替换输出数据集路径。此示例使用一个 轻量级转换.

import pandas as pd
from language_model_service_api.languagemodelservice_api_completion_v3 import (
    DialogChatMessage,
    DialogRole,
    GenericChatCompletionRequest,
)
from palantir_models.models import GenericChatCompletionLanguageModel
from palantir_models.transforms import GenericChatCompletionLanguageModelInput
from transforms.api import Output, transform


@transform.using(
    model=GenericChatCompletionLanguageModelInput("<model-rid>"),
    output=Output("/path/to/output/dataset"),
)
def compute(model: GenericChatCompletionLanguageModel, output):
    request = GenericChatCompletionRequest(
        messages=[
            DialogChatMessage(
                role=DialogRole.SYSTEM,
                content="Answer questions in one sentence.",
            ),
            DialogChatMessage(
                role=DialogRole.USER,
                content="Why is the sky blue?",
            ),
        ],
        max_tokens=256,
    )
    response = model.create_chat_completion(request)
    output.write_table(pd.DataFrame({"completion": [response.completion]}))

GenericChatCompletionLanguageModelInput 向计算函数提供一个 GenericChatCompletionLanguageModel 。相同的模型输入和请求类型也可以在 Spark 转换中使用，配合 @transform(...).

GenericChatCompletionRequest

导入 GenericChatCompletionRequest （来自 language_model_service_api.languagemodelservice_api_completion_v3.

Python 参数类型必需描述
messageslist[DialogChatMessage]是要按顺序发送给模型的对话。请参阅 消息结构.
temperaturefloatNo在受支持的情况下控制采样随机性。支持的值和行为取决于所选模型。
stop_sequenceslist[str]No在模型支持的情况下，遇到这些序列时停止生成。
max_tokensintNo为此请求生成的最大输出 token 数量。这不包括输入 token，并受所选模型的限制约束。

可选参数可以省略。并非所有模型都有一套统一的默认值或支持的参数值；服务和所选模型决定了省略参数时的行为。从必需的消息开始，仅添加你的模型支持的参数。

Python 名称为 stop_sequences 和 max_tokens。在序列化请求中，这些字段命名为 stopSequences 和 maxTokens.

此请求支持文本消息和上面列出的生成参数。它不定义图像输入、工具调用或结构化输出 schema。

消息结构

导入 DialogChatMessage 和 DialogRole 来自与以下相同的模块： GenericChatCompletionRequest.

字段类型描述
roleDialogRoleDialogRole.SYSTEM, DialogRole.USER，或 DialogRole.ASSISTANT.
contentstr消息的文本。

构建对话时请遵循以下规则：

  • 以一个 SYSTEM or USER message.
  • 用途 SYSTEM 开头（仅在需要时作为第一条消息）。
  • 在一个 SYSTEM 消息之后跟一个 USER message.
  • 在可选的系统消息之后交替使用 USER and ASSISTANT 消息。

例如，包含历史记录的对话可以有以下角色： SYSTEM, USER, ASSISTANT, USER。当你希望模型将之前的轮次用作上下文时，请将它们包含在 messages 中。

GenericChatCompletionResponse

model.create_chat_completion(request) 返回一个 GenericChatCompletionResponse 包含以下字段：

Python 属性类型描述
completionstr生成的文本。读取此字段以获取答案。
token_usageTokenUsageToken 计数和模型的上下文窗口限制。

Token 使用对象公开了 prompt_tokens （输入 token）、 completion_tokens （输出 token）以及 max_tokens （模型的上下文窗口，包括输入和输出 token）。 response.token_usage.max_tokens 的含义与请求中的 max_tokens 输出限制不同。

此响应有一个 completion 字段，而不是 choices 所使用的 GptChatCompletionResponse.

模型选择与自定义模型

在以下位置设置模型 RID： GenericChatCompletionLanguageModelInput. GenericChatCompletionRequest 没有模型或提供商字段。

折线图 已注册模型，请使用其完整 ri.language-model-service..registered-model.<id> RID。Python 客户端使用该标识符调用已注册的模型。注册和配置模型决定了哪个模型端点处理该请求。

在调查自定义模型集成时：

  • 确认输入使用了预期的模型 RID，并且你有权访问该模型。
  • 确认消息角色、顺序和内容遵循上述请求结构。
  • 检查所选模型对每个可选参数的支持情况。通用的请求类型并不能保证每个模型的行为完全相同。
  • 从以下位置读取生成的答案： response.completion.

有关将自托管或外部模型连接到 AIP 的指导，请参阅 将你自己的模型接入 AIP.
