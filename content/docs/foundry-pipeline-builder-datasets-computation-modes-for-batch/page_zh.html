批量输入数据集的计算模式

您可以根据您的使用场景，选择以快照或增量方式读取输入数据集。

快照计算

快照计算会对整个输入执行转换，而不仅仅是新添加的数据。每次构建时，输出数据集都会被最新的管道输出完全替换。

最适用于以下情况：

  • 输入数据集未通过 APPEND transactions.
    • 当输入使用 SNAPSHOT 事务写入时，无法以增量方式读取输入。
  • 输出数据集无法通过 APPEND transactions.
    • 示例：每次运行时整个输出数据集都可能发生变化，需要快照输出。
  • 输入数据集较小。
    • 在这种情况下，快照计算与增量计算的效率相近。

增量计算

增量计算仅对自上次构建以来追加到所选输入的新数据执行转换。这可以减少计算资源，但存在一些重要的 限制.

只有当所选输入数据集通过 APPEND or UPDATE 不修改现有文件的事务进行更改时，管道才会以增量计算方式运行。将快照输入标记为增量不会产生任何效果。

最适用于以下情况：

  • 输入数据集通过 APPEND 事务或附加 UPDATE transactions.
    • 这表示在添加新数据时，先前的输出保持不变。增量计算减少了每次构建时处理的数据量。
  • 您不需要引用先前的输出。
    • Pipeline Builder 目前不允许 read mode: previous。但是，某些输出写入模式支持此读取模式的常见使用场景。 了解有关 Pipeline Builder 中输出写入模式的更多信息。
  • 输入数据集较大且经常添加新数据。
    • 增量构建可以节省计算资源和时间，并带来性能上的优势。

增量计算限制

本节概述了可能适用于您工作流程的限制。在设置增量计算之前请先查看本节，以确保正确实施。

  • 连接（Join）： 对于涉及增量数据集的连接，增量数据集必须位于连接的左侧，而快照数据集位于右侧。也支持两个增量数据集之间的连接。
    • 连接中的快照输入： 如果快照输入接收到新事务，任何同样涉及增量数据集的下游连接将继续以增量方式运行。Pipeline Builder 不支持使用连接右侧快照输入的变更来强制重新运行管道。
  • 合并（Union）： 合并的所有输入必须使用相同的计算模式（全部为快照或全部为增量）。
  • 转换： 可能更改先前输出的转换仅限于当前事务。窗口函数、聚合和数据透视仅应用于当前事务的数据，而不应用于先前的输出。
  • 重放（Replay）： 如果您的管道逻辑发生了变化，并且您希望将新逻辑应用于之前已处理的输入事务，可以选择在部署时进行重放。仅支持对整个输入进行重放。

强制增量执行

为确保您的管道始终以增量方式运行，您可以启用管道 Require incremental execution 设置中的 构建设置。启用后，配置为增量运行的作业在无法进行增量执行时将自动失败。这有助于防止意外的快照场景，例如意外被快照的输入，或因输出 schema 变更而强制进行的快照。
