入门

SAML 2.0（安全断言标记语言）↗ 是一种基于 XML 的数据格式，用于在以下两者之间交换身份验证和授权数据： 服务提供商 （通常缩写为 SP），例如 Foundry，以及 身份提供商 （IdP），例如 Azure AD 或 Okta。SAML 2.0 最常见的用例是 单点登录 （SSO）——通过 Web 浏览器进行。

概念

以下部分将讨论 Foundry 中常见的身份验证概念。

SAML 集成元数据

SAML 集成元数据（也称为服务提供商元数据）是需要传递给身份提供商的 Foundry 相关信息。这些信息包括：

  • 实体 ID： 供身份提供商识别 Foundry 的唯一 ID，采用 URN ↗ 格式 urn:uuid:[$UUID]。
  • 断言使用者服务（ACS）URL： 接受 SAML 响应消息以便基于断言建立会话的 Foundry 端点。
  • 单点登出 URL： 接受来自身份提供商的 SAML 单点登出请求的 Foundry 端点。
  • 证书： 用于对发送给身份提供商的 SAML 消息进行签名。

此信息被编码为一个自动生成的 XML 文件，客户可以将其整体复制并上传到身份提供商。此外，Control Panel 会将信息提取到单独的字段中，以便逐个复制。

身份提供商元数据

身份提供商元数据是有关身份提供商且需要传递给 Foundry 的信息。此信息包括身份提供商的实体 ID、单点登录（SSO）和单点登出 URL，以及证书。

身份提供商元数据被编码为 XML 文件，可以通过以下方式上传到 Control Panel：

  • Upload：从身份提供商处保存 XML 文件，并将其上传到 Control Panel。
  • Fetch：提供元数据发现 URI，Foundry 可以从中检索有关您的身份提供商的信息，包括您身份提供商的实体 ID、单点登录（SSO）、单点登出 URL（SLO）以及证书。您还需要配置网络出口策略，以使 Foundry 能够访问所提供的元数据发现 URI。

SAML 证书具有有效期，过期后用户可能会遇到登录问题。当与身份提供商关联的证书将在未来 30 天内到期时，会显示一个 警告横幅 将显示在 Control Panel 中。

电子邮件域

电子邮件域用于决定将哪些身份提供商集成作为登录选项呈现给用户。当用户在登录界面输入其电子邮件或用户名时,系统会测试所有已配置身份提供商集成的电子邮件域,并仅显示匹配的身份提供商集成。

电子邮件域可以是正则表达式,但通常采用简单形式 @example.com,后者会被自动转换为 .*@example\.com。使用 .* 即可将该身份提供商集成显示给所有用户。

请注意,电子邮件域的简单形式(@example.com)和正则表达式(.*@example\.com)默认均区分大小写。通过在正则表达式开头添加 (?i) 即可使电子邮件域不区分大小写。因此,简单形式 @example.com 的不区分大小写版本为 (?i).*@example\.com 或 (?i)@example\.com。

支持的主机

支持的主机用于:

  • 构建 SAML 集成元数据中的 ACS 和 Single Logout URL。
  • 确保该集成仅显示给使用这些主机登录的用户。

您可以从为您的注册配置的主机中进行选择。

映射属性

将 SAML 响应映射到 Foundry,以确保传递的用户属性足够且正确。

用户属性

在 SAML 登录过程中，用户通过身份提供程序完成身份验证后，系统会将 SAML 响应发送到 Foundry。此 SAML 响应包含用户的属性（也称为“声明”），例如姓名、电子邮件以及任何可用的附加信息。这些属性以属性键到值（例如 email → user@example.com）或多个值的映射形式发送。

为了让 Foundry 获取正确的用户属性值，您必须将身份提供程序属性（或“声明”）映射到对应的 Foundry 属性。Foundry 需要以下映射：

  • ID：默认设置为 NameID ，但可以更改为其他稳定的标识符。此值应始终存在于 SAML 断言中，且具有静态唯一值。
  • 用户名：默认设置为 NameID ，但可以更改为其他人类可读的属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name ，适用于 Azure AD）。
  • 电子邮件：应映射到电子邮件属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress ，适用于 Azure AD）。
  • 名字：应映射到名字属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/givenname ，适用于 Azure AD）。
  • 姓氏：应映射到姓氏属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/surname ，适用于 Azure AD）。

查看 Azure AD 和 Okta的参考映射。

您可以设置更多映射，以便在 Foundry 中创建更多用户属性，只需点击 添加属性映射。在左侧字段中输入 Foundry 中的属性名称，并在右侧字段中输入身份提供商中的属性名称。

对于每个映射，都有一个切换开关，供您选择当 SAML 响应中的属性具有多个值时的行为。此切换开关可设置为 第一个 （这将使用收到的第一个值填充该属性）或 全部 （这将使用收到的所有值填充该属性）。

提供商组

您还可以将 Foundry 配置为根据身份提供商属性创建组（称为“提供商组”），从而在 Foundry 中镜像您现有的组成员身份。您可能还需要额外配置您的提供商，以在 SAML 响应中包含组属性。

要为提供商组设置映射，请勾选标为 从身份提供商导入用户组 的复选框，并将随 SAML 声明一起发送的属性键输入到 组属性映射 字段。用户登录时，所配置属性的每个值都将镜像为提供者组，并且用户将被登记为成员。如果取消选中此复选框，则登录时提供者组的成员资格将不会保持最新。如果您决定保持取消选中状态，我们建议启用 SCIM 以在无需交互式登录的情况下更新提供者组的成员资格。

（可选）您可以在 用户组属性模式 字段中设置正则表达式模式，以便从所配置属性的每个值中提取组名。与模式匹配的文本将成为 Foundry 中的组名，因此该模式应匹配完整的组名。

如果每个值仅包含组名，请将此字段留空。例如，以下三个值 Engineering、 Analysts和 Admins 将创建具有这些名称的三个提供者组。当单个值包含多个组名时，请设置模式。例如，如果属性以下列单个值的形式到达 Engineering,Analysts,Admins，则模式 [^,]+ 将创建相同的三个提供者组。

故障排除

“登录失败，因为无法找到合适的身份验证提供商。请联系您的管理员以获取进一步帮助。”错误

此错误表明，用户输入的用户名与任何身份验证提供商的 电子邮件域 均不匹配，这些电子邮件域已在 Control Panel 中配置并加入允许列表。这也可能意味着，用户尝试从中登录的主机未被添加为其配置的身份验证提供商的 受支持主机 。

"有 x 个提供商的证书将在 30 天内过期。"

此警告横幅表示身份提供商元数据中的证书将在 30 天内过期。身份提供商应切换到新证书，以避免身份验证中断。您可以通过手动上传或自动刷新来解决此问题。

手动上传

  1. 在身份提供方中生成新证书。 确保旧证书仍然存在且处于活动状态。 这样，在新元数据传递到 Control Panel 之前，登录仍能正常工作。
  2. 在 Control Panel 中，通过 Upload 方法将新的 XML 文件上传给您的提供方，并确认您可以查看提取出的即将过期证书和新证书。
  3. 保存后，身份提供方即可切换为使用新证书并移除旧证书。移除即将过期的证书后，无需重新上传元数据。

请注意，如果您的身份提供方在您将新的 XML 文件上传到 Control Panel 之前就开始使用新证书进行签名，用户将遇到登录问题。

自动刷新

当您配置上述 Fetch 方法时，您可以选择 使用提供方元数据 URI 自动刷新身份提供方的元数据。当您的身份提供方轮换到新证书时，下一次登录尝试最初会失败，从而促使 Foundry 自动从元数据发现 URI 获取更新的元数据并重试请求，而不会中断用户的登录体验。

请注意，如果您的身份提供者在证书轮换期间更改了元数据 URI，则自动元数据刷新将无法正常工作。如果发生这种情况，您必须在现有证书到期之前，在 Control Panel 中手动更新元数据发现 URI。

某些身份提供者会在其元数据中包含一个 validUntil 日期。该日期可能与当前生效的签名证书的到期时间相关联，而非所有已发布证书中最晚的到期时间。因此，即使元数据中已发布新证书，一旦超过 validUntil 日期，元数据本身也会失效，从而导致登录失败。当身份提供者改用新证书时， validUntil 日期通常会随之更新，以反映新证书的到期时间。

启用自动元数据刷新后，Foundry 会在证书切换后获取新的元数据，其中包含更新后的 validUntil 日期，从而解决因 validUntil 日期过期而导致的登录失败，无需人工干预。如果未启用自动元数据刷新，则在身份提供者改用新证书后，您需要将更新后的提供者元数据重新上传到 Control Panel。
