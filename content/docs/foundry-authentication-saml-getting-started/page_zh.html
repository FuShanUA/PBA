开始使用

SAML 2.0（安全断言标记语言）↗ 是一种基于 XML 的数据格式，用于在 服务提供商 （通常缩写为 SP），例如 Foundry，与 身份提供商 (IdP）之间交换身份验证和授权数据。SAML 2.0 最常见的用例是 单点登录 (SSO），通过 Web 浏览器进行。

概念

在以下部分中，将讨论 Foundry 中常见的身份验证概念。

SAML 集成元数据

SAML 集成元数据，也称为服务提供商元数据，是需要传递给身份提供商的 Foundry 相关信息。此信息包括：

  • 实体 ID： 用于向身份提供商标识 Foundry 的唯一 ID，采用 URN ↗ format urn:uuid:[$UUID].
  • 断言消费服务（ACS）URL： Foundry 的端点，用于接受 SAML 响应消息，以便基于断言建立会话。
  • 单一登出 URL： Foundry 的端点，用于接受来自身份提供商的 SAML 单一登出请求。
  • 证书： 用于对发送给身份提供商的 SAML 消息进行签名。

此信息被编码为一个自动生成的 XML 文件，客户可以将其整体复制并上传到身份提供商。此外，Control Panel 会将这些信息提取到单独的字段中，以便逐个复制。

身份提供程序元数据

身份提供商元数据是需要传递给 Foundry 的身份提供商相关信息。此信息包括身份提供商的实体 ID、单点登录（SSO）和单一登出 URL，以及证书。

身份提供商元数据被编码为一个 XML 文件，可以通过以下方式上传到 Control Panel：

  • Upload：从身份提供商保存 XML 文件并将其上传到 Control Panel。
  • Fetch：提供元数据发现 URI，Foundry 可以从中检索有关您的身份提供商的信息，包括您的身份提供商的实体 ID、单点登录（SSO）、单一登出 URL（SLO）以及证书。您还需要配置网络出口策略，以使 Foundry 能够访问所提供的元数据发现 URI。

SAML 证书具有有效期，过期后用户可能会遇到登录问题。当与身份提供商关联的证书将在未来 30 天内到期时， 警告横幅 将显示在 Control Panel 中。

电子邮件域名匹配

电子邮件域名用于决定向用户展示哪些身份提供商集成作为登录选项。当用户在登录界面输入其电子邮件或用户名时，Foundry 会通过检查所有已配置身份提供商的电子邮件域名来确定将显示哪些身份提供商集成。只有与用户电子邮件域名匹配的已配置身份提供商集成才会显示。

电子邮件域名可以是正则表达式，但通常采用简单形式 @example.com，它将被自动转换为 .*@example\.com来查找覆盖缺口；具有该键的节点是您工作流中没有任何监控视图在监视的资源。 .* 。

电子邮件域名的简单形式（@example.com）和正则表达式（.*@example\.com）默认均区分大小写。可以通过在正则表达式开头添加 (?i) 来使电子邮件域名不区分大小写，因此简单形式 @example.com 将是 (?i).*@example\.com or (?i)@example\.com.

支持的域名主机

支持的域名主机用于：

  • 在 SAML 集成元数据中构建 ACS 和单一登出 URL。
  • 确保仅向使用这些域名主机登录的用户展示该集成。

您可以从为您的部署配置的域名主机中进行选择。

映射属性

将 SAML 响应映射到 Foundry，以确保传递充分且正确的用户属性。

用户属性

在 SAML 登录过程中，用户通过身份提供程序完成身份验证后，SAML 响应会被发送到 Foundry。此 SAML 响应包含用户的属性（也称为“声明”），例如姓名、电子邮件以及任何可用的附加信息。这些属性以属性键到值的映射形式发送（例如 email → user@example.com）或多个值。

为了让 Foundry 获得正确的用户属性值，您必须将身份提供程序的属性（或“声明”）映射到匹配的 Foundry 属性。Foundry 需要以下映射：

  • ID：设置为 NameID 默认情况下，但可以更改为其他稳定标识符。Foundry 使用此值将登录与现有账户进行匹配。该值必须非空、始终存在于 SAML 断言中，并且格式保持一致（包括大小写）。它必须在账户的整个生命周期内保持稳定，并永久且唯一地标识单个用户。避免使用可能发生变化的值（例如电子邮件地址或用户名），因为变化可能会中断账户访问。
  • 用户名：设置为 NameID （默认值），但可以更改为其他人类可读的属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name ，适用于 Azure AD）。
  • 电子邮件：应映射到电子邮件属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/emailaddress ，适用于 Azure AD）。
  • 名字：应映射到名字属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/givenname ，适用于 Azure AD）。
  • 姓氏：应映射到姓氏属性（例如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/surname ，适用于 Azure AD）。

查看以下身份提供程序的参考映射： Azure AD 和 Okta.

您还可以通过点击以下按钮设置其他映射，在 Foundry 中创建更多用户属性： 添加属性映射。在左侧字段中输入 Foundry 中的属性名称，在右侧字段中输入身份提供程序中的属性名称。

对于每个映射，都有一个开关，供您选择当属性在 SAML 响应中具有多个值时的行为。此开关可以设置为 第一个 （将使用收到的第一个值填充该属性）或 所有 （将使用收到的所有值填充该属性）。

提供程序组

您还可以配置 Foundry 根据身份提供程序属性（称为“提供程序组”）创建组，从而允许您在 Foundry 中镜像现有的组成员身份。您可能还需要额外配置您的提供程序，以在 SAML 响应中包含组属性。

要为提供程序组设置映射，请勾选标有以下内容的复选框： 从身份提供程序导入用户组 ，并在以下字段中输入将随 SAML 声明一起发送的属性键： 组属性映射 字段。当用户登录时，所配置属性的每个值都将被镜像为提供程序组，并且该用户将被注册为成员。如果未勾选此复选框，提供程序组的成员身份将不会在登录时保持更新。如果您决定保持不勾选，我们建议启用 SCIM 以在无需交互式登录的情况下更新提供程序组成员身份。

（可选）您可以在以下字段中设置正则表达式模式： 用户组属性模式 字段，用于从所配置属性的每个值中提取组名称。与模式匹配的文本将成为 Foundry 中的组名称，因此该模式应匹配完整的组名称。

如果每个值仅包含组名称，请将此字段留空。例如，这三个值 Engineering, Analysts日 Admins 将创建三个具有这些名称的提供程序组。当单个值包含多个组名称时，请设置模式。例如，如果该属性以单个值的形式到达 Engineering,Analysts,Admins，则模式 [^,]+ 将创建相同的三个提供程序组。

故障排除

“登录失败，因为找不到合适的身份验证提供程序。请联系您的管理员以获取进一步帮助。”错误

此错误表示用户输入的用户名与任何身份验证提供程序的 电子邮件域名 不匹配，这些域名已在 Control Panel 中配置并加入允许列表。这也可能意味着用户尝试登录的主机未被添加为其所配置身份验证提供程序的 受支持主机 。

“有 x 个提供程序的证书将在 30 天内过期。”

此警告横幅表示身份提供程序元数据中的证书将在 30 天内过期。身份提供程序应切换到新证书，以避免身份验证中断。您可以通过手动上传或自动刷新来解决此问题。

手动上传

  1. 在身份提供程序中生成新证书。 确保旧证书仍然存在且处于活动状态。 这样，在新元数据传递到 Control Panel 之前，登录将继续正常工作。
  2. 在 Control Panel 中通过 Upload 方法将新的 XML 文件上传到您的提供程序，并确认您可以查看提取到的即将过期的证书和新证书。
  3. 保存后，身份提供程序即可切换到使用新证书并删除旧证书。一旦删除了即将过期的证书，无需重新上传元数据。

如果您的身份提供程序在您将新的 XML 文件上传到 Control Panel 之前就开始使用新证书进行签名，用户将会遇到登录问题。

自动刷新

当您配置 Fetch 上述方法时，您可以选择 使用提供程序元数据 URI 自动刷新身份提供程序的元数据。当您的身份提供程序轮换到新证书时，下一次登录尝试最初会失败，这会促使 Foundry 自动从元数据发现 URI 获取更新的元数据并重试请求，而不会中断用户的登录体验。

如果您的身份提供程序在证书轮换期间更改了元数据 URI，自动元数据刷新将无法工作。如果发生这种情况，您必须在现有证书过期之前在 Control Panel 中手动更新元数据发现 URI。

某些身份提供程序在其元数据中包含 validUntil 日期。此日期可能与当前活动签名证书的过期时间相关联，而不是所有已发布证书中的最新过期时间。因此，即使新证书已发布到元数据中，一旦 validUntil 日期过去，元数据本身将失效，从而导致登录失败。当身份提供程序切换到使用新证书时， validUntil 日期通常会更新以反映新证书的过期时间。

启用自动元数据刷新后，Foundry 将在证书切换后获取新元数据，其中包含更新后的 validUntil 日期，从而解决由过期的 validUntil 日期引起的登录失败，无需人工干预。如果未启用自动元数据刷新，则在身份提供程序切换到新证书后，您需要将更新后的提供程序元数据重新上传到 Control Panel。
