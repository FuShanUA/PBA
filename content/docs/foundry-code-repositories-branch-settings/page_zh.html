分支设置

本页面将引导您了解 Code Repositories 中的各种分支设置：

  • 设置默认分支
  • 选择拉取请求合并模式
  • 保护分支
  • 配置分支回退

默认分支

在包含多个分支的 Code Repositories 中，可以将默认分支配置为基础分支。默认情况下，所有拉取请求和提交都将针对该分支进行，除非另行选择。通常，默认分支是 master 分支的情况下对分支执行操作。

您可以通过导航到以下位置来选择 Code Repository 的主分支 Settings > Branches > Default branch.

合并模式

有多种策略可用于合并拉取请求中提议的代码更改。在“设置”选项卡中，您可以选择一个或多个合并模式，供代码作者在拉取请求页面中使用。

  • 压缩并合并 - 压缩并合并模式将在目标分支上创建一个包含拉取请求引入的所有更改的单一提交。这将在默认分支上形成更精简的提交历史。
  • 合并 - 当您使用 合并 时，在分支上创建的所有单独提交将连同合并提交一起添加到目标分支。在目标分支的提交历史中，所有单独提交将以其原始时间戳显示，标明它们在开发分支上的创建时间。
  • 快进合并 - 当目标分支到您的分支之间存在直接路径（目标分支上没有其他更改）时，快进合并会将目标分支推进到开发分支的最前端，并合并它们的提交历史。

所有选定的合并模式都将作为选项显示在拉取请求页面中。如果选择了“压缩并合并”模式，它将作为主要选项显示，其他选定的模式则可在菜单中选择。

受保护分支

当有多个作者向同一个代码仓库贡献代码，或该仓库支撑关键数据资产时，您可以保护您的分支，以实现更高水平的治理并防止意外更改。受保护分支只能通过拉取请求进行修改，并且必须满足一组预定义的要求。

默认情况下，只有 Code Repository 的所有者可以更改分支保护设置，而所有者和编辑者都可以将拉取请求合并到受保护分支。无论权限如何，所有代码作者都必须遵守受保护分支策略。

您可以在分支设置面板中设置以下要求：

  • 要求 ci/foundry-publish 成功运行
  • 要求代码审查
  • 要求特定审查者
  • 要求安全审批
  • 限制稳定版本标签（仅限 Functions 仓库）

要求 ci/foundry-publish 成功运行

为了将更改发布到您的数据，持续集成流程 ci/foundry-publish 必须成功运行并完成。如果在流程成功完成之前合并更改，则无法保证更改会生效，因此强烈建议将此作为受保护分支的一项要求。

要求代码审查

保护关键分支的一个好处是，在将代码更改合并到生产环境之前，能够获得协作者的审查。任何有权合并更改的人都可以对拉取请求提交审查（默认情况下：仓库的所有者和编辑者）。

您可以强制执行以下审查策略：

  • 要求合并前无拒绝 - 如果至少一名审查者拒绝了代码更改，这将阻止拉取请求合并。
  • 要求合并前至少获得一个批准 - 这将确保代码在更改合并之前经过审查和批准。

要求特定审查者

您可以要求在合并拉取请求之前获得特定用户或组的批准。要满足组要求，至少需要该组的一名成员批准该拉取请求。就其本身而言，只要收到了批准，此策略允许存在拒绝。例如，如果组的一名成员拒绝了更改而另一名成员批准了更改，则批准将优先于拒绝，除非适用“要求无拒绝”策略。

必需的审阅者仍需要代码仓库访问权限

要求用户/组批准确实 不 会授予他们审阅拉取请求的权限。请始终确保必需的审阅者也拥有代码仓库的访问权限。

配置高级批准策略

高级拉取请求批准策略根据拉取请求中修改的文件来确定审阅所需的用户和组。在受保护分支的分支设置中，选择 编辑，然后选择 高级批准策略 以开始配置策略。

直方图 编辑策略 选项卡提供了一个基于表单的编辑器。高级批准策略会对规则的逻辑运算符进行分组，例如 ALL or ANY。选择一个规则以提供元数据，例如规则的名称或描述。开启 规则有条件地适用 以仅在拉取请求中修改的文件匹配某个正则表达式时才应用此规则。例如，在 Python 转换的典型文件夹结构中， ["transforms-python/src/myproject/datasets/.*\\.py"] 将匹配 datasets 文件夹中的所有 Python 文件。

在 Workshop 应用程序的 查看 YAML 选项卡中，您可以直接修改、复制和粘贴策略的 YAML 表示形式。这对于对策略进行批量编辑非常有用，例如查找和替换某个搜索词。

要求安全审批

要停止传播 安全标记 在分支上，该分支必须受到保护。在仓库上启用安全更改后，它将自动且不可变地要求在合并拉取请求之前进行安全检查和批准（如有必要）。阅读更多关于 移除继承的标记.

限制稳定版本标签

在函数仓库中，您可以对函数稳定版本的发布强制实施限制。一旦为仓库配置了至少一个受保护分支，将提供一个额外的开关用于 仅允许从受保护分支标记稳定版本.

If 仅允许从受保护分支标记稳定版本 启用后，从仓库的特性分支（非受保护分支）进行标记将阻止用户提交稳定的语义化版本字符串。例如， 1.2.3 是一个稳定的语义化版本，而 1.2.3-rc1 表示预发布版本，允许从特性分支发布。

调用您的函数的应用程序可能配置为引用某个 版本范围；例如，某个 Workshop 模块可能会调用某个函数 foo 在版本 >=1.2.3 <2.0.0，因此如果您发布版本 1.3.0，该 Workshop 模块现在将调用此版本（1.3.0).

为防止新版本出现意外行为，我们建议代码更改在以新的稳定版本发布之前经过审阅和测试。 仅允许从受保护分支标记稳定版本 开关确保所有更改在以稳定版本发布之前必须经过审阅，因为更改必须经过代码审阅才能合并到受保护分支中。

由于版本范围会忽略预发布版本，您可以发布一个预发布版本，例如 1.3.0-test 以防止下游应用程序调用新版本。启用 仅允许从受保护分支标记稳定版本 开关允许从特性分支发布预发布版本，以便可以在下游应用程序中测试版本，而不会在生产环境中造成问题。

取消保护分支

所有者可以在 Code Repository 设置中取消分支保护。但是，具有活动安全更改的分支，例如 停止标记传播，在分支没有安全更改之前无法取消保护。要取消具有活动安全更改的分支的保护，应通过拉取请求移除这些更改。然后可以在 Code Repository 设置中取消该分支的保护。

回退分支

Code Repositories 允许您在任何分支上构建数据集，并查看转换对数据的影响。如果转换的输入数据集尚未在当前分支上构建，系统将尝试从回退分支列表中查找已构建的版本。除非另行配置，默认分支将自动设置为回退分支。您可以为每个分支设置不同的回退分支，并在需要时设置多个回退分支。

此配置仅适用于设置它的 Code Repository 中的构建和操作。它对其他 Foundry 应用程序或在仓库之外触发的构建（例如，使用计划构建）没有影响。

您还可以配置 如果希望用户在每次运行预览前手动确认，请开启 与 Code Repositories 分支同名的分支，以便 Pipeline Builder 转换从该匹配分支读取输入数据集。Pipeline Builder 支持 回退分支配置 同样允许您控制当输入数据集尚未在当前分支上构建时使用哪个分支。
