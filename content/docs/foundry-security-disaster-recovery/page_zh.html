灾难恢复

本页面介绍完全托管的云部署的灾难恢复。对于本地部署或客户管理基础设施的部署，相关安排按环境逐一定义。在这些场景下，请联系 Palantir 支持团队了解具体详情。

Palantir 的灾难恢复解决方案可防范两大类灾难场景：

  • 通过高可用性基础设施防范大规模中断，例如数据中心丢失
  • 通过例行自动备份防范运营中断，例如意外删除或数据损坏

针对这两种场景，本页面概述了平台如何保持可用、数据如何得到保护和恢复，以及 Palantir 与您（客户）之间的共同责任领域。

高可用性

对于使用我们完全托管云基础设施的客户，Palantir 提供高可用性，以确保平台在发生硬件和基础设施故障时持续运行。

Foundry 在云区域内跨多个可用区以双活（active-active）配置运行。多个节点同时处于活动状态，并行处理请求，并双向复制数据。如果单个节点或整个可用区不可用，其余节点将继续处理请求，故障转移将自动完成。

由于同一区域内的各可用区在物理上相互分离——拥有独立的供电、网络和冷却设施——因此单个数据中心的损失不会导致平台下线，也不会造成永久性数据丢失。在此类事件发生期间，平台可能以降级状态运行（例如，部分用户可能会注意到性能下降），但数据依然安全，服务仍会继续。

自动备份

高可用性可防范基础设施故障，但无法防范意外删除或数据损坏等事件，因为在这些事件中，不希望发生的更改会被复制到所有活动节点。为了应对这一问题，Palantir 会对平台进行定期备份。

不同类别的数据以不同的方式受到保护。

平台元数据和配置

Palantir 使用名为 Rescue 的服务来备份和恢复构成平台的各项服务的元数据和配置。这包括数据目录和本体论元数据、本体论编辑内容、用户生成的元数据（例如代码仓库和 Workshop 模块）以及相关的平台状态。备份按固定周期进行，在传输过程中和静态存储时均经过加密，并存储在加密的云对象存储桶中（例如 AWS S3、Azure Blob Storage、Google Cloud Storage 或 OCI Object Storage）。Palantir 会对 Rescue 进行持续监控，以确保这些备份的健康状况。保留期默认为七天，可根据您 Foundry 管理员的要求进行不同的配置。

在灾难场景中，Rescue 备份会与从客户管理的源系统重新摄取的数据结合使用，以将平台恢复到最近的时间点。

对象存储中的客户数据

上述元数据/配置备份的范围仅限于数据库基础设施，不包括对象存储中保存的文件，例如 AWS S3、Azure Blob Storage、GCP Cloud Storage 或 OCI Object Storage。对象存储中保存的客户数据通过底层云存储服务的原生持久性和冗余功能（例如存储桶版本控制）进行保护，这些功能旨在防止数据丢失。

共担责任

Palantir 负责保护 Palantir 平台以及使其运行的元数据和配置。客户负责其上游源系统中数据的完整性和备份。
