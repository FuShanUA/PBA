测试运行

测试运行让您可以在最终用户应用操作类型之前，先在 Ontology Manager 中对其进行模拟。当您提交测试运行时，Foundry 会根据您提供的参数值对操作进行评估，并返回该操作将会做出的编辑，以及详细的执行明细。

测试运行产生的编辑不会应用到您的本体论中。测试运行是一种安全的方式，可在不更改任何数据的情况下，查看操作将做出的编辑及其执行方式。

测试运行可在操作类型编辑器中操作表单预览的测试运行选项卡中使用。

运行测试

  1. 在 Ontology Manager 中打开一个操作类型，并打开操作表单预览。
  2. 确认预览已设置为表单布局。测试运行在表单布局中可用，在表格布局中不可用。
  3. 在操作表单预览中选择测试运行标签页。
  4. 在表单中填入您想要测试的参数值。
  5. 选择提交以运行测试。

运行完成后，测试运行的结果将显示在操作表单预览中。

测试运行会在您当前的本体论分支上评估操作类型，并以您的权限执行，强制执行与常规操作提交相同的对象安全性和提交标准。如果您能够在 Ontology Manager 中查看操作类型配置，就可以运行测试。

当操作类型存在未保存的编辑时，测试运行不可用。请在运行测试之前保存更改，以便测试评估的是已保存的配置。

解读结果

已完成的测试运行会将结果显示在两个标签页中。

建议的更改

建议的更改选项卡列出了操作将对本体论做出的编辑，包括创建、修改和删除的对象和关联。属性更改以当前值与建议值之间的对比形式显示。如果操作不会产生任何编辑，该选项卡将显示无建议的更改。

详情

详情选项卡说明了操作的评估方式以及直接编辑之外还会发生的情况：

  • 执行日志：对运行的逐步分解，涵盖元数据加载、依赖项验证、提交条件、参数验证和编辑计算。使用此日志可以了解操作为何成功或在何处失败。
  • 副作用：操作将触发的副作用的预览，例如通知。您可以打开通知预览，查看将生成的内容和接收者。
  • 引用的实体：操作在运行期间引用的对象类型、关联类型、接口类型以及函数。

如果操作失败，详情选项卡会将错误分为两类：

  • 面向管理员的错误：用于调试的技术细节。
  • 面向最终用户的错误：显示给触发操作的用户的消息。

测试运行期间会跳过哪些内容

测试运行仅执行确定操作结果所需的工作。在应用操作后才会生效的副作用将被跳过。当您的操作类型包含以下任意内容时，操作表单预览会通知您这些内容将被跳过：

  • 副作用 Webhook不会被调用。
  • 通知不会被发送。测试运行结果中会显示本应触发的通知的明细。
  • 计划构建不会被触发。

外部调用

为了获得准确的结果，测试运行会执行操作达到其结果所需的函数和调用。这包括操作的规则中使用的函数、生成通知正文或收件人的函数、生成 webhook 负载的函数、回写 webhook，以及访问外部资源的函数。仅执行确定操作结果所需的调用。

由于会执行外部调用，因此它们可能会影响外部系统。当您的操作类型包含其中任何调用时，Foundry 会列出执行来源，并在测试运行继续之前提示您确认外部调用。这些调用仅在您确认之后才会执行。

限制

  • 测试运行仅在表单布局中可用；在表格布局中不可用。
  • 当操作类型存在未保存的编辑时，测试运行不可用。请在运行测试之前保存您的更改。
  • 应用操作后生效的副作用将被跳过，如测试运行期间会跳过哪些内容中所述。某些由函数支撑的调用仍会执行；请参阅外部调用。
