嵌入 Workshop 模块

Workshop 提供两项支持嵌入其他 Workshop 模块的功能： Embedded Module 小部件和 循环 section 布局（"loop 布局"）。

这些功能允许构建可嵌入到其他 Workshop 模块中的 Workshop 模块。嵌入式模块支持 Workshop 提供的所有功能，但在嵌入式模块与嵌入模块之间的交互方面存在一些 限制 。本文档有时会将嵌入其他模块的模块称为"父"模块，将被嵌入的模块称为"子"模块。当本文档提到"嵌入式模块"时，该提法同时适用于 Embedded Module 小部件，以及嵌入在 循环 布局中的模块，除非另有说明。

用例

嵌入式模块有许多用例，包括：

  • 跨多个模块复用
  • 在单个模块内复用
  • 可维护性
  • Marketplace 自定义
  • 就地替换 Workshop 模块

跨多个模块复用

嵌入式模块允许配置单个子模块并在多个父模块中复用。可以构建的嵌入式模块类型包括：

  • 已配置的对象视图
  • 具有复杂配置的单个小部件
  • 由复杂变量逻辑支撑的一组小部件
  • 完全不含小部件的复杂变量逻辑

在单个模块内复用

嵌入式模块可以在单个父模块中使用多次，可通过 loop 布局（同时支持对象集和数组）或单独的嵌入式模块小部件实现。在同一个父模块中被多次嵌入的子模块示例包括：

  • 基于所提供变量派生的自定义卡片视图
  • 每个选项卡或页面显示一次的一组小部件

可维护性

嵌入式模块可用于将较大的父模块拆分为多个子模块，以提高可维护性。这样每个子模块可以拥有自己的变量作用域，并且不同的 Workshop 构建者可以同时编辑不同的子模块。

Marketplace 自定义

在使用 Marketplace 打包 Workshop 模块时，嵌入式模块可提供自定义区域。嵌入的子模块将作为依赖项打包，在安装时，Marketplace 用户可以选择一个具有相同模块接口变量类型签名的模块，来自定义已安装父模块的一部分。

就地替换 Workshop 模块

嵌入式模块可用于部署新的 Workshop 模块实现，而无需更改用户已在使用的 Workshop 资源。您可以将嵌入式模块用作模块中的唯一小部件来实现这一点。这样您就可以对模块进行重大更改，而无需用户迁移到新的 Workshop 资源。

跨嵌入式模块通信

用途 模块接口变量 在父模块与子模块之间或同级模块之间进行通信。例如，这些共享的接口变量可以支撑共享状态，如所选对象、所选选项卡或是否显示叠加层。Workshop 始终使用父模块的变量定义来支撑这些映射的接口变量，并忽略嵌入式模块的接口变量定义； 嵌入式模块接口配置 对此行为有更详细的描述。嵌入式模块可以通过事件修改接口变量的值，从而使引用这些变量的其他位置能够根据更新后的值做出响应。

但是，在子模块内部更新的变量不会自动传播回父模块。要让子模块中的更改反映到父模块的变量中，您必须在子模块中显式配置一个"设置变量"事件，通过模块接口针对父模块的变量。

当你在编辑模式下打开嵌入的子模块时（例如，通过 打开引用的模块 来自 Embedded Module widget 或一个 循环 实例），子模块编辑器会打开，并应用任何已映射的模块接口变量的当前值。这与查看模式下的行为一致，便于使用父模块中存在的相同状态来调试嵌入模块。

局限性

子模块不继承模块设置

在模块级别为子模块进行的配置，例如 路由, 状态保存日 自动刷新，不会被使用。这意味着必须为每个你打算使用自动刷新的模块显式配置自动刷新，并且自动刷新在嵌入模块的上下文中将无法工作。要在一个不自动刷新的父模块中嵌入一个会自动刷新的模块，你可以使用 iFrame widget 来嵌入一个单独的模块，作为会自动刷新的沙箱环境。你可以设置一个 URL 查询参数 embedded=true 来隐藏 Foundry 侧边栏。

如果你的工作流需要，你可以在父模块级别配置这些设置，并通过 模块接口.

事件传递

嵌入模块不支持 事件传递. 事件传递 的概念，后者允许构建者将事件配置从父模块传递到子模块，使子模块能够调用引用父模块配置的事件（例如，子模块调用一个在父模块中打开覆盖层的事件）。

To 跨嵌入模块进行通信，父模块可以将支撑布局状态的变量传递给子模块的模块接口变量，作为子模块修改父模块布局状态的一种方式。

带有地图模板的派生属性

当嵌入子模块时，派生属性会在父模块中以带前缀的 ID 重新注册，以避免跨嵌入模块的冲突。常规 widget 可以正常工作，因为其配置直接存储在 widget 定义中，并经过 ID 替换逻辑处理。然而，地图 widget 的配置以模板形式存储，这些模板会继续引用原始的派生属性 ID。因此，派生属性可能会出现在表格等 widget 中，但不会出现在父模块的地图悬停卡片上。

要解决此限制，请将派生属性直接复制到父模块，而不是依赖嵌入模块的注册。这样可以保留原始 ID，使地图模板引用的 ID 与父模块中注册的 ID 相匹配。

嵌入模块的溯源

与 Workshop 中的其他 "Foundry apps" widget 类似，其他 Workshop 模块所使用的嵌入模块的溯源信息不会由 调度指标.

自引用嵌入模块

默认情况下，模块不能嵌入自身，无论是直接嵌入还是通过子模块链嵌入。如果在未启用该功能的情况下配置了自引用，模块将向构建者显示警告，并且不向查看者渲染任何内容，以防止可能出现的无限嵌入模块链。

启用自引用嵌入模块时请谨慎使用。无效的层级结构或循环引用可能导致无限递归，使模块无法使用。

嵌入模块的权限

嵌入模块是独立的资源，拥有自己的权限设置。如果用户有权查看嵌入了某个子模块的父模块，但无权查看该子模块，用户将看到 "加载模块失败" 错误。

性能

嵌入式模块应具有与普通 Workshop 模块相似的性能特征。一个显著的区别是，嵌入式模块的初始化会延迟到该模块在视图中显示时才进行。一旦初始化完成，嵌入式模块的运行效果应与整个模块在同一位置配置时完全相同。

嵌入式模块通常会缩短父模块的初始加载时间，因为它们是在初始渲染之后延迟加载的。但是，如果初始页面上同时显示多个层级的嵌入，初始加载可能会因“瀑布”效应而变慢，即每个层级必须按顺序依次加载。为了优化加载时间，请考虑将较大的模块拆分，使初始不可见的部分拆分为嵌入式模块。

子模块配置将按实例进行一次初始化，这会带来初始化其变量的开销，但如果在多个实例中重复使用，子模块配置只需加载一次。

编辑包含多个嵌入式模块的父模块时，请避免打开每个嵌入式模块的标签页，因为这样做会在后续的编辑会话中造成性能损失。如果需要检查或修改特定的嵌入式模块，请考虑直接打开该模块，而不是通过父模块的编辑器打开。

嵌入式模块和循环布局的使用使构建者能够更轻松地配置非常大且复杂的模块。构建者应注意同时显示的控件和变量的总数，尤其是那些加载开销较大的控件和变量。
