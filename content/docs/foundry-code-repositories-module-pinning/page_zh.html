在平台内固定 Spark 模块

Code Repositories 允许您为仓库固定 Spark 模块。这会强制使用特定版本的 Spark。您可以为新构建和现有构建固定 Spark 模块。

我们建议您始终使用最新版本的 Spark，以获得最新的性能和安全功能。固定 Spark 模块应作为临时措施。

如何固定 Spark 模块

在 Data Connection 中导航至 设置 Code Repositories 中的标签页，然后选择 运行时覆盖.

创建固定

在 运行时覆盖 标签页中，选择 设置固定.

您可以在所有分支或特定分支上创建固定。您可以选择要固定的 Spark 模块版本（适用于给定仓库中可用的每种模块类型），还可以指定到期日期。到期日期不能超过当前日期 90 天。固定将在 90 天期限结束时或您指定的到期日期到期，以较早者为准。到期日期之后，您的构建可能会失败。

不稳定和非推荐版本会带有警告标志前缀。除非绝对必要，我们不建议使用这些版本。

在所有分支上创建固定

首先指定您要固定的 Spark 版本和到期日期。

应用 保存 以设置固定。

在特定分支上创建固定

您可以为每个分支固定版本。您还可以为未指定的分支选择版本。

应用 保存 以设置固定。在下面的示例截图中，我们在所有分支上为版本 1.916.0 创建了一个固定，该固定设置为于 2023 年 12 月 20 日上午 12:00 到期。

设置固定后，您可以查看固定已创建的确认信息。

编辑现有固定

选择 编辑 允许您修改固定。您可以使用与创建固定相同的工作流程更改分支、版本和到期日期。选择 表中，可通过点击 将移除固定并为 Expired 您之前设置的固定添加标签。

您可以在Carbon工作区中选择 还原 以重新创建您归档的固定。

查看您的固定

在 Build Preview > view details 页面，您可以查看为仓库固定的版本。

使用固定来控制 Code Repositories CI 中的 transforms 版本

在 Code Repositories 中为构建运行持续集成 (CI) 时，会根据仓库模板的当前版本选择 transforms 库 的版本。如果应用了固定，CI 将改用固定指定的库版本（前提是该版本高于模板声明的最低版本）。用户可以利用固定更快地访问新版本的 API 以及代码辅助和 本地开发.

FAQ

1. 为什么固定会在 90 天后到期？为什么我不能更长时间地使用它？

我们建议您始终使用最新版本的 Spark。不这样做意味着您可能错过性能和安全修复及改进，这可能对您的构建产生不利影响。

话虽如此，我们理解可能存在需要固定的特定用例，因此我们提供此功能，但需注意它应临时使用。在到期日期之前，我们建议您在您那边进行必要的更改，以与最新版本的 Spark 兼容。

2. 当我的固定即将到期时，我可以通过 UI 收到通知吗？

此功能正在开发中。

3. 我可以通过 Job Tracker UI 固定单个构建吗？

此功能正在开发中。

4. 我是否需要升级或在我这边进行更改才能使用此功能？

您无需进行任何升级或操作。

5. 此功能是否仅适用于新构建，还是也可以应用于现有构建？

您可以将此功能用于新构建和现有构建。

6. 如果我的作业已经在 cdconfig 中被固定（pin），会发生什么？

平台内的固定（pin）将始终优先。
