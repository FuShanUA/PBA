平台概览

Palantir AIP 为全球最关键的商业和政府场景中的实时、AI 驱动的决策提供支持。从 公共卫生 ↗ 到 电池生产 ↗，各类组织都依靠 Palantir 在其企业中安全、可靠且高效地利用 AI——并 推动取得运营成果 ↗。

简而言之，Palantir AIP 将生成式 AI 与运营相连接。AIP 与 Foundry（Palantir 的数据运营平台）和 Apollo（Palantir 用于自主软件部署的任务控制中心）共同构成了一个 AI Mesh ，可提供全方位的 AI 驱动产品——从基于 LLM 的 Web 应用程序，到使用视觉语言模型的移动应用程序，再到嵌入本地化 AI 的边缘应用程序。我们将这整套能力、功能和工具统称为 Palantir 平台。

虽然许多因素都有助于通过 Palantir 平台实现并扩大运营影响——包括 AIP Bootcamps ↗，其中客户亲自动手，短短数小时内即可利用 AI 取得成果——而关键的差异化因素则是一种软件架构，其核心正是 Palantir 本体论。

本体论

本体论旨在表示企业中的 决策 ，而不仅仅是数据。世界上的每个组织都面临着如何执行最佳决策的挑战，这些决策往往需要实时进行，同时还要应对不断变化的内部和外部条件。

这些决策流程的复杂性体现在本体论中，它促进了与现有企业系统之间的深度双向互操作性。本体论会自动将相关的数据、逻辑和操作组件集成到现代化的、AI 可访问的计算环境中。由此，除常规的商业智能和分析工作流之外，还能快速开发支持 AI 协作的运营应用程序。

决策组件

每个决策都可以分解为 数据、 逻辑和 操作。

  • 数据： 哪些关于世界和我们运营的相关事实或真相构成了此次决策的背景？
  • 逻辑： 哪些组织或业务规则可作为此次决策的护栏？在不同假设下，某些结果出现的概率是多少？在以往的类似情况下，我们采取了哪些措施，结果如何？我们的预测和优化模型提供了哪些输入？
  • 操作： 这项决策的“动力学”或影响是什么——也就是说，该决策如何在现实世界中显现？我们如何减少或压缩在 AIP 中做出决策与在生产环境中影响结果之间的步骤？

在 Palantir 平台中，所有这些组件都旨在促进 AI 协作模式，以释放您的操作人员、分析师和领域专家的全部潜力。

数据

本体论将数据集成为 对象和关联 ，从而使现实世界中运营的复杂性对人类和 AI 而言都易于理解。这将解锁构建 人 + AI 协作 工作流的能力。

本体论原生支持广泛的数据类型以及多种扩展基元，例如 语义搜索 （用于解锁非结构化数据）、 媒体引用 （用于处理图像和视频）以及 值类型 用于将额外的约束和上下文嵌入到数据中。这些是 AI 工作流开发所需的数据构建模块，将在下文的 逻辑 和 操作 章节中进一步描述。

该数据模型驱动着开箱即用的应用程序，可用于探索结构化、非结构化、地理空间、时序、仿真及其他数据模态。这些基线工具集成了具备上下文感知能力的 AIP Assist ，从而大幅缩短在平台中探索和分析数据的价值实现时间。

除应用构建和分析之外，在本体论中对数据进行建模还会自动创建强大的 API 网关和本体论软件开发工具包（OSDK），作为整个企业范围内连接的“运营总线”。

数据连接

数据很少会以干净、正确且结构规范的格式打包交付，而这种格式正是准确、可靠地向决策者呈现事实所必需的。为此，Palantir 平台提供了一个可扩展、多模态的数据连接与集成框架，可与各类企业数据系统开箱即用地配合使用。

管道构建器 将 LLM 数据转换 封装成一个即点即用的工具包，让用户能够轻松使用最新的 LLM 来驱动基于管道的转换，例如分类、情感分析、摘要、实体抽取或翻译。这为在本体论中自动创建“提案”以供操作员审查和批准奠定了基础，从而避免了每次都向模型发起实时请求所带来的延迟。（请注意，正如在下文 逻辑 一节中所讨论的，这两种与模型交互的方式高度互补。）

此外， AIP Assist 在 Pipeline Builder 和 代码仓库 中通过一个 AI 伙伴来加速数据工程——它不仅能够访问 Palantir 文档和通用代码片段库，还深度集成到平台前端，可以建议下一步操作或相关教程。

逻辑

如果说数据定义了我们决策的背景，那么逻辑则封装了用于丰富这一背景的推理与分析，使 Human+AI 团队能够做出更好的决策。这既可以作为额外的背景信息，以模型输出和可视化结果的形式呈现在运营应用程序中，也可以直接融入操作的机制之中。

鉴于这一定义十分宽泛，定义和执行逻辑的能力贯穿整个平台；例如，让我们来考虑 模型， 业务逻辑，以及 模板化分析和报告。

模型

生成式 AI、LLM、预测、优化器等。

LLM 或预测等模型接受参数并提供输出，作为当前决策的上下文。在数据科学家所熟悉的循环中，这些模型通常需要经历训练与优化的迭代过程；然而，在生产中将这些模型用作运营工作流可能是一项挑战。Palantir 的建模能力可以促进模型的运营部署。

在 Palantir 平台中，模型的完整生命周期会被记录为一个 建模目标 ，而模型本身的逻辑则通过 模型适配器进行抽象。这种方法意味着，无论您是 在平台中训练、 自带容器，还是 上传预训练模型，各种类型的模型都可以通过 函数 绑定到本体论，以便嵌入运营应用进行实时交互，或配置为 批量部署 ，并安排在数据管道中执行。

专门针对生成式 AI，Palantir 的 语言模型服务 提供统一的多模态交互接口，同时抽象了具体的模型和提供商实现细节，让跨各类商用 LLM 的开发变得简单。为了进一步改善结果，Palantir 的 评估 工具使您能够随时间推移并在不同模型之间对 LLM 性能进行基准测试，以监控漂移并自信地做出更改。

业务逻辑

业务规则、流程映射、语义搜索

建模方法采用“自下而上”的方式对数据进行训练，而业务逻辑通常基于运营领域所遵循的显式或隐式规则，采用“自上而下”的方式。这些规则可能存在于外部系统中，Palantir 可以通过 外部函数 和 Webhooks 直接连接到该系统，以便在运营工作流中进行实时交互，或通过 外部转换 实现管道连接。业务逻辑也可以直接在 Palantir 平台中使用 规则 和 Pipeline Builder 编写数据管道中的逻辑，并使用 Automate 和函数编写将要实时执行的逻辑。

模板化分析与报告

对象视图、分析模板、生成的报告

逻辑并非仅存在于数据科学模型或硬编码的业务规则中；分析师通常会在一次性调查、分析或报告中捕获并收集高价值逻辑。在 Palantir 平台中，您可以使用点击式分析工具构建分析和仪表板，如 Contour 和 Quiver，以及笔记本，例如 代码工作区。本体论数据模型的语义使这些分析产品易于模板化并重复使用，无论是嵌入 对象视图 或 Workshop 应用程序中，还是以独立的 仪表板形式呈现。这些对象视图、模板化分析和仪表板可以接入运营应用，提供一目了然的洞察以指导决策，同时也为进一步的即席探索提供了途径。

综合来看，逻辑的这三个方面——模型、业务逻辑以及模板化分析和报告——提供了一个工具包或调色板，用户可以从中自由组合搭配，以便在关键时刻为决策者提供所需的全部背景信息。

操作

任何决策若要产生影响，就必须传播到现实世界中。正是在这里，操作定义了企业的“动词”——即所做的事情——并控制着人工操作员或 AI 智能体如何确保其决策得以持久生效，无论是在本体论数据模型中，还是通过与 外部系统进行交互。此外，在本体论中捕获决策结果，可以让用户将特定决策与未来数据中对结果的观察关联起来。这样就形成了反馈循环，能够将未来的决策置于以往选择的背景之中，并可用于重新训练或微调模型，或只是让操作人员对过去有更清晰的认识。

在本体论中表示这些"动力学"的原子单元是一个 操作，它为更改或创建数据以及编排外部系统中的变更提供了具体、细粒度的控制。基本操作可通过点击式表单配置界面轻松定义。任意复杂度的操作都可以通过 函数支撑的操作 以及 本体论编辑 Typescript API来指定。操作还可以打包到 本体论软件开发工具包 （OSDK）以及 平台 API 中，以便自定义应用程序开发和现有的第三方工具能够轻松且安全地写回本体论。

权限 决定了每个操作可由哪些用户或代理在何种条件下执行，从而在最底层为安全、可审计且透明的控制奠定基础。

在复杂且紧密耦合的环境中（例如供应链或生产车间），一个微小的变更就可能引发连锁效应，带来意想不到或非预期的后果。 Scenario 原语允许用户通过对本体论的某个分支进行更改来推演这些后果，从而有效地创建一个沙盒世界，可在其中基于该潜在变更（及其下游）进行预测、业务流程建模和其他分析。 Vertex 应用专注于此类流程可视化和场景测试； Workshop 应用构建器原生支持场景，可用于开发包含“如果……会怎样”工作流的运营应用。

这些原语为在生产工作流中运行的 Human+AI 团队营造了一个安全的开发环境。“操作”（Actions）提供的细粒度权限和访问控制提供了一个“控制平面”，智能体在其中被沙盒化，其可使用的数据和工具均受到特定限制。在大多数模式中，AI 智能体并不会直接进行更改，而是创建提案：要么通过与 AIP Logic 函数（已集成到 Workshop 中）的直接集成来同步提交，要么异步地通过 Automate 或 Use LLM Pipeline Builder 中的节点。随后，生成的提案可呈现给操作人员，供其进行完善、提供反馈并作出最终决策。这种基于提案的模式不仅强化了“人在回路”范式，还会生成有价值的元数据，从而形成良性循环，使 Agent 能够通过持续反馈不断学习和演进。

本体论构建

如上所述，为了创建以决策为中心的全面企业模型，本体论集成了以下内容：

  • 数据，即 对象和关联；

本体论的这些构建基块使操作员和 AI 都能够理解现实世界运营的复杂性，从而解锁了构建人机混合工作流的能力。其他功能包括：

  • 用于从最终用户捕获数据并回传至语义基础的结构化机制；

  • 本体论软件开发工具包（OSDK），用于将本体论用作贯穿企业所有部分的“运营总线”。
