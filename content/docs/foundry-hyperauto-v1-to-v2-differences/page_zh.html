从 HyperAuto V1 迁移到 V2

日落

HyperAuto V1 目前处于 日落 阶段，并将在未来某个日期被弃用。目前仍提供全面支持。不建议创建新的 V1 管道，用户应从 HyperAuto V1 迁移到 V2，具体步骤详见 迁移文档.

HyperAuto V2 是对 HyperAuto V1 的重大升级，提供了增强的性能和功能，包括：

  • 通过点击式向导实现更简便的配置流程。
  • 能够生成 如果希望用户在每次运行预览前手动确认，请开启 管道，可提供数据处理过程的完全透明性、全面的变更管理工作流程以及显著的性能提升。
  • 输入数据的实时流式传输，支持对时间要求严格的运营应用。

HyperAuto V1 与 V2 之间的显著功能差异

下文介绍了 HyperAuto V2 的重要更新和变更。

源类型支持

截至 2024 年 4 月 29 日，HyperAuto V2 仅支持 SAP 数据。强烈建议使用 SAP 数据的 V1 用户开始将其使用迁移至 V2（参见 开始使用).

多源支持

在 HyperAuto V1 中，用户可以将单个管道连接到多个源，并在最后执行宽联合（wide union）。但是，这种方法可能会产生意外结果，现已不推荐使用。特别是，主键和外键若使用了 source 作为前缀，则在源名称发生更改时可能会失效。

在 HyperAuto V2 中，每个管道只能连接到一个源。因此， source 列不会在输出数据集中生成，并且不再用作主键或外键生成中的前缀。

建议需要此功能的用户重新实现一个在 HyperAuto V2 下游执行合并（union）的管道。

外键生成

HyperAuto V1 对外键生成采用了宽松的方法，这通常会导致在表之间创建无法准确反映底层数据关系的外键，从而可能产生不准确和误导性的解释。

HyperAuto V2 中生成键的逻辑已更新，采用更保守的方法以提高准确性；因此，外键列的列表有所不同。如果您认为 V2 中错误地遗漏了某个外键，请联系您的 Palantir 代表。

列重命名

HyperAuto V2 使用更丰富的元数据来重命名列，因此在输出数据集中生成的列名可能与 HyperAuto V1 有所不同。

自定义清洗函数

HyperAuto V2 不支持实现自定义清洗函数并将其作为管道的一部分进行应用。建议用户在 HyperAuto 下游创建管道来实现其自定义逻辑。

批量联合输入

HyperAuto V2 不支持配置多个链接到同一输出表的同步（在 V1 中称为 批量联合组件 ）。建议用户联合其输入 预先 到 HyperAuto V2，然后配置一个 基于文件夹的管道 以从 HyperAuto 获取数据。

将现有 HyperAuto V1 管道迁移到 HyperAuto V2

建议用户通过以下方式将其管道从 HyperAuto V1 逐步迁移到 V2：

  1. 创建一个新的 HyperAuto V2 管道，复制现有的 V1 配置并使用相同的输入。
  2. 识别管道的下游消费者（代码仓库、分析、应用程序），并逐步将其指向新的 HyperAuto V2 输出。

在已决定 不 迁移到 HyperAuto V2，现有的 V1 仓库将保持原样，但会与原始模板“断开”。这意味着该仓库将被转换为普通的 Python 转换仓库，并像其他任何自定义仓库一样由用户所有。

将 HyperAuto V1 仓库与原始模板断开后， 自动创建拉取请求的流程 将被停用，用户必须手动创建拉取请求才能更新其 V1 配置。
