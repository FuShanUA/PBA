Trace 视图

该 Trace 视图提供了工作流执行的可视化时间线，展示不同服务之间如何交互以及时间花费在何处。具体而言， 分布式 Trace 是指从请求生成到收到响应之间所有事件构成的时间线；这些事件可能跨越进程、网络和安全边界。分布式 Trace 是理解请求在应用程序中所经路径的关键。

所需权限

要查看 Trace 和服务日志，管理员必须为相关项目启用 日志访问 。用户始终可以访问自己过去 24 小时内的执行日志，但在 CBAC 堆栈上除外，在这些堆栈中必须启用日志访问才能查看 Trace 和服务日志。

Trace 视图的关键元素

  • 时间线可视化： 水平条形显示每个操作的持续时间。
  • 服务层级： 嵌套的 Span 显示了操作之间的父子关系。
  • 资源类型： 颜色指示每个 Span 是由函数、操作、自动化、模型还是 LLM 调用产生的。
  • 性能指标： 每个 Span 都会显示其执行时间。

分析 Trace 详情

您可以选择任意 Span 来查看该特定操作的完整 Trace 日志详情 。

Trace 详情包括：

  • 操作名称： 正在执行的特定函数、操作、语言模型、自动化、模型或内部操作。
  • 持续时间： 操作的执行时间。
  • 输入/输出数据： 对于函数执行请求，您可以查看传递给该操作以及从该操作返回的参数。
  • 模型交互： 对于 LLM 调用，您可以查看提示词、响应和 token 用量。
  • 错误信息： 失败操作的堆栈跟踪和错误消息。
  • 跟踪标识符： foundryTraceId，即 Foundry 分配的用于获取遥测数据的标识符，以及 x-b3-traceid，即标准分布式跟踪标识符，包含在每个服务日志条目的 tags 字段中（尽力而为；在源自 Foundry 之外的日志（例如使用本体论 SDK 构建的应用程序）中可能缺失）。

相关功能

  • 执行历史：在深入分析跟踪之前，查看所有最近的执行记录。
  • 服务日志：访问每个 span 的详细日志消息。
  • 性能监控：分析跟踪数据以识别优化机会。
