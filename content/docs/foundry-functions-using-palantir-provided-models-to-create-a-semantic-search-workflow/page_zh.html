示例语义搜索函数

本节中的代码示例可在以下语言中找到 TypeScript v2, Python和 Python 函数；请选择与您的函数版本相匹配的选项卡。TypeScript v1 将每个函数定义为导出类上的一个方法，并对该方法应用 @Function() 装饰器（来自 @foundry/functions-api ，然后通过以下方式查询本体论 Objects.search()。TypeScript v2 使用以下方式定义函数 export default，并从以下位置导入类型 @osdk/functions导入类型，并通过作为第一个参数接收的 本体论 SDK 客户端作为参数传入。Python 使用 @function 装饰器，并在函数体中构造一个 Ontology SDK 客户端。如需完整比较，请查看 TypeScript v1 与 TypeScript v2 的对比.

这三个版本的区别在于查询嵌入的生成位置以及函数必须定义的位置：

  • TypeScript v2 使用 Palantir 提供的嵌入模型自行嵌入查询，然后将生成的向量传递给 nearestNeighbors。该函数是导出类上的一个方法，按照惯例定义在 functions-typescript/src/index.ts.
  • Python 将用户的文本直接传递给 nearestNeighbors，它接受查询向量或查询文本。无需单独的嵌入调用，因此两步工作流合并为一步。该函数必须是 typescript-functions/src/functions 目录中某个文件的默认导出，且文件名必须与函数名一致；请查看 编写函数 以了解完整要求。
  • 或 也接受通过以下方式以文本形式传入的查询 nearest_neighbors。该方法是测试版功能，因此函数使用以下方式声明 @function(beta=True).

像 TypeScript v1 示例那样使用以下方式将嵌入生成为单独的步骤 TextEmbeddingAda_002.createEmbeddings，在文档中没有对应的 TypeScript v2 等价实现。本工作流不需要这一步，因为查询文本会在 KNN 搜索过程中被嵌入。如果要在 TypeScript v2 或 Python 函数中出于其他目的直接调用 Palantir 提供的模型，请查看 TypeScript v2 和 Python 函数中的语言模型.

不同 TypeScript 版本之间的邻居数量上限有所不同。TypeScript v1 将 k 值限制在以下范围内 0 < K <= 100，而 TypeScript v2 的 numNeighbors 参数接受以下范围内的值 1 to 500.

TypeScript v1 在取前 k 个结果之前，使用单独的 .orderByRelevance() 调用对匹配结果进行排序。TypeScript v2 通过传递以下参数来请求按相关性排序 $orderBy: "relevance" to fetchPage()。Python 没有文档记载的等价实现；相反，传递给搜索的邻居数量会限制结果。Python 的 nearest_neighbors 方法返回的对象还带有 _score 字段中，复制在 Quiver 仪表板中定义的对象输入名称。

下面的 TypeScript v2 和 Python 示例接受与 TypeScript v1 示例相同的查询文本和邻居数量，并返回最近的对象。TypeScript v2 函数还额外接收一个 Ontology SDK 客户端作为其第一个参数。

在下面的每个代码片段中，请将每一处 ObjectApiName 替换为您唯一的对象类型。该标识符有时可能显示为 objectApiName 其中首字母为小写。

import { Function, Integer } from "@foundry/functions-api";
import { Objects, ObjectApiName } from "@foundry/ontology-api";
import { TextEmbeddingAda_002 } from "@foundry/models-api/language-models"

export class MyFunctions {
    @Function()
    public async findRelevantObjects(
        query: string,
        kValue: Integer,
    ): Promise<ObjectApiName[]> {
        if (query.length < 1) {
            return []
        }
        const embedding = await TextEmbeddingAda_002.createEmbeddings({inputs: [query]}).then(r => r.embeddings[0]);

        return Objects.search()
                    .objectApiName()
                    .nearestNeighbors(obj => obj.embeddings.near(embedding, {kValue: kValue}))
                    .orderByRelevance()
                    .take(kValue);
    }
}

import { Client, Osdk } from "@osdk/client";
import { Integer } from "@osdk/functions";
import { ObjectApiName } from "@ontology/sdk";

export default async function findRelevantObjects(
    client: Client,
    query: string,
    kValue: Integer,
): Promise<Osdk.Instance<ObjectApiName>[]> {
    if (query.length < 1) {
        return [];
    }

    // nearestNeighbors embeds the query text, so no separate embedding call is needed.
    const page = await client(ObjectApiName)
        .nearestNeighbors(query, kValue, "embeddings")
        .fetchPage({ $pageSize: kValue, $orderBy: "relevance" });

    return page.data;
}

from functions.api import function, Integer
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.objects import ObjectApiName


@function(beta=True)
def find_relevant_objects(query: str, k_value: Integer) -> list[ObjectApiName]:
    if len(query) < 1:
        return []

    client = FoundryClient()
    # nearest_neighbors embeds the query text, so no separate embedding call is needed.
    return list(
        client.ontology.objects.ObjectApiName.nearest_neighbors(
            query=query,
            num_neighbors=k_value,
            vector_property=ObjectApiName.object_type.embeddings,
        )
    )
