使用Palantir提供的模型创建语义搜索工作流

要使用Palantir提供的语言模型， 必须先在您的注册中启用AIP。您还必须拥有使用 AIP开发者功能的权限。使用自定义模型？请改为查看 使用自定义模型创建语义搜索工作流 。

本页说明了使用 Palantir提供的嵌入模型构建概念性端到端语义搜索工作流的过程。

操作说明

首先，您需要生成嵌入向量，并将其存储在具有 vector 类型的对象类型中。然后，您可以在 Workshop中设置语义搜索工作流、构建 AIP Chatbot Workshop小部件 解决方案，或者创建自定义语义搜索函数以用于 Workshop 和 AIP Logic。

先决条件：

  • 生成嵌入向量并创建对象类型

选项：

  • 在Workshop中使用KNN对象集创建简单的语义搜索工作流（无代码）
  • 使AIP Chatbot能够对对象进行语义搜索（无代码）
  • 创建一个跨对象进行语义搜索的函数，供Workshop和/或AIP Logic使用

生成嵌入向量并创建对象类型

我们将使用 Pipeline Builder ，通过 Text to Embeddings 表达式将数据集中的文本嵌入为向量。该表达式接受一个字符串，并使用 Palantir 提供的模型之一将其转换为向量；在本例中，该模型是 text-embedding-ada-002 嵌入模型。

然后可以将这些嵌入作为向量属性添加到本体论中。

如果您希望对使用 Palantir 提供的模型生成嵌入的过程进行更多控制，请参阅 Python 转换中的语言模型。

在 Workshop 中使用 KNN 对象集创建简单的语义搜索工作流（无代码）

KNN 对象集无法按相关性排序。如果您需要有序的结果，请使用 函数方法 （适用于 TypeScript v1 或 TypeScript v2）。这两个版本都支持按相关性排序。

配置 KNN 对象集 （在 Workshop 中）是一种简单的无代码方式，可用于构建语义搜索工作流。

  1. 创建对象集 变量 并选择包含嵌入属性的对象类型。
  2. 选择筛选器 + On a property 选项，然后从菜单的属性列表中选择您的嵌入属性。
  3. 选中后，应会出现 K 最近邻配置。如果未出现此配置，请确认您选择的属性是嵌入属性。

在此面板中，您可以配置：

  • K 值： 一个介于 1-100 之间的数字，用于指定语义搜索中返回的对象数量。
  • 查询： 执行语义搜索时用作查询的字符串变量。
  1. 接下来，创建一个 文本输入 部件，并将其输出变量添加到上述 KNN 查询选项中。
  2. 最后，添加一个 对象表 部件，并将其输入变量配置为新创建的 KNN 对象集。

如需进一步自定义语义搜索逻辑，请参阅 关于函数的章节。

使用 AIP Chatbot（无代码）

AIP Chatbot（前身为 AIP Agents）是在 AIP Chatbot Studio 中创建的，非常适合用来开始对您的对象进行语义搜索，因为它们无需编写任何代码。如需了解更多，请参阅 在对功能进行更多控制的情况下集成语义搜索。

请按照 入门 指南中的说明操作，创建 AIP Chatbot，并添加 本体论上下文 或 本体论语义搜索 工具。此初始设置将使您能够要求 AIP Chatbot 对对象进行语义搜索。

创建一个函数来跨对象进行语义搜索，以便在 Workshop 和/或 AIP Logic 中使用

创建一个 函数仓库 ，并创建一个用于查询您的对象类型的函数。目标是获取用户输入并运行 KNN 搜索 针对该对象类型。在 TypeScript v1 中，要生成向量，首先需要使用同一个 Palantir 提供的模型 （即之前使用的模型）。要了解如何将 Palantir 提供的模型导入 TypeScript v1 函数，请参阅 TypeScript v1 函数中的语言模型。TypeScript v2 和 Python 以文本形式接受查询，如下所述。

为函数启用向量属性

在继续之前，请确保该条目 "enableVectorProperties": true 存在于 functions.json 文件中，该文件位于您的 Functions 代码仓库中。如果此条目不存在，请将其添加到 functions.json 中，然后提交更改以继续。如需进一步帮助，请联系您的 Palantir 代表。

该 functions.json 配置文件是 TypeScript v1 仓库特有的工件。对于 TypeScript v2 或 Python 仓库，文档中并未记录等效的向量属性设置，因此请勿假定此条目也适用于这些仓库。如果 KNN 搜索在 TypeScript v2 或 Python 仓库中失败，请联系您的 Palantir 代表。

语义搜索函数示例

本节中的代码示例可在 TypeScript v1、 TypeScript v2和 Python 函数中使用；请选择与您的函数版本相匹配的选项卡。TypeScript v1 将每个函数定义为导出类上的一个方法，将 @Function() 装饰器（来自 @foundry/functions-api ）应用于该方法，对本体论的查询则通过 Objects.search()。TypeScript v2 使用 export default定义函数，从 @osdk/functions导入类型，并通过一个作为参数传入的 Ontology SDK 客户端来查询本体论。Python 使用 @function 装饰器，并在函数体中构造一个 Ontology SDK 客户端。如需完整对比，请查阅 TypeScript v1 与 TypeScript v2 的对比。

这三个版本的区别在于查询嵌入向量的生成位置，以及函数必须定义的位置：

  • TypeScript v1 使用 Palantir 提供的嵌入模型对查询本身进行嵌入，然后将得到的向量传递给 nearestNeighbors。该函数是导出类中的一个方法，通常定义在 functions-typescript/src/index.ts中。
  • TypeScript v2 将用户的文本直接传递给 nearestNeighbors，后者接受查询向量或查询文本。无需单独进行嵌入调用，因此两步工作流程合并为一步。该函数必须是 typescript-functions/src/functions 目录中某个文件的默认导出，并且文件名必须与函数名一致；请查阅 编写函数 以了解完整要求。
  • Python 也通过 nearest_neighbors接受文本形式的查询。该方法是一项 Beta 功能，因此函数需要通过 @function(beta=True)来声明。

将嵌入作为单独的步骤来生成，正如 TypeScript v1 示例中使用 TextEmbeddingAda_002.createEmbeddings，没有文档记录的 TypeScript v2 等效功能。此工作流不需要该功能，因为查询文本在 KNN 搜索期间会被嵌入。若要出于其他目的从 TypeScript v2 或 Python 函数中直接调用 Palantir 提供的模型，请查阅 TypeScript v2 和 Python 函数中的语言模型。

各 TypeScript 版本之间的邻居数量限制有所不同。TypeScript v1 将 k 值限制在 0 < K <= 100范围内，而 TypeScript v2 的 numNeighbors 参数取值范围为 1 至 500。

TypeScript v1 在获取前 k 个结果之前，会使用单独的 .orderByRelevance() 调用来对匹配结果进行排序。TypeScript v2 通过将 $orderBy: "relevance" 传递给 fetchPage()来请求按相关性排序。Python 没有文档记录的等效功能；相反，传递给搜索的邻居数量会限制结果数量。Python 的 nearest_neighbors 方法返回的对象还带有 _score 字段。

下面的 TypeScript v2 和 Python 示例接受与 TypeScript v1 示例相同的查询文本和邻居数量，并返回最近邻对象。TypeScript v2 函数还会额外接收一个本体论 SDK 客户端作为其第一个参数。

在下面的每个代码片段中，请将 ObjectApiName 的每个实例都替换为您特有的对象类型。该标识符有时会显示为 objectApiName ，且首字母为小写。

import { Function, Integer } from "@foundry/functions-api";
import { Objects, ObjectApiName } from "@foundry/ontology-api";
import { TextEmbeddingAda_002 } from "@foundry/models-api/language-models"

export class MyFunctions {
    @Function()
    public async findRelevantObjects(
        query: string,
        kValue: Integer,
    ): Promise<ObjectApiName[]> {
        if (query.length < 1) {
            return []
        }
        const embedding = await TextEmbeddingAda_002.createEmbeddings({inputs: [query]}).then(r => r.embeddings[0]);

        return Objects.search()
                    .objectApiName()
                    .nearestNeighbors(obj => obj.embeddings.near(embedding, {kValue: kValue}))
                    .orderByRelevance()
                    .take(kValue);
    }
}

import { Client, Osdk } from "@osdk/client";
import { Integer } from "@osdk/functions";
import { ObjectApiName } from "@ontology/sdk";

export default async function findRelevantObjects(
    client: Client,
    query: string,
    kValue: Integer,
): Promise<Osdk.Instance<ObjectApiName>[]> {
    if (query.length < 1) {
        return [];
    }

    // nearestNeighbors embeds the query text, so no separate embedding call is needed.
    const page = await client(ObjectApiName)
        .nearestNeighbors(query, kValue, "embeddings")
        .fetchPage({ $pageSize: kValue, $orderBy: "relevance" });

    return page.data;
}

from functions.api import function, Integer
from ontology_sdk import FoundryClient
from ontology_sdk.ontology.objects import ObjectApiName


@function(beta=True)
def find_relevant_objects(query: str, k_value: Integer) -> list[ObjectApiName]:
    if len(query) < 1:
        return []

    client = FoundryClient()
    # nearest_neighbors embeds the query text, so no separate embedding call is needed.
    return list(
        client.ontology.objects.ObjectApiName.nearest_neighbors(
            query=query,
            num_neighbors=k_value,
            vector_property=ObjectApiName.object_type.embeddings,
        )
    )
