故障排除参考

本页面介绍 Foundry Rules 的若干常见问题及调试步骤。

错误消息

ReadonlyObjectError

请确保您创建的每个对象都关联了回写数据集。请查看以下步骤中的构建回写数据集部分 编写并运行规则 的文档以获取更多信息。

400: Actions:InvalidParametersForApply

Action 请求中缺少某些必需参数。请验证 Action 是否已正确配置。

自定义属性的提案差异显示不正确

要让提案组件正确显示差异，请按照以下步骤操作：

  1. 在 Workshop 应用中，将 new_<PROPERTY> 属性添加到 按分组的属性 （位于 Proposal Reviewer 组件配置中）。此处无需选择“当前”值。

  2. 如有需要，可编辑属性名称以移除“new”前缀。

  3. 将 foundry-rules.property-diff-for:ID_OF_NEW_PROPERTY 类型类添加到 current 属性（属于 proposal 对象）。类型类由 kind 以及一份 name表征，写作 kind.name。在 foundry-rules.property-diff-for:new_<PROPERTY>的情况下，kind 为 foundry-rules ，名称为 property-diff-for:new_<PROPERTY>.

旧版错误

2022 年 7 月之前，Foundry Rules（之前称为 Taurus）需要额外的配置，并使用了略有不同的概念。以下错误与该流程相关。如果您在 2022 年 7 月之后部署了 Foundry Rules 并遇到以下任一问题，请尝试导航到 Workflow Configuration Editor 以查看工作流中是否存在任何错误。

Taurus:MissingOntologyInformation

此错误表示错误消息中标识的所请求的本体论信息不存在，或者转换没有访问它的权限。请检查以下步骤以修复该错误：

  1. 验证消息中的 RID 或 ID 是否存在于 本体论管理器.
  2. 验证所有对象类型 和 在 Foundry Rules Workshop 应用中使用的关联已通过 Ontology Imports 辅助工具导入到 Project 中，该工具位于 设置 Code Repository 的选项卡中。
  3. 验证所有对象类型的 RID 和 在 Foundry Rules Workshop 应用中使用的关联已列在 @AdditionalInputs 转换代码顶部的部分中。了解更多信息，请参阅 的定义，使用 @AdditionalInputs.
  4. 确保在 Foundry Rules Workshop 应用中使用的所有对象类型和多对多关联的支撑数据集均已 到本体论即代码中。应用程序绝不会因本体论类型的创建方式而被孤立。 到 Project 中，使用 Project References （位于 Project 视图的部分）。这包括由 Restricted Views 支撑的任何对象或关联。

TransformsGradlePlugin:StaticTaurusDependencyDisallowed

此错误表示不再允许在 tau-execution-core 上声明静态版本号依赖。要修复此错误，请将声明的版本更改为版本范围 [0,1[ 而不是静态版本号：

  1. 首先，导航到 分支回退 包含 Foundry Rules 转换的
  2. 启用 “显示隐藏文件和文件夹”.
  3. 在 Project 级别的 build.gradle 文件中，更改以下行 compile "com.palantir.tau-execution:tau-execution-core:0.x.x" to compile "com.palantir.tau-execution:tau-execution-core:[0,1[".
    • 如果还有另一行， compile "com.palantir.tau-grammar:tau-grammar-api-objects:0.x.x"，然后选择 请删除此行.
  4. 提交结果后，检查应能通过。

Taurus:UnknownMeasureName

当传感器对象缺失或转换没有正确的权限时，可能会出现此错误。请检查以下内容以修复该错误：

  • 检查根对象与传感器对象之间关联的 RID 是否已通过 Ontology Imports 辅助工具导入到 Project 中，该工具位于 设置 Code Repository 的选项卡中。
  • 检查根对象与传感器对象之间关联的 RID 是否已列在 @AdditionalInputs 转换代码顶部的部分中。
  • 检查传感器对象的支撑数据集是否列在 @AdditionalInputs 转换代码顶部的部分中。
  • 检查传感器对象的支撑数据集是否 到本体论即代码中。应用程序绝不会因本体论类型的创建方式而被孤立。 到 Project 中，使用 Project References 项目视图的部分中。

确认您已按照 部署指南.
