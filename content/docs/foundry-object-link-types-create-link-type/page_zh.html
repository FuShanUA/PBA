创建关联类型

我们建议使用下文所述的引导式助手来创建和配置新关联类型。但是，如果您在完成对象创建流程之前退出了该助手，则可以通过为新关联类型指定关联类型、键和 API 名称来手动完成该流程。

访问关联类型创建助手

导航到本体论管理器。要访问关联类型创建助手，请选择以下方法之一：

  • 选择 新建 （位于右上角），然后选择 关联类型。



  • 在左侧边栏中，选择 关联类型 （位于 资源下）。然后，选择 新建关联类型 （位于 关联类型 页面右上角）。

  • 导航到要关联的对象类型，然后选择 创建新关联类型 （位于对象类型 概览 页面上的关联类型图中）。



配置新关联类型

新关联类型助手将引导您完成以下步骤：

  • 选择关系类型
  • 定义关联资源
    • 外键关系类型
    • 联接表数据集关系类型
    • 支撑对象关系类型
  • 定义关联类型名称
  • 保存位置
  • 将更改保存到本体论

选择关系类型

  1. 在 创建新关联类型 对话框中，请为该关联选择关系类型。

  2. 请选择用于定义两个对象之间关联的关系类型：

    • 对象类型外键： 支持“一对一”和“多对一”基数的关联类型。此选项允许您选择表示所需对象外键及相应主键的属性。请参阅下方的 部分，了解 使用外键定义关联资源的详细信息。
    • 连接表数据集： 适用于“多对多”基数的关联类型。此选项允许您使用连接表数据集来支撑该关联。请参阅下方的 部分，了解 使用数据集定义关联资源的详细信息。
    • 支撑对象类型： 对象支撑的关联类型扩展了多对一基数的关联类型，为将对象类型用作关联类型存储解决方案提供一流支持。请参阅下方的 部分，了解 定义由对象支撑的关联资源的详细信息。如需更多信息，请参阅 对象支撑的关联 部分。

在以下示例中，假设有两个通过基数相互关联的对象类型：一个 Aircraft 对象类型和一个 Flight 对象类型。基数类型包括：

  • 一对一基数： 这表示一个 Aircraft 应关联到单个 Flight。一对一基数表明了预期关系，但并不会强制执行一对一基数。
  • 一对多基数： 这表示一个 Aircraft 可以关联到多个 Flights。
  • 多对一基数： 这表示多个 Aircraft 可以关联到一个 Flight。
  • 多对多基数： 这表示一个 Aircraft 可以关联到多个 Flights，而一个 Flight 可以关联到多个 Aircraft。
  1. 选择 下一步 以进入下一步。



定义关联资源

外键关系类型

一个 外键 是某个对象类型上的属性，用于存储另一个对象类型的主键值，表示这两个对象类型之间的现实世界关系。此概念类似于关系数据库中的外键，即一个表中的列引用另一个表的主键列。在一对一或多对一基数关联类型中，您将为该关联定义外键属性和主键属性。一个对象类型的 外键 属性必须引用另一个对象类型的 主键 属性。

例如， Tail Number 属性是 Aircraft 对象类型的主键，唯一标识每架飞机。该 Flight Tail Number 属性属于 Flight 对象类型是外键,表示分配给该航班的飞机。将在 Aircraft 和 Flight 对象类型之间创建关联,前提是 Tail Number (来自 Aircraft )与 Flight Tail Number (来自 Flight)相匹配。

  1. 在 关联资源 步骤中,为您的关联选择对象类型。

  2. 从右侧的下拉菜单中选择主键对象类型(在我们的示例中为Aircraft )。

  3. 从左侧的下拉菜单中选择外键对象类型(在我们的示例中为Flight )。创建对话框将检测并自动选择外键,前提是满足以下条件:

    • 外键与所关联对象类型的主键相匹配。
    • 两个对象的属性类型相匹配。

  4. 选择将构成关联的属性:

    • 对于外键对象类型,选择将用作源对象类型外键的属性(Flight Tail Number 用于 Flight 对象类型)。
    • 由于每个对象类型只有一个主键,因此会自动选中该对象类型的主键(Tail Number 用于 Aircraft 对象类型)。

  5. 选择 下一步 以继续。



联接表数据集关系类型

在多对多基数关系中，请选择一个数据源，其中包含第一个对象类型主键（Aircraft 在我们的示例中）与第二个对象类型主键（Flight 在我们的示例中）之间所有链接组合。

需要支撑数据源的多对多基数关系是使用户能够 编辑或写回 关联类型所必需的。

  1. 在 关联资源 步骤中，为您的关联选择对象类型。
  2. 从左侧下拉菜单中选择第一个对象类型（Flight）。
  3. 从右侧下拉菜单中选择第二个对象类型（Aircraft）。
  4. 选择连接表数据集。请选择一个包含与所选两个对象类型的主键相匹配的列的数据集。一个列只能映射到一个主键。
    • 现在可以为新的关联类型自动生成连接表。 生成连接表 选项将根据您选择的两个对象类型的主键创建一个具有正确架构的数据集。这意味着，如果您有用户编辑支撑的数据，或者希望稍后提供生产数据，都可以更快地开始使用。
  5. 选择关联类型的支撑数据源中哪些列映射到每个被关联对象类型的主键。
  6. 选择 下一步 以继续。



支撑对象关系类型

在创建由对象支撑的关联之前，请确保 前置 对象和关联已创建。

  1. 选择在先决条件中创建的对象类型，以表示所需的关联类型。左侧和右侧的对象表示将要关联在一起的两个实体。中间的对象充当中介，提供有关这两个实体之间连接的额外元数据，并支撑该关联。
  2. 如果左侧和右侧的对象与中间的中介对象之间存在多个关联，请使用下拉菜单选择左右对象与中介对象之间所需的关联。



定义关联类型名称

  1. 在 关联类型名称 步骤中，为新关联类型提供显示名称和 API 名称。
  2. 为关联类型的每一端输入显示名称。关联类型恰好有两端，分别对应其所关联的两个对象类型，每一端表示该关联 指向 该对象类型。在我们的示例中， Aircraft 对象类型的显示名称描述了从 Flight 到 Aircraft的关联。您可以选择显示名称 Assigned Aircraft ，因为一个 Flight 有一个 Assigned Aircraft。由于同一关联类型的两侧是一起配置的，因此可以在任一方向遍历该关联类型；无需为相反方向定义单独的关联类型。请参阅 方向性 以了解更多详情。
  3. API 名称将根据显示名称自动生成，但如有需要，您可以对其进行修改。
    • API 名称字段用于在代码中以编程方式引用关联类型。关联类型某一侧的 API 名称可用于返回该类型的对象。例如，如果关联类型 Aircraft 侧的 API 名称为 assignedAircraft，则调用 Flight.assignedAircraft.get() 将返回 Aircraft 对象，这些对象关联到那些 Flight 对象。
    • 关联类型 API 名称 必须 遵循以下要求：
      • 以小写字母开头，且仅由字母数字字符组成。
      • 在与同一对象类型关联的所有关联类型中保持唯一。
      • 长度在 1 到 100 个字符之间。
      • 经过 NFKC 规范化。
      • 不是保留关键字。
    • 了解有关 API 名称的更多信息。
  4. 选择 下一步 以继续。



保存位置

在最后一步中，选择一个用于保存此关联类型的项目。然后， 提交。完成这些步骤后，您的新关联类型将被创建，但尚未保存。

保存对本体论的更改

返回 Ontology Manager 后，选择右上角的 保存 以 将更改应用到您的本体论。

对象支撑的关联

对象支撑的关联类型在多对一基数关联类型的基础上进行了扩展，为将对象类型用作关联类型的存储解决方案提供一流支持。对象支撑的关联类型允许在关联上包含额外元数据，并支持受限视图。

对于对象支撑的关联，除了 Aircraft 和 Flight 对象之外，还需为 Flight Manifest假定一个额外的对象类型。借助对象支撑的关联，您可以使用 Flight Manifest 对象类型来关联 Aircraft 和 Flight 对象。与外键或数据集支撑的关联不同，该 Flight Manifest 对象可以包含额外属性，例如 Pilot 和 First Mate ，以提供有关该关联的额外元数据。

创建对象支撑的关联类型的前提条件

在创建对象支撑的关联类型之前，您必须先完成以下操作：

  1. 创建关联类型两侧的对象类型。请参阅 创建对象类型 以了解更多详情。
  2. 创建将两个对象类型关联在一起的支撑对象类型。
  3. 创建关联类型的每一侧与支撑对象类型之间的多对一关联类型。请参阅 配置新的关联类型 以了解更多详细信息。

对于 Aircraft、 Flight和 Flight Manifest 示例（如上所述），您需要创建以下资源：

  1. 创建关联类型两侧的对象类型。
    1. Aircraft 对象类型
    2. Flight 对象类型
  2. 创建将两个对象类型关联在一起的支撑对象类型。
    1. Flight Manifest 对象类型
  3. 创建关联类型的每一侧与支撑对象类型之间的多对一关联类型。
    1. 关联： Aircraft 对象类型与 Flight Manifest 对象类型
    2. 关联： Flight 对象类型与 Flight Manifest 对象类型

创建这些资源后，即可创建对象支撑的关联类型。

将现有关联转换为对象支撑的关联类型

现有关联可以转换为对象支撑的关联类型。在修改现有关联之前，必须满足 前提条件 （针对对象支撑的关联类型）。

要修改现有关联的关联类型：

  1. 在 Ontology Manager 中打开该关联。
  2. 在 配置 部分，更新联接方法并选择 对象类型。
  3. 在以下位置选择支撑对象类型： 将关联类型更新为对象支撑的关联类型 对话框。
  4. 在 将关联类型更新为对象支撑的关联类型 对话框中，选择从关联边到支撑对象的关联类型。
  5. 选择 更新为对象支撑。

使用对象支撑的关联类型

目前，对象支撑的关联类型可在 Object Explorer、Vertex 和 Workshop 中查看。选择某个关联，即可查看该关联的支撑对象属性。请注意，在 Vertex 中，关联标题将改为显示该关联的支撑对象标题。

故障排除

错误： Phonograph2:DatasetAndBranchAlreadyRegistered

如果您收到错误 Phonograph2:DatasetAndBranchAlreadyRegistered，则支撑您尝试保存的关联类型的数据源已在本体论中支撑另一个不同的关联类型，无法再次使用。
