从对象存储 v1 (Phonograph) 迁移到对象存储 v2

对象存储 v2 (OSv2) 的改进所需的架构变更 改进 要求将对象存储 v1 (Phonograph) 中带有连接表的对象类型和多对多关联类型迁移到对象存储 v2 (OSv2)。

从对象存储 v1 迁移到 v2 对所有对象类型而言是 强制性的 。 本体论管理器 为对象类型和多对多关联类型的迁移提供了一个集成框架。

Foundry 本体论不要求一次性迁移所有对象类型和多对多关联类型。它可以在部分对象类型仍位于对象存储 v1 (Phonograph)、部分位于对象存储 v2 (OSv2) 的情况下正常运行。Foundry 的 本体论管理器 还支持 批量迁移本体论类型.

运行迁移前的注意事项

迁移行为

  • 对对象类型的本体论定义进行的任何可能导致 Funnel 替换管道 的更改都将中止任何正在进行的迁移。为避免这种情况，请确保对象类型架构在整个迁移过程中（包括浸泡期）保持稳定，并在 然后 启动迁移之前执行任何架构更改。
  • 对象存储 v1 (Phonograph) 的注册会在 Ontology Manager 中保存的任何更改时同步更新。但是，Funnel 会异步记录本体论定义的更改，因此在 Ontology Manager 中保存本体论更改与 Funnel 检测到该更改之间存在延迟。因此，诸如 start or abort 之类的迁移事件可能会在保存本体论后延迟几秒钟才出现在 Ontology Manager 中。
  • 对象存储 v1 (Phonograph) 支持通过对象存储 v1 (Phonograph) 编辑 API 直接编辑对象和关联类型。此交互方式已被弃用，且与 OSv2 不兼容。在为包含用户编辑的对象类型启动迁移之前，请确保您的 使用方式是兼容的。然后，在 Ontology Manager 中找到该对象类型并导航到 数据源 选项卡。打开 Only allow edits via actions 以解除该对象类型迁移的阻止。
  • 在从迁移定义开始的整个迁移期间（包括浸泡期），用户编辑将被自动禁用。在迁移过程中无法发布新的用户编辑，但对象读取仍可正常访问，不会中断。
  • 迁移提供了保留对象类型编辑历史和归属信息的选项。
    • 启用此选项将在迁移过程中包含编辑历史，这会产生额外的处理和存储计算成本。
    • 如果未启用保留编辑历史的选项，则在迁移过程中将不会保留对象类型的编辑历史和归属信息，并且只会将对象存储 v1 (Phonograph) 中每个对象实例的最新状态迁移到对象存储 v2。迁移完成后，将无法从对象存储 v1 (Phonograph) 恢复完整的编辑历史。用户需要确认，在迁移到对象存储 v2 时，用户编辑（操作）的历史记录将不会被保留，但操作日志除外。
  • 迁移带有小数属性的对象类型时，可能需要执行额外的操作来设置小数的精度或标度。如果对象包含小数属性，或者需要在该属性上设置小数的精度或标度，则可能出现以下错误：
    • 错误： The current version of the object type has an invalid definition which Object Storage v2 is unable to index. ObjectsDataFunnel:DecimalPropertyTypeMissingPrecisionOrScale 在配置迁移到对象存储 v2 时
    • 错误： Precision does not match backing column.
    • 错误： Scale does not match backing column.
  • 要解决这些与带有小数属性的对象类型相关的错误，请按照以下步骤操作：
    1. 在 Data Connection 中导航至 属性 在 Ontology Manager 中的选项卡。
    2. 选择出现错误的属性。
    3. 为该属性设置所需的精度和标度值。使用 修复 按钮将根据您的支撑数据自动设置精度和标度值。

不兼容的使用方式

对象存储 v2 中的某些交互被视为 流重新部署是指从之前保存的检查点恢复流处理作业的过程。当流处理作业暂停或停止时，会在数据中创建一个书签，指示已读取记录的位置。在流运行期间，也会定期创建书签（也称为检查点）。这使得在流因任何原因遇到故障时能够进行恢复。 并且它们与对象存储 v2 不兼容。此类不兼容用法会被跟踪并在 本体论管理器中进行报告。选择 不兼容的使用方式 警报将提供过去 30 天内任何不兼容用法的可视化，以协助修复。如果 不兼容的使用方式 视图无法访问，请联系您的 Palantir 代表以启用此功能。

非阻塞性的不兼容用法

某些不兼容用法，例如直接调用对象存储 v1（Phonograph）端点的 API 调用，不会阻止启动向 OSv2 的迁移，但在对象类型迁移到 OSv2 之后会失败。

您应调查不兼容用法并确定是否需要采取行动，例如将直接的对象存储 v1（Phonograph）调用迁移到 对象集服务（Object Set Service） 以进行对象查询/读取， 操作 以进行对象编辑，以及 本体论元数据服务（Ontology Metadata Service） 以获取对象类型元数据信息。如果这些不兼容用法已不再相关，或者可以在无不良后果的情况下失效，您可以在不进行修复的情况下启动迁移。

阻塞性的不兼容用法

OSv1 与 OSv2 之间的其他差异（例如未启用仅通过操作进行编辑）将主动阻止在 Ontology Manager 中进行迁移。

在这种情况下，您必须在开始迁移之前移除所有不兼容用法。

无不兼容用法

没有任何不兼容用法或破坏性变更的对象类型将在横幅中显示绿色对勾图标，表示该对象类型已准备好进行迁移。

迁移实体

启动迁移

要启动迁移，请导航到您的 数据源 对象类型或带有联接表的多对多关联类型的选项卡，然后转到 索引元数据 部分。如果该对象类型符合迁移条件，您将能够选择对象存储 v2 单选按钮，这将打开一个用于选择迁移参数的向导。如果此部分不存在，则您很可能正在使用一个对所有对象类型和联接表关联类型强制使用对象存储 v2 的本体论。

本体论元数据服务会跟踪由对象存储 v1（Phonograph）支撑的对象类型的不兼容用法。当您尝试迁移具有不兼容用法的对象类型时，它会触发警报。您还必须确保对象类型架构不包含任何破坏性变更。

过渡时间窗口

直方图 过渡时间窗口 选项允许您为安全迁移设置首选时间窗口；例如，您可能希望设置一个星期几和时间，使对象类型的使用场景在该时段活动最少。请注意，迁移过程开始后，启动第一个 Funnel 管道可能需要长达 30 分钟。只有在第一次同步到 OSv2 成功完成后才会计算过渡时间窗口，因此在同步完成时已在进行中的窗口不符合条件。如果迁移无法在第一个过渡时间窗口内完成，则对象集服务将等待下一个窗口才开始从 OSv2 读取数据。

如果未设置过渡时间窗口，则迁移将在第一个 Funnel 管道成功后立即开始。

已禁用的操作类型

在迁移期间，用户将无法应用编辑，因为从迁移定义的那一刻起，在整个迁移期间（包括浸泡期）内编辑将被自动禁用。对象读取将保持可访问，不会中断。

浸泡期

如果您在迁移过程中需要回退到对象存储 v1（Phonograph），这是可行的，无需在此期间对数据重新建立索引 浸泡期。迁移框架将使对象存储 v1（Phonograph）索引与对象存储 v2（OSv2）保持同步，直到浸泡期结束。浸泡期可以按天为单位进行设置，最长为 14 天（可以选择指定小时数），并且只有在迁移通过过渡窗口后才会开始。将浸泡期设置为 0 天意味着，一旦 OSv2 索引就绪且过渡窗口被激活，该对象类型的 OSv1 索引将立即被删除。

在浸泡期内，Foundry 本体论后端会自动将所有查询路由到 OSv2，任何对 OSv1 的请求都将被拒绝。您可以使用这段时间来验证读取对象类型的工作流在迁移后是否按预期工作。如果您在浸泡期内遇到任何问题，可以 中止迁移 以立即切换回使用 OSv1 索引。

浸泡期结束后，将无法回滚到 OSv1。如有任何疑问，您可以联系 Palantir Support。

在浸泡期内，对象类型将在 OSv1 和 OSv2 中进行双重索引；这将产生额外的计算和存储开销。如果您希望避免额外的资源使用，可以在配置迁移时将浸泡期设置为 0 天。

迁移回写数据集

在对象存储 v1（Phonograph）中， 回写数据集 是启用对象类型或带联接表的多对多关联类型的用户编辑所必需的。对象存储 v2 用 物化数据集取代了回写数据集。对象存储 v2 不需要物化数据集来启用用户编辑。在 OSv2 中物化数据集是可选的，只有在下游使用需要时，您才需要创建物化。

对象和关联类型的回写数据集可以在 OSv2 中作为物化数据集进行迁移。物化数据集将保留相同的列，与现有的下游管道保持兼容。此开关仅在您于其他应用中使用当前回写数据集时才有意义。如果您选择不迁移回写数据集，该数据集本身不会被删除；相反，该数据集将是静态的，并包含上次构建时的数据。用户编辑仍将迁移到 OSv2。

如果回写数据集包含未映射到任何对象类型属性的列，这些列将在迁移过程中被丢弃。

中止迁移

如果在切换到对象存储 v2 后发现性能回退或遇到错误，您可以在浸泡期内安全地中止正在进行的迁移并回退到 OSv1。在整个迁移过程中，迁移框架会确保 OSv1 索引与任何新的数据同步保持最新。

如果正在迁移的对象类型存在现有的用户编辑，则在迁移完成之前，任何新的用户编辑都将被禁用。

同步失败

您的对象类型在迁移过程中可能无法同步。如果是这种情况，您将在对象类型的 PIPELINE_FAILED 部分看到错误，位于对象类型的 索引元数据 标签页中。如果发生这种情况，请按照 数据源 调试漏斗批处理管道 的说明进行操作，以调查并解决该问题。 批量迁移

批量迁移

您可以通过导航至左侧导航栏中的 ,其中显示地图上各对象类型的对象数量。下方,每种属性类型各有一个部分,涵盖地图上存在的所有对象类型。面板顶部的筛选框允许您将结果筛选为名称匹配的属性。 部分并同时选择多个对象类型，来使用相同的过渡窗口和浸泡时间配置批量运行迁移。该流程和设置向导与迁移单个对象类型时相同。我们建议采用渐进式迁移，每次批量迁移少于 100 个实体，以防止出现意外复杂性或错误。

对于仅启用 OSv2 的本体论，此向导将不会显示在界面中。
