设置和使用实时部署

A 实时部署 是一种持久、可扩展的部署，用于承载您的发布版本，您可以通过 API 端点与其交互。 实时部署可以与您的批量部署一起在建模目标中进行管理，享受自动升级、可观测性和权限结构等所有相同的好处。 现在也可以直接在模型页面上配置实时部署 ，而无需目标。

要求

在创建新的实时部署之前，建模目标必须包含带有相应标签的现有发布版本（ Staging or Production).

创建部署

要创建新的实时部署，请导航至 部署 部分（位于建模目标底部），然后选择蓝色的 + 创建部署 按钮。

填写部署名称、描述，以及此部署应基于当前的预发布（staging）还是生产（production）已发布模型。配置完成后，选择 创建部署.

选择新创建的部署以打开详情页面，您将看到中间状态，表明包含最新发布版本和推理代码的容器镜像正在部署中。

发布函数

您可以为该部署发布一个 函数 ，从而支持在 来运行该专业代码代理。你还可以通过, 和及其他最终用户应用中使用模型进行实时推理。

要发布函数，请导航至部署的 详情 页面并选择 发布函数。这将创建一个与您的模型具有相同输入和输出 API 的包装函数，可以 从函数仓库中导入并调用 以添加自定义业务逻辑。

有关函数行为、版本升级和配置选项的详细信息，请参阅 模型函数开发者指南.

状态与健康

部署完成更新后，状态和健康应均显示为绿色对勾。这表示部署已准备好接受查询，并且已成功更新为包含最新发布的模型。

测试实时部署

您可以通过部署详情页面上的 查询 标签页来测试实时部署端点。您可以编写输入请求，将其发送到实时端点，并查看模型输出响应。有两种可用的查询类型：单 I/O 和多 I/O。

单 I/O 查询仅支持单个表格输入/输出，而 多 I/O 查询仅支持 ModelAdapter API （在模型资产中定义）。模型资产同时支持单 I/O 和多 I/O 查询类型，而基于数据集的部署仅支持单 I/O 查询。

部署操作

管理操作

对正在运行的实时部署可以执行两种操作：

  • 禁用 以关闭部署，但仍允许重新启用以利用相同的 目标 RID.
  • 删除 以完全移除部署。旧的目标 RID 将不再能够被查询。

已禁用的实时部署仍会显示在目标的部署页面上，并且可以再次启用。

资源配置

实时部署配置了最小和最大副本范围，可根据请求量以及 CPU 和 GPU 数量实现自动水平扩展。

您可以在创建部署时配置资源需求，也可以在事后进行编辑。编辑运行时配置将自动触发部署的重新运行，并在无停机的情况下升级端点。

要配置新的实时部署，请选择 创建部署中，选择 实时 位于 部署类型，然后输入最小和最大副本范围以及资源配置。

要编辑已配置的副本范围和资源，请导航至 部署 建模项目中的部分，从列出的部署中选择您的部署，然后选择下方的编辑按钮 运行时配置 以编辑副本范围或资源配置。

查看部署服务日志

每个实时部署都会发出一系列描述部署启动进度的日志；这些日志包括部署将尝试下载和安装的发布环境中 Conda 包的 URI，以及下载模型本身的详细信息。如果部署未能成功启动，可能会有相关的警告或错误级别日志，帮助您了解发生了什么。

要直接从正在运行的实时部署查看服务日志，请导航至 日志和指标 部署详情页面上的选项卡。您可以指定要搜索的时间窗口，按任意字段筛选日志，以及在视图中添加或删除列。您还可以使用右上角的下载按钮将所有日志下载为文本文件。

由于您可能已将部署配置为使用多个副本运行，您可能会看到看似重复的日志——每组日志来自不同的副本。但是，每条日志都包含一个带有唯一 node_id 的标签，如有需要，您可以使用它按副本进行筛选。您可以使用以下表示法：

查看部署指标

直方图 日志和指标 选项卡提供两种类型的指标： Kubernetes 主机 和 推理容器。请务必了解这些指标类型之间的区别，以便正确监控和调试您的模型。

Kubernetes 主机指标

Kubernetes 主机指标显示主机上运行的所有进程所使用的内存和 CPU 使用率百分比，而不仅仅是与特定模型相关的进程。这些指标对于调试与调度和资源限制相关的问题非常重要。例如，如果您的模型性能缓慢但主机指标达到 100%，则您的模型可能正受到 Kubernetes 主机的限制。

推理容器指标

推理容器指标有助于调试 Python 模型和模型适配器逻辑中的资源使用情况。这些指标提供推理容器的确切内存使用量和 CPU 核心使用量，独立于整个 Kubernetes 主机。目前，基于容器的模型不提供使用指标。

如果您只能查看 Kubernetes 主机指标而无法查看推理容器指标，则您的容器可能运行在过时的实时部署版本上。请重启您的实时部署以更新版本并查看所有指标。

Spark 模型支持

测试版

支持的 Spark 版本可能会在即将发布的版本中发生变化，并且不保证向后兼容。如果您的模型与当前 Spark 版本不兼容，您可能需要重新构建它。

所有实时部署现在在初始化时都安装了 JDK 和 Spark 发行版。这使得 Spark 模型能够与实时部署兼容。在此交互式环境中，仅支持本地 Spark，这意味着所有处理都在单个 JVM 内完成。

如果您的模型需要 Spark DataFrame 输入，则更可能出现数据转换问题，因为请求是以 JSON 格式发送的。在开发需要 Spark 数据帧的自定义模型时，您应该在前处理阶段或直接在 transform 函数中手动执行此转换。以下是一个简单的示例：

import pandas as pd
from pyspark.sql import SparkSession

def _transform(model, df):
    if isinstance(df, pd.DataFrame):
        df = SparkSession.builder.getOrCreate().createDataFrame(df)
    return model.predict_spark_df(df)
