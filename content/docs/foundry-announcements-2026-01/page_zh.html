使用 Foundry Branching 安全地开发和测试对象视图

Foundry Branching 现已支持对象视图，使您能够在隔离环境中开发和测试对象视图变更，然后再将其部署到生产环境。

对象视图是本体论与最终用户之间的关键接口。通过分支功能，您可以更安全地进行迭代：在隔离环境中测试变更、与多个团队协作而互不冲突，并在部署前确保质量——所有这些都使用您已在 Workshop 模块和本体论资源中使用的相同工作流。

核心功能：

  • 基于分支的开发： 在分支上添加、删除和修改对象视图，安全地迭代结构性变更（标签页、可见性条件）和内容变更（Workshop 模块），而不会影响生产环境。
  • 跨应用程序测试： 在 Workshop 应用程序中嵌入分支上的对象视图，并在本体论管理器中预览这些视图，以便在合并前验证更改。
  • 冲突解决： 当更改出现在 main上时，请变基您的对象视图。系统会显示一个直观的对话框，自动解决非冲突的更改，并引导您解决冲突。

Foundry 分支上的对象视图及其关联（已修改）Workshop 模块的示例。此处，该分支上仅修改了一个名为 "Museum" 的对象类型。"Full Object View Tabs" 资源表示对象视图本身的结构性更改。"Full Object View • Museum History" 和 "Panel Object View" 资源表示该对象视图所使用的 Workshop 模块的更改。

当您的分支与 main 之间检测到冲突时，系统将提示您进行变基，并显示此对话框以解决冲突。

已知限制：

  • 目前尚不支持审批，因此分支上的所有对象视图更改都会自动获得批准。
  • 旧版对象视图选项卡无法在分支上编辑。

入门

若要将对象视图添加到分支，请在对象视图编辑器中的分支上保存对象视图版本，该编辑器可通过本体论管理器访问。有关使用分支对象视图的详细指南，请参阅 文档。

Workflow Lineage 中新增的运行历史筛选功能

发布日期：2026-01-29

您现在可以筛选 运行历史 ，以便在 Workflow Lineage 中快速查找函数、操作、自动化和逻辑的特定执行记录。 运行历史 标签页提供过去七天内所有执行记录的完整视图，并且按多个条件进行筛选，可在执行量较大的环境中更快地调试问题或审核工作流。

可用筛选条件

按以下条件的任意组合筛选运行历史记录：

  • 状态：成功或失败的执行
  • 时间戳范围：指定日期范围内的执行
  • 用户：由特定用户触发的执行
  • 运行时间范围：在指定持续时间范围内的执行记录
  • 版本：针对指定版本的执行记录（仅限函数）
  • 调用方：源自指定资源的执行记录
  • 失败类型：因特定原因而失败的执行记录

按时间戳、运行时和调用方 RID 筛选的函数执行运行历史。

按状态和失败原因筛选的逻辑执行运行历史。

当您指定多个筛选条件时，结果将仅包含符合所有指定筛选条件的执行。例如，查找过去 24 小时内由特定用户触发的失败执行，或识别超出特定持续时间阈值的长时间运行的执行。

此功能在所有注册中均可用。请查阅 文档 以了解有关筛选运行历史的更多信息。

在 DevOps 中通过跟踪源文件夹自动打包资源

发布日期：2026-01-29

在 DevOps 中跟踪源文件夹，您可以自动打包 Compass 项目或文件夹中的所有资源。无需手动维护各个资源，每次发布新版本时，DevOps 都会自动包含源文件夹中的资源。

当您拥有一个明确定义的项目，且该项目反映了您希望在产品中包含的资源时，跟踪源文件夹有助于简化新产品的发布流程。

DevOps 的新产品落地页现在提供跟踪源文件夹的选项。

配置选项

对于 Compass 文件系统中不存在的文件，您可以使用文件夹设置来额外跟踪相关资源。例如，您可以跟踪文件夹中数据集上的所有健康检查，或文件夹内代码仓库中定义的函数。您还可以通过配置忽略的子文件夹来排除不应打包的资源，例如实验性工作。

为了增加灵活性，您可以组合使用手动添加的输出和文件夹跟踪的输出。这允许您手动添加 Compass 文件系统中不存在且未被设置涵盖的资源。

跟踪源文件夹时，可以使用多种配置设置。

迁移现有产品以跟踪源文件夹

如果您的现有产品中的资源是手动添加的，并且这些资源共享同一个 Compass 项目，则可以执行一次性迁移，将您的产品配置为跟踪源文件夹。迁移对话框将向您显示预览，其中包括现在将作为文件夹的一部分进行跟踪的资源，以及由于不在 Compass 文件系统中或未通过文件夹跟踪设置引入而将继续手动跟踪的资源。

如果您决定文件夹跟踪不再适合您的产品，可以切换回手动输出管理，方法是使用 禁用文件夹 跟踪选项。

文件夹跟踪迁移模态框允许您将现有产品迁移为跟踪源文件夹。

在 DevOps 中了解有关跟踪源文件夹的更多信息。

AIP 中的 LLM 现已提供预留容量

发布日期：2026-01-22

对于无地域限制的注册以及部分受美国/欧盟地域限制的注册，许多 LLM 现已默认提供预留容量。预留容量可保护关键生产工作流，使其免受共享项目或注册在令牌和请求方面的限制，从而帮助确保不间断运营。

什么是预留容量？

预留容量允许您在 LLM 上为关键生产工作流预留专用的每分钟令牌数（TPM）和每分钟请求数（RPM），确保其不受共享项目或注册限制的影响。 在文档中了解有关此功能的更多信息。

使用预留容量无需支付额外费用。

如何查看您的预留容量

要查看某个注册中的所有预留容量产品：

  • 导航至 资源管理 > AIP 使用情况和限制 > 预留容量.
  • 从下拉菜单中选择模型以查看可用容量。
  • 如果 预留容量 标签页不存在，则表示您的环境目前无法使用预留容量。

您可以在资源管理中查看预留容量。

当项目达到其预留容量上限时，该项目将使用标准项目和注册限制继续无缝运行。预留容量在您现有限制的基础上提供额外吞吐量，并且仅适用于由注册管理员专门启用的项目。

  • 批量管理： 在文件夹或项目级别设置权限，即可一次性控制对多个资源的访问，无需再逐项设置权限。
  • 更清晰的可见性： 该 安全 选项卡和侧边栏现在会显示所有资源（包括本体论）的权限和项目上下文。
  • 功能增强： 作为项目资源，本体论可以使用文件夹、访问请求、标记和标签等 Compass 功能。

要将现有本体论资源迁移至基于项目的权限，请查阅 迁移指南。

选择退出此变更

要继续对新本体论使用旧版权限系统，请导航至 配置 标签页，该标签页位于 Ontology Manager 并关闭 新的本体论资源将保存到项目中。

为防止新创建的本体论默认使用基于项目的权限系统，请前往 配置 选项卡（位于 Ontology Manager 中），并关闭 新的本体论资源将保存在项目 设置中。

当前限制

在使用基于分类的访问控制 (CBAC) 或默认本体论时,本体论的项目权限尚不可用。

使用模型上下文协议 (MCP) 将 AI 智能体连接到您的本体论

发布日期：2026-01-13

Ontology MCP 使开发人员能够将 开发者控制台 应用程序公开给 AI 智能体，所采用的模型上下文协议 (MCP) 是一项用于将智能体连接到数据源的开放标准。开发者控制台应用程序中的资源（包括对象、操作和查询）将成为智能体可以发现和使用的工具。此功能既适用于专业代码框架（LangChain、CrewAI、自定义 Python/TypeScript），也适用于低代码平台（Copilot Studio 及其他智能体构建工具）。Ontology MCP 测试版将于 2026 年 1 月底面向所有拥有开发者控制台访问权限的用户推出。

开发者控制台中的 Ontology MCP 配置页面，已选中 Claude Code 智能体。

有哪些新功能？

以前，将 AI 智能体连接到本体论需要为每个源系统和智能体框架构建自定义集成，这要求对框架的 API 模式和 Foundry 的 SDK 都有深入的了解。借助本体论 MCP，您只需配置一次 MCP 服务器，即可连接任何兼容的智能体框架。MCP 协议负责处理身份验证、工具发现和执行。您的 Developer Console 应用程序定义了智能体可以访问哪些资源，而 MCP 可确保智能体只能与您明确公开的资源进行交互。

何时使用本体论 MCP

  • 您正在构建需要与本体论数据或操作交互的 AI 智能体
  • 您希望支持多个智能体框架，而无需维护单独的集成
  • 您需要让具有不同开发偏好的团队能够访问相同的本体论资源
  • 您需要对智能体可以访问的本体论资源进行细粒度控制

入门

要开始使用本体论 MCP，请打开您的 Developer Console 应用程序并导航至左侧的 MCP 标签页。选择 启用 MCP 客户端以使用 MCP 连接到此应用程序，并为 MCP 服务器添加支持 Markdown 的描述。然后，从列表中选择您的智能体框架，以查看特定于框架的安装说明

本体论 MCP 与 AIP Agents

本体论 MCP 将本体论访问能力扩展到外部智能体框架。 AIP Agents 在平台内提供原生的智能体构建能力。在平台内工作流中使用 AIP Agents，在将外部框架连接到您的本体论时使用 Ontology MCP。

如需了解有关 Ontology MCP 以及如何在 Foundry 和您的 Developer Console 应用程序中使用智能体的更多信息，请观看 YouTube 视频 ↗ （来自我们 DevCon 4 的演示）。

Data Connection 引入监听器以捕获入站 Webhook

发布日期：2026-01-08

监听器（Listeners）是 Data Connection 的一项新功能，可让您直接在 Palantir 平台中接收入站 Webhook 事件。该功能将于 1 月 5 日当周推出公开测试版。当外部系统缺乏 OAuth 2.0 身份验证支持，或无法将有效负载格式化为符合标准 Foundry API 端点的格式时，将这些系统的实时事件集成到 Foundry 历来颇具挑战。监听器通过预配 URL 端点来弥补这一空白，这些端点实现了特定于系统的消息签名和验证方案（与数据形状无关），从而为接收来自外部源的事件流提供了一种简单、低延迟的机制。

如需更多信息（包括支持的监听器列表和设置指南），请查阅监听器文档。

从 Data Connection 支持的监听器中进行选择，以配置并接收入站 webhook 事件。

监听器的工作原理

为了接收来自外部系统的入站事件，Data Connection 监听器会提供一个 URL 端点，为特定外部系统实现相应的消息签名或其他验证方案，并提供一种简单且低延迟的机制，用于将事件流接收到 Palantir 平台中。结合流式管道、自动化或批量分析来利用监听器输出流，创建功能强大的事件处理工作流。

子域名配置与零停机端点轮换

您可以为监听器生成一个子域名，以建立一个独立的入口点，与 Foundry 租户的其余部分相比，其网络入口范围更广。这样可以将 webhook 流量与其他平台操作隔离，对外部系统连接提供额外的控制，并实现统一治理，同时带来额外的安全优势。

监听器还具备端点轮换功能，可在监听器端点遭到入侵时提供保护。如果 URL 意外泄露，可在零停机的情况下迁移到新端点。轮换端点时，您可以设置过期日期以实现无缝的零停机过渡，也可以在需要更快采取行动时立即删除旧端点。端点一旦过期，便不再处理事件。

数据连接监听器消除了以往阻碍从外部系统实时摄取事件的身份验证和有效负载格式化障碍，从而扩展了 Foundry 的集成能力。

有关更多信息，请参阅监听器子域文档。

监听器入门

注册管理员可以通过在 数据连接 页面中开启相应功能来启用监听器，该页面位于 控制面板。

启用后，用户可以在 Data Connection 应用程序中访问 监听器 选项卡，以将 Palantir 平台连接到外部系统和工作流。
