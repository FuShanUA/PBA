创建新的 Developer Console 应用程序

在本页面中，我们将逐步介绍创建新的 Developer Console 应用程序的以下流程：

  • 将对象类型、操作类型和其他本体论资源添加到 SDK 应用程序。
  • 添加用于访问 Platform API 的操作和资源。
  • 以任何受支持的语言生成软件包。
  • 使用为您的应用程序专属 SDK 生成的自定义文档。

使用 Developer Console 创建应用程序

导航到 Developer Console （在您的 Foundry 实例中），然后选择 + 新建应用程序。

如果您没有看到 + 新建应用程序 按钮，则您可能需要额外的权限。请参阅 权限文档 了解更多详情。

接下来，按照出现的创建向导中的步骤操作，并添加以下详细信息：

  • 在 基本信息 页面上，为您的应用程序添加图标；当用户看到同意屏幕时，该图标将用于标识该应用程序。

  • 在 应用程序类型 页面上，选择 面向客户端的应用程序。

对于使用服务用户的后端服务或服务器端应用程序，请选择 后端服务。请参阅 搭建后端 TypeScript 应用程序 以获取完整的分步说明。

  • 在 授权码模式 部分（位于 权限 页面）中，将重定向 URL 设置为 http://localhost:8080/auth/callback。

请按照 配置 CORS 中的说明，将 http://localhost:8080 添加到您在 Control Panel 中的 CORS 策略。 如果您没有权限配置 CORS，且您的 Foundry 管理员无法为您配置 CORS，请将重定向 URL 设置为 https://localhost:8080/auth/callback。

资源

  • 在 资源 页面中，选择 是，生成本体论 SDK。

  • 选择要使用的本体论。您可以选择任何本体论，而不受命名空间的限制。

请注意，一旦生成本体论 SDK，与之关联的本体论将无法更改。

  • 选择您希望 OSDK 包含的对象类型和操作类型。在本练习中，请选择您可以使用的任意对象类型。

您选择的数据实体将控制应用程序的两个方面：

  • 生成的类型： 将根据所选实体创建特定语言的绑定。此外，还将根据您的选择生成集成的 API 文档。
  • 应用程序令牌： 通过 OAuth 2.0 流程获得的令牌默认仅限于所选的实体集合。有关更多详细信息，请参阅 资源访问限制。
  • 如果您需要使用您的应用程序发起 Platform API 请求 ，请务必添加相应的资源和操作，方法是通过 Platform SDK 标签页。

在 客户端允许的操作 表中授予的操作可能允许应用程序访问底层服务端点。

  • 查看并确认您输入的信息，然后选择 创建应用程序 以创建应用程序。
  • 最后，您必须选择 生成首个版本 以获取所创建软件包的第一个版本。

创建后设置应用程序限制

创建向导中不包含受限或不受限设置。每个应用程序都会被创建为 受限应用程序，这意味着 Developer Console 会控制应用程序可以在 Foundry 中使用的资源和操作。

如果您的应用程序需要的是广泛的平台级访问权限——例如，访问项目之外的资源——请在应用程序创建后更改此设置：

  1. 打开应用程序，然后从左侧导航面板中选择 OAuth 和限制 。
  2. 在 应用程序限制下，选择 不受限。

有关完整的操作步骤（包括创建应用程序时需要做出的身份验证选择），请参阅 创建不受限应用程序。

特定于本体论的文档

Developer Console 会根据您选择的本体论实体生成文档。该文档提供 TypeScript、Python 和 cURL 版本；您可以使用控制台右上角的下拉菜单在不同语言之间切换。

在上面的示例中，每种对象类型、操作类型和函数都有相应的文档说明。文档中包含代码示例，展示了如何返回特定属性或如何使用参数；您可以直接将这些示例复制并粘贴到您的代码中。

后续步骤

  • 设置应用程序限制: 每个应用程序在创建时均处于受限状态。如果您的应用程序需要广泛的平台级访问权限，请更改此设置。
  • 在授权时请求作用域: 在代码中定义您的应用程序所请求的操作。
  • 在 Foundry 上托管您的应用程序: 通过 Foundry 子域提供纯前端应用程序。
