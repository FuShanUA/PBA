自动化历史可见性和范围

自动化可以配置不同的范围选项，以确定谁可以访问操作和逻辑执行的运行历史。

无论采用哪种范围模式，自动化都以所有者身份执行。这意味着：

  • 操作条件：所有者必须满足提交要求（组成员身份和权限）。
  • 计算令牌：函数接收所有者的身份验证令牌。
  • 编辑归属：对象编辑历史和审计日志将更改显示为由所有者执行。
  • 权限：所有本体论读取/写入均使用所有者的访问级别。

项目范围自动化（推荐）

项目范围自动化要求将自动化中使用的所有传递资源导入到项目中。当依赖项发生变化时（例如，操作引用了某个函数的新版本），请更新自动化以重新导入引用并重新生成范围。

如果可能，项目范围模式是自动化的推荐设置。项目范围通过使运行历史（包括效果执行）对所有满足运行标记要求的用户可见，从而支持团队协作。项目范围自动化仍以自动化所有者的身份运行。

限制

项目范围模式目前不支持：

  • 有状态函数，包括：
    • 已部署的 Python 函数
    • AIP 聊天机器人函数
  • 使用平台 SDK 的 Python 和 Typescript v2 函数
  • 通知效果
  • 跨组织工作流

此外，项目范围模式对以下内容的支持有限：

  • 具有 受限视图的对象类型：自动化的所有者以及事件历史的任何查看者都必须有权访问所有行。
  • 具有 对象安全策略的对象类型：更新安全策略后，必须将其重新导入到项目中。

此外，Typescript v1 的依赖计算采用尽力而为的方式，可能会遗漏实体，这意味着依赖关系可能被错误计算。请考虑使用 Typescript v2。

用户范围自动化

在用户范围模式下，只有自动化的所有者才能访问运行历史。为了更好地进行团队协作和调试，建议将自动化设置为项目范围模式。

启用 共享触发历史 后，对条件中的标记数据拥有权限的用户可以看到运行已执行，但效果的执行仍仅对自动化的所有者可见。有关配置和查看共享历史的更多信息，请查阅 共享历史事件 文档。
