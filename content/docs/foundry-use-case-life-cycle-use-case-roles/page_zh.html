用例角色

用例角色旨在利用 Foundry 中的数据开发特定的分析或成果。组织域、项目群团队或单个项目经理都可以管理用例团队。在 Foundry 旅程的早期阶段，由单个项目经理进行管理尤为常见。

域负责人

域负责人不一定属于某个用例团队或角色，但他们是负责特定组织域投资回报率（ROI）成功的组织负责人。这包括大规模的组织域，其中通常包含多个工作流。域负责人与项目群团队成员密切合作，为用例优先级排序讨论提供战略性意见，此类讨论应定期进行。

工作流负责人

工作流负责人负责管理规模经济的生产（通过信息共享，例如已开发的分析和模型，以及本体论表），并确保将适当的能力部署到相邻的用例中（例如，将一组应用程序部署到相同的用户群）。当某个组织的组织域包含大量用例时，此角色就会发挥作用。

用例负责人

用例负责人是与为项目做贡献的工程师并肩工作的项目经理。用例负责人确保技术和组织目标保持一致、遵守平台上开发的最佳实践标准，并与其他项目团队进行协调。

他们负责

  • 用例的 ROI、执行和最终用户采用；
  • 管理项目特定的权限和访问控制；以及
  • 协调团队，确保为最终用户提供项目问题、健康检查、日程安排和应用程序支持。

产品负责人

产品负责人对用例功能的开发路线图和实施负责，这些功能应在规划阶段进行识别、确认和记录。产品负责人是产品开发早期阶段需要参与的关键利益相关者，以确保他们了解组织需求以及产品如何最好地为其最终用户带来价值。产品负责人是希望了解产品开发进展和成果的人员的主要联系对象。

组织/主题专家

组织 SME 从其组织域提供专业知识和指导，以确保项目工作与组织需求保持一致。此人通常是旧有工具的高级用户，深入了解特定问题域的当前工作流、与这些当前操作相关的不足之处，以及关于如何优化用户体验和工作流以最大化 ROI 的想法。

用例开发者

用例开发者是负责用例开发的工程师和分析师。他们使用来自本体论层的数据。用例开发者通常根据项目范围拥有不同的专长，包括：

  • 数据分析师：
    • 对临时分析和模板化分析、报告、可视化和仪表板进行界定、设计和实施，以回答关键问题。
    • 在管道构建过程中执行一次性的质量和一致性检查。
  • 数据工程师：
    • 编写数据集的转换、优化和操作，以满足用例及其成果的需求。
    • 在一个或多个项目中监控和管理最重要的数据集，遵守中央项目群团队的指导原则。
    • 根据定义的贡献流程向本体论做出贡献。
  • 数据科学家/机器学习专家：
    • 执行建模、机器学习、分类和回归，以丰富和可视化数据，为决策工作流提供支持。
  • 应用程序开发者：
    • 在以下工具中开发决策驱动的界面 来运行该专业代码代理。你还可以通过, 将收集到的信息存储在, 的流可在日 对象资源管理器r.

    • 使用 Foundry Gateway API 通过第三方工具构建外部应用程序。

所需用例开发人员的数量在很大程度上取决于各个用例的目标和需求，以及可用用例开发人员的技能组合。

最终用户

最终用户和自助服务用户在已开发的工作流、应用程序或数据制品中工作，以履行其日常组织职责，包括临时分析、报告、运营改进和日常决策。
