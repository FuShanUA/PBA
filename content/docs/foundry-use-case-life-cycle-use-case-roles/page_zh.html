用例角色

用例角色旨在利用 Foundry 中的数据开发特定的分析或成果。组织域、项目群团队或单个项目经理均可管理用例团队。在 Foundry 之旅的早期阶段，由单个项目经理进行管理的情况尤为常见。

域负责人

域负责人不一定属于某个用例团队或担任特定用例角色，但他们是负责确保特定组织域投资回报 (ROI) 取得成功的组织负责人。这包括规模化的组织域，此类域通常包含多个工作流。域负责人与项目群团队成员密切合作，为用例优先级排序讨论提供战略性意见，此类讨论应定期进行。

工作流负责人

工作流负责人负责管理规模效益的产出（通过信息共享，例如共享已开发的分析和模型以及本体论表），并确保将合适的能力部署到相邻用例中（例如将一组应用程序部署到同一用户群体）。当特定组织的组织域包含相当数量的用例时，此角色便能发挥重要作用。

用例负责人

用例负责人是与参与项目的工程师并肩协作的项目经理。用例负责人确保技术与组织目标保持一致、遵守平台上开发工作的最佳实践标准，并协调其他项目团队之间的合作。

他们负责

  • 用例的投资回报率（ROI）、执行以及最终用户采纳情况；
  • 管理特定于项目的权限和访问控制；以及
  • 协调团队，确保为最终用户提供项目问题处理、健康检查、时间安排和应用程序支持。

产品负责人

产品负责人对开发路线图和用例功能的实现负责，这些内容应在规划阶段予以识别、确认和记录。产品负责人是需要在产品开发早期阶段参与其中的关键利益相关者，以确保其了解组织需求以及产品如何才能最大程度地惠及最终用户。对于希望了解产品开发进展和成果的人员而言，产品负责人是主要的联系对象。

组织/领域专家

组织级 SME 从其所在组织领域提供专业知识和指导，以确保项目工作与组织需求保持一致。这类人员通常是旧有工具的高级用户，深入了解特定问题领域的现有工作流程、与这些现有操作相关的不足之处，以及关于如何优化用户体验和工作流以实现 ROI 最大化的见解。

用例开发者

用例开发者是负责用例开发的工程师和分析师。他们使用来自本体论层的数据。用例开发者通常根据项目范围拥有不同的专业方向，包括：

  • 数据分析师：
    • 规划、设计和实施临时分析与模板化分析、报告、可视化和仪表板，以回答关键问题。
    • 在管道构建过程中执行一次性的质量和一致性检查。
  • 数据工程师：
    • 编写数据集的转换、优化和处理操作，以满足用例及其成果的需求。
    • 在一个或多个项目中监控和管理最重要的数据集，并遵循中央项目团队的指导方针。
    • 根据既定的贡献流程向本体论回馈贡献。
  • 数据科学家/机器学习专家：
    • 执行建模、机器学习、分类和回归，以丰富数据并进行可视化，从而服务于决策工作流。
  • 应用开发者：
    • 在以下应用中开发决策驱动型界面： Workshop、 Slate、 Quiver和 Object Explorer.
    • 在 Ontology Manager中定义对象类型及其相关操作。
    • 借助 Foundry Gateway API，使用第三方工具构建外部应用程序。

所需用例开发人员的数量在很大程度上取决于各个用例的目标和需求，以及现有用例开发人员的技能组合。

最终用户

最终用户和自助服务用户在已开发的工作流、应用程序或数据产物中开展工作，以履行其常规组织职责，包括即席分析、报告、运营改进和日常决策。
