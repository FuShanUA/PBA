准备数据集以供下载

以下导出流程属于高级工作流，仅当您无法使用 操作 菜单直接从 Foundry 界面下载数据，或无法 从其他 Foundry 应用导出数据时才应执行.

本指南介绍如何使用转换在 代码仓库 or 如果希望用户在每次运行预览前手动确认，请开启.

准备数据

准备 CSV 以供下载的第一步是创建经过筛选和清理的数据集。我们建议执行以下步骤：

  1. 确保数据样本可以导出并遵守数据导出控制规则。具体而言，您应验证导出是否符合您组织的数据治理策略。
  2. 将数据筛选到满足必要目标的最小规模。为获得最佳性能，CSV 格式数据的未压缩大小应小于默认的 HDFS 块大小（128 MB）。为此，您应只选择必要的列并尽量减少行数。您可以通过筛选特定值或抽取任意行数（例如 1000 行）的随机样本来减少行数。尝试创建大于 128 MB 的 CSV 可能会耗费更多时间，并且可能需要额外的 Spark executor 内存才能成功。
  3. 将列类型更改为 string。由于 CSV 格式缺少 schema（列的类型和标签未强制执行），建议将所有列转换为字符串。这对于时间戳列尤其重要。

以下 Python (PySpark) 示例代码展示了将上述部分原则应用于纽约市出租车行程数据集的情况。

def prepare_input(my_input_df):
    from pyspark.sql import functions as F

    filter_column = "vendor_id"
    filter_value = "CMT"
    df_filtered = my_input_df.filter(filter_value == F.col(filter_column))

    approx_number_of_rows = 1000
    sample_percent = float(approx_number_of_rows) / df_filtered.count()

    df_sampled = df_filtered.sample(False, sample_percent, seed=0)

    important_columns = ["medallion", "tip_amount"]

    return df_sampled.select([F.col(c).cast(F.StringType()).alias(c) for c in important_columns])

使用类似的逻辑和 Spark 概念，您也可以在 Pipeline Builder 或其他 Spark API（如 SQL 或 Java）中实现此准备工作。

缩减为一个分区并设置输出格式

数据准备好导出后，您需要将数据重新分区或合并为单个分区，以便输出包含一个可供下载的文件。然后，将输出格式设置为 CSV 或其他受支持的输出格式，如 JSON、ORC、Parquet 或 Avro。以下示例展示了如何在 Pipeline Builder、Python 和 SQL 中重新分区数据并设置输出格式。

两者 repartition(1) 和 coalesce(1) 都可以将数据缩减为单个分区，但 coalesce 在同一转换中执行筛选操作时应避免使用 coalesce 因为它会合并上游任务，可能导致筛选操作以非分布式方式运行。

from transforms.api import transform, Input, Output
@transform(
     output=Output("/path/to/python_csv"),
     my_input=Input("/path/to/input")
)
def my_compute_function(output, my_input):
     output.write_dataframe(my_input.dataframe().repartition(1), output_format="csv", options={"header": "true"})

CREATE TABLE `/path/to/sql_csv` USING CSV AS SELECT /*+ REPARTITION(1) */ * FROM `/path/to/input`

在上述示例中，我们缩减为一个分区，以便输出数据集恰好包含一个可供下载的 CSV 文件。因此，全部数据必须能够容纳在单个 Spark executor 的内存中，这也是我们建议先对数据进行筛选或采样的原因。如果无法对数据进行筛选或采样，而数据又太大而无法容纳在单个 executor 的内存中，您可以使用适当的 Spark 配置文件来增加 executor 内存。或者，您可以为分区数使用非 1 的值。使用 repartition 且值大于 1 时，将减少单个 executor 内存中必须保存的数据量，但这也意味着输出数据集将包含多个 CSV 文件，需要逐个下载而不是下载一个文件。
