函数的版本范围依赖

Workshop、Actions 和 Automate 可以依赖固定的函数版本，也可以依赖版本范围。版本范围支持自动运行时升级，这可以减少开发工作量，并允许 已部署的函数 在不停机的情况下进行升级。

虽然版本范围依赖是一项强大的功能，但它也带有一定的风险（例如，存在 特定于 Actions 的权限影响）。本文档说明了版本范围解析背后的机制，以便您更好地理解这些风险，并就版本范围依赖是否适合您的应用做出明智的决定。

本文档页面假设您已具备向后兼容性和语义化版本控制（Semantic Versioning）系统等主题的背景知识。如果您不熟悉这些主题，请查阅我们关于 函数版本控制的文档。

您还应熟悉版本优先级的相关规则，具体定义见 语义化版本控制规范 ↗。换句话说，给定两个不同的版本，您应该能够判断哪一个版本的优先级更低。例如， 1.0.0-rc.1 < 1.0.0 < 1.0.1 < 1.1.0 < 2.0.0。

版本范围

在最简单的形式下，版本范围是一系列版本不等式的集合，如果某个版本满足该范围中的所有不等式，则称该版本“满足”该范围。例如，版本 1.2.0 满足该范围 >=1.0.0 <2.0.0。

在内部实现上，函数版本范围的语义借鉴自 NPM（JavaScript 生态系统中广受欢迎的包管理器）。请查阅 NPM 关于版本范围的文档 ↗ 以了解严格的定义。

目前，Workshop 和 Actions 等应用程序仅允许由向后兼容版本（即次版本或补丁版本升级）组成的版本范围。

Workshop 和 Actions 所使用的这种向后兼容范围在 NPM 中的等价形式是 插入符范围 ↗。

版本范围解析

除已部署的函数外，当您以版本范围的形式依赖某个函数时，系统将在运行时执行期间选定满足该范围的具体版本。具体而言， 满足该范围的最高 版本最终将被选定（可能需要几分钟才能获取到新发布的版本）。

已部署的函数

对于已部署的函数，具体版本则会解析为当前已部署的版本（前提是该版本满足范围）。如果已部署的版本不满足该范围，则会返回错误。

风险

虽然函数开发者会被引导遵循语义化版本规范和通用最佳实践，但在非主版本发布中始终有可能意外引入破坏性变更。函数发布者可以通过 限制稳定版本标签 使其只能应用于受保护分支，以此降低这一风险。这种限制要求在发布可能被下游应用程序自动使用的稳定版本之前，先进行代码审查。

如果您的应用程序引入了破坏性变更，可能会引发各种问题，例如运行时故障或意外行为。

发现破坏性变更后，您应立即联系该函数的开发者，以便他们 发布修复；在此期间，您应将函数依赖项固定到最后一个可正常运行的版本。

考虑到已部署函数的依赖项这一注意事项，如果您的应用程序有严格的正常运行时间要求且无法容忍任何破坏性变更，则应使用固定版本的依赖项。

操作中的权限与溯源

当函数版本范围在 函数支撑的操作中使用时，存在一些涉及权限与溯源的重要注意事项，可能会影响操作行为。有关这些影响的更多信息，请参阅操作文档中的 自动升级部分。
