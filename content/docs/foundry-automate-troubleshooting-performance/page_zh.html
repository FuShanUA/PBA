自动化性能故障排查

本指南帮助您识别意外性能问题的根本原因并提供解决方案。本页面介绍了常见的性能峰值模式、系统化的诊断流程，以及降低资源消耗的即时缓解措施。

如需有关设计高效自动化的前瞻性指导，请参阅 性能最佳实践。

常见的性能峰值模式

以下是常见模式，可帮助您识别和诊断自动化性能问题。

模式 1：针对频繁更新对象的活跃自动化

症状： 该自动化在短时间内运行了多次，产生了意外的资源消耗。例如，包含大量对象更新的自动化可能会产生多次自动化运行，而每次运行都可能触发下游影响。

根本原因： 某个对象类型更新非常频繁，而该自动化配置了“对象更新时”条件，且未设置基于时间的上限。这种情况通常发生在先前暂停的自动化被取消暂停时。

修复方法：

  1. 立即暂停该自动化，以停止后续执行。
  2. 添加具有适当间隔的基于时间的条件，以限制执行频率。
  3. 请验证 单次执行 模式已启用。
  4. 恢复该自动化，并在接下来的一天内密切监控执行次数。

模式 2：链式自动化滚雪球式增长

症状： 多个自动化按顺序运行,执行次数呈指数级增长。

根本原因: 自动化形成了一条链,每个自动化编辑对象时会触发序列中的下一个自动化:

  • Automation A 编辑对象
  • 这些编辑会触发 Automation B,它会分别处理每个对象
  • Automation B 编辑更多对象,触发 Automation C
  • 这种乘数效应会将初始更新转化为呈指数级增长的执行次数

如何修复:

  1. 暂停链中所有下游自动化。
  2. 评估是否可以将逻辑合并到更少的自动化中。
  3. 确保剩余的所有自动化都使用批量处理(ObjectSet 输入和 单次执行 模式)。
  4. 每次重新启用一个自动化,并在每次启用后监控执行次数。

模式 3:函数操作效率低下

症状: 函数执行时间较长,且资源消耗随对象数量增长的扩展性很差。

根本原因: 函数中包含循环,每次迭代都查询一次本体论,而不是批量处理对象。

如何修复:

  1. 检查函数代码中是否存在内部包含本体论查询的循环。
  2. 进行重构,预先加载所有所需对象或使用后端聚合。
  3. 在可能的情况下,将操作输入更改为接受 ObjectSet 而不是单个对象。

如需全面的函数优化指南,请参阅 优化函数性能。

模式 4:函数自调用循环

症状: 单个函数被调用多次,通常是递归调用。

根本原因： 一个函数编辑对象，而这些编辑会触发调用该函数的同一个自动化，从而形成循环。如果没有防护措施，这种情况可能会持续发生，直到被手动停止。

如何修复：

  1. 为对象添加状态标志或时间戳，以防止重复处理。
  2. 添加条件逻辑，在进行编辑之前检查是否需要处理。
  3. 考虑是否应将逻辑完全移出 Automate。

诊断流程

要调查性能激增问题，请按照以下步骤操作：

  1. 检查自动化的执行历史： 打开自动化并查看执行历史。需要考虑的关键问题：

    • 它在过去一天内运行了多少次？
    • 执行激增是从什么时候开始的？
    • 频率是否随时间推移而增加？

  2. 确定条件触发频率： 检查条件配置和对象更新模式。需要考虑的关键问题：

    • 满足条件的对象多久更新一次？
    • 是否配置了基于时间的条件？如果是，间隔是多少？
    • 更新的发生频率是否高于预期？

  3. 追踪自动化链： 使用 Autopilot 或 Workflow Lineage 以了解依赖关系。需要考虑的关键问题：

    • 哪些自动化会触发其他自动化？
    • 完整的影响链是什么？
    • 是否存在潜在的雪球效应，即一次执行会成倍增加？

  4. 审查函数实现： 检查自动化调用的函数。需要调查的关键主题：

    • 函数中是否包含带有本体论查询的循环？
    • 是否正确使用了批量处理模式？
    • 检查函数执行时间和外部调用次数。

  5. 查找递归条件： 确定自动化是否正在触发自身。需要考虑的关键问题：

    • 函数是否编辑了会导致同一自动化的条件再次得到满足的对象？
    • 是否存在用于防止递归处理的状态标志或防护措施？
    • 执行历史是否显示快速的重复调用？

立即缓解步骤

当发现性能或资源消耗激增时，请按优先级顺序采取以下操作：

  1. 止血

    • 立即暂停导致激增的自动化。这可以防止在调查期间进一步消耗资源。

  2. 评估影响

    • 检查 Resource Management 以了解总体资源影响。
    • 识别可能同样需要暂停的下游自动化。
    • 确定问题追溯到多久之前。

  3. 应用快速修复

    • 如果缺少基于时间的条件，请添加一个。
    • 将执行模式更改为 单次执行 如果当前设置为多次执行。
    • 向函数添加条件逻辑，以跳过不必要的处理。

  4. 监控恢复情况

    • 以降低频率或缩小范围的方式恢复自动化。
    • 在接下来的一天内密切监控执行次数。
    • 验证资源消耗是否恢复到预期水平。

工具和资源

以下是一些提供诊断信息的资源。

关于执行历史和成本明细

  • Automate 执行历史: 显示运行次数、时间以及成功或失败状态
  • 函数日志: 包含错误消息和执行时间详细信息
  • 本体论管理器: 显示查询成本，但对即时故障排除帮助不大
  • 资源管理: 提供按服务和资源类型划分的整体成本明细

自动化工作流概述

  • Autopilot: 用于大规模管理和监控自动化工作流的控制中心
  • 工作流血缘: 可视化展示自动化依赖关系和链
