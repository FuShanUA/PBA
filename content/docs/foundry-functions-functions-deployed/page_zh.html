部署函数

前提条件

本指南要求您已经编写并发布了 Python 或 TypeScript v2 函数。请查阅 Python 函数入门 或 TypeScript v2 函数入门 文档以获取教程。

在已部署执行模式和无服务器执行模式之间进行选择

如果您的租户已启用无服务器函数，新建的仓库将默认使用该模式。对于大多数用例，我们通常推荐使用无服务器函数。虽然已部署函数在某些情况下可能有用，但无服务器执行模式所需的维护更少，并且可以避免长期运行部署所带来的相关成本。

已部署函数具备一些无服务器函数所不具备的功能：

  • 已部署函数的长期运行特性意味着，如果函数能够容忍重启，则可以启用本地缓存。
  • 无服务器函数支持 外部数据源 使用所提供的源对象中的客户端，但不支持第三方客户端。您必须部署函数，才能使用第三方客户端进行外部 API 调用。
  • 已部署函数支持 GPU 分配，可通过并行处理加速计算密集型的模型训练和推理工作流，而无服务器函数则不支持。
  • 已部署函数可以访问完整的服务发现 API，而无服务器函数只能访问有限的服务发现 API 子集，例如 api_gateway 和 telemetry。

已部署函数存在一些不适用于无服务器执行的限制：

  • 无服务器函数支持按需执行单个函数的不同版本，从而使升级更加安全。使用已部署函数时，一次只能运行一个函数版本。
  • 无服务器函数仅在执行时产生费用，而已部署函数只要部署处于运行状态就会持续产生费用。
  • 无服务器函数所需的前期设置和长期维护较少，因为基础设施会自动管理。

要为您的注册启用无服务器函数，请联系您的 Palantir 管理员。

架构

函数可以以无服务器模式运行并利用按需资源，也可以部署到长期运行的容器中。

如果您的注册中已启用无服务器函数，我们建议使用无服务器函数，而不是已部署函数。虽然存在 一些已部署函数很有用的场景，但无服务器执行器通常更为灵活。

当您的函数部署后，系统将创建一个长期运行的环境来处理传入的执行请求。该环境将根据请求量进行扩缩容，并偶尔会被自动化进程重启。单个仓库中的所有函数由单个部署托管。

当函数通过 Marketplace 发布时，其执行模式和部署配置将被打包并复现。请查看 Marketplace 中的已部署函数 以了解详细信息和限制。

计算成本

已部署的函数将因运行中的部署而产生计算成本。无服务器函数仅在执行时才产生成本。

部署函数

按照以下步骤配置和部署函数：

  1. 打开您的函数仓库并导航到 分支 选项卡，然后选择 标签和发布。
  2. 将鼠标悬停在要部署的函数上，然后选择 在 Ontology Manager 中打开。

  1. 从左侧的版本选择器中选择您要使用的函数版本。
  2. 选择 配置执行。

  1. 如果您的环境中启用了无服务器函数，您将看到在无服务器和已部署之间切换的选项。如果未选择该选项且不存在部署，则默认使用无服务器。

  1. 选择 已部署 执行模式选项。

  2. 如果该函数尚未存在部署，请选择 创建部署。

  1. 首次创建部署时，将为配置应用默认值。您可以向下滚动到页面底部查看完整配置。

  1. 根据需要修改部署配置。您可以配置以下内容：
    • 分配给部署的计算资源，包括 CPU、GPU 和内存。
    • 基于请求负载进行自动扩缩容的最小限制和最大限制。
    • 部署启动时将设置的环境变量。
    • 函数在返回超时错误之前允许运行的总时长。与其他部署设置不同，超时是针对每个函数版本单独配置的。

  1. 选择 保存并启动部署 以保存任何更改并启动部署。您也可以选择 保存但不启动部署 以保存配置而不启动部署。

  1. 如果您选择了 保存并启动部署 选项，您需要等待托管该函数的部署启动。这可能需要几分钟时间。

  2. 要验证部署是否正在运行，请导航到包含该函数的代码仓库并运行该函数。该函数应成功执行并返回预期结果。
