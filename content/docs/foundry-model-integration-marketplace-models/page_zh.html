将建模资源添加到 Marketplace 产品中

您可以使用 Foundry DevOps 以将您的建模资源包含在 市场产品 中，以便其他用户安装和重用。 了解如何创建您的第一个产品。

支持的功能

模型可以在 DevOps 中作为产品的一部分打包，并通过 Marketplace 部署以实现发布管理目的。您也可以将模型的直接部署和已发布的模型函数打包在同一个产品中。模型还支持作为产品输入，允许用户在安装过程中选择模型。

打包模型

模型可以作为 Marketplace 产品打包为 输出 （将要部署的内容）或包含为 输入 供用户在安装过程中选择。

有两种方法可以将模型包含在产品的输出中， 随内容一起包含日 随生产者一起包含.

随内容一起包含

直方图 随内容一起包含 选项会将模型安装为静态资产，部署后无法重新构建。使用此选项时，以下内容会被复制到模型资源中：

  • 已保存的模型文件和权重。
  • 包含模型适配器类的 Python 库。
  • 用于在以下位置支持实时部署的容器镜像： 模型应用程序 以及 《建模目标》.
  • 直方图 转换中的 sidecar 模型推理.

只有当模型总大小（包括文件和底层容器镜像）小于 8 GiB 时，模型才能部署为 随内容一起包含 。DevOps 应用程序会验证此条件，如果不满足则会显示错误。

随生产者一起包含

直方图 随生产者一起包含 选项会安装用于构建模型的逻辑，以便在部署后可以构建模型。这使用户能够部署可以通过计划持续训练的模型。此选项适用于在代码仓库中构建的模型、 发布为转换的 Jupyter® 笔记本以及 Model Studio中构建的模型，但不适用于从 Jupyter® 笔记本交互式发布的模型。这是因为交互式发布的模型被视为静态资产，没有与之关联的逻辑。使用此选项时，建议打包最新版本的模型以避免混淆。

使用代码仓库生产者部署的模型 不要 定义的容器镜像，因为容器镜像是在仓库中运行检查时生成的，并用于后续生成模型的构建。安装产品时不会运行检查，因此已安装的模型构建无法为模型生成容器镜像。模型版本缺少容器镜像将导致无法在已部署版本中使用转换中的 sidecar 模型推理和实时部署。

要解决此问题，请在已安装的生成模型的仓库上手动触发检查，以构建容器镜像并使其可用于后续的模型训练构建。需要手动触发检查以确保 Python 适配器逻辑和容器中的环境与源模型中的相同。每当部署新版本的模型时，都必须执行此操作。

将模型用作产品输入

除了将模型打包为输出之外，产品构建者还可以将模型包含为产品的 输入 。在安装过程中，用户通过模型选择器选择要使用的模型，从而可以解析依赖组件所需的特定模型版本。这避免了打包模型本身的需要，减小了包的大小，并让安装者可以灵活选择其注册环境中已有的模型。

当模型在打包的转换中用作 ModelInput 时，转换必须设置 use_sidecar=True。sidecar 在其自己的容器中运行模型适配器，无需将适配器库导入仓库环境。建议在所有情况下使用 use_sidecar=True 。了解更多关于 以 sidecar 容器运行模型.

实时部署

您可以将一个 直接模型部署 与其模型一起打包。Marketplace 会使用其保存的配置安装该部署，包括计算资源、副本限制、扩缩容配置、环境变量和线程数。

打包实时部署

打包之前，请在模型的默认分支上创建直接部署并保存其配置。不支持其他分支上的部署、Modeling Objective 部署以及配置了外部源的部署。

要将部署包含在产品中：

  1. 在以下位置将模型添加为产品输出： 在页面底部选择.
  2. 选择 随内容一起包含 or 随生产者一起包含 用于模型的 打包模式.
  3. 自动预览行为 打包实时部署中，选择 是。当模型在其默认分支上具有直接部署时，此选项可用。
  4. 查看产品输出。DevOps 会包含实时部署，以及（如果您已发布）与该部署关联的模型函数。

直方图 打包实时部署 选项适用于两种打包模式。如果您选择 No 或将该选项保持未设置状态，模型不会自动包含其部署或函数。您仍然可以在已安装的模型上手动 创建直接部署 。

安装并启动实时部署

在 安装期间，配置 自动启动实时部署 输入：

  • 将其设置为 true 以自动启动新安装的或已停止的部署。
  • 将其保持为默认值 false 以使新部署保持停止状态，直到您手动启动它。

安装完成后，打开已安装的模型并选择 实时部署 以检查其状态。要启动已停止的部署，请选择 开始部署 ，该选项位于 概述 选项卡。模型函数可以在其部署运行之前安装，但在函数能够提供推理请求服务之前，部署必须处于运行状态。

使用 随内容一起包含时，Marketplace 会使用已安装的模型版本创建部署。使用 随生产者一起包含时，如果尚无可用版本，部署将等待模型版本构建完成。配置产品的 构建设置 以在安装期间构建模型，或在启动部署之前构建已安装的模型。对于代码仓库生产者，请遵循 容器镜像要求.

升级实时部署

产品升级会将打包的部署配置应用于已安装的部署。在默认分支上发布的新模型版本会自动更新部署，包括由常规构建和 Marketplace 升级创建的版本。

。部分设置也可以在源级别进行配置。 自动启动实时部署 to false 在升级期间不会停止正在运行的部署。已停止的部署将保持停止状态，除非您手动启动它或将此输入设置为 true.

模型函数

您可以将已发布的 模型函数 与其模型和直接部署一起打包。Marketplace 会将已安装的函数连接到目标环境中的模型和部署。

打包模型函数

要在打包模型时包含函数， 发布该函数 在打包之前，在模型的默认分支部署上执行此操作。然后选择 是 位于 打包实时部署 作为模型输出。DevOps 会自动包含已发布的函数；您无需在安装后手动发布它。

您还可以 将模型函数添加为函数输出 并直接选择其版本。该函数包含对其支撑部署以及与该函数版本关联的模型版本的依赖关系。 实时部署打包要求 仍然适用。

选择匹配的模型和函数版本。您可以显式选择较旧的函数版本，但如果它需要与产品中所选版本不同的模型版本，Marketplace 会报告冲突。当未显式选择函数版本时，Marketplace 会自动解析它；它不会搜索较旧的函数版本来匹配您选择的模型版本。

在另一个函数中使用模型函数

您可以将模型、其部署、其函数以及调用它的应用程序或函数打包到单个产品中。例如，将模型函数与 Workshop 应用程序 or 另一个函数 一起打包，后者会导入该函数。Marketplace 会更新这些引用，以使用已安装的模型函数。

如果您希望在目标环境中重用现有函数，请将模型函数配置为产品输入，并在安装过程中选择它。

Marketplace 会跟踪导入到仓库中的模型函数。它不会跟踪通过 Platform SDK 直接查询的模型函数（未经过导入），因此在安装过程中这些引用不会被自动更新。

的类型化对象。对于 Python 和 TypeScript v2 函数，模型函数必须注册到本体论才能导入到仓库中。如果您的模型函数仍绑定到空间（space-bound）， 请将其迁移为绑定到本体论 以利用结构化依赖跟踪和 Marketplace 输入映射。

升级模型函数

Marketplace 会在安装和产品升级过程中管理打包模型函数的发布。对于仍是 Marketplace 安装输出的模型，在默认分支上发布新的模型版本会更新实时部署，但不会自动发布另一个函数版本。无论打包模型时使用何种 打包实时部署 设置，此行为均适用。

对于 随生产者一起包含，因此定时或手动重新训练会更新默认分支上的部署，而函数仍保持其已安装的版本。如果重新训练保留了模型 API，已安装的函数可以继续处理请求。

当 模型 API 发生变化，已安装的函数可能与部署不再匹配，推理请求可能会失败。要安装匹配的函数，请更新源模型函数以及调用它的任何函数或应用程序，然后发布新的产品版本并升级安装。请单独更新产品之外的消费者，包括将模型函数用作输入的安装。

不支持的建模功能和限制

  • 建模目标： 用途 直接模型部署 用于实时目标部署，以及 模型转换 用于批量部署。
  • 实时部署： 只有模型默认分支上的直接部署才能被打包。不支持其他分支上的部署以及配置了外部源的部署。
  • 包含内容的模型只有在总大小（包括权重、Python 环境和底层容器镜像）小于 8 GiB 时才能打包。
  • 外部模型 在 DevOps 或 Marketplace 中不受支持。
