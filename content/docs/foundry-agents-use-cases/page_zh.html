专业代码智能体的用例

专业代码智能体将大语言模型与 Ontology SDK (OSDK)、 Ontology MCP (OMCP)以及 Palantir MCP 相结合，以读取数据、对数据进行推理，并在整个平台上执行操作。以下模式和示例介绍了使用专业代码智能体的常见方式。

本体论数据智能体

本体论中的变更会触发专业代码智能体，该智能体随后会通过 OSDK 或 OMCP 读取相关对象。智能体利用模型对数据进行推理，并将结果写回本体论。此模式在通过 Automate 于对象发生变更时触发时效果很好。

示例：理赔争议智能体

理赔被拒绝后会触发专业代码智能体。该智能体通过本体论读取该理赔及其被拒原因。它利用模型解释拒赔原因以及客户可以如何补救，然后将解释和建议的后续步骤写回理赔对象。这有助于客户更快地理解并解决拒赔问题，从而节省时间和成本。

平台资源智能体

平台事件会触发这些专业代码代理，它们使用 Palantir MCP 来检查和修改代码仓库和转换等资源。代理借助模型推理确定需要更改的内容，然后在平台上应用更改。

示例：构建修复代理

构建失败事件会触发专业代码代理。代理会找到该失败构建所属的转换仓库，并使用 Palantir MCP 读取构建日志。它使用模型确定失败原因，在仓库中编写修复代码并进行测试。最后，代理提交拉取请求供开发者审核。

迁移代理

迁移代理结合 本体论数据代理 和 平台资源代理 模式，将遗留系统迁移到 Foundry。遗留源代码首先会被摄取到本体论中。代理使用 OSDK 和 OMCP 来理解现有功能，然后使用 Palantir MCP 构建 Foundry 资源，在现代系统中复现遗留逻辑。

示例：遗留系统迁移代理

来自遗留系统的源代码会被摄取为本体论对象。专业代码代理通过 OSDK 和 OMCP 读取并推理现有逻辑，随后使用 Palantir MCP 生成转换、函数和本体论资源，以便在 Foundry 中重现该逻辑。
