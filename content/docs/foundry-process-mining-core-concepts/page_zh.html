核心概念

我们建议您在使用 Machinery 应用程序之前先了解以下概念。

流程

在现实世界的流程中，文档、设备或个人等实体会随时间在不同 状态 之间转换。其中许多流程对象可以相互关联，以表示流程中涉及的多个实体。在 Machinery 中，您可以通过包含状态和操作的流程容器对这些流程进行建模。这些流程容器可以相互关联，甚至可以嵌套。

流程中的实体（也称为“流程对象”）可以由您本体论中的对象类型表示，例如 Claim、 Flight 或 Employee。该对象类型必须具有一个用于表示对象状态的字符串类型属性。

状态

状态描述对象的当前状况。例如，包裹可能处于 进行中 或 已送达 状态。可能的状态必须是可枚举的。例如， Name 属性就不合适，因为可能的名称有无穷多个。

状态转换显示为状态节点之间的边。

每个对象必须处于 一个 个可能状态之一（在任一给定时间）。不满足此条件的场景应建模为流程层级结构。例如，员工的状态可能为 new-hire 或 onboarded，同时也可能为 paid 或 awaiting payment 。这些应当是单独的流程，并由父流程跟踪员工是否为 payable。

在本体论中，状态被编码为该 State 属性的字符串值。此值等同于Machinery中的状态ID。要更改图中显示的状态标签，您可以覆盖显示名称。

Machinery中的状态ID等同于您数据中的状态值。为避免输入错误或不一致，您可以使用枚举 值类型来支撑您的状态属性。这将确保本体论中的数据只能采用预定义的一组值。Machinery会检测到此设置并保持流程状态同步。

操作与自动化

操作是状态转换的原因。在平台内发生的状态变更由 操作定义。您可以将它们导入到Machinery图中，并确定它们在流程中的角色。

流程日志

流程的本质在于实体会随时间发生变化。为了识别对象所经历路径中的模式，或者计算诸如在某个状态下平均停留时间之类的指标，必须捕捉变化的时间维度。Machinery 通过维护一个 Log 对象类型来追踪对对象所做的每一次更改，无论这些更改来自外部数据源还是 Foundry 操作。

您可以像查看任何其他对象类型一样查看此对象类型，但您不应自行在其上定义操作，因为该日志对象类型由 Machinery 自动维护。

每个日志对象类型追踪单个对象类型属性的更改。每个流程都可以拥有自己的流程日志。

对于在平台之外发生的流程，您需要提供一个变更日志格式的数据集，用于追踪哪个对象在什么时间进入了哪个状态。Machinery 会计算分析和监控所需的派生数据，例如上一个状态、状态之间的持续时间，以及对象迄今为止所经历的路径。
