保护令牌和 API 密钥

Foundry 用户务必保护好自己的令牌、API 密钥及其他身份验证材料。如果令牌被外部泄露（无意中暴露）或被恶意行为者窃取，未经授权的第三方可能会在受损令牌的用户上下文中访问 Foundry。

令牌

Foundry 使用多种不同类型的令牌：

  • 用户生成的令牌
  • 会话令牌
  • 数据连接器协调器令牌

用户生成的令牌

用户生成的令牌（或个人访问令牌）是一种 API 密钥，可授予用户级别的权限以访问平台中的所有应用程序。用户可以在创建令牌时为其指定生存时间（TTL）。TTL 是访问令牌保持有效可用的最长时间。TTL 一旦到期，令牌即被撤销。

用户生成的令牌的一项安全特性是：它们无法生成其他用户生成的令牌。只有会话令牌才能用于创建新的用户生成的令牌。 了解如何生成此类令牌。

会话令牌

会话令牌是一种临时性、有时效限制的令牌，以 cookie (PALANTIR_TOKEN) 的形式存储在您的浏览器中。生成会话令牌时，该令牌会自动分配一个生存时间 (TTL)。默认 TTL 为 16 小时。TTL 到期后，令牌将被撤销。

数据连接器协调器令牌

数据连接器协调器令牌用于向 Foundry 安装实例验证数据连接器代理的身份。默认情况下，此令牌存储在 {BOOTVISOR_DIRECTORY}/var/data/coordinator-token.json。数据连接器协调器令牌授予特定于代理的平台访问权限。

创建新数据连接器时，系统会将一个有时效限制的令牌动态插入到部署 tarball 中。此 tarball 应被视为敏感内容，因为其中包含身份验证材料。

如果为数据连接器代理配置了指向其他数据源（如 SQL 数据库）的凭证，则代理本地可能会缓存或存储额外的凭证材料。

令牌的最佳实践

为防止您的令牌和 API 密钥被泄露或滥用，我们建议遵循以下最佳实践和行为规范：

  1. 切勿将令牌提供给其他用户或公开发布。
  2. 在本地使用令牌时，最好使用环境变量。
  3. 如果您选择使用 dotfiles 存储 token，请确保这些 dotfiles 已被排除在版本控制之外。
  4. 不要将 token 放入命令行参数中。
  5. 不要在脚本或软件中硬编码 token。
  6. 撤销未使用或不必要的 token。
  7. 为用户生成的 token 设置合理的存活时间（TTL）值。
  8. 不要在其他设备上使用基于浏览器的 cookie 同步技术。
  9. 尽量减少您使用的浏览器扩展数量。

Token 泄漏

如果 token 在未经授权的系统上被暴露或可被访问，例如被意外发布到公开可用的代码仓库中，则该 token 视为已“泄漏”。任何 token 泄漏都应被视为信息安全事件。您应立即采取措施禁用该 token，然后将问题通知您的信息安全团队。不同类型 token 的禁用步骤请参见下文。

撤销用户生成的 token

您可以在 Foundry 用户界面中撤销用户生成的 token。要了解具体操作方法，请参阅 用户生成 token 相关文档。

撤销会话 token

要撤销会话 token，只需退出登录 Foundry 实例即可。

GitHub token 撤销服务

Palantir 的信息安全团队运行一项自动化服务，该服务会尝试识别并撤销源代码控制系统中泄漏的 token，该服务部署于 Github.com ↗。如果令牌泄露到 GitHub 上的公共仓库,GitHub 令牌撤销服务将收到通知,并会自动尝试代表您撤销该令牌。

如果发生此类撤销,GitHub 令牌撤销服务将无法通知您。此外,如果该服务无法通过网络访问您的 Foundry 安装,该服务将无法为您自动撤销令牌。
