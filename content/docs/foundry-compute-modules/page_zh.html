计算模块

应用访问权限

要启用计算模块，请联系您的平台管理员 修改应用访问权限 （在控制面板中进行）。

您还可以在平台内的计算模块应用中查看此文档，以获得高效的开发者体验。

计算模块使您能够在 Palantir 平台上部署交互式容器，从而引入您现有的代码库（无论使用何种语言），并在平台内运行这些代码。具体而言，您可以将无服务器 Docker 镜像作为计算模块在 Palantir 平台中运行，并根据前端应用中的负载对其进行水平扩展或缩减，例如 Workshop 和 Slate。

计算模块入门

通过我们的计算模块快速入门指南开始开发：

  • 从 Workshop 模块或 Slate 应用中调用自定义容器或模型： 编写一个可从 Workshop 或 Slate 查询的容器函数。请查阅有关 构建由计算模块支撑的函数 的文档，以开始使用 Palantir 的 TypeScript 或 Python SDK。
  • 使用自定义容器将数据同步到 Foundry： 编写一个容器，用于将来自自定义数据源的数据添加到流、数据集或媒体集中。请查阅有关 构建由计算模块支撑的管道 开始使用 Palantir 的 TypeScript 或 Python SDK。
  • [高级] 通过编写自定义客户端与任何语言集成： 要在不使用专用 SDK 的情况下以某种语言集成容器，您可以 编写自定义客户端 以实现计算模块客户端规范。

计算模块的用例

计算模块为您提供了在平台中与自己的代码或第三方代码交互的新方式，可实现以下用例：

  • 容器支撑函数： 编写可从 Workshop 或 Slate 等应用程序中查询的容器函数。
  • 基于容器的数据集成： 连接任意数据源，并将数据摄取到流、数据集或媒体集中。
  • 托管自定义模型： 托管自定义或开源模型，并在 Foundry 应用程序中以交互方式查询它们。

为什么使用计算模块？

计算模块具有多项关键优势：

  • 集成现有代码库： 如果您拥有对业务至关重要的代码，而在 Foundry 中重写这些代码有风险或成本高昂，则可以将这些代码容器化为 Docker 镜像，并将其作为计算模块运行。
  • 使用任何编程语言： 运行任何可以容器化的代码，而不受语言限制。这意味着您不会受到 Foundry 原生支持语言的限制。
  • 动态和预测性水平扩展： 如果您预计需要处理数量不定的请求，计算模块可以根据当前和历史负载增加或减少可用副本的数量，从而确保更高的可用性。
  • 外部连接和平台内连接： 利用 Palantir 产品编写自定义逻辑。例如，您可以读取和写入数据集或媒体集，或连接到外部系统。

请注意，计算模块并非在所有情况下都适用。我们不建议在以下情况下使用计算模块：

  • 动态垂直扩展： 如果您预计单个请求的大小会发生巨大变化（例如从 1MB 到 100GB），并希望支持动态垂直扩展，那么计算模块在“开箱即用”的情况下性能可能较差，因为所分配的资源量是静态的，并且需要手动定义。可以为同一计算模块创建资源配置不同的多个层级，并在这些层级之间进行切换，但这种解决方案可能更加复杂和繁琐。
  • 替换 Foundry 原生支持的现有功能： 从理论上讲，计算模块可用于构建任何所需的功能。然而，由于其高度通用且功能强大，这可能会以解决方案更加复杂为代价。

架构

每个计算模块由多个副本组成。副本数量会随请求量的变化而变化。

每个副本都包含相同的一组一个或多个隔离容器。其中一个容器充当入口点,它必须实现一个持续轮询待处理事件的客户端。其他容器可以包含任何内容。

默认情况下,设置多容器计算模块几乎没有防护措施。一种建议的方法是让它们使用标准网络协议进行通信;另一种建议是使用共享卷挂载。同一副本中的容器可以通过这些方法(以及其他方式)进行通信,但容器无法跨副本通信,且您不应依赖它们可能累积的任何状态。

要开始使用,请查看 在 Palantir 平台中构建计算模块的指南。
