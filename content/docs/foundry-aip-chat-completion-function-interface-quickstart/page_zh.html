使用函数接口注册 LLM [旧版]

旧版

本页面介绍了使用函数接口注册 LLM 的旧版方法，该方法已被 已注册模型实现 于 2026 年 3 月取代，后者现为推荐的方法。

本页面上的 TypeScript 示例使用 TypeScript v1 函数 API，而通过函数接口注册模型仅在 TypeScript v1 中受支持。此注册方法没有 TypeScript v2 的等效实现；请改用 已注册模型 。

在使用函数接口注册 LLM 之前，请联系 Palantir 支持团队。

您可以在 Palantir 平台中使用自己的 LLM，方法是借助 函数接口。例如，您可以引入自己微调的模型以在 AIP Logic 中使用，从而为用户提供更大的灵活性和更多选择。函数接口使您能够注册并使用 LLM，无论这些模型是本地部署、托管在您自己的云上，还是在其他平台上微调的。

目前有两种方法可以建立与 OpenAI 的自定义连接：

  • Webhook： 您可以创建一个 webhook，并从您的 TypeScript 代码仓库中直接调用它。本教程采用此方法。
  • 直接数据源： 您可以在 Data Connection 中创建 REST API 数据源，并从您的 TypeScript 函数中发起 fetch 调用。

本教程介绍如何创建源来定义您的 LLM 的 API 端点、通过 webhook 从 TypeScript 函数调用模型,以及发布函数以供在 Palantir 平台中使用(例如,在 AIP Logic 或 Pipeline Builder 中使用)。

前提条件

  • 请先熟悉 如何设置 Data Connection 源和网络策略 以了解如何将您的特定 LLM 端点连接到 Foundry。
  • 我们建议您至少了解在 Foundry 中编写 TypeScript 函数的基础知识。如需了解更多信息,请参阅 函数入门。

教程概述

在本教程中,您将编写一个 TypeScript 函数,通过 webhook调用外部 OpenAI 模型,实现 ChatCompletion 函数接口,并将模型注册到 Foundry。完成本教程后,您将能够在 AIP Logic 中原生使用自定义 LLM API。

  1. 设置 REST 源和 webhook。
  2. 使用 TypeScript 函数实现 ChatCompletion 接口。
    • 创建一个 TypeScript 代码仓库,您将在其中编写实现函数接口的函数。
    • 将以下资源导入您的仓库:
      • OpenAI 源及关联的 webhook
      • 该 ChatCompletion 函数接口
    • 编写一个 TypeScript 函数,并使用 @ChatCompletion 函数接口并调用您的源。
    • 保存并发布您的函数。
  3. 您的函数现在将使您能够 在 AIP Logic 中使用您注册的 LLM。

设置 REST 源和 webhook

为了维护平台安全，您需要使用 Data Connection 应用程序将对 OpenAI 的调用注册为 webhook。以下步骤介绍了如何在 Data Connection 中设置 REST API 源和 webhook。

了解有关如何创建 webhook 并在 TypeScript 函数中使用它的更多信息。

设置源

  1. 打开 Data Connection 应用程序。

  2. 选择 新建源。

  3. 搜索 REST API。

  4. 在 协议源下，选择 REST API。

  5. 在 连接到您的数据源 页面上，选择 Foundry worker。

  6. 为您的源命名，并将该源保存到文件夹中。本示例使用的源名称为 MyOpenAI。

  7. 在 连接详细信息下，请执行以下步骤：

    • 将域名基础 URL 设置为 https://api.openai.com ，并将 身份验证 设置为 Bearer token。 了解有关 OpenAI API 的更多信息。 ↗。
    • 请按照 OpenAI 的说明 ↗ 来创建 API 密钥 ↗。
    • 将新创建的 API 密钥复制粘贴到 Data Connection 中的 Bearer token 字段中。
    • 将端口设置为 443。
    • 再创建一个密钥，名为 APIKey 并粘贴与 bearer token 字段中使用的相同 API 密钥。
    • 将 https://api.openai.com 添加到 Palantir 托管的 SaaS 平台与外部域名之间的网络出站允许列表中。为此，您可以导航至 网络连接 并选择 请求并自行批准新策略。
      • 如果您没有执行此步骤所需的权限，请联系您的 Palantir 代表。

  8. 您必须启用 导出配置 ，才能在 AIP Logic 和 Pipeline Builder 等平台应用中使用此 API 端点。要启用 导出配置，请开启以下选项：

    • AIP Logic： 开启 启用导出到此源，无需进行标记验证；这将使您能够在 AIP Logic 中使用您的 LLM。
    • Pipeline Builder： 开启 启用导出到此源；这将使您能够在 Pipeline Builder 中使用您的 LLM。请注意，此功能目前处于 beta 开发阶段，可能无法在您的 enrollment 上使用。

  9. 您必须 启用代码导入 ，才能在您的函数中使用此端点。

    • 开启 允许将此源导入代码仓库。
    • 开启 允许将此源导入管道。

  10. 选择 继续 和 开始使用 以完成您的 API 端点和出站设置。

import { isErr, UserFacingError } from "@foundry/functions-api";
import { OpenAI } from "@foundry/external-systems/sources";
import { ChatCompletion } from "@palantir/languagemodelservice/contracts";
import {
    ChatMessageRole,
    FunctionsGenericChatCompletionRequestMessages,
    FunctionsGenericChatCompletionResponse,
    GenericChatMessage,
    GenericCompletionParams,
} from "@palantir/languagemodelservice/api";

export class MyFunctions {
    @ChatCompletion()
    public async myFunction(
        messages: FunctionsGenericChatCompletionRequestMessages,
        params: GenericCompletionParams
    ): Promise<FunctionsGenericChatCompletionResponse> {
        const res = await OpenAI.webhooks.CreateChatCompletion.call({
            model: "gpt-4o",
            messages: convertToWebhookList(messages),
        });

        if (isErr(res)) {
            throw new UserFacingError("Error from OpenAI.");
        }

        return {
            completion: res.value.output.choices[0].message.content ?? "No response from OpenAI.",
            tokenUsage: {
                promptTokens: res.value.output.usage.prompt_tokens,
                maxTokens: res.value.output.usage.total_tokens,
                completionTokens: res.value.output.usage.completion_tokens,
            },
        }
    }
}

function convertToWebhookList(
    messages: FunctionsGenericChatCompletionRequestMessages,
): Array<{ role: string; content: string; }>  {
    return messages.map((genericChatMessage: GenericChatMessage) => {
        return { role: convertRole(genericChatMessage.role), content: genericChatMessage.content };
    });
}

function convertRole(role: ChatMessageRole): "system" | "user" | "assistant" {
    switch (role) {
        case "SYSTEM":
            return "system";
        case "USER":
            return "user";
        case "ASSISTANT":
            return "assistant";
        default:
            throw new Error(`Unsupported role: ${role}`);
    }
}
