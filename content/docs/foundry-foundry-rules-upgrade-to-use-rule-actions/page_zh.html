升级以使用规则操作

这些步骤适用于旧版本的 Foundry Rules（之前称为 Taurus）。如果您刚开始部署 Foundry Rules，则无需执行以下步骤，这些步骤已作为 默认设置的一部分包含在内。除非您被专门指引到本节，否则您很可能不需要按照这些步骤操作。

以前，Foundry Rules 仅支持将数据集 输入 到规则中，并且没有 规则操作的概念。虽然在对象上编写规则是一项可选功能，但我们强烈建议升级以使用 规则操作，尤其是在您升级使用对象时。

要在 Foundry Rules 中启用对象和规则操作，请按照以下步骤操作：

所有屏幕截图均使用虚构数据。

  1. 升级您的 Foundry Rules 转换库版本： 确保 tau-execution:tau-execution-core 为 至少 版本 0.60.4，位于项目级的 build.gradle 文件中：

    • compile "com.palantir.tau-execution:tau-execution-core:0.60.4"
    • 如果您找不到 build.gradle 文件，请勾选 “显示隐藏文件和文件夹” 选项，该选项位于 “文件” 侧边栏中的齿轮图标下。

  2. 更新逻辑版本： 在您的 Foundry Rules Workshop 应用中使用编辑模式，导航到 规则编辑器小组件 并更改 逻辑版本 为 "V1"。虽然更改此选择器不会造成破坏性影响，但在将其更改为 V1 后，就无法再将版本改回 V0。不过，返回 V0 也不会带来任何好处。

  3. 将对象添加到 Workshop 应用程序： 在同一个 Workshop 应用程序中，将您希望在 Foundry Rules 中使用的任何对象类型添加到 允许的对象类型 对象集变量中。该变量应是您希望公开的所有对象类型的联合对象集，如下所示。

    • 如果您要从数据集切换到相应的对象，则应让该数据集在 Foundry Rules 中保持可用，直到所有现有规则均迁移为使用该对象为止。不过，无需急于立即切换为使用该对象，因为在两者均已声明的情况下，转换仍可继续正常运行。

  4. 添加规则操作： 在 本体论管理器中创建合适的 Foundry 操作后，若要将该操作添加到 Workshop 应用程序，请点击 添加规则操作。

    了解更多关于 配置 规则操作的信息。

    向 Workshop 配置添加规则操作后，下次编辑每条现有规则时，都需要为其配置规则操作。但需要注意的是，即使未为每条规则配置规则操作，旧的转换管道仍将继续正常工作。因此，迁移不会产生任何停机时间，并且可以按照适合用户的节奏进行迁移。

  5. 更新转换管道代码： 更新转换管道的最简单方法是在本体论管理器中更新规则工作流模板的现有实例，添加缺失的对象和操作。然后，部署更新后的转换以用作参考。部署参考后，您可以 配置转换管道 以将此新代码映射到您现有的工作流。

    如上文所述，要使新的转换代码正常工作，所有规则都必须配置规则操作。因此，我们建议在分支上进行转换更改，并在合并之前测试这些转换更改。
