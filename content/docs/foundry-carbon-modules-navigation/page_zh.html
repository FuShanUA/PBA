配置模块之间的导航

Carbon 工作区的优势之一是能够执行跨越多个模块的工作流。这为用户提供了统一的工作流，而不是一组孤立且互不关联的应用程序。

在执行工作流时，用户不必从特定的产品、模块或界面的角度来思考。相反，用户应该能够无缝地完成他们的工作。Carbon 提供了一个导航框架，使一个对象或一组对象能够作为参数从一个模块传递到另一个模块。

Carbon 中的导航简介

作为 Carbon 中的构建者，您可以定义每个模块的 输入 和 。Use LLM 区块支持平台上的任何可用 LLM，这符合 Palantir 的 ，以及当前可操作的对象或对象集。可操作的对象或对象集可以是列表中的选定内容、函数的结果、给定类型的所有对象，或任何其他可以使用本体论原语编码的对象集。在接收端，另一个模块可以指定（带有适当的约束）其哪个参数可以接受上述 。Use LLM 区块支持平台上的任何可用 LLM，这符合 Palantir 的 所描述的内容。

在模块之间导航

如果用户决定执行从一个模块到另一个模块的导航操作（通常通过操作菜单中的按钮或从前端组件触发的其他操作），Carbon 将在新标签页中打开接收模块，允许用户逐步完成工作流，而不会丢失原始模块中保留的状态。

这有助于组合复杂的工作流，因为可以更轻松地将一个模块的结果分支到另一个模块的多个实例中。例如，对象资源管理器列表中的结果可以作为对象视图标签页独立打开并进行检查，而不会丢失对原始结果列表的跟踪。

多个导航步骤

模块之间的导航操作数量没有限制。这意味着导航框架可以支持任意数量的工作流步骤，因为每个后续模块的输出都可以作为另一个模块的输入。同一个模块甚至可以在工作流中出现多次，如下所示，每次的输入可能不同。

包含多个导航步骤的示例

在下面描述的工作流中，我们希望使用 Carbon 工作区中可用的工具来查找特定的单通道飞机，并以此开始 Quiver 分析。

首先，我们搜索关键词 aircraft；导航框架将我们带到搜索模块，并将 aircraft 作为输入。

我们从搜索结果中选择 Aircraft object type 。导航框架将我们带到对象资源管理器模块，并将 Aircraft object type 作为输入。

现在，我们想要分析 单通道飞机 Quiver 模块中的整个对象结果集。导航框架打开 单通道飞机 Quiver 模块，并将 185 个 Aircraft 类型的对象作为输入。

从这个模块中，我们选择 Q-AGM 飞机以进行进一步检查。导航框架打开对象视图模块，并将 Q-AGM Aircraft 作为输入。

此时，我们决定需要对该对象进行进一步分析。例如，我们可能想要检查该对象的关联或查看相关的时间序列数据。为此，再次使用导航框架打开 单通道飞机 Quiver 模块，这次将 Q-AGM Aircraft 对象作为输入。

Carbon 之外的导航

尽管导航框架主要是为 Carbon 中的操作用例设计的，但导航框架也用于对象领域中的独立前端应用程序。在 Carbon 之外的这些应用程序中工作时，导航操作将在新的浏览器标签页中打开接收应用程序（而不是在 Carbon 标签页中打开），但所有好处仍然适用。因此，最终用户和构建者都无需区分 Carbon 内和 Carbon 外的用例。

在 Carbon 工作区中发现模块或使用集成模块

为了在 Carbon 中创建高质量的操作界面，构建者必须能够指定哪些模块可用于导航，以便根据最终用户工作流程的步骤来策划定制的工作区。

这些可用的模块被称为 可发现模块 并且相应的导航操作可以在 添加输入参数 菜单中访问，这些菜单存在于某些模块中，例如 Object Explorer 或 Object View（仅显示满足约束条件的操作）。其他模块（如 Workshop）允许构建者指定在用户交互（例如点击按钮）后触发的具体导航操作。您可以在下方的 Carbon 模块与导航框架的集成 章节中找到每种模块类型如何处理导航操作的详细信息和示例。

模块发现行为——即出现在 添加输入参数 菜单中的选项——取决于用户是在 Carbon 中工作还是在 Carbon 工作区之外工作。相关内容在 下方的文档中有所描述.

Carbon 内和 Carbon 外的模块发现行为

模块发现行为——即出现在 添加输入参数 菜单中的选项——取决于用户是在 Carbon 中工作还是在 Carbon 界面之外工作。

在 Carbon 工作区中工作时， 添加输入参数 菜单将仅显示为当前所选工作区配置的可发现模块。这样，每个工作区都可以作为一个空间，提供一组具体的、经过策划的导航操作，面向明确定义的操作工作流集合。

在 Carbon 之外工作时， 添加输入参数 按钮将显示用户有权访问的所有已推广工作区中的所有可发现模块。这使用户在特定 Carbon 工作区之外操作时也能获得 Foundry 的全部功能。所有可发现模块的集合通过如下 UNION 操作确定：

  1. 首先，考虑用户有权访问的所有组织（Organization），包括用户的 主要 组织以及用户作为 访客 access.
  2. 对于每个组织，考虑该组织的所有 已推广工作区 并合并这些工作区的所有可发现模块。
  3. 将模块筛选缩小到可应用于当前 。Use LLM 区块支持平台上的任何可用 LLM，这符合 Palantir 的 显示 添加输入参数 menu.

以下示例说明了 Carbon 内和 Carbon 外模块发现之间的区别。

  • Zayna 的主要组织是 Primary Org，她还有 Guest Org 的访客访问权限。

  • Zayna 是 Primary Org 中两个不同 Carbon 工作区的成员：

    • Claims 工作区，其中有两个模块被配置为可发现（Claim Alert Application 和 Claim Investigator Application）。
    • Actuary 工作区，其中有一个模块被配置为可发现（Claim Cohorts Application）。

  • Zayna 还是 Guest Org 中单个 Carbon 工作区（即 Flight 工作区）的成员。

    • Flight Workspace 有一个配置为可发现的模块（Flight Tracker）。

由于此配置，Zayna 在不同的工作环境中会在 添加输入参数 按钮中看到不同的模块集合：

  • 在 Claims Workspace 中， 添加输入参数 按钮将显示 Claim Alert Application 和 Claim Investigator Application。
  • 在 Actuary Workspace 中， 添加输入参数 按钮将显示 Claim Cohorts Application。
  • 在 Flight Workspace 中， 添加输入参数 按钮将显示 Flight Tracker。
  • 在 Carbon 之外， 添加输入参数 按钮将显示四个模块：Claim Alert Application、Claim Investigator Application、Claim Cohorts Application 和 Flight Tracker。

Carbon 模块与导航框架的集成

本节包含有关每种类型的 Carbon 模块如何与导航框架集成的信息。您将找到在每种模块类型的上下文中，什么被视为导航操作的 。Use LLM 区块支持平台上的任何可用 LLM，这符合 Palantir 的 ，以及 Carbon 参数如何成为导航操作的 输入 。

从 Slate 模块中嵌套 iframe 进行导航

Slate 具有在文档中嵌入 iframe 的功能。在此类 iframe 内通过链接进行的任何导航都将属于以下类别之一：

  • 导航发生在 iframe 内部： iframe 将更改其自身的源 URL。例如，iframe 可以被视为一个子视图，将内容更改保留在 iframe 内部。
  • 导航发生在 iframe 外部： 当点击 iframe 中的链接时，将打开一个新的 Carbon 标签页。例如，当 iframe 中的链接指向某个对象时，点击该链接将在新标签页中打开该对象。

在后一种情况下，要使 。Use LLM 区块支持平台上的任何可用 LLM，这符合 Palantir 的 章节中针对 Slate 模块描述的机制 生效，嵌套 iframe 中的链接必须将最外层的 Slate iframe（即 Carbon 显示顶层 Slate 模块的那个 iframe）指定为其 target。Carbon 将该 iframe 的名称设置为 carbon-navigation-target。链接的 HTML 代码示例如下：

>
  Link to an object with target="carbon-navigation-target"
</a>
