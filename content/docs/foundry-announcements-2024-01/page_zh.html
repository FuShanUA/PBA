为 Workshop 中的 Tabs 小组件引入增强的设计功能

发布日期：2024-01-25

应用程序构建者现在可以体验 Workshop 中 Tabs 小组件改进的主题设置和设计选项。此次更新在 Tabs 小组件的样式设置和配置方面提供了更大的灵活性，帮助构建者在创建模块时满足其功能和审美需求。

通过四种全新设计预设满足模块需求

应用程序构建者现在可以从四种设计预设中进行选择，以打造专业且时尚、适合各类模块需求的 Tabs 小组件。可用的预设包括：outline、block、prominent 和 grouped。

Tab 预设选项和预览。

在每个预设中，应用构建者可以通过定义额外的配置偏好设置（包括标签页大小）来解锁新功能。例如，选择小号、中号或大号标签页的选项有助于增强内容的可读性，同时使标签页能够更好地容纳其他小部件。标签页大小还可用于创建嵌套效果，让应用构建者能够在标签页之间建立层级结构。

1. 醒目的标签页，2. 使用不同标签页大小的嵌套效果，3. 分组的标签页

用于增强灵活性的额外显示和格式设置

借助新增的显示和格式设置，现在可以实现更强大的自定义功能，包括：

  • 颜色主题： 为标签页设置主色，并为标签页标签、图标和徽章的不同部分选择颜色。此选项有助于与容器背景形成对比，从而提升标签页对终端用户的可见性。
  • 方向和对齐： 选择以水平或垂直方式显示标签页。您还可以将标签页相对于标签页容器进行左对齐或居中对齐，这有助于优化小部件的整体文档流。
  • 条件可见性： 使用您选择的变量来确定选项卡应可见、禁用还是完全隐藏。借助此功能，您可以根据应用程序和用户的状态更好地隐藏或显示信息。

有关 Workshop 中 Tabs 部件的更多信息，请查阅更新后的 文档。

推出媒体集（Media Sets），一种整理非结构化媒体数据的新方式

发布日期：2024-01-25

媒体集将于 2024 年 1 月 29 日当周正式全面推出，使用户能够增强涉及非结构化数据的工作流功能。

一个 媒体集是具有共同架构的媒体文件的集合 ，旨在处理大规模非结构化数据，并便于对音频、图像和 PDF 等媒体项进行复杂处理（即将支持视频）。您可以使用媒体集来增强媒体工作流和管道，从而实现灵活的存储访问、计算优化以及特定于架构的转换。此外，您还可以选择创建直接从 Azure 或 S3 外部源系统读取数据的虚拟媒体集，从而省去繁重的数据传输和存储工作。 本地部署环境的用户可以通过 Palantir Support 启用媒体集功能。

媒体集支持导入音频、图像和 PDF。

适用于转换的灵活配置设置

媒体集可根据您的延迟要求配置为 带事务（类似于 Catalog 数据集），或 无事务 （此时类似于流）的模式。设置完成后，您可以使用部分现有的 开箱即用转换 ，这些转换可在 Transforms 中通过 transforms-media SDK 加以利用，同时对 Pipeline Builder 中更多转换功能的支持也正在积极开发中。

探索由媒体集驱动的新工作流

以下是引入媒体集后您现在可以完成的一些示例工作流：

  • 使用 Pipeline Builder 进行 PDF 文本提取： 使用 Pipeline Builder 轻松构建基于 PDF 源的复杂工作流。
  • 优化的缩略图和平台预览： 在整个平台上快速直观地查看上传的文件。 文件格式规范化：只需将文件上传到 MP3 媒体集，即可将 8 种以上的音频格式转码为 MP3。
  • Vortex 中的栅格切片（TIFF、NITF）： 上传您的地理空间影像，并使用媒体引用属性进行本体化，或直接使用 Vortex 的原生切片功能。
  • DICOM 图像支持： 无需在管道中进行预处理，即可在媒体集或 Workshop 应用中预览 DICOM 文件。

有关媒体集的更多信息，请参阅我们的 公开文档。

代码仓库中 TypeScript 对象上的函数 性能改进

发布日期：2024-01-16

我们很高兴地宣布，代码仓库中 TypeScript Functions on Objects (FoO) 的编写体验得到了改进。这些更新显著缩短了实时预览的加载时间和检查时间，并提升了编辑器的响应速度。

Code Assist 和 CI 检查中的函数发现速度现在提升了 10 倍以上

代码仓库会对 TypeScript 代码进行大量分析，以识别用户编写的函数、自动检测被读取和编辑的对象类型，并标记潜在的问题模式（例如不安全的类型转换）。由于函数发现工作流中的静态分析操作已被更高效的替代方案取代，实时预览加载时间和 CI 检查速度现在显著提升。

举例来说，在一个包含 50,000 多行 TypeScript 代码和 3,000 多个函数的测试仓库中，TypeScript 资产包版本 0.527.0 的函数发现耗时约 1.6 秒，而之前的运行时间为 25 秒，速度提升了 15.6 倍。

在基准测试仓库上，函数发现改进前（25 秒）与改进后（约 1.6 秒）的对比。

要享受这一速度提升，请将您的仓库升级到最新版本。前往仓库窗口右上角的省略号菜单并选择 升级。

升级您的仓库，体验更快的预览加载速度和 CI 检查。

性能更强的 Code Assist TypeScript 语言服务器

由于更好地处理了 CPU 密集型操作，代码补全等常用语言功能现在更加高效。

背景信息：TypeScript 语言服务器会主动处理每一次按键操作，以提供自动补全和错误识别。过去，大型仓库中的过期请求会创建不必要的长时间运行的子进程，从而降低系统响应速度。

TypeScript 语言服务器的自动补全和错误识别功能。

为了解决不必要的进程问题，现在会取消过期请求，并实施了多项其他优化。因此，语言服务器的效率得到显著提升，为使用 TypeScript 语言服务器版本 0.188.0 的用户带来更加响应迅速、无缝流畅的体验。

在文档中了解有关代码仓库的更多信息.

AIP Agent 小部件配置面板。

自动迁移 Checkpoints Admin 用户和组至 Control Panel 中的 Data Governance Officer 默认角色（2024 年 1 月 31 日之后）

发布日期：2024-01-09

Control Panel 中的 Checkpoints Admin 角色正在被弃用。当前的 Checkpoints 管理员工作流（配置组织范围的检查点 和 审查组织范围的记录）已授予给 Control Panel 中的 Data Governance Officer 默认角色，而在 1 月 31 日之后，所有被分配到 Checkpoints Admin 角色的用户和组将被自动迁移至 Data Governance Officer 角色。

当这些用户被迁移至 数据治理官 角色，他们将自动获得分配给该角色的当前和未来工作流的访问权限。请参阅下方屏幕截图，了解当前工作流的概览。很可能 检查点管理员 已经在承担某种数据治理职责，因此在大多数情况下，扩展他们对更多数据治理工作流的访问权限是合理的。否则，您可以创建并定义一个与当前 检查点管理员 角色权限一致的自定义角色，具体操作请参见下方提供的说明。

现有 DGO 工作流和设置，供参考。

为什么 检查点管理员 角色会被弃用？

该 检查点管理员 角色是控制面板中的一个旧版管理权限角色。这些旧版角色正在被逐步淘汰，取而代之的是默认组织角色，旨在提高平台管理员权限设置的可发现性、可读性和可定制性。

检查点本身是 Foundry 数据治理产品体系中的一个坚实支柱，而由于 检查点管理员 工作流都与数据治理相关，因此它们最适合由 数据治理官 默认角色持有。

创建并定义一个与现有 检查点管理员 权限一致的自定义角色（可选）

或者，如果您不希望将用户从 检查点管理员 迁移到 数据治理官，请按照以下步骤为您的 Checkpoint 管理员用户创建一个自定义角色。

首先，您可以查看授予 数据治理官 的工作流，方法是导航至 组织设置 > 组织权限 > 数据治理官 （在 Control Panel 中，如本公告中的第一张截图所示）。

如果您不想将所有 Checkpoints 管理员 用户迁移到 数据治理官 角色中，则可以为 Checkpoints 管理员定义一个自定义角色，并将您的用户移至该角色。这应该只需很少的时间（约 5 分钟）。

  • 在 Control Panel 中，前往 组织设置 > 组织权限 。
  • 要创建一个新的自定义角色，请选择 新建角色。
  • 为这个新角色授予“ 管理 Checkpoints 配置并审查 Checkpoint 记录 ”工作流。
  • 将所有用户和群组从 Checkpoints 管理员 应用程序管理员角色添加到这个新的自定义角色中。您可以前往以下位置查找这些用户和群组： 组织设置 > 组织权限 > 应用程序特定角色 > Checkpoints 管理员。

Checkpoints 管理员角色的组织权限详情。

  • ⚠️ 重要提示：请从 Checkpoints 管理员应用程序特定角色中移除所有用户和群组！ 在 1 月 31 日之后被分配到该角色的任何用户或组，都将被自动添加到 Data Governance Officer 角色。
  • 有关迁移的更多信息，请参阅以下文档页面：
    • 配置检查点条件
    • 组织管理员审查
