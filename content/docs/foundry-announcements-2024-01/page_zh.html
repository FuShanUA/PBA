Workshop 中 Tabs 部件推出增强的设计功能

发布日期：2024-01-25

应用程序构建者现在可以为 Workshop 中的 Tabs 部件体验改进的主题和设计选项。此更新在样式设置和配置 Tabs 部件方面提供了更大的灵活性，帮助构建者在创建模块时满足其功能性和美观性需求。

通过四种全新设计预设满足模块需求

应用程序构建者现在可以从四种设计预设中进行选择，以实现专业且美观的 Tabs 部件，满足各类模块的需求。可用的预设包括：outline、block、prominent 和 grouped。

标签页预设选项和预览。

在每个预设中，应用程序构建者可以通过定义其他配置偏好（包括标签页大小）来解锁新功能。例如，从小、中或大标签页中进行选择的选项有助于提高内容的可读性，并使标签页能够更好地容纳其他部件。标签页大小还可用于创建嵌套效果，使应用程序构建者能够在标签页之间建立层级结构。

1. Prominent 标签页，2. 使用不同标签页大小的嵌套效果，3. Grouped 标签页

额外的显示和格式设置，带来更强的灵活性

通过新增的显示和格式设置，现在可以实现更强的自定义功能，包括：

  • 颜色主题： 为标签页设置主色，并选择标签页标签、图标和徽章不同部分的颜色。此选项有助于与容器背景形成对比，提高最终用户对标签页的可见性。
  • 方向和对齐方式： 选择以水平或垂直方式显示标签页。您还可以使标签页相对于标签页容器左对齐或居中对齐，这有助于优化部件的整体文档流。
  • 徽章： 使用您选择的变量确定标签页应可见、禁用还是完全隐藏。此功能使您能够根据应用程序和用户的状态更好地隐藏或显示信息。

有关 Workshop 中 Tabs 部件的更多信息，请查阅更新后的 文档.

推出 Media Sets，一种组织非结构化媒体数据的新方式

发布日期：2024-01-25

Media sets 将于 2024 年 1 月 29 日当周正式发布，使用户能够增强涉及非结构化数据的工作流功能。

A 媒体集是具有通用 schema 的媒体文件集合 旨在处理大规模非结构化数据，并促进对音频、图像和 PDF 等媒体项的复杂处理（对视频的支持即将推出）。您可以使用媒体集来增强媒体工作流和管道，实现灵活存储、计算优化以及特定于 schema 的转换。此外，您还可以创建直接从 Azure 或 S3 外部源系统读取的虚拟媒体集，从而绕过繁琐的数据传输和存储流程。 本地部署的用户可以通过 Palantir Support 启用媒体集功能。

媒体集支持导入音频、图像和 PDF。

灵活的转换配置设置

可以根据您的延迟需求将媒体集配置为 带事务（类似于 Catalog 数据集），或 无事务 （类似于流）。设置完成后，您可以使用部分现有的 开箱即用的转换 这些转换可通过 transforms-media SDK 在 Transforms 中使用，Pipeline Builder 中对更多转换的支持正在积极开发中。

探索由媒体集驱动的新工作流

以下是随着媒体集的推出您现在可以完成的一些示例工作流：

  • 使用 Pipeline Builder 进行 PDF 文本提取： 使用 Pipeline Builder 轻松构建包含 PDF 源的复杂工作流。
  • 优化的缩略图和平台预览： 在整个平台中快速、直观地查看上传内容。 文件格式规范化：只需将文件上传到 MP3 媒体集中，即可将 8 种以上的音频格式转码为 MP3。
  • Vortex 中的栅格切片（TIFF、NITF）： 上传您的地理空间影像，并使用媒体引用属性进行本体化，或直接使用 Vortex 中的原生切片功能。
  • DICOM 图像支持： 在媒体集或 Workshop 应用中预览 DICOM 文件，无需在管道中进行预处理。

有关媒体集的更多信息，请参阅我们的 公开文档.

Code Repositories 中对象上的 TypeScript 函数（FoO）性能改进

发布日期：2024-01-16

我们很高兴地宣布 Code Repositories 中对象上的 TypeScript 函数（FoO）编写体验得到改进。这些更新显著缩短了实时预览的加载时间和检查时间，并提升了编辑器的响应速度。

Code Assist 和 CI 检查中的函数发现速度均提升 10 倍以上

Code Repositories 会对 TypeScript 代码进行深入分析，以识别用户编写的函数、自动检测读取和编辑的对象类型，并标记潜在的问题模式（例如不安全的类型转换）。由于函数发现工作流中的静态分析操作已被更高效的替代方案取代，实时预览加载时间和 CI 检查现在显著加快。

举例来说，在一个包含 50,000 多行 TypeScript 代码和 3,000 多个函数的测试仓库中，TypeScript 资产捆绑包版本 0.527.0 的函数发现耗时约 1.6 秒，而之前的运行时间为 25 秒，速度提升了 15.6 倍。

在基准测试仓库中，函数发现改进前（25 秒）与改进后（约 1.6 秒）的对比。

要享受这一速度提升，请将您的仓库升级到最新版本。导航到仓库窗口右上角的省略号并选择 升级.

升级您的仓库，以体验更快的预览加载时间和 CI 检查。

性能更佳的 Code Assist TypeScript 语言服务器

得益于对 CPU 密集型操作的更好处理，代码补全等常用语言功能现在更加高效。

作为背景信息，TypeScript 语言服务器会主动处理每次按键，以实现自动补全和错误识别。过去，大型仓库中过时的请求会产生不必要的长时间运行的子进程，从而降低系统的响应速度。

TypeScript 语言服务器提供的自动补全和错误识别功能。

为解决不必要的进程问题，现在会取消过期的请求，并实施了多项其他优化。因此，语言服务器的效率显著提升，为使用 TypeScript 语言服务器版本 0.188.0 的用户提供了更灵敏、更流畅的体验。

在文档中了解有关 Code Repositories 的更多信息.

AIP Agent 组件介绍

发布日期：2024-01-11

注意： 自 2026 年 4 月 27 日当周起，AIP Agent 部件已更名为 AIP Chatbot 部件。所有现有功能和特性保持不变。

AIP Agent 部件现已在启用 AIP 的注册环境中可用，是一项 Workshop 功能，可将 AIP Logic、函数以及由 LLM 驱动的本体论探索能力引入您的运营应用。此外，通过使用 Workshop 变量，该部件可以读取和写入您的应用状态。

AIP Agent 部件配置面板。

在应用上下文中扩展部件功能

您可以授予该部件访问工具（AIP Logic、对象上的函数、其他 Workshop 应用等）的权限，以在应用上下文中扩展其功能。例如，您可以在 AIP Logic 中定义一个由 LLM 支撑的函数，将其添加为工具，并在 Workshop 应用中查看 AIP Logic 调用的每次运行记录，以便在调试器中进行审查。

使 Agent 部件能够理解用户引用并与可视化交互

与其他 Workshop 部件一样，您可以在变量中保存和读取对象集。配置完成后，Agent 部件可以解读用户引用的主题，并更新预定义的对象集变量，随后可将该变量传递给 Workshop 应用中的其他部件。

使用默认 LLM 工具探索和遍历本体论

该部件还配备用于遍历对象、读取和筛选属性以及运行聚合的标准 LLM 工具。这些工具可以在部件的配置面板中进行管理。

对 Agent 部件进行白标定制，以契合您的应用场景

您可以编辑零状态、添加新徽标、更改 AIP Agent 部件的助手名称，并设置建议提示词，从而根据您预期的工作流定制 Agent 部件。

强大的配置功能，支持细致入微的使用场景

AIP Agent 部件提供一整套强大的配置选项，包括：

  • 定义部件的角色、配置工具和功能，并设置引用工具和变量的提示词

    • 此组件允许您在应用上下文中确立部件的角色。提供一段描述部件功能的提示词，并使用指定名称引用已配置的工具和变量 / 命令来引用工具和变量。该配置还便于设置部件可访问的工具和功能，您也可以在整个提示词中引用它们。

      AIP Agent 部件配置面板，其中基础配置和工具部分已填写。

  • 设置本体论和应用上下文

    • 自定义部件对 workshop 变量的访问权限，并配置部件应感知的对象类型。用户可以自定义 AIP Agent 部件对 workshop 变量的读取或写入权限，还可以为部件配置需要感知的对象类型。

      在部件设置中管理本体论和应用上下文。

  • 高级工具配置

    • 通过配置 LLM 对默认 AIP 工具的访问权限，实现对默认 AIP 工具的更严格控制。此组件提供自定义 LLM 对默认 AIP 工具访问权限的选项，让您能够更好地控制这些工具对部件的可用性。

自动迁移 Checkpoints Admin 用户和组至 数据治理官 2024 年 1 月 31 日之后 Control Panel 中的默认角色

发布日期：2024-01-09

直方图 Checkpoints Admin Control Panel 中的角色即将弃用。当前的 Checkpoints 管理员工作流（配置组织范围的检查点 和 审查组织范围的记录）已被授予 数据治理官 Control Panel 中的默认角色，1 月 31 日之后，所有分配给 Checkpoints Admin 角色的用户和组将自动迁移至 数据治理官 组织概览

当这些用户被迁移到 数据治理官 角色时，他们将自动获得分配给该角色的当前和未来工作流的访问权限。请参阅下面的截图以了解当前工作流的概览。很可能 Checkpoint Admins 已经在承担某些数据治理职责，因此在大多数情况下，扩展他们对其他数据治理工作流的访问权限是合理的。否则，您可以按照下面提供的说明创建并定义一个与当前 Checkpoints Admin 角色权限相同的自定义角色。

现有 DGO 工作流和设置，供参考。

为什么 Checkpoints Admin 角色将被弃用？

直方图 Checkpoints Admin 角色是 Control Panel 中的一个旧版管理权限角色。这些旧版角色正在被逐步淘汰，取而代之的是默认组织角色，以提高权限设置对平台管理员的可发现性、可读性和可定制性。

Checkpoints 本身是 Foundry 数据治理产品的重要组成部分，并且由于 Checkpoints Admin 工作流都与数据治理相关，因此最适合由 数据治理官 默认角色持有。

创建并定义一个与现有 Checkpoints Admin 权限相同的自定义角色（可选）

  • 管理检查点配置和审查检查点记录 Checkpoints Admin 将 Organization settings > Organization permissions > Application-specific roles > Checkpoints admin.

  • Checkpoints Admin 角色的组织权限详情。 ⚠️ 重要提示：请从 Checkpoints Admin 应用特定角色中移除所有用户和组！
