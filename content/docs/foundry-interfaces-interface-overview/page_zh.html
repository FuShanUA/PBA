接口

An 接口 是一种本体论类型，用于描述对象类型的结构及其能力。接口允许对共享相同结构的对象类型进行一致的建模和交互。例如，一个 Facility 接口可以包含 Facility Name 和 Location 属性。 Facility 可以由诸如以下对象类型实现： Airport, Manufacturing Plant，或 Maintenance Hangar，每个对象类型都可以包含额外的特定类型属性。

通过使用 Facility 接口，工作流可以与 Airport, Manufacturing Plant日 Maintenance Hangar 对象类型进行交互，无论是整体还是独立地，而无需了解这些对象类型的具体细节。此外，如果引入了实现该 Facility 接口的新对象类型，工作流将立即与这些新对象类型兼容，无需额外的重构。

请查阅 当前支持级别 以了解有关在平台中何处可以使用接口的更多信息。

接口功能

接口由接口属性、 链接类型约束, 操作类型约束日 元数据 组成。接口属性可以在接口上本地定义（推荐），也可以使用 共享属性来定义。一个接口可以由多个对象类型实现。

与编程语言中的接口非常相似，您可以 扩展接口 来创建一个继承原始接口属性的子接口，然后向子接口添加新的、更具体的属性。对象类型随后可以 实现该接口 以表明它们符合接口定义。对象类型可以实现多个接口，以用于不同的工作流。接口还可以扩展多个其他接口，包括那些自身扩展了其他接口的接口，从而形成通过多层接口继承的属性。

接口与对象类型的区别

在本体论中，接口与对象类型之间既有功能上的区别，也有样式上的区别。

对象类型是具体的；它们具有由共享属性或本地属性定义的结构，由包含属性值的数据集支撑，并且可以实例化为对象。

相比之下，接口是抽象的；它们具有由接口属性定义的结构，不由数据集支撑，并且不能直接实例化，而必须作为特定的对象类型进行实例化。

在样式上，接口在平台中通过图标周围的虚线与对象类型进行视觉区分。

当前支持级别

随着对接口本体论类型支持的不断扩展，其在 Palantir 平台中的可用性会有所不同。

接口目前在以下应用程序和服务中受支持：

  • 本体论管理器: 定义、编辑和实现接口。
  • 实现程序化 DevOps，使团队能够沿用现有流程，以自包含、可重现且经加密签名的捆绑包交付代码。: 打包和安装接口。
  • 函数: TypeScript v2 函数。

接口目前在以下应用程序和服务中受到部分支持：

  • 操作: 定义用于创建、修改、删除或关联实现接口的对象的操作。接口操作类型约束目前处于测试阶段，可用于定义实现接口的各对象类型的预期操作能力。
  • 对象集服务（Object Set Service）: 按接口搜索和排序对象。按接口聚合的支持正在开发中。对接口关联类型的支持正在开发中。
  • 本体论 SDK: 将接口用作与实现对象类型进行交互的 API 层。支持程度因语言而异；目前支持 TypeScript，对 Java 和 Python 的支持正在开发中。
