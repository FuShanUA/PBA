Spark 配置文件参考

本页面是 Foundry 中可用的 Spark 配置文件参考。在此处了解有关 Spark 和配置文件的更多信息：

  • Spark 概念
  • 应用 Spark 配置文件

驱动程序核心数

此系列中的配置文件用于配置以下参数的值 spark.driver.cores.

此参数控制分配给 spark driver 的 CPU 核心数。实际上，除非在同一 spark 模块中并发运行许多 spark 作业的特殊情况，否则无需覆盖此参数。

驱动程序内存

此系列中的配置文件用于配置以下参数的值 spark.driver.memory.

此参数控制分配给 spark driver JVM 的内存量。在某些情况下可能需要调大此值，例如将大量数据收集回 driver 时，或执行大型广播连接时。

此参数仅控制 JVM 内存，而不控制 Python 进程可用的内存。如果您要将大量数据拉取到本地以使用以下工具执行转换 DuckDB，则需要使用其他配置文件。

执行器核心数

此系列中的配置文件用于配置以下参数的值 spark.executor.cores.

此参数控制分配给每个 spark executor 的 CPU 核心数，进而控制每个 executor 中并发运行的任务数。实际上，在正常的 transforms 作业中很少需要覆盖此参数。

执行器内存

此系列中的配置文件用于配置以下参数的值 spark.executor.memory 及相关设置。

此参数控制分配给每个 spark executor JVM 的内存量。此内存在 executor 上运行的所有任务之间共享（由 Executor Cores 配置文件控制）。如果每个 spark 任务中处理的数据量非常大，则可能需要调大此值。

Executor 内存开销

此系列中的配置文件用于配置以下参数的值 spark.executor.memoryOverhead.

此参数控制在 spark executor JVM 内存之外分配给每个容器的内存量。如果您的作业需要在 JVM 之外使用大量内存，则可能需要调大此值。

Executor 数量

此系列中的配置文件用于配置以下参数的值 spark.executor.instances 及相关设置。

此参数控制为运行作业而请求的 executor 数量。增大此值会增加可并行运行的任务数，从而提升性能（前提是作业具有足够的并行度），但代价是占用更多资源。

实际上，只有在作业规模较大且有特定组织需求需要快速完成时，才需要覆盖此参数。

动态分配

此系列中的配置文件用于配置以下参数的值 spark.dynamicAllocation.enabled, spark.dynamicAllocation.minExecutors 和 spark.dynamicAllocation.maxExecutors.

此参数通过指定 executor 数量范围（而非固定数量）来控制为运行作业而请求的 executor 数量。Spark 会将请求的 executor 数量扩展至 maxExecutors，并在不需要时释放这些 executor。当所需 executor 的确切数量不总是一致时，或在某些可加快启动时间的场景下，这可能会有所帮助。模块不保证获得所请求的 maxExecutors 数量，并且由于 executor 数量可变，不同运行之间的性能可能会有所差异。

实际上，只有在作业规模较大且充分了解动态分配的优缺点时，才需要覆盖此参数。

自适应查询执行

此系列中的配置文件用于启用和禁用自适应查询执行（AQE）。

启用 AQE 后，Spark 会在运行时自动设置分区数，从而可能加快您的构建速度。它可以避免因分区过少而导致并行度不足，以及因小分区过多而导致开销过大。

AQE 的目标是使每个分区的输出大小保持在 64 MB 左右。例如，总输出大小为 512 MB 时将产生大约 8 个分区。

您可以使用此系列中的文件大小配置文件来增大目标大小。如果写入的数据会被频繁读取（例如在 Contour 分析中），建议使用 128MB 或更大的分区大小。

如果总输出较小但计算非常耗时（例如由于开销高昂的 UDF），您可能需要禁用 AQE。在这种情况下，AQE 可能会降低并行度并减慢计算速度。

每个任务的核心数

这些配置文件配置以下项的值 spark.task.cpus。它们属于 Miscellaneous 配置文件系列。

此项控制为每个任务分配多少个核心。实际上，很少需要覆盖此设置。如果您想控制作业的并行度，请查看 Executor Cores（执行器核心数） 来替代。

Arrow

使用这些配置文件可以启用或禁用 Arrow，用于 Pandas 和 PySpark 数据框之间的转换。要使用 Arrow，请确保您的 Transform 依赖于 pyarrow 包中导入。

调用 spark.createDataFrame() 时使用 Pandas 数据框或 toPandas()，Spark 必须序列化所有行，才能 在两种格式之间进行转换。对于大型数据框，这是一个缓慢的过程，可能成为 您的 Transform 的瓶颈。使用 Pandas Transform 时，在读取和写入数据时都会发生此序列化过程。

Arrow 是一种更高效的序列化格式，可显著加快此转换速度（如 Arrow 官网 ↗).

Kubernetes

此系列中的配置文件控制 Spark 作业执行方式的底层细节。

使用对底层机器 CPU 架构不敏感的库时，您可以使用配置文件强制 Spark 作业在特定架构上运行。某些环境只能访问 AMD 架构的机器；在这些环境中，使用 ARM 架构覆盖的作业将无法成功运行。

直方图 KUBERNETES_OPEN_PORTS_ALL 配置文件启用 Spark 执行器之间的网络通信，这是 分布式模型训练.

列统计信息

此配置文件启用逐列统计信息的计算，包括 min, max日 mean 值。此配置文件默认设置为 false ，这意味着只会计算逐列的 null 计数以及数据集级别的指标（例如行数）。
