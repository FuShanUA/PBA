Palantir MCP 现已支持工具搜索，可减少启动时的 token 用量

发布日期：2026-06-30

Palantir MCP 现已支持工具搜索，该功能在启动时仅公开一个工具 — search_tools — 而非完整目录，从而减少 token 用量。您的智能体只有在搜索到其他工具时才会将其激活，因此加载到上下文中的工具定义更少。

工具搜索的作用

启用工具搜索时，Palantir MCP 启动后将仅暴露 一个工具 — search_tools — 而非完整的工具目录。接下来：

  • 当你向智能体发送提示时，智能体会调用 search_tools 并传入你的任务的简短描述。
  • search_tools 将对目录进行排序 在本地 依据工具名称、类别和精选关键词， 激活 最匹配的工具，并返回它们的描述。这意味着无需额外的模型调用或网络往返。
  • 代理直接调用已激活的工具。

这可以保持上下文精简：代理无需预先加载数十个工具定义，而只加载与任务相关的少数几个。

已激活的工具将在会话的剩余时间内保留在您的工具列表和上下文中。重新连接到服务器会将您的工具列表重置为仅 search_tools.

客户端要求： 工具搜索依赖于您的 MCP 客户端在新工具被激活时刷新其工具列表，使用 tools/list_changed 通知。未进行动态刷新的客户端将无法看到新激活的工具。因此，Continue 不使用工具搜索。

如何启用该功能

工具搜索为可选功能。默认情况下，所有工具在启动时加载，行为与现在完全一致。要启用工具搜索，可采用以下任一方式：

  • 将 --tool-search 参数传递给服务器， 或
  • 设置环境变量 PALANTIR_MCP_TOOL_SEARCH=true

这两个选项是等效的；选择适合您配置的方式即可。

Claude Code (claude mcp add)

使用该标志：

claude mcp add palantir-mcp \
    --scope project \
    -e FOUNDRY_TOKEN=<token> \
    -- npx "-y" "palantir-mcp" "--tool-search" "--foundry-api-url" "https://<enrollment>.palantirfoundry.com"

请注意，新的 --tool-search 参数必须放 在 该 --之后，作为参数传递给 palantir-mcp （而不是 claude mcp add）。

或者，同样可以使用环境变量：

claude mcp add palantir-mcp \    
  --scope project \
    -e FOUNDRY_TOKEN=<token> \
    -e PALANTIR_MCP_TOOL_SEARCH=true \
    -- npx "-y" "palantir-mcp" "--foundry-api-url" "https://<enrollment>.palantirfoundry.com"

Agent Flows（专业代码智能体）

export const PALANTIR_MCP_CONFIGURATION: McpStdioServerConfig = {
  type: "stdio",
  command: "palantir-mcp",
  args: ["start", "--tool-search", "code-workspaces"],
  env: {
    FOUNDRY_PROXY_URL: `https://${process.env.FOUNDRY_PROXY_URL!}/`,
    FOUNDRY_SERVICE_DISCOVERY_V2: process.env.FOUNDRY_SERVICE_DISCOVERY_V2!,
    FOUNDRY_EXTERNAL_HOST: "https://<host>.palantirfoundry.com",
    FOUNDRY_PROXY_TOKEN: process.env.FOUNDRY_PROXY_TOKEN!,
    FOUNDRY_SCOPED_TOKEN: process.env.FOUNDRY_SCOPED_TOKEN!,
    MAESTRO_REPO_RID: process.env.MAESTRO_REPO_RID!,
    NODE_EXTRA_CA_CERTS: process.env.NODE_EXTRA_CA_CERTS!,
  },
};

请注意 "--tool-search" 参数。或者，您也可以改为将 PALANTIR_MCP_TOOL_SEARCH: "true" 添加到 env 块。

为全局分支引入新的生命周期功能

发布日期：2026-06-23

全局分支现在可以处于以下四种状态之一：活跃、非活跃、已合并和已归档（之前称为“已关闭”）。

  • 活跃： 一个您正在积极处理的开放分支。
  • 非活跃： 一个近期没有活动的开放分支。
  • 已合并： 一个更改已集成至目标分支的分支。
  • 已归档： 一个您已手动停用的分支。取代了之前的

本次功能发布改变了两个分支行为。分支不再自动关闭；近期无活动的分支现在会变为非活动状态。您还可以恢复在此版本发布后归档的分支，使其恢复为活动状态。

非活动分支

分支在一段时间无活动后会自动变为非活动状态。在这种状态下，平台会取消对本体论资源的索引，并在设定的期限后删除数据。非活动分支上资源的构建会立即失败。当分支变为非活动状态时，您会收到电子邮件通知和平台内通知。您可以重新激活该分支以继续工作。

归档分支

归档分支需要手动操作；归档始终是手动完成的。归档分支时，您会收到电子邮件通知和平台内通知。取消索引、构建失败和数据删除的工作方式与不活跃分支上的相同。平台会保留元数据（例如之前修改过的资源），因此您可以恢复已归档的分支。已归档的分支不会显示在分支选择器中。您可以在 Global Branching 应用程序中打开并恢复它们。

保留策略

数据删除和分支不活跃的时间期限可以在 Control Panel 的 全局分支保留策略设置下进行修改。

  • 分支不活跃：打开的分支在被标记为不活跃之前可以持续无活动的时间期限。默认值：35 天。
  • 分支数据删除：仅存在于不活跃或已归档分支上的数据在被删除之前的保留时间期限。默认值：7 天。

Control Panel 中的全局分支保留策略页面，您可在其中设置两个时间段（以天为单位）：一个是打开的分支在持续多长时间无活动后会被标记为非活跃，另一个是仅存在于非活跃或已归档分支中的数据在删除前的保留时长。

SQL Studio 是 Foundry 专用的 SQL 应用程序，现已正式发布

发布日期：2026-06-16

SQL Studio，即 Foundry 专用于编写和运行 SQL 查询的应用程序，现已于 6 月 15 日当周正式发布。SQL Studio 将交互式 SQL 分析引入 Foundry，同时覆盖表格数据和本体论对象类型，并由专门构建的 SQL 引擎和 AI 辅助查询编写功能提供支持。

SQL Studio 为表格数据和本体论对象的 SQL 分析提供了交互式的 AI 辅助界面。

SQL Studio 基于上下文 SQL 控制台 构建而成，该控制台内嵌于 Dataset Preview、Data Lineage 和 Ontology Manager 等应用程序中，现在提供了一个专用应用程序，支持对表格数据进行 SQL 读写、对本体论对象类型进行读取，并能够发布可复用的 Ontology SQL 函数。

由 Ontology SQL 和 Furnace 提供支持

SQL Studio 基于两个 Foundry SQL 引擎构建，这两个引擎共享一个通用的 Spark SQL 方言：Ontology SQL 用于查询本体论对象类型，Furnace 用于查询表格数据。

Ontology SQL 是 Foundry 的 SQL 引擎，用于查询本体论对象类型和多对多关联。查询通过内存计算路径直接针对对象存储执行，在支持的查询形态下实现快速响应，而更复杂的查询会自动路由到 Spark。

Furnace 是 Foundry 用于表格数据的 SQL 引擎。它根据工作负载在 Trino 和 Spark 之间动态路由查询，并同时支持读取和写入操作。

主要功能

SQL Studio 将完整的 SQL 分析体验集中于一处：

  • 统一的数据和对象查询： 在单个应用程序中查询表格数据和本体论对象类型，在数据模式和对象模式之间切换，同时使用通用的 Spark SQL 方言。
  • 低延迟交互式分析： SQL Studio 专为迭代开发工作流而构建。查询会被动态路由到最合适的计算引擎（包括针对受支持查询形态的更快速的非 Spark 选项），并在预热的完全托管计算资源上运行。
  • AI 辅助代码生成： 对话式 AIP 侧边栏可帮助您编写、解释和调试查询。它了解 Foundry 支持的 SQL 方言，并可查看您的编辑器内容，包括当前代码以及所引用的数据集、表和对象类型的架构。
  • 以表格或图表形式预览结果： 以表格形式查看查询结果，使用内置图表类型（折线图、柱状图、散点图、饼图和直方图）对其进行可视化，或创建由 Vega 驱动的自定义图表。结果限制可以配置：默认情况下，查询返回 1,000 行的预览，具有相应权限的用户每个查询最多可返回 10,000 行。
  • 保存并共享 SQL 工作表： 使用草稿区进行一次性分析，或将您的工作保存为 SQL 工作表。您可以私下保存工作表以供个人重复使用，也可以将其保存到项目中与同事共享。每次保存都会创建一个新版本，供您稍后查看和还原，而未保存的更改会自动暂存，因此您正在进行的工作可在不同会话之间保留。SQL Studio 支持多个编辑器标签页，因此您可以同时处理多个工作表。
  • 读写支持： 除了 SELECT 查询之外，SQL Studio 还支持对数据集执行 CREATE TABLE 操作； CREATE， INSERT， UPDATE，以及 DELETE 对 Iceberg 表执行的操作；以及 SHOW FUNCTIONS 元操作，用于列出所支持的 SQL 函数及其 schema。
  • 本体论 SQL 函数（测试版）： 定义针对对象类型的可重用、参数化的 SQL 查询，并将其发布为 SQL 函数。受支持的查询形式可在与本体论 SQL 查询相同的内存路径上以低延迟执行。可在整个 Foundry 中使用它们，包括在 Workshop、操作、Automate 和本体论 SDK 中。SQL 函数目前处于测试阶段，并非在所有 Foundry 环境中都已启用；如需加入，请联系您的 Palantir 代表。

入门

SQL Studio 可通过“应用程序”菜单访问。

有关 SQL Studio 功能的信息，请参阅 SQL Studio 文档。如需语法指导，请参阅 SQL 方言文档。要详细了解底层引擎，请参阅 Furnace 和 本体论 SQL 概述。
