目标

A 建模目标 是一个项目，将上下文、相关数据源、元数据和模型全部集中围绕一个特定的运营问题。您可以将目标视为建模问题的定义——该问题的 接口 ，而提交的模型则提供其 实现.

建模目标是建模生态系统的沟通枢纽，并作为系统记录，用于随时间推移评估、审查和逐步将模型解决方案投入运营。

目标与 指标 相关联，后者定义了提交到目标的模型应如何相互评估。

提交

当模型被 提交 到建模目标以进行管理和评估时，将创建该模型版本的一个副本。这一不可变的提交类似于代码的 Pull Request——提交模型时，您是在请求一次全面的审查。建模目标在功能上是潜在可用于生产的模型版本的目录。

Releases

模型提交后，可以将其 发布。发布是包含模型提交代码的带版本、打包且可用于生产的资产。可以将发布视为对目标中定义的建模问题的已接受解决方案。

发布包含可配置的环境标签（例如 "Staging" 或 "Production"）、用户定义的版本号以及一个简短的描述字段——发布说明。

已发布的模型支持 部署，即生产推理管道或交互式端点。可以将部署配置为获取最新的带标签发布。例如，具有 "Production" 环境的部署将获取最新的带 "Production" 标签的发布。

发布系统通过要求经由带标签和带版本的发布进行有意的升级，为生产部署提供保护，同时为生产管道提供可审计的模型版本历史。

部署

部署 使选定的已发布模型能够交付给消费者，包括生产管道、运营应用程序和 API 订阅者。

部署为 Foundry 中的模型提供了一个受治理的持续集成与持续交付（CI/CD）层。随着模型提交被审查和发布，相应的部署会自动获取新的模型版本而无需停机，同时保留血缘关系。

部署的类型

批量部署

批量部署 通过在指定的输入 Foundry 数据集上执行模型并将结果发布到输出数据集中，从而在管道内运行模型。它们利用分布式计算，适用于生产管道（例如，预测一个县内所有地址的房价）以及大规模非实时处理（如批量计算机视觉或文档分析）。即使部署的模型被切换，消费者也可以从一致的输出数据集中读取数据。

批量部署通常通过构建计划进行管理，并利用 Foundry 的 内部构建工具。权限从输入数据集、模型、目标和所属项目传播。 了解如何设置批量部署。

实时部署

对于低延迟或交互式场景，可以通过 实时部署来提供模型服务，它提供一个可交互查询的无服务器 REST API 端点。

实时端点可以独立设置权限，并以配置的复制和资源执行。它们还具有高可用性，这意味着可以通过 CI/CD 更新模型而不会导致端点停机。

您可以将实时部署集成到运营应用程序中 ，方法是为您的模型创建一个交互式实时端点 ，或使用 模型上的函数.

指标

建模中最关键的步骤之一是了解模型的性能如何以及在什么条件下表现良好。Foundry 使您能够生成和跟踪 指标 ，这些指标基于评估数据集以及该数据中的逻辑子集。指标及其关联的输入数据集支持以下系统中的评估工作流 《建模目标》.

可以生成指标 临时 （例如，在开发时），或作为建模目标的一部分系统性地生成 自动模型评估。随后这些指标将在模型预览中可见，并可与评估仪表板中的其他模型进行比较 评估仪表板.

A MetricSet 封装了单次模型评估的数值指标、图像和图表。 MetricSets 包含对相应模型（及版本）的引用，以及计算指标所用的单一数据集和事务（即版本）。此数据集引用被称为“输入数据集” MetricSet. 请参阅指标集可用的选项范围。

元数据

一个目标具有关联的、高度可配置的 元数据 可用于支持广泛的管理和协作工作流。可以在每次模型提交时收集自定义元数据字段，这有助于将模型相互比较。
