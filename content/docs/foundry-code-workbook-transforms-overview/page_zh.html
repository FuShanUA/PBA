转换

转换 是一些逻辑片段，它们接受一个或多个输入并返回单个输出。输入和输出可以是 Foundry 数据集或模型。

Code Workbook 目前支持三种类型的转换：

  • 选项卡，选择 转换允许用户使用自己选择的编程语言编写任意逻辑。
  • 模板 转换将代码抽象到一个简单的、基于表单的界面之后，该界面可在不同工作簿和用户之间复用。
  • 手动输入 转换允许用户将数据输入到节点中。

添加转换

在 Code Workbook 中，有多种方法可以添加新转换。

使用直方图中的 新建转换 按钮（位于图形左上角），您可以通过该按钮选择要添加的转换类型。例如，选择 Python 代码 以添加新的 Python 代码节点，或 模板 以打开模板浏览器。

或者，将鼠标悬停在图中的现有转换上，然后点击蓝色的 + 按钮以打开选择下拉菜单。新创建的转换将成为所选转换的子转换。

编辑转换

编辑名称

Code Workbook 中的转换可以保存为数据集。进一步了解 数据持久化.

未保存为数据集的转换由一个特定于工作簿的别名来标识，您可以通过该别名在代码中引用此转换。对于输入数据集以及已保存为数据集的转换，Code Workbook 会为每个数据集显示两个不同的名称：底层 Foundry 数据集的名称，以及一个特定于工作簿的别名。

使用别名有以下几个好处：

  • 您可以采用符合工作簿逻辑的直观方式来引用数据集。例如，如果两个名为“Titanic”的数据集位于不同的文件夹中，分别对应不同的更新频率，您可以将其中一个的别名设置为 titanic_historical，另一个则设置为 titanic_daily_feed.
  • 您可以自由编辑数据集别名，而不会更改在 Foundry 其他位置使用相同数据集的任何用户的数据集名称。
  • 您可以在分支上更改数据集的别名，并跨分支合并此更改。

要编辑数据集名称或其别名，请在逻辑面板中点击该名称，输入新名称，编辑完成后按 Enter 键。如果您更改了数据集名称或别名，系统将提示您根据需要自动更新另一个名称。

添加输入

点击任意转换即可打开逻辑面板。要添加输入，请点击顶部输入栏中的 + 按钮，然后点击所需的输入。

要添加多个输入，请使用 +.

选项卡，选择

代码转换会以代码编辑器的形式显示，并针对您在当前 Workbook 中使用的语言预先填充了基本结构。请参阅 语言文档 以了解每种语言编写代码的具体细节。

全局代码

直方图 全局代码 窗格允许您定义在 Workbook 中每个代码转换之前执行的代码。全局代码窗格可用于定义变量和函数，这些变量和函数在整个 Workbook 的转换中均可用。

模板

对于 模板转换，逻辑面板会显示一个表单，用于编辑模板参数。

  • 单击数据集参数后，单击图中的任意数据集，即可将其设置为该参数的值。
  • 列参数取决于输入数据集是否已指定。指定后，您可以从列名称的下拉列表中进行选择。
  • 对于整数和字符串等值参数，您可以输入自定义值。

手动输入

要添加手动输入节点，请点击图上的 手动输入 按钮。

在 手动输入 标签页中输入数据。目前支持的列类型包括 Double、Integer、Boolean 和 String。 仅支持 500 行。

复制并粘贴，轻松引入来自其他位置的数据。

运行转换

选择 运行 以在底部面板中执行选定的转换。要运行所有下游转换，请选择箭头图标并选择 运行所有下游转换.

运行转换需要对工作簿拥有编辑权限，还需要访问所有 标记 （即工作簿所使用的任何数据集用到的标记）。

此外，还有多个可用于快速运行代码的快捷键。键入 ? 即可查看快捷键列表。

有两种方法可以同时运行多个转换：

  • 在关系图中使用 Ctrl + Click 或 Cmd + Click 选择多个数据集。然后在关系图上的任意位置右键单击并选择 运行 N 个数据集 派生序列小部件
  • 点击顶部栏中的设置图标（），然后选择 运行所有转换.

当转换正在运行时，任何打印输出都会流式传输到“日志”选项卡。这使您能够在转换执行过程中打印输出，并在转换仍在运行时查看结果，这对于调试或测算逻辑的执行时间非常有用。

一旦保存到数据集，代码中应用的任何数据排序都可能不会保留。换句话说，如果您运行一个对数据进行排序的转换，当您以数据集的形式查看数据时，数据可能不会按该顺序排列，但转换中的其他操作仍会被应用。

预览

在 Code Workbook 中运行转换时，系统会计算一个 50 行的预览，以便查看结果的形态。在数据集完成写入 Foundry 之前，此预览会显示在预览标签页中。数据集持久化到 Foundry 后，预览标签页将更新为完整结果。

在可视化标签页中，您可以将图下载为图像或将其添加到报告中。这些操作也可通过上下文菜单执行。

非确定性转换

某些转换是非确定性的——即使输入数据和转换逻辑相同，它们也会返回不同的结果。一些可能导致非确定性转换的函数包括：调用当前时间戳、行号、单调递增 ID，以及对包含重复值的列进行排序后执行的转换。

在 Code Workbook 中，运行转换将启动两个作业：一个作业计算 50 行预览，另一个作业在完整数据集上计算转换并将结果写入 Foundry。如果存在非确定性转换，您在 50 行预览中看到的结果可能与 Foundry 数据集中的结果不匹配。

在转换中运行非确定性代码时，数据帧不一定会被物化。例如，假设您有一个非确定性转换 Transform A，它是 Transform B 和 Transform C 的父级。如果您在 Code Workbook 中分别运行每个转换，每个数据集都会按顺序写入 Foundry，从而在转换 B 和 C 之间产生一致的结果。但是，如果您在 A 上选择 "Run all downstream"（运行所有下游），由于在运行 B 和 C 时 A 不一定会被物化，您可能会看到相互冲突的结果。在 Data Lineage 中运行构建同样可以避免这种情况，因为每个数据集都会被物化并按顺序计算，而转换为 Pandas 数据帧亦是如此。

一些会导致非确定性转换的函数示例包括 current_date(), current_timestamp()日 row_count()，但其他函数也可能导致非确定性。有关 Spark 计算转换时可能产生意外行为的方式的更多信息，请参阅 Apache Spark 文档 ↗.
