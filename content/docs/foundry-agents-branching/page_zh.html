在全局分支上开发专业代码代理

Beta

专业代码代理目前处于 Beta 开发阶段，可能无法在您的租户中使用。在开发过程中，功能可能会发生变化。

专业代码代理可与 全局分支集成，让您能够与已分支的本体论和应用更改一同开发和测试代理代码，而不会影响 main 分支。在全局分支上运行的代理会自动将该分支用于 Ontology SDK (OSDK) 和 Ontology MCP 的读写操作。

分支上下文并不会延伸到每个接口。OSDK 和 Ontology MCP 操作针对的是选定的全局分支，但它们使用的本体论架构来自 main 分支，因此仅存在于全局分支上的本体论类型更改不会反映在生成的类型或可用工具中。Platform API 请求不具备分支感知能力，因此不会在选定的全局分支上运行。

Palantir MCP 不支持全局分支上下文。请勿使用 Palantir MCP 检查或修改全局分支上的资源。

先决条件

在全局分支上开发专业代码代理之前，请确保：

  • 您的租户已启用全局分支和代理分支功能。请联系 Palantir 支持团队申请访问权限。
  • 您拥有一个 角色 ，允许您编辑智能体的代码仓库，例如其项目中的默认 Editor 或 Owner 角色。
  • 智能体仓库使用支持全局分支（Global Branching）的模板版本。如果在将仓库添加到分支时 Foundry 报告该仓库已过时，请 升级该仓库 并重试。

将智能体仓库添加到全局分支

要在全局分支上开发智能体：

  1. 打开智能体的代码仓库或代码工作区。
  2. 打开分支选择器，然后创建或选择全局分支。
  3. 如果出现提示，请选择 添加 以将仓库添加到分支。

Foundry 会创建一个与全局分支关联的仓库分支，并在代码工作区中将其检出。在迭代过程中，请将智能体代码更改提交到此仓库分支。

在全局分支上测试智能体

在代码工作区中使用 npm run start运行智能体，具体说明请参阅 在 Foundry 中构建专业代码智能体。智能体模板会解析与已检出的仓库分支关联的全局分支。随后，OSDK 和本体论 MCP 操作将从该全局分支读取数据并向其写入数据。 由智能体库提供的 OSDK 客户端 会自动继承调用的全局分支上下文。如果通过其他方式构建客户端，则除非显式配置其分支上下文，否则它不会在全局分支上运行。

如果您的智能体调用了某个操作，请在测试该操作之前，在同一全局分支上索引该操作的目标对象类型。在 本体论管理器中，选择全局分支，打开目标对象类型，然后选择 索引对象类型 （位于横幅中）。等待索引完成后，再运行该智能体。

已发布的智能体函数在同一全局分支上的资源中被调用时，也会接收全局分支上下文。位于分支上的智能体函数及其写入的数据与 main 以及其他全局分支相互隔离。

在全局分支上发布智能体

发布后，该智能体函数即可供同一全局分支上的资源使用：

  1. 提交您想要发布的智能体更改。
  2. 选择 标记版本 （位于仓库界面中）。
  3. 选择全局分支，并选择一个稳定的版本目标。该版本目标将发布到 main （在全局分支合并时）。
  4. 选择 标记并发布。

Foundry 会创建一个分支预发布版本，并将代理函数发布到全局分支。请勿直接使用 Git 创建标签；仓库接口会创建全局分支所需的版本。

您可以在迭代过程中重新发布到同一版本目标。全局分支上使用该版本目标的资源会自动解析最新的分支预发布版本。已发布的函数无法从 main 或其他全局分支获取。

当代理函数已发布到另一个全局分支时，请勿在全局分支上更改代理 API 名称或本体论绑定。这些值用于跨全局分支标识该函数。

从全局分支合并代理

当代理及其依赖资源准备就绪后，请创建并合并 全局分支提案。Foundry 会合并仓库变更，并将选定的稳定版本目标发布到 main。之前使用分支版本目标的资源随后将解析 main上的稳定版本。

在合并之前，请确保版本目标在 main 上仍然可用，并解决 Global Branching 应用程序中显示的所有检查项。
