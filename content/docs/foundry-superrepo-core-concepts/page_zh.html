核心概念

Beta

SuperRepo 处于开发的 beta 阶段,在您的注册环境中可能无法使用。功能在持续开发过程中可能会发生变化。

SuperRepo 的生命周期分为三个步骤:开发、构建和部署。SuperRepo 允许您在本地通过预览进行开发,使用您选择的构建系统生成可重现的产物,并以编程方式部署该产物。您可以将该产物上传到 Marketplace,随后可将其安装到一个或多个注册环境中。

SuperRepo 可以由 Foundry 生态系统中的多个组件组成,每个组件都有其自身的复杂细节,这些细节在各自的文档章节中有所介绍。以下各节对 SuperRepo 中的一些概念进行了概括性描述。

开发

在开发过程中,Foundry CLI 会在本地运行您的 SuperRepo,以便您同时对本体论、函数和应用程序进行迭代。

预览

SuperRepo 预览的工作方式是在您的计算机上运行一系列本地服务器，以模拟与真实 Foundry 实例之间的部分交互。在预览模式下，SuperRepo 使用嵌入的本体论在本地提供本体论行为的近似模拟。函数在特定语言的预览运行时中运行，查询和函数支撑的操作则通过嵌入的本体论进行路由。您的 本体论 SDK 应用程序在本地托管，并针对这些服务器运行。

本体论即代码

本体论即代码为您提供了一种专业代码方式，用于在 SuperRepo 中定义您的本体论实体。您的对象类型、接口、操作和其他实体的 TypeScript 定义会在您的产品部署后被编译并物化为您注册环境中的真实实体。本体论即代码是您实体的事实来源，因此您应当通过代码定义来管理所有变更。

有关本体论即代码 API 参考，请查阅 其开源代码仓库 ↗。如需此工作流的 UI 优先等效方案，请查看 创建对象类型。

OSDK

SuperRepo 会自动为您的本体论即代码定义生成 SDK 绑定，这些绑定可在您的函数和本体论 SDK 应用程序中原生使用。本地开发服务器会监视本体论的变更，并在需要时自动重新生成绑定。

有关本体论 SDK 的文档，请参阅 本体论 SDK 部分。

导入

您的注册中已存在的本体论实体（包括在 本体论管理器中创建的实体）可以通过 foundry import ontology 命令导入到您的 SuperRepo 中，而无需在代码中重新定义。导入操作会为这些实体生成 OSDK 和本体论即代码类型，因此您可以在 SuperRepo 的各个组件中使用它们。该命令会将导入元数据写入一个锁定文件，您应当将该文件提交到您的仓库，因为代码生成基于该文件。有关导入工作流程的演练，请查看 教程：使用 SuperRepo 进行开发。

构建

构建步骤会将您的 SuperRepo 中声明的组件转换为单个可复现的构建产物，您既可以使用默认模板提供的构建工具，也可以使用自己选择的构建系统。

Foundry CLI

SuperRepo 通过针对每个组件的命令来管理构建和预览，这些命令位于 Foundry CLI。开箱即用，SuperRepo 提供了预先选定构建工具的模板，用于编排和管理构建步骤及其依赖项。但是，由于各组件构建采用模块化设计，您可以灵活地控制 SuperRepo 构建工作流。Foundry CLI 的设计使您能够自带构建系统，同时仍能生成 SuperRepo 构件。

持续集成

SuperRepo 的指导原则之一是它可以在平台之外进行托管、构建和部署。其中一个重要部分是能够从持续集成提供商处运行 SuperRepo 工作流。有两个工作流值得重点介绍：

  • 测试： 由于 SuperRepo 本身就是代码，因此测试起来非常简单。CLI 附带了嵌入式本体论，因此您可以编写涵盖整个工作流程的集成测试。对本体论进行 lint 检查是另一种成熟的模式：需要强制执行样式和设计模式准则的本体论所有者会编写 linter，在部署前检查代码中的实体定义。
  • 发布管理： 每个组件构建完成后，运行 foundry bundle --project-version <VERSION> 命令以生成最终的构建产物。 --project-version 选项需要一个语义化版本，该版本会成为 Marketplace 产品版本。在平台内的 SuperRepo 体验中，每个带有语义化版本标签的提交都会作为一个产品版本发布，并且 Git 标签会被传入 --project-version 选项。目标是让您能够灵活使用任何适合自己的发布流程。如果您的 foundry.yml 声明了多个产品，请改用 foundry bundle product 和 foundry bundle store 命令。请参阅 打包多产品 SuperRepo 了解详情。

部署

部署会将构建步骤生成的产物安装到一个或多个 Foundry enrollment 上，既可以由 Palantir 平台本身执行，也可以由外部 CI 系统执行。

Marketplace

SuperRepo 原生可编译为 Marketplace 产品 可安装在 Foundry 注册中。诸如 Marketplace 输入、目标注册和存储等安装参数可在 SuperRepo 内部进行静态配置，从而使安装成为一个自动化的零点击过程。

CLI 使用 foundry deploy 命令执行 Marketplace 部署。您可以通过环境 YAML 文件提供配置项。默认情况下， foundry deploy 会查找名为 env.yml的文件；传入 --env-file-path 可将其指向其他文件。要以交互方式创建该文件，请运行 foundry deploy configure。

内部部署

如果您的 SuperRepo 源代码托管在 Palantir 平台内部，请为您的仓库版本打上标签，Foundry CI 将为您构建并部署生成的产品。请查看 从 Palantir 平台部署 以了解完整工作流。

外部部署

如果您的 SuperRepo 源代码托管在 Palantir 平台外部，请使用 Foundry CLI 从您的终端或任何 CI 系统构建并部署它。请查看 从 Palantir 平台外部部署 以了解完整工作流。
