对象下拉菜单安全注意事项

对象下拉菜单验证中的静态值筛选器会暴露给所有能够查看该操作类型的用户。使用这些筛选器存在向无权查看被筛选对象的用户暴露属性值组合的风险。通过依靠对象属性或参数来筛选对象集，可以缓解此风险。这些值不会直接显示在界面中。

示例：数据隐私问题

举个例子，假设我们有一个带有 Investigation Name 属性的 Document 对象。在我们的操作类型中，我们对对象引用参数添加了一个筛选器，以便仅显示调查名称为 Area 51 Investigation 的文档。

在此情况下，我们可能会向无法查看这些文档的用户透露 Area 51 Investigation 是某些 Document 对象的属性值。

这仅适用于静态值筛选器。当通过参数或另一个对象的属性筛选 Investigation Name 属性时，不会引用 Area 51 Investigation，原因如下：

  • Investigation Name 参数由用户提供。不会向操作类型查看者透露任何有关底层数据的信息。
  • Investigation Object 参数将遵循此用户现有的对象可见性限制。

因此，这两个搜索查询均不构成数据隐私问题。

技术细节

在大多数情况下，操作后端会对操作类型定义中的敏感信息进行脱敏处理，以避免暴露敏感属性值。例如，无法编辑操作类型的用户将看不到操作提交标准。同样，用户在界面中查看操作类型定义时，或在后端检查响应时，都无法看到新的对象下拉筛选器。

然而，在查看操作表单时，对象下拉列表验证会被转换为一个对象集。这意味着用户可以查看包含此对象集的网络请求。在上面的示例中，用户将收到一个包含 Investigation Name = 'Area 51 Investigation' 筛选器的对象集 RID，即使他们无法查看其任何对应对象，也会揭示该属性值的存在。

这意味着这些值将不会在界面中对任何用户可见。如果可见性是比安全性更值得关注的方面，则可以忽略此警告。
