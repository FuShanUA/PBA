HyperAuto V2 架构

本页面介绍 HyperAuto V2 的架构。有关 HyperAuto V1 架构的说明，请访问 HyperAuto V1 概述.

HyperAuto V2 围绕数据集成工作流的三个主要组件提供编排和自动化功能—— 数据同步, Builder 管道日 本体论 ——以便从支持的源自动生成可直接使用的输出。

HyperAuto 利用数据源的元数据，实时查询源，从而对如何构建同步、应应用何种转换逻辑以及如何设计合适的本体论得出意见。

HyperAuto 管道是指由单个 HyperAuto 实例管理的所有资源，从同步到对象。每个管道以用户提供的源表列表作为输入，将其同步到 Foundry（如有需要），并将其转换为有价值的、可直接使用的输出数据集以及（可选的） 本体论对象。用户可以针对每个源创建多个 HyperAuto 管道，以满足其个性化需求。

数据同步

当不存在与源的直接连接时，HyperAuto 也支持使用静态文件，在这种情况下本节不适用。请参阅 基于文件夹的 SAP 文档 以了解更多信息。

HyperAuto 提供对源上全部可见表的访问。如果用户选择的源表未映射到现有数据同步，则会自动生成新的数据同步。

如果所选源表已存在一个或多个数据同步，默认将选择最新的同步。你可以在 输入配置 页面上通过悬停在 配置输入表 按钮上进行更改。在那里，你可以选择使用其他现有同步，或选择创建新的同步。

根据数据规模的不同，如果 HyperAuto 创建了新的数据同步，生成过程可能会显著延长。这是因为数据同步需要在 HyperAuto 其余流程（例如 builder 管道生成）开始之前完成一次初始运行。

数据转换（Pipeline Builder）

HyperAuto 管道中的数据转换可以将难以使用的源数据转换为经过清洗和丰富的输出，可直接用于分析和应用构建。

HyperAuto 管道由自动生成的 builder 管道 驱动——这是 Foundry 中主要的数据转换方法。

HyperAuto 根据源类型和用户偏好动态生成有主见的转换逻辑。用户可以通过选择 查看管道 在 HyperAuto 管道概述页面中查看此 builder 管道。对该管道的编辑需通过 提案.

HyperAuto 中可用的转换功能类型如下：

  • 清洗： 源系统导出的数据通常存在常见的“清洁度”问题，例如数据类型不正确、对 null / 空值处理不当，或字符串值中存在多余的空格。HyperAuto 提供有主见的转换选项来修复这些问题（以及更多）。
  • 重命名： 通过使用源的元数据，HyperAuto 可以将输出表和列重命名为具有描述性且易于理解的名称，而不是沿用通常难以人工阅读的 schema。
  • 连接（Join）： 源系统通常将相关信息（例如元数据）存储在单独的表中，例如在遵循“规范”数据模型时。HyperAuto 利用其对源数据模型的理解将这些表连接在一起，提供一套去规范化的、内容丰富的输出数据集，便于分析，并为本体论奠定坚实基础。
  • 过滤： HyperAuto 可以自动过滤掉不需要的行（例如重复数据），例如对变更数据捕获（CDC）输入进行去重。

同时支持 批处理 和实时 流式 两种管道模式，请参阅 配置选项 以了解更多详情。

本体论

HyperAuto 可以使用源的数据模型，基于生成的输出数据集动态生成 本体论 ，包括定义对象之间的语义关联。

启用此设置后，您可以在几分钟内从新的（受支持的）数据源直接生成完全定义的本体论，无需任何手动干预。

如果您对此功能感兴趣，请联系您的 Palantir 代表。

资源管理

HyperAuto 管道旨在完全控制其创建的所有资源，使用户能够持续获得系统的好处和升级，包括性能升级和错误修复。这些管道的设计也便于调整已生成的资源，例如向管道添加新的转换步骤或输入。

对底层资源（例如同步或 builder 管道）的任何编辑都必须通过 HyperAuto 应用程序进行管理，以避免变更冲突。

如有需要，删除 HyperAuto 管道资源将解除其对相应 builder 管道的所有权，从而可以像平常一样直接编辑 builder 管道。
