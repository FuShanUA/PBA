设置 agent

An 代理 是一个可下载的程序，安装在您的组织网络中，并通过 Foundry 的 数据连接 接口进行管理。代理能够连接到您的组织网络内的不同数据源。它们用于启用 代理代理出站策略 以提供对私有托管源的网络连接，并启用 代理工作器连接 以从这些源读取数据，并使用受限访问令牌安全地摄取到 Foundry。

本指南将引导您完成创建代理所需的步骤。首先，请完成以下操作：

  1. 登录 Palantir 后，导航至 数据连接 使用左侧的 侧边栏.
  2. 选择 代理 tab.
  3. 选择 新建代理 （位于右上角）。

如果您没有看到创建新代理的选项，则可能没有执行此操作所需的角色。 在 Control Panel 中了解有关管理代理创建工作流的更多信息。

代理运行后，如果您想将数据源连接到 Foundry，则必须获取代理可用于安全读取数据的数据源系统凭据。根据您组织的网络设置，您可能还需要配置网络设置，以允许代理访问源系统。

查看以下部分，开始设置您的代理：

设置

创建代理主机

代理程序要成功运行，必须托管在合适的环境中（理想情况下是使用 Linux 作为操作系统的环境）。

Foundry 代理最常用的托管方法是在云环境中配置 Linux 虚拟机 (VM)。例如，您可以在 AWS、Azure 或 GCP 中配置 Linux VM，但也可以将代理托管在您组织拥有的 Linux 服务器上。虽然可以在 Windows 上托管 Foundry 代理，但 Palantir 不建议这样做，只有在无法在 Linux 环境中托管时才应使用。

用于代理的主机应专用于运行单个 Foundry 代理，不应与任何其他服务或进程共存。 不支持在同一台机器上运行多个 Foundry 代理。

有了合适的代理托管位置后，下一步是确保主机满足 Foundry 代理正常运行所需的硬件和操作系统要求。这些要求包括以下内容：

  • 64 位 Linux 或其他 Linux 操作系统（建议使用 RHEL 8 或更高版本、Ubuntu 22.04 或更高版本或同等版本）

    • 代理运行在自带的、为 Linux/x86-64 编译的 JDK 上。如有必要（例如在 AWS Graviton 或其他基于 ARM 的 CPU 上运行时），可以通过修改以下值在单独的 JDK 上运行代理 javaHome in service/bin/launcher-static.yml.

      我们通常不建议在单独的 JDK 上运行代理，且未来可能不再提供对此的支持。

  • 4 个 CPU 核心

  • 16 GB RAM

  • 500 GB 可用磁盘空间挂载于 /opt （建议使用 SSD）

建议的限制如下：

  • 核心文件大小： 硬限制和软限制均为 0
  • 打开文件数： 硬限制和软限制均为 262144
  • 运行中的进程： 硬限制和软限制均为 65536
  • 堆栈大小： 硬限制和软限制均为 32768 (KB)
  • 最大锁定内存： 硬限制和软限制均为“无限制”

配置 agent 网络访问

代理仅向 Foundry 发起出站连接。要成功建立网络访问，您必须允许以下内容：

  • 代理主机上的出站
  • Foundry 中的入站

允许出站和入站后，通过在代理主机上执行以下命令，验证您的主机是否可以与 Foundry 虚拟私有云 (VPC) 通信：

curl -s https://<your domain name>/magritte-coordinator/api/ping > /dev/null && echo pass || echo fail

如果一切按预期运行，您应该会看到 pass 作为输出； fail 表示与 Foundry VPC 的连接测试未完成。

代理主机上的出站

代理需要网络出口才能访问 Foundry VPC，该访问通过互联网进行。如果您的网络默认不允许出口流量，则可能需要进行特定配置，以允许从您的代理（和/或其主机）到您的 Foundry 实例的出站连接，例如开放防火墙或 配置代理 以实现出口访问。

您可以从 Data Connection 中代理设置工作流的 服务器设置 选项卡中复制 Foundry 的域名和端口，以正确配置出口网络访问。

Foundry 中的入站

Foundry 必须允许来自您服务器 IP 的入站流量。您可以在 Control Panel 的 网络入口 页面中管理入站规则。在您批准的入站规则之外，您的 Foundry 域将无法被访问。

使用防火墙保护代理主机

我们强烈建议在代理主机上配置防火墙，以监控网络流量并将其限制在严格必要的目标范围内。请务必仍允许代理主机与 Foundry 通信。可用的防火墙和监控选项取决于您运行代理所使用的操作系统，以及您组织的安全最佳实践。

设置自动重启

如果您未设置自动重启，那么每当代理崩溃或代理主机重启时，都会出现服务中断。

要为代理管理器设置在崩溃时自动重启，请运行命令 ${AGENT_MANAGER_DIR}/service/bin/auto_restart.sh 在虚拟机或机器终端上，以具有创建 cron 任务权限的用户身份，从代理管理器的服务目录中执行。

如果您需要停止自动重启（例如在升级代理管理器时），可以通过运行以下命令来实现 ${AGENT_MANAGER_DIR}/service/bin/auto_restart.sh clear.

将代理资源保存到 Project 中

接下来，您必须为新代理命名，并选择一个 Project 来保存它。在 Foundry 中，代理被视为一种 资源 ，保存到 Project 中以实现高度可配置的权限。

我们建议创建一个新的 Project 来存储您的代理。

Foundry 中的权限是一个广泛的主题。如果您想了解更多信息，可以参考以下资源：

  • 管理代理权限的建议
  • 关于如何为数据管道端到端设置权限的指南
  • 关于代理权限如何与 Project 和角色交互的完整参考

下载并安装代理

请按照主机上的平台内指南，在您已配置所需磁盘空间的目录中下载并解压安装包，然后启动代理。

如果您需要配置代理，更多详细信息请参阅 代理配置文档.

代理成功启动后，请按照步骤 配置自动升级 以确保您的代理保持更新。

后续步骤

现在您已创建、安装并启动了代理，请导航到 Data Connection 中的代理页面，您可以在其中 配置和监控代理的权限、健康状态和连接情况.

代理设置完成后，您可以继续 设置源 以将您的代理与组织的数据源连接起来。
