大规模使用媒体

媒体集限制

  • 可上传到媒体集的媒体项数量没有限制。
  • 事务性媒体集每次事务的上传限制为 10,000 项。
  • 非事务性媒体集没有项上传限制（因为没有事务）。
  • 媒体集中的项的路径不能超过 256 个字符。尝试将路径超过 256 个字符的项添加到媒体集将导致 MediaSet:MediaItemPathInvalid 错误。
  • 每个媒体项的最大文件大小为 50 GB。
  • 对于增量转换， 限制 媒体集输入的批量大小是受支持的。

限流

虽然可以大规模地与媒体集交互，例如上传或转换数百万个媒体项，但应实现错误处理，以确保管道稳定性。在大规模与媒体集交互时，媒体集服务可能会通过返回状态代码为 429 或 503 的服务质量（QoS）错误来进行限流。这表明媒体集服务目前无法处理存储或计算负载。

当服务进行限流时，客户端不应因 QoS 错误而失败，而应构建适当的重试机制。

例如，如果客户端通过向 /{mediaSetRid}/items提交 PUT 请求来上传数百万个媒体项，则客户端应重试任何收到 QoS 错误的媒体项上传请求。

在 Python 转换中使用 transforms-media 库时，通常已经内置了重试机制。例如，在将媒体文件从编目数据集上传到媒体集时，所提供的库方法已经内置了用于处理 QoS 错误的重试逻辑。
