在 Foundry 中构建专业代码智能体

本指南将引导你完成专业代码智能体的构建，从创建代码仓库到将智能体发布为 Foundry 函数。发布后，你就可以在 Workshop 或本体论 SDK 中调用该智能体。

前提条件

开始之前，请确保你具备以下条件：

  • 有权访问你的智能体将读取和写入的本体论。
  • 在 Foundry 环境中创建代码仓库的权限。

步骤 1：创建专业代码智能体

首先，为你的专业代码智能体选择一个 智能体模板 。选择 + 新建仓库 按钮以创建新的代码仓库，然后在 你要构建什么？ 下搜索，以找到与你的智能体框架匹配的模板。以下智能体框架均有可用的仓库类型： Claude Agent SDK ↗、 OpenAI Agents SDK ↗以及 Google Agent Development Kit (ADK) ↗。

选择模板后，请在仓库配置页面上完成以下操作：

  1. 为你的专业代码智能体输入 名称 ，并为仓库选择 位置 。
  2. 确认 仓库类型 与你的智能体框架匹配。
  3. 选择你的专业代码智能体将使用的 本体论 。此选择器为必填项，它决定了 本体论绑定 ，供智能体的 作用域权限使用。
  4. 查看 Agent API 名称。该名称根据仓库名称自动生成，可以编辑。当从 Workshop 或 OSDK 调用您的 pro-code 代理时，Agent API 名称用于标识该代理的函数。

生成仓库后，系统会将您导航至 在 Foundry 中构建代理 页面，并引导您完成构建 pro-code 代理的后续步骤。

生成的仓库遵循 文档中所述的结构，您的代理逻辑位于 agent/ 目录中，共享平台工具位于 utils/。

步骤 2：配置 pro-code 代理

生成的仓库附带适用于 本体论 SDK (OSDK)、 本体论 MCP (OMCP) 和 Palantir MCP 的简化配置。由于该代理使用作用域权限，您无需提供客户端 ID、密钥或 Foundry 令牌。

构建与您的本体论绑定的 OSDK 客户端，并获取本体论 MCP 配置：

在开发过程中，请在本地运行 pro-code 代理以测试其行为。在您的代码仓库中打开一个终端，安装依赖项，然后启动代理，并提供您的 AgentArguments 架构中定义的任何参数：

步骤 5：发布 pro-code 代理

当您的 pro-code 代理成功构建后，即可通过标记版本来发布它。标记版本时，系统会将该代理连同其本体论绑定和代理 API 名称一同注册，并且模板的持续集成会将已打标签的构建部署为异步 Foundry 函数。

首先，提交您的更改。您可以在平台内的代码仓库界面中编辑并提交，也可以在您的编辑器中使用 适用于 Visual Studio Code 的 Palantir 扩展。

然后，通过以下任一方式标记版本：

  • 代码仓库界面： 选择 标记版本 以从您的默认分支创建发布标签，根据更改的范围设置标签名称，然后选择 标记并发布。此流程与其他 TypeScript 函数的发布方式相同。
  • Git 标签： 从您的本地克隆创建并推送 git 标签，例如 git tag 1.0.0 后跟 git push --tags。

第 6 步：运行专业代码代理

发布后，我们建议在 Automate 中，使用指向该代理函数的 函数效果 来运行该专业代码代理。你还可以通过 Workshop、 本体论 SDK以及本体论操作来调用该代理。

由于代理函数不返回任何值，请让你的专业代码代理将结果写入本体论对象，以便使用其输出。有关详细信息和注意事项，请查看 触发专业代码代理。

记录日志并调试代理

将 console.log()、 console.warn()或 console.error() 语句添加到你的 TypeScript 代理代码中，以便记录用于调试的信息。请包含有助于追溯某次特定运行的非敏感标识符和上下文。

日志消息显示的位置取决于代理的运行方式：

  • 在本地测试期间： 当你在本地使用 npm start 运行代理时（如 第 4 步所述），日志输出将与代理的响应流一起写入你的终端。
  • 发布后： 由于该代理以异步 Foundry 函数的形式部署，其运行时日志可在 工作流血缘中查看。打开某次特定的执行，然后选择 查看日志详情 ，以检查其 服务日志。

要查看跨多次执行的日志，请使用 日志搜索 从源执行器（即调用链中的第一个可执行资源）开始。例如，如果某个 Automation 调用了该代理，请从 Automation 节点而非代理函数开始搜索。

日志可见性取决于您的权限。您可以查看自己过去 24 小时内的执行日志，但在 CBAC 栈上除外。访问其他执行记录需要 编辑 权限（针对源执行器）、已启用的 日志访问，以及访问应用于日志的所有标记的权限。请遵循 有效日志记录指南 来选择日志级别并避免记录敏感数据。
