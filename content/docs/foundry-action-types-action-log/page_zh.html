操作日志

操作日志将成功的操作提交建模为对象类型，以便在对象感知的 Foundry 工具中进行分析和显示。使用操作日志对象类型作为决策工作流的输入，并监控本体论的变更。

操作日志旨在捕获通过提交操作做出的决策，并将这些决策作为本体论中的数据提供。对于需要记录对象所有编辑的用例， 编辑历史 可以为对象类型启用。

背景

操作是修改本体论并触发相关副作用的主要方式。通常，这些本体论修改是特定决策的结果，或伴随数据审计要求。操作日志简化了表示这些决策和数据编辑的对象类型的生成和维护。为了便于识别，生成的操作日志对象类型采用显示名称 [Log] <action type name> 和复数显示名称 [Logs] <action type name>.

何时使用操作日志

Foundry 提供了多项回答变更相关问题的功能，它们不可互换。请使用下表进行选择。

您需要回答的问题可使用的功能
做出了什么决策、由谁做出、何时做出以及在什么背景下做出？操作日志
无论编辑是如何进行的，该对象的每次编辑的完整历史是什么？编辑历史
此操作成功或失败的频率如何，需要多长时间？操作指标
如何撤销操作应用的编辑？撤销或还原操作
当操作开始失败时，如何收到警报？监控

这一划分的两个后果值得直接说明：

  • 操作日志记录 成功的 仅记录操作提交，不记录失败。 操作指标 跟踪失败。
  • 操作日志记录通过 操作类型进行的编辑。在操作类型之外应用的编辑（例如直接写入支撑数据源或旧版 Foundry Forms 回写）不会生成操作日志对象。这一区别在于路径而非客户端：通过 API 或 SDK 应用的操作类型会像在用户界面中一样生成操作日志对象，而 Object Explorer 内联编辑 由操作支撑，因此会被记录。如果您需要覆盖无论路径如何的每次编辑，请查看 如何应用编辑.

在何处配置操作日志

操作日志在 本体论管理器 中的两个独立位置进行配置。

要为单个操作类型生成操作日志对象： 打开操作类型并选择 功能 选项卡。找到 创建操作日志对象 部分，界面将其描述为 每次此操作成功触发时生成一个对象。启用开关，然后选择 生成对象类型 以创建支撑操作日志对象类型。

要要求编辑给定对象类型的每个操作都具备操作日志： 打开对象类型，选择 数据源 选项卡，然后找到 编辑 部分并启用 仅允许带操作日志的操作类型。界面将其效果描述为 所有编辑此类型对象的操作都需要操作日志才能运行。

操作日志要求开关在启用编辑之前处于隐藏状态

仅允许带操作日志的操作类型 仅在对象类型已启用编辑时才会出现。如果找不到该开关，请先启用 允许编辑 ，保存更改，然后返回 数据源 选项卡。查看 允许用户编辑对象和关联 了解如何启用编辑。再次关闭 允许编辑 也会清除此设置。

操作日志本体论

操作日志对象类型与操作类型一一对应。提交操作时会生成对应操作日志对象类型的一个新对象。这个新创建的对象会自动关联到所提交操作编辑的所有对象。通过将日志对象类型与操作类型一一对应地建模，操作日志可以捕获特定对象编辑之外的上下文，例如同时编辑了哪些其他对象，以及操作提交时世界的状态（由本体论表示）。

例如，设想一个 Close Alerts 操作类型，用于修改多个选定 Alert 对象的 "Status" 属性为 "Closed"。配置操作日志后，一次性关闭 10 个 Alert 对象将生成一个 action log 对象，其中包含指向全部 10 个对象的外键关联 Alert 对象进行语义搜索。

要应用由操作日志支撑的操作类型，用户需要拥有操作日志对象类型的相应权限，就像对该操作类型可能通过规则和函数创建或修改的任何其他对象类型一样。请查看 权限 以了解完整的操作类型权限模型。

操作日志 schema

直方图 创建操作日志对象 部分展示了它可以捕获的值，分为 要记录的值，分为 必需值 和 可选值。 必需值 组中的值不能从配置中移除。操作日志摘要在 摘要 上述章节 要记录的值.

必需值 包括以下内容：

  • 操作 RID： 单次操作提交的唯一标识符
  • 操作类型 RID： 单个操作类型的唯一标识符
  • 操作类型版本： 每次更新操作类型时自动递增的版本号
  • 当前时间戳： 操作的 UTC 时间戳。对于 Object Storage v2，这是 提交时间戳.
  • 当前用户： 提交用户的 Multipass 用户 ID
  • 已编辑的对象： 操作编辑的所有对象的主键值。不支持存储已编辑对象中主键以外的属性。

直方图 必需值 组还包括副作用和回退的来源信息，这在审计编辑发生原因时非常有用：

  • 操作调用的 webhook 的标识符，包括同步和异步
  • 操作发送的通知的标识符，以及被通知的用户
  • 操作应用所在的 场景 的 RID（如有）
  • 操作是否被回退，以及执行回退的用户和时间戳

可选值 包括以下内容：

  • 参数值
  • 对象引用参数的属性值 （如果启用了 allow multiple values ，则对象引用参数不支持此功能）

操作日志对象类型可以配置为存储未被操作编辑的对象属性。这使您可以存储数据编辑以及与本体论编辑的上下文或动机相关的信息。

回到 Close Alerts 操作类型的示例，设想这些 Alert 对象还有一个 "Priority" 属性，包含 "High Priority" 和 "Low Priority" 值，以及 "Created at" 时间戳和 "Source" 机器。操作日志支持存储这些属性，即使它们未被 Close Alerts编辑。通过在 "Priority" 上进行聚合，无需编辑该列，我们就可以回答诸如“大多数 "High Priority" 告警的来源在哪里？”或“关闭 "High Priority" 告警需要多长时间？”等问题。

摘要

直方图 摘要 部分（见上文） 要记录的值中保存了一个描述该操作的可自定义字符串。接口将其描述为 添加人类可读的摘要，说明发生了什么。您可以通过按 /.

操作日志时间戳

对于写入 Object Storage v2 的操作，操作日志和 编辑历史 使用相同的提交时间戳。操作在准备将编辑提交到存储时捕获此 UTC 时间戳。它并不表示编辑在查询中变为可见的确切时间。

由 当前用户/时间 in 操作规则 提供的时间戳表示操作执行的开始时间，并在整个执行过程中保持不变。因此，由此规则设置的时间戳属性的值可能早于操作日志时间戳。

例如，一个操作于 12:00:00 UTC 开始，并于 12:00:05 UTC 准备提交其编辑。规则值为 12:00:00 UTC。操作日志和编辑历史使用 12:00:05 UTC。

还原操作会保留其操作日志时间戳。操作日志会单独记录还原的时间戳。

限制与约束

在设计围绕操作日志的工作流之前，请先查看以下约束。

约束详情
属性类型一旦创建即固定操作日志属性的类型在属性创建后无法更改。如果日志映射到的源属性的类型随后发生更改，该操作类型将无法通过验证。要恢复，请创建一个具有新类型的操作日志属性，并更新映射以引用它。
摘要长度操作日志摘要最多接受 20 个部分。每个字面文本部分最多接受 50 个字符。此长度限制不适用于参数部分。
摘要内容操作日志摘要不能引用对象类型参数。
对象引用参数只有单值对象引用参数才能向日志提供属性值。带有 allow multiple values 已启用的参数不能。
媒体引用参数使用媒体引用的参数不会包含在操作日志中。
不回填启用操作日志不会为已提交的操作创建日志对象。日志记录从配置保存之时开始。
编辑限制操作日志对象与其他对象编辑一样，受相同的 规模和属性限制 约束。

函数支撑的操作类型上的操作日志

要为函数支撑的操作类型配置操作日志，支撑的 Ontology 编辑函数必须配置 Edits 溯源。请参阅 函数文档 以了解有关 Edits 溯源的更多信息。

操作日志时间线

您可以使用 《操作日志时间线》： Workshop 中的小组件在时间线中查看操作日志对象类型。配置时间线以支持数据审计，并回答“更改了什么、由谁更改、何时更改？”的问题。

在 Workshop 中，可以将操作日志对象类型合并在一起，以全面查看某个用例内或跨 Ontology 的编辑情况。

通过选择被编辑的对象类型来配置操作日志时间线。然后选择要显示哪些操作日志对象类型，以及所需的操作日志对象类型属性。

还可以使用 评论 小部件。

故障排除

当操作日志配置错误时，平台会显示以下消息。

消息含义和解决方法
Action Log required but not enabled某个操作类型没有操作日志，但其编辑的对象类型需要操作日志。请在 创建操作日志对象 上启用 功能 tab.
Associated object type is missing. Logs are not being recorded.此配置所支撑的操作日志对象类型已不存在，因此不会写入任何日志。请选择 生成对象类型 以创建新的操作日志对象类型。
Action log has no writeback dataset defined操作日志对象类型没有回写数据集，因此无法存储日志对象。请配置 回写数据源 （针对该操作日志对象类型）。
This property will not be used for logging until indexing is complete.新添加的操作日志属性正在等待索引。索引完成后，该属性的日志记录将开始。
Function has no Edits Decorator支撑该操作类型的函数未声明 Edits 溯源，而操作日志需要溯源。请查看 函数文档.

某些平台消息会提到 操作日志规则。这与 创建操作日志对象 部分中的配置相同（位于该操作类型的 功能 标签页。
