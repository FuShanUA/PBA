时间序列告警

时间序列告警是一种在时间序列数据满足用户指定条件时生成告警（即“事件”）的方法。您可以使用 Quiver 的 时间序列搜索 卡片，在时间序列数据中识别感兴趣的时段。此时间序列搜索背后的逻辑会被保存，并使用 Automate 将其复制到相同类型的对象上。当自动化运行时，任何新识别出的时间间隔都会作为对象输出到告警对象类型中。

告警对象类型可以存储来自一个或多个已配置自动化的告警数据，但它仅与一个评估作业相关联。因此，一个作业可以关联多个自动化。作业是一个 Spark 或 Flink 作业，可以在 Builds 应用程序中查看。具体而言，该作业会输出一个支撑该告警对象类型的数据集或流，其中每一行都是一次告警更新。

告警类型

平台支持对 批处理 和 流式 时间序列进行告警。

批处理告警

批处理告警会运行一个 Spark 任务，该任务会根据配置的规则增量读取并计算时间序列逻辑，以生成告警。 仅当新时间序列数据以数据集事务的形式到达时，才会生成新告警。这意味着接收告警的端到端延迟等于数据摄取到 Foundry 平台的延迟加上任务运行时间。 批量告警支持从数据集和流中读取数据。 但在流的情况下，数据是从 归档 中读取的，这会额外增加 10 分钟的延迟。

批量告警会尝试增量读取数据尾部，以降低计算成本并减少延迟。但是，对于某些插值设置或有状态操作，这可能会导致 与 Quiver 的结果存在差异。一般来说，规则的有状态程度越低，遇到的差异就越少。

流式告警

流式告警会运行一个 Flink 根据配置的规则增量读取并计算时间序列逻辑以生成告警的作业。 当相关时间序列的新数据点到达时，此计算会逐点进行。这意味着，在数据摄取到 Foundry 平台后，流式告警的端到端延迟应为秒级。 基于有状态逻辑的流式告警在输出结果之前可能需要一段“预热”期。例如，12 小时的滚动聚合需要约 12 小时的数据点。

流式告警仅支持流式输入。如果您的逻辑中存在非流式支持的时间序列同步，流式告警作业将无法解决这些告警。

监控与可观测性

您可以通过 Automate 应用程序监控时间序列告警自动化的健康状况和性能。为确保您的流式告警自动化正常运行，请同时检查评估作业状态和自动化执行历史记录：

  • 检查作业状态： 在您的自动化概览页面上，导航至 时间序列评估状态 部分。请验证该作业正在运行且状态正常，没有错误或警告。

  • 查看评估历史记录： 在 Automate 应用程序 中导航至您的自动化，然后选择 历史记录 选项卡。 历史记录 选项卡会显示最近的评估运行、时间戳以及表明评估成功还是失败的状态指示器。如果评估失败，请查看详细的错误消息以找出根本原因。

要求

以下各节说明了创建时间序列警报时必须遵循的要求：

时间序列对象类型

时间序列本体论是创建时间序列警报的前提条件。时间序列警报是针对 时间序列对象类型创建并存储在其上的，可以是 根对象类型上的时间序列属性 或 传感器对象。请查看 时间序列本体论文档 以了解更多信息。

逻辑要求

时间序列警报逻辑管理由 Quiver 提供支持。大多数 Quiver 时间序列操作在时间序列警报中均受支持；请查看时间序列警报逻辑中 支持的操作 的完整列表。

时间序列警报可以通过 Quiver 和 Automate 创建，但只能在 Automate 中编辑。我们建议先通过 Quiver 进行初步的探索性分析，以确定要编写哪些警报规则，后续管理则通过 Automate 应用完成。或者，如果您已经知道自己需要哪些规则，也可以使用 Automate 在精简的界面中编写简单的规则。

时间序列警报逻辑必须包含单个 根对象。根对象以及与根对象关联的传感器对象上的时间序列属性均可在逻辑中使用。有关根对象类型与传感器对象类型之间区别的更多信息，请查阅 时间序列对象类型 文档。

自动化

时间序列警报功能直接集成到 Automate 中。时间序列警报会输出到一个 Alert 对象类型，您可以选择在该对象类型上配置效果，效果可以是 操作 或 通知。如果更希望对生成的警报进行进一步的管道处理，则可以省略效果。 有关 Automate 特定配置的更多信息，请参阅 Automate 入门文档。

权限要求

要创建时间序列警报自动化，您需要具备 对象类型编辑权限 （针对您要将警报绑定到的对象类型）。要查看现有的自动化，您需要对该对象类型具备查看权限。

注意事项

时间序列告警自动化旨在用于监控健康数据中的异常事件。时间序列告警自动化 并非 旨在检查数据管道在数据量、质量等方面是否符合预期。对于这些情况，我们建议使用 Data Health 或 流监控。
