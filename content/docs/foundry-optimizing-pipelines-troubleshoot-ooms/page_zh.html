排查内存不足（OOM）错误

内存不足错误可能以以下几种方式在作业中表现出来：

  • 看到 “作业因阶段失败而中止”
  • 看到 “ExecutorLostFailure”
  • 看到 “Spark 模块在作业 [jobID] 使用它时终止。（ExitReason: MODULE_UNREACHABLE）”
  • 看到 与驱动程序失去连接

这些错误消息表明您已超出此构建所允许的最大内存。这通常不是平台的故障，而是您要求平台运行的构建本身的问题。您可以采取以下几个步骤来减少运行构建所需的内存。

要进行排查，请执行以下步骤：

  • 如果您的转换是用 Python 或 Pandas 编写的：
    • 尽可能将您的计算迁移到 PySpark 中，以利用整个计算集群的强大能力。纯 Python 和 Pandas 中的逻辑在驱动程序中的单个处理器上执行，可能比您的笔记本电脑还要慢。
  • 如果您的转换使用了连接（join）：
    • 查找“空值连接”——即连接到许多行值为 null 的列。这会显著增加连接的内存消耗。要解决此问题，您可以在转换或之前的转换中过滤掉问题列中的 null 值。
    • 查找会大幅增加输出数据集行数的连接，并确认这是否必要。一个技巧是运行一个 Analysis 来计算数据集中每个键的行数以及连接后的结果行数。
    • 查找可以进行检查点（checkpoint）的递归连接。对单个表的重复连接会导致查询计划迅速膨胀。使用检查点来缓存中间结果以避免这种情况。
  • 检查输入数据集中文件的大小 （数据集 → 详情 → 文件 → 数据集文件）。每个文件应至少为 128MB。如果文件太小或太大，您需要对其进行重新分区。
  • 将转换拆分为多个较小的转换。这也有助于您确定转换的哪一部分导致了失败。
  • 从输入数据集中删除不需要的列，或对数据集进行预过滤以删除不需要的行，从而减少 Spark 需要在内存中保存的数据量。
  • 如果可以，请简化转换的逻辑。
  • 在代码优化不足以成功构建作业的情况下，您可以分配额外的资源，但这样做可能会增加与构建相关的计算成本。有关分配额外资源的更多信息，请参阅：
    • 何时修改默认的 Spark 配置文件：根据您的错误，提供关于应增加哪些 Spark 配置文件的指导。
    • Spark 配置文件参考：Foundry 中可用的 Spark 配置文件列表。
    • 应用 Spark 配置文件：有关如何将自定义 Spark 属性应用于作业的说明。
