元数据参考

属性在本体论中由以下元数据表示：

  • ID： 属性的唯一标识符，主要用于在配置应用程序时引用该属性。例如， start-date 可以是开始日期属性的 ID。
  • 显示名称： 在用户应用程序中访问该属性值时向用户显示的名称。例如， start date 属性的显示名称可以是 Start date.
  • 描述： 任何人都可以在用户应用程序中阅读的关于该属性的说明文本。例如， start date 属性的显示名称可以是 The day the employee began new hire training.
  • RID： Foundry 中每个资源自动生成的唯一标识符。属性的 RID 将在平台各处的错误消息中被引用。
  • 状态： 向用户和其他本体论构建者表明该属性在开发流程中所处的阶段。它可以是 active, experimental，或 deprecated。默认情况下， start date 属性的状态为 experimental。阅读更多关于 状态的信息.
  • API 名称： 在代码中以编程方式引用该属性时使用的名称。例如， start date 属性的显示名称可以是 startDate。阅读更多关于 API 名称（TSv1）.
  • 键： 指示该属性是否为对象类型的标题键或主键。
    • 直方图 标题键 是充当该类型对象显示名称的属性。例如，将 full name 属性设置为 Employee 对象类型的标题键后，将使用该属性的值（例如虚构的员工 “Melissa Chang” 和 “Diego Rodriguez”）作为各个 Employee object.
    • 直方图 主键 是充当对象类型每个实例唯一标识符的属性，这意味着支撑数据源中的每一行在该属性上的值必须不同。例如， employee number 属性的值可用于将 “Melissa Chang” 标识为组织内的一名唯一员工。
  • 基础类型： 指示该属性值的类型，并确定用户应用程序中可用的操作集合。例如， start date 属性的基础类型为 date。用户应用程序将允许您使用该属性配置时间线小部件。
  • 值格式化： 根据属性的基础类型，可以对属性应用数值格式化、日期和时间格式化、用户 ID 和资源 ID 格式化，将其原始值转换为用户应用程序中更易读的形式。阅读更多关于 和.
  • 条件格式化： 在属性上设置的规则，用于规定该属性值在面向用户的应用程序中的渲染方式（例如颜色、对齐方式等）。例如，您可以在 full name 属性上设置一条规则：如果 start date 属性的值早于两周之前，则将其值显示为绿色，以在用户应用程序中表明这是一名新入职员工。阅读更多关于 条件格式设置.
  • 类型类： 由用户应用程序解析的其他元数据。阅读更多关于 类型类的信息.
  • 渲染提示： 向用户应用程序发出的关于如何渲染该属性的指示，可能与同一基础类型的大多数属性不同。许多渲染提示可用于影响该属性所定义的对象类型重新索引的性能。例如，如果您不希望任何用户在用户应用程序中对 start date 属性进行搜索或排序，您可以取消选择 searchable and sortable 渲染提示，从而提高 Employee 对象类型的重新索引性能。阅读更多关于 渲染提示的信息.
  • 可见性： 向用户应用程序指示该属性的显示突出程度。 prominent 属性将使应用程序优先向用户显示该属性。 hidden 属性不会出现在用户应用程序中。默认情况下， start date 属性的可见性为 normal.

了解有关在本体论中创建和配置属性以及属性元数据验证要求的更多信息。

支持有限的属性基础类型

某些属性基础类型的支持有限。这些类型带有 Limited support 标记，该标记在属性基础类型选择器中可见。

  • byte:
    • 此类型的属性不能在操作类型中使用。
  • float:
    • 此类型的属性不能在操作类型中使用。
  • short:
    • 此类型的属性不能在操作类型中使用。
  • vector:
    • 向量只能通过以下方式查询： KNN (TSv1).
    • 向量最大维度为 2048。

有关操作类型中属性基础类型限制的更多信息，请参阅 有关受支持属性类型的文档.
