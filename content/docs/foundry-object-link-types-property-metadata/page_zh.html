元数据参考

属性在本体论中由以下元数据表示：

  • ID： 属性的唯一标识符，主要用于在配置应用程序时引用该属性。例如， start-date 可能是开始日期属性的 ID。
  • 显示名称： 在用户应用程序中，向访问该属性值的所有用户显示的名称。例如， start date 属性的显示名称可能是 Start date。
  • 描述： 有关该属性的说明文本，任何人都可在用户应用程序中阅读。例如， start date 属性的描述可能是 The day the employee began new hire training。
  • RID： 为 Foundry 中每个资源自动生成的唯一标识符。属性的 RID 将在整个平台的错误消息中被引用。
  • 状态： 向用户和其他本体论构建者表明该属性在开发流程中所处阶段的信号。它可以是 active、 experimental或 deprecated。默认情况下， start date 属性的状态将为 experimental。详细了解 状态。
  • API 名称： 在代码中以编程方式引用该属性时使用的名称。例如， start date 属性的 API 名称可能是 startDate。详细了解 API 名称。
  • 键： 指示该属性是否为对象类型的标题键或主键。
    • 该 标题键 是充当此类型对象显示名称的属性。例如，将 full name 属性设置为 Employee 对象类型的标题键后，将使用该属性的值（例如虚构员工“Melissa Chang”和“Diego Rodriguez”）作为各个 Employee 对象的显示名称。
    • 该 主键 是充当对象类型每个实例唯一标识符的属性，这意味着支撑数据源中的每一行在该属性上的值都必须各不相同。例如， employee number 属性的值可用于将“Melissa Chang”标识为组织内的唯一员工。
  • 基本类型： 指示此属性的值类型，并确定用户应用程序中可用的操作集合。例如， start date 属性的基本类型为 date。用户应用程序将允许您使用此属性配置时间轴小组件。
  • 值格式设置： 根据属性的基本类型，可对属性应用数值格式设置、日期和时间格式设置以及用户 ID 和资源 ID 格式设置，从而在用户应用程序中将其原始值转换为更易读的形式。详细了解 值格式设置。
  • 条件格式设置： 在属性上设置的规则，用于规定该属性值在面向用户的应用中的呈现方式（例如颜色、对齐方式等）。例如，您可以在 full name 属性上设置一条规则，当 start date 属性的值距今不到两周时，将其值显示为绿色，以便在用户应用中表明这是一位新入职的员工。详细了解 条件格式设置。
  • 类型类： 由用户应用解读的附加元数据。详细了解 类型类。
  • 渲染提示： 向用户应用发出的关于如何渲染该属性的指示，其渲染方式可能不同于大多数具有相同基础类型的属性。许多渲染提示可用于影响定义该属性的对象类型的重建索引性能。例如，如果您预计不会有任何用户在用户应用中对 start date 属性进行搜索或排序，则可以取消选择 searchable 和 sortable 渲染提示，从而提升 Employee 对象类型的重建索引性能。详细了解 渲染提示。
  • 可见性： 向用户应用指示显示该属性时的突出程度。具有 prominent 可见性的属性将使应用优先向用户显示该属性。具有 hidden 属性将不会出现在用户应用程序中。默认情况下， start date 属性将具有可见性 normal。

仅受有限支持的属性基本类型

某些属性基本类型仅受有限支持。这些类型会标有 Limited support 标签，该标签在属性基本类型选择器中可见。

  • byte：
    • 此类型的属性无法在操作类型中使用。
  • float：
    • 此类型的属性无法在操作类型中使用。
  • short：
    • 此类型的属性无法在操作类型中使用。
  • vector：
    • 向量只能通过 KNN进行查询。
    • 向量的最大维度为 2048。

要详细了解操作类型中属性基本类型的限制，请参阅 有关受支持属性类型的文档。
