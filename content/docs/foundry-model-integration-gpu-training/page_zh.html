使用 GPU 训练模型

本页概述了在 Foundry 中训练机器学习模型时利用 GPU 资源的流程。GPU 加速可以显著缩短深度学习模型和其他计算密集型算法的训练时间。在 Foundry 中使用 GPU 训练模型的推荐方法是使用 Jupyter® 代码工作区 （已配置一个或多个 GPU）。

前提条件

只有源自分配了 GPU 资源队列 的项目中的作业才能使用 GPU。您可以通过选择项目文件树视图右侧边栏中的旗帜图标，检查您的项目是否已配置资源队列，如下所示。

资源管理管理员 拥有为项目分配资源队列所需的权限。该用户组可以在控制面板中进行配置。资源队列可以在资源管理应用程序中分配，该应用程序可从左侧边栏的 应用程序 部分访问，也可以通过选择上述示例中显示的链接访问。如果您不属于该用户组，请联系您的 Palantir 管理员或 Palantir 代表为您的项目启用 GPU，为此需提交 Foundry Issue。

有关支持的 GPU 类型以及 GPU 如何影响计算资源使用量的详细信息，请参阅 代码工作区 或 代码仓库 计算使用量文档。请注意，根据您的托管配置，文档中列出的 GPU 类型可能并非全部都适用于您的注册环境。您的注册环境可能没有任何可用的 GPU 类型。请联系 Palantir 支持团队，以启用您的注册环境中当前不可用的 GPU 类型。

在 Jupyter® 和 VS Code 工作区中使用 GPU

可以在代码工作区侧边栏的 Settings 菜单中请求 GPU，无论是 VS Code 还是 Jupyter® 工作区：

要获取包含支持 GPU 的 TensorFlow、PyTorch 或类似软件包的环境，您可以在配置了 GPU 的代码工作区中安装该软件包。

以下步骤概述了如何在代码工作区中成功设置 GPU：

  1. 启动一个代码工作区，并在 Settings 菜单中启用 GPU。
  2. 安装您所需的机器学习库（例如 TensorFlow 或 PyTorch），可使用 Maestro 或 Libraries 侧边栏， 但需在 将 GPU 添加到工作区后进行。
  3. 验证是否已安装支持 GPU 的软件包版本。请查看下方的 验证步骤 ，了解有关如何验证的更多详细信息。
  4. 如有必要，请重置或更新您的环境，以确保已安装支持 GPU 的构建版本。请查看下方的 故障排除部分 ，了解更多信息。

故障排除

本部分针对 Python 中支持 GPU 的软件包的常见问题提供了快速参考。请查看下方的 Python 库注意事项 以了解更多信息。

安装的是仅 CPU 的软件包，而非 GPU 软件包

在配置 GPU 之前就安装 TensorFlow 等软件包是一个常见错误。如果发生这种情况，安装的将是该库的仅 CPU 版本。您可以检查锁定文件或安装日志中的构建字符串，以确认您的工作区是否属于这种情况。支持 GPU 的构建版本在名称中包含 cuda ，而仅 CPU 的构建版本包含 cpu。

解决方案： 安装该软件包 需在 将 GPU 添加到工作区之后进行，或者在添加 GPU 后重置环境。

详细信息： 在没有 GPU 的工作区中安装 TensorFlow 或类似库时，Conda 会解析为仅 CPU 的构建变体。构建字符串将包含 cpu ，如下所示： cpu_py310heba74a3_3。相比之下，支持 GPU 的版本将在构建字符串中包含 cuda ，例如： tensorflow-2.17.0-cuda120py310heb3ae67_203。以下是安装这些软件包时的日志示例：

您还可以通过查看 Lockfile （可在 Jupyter 的 Libraries 侧边栏中找到）来确认安装的是哪个构建版本。在 VS Code 中，锁定文件位于 .maestro/hawk.lock。编辑 meta.yaml 或 hawk.lock 文件不受支持,并可能导致问题;请始终使用 库 侧边栏或 Maestro 命令。

无法求解的环境错误:由于没有可行的选项,无法安装 CUDA

例如,尝试强制安装支持 GPU 的软件包, tensorflow=2.17.0=*cuda* 在没有 GPU 的情况下,此操作将失败,并出现无法求解的环境错误,该错误引用了 __cuda。

解决方案: 先向工作区添加 GPU,然后再安装该软件包。

详细信息: 如果您在没有 GPU 的工作区中通过指定构建字符串来强制安装支持 GPU 的软件包版本,conda 将因缺少 __cuda 虚拟软件包而无法解析依赖项。以下是尝试强制安装支持 GPU 的软件包版本的命令示例:

maestro env conda install tensorflow=2.17.0=*cuda*

您将看到以下错误消息:

ERROR ❌  Unsolvable environment error: ["tensorflow ==2.17.0 *cuda* cannot be installed because there are no viable options:
└─ tensorflow 2.17.0 | (...) | 2.17.0 would require
└─ __cuda *, for which no candidates were found."]

向工作区添加 GPU 不会触发新的环境求解

如果您在安装仅支持 CPU 的软件包后添加了 GPU,环境不会自动将已安装的软件包更新为支持 GPU 的版本。

解决方案: 重新安装软件包 (在 添加 GPU 之后),或使用以下命令重置环境:

maestro env reset --hard

或者,添加或移除依赖项以触发新的环境求解。

详细信息: 当 GPU 被添加到已安装仅 CPU 版本软件包的工作区时，环境还原过程会使用现有的锁定文件，而该锁定文件仍然满足原始的仅 CPU 约束条件。因此，已安装软件包的支持 GPU 的版本将不会自动安装。要获取支持 GPU 的版本，您必须重新安装该软件包 在 添加 GPU 后，重置环境以强制重新求解，或更改依赖项以使锁定文件失效。不建议手动删除锁定文件；请始终使用受支持的命令来管理环境。

要在使用 Spark 的 Python 转换 中使用 GPU，请将 DRIVER_GPU_ENABLED 和/或 EXECUTOR_GPU_ENABLED 配置文件导入到您的项目中，并在您的代码仓库中使用它们。这不需要指定 GPU 类型，而是直接使用项目的资源队列中可用的 GPU 类型。详细了解如何 导入 Spark 配置文件。

除非您的代码或您所使用的库支持在 Spark 上分发推理或训练，否则您需要确保您的代码能够处理诸如将模型训练和推理工作分发给执行器之类的任务。

优先使用轻量级作业，而非仅 driver 的 Spark 作业

与使用仅 driver 配置的 Spark 相比，使用轻量级转换是性能更优的选择。Spark 在分发工作以及将 Spark DataFrames 转换为 Python 对象（例如您的模型可能需要的 Pandas DataFrames）时会引入开销。我们建议使用 lightweight 装饰器来避免使用 Spark 转换，除非您希望将工作分发给执行器，或者您的模型可以原生使用 Spark DataFrames。其中一个例外是以容器方式运行模型，相关说明请参阅 下文。请注意，以容器方式运行模型仅在 Spark 转换中受支持，在轻量级转换中则不受支持。

在代码仓库中安装支持 GPU 的软件包

以下说明仅适用于在 Palantir 平台的代码仓库用户界面中管理的仓库。要在基于浏览器的 VS Code 中使用支持 GPU 的软件包，请参阅 上文中的代码工作区说明。

在代码仓库中，生成环境规范的 conda 环境求解过程与实际构建在不同的服务器上运行。执行 conda 求解的服务器没有 GPU，也无法配置为使用 GPU。取而代之的是，Foundry 允许用户通过使用 CONDA_OVERRIDE_CUDA 环境变量来指定希望运行的 CUDA 版本，具体请参见 conda 关于虚拟包的文档 ↗中的建议。要进行此设置，请在您的仓库中选择齿轮图标，切换 显示隐藏文件和文件夹，找到嵌套最深的 build.gradle 文件，并添加以下各行。您还需要指定您需要的是支持 GPU 的软件包，方法是安装 pytorch-gpu， tensorflow-gpu 或使用上文所述的构建字符串约束。

检查您支持的最大 CUDA 版本

要确定您的 GPU 支持的最大 CUDA 版本，请运行 nvidia-smi 命令，在启用了 GPU 的代码工作区终端中运行。输出结果的右上角将显示 CUDA 版本，表示支持的最高 CUDA 版本；您可以使用不超过该版本的任何 CUDA 版本。请选择与您的 GPU 和机器学习框架均兼容的 CUDA 版本。有关更多信息，请查看下方 Gradle 代码片段中的框架文档链接。

Python 库注意事项

conda 中支持 GPU 的软件包

Foundry 中的 Conda

我们建议使用 conda 而非 PyPI 和 Pip 来管理 Python 环境，因为 conda 不允许安装依赖项不兼容的软件包。发生冲突时，conda 会抛出错误并拒绝安装存在冲突的软件包。这确保了 Foundry 用于实现核心功能的 Python 库（例如 transforms-python 或 palantir_models ）无论用户尝试安装什么软件包，都能继续正常工作。

机器学习库（例如 tensorflow 或 pytorch ）通常只发布其软件包的 CPU 版本，以避免不必要地下载 GPU 训练所需的大型二进制文件（如 CUDA）。请务必确保已安装支持 CUDA 的库版本。否则，该库将无法检测并使用 GPU，模型训练将仅在 CPU 上运行。

Conda 会检查源系统上安装的 GPU，以确定要安装的软件包版本。如果系统上没有 GPU，conda 将选择该软件包的仅 CPU 构建版本进行安装。如果试图通过指定特定构建版本来强制安装支持 GPU 的软件包，将会导致 conda 的依赖项解析因系统缺少 GPU 而失败，并通过 __cuda 虚拟包，相关说明请参阅 conda-forge 文档 ↗。上文各节通过代码工作区和代码仓库的示例，帮助您更好地理解这一点的影响，以及如何在 Foundry 中使用 GPU。

Pip

如有需要，您也可以在代码仓库和代码工作区中使用 pip 安装软件包。请注意，这会在现有 conda 环境的基础上安装 pip 软件包及其依赖项，并忽略 conda 软件包的任何依赖项要求。

import torch
import time
import logging

logger = logging.getLogger(__name__)

A_cpu = torch.randn(5000, 5000)
B_cpu = torch.randn(5000, 5000)
start_time = time.time()
C_cpu = torch.matmul(A_cpu, B_cpu)
cpu_time = time.time() - start_time
logger.warning(f"CPU execution time: {cpu_time:.4f} seconds")

if torch.cuda.is_available():
    A_gpu = torch.randn(5000, 5000, device='cuda')
    B_gpu = torch.randn(5000, 5000, device='cuda')

    # Warm-up run to initialize the GPU
    _ = torch.matmul(A_gpu, B_gpu)
    torch.cuda.synchronize()

    # Actual benchmark
    start_time = time.time()
    C_gpu = torch.matmul(A_gpu, B_gpu)
    torch.cuda.synchronize()  # Waiting for GPU computation to finish
    gpu_time = time.time() - start_time

    logger.warning(f"GPU execution time: {gpu_time:.4f} seconds")
    logger.warning(f"GPU speedup: {cpu_time/gpu_time:.2f}x faster")

使用 GPU 时通过 sidecar 运行推理

当模型并非由其导入到的仓库生成，且该仓库正在运行推理时，需要导入模型的 Python 依赖项，并对照该仓库的依赖项对其进行解析。这可能会导致问题，例如模型的库被解析为不同的版本，或因依赖冲突而产生错误。当涉及复杂的支持 GPU 的依赖项时，情况尤其棘手。

在这种情况下，我们建议设置 use_sidecar=True 于 ModelInput 类中。这会与每个执行器和驱动器一起运行一个容器，该容器使用所需的 Python 环境加载模型。可以在 sidecar 容器上使用 sidecar_resources 参数请求 GPU，如下例所示：

from transforms.api import transform, Input, Output, configure, LightweightInput, LightweightOutput
from palantir_models.transforms import ModelInput
from palantir_models import ModelAdapter

# Using use_sidecar=True with @transform.using requires palantir_models version 0.2010.0 or higher.
@transform.using(
    inference_output=Output("path_to_output"),
    inference_input=Input("path_to_input"),
    model=ModelInput(
        "path_to_model",
        use_sidecar=True,
        sidecar_resources={"gpus": 1, "cpus": 3.4, "memory_gb": 16}
    ),
)
def compute(
        inference_output: LightweightOutput,
        inference_input: LightweightInput,
        model: ModelAdapter
    ):
    inference_results = model.transform(inference_input)
    inference = inference_results.df_out
    inference_output.write_pandas(inference)
