HyperAuto V1 常见问题

日落

HyperAuto V1 目前处于 日落 阶段，并将在未来某个日期被弃用。目前仍提供全面支持。不建议创建新的 V1 管道，用户应从 HyperAuto V1 迁移到 V2，具体步骤详见 迁移文档.

常规使用提示与指南

  • 我可以在 SDDI 仓库中调试和预览代码吗？
  • 我可以配置一个调度，将新表自动添加到其中吗？
  • 我的某个表 / derived_element 失败，原因是 MODULE_UNREACHABLE，我该怎么办？
  • 我添加了表 <TABLE_NAME> 到我的管道中，但当我尝试构建我的管道时，构建失败并出现 AssertionError: 0 instances of <TABLE_NAME> found in 'objects' metadata table
  • 如果我在 Bellhop 配置文件中添加新表，是否需要提升语义版本？
  • 我可以禁用 SDDI 代码仓库生成的某些中间阶段吗？

我可以在 SDDI 仓库中调试和预览代码吗？

是的，您可以在 SDDI 仓库中调试和预览代码。在 SDDI 仓库中，导航到文件 /transforms-bellhop/src/software_defined_data_integrations/transforms/pipeline_builder.py ，然后从 预览 按钮。

我可以配置一个调度，将新表自动添加到其中吗？

SDDI 仓库会生成一个名为 BUILD 的数据集，该数据集连接到此仓库生成的所有最终数据集。为了确保所有新摄取的表都能被构建，请创建一个新的完整构建（Full Build）计划（包括上游数据集），使用此 BUILD 数据集作为目标。智能调度器只会为原始数据已刷新的管道部分启动构建。

我的某个表 / derived_element 失败，原因是 MODULE_UNREACHABLE，我该怎么办？

MODULE_UNREACHABLE 通常表明您的 Spark 环境中的 DRIVER_MEMORY 不足。您可以在您的 SourceConfig.yaml 文件中为选定的表应用 Spark 配置文件；请参阅 配置参考 以了解详情。请不要忘记先 导入分配的配置文件 到您的仓库配置中。

我添加了表 <TABLE_NAME> 到我的管道中，但当我尝试构建我的管道时，构建失败并出现 AssertionError: 0 instances of <TABLE_NAME> found in 'objects' metadata table

请确保您已重新运行元数据数据集 objects, links, fields 和 diffs 在新表格被摄取并添加到您的 SDDI 管道之后。

如果我在 Bellhop 配置文件中添加新表，是否需要提升语义版本？

不，向 Bellhop 配置文件添加新表后，不需要提高语义版本。但是，您需要重新构建元数据数据集 objects, links, fields日 diffs.

我可以禁用 SDDI 代码仓库生成的某些中间阶段吗？

可以。外键生成、富化阶段和重命名阶段可以通过 PipelineConfig 文件中的参数来禁用。必须递增 deploymentSemanticVersion 才能使更改生效。

禁用其中任何一个或全部步骤都会对数据架构造成影响，并可能导致数据的下游使用中断。
