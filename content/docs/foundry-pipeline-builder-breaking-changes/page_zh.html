破坏性变更

当流式或增量管道中的有状态函数被修改时，就会发生破坏性变更。转换分为行级转换和有状态转换两种。

  • 行级转换： 只需单行中的数据即可产生结果，例如 Multiply numbers or Filter.
  • 有状态函数： 一种需要跨多行数据才能产生结果的转换。

主要有五种有状态函数：

  • 聚合（流式中的窗口聚合）
  • 外连接缓存（仅限流式）
  • 心跳检测（仅限流式）
  • 时间限定的去重（仅限流式）
  • 时间限定的事件时间排序（仅限流式）

当有状态函数被修改时，先前的输出可能不再准确。例如，假设您正在筛选偶数并求其总和。如果您将筛选条件改为所有奇数，现有状态将是偶数之和，而所有新的筛选值都是奇数。因此，该总和的含义现在变得不明确，它是一组偶数之和加上一组奇数之和。要刷新状态，您可以运行 重放.

重放有两种类型：

  • 从输入数据起点重放： 从数据起点重放您的管道，具体是流的起点还是输入数据集上的第一个事务，取决于输入是流还是增量数据集。

  • 从指定时间之前重放（仅适用于流式）： 使用从指定时间之前开始的上游数据重放管道。粒度重放将包含从在指定时间之前提交的第一个事务开始的所有数据；此之前的所有数据将不会被处理。这意味着您可能会获得在您指定时间之前一个事务的数据。

重放可以是可选的或必需的；在发生破坏性变更的情况下，Pipeline Builder 会自动检测到此类变更，并在部署时要求进行重放。下图显示了增量管道中的强制重放。

当发生状态中断时，Pipeline Builder 会将重放移至 错误 选项卡，并阻止管道部署，直到该中断得到解决。这可确保您在继续部署之前确认并处理破坏性变更。

为防止意外重放， 部分中选择 已应用标签 部署管道 面板默认处于折叠状态，且所有重放选项均未选中。当您选择重放策略时，将出现一个 确认重放策略 模态框，用于在执行之前解释该策略并识别任何下游影响。

状态中断的常见原因

以下变更通常会导致需要完全重放的状态中断。了解这些场景可以帮助您规划管道修改并避免意外停机。

有状态转换的修改

移除或修改有状态转换（如聚合、外连接缓存或心跳检测）需要完全重放。这包括移除输入到有状态转换的输入，因为有状态函数在没有被移除的数据的情况下无法再产生一致的结果。

影响有状态转换的输入变更

添加或删除输入会触发状态中断，您可以在不进行完整重放的情况下确认该中断。但是，对输入到有状态转换的输入所做的更改可能会破坏与历史数据的逻辑一致性。例如，如果某个有状态聚合依赖于特定输入，而该输入被删除或替换，则现有状态将不再准确反映管道处理的数据。

即使 Pipeline Builder 允许您在不重放的情况下确认输入更改，也应评估该更改是否会影响管道中后续的有状态转换。如果会受到影响，则可能仍需要进行重放以保持数据一致性。

输出 schema 更改

向输出 schema 添加新列不需要重放。但是，从输出 schema 中删除列是一种需要重放的状态中断，因为现有输出数据包含不再与更新后的 schema 匹配的列。

源管道更改

重放为当前管道提供输入的管道可能也要求您重放自己的管道。当源数据被重新处理时，到达管道输入的数据可能与管道最初处理的数据不同，这可能会使有状态转换的当前状态失效。

当上游流式管道在启用 重置输出（Reset Outputs on replay） 的情况下运行时（这是默认行为），上游管道的输出数据集将被清空，并仅使用重放窗口中的数据重新填充。在这种情况下，下游管道应从输入数据的起始处开始重放，而不是从特定时间窗口开始重放。这可确保下游输出（例如本体论对象）在整个重新处理的期间内被正确重建，而不会产生重复数据。

保留状态的修改

Pipeline Builder 包含一些功能，允许在不重放的情况下进行某些管道修改。这些功能使您能够从上次中断的位置继续处理，保留您的流历史记录，并避免对下游消费者造成影响。

输入和输出修改

您可以在部署后修改管道的输入和输出。具体行为取决于更改的类型：

  • 添加输入： 新输入将从头开始读取，而现有输入则从其上次处理的位置继续。
  • 删除输入或输出： 与被删除的输入或输出关联的状态将从处理集群中删除，无需重放。
  • 添加输出： 添加输出会导致需要重放的状态中断，重放可以从一段时间之前开始，也可以从输入数据的起始处开始。

当 Pipeline Builder 检测到输入或输出更改时，状态中断模块会提示您确认该更改。此确认告知系统从中断的位置继续处理，而不是要求重放。

如果您删除作业组内的输入或输出，则确认选项不可用，需要进行重放，重放可以从一段时间之前开始，也可以从输入数据的起始处开始。请评估对输入或输出的任何更改是否会影响管道中后续的有状态转换，因为可能仍需要进行重放以保持数据一致性。

Schema 更改

输入 schema 在部署管道时会被固定。如果输入 schema 发生更改，管道将继续使用之前的 schema 读取数据，直到您手动重新部署。

对于输出 schema，添加新列不需要重放。但是，从输出 schema 中删除列是一种需要重放的状态中断。

选择性数据重新摄取

您可以从特定时间点重新摄取数据，而无需重置输出视图。当您选择重新摄取时，重新摄取时输出中存在的所有数据都会被保留，使您能够在保持现有输出状态的同时重新处理历史数据。

要配置此行为，请展开 高级 部署面板中的部分，并在重放管道时禁用 重置输出（Reset Outputs on replay） 选项。

强制输出采用增量行为

您可以使用以下设置在管道中强制执行增量执行 要求增量执行 设置（位于 Pipeline Builder 中）。

此设置可确保配置为增量运行的作业在无法进行增量执行时自动失败。这有助于防止意外的快照场景，例如：

  • 意外被快照的输入
  • 因输出 schema 变更而强制执行的快照
  • 其他意外的全量刷新

此功能也可在 PySpark 增量转换中通过设置以下参数来使用 require_incremental=True 菜单中选择 @incremental 装饰器配合使用。

请按照以下步骤为您的管道配置强制增量执行：

  1. 在以下位置打开您的管道 如果希望用户在每次运行预览前手动确认，请开启.
  2. 选择 构建设置 Deploy 按钮右侧的滑块图标或右侧工具栏中。
  3. 向下滚动至 高级配置.
  4. 在您的终端会话中将 要求增量执行 to True。此设置默认处于禁用状态（设置为 No value).

关键注意事项

  • 启用后， 所有 管道中的增量输出在无法增量运行时将失败，无论作业分组如何。
  • 直方图 要求增量执行 设置只能设置为 True 前提是您的管道至少有一个增量输入或输出。否则，启用此选项将导致部署错误。
  • 配置为要求增量执行的管道只有在管道变更需要状态中断（state break）时才能以快照方式运行。在运行之前，系统会要求您确认这一点。

提交空事务

Pipeline Builder 中的增量管道包含一项构建设置，允许您在构建产生零输出行时提交空事务。启用后，Pipeline Builder 会提交空事务，以避免在后续构建中重新处理输入。

此设置适用于某些构建可能合理地不产生输出行的增量管道。如果未启用此设置，未产生输出的输入数据将在后续构建中被重新处理。

要配置此设置：

  1. 在以下位置打开您的管道 如果希望用户在每次运行预览前手动确认，请开启.
  2. 选择 构建设置 Deploy 按钮右侧的滑块图标或右侧工具栏中。
  3. 向下滚动至 高级配置.
  4. 启用 提交空事务 option.
