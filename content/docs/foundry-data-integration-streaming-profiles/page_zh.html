流式处理配置文件

使用 Palantir 平台进行流式处理时，Flink 运行时环境的所有配置方面都由平台为您管理，包括为 Flink 作业配置提供合理且经济高效的默认设置。在大多数情况下，您无需自行配置任何内容即可在 Flink 计算引擎上以高性能方式运行作业。

但是，有时您的作业需要的资源会超过 Foundry 流式处理默认提供的资源。此类资源可能包括额外的并行度（例如，当您的数据流吞吐量非常高时），或者在状态非常大或记录非常大时可能需要的 JobManager 或 TaskManager 的额外资源。

对于这些作业需要额外资源的情况，Palantir 提供了一组可用于调整特定配置选项的作业配置文件。这些配置文件仅提供全部可用 Flink 配置中的一部分，因为 Palantir 流式处理平台可以为您管理大部分内容。

与 代码仓库中的 Spark 配置文件类似，每个流式处理作业配置文件管理流式处理作业资源需求的特定组件，并且流式处理作业配置文件可以相互组合以满足您的用例需求。

何时使用流式处理配置文件

通常，您永远不需要在平台中使用流式处理配置文件，因为我们的默认流式处理配置旨在为大多数用例提供高性能和成本效益。但是，我们建议仅在您的流式处理作业遇到与以下内容相关的特定问题时才使用流式处理配置文件：

  • 非常高的吞吐量
  • 非常大的记录
  • 非常大的状态需求

您可以通过考虑作业需求、JobTracker 界面中提供的日志和错误消息以及对 Flink 的基本了解，来决定需要哪些额外的配置文件。

管理流式处理配置文件

由于流式处理配置文件可用于确定分配给永久运行的流式处理作业的资源总数，因此这些配置文件上设置了若干管理控制来管理 流式处理成本.

项目引用

在 Palantir 平台中，项目（Project）定义了相关工作周围的概念边界，以及用于应用和管理访问权限的安全边界。安全和管理控制的默认应用是在项目级别。通常，使用数据或资源要求它们存在于您的当前项目中或导入到您的当前项目中，从而授予它们 项目引用（Project Reference）。您可以在 引用 项目工作区侧面板的部分中查看项目中的所有引用。

应用于流式处理配置文件的主要管理控制是要求将它们作为项目引用添加到与相关流式处理管道或应用程序相同的项目中。如果您尝试使用未导入到您的项目中的流式处理配置文件，您的作业将失败并显示指示此缺失要求的错误。

通过使用 Project 引用作为管理控制手段，可以向更高级的用户授予代表其他用户将配置文件导入 Project 的能力。这样，管理员可以在细粒度级别上控制流式配置文件的使用位置，同时允许更多操作型用户使用已被授予访问权限的配置文件。

将配置文件作为 Project 引用导入

通常，配置文件会通过配置文件选择器组件自动导入相关应用程序内的 Project 中。例如，Pipeline Builder 中的配置文件选择器会自动导入所选的配置文件。

所有用户都可以将大多数配置文件作为 Project 引用导入其 Project，前提是他们拥有导入资源的足够权限。这通常意味着用户已被分配了一个角色，该角色授予他们 compass:import-resource-to 对 Project 的权限。你可以通过导航到 角色 标签页，在你的用户 设置中。使用 Filter operations... 搜索工具搜索该权限。

要查看所有可用流式配置文件的列表，请访问控制面板中“注册设置”部分的“流式配置文件”标签页。在这里，你可以选择任何特定配置文件，并查看该配置文件已被添加为 Project 引用的所有 Project（你有权访问的），还可以将其导入新的 Project。你也可以从已导入配置文件的 Project 中移除对该配置文件的引用；但请注意 这将中断该 Project 中依赖该配置文件的所有流式作业，因为我们要求配置文件必须导入到与流式作业相同的 Project 中才能使用。

使用大型流式配置文件

对于授予大量资源的配置文件，必须使用 流式处理配置文件 AIP 使用量与限制 注册设置 部分创建 Project 引用，位于 控制面板。此设置仅对被指定为 Enrollment Resource Administrators的用户启用。这些管理员可以在 选项卡 标签页中进行分配，并且可以将受限配置文件导入他们有权访问的任何 Project。

管理员将配置文件导入 Project 后，任何有权访问该 Project 的用户都可以使用该配置文件。
