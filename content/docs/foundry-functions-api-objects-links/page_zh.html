API：对象和关联

本页面介绍 TSv1。TSv2 和 Python 通过 Ontology SDK 读取对象：参见 按语言划分的对象 API，或 关联 以了解 TypeScript OSDK 参考文档中的 TSv2 遍历 API。

每个 对象类型 导入到您的项目后都会转换为 TypeScript v1 API，以便您可以轻松访问和操作 Foundry 中可用的对象。

属性

属性 的每个属性都会转换为为每个对象类型生成的 TypeScript 接口上的字段。生成的字段名称使用本体论中指定的 API Name。

您可以使用简单的点表示法访问每个属性的字段：

Copied!
1
const firstName = employee.firstName;

由于属性可能没有设置具体值，访问属性值时返回的类型可能是 undefined。在 TypeScript 中，除非您显式处理 undefined 的情况，否则编译器会报错。参见 本指南 以了解更多详细信息。

数组属性

在 TypeScript v1 中，对象类型上的数组属性会转换为 ReadonlyArray 类型。这是为了让 编辑 数组属性的语义更加清晰——修改数组属性值的唯一方法是使用一个全新的数组值来更新它。

因此，在操作数组属性的值之前，请先复制该数组属性：

Copied!
1
2
3
4
// Copy to a new array
let arrayCopy = [...myObject.myArrayProperty];
// Now you can modify the copied array
arrayCopy.push(newItem);

TypeScript v2 将数组属性类型化为普通的 T[] 而不是 ReadonlyArray，因此编译器允许就地修改它。编辑操作仍然会替换整个数组值，因此在每个版本中都要构建一个新数组并将其赋值给该属性。Python 的行为与此相同；参见 本体论编辑.

关联类型

关联类型 之间的关联也会转换为每个对象类型的 TypeScript 接口上的顶层字段。要遍历关联，请访问该字段，然后调用用于加载对象的方法之一。关联类型字段名称使用本体论中指定的 API Name 生成。

Foundry 本体论支持定义一对一、一对多和多对多关联类型。当访问关联的 1 一侧时，生成的字段类型为 SingleLink ，您可以使用 get() or getAsync() 编写接受并返回 Column 对象的辅助函数

Copied!
1
const manager = employee.manager.get();

当您遍历一对一或多对一关联时，返回值可能是 undefined （如果没有关联的对象）；请遵循 指南 来处理这些关联的 undefined 值。

当访问 many 一侧时，生成的字段类型为 MultiLink 类型。您可以使用 all() or allAsync() 方法访问关联对象的数组。如果没有关联的对象，这些方法将返回一个空数组：

Copied!
1
const employees = employee.reports.all();

遍历关联可能开销较大，因为它需要在后端加载哪些对象是相互关联的。有关如何更高效地执行关联遍历的详细信息，请参见 本节.

调用返回的关联对象数组 .all() or .allAsync() 是否为 ReadonlyArray。如果您想修改该数组，请先制作它的副本：

Copied!
1
let copiedEmployees = [...employee.reports.all()];

您可以将关联作为 ObjectSet 进行遍历，以避免将关联的对象实例加载到内存中。在本体论中创建关联时，将在此类型的对象集上生成 API，以便向其他关联的对象集进行“搜索周边”（search around）。

Copied!
1
2
3
4
5
6
7
import { ObjectSet, Employee, OtherObjectType } from "@foundry/ontology-api";

// Assume you have an object set available:
// const employee_id = "123";
// const employeeObjectSet : ObjectSet<Employee> = Objects.search().employee().filter(exactMatch(employee_id));

const linkedObjs: ObjectSet<OtherObjectType> = employeeObjectSet.searchAroundToOtherObjectType();

如果您操作单个对象实例并从该实例进行搜索周边，您将获得一个 MultiLink<objectType>。您无法将此 MultiLink 转换为 ObjectSet；您必须将对象实例转换为对象集，才能切换到其他对象集。

Copied!

// Assuming:
// const employee: Employee

// MultiLink can be loaded in memory to process further.

const linkedObjs: MultiLink<objectType> = employee.reports

// Convert a sole object instance to an object set. This statement will take longer than an `employee().filter()` statement.
const employeeObjectSet : ObjectSet<Employee> = Objects.search().employee([employee])

// From there, you can use the above "searchAroundToOtherObjectType" to process only object sets.

有关 TSv2 形式，请参见 关联 （位于 TypeScript OSDK 参考文档中），以及 关联遍历映射 以了解逐个方法的转换。有关每个 TSv1 标识符和类型与其 TSv2 等价项的映射，请查阅 标识符参考.

本体论元数据

Functions 通过提供对象和属性列表来提供对可用本体论的访问。本体论元数据信息可通过访问每个对象类型的常量类型来获取。有关更多详细信息，请参见以下各节。

这些本体论元数据 API 仅支持 TSv1，没有 TSv2 或 Python 的等效版本。

对象属性元数据

对象属性还包括类型元数据，它提供对每个属性类型的编程访问。您可以将此功能用于高级工作流，例如识别给定类型的所有属性，或验证给定属性名称是否具有特定类型。

例如，对于包含员工对象的本体论 类型，您可以访问该对象上的类型信息 类型的 属性，如下所示：

Copied!
1
2
3
import { Employee } from "@foundry/ontology-api";
...
const type = Employee.properties.firstName;

在这种情况下，如果 firstName 是 Employee 对象类型上的一个字符串属性，那么它的类型将是 StringPropertyBaseType.

可用的属性类型如下：

  • BooleanPropertyBaseType
  • BytePropertyBaseType
  • DatePropertyBaseType
  • FloatPropertyBaseType
  • TimestampPropertyBaseType
  • ShortPropertyBaseType
  • GeohashPropertyBaseType （与 geopoint 属性一起使用，以前命名为 geohash properties.)
  • DecimalPropertyBaseType
  • StringPropertyBaseType
  • LongPropertyBaseType
  • IntegerPropertyBaseType
  • DoublePropertyBaseType
  • ArrayPropertyBaseType
  • VectorPropertyBaseType
