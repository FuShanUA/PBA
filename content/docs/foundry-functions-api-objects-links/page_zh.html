API：对象和关联

每个 对象类型 在被导入到您的项目中后，都会被转换为 TypeScript API，以便您轻松访问和操作 Foundry 中可用的对象。

属性

属性 （各对象类型的）都会被转换为针对各对象类型生成的 TypeScript 接口上的字段。生成的字段名称使用本体论中指定的 API Name。

您可以通过简单的点表示法访问每个属性的字段：

Copied!
1
const firstName = employee.firstName;

请注意，由于属性可能未设置具体值，访问属性值时返回的类型可能是 undefined。TypeScript 编译器会报错，除非您显式处理 undefined 情况。请参阅 本指南 以了解更多详细信息。

数组属性

对象类型上的数组属性会被转换为 ReadOnlyArray 类型。这样做的目的是让 编辑 数组属性的语义清晰——修改数组属性值的唯一方法是使用一个全新的数组值来更新它。

如果您想操作数组属性的值，请先为其创建一个副本：

Copied!
1
2
3
4
// Copy to a new array
let arrayCopy = [...myObject.myArrayProperty];
// Now you can modify the copied array
arrayCopy.push(newItem);

关联类型

关联类型 对象类型之间的关联也会被转换为每个对象类型的 TypeScript 接口上的字段。要遍历关联，请访问该字段，然后调用用于加载对象的方法之一。关联类型的字段名称使用本体论中指定的 API Name 生成。

Foundry 本体论支持定义一对一、一对多和多对多的关联类型。当访问关联的 1 侧时，生成的字段为 SingleLink 类型。您可以使用 get() 或 getAsync() 方法访问关联的对象：

Copied!
1
const manager = employee.manager.get();

与属性一样，当您遍历一对一或多对一的关联时，返回值可能为 undefined （如果不存在关联的对象）。请遵循该 指南 来处理这些关联的 undefined 值。

当访问关联的 many 侧时，生成的字段为 MultiLink 类型。您可以使用 all() 或 allAsync() 方法访问由关联对象组成的 Array。如果不存在关联的对象，这些方法将返回一个空 Array。

Copied!
1
const employees = employee.reports.all();

遍历关联的开销可能较大，因为这需要在后端加载哪些对象相互关联的信息。有关如何更高效地执行关联遍历的详细信息，请参阅 本章节。

调用 .all() 或 .allAsync() 所返回的关联对象数组是一个 ReadOnlyArray。如果要修改该数组，请先创建它的副本：

Copied!
1
let copiedEmployees = [...employee.reports.all()];

你可以将关联作为 ObjectSet 来遍历，以避免将关联的对象实例加载到内存中。在本体论中创建关联时，将会在此类型的对象集上生成 API，以便“向外搜索”到其他关联的对象集。

Copied!
1
2
3
4
5
6
7
import { ObjectSet, Employee } from "@foundry/ontology-api";

// Assume you have an object set available:
// const employee_id = "123";
// const employeeObjectSet : ObjectSet<Employee> = Objects.search().employee().filter(exactMatch(employee_id));

const linkedObjs: ObjectSet<OtherObjectType> = employeeObjectSet.searchAroundToOtherObjectType();

如果你对单个对象实例进行操作并从该实例向外搜索，你将得到一个 MultiLink<objectType>。你无法将此 MultiLink 转换为 ObjectSet；你必须将该对象实例转换为对象集，才能转向其他对象集。

// Assuming:
// const employee: Employee

// MultiLink can be loaded in memory to process further.

const linkedObjs: MultiLink<objectType> = employee.reports

// Convert a sole object instance to an object set. This statement will take longer than an `employee().filter()` statement.
const employeeObjectSet : ObjectSet<Employee> = Objects.search().employee([employee])

// From there, you can use the above "searchAroundToOtherObjectType" to process only object sets.

本体论元数据

Functions 通过提供对象和属性列表来提供对可用本体论的访问。通过访问每种对象类型对应的常量类型，即可获取本体论元数据信息。有关更多详细信息，请参阅以下章节。

对象属性元数据

对象属性还包括类型元数据，让你能够以编程方式访问每个属性的类型。你可以将此功能用于高级工作流，例如识别给定类型的所有属性，或验证给定属性名称是否具有特定类型。

例如，对于本体论中包含的员工对象 类型，您可以访问该对象 类型的 属性的类型信息，如下所示：

Copied!
1
2
3
import { Employee } from "@foundry/ontology-api";
...
const type = Employee.properties.firstName;

在本例中，如果 firstName 是 Employee 对象类型上的字符串属性，则其类型将是 StringPropertyBaseType。

可用的属性类型如下：

  • BooleanPropertyBaseType
  • BytePropertyBaseType
  • DatePropertyBaseType
  • FloatPropertyBaseType
  • TimestampPropertyBaseType
  • ShortPropertyBaseType
  • GeohashPropertyBaseType （用于 geopoint 属性，以前称为 geohash 属性。）
  • DecimalPropertyBaseType
  • StringPropertyBaseType
  • LongPropertyBaseType
  • IntegerPropertyBaseType
  • DoublePropertyBaseType
  • ArrayPropertyBaseType
  • VectorPropertyBaseType
