启用用户交互

几乎每个应用都需要用户交互，Slate 提供了三个主要功能来实现交互性：

  • 输入控件： 用于捕获输入的简单控件，提供常见的 UX 元素，例如下拉列表、文本字段、单选按钮等。
  • 其他控件中的选择状态： 大多数其他控件类型都支持某种形式的选择。选择在各个控件中的工作方式略有不同，因此你需要亲自尝试以了解可能的选择类型。
  • 事件触发器： 所有控件都有一组事件触发器，当控件状态发生变化或用户执行操作时会进行广播。请查看 事件 文档 以了解如何将事件整合到你的应用中的更多细节。

捕获用户输入的最简单模式是静态表单：添加输入控件并提供静态选项，然后可以在查询和函数中引用用户选择，以提供动态视图。不过，通常存在某种“链式”输入的复杂性，即一个或多个输入中的选择会影响下一组输入的可用选项集。保持这些链条简短且易于理解非常重要——需要设置的参数过多可能导致应用不直观且性能不佳。请参阅下面的“开放式探索”反模式。

在这种更复杂的依赖输入配置中，最佳实践是将配置筛选器的工作流与分析结果数据的工作流分开。简单来说，这意味着你应该将任何依赖这些用户输入的查询设置为 manual ，并为用户提供一个按钮控件来 更新数据。这种模式可确保你的应用不会在每次筛选器更改时重新运行所有查询而浪费资源（以及用户时间）。如果你有任何类型的自由文本输入——例如 文本字段 or 文本区域 类型的控件——这一点尤其关键，否则查询等下游依赖项将 在用户的每次按键时重新求值。

回写工作流

当你的应用捕获用户输入以回写数据时，你 必须 应将查询配置为手动运行，并在明确的用户操作时触发查询。否则，持久化数据的查询将在每次输入更改时运行，包括文本输入控件中的每次按键，从而导致高度意外的行为。

在会话之间保持用户选择

如果你的应用需要配置多个不同的输入才能获得有用的视图，用户可能希望有一种方法来“保存”其配置，以便分享或稍后返回。

可以 构建此功能的自定义版本，但使用内置的 可共享视图 功能来自动映射所有列。

“动态输入”

有时你需要捕获似乎不适合放入静态输入 widget 的输入。在许多情况下，你可以换个角度思考问题，找到简单的解决方案，但假设你需要允许用户构建更复杂的筛选器，或者你的用例似乎无法通过任何创造性地使用静态输入的方式来实现。

你可能会想使用 Repeating Container widget 来实现此工作流，但这些 widget 仅限于显示用途。你可以在 repeating container 内使用输入 widget，但其作用域 唯一 仅限于该容器，除了容器内的其他 widget 之外，你将无法引用该输入 widget 的任何实例。

相反，您可以只保留输入的一个实例，但允许用户通过“保存”其选择来多次进行选择。您可以在 HTML widget 中显示累积的选择，甚至可以内置删除先前选择的功能。

要实现此模式，请使用一个变量 v_userSelections 并将其设置为一个空数组（[]）。然后，每当用户点击按钮保存其选择时，您可以更新此变量：

相互依赖的筛选器

依赖图的性质决定了您无法将 widget 配置为彼此循环依赖。输入 widget 之间的依赖关系需要“自上而下”传递，您将无法构建一组筛选器，使得 任意 筛选器的选择会影响 所有 小部件。

可共享视图

可共享视图允许用户捕获 Slate 应用程序的当前状态，并生成一个可与他人共享的唯一 URL。当其他用户打开该 URL 时，应用程序将加载创建视图时存在的相同选择和配置。

可共享视图存储以下内容：

  • 所有 widget 的当前值 交互属性；这些是可以通过用户交互更改的属性，例如 selectedValue.
  • 所有局部变量的当前值 变量.

加载可共享视图 URL 时，保存的值将覆盖 widget 和局部变量的默认值，下游依赖项将相应地初始化。

创建可共享视图

要手动创建可共享视图，请在 要在标记和发布函数的过程中查看进度，请选择 模式下打开应用程序，并选择 获取可共享视图 来自 操作 下拉菜单。这将生成一个带有视图 ID 的唯一 URL，您可以将其共享。

Slate 应用程序构建者可以使用 slate.saveView 和 slate.loadView 操作以编程方式创建和加载可共享视图。 slate.viewSaved 事件在视图保存后触发，提供可以传递给 slate.loadView.

局限性

可共享视图具有以下限制：

  • 仅限主页： 可共享视图目前仅保存和恢复 Slate 应用程序的主页状态。仅包含局部变量；共享变量不会被保存或恢复。
  • Widget 和变量名称： 可共享视图与 widget 和变量名称绑定。如果在创建视图后重命名了某个 widget 或变量，则在加载视图时将不会恢复该 widget 或变量的保存状态。
  • Widget 类型更改： 如果某个 widget 的类型在保存视图和打开视图之间发生了更改，则该 widget 的保存状态将不会被应用。
  • 与版本无关： 可共享视图适用于应用程序的任何版本。在应用程序某个版本上创建的视图可以在任何其他版本上加载，只要所引用的 widget 和变量名称仍然存在。
