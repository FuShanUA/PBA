身份验证

您可以通过以下方式向 SQL Server 进行身份验证：

  1. 用户名和密码： 提供用户名和密码。我们建议使用服务凭证而非个人用户凭证。
  2. Active Directory Msi*：此选项将使用 authentication=ActiveDirectoryMSI JDBC 设置。 msiClientId 可以选择提供。
  3. Active Directory Password*：此选项将使用 authentication=ActiveDirectoryPassword JDBC 设置。必须提供 Active Directory 用户的用户名和密码才能使用此设置。
  4. Active Directory Service Principal*：此选项将使用 authentication=ActiveDirectoryServicePrincipal JDBC 设置。必须指定主体 ID（有时称为应用程序 ID 或客户端 ID），并提供该主体 ID 的密钥。

有关这些身份验证模式的更多信息，请参阅 官方文档 ↗。对于所有身份验证选项，请确保所提供的用户和角色在目标数据库上具有必要的权限，并具有对目标表的读取或写入权限。

* Azure Active Directory 现已更名为 Microsoft Entra ID ↗；不过，Microsoft 发布的 SQL Server 驱动程序上的 JDBC 选项仍保留引用 Active Directory 的原始名称。

网络

Microsoft SQL Server 连接器需要访问您要连接的 SQL Server 实例的网络权限。SQL Server 连接通常使用主机名在端口 1433 上进行连接。

对于 SQL Server 连接，相应的 出站策略覆盖 中设置源时，必须添加相应的 Data Connection 应用程序.

中设置源时添加。

对于托管在 Azure SQL 或 AWS RDS 等云服务上的 SQL Server 实例，您必须为从云提供商控制台获取的主机名添加出站策略。 Azure SQL 文档 ↗.

  • 如果使用 Azure 重定向模式，则还必须为所有解析出的 IP 地址添加出站策略。解析出的 IP 可能会不时变化，您必须更新出站策略以允许新的 IP。例如，如果您的 SQL Server 实例托管在 Azure 上，您可以在 Settings > Properties 中找到有关 Azure SQL 实例公共 IP 地址的更多信息。要查找您的 Azure SQL 实例的主机名，请导航到 Azure 门户中的 Server Name 字段。以下是基于主机名的 Azure SQL 出站策略示例： <your-database-name>.database.windows.net (port 1433)
  • 要查找解析出的 IP，您可以在命令行中运行 nslookup <your-database-name>.database.windows.net 。最终结果将是该主机名在 Azure 中解析到的 IP 地址。以下是基于 IPv4 的 Azure SQL 出站策略示例： x.x.x.x (port 1433)。Azure SQL 会在多个主机之间进行负载均衡，因此您可能需要多次运行 nslookup 命令并添加所有解析出的 IP 地址。

如果您从同样托管在 Azure 中的 Foundry 实例连接到 Azure SQL 实例，则需要使用 代理 连接策略选项。对于源自 Azure 内部的流量，连接策略默认为 Redirect。对于 Azure 到 Azure 的连接，使用重定向选项进行连接需要为 11000 到 11999 范围内所有端口上的所有 Azure SQL IP 地址配置出站策略。这是可行的，但由于权限过于宽松，不建议这样做。有关 Azure SQL 连接策略的详细信息，请参阅官方 Azure SQL 文档 ↗.

批量同步一致性

一个 Foundry SNAPSHOT 事务 会替换输出数据集中先前摄取的数据。它不会在 SQL Server 中自动启用快照隔离。

当 READ_COMMITTED_SNAPSHOT is OFF，SQL Server 的默认 READ COMMITTED 隔离并不保证源的时间点视图。在索引内或分区之间移动行的并发更新可能导致行重复或丢失，即使同步运行单个查询并成功完成也是如此。

读取一致的快照

要为读取单个表的批量同步请求快照隔离：

  1. 与数据库管理员确认 ALLOW_SNAPSHOT_ISOLATION is ON 针对源数据库。此选项默认 OFF 在 SQL Server 用户数据库中处于启用状态。

  2. 当 配置批量同步获取资源，请将 SET TRANSACTION ISOLATION LEVEL SNAPSHOT; 在现有的 SELECT 语句之前，位于 字段中运行 字段中。例如：

2
SET TRANSACTION ISOLATION LEVEL SNAPSHOT;
SELECT * FROM dbo.MyTable;

  3. 预览查询，然后保存并运行同步。

将两个语句保留在同一个 字段中运行 字段中。这会为提取请求一致的快照，而不会启用数据库范围的 READ_COMMITTED_SNAPSHOT。单独的同步和并行查询不共享快照。

有关隔离级别及其前提条件的更多信息，请参阅 SQL Server 文档 ↗.

Db2 连接器支持

Microsoft SQL Server 源支持 （CDC）同步。Db2 CDC 同步是通过 同步。

要为 Microsoft SQL Server 启用变更数据捕获，您必须运行类似下方的命令在数据库上启用 CDC。

USE <database>
GO
EXEC sys.sp_cdc_enable_db
GO

然后，在需要记录变更日志的每个表上运行另一条命令：

EXEC sys.sp_cdc_enable_table
    @source_schema = N'<schema>'
  , @source_name = N'<table_name>'
  , @role_name = NULL
  , @capture_instance = NULL
  , @supports_net_changes = 0
  , @filegroup_name = N'PRIMARY';
GO

一旦为您希望同步到 Foundry 的表启用了变更数据捕获，您可以导航到 概述 页面并选择 + 创建 CDC 同步 来开始创建新的变更数据捕获同步。

探索运行时必须处于工作状态才能创建变更数据捕获同步。如果运行时仍在初始化，您可能需要等待几秒钟并刷新页面，然后再创建同步。

有关这些命令以及在 Microsoft SQL Server 中使用变更数据捕获 (CDC) 的更多信息，请参阅 官方文档 ↗ 适用于所使用的 SQL Server 版本。

变更数据捕获权限设置

要成功读取 CDC 数据，您需要确保已为数据库用户提供了足够的权限。

  • 您可以使用以下查询验证您的权限： SELECT HAS_PERMS_BY_NAME('cdc', 'SCHEMA', 'EXECUTE') AS HasExecutePermission;。如果 True 则结果将返回 1；如果 False.
  • 您可以在源系统本身中运行以下查询来授予缺失的权限： GRANT EXECUTE ON SCHEMA::cdc TO <USER>;

故障排除

使用 Active Directory 密码身份验证时登录失败

如果您收到 Login failed for user ''. 身份验证选项时收到 Active Directory Password 错误，这通常表明您的 SQL Server 实例仅支持 Kerberos 或 NTLM 身份验证，不接受 Azure Active Directory 身份验证。

直方图 ActiveDirectoryPassword 身份验证方法针对 Azure Active Directory 进行身份验证，而不是使用 Kerberos 或 NTLM 协议。如果您的 SQL Server 配置为仅接受 Kerberos 或 NTLM 身份验证，则 Azure AD 身份验证尝试将被拒绝。

要解决此问题，请创建自定义 JDBC 连接并设置 JDBC 参数 authenticationScheme=NTLM 以改用 NTLM 身份验证。

import logging
from pandas import DataFrame
from transforms.external.systems import ResolvedSource
from transforms.api import lightweight, Output, transform_pandas
from transforms.external.systems import external_systems, Source
import pymssql
import pandas as pd

logger = logging.getLogger(__name__)

@lightweight
@external_systems(
    mssql_source=Source("<source_rid>")
)
@transform_pandas(
    Output("<dataset_rid>")
)
def compute(mssql_source: ResolvedSource) -> DataFrame:
    # Inventory threshold parameter (this could also be read from an input DataFrame)
    INVENTORY_THRESHOLD = 60

    connection_parameters = {
        "server": "<your_server_name>",
        "database": "<your_database_name>",
        "port": "1433",
        "user": "<your_user_name>",
        "password": mssql_source.get_secret("MSSQL_BASIC_AUTH_PASSWORD"),
        "encryption": "require",
        "timeout": 30
    }
    try:
        with pymssql.connect(**connection_parameters) as connection:
            df = pd.read_sql(
                'SELECT * FROM Fruits WHERE Inventory < %s',
                connection,
                params=(INVENTORY_THRESHOLD,)
            )
    except Exception as e:
        logger.error(f"Error querying MSSQL Fruits table: {e}")
        raise RuntimeError(f"Failed to fetch Fruits data from MSSQL: {e}") from e
    return df

import logging
from transforms.api import lightweight, Output, transform_pandas, Input
from transforms.external.systems import external_systems, Source
import pymssql
import pandas as pd

logger = logging.getLogger(__name__)

@lightweight
@external_systems(
    mssql_source=Source("<source_rid>")
)
@transform_pandas(
    Output("<dataset_rid>"),
    fruits_df=Input("<dataset_rid>") # DataFrame with schema [FruitName: String, Inventory: Integer, PricePerKg: Double]
)
def compute(mssql_source, fruits_df):
    # Connection parameters
    connection_parameters = {
        "server": "<your_server_name>",
        "database": "<your_database_name>",
        "port": "1433",
        "user": "<your_user_name>",
        "password": mssql_source.get_secret("MSSQL_BASIC_AUTH_PASSWORD"),
        "encryption": "require",
        "timeout": 30
    }
    results = []
    try:
        with pymssql.connect(**connection_parameters) as connection:
            with connection.cursor() as cursor:
                for _, row in fruits_df.iterrows():
                    fruit_name = row["FruitName"]
                    inventory = row["Inventory"]
                    price_per_kg = row["PricePerKg"]

                    # Try to update; if no row updated, then insert
                    update_sql = """
                        UPDATE Fruits
                        SET Inventory = %s, PricePerKg = %s
                        WHERE FruitName = %s
                    """
                    cursor.execute(update_sql, (inventory, price_per_kg, fruit_name))
                    if cursor.rowcount == 0:
                        insert_sql = """
                            INSERT INTO Fruits (FruitName, Inventory, PricePerKg)
                            VALUES (%s, %s, %s)
                        """
                        cursor.execute(insert_sql, (fruit_name, inventory, price_per_kg))
                        results.append({"FruitName": fruit_name, "action": "inserted"})
                    else:
                        results.append({"FruitName": fruit_name, "action": "updated"})
                connection.commit()
    except Exception as e:
        logger.error(f"Error updating MSSQL Fruits table: {e}")
        raise RuntimeError(f"Failed to update Fruits data in MSSQL: {e}") from e
    # Return a DataFrame summarizing the actions
    return pd.DataFrame(results, columns=["FruitName", "action"])
