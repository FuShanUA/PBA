管道构建器现在支持在您的 LLM 运行中输出错误

发布日期：2024-05-23

您现在可以将 LLM 输出列配置为在行失败时同时包含输出值和错误消息，从而更轻松地调试与 LLM 相关的问题。借助此功能，您将在输出列中收到以结构体（struct）形式呈现的 LLM 响应和错误消息。这种对 LLM 错误的透明呈现使您可以更轻松地调试处理问题，并了解您的模型在幕后的运行情况。示例错误消息可能包括：

  • "超出上下文限制"
  • "无法强制转换为提供的输出类型"
  • "输入提示词为 null 或空"

配置为包含错误的 LLM 提示词示例。

要使用此功能：

  1. 在管道构建器中，打开一个 Use LLM 节点并创建提示词。
  2. 找到 输出类型 部分。
  3. 勾选 包含错误 复选框。

包含 LLM 错误消息时，节点输出将为 struct 类型，其中同时包含常规输出值（可以是任何受支持的输出类型，包括 struct）以及相关的错误消息。

带有错误消息的 struct 输出类型示例（包含一个数组、一个字符串和一个整数）。

您可以轻松开启或关闭此功能，以灵活控制错误透明度，只需取消勾选 包含错误 复选框即可。

请参阅我们的文档，详细了解如何在 Pipeline Builder 中使用 LLM。

Slate 中的页面和共享变量功能简介

发布日期：2024-05-23

页面 为应用程序构建者提供了将应用程序的 UI、逻辑和资源（数据、变量、函数、事件）拆分到单个应用程序内不同页面的能力，为每个页面提供隔离的作用域，且各页面单独加载，包括小组件、函数、查询等。此外，您现在可以对变量进行更细致的控制，能够按页面作用域将变量配置为 "local"（局部）和 "shared"（共享），其中共享变量可在任何页面中访问，从而提升应用程序的设计、性能和用户体验。

加快应用加载速度

一种常见的模式是拆分 Palantir 将 Slate 应用程序划分为多个视图的一种方法是使用选项卡式容器。然而，这种方法可能导致页面加载量非常大，限制开发人员对数据加载的控制程度，并且由于组件和工具采用单一列表，会在工具的可维护性和组织方面带来挑战。

从选项卡式容器切换到页面后，较大的应用程序可以更快地加载信息，因为它们只加载与每个页面特定范围相关的数据。

现在可以在单个 Slate 应用程序中构建多个页面。

这种方法可以将应用程序的逻辑流程划分到各个页面中，并使用具有有意义名称的 URL 路由。此外，在分享指向 Slate 应用程序的链接时，可以在 URL 中使用页面名称直接导航到相应页面。

现在可以将应用程序的逻辑流程划分到各个页面中，并使用具有有意义名称的 URL。

提高应用程序稳定性

将复杂的 Slate 应用程序的逻辑拆分为多个页面还可以简化重构，从而提高可维护性和性能。

页面之间的无缝导航

新的 onNavigate 事件和 navigateTo 操作支持在同一应用程序内的页面之间进行简单的导航。导航到某个页面时，URL 路由将更新为指向目标页面。

导航到某个页面将更新 URL 路由，使其指向目标页面。

在页面之间共享应用状态

新增的 Shared 变量可在任何 Slate 页面中访问，从而实现跨页面的应用级状态共享。

引入针对本体论用户编辑和数据源更新的冲突解决策略 [GA]

发布日期：2024-05-23

Foundry 本体论中的对象实例既可以由输入数据源创建和修改，也可以由用户编辑创建和修改。当单个对象实例（例如具有特定主键值的行或对象）同时从输入数据源和用户编辑接收数据时，这些接收到的值必须通过一种 冲突解决策略来透明地解决。

您可以 配置 对象类型级别的冲突解决策略。在 Ontology Manager 中选择一个对象类型，然后导航至 数据源 部分。

请注意，冲突解决策略仅适用于 Object Storage v2 对象类型。

冲突解决策略

本体论编辑有两种冲突解决策略：

  • 应用用户编辑（默认）：使用此策略时，对象实例的最终状态始终由应用于该实例的用户编辑决定，而不受该对象实例未来任何数据源更新的影响。
  • 应用最新值（有限测试版）：使用此策略时，仅当用户编辑的时间戳值晚于给定对象实例的数据源更新的时间戳值时，才会应用用户编辑。

此策略还要求数据源包含一个 Timestamp 类型的属性；Date 属性类型不适用于此选项。 Timestamp 属性用于评估是否应应用用户编辑或输入数据源更新。

在 Ontology Manager 中配置冲突解决策略。

为多个数据源配置不同的解决策略

您可以为对象类型的每个输入数据源配置不同的冲突解决策略。例如，对于由两个数据源支撑的对象类型，您可以配置一个数据源使用 应用用户编辑 策略，另一个数据源使用 应用最新值 策略。

在 Ontology Manager 中为多个数据源配置冲突解决策略。

如果用户编辑更新了多个数据源中的属性，Ontology Manager 将使用支撑该属性的数据源的冲突解决策略，确定是始终应用还是有条件地应用这些编辑。

隆重推出 AIP Accelerate [Beta]，您的 LLM 工作流笔记本环境。

发布日期：2024-05-21

AIP Accelerate 是一个用于构建大语言模型 (LLM) 驱动工作流的笔记本环境。AIP Accelerate 将于 6 月 3 日当周在各个 enrollment 中推出，使您能够快速迭代利用各种形式数据的 LLM 提示词，无论是从 Foundry 导入的数据集，还是您计算机上的文件。借助 AIP Accelerate 提供的 LLM 操作库，您可以构建复杂的思维链、解读上传的图像，并生成由 LLM 驱动的洞察。凭借对最新生成式 AI 模型的支持，AIP Accelerate 是一个运用 LLM 能力开展调查型业务工作流的沙盒环境。

AIP Accelerate 落地页。

LLM 的响应效果在很大程度上取决于上下文环境。AIP Accelerate 使您能够通过使用 Context Threads。上下文线程是 Accelerate 的主要组件之一，表示提供给大型语言模型的信息链。单元格通过上下文线程将信息向下传递给其子单元格。工作流构建者可以使用上下文线程突破线性聊天模式，构建不受单一上下文路径限制的工作流。此外，AIP Accelerate 利用平台内的原语，支持对各种形式的结构化和非结构化数据（如表格数据、PDF 或图像文件）执行操作，以进行复杂分析。

AIP Accelerate 上下文线程，其中子 LLM 单元格继承其父单元格的上下文，从而继续对话。

在上图中，我们有一个包含两个单元格的上下文线程。我们可以继续嵌套单元格以深入与 LLM 的对话，也可以在任意单元格之后进行分支，走另一条不同的路径。

安全且可自定义的 AI 驱动分析

AIP Accelerate 的主要功能包括：

  • 用户友好的界面： AIP Accelerate 拥有直观的界面，使工作流构建者能够轻松使用 LLM 构建复杂的多维分析。
  • 生成式 AI 模型： 自定义在执行基于文本和基于视觉的任务时使用哪些可用的 LLM。
  • 对真实数据进行操作： 在平台内的数据上部署 LLM，例如数据集或媒体集（图像或 PDF 文档）。
  • 共享结果： 将分析结果保存为新数据集，供其他 AIP 工具使用，或与其他用户共享工作流。
  • 数据安全： AIP Accelerate 建立在同样严格的 安全 模型之上，该模型治理着 Palantir 平台的其余部分，包括基于用户的数据权限。这些平台安全控制仅授予 LLM 完成任务所需的访问权限。

AIP Accelerate 正在积极开发中，对更多操作的支持即将推出。

AIP Assist 不仅能解决代码方面的即时问题，还能让开发者深入了解今后如何避免类似问题。

本体论管理器已更新为仅预先加载与各用户最相关的资源，从而显著提升了启动性能。从本周起，您在本体论管理器中工作时将体验到更快的加载速度。无需任何用户操作即可启用此增强功能。

  • 高效加载最近使用的本体论资源： 您可以更快地查看或编辑与您最相关的工作。
