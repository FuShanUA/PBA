前提条件

在本教程中，我们将使用与 Demo Ticket 相同的对象类型和示例对象，如 操作入门教程中所示.

首先，编写一个本体论编辑函数来执行操作所需的编辑。这需要：

  • 使用对象上的函数 TypeScript 模板设置一个仓库，
  • 将相关的对象类型导入到你的仓库中，以及
  • 发布本体论编辑函数供操作读取。

有关这些步骤的信息可以在函数文档中找到：

@OntologyEditFunction()
public addPriorityToTitle(ticket: DemoTicket): void {
    let newTitle: string = "[" + ticket.ticketPriority + "]" + ticket.ticketTitle;
    ticket.ticketTitle = newTitle;
}

用于操作类型的函数必须使用 @OntologyEditFunction() 而非 @Function()进行注解。更多详细信息可以在以下文档中找到： 对象上的函数.

自动升级

你可以选择为操作所引用的函数启用自动升级。启用后，操作将在 版本范围 和 上依赖该函数，并在运行时解析版本。 在运行时解析版本。

要为操作启用自动升级，请导航到操作的 规则 部分并选择 函数 参数。在 函数 下拉菜单中，选择你想要运行的函数的最低版本，并启用 自动升级 选项。这将对应于一个版本范围依赖，该范围包含所选最低版本的所有向后兼容版本，例如次要版本或补丁升级。

对于以下形式的函数版本，自动升级将被禁用 0.y.z。这些版本保留用于初始开发阶段，函数 API 和行为可能会频繁更改，不应视为稳定版本。请参阅有关 选择发布版本.

安全性

如果为函数支撑的操作启用了自动升级，没有 操作编辑权限 的用户可以通过更改支撑函数来修改操作的行为。这是因为函数的编辑权限与操作的权限没有关联。

破坏性更改

自动升级可能由于 流重新部署是指从之前保存的检查点恢复流处理作业的过程。当流处理作业暂停或停止时，会在数据中创建一个书签，指示已读取记录的位置。在流运行期间，也会定期创建书签（也称为检查点）。这使得在流因任何原因遇到故障时能够进行恢复。 导致操作执行失败。

来源

操作的溯源根据所选的最低函数版本的溯源进行设置。如果函数的较新版本返回此溯源之外的编辑（例如，额外的对象类型），操作执行将失败。目前，溯源仅包含操作在运行时可能编辑的对象类型。
