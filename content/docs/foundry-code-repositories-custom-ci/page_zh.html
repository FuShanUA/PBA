自定义 CI

您可以通过添加以下内容来扩展在您的仓库中运行的持续集成 (CI) 检查 自定义 CI 作业 or 自定义 Gradle 任务.

添加自定义 CI 作业 [Beta]

测试版

自定义 CI 作业目前处于 测试版 开发阶段。在积极开发期间,功能可能会发生变化。

在 Foundry 代码仓库中， ci.yml 文件定义了由 Foundry 管理的默认 CI 作业。要向检查中添加您自己的作业，请在 ci.additions.yml 文件。

通过自定义 CI 作业，您可以：

  • 向检查中添加作业，每个作业运行一系列 shell 命令。
  • 为所有作业（包括默认作业）设置环境变量，或为单个自定义作业设置环境变量。
  • 使用以下项的出站策略和密钥，将所有作业（包括默认作业）连接到外部系统 Data Connection 数据源.

您可以将包含自定义 CI 作业的仓库包含在 市场产品中。这些作业不保证在安装后运行，并且可能导致 CI 检查失败。

创建自定义 CI 作业

要添加作业，请创建一个名为 ci.additions.yml 的文件，放在仓库的根目录下。仓库升级绝不会覆盖此文件。

在运行以下示例之前， 准备并导入一个数据源 其 API 名称为 MySource 以及一个名为 password的密钥。该示例定义了一个环境变量，声明了该数据源，并添加了一个打印 GREETING 值并验证 password 密钥是否可用的作业。

env:
  GREETING: Hello from a custom CI job

sources:
  - MySource

jobs:
  print-greeting:
    timeout: 5 minutes
    steps:
      - echo "$GREETING"
      - test -n "$MySource_password"

直方图 test -n "$MySource_password" 步骤将失败，如果 MySource_password 环境变量为空或未设置。这可以在不将其值打印到日志的情况下确认密钥可用。

提交该文件以运行检查。在 检查 标签页中，每个作业都会单独显示，并具有各自的状态和日志。

文件参考

直方图 ci.additions.yml 文件支持以下顶级键。所有键均为可选。如果文件包含任何其他顶级键，检查将失败。

键（Key）描述
env每个作业（包括在 ci.yml中定义的作业）都可用的环境变量。每个键是一个变量名，每个值是该变量的值。
jobs要运行的作业。每个键是一个作业名，每个值定义该作业。
sources作业可以使用的数据源的 API 名称。有关更多信息，请查看 在作业中使用数据源.

中的每个作业 jobs 支持以下字段：

字段描述
steps必需。按顺序运行的 shell 命令列表。每个步骤在单独的 bash 进程中从仓库根目录运行，因此您在一个步骤中导出的变量在后续步骤中不可用。如果某个步骤返回非零退出代码，则该作业失败，其余步骤不会运行。
timeout可选。作业的最长持续时间，例如 10 minutes。如果作业超过此持续时间，则失败。如果省略 timeout，则该作业没有单独的限制，但整个 CI 运行仍受平台配置的超时限制，该超时在所有作业之间共享，默认为 60 分钟。
env可选。仅此作业可用的环境变量，格式与顶级 env 键相同。如果作业级变量与顶级变量同名，则以作业级的值为准。

规则

如果 ci.additions.yml 不遵循以下规则，检查将失败：

  • 中的名称 env and jobs 不得已在 ci.yml中定义。您可以添加新名称，但不能更改由 Foundry 管理的配置。
  • 作业不得设置 order.

自定义作业在 ci.yml中定义的所有作业之后运行，顺序与它们在 ci.additions.yml。如果 ci.yml 中的作业排序方式为 order 且其中一个作业失败，则自定义作业不会运行。

在作业中使用数据源

作业可以通过 Data Connection 数据源连接到外部系统。当您在 ci.additions.yml中声明数据源时，检查会将该数据源的 出站策略覆盖 应用于所有作业（包括默认作业），并将该数据源的密钥作为环境变量提供。

准备数据源

在作业可以使用数据源之前，请在 Data Connection 中对该数据源配置以下设置：

  1. 导航至 Connection settings > Code import configuration，开启 允许将此源导入到代码仓库，并确保该源具有 API 名称。作业通过此名称引用该源。
  2. 导航至 Connection settings > Export configuration 并开启 在不进行标记验证的情况下启用导出到此源.

检查不会验证仓库中数据的标记，且作业可能会将该数据发送到外部系统。请查看 自定义 CI 作业的权限 和 启用导出所需的权限 ，然后再启用此设置。

将源导入仓库

将源导入包含以下内容的仓库 ci.additions.yml构造一个本体论编辑容器。例如：

  • 在 Python 转换仓库中，使用 外部系统 侧边栏。更多信息请查看 将源导入代码.
  • 在函数仓库中，使用 资源导入 侧边栏.

导入源需要 Editor 对源的权限。

声明源

在顶层列出作业可以使用的源的 API 名称 sources 键，如下所示 自定义 CI 作业示例.

每个声明的源都必须导入仓库并具有 API 名称。作业无法使用已导入仓库但未在以下位置声明的源 ci.additions.yml.

访问源密钥

检查会将已声明源的每个密钥作为名为以下名称的环境变量提供 <source API name>_<secret name>。例如，如果 API 名为以下名称的源 MySource 具有名为以下名称的密钥 password，作业可以从以下位置读取该密钥 MySource_password 环境变量指向的文件。

源密钥变量优先于以下位置中同名变量 env。如果两个源生成相同的变量名，作业只会收到其中一个值。请确保每个源 API 名称与密钥名称的组合都是唯一的。

可用工具

作业在包含以下工具的精简 Linux 环境中运行：

  • bash 以及常用命令行实用程序，例如 grep, sed, find, xargs, tar, gzip, bzip2日 base64
  • git
  • python3 和 Python 标准库
  • Java 开发工具包 (JDK)，位于 $JAVA_HOME

诸如以下工具 curl 和 ssh 不可用。要发出 HTTP 请求，请使用 Python，例如配合 urllib.request 模块 ↗.

创建自定义 Gradle 任务

您可以将自定义检查创建为 Gradle ↗ 任务。将这些任务添加到语言子文件夹中相应的内部 build.gradle 文件中。以下示例定义了一个在运行时打印 Hello World 的 Gradle 任务。 doLast 方法会创建一个在任务执行时（而非配置时）运行的任务操作。

// Define custom task
task customTask {
    doLast {
        println "Hello World"
    }
}

要在 CI 检查期间运行某个任务，CI 任务必须依赖于它。请在同一个 build.gradle 文件中定义此依赖关系。在以下示例中， check 任务在 CI 中的 customTask 之后运行，并且 Hello World 消息会显示在 CI 日志中。

Copied!
1
2
// Add CI dependency on custom task
project.tasks.check.dependsOn customTask

要在任务列表末尾运行某个任务，请改用以下语法。

Copied!
1
2
// Execute custom task after CI checks are published
project.tasks.publish.configure { finalizedBy customTask }

要添加依赖关系，请使用以下 CI 任务： project.tasks.check, project.tasks.test日 project.tasks.publish。请勿使用或依赖其他 CI 任务（例如内部任务），因为它们不受保证且可能会发生变化。

有关 Gradle 构建脚本的更多信息，请查看 Gradle 文档 ↗.

请勿将自定义检查添加到 ci.yml 文件，因为 仓库升级 会覆盖它。要在检查期间运行其他命令，请使用 自定义 CI 作业 来替代。
