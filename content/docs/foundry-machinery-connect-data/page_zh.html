将数据连接到 Machinery

通过将流程连接到数据源，您可以弥合抽象流程定义与真实世界观测之间的差距。此数据可用于进行初步 流程挖掘 或 监控性能并查找瓶颈。

Machinery 连接到本体论中的两类对象数据： 流程对象 以及 日志对象。用于数据配置的侧面板可通过主工具箱或流程容器访问。

流程对象

流程对象是经历某个流程的实体。

例如，这可能是一个 Employee （用于入职流程），或者是一个 Invoice （用于采购到付款流程）。该实体的状态由一个字符串属性显式跟踪，该属性通常称为 state。该属性的值 state （例如

状态值可能具有依赖项，例如操作中的提交条件，或由特定状态条件触发的自动化。在 Machinery 中更改状态值不会更新这些依赖项，也不会更改本体论数据中的值。

在多流程设置中，每个流程容器恰好捕获对象类型上的一个状态属性。

流程对象类型表示实体的最新状态，因此无法提供有关状态转换和时间模式的信息。

日志对象

日志对象表示对实体状态的单次变更。日志对象包含对流程实体的引用、该实体的先前状态、新状态以及转换的时间信息。

  • 日志 ID（字符串）[必填]： 日志对象的主键。
  • 流程 ID（字符串）[必填]： 正在跟踪的流程对象的主键。在流程对象与日志对象之间设置本体论关联时使用。
  • 旧状态（字符串）[必填]： 转换的起始状态。
  • 新状态（字符串）[必填]： 转换的结束状态。
  • 时间戳 (timestamp) [必需]： 进入结束状态的时间戳。
  • isLatest (boolean) [可选]： 如果此日志是流程对象的最新日志，则为 True，否则为 False。
  • 持续时间 (long) [可选]： 自进入旧状态以来的持续时间（以毫秒为单位）。
  • 路径 (string) [可选]： 到目前为止遇到的所有状态的列表，包括当前状态。必须是序列化的 JSON 字符串。
  • 操作类型 RID（字符串）[可选]： 导致该转换的操作类型的标识符。通常， NULL 用于外部变更。
  • 所属 RID（字符串）[可选]： 执行该操作的应用程序的标识符。可用于区分手动操作与自动操作。 NULL 用于外部变更。

维护此类日志需要在编辑时进行编排。Machinery 提供了一个标准解决方案，可在应用程序内安装。设置日志对象类型需要流程对象类型。

系统将通过对话框引导您完成设置。您可以选择要跟踪的编辑来源：

  • 如果流程对象类型接收来自外部数据源的更改，您可以选择并配置变更日志数据集。
  • 如果流程对象类型可以在平台中进行编辑，您可以选择 在流程对象类型上启用编辑历史 并将这些编辑包含在日志对象类型中。Machinery 将自动创建编辑历史的物化数据集，使其可用于汇总分析。

目前不支持为具有多个数据源或行级权限的对象类型跟踪来自平台编辑的日志。

如果要跟踪来自外部数据源的更改，您必须选择采用标准变更日志格式的数据集，该格式是 Machinery 日志对象类型架构的简化版本。该数据集通常位于对象类型数据源的上游，并包含以下列：

  • processId (string) [required]: 流程实体的唯一标识符。
  • state (string) [必填]: 进程进入的新状态。
  • timestamp (timestamp) [必填]: 转换发生的时间戳。
  • isDeleted (boolean) [可选]: 用于将实体标记为已删除的属性。如果最新日志的 isDeleted 为 True，该对象将不会出现在本体论中。

确认后，Machinery 将安装一个 Marketplace 产品 到您选择的文件夹中。此产品包含一个 Pipeline Builder 管道，用于根据所配置的数据源计算出正确格式的日志条目。该产品还会部署日志对象类型本身，并在其与您的流程对象类型之间建立本体论关联。

安装完成后，管道需要完成一次初始构建，并且日志对象类型需要在数据库中建立索引，之后数据才可用于挖掘和监控。

已部署的管道计划在其任一数据源发生更改时运行。因此，日志对象类型会比流程对象类型滞后一次构建和一次索引作业，通常约为 2-5 分钟。如果您需要实时更新，则需要维护自定义日志对象类型。

如果自定义日志对象类型满足最小 schema 要求，您可以手动对其进行映射。
