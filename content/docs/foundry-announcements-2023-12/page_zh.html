AIP Logic [GA] 正式发布

发布日期：2023-12-14

AIP Logic 是一个无代码开发环境，用于构建、测试和发布由大型语言模型驱动的函数。借助 AIP Logic，您可以构建功能丰富、利用本体论的 AI 驱动函数，而无需承受开发环境和 API 调用通常会引入的复杂性。应用构建者可以使用 Logic 的直观界面来设计提示词、进行测试、评估和监控、设置自动化等。

您可以使用 AIP Logic 来自动化和支持您的关键任务，无论是将非结构化输入中的关键信息连接到本体论、解决日程安排冲突、通过找到最佳分配方案来优化资产性能，还是应对供应链中的中断。

AIP Logic 的着陆页。

访问 AIP Logic

您可以从平台的工作区导航栏访问 AIP Logic，也可以使用快速搜索快捷键 CMD + J (macOS) 或 CTRL + J (Windows)。或者，您可以从您的 文件 中创建新的逻辑函数，方法是选择 +New ，然后选择 AIP Logic，如下所示。

“+ 新建”下拉菜单。

开发路线图上有哪些内容？

以下 AIP Logic 功能目前正在开发中：

  • Logic Assistant： 在编写提示词时获得 AI 辅助，并检查是否缺少工具和数据。构建更可靠的 Logic 函数，并受益于更快的提示词迭代和更低的错误率。
  • 版本管理与分支： 创建、管理和合并 AIP Logic 函数的不同版本和分支。
  • 评估： 结合您的本体论定义建立评估和测试框架，以衡量 Logic 函数的有效性。

自由形式分析微件简介

发布日期：2023-12-12

自由形式分析 Workshop 微件 使用户能够在 Workshop 应用程序的框架内灵活地独立调查对象数据。该小部件现已正式推出，用户可以受益于由 Quiver 强大的功能套件驱动的简洁的基于路径的分析界面。

使用自由形式分析小部件，直接在 Workshop 应用程序中调查数据。

在 Workshop 应用程序内无缝进行数据探索

借助自由形式分析小部件，用户可以在 Workshop 应用程序内探索对象数据，并与其他人共享其调查结果，以减少重复工作并改进其工作流程。以前，当用户想要深入研究 Workshop 应用程序中的数据时，需要使用 Contour 或 Quiver 来支持其调查。

现在，借助自由形式分析小部件，以下用例将从中受益：

  • 数据探索： 在现有 Workshop 应用程序中探索数据并创建量身定制的调查。
  • 根因调查： 在收到警报后，用户可以在预定义的一组可视化基础上进行构建，并朝着与其调查最相关的任何方向深入钻取数据——包括探索关联的对象类型。
  • 应用程序原型设计： 构建者可以查看已保存的分析，以了解常见的偏离既定路径的探索模式，然后将这些模式纳入生产工作流程中。
  • 队列创建： 用户可以向下钻取以创建自定义同类群组，并将其保存为组，供在应用程序的其他地方使用。

开始使用自由形式分析小组件

要开始使用自由形式分析小组件，只需在 Workshop 小组件主页中搜索该小组件。然后，进行配置：

  1. 提供一个 输入对象集 ，作为分析的基础输入。
  2. 定义当路径中没有卡片时小组件应如何配置，方法是设置 空状态标题 和 空状态描述。
  3. 确定 输出对象集，这将保存输出对象集，以供在 Workshop 中的其他位置引用。
  4. （可选）开启 “启用路径保存” ，该选项会将路径中的各个卡片复制并添加到 Notepad 文档中。用户应注意，只有位于已保存分析路径中的卡片才能被复制。

分析路径可以保存为公开或私有，以供将来参考，还可以在 Quiver 中打开，或复制到 Notepad 文档中。

自由形式分析小组件配置

要了解更多信息，请参阅 自由形式分析小组件 文档。

import { GPT_4 } from "@foundry/models-api/language-models";

@Function()
public async sentimentAnalysis(userPrompt: string): Promise<string> {
    const systemPrompt = "Provide an estimation of the sentiment the text the user has provided. \
    You may respond with either Good, Bad, or Uncertain. Only choose Good or Bad if you are overwhelmingly \
    sure that the text is either good or bad. If the text is neutral, or you are unable to determine, choose Uncertain."

    const systemMessage = { role: "SYSTEM", content: systemPrompt };
    const userMessage = { role: "USER", content: userPrompt };
    const gptResponse = await GPT_4.createChatCompletion({messages: [systemMessage, userMessage], params: { temperature: 0.7 } });
    return gptResponse.choices[0].message.content ?? "Uncertain";
}

Pipeline Builder 中的 Text to Embeddings 板块

Pipeline Builder 现已包含一个功能强大的全新 Text to Embeddings 板块。 嵌入向量 嵌入向量是文本的密集向量表示，旨在捕捉文本中词语或短语的语义含义，供 LLM 处理。嵌入向量将文本转换为可供 LLM 处理的数值形式。

数值表示（嵌入）支持基于上下文相似性（而不仅仅是句法相似性）来比较文本数据。例如，在比较“cat”（猫）、“dog”（狗）和“balloon”（气球）这些词时，嵌入可以帮助确定“cat”和“dog”在含义上的关联比“cat”和“balloon”更紧密，并可利用这一理解来驱动高级文本分析和操作。

在 Pipeline Builder 中使用嵌入对于涉及语义搜索的工作流尤其有益，因为它使 LLM 能够通过评估向量的相似性来执行更有效、更细致且更准确的搜索。
