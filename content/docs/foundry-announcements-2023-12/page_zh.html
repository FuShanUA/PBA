AIP Logic 正式发布 [GA]

发布日期：2023-12-14

AIP Logic 是一个无代码开发环境，用于构建、测试和发布由大语言模型驱动的函数。借助 AIP Logic，您可以构建功能丰富的 AI 驱动函数，利用本体论，同时避免开发环境和 API 调用通常带来的复杂性。使用 Logic 的直观界面，应用构建者可以设计提示词、进行测试、评估和监控、设置自动化等。

您可以使用 AIP Logic 来自动化和支持您的关键任务，无论是将非结构化输入中的关键信息连接到您的本体论、解决调度冲突、通过寻找最佳分配来优化资产性能，还是应对供应链中的中断。

以下 AIP Logic 功能目前正在开发中：

  • Logic 助手： 在编写提示词时获得 AI 辅助帮助，并检查缺失的工具和数据。构建更可靠的 Logic 函数，享受更快的提示词迭代速度和更低的错误率。

自由格式分析小组件简介

发布日期：2023-12-12

直方图 自由格式分析 Workshop 小组件 使用户能够在 Workshop 应用程序的框架内灵活地独立调查对象数据。该小组件现已正式发布，允许用户受益于由 Quiver 强大的功能套件驱动的简单基于路径的分析界面。

使用自由格式分析小组件直接在 Workshop 应用程序中调查数据。

在 Workshop 应用程序内无缝探索数据

借助自由格式分析小组件，用户可以在 Workshop 应用程序内探索对象数据，并与他人分享他们的调查，以减少重复工作并优化工作流程。以前，当用户想要深入研究 Workshop 应用程序中的数据时，他们需要使用 Contour 或 Quiver 来支持其调查。

现在，借助自由格式分析小组件，以下用例将受益：

  • 数据探索： 在现有的 Workshop 应用程序中探索数据并创建定制调查。
  • 根因调查： 在收到警报后，用户可以基于预定义的可视化集合进行构建，并朝着与其调查最相关的方向深入钻取数据——包括探索关联的对象类型。
  • 应用程序原型设计： 构建者可以查看已保存的分析以了解常见的偏离常规路径的模式，然后将其纳入生产工作流程中。
  • 队列创建： 用户可以向下钻取以创建自定义队列，并将其保存为一个组，供应用程序中的其他地方使用。

开始使用自由格式分析小组件

要开始使用自由格式分析小组件，只需在 Workshop 小组件主页中搜索该小组件。然后，进行配置：

  1. 提供一个 该输入变量决定了微件中展示的对象数据。 作为分析的基础输入。
  2. 通过设置以下内容，定义当路径中没有卡片时小组件的配置方式 空状态标题 和 空状态描述.
  3. 确定 输出对象集，它将保存输出对象集，供 Workshop 中的其他地方参考。
  4. 或者，开启 启用路径保存 它将复制路径中的各个卡片并添加到 Notepad 文档中。用户应注意，只有当卡片位于已保存的分析路径中时才能被复制。

分析路径可以保存为公共或私有以供将来参考，也可以在 Quiver 中打开，或复制到 Notepad 文档中。

import { GPT_4 } from "@foundry/models-api/language-models";

@Function()
public async sentimentAnalysis(userPrompt: string): Promise<string> {
    const systemPrompt = "Provide an estimation of the sentiment the text the user has provided. \
    You may respond with either Good, Bad, or Uncertain. Only choose Good or Bad if you are overwhelmingly \
    sure that the text is either good or bad. If the text is neutral, or you are unable to determine, choose Uncertain."

    const systemMessage = { role: "SYSTEM", content: systemPrompt };
    const userMessage = { role: "USER", content: userPrompt };
    const gptResponse = await GPT_4.createChatCompletion({messages: [systemMessage, userMessage], params: { temperature: 0.7 } });
    return gptResponse.choices[0].message.content ?? "Uncertain";
}

Pipeline Builder 中的文本转嵌入（Text to Embeddings）板块

Pipeline Builder 现在包含一个功能强大的全新文本转嵌入（Text to Embeddings）板块。 嵌入向量 是文本的密集向量表示，旨在捕获文本中词语或短语的语义含义，以供 LLM 处理。嵌入将文本转换为可供 LLM 处理的数值形式。

这种数值表示（嵌入）允许基于上下文相似性（而不仅仅是句法相似性）来比较文本数据。例如，在比较“cat”、“dog”和“balloon”这几个词时，嵌入可以帮助判断“cat”和“dog”在语义上比“cat”和“balloon”更为相关，并利用这一理解来驱动高级文本分析和操作。

在 Pipeline Builder 中使用嵌入对于涉及语义搜索的工作流尤其有益，因为它使 LLM 能够通过评估向量的相似性来执行更有效、更细致、更准确的搜索。
