布局

布局组件 用于将视图排列到不同的容器中，从而在特定标签页内组织和构建对象视图页面的布局。

每个对象视图可具有三个层级的布局控制：

  • 标签页，具备一系列功能，相关说明见 配置标签页
  • 标签页内的布局组件（也称为容器），使您能够在内容框中组织对象视图。
  • 所有内容组件（可视化、属性和关联、筛选器等）都是对象视图的基本构建单元。

以下是布局容器的类型：

  • 页面的视觉设计—— 水平分布 和 垂直堆叠容器。
  • 在标签页内嵌套添加另一层级的内容—— 标签式容器。
  • 根据用户与之交互的 筛选器 来启用内容的显示/隐藏—— 条件容器。
  • 显示文本，并使用对象值丰富其内容—— Markdown 组件。

水平分布

此组件使您能够通过在容器中水平分布、并排显示各个组件，直观地组织对象视图的布局。它只是一个容纳其他组件的容器，本身没有其他功能。

配置

添加水平分布小部件后，您可以在配置中点击“添加项目”，向此容器内添加不同的小部件，点击后将打开小部件选择器。

有两种选项可用于确定如何为容器内的每个小部件分配宽度：

  • 相对（Relative）- 为容器内的每个小部件选择一个整数。小部件将根据其相对数值进行分布。示例：3 个小部件的大小分别为 A=1、B=3、C=2；小部件 A 将占用 1/6 的长度，小部件 B 将占用 3/6 的长度。
  • 像素（Pixel）- 为每个小部件选择分配的绝对像素数。如果像素总和超出对象视图的限制（约 1150 像素），小部件将“溢出”页面。

常见问题与注意事项：

  • 请务必为水平分布小部件添加标题，这是添加该小部件的必要条件。标题将显示在小部件的标题栏上。

垂直堆叠容器

此小部件使您能够以可视方式组织对象视图的布局，方法是在容器内垂直排列显示各个小部件，自上而下逐一堆叠。它只是一个容纳其他小部件的容器，本身不具备独立功能。

配置

添加垂直堆叠容器小部件后，您可以通过配置在该容器中添加不同的小部件，方法是点击“添加项目”，这将打开小部件选择器。

常见问题和注意事项：

  • 请务必为垂直堆叠容器小部件添加标题，这是添加该小部件的必要条件。
  • 若要将垂直堆叠容器与其他小部件并排对齐，请转到配置中的“格式”选项卡，选择左对齐/右对齐，而非默认的“全宽”。
  • 在配置的“设置”下，使用每个选项卡旁边的上/下箭头来选择选项卡的顺序。您还可以删除选项卡或替换每个选项卡内的小部件。

选项卡式容器

通过在当前标签页内创建一个标签页容器，为您的对象视图添加另一层标签页。用户可以在这些标签页之间浏览，每个标签页包含单个小组件（该小组件也可以是多个小组件的容器）。

标签页容器只是其他小组件的容器，其本身没有独立的功能。

配置

  • 添加标签页容器小组件后，您可以通过点击“添加标签页”在此容器内添加不同的组件标签页，这将打开小组件选择器。
  • 每个标签页的名称是该标签页上小组件的标题，显示在配置中的“格式”下。
  • 使用配置中“设置”下每个标签页旁边的向上/向下箭头来选择标签页的顺序。您还可以借此删除标签页或替换每个标签页内的小组件。

常见问题和注意事项：

  • 在本体论中的核心对象中，有时需要使用此标签页。但请注意，“标签页中的标签页”会增加用户体验的复杂性。
  • 请务必为选项卡式容器小部件添加标题，这是添加该小部件的必要前提。标题将显示在小部件的标题栏上。

条件容器

条件容器可根据条件显示或隐藏内容。此条件可以基于：

  • 用户在对象视图上应用的筛选器
  • 对象或关联对象的属性值
  • 是否存在特定类型的关联对象

配置

此小部件支持添加一个或多个 条件分区。其中每个分区都包含一个 条件 以及一个或多个小部件，这些小部件会 根据该条件显示 。要设置条件分区，请按照以下三个步骤操作：

步骤 1 – 设置条件

第一步是定义用于确定容器内容显示还是隐藏的条件。共有三种不同类型的条件：

条件 1 – 筛选器

筛选器 条件会根据对象视图上是否应用了筛选器来显示或隐藏容器内容。此条件可以通过三种不同的方式进行配置：

  • 特定筛选器 – 仅当在特定属性上应用了筛选器时，才会显示容器的内容。该属性既可以是当前查看对象的属性，也可以是关联对象的属性。这意味着，要使用此条件，必须存在另一个筛选器控件，专门针对此条件中定义的相同对象和属性进行筛选。
    • 示例：在配置机场的对象视图时，有一个筛选器，用于仅保留已取消的航班（Status = “Cancelled”）。显示已取消航班详细信息的条件容器被配置为仅当应用此类特定筛选器时才显示。
    • 注意：要使此条件类型正常工作，需要在“筛选关联对象”和“筛选属性”下拉菜单中选择相同的对象类型。
  • 无筛选器 – 仅当在当前标签页或与该标签页共享交叉筛选器的任何标签页中未应用任何筛选器时，才会显示该容器。这可以是任何类型的筛选器，例如日期筛选器、下拉筛选器、按钮筛选器等。
  • 任意筛选器 – 仅当在当前标签页中，或在与该标签页共享交叉筛选器的任一标签页中应用了至少一个筛选器时，才会显示该容器。与 无筛选器一样，这可以是任何类型的筛选器，例如日期筛选器、下拉筛选器、按钮筛选器等。

条件 2 – 属性

该 属性 条件会根据对象某个属性的值来显示或隐藏容器的内容。该对象既可以是当前查看的对象，也可以是关联对象。对于关联对象，其与当前对象的关系必须是 一对一 或 多对一，在这种情况下，当前对象需要位于关系的“多”端。

要使用此条件类型，您需要先选择要使用的属性。接下来，您需要定义何时根据该属性来显示条件容器的内容。共有四个选项：

  • 已定义 – 该属性的值不为 null。
  • 未定义 – 该属性的值为 null。
  • 属于以下之一 – 该属性的值与您定义的其中一个值匹配。
  • 不是以下之一 – 该属性的值 不 与您定义的其中一个值匹配。

对于 是以下之一 和 不是以下之一，您定义的值将被转换以匹配属性类型（如果属性类型为整数、双精度数、日期或布尔值）。有关如何执行此属性比较的更多详细信息，请参见下文。

条件 3 – 关联对象

该 关联对象 条件会根据是否存在特定类型的关联对象来显示或隐藏容器的内容。要设置此条件，您首先需要选择一个关联路径。然后，您需要决定在哪种情况下显示条件容器的内容：所选路径的关联对象 存在 还是 不存在。

此条件的逻辑可以通过将其与关联对象视图进行比较来推断。带有此条件的容器，其内容只应在以下情况下显示：具有相同关联路径的关联对象视图会显示至少一个对象（如果关联对象应该 存在），或者不显示任何对象（如果关联对象应该 不存在).

第 2 步 – 添加小组件

定义条件后，第二步是配置要在容器中显示的实际内容。点击“添加分区”按钮，并根据需要添加任意数量的小组件。请注意，您可以使用向上/向下箭头对条件容器中显示的小组件进行排序。

第 3 步 – 选择布局

最后，第三步也是最后一步是选择容器的布局。布局可以是以下两种之一：

  • 水平 – 小组件从左到右显示，类似于水平分布容器小组件
  • 垂直 – 小组件从上到下显示，类似于垂直堆叠容器小组件

完成这三个步骤后，您的条件容器应该已配置完成，可以使用了！

常见问题与注意事项：

  • 属性值比较是如何进行的？
    • 字符串值会正常进行匹配
    • 对于数值属性，小组件中的所有输入值都会被转换为数字，并与数值属性进行比较（例如，输入字符串 3.1415，它会被转换为 double 类型）
    • 对于布尔属性，如果您在小组件中输入“true”、“yes”和“1”，它们都会被视为真值输入，其余值均被视为假值。
    • 日期和时间戳值在转换为字符串后进行匹配
    • 目前不支持数组
  • 如果添加了多个条件，条件将自上而下进行评估 - 第一个满足的条件对应的部分将被渲染，其他部分将被忽略。
  • 基于属性值的条件容器选项适用于 1 对 1 或多对 1 的关系，其中当前显示的对象位于关联侧（“多”方）。
    • 它 不 允许使用当前对象位于主体侧的多对多或 1 对多关系作为条件，并且它 不 允许根据关联对象值的聚合来设置条件可见性。
    • 示例：在查看飞机对象时，我可以添加一个取决于其所属航空公司的条件（假设它只属于一家航空公司），但无法添加取决于“它是否具有带属性 X 的关联航班对象？”的条件。
  • 此小组件是标签页级可选“可见性”配置的扩展，但作用在小组件级别。但是，它并非完全等同：
    • “可见性”使您能够根据用户配置文件定义条件标签页。
    • 此小部件允许您设置条件视图：（1）在单个标签页内；（2）提供根据所应用的筛选器控制条件可见性的选项（取决于用户的交互）；（3）不包含基于用户配置文件的条件视图。
  • 若要启用条件区块选项，使其根据所应用的筛选器显示/隐藏，请务必在右侧栏配置编辑器的“设置”下勾选“交叉筛选”复选框。
  • 条件容器（Conditional Container）只是一个容纳其他小部件的容器，其中的小部件可水平或垂直分布。

Markdown

此小部件支持将富文本添加为对象视图布局的一部分。它提供了一个纯文本编辑器，基于 Markdown 轻量级富文本格式化语法（markdown-it 库）。此外，此小部件还允许将对象属性值作为文本的一部分进行模板化。

配置

  • 文本框是一个简单的文本编辑器，并支持标准的 markdown-it 库。
  • 对象属性模板化 - 使用 {{propertyName}} 格式（双花括号），以当前对象属性值对 Markdown 内容进行模板化。propertyName 是 本体论中的属性的确切名称（区分大小写）。此外，还支持 {{objectId}}、{{objectTypeId}} 和 {{objectTypeRid}} 值。

附加配置：

  • 换行，有 2 个选项：
    • 启用换行 - 开启时（默认），编辑器中的单个换行符会作为实际换行生效；关闭时，编辑器中的换行不会影响结果。使用标题格式仍然可行。
    • 将 "\n" 转换为换行 - 显示 \n 为换行符（需要开启"启用换行"）。
  • 启用净化 HTML 渲染 - 使用 markdown-it 进行安全的 HTML 渲染。禁止嵌入来自对象属性的 HTML；出于安全考虑，所有属性值都会被转义。

常见问题与注意事项：

  • 目前，使用 {{propertyName}} 格式包含的长文本和数组可能会溢出文本框，且默认不会被渲染。
