调度排障

调度器指标页面

排查调度问题的最佳方式之一是查看 调度器指标页面。指标页面可以告诉你失败的原因，包括常见的失败模式，例如：

  • 直方图 计划构建失败。你将在 Run History 标签页中看到失败构建的证据，点击这些构建将导航到 Builds 应用中的构建报告以查看完整日志。
  • 直方图 计划构建被忽略。该 Run History 标签页将显示 Ignored ，在状态列中，任何被触发但未构建的构建都会显示该状态。
  • 直方图 调度未触发 在预期的时间或频率。对于这种情况， Run History 标签页可能不会在你预期的时间显示构建已被触发。

直方图 Versions 标签页显示过去的调度版本和编辑记录，如果你的调度突然开始表现异常，该页面可能会很有用。检查与该变化相符的调度版本变更，并考虑将调度恢复到之前正常工作的状态。

计划构建失败

你可以通过检查 Run History 标签页来验证调度是否在预期时间被触发，该标签页位于 调度器指标页面.

如果调度已被触发，但构建随后失败，你可以按照 调试指南.

对该构建进行调试。如果未设置适当的权限，调度也将无法构建。调度的权限取决于其使用的令牌模式。参见 项目范围的调度 的文档以获取更多信息。

计划构建被忽略

你可以通过检查 Run History 标签页来验证调度是否在预期时间被触发，该标签页位于 调度器指标页面。这通常也会给出调度被忽略的原因。

所有数据集均为最新

如果所有目标数据集均为最新，即自上次构建以来其输入未发生更新，则调度运行将被忽略。如果是这种情况，你将在 Run History 标签页中看到此原因。在 调度编辑器中，导航到调度列表。然后你可以选择按 Out-of-date为数据血缘图着色，这将让你概览哪些作业规格被视为过期。

在特殊情况下，可以使用 Force Build 选项来覆盖此行为，该选项位于 高级设置中，但在这些情况之外使用会造成计算资源浪费。如果任何目标数据集是由 Phonograph 同步、包含 API 调用的转换或数据连接同步构建的，它们可能不会显示为过期，并且可能需要启用 Force Build 选项才能运行调度。

调度构建部分数据集

如果调度仅触发了部分数据集，你将在 Run History 标签页来验证调度是否在预期时间被触发，该标签页位于 调度器指标页面.

其中一个原因是只有部分数据集过期。调度器将只构建过期的数据集，而最新的数据集将在构建过程中被忽略。参见 所有数据集均为最新 以了解更多排障细节。构建 Ignored 的情况发生在所有这些数据集均为最新时。

另一个原因可能是该数据集未包含在构建的数据集图中。在 调度编辑器中，当选中某个调度时，要构建的数据集会在数据血缘图中高亮显示。数据集的选择取决于 构建类型。如果使用 Connecting build，你应特别注意验证在多个分支上使用相同数据集的调度是否存在连接数据集。

调度未触发

你可以通过检查 Run History 标签页来验证调度是否在预期时间被触发，该标签页位于 调度器指标页面。这里的一些常见调试步骤包括：

  • 检查 调度是否已暂停。已暂停的调度在取消暂停之前不会触发。
  • 检查 调度触发器配置。如果之前是成功的，请检查调度历史记录，看看触发器最近是否有变更。
  • 如果计划使用事件触发器，请验证预期的事件是否确实发生了。例如，如果构建应在输入更新时触发，请检查输入上的最后一次构建是否成功运行，以及该构建上的事务是否已成功提交到 数据集预览历史记录视图.

计划重试次数与配置不符

请注意，并非所有类型的失败都可以重试。计划运行时的重试次数将受限于管理员配置的最大值。参见 部分中选择 的文档以获取更多信息。

计划失败并出现 JobSpecInputsTrashed 或 JobSpecOutputsTrashed，或者数据血缘警告某些数据集已被移入回收站

这意味着计划包含或读取了一个已被移入回收站的资源。您可以通过以下方式之一来解决：

  • 从回收站还原已删除的数据集。
  • 从计划中排除已删除的数据集。如果该数据集被用作计划中另一个下游数据集的输入，您还需要执行以下操作之一：
    • 将下游数据集与被移入回收站的数据集一并排除。
    • 修改下游数据集的逻辑，使其不再以被移入回收站的数据集作为输入。

调度器权限

如果您遇到无法编辑计划的问题，项目范围的权限可能是根本原因。

要在以下模式中编辑计划： 项目范围模式，用户必须拥有 Edit 对目标数据集的权限， View 对触发数据集的权限以及 Edit 对计划所属项目的权限。如果有某个数据集您已失去权限，请在保存更改之前将该数据集从计划中移除。

要编辑、删除或暂停计划，用户需要拥有 Edit 对目标数据集的权限以及 Edit 对计划所属项目的权限。要查看计划，用户需要拥有 View 对目标数据集的权限。
