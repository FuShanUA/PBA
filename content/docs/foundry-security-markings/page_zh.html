标记

标记 为 Foundry 中的文件、文件夹和 Project 提供额外的访问控制层级。标记定义了资格条件，将可见性和操作限制为满足这些条件的用户。要访问某个资源，用户必须是该资源所应用的所有标记的成员才能访问它。平台管理员通常在组织内管理标记。

对标记的访问是二元的（全有或全无）。无论 角色，除非用户满足所有标记要求，否则无法以任何方式访问文件。

标记旨在让数据保护官能够集中管理和审计究竟谁可以访问任何给定的数据类别。标记的一个常见用例是限制对个人身份信息（PII）的访问。例如，您可能有一组用户只有在完成一系列培训后才有资格访问敏感的 PII 数据。平台管理员可以创建一个 PII 标记并将其应用于敏感数据集。此标记确保对 PII 的访问仅限于适当的用户，并且不能共享到该组之外。

隐私最佳实践是将标记与资源权限结合使用，使访问既反映资格条件，也反映用户使用该资源的需要。这种最小权限方法限制了不必要的暴露，同时允许策略限制随派生数据传播；请查阅 实践中的隐私与公民自由 以获取相关指导。

标记是强制性控制，而角色是自主性控制。强制性控制 限制 访问，要求用户必须拥有特定标记才能访问数据。标记本身上的 Expand Access 权限（一种集中管理的权限）是移除标记所必需的。例如，用户可能在带有 PII 标记的数据集上拥有 Owner 角色。除非他们还拥有该标记的 Expand Access 权限，否则 Owner 角色不允许他们移除该标记。相比之下，自主控制 扩展 访问权限，并通过数据共享工作流授予，没有集中化的限制。例如，对某个资源拥有 Owner 角色的任何用户都可以将 Owner 角色授予另一个用户或组。

用户必须是文件、文件夹或 Project 上所有标记的成员才能获得访问权限，因为标记是合取的（布尔 AND).

继承

标记会 继承 沿着文件层级和直接依赖关系传播，并通过转换和分析逻辑传播。从带有标记的文件、文件夹或 Project 派生的所有资源都将继承标记，除非该标记被显式移除。与基于数据在平台中所在位置的角色访问控制不同，标记随数据一起传播。文件可以通过两种方式继承标记：通过 文件层级 和/或通过 数据依赖关系.

文件层级

文件可以通过包含它的 Project 或文件夹继承标记。如果 Project 或文件夹带有标记，其中的每个文件或文件夹都会继承该标记。这意味着限制对 Project 或文件夹的访问总是会限制对其内部所有内容的访问。

数据依赖关系

限制对数据集的访问总是会限制对从其派生的任何数据的访问。这是因为数据集文件可以从它所依赖的数据集（例如上游数据集）继承标记。如果数据集带有文件标记，那么依赖它的每个数据集都会继承该标记，继承的标记被称为数据标记。

应用标记被视为敏感操作，因为该标记将 立即 沿所有文件和数据依赖关系被继承。这可能会无意中锁定下游的其他用户。在使用之前，请先了解如何 安全地应用标记 。

同样，移除标记也被视为敏感操作。您可以从最初应用标记的文件、文件夹或 Project 中移除标记，这将 立即 从下游文件和数据依赖项中移除该标记。或者，可以在转换中移除标记，但这只会移除该标记 。了解如何安全地移除标记 移除标记 在移除之前，请先了解如何安全地移除标记。

使用标记

标记旨在 限制 对文件、文件夹和项目等资源的访问。标记不应用于 授予 访问权限。当用户满足一组标记条件时，他们将获得对该标记及相关资源的访问权限。但是，用户 获得 访问权限的用户并不总是应该 已 访问。应根据项目上基于角色的权限授予用户对文件的访问权限。

例如，假设某个 PII 标记用于限制对包含员工个人身份信息（PII）的所有 Foundry 数据的访问。这些 PII 可能存在于财务记录（如社会安全号码）、健康记录（如有关年龄、性别或诊断的信息）或其他个人数据（如姓名或地址）中。

要处理 PII，用户需要接受适当的培训。假设财务部门的某位用户已完成所需的培训，并有资格访问该 PII 标记。由于该用户来自财务部门，因此该用户被授予 Viewer 财务数据项目上的角色。即使该用户有资格查看其他包含员工 PII 的数据，其在项目中的角色仍然决定其访问级别。

标记应用于对需要额外保护的敏感数据定义访问限制。有多种方法可以应用与数据敏感性相关的标记：

  • 每个敏感数据类别一个标记
    • 在最常用的标记结构中，每个敏感数据类别创建一个标记。每个标记限制对包含该数据类别的所有资源的访问。如果数据具有多种敏感性类型，则所有相应的标记都会应用于该资源；只有有权访问所有相关敏感类别的用户才能获得对该资源的访问权限。
    • 为标记要求和敏感性类型建立明确定义的标准可能会很有用。例如，您可以将包含性别、年龄、种族等个人属性的所有数据标记为 PII marking.
  • 每个敏感数据所有者一个标记
    • 在这种结构下，数据所有者可以决定如何限制对其所拥有数据的访问。采用每个敏感数据所有者一个标记的方式，由团队或用户组拥有的敏感数据会被标记，数据所有者可自行决定向用户授予对该标记的访问权限。例如，销售团队生成、使用和管理所有数据都可以标记为 Sales Data 标记，数据所有者只会向符合条件的用户授予对销售数据的访问权限。
    • 为了给数据所有者提供对其数据资产的额外控制，标记会传播。这意味着，如果有权访问该数据的用户尝试从该数据创建派生资源以与其他用户共享，则数据所有者需要授予其他用户对该标记的访问权限，才能解锁他们对派生资源的访问。
  • 针对不同管道阶段的标记
    • 数据集可以以原始形式摄取到 Foundry 中，通常需要经过处理和转换才能准备好与最终用户共享。原始数据可能包含不适合下游用户的敏感信息，管理员可以选择应用 Raw Data 标记以限制未经授权用户的访问。在通过处理去除 PII（例如哈希或加密）之后，管理员可以移除 Raw Data 标记，并在管道的后续阶段应用其他相关标记以进一步保护数据。
  • 使用标记限制数据发现
    • 由于标记以全有或全无的方式限制访问，因此如果您必须隐藏资源（如文件、文件夹或 Project）的存在，应使用标记。标记可以确保无权访问该标记的用户不会在搜索结果或 Project/文件夹视图中看到被标记的数据。

在 Foundry 中实施标记时，可以组合使用上述策略。例如，您可以有一个 Raw Data 标记位于管道的开头，然后在后处理阶段为每个敏感数据类别设置一个标记。

示例：保护医疗数据

考虑一家假设的医疗机构中三个级别的敏感患者数据：

  • 合成数据：这是敏感度最低的数据，创建用于模拟真实的患者记录。所有合成数据都由 Synthetic Data marking.
  • 去标识化数据：此类数据包含一些敏感字段，但所有直接标识符都已被移除。此类数据可能与其他数据文件结合以识别患者身份。所有此类数据都标记为 De-identified Data marking.
  • 含标识符数据：此类数据可能包含可用于直接识别单个患者身份的标识符。这是患者数据的最高敏感级别。所有此类数据都标记为 Identifiable Data marking.

在这种情况下，数据级别是分层的，具有 Identifiable Data 标记的用户也有权访问 De-identified Data 标记和 Synthetic Data 标记。同样，有权访问 De-identified Data 标记的用户也有权访问 Synthetic Data 标记。

在 Foundry 中，含标识符数据（标记为 Identifiable Data 标记）的数据通过移除标识符字段被转换为去标识化数据（标记为 De-identified Data 标记）。标记管理员或数据所有者会审查转换逻辑中的任何更改，以确保去标识化数据中不包含任何标识符。其他复杂的转换会生成合成数据，并标记为 Synthetic Data 标记。在每个转换阶段，先前的标记会被移除，然后添加一个突出显示数据更新后状态的标记，如下面的屏幕截图中的示意数据所示。

示例：保护调查数据

案件调查数据尤其敏感，例如反洗钱调查。一个案件的数据不得与另一个案件的数据混合。此外，当调查人员审查另一个案件时，不应看到该案件的数据。标记可实现这些案件访问限制：

  • 有关特定案件的数据（包括资源、图像、数据集和其他证据）都标记有一个唯一的 Case - xxxxxx 标记，其中 xxxxxx 表示案件编号。
  • 只有作为特定案件调查员的用户才能获得该案件标记的访问权限。一名调查员在给定时间可以访问多个案件，但这种访问权限会通过各自的标记加以区分。

示例：保护银行数据

在一家假设的银行中，每个团队或部门对其产生或管理的数据拥有完全的控制权。也就是说，每个团队决定其他哪些团队可以访问其数据资产，无论是全部还是部分。在本示例中，我们通过考虑具有相应标记的团队来简化组织设置：消费者金融、内部合规和市场营销。

  • 假设消费金融团队和市场营销团队分别向内部合规团队授予对以下内容的访问权限： Consumer Finance and Marketing 标记。然后，内部合规团队可以验证数据是否在预先批准的工作流程中被正确使用，并进行季度审计。
  • 季度审计的结果记录在带有以下标记的报告中： Internal Compliance 标记，同时移除另外两个标记。这些审计结果只能由内部合规团队访问。如果内部合规团队想要与 DPO（数据保护办公室）共享季度审计报告，内部合规团队可以授予 DPO 访问该 Internal Compliance 标记的权限，以便 DPO 审查合规报告。

请查阅 管理文档 了解如何配置标记。

使用限定范围的会话

作用域会话 使用户能够在 Foundry 会话期间选择预定义标记的一个子集进行访问，从而在不同类型的工作之间创建视觉隔离。如果您的组织启用了范围限定会话，您在登录 Foundry 后可能需要选择一个范围限定会话。这会将您的 Foundry 访问权限限制在范围限定会话中的标记子集内。

选择限定范围的会话后，将显示一个工作区横幅，其中显示该限定范围会话的名称。

如果您有权访问多个限定范围的会话，可以将鼠标悬停在工作区横幅上并选择 更改限定范围的会话。这将弹出登录时显示的限定范围会话对话框，允许您选择一个限定范围的会话。如果您选择的限定范围会话与当前的不同，页面将刷新，您将被限制在您新选择的限定范围会话中。

此外，某些用户可能可以选择进入 无范围限制访问 会话。此选项允许用户绕过范围限定会话的限制，访问其所有标记。
