Webhook

一个 Webhook 是 Data Connection 中的一个概念，它支持向外部系统（例如 Salesforce、SAP 或任何已配置的 HTTP 服务器）发送请求，通常用于修改该外部系统中的数据。

通过设置 Webhook 并将其配置为在操作中使用，当最终用户在 Foundry 中应用操作时，您便可以向外部系统发送数据。这使得 Foundry 中的工作流能够直接与源系统连接，并将数据和决策写回这些系统。

本部分详细介绍了在操作中配置 Webhook 的各种可用选项。有关分步教程，请参阅 如何在操作中添加 Webhook。

Webhook：写回与副作用

在操作中配置使用 Webhook 的方式有两种：作为 写回 或作为 副作用。

为方便起见，下表对写回 Webhook 与副作用 Webhook 的行为进行了对比。

类型应用时机是否向最终用户显示失败？时序
写回在对象更改之前是在用户看到成功或失败之前
副作用在对象更改之后否可能在用户看到成功消息之后

以下各节将更详细地介绍回写 webhook 和副作用 webhook。

回写 webhook

配置为 回写时，webhook 的执行将 先于 任何其他规则的评估；如果 webhook 执行失败，将不会进行任何其他更改。如果您希望确保 Foundry 中的更改不会先于外部系统发生，则应将 webhook 设置为回写。

这一行为在 Foundry 与外部系统之间实现了一定程度的事务性。使用回写 webhook 可以保证：如果对外部系统的请求失败，则不会对 Foundry 本体论应用任何更改。但是，外部请求仍有可能成功，而本体论更改却失败。

由于回写 webhook 失败时会停止应用操作，因此只能将单个 webhook 配置为回写。如果在应用操作时该 webhook 失败，将向最终用户显示描述该失败的错误。

当 webhook 配置为回写时，其输出参数可在后续规则中使用。请参阅下文中的 输出参数 部分，以了解更多详细信息。

副作用 webhook

配置为 副作用，将会执行一个 webhook 在 其他规则评估完成后。这意味着对 Foundry 对象的修改将在应用副作用之前发生。您可以在单个操作中配置多个副作用 webhook，并且它们将按任意顺序执行。在包含副作用 webhook 的操作中，最终用户将在 Foundry 对象被修改后看到成功消息；而副作用的执行可能发生在成功消息显示之后。

如果您需要在单个操作中多次调用某个 webhook，可以使用副作用 webhook 并提供有效载荷列表作为输入来实现。这将按照所提供列表中有效载荷的数量触发相应次数的 webhook，并且不保证处理顺序。相关示例请参阅下方的 输入参数 部分。

当您想要发送尽力而为的通知或写回多个外部系统时，应当使用副作用 webhook。

输入参数

若要在操作中配置 Webhook，您必须填写其所有必需的输入参数。有关 Webhook 输入参数的通用参考资料，请参阅 Data Connection 文档。

配置 Webhook 输入参数有两种方式：映射到操作参数，或使用函数。

映射到 操作参数时，每个必需的 Webhook 输入都必须设置为相同类型的操作参数、静态值或对象参数的属性。

使用 函数时，您必须选择一个返回自定义类型的函数，该自定义类型需包含所有必需的 Webhook 输入参数，并与 Webhook 类型高度匹配，否则您将收到 OntologyMetadata:ActionWebhookInputsDoNotHaveExpectedType 错误。当您想要使用逻辑来填充输入时，使用函数填充 Webhook 输入参数会很有用，尤其是当该逻辑基于本体论对象时。例如，您可以获取关联对象并从这些对象中提取属性值，以预填充 Webhook 输入。

import { Function, UserFacingError } from "@foundry/functions-api";
import { Company } from "@foundry/ontology-api";

export interface MyWebhookInput {
    name: string;
    industry: string;
    country: string;
}

export class MyWebhookFunctions {
    @Function()
    public returnWebhookInput(company: Company): MyWebhookInput {
        if (!company.name || !company.industry || !company.country) {
            throw new UserFacingError("Some required fields are not set.");
        }
        return {
            name: company.name,
            industry: company.industry,
            country: company.country,
        }
    }
}

import { Function } from "@foundry/functions-api";
import { Company } from "@foundry/ontology-api";

export interface MyWebhookInput {
    arg1: string;
    arg2: string;
}

export class MyFunctions {
    @Function()
    public createWebhookRequest(company1: Company, company2: Company): MyWebhookInput[] {
        return [
        {
           arg1: company1.someProperty,
           arg2: company1.someOtherProperty,
        },
        {
           arg1: company2.someProperty,
           arg2: company2.someOtherProperty,
        }
        ];
    }
}

输出参数

当 Webhook 被配置为 回写 Webhook时，您可以在后续规则中使用其输出参数。这在以下情况下非常有用：您希望立即将外部系统返回的数据写入 Foundry 对象，或将其用于后续 通知 或 副作用 Webhook。

有关 Webhook 输出参数的通用参考资料，请参阅 数据连接文档。

要在后续逻辑规则中使用输出参数，请在为逻辑规则填充值时选择 回写响应 ，然后选择您希望使用的特定输出：

OAuth 2.0 身份验证

在 REST API 源上配置 Webhook 且该源使用 出站应用程序 进行身份验证时,Foundry 会代表用户管理 OAuth 2.0 授权流程。开发人员无需处理令牌获取或刷新。Foundry 会在每次 Webhook 调用时传递正确的访问令牌。

有关 Foundry 各工作流中对 OAuth 2.0 出站应用程序支持的完整概述,请参阅 OAuth 2.0 出站应用程序 文档。
