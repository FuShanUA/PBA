Webhook

A TypeScript v1 函数无法直接从源获取 OAuth 令牌。要在 TypeScript v1 函数中通过 OAuth 2.0 API 进行身份验证，请将调用封装在 是 Data Connection 中的一个概念，它支持向外部系统（例如 Salesforce、SAP 或任何已配置的 HTTP 服务器）发送请求，通常用于修改该外部系统中的数据。

通过设置 webhook 并将其配置为在操作中使用，您可以在最终用户于 Foundry 中应用操作时向外部系统发送数据。这使得 Foundry 中的工作流能够直接与源系统连接，并将数据和决策写回这些系统。

本节详细介绍在操作中配置 webhook 的各种可用选项。有关分步教程，请参阅以下文档： 如何在操作中添加 webhook.

Webhook：写回与副作用

在操作中配置 webhook 有两种方式：作为 回写 或使用 副作用.

为方便起见，下表对比了写回 webhook 和副作用 webhook 的行为。

类型应用时是否向最终用户显示失败？时机
回写在对象更改之前是在用户看到成功或失败之前
副作用在对象更改之后No可能在用户看到成功消息之后

以下各节将更详细地介绍写回 webhook 和副作用 webhook。

写回 webhook

当配置为 回写时，webhook 将被执行 然后 任何其他规则被评估之前；如果 webhook 执行失败，则不会进行任何其他更改。如果您希望确保在外部系统之前不在 Foundry 中进行更改，应将 webhook 设置为写回。

这种行为在 Foundry 与外部系统之间实现了一定程度的事务性。使用写回 webhook 可以保证：如果对外部系统的请求失败，则不会对 Foundry 本体论应用任何更改。但是，外部请求仍有可能成功，而本体论的更改却失败。

由于写回 webhook 失败时操作会停止应用，因此只能将单个 webhook 配置为写回。如果在应用操作时此 webhook 失败，将向最终用户显示描述该失败的错误。

当 webhook 配置为写回时，其输出参数可在后续规则中使用。请参阅 输出参数 一节以了解更多详情。

副作用 webhook

当配置为 副作用时，webhook 将被执行 在 其他规则被评估之后。这意味着对 Foundry 对象的修改将在应用副作用之前发生。您可以在单个操作中配置多个副作用 webhook，它们将按无特定顺序执行。在包含副作用 webhook 的操作中，最终用户将在 Foundry 对象被修改后看到成功消息；执行副作用可能发生在显示成功消息之后。

如果您需要从单个操作多次调用 webhook，可以通过副作用 webhook 并提供负载列表作为输入来实现。这将按所提供列表中的负载数量触发相应次数的 webhook，并且不保证按特定顺序处理。相关示例可在下方的 连接，这些参数在生成时传递。 区域的字段中添加命令。

当您希望发送尽力而为的通知或写回多个外部系统时，应使用副作用 webhook。

输入参数

要在操作中配置 Webhook，必须填写其所有必需的输入参数。有关 Webhook 输入参数的通用参考材料，请参阅 Data Connection 文档.

配置 Webhook 输入参数有两种方式：映射到操作参数，或使用函数。

在映射到 Action 参数时，每个必需的 Webhook 输入必须设置为相同类型的 Action 参数、静态值或对象参数的属性。

使用 函数时，您必须选择一个返回自定义类型的 Function，该类型包含所有必需的 Webhook 输入参数，并与 Webhook 类型高度匹配，否则您将收到 OntologyMetadata:ActionWebhookInputsDoNotHaveExpectedType 错误。当您希望使用逻辑来填充输入时，使用 Function 填充 Webhook 输入参数会很有用，尤其是当该逻辑基于本体论对象时。例如，您可以检索关联的对象并从这些对象中提取属性值，以预填充 Webhook 输入。

import { Function, UserFacingError } from "@foundry/functions-api";
import { Company } from "@foundry/ontology-api";

export interface MyWebhookInput {
    name: string;
    industry: string;
    country: string;
}

export class MyWebhookFunctions {
    @Function()
    public returnWebhookInput(company: Company): MyWebhookInput {
        if (!company.name || !company.industry || !company.country) {
            throw new UserFacingError("Some required fields are not set.");
        }
        return {
            name: company.name,
            industry: company.industry,
            country: company.country,
        }
    }
}

export interface MyWebhookInput {
    arg1: string;
    arg2: string;
}

export class MyFunctions {
    @Function()
    public createWebhookRequest(company1: Company, company2: Company): MyWebhookInput[] {
        return [
        {
           arg1: company1.someProperty,
           arg2: company1.someOtherProperty,
        },
        {
           arg1: company2.someProperty,
           arg2: company2.someOtherProperty,
        }
        ];
    }
}
