发布渠道

概述

发布渠道会根据稳定性、标签等通用属性对产品发布版本和模块发布版本进行分组。环境操作员会将环境中的实体订阅到发布渠道。在解析确定的维护窗口期间,Apollo 会将实体升级到发布渠道中通过所有约束的最新发布版本。

Apollo 拥有一组默认发布渠道,此外还支持自定义发布渠道。

发布渠道晋升

可以通过以下三种方式之一将发布版本添加到发布渠道:

  • 当发布版本发布到 Apollo 时,会自动将其添加到默认发布渠道。
  • 如果发布版本满足发布渠道的标签要求,发布渠道贡献者可以手动将发布版本添加到发布渠道。
  • 产品和模块编辑者可以配置发布晋升管道，在配置的维护窗口期间，如果发布满足必要的标签和健康要求，这些管道会自动将发布依次添加到后续的发布渠道。请注意，只有产品发布管道可以配置用于晋升的健康要求。

默认发布渠道

Apollo 中有三个默认的发布渠道，发布在发布时可能会被自动添加到这些渠道：DEV、RELEASE_CANDIDATE 和 RELEASE。发布会根据其版本号的格式被添加到相应渠道，版本号的格式决定了版本类型：

  • 版本类型为 Release 的发布会被添加到 DEV、RELEASE_CANDIDATE 和 RELEASE 发布渠道。
  • 版本类型为 Release Candidate 的发布会被添加到 DEV 和 RELEASE_CANDIDATE 发布渠道。
  • 其他类型版本的发布会被添加到 DEV 发布渠道。

详细了解产品发布版本类型。

手动发布渠道晋升

发布渠道贡献者可以手动将发布添加到其发布渠道。当在将发布晋升到晋升管道中处于上游位置的发布渠道之前需要进行手动测试或验证时，此功能非常有用。在应对需要覆盖已配置发布渠道晋升管道的支持或稳定性事件时，手动晋升也非常有用。

详细了解手动晋升工作流。

发布晋升管道配置

产品和模块编辑者可以配置发布晋升管道，这些管道定义了发布如何从一个默认或自定义发布渠道晋升到其他发布渠道。他们可以设置：

  • 发布在到达最终发布渠道之前必须依次经过的发布渠道序列。
  • 晋升管道的每个阶段需要满足的条件。

详细了解如何配置发布晋升管道。

默认晋升管道

Hub 管理员可以为 Hub 配置默认晋升管道，作为新产品和模块的起点。

当新产品或模块的第一个版本发布时，Apollo 会根据相应的 Hub 默认设置填充该产品或模块的晋升管道。对 Hub 默认晋升管道的更改不会追溯应用于已配置晋升管道的产品或模块。Hub 管理员可以将默认设置应用于未设置管道的现有产品。

了解更多关于配置默认晋升管道的信息。

晋升超时

Apollo 会强制执行多项超时设置，以防止晋升操作无限期地处于进行中状态。

  • 浸泡时长超时：在金丝雀浸泡期间，如果经过配置的浸泡时长的两倍时间仍未满足健康条件，则晋级将被取消。此计算不包含周末时间。例如，如果浸泡时长为 24 小时，则在工作日时间经过 48 小时后若金丝雀仍不健康，晋级将超时。如果正在浸泡的版本是源通道上未被撤回的最新 Release，则此超时将被禁用，因为没有更新的 Release 可供晋级。
  • 等待金丝雀超时：如果金丝雀实体无法达到正在晋级的版本，则晋级将在七天后被取消。
  • 整体晋级超时：如果晋级已运行超过 30 个日历日，则将被取消。与其他超时不同，这是实际时间超时，不排除周末。如果晋级因等待标签要求或维护窗口得到满足而停滞，则可能会发生这种情况。
