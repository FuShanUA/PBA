数据集和对象集

数据集

在 Contour 和 Code Workbook 中，用户可以选择输出数据集（表格数据）来保存分析结果。这些数据集可在 Contour、Code Workbook 和 Fusion 等应用中使用，也可与其他用户共享。

Contour 和 Code Workbook 并未针对创建生产管道进行优化。如果您正在构建或维护生产管道，请使用 代码仓库 应用，它包含版本历史、分支和拉取请求，以及其他对构建稳健管道至关重要的功能。更多信息请参阅 这篇对 Foundry 各类编写基于代码的转换工具的比较。

Contour

您可以通过选择以下选项来保存 Contour 路径的结果 保存为数据集 （位于路径底部）。为数据集命名并选择保存位置后，该数据集将随分析结果一起构建。 了解有关从 Contour 保存数据集的更多信息。

代码仓库（Code Repositories）

您可以通过选择以下选项，将 Code Workbook 转换的结果保存为数据集 保存为数据集。默认情况下，新的转换不会保存为数据集。 了解有关从 Code Workbook 保存数据集的更多信息。

什么时候 Code Repositories 更合适？

我们建议使用 代码仓库 应用来创建稳健的生产管道，并支持需要额外治理和监控层的工作流。借助 Code Repositories，数据工程师可以批量创建高效的管道。

适合使用 Code Repositories 的示例工作流包括：

  • 需要增量计算的大规模数据每日管道。
  • 具有严格治理要求的高可见性管道，需要能够回退到历史代码的先前版本，或在单元测试成功通过后才允许代码变更。

适合在 Contour 或 Code Workbook 中保存数据集的示例工作流包括：

  • 一次性捕获数据，然后在另一个分析应用中使用。

虽然您可以为在 Contour 和 Code Workbook 中创建的数据集设置构建计划，但管道化工作流通常应归属于 Code Repositories。

对象集

对象集是现实世界实体的列表，保存后可供日后参考，并可在支持对象的各类 Foundry 应用程序中使用。对象集会作为资源保存，便于与合作者共享。

对象集有两种类型：

  • 静态对象集： 静态对象集保存为主键列表，无论输入数据发生任何变化，它都将保持不变。
  • 动态对象集： 动态对象集保存为用于创建该对象集的筛选器的表示形式。当新数据与筛选器匹配时，对象集将随之更新。

在 Quiver 分析中创建的对象集可以保存在 Foundry 中。保存后，这些对象集可以在新的 Quiver 分析中导入，或在其他 Foundry 应用（如 Object Explorer）中打开。

要导出对象集，请点击卡片右上角的 图标打开对象集卡片的编辑器，然后导航到“导出”选项卡。

要导入对象集，请使用 导入已保存的对象引用 卡片。

阅读更多关于 如何在 Quiver 中导入和导出对象集.
