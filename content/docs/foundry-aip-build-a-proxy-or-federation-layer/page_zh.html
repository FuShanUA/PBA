使用 AIP 构建代理或联合层

代理或联合层位于 AIP 与一个或多个外部模型提供商之间。您的计算模块接收来自 AIP 的推理请求,应用自定义逻辑,并将其转发给外部提供商。这使您能够精确控制哪些数据离开您的环境,以及请求的路由方式。

用例

  • PII 脱敏: 在提示词到达外部提供商之前,先剥离或遮蔽其中的敏感数据。
  • 提示词注入: 在转发之前,前置系统提示词、附加指令或转换请求内容。
  • API 格式重映射: 在 AIP 预期的提供商 API 格式与使用不同格式的提供商之间进行转换。
  • 多提供商联合: 根据成本、延迟或模型可用性,将请求路由到单个已注册模型背后的多个提供商。

其他前提条件

除了常规 前提条件 (适用于由计算模块支撑的模型)外,将计算模块用作代理或联合层还需要:

  • 网络出站: 您的计算模块必须能够访问外部模型提供商。请通过 源 在 Data Connection 中配置出站,并应用相应的网络策略。
  • 机密信息: 必须将外部提供商的 API 密钥或其他凭据附加到源。您的容器在运行时通过 SOURCE_CREDENTIALS 环境变量。请查看 源 以了解配置和读取机密的详细信息。

如何使用 AIP 构建代理或联合层

  1. 构建一个容器来实现 受支持的提供商 API 格式。该容器应接收来自 AIP 的请求，应用您的自定义逻辑（例如脱敏、路由或提示词注入），并将其转发给一个或多个外部提供商。
  2. 创建一个 源 （位于 Data Connection 中），并配置网络策略以允许出站访问您的外部提供商。将 API 密钥或其他凭证作为机密附加。
  3. 设置 application.port 标签，将其写入您的 Dockerfile，并将镜像发布到 Artifacts。如需通用容器指导，请查看 计算模块容器 文档。
  4. 创建一个 计算模块 ，使用已发布的镜像，并附加您之前创建的源。将最小副本数设置为至少一个。
  5. 注册模型 ，在 Control Panel 中完成，并配置其能力。
  6. 选择该模型，可在任意 受支持的 AIP 应用中进行。
