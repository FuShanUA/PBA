我的自定义环境初始化缓慢

初始化缓慢通常表明环境定义过大或过于复杂。初始化时间往往随环境中包的数量呈超线性增长。此外，Foundry 通常会预先初始化常用的环境，因此如果您基于默认配置文件创建了自定义环境，速度变慢很可能是因为您不再使用预先初始化的环境，而必须等待新环境的创建。参见 环境创建简介 以了解有关环境创建过程的更多详情。

请尝试以下操作：

  1. 撤销 - 如果环境在配置发生更改后开始初始化缓慢，请尝试还原该更改。在某些情况下，即使只添加一个包也可能显著增加初始化时间。
  2. 简化 - 从环境定义中移除任何不需要的包。小型的专用环境比大型的通用环境性能要好得多。
  3. 固定版本 - 在环境配置面板中为某些包添加版本约束，如 选择环境中所述。对具有许多可能版本的包（如 python ）以及具有复杂依赖关系图的包（如 scipy）执行此操作最为有效。如果添加某个特定包导致环境变慢，请尝试为该包固定一个版本。
    • 注意事项：添加版本固定可能导致环境无法满足。如果环境初始化失败，请尝试放宽固定版本。例如， python=3.6.10 将仅匹配该版本，但 python=3.6 将匹配 python 3.6.x中的任意一个，因此更有可能被满足。
    • 一种选择是等待您的环境（不带固定版本）完成解析，然后查看选择了哪些版本（参见 查看已解析的环境）。然后您可以为这些特定版本添加固定，直到初始化性能足够快。通常的最佳做法是为具有许多依赖项的包固定版本，而让其他所有包保持不固定。

环境初始化失败

如果您的环境初始化失败，您可以查看环境启动错误日志，以获取有关问题原因的更多信息。

日志的第一行将显示 Execution failed with non-zero exit code: 后跟一个整数错误代码。此错误代码指示具体的故障模式。

代码 1 - 环境解析错误

此错误表示指定的包（和/或其依赖项）中有一部分不兼容或无法安装。如果环境配置面板中的最近更改导致初始化开始失败，请尝试还原该更改。以下是常见环境解析错误的列表。

新的 Mamba 错误消息

Palantir 贡献 ↗ 通过提供格式更佳的环境初始化错误消息，为开源 Mamba 社区做出了贡献。自 2023 年 2 月起，Foundry 服务受益于能更准确地反映环境失败所违反的依赖关系树的错误消息。

有关理解这些新消息、如何解读它们以及如何修复它们的指导，请参见 新的错误消息.

旧版 Mamba 错误消息

以下列出了在引入 新的 Mamba 错误消息 之前旧版错误消息中的常见错误消息列表。

未找到包

在这种情况下，没有任何已配置的渠道提供该包 A 依赖项。

1
Problem: nothing provides requested A.a.a.a

如果您的包的固定版本不存在，则可能会发生这种情况。如果是这种情况，请尝试放宽或移除包的版本限制，在 meta.yml中；例如， matplotlib 1.1.1 可以改为 matplotlib。或者，这也可能意味着环境管理器无法找到安装指定版本所需的包。

未找到依赖项

在这种情况下，包 A 包含一个必需的依赖项 B ，但没有任何渠道提供该依赖项。

Copied!
1
Problem: nothing provides B-b.b.b needed by A-a.a.a:

B 可以是用户明确请求的包（在 meta.yml/foundry-ml/vector 配置文件中），也可以是一个传递依赖项。

如果 B 在您的租户中不可用于安装，则可能会发生这种情况；例如， B 可能已被撤回，因此无法安装。

如果是这种情况，请尝试移除 A 的固定版本，以防存在一个 A 版本，其所有依赖项均可用；或者联系您的 Palantir 代表，将所需的包导入 Foundry。

修复代码 1 错误

要修复环境故障，请考虑以下步骤：

  1. 检查环境启动日志中的 STDOUT 。
  2. 创建一个失败求解的最小示例。不断移除包，直到环境初始化成功，然后再逐个添加包，直到确定哪些包是阻碍因素。
  3. 尝试通过移除包固定来放宽约束。
    • 您可以在不同的窗口中打开多个工作簿或同一工作簿的多个分支，以加快此过程。
    • 我们建议使用二分法来发现问题。在一个工作簿中尝试移除所有约束，在另一个工作簿中移除一半约束，再在另一个工作簿中移除另一半约束，依此类推。

代码 137 - 模块内存不足

此错误通常表示环境初始化所需的内存超过了 Spark 模块上可用的内存。如果环境配置面板中的最近更改导致初始化开始失败，请尝试还原该更改。否则，请尝试以下一个或多个建议：

  • 从环境中移除不需要的包。内存使用量随环境中包的数量呈超线性增长，因此即使只移除几个包也可能足以解决问题。
  • 按照 环境初始化缓慢 部分的步骤 3 所述，为某些包添加版本约束。您固定的每个包版本都会降低环境求解的复杂度，从而减少初始化环境所需的内存量。

如果在移除所有不需要的包并将一些剩余的包固定到特定版本后，您的环境仍然无法初始化，请联系您的 Palantir 代表，并提供您尝试过的所有调试步骤的详细信息。

其他代码

如果您的环境初始化失败并出现上述列表中未列出的错误代码，并且重试后环境再次失败，请联系您的 Palantir 代表，并提供错误日志的完整文本。

默认环境初始化速度不一致

我们预计默认配置文件的初始化有时会很快，有时则需要较长时间。在后一种情况下，您需要等待 Mamba 解析您的环境规范并将其安装到支撑您 Workbook 的 Spark 模块上。这是默认行为。在前一种情况下，要么您获得的是预初始化的模块，要么您的环境规范与缓存中已解析的环境相匹配，可以立即安装。如果许多用户在大致相同的时间打开 Workbook，则您获得预初始化模块的可能性较低，需要等待新模块启动。

需要同时使用 Conda 包和 JAR 的包

某些软件包需要同时具备 Conda 包和 JAR 才能使用。一个常见的例子是 graphframes 包。此类软件包需要特殊的设置流程，如果该软件包此前未在您的实例中进行配置，您可能会在构建时遇到以下错误：

Copied!
1
o257.loadClass.: java.lang.ClassNotFoundException:<Class>

可以将 JAR 文件添加到配置文件的配置中，位置在 高级 控制面板中 Conda 环境配置选项卡的相应部分（参见 配置 Code Workbook 配置文件）。如果您在配置此类软件包时需要帮助，请联系您的 Palantir 代表。
