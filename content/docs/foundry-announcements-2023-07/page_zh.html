Python 版本弃用

发布日期：2023-07-27

遵循开源 Python 的 EOL 时间线，Foundry 正在弃用 Python 3.6 和 3.7。代码仓库中将尝试自动升级，代码工作簿和较旧的 foundry_ml 模型需要手动操作。从 Python 3.8 开始，将严格遵循上游 EOL 弃用时间线。

请查阅 Python 版本部分 查看文档中支持哪些版本及其各自的弃用时间线。我们建议您始终将资源保持在最新支持的版本上。

为什么要弃用 Python 3.6 和 3.7？

开源 Python 每年都会将旧版本标记为 生命周期结束（EOL）↗ 并停止官方支持。Python 3.6 和 3.7 已过其 EOL，继续使用 EOL 的 Python 版本会带来安全风险，此外还需考虑以下事项：

  • PySpark 等核心包正在硬性弃用较旧的 Python 版本（例如，Spark 中对 Python 3.6 和 3.7 的弃用），我们无法为使用已弃用 Python 版本的 Python 作业提供运行时改进或错误修复。
  • 开源库持续发布新版本，这些新版本不再兼容已弃用的 Python 版本，导致检查和作业失败。

弃用对我作为用户意味着什么？

如果您拥有使用已弃用 Python 版本的资源，根据以下时间线，您将无法在这些资源上进行开发：

  • 2024 年 1 月 31 日
    • 如果您的任何工作流依赖于已弃用的 Python 版本，部分工作流将不再受支持，且在出现故障时您将无法获得支持。如果事先与 Palantir 达成一致，少量资源可以被加入白名单以获得延长支持
  • 2024 年 4 月 1 日
    • 所有依赖 Python 3.6 和 3.7 的工作流将不再受支持，并将开始失败。

将 Foundry 资源迁移到受支持的 Python 版本

Foundry 资源迁移将遵循以下模式：

  • 代码仓库：将以自动补丁 PR 的形式尝试自动升级。
  • 其他资源：将显示包含说明和链接的信息横幅，以帮助您脱离已弃用的 Python 版本。请查看 故障排除指南 的文档以获取更多信息。

目前，平台支持的最新版本是 Python 3.10。。Python 3.8。 和 3.9.* 也可接受，但它们将比 3.10.* 更早被弃用

未来的 Python 版本弃用

从 Python 3.8 开始，Foundry 将严格遵循上游生命周期结束时间线，并在 Python 版本达到上游生命周期结束时立即在 Foundry 中将其弃用。更多信息请参阅 Python 版本 文档中的相关内容。

对象上的 Functions 中引入 Foundry 模型 [正式发布]

发布日期：2023-07-20

您现在可以在对象上的 Functions 中调用模型（通过 FoundryML 实时部署提供服务），从而扩大了模型在本体论上下文中的执行范围，这些模型可在 Workshop 以及 Palantir Foundry 的其他地方使用。模型函数可以在任何使用普通函数的地方被调用。

您现在可以做什么

  • 复杂的本体论映射： 借助函数的强大功能，用户现在可以设置关联、创建对象，甚至放宽目标绑定 UI 中模型输入与输出之间存在的 1:1 约束。
  • 模型作为操作： 由 'OntologyEditFunction' 支撑的操作现在可以调用模型。这些操作既可以直接应用于主本体论，也可以应用于某个情景（Scenario），然后再合并回去。
  • 模型作为基本函数： 不影响本体论而是直接驱动可视化的模型，现在可以轻松集成到返回 Workshop 特定数据类型的对象上的 Functions 中。此功能可提升性能，并避免涉及情景（Scenario）的不必要设置。
  • 最后一刻的特征工程： 函数可以执行对象搜索和聚合，从而在到达模型之前完成特征构建。

要求

要启用此工作流程，您必须先从 FoundryML 实时部署的配置页面为其配置 API 名称，并满足以下要求：

  • 最低 Apollo 产品版本：

    1. functions-typescript-asset-bundle: >= 0.442.0
    2. functions-parent-template-bundle: >= 3.5.0

  • 最低 gradle.properties 版本：

    1. functionsTypescriptVersion >= 0.442.0
    2. functionsVersion: >= 3.5.0

模型上的 Functions 如何工作

该工作流程始于保存在 Foundry 中的模型。用户将其提交到建模目标，并通过 Foundry ML Live 进行部署。

函数仓库新增了一个导入 Foundry ML Live 部署的选项，类似于本体论导入对话框。这会注册模型部署，并允许 Code Assist 为导入的 Foundry ML Live 部署自动生成 TypeScript 绑定，这些绑定可以使用部署的 API 名称进行导入。

代码中提供的接口包含一个 transform() 方法，该方法会调用 Foundry ML Live。建模函数可以利用新的 Model Asset 原语来提供一个类型化的 transform() 以反映模型的输入和输出。请参阅下方了解预期的导入工作流程和示例代码：

如果我已经在使用模型上的函数，该怎么办？

推出资源管理数据导出功能

发布日期：2023-07-20

资源管理管理员现在可以从 Control Panel 将资源管理数据导出到 Foundry 数据集，从而能够在 Contour 等 Foundry 工具中对使用数据进行自定义调查和分析。

要从 Control Panel 导出您的数据，请导航至 内部数据集导出 并将您的细粒度使用数据导出到新数据集。该数据集导出后，将保持与上游数据源的同步更新。与审计日志一样，敏感数据集导出后，请确保为相应数据集设置适当的权限。

导航至 内部数据集导出以导出 来自 Control Panel 的资源管理数据。

RMA 数据的 schema 如下：

  • enrollment：导出使用数据所来自的注册（enrollment）。此列将包含单个注册的 RID。
  • invoiced_dimension：此行使用数据所属的计费维度，如注册合同中所规定。
  • source：特定行使用数据所属的来源。
  • summary_resource_rid：细粒度使用数据的父级。对于数据集，这是保存该数据集的项目（Project）；对于本体论对象，这是本体论的 RID。
  • granular_resource_rid：此使用数据所属的资源。
  • date：此使用数据被消耗的日期。
  • usage：消耗的使用量。
  • usage_unit：使用量的单位。对于存储，单位为 GB-月；对于计算，单位为计算秒数。

有关更多信息，请参阅 内部数据集导出 文档。

推出容器支持的模型 [GA]

发布日期：2023-07-18

容器支持的模型的推出使您能够配置由容器镜像支持的模型，显著扩展了可在 Foundry 中用于批量或实时推理的模型范围。您现在可以将任意执行逻辑打包到容器镜像中，并在 Foundry 中使用该模型进行评估、推理以及与运营应用程序的集成。容器支持的 Model Asset 对于大型预训练模型、使用 Foundry Models 原生不支持的语言（如 R）编写的模型，或已出于其他目的容器化的模型特别有用。

容器支持的模型的主要特性

  1. 灵活性：容器可以配置为支持广泛的机器学习框架、自定义代码和语言。
  2. 建模版本控制：容器支持的模型可以打包为模型版本（Model Version），从而允许在 Foundry 中对模型进行独立的评估、审查和发布。
  3. GPU 支持：容器支持的模型可以配置为在 Foundry 中访问一系列 GPU 来执行推理和运行。
  4. 媒体：容器支撑的模型可以访问表格和媒体数据，从而能够在 Foundry 中原生配置计算机视觉、音频和视频工作流。

如何配置容器支撑的模型

  1. 在控制面板中启用 容器工作流.
  2. 创建模型资产并 推送您的容器镜像 到该资产。
  3. 作者 模型适配器 与您的容器进行交互。
  4. 配置模型版本 使用容器镜像和模型适配器。
  5. 部署您的容器支撑模型 and 将其与运营应用程序集成.

有关容器支撑模型的更多信息（包括如何创建、部署和管理它们的详细说明），请参阅我们的 文档.

时间序列全新工作流和 UI 介绍

发布日期：2023-07-18

Foundry 中的时间序列设置工作流涵盖多个阶段：将数据转换为正确的形状、构建强大的本体论以丰富分析，以及创建分析和运营应用程序以做出关键业务决策。时间序列设置流程现在提供操作指引和更新的用户界面，使 Foundry 的新老用户都能更轻松地使用。

时间序列工作流探索操作指引

数据集预览、本体论管理器和管道构建器中现已提供新的操作指引。这些实用的指南介绍了相关概念和工作流，您可以通过阅读来进一步了解如何在 Foundry 中使用时间序列数据。

在数据集预览中，您可以选择对流式或批处理数据集“分析数据”，并打开操作指引以了解时间序列工作流的关键概念和设置要求。

在本体论管理器中，新的操作指引可帮助您创建或选择时间序列对象类型并完成时间序列属性的设置。这些操作指引包含展示 Foundry 中时间序列数据架构和用法的可视化示例。

改进的时间序列管理界面

本体论管理器中更新的用户界面允许您直接从“功能”选项卡创建和管理时间序列属性。您可以在此处关联现有管道中的时间序列同步，或构建新管道来创建时间序列同步。

此外，Pipeline Builder 现在完全支持从流式或批处理时间序列数据创建时间序列输出。 了解有关 Pipeline Builder 输出的更多信息.

如需了解更新后的工作流程和新功能，请导航至 时间序列文档。已对以下内容进行更新： 关键概念 和 端到端设置流程，从数据到分析。

开发路线图上有哪些内容？

作为让 Palantir 的时间序列产品成为制造、自动化和流程管理领域行业领导者这一目标的一部分，我们持续投资于让整个使用过程直观轻松的关键领域。以下功能目前正在开发中：

  • 创建分类时间序列：在平台各处以 Workshop、Object Explorer 和 Quiver 可视化分类时间序列属性，近期重点是在 Workshop 的指标卡片和对象表格中增加对分类时间序列的支持。
  • 度量概念改进：度量概念将仅作为本体论设置上的区分，为最终用户提供统一的体验，使其在分析和运营应用中访问时间序列属性时，无论这些属性是直接位于根对象类型上，还是位于关联的传感器对象上（例如，通过度量），都能获得一致的体验。

  • 分支创建： 您现在可以在对本体论进行所需更改后选择保存来创建包含这些更改的分支，或者在做出任何更改之前选择创建分支。

  • 提案概览： 提案概览页面集中展示提案的高层级信息，例如描述、阶段、审阅者以及与本体论更改相关的任务。概览页面也是编辑提案、添加审阅者、审阅待处理任务以及将提案推进到下一阶段的起点。

  • 审阅提案： 审阅者可以选择批准或拒绝更改，并添加评论以支持其审阅。

  • 发布提案： 当所有更改都经过审阅并批准后，您或您的协作者可以选择将更改保存到本体论中。

从控制面板启用本体论提案

可以为所有私有本体论以及所有不存在多组织协作的默认本体论启用提案。要启用本体论提案，请访问控制面板中的本体论设置选项卡，并为您的组织开启 本体论提案 。

有关更多信息和使用指南，请参阅 本体论分支 （位于公开文档中）。

在 Quiver 中引入 AIP [Beta]

发布日期：2023-07-06

AIP 现已在 Quiver 中可用，使各种经验水平的新老应用构建者、数据分析师和领域专家都能通过自然语言提示轻松探索数据。AIP 与 Quiver 的功能相集成，可以推断卡片及其配置，以构建有意义的图表。

Quiver 中的 AIP 可以帮助：

  • 通过生成支撑答案的分析来回答业务和分析问题
  • 配置输出可视化（布局、颜色、方向、标题等） 学习如何使用 Quiver 应用程序 凭借其广泛而强大的数据转换、可视化和仪表板功能套件

您可以查看 AIP 的建议、审阅其背后的依据，然后接受或拒绝这些建议。只需点击一个按钮，您就可以灵活轻松地转换您的分析。

更快地生成分析并获得洞察

现在，使用 AIP 在 Quiver 中回答业务和分析问题比以往任何时候都更快。用户只需向 Quiver 提出自然语言问题即可生成分析，例如：

  • 2020-2022 年期间，亚特兰大和德克萨斯州按收入排名靠前的零售商有哪些？
  • 2022 年 A 公司和 B 公司的营销支出总额是多少？各公司分别是多少？
  • 每个零售商在每个广告渠道的营销支出总和是多少？

（以下演示截图展示的是示例数据）

AIP 使用大型语言模型 (LLM) 解析用户的问题，然后构建相应的 Quiver 图表，并附上有用的说明，解释为什么选择了特定卡片以及这些卡片如何根据相应的提示进行配置。

然后，Quiver 用户可以将生成的图表一次性添加到分析画布中，进一步修改或最终确定每个卡片的配置或可视化。

通过描述所需输出来配置可视化

Quiver 用户现在无需了解每张 Quiver 卡片提供的可视化设置，即可获得完美的可视化效果。AIP 让更新卡片配置变得轻而易举，因为用户可以向 AIP 描述配置，例如：

  • “将图例移到底部，并将样式更改为分组”。
  • “将指标更改为销售额总和，并将 y 轴标题更新为 Total Sales".

对于每个命令，AIP 都会返回卡片配置建议——并附有每条建议的生成原因说明——用户可以接受或拒绝这些建议。

目前，Quiver 中的 AIP 仅支持对象集和对象卡片。受支持的卡片带有 "AIP Support" 标签。

AIP 缩短了新老 Quiver 用户实现价值的时间，只需一个用户命令即可将 Quiver 的全部高级功能展现出来。这些新功能代表了 AIP 增强 Quiver 分析的令人兴奋的方式的开端，更多功能即将推出。

有关更多信息，请参阅文档 Quiver 的 AIP 功能.
