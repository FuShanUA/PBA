Python 版本弃用

发布日期：2023-07-27

遵循开源 Python 的生命周期结束（EOL）时间线，Foundry 正在弃用 Python 3.6 和 3.7。系统将尝试对代码仓库进行自动升级，但 Code Workbook 和较早的 foundry_ml 模型需要手动操作。从 Python 3.8 开始，将严格遵循上游的 EOL 弃用时间线。

请查看文档中的 Python 版本部分 ，以了解支持哪些版本及其各自的弃用时间表。我们建议您始终将资源保持在最新支持的版本上。

为什么要弃用 Python 3.6 和 3.7？

开源 Python 每年都会将旧版本 Python 标记为 生命周期结束（EOL）↗ 并停止官方支持。Python 3.6 和 3.7 已超过其 EOL 期限，继续使用已 EOL 的 Python 版本会带来安全风险，此外还需考虑以下几点：

  • PySpark 等核心软件包正在强制弃用较旧的 Python 版本（例如 Spark 中对 Python 3.6 和 3.7 的弃用），我们无法为使用已弃用 Python 版本的 Python 作业提供运行时改进或错误修复。
  • 开源库会不断发布新版本，而这些新版本与这些已弃用的 Python 版本不再兼容，从而导致检查和作业失败。

作为用户，弃用对我而言意味着什么？

如果您拥有的资源使用了已弃用的 Python 版本，根据以下时间线，您将无法在这些资源上进行开发：

  • 2024年1月31日
    • 如果您的任何工作流依赖于已弃用的 Python 版本，某些工作流将不再受支持，并且在出现故障时您将无法获得任何支持。如果事先与 Palantir 达成一致，可将有限的一组资源加入白名单以获得延长支持
  • 2024年4月1日
    • 所有依赖 Python 3.6 和 3.7 的工作流将不再受支持，并将开始失败。

将 Foundry 资源迁移至受支持的 Python 版本

Foundry 资源迁移将遵循以下模式：

  • 代码仓库：将尝试以自动补丁 PR 的形式进行自动升级。
  • 其他资源：将显示包含说明和链接的信息横幅，以帮助您从已弃用的 Python 版本迁移。请查阅 故障排除指南 以了解更多信息。

目前，平台支持的最新版本是 Python 3.10。。Python 3.8。 和 3.9.* 也被接受，不过它们将比 3.10.* 更早被弃用

未来 Python 版本弃用

从 Python 3.8 开始，Foundry 将紧密遵循上游的生命周期终止时间表，并在 Python 版本达到上游生命周期终止时立即在 Foundry 中弃用相应版本。如需更多信息，请参阅 Python 版本 （见文档）。

在对象上的函数中引入 Foundry 模型 [GA]

发布日期：2023-07-20

您现在可以在对象上的函数中调用模型（由 FoundryML 实时部署提供服务），从而扩大了模型在本体论上下文中执行、以及在 Workshop 和 Palantir Foundry 其他位置使用的范围。基于模型的函数可以在任何使用普通函数的地方使用。

您现在可以做什么

  • 复杂本体论映射： 借助函数的强大功能，用户现在可以设置关联、创建对象，甚至放宽 Objective 绑定 UI 中存在的模型输入与输出之间 1:1 的约束。
  • 将模型用作操作： 由 'OntologyEditFunction' 支撑的操作现在可以调用模型。这些操作既可以直接应用于主本体论，也可以先应用于某个 Scenario，然后再合并回去。
  • 将模型用作基本函数： 不影响本体论而是直接驱动可视化的模型，现在可以轻松集成到返回 Workshop 特定数据类型的对象上的函数中。这一能力可以提升性能，并避免涉及 Scenario 的不必要设置。
  • 最后一刻的特征工程： 函数可以执行对象搜索和聚合，从而能够在到达模型之前进行特征构建。

要求

要启用此工作流，您必须先在其配置页面中为您的 FoundryML 实时部署配置 API 名称，并满足以下要求：

  • Apollo 产品最低版本：

    1. functions-typescript-asset-bundle: >= 0.442.0
    2. functions-parent-template-bundle: >= 3.5.0

  • gradle.properties 最低版本：

    1. functionsTypescriptVersion >= 0.442.0
    2. functionsVersion: >= 3.5.0

模型函数的工作原理

该工作流以保存在 Foundry 中的模型开始。用户将其提交到建模目标，然后通过 Foundry ML Live 进行部署。

函数仓库新增了一个导入 Foundry ML Live 部署的选项，类似于本体论导入对话框。这会注册模型部署，并允许 Code Assist 为导入的 Foundry ML Live 部署自动生成 typescript 绑定，之后可以使用部署的 API 名称导入这些绑定。

代码中提供的接口包含一个 transform() 方法，该方法会调用 Foundry ML Live。建模函数可以利用新的 Model Asset 原语来提供类型化的 transform() ，以反映模型的输入和输出。请参阅下面的预期导入工作流和示例代码：

如果我已经在使用模型函数，该怎么办？

对于已在使用模型上的函数的用户，如果您选择升级仓库，此 GA 版本包含破坏性变更。我们建议所有用户迁移旧仓库，这是一个相当简单的过程：

  1. 为您的 ML Live 部署定义 API 名称
  2. 在您的函数仓库中创建一个新分支

推出资源管理数据导出功能

发布日期：2023-07-20

资源管理管理员现在可以从 Control Panel 将资源管理数据导出到 Foundry 数据集，从而能够在 Contour 等 Foundry 工具中对使用数据进行自定义调查和分析。

要从 Control Panel 导出您的数据，请导航至 内部数据集导出 并将您的细粒度使用数据导出到新数据集。该数据集导出后，将与上游数据源保持同步更新。与审计日志一样，敏感数据集一经导出，请确保对相应数据集进行适当的权限设置。

导航至 内部数据集导出以导出 来自 Control Panel 的资源管理数据。

RMA 数据的结构如下：

  • enrollment：导出用量数据所对应的注册。此列将包含单个注册 RID。
  • invoiced_dimension：此用量行所属的计费维度，如注册合同中所规定。
  • source：特定用量行所属的源。
  • summary_resource_rid：细粒度用量的父级。对于数据集，这是保存该数据集的项目；对于本体论对象，这是本体论 RID。
  • granular_resource_rid：此用量所属的资源。
  • date：消耗该用量的日期。
  • usage：已消耗的用量。
  • usage_unit：用量单位。对于存储，单位为 GB-月；对于计算，单位为计算秒。

如需了解更多信息，请参阅 内部数据集导出 文档。

推出基于容器的模型 [GA]

发布日期：2023-07-18

容器支撑模型的引入使您能够配置由容器镜像支撑的模型,显著扩展了可在 Foundry 中用于批量或实时推理的模型范围。您现在能够将任意执行逻辑打包到容器镜像中,并在 Foundry 中使用该模型进行评估、推理,以及与运营应用程序集成。容器支撑的模型资产对于大型预训练模型、使用 Foundry 模型原生不支持的语言(例如 R)编写的模型,或已出于其他目的进行容器化的模型尤其有用。

容器支撑模型的主要特性

  1. 灵活性:容器可以配置为支持各种机器学习框架、自定义代码和语言。
  2. 模型版本管理:容器支撑模型可以打包为模型版本,从而允许在 Foundry 中对模型进行独立的评估、审查和发布。
  3. GPU 支持:容器支撑模型可以配置为在 Foundry 中执行,并可访问多种 GPU 以进行推理和执行。
  4. 媒体:容器支撑模型可以访问表格数据和媒体数据,从而能够在 Foundry 中原生配置计算机视觉、音频和视频工作流。

如何配置容器支撑模型

  1. 启用 控制面板中的容器工作流。
  2. 创建模型资产并 推送您的容器镜像 到其中。
  3. 编写 模型适配器 以与您的容器交互。
  4. 配置模型版本 ，为其指定容器镜像和模型适配器。
  5. 部署您的容器支撑模型 并 将其与运营应用程序集成。

有关容器支撑模型的更多信息（包括如何创建、部署和管理此类模型的详细说明），请参阅我们的 文档。

推出适用于时间序列的更新版工作流和 UI

Foundry 中的时间序列设置工作流跨越多个阶段，用于将数据转换为正确的格式、构建强大的本体论以丰富分析，并创建分析和运营应用程序来做出关键业务决策。时间序列设置流程现提供分步指南和更新后的用户界面，使 Foundry 的新老用户都能更轻松地使用。

用于探索时间序列工作流的分步指南

在本体论管理器中，新的分步指南可帮助您创建或选择时间序列对象类型，并完成时间序列属性的设置。这些分步指南包含直观的示例，展示了 Foundry 中时间序列数据的架构和用法。

改进后的时间序列管理界面

本体论管理器中更新后的用户界面让您能够直接在“功能”选项卡中创建和管理时间序列属性。您可以在这里关联现有管道中的时间序列同步，也可以构建新管道来创建时间序列同步。

此外，管道构建器现在完全支持基于流式或批量时间序列数据创建时间序列输出。 了解有关管道构建器输出的更多信息.

如需了解更新后的工作流和新功能，请导航至 时间序列文档。我们已更新了 关键概念 和 端到端设置流程，涵盖从数据到分析的完整过程。

开发路线图上有哪些内容？

为了实现让 Palantir 的时间序列产品成为制造、自动化和流程管理领域行业领导者的目标，我们持续投资于让整个使用过程直观而轻松的关键领域。以下功能目前正在开发中：

  • 创建分类时间序列:在 Workshop、Object Explorer 和 Quiver 中跨平台可视化分类时间序列属性,近期重点是在 Workshop 的指标卡片和对象表格中添加对分类时间序列的支持。

  • 分支创建： 现在，您可以在完成所需的本体论更改后选择“保存”来创建包含这些更改的分支，也可以在进行任何更改之前选择“创建分支”。

  • 提案概览： 提案概览页面集中展示了提案的概要信息，例如描述、阶段、审阅者以及与本体论更改相关的任务。概览页面也是编辑提案、添加审阅者、审阅待处理任务以及将提案推进到后续阶段的起点。

  • 审阅提案： 审阅者可以选择批准或拒绝更改，并添加评论以支持其审阅。

  • 发布提案： 当所有更改都经过审核和批准后，您或您的协作者可以选择将更改保存到本体论中。

从控制面板启用本体论提案

可以为所有私有本体论以及所有未在多个组织之间开展协作的默认本体论启用提案。要启用本体论提案，请访问控制面板中的“本体论设置”选项卡，并开启 “本体论提案” （为您的组织）。

如需更多信息和使用指南，请参阅 “本体论分支” （见公开文档）。

在 Quiver 中引入 AIP [Beta]

发布日期：2023-07-06

AIP 现已在 Quiver 中可用，让新老应用程序构建者、数据分析师以及各种经验水平的专业领域专家都能通过自然语言提示轻松探索数据。AIP 与 Quiver 的功能深度集成，能够推断卡片及其配置，以构建有意义的图形。

Quiver 中的 AIP 可以帮助：

  • 通过生成支持答案的分析来回答业务和分析问题
  • 配置输出可视化（布局、颜色、方向、标题等） 学习如何使用 Quiver 应用程序 凭借其丰富而强大的数据转换、可视化和仪表板功能套件

您可以查看 AIP 的建议、审阅其背后的依据，然后选择接受或拒绝。只需一键点击，您就能灵活轻松地转换您的分析。

更快地生成分析并获取洞察

借助 AIP，在 Quiver 中回答业务和分析问题的速度比以往任何时候都快。用户只需向 Quiver 提出自然语言问题即可生成分析，例如：

  • 2020 年至 2022 年期间，亚特兰大和德克萨斯州收入最高的零售商有哪些？
  • 2022 年 A 公司和 B 公司的营销支出总额是多少？各公司分别是多少？
  • 各零售商在每个广告渠道上的营销支出总和是多少？

（以下演示截图所示为虚拟数据）

AIP 使用大语言模型（LLM）解析用户的提问，进而构建出相应的 Quiver 图表，并附上有用的说明，解释为何选择了特定卡片，以及这些卡片如何根据相应提示进行配置。

Quiver 用户随后可以将生成的图表一次性添加到分析画布中，以便进一步修改或最终确定每张卡片的配置或可视化效果。

通过描述所需输出结果来配置可视化

Quiver 用户现在无需了解每张 Quiver 卡片提供的可视化设置，即可获得完美的可视化效果。AIP 让更新卡片配置变得轻而易举，因为用户只需向 AIP 描述所需的配置，例如：

  • “将图例移至底部，并将样式更改为分组”。
  • “将指标更改为销售额总和，并将 y 轴标题更新为 Total Sales".

对于每条指令，AIP 都会返回卡片配置建议——并附有关于为何提出每条建议的说明——用户可以接受或拒绝这些建议。

目前，Quiver 中的 AIP 仅支持对象集和对象卡片。受支持的卡片带有“AIP 支持”标签。

AIP 可缩短新老 Quiver 用户实现价值的时间，只需一条用户命令即可将 Quiver 的全套高级功能推向前沿。这些新功能标志着 AIP 增强 Quiver 分析的诸多精彩方式的开端，后续还将推出更多功能。

请参阅文档，详细了解 Quiver 的 AIP 功能。
