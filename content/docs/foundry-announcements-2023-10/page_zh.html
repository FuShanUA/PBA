推出本体论清理工具：简化并优化您的本体论

发布日期：2023-10-31

该 本体论清理工具，于 10 月 30 日当周正式可用，旨在让本体论导航更加便捷、提升搜索性能，同时通过识别适合删除的对象类型来优化存储成本。

本体论清理工具为您提供以下功能，帮助您高效管理本体论：

标志

标志可帮助您轻松识别需要关注的对象类型。您可以从预置列表中选择要启用的标志，并为每个标志分配重要级别，从而根据自身特定需求自定义该流程。

自定义标志设置并选择清理配置

操作

本体论清理工具提供三项核心操作，帮助您有效处理已标记的对象类型：

  • 暂缓： 在可配置的时间段内将对象类型暂时从清理队列中隐藏。这样，您可以在弃用或删除之前先审查并评估其相关性。
  • 弃用： 将对象类型标记为弃用，以表明其已过时。此操作为用户提供了过渡期，以便适应替代方案。
  • 删除： 从您的本体论中永久移除已标记的对象类型，释放存储空间，同时提升本体论的整体性能。

已选择要暂缓、弃用或删除的对象类型

保存或提议您的更改

识别出多余的对象类型后，您可以直接标记并将所需更改保存到本体论中，从而确保立即实施清理流程。或者，您也可以创建提案，在进行任何修改之前，促进其他利益相关者参与协作决策和反馈收集。

请参阅 Foundry 上有关 本体论清理工具 的文档，并开始优化您的本体论。

推出 AIP 生成的 Vega 图表

发布日期：2023-10-31

Quiver 让用户能够使用 Vega ↗ 或 Vega-Lite ↗ 库来创建完全可自定义的交互式可视化。然而，以 JSON 格式编写有效的 Vega 图表配置容易出错。我们很高兴地宣布，借助 AIP，现在只需用自然语言描述所需的图表或更改，即可生成 Vega 图表配置。

描述所需的 Vega 图表

要使用 AIP 帮助生成您的 Vega 图表，只需提供提示词并选择 配置。AIP 将给出建议供您审阅。要接受建议，请选择 应用。如果您希望 AIP 给出其他建议，请编辑您的提示词，然后选择 重新配置。

在下面的示例中，AIP 根据提示词建议了一个图表配置，该图表包含感兴趣的两个数值属性：咖啡因含量和 pH 值。

基于给定提示词的 AIP 建议

要接受 AIP 建议的更新，请选择 应用。Vega 图表将根据更新后的 Vega 规范渲染可视化。

AIP Vega 图表配置

在现有图表的基础上进行构建

AIP 可以识别并区分提示词中包含的抽象概念，并利用这些信息帮助生成或修改 Vega 图表。例如，AIP 可以引用先前生成的图表的特征，让您能够“在现有图表的基础上进行构建”。

在下图中，用户提供的提示词为：“图表上的两条线将这些点分成了 4 个象限。为每个象限着不同的颜色”。AIP 识别出由垂直线和水平线定义的区域是象限，尽管当前图表配置中不包含任何象限的定义或配置。

AIP 可以使用包含先前生成图表引用的提示词

AIP 能够准确生成与用户提示词相符的所需图表，该图表是在初始图表的基础上构建的。

AIP 生成的 Vega 图表

使用 AIP Generate 创建 Vega 图表

使用 AIP 生成的 Quiver 分析图表可以包含 Vega 图表。若要让 AIP 生成 Vega 图表而非 Quiver 原生可视化（例如折线图或散点图），请在提示词中明确指出 AIP 应返回“Vega plot”。例如，一个准确的提示词可以是：“Show caffeine vs ph on a scatter plot using a vega plot”。

请查阅 Vega 图表文档。

向 Quiver 引入物化功能

发布日期：2023-10-17

物化 是 Quiver 中的一种新 数据类型 ，为分析师提供了一种大规模转换、可视化和分析本体论数据的方式，能够突破使用转换表时数据连接和转换中存在的 5 万行限制。

具体而言，物化允许您：

  • 对对象数据执行连接（左/右/内/全连接）
  • 派生新列、筛选或聚合对象数据
  • 绘制数据，可使用 分类图表 或 Vega 图

如何使用数据集？

使用 数据集卡片 进行以对象集作为输入的大规模分析，让 Quiver 在后台无缝转换对象集。从对象集出发，使用位于新增的 数据集 后续操作下的任意卡片，或使用 对象集数据集 卡片执行显式转换。

数据集卡片菜单

要了解数据集卡片由哪些支撑数据集基元驱动，只需将鼠标悬停在数据源图标上即可进行追踪。

在数据集卡片中快速将数据追踪到其支撑数据集

用于灵活分析的表达式和连接

除了 Quiver 中新增的数据集卡片之外，您还可以考虑通过以下方式解锁新的功能和工作流：

  • 使用表达式卡片，它类似于 Contour 表达式面板，以派生新列或执行复杂筛选。窗口函数等高级功能可解锁新的分析类型。
  • 使用 Join 卡片对对象数据大规模执行左连接、右连接、内连接和全连接。
  • 将结果与现有的 Quiver 卡片（如转换表格和 Vega 图表）相结合，以支持新的工作流程。

Join datasets 卡片配置示例

选择 AIP Configure 选项*，即可在 Expression 卡片中使用自然语言创建表达式，例如：

  • “通过将两个分数列相乘，计算一个名为‘用户总分’的新列”
  • “针对每个有机类别，通过将两个分数列相乘来计算‘用户总分’”
  • “计算每个有机类别的平均可持续性得分”
  • “将 Organic 列中的值更新为驼峰式”
  • “将两个产品名称列拼接为一列”
  • “计算每个商店每种产品的总收入，同时考虑价格和销售数量”

AIP 窗口中的自然语言提示输入

AIP 生成与自然语言提示匹配的表达式

出站应用程序简介 [GA]

发布日期：2023-10-17

出站应用程序 为管理员提供了一种新方法，用于管理从 Foundry 中构建的工作流到外部系统的 OAuth 2.0 连接。

出站应用程序在组织级别进行管理，表示一组配置，使 Foundry 能够充当 OAuth 2.0 客户端。该应用程序会向另一个系统发出请求，该系统可以充当 OAuth 2.0 服务器。

在 Control Panel 中创建出站应用程序

出站应用程序是在 出站应用程序 中创建的，该页面位于 Control Panel 的 组织设置下。要查看此页面，您必须拥有 管理出站应用程序 工作流的访问权限，该权限默认授予 Organization administrator Control Panel 中的角色。

如果您有权访问多个组织,请务必选择您希望在其中创建出站应用程序的组织。该组织中所有有权在数据连接中设置数据源的用户,都将能够选择任何出站应用程序作为其连接的授权机制。

点击式配置

出站应用程序在设计上专注于简化工作流程。创建和配置新的出站应用程序时,用户将通过直观的分步向导进行操作。用户可根据需要轻松调整设置,并获得针对输入格式的交互式验证。

创建出站应用程序工作流

直接支持云端和本地部署的 OAuth 服务器

要设置可通过互联网访问的出站连接, 直接连接 是推荐的做法。

对于需要非标准令牌握手的 OAuth 服务器, 自定义的基于 Webhook 的握手 通过 REST API 数据源(使用 代理运行时 )同样受支持。此方法需要您自行编写请求来执行 OAuth 2.0 握手。

使用出站应用程序

出站应用程序创建并启用后,即可用作 REST API 数据源中某个域的身份验证方法。配置域时,请选择 OAuth 2.0 然后从下拉菜单中选择所需的出站应用程序。

在 REST API 源中为域设置身份验证方法。

任何使用配置了 OAuth 2.0 的域的 webhook 都会导致每个用户在首次尝试运行时收到交互式提示。Webhook 通常由 Workshop 中的操作触发。运行操作时，系统会提示用户通过登录 OAuth 2.0 服务器，授权 Foundry 代表其与系统进行交互。

提示用户授权 Foundry 与系统进行交互

如果配置了令牌刷新工作流，除非在外部系统中撤销了授权或重置了出站应用程序，否则用户不太可能再次看到此提示。如果未配置刷新工作流，最终用户将在生成的令牌过期时看到身份验证弹出窗口。令牌通常会在几分钟或几小时内过期，我们建议使用刷新流程以获得更好的用户体验。

有关出站应用程序的更多信息，请参阅 文档。

推出模型资产 [GA]

发布日期：2023-10-17

模型资产是将所有机器学习 (ML) 和人工智能 (AI) 模型集成到 Foundry 中的推荐方法。模型资产提供了一种一致的方法，可将模型集成到 Foundry 的 ModelOps 应用程序和建模目标中，并通过 Workshop、Slate、数据转换和模型函数将其直接集成到运营应用程序中。

模型导入图

如何使用模型资产？

您可以通过多种方式创建模型资产，以便在 Foundry 中部署任何模型，包括：

  • 在 Foundry 中使用代码仓库训练的模型
  • 在 Foundry 外部训练并作为非结构化数据集保存到 Foundry 的模型文件
  • 在 Foundry 外部容器化并推送到 Foundry Docker 镜像仓库的模型
  • 在 Foundry 外部训练和托管的模型

模型资产的一致接口使机器学习工程师、数据科学家和项目团队能够轻松地在 Foundry 应用程序中使用模型。团队可以在无需迁移或停机的情况下更新模型权重、架构甚至托管基础设施。Foundry 会自动跟踪和维护数据和模型的血缘关系，从而提供全面的项目历史记录，其中包括所有模型、其性能指标和发布版本。

使用在新的 palantir_models Python SDK 中定义的新 ModelAdaptor 接口，解锁模型资产的所有优势。

Foundry 中的下一代模型

模型资产（使用 palantir_models创作）现已被推荐用于替代数据集模型（使用 foundry_ml创作）。模型资产不仅提供与数据集模型相同的功能，还提供额外功能，包括：

  • 更高的灵活性，使数据科学家能够通过模型适配器定义自定义的模型序列化、反序列化和推理逻辑
  • 通过自动将模型依赖项与模型捆绑在一起来简化依赖项管理，无需共享 Python 库、自定义阶段，也无需在部署时重新解析环境
  • 原生安全的凭据和出口策略，用于连接外部托管的模型
  • 在 Rubix（Palantir 的 Kubernetes 环境）中执行容器化的模型逻辑

流式转换目前正在迁移到 Java 17 [迁移/弃用]

发布日期：2023-10-02

根据 “流式转换向 Java 17 的迁移定于 2023 年 9 月底进行 [迁移/弃用]” 公告，所有流式转换的运行时已开始从 Java 11 迁移至 Java 17，以利用后者在性能和安全性方面的改进。此次迁移将在接下来的一周内逐步推广至所有 Palantir Foundry 租户。

值得注意的是，Java 17 运行时引入了一项破坏性变更，阻止了对 JDK 内部类成员的反射访问。因此，我们已采取措施为所有核心 Flink 功能恢复原有的访问行为，以防止该变更带来不利影响，但以下情况除外：用户编写的代码（例如 Foundry UDF 定义）访问了受限类且尚未修复。如果某个流受到影响，该流的构建将失败，并抛出包含以下消息的异常：

  • java.lang.IllegalAccessException: class <some class name> cannot access class <internal JDK class name> (in module <internal module>) because module <internal module> does not export <internal JDK package> to unnamed module @<module id>.

如果某个流以这种方式失败且是 UDF 转换，请查看上方链接的相关先前公告中的说明，以识别并移除进行非法访问的组件。

如果失败的流不是 UDF 转换，请联系您的 Palantir 管理员，寻求帮助以修复受影响的流。
