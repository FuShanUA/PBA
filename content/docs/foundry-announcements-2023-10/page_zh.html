推出本体论清理工具：简化并优化您的本体论

发布日期：2023-10-31

直方图 本体论清理工具将于10月30日当周正式发布，旨在提高本体论导航和搜索性能的便捷性，同时通过识别适合删除的对象类型来优化存储成本。

本体论清理工具提供以下功能，帮助您高效管理本体论：

标志

标记可帮助您轻松识别需要关注的对象类型。您可以从预置列表中选择要启用的标记，并为每个标记分配重要级别，从而根据您的特定需求自定义流程。

自定义标记设置并选择清理配置

操作

本体论清理工具提供三种基本操作，可有效处理被标记的对象类型：

  • 暂时静音此监控规则的通知。当静音处于活动状态时，在标题中会出现指示器。 在可配置的时间段内，将对象类型暂时从清理队列中隐藏。这样，您可以在弃用或删除它们之前，先审查并评估其相关性。
  • 弃用： 将对象类型标记为已弃用，以表明其已过时。此操作为用户提供了一个过渡期，以便适应替代选项。
  • 删除： 从本体论中永久移除被标记的对象类型，释放存储空间，同时提升本体论的整体性能。

已选择暂停、弃用或删除的对象类型

保存或提议您的更改

在识别出多余的对象类型后，您可以直接将所需的更改标记并保存到本体论中，确保清理流程立即生效。或者，您也可以创建提议，在进行任何修改之前，促进与其他利益相关者的协作决策和反馈收集流程。

请参阅 Foundry 文档中的 本体论清理工具 ，并开始优化您的本体论。

Quiver 推出物化功能

发布日期：2023-10-17

物化 是一项新的 在卡片之间的变化 Quiver 中的功能，为分析师提供了一种大规模转换、可视化和分析本体论数据的方式，能够突破使用转换表时数据连接和转换中存在的 5 万行限制。

具体而言，物化功能允许您：

  • 对对象数据执行连接（左/右/内/全）
  • 派生新列、筛选或聚合对象数据
  • 绘制数据时使用 分类图表 or Vega 图

如何使用数据集？

用途 数据集卡片 用于以对象集为输入的大规模分析，让 Quiver 在后台无缝转换对象集。在对象集中，使用位于新的 数据集 后续操作下的任意卡片,或使用 对象集数据集 卡片。

数据集卡片菜单

要了解哪些支撑数据集基元在为数据集卡片提供支持，只需将鼠标悬停在数据源图标上即可追溯。

在数据集卡片中快速追溯数据至其支撑数据集

用于灵活分析的表达式和连接

除了 Quiver 中新增的数据集卡片外，您还可以通过以下方式解锁新的功能和工作流：

  • 使用表达式卡片，类似于 Contour 表达式面板，来派生新列或执行复杂的筛选。窗口函数等高级功能可解锁新的分析类型。
  • 使用连接卡片对对象数据大规模执行左连接、右连接、内连接和全连接。
  • 将结果与现有的 Quiver 卡片（如转换表和 Vega 图表）相结合，以支持新的工作流。

连接数据集卡片配置示例

选择 AIP 配置 选项*，在表达式卡片中使用自然语言创建表达式，例如：

  • “通过将两个得分列相乘，计算一个名为‘总用户得分’的新列”
  • “针对每个有机类别，通过将两个得分列相乘来计算‘总用户得分’”
  • “计算每个有机类别的平均可持续性得分”
  • “将 Organic 列中的值更新为驼峰式大小写”
  • “将两个产品名称列拼接为其中一列”
  • “计算每家商店每种产品的总收入，同时考虑价格和销量”

Outbound 应用程序介绍 [GA]

发布日期：2023-10-17

Outbound 应用程序 为管理员提供了一种新方法，用于管理从 Foundry 中构建的工作流到外部系统的 OAuth 2.0 连接。

在组织级别管理，出站应用程序表示 Foundry 作为 OAuth 2.0 客户端运行所需的一组配置。该应用程序向另一个可作为 OAuth 2.0 服务器.

在 Control Panel 中创建出站应用程序

出站应用程序在 Outbound 应用程序 中的 Control Panel 内创建，位于 组织设置下。要查看此页面，您必须拥有 管理出站应用程序 工作流的访问权限，该权限默认授予 Control Panel 中的 Organization administrator 角色。

如果您有权访问多个组织，请务必选择您希望在其中创建出站应用程序的组织。该组织中所有有权在 Data Connection 中设置数据源的用户都将能够选择任何出站应用程序作为其连接的授权机制。

点击式配置

Outbound 应用程序的构建以简化工作流为重点。要创建和配置新的出站应用程序，用户需与直观的分步向导进行交互。设置可以根据需要轻松调整，并且用户会收到针对输入格式的交互式验证。

创建出站应用程序工作流

直接支持云端和本地 OAuth 服务器

要设置可通过互联网访问的出站连接， 直接连接 是推荐的做法。

对于需要非标准令牌握手的 OAuth 服务器， 基于自定义 webhook 的握手 通过 REST API 使用 代理运行时 的源也受支持。此方法需要自行编写请求来执行 OAuth 2.0 握手。

使用出站应用程序

创建并启用出站应用程序后，可将其用作 REST API 源中某个域的身份验证方法。配置域时，选择 OAuth 2.0 ，然后从下拉列表中选择所需的出站应用程序。

为 REST API 源中的域设置身份验证方法。

任何使用配置了 OAuth 2.0 的域的 webhook 都会在每个用户首次尝试运行时触发交互式提示。Webhook 通常由 Workshop 中的操作触发。运行操作时，系统会提示用户登录 OAuth 2.0 服务器，以授权 Foundry 代表其与系统进行交互。

提示用户授权 Foundry 与系统进行交互

模型资产简介 [GA]

发布日期：2023-10-17

模型资产是将所有机器学习 (ML) 和人工智能 (AI) 模型集成到 Foundry 中的推荐方法。模型资产提供了一种一致的方法，可将模型集成到 Foundry 的 ModelOps 应用程序、建模目标中，并通过 Workshop、Slate、数据转换和模型函数直接集成到运营应用程序中。

模型导入示意图

如何使用模型资产？

您可以通过多种方式创建模型资产，以便在 Foundry 中部署任何模型，包括：

  • 在 Foundry 中使用 Code Repositories 训练的模型
  • 在 Foundry 之外训练并作为非结构化数据集保存到 Foundry 的模型文件
  • 在 Foundry 之外容器化并推送到 Foundry docker 注册表的模型
  • 在 Foundry 之外训练和托管的模型

模型资产的一致接口使机器学习工程师、数据科学家和项目团队能够轻松地在 Foundry 应用程序中使用模型。团队可以更新模型权重、架构甚至托管基础设施，而无需迁移或停机。Foundry 会自动跟踪和维护数据和模型的血缘关系，提供包含所有模型、其性能指标和发布版本的完整项目历史记录。

使用新的 palantir_models Python SDK 中定义的新 ModelAdaptor 接口，以解锁模型资产的所有优势。

Foundry 中的下一代模型

模型资产（使用 palantir_models创作）现在被推荐用于替代数据集模型（使用 foundry_ml创作）。模型资产不仅提供与数据集模型相同的功能，还提供其他特性，包括：

  • 更高的灵活性，使数据科学家能够通过模型适配器定义自定义的模型序列化、反序列化和推理逻辑
  • 简化的依赖管理，自动将模型依赖与模型捆绑在一起，无需共享 Python 库、自定义阶段以及在部署时重新解析环境
  • 为连接外部托管的模型提供原生安全的凭据和出口策略
  • 在 Rubix（Palantir 的 Kubernetes 环境）中执行容器化的模型逻辑
  • 支持多输入和多输出模型转换

要开始使用模型资产，请查看更新后的 模型训练教程，以及以下补充文档：

流式转换现在正在迁移到 Java 17 [迁移/弃用]

发布日期：2023-10-02

根据 “流式转换迁移到 Java 17 计划于 2023 年 9 月底完成 [迁移/弃用]” 公告，所有流式转换开始将其运行时从 Java 11 迁移到 Java 17，以利用后者在性能和安全性方面的改进。此次迁移将在未来一周内逐步推广到所有 Palantir Foundry 租户。

值得注意的是，Java 17 运行时引入了一项重大变更，阻止对 JDK 内部类成员的反射访问。因此，我们已采取措施为所有核心 Flink 功能恢复旧的访问行为，以避免此变更造成不利影响，但用户编写的代码（例如 Foundry UDF 定义）访问受限类且尚未修复的情况除外。当流受到影响时，流构建将失败并抛出包含以下消息的异常：

  • java.lang.IllegalAccessException: class <some class name> cannot access class <internal JDK class name> (in module <internal module>) because module <internal module> does not export <internal JDK package> to unnamed module @<module id>.

如果流以这种方式失败且是 UDF 转换，请查看上方链接的相关先前公告中的说明，以识别并删除进行非法访问的组件。

如果失败的流不是 UDF 转换，请联系您的 Palantir 管理员以协助修复受影响的流。
