专业代码智能体模板

创建专业代码智能体时，您的代码仓库将由智能体模板生成。该模板附带了简化配置，适用于 Ontology MCP (OMCP)、 Palantir MCP和 Ontology SDK (OSDK)，通用设置由智能体库提供。该模板使您的代码仓库专注于智能体逻辑，而非平台底层设施。

受支持的模板

模板适用于以下智能体框架：

  • Claude Agent SDK： 一个基于 Claude Agent SDK ↗构建的 TypeScript 模板，适用于使用 Claude 模型的智能体。智能体循环由 query 函数驱动，工具通过 MCP 服务器公开。
  • OpenAI Agents SDK： 一个基于 OpenAI Agents SDK ↗构建的 TypeScript 模板，适用于使用 OpenAI 模型的智能体。智能体循环由 Agent 和 run 原语驱动。
  • Google ADK： 一个基于 Google Agent Development Kit (ADK) ↗构建的 TypeScript 模板，适用于使用 Google Gemini 模型的智能体。智能体循环由 Agent 和 InMemoryRunner 原语驱动。Gemini 通过 Foundry 语言模型代理进行路由，因此无需 Google API 密钥。

这些模板共享相同的 项目结构、参数 schema、默认 MCP 配置和发布流程。它们在定义 agent 循环和自定义工具的方式上有所不同。在创建你的 pro-code agent 时，请选择一个模板。除非另有说明，本节中的示例均使用 Claude Agent SDK 模板。

以下各项的默认 MCP 配置： Palantir MCP、 本体论 MCP以及 Python 转换 MCP 由 agent 库提供。你可以使用 MCP 配置函数 来检索它们，相关说明见下文。

要添加你自己的 MCP 配置，请在 agent/下创建一个新文件，例如 agent/mcps/custom.ts，并在 agent 循环中按照与 MCP 配置函数相同的方式对其进行注册。将自定义配置保留在你自己的文件中，可以避免代码仓库升级期间出现冲突。

Palantir MCP 提供用于与平台交互的工具。如需减少 token 用量，您可以启用 工具搜索 功能（适用于 Palantir MCP），以便按需发现工具，而不是一次性全部加载。

自定义您的 pro-code 代理

系统提示词

编辑 agent/systemPrompt.ts 以更改定义 pro-code 代理行为方式的指令。

代理参数

Pro-code 代理可以接受为每次运行提供的参数。请在 AgentArguments schema（位于 agent/index.ts ）中使用 defineInputs定义它们：

export const AgentArguments = defineInputs({
  additionalAgentContext: t.string().optional(),
  // Add your own arguments here

调用代理时会自动接受这些参数，并在将代理发布到 Foundry 时将其注册为输入类型。

import { Agent, run, MCPServer } from "@openai/agents";

export async function runAgent(args: AgentArgs) {
  const mcpServers: MCPServer[] = [
    // Add MCP servers here
  ];

  for (const server of mcpServers) {
    await server.connect();
  }

  try {
    const agent = new Agent({
      name: "MyAgent",
      instructions: "...",
      mcpServers,
      tools: [myTool],
      model: "gpt-5.4",
    });

    const result = await run(agent, "...", { stream: true });

    // Consume the agent's response stream

    await result.completed;
  } finally {
    for (const server of mcpServers) {
      await server.close();
    }
  }
}

import { Agent, InMemoryRunner, MCPToolset, stringifyContent } from "@google/adk";
import { FoundryGemini } from "./foundryGemini";

export async function runAgent(args: AgentArgs) {
  const mcpToolsets: MCPToolset[] = [
    // Add MCP toolsets here
  ];

  try {
    const agent = new Agent({
      name: "MyAgent",
      instruction: "...",
      tools: [...mcpToolsets],
      model: new FoundryGemini({ model: "gemini-2.5-flash" }),
    });

    const runner = new InMemoryRunner({ agent });

    for await (const event of runner.runEphemeral({
      userId: "user",
      newMessage: { role: "user", parts: [{ text: "..." }] },
    })) {
      if (event.content) {
        console.log(stringifyContent(event));
      }
    }
  } finally {
    for (const toolset of mcpToolsets) {
      await toolset.close();
    }
  }
}

将 OSDK 和 OMCP 添加到您的 pro-code 智能体

该模板使 OSDK 和本体论 MCP 均可供您的 pro-code 智能体使用，无需客户端凭据，而是通过该智能体的 作用域权限。

本体论 SDK

要让您的 pro-code 智能体能够访问本体论资源，请向该智能体添加本体论 SDK。与在代码工作区中创建 SDK 时一样，选择要包含的对象类型、操作类型和查询函数，然后生成 SDK。如需分步指导，请查阅 创建新的本体论 SDK。

要直接读取和写入本体论数据，请构建一个绑定到您所选本体论的 OSDK 客户端。本体论资源标识符（RID）由生成的 SDK 公开：

Copied!
1
2
3
4
import { getOntologySdkClient } from "@palantir/agent-templates-bundle";
import { $ontologyRid } from "@ontology/sdk";

const client = await getOntologySdkClient($ontologyRid);

如需在 pro-code 智能体中使用 OSDK 的指导，请查阅 本体论 SDK 文档 以及 TypeScript OSDK 参考文档。

本体论 MCP

当您向 pro-code 代理添加本体论 SDK 时，系统会基于相同的 SDK 资源创建本体论 MCP。本体论 MCP 会将 SDK 中的对象类型、操作类型和查询函数公开为 MCP 工具，供代理的模型调用。

要使用本体论 MCP，请使用 getOntologyMcpConfiguration 函数获取其配置，并将其传递给您 pro-code 代理的 MCP 服务器，具体说明请参见下文的 MCP 配置函数 。如需了解本体论 MCP 所公开工具的更多信息，请参阅 本体论 MCP 文档。

MCP 配置函数

代理库通过以下函数提供默认 MCP 服务器配置：

函数连接到描述
getOntologyMcpConfiguration本体论 MCP将本体论 SDK 中的对象类型、操作类型和查询函数公开为模型可调用的工具。必须先添加 SDK，如 本体论 SDK中所述。
getPalantirMcpConfigurationPalantir MCP提供多种与 Palantir 平台交互的工具。
getPythonTransformsMcpConfigurationPython 转换 MCP提供与 Foundry Python 转换交互的工具，例如预览和发现转换。

每个函数均为 async ，并在运行时解析连接详细信息。由于 URL、命令和授权详细信息是通过 限定范围的权限，无需客户端 ID、密钥或 Foundry 令牌。

这些函数是特定于框架的：每个函数都会返回您的智能体框架所需的 MCP 服务器类型。请从与您的模板相匹配的包路径中导入它们：

框架导入路径返回类型
Claude Agent SDK@palantir/agent-templates-bundle/mcp/anthropicMcpHttpServerConfig 或 McpStdioServerConfig
OpenAI Agents SDK@palantir/agent-templates-bundle/mcp/openaiMCPServerStreamableHttp 或 MCPServerStdio
Google ADK@palantir/agent-templates-bundle/mcp/googleMCPToolset

请记住，每个函数都是异步的：请先 await 它，然后再将结果注册到您的智能体循环中。

Palantir MCP 和 Python Transforms MCP 需要使用您的 Foundry 前门主机（FOUNDRY_EXTERNAL_HOST）。此主机会在运行时使用智能体自身的凭据从 Control Panel 为您解析。因此，即使智能体通过 Marketplace 安装到了不同的 enrollment 上，该主机也仍然是正确的。如果无法解析该主机，配置将回退到生成仓库时记录的主机。要覆盖该回退行为，请将 fallbackHost 选项传递给 getPalantirMcpConfiguration 或 getPythonTransformsMcpConfiguration。
