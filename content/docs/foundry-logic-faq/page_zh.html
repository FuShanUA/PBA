如何减少我的 token 数量？

AIP Logic 中的所有活动都会计入令牌限制，工具响应也不例外。令牌限制按块重置。您可以在 Debugger 中每条消息的末尾查看所使用的令牌数量。如果进度条显示为红色，请考虑减少令牌数量，以确保可靠的性能。

我们建议您采取以下步骤来减少 token 数量：

  • 从您的输入对象中选择所需的特定属性，或指定要查询的对象属性，以减小 LLM 发送和接收的字符串（OBJECT_NAME property1 property2 等）的大小；您可以在调试器中选择 显示原始数据.
  • 使用 计算器工具 工具时，请选择要发送给 LLM 的属性子集。
  • 请考虑 将单个区块拆分为多个 使用 LLM 区块；每个区块都有令牌限制，因此您可以尝试将一个区块分解为多个中间步骤。
  • 将您的 LLM 模型更改为 32k。
  • 请尽可能使用确定性区块，例如转换区块、 执行区块日 应用操作块。这些块有助于产生更可预测的结果，并且不使用任何令牌，从而使您的逻辑更高效、更易于管理。

应何时将 Logic 函数保留在一个块中，而何时又应将其拆分为多个块？

单个大块可让您在试验 LLM 功能时快速迭代并轻松进行大幅修改，但在以下情况下，您可能需要将 Logic 拆分为多个块：

  • 您希望 LLM 执行多个步骤，但得到的结果不一致。
  • 该块即将达到其上下文限制。
  • 每次运行执行时间过长。

由于每个块都有其自己的上下文窗口，拆分为多个块可能具有以下优势：

  • LLM 只能访问您传入的内容；单个大块中的中间结果可能是不相关的。
  • 您不太可能耗尽 token。
  • 多个较小的任务可能比一个长任务执行得更快。

如何提升 AIP Logic 块的性能？

要提高 AIP Logic 块的性能，请尝试以下建议：

  • 选择 5-10 个输入/输出对示例，并在每次修改提示词时运行它们。将这些保存为 AIP Logic 中的单元测试。
  • 为 LLM 提供少样本示例；这可以让模型更容易理解任务，从而显著提升 LLM 性能。您可以输入供 LLM 参考的系统提示词。
  • 如果您遇到意想不到的失败，可以通过让 LLM 解释其计划和对问题的理解，来验证模型是否正确“理解”了您的数据——这有助于了解缺少了哪些上下文。
  • 考虑使用动态少样本示例来构建反馈循环。
  • 使用确定性的转换看板，例如转换块， 执行区块日 应用操作块.
  • 用途 AIP 评估 以运行评估。在迭代提示词时，若要理解失败的测试用例，请选择 在 AI FDE 中分析 （位于运行结果中），以识别根本原因并获取建议的提示词更改。

是否可以使用 Logic 支持语义搜索工作流？

是的，您目前可以添加一个工具，使 Logic 能够在本体论上执行语义搜索，这可以通过操作实现，也可以通过编写一个随后从 AIP Logic 调用的对象函数来实现。请查看 语义搜索工作流 教程以了解更多信息。

LLM 如何从反馈中“学习”？

如果适合您的工作流，您可以使用这种设计模式帮助 LLM 从反馈中“学习”：

  1. 每当 LLM 提出建议时，记录 (1) 建议内容以及 (2) 推理过程。然后，在将 Logic 函数连接到 Workshop 并构建人工审查流程时，将 (3) 人工反馈以及 (4) 经人工验证的正确决策写回。在本示例中，假设我们将这个写回对象称为“Suggestion”对象。
  2. 在您的 Logic 函数中，让 LLM 能够使用 计算器工具 工具作用于 “Suggestion” 对象，搜索 LLM 曾提出相同建议的其他实例。让 LLM 处理人类反馈，然后询问 LLM 是否继续执行该 LLM 的建议。

如何确保我的 Logic 输出正确？

添加单元测试以检查函数在给定输入上是否成功运行。你还可以使用 AIP 评估 为你的 Logic 函数创建评估套件。要生成套件，请打开 Evals 标签页并选择 使用 AI FDE 生成。AI FDE 会根据您的函数生成测试用例和评估器。在运行评估之前，请审查并优化生成的测试用例和评估器。若要分析失败的测试用例，请选择 在 AI FDE 中分析 （位于运行结果中），以识别根本原因并获取建议的提示词更改。详情请参阅 AIP Evals：入门.

一个 LLM 模块可以返回多个值吗？

是的。通过使用 "Struct" 输出类型，您可以返回多个命名值。

我可以配置我的工具向 LLM 块提供多少个对象吗？

是的，当您在 LLM 块中的函数工具上添加对象查询工具时，您可以选择 配置对象返回限制 以选择您希望从任意工具使用中返回的对象数量。

为什么我的函数在 AIP Logic Debugger 中成功执行，但在 Workshop 中或通过 API 调用时却失败？

在 Debugger 中测试和开发您的 AIP Logic 函数时，该函数不受五分钟执行时间限制。但是，当从 Workshop 环境或通过函数执行 API 调用该函数时，将强制执行五分钟执行时间限制。
