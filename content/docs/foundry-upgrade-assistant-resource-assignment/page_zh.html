资源分配

资源可以分配给组或单个用户。通知会以个人身份或组成员身份发送给用户（使用组成员身份来确定是否有资源分配给某个用户）。

在大多数情况下，资源由 Upgrade Assistant 依靠 启发式规则 基于 资源的类型 直接分配，以确定合适的负责人或组。本页面的其余部分介绍了 Upgrade Assistant 使用的各种分配启发式规则。

或者，负责在平台中实施变更的相关方可以直接将资源分配给组或用户。在这种情况下，Upgrade Assistant 仅记录该分配。

在所有情况下，资源一次最多只能分配给 100 个组或用户。

Compass 资源的分配启发式规则

Compass 资源 根据其所属的 项目 进行分配。 如果可能，资源将分配给项目的 联系人。如果找不到指定的联系人，资源将分配给在项目上具有 Owner 角色的用户和组。

Compass 资源分配的最佳实践

  • 确保已设置项目的联系人，并且该联系人反映了项目的实际所有权。
    • 联系人可以充当调度员，根据其对业务的了解重新分配资源。
    • 如果联系人不可用，请考虑审查在项目上具有 Owner 角色的组或用户。如果可能，将 Owner 缩减为一组特定的用户。

注册资源的分配启发式规则

注册资源 分配给担任 维护操作员的用户。这些用户在相关组织上具有 OPERATOR-VIEW-PROGRESS 操作权限。此操作在 Control Panel 中显示为 在 Upgrade Assistant 中查看进度，并且默认授予某些角色，例如 技术合规官员。如果找不到此类用户，资源将分配给 组织管理员.

注册资源分配的最佳实践

  • 确保 技术合规官员 角色拥有一定数量熟悉 Upgrade Assistant 的用户。

其他资源的分配启发式规则

对象类型资源分配给在给定对象类型上具有编辑者或所有者角色的用户。受限对象类型分配给同时也是支撑数据集的编辑者或所有者的用户。

其他类型的资源，例如 Compass 空间、关联类型、操作类型或计划，没有默认的启发式规则。对于这些资源，Upgrade Assistant 依靠报告受影响资源的服务来提供分配信息。了解如何识别 其他资源.

"需要分类"分配启发式规则

在某些情况下，资源可能会被分配给 维护操作员 ，分配原因列为"需要分类"。当标准启发式规则不足以解决问题时，会应用此分配启发式规则。

具体而言，"需要分类"适用于以下情况：

  • 标准启发式规则 未识别出任何被分配人。例如，没有用户被识别为项目联系人或项目所有者。
  • 标准启发式规则识别出 过多的被分配人。例如，资源所属的项目由一个包含 1000 个用户的组拥有，且未列出联系人。

在这些情况下，资源将分配给维护操作员进行分类，并适当地重新分配给相关用户。
