配置日志记录 [Beta]

Beta

日志导出功能目前处于 beta 开发阶段，此功能可能无法在您的注册中使用。在持续开发期间，功能可能会发生变化。请联系 Palantir 支持团队了解更多信息。

Foundry 中的应用程序会发出日志，让您能够了解其运行情况，包括转换运行、构建失败和其他系统事件。

Foundry 日志包含有关以下内容的信息：

  • 应用程序和函数执行事件
  • 转换和管道运行
  • 构建和部署活动
  • 系统错误和警告

此外，用户在代码仓库中编写的任何日志也将被发出。

这些日志可以导出到 Foundry 流式数据集，用于实时监控和分析。此功能仅适用于组织管理员，他们可以配置一个目标位置，使来自 Foundry 应用程序的日志流入 Foundry 流式数据集。

除日志导出管理外，平台内的本体论和 AIP 日志访问权限由组织管理员和信息安全官管理。

要开始管理您组织的日志可观测性设置：

  1. 导航到 Control Panel 应用程序。
  2. 在顶部横幅中，从下拉菜单中选择相关组织。
  3. 在左侧边栏中，选择 日志可观测性设置 ，该选项位于 组织 部分下。或者，在主页中搜索 Log observability settings 并在搜索结果中选择相关页面。

导出 Foundry 日志

Foundry 日志可以按组织直接导出到 Foundry 流式数据集中。

定义导出配置后，日志条目将从配置创建之时起持续写入流式数据集。您可以使用 Foundry 丰富的数据转换和可视化工具套件实时处理和分析数据，或将日志导出到外部监控系统。

导出权限

要导出 Foundry 日志，用户必须是 组织管理员。该角色提供为组织配置日志导出目标位置所需的权限。请参阅 组织权限 以了解组织级权限的更多详细信息。

日志数据可能包含敏感信息。我们建议将 安全标记 应用于输出流式数据集，以控制对此数据的访问。您可以在创建导出时直接应用标记，也可以之后将其添加到数据集中。

要求和限制

日志导出以每个源执行器 基础。源执行器是发出日志的资源，例如函数、操作或自动化。配置导出时，Foundry 会从位于您所选项目中的源执行器收集日志，并针对这些源执行器（而非仅针对导出数据集）评估以下约束条件。

在设置日志导出之前，必须满足以下要求：

  • 导出数据集上的每个组织标记也必须存在于源执行器上： 导出数据集还必须带有至少一个组织标记。导出数据集会继承其创建位置的组织标记，因此请选择一个位置，使其组织标记均存在于您打算从中导出日志的源执行器上。
  • 操作必须使用基于项目的权限： 导出范围中包含的任何操作类型都必须迁移到 基于项目的本体论权限 ，然后才能为其设置日志导出。仍由 旧版本体论权限 管理的操作类型必须先 迁移到基于项目的权限。

下表显示了哪些导出数据集会接收来自带有组织 A 和组织 B 标记的源执行器的日志：

导出数据集组织标记已导出日志
组织 A是
组织 A、组织 B是
组织 A、组织 C否。组织 C 不在源执行器上。
无否。至少需要一个组织标记。

定义导出配置

Foundry 日志可以从属于一组项目的资源导出，也可以从组织中的所有资源导出。定义导出配置时存在一些限制：

  • 每个组织最多可以有 50 个导出配置。
  • 每个项目最多可以包含在三个导出配置中。
    • 此限制包括从所有项目导出日志的配置。
  • 为配置选择一组项目时，每个配置最多可以包含 100 个项目。

我们建议从特定项目中的资源导出日志，而不是从所有组织资源导出。这样可以简化对生成的数据集的访问控制。

按照以下步骤定义导出配置：

  1. 选择 创建日志导出，这将打开一个用于定义配置的对话框。

  1. 选择要从中导出相关日志的项目。您可以使用下拉菜单按空间筛选项目列表，或按名称搜索项目。已包含在其他导出配置中的项目会显示一个计数，指示现有导出的数量。

  1. 指定用于导出日志的流式数据集的名称和位置。该位置必须位于 Foundry 文件系统内，且不能是用户创建的文件夹。

  1. 选择一种 日志架构 格式。Foundry 提供两种架构类型：一种是内部 Palantir 格式，以序列化 JSON 字符串的形式提供有效负载；另一种是 OpenTelemetry (OTel) 协议格式，将有效负载序列化为协议缓冲区二进制数据。在同一步骤中，使用 取消脱敏用户 ID 开关来控制导出日志中的用户 ID 是否被脱敏。默认情况下，用户 ID 会被脱敏。

  1. 在 应用标记 步骤中，选择要应用于输出流式数据集的安全标记。此步骤为可选，但建议执行，以便控制对日志数据的访问，因为这些数据可能包含敏感信息。创建导出配置后，所选标记将应用于生成的日志数据集。

  1. 选择 创建配置 前，请先查看摘要和访问要求。摘要会显示所选标记以及其他配置详细信息，以便您在创建导出前确认自己的选择。

  1. 配置创建后，该配置将显示在现有配置列表中。所有已应用的标记都会与导出配置详细信息一起显示。

请注意,首次配置日志导出时,日志最多可能需要五分钟才能开始流式传输到导出位置的数据集中。

禁用日志导出

要禁用日志导出,请选择配置右侧的垃圾桶图标,以删除列出的所有日志存储配置。生成的数据集将继续存在,但不会再向其中导出新日志。此外,如果流式数据集位于回收站中或已被永久删除,日志将停止导出。

分析日志数据

日志存储数据集可能包含大量流式数据,因此我们建议在执行分析之前对数据集进行适当筛选。可以考虑使用基于时间的筛选,聚焦于与您的监控和故障排除需求相关的日志条目。

Foundry 提供了许多用于执行日志分析的强大工具,例如 转换 和 Pipeline Builder。

日志架构

Foundry 应用程序日志是遵循一致架构的结构化日志,因此适合进行程序化分析和监控。

具体而言,Foundry 日志包含有关各种应用程序事件的信息,包括转换执行、构建过程、系统错误以及其他运维活动。日志结构因生成日志条目的应用程序或服务类型而异。

特定于应用程序的信息会被捕获到结构化字段中，这些字段提供有关所执行操作的上下文，包括执行详细信息、错误信息和性能指标。

Foundry 提供两种架构类型：

  • 一种 Palantir 内部格式，将有效负载作为序列化 JSON 字符串提供
  • OpenTelemetry (OTel) 协议以 OTel 协议 ↗ 格式提供日志，其有效负载被序列化为协议缓冲区二进制数据，以便下游摄取至 OTel 收集器。

日志归因

Foundry 应用程序日志由平台内的各种服务和应用程序生成。当日志流式传输到所配置的数据集时，系统会对其进行筛选，以仅包含与配置了日志存储配置的组织相关的日志。

为给定组织配置的日志导出将接收该组织所使用的应用程序和服务的日志。这包括转换执行、构建以及在该组织上下文中执行的其他活动。

生成日志的资源的 RID 包含在日志条目中，可用于将日志追溯到该资源。

日志保证

Foundry 日志 并非 审计日志。无法保证日志传递 100% 可靠。

Foundry 生成的日志内容可能会变更，恕不另行通知。

本体论和 AIP 工作流的平台内日志访问

本体论和 AIP 的平台内日志访问在项目级别进行管理。用于平台内查看的日志访问控制与为导出流式数据集配置的权限不同。这些控制专门适用于从已启用项目调用的函数、操作、自动化工作流和语言模型。

服务和跟踪日志可能包含工作流可访问的任何数据源中的敏感内容,包括语言模型提示和补全、对象属性值以及用户提供的输入。平台不会传播来自源执行器资源或执行所访问的任何数据的标记;只有您在启用日志访问时选择的标记才会对查看者强制执行。请选择能够反映工作流可能触及的数据的最高敏感度的标记,并在启用前审查由此产生的访问范围。

您可以在 控制面板 中配置平台内日志访问,或直接在 工作流血缘中的资源节点上配置。

用户必须具备以下条件,才能查看其未调用的日志(保留期为 30 天):

  • 已启用日志读取 (适用于源执行器所在的项目,或通过资源级别的覆盖设置)
  • 标记访问权限 到项目日志访问设置或资源级覆盖中配置的任何标记。
  • 编辑权限 ，该权限针对发出日志的源执行器。

具体而言，对编辑权限的要求对应于 foundry-telemetry-service:view-execution-history 操作，该操作由 Editor 角色默认授予。您可以通过其他角色授予此操作，方法是使用 自定义角色。

无论管理员所管理的日志访问状态如何，用户都可以查看自己在过去 24 小时内运行的执行的日志。此例外不适用于 CBAC 堆栈。

有关查看要求及其对应角色的权威列表，请参阅 日志权限。

在控制面板中配置日志访问

要按项目管理平台内的日志访问控制：

  1. 导航至 日志访问 标签页。此标签页会显示为您的组织启用了日志读取的项目（若有）。默认情况下，组织内所有项目的日志访问均处于禁用状态。

  1. 要为项目启用日志访问，请选择 添加项目，这将打开一个对话框，用于配置项目的遥测日志可见性。

  1. 选择项目后，将出现第二个对话框，用于为该项目启用日志读取并应用必要的标记。

  1. 为项目启用日志访问权限后，该项目将显示在已启用项目列表中。

  1. 随后，您应该会看到更新后的策略在整个平台中得到反映，驻留在该项目中的所有源执行器资源均已启用日志查看权限。

在 Workflow Lineage 中配置日志访问权限

除了 Control Panel 流程，管理员还可以在 Workflow Lineage 的 日志访问概览 对话框中查看和调整资源的日志访问权限。请按照 日志权限中的说明打开该对话框，然后选择 编辑 （位于 日志访问策略 要求上），以打开配置步骤。

我们建议采用项目级日志访问权限。选择 在 Control Panel 中配置 ，以使用 Control Panel 流程来启用它。

配置步骤会显示一个表格，其中汇总了为该资源解析日志访问权限的位置：

列含义
当前项目当前包含该资源的项目。显示 已启用 或 未配置。
归属项目资源在日志访问方面的归属项目，即资源最初发出遥测数据时所在的项目。仅当其与当前项目不同时才会显示。显示 已启用 或 未配置。
资源覆盖资源级覆盖，在覆盖处于活动状态或项目已禁用日志访问时显示。显示 已启用、 已禁用或 未配置。

更新项目归属

出于日志访问的目的，源执行器会归属于某个项目。默认情况下，归属项目是源执行器首次写入日志时所在的项目。如果资源在写入第一条日志后被移动，当前项目与归属项目就会不一致，此时会同时针对这两个项目强制执行日志访问控制。

当两个项目不一致时，管理员可以将归属重新指向当前项目：将鼠标悬停在上一个项目的状态标签上，然后选择 清除并继承。

为旧版本体论权限配置资源覆盖

只有在将操作迁移到 本体论基于项目的权限后，才能在项目级别管理该操作。仍由 旧版本体论权限 管理的操作必须先 迁移到基于项目的权限。操作迁移后，管理员会通过清除旧版本体论资源标识符来更新其项目归属。

对于使用旧版本体论权限的操作，配置步骤提供两条路径：将操作迁移到项目（推荐），或配置资源覆盖。操作的本体论资源标识符将代替项目显示；管理员无法启用该操作，也无法通过 Foundry 的项目和文件系统访问它。

在操作迁移之前，您可以通过激活资源覆盖并应用 必需标记 来启用日志访问，查看者必须持有这些标记才能读取资源的日志。这些标记将应用于日志，并叠加在资源上已有的任何标记以及项目日志设置之上。

日志可能包含来自所访问对象或数据的敏感信息。该数据上存在的安全标记不会自动传播到日志，必须手动应用。

已禁用的资源覆盖已弃用。如果表中显示已禁用的覆盖，请将其移除并依赖项目级策略；对话框会阻止 下一步 ，直到您完成此操作。

配置策略后，选择 下一步 以继续进入确认步骤。

确认变更

在更改生效之前，您必须勾选确认复选框，确认您了解安全方面的权衡。启用覆盖时，您确认敏感对象数据可能会被记录到日志中，且您已应用正确的标记。清除覆盖时，您确认该资源将恢复为项目级别的日志可见性。勾选复选框后，请选择 应用更改 以保存。

删除日志历史

具有 Information security officer 或 Enrollment administrator 角色的用户可随时删除日志。在 Workflow Lineage 的 运行历史 或 日志搜索 面板中，选择 编辑权限 > 删除日志历史 > 删除日志。

删除日志历史的操作不可逆，将永久删除源自此资源的所有执行日志。
