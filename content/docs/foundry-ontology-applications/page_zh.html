Foundry 包含许多专门开发用于在本体论之上原生运行的应用程序。这些对象感知应用程序共同提供了一个强大的分析和操作平台，支持各种用例和用户类型。

应用程序参考

对象视图

对象视图 是与特定对象相关的所有信息和工作流的中心枢纽。这包括对象的关键“背景数据”、任何关联的对象、关键相关指标，以及与该对象相关的关键分析、仪表板和应用程序的链接（或嵌入）。

例如， Airport 对象类型对象视图可能为每个 Airport 对象提供以下信息：

  • 背景数据，例如 country, city, longitude, latitude等。
  • 所有 Aircraft 对象以及与 Flight 对象关联的 Airport
  • 嵌入的 Airport Covid Response workflow
  • 指向 Root-Cause Analysis 的 Flight delay 事件的链接，该事件与 Airport

对象浏览器

对象浏览器 是一个搜索和分析工具，用于解答有关本体论层中任何内容的问题。用户可以通过可视化方式构建搜索查询，从简单的筛选器到 Search Around，以查找感兴趣的对象。然后，他们可以使用探索视图浏览生成的对象集，或将其作为结果表查看。此外，用户可以比较和对比对象集，并对对象集执行批量操作（例如回写）。之后，用户可以导出对象集或在兼容的应用程序（如 Workshop）中打开它们。

探索视图是一组预设且可配置的可视化（如图表或地图），用户可以进一步利用这些可视化深入钻取特定的对象子集。Object Explorer 无需预先配置，适合技术背景较弱的用户使用。

用例

对象感知应用程序支持的主要用例包括 发现, 了解如何通过, 仪表盘日 应用程序.

  • 发现 使用户能够找到合适的信息或工作流。发现功能主要通过两个核心特性来实现：精选内容中心和搜索。精选内容中心（有时称为着陆页或“360 视图”）涵盖从面向所有用户的综合标准视图，到面向特定用户群体或用例的定向视图。搜索功能通过关键词的自由文本搜索，以及通过关联遍历或下钻进行的更迭式搜索来支持发现。
  • 了解如何通过 使用户能够回答广泛的问题。这些问题从简单的（某产品的平均客户留存率是多少？）到非常复杂的（随着时间的推移，三个不同的客户群体在留存率和总收入方面如何比较，包括所有产品以及每个单独产品？）。分析路径是探索性的，这意味着它由最终用户自己定义，并且通常是高度迭代的；随着初始问题得到解答，新的问题会被开发出来并纳入分析路径。
  • 仪表盘 是一组预先配置的可视化内容，主要由更广泛的消费者用户以只读方式使用。仪表板通常用于将有意义的 分析 转化为定期报告或运营监控。仪表板的特点是包含大量图表和其他可视化内容，但其可定制性和交互性不如 应用程序 （见下文）。仪表板通常带有参数化设置，使用户能够将可视化内容筛选到不同的数据子集。
  • 应用程序 是交互式的自定义操作界面，面向特定用户群体以解决特定问题。应用程序通常比仪表板更复杂，旨在使用户能够遵循特定的、预设好的工作流。虽然应用程序可能包含执行决策所需的一些精选分析内容（例如统计数据、图表、图形等），但它通常还包含多个工作流元素，并且经常捕获用户输入（例如回写）。

工作流风格

对象感知应用程序针对主要工作流风格进行了优化。

  • 探索型应用程序 不需要由“构建者”用户预先配置，一旦数据被建模到本体论中，最终用户即可开箱即用。在探索型应用程序中，最终用户定义自己的分析路径，并可以回答各种未预先确定的问题。探索型应用程序通常包含一组搜索、可视化和转换功能来实现这一点。主要以探索为主的对象感知应用程序包括 Object Explorer 和 Quiver。
  • 工作流特定型应用程序 需要由“构建者”用户预先配置，最终用户才能实际使用。这对于具有两个主要用户群体的仪表板或应用程序来说很典型：(1) 配置特定仪表板或应用程序的构建者群体，以及 (2) 应用程序为其构建的下游最终用户。Workshop 和 Slate 模块都需要由“构建者”用户在编辑模式下预先配置。

某些应用程序（如 Quiver）可以同时适应两种工作流风格，因为虽然它们的主要模式是探索性的，但其输出可以配置为供更广泛使用的工作流特定型产物。虽然 Quiver 分析具有高度探索性，但它们可以发布为 Quiver 仪表板，即面向更广泛受众的预先配置的分析视图。

配置模型

配置模型描述了用户界面在最终用户使用之前必须配置的程度。

  • 即开即用 应用程序可以被用户有效且立即地使用，几乎不需要配置或维护负担。例如，Object Explorer 几乎不需要配置，一旦定义了本体论，最终用户即可立即使用。
  • 可自定义 应用程序需要前期投入（通常由单独的“builder”用户）来实现一个为最终用户解决特定问题的接口。这也意味着更高的持续维护成本。但是，由此产生的应用程序通常是一个符合用途的接口，能够完全满足特定工作流程的需求。Workshop 和 Slate 是此类自定义的示例。
