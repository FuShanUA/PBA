Databricks 计算下推

Foundry 提供了在使用 虚拟表时将计算下推到 Databricks 的能力。当使用注册到同一数据源的 Databricks 虚拟表作为管道的输入和输出时，可以将计算完全联邦到 Databricks。

本文档将引导您完成在代码仓库中编写 Python 转换 的整个过程，该转换可完全在您的 Databricks 环境中执行。此功能利用了 Databricks Connect。请参阅 Databricks 官方文档 ↗ ，以了解更多有关 Databricks Connect 功能和限制的信息。

快速开始

本示例展示了如何在 Python 转换管道中使用 Databricks 转换。假设我们有以下使用 PySpark 的 Spark 管道，通过 @transform：

from pyspark.sql.functions import col
from transforms.api import transform, Input, Output


@transform.spark.using(
    source_table=Input('/Project/folder/input'),
    output_table=Output('/Project/folder/output'),
)
def compute(source_table: TransformInput, output_table: TransformOutput):
    df = source_table.dataframe()
    df = df.filter(col('id') > 1)
    output_table.write_dataframe(df)

要将其转换为 Databricks 转换，您必须：

  1. 查看 在 Python 转换中使用表的前提条件。
  2. 安装 databricks-connect ，可在 Libraries 选项卡中完成。
  3. 导入 @databricks 装饰器，并将其应用于您的转换。

如需更多详细信息，请查阅下方文档中的 设置 部分。

from pyspark.sql.functions import col
from transforms.api import transform
from transforms.tables import (
    databricks,
    DatabricksInput,
    DatabricksOutput,
    TableInput,
    TableOutput,
)


@transform.databricks.using(
    source_table=TableInput('/Project/folder/input'),
    output_table=TableOutput(
        '/Project/folder/output', # Where to register the Databricks output as a virtual table in Foundry
        "ri.magritte..source.1234", # Your Databricks source connection
       "CATALOG.SCHEMA.TABLE", # The location to which the transform output will be written in Databricks
    ),
)
def compute(source_table: DatabricksInput, output_table: DatabricksOutput):
    df = source_table.dataframe()
    df = df.filter(col('id') > 1)
    output_table.write_dataframe(df)

鉴于 Databricks Connect 使用 pyspark.sql.DataFrame ↗ API，您会发现代码本身的逻辑基本保持不变。主要区别在于该转换使用的是在 Databricks 中运行的 Spark 计算。

TableInput 和 TableOutput 参数将用于替代 Input 以及 Output 引用转换的输入和输出 Databricks 虚拟表。转换函数会被传入 DatabricksInput 和 DatabricksOutput 参数，这些参数可用于读取和写入 Databricks 中的表。

该 @databricks 装饰器（如上所示）仅兼容 TableInput 和 TableOutput 参数。作为转换的输入和输出引用的表必须注册到同一个 Databricks 源。

使用 @incremental 装饰器进行的增量计算目前在向 Databricks 进行计算下推时不受支持。

设置

要将计算下推与 Databricks 结合使用：

  1. 创建一个 Python 代码仓库。
  2. 请查看 在 Python 转换中使用表的先决条件。
  3. 安装 databricks-connect 库。我们建议使用 16.4 版本，因为该版本与无服务器计算完全兼容。如果使用经典计算，则必须使用与您的 Databricks 集群版本兼容的版本。请参阅 Databricks 官方文档 ↗ 以了解更多信息。

该 databricks-connect 库可以通过您的代码仓库环境中的 “库” 选项卡 来安装。请注意， databricks-connect 只能通过 PyPI 获取，无法通过 Conda 获取。或者，您也可以手动将该库添加到 pip requirements 块下（位于 conda_recipe/meta.yaml 文件中）。例如，要安装 16.4 版本的 databricks-connect，请添加：

API 要点

以下各节将重点介绍 Databricks 转换 API 与常规 Python 转换之间的差异。在使用 @databricks之前，请确保您已完成上述 设置 步骤。

Databricks 转换使用 transforms.tables.TableInput 和 transforms.tables.TableOutput 参数来引用输入和输出 Databricks 虚拟表。 TableInput 可以通过文件路径或 RID 引用虚拟表。 TableOutput 需要：

  1. 在 Foundry 中创建虚拟表的文件路径。
  2. 该 源 ，即虚拟表将要注册的位置。
  3. 在 Databricks 中写入表的位置。此位置可以通过 DatabricksTable("<catalog>", "<schema>", "<table>") 或 "<catalog>.<schema>.<table>" 语法来指定。 catalog， schema 和 table 对应于 Unity Catalog 中表标识符的三级命名空间结构。请参阅 Databricks 官方文档 ↗ 以了解更多信息。

在 API 方面， DatabricksInput 和 DatabricksOutput 与常规 Python 转换类似。 .dataframe() 将输入表加载为 pyspark.sql.DataFrame。 .write_dataframe() 将 pyspark.sql.DataFrame 写入输出表。转换逻辑本身可以使用 PySpark 转换来表达。

并非所有 PySpark 功能都在 Databricks Connect 中受支持。请参阅 Databricks 官方文档 ↗ 以了解功能可用性和限制的详细信息。

输出表类型

您可以在 Databricks 中使用以下任一表类型来写入输出表：

  • 托管 Delta： 以 Delta Lake 格式存储在 Databricks 托管存储中的表。
  • 外部 Delta： 以 Delta Lake 格式存储在外部存储位置的表。
  • 托管 Iceberg： 以 Iceberg 格式存储在 Databricks 托管存储中的表。

您可以使用 format 和 location 参数（位于 DatabricksTable 或 write_dataframe 上）来配置输出表类型。如果 format 和 location 未指定，则该表将写为托管 Delta 表（Databricks 中的默认表类型）。使用 format="iceberg" 将输出写为托管 Iceberg 表。使用 location="<STORAGE_LOCATION>" 将输出写为外部 Delta 表，其中 <STORAGE_LOCATION> 指向云对象存储中用于存储该表的外部存储路径。

from transforms.tables import (
    databricks,
    DatabricksTable,
    DatabricksInput,
    DatabricksOutput,
    TableInput,
    TableOutput,
)

@transform.databricks.using(
    source_table=TableInput('/Project/folder/input'),
    managed_delta_output_table=TableOutput(
        '/Project/folder/output',
        "ri.magritte..source.1234",
       "CATALOG.SCHEMA.MANAGED_DELTA_TABLE",
    ),
    managed_iceberg_output_table=TableOutput(
        '/Project/folder/output',
        "ri.magritte..source.1234",
       "CATALOG.SCHEMA.MANAGED_ICEBERG_TABLE",
    ),
    external_delta_output_table=TableOutput(
        '/Project/folder/output',
        "ri.magritte..source.1234",
        DatabricksTable(
            catalog="CATALOG",
            schema="SCHEMA",
            table="EXTERNAL_DELTA_TABLE",
            location="s3://some-bucket/path/to/table"
        ),
    ),
)
def compute(
    source_table: DatabricksInput,
    managed_delta_output_table: DatabricksOutput,
    managed_iceberg_output_table: DatabricksOutput,
    external_delta_output_table: DatabricksOutput,
):
    df = source_table.dataframe()

    # write to a managed Delta table
    managed_delta_output_table.write_dataframe(df)

    # write to a managed Iceberg table by specifying the format option inline
    managed_iceberg_output_table.write_dataframe(df, format="iceberg")

    # write to an external table where the location has been specified in the DatabricksTable
    external_delta_output_table.write_dataframe(df)

计算配置

默认情况下，将使用无服务器计算建立 Databricks Connect 会话。这相当于使用 @databricks(serverless=True)。

或者，您可以使用 with_compute(cluster_id="<cluster-id>") 来配置与特定计算集群的连接。

有关 Databricks Connect 计算配置的信息，请查阅 Databricks 官方文档 ↗。

用户自定义函数 (UDF)

用户自定义函数 (UDF) 在 Databricks Connect 中受支持。当你执行包含 UDF 的 PySpark DataFrame 操作时，Databricks Connect 会对 UDF 进行序列化，并将其作为请求的一部分发送到服务器。有关 UDF 功能和限制的完整详细信息，请参阅 Databricks 官方文档 ↗。

以下示例定义了一个简单的 UDF，用于对某一列中的值求平方：

from pyspark.sql.functions import col, udf
from pyspark.sql.types import IntegerType
from transforms.api import transform
from transforms.tables import (
    databricks,
    DatabricksInput,
    DatabricksOutput,
    TableInput,
    TableOutput,
)


@udf(returnType=IntegerType())
def double(x):
    return x * x


@transform.databricks.using(
    source_table=TableInput('/Project/folder/input'),
    output_table=TableOutput(
        '/Project/folder/output',
        "ri.magritte..source.1234",
       "CATALOG.SCHEMA.TABLE",
    ),
)
def compute(source_table: DatabricksInput, output_table: DatabricksOutput):
    df = source_table.dataframe()
    df = df.withColumn("doubled", double(col("id")))
    output_table.write_dataframe(df)

为 UDF 指定 Python 依赖项

Databricks Connect 支持指定 UDF 所需的 Python 依赖项。这些依赖项会作为 UDF 的 Python 环境的一部分安装到 Databricks 计算资源上。你可以使用 with_dependencies(dependencies=["<dependency>"]) 来配置要安装到 UDF 环境中的额外依赖项。

from pyspark.sql.functions import col, udf
from pyspark.sql.types import StringType
from transforms.api import transform
from transforms.tables import databricks, DatabricksOutput, TableOutput


@udf(returnType=StringType())
def get_joke():
    from pyjokes import get_joke
    return get_joke()


@transform.databricks.using(
    output_table=TableOutput(
        '/Project/folder/output',
        "ri.magritte..source.1234",
       "CATALOG.SCHEMA.TABLE",
    ),
).with_dependencies(dependencies=["pyjokes<1"])
def compute(output_table: DatabricksOutput):
    df = output_table.spark_session.range(1, 10)
    df = df.withColumn("jokes", get_joke())
    output_table.write_dataframe(df)

如果你遇到诸如 ModuleNotFoundError: No module named 'myproject'之类的错误，则通常表示你的 UDF 引用了仅存在于本地环境中的代码，而执行该 UDF 的 Databricks Spark 工作节点无法访问这些代码。为避免出现此错误，请确保你的 UDF 不直接依赖于本地模块中定义的函数或类。你可以通过以下方式之一来解决此问题：

  • 将必要的逻辑 直接内联到 UDF 定义中。
  • 同时定义 UDF 及其支撑代码 在 @transform 函数的主体内。
  • 将 UDF 及其支撑代码封装在一个函数中， 该函数返回对该 UDF 的引用，并在转换中调用此函数以创建 UDF。
