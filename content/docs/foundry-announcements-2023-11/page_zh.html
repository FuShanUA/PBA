模型推理历史数据集 [正式发布]

发布日期：2023-11-28

我们很高兴地宣布，您现在可以在 Foundry 中创建模型推理历史数据集。这些数据集会捕获建模目标中实时部署处理的所有推理请求（输入）和推理结果（输出），从而简化各种工作流，包括漂移检测、持续再训练、性能评估和使用分析。

利用实时部署数据

模型推理历史数据集会跟踪实时部署的请求和响应。此功能为生产用例提供了宝贵的反馈，模型开发者可以借此了解真实客户和用户如何使用该模型。

例如，考虑使用实时部署在网站上提供推荐服务。模型推理历史会记录用户访问以及为每个用户提供的推荐。借助这些记录，开发者可以分析数据集，以确定推荐对特定用户的有效性。在这种情况下，数据集通过支持使用分析来创造价值，从而为优化和资源分配决策提供依据。

虽然当前的 模型评估流程 支持持续再训练和性能评估，但这些现有功能并不提供模型使用情况的用户反馈。因此，与模型推理历史数据集不同，这些功能更适合已有训练和测试数据的场景，而非实时数据。

使用模型推理历史数据集

要创建模型推理历史数据集，请导航至建模目标的 部署 页面，选择实时部署，然后选择 创建数据集 图表工具 模型推理历史 部分。我们强烈建议添加安全标记，因为输入和输出可能包含敏感信息。

模型推理历史是从建模目标的“部署”页面创建的。

创建后，数据集将记录关键信息，例如时间戳、用户 ID、请求 UUID 以及输入和输出的 JSON 表示形式。

启用和禁用数据集

要临时启用或禁用模型推理历史，请导航至 模型推理历史 卡片并使用 启用记录 开关。要永久禁用模型推理历史，请选择 移除 按钮，位于数据集旁边的 模型推理历史 卡片。

有关此主题的更多信息，请参阅 模型推理历史 文档。

from transforms.api import transform_pandas, Input, Output, lightweight

@lightweight
@transform_pandas(
    Output('/Project/folder/output'),
    df=Input('/Project/folder/input')
)
def compute(df):
    return df[df['Name'].str.startswith("A")].sort_values(by="Age")

转换基准研究

通过比较优化复杂转换和简单转换的基准，可以证明 Lightweight API 的优势。作为背景，下面展示的两个基准图对平均端到端运行时间进行了受控优化比较：五种计算引擎在 19 种不同数据集规模上执行相同的转换逻辑，重复七次。阴影带表示标准误差。每个转换均配置了 8 个 vCPU 和 32 GB 内存。曲线的提前终止表示达到了内存不足（OOM）条件。Polars 使用了通过 .polars(lazy=True) 访问的流式模式。

下面的基准图展示了一个相当复杂的管道，包含一个 explode 操作，后跟多个 join 和一个 group-by，分别使用 Pandas、Polars 和 PySpark 的 API 原生实现。

展示复杂转换优化的基准图

在这种情况下，使用无 Spark 的 Lightweight 后端可将启动开销几乎减少一半。此外，两种单节点优化的数据处理库 Pandas ↗ 和 Polars ↗ 在大约 1000 万行之前始终保持显著更快的速度，因为它们不像 Spark 那样需要等待网络绑定的 shuffle 结果。然而，对于更大的数据集和更复杂的操作，Spark 的查询计划在扩展性上要高效得多，因此在这些用例中推荐使用 Spark。

相比之下，将更简单的管道应用于更大的数据表明，即使在极其庞大的数据集上，Spark 也并不总是能够胜过 Polars。

展示简单转换优化的基准图

上图突出显示了一个关键观察结果：所实现的转换逻辑接近于简单，仅包含对数据集未进行分区的一列的单一过滤操作。在这种管道较为简单的设置中（例如算子较少且内存友好的连接），Lightweight Polars 的流式模式 ↗ 的性能远超 Spark，推荐用于所有规模的数据集。提醒一下，当 @transform 被装饰时 @lightweight，Spark 方法将不可用。

我们正在积极开发 Lightweight API。因此，一些功能（包括取消标记工作流或外部转换）尚不支持。以下功能即将推出：

  • 更多计算引擎支持（如 DuckDB 或 cuDF）
  • 自定义 Docker 镜像支持
  • 增量转换支持

附加信息

对于规模较小的数据集或较简单的处理逻辑，我们建议使用 Lightweight 转换以获得更快的计算速度。

Foundry 中的语义搜索支持现已正式发布 [GA]

发布日期：2023-11-13

随着向量属性和函数的引入，Palantir Foundry 现在支持本体论中的语义搜索。用户现在可以在本体论中为对象创建向量属性类型，并对对象（FoO）使用 K 近邻（KNN）函数，从而实现对对象的语义搜索。此功能使得可以利用本体论的模型输出获得更准确的结果。

Foundry 中的语义搜索功能可支持多种用例，包括改善文档库用户搜索特定主题时的体验。借助语义搜索支持，用户的查询可以根据其语义含义进行匹配并返回相关对象。此外，通过访问本体论，这些结果还可以回传到 LLM 中，以生成实用且用户友好的提示，从而增强现有的 AIP 构建器功能。

什么是语义搜索？

语义搜索是一种考虑查询上下文以返回更准确、更相关搜索结果的搜索技术。与仅匹配查询中完整短语而不考虑上下文的关键词搜索不同，语义搜索融入了用户搜索词背后的含义。

Foundry 中的语义搜索支持通过对本体论的多项增强来实现，包括：

  • 在 Object Storage v2 (OSv2) 中引入向量属性类型
  • 通过对象上的函数进行 K 近邻（KNN）搜索

从 Foundry 建模目标获得的浮点数组生成向量属性，然后在 FoO 函数中使用 KNN 搜索相似向量。有关详细的端到端语义搜索工作流示例，请参阅 语义搜索工作流教程.

配置向量属性类型

新的向量类型可用于将模型生成的嵌入捕获到本体论中。可以在任何固定维度的浮点数组数据集字段上创建向量属性。有多种相似度函数可用于比较向量，可根据用例和模型输出进行选择。

在 Ontology Manager 中，您可以配置向量属性：首先选择类型，然后选择维度（即此属性所基于的模型的输出长度），最后选择相似度函数，该函数决定如何将此向量属性类型与其他具有相同向量属性类型的对象进行比较。

对象上的 K 近邻函数

新增的对象上的 K 近邻（KNN）函数（FoO）支持简化了创建函数以对对象类型进行语义查询的过程。可以使用实时模型生成的向量或对象中的现有向量对该对象类型执行 KNN 搜索。请查看以下内容的更多信息： 文档中的 KNN FoO 函数.

Control Panel 角色现在将在 Platform Settings 中授予成员 Organization 权限

发布日期：2023-11-02

Organization 权限正分两个阶段从 Platform Settings 迁移到 控制面板 以提高可读性、减少混淆，并为平台管理员在权限设置方面提供更大的灵活性。目前，控制用户体验 Foundry 的各项设置（包括权限管理、成员资格、标记类别和组成员资格）在 Platform Settings 界面中管理，但将通过此次迁移整合到 Control Panel。

  • 第 1 阶段 （从 11 月 20 日当周开始）：Platform Settings 的工作流/权限将添加到 Control Panel 角色中。

  • 第二阶段 （预计 2024 年第一季度）：Platform Settings 权限的其余成员将迁移到包含相应工作流/权限的 Control Panel 角色。用户完全迁移后，旧版 Organization 平台设置将仅在 Control Panel 中可用。第二阶段变更的详细信息将在未来的公告中说明。

请仔细阅读以下通知，以了解权限更新将如何影响您和您的 Organization。

我们为什么要这样做？

我们发现用户对哪些权限在 Control Panel 中授予、哪些在 Platform Settings 中授予感到困惑。整合到单一界面可以提高清晰度并降低管理工作流的复杂性。

当前的权限系统不够灵活，并且由于顶级管理员独占某些任务的访问权限，导致其工作量过重。Control Panel 中的角色支持开箱即用的自定义，并且可以通过自定义角色以细粒度的方式授予这些工作流的权限。

这些变更将如何影响用户和现有权限？

在第 2 阶段结束时，所有现有权限将被自动迁移，不会导致任何访问权限或特权的丢失。但是，有几点重要变更需要注意：

第 1 阶段变更（于 11 月 20 日当周生效）

为了不再使用 Platform Settings 权限，我们首先必须在 Control Panel 中将这些权限/工作流授予相应角色。将创建一个新角色，并为一些现有角色添加新的工作流，从而使现有角色成员获得与角色描述相符的额外权限。

我们建议您提前根据贵组织的角色成员身份审查以下变更，以考虑安全性问题，并在必要时在 Control Panel 中更新角色。

以图表形式展示第 1 阶段变更中角色到 Control Panel 角色的映射关系

组织管理员获得 Manage 权限以及 Platform Settings 中授予的其他权限

组织管理员获得管理权限、成员资格、标记类别以及控制扩展访问/应用于组织的权限。

拥有组织管理员默认角色的用户将能够执行之前通过 Platform Settings 授予的工作流（管理权限、管理成员资格、管理标记类别以及查看组成员资格）。此变更延续了我们的理念，即组织管理员是一个高特权角色，应能够管理组织的所有方面。

扩展访问将保持独立，不会自动授予组织管理员。但组织管理员将能够通过导航到以下位置来管理拥有此功能的用户和组 Control Panel > Organization Permissions 标签页。

组织设置查看者获得 View group membership

拥有组织设置查看者默认角色的用户将能够查看该组织的组成员资格。目前，此 Control Panel 角色授予对 Control Panel 中组织权限的只读访问权限，但在未来几个月中将添加更多只读工作流。

数据治理官获得 Manage marking categories

拥有数据治理官默认角色的用户将能够为该组织管理标记类别。

[NEW] Users and groups administrator 默认角色

Control Panel 中将新增一个名为“用户和组管理员”的默认角色。添加到此角色的用户将能够管理该组织的成员资格。

[新增] 组织 Marking permissions 标签页

Control Panel 的组织权限部分将新增一个标记权限选项卡。这是对 Platform Settings 中“应用于组织”和“扩展访问”部分的一对一替代。

Control Panel 上新增的标记权限选项卡，供组织管理员查看组织权限和现有权限

第 2 阶段变更（计划于 2024 年第 1 季度）

在第 2 阶段中，现有权限授予将被自动迁移到 Control Panel 角色，Platform Settings 上的界面将被完全弃用并移除。在第 1 阶段启动后，我们将提供有关第 2 阶段详情的更多沟通。在第 1 阶段开始时，我们建议管理员：

  • 不再依赖 Platform Settings 来管理这些权限，而是通过相应的 Control Panel 角色进行授予；以及
  • 手动审计 Platform Settings 中的现有权限授予，并将其迁移到目标 Control Panel 角色。

有关权限及其基元在 Foundry 中如何运作的更多信息，请查阅以下文档 注册与组织 （在 Foundry 中）的更多信息。

Objects Monitoring 升级为 Automate [正式发布]

发布日期：2023-11-02

发布后，我们建议在将于 11 月 20 日当周正式发布，是全新的、完全向后兼容的产品，将取代 Objects Monitoring，成为 Foundry 中所有业务自动化的统一入口。所有现有的对象监控器将自动迁移到新应用程序中，并继续正常运行，无需任何更改。

Automate 摘要页面一览

Automate 允许用户在对象条件之外新设置时间条件，并将其关联到在条件满足时自动执行的操作或通知。相比 Objects Monitoring，Automate 提供了许多改进和扩展，包括全新设计的自动化创建用户界面、更多条件和效果配置选项，以及与平台中其他应用程序的原生集成。

用于稳健配置的新条件和效果

除了 Automate 能够创建永不过期的自动化之外，您现在还可以配置各种新的条件、效果和原生集成，为您提供更大的自动化灵活性。

条件

  • 时间条件：配置一个时间表，并在预定义的时间执行效果（例如，“每周一上午 9 点”）。
  • 对象集条件
    • 对象修改条件：当对象的任意或特定属性发生更改时触发效果
    • 允许内联指定受监控的对象集（不再需要保存的 Hubble 探索）
    • 新的执行模式（除现有的批量模式外）
      • 逐对象执行：允许为每个触发自动化的对象分别触发效果
      • 逐组执行：允许为预定义的组触发效果
    • 实时补丁支持：可实时监控的对象集现在可以立即获取来自操作（Action）的更改
  • 时间和对象集组合条件：在预定义的时间检查对象集条件（例如，“每周一上午 9 点，且针对任何新的警报对象”。）

“效果”

  • 通知
    • 属性支持的收件人：使用对象属性动态设置通知效果的收件人
    • 附件：选择 Notepad 或 Notepad 模板，以 PDF 形式自动附加到电子邮件通知中
      • 或
      • Notepad 模板
        • 支持从对象条件传递受影响的对象
    • 函数支持的通知
      • 支持传递单个受影响对象、对象引用、对象列表和对象集参数
  • 操作
    • 支持提供动态对象集定义作为对象集参数

原生集成

  • 原生 Notepad 集成
    • 直接从 Notepad 设置自动化，无需切换到 Automate
  • 原生本体论管理应用程序（OMA）集成
    • 从 OMA 设置自动化，并查看与特定对象类型或操作（Action）类型关联的所有自动化

开发路线图上有什么？

我们计划扩展 Automate 的功能，并将其进一步嵌入其他 Foundry 应用程序中，重点改进以下方面：

  • 对流式对象类型的支持
  • 基础设施改进以提高执行限制
  • 与 Machinery 的原生集成
  • 与 Foundry Logic 的原生集成

有关更多信息，请查阅 发布后，我们建议在 文档，或了解如何 开始使用 Automate.
